# Custom Agents & Model Selection

## Intent
Houses the two modules implementing user-defined custom agents (`agents.toml`) and per-agent model selection:

- `EvoGit.CustomAgents` (`../custom_agents.ex`) — pure-function TOML file store for custom agent definitions, living at `<config_dir>/agents.toml` (next to `config.toml`).
- `EvoGit.CustomAgents.ModelSelector` (`model_selector.ex`) — compiles and evaluates the user-provided `[model_selection] script` (an Elixir expression) per agent spawn to pick the agent's LLM model.

## API Surface

### `EvoGit.CustomAgents` (TOML store)

Pure functions, NO GenServer — every call reads/writes the TOML file directly (fresh read per call; nothing cached in this module, so external edits are picked up automatically).

- `path/0` → full path of the `agents.toml` file.
- `list/0` → `[definition_map]` (atom-keyed, schema-defaults applied; `[]` when missing/empty). Lenient: unknown values pass through unvalidated; skeleton file auto-created on first access.
- `get/1` (id) → definition map | `nil`.
- `save/1` (map) → `{:ok, definition} | {:error, atom}`. Upsert by explicit id; absent id auto-generated by slugifying `:name` (max 40 chars; collision → `:duplicate_id`). Preserves `[model_selection]`.
- `delete/1` (id) → `:ok | {:error, :not_found}`. Preserves `[model_selection]`.
- `model_selection_script/0` → script `String.t()` | `nil`.
- `save_model_selection_script/1` → `:ok | {:error, term}` (empty string removes the key; preserves `[[agents]]`).
- `reload/0` → `:ok` — invalidates BOTH the `ModelSelector` compile cache AND the `EvoGit.CustomTools` custom-tools load cache (each guarded with `Code.ensure_loaded?/1` + `function_exported?/3` + `apply/3`, warning-free when a module is absent).
- `stringify_keys/1` (public, `@doc false`) → shared map-stringify helper: `EvoGit.RemoteConnections` (`lib/evo_git/remote_connections.ex`) calls it when serializing connection maps to TOML, rather than keeping a local copy. New code needing string-keyed map serialization for config/TOML stores should reuse `CustomAgents.stringify_keys/1` instead of duplicating it.

**Validation error atoms** (`save/1` only — reads never raise): `:missing_name, :missing_prompt, :invalid_agent_type, :invalid_delegation_level, :invalid_model_spec, :invalid_max_turns, :invalid_tools, :invalid_subagents, :duplicate_id`.

**Definition map** (atom keys, defaults applied on save): `%{id (auto-slugified from name when absent), name (required), description (optional), prompt (required), agent_type (:read_write default | :read), delegation_level (:low default | :high), model_id (legacy default model PROFILE id; nil = auto), model_spec (optional canonical account/model/effort selection; nested keys are strings), max_turns (per-agent turn cap override), tools (whitelist of tool-name STRINGS — built-in tool names or user-defined custom tool names from `<config_dir>/tools/`, resolved by `EvoGit.CustomTools`; nil = built-in tools only, custom tools are opt-in), subagents (default []; built-in type-name STRINGS)}`.

### `EvoGit.CustomAgents.ModelSelector` (script evaluator)

- `compile_script/1` (body string) → `{:ok, fun} | {:error, {:compile_error, msg}}`. The body is wrapped as `fn agent -> <body> end` (`agent` variable in scope; last expression is the result).
- `select_model/1` (agent map) → `{:ok, model_id | selection | nil} | {:error, {:script_raised, message} | {:invalid_result, message} | {:compile_error, message}}`.
A canonical `selection` requires nonempty binary `provider_profile_id` and `model`, accepts atom or string input keys (atom keys win when both forms are present), and returns only atom-keyed selection fields.
Optional `reasoning_effort` accepts the schema's nonempty string or non-nil atom values and returns a string via `ProviderProfiles.Normalize.string_effort/1`; absent/nil effort is omitted so the schema chooses its configured default.
Malformed maps return `:invalid_result`, while account/model existence and supported effort inventories remain the schema resolver's responsibility.
`nil`/`""`/`false` → default model, and ordinary script exceptions are rescued, but throws/exits are not caught (called inline from the scheduler GenServer).
- `status/0` → `:ok | {:error, {:compile_error, msg}}` (dashboard surfacing of broken scripts).
- `enabled?/0` → `boolean()`.
- `describe_contract/0` → human-readable contract text (UI help).
- `invalidate/0` → `:ok` — erases the compile cache (called by `CustomAgents.reload/0`).

**`agent` map contract**: `%{agent_type: module() | :custom, custom_agent_id: String.t() | nil, depth: non_neg_integer(), parent_id: pos_integer() | nil, task_id: String.t() | nil, objective: String.t()}`.

## Constraints

- **Both modules live in this directory** — the store is `../custom_agents.ex` (one level up, sibling of this dir); do not relocate it.
- **`tools`/`subagents` entries are STRINGS in the TOML.** `save/1` rejects atom entries (`:invalid_tools` / `:invalid_subagents`) via `valid_string_list?/1`; custom tool names are ordinary non-empty strings, so they already pass this validation unchanged (the store does not resolve them — resolution is a runtime concern owned by `EvoGit.CustomTools`). `EvoGit.Agents.Custom` tolerates atom entries defensively at runtime, but the store is the contract owner — do not weaken validation to accept atoms.
- **ModelSelector caching**: compiled script cached in `:persistent_term` keyed `{__MODULE__, :cache, path}` storing `{mtime, size, entry}` — one `File.stat` + one `:persistent_term.get` per spawn after first compile; external edits picked up when mtime/size change. Lazy compile (never at boot) so a broken script cannot block scheduler startup.
- **Evaluation trust boundary**: `compile_script/1` concatenates the body into `fn agent -> ... end` and calls unrestricted `Code.eval_string/1`; `evaluate_script/2` invokes the returned value inline in the caller (normally the scheduler GenServer), with no worker process, timeout, sandbox, AST allowlist, resource limit or side-effect rollback.
Both boundaries use `rescue` only, not `catch`, so ordinary exceptions become error tuples but throws/exits, blocking code and VM-global side effects are not contained.
The string wrapper is not syntactic confinement: supplied source can close the anonymous function and add top-level expressions, and macro expansion can execute code during compilation, including from `status/0` or `enabled?/0` on a cache miss.
This mechanism is for trusted user configuration, not a safe evaluator for agent-generated expressions.
`normalize_result/1` accepts any binary as a legacy model/profile id and structurally valid canonical account/model maps without checking configured existence, maps nil/empty-string/false to default, and inspects invalid values without a byte/time budget.
- Consumers: `EvoGit.AgentScheduler.Dispatch.register_agent/7` (calls `select_model/1` per spawn, BEFORE `resolve_model_for_agent/2`; skipped when `spec.opts[:model_id_locked]`) and the `:evo_dash` settings UI (CRUD + script editor + `status/0` surfacing). Tests: `test/evo_git/custom_agents_test.exs`, `test/evo_git/agents/custom_test.exs`.

## Canonical provider-profile persistence and integration
`CustomAgents.normalize_definition/1` in `../custom_agents.ex` preserves an optional `model_spec` through save/list/get and TOML round-trips, alongside the legacy `model_id` fallback; saving a canonical selection never removes that legacy id.
A definition's canonical `model_spec` requires nonempty binary `provider_profile_id` and `model`, with optional `reasoning_effort` as a nonempty string or non-nil atom normalized to a string.
Nested atom or string input keys are accepted, atom keys win when both are present, and persisted/returned selection keys are strings (unlike `ModelSelector`'s atom-keyed result).
Absent/nil `model_spec` means no canonical definition default, absent/nil effort is omitted, and unknown selection keys are dropped.
`save/1` rejects structurally malformed selections with `:invalid_model_spec`, while reads remain lenient and account/model existence and supported reasoning efforts are validated by the runtime schema resolver, not the store.
Persistence alone does not apply a definition default at spawn: runtime consumers own selection priority and must pass canonical selections to the schema resolver rather than treat maps as legacy model ids.
An explicit `AgentSpec.model_spec` takes priority over legacy ids, defaults and scripts without fallback; the legacy path otherwise prioritizes a user-locked model over the script, then the caller/custom-agent legacy default, then the scheduler default.
`status/0` checks compilation only, not returned selection validity or configured existence.
Selector regression tests belong under `test/evo_git/custom_agents/`, including the existing `model_selector_test.exs`; test files must not live under `lib/`.
