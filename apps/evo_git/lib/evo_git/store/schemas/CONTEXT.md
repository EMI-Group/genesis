# Store Persistence Schemas

## Intent
These Ecto schemas describe persistence rows rather than public domain structs.
SQL constraints, indexes and database defaults are owned by migrations, not established by these schema declarations.

## API Surface
Every module exports `columns/0`, returning column-name strings in Ecto schema-declaration order.
`TaskRow` and read-only `TaskRowRaw` share 21 fields in order: `id, type, status, opts, started_at, finished_at, logs, result, review_status, usage, agent_count, base_sha, commit_sha, lease_expires_at, model_id, project_path, branch_name, error, session_mode, pause_kind, updated_at`.
Both task schemas use a string `id` primary key without autogeneration, and neither declares field defaults.
`TaskRow` uses Store custom types for task type/status/review status, JSON payloads, timestamps, lease milliseconds, session mode and pause kind, while `updated_at` uses `TaskTimestampRaw`.
`TaskRowRaw` uses integers only for `agent_count` and `lease_expires_at`, with every other field a string, so row decoding can occur outside Ecto's loader.
`TaskAgentArchiveRow` declares 23 fields in order: `task_id, agent_id, parent_id, depth, agent_type, context_node_path, objective, result, base_commit, final_commit, branch_name, archive_ref_start, archive_ref_final, repo_id, repo_root, repo_path, usage, llm_settings, agent_settings, foreign_repos, compression_count, started_at, completed_at`.
The archive has a composite `task_id` string plus `agent_id` integer primary key, integer `parent_id/depth/compression_count`, four custom archive JSON fields, and strings elsewhere.
Archive schema fields have no Ecto defaults, including `depth` and `compression_count`, whose documented SQL defaults are zero.
`VctMountRow` declares `point, path, name, kind, last_opened_at`, with a non-autogenerated string `point` primary key, strings for path/name/kind, and `Types.TaskTimestamp` for last-opened time.
The only explicit Ecto field default in this directory is `VctMountRow.kind`, which defaults to `"git"`.

## Constraints
No schema uses `timestamps()` or declares changesets, validation functions, check constraints, foreign keys or unique constraints.
The VCT moduledoc describes `path` as unique, but actual SQL uniqueness and nullability must be verified in migrations.
Task schema order need not equal physical column order on upgraded databases because reads address columns by name.
The task schemas require both `session_mode` and `pause_kind` to exist even if an existing migration ledger already claims versions that add them.
`TaskRowRaw` is read-projection-only; writes must use typed schemas or Codec encoding.

## Routing Table
There are no child directories.
Migration DDL and upgrade behavior belong outside this node in `apps/evo_git/priv/repo/migrations/` and `../boot.ex` plus `../historical_sources.ex`.
