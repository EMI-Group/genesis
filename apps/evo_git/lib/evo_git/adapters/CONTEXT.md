# Adapters

## Intent
Adapter layer wrapping external tool CLIs behind a safe, idiomatic Elixir API. Contains the Git adapter (all `System.cmd("git", ...)` calls behind structured result tuples), the GitHub adapter (`gh` CLI issue queries — no GitHub API HTTP calls), and a CoW-optimized worktree creation module.

## Routing Table
None — leaf directory (`git.ex`, `github.ex`, `cow_worktree.ex`).

## API Surface

### `EvoGit.Adapters` (parent module — `../adapters.ex`)
Documentation-only module declaring the adapter namespace.

### `EvoGit.Adapters.Git` (`git.ex`)
Low-level Git CLI wrapper centred on **worktree isolation**. Every function takes a `path` (working directory) as its first argument and returns tagged tuples.

| Category | Key Functions |
|---|---|
| **Generic execution** | `run/2` — execute arbitrary `git` args in a directory |
| **Worktree** | `add_worktree/4`, `prune_worktrees/1` |
| **Working tree ops** | `checkout/2`, `reset_hard/2`, `clean/1`, `add/2`, `commit/2` |
| **Merge** | `merge/2`, `merge_octopus/2`, `merge_base/3`, `merge_ff_only/2` — thin wrappers over one private `do_merge/2` via `run/2`; `merge_ff_only/2` = `run(["merge", "--ff-only", ref], path)` |
| **Status / query** | `conflict_files/1`, `status/1`, `rev_parse/2`, `rev_parse_short/2`, `check_ignore/2`, `remote_url/1,2` |
| **Clone / sync** | `clone/2,3`, `fetch/2` — remote clone (extra args like `["--depth", "1"]` between `clone` and url/path; runs from `File.cwd!()`) + fetch; used by `EvoGit.SelfReflectiveSource` |
| **Tree listing** | `ls_tree_names/2` (recursive file list, gitlinks excluded), `ls_tree_gitlinks/2` (gitlink paths only, mode `160000`/type `commit`) — shared private parser `parse_ls_tree_output/2`; `ls_tree_gitlinks/2` feeds `EvoGit.Runtime.Helpers.load_repo_notes/2` |
| **History** | `log/2`, `file_history/3`, `show/2` |
| **Diff** | `diff/4`, `file_diff/5`, `diff_stat/3`, `diff_numstat/3`, `diff_shortstat/3`, `diff_name_only/3` — changed file paths between two commits |
| **Notes** | `add_note/4`, `remove_note/3`, `show_note/3`, `get_note/4`, `list_notes/2` |
| **Tags** | `tag/3`, `delete_tag/2` |
| **Refs** | `update_ref/3`, `delete_ref/2` — archive refs protecting commits from GC |
| **Branches** | `create_branch/3`, `current_branch/1`, `list_branches/1`, `list_branches/2`, `branch_exists?/2`, `delete_branch/2` |
| **Init** | `init/1` |
| **GitHub** | `gh_available?/0`, `create_pull_request/5`, `create_origin_remote/1`, `origin_default_branch/1`, `has_origin_remote?/1`, `push_branch/2` |

**Return convention (uniform):** every function returns `{:ok, value}` or `{:error, {tag, output}}` (output = trimmed `String.t`). Tag table:

| Tag | Meaning |
|-----|---------|
| `code :: integer` | git CLI exited non-zero (other than the conflict case) |
| `:conflict` | git exited 1 in a merge-style conflict (or any other exit-1 command) |
| `:enoent` | repository path does not exist (`run/2` pre-check) |
| `:no_note` | `git notes show` found no note for the object (`get_note/4`) |
| `:invalid_json` | note content is not valid JSON metadata (`get_note/4`) |
| `:temp_file` | writing the temporary `-F` content file failed (`add_note/4`, `commit/2`) — output is the `:file.format_error/1` reason string |

This matches `EvoGit.Review`, which normalizes adapter errors to exactly this `{tag, output}` form (review.ex:380-381, 460-461).

**Documented exceptions** (deliberately NOT part of the uniform contract):
- Predicates `branch_exists?/2`, `gh_available?/0`, `branch_has_unique_commits?/3`, `has_origin_remote?/1` return booleans (consumed in boolean contexts, e.g. review.ex:347, pull_request.ex:20-22).
- `origin_default_branch/1` always returns `{:ok, branch}` with a `"main"` fallback (pull_request.ex:26-28 pattern-matches only `{:ok, branch}`; origin/HEAD is frequently unset).
- `commit/2` treats "nothing to commit, working tree clean" (exit 1) as success `{:ok, _}`.

Notes on specific functions:
- `ls_tree_names/2`, `diff_name_only/3`, `check_ignore/2`, `list_branches/1`, `list_branches/2` return `{:ok, [files]}` (empty on no results).
- `ls_tree_names/2` runs `git ls-tree -r <treeish>` (NOT `--name-only`, which hides the entry type) and **excludes gitlink/submodule entries** — actual file paths only. Submodule dirs arrive in worktrees as **empty placeholders** (same as `git worktree add`); populate via `git submodule update --init`.
- `check_ignore/2`: exit 1 ("no matches") → `{:ok, []}` — a valid result, not an error.
- `get_note/4` → `{:error, {:no_note, output}}` (missing note) / `{:error, {:invalid_json, note_content}}` (unparseable or non-map JSON) / passes through other `{:error, {tag, output}}` (e.g. `:enoent`).
- `merge/2`/`merge_octopus/2` share one private `do_merge/2` → `run/2`; conflict (exit 1) → `{:error, {:conflict, output}}`, other exits → `{:error, {code, output}}`.
- **Merge dry-runs use NO worktrees**: `Review.check_merge/3` runs `git merge-tree --write-tree --name-only --no-messages <branch_sha> <target_sha>` via `run/2` — an in-memory real merge touching no worktree, index, or ref (nothing ever created under `.genesis/`). Requires git >= 2.38. Clean → exit 0 (stdout = resulting tree OID); conflict → exit 1 (stdout = conflicted tree OID line(s) + one conflicted path per line; OID lines dropped by shape `~r/^[0-9a-f]{40}$/`); exit-1 non-conflict errors (e.g. missing ref) → `{:error, {:merge_failed, output}}`; other failures → `{code, output}`. No `merge_abort` helper exists. After a conflicted `merge/2` the repo is left mid-merge (MERGE_HEAD + unmerged index + conflict markers); `git checkout --force <branch>` clears all three (so `Review.merge_into_other`'s `force_restore_branch` discards the conflicted state), but `Review.merge_into_current` (target == checked-out branch) returns `{:conflict, details}` with NO restore — the repo stays mid-merge on that branch.

### GitEnv — commit identity & environment (`git_env.ex`)

`EvoGit.GitEnv.git_env(repo_path)` builds the environment for every git invocation (used by `EvoGit.Adapters.Git` and the sandbox backends via `git_env_list/1`).

- **Commit-identity priority**: (1) inherited environment (`System.get_env/1`, non-empty; empty string treated as unset, mirroring git) — NEVER clobbered; (2) repository's effective `git config user.name`/`user.email` (no scope flag → repo → global → system); (3) fallback `"Genesis"`/`"noreply@evogit.ai"` only when nothing is configured anywhere, so automated commits never fail "Please tell me who you are".
- **Memoized per repo path** in `:persistent_term` (`{GitEnv, :config_identity, repo_path}`; the `nil` key = global/no-repo resolution). Stale-until-VM-restart is an accepted trade-off (avoids 2 extra process spawns per git invocation); inherited env vars are read fresh at call time, never memoized. Only bare `git_env/0` calls (nil path) resolve global-level identity.
- Test helper: `GitEnv.clear_config_identity_cache/1` (`@doc false`).
- `git_env/1` always sets `LC_ALL=C` + `GIT_EDITOR` (resolved `true` path); used by both `EvoGit.Adapters.Git` and the sandbox backends (`git_env_list/1`).
- **No git-config-file suppression → every git spawn re-reads global/XDG config (NFS exposure)**: the env map (git_env.ex:75-86) sets exactly `LC_ALL`, `GIT_EDITOR`, and the four identity vars — NO `GIT_CONFIG_GLOBAL`/`GIT_CONFIG_NOSYSTEM`/`GIT_CONFIG_SYSTEM`/`XDG_CONFIG_HOME`/`HOME`/`GIT_DIR`/`GIT_TEMPLATE_DIR` override exists anywhere in lib/config (rg-verified). Git therefore performs its own full startup config discovery (system `/etc/gitconfig` → global `~/.gitconfig` → `$XDG_CONFIG_HOME/git/config` → repo `.git/config` via the worktree gitdir) on EVERY spawn, so with HOME/XDG on NFS every git invocation — even `rev-parse`/`status` against a local-SSD repo — touches NFS regardless of the repo location. And the identity memoization is keyed per repo/worktree PATH (git_env.ex:175-187) while worktrees are created FRESH per agent run (`<repo>/.genesis/workers/worker_T<task>_A<agent>`, `Worktrees.workers_dir`), so each new worktree takes at least one cold miss: 2 extra untimed raw-`System.cmd` `git config` spawns in the parent process (git_env.ex:194-222, `:infinity` default) that themselves read the NFS global config. Conditional extras per spawn: `includeIf`/`core.hooksPath`/`init.templatedir`/`credential.helper` from that global config can add further NFS opens (credential helpers only on network ops — `fetch`/`clone`/`push`, none of which run in a task's finalizing window).

## Branch / Ref Mutation Inventory (which adapter calls can overwrite an existing branch or ref)

- **`Git.create_branch/3` (git.ex:664-667)** → `run(["branch", branch_name, commit_sha], repo_path)` = plain **`git branch <name> <sha>`**. There is NO `-f`/`--force` variant in the adapter. **An already-existing branch is NEVER overwritten**: git refuses and exits **128** → the uniform error arm (git.ex:103-104) yields `{:error, {128, "fatal: a branch named '<name>' already exists"}}` (tag is the integer `128`, NOT `:conflict`; only exit 1 maps to `:conflict`). Call sites (`Runtime.Helpers.merge_and_report/4` primary helpers.ex:57 + foreign `create_foreign_branch/3` helpers.ex:165) tolerate the failure → report entry keeps `commit_sha` with `branch_name: nil`. Nothing deletes the branch first; a name collision (e.g. re-running a task whose `genesis/agent_<hex>` branch already exists) therefore silently produces no branch. Note the branch name is created at `commit_sha` and is NOT checked out anywhere (no worktree/index/HEAD movement).
- **`Git.add_worktree/3,4` (git.ex:144-173)** — checks out `base_sha` in the new worktree, and it DOES replace an existing branch-name ref, via delete + recreate: if `branch_name` is non-nil AND `branch_exists?/2`, it first calls `delete_branch/2` (`git branch -D`) with the **result intentionally ignored** (git.ex:146-150), then runs `git worktree add -b <branch> <path> <base_sha>` (git.ex:158) — i.e. the branch is force-(re)pointed at `base_sha`. If the old ref is checked out in a LIVE worktree, git refuses the `-D` AND the `-b` add fails with exit 128 "a branch named ... already exists"; the failure path then runs `cleanup_failed_worktree_add/3` (git.ex:184-191, best-effort branch `-D` + `remove_leftover_worktree_dir/1`) and returns the `{:error, {128, output}}`. With `branch_name = nil` (the `/3` arity) it is a **detached checkout**: `git worktree add --detach <path> <base_sha>`.
- **`Git.reset_hard/1,2` (git.ex:229-231)** → `git reset --hard <sha>` (default `"HEAD"`) — the only call in the adapter that MOVES the currently-checked-out branch ref and discards working-tree changes. Production call site: `EvoGit.SelfReflectiveSource` (`self_reflective_source.ex:288`, `Git.reset_hard(dir, "origin/<branch>")` to sync the managed clone).
- **`Git.update_ref/3` (git.ex:327-330)** → `git update-ref <ref> <sha>` — unconditionally creates OR overwrites a ref (no `--no-deref`, no old-value check; test-pinned overwrite: git_test.exs:299-315). Used only for archive refs (`agent/tools/complete_task.ex:298-299`, `refs/genesis/archive/...`) — does not touch the worktree/index/HEAD.
- **`Git.delete_ref/2` (git.ex:335-337)** → `git update-ref -d <ref>`.
- **`Git.delete_branch/2` (git.ex:622-624)** → `git branch -D <name>` — FORCE delete (ignores unmerged commits; refuses only when checked out in a worktree). Callers: `add_worktree`/`cleanup_failed_worktree_add` (git.ex:149,186), `CowWorktree` (cow_worktree.ex:197,372), `Review` (review.ex:368,387,503), `SubagentProcessing` (subagent_processing.ex:510), `Worktrees.delete_branch_tolerant/2`.
- **`Git.add_note/4,5` `force` arg (git.ex:534-546)** → `git notes add -f` — overwrites an existing note (the `-f` flag is scoped to `notes add` only).
- **`CowWorktree` (cow_worktree.ex)**: pre-deletes an existing branch (cow_worktree.ex:196-198, result ignored) then `git worktree add --no-checkout -b <branch> <path> <target_commit>` (:200-203); on failure `cleanup_failed_worktree_add/3` (:213). Its `checkout_target/2` (:250-258) is PATH-LIMITED (`git checkout <target_commit> -- .`, not forced) and `cleanup_partial_worktree/3` (:365-375) runs `git worktree remove --force <path>` + best-effort `branch -D` — the `--force` there removes a worktree with modifications, NOT a ref rewrite.
- **No force-push anywhere**: `Git.push_branch/2` (git.ex:729-731) is `git push -u origin <branch>` (no `--force`). `merge/2`, `merge_octopus/2`, `merge_ff_only/2`, `checkout/2` carry no force flags.

## Known Issues — Windows argv quoting (`-m` vs `-F`)

**Never pass arbitrary user/LLM-generated content (commit messages, note content) as a `-m` argv element.** On Windows, git-for-Windows' MSYS2 runtime re-parses the command line: embedded double quotes split an argument into multiple argv tokens, and a token starting with `>` is treated as an option switch (`error: unknown switch `>'`). Hit with `git notes add -m <JSON metadata>` (pretty-printed JSON always contains quotes, newlines, and often `>`/`->`).

- `Git.add_note/4` and `Git.commit/2` write content to a unique temp file (`System.tmp_dir!()` + `genesis_git_msg_<unique_integer>.json|.txt`; Windows path passed with forward slashes — safe for MSYS2) and run `-F <file>` instead of `-m`. `-F` matches `-m` semantics: both apply the `whitespace` cleanup for non-edited messages (byte-identical stored messages incl. embedded quotes and `>`); `git notes -F` strips `#`-comment lines and surplus empty lines. Content written exactly as given (no trailing newline).
- Temp-file deletion ALWAYS runs via `try/after` (NOT `try/rescue` — nothing rescued/swallowed, so the no-`try/rescue` constraint is not violated). `File.write` (non-bang) failure → `{:error, {:temp_file, reason_string}}` (`:file.format_error/1`).
- **Rules for future work**: content-bearing args → `-F <tempfile>` using the private `temp_file_path/1` + `normalize_temp_path/1` helpers (git.ex) + `try/after` cleanup; never `-m`.
- Safe call sites: `tag/3`/`delete_tag/2` (zero callers in lib/test); `create_branch/3` (names from `Runtime.Helpers.generate_branch_name/1` — `genesis/agent_<hex>`, safe alphabet); `add_worktree/4` fallback (uses `Worktrees.branch_name/2` — `evogit-agent-T<task>-A<agent>`, safe alphabet); `create_pull_request/5` title/body go to the `gh` CLI (native Go binary parsing via CommandLineToArgvW, NOT MSYS2 — Erlang's Windows argv quoting round-trips embedded quotes correctly) — different bug class. `agent/tools/context.ex` passes commit messages via `git commit -F <tempfile>` under `EvoGit.Sandbox.resolve_tmpdir()` (details in `agent/tools/CONTEXT.md`).

### Known Issues — No Timeout, No Logging, No Test Seam on git invocations

Diagnostic-relevant facts for hangs/slowness (e.g. a task stuck in `:finalizing` on a slow NFS home dir):

- **Every git call in `git.ex` runs with NO timeout (`:infinity`)**. The single raw invocation envelope `run_git/2` (git.ex:78-84) is `System.cmd(EvoGit.Executable.resolve("git"), args, cd: path, stderr_to_stdout: true, env: EvoGit.GitEnv.git_env(path))` — no `:timeout` option, so Elixir's default `:infinity` applies: the caller blocks in `receive` until the git child exits. If the child enters uninterruptible D-state (NFS hard-mount hang) the port never delivers `:exit_status` and the caller blocks FOREVER. `git.ex` contains ZERO occurrences of `:timeout`/`Port`/`receive`/`kill` — no BEAM-side watchdog anywhere in the module. This is the code path behind the `:finalizing` window: `Runtime.Helpers.merge_and_report/4` calls `Git.rev_parse` + `Git.create_branch` (helpers.ex:42,51,157) which run as blocking System.cmd in the wrapper process. Besides `run/2`, the `run_git/2` envelope is ALSO invoked directly — equally untimed — by `check_ignore` (git.ex:342), `branch_exists?/2` (:688), `branch_has_unique_commits?/3` (:713), `has_origin_remote?/1` (:782), `origin_default_branch/1` (:830); the three `gh` CLI calls (`create_pull_request/5` git.ex:743-759, `create_origin_remote/1` :798-811, private `get_github_username/0` :849) are bare untimed `System.cmd` too.
- **Contrast — the timed machinery is NOT on the adapter's path, and NOT even on the `sandbox_run` path**: timeout + whole-tree kill exist ONLY in the sandbox `run_with_partial/6` implementation (`sandbox/none.ex:221-304` `run_with_partial_windows/5`; same pattern in linux/bwrap/macos), reached only via `EvoGit.sandbox_run_with_partial/6` (lib/evo_git.ex:107-116) → `Sandbox.run_with_partial/6` (sandbox.ex:127-129) — used by ShellTool/`run_bash` (shell_tool.ex:24,181; default 180s). Plain `EvoGit.sandbox_run/4` (lib/evo_git.ex:83-85) → `Sandbox.run/4` (sandbox.ex:89-92) → backend `run/4` is an **UNTIMED blocking `System.cmd` on every backend** (linux.ex:94-107 systemd-run `--wait` with NO `RuntimeMaxSec`/`TimeoutStopSec` property, bwrap.ex:261-286, none.ex:34-66). So agent write-tool `git add`/`git commit` (tools/context.ex:293,336) AND the agent-facing `run_git` tool (`agent/tools/git.ex:65`, `EvoGit.sandbox_run`) are ALL untimed — `run_bash` is the only timed tool exec. `git.ex` itself never calls either sandbox function.
- **Zero `Logger` calls in `git.ex`** — no per-invocation logging of command+repo at ANY level (debug included). A hung/slow git call is invisible in logs except via caller-side logging.
- **No test seam / no mocking**: no app-env `git_runner` override, no Mox/Meck anywhere in the codebase (comments at `context_compression_test.exs:176`, `tool_dispatch_retry_slot_test.exs:24`); `git_test.exs` runs REAL git against real temp repos. The ONLY injection point is `EvoGit.Executable.resolve("git")` (git.ex:79) — a PATH lookup via `System.find_executable` (executable.ex:19-24) with a bundled `priv/vendor` fallback — so a test could theoretically prepend a fake blocking `git` script to PATH, but none does. There is no test covering a hangs-forever git.

### `EvoGit.Adapters.GitHub` (`github.ex`)
Thin wrapper for GitHub issue queries via the `gh` CLI (`gh issue list` / `gh issue view`) — no GitHub API HTTP calls. `gh_available?/0` is **reused from `EvoGit.Adapters.Git`** (never duplicated).

**Invocation conventions** (deliberately distinct per binary):
- **gh**: `System.cmd("gh", args, cd: repo_path, stderr_to_stdout: true)` — plain `"gh"`, no GitEnv. Every invocation guarded by `Git.gh_available?/0` first (`System.cmd("gh", ...)` raises `ErlangError` when gh is not on PATH).
- **git**: `System.cmd(EvoGit.Executable.resolve("git"), args, cd: repo_path, stderr_to_stdout: true, env: EvoGit.GitEnv.git_env(repo_path))`.
- `:enoent` convention: every function PRE-CHECKS `File.dir?(repo_path)` → `{:error, {:enoent, repo_path}}`.

**Functions** (all take `repo_path` first; pinned check order: dir exists → gh available → upstream resolvable → run gh):

| Function | Success | Errors |
|---|---|---|
| `github_upstream/1` | `{:ok, %{owner, repo, url, gh_available}}` | `{:error, {:enoent, _}}` / `{:error, :no_github_upstream}` (non-GitHub origin URL, or no origin remote — contract-pinned exit 128, plus exit 2 from git ≥2.55 "No such remote") / `{:error, {:code, code, trimmed_output}}` |
| `list_github_issues/2` (`opts \\ []`: `:state` default `"open"`, `:limit` default 100, integer) | `{:ok, [issue_map]}` | `{:error, {:enoent, _}}` / `{:error, :gh_not_available}` / upstream error as-is / `{:error, {:gh, code, trimmed_output}}` / `{:error, {:invalid_json, reason}}` (malformed JSON — `reason` = Jason error; non-array — `reason` = `:not_an_array`) |
| `github_issue_markdown/2` | `{:ok, markdown}` | same error shapes as `list_github_issues/2` (view JSON is a single object; non-object → `{:error, {:invalid_json, :not_an_object}}`) |

**Upstream URL parsing**: own regexes (NOT git.ex's `@repo_url_re`, which covers https only) — https `https://github.com/owner/repo` AND ssh `git@github.com:owner/repo.git`, each with optional trailing `.git`/slash/whitespace (input trimmed first, then anchored match). `url` = trimmed origin URL verbatim; `repo` has `.git` stripped.

**JSON normalization** (list fields `number,title,state,labels,url,author,createdAt`; view uses `body` instead of `createdAt`): each gh object → `%{number: integer, title: String.t(), state: String.t(), labels: [String.t()], url: String.t(), author: String.t(), created_at: String.t()}` (list map has exactly these 7 keys). `labels` = `name` strings extracted from label objects (missing `name` skipped); `author` = `login` of the author map (missing → `""`); `createdAt` → `:created_at`.

**Pinned markdown format** (`github_issue_markdown/2`, asserted character-for-character):
- With labels: `# GitHub Issue #<n>: <title>\nURL: <url> | State: <state> | Labels: <l1>, <l2>\n\n<body>`
- WITHOUT labels the labels segment is omitted: `# GitHub Issue #<n>: <title>\nURL: <url> | State: <state>\n\n<body>`
- Labels joined with `", "`; body embedded verbatim after one blank line. No `try/rescue` — all failures are tagged tuples.

### `EvoGit.Adapters.CowWorktree` (`cow_worktree.ex`)
CoW (copy-on-write) optimized worktree creation: create an EMPTY linked worktree (`git worktree add --no-checkout`), copy the unchanged ("shared") tracked files from a source working tree via `cp` (Linux reflink attempt, macOS clonefile), then `git checkout <commit> -- .` materializes the remaining paths. **Optimization with graceful fallback** — a failure returns `{:fallback, reason}` so the caller (`AgentScheduler.Worktrees.create_worktree/6`, the ONLY production call site — `worktrees.ex:110-117`) falls back to `Git.add_worktree/4` (`git worktree add -b <branch> <path> <base_sha>` = FULL checkout) for THAT creation; all fallback returns are routed through `handle_fallback/2` (see below), which disables CoW persistently ONLY for a permanent reason. **Shape-agnostic w.r.t. the Git adapter contract** — its tagged `with` patterns and catch-all `error` arms are contract-agnostic; its `{:error, code, output}` comes from its OWN internal `cp` invocations (`copy_files_linux/3` cow_worktree.ex:281, `copy_files_macos/3` :322), NOT the Git adapter.

Public API: `enabled?/0` (gate — reads `[:git, :cow_worktree_creation]` config `:auto`/`:enabled`/`:disabled`, default `:auto`, schema `config/schema/definitions.ex:563`; `:auto` auto-detects ONCE as non-Windows + `cp` on PATH, caches via persistent-term), `create_worktree/5` (`(repo_root, worktree_path, target_commit, branch_name, source_path)` → `:ok` | `{:fallback, reason}`), `flag/0`/`enable/0`/`disable/0` (persistent-term flag `:evogit_cow_worktree_enabled`). `source_path` = source working tree: top-level agents copy from repo root; subagents copy from the parent agent's worktree (`Worktrees.resolve_source_path/2`). Two `@doc false` public helpers exist solely for direct unit tests: `permanent_reason?/1` (reason → boolean — `true` only for `:unsupported_platform`) and `handle_fallback/1,2` (`handle_fallback(reason, detail \\ nil)` — the single fallback choke point: calls `disable/0` ONLY for permanent reasons, logs, returns `{:fallback, reason}`).

**Algorithm** (`create_worktree/5`, cow_worktree.ex:99-179): `rev_parse` source worktree → `status --porcelain` dirty files → `diff_name_only` changed-between-commits → `ls_tree_names` all target-tree files → shared = `target ∖ changed ∖ dirty` (113-116) → `worktree add --no-checkout -b <branch> <path> <target_commit>` (185-209) → `copy_shared_files/3` then `checkout_target/2`. File lists come from `git ls-tree -r`, so **gitlink/submodule paths are excluded** (submodules arrive as empty placeholders) and dirty submodules are excluded like any file (`parse_dirty_files/1`, 359-373). Copies are batched `@batch_size 1000` — Linux: one `cp --reflink=auto --preserve=timestamps --parents <files…> <wt>/` per batch (`cd: source_path`, 281-297); macOS: one `cp -cp <files…> <dest>` per distinct parent dir, dirs pre-created via `File.mkdir_p` (299-343); other platforms → `:unsupported_platform` in `copy_shared_files/3` → `handle_fallback(:unsupported_platform)` (a PERMANENT reason — the only one that disables CoW). The copy is SEQUENTIAL within a batch (one `cp` process); parallelism comes only from many agents each running their own `cp` concurrently.

**⚠️ No filesystem-capability probe — the "CoW" benefit is FS-dependent and silently degrades.** `enabled?/0` checks only non-Windows + `cp` on PATH; it never probes reflink/clonefile support. `cp --reflink=auto` (and macOS `cp -cp`) fall back to a FULL byte copy with no error when the FS cannot reflink, so on such an FS the CoW path still copies every shared tracked file byte-for-byte — with many agents fanning out this saturates the disk. btrfs/XFS (reflink) and APFS (clonefile) already give true metadata-only clones through the SAME code path, so no code change is needed there. `{:fallback, reason}` (including `:disabled`) always lands on `Git.add_worktree` (full checkout), so a filesystem-level snapshot/clone primitive can reuse the identical fallback contract.
**⚠️ Known issue — the fake "CoW" copy is not what saves work, and its mtimes do NOT survive.** `git worktree add --no-checkout` leaves the new worktree's index EMPTY, so the following `git checkout <target_commit> -- .` (`checkout_target/2`) re-extracts EVERY path in the target tree (new inode, mtime = now), overwriting both the mtimes and the content transfer the preceding `cp` had just made — the "git stat+hash-skips already-present files" comment in `populate_worktree/5` does not hold for this flow (verified by direct repro on git 2.54: a copied file keeps mtime `2020-01-02` after `cp --preserve=timestamps`, then becomes mtime=now with a new inode after the checkout). Consequence: worktree creation gets no cache-warmth benefit from this adapter's copy; the copy path that DOES preserve mtimes end-to-end is the Worktree Init Script catalog (`EvoGit.Runtime.WorktreeInitScript`), whose `cp --preserve=timestamps` / `cp -cRp` is the LAST step. A flow that preserves mtimes was repro-verified (`git read-tree <target_commit>` + `git update-index --refresh` + `git checkout-index -a`) but is NOT implemented — changing the checkout step is a behavior change that must keep the `{:error, code, output}` / `{:fallback, reason}` contract.

**Algorithm**: resolve source HEAD → dirty files in source working tree → changed files between source and target commits → all target tree files → shared files (identical + not dirty) → `git worktree add --no-checkout` → copy shared files via batched `cp` (Linux: `--reflink=auto --preserve=timestamps --parents`, ~1000 files/invocation; macOS: `-cp` clonefile + timestamp preservation with pre-created dirs, files grouped by parent dir via `Enum.group_by(&Path.dirname/1)` with ONE `cp -cp` per distinct directory; top-level files (`dir == "."`) target the worktree root directly) → checkout remaining files. All steps handle errors gracefully (NO `try/rescue`), cleaning up partial worktrees and returning `{:fallback, reason}` — which disables the feature ONLY for the permanent `:unsupported_platform` reason. **Gitlink/submodule entries are excluded from the file lists** (`ls_tree_names/2` never returns gitlink paths — a populated submodule checkout is a DIRECTORY; feeding it to `cp` as a file would fail). Submodule paths arrive in the worktree as **empty placeholder dirs** (populate via `git submodule update --init`). `parse_dirty_files/1` parses submodule `git status --porcelain` lines (e.g. ` M vendor/Sub`) with the same path slicing as regular files, so a dirty submodule is excluded from the copy list like any other dirty file.

**I/O profile / concurrency (how many processes per creation)**: `create_worktree/5` (cow_worktree.ex:99 — arity is 5, NOT 6) issues per creation, on Linux, ~8–10 blocking `System.cmd` OS processes plus `ceil(shared_files / 1000)` `cp` processes: (1) `git rev-parse HEAD` in `source_path` (`Git.rev_parse`, :101), (2) `git status --porcelain` in `source_path` (`Git.status`, :103 — O(working-tree) stat + hash of modified files), (3) `git diff --name-only <source_sha> <target_commit>` in `repo_root` (`Git.diff_name_only`, :105), (4) `git ls-tree -r <target_commit>` in `repo_root` (`Git.ls_tree_names`, :107 — O(total tracked files) full listing), (5) optional `git branch -D` if the branch exists (:187), (6) `git worktree add --no-checkout -b <branch> <path> <commit>` (:191 — registration only, no file writes), (7) `cp --reflink=auto --preserve=timestamps --parents <batch…> <dest>/` in 1000-file chunks (`copy_files_linux/3`, :281-297 — one process per chunk, all shared files), (8) `git checkout <target_commit> -- .` (`checkout_target/2`, :248 — a FULL-tree index/stat pass; re-extracts EVERY path of the target tree (the index is EMPTY after `--no-checkout`), the copied files' mtimes included — see the ⚠️ known-issue bullet above). The caller (`EvoGit.AgentScheduler.Worktrees.assign_and_prepare_worktree/3`, worktrees.ex:315-317) then adds `git clean -fd` + `git checkout <branch_name>`. macOS is WORSE for spawn count: `copy_files_macos/3` (:299-343) issues ONE `cp -cp` per distinct parent directory per batch (up to ~1000 spawns per batch) plus `File.mkdir_p` per dir.
**Only git-TRACKED files are copied** — the copy set is derived from `git ls-tree -r` (gitlinks/submodules excluded by the parser), so untracked/generated files (`.genesis`, `node_modules`, build outputs) are never copied by the adapter. There is NO explicit exclusion list in the adapter (rg-verified) — `.git` is git metadata, `.genesis`/`.node_modules` are untracked/gitignored. Dirty (modified) tracked files in the source are also excluded from the copy and re-materialized by the final `git checkout`.
**No serialization, no lock, no rate-limit in the adapter** — `create_worktree/5` is a pure per-call function with zero shared state. Concurrency of the creation PIPELINES is bounded by `EvoGit.AgentScheduler.WorktreeManager`: each create request is pushed onto a FIFO `admission_queue` and started only while `creating_count < Application.get_env(:evo_git, :max_concurrent_worktree_creation, 4)` (default 4, cap read at ADMISSION time), so at most 4 full-tree copy pipelines run at once and any extra requests wait in the queue to be started later. Creation is still offloaded to a spawned `Task.start` per agent (the GenServer stays responsive for `:DOWN` handling), and this cap bounds CREATE-pipeline concurrency ONLY — never live worktrees/agents.
**Fallback reasons are transient or permanent, and only permanent disables CoW**: every fallback return is routed through `handle_fallback/1,2` (the single choke point) which calls `disable()` ONLY when `permanent_reason?/1` is true. **Permanent** = `:unsupported_platform` (the platform has no CoW copy backend — can never succeed in this VM) → `:persistent_term` `{EvoGit.Adapters.CowWorktree, :evogit_cow_worktree_enabled}` = `:disabled`, and `enabled?/0` then returns false until VM restart. **Transient** = `:no_source_head`, `:no_source_status`, `:no_changed_files`, `:no_target_tree`, `:worktree_add_failed`, `:cp_failed`, `:checkout_failed` (I/O pressure, subprocess/lock/git failure) → `{:fallback, reason}` for THAT creation only; CoW stays ENABLED and the next creation retries the CoW path. There is deliberately NO cooldown timer. `enabled?/0`'s `:auto` mode independently disables on the permanent condition "Windows or no `cp` on PATH". A separate `{:fallback, :disabled}` is injected by worktrees.ex:119 when CoW is off.

## Constraints

- One adapter module per external tool; each file must follow the `EvoGit.Adapters.<Tool>` naming pattern.
- All external command invocation must go through `run/2` (or equivalent `System.cmd` wrappers) to keep error handling consistent.
- Functions must never raise on CLI failures — always tagged tuples. Uniform error shape: `{:error, {tag, output}}` (see return contract above).
- No business logic belongs here; adapters are thin wrappers translating CLI I/O into Elixir data structures.
- No `try/rescue` — errors are returned as tagged tuples, never rescued/swallowed.
- **CowWorktree** is an exception to the "thin wrapper" rule — it orchestrates a multi-step optimization, but follows the no-`try/rescue` convention and uses non-crashing variants (`File.mkdir_p/1`, `case`/`with` for error propagation).
