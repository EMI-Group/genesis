# Agent Context Compression — two-stage pipeline

## Intent

Context compression relieves a conversation that outgrew its CONFIGURED context window, cheapest stage first: a model-free tool-result pruner runs first but is adopted only when it recovers a LOT (down to a fraction of the window), otherwise a summarising LLM checkpoint runs over the ORIGINAL transcript.
The single entry point is `EvoGit.Agent.ContextCompression.compress_if_needed/2` (called at the top of every `EvoGit.Agent.Runner.loop/1` iteration), which orchestrates both stages; this directory holds the pure sub-modules it composes.
No module here owns a process, writes configuration or uses `try`/`rescue` — the one LLM call lives in `LlmRetry`, and its only scheduler interaction is the LLM slot request.

## Pipeline

`compress_if_needed/2` takes `agent_id:`, `llm_model:`, `llm_context_window:` (default `EvoGit.Config.Schema.LLM.default_context_window/0` = 200_000) and `llm_generation_params:` and returns the `%LoopState{}` (compressed or untouched) or the terminal `{:error, {:llm_request_rejected, message}}`.
Its work only starts for a conversation shaped `[_system, _first_user | _rest]`; any other shape is returned unchanged.

1. **Gate** — `Threshold.for_model(llm_model, context_window: llm_context_window)` resolves the trigger and `Threshold.exceeded?/2` compares it with `state.total_tokens` (the LAST turn's provider-reported `input + output + reasoning`).
   The window is ALWAYS the configured one; the model catalog supplies only the output reservation.
   Below the trigger nothing is logged and no LLM slot is acquired.
2. **Stage 1 — `ToolResultPruner.prune/1`** rewrites the text of `:tool` results OLDER than the recency boundary (head + marker + tail) and collapses their media parts into one placeholder; `Threshold.project/3` scales the reported token count by the pruning ratio.
   It is adopted ONLY when `pruned > 0` AND the projection is at or under the Stage-1 target (`Threshold.pruning_target/2` = `min(threshold, round(window * fraction))`, fraction default 0.5) AND the projection is below the reported count.
   An adopted prune IS the whole compression: the PRUNED messages are kept and no LLM call happens.
   Any other outcome logs the rejection (projected vs target) and DISCARDS the pruned list — pruning rewrites history and invalidates the provider prefix cache, so a small saving is a net loss.
   `[:llm, :tool_result_pruning]` (a non-boolean/nil value is treated as `true`) set to `false` skips Stage 1 entirely: `ToolResultPruner.prune/1` is not called at all.
3. **Stage 2 — `Checkpoint.split/2`** splits the ORIGINAL, un-pruned transcript (never the pruned list) into `head` (`[system, first_user]`, byte-identical), `old` (to be replaced) and `recent` (the last K turns, verbatim).
   An empty `old` skips stage 2 with a log line — an LLM call would have nothing to replace — and keeps the ORIGINAL list.
4. **Summary request** — `SummaryPrompt.instruction(Checkpoint.prior_summary(messages))` is appended as ONE `:user` message to the ORIGINAL transcript and handed to `LlmRetry.summarise/4`, which owns the slot-per-attempt discipline and the failure classification.
   Sending the original (larger) request is deliberate: pruning the request body would hide from the summariser exactly the information the summary must preserve.
5. **Rebuild** — `Checkpoint.build(messages, summary, context_window: Map.get(info, :window))` yields `head ++ [checkpoint] ++ recent`, and the plain runtime-context refresh message (`EvoGit.Agent.ContextBuilder.build_context_refresh_message/2`) is appended as the LAST message on every compression event.
   The agent's LIVE background-job snapshot rides only this SUMMARISING path: `refresh_messages/2` puts `EvoGit.BackgroundJobs.snapshot(owner_pid: self())` on the state map handed to the builder only when `include_background_jobs?` is true, so the `<context>` block gains a `## Background Jobs` sub-section (`EvoGit.Agent.BackgroundJobNotice.section/1`) carrying the CURRENT snapshot; every earlier refresh message is dropped first (`ContextCompression.drop_stale_refreshes/1`, which rejects every message matching `ContextBuilder.refresh_message?/1`), so exactly ONE refresh — and therefore exactly ONE `## Background Jobs` section — survives a compression, even when an older snapshot sits inside the protected recent tail.
   The stage-1 prune-only adopted path appends the same plain refresh with NO jobs section and performs the same refresh cleanup.

Every compression event — adopted prune, nothing-to-replace, blank summary, real checkpoint — increments the agent's compression count and resets `state.total_tokens` to 0, so the stale count cannot retrigger compression before the next LLM call reports a fresh one.
Usage is charged wherever the request was billed: the adopted-prune path leaves `state.usage` untouched, the blank-summary path adds the spent usage while keeping the ORIGINAL context (a blank summary must never fabricate a checkpoint that drops the transcript).

## Constraints

- **`[system, first_user]` stays BYTE-IDENTICAL** and the last K turns stay VERBATIM (metadata, turn tags, `tool_call_id`/`tool_calls` pairing intact) — the provider's cached prefix survives every compression.
- **Recency is ONE rule shared by both stages** (`Recency.boundary/2`): the last `keep` distinct turns (turn tags from `metadata[:turn]`, stamped by `ContextBuilder.tag_message_turn/2`) combined with a positional floor of the last `2 * keep` messages, always taking the SMALLER (earlier) index — it protects MORE, never less, and the protected region is one contiguous suffix so neither stage can punch a hole in the middle of the conversation.
- **Pruner candidates are only `:tool` messages strictly below the boundary.** The system prompt, the first user message, every `:user`/`:assistant` message and everything in the recent window are untouched.
- **The pruner never shortens or reorders the message list** and never touches `tool_call_id`/`tool_calls`, so assistant `tool_calls` ↔ tool-result pairing cannot break.
- **Pruning never grows a message:** `chars_after <= chars_before` holds unconditionally (a pathological `:head_chars`/`:tail_chars` override leaves the part alone). A no-op call returns the same list with `pruned: 0`.
- **No raw media payload survives in the old region:** media parts (`:image`, `:image_url`, `:video_url`, `:file`) collapse into ONE text placeholder per message, emitted where the first media part was; `:thinking`/`:provider_block` parts are preserved verbatim.
- `prune/2` opts: `:keep_recent_turns`, `:threshold_chars` (8192), `:head_chars` (4096), `:tail_chars` (1024). Unusable overrides fall back to the defaults instead of raising — this runs on every turn.
- **`Threshold` derives from the CONFIGURED window, never from a fixed number:** `reserved = clamp(output || 8192, 1024, 32768)`, `raw = min(0.8·W, W - reserved - 65_536)`, `floor = min(32_000, 0.9·W)`, `threshold = raw |> max(floor) |> min(0.9·W)` — so `W = 1_000_000 → 800_000`, `200_000 → 126_272`, `131_072 → 57_344`, `64_000 → 32_000` (the floor wins), `32_768 → 29_491`.
- **`[:llm, :compression_threshold_tokens]` is an optional OVERRIDE, not a fallback:** a positive integer wins verbatim (`source: :config`); the schema default is `nil`, which derives from the window (`source: :window`).
- **`Threshold`'s window comes from `opts[:context_window]`** (positive integer, else `EvoGit.Config.Schema.LLM.default_context_window/0` = 200_000) — configured per model profile via `context_window` and threaded from `AgentState.llm_context_window`; the model catalog is read ONLY for `limits.output` (tolerant atom/string keys, itself raise-free), never `limits.context`.
- **`pruning_target/2` = `min(threshold, round(window * fraction))`** — the fraction defaults to `default_pruning_target_fraction/0` (0.5) and anything outside the open interval `(0, 1)` (non-numbers included) normalizes to it; a nil/unusable window yields the threshold, an unusable `info` yields 0; never raises.
- **Stage 1 adoption needs ALL THREE** (`pruned > 0`, projection `<=` target, projection `<` reported count) — otherwise the pruned list is discarded and Stage 2 runs over the ORIGINAL list.
- **Stage 2 always reads the ORIGINAL transcript** (`split`, `prior_summary`, the request body and `build` all use the un-pruned list); the ORIGINAL list is also kept on the nothing-old and blank-summary paths.
- `exceeded?/2` is strictly greater-than and total (an unusable info map never fires); `project/3` keeps TOKENS as the unit, is clamped to never exceed the input, and returns the input unchanged when `chars_before == 0` or nothing shrank.
- **The checkpoint is ONE `:user` message** (never `:system`/`:assistant`) carrying the pinned "automatically generated checkpoint … do NOT acknowledge this checkpoint" preamble plus the summary inside `<compacted-summary>`; the retained suffix never starts with an orphaned `:tool` message (the split index rewinds to the assistant message that produced it, never below the head).
- **The summary uses the eight fixed sections in order** (`## Primary Request and Intent`, `## Key Technical Concepts`, `## Files and Code`, `## Errors and Fixes`, `## Pending Jobs`, `## Current Work`, `## Next Step`, `## Critical Context`), preserves exact paths/commands/error strings verbatim, must not mention the summarisation request, and must not reproduce the objective (the first user message is retained).
- **The summary never duplicates background-job state**: `## Pending Jobs` is generic "work started but not finished, one line each" and the prompt states that background shell jobs are tracked automatically by the runtime and re-injected there, so no job ids, statuses or output belong under it; the eight fixed headers are unchanged.
- **Repeated compactions accumulate:** `SummaryPrompt.instruction/1` merges the previous checkpoint's summary (under `<prior-checkpoint-summary>`, deliberately NOT the checkpoint tags) and `Checkpoint.prior_summary/1` reads it back from the last checkpoint message.
- **`build/3` returns `replaced: 0` with the input list unchanged** when there is nothing old to replace or the summary is blank/non-binary — the caller's signal that nothing was compacted.
- **`LlmRetry.summarise/4` acquires and releases the LLM slot PER ATTEMPT** (`AgentScheduler.with_llm_slot/2` wraps exactly one `stream_text` + `process_stream`), so a backoff sleep happens with the slot FREE and a retrying agent still blocks on slot re-acquisition while the scheduler is paused.
- **`LlmRetry` classification mirrors `ToolDispatch.call_llm_with_retry/5`:** a non-retryable provider rejection (`EvoGit.Agent.LlmError.non_retryable?/1`) returns `{:error, {:llm_request_rejected, message}}` immediately (ONE request, no sleep, no scheduler backoff, message built with the caller's own `gen_opts`/`llm_model` so no scheduler lookup can raise); model exhaustion (`TruncationFeedback.classify_model_exhaustion/1`) reports `AgentScheduler.report_llm_error(..., LlmRetryPolicy.model_exhaustion_delay(15))` once and raises (the long wait belongs to the scheduler backoff + crash-retry, and this loop must stay cancel-safe); an ordinary transient error with attempts left sleeps a short exponential backoff (`:llm_retry_backoff_base_ms`, `Retry.DelayStreams` exponential/randomize/cap 60 s) and retries; attempts exhausted raises.
- **Raising is deliberate — there is no "fall back to the pruned context" degradation.** The retained last-K-turns tail may itself exceed the window, so a silent fallback would only defer the overflow to the very next LLM request (a hard provider error) with no operator-visible signal. Raises are `raise MatchError, term: {:error, reason}`, preserving the pre-existing crash-retry / scheduler-backoff semantics.
- **Runtime-context freshness is APPENDED, never a rewrite of message #1** (`ContextBuilder.build_context_refresh_message/2`, appended as the LAST message whenever a non-blank `<context>` block renders): a CONTEXT.md edit made in the worktree mid-run is visible again while the cacheable prefix stays byte-identical.
- **Only the summarising refresh re-injects live background jobs**: `refresh_messages/2` puts `EvoGit.BackgroundJobs.snapshot(owner_pid: self())` on the state map handed to the builder only when `include_background_jobs?` is true, so the `<context>` block gains a `## Background Jobs` section (`EvoGit.Agent.BackgroundJobNotice.section/1`) listing job id, status/detail and command/label; every earlier refresh message carrying that section is dropped first (`drop_stale_background_job_refreshes/1` — detection is `ContextBuilder.refresh_message?/1` AND the `"## Background Jobs"` marker, total over malformed shapes), so exactly ONE section (the current snapshot) survives; the stage-1 prune-only adopted path appends the plain refresh with NO job snapshot and performs no background-job cleanup. `snapshot/1` is non-reconciling and answers `[]` when the registry is down, so no registry failure can fail a compression and no broad rescue exists.

## Notes for Agents

- **Recency math must never be re-implemented** in a caller — call `Recency.boundary/2`.
- The sub-modules are TOTAL about unexpected MESSAGE shapes (binary legacy `content`, atom- or string-keyed maps/parts, non-integer opts falling back to defaults) because they run in the per-turn path; passing a non-list message list is out of contract and raises a `FunctionClauseError`.
- The stage-2 attempt budget is the call-time app-env seam `:compression_llm_max_attempts` (default 3) — an operational knob, not a `config.toml` key.
- Gating config keys belong to the config layer, not this directory: `[:llm, :compression_threshold_tokens]` (nil = derive), `[:llm, :tool_result_pruning]` (default `true`) and `[:llm, :tool_result_pruning_target_fraction]` (default `0.5`); the window itself is the model profile's `context_window`.
- The orchestrator's log lines state the decision: threshold + `source` + window, then `stage 1 adopted` / `stage 1 rejected` with projected vs target tokens, or `stage 1 (tool-result pruning) disabled by config`.
- `EvoGit.Agent.ContextBuilder.refresh_first_user_message/2` still exists and is tested, but compression does not use it: rewriting message #1 would break the provider's cached prefix.

## Test Strategy

- Pure-module tests live in `apps/evo_git/test/evo_git/agent/compression/` (`threshold`, `tool_result_pruner`, `checkpoint`, `summary_prompt`); `Recency`'s boundary rule is exercised through the pruner and checkpoint suites and `LlmRetry` through the orchestrator suites below, so neither has a file of its own. `threshold_test.exs` must be `async: false` because it swaps the global `:llm_model_metadata_fun` seam — which now only drives the output reservation.
- `Threshold` needs coverage for `pruning_target/2` (fraction normalization, nil window, unusable info) and for the explicit-override vs derived-window split; orchestrator tests need the Stage-1 adopt/reject gate and the Stage-2-over-original guarantee.
- Orchestration is covered by `test/evo_git/agent/context_compression_test.exs` (gate + usage accumulation, in-memory), `context_compression_stages_test.exs` (a raw-TCP SSE stub driving real `ReqLLM.Response` values; a live background job started in an isolated `EvoGit.BackgroundJobs` registry whose id must appear in the STAGE-2 post-compression refresh message, plus the stage-1 negative assertion that its adopted-prune refresh carries no `## Background Jobs` section, and a second-compression assertion that exactly ONE current section survives) and `context_compression_fail_fast_test.exs` (non-retryable rejection, transient retry, model exhaustion, against `EvoGit.TestLlmServer`).
