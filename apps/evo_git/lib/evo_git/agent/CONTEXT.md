# EvoGit Agent Behaviour & Tools

## Intent
`EvoGit.Agent` is the behaviour every agent module `use`s; the runtime loop is `EvoGit.Agent.Exchange` over `%EvoGit.Agent.State{}`, driven by the per-agent `EvoGit.Agent.Session`, and `EvoGit.Agent.Runner` is only a helper module.
A run finishes ONLY by replying with NO tool calls — that reply text IS the report — and `EvoGit.Agent.Completion.Builder.finalize/2` writes the completion side effects once, at the session's terminal outcome; there is NO completion tool.
This node owns the exchange engine + tool-dispatch orchestration, the LLM tool library, `State`/`Result`, compression orchestration, subagent spawning/merging, token/cost accounting and the PUSH-ONLY delta stream.
Agent TYPE implementations live in `../agents/`; per-tool contracts `tools/CONTEXT.md`; compression stages `compression/CONTEXT.md`; streaming `stream/CONTEXT.md`; session mechanics `session/CONTEXT.md`.

### Helper Modules
- **`ContextCompression`** — `compress_if_needed/2` is `%State{}` → `%State{}` at every turn top, window-relative over the CONFIGURED `context_window` (default 200_000, NEVER catalog metadata) with the `[:llm, :compression_threshold_tokens]` override; stage 1 prunes old tool text/media model-free and is adopted only at/under `Threshold.pruning_target/2`; stage 2 keeps `[system, first_user]` BYTE-IDENTICAL plus a bounded verbatim tail and ONE UNTAGGED checkpoint `:user` message — `compression/CONTEXT.md`.
- **`Completion.Builder`** — `finalize/2` is the ONE completion entry point; fixed order: `Dispatch.commit_pending_in_worktree/0` (the worktree commit; no-op for a clean workspace and repo-less agents, never raises) → POST-commit HEAD (`sync_and_get_current_commit/1`, RAISES a descriptive `rev_parse` error when the worktree vanished) → live HEAD (`Runner.refresh_commit_sha/1`) → `Completion.complete/4` ONCE (git note + archive refs + `%Result{}`); answers `{:ok, %Result{}}` or `{:error, {:agent_state_not_found | :sched_meta_not_found, agent_id}}`, never a plain git error.
- **`CompletionProtocol`** — `classify/1` → `{:tool_calls, calls} | {:text_reply, text} | :empty` (usable text = IMPLICIT COMPLETION); `report_text/1` (thinking never becomes the report); `:empty` → ONE nudge then `{:error, :protocol_violation}`.
- **`ToolInvocation`** — `arguments/1` (a decoded object passes; a non-blank UNPARSEABLE string passes RAW; else `{:error, reason}`), `invalid_arguments_result/1` → `"Error: invalid arguments: <reason>"`, missing arg → `"Missing required argument '<key>'"`; `resolve_timeout/4` = an explicit POSITIVE duration in ANY shape capped by `max_tool_timeout`, else `default_timeout/2`; `resolve_timeout/4` reads non-positive/unparseable as ABSENT.
- **`ToolNames`** — `normalize/1`: `read`/`write`/`edit` → `*_file`, shell aliases (case-insensitive) → the platform name, `grep`/`ripgrep` → `rg`, `websearch` → `search_web`, `task`/`subagent` → `subagent_manager`; unknown names pass through.
- **`SubagentProcessing`** — spawns subagents, resolves cross-repo paths, merges same-repo results, deletes only merged/auto-resolved branches; an unresolvable `base_sha`/non-git root yields `{:error, {call, index, msg}}`; gate rejections surface verbatim as `"Error: #{msg}"`.
- **`TurnWarning`** — level/interval math for `:beginning | :middle | :end | :critical` (`:low` delegation skips `:beginning`); merge-conflict suppression never advances `last_warned_level` while `:end`/`:critical` ALWAYS fire; the flag comes from `ConflictState.in_conflict?/0`, never a git call.
- **`LlmError`** — `non_retryable?/1` unwraps tuples, `%ReqLLM.Error.API.Stream{}`/`Request{}` and `:cause` (depth ≤ 5): `retryable == true` or 408/409/425/429/500..599 → retryable; other 400..499 or `retryable == false` → non-retryable; no signal → retryable. `format_failure/1` = status + provider code + provider name + human message; `/2` adds the parameter NAMES sent plus the "remove unsupported parameters" line naming `<spec>` (never values).
- **`Cost` / `Usage`** — `Cost.recompute/3` prices raw counts via `LLMDB.Pricing.components_for(model, %{pricing_period: period})` (`kind: "token"` components only), `total_cost` = `input_cost + output_cost` at 6 decimals; `apply_to_usage/3` overrides only those three fields and only on a non-nil recompute. `Usage.cache_hit_rate/1` = `cached_tokens / input_tokens * 100`; a lost usage payload drops the WHOLE turn's usage, and DeepSeek's `prompt_cache_hit_tokens` is never read.
### Tool Library (`EvoGit.Agent.Tools`)
- `schemas/0` = the standard coding set (incl. read-only `WebFetch`, plus `WebSearch` when `[:tools] search_enabled`), with `Lsp` appended LAST only when `EvoGit.Config.lsp_enabled?/0`; `read_only_schemas/0` = read set + `Context.read/write/edit` + `ShellTool` + `WebFetch` (+ the same gates).
- `job_output`/`job_list`/`job_kill` sit in BOTH schema lists and NEITHER write list; `default_timeout_ms/1` = `[:scheduler, :max_tool_timeout]` for `job_output` (derived at call time), 120_000 (shell), 30_000 (`elixir_eval`), `nil` otherwise; `timeout_arg_is_wait_budget?/1` is `true` only for `job_output`, so its advertised default is a FLOOR even against an explicit `timeout`.
- `@write_tools` (17) = `create_files write write_file edit edit_file bash make_dir write_context edit_context run_bash run_powershell run_git skill_add skill_edit skill_remove skill_enable skill_disable`, always normalized first; a custom tool is a write unless `read_only?/0` says otherwise.
- `elixir_eval` is dispatch-only, absent from BOTH shared schema sets, exposed only by the reflective assistant's own schema list, and EVERY tier is serial; `Tools.execute/5` reserves it before the pd-based write guards and `ElixirEval.Authorization` validates the live root reflective owner against scheduler ETS, ancestry and task lifecycle independently of tool-task role flags.
- Legacy `run_command` is unconditionally refused by `Tools.execute/5`; direct `RunCommand`/`CommandShell` APIs stay live outside agent dispatch. Write/sudo outer timeouts are floored to `CommandApproval.timeout() + 30_000`, then capped by `max_tool_timeout`; numeric `timeout_ms` is only the inner engine cap (5 s), and read/default/invalid tiers get no approval floor.
### Delegation Hinting
Two fire-once per-child-dir hints (`DelegationHints`; counters in `State.delegation_hints` + the pd; `filter_child_paths_if_conflicts/2` suppresses them in a merge conflict): write volume > `[:scheduler, :delegation_hint_threshold]` (5) and `:high`-agent read volume > `[:scheduler, :read_delegation_hint_threshold]` (8); the conflict list comes from the per-turn `ConflictState.files/0` snapshot.

### Subagent Objective & File Handoff (no automatic path plumbing)
A parent hands work to a child ONLY via the spawn call's `objective` STRING plus the child's checkout; `build_subagent_specs/3` forwards `args["objective"]` VERBATIM to `AgentSpec.new/5`.
The `path` arg is a DIRECTORY node — RELATIVE for same-repo targets, ABSOLUTE only for foreign repos; a file path is redirected to its parent dir; an unknown absolute path is rejected with a self-correcting hint.
A child's dir is its fresh worktree at `spec.phylo_node.current_commit` (= cwd), so objectives must not carry worktree paths or `cd`, and parent changes are visible only if COMMITTED before the spawn; inherited opts: `repo_id`, `foreign_repos`, `repo_notes`, `archive`, `model_id`, `task_tmpdir`.

## Exchange Engine, State & Test Seams
`Exchange.run/2` is the public entry: ONE exchange = N turns; a `{:yield}` is terminal for ONE exchange, never for the agent (only `:interactive` produces one — `ToolDispatch.process_llm_response/7` commits the pending work and returns it instead of finalizing), so a `:oneshot` run is exactly ONE exchange; `:finish` and `:yield` are checkpointed identically, once, before the outcome is returned.
`%State{}` carries no funs and no pids, so the whole struct is snapshot-able and JSON-clean; the turn loop's continuations are closures created by `run/2` and handed to `Turn.run/3`, never stored. Seams resolve through `Exchange.Seams.from_opts/1` — explicit `opts` key, else the call-time app env, else `nil` = production path.
| Option key | App env | Arity | Return shape | Production default (absent key) |
|---|---|---|---|---|
| `:llm_call` | `:agent_exchange_llm_call` | 5 — `(context, tools, llm_generation_params, agent_id, max_retries)` | `{:ok, response} \| {:implicit_completion, response, text} \| {:error, reason}` | `LLMPrompting.prompt_until_tools_or_limit/5`; else the real `call_llm_with_retry/5` path |
| `:tool_batch` | `:agent_exchange_tool_batch` | 2 — `(indexed_calls, state)` | `[{index, tool_call_id, name, output}]` | none — replaces the real batch, hint tracking AND commit sync |
| `:scheduler` | `:agent_exchange_scheduler` | 3 — `(kind, payload, state)` | `term()` (CONTROL-PLANE only: `:drain_inputs`, `:cancel_requested?`, `:clear_cancel`) | `AgentScheduler.Store` drains/flags |
| `:checkpoint` | `:agent_exchange_checkpoint` | 1 — `(state)` | any `term()` — DISCARDED (observable-only) | the session worker sends `{:checkpoint, %State{}}` to the session, which merges summary fields via `Session.Summary.publish/3` |
The `:checkpoint` seam is the turn BOUNDARY hook: exactly ONCE PER TURN after that turn's state update — handed to the recursive loop step for a CONTINUING turn (inside `continuations/2`, so turn-0 never counts) and once with the finishing turn's state in `run/2`; `{:error, reason}` checkpoints nothing, the return value is discarded, and an explicit `nil`/`false` means no state work. The engine reads from the STRUCT, never ETS: `objective`, `llm_model`, `llm_generation_params`, `llm_context_window`, `max_turns`, `max_depth`, `max_retries`, `repo_less`, `repo_path` and `current_commit` (post-tool via the per-process `:evogit_current_commit`).

## Provider-Profile Model Selection
`model_spec` is the complete string-keyed selection (`provider_profile_id`, `model`, optional `reasoning_effort`); the provider profile identifies account/slot ownership, not a catalog entry. Scheduler admission owns `Schema.resolve_model_spec/2` and populates the effective `llm_model`, `llm_generation_params`, configured `llm_context_window` and complete `model_spec`, consumed per turn without re-resolution.
`SubagentProcessing` forwards a locked parent's resolution as explicit `model_spec` and an unlocked one's as `default_model_spec` (never `model_spec: nil`); inherited precedence is live `parent_state.model_spec` → `parent_spec.model_spec` → `opts[:model_spec]` → `opts[:default_model_spec]`, pinned by inspecting `child.opts[:default_model_spec]` plus the ABSENCE of an explicit `:model_spec` key.
`Cost.recompute_for_agent/2` prices effective `llm_model` with the period from `model_spec["provider_profile_id"]` (legacy `model_id` when absent), and an unknown canonical account never borrows a stale legacy schedule; completion retains the selection in `llm_settings.model_spec`.

## Subagent Merge Conflict Resolution (`EvoGit.Agent.ContextMerge`)
A parent merges every SAME-REPO child commit into its worktree; `CONTEXT.md` conflicts are ownership-resolved by `ownership_strength/2` over a repo-relative `.../CONTEXT.md` (`3` = the node path IS the file's directory, `2` = a strict segment-wise ancestor, `./` = everybody's, `1` = unrelated).
- `decide/3`: out of the child's scope (1) → keep OURS + record the dropped edit with its truncated `git diff <base> <child_sha> -- <file>`; child strictly deeper → THEIRS; shallower → OURS; EQUAL ownership ≥ 2 → unresolved.
- `merge_children/2,3`: ONE attempt (`git merge` / `git merge_octopus`) — clean → `:clean` (`:no_changes` when HEAD did not move); on conflict it aborts and children merge one at a time in SPAWN order against the CURRENT "ours" (option `:parent_node_path`, default `"./"`, plus already-merged children that touched the file). Non-`CONTEXT.md` and equal-ownership conflicts are never auto-picked: that child aborts, the pass ends at `:conflict`, the rest are `:not_attempted`, and every failure path aborts cleanly at a reported HEAD.
- `Report` (`:clean | :no_changes | :conflict | :error` + `starting_sha`, `head_sha`, `merge_output`, `entries` with `:merged | :auto_resolved | :conflict | :not_attempted` status, `auto_resolutions`, `dropped_edits`, `genuine_conflicts`, `error`); `format_note/2` is `nil` for `:no_changes`, else verdicts + dropped diffs + `git merge <sha>` next steps. `collect_mergeable_results/3` takes same-`repo_id` children in spawn order; `delete_merged_branches/2` deletes ONLY `:merged`/`:auto_resolved`.

## Spawn Fan-Out & Process Topology
`ToolDispatch.batch_execute_tools/5` only resolves the agent-side context into ONE `EvoGit.ToolRuntime.Request`; partition, `Task.async_stream` parameters, `$callers` topology, slot acquisition, tool-task pd re-installation and the durable-owner rule live in `../tool_runtime/CONTEXT.md`. `Tools.serial_tool?/1` is the single classification source, the evaluator never trusts tool-task role pd, and the pd key/owner table is in `./session/CONTEXT.md`.
One batch of subagent calls is ONE blocking `AgentScheduler.spawn_sub_agents/2` (`timeout: :infinity`) dispatched together via `Subagents.spawn_validated_subagents/5`; **no spawn-COUNT cap in code** (width is prompt-driven) — only DEPTH (`[:scheduler] max_agent_depth` default 8), spatial-contract validation and the one-at-a-time writable-foreign-repo gate. **The parent BLOCKS**, status `:waiting`, holding NO LLM or tool slot.

## Grace Period & Graceful Cancellation (exchange-side)
Both kinds enter via `Exchange.Grace.enter_grace/2,3`: `maybe_recovery_auto_commit/1` FIRST (best-effort "auto-commit: turn-limit recovery" — for cancel this is "save the changes"), then `in_grace_period: true` + the budget, then the private turn loop.
- **Both grace kinds use a 3-turn budget**: turn-limit recovery (`trigger_turn_limit_recovery?/1`) and cancel-grace (`maybe_enter_cancel_grace/1`, in the turn loop right AFTER `drain_and_inject_user_messages/1`: the ETS `cancel_requested` flag is cleared, `message: nil` — the cancel message already arrived via the drain). Three turns cover "one bounded final commit + a plain-text report"; a third continued turn hard-stops.
- **Recovery message contract** (`recovery_warning_message/2`, reading `state.objective`): states the exceeded budget and the number of final turns, the ONE completion rule (a reply with NO tool calls ends the run and its text IS the report), and the terminal consequence (window used up without such a reply → the run stops with NO report); it permits at most ONE final commit in the first of those turns, only when work is genuinely uncommitted, and instructs the agent to STOP and report what was done / what remains / what a follow-up must pick up.
- **Budget semantics**: a CONTINUING turn (a plain-text reply consumes nothing) decrements `grace_turns_remaining`; at `<= 1` → `{:error, :recovery_failed}`.

## Lifecycle & Run Lifecycle
`Session.Setup.bind_worktree/2` runs FIRST, inside the session's ONE start task (so a slow/queued create never blocks the session process): for non-repo-less agents it BLOCKS on `WorktreeManager.create_worktree_for_agent/6` (raising on error) before `build_initial_state/3` and the worker, so EVERY agent (incl. subagents) allocates its worktree before queueing for an LLM slot; creation is admission-bounded by the `max_concurrent_worktree_creation` FIFO queue.
`ToolDispatch.current_model/0` and `current_generation_params/0` resolve the caller via `current_agent_id()` + `Store.get_agent_state/1` and RAISE a DESCRIPTIVE `ArgumentError` naming caller + agent id when there is no agent id or no summary row (`fetch_current_agent_state!/1`) — do NOT add nil fallbacks (pinned by `tool_dispatch_retry_slot_test.exs`).
Every agent run STARTS with ONE fresh exchange (`Session.Setup.build_initial_state/3` always builds `[system, user]` via `ContextBuilder.build_initial_messages/4`, context tree rebuilt from disk; no entry point accepts an existing `%ReqLLM.Context{}`), and a resumed/cancelled TASK is a brand-new task row plus session, with `TaskRegistry.ResumeContext` seeding OPTS only.
`Exchange.run/2`'s turn loop never `receive`s and never blocks for external input: its only inbound channels are the LLM response and the per-turn drains; `drain_and_inject_user_messages/1` is ETS-only and non-blocking (`AgentScheduler.Store.drain_pending_user_messages/1` over `ControlPlane`'s inbox) and REQUIRES a LIVE agent (`{:error, :not_found}` once the row was recycled) — the ONLY mid-run follow-up channel.
Termination is exhaustive: implicit completion → `{:finish, state, %Result{}}` (side effects written INSIDE `process_llm_response/7` via `finalize/2`, before the stack unwinds) or → `{:yield, state, text}` for `:interactive`; grace exhaustion → `{:error, :recovery_failed}`; non-retryable rejection → `{:error, {:llm_request_rejected, message}}`; every other exhausted-retry path RAISES and is crash-retried by the scheduler.

## Interactive Sessions — contracts here, mechanics in `session/CONTEXT.md`
An `:interactive` session runs N exchanges on ONE `EvoGit.Agent.Session` pid, while a `:oneshot` agent (the macro default, and every production agent today) runs exactly one exchange and stops; mode resolution, `:awaiting_input` parking, `start_input/3` policy (`:queue`/`:interrupt`), append-only resume and `on_yield/1` are the session's.
Budgets: ONE exchange via `EvoGit.Agent.exchange_turn_budget/1` (`state.max_exchange_turns`, else `state.max_turns`) counted from `state.exchange_turn_base`; the WHOLE session via `session_turn_budget/1` (`state.max_session_turns`, else the call-time seam `:interactive_session_turns`, default `exchange_turn_budget * 10`, non-positive/non-integer values IGNORED); production dispatch leaves both override fields unset. `trigger_turn_limit_recovery?/1` applies the burst-or-session condition for `:interactive` and plain `turn >= max_turns` for `:oneshot`, and BOTH exhaustions enter the SAME 3-turn grace window.
Resume keeps conversation, worktree and identity VERBATIM and rebases `exchange_turn_base` (context tree never rebuilt, `prompt_cache_key` unchanged, so the prefix cache survives); completion is written exactly ONCE per session, a `:yield` writes nothing, and the worktree is reclaimed once when the session stops.

## Durable Per-Agent State (`:persistent_state`) — crash-recoverable runs
`%State{}.persistent_state` is the per-agent durable-state flag: the task opt `:persistent_state` (default `true`) resolved at spawn and inherited by subagents exactly like `:archive`, while the STRUCT default is `false` so hand-built/unit-test states never write.
Every turn boundary delegates to `Session.Persistence` from `Session.publish_checkpoint/2`: ONE `EvoGit.AgentState.checkpoint/4` cast — `append` of the new tail when the old list is a prefix AND `compression_count` is unchanged AND a baseline exists, `rewrite` of the full list otherwise, and an unchanged transcript still casts a SCALAR-ONLY `append` (no chunk row, while `turn`/`usage`/`total_tokens`/`current_commit` advance). The baseline lives in the SESSION process dictionary and encoding happens in the agent-state server's writer.
The entry carries `owner: self()` plus a SMALL fixed fields map (identity, objective, model selection, `turn`, `usage` PLAIN map, `total_tokens`, `compression_count`, `current_commit`, `pending_inputs`, `phase`), never the whole struct; a store-reported continuity gap (`{:agent_state_resync, task_id, agent_id}`) is always answered with a full `:rewrite`.
On a crash retry or pause resume of the SAME agent_id (`restore_agent_state`) `Setup.build_initial_state/3` restores ONLY conversation state (transcript, `turn`, `usage`, `total_tokens`, `compression_count`, `prompt_cache_key`, `objective`, `pending_inputs`, `pending_tool_batch`, `current_commit`) and keeps the fresh identity, worktree, repo paths, model selection and phase; a missing/corrupt/unavailable row leaves the fresh state untouched with ONE warning, and the restored transcript is AUTHORITATIVE. `Persistence.complete/1` marks completion only on the one-shot terminal delivery — never `:awaiting_input`, never force cancel.
- **The PRE-BATCH checkpoint makes an in-flight batch durable**: `advance_turn_context/2` puts the assistant `tool_calls` message into `state.context` BEFORE the batch, then `ToolDispatch.begin_tool_batch/4` writes the `%ToolBatch{}` marker onto `state.pending_tool_batch` and fires the SAME `:checkpoint` seam IMMEDIATELY before the first tool executes, at the ALREADY-INCREMENTED `state.turn` (marker backed by its own `agent_states.pending_tool_batch` column).
- **Marker invariant**: `pending_tool_batch != nil` ⟺ a batch is executing RIGHT NOW; every path that stops executing one clears it (`continue_after_tools/7` once results are appended, the protocol-violation path, `Exchange.terminal_state/1`), and `persistent_state: false` writes no marker and fires no pre-batch checkpoint.
- A crash mid-batch resumes with the `tool_calls` message AND the marker; `Resume` treats the marker as PROVENANCE and the transcript as the truth (a dangling tail of unanswered calls), repairs it and appends exactly ONE `[RESUME]` notice — `resume/CONTEXT.md`. A marker or dangling tail on a `:clean_pause` resume proves an interruption, so that resume is repaired and narrated as one too; only an INTACT clean pause gets the neutral notice naming its pause checkpoint commit (or the task-base fallback).
- **Tool RESULTS stay TURN-BOUNDARY granular**: `continue_after_tools/7` checkpoints that same turn after appending every result, and the batch-completion entry is adopted ONLY by the batch-completion arm of `Session.adoptable?/2`, so no checkpoint ever lands in the MIDDLE of a batch.

## Update-Timing Safety (in-flight state vs BEAM restart)
Cross-cutting restart/idle semantics live in `../CONTEXT.md` and `../task_registry/CONTEXT.md`; this node owns only what an exit does to an IN-FLIGHT agent.
- **No turn-level wall-clock timeout**: hard stops are `max_turns` (128, incl. subagents), `max_turns_root` (1000, root only) and the 3-turn grace window (TURNS, not wall-clock); bounds are LLM stream receive 30 s (300 s thinking), `stream_pool_timeout` 300 s, inner retries + 15 outer attempts, per-tool `min(requested, max_tool_timeout)` and unbounded subagent waits.
- **Per-turn publication, in-memory only**: `context.messages` lives in the session-owned `%State{}`; the ONE publication path is the `:checkpoint` seam — `Session.Worker` → `Session.Summary.publish/3`, which merges only the SUMMARY fields (`turn`, `message_count`, `usage`, `total_tokens`, `compression_count`, `last_activity_at`) onto `:evogit_agent_summary` and never writes `context`. ETS dies with the VM, so the summary row is NOT a conversation store; the durable copy is the opt-in `EvoGit.AgentState` checkpoint.
- **`Session.Worker.run/3`'s `after` block** runs `Dispatch.commit_pending_in_worktree/0` ("Agent: auto-commit fallback") on ANY agent-process exit (normal, error, crash) BEFORE handing the value back — NOT on `:brutal_kill` or VM shutdown. `Result.commit_sha` was captured BEFORE the fallback, so `run/3` re-reads HEAD via `Runner.refresh_commit_sha/1` (never raises); `merge_and_report/3,4` treats a match or nil as `no_changes: true`, `branch_name: nil`, NO `genesis/agent_*` branch.
- **Terminal exit semantics**: `Session.Worker.run/3` returns `:ok` after sending `{:exchange_finished, self(), outcome}`, so a `:oneshot` session reaches `:normal`; only a RAISE in the engine or `Session.cancel(pid, :force)` is ABNORMAL, a worker dying without an outcome stops the session with its own exit reason, and a `bind_worktree/2` raise stops the SESSION and skips the fallback.

## LLM Request Assembly (what actually reaches ReqLLM)
ONE call site per turn: `LLMPrompting.run_llm_attempt/4` calls `ReqLLM.stream_text(current_model(), context, request_params)` inside `with_llm_slot/2`, wiring `ReqLLM.StreamResponse.process_stream/2` callbacks from `Stream.Sink.stream_opts/0`; `current_model/0` returns `AgentState.llm_model` (a `"provider:model"` string, or a `%{provider: atom, id: model, base_url: url, extra: map}` for a custom-endpoint account) and `context` is the whole `%ReqLLM.Context{}` by value.
`request_parameters/2` is literally `Keyword.merge([tools: tools], llm_gen_opts)` — no validation, filtering or extra keys at call time; `llm_gen_opts` is `state.llm_generation_params`, read from the struct once per turn. Compression's stage-2 call reuses the same model and keyword list and passes NO tools.
`llm_generation_params` is produced ONCE at admission by `Config.Schema.LLM.profile_generation_params/1`: at most `:temperature :max_tokens :reasoning_effort :top_p :top_k :frequency_penalty :presence_penalty :provider_options :api_key` (nils omitted, constraint-filtered, `api_key` appended last and resolved once — a credential is frozen per agent, while an OAuth `oauth_file` rides as a PATH re-read per request). ReqLLM adds `max_tokens` from the catalog output limit when omitted, plus `stream: true`; unknown keys are NOT silently dropped (`NimbleOptions.validate!`), provider-schema keys auto-hoist into `:provider_options`, and `@internal_keys` (`:api_key :auth_mode :oauth_file :base_url :req_http_options …`) bypass validation.
Request identity is FROZEN at registration: `prompt_cache_key`/`session_id` ride INSIDE the account's `provider_options` via `Config.Schema.LLM.with_cache_identity/3` (provider-gated — `:openai` key only, `:openai_codex` key + session — explicit account value wins), so every turn/retry/compression call shares one routing key; the only other Genesis-added option is `provider_options: [store: false]` for a NATIVE OpenAI endpoint. No `cache_control`, `user`, seed, option-level `metadata`, `include` or `telemetry` exists.
Tools ride the SAME keyword list (`tools:`), rebuilt every turn by `Turn.effective_tools/1` = `available_tools()` ++ per-run `skill_schemas`, minus subagent tools at max depth — a literal ordered list, stable unless a call-time config gate (`search_enabled`, `lsp_enabled`) flips mid-run.

## LLM Request Retry Mechanism (3 layers)
**Layer 1 — EvoGit outer loop (`call_llm_with_retry/5`)**: MANUAL recursive attempt loop, first attempt index 0, no initial sleep, attempts = `max_retries + 1` (`agent_state.max_retries` / `[scheduler] max_retries`, default **15**). Each attempt runs inside `with_llm_slot/2` for ONE `stream_text` + `process_stream`, released (`after`) BEFORE any backoff (an excess-queuing error also bumps `ReqLLMPool`); the agent keeps its turn and context across attempts.
- **Classification** (`handle_llm_failure/7`): `TruncationFeedback.classify_model_exhaustion/1` on the RAW reason plus `LlmError.non_retryable?/1` on the unwrapped struct — model-exhaustion → non-retryable → attempts exhausted → ordinary transient (a wrapped 402 without a balance/quota phrase is ordinary transient).
- **Exhaustion with attempts left** re-reports a growing per-model backoff and RECURSES IMMEDIATELY (no agent-side sleep; the wait is the scheduler queue, cancel-safe). **Ordinary transient** sleeps an exponential schedule from `:llm_retry_backoff_base_ms` (default 1_000 ms), doubling, capped 60_000 ms, ±10% jitter. **Exhausted** raises `"LLM request failed after N retries"` out of `prompt_until_tools_or_limit/6` → agent crash → scheduler crash-retry (`[:scheduler, :agent_max_retries]` default 3).
- **Fail-fast on a non-retryable rejection**: a deterministic 4xx (HTTP 400, Z.AI code 1210, `retryable: false`) returns `{:error, {:llm_request_rejected, message}}` after the FIRST attempt — no sleep, no further attempt, no scheduler backoff, ONE `Logger.error` — and `prompt_until_tools_or_limit/6` + `do_turn/6` pass it through (NOT the grace path), so the task persists `:failed`. The message is `LlmError.format_failure/2` over the exact `stream_text/3` keyword list.
**Layer 2 — ReqLLM inner retries** (inside each `stream_text/3`): default **3** (a per-profile generation param); only HTTP 429 (`Retry-After` seconds→ms; missing/unparseable/zero → 1000 ms) and transport errors BEFORE any body data — never 5xx/other statuses, nothing once streaming started. The slot is held only for the call (`after`), so backoff sleeps happen with it FREE.
**Layer 3 — scheduler per-model backoff**: `report_llm_error/3` → `Slots.handle_report_llm_error/4` sets `llm_backoff_until[model_id]` for BOTH `:rate_limit` and `:insufficient_balance`, re-queues that model's waiters and schedules `:retry_llm_waiting`; a nil/unknown class is a no-op, expired backoffs clear on any grant path, scope is per `model_id` — `../agent_scheduler/CONTEXT.md`.

No attachments / non-root / repo-less → the legacy plain-binary `user(combined_prompt)` fast path (byte-identical); a ROOT agent with attachments → `user([text | media parts])`.

Only the summarising refresh injects background jobs.

## User-Authored Message Marker (`:user_authored`)
`EvoGit.Agent.MessageMarker` owns ONE display metadata key, `:user_authored => true`, so a consumer reading a transcript (`Session.history/2`, `Stream.Snapshot.messages`) can tell a real user turn from harness text that shares the `:user` role.
Exactly TWO messages carry it: the session's FIRST user turn (the wrapped `<context>`/`<objective>` message), stamped by `Session.Setup.build_initial_state/3` via `mark_first_user_authored/1` AFTER turn tagging (so `turn: 0` + `timestamp` survive), and a message actually delivered by a USER SEND at runtime (the pending-message transport drained by `drain_and_inject_user_messages/2`), stamped via `ContextBuilder.build_user_authored_message/2`.
The rule is OPT-IN — an unmarked message is the default — so no synthetic injection can acquire it: turn-limit/grace warnings, background-job notices, compression checkpoints, the runtime-context refresh, the empty-response nudge and the subagent merge-conflict note all stay unmarked; the scheduler-injected graceful-cancel save-work notice travels the same transport and `Pending` recognizes it by exact text, leaving it unmarked too.
`%ReqLLM.Message{}.metadata` is internal bookkeeping, never encoded into a provider request body, so the marker changes no prompt text and no wire shape; it merges into existing metadata (`:turn`, `:timestamp`, `:checkpoint`) and both stamping and reading are TOTAL. `ContextBuilder.build_injected_message/2` deliberately stays NEUTRAL (no marker) — it serves every synthetic injection; `build_user_authored_message/2` is that plus the marker, and the marker survives a session snapshot and `Session.history/2`.

Images/audio ride real req_llm content parts at THREE sites: the ROOT agent's first user message (`:attachments` task opt), an injected user message, and a TOOL RESULT. `EvoGit.Attachments` (`../attachments.ex`) owns content shape, the ≤4 attachments / ≤15 MiB raw caps, base64 at every data-plane boundary and `Attachments.message/1` — `../CONTEXT.md` ("Multi-Modal Content").

- Compression keeps recent tool media (last K turns VERBATIM) and collapses older tool media into `[... tool result media omitted ...]` per message; no built-in tool produces media today (`read` is text-only, `web_fetch` omits binary bodies, custom tools are string-only).
### Multimodal Tool Outputs (`EvoGit.Agent.ToolOutput`)

## Tool-Execution Crash Semantics (raises are CONTAINED in the tool task)
Each call runs in a LINKED `Task.async` inside `ToolRuntime.Executor.execute_tool_with_timeout/4` (hosted by the AGENT process in the serial phase, by a `Task.async_stream` worker in the parallel phase), and `execute_tool_task/4` wraps `Tools.execute/5` in `try/rescue/catch`: a raise → `{:tool_crashed, :error, exception, __STACKTRACE__}`, a throw/other exit → `{:tool_crashed, kind, reason, __STACKTRACE__}`; the failure is carried RAW and formatted exactly ONCE at the reporting boundary, reaching the model as `"Error: Tool execution crashed: …"` and the tracked terminal fact as `{:crashed, detail}`; only `:normal`/`:shutdown`/`:kill`/`{:shutdown, _}` re-raise. The agent therefore SURVIVES a raising tool (`nil` yield = its own timeout arm), and `Tools.execute/5` has NO try/rescue around a tool implementation.
- **Timeout is a per-call WHOLE-CALL budget** (not idle) resolved by `resolve_timeout/4`; `apply_advertised_tool_timeout/4` raises it to `Tools.default_timeout_ms/1` when no USABLE explicit `timeout` was given, except `job_output` where the advertised default is a FLOOR even against an explicit argument; write/sudo `elixir_eval` calls are floored to `CommandApproval.timeout() + 30_000` and still capped by `max_tool_timeout`. Evaluator `timeout_ms` only controls the inner engine (≤ 5 s plus bounded cleanup).
- `Task.shutdown/2` unlinks before killing (link-safe), and **timeout excludes slot queueing and final rendering**: `with_tool_slot/2` is entered before `Task.async`/`Task.yield`, and `sanitize_tool_result/3` runs after the yield.
- **Direct-eval return contract**: successful output must be a binary, `%ToolOutput{}` or nil (`ToolOutput.wrap/1`), never an arbitrary evaluated term; render with explicit inspection limits INSIDE the tool, since post-yield rendering errors sit outside `execute_tool_task/4`'s containment boundary.
- The sanitizer strips invalid UTF-8/ANSI/progress artifacts and clips output but does NO secret redaction — truncation is not a confidentiality boundary.
- **NO escalation to the app**: the per-exchange worker is `Task.Supervisor.async_nolink(EvoGit.TaskSupervisor, …)` under a `:temporary` session, so OTP never counts its exit toward restart intensity; the scheduler crash-retries (`agent_max_retries` 3) then fails it, so a tool failure is NEVER fatal.

## Tool Dispatch Flow & Turn-Loop Contract
- `effective_tools/1` = `available_tools()` `++ skill_schemas`, minus subagent tools at max depth; the macro default `available_tools/0` = `Tools.schemas() ++ SubagentSchemas.schemas(__MODULE__)` (no completion tool exists).
- **The per-agent whitelist grants SCHEMAS ONLY — there is NO runtime membership filter**: an unknown name falls to `execute_tool/5`'s catch-all → `EvoGit.CustomTools.execute/3` (a configured custom tool wins over a same-named dynamic skill) → dynamic-skill lookup → `"Error: Unknown tool '<name>'. Did you mean '<closest>'? Available tools: ..."` (`String.jaro_distance/2` ≥ 0.7). **A protocol violation is an `:empty` turn ONLY**, while zero tool calls with usable text is an IMPLICIT COMPLETION. Repo-less consequence: a non-write tool outside both `@write_tools` and the agent's list WOULD run (`skill_*` readers; `WebSearch.execute/3` has NO runtime `search_enabled` gate).
- **Execute-time gate chain** (`Tools.execute/5`, sole call site `ToolRuntime.Executor.execute_tool_task/4`): `run_command` refusal → map args (or JSON-string-decoded) → alias normalization → reserved `elixir_eval` route → `maybe_block_repo_less/5` → `maybe_block_read_only_foreign_repo/5` → `execute_tool/5` plus custom/skill fallback. `write_call?/2` = `write_tool?/1` OR a shell background start, and normalization precedes both role guards so aliases cannot bypass them.
- **Flow**: `do_turn/6` → `prompt_until_tools_or_limit/6` → `process_llm_response/7` (`dedupe_and_sync`, turn-tag context — no ETS write; the turn is published by `:checkpoint`) → a text reply finishes via `finalize/2`, or yields `{:yield, state, text}` WITHOUT finalizing for `:interactive`; tool calls go `process_tool_calls/3` → `process_regular_tool_calls/3` → partition subagent vs standard via `subagent_module_for` → `batch_execute_tools/4` → results re-sorted by index in `continue_after_tools`. **One LLM response = ONE blocking batch**: every `tool_calls` entry runs synchronously and the loop returns to the LLM only after all results are appended as `:tool`-role messages; a write/sudo `elixir_eval` BLOCKS its serial tool task (holding its tool slot) while approval is pending.
- **Every tool call gets a result**: `{:error, reason}` → `"Error: #{inspect(reason)}"`, crash → `"Error: Tool execution crashed: ..."`, timeout → `"Error: Tool execution timed out after ..."`, unknown name → `"Error: Unknown tool ..."`; `dedupe_tool_calls/2` dedupes WITHIN one response by `:id` then `{name, args_map}` (NO cross-turn detection, NO call cap).
- **Injection points**: the ONE external one is `drain_and_inject_user_messages/1` at the top of every turn BEFORE the LLM call; the ONE internal one is `inject_background_job_notices/1` AFTER it and BEFORE `maybe_enter_cancel_grace/1`, claiming finished-but-unannounced jobs exactly once as ONE turn-tagged `:user` notice, SKIPPED during grace.
- **Streaming is push-only, watcher-gated**: live activity is captured independently of watchers, and the watcher-independent `:checkpoint` summary merge (`{:agent_updated, agent_id, changed_fields, node}`) covers summary changes only; correlation is just `metadata[:turn]` + `metadata[:timestamp]`.
- **Exact-code approval replaced legacy commands**: `elixir_eval` supersedes `run_command` — read needs no approval, write/sudo require per-call approval of the exact code via `CommandApproval.request_eval/5`, authority is revalidated around execution, and a denied/timed-out approval never starts evaluation — `tools/CONTEXT.md`.

## Repo Identity, Paths, Repo-Less Agents, Foreign Repos, TMPDIR & Archive
`Session.Setup` takes the scheduler's `dispatch_ctx` (a KEYWORD list; `%AgentSpec{}` = `Keyword.fetch!(ctx, :spec)`) with repo identity PRE-RESOLVED as ctx keys `:repo_root`, `:repo_id`, `:worktree_path`; primary root = `Worktrees.repo_root_from_worktree/1`, foreign root = the `spec.foreign_repos` entry whose `id == spec.repo_id` (ID match, NEVER path matching). `%AgentState{repo_id, repo_root, foreign_repos}` is set once at registration, so `AgentState.repo_root` is the ROOT while pd `:repo_path` is the TRANSIENT worktree.
Worktree base = `spec.phylo_node.current_commit`; subagent phylo bases: same-repo = explicit `commit_id` (rev_parse-validated) else the parent's live `current_commit`, cross-repo = foreign `base_sha` → tracked `foreign_repo_commits` → foreign HEAD. Single-repo assumptions: ONE `:repo_path`/`:genesis_repo_root`/`:worktree_path` per agent, ONE base→final commit pair, ONE branch `evogit-agent-T<n>-A<m>`; the init script runs only for `spec.repo_id == "primary"`.
- **Repo-path crash points**: `bind_worktree/2` RAISES on a create error; repo-less syncing answers `:ok`/`nil` so `finalize/2` finishes without git, while a repo-backed agent raises descriptive errors on unset `:repo_path`, a vanished worktree or `rev_parse`. `batch_execute_tools/4` requires BOTH `:repo_path` and `:genesis_repo_root`, `build_initial_state/3` validates `Path.join(repo_path, node_path)` → `{:error, :path_not_exist}`, and the agent process NEVER chdirs.
- **Repo-less agents**: `Process.get(:repo_less)` with `:repo_path` at the REAL source root (`SelfReflectiveSource.reference_path() || File.cwd!()`); write tools stay forbidden through `write_call?/2`, while `elixir_eval` is a separately authorized capability. Dispatch uses `:repo_less_repo_path` (fallback `:repo_root`), forces `attachments` nil, skips the path check, and the run is single-shot under `max_turns_root` (1000).
- **Foreign repos**: a WRITABLE non-primary repo carries a persistent read view `<root>/.genesis/foreign_repos/<id>`; a RELATIVE spawn path keeps the PARENT's `repo_id`, and `build_subagent_specs/3` keys `ContextNode.load` AND the phylo clause on `same_repo?` — `../agent_scheduler/CONTEXT.md`.
- **STALENESS HAZARD (READ SIDE)**: a non-nil task-level `base_sha` wins unconditionally over the parent's tracked map (pinned by `test/evo_git/agent/subagent_processing_test.exs`), masking intra-task progress: a later foreign spawn restarts there, a NESTED agent's spawn (empty own map) falls back to foreign HEAD, and an advanced foreign commit can be unreachable from the reviewed branch.
- **TMPDIR**: one managed dir per TASK (`Session.Setup.ensure_tmpdir/1` → `put_current/1`), inherited by subagents and re-installed per batch, and `bash` runs with `TMPDIR=<Sandbox.resolve_tmpdir()>` which PREFERS `TaskTmpdir.current/0` — `../sandbox/CONTEXT.md`.
- **Tool path scope is ASYMMETRIC**: WRITE tools (`file_write`, `file_edit`, `file_create`, `make_dir`, `context`) call `Shared.validate_file_scope/4` and reject paths outside `repo_path`, outside `node_path` or inside a read-only foreign repo (ALLOW-ALL for a `"./"` node path and a non-binary `node_path`; `read_context` is unscoped), while READ/exec tools accept arbitrary `EvoGit.Platform.safe_expand/2` paths except `web_fetch` and `lsp`'s — `tools/CONTEXT.md`.
- **Archive**: `Completion.write_archive_refs/7` (gated `archive && base_commit`) upserts the ONE `task_agent_archives` row and writes the `refs/genesis/archive/T<task>-A<local>-start/-final` refs plus the metadata note IN THE COMPLETING AGENT's process; nothing rides `%Result{}`, dates are ISO-8601 STRINGS, and credentials are NEVER archived.

## Constraints
- Every agent MUST `use EvoGit.Agent` and implement `system_prompt/0`; system prompts MUST NOT contain dynamic state, objectives or context trees (those are injected as user prompts), and a read-only agent restricts `available_tools/0` to read-only tools (completion is implicit, so no tool is injected by the macro).
- Tool schemas use the `ReqLLM.tool/2` format; agents commit before delegating subagents (the auto-commit fallback enforces it). **State discipline**: loop state is always a `%EvoGit.Agent.State{}`; **Result discipline**: completion produces `%Result{}` and consumers pattern-match on struct fields, not `Map.get/2`.
- Streaming is PUSH-ONLY (`./stream/`): never add a replay buffer, cursor or polling loop, and never broadcast the full context — a delta plus a monotonic `seq` and a bounded `snapshot/1` are the whole contract.

## Conversation Mutation Map & Prompt-Cache Prefix Stability
Between turns the conversation only GROWS by appends; existing messages stay byte-stable EXCEPT two rewrites of the NEWEST assistant message and compression. Message #1 (`[system, first_user]`) is FROZEN at run start, clock line included (`NaiveDateTime.local_now/0`, MINUTE granularity); every later clock lives in an APPENDED refresh message.
Each turn appends, in order: the turn warning (`check_limit_warnings/1`), drained user messages, one `[NOTICE]`, the assistant message, tool results + an optional merge-conflict note; `dedupe_and_sync/3` then rewrites that assistant message's `tool_calls` when duplicates were dropped and `compact_reasoning_details/1` merges streamed `reasoning_details` fragments into ONE entry.
`metadata` (`:turn`, `:timestamp`, `:checkpoint`) is LOCAL ONLY, never encoded on the OpenAI-compatible path (`include_metadata?` false), so turn tagging cannot break a provider cache prefix; only compression mutates already-sent messages (stage 1 rewrites old tool results, `Recency` truncates tail content, `drop_stale_refreshes/1` DELETES an earlier refresh from the MIDDLE).
**Wire stability**: `request_parameters/2` plus admission-fixed `llm_generation_params` are the whole per-request surface, so nothing varies per turn; a low reported cache hit points at provider routing/TTL, run-unique message-#1 content (per-agent worktree path + minute clock) or compression — never per-turn prompt mutation.

## Known Issues
- **A grace-exhausted SUBAGENT's committed partial work is DISCARDED**: `{:error, :recovery_failed}` carries NO sha even though the `after` fallback / `maybe_recovery_auto_commit/1` committed the tree; `collect_mergeable_results/3` takes only `{:ok, %Result{commit_sha: sha}}`, `destroy_worktree/3` deletes its `evogit-agent-*` branch, the parent sees "exceeded its execution limit", and no archive refs are written — the 3-turn grace window is the mitigation, not a fix.
- **`Completion`'s metadata note and archive refs lag the reported `commit_sha` on a fallback-only commit**: written at the PRE-fallback sha while `run/3` refreshes `Result.commit_sha` to the POST-fallback HEAD.
- **Cost is recomputed by EvoGit; ReqLLM's reported cost is NOT trusted** (counts stay accurate): a `nil` recompute KEEPS the reported values; `total_cost` is TOKEN cost only and a `{provider, model}` TUPLE spec raises inside `ReqLLM.model/1`, contained by `Cost`'s `safe/3`; `reasoning_tokens` is not a `%Usage{}` field — `update_turn_usage/2` adds it into `state.total_tokens` and `Cost` maps that meter into `output_cost`.
- **Thinking text is DUPLICATED in a stored assistant message**: ReqLLM materializes it both as a `:thinking` content part (after `:text`) and as `message.reasoning_details`, and only `reasoning_details` is compacted — so **any consumer joining `message.content` parts without a `type == :text` filter renders thinking as the response** (`EvoDashWeb.AgentsLive.message_to_history_entry/1`, `HomeLive.Messages.message_text/1`).
- **LLM errors become abnormal agent exits only here**: the exhaust-all-retries raise in `prompt_until_tools_or_limit/6`, the `ContextCompression` `MatchError` on a non-fail-fast error, and the `with_llm_slot/2` raise on a non-`:ok` slot reply (`{:error, :cancelled}` from a force-kill/cancel purge); `do_turn/6` matches exactly FOUR shapes from `prompt_until_tools_or_limit/6`.
