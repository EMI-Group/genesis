# EvoGit Agent Behaviour & Tools

## Intent
`EvoGit.Agent` is the behaviour every agent module `use`s — the macro injects defaults, overridable callbacks and the `complete_task` tool; the loop is `EvoGit.Agent.Runner`.
This node owns the loop + tool-dispatch orchestration, the LLM tool library, `LoopState`/`Result`, compression orchestration, subagent spawning/merging and token/cost accounting.
Agent TYPE implementations live in `../agents/`; per-tool contracts `tools/CONTEXT.md`; compression stages `compression/CONTEXT.md`.

## API Surface

### Data Structs
| Struct | Purpose |
|---|---|
| `EvoGit.Agent.LoopState` | Turn-threaded loop state; enforced keys `agent_id`, `agent_module`, `depth`, `node_path`, `context`; also `grace_turns_remaining` (default `0` = not in grace), `in_grace_period`, `delegation_hints`, `foreign_repos`. |

### Helper Modules
- **`EvoGit.Agent.ContextCompression`** — `compress_if_needed/2` runs the two stages at the top of `loop/1`; trigger is window-relative over the CONFIGURED `context_window` (default 200_000, NEVER catalog metadata): `min(0.8·W, W − reserved − 65_536)`, floored `min(32_000, 0.9·W)`, capped `0.9·W`; `[:llm, :compression_threshold_tokens]` overrides. Stage 1 prunes old tool text/media model-free, adopted ONLY when the projection lands at/under `Threshold.pruning_target/2` (`[:llm, :tool_result_pruning_target_fraction]` 0.5) and the count fell, else DISCARDED; `[:llm, :tool_result_pruning]` disables. Stage 2 keeps `[system, first_user]` BYTE-IDENTICAL and a recent tail VERBATIM that is bounded by `Recency.tail_budget/1` (`0.2 × window`, capped at 40_000 tokens; the boundary only ever shrinks the tail and never orphans a tool result) plus a forward-progress guard; the checkpoint is exactly ONE UNTAGGED `:user` message (`metadata[:checkpoint] = true`), a prior checkpoint is always replaced, and both rebuild paths drop stale runtime-context refreshes, so repeated compactions keep exactly one checkpoint and exactly one refresh. `compression/CONTEXT.md`.
- **`EvoGit.Agent.CompletionProtocol`** — `classify/1` → `{:tool_calls, calls} | {:text_reply, text} | :empty` (`{:text_reply, text}` with usable text = IMPLICIT COMPLETION, not a failure); `report_text/1` → `{:ok, text} | :empty` (thinking text never becomes the report). `:empty` → ONE nudge (`@max_no_tool_call_nudges` 1) then `{:error, :protocol_violation}` → `handle_protocol_violation/3`.
- **`EvoGit.Agent.ToolInvocation`** — `arguments/1` (a decoded object passes; a non-blank UNPARSEABLE string passes through RAW for `Tools.execute/5`'s `is_binary` self-correction; else `{:error, reason}`, so a nil `args_map` never reaches the tool), `invalid_arguments_result/1` → `"Error: invalid arguments: <reason>"`, missing arg → `"Missing required argument '<key>'"`; `resolve_timeout/4` = explicit positive integer capped by `max_tool_timeout`, else `default_timeout/2` (shell → ≥ `@shell_default_timeout_ms` 120_000, others → `[:scheduler, :default_tool_timeout]`).
- **`EvoGit.Agent.ToolNames`** — `normalize/1`: `read`→`read_file`, `write`→`write_file`, `edit`→`edit_file`, shell aliases (`shell`, `sh`, `execute_bash`, `bash_command`, `run_shell`, `shell_command`, `run_bash`, `run_powershell`, case-insensitive)→the platform name, `grep`/`ripgrep`→`rg`, `websearch`/`web_search`→`search_web`, `task`/`subagent`→`subagent_manager`; unknown names pass through.
- **`EvoGit.Agent.SubagentProcessing`** — spawns subagents, resolves cross-repo paths, merges same-repo results, deletes only merged/auto-resolved branches; child phylo node = same-repo parent `current_commit` / cross-repo `base_sha` → tracked commit → foreign HEAD, and an unresolvable `base_sha`/non-git root yields `{:error, {call, index, msg}}` (never a MatchError); `format_subagent_result/1` surfaces gate rejections verbatim as `"Error: #{msg}"`.
- **`EvoGit.Agent.TurnWarning`** — `:beginning` at ~25% of budget (min turn 6); `:middle` every 15 turns (`:high`) / 45 (`:low`); `:end` at ≤ `min(10, max(3, div(max_turns, 6)))`; `:critical` at ≤ `min(5, max(1, div(max_turns, 20)))`; `:low` skips `:beginning`. The DELEGATION notices (`:beginning`, `:middle`) are suppressed while the agent's worktree is in a merge conflict — `last_warned_level` does not advance and `turns_since_subagent` is frozen (delegation still resets it to 0; counting resumes after resolution), so both resume firing normally once the conflict clears — while the turn-budget notices (`:end`, `:critical`) ALWAYS fire; rationale: subagents always branch from a clean commit, so they can never resolve conflict markers in the parent's worktree. `check_positional/5` / `check_middle/5` take a defaulted final `opts \\ []` (`:in_conflict`), read from the end-of-previous-turn snapshot via `ConflictState.in_conflict?/0` — a plain pd read, never a git call at warning time.
- **`EvoGit.Agent.LlmError`** — `non_retryable?/1` unwraps error/exit/throw/shutdown tuples, `%ReqLLM.Error.API.Stream{}`/`Request{}` and map-or-keyword `:cause` (depth ≤ 5): `retryable == true` or 408/409/425/429/500..599 → retryable; other 400..499 or `retryable == false` → non-retryable; no signal → retryable (model-exhaustion wins on the UNWRAPPED struct). `format_failure/1` = status + provider code + provider name + human message; `/2` adds `Request parameters sent: [a, b].` + the "remove unsupported parameters" line naming `<spec>` (absent → byte-identical to `/1`). Anti-leak: parameter NAMES only (`parameter_names/1`, sorted, ≤32 + `... N more`) + model identity (`:id`/`:model`/`:provider`).
- **`EvoGit.Agent.Cost`** — self-computed LLM cost (ReqLLM's reported cost NOT trusted); pure + total. `recompute(usage_map, model_spec, period)` prices raw counts via `LLMDB.Pricing.components_for(model, %{pricing_period: period})` — only `kind: "token"` components minus `pricing.excluded_cost_components` — by id prefix into `input_cost` (input/cache) / `output_cost` (output/reasoning), `total_cost` = sum, 6 decimals. `period_for_model_id/1` (`"peak" | "off_peak"`, default `"off_peak"`) → `period_for_profile/1` (PeakHours; nil/`""` tz → local; error → off_peak; seams `:peak_hours_now_fun`/`:peak_hours_utc_now_fun`). `apply_to_usage(%Usage{}, raw_map, agent_id)` overrides only the three cost fields, only when the recompute returns a value.

### Tool Library (`EvoGit.Agent.Tools`)
- `schemas/0` = the standard coding set (incl. read-only `WebFetch`, plus `WebSearch` when `[:tools] search_enabled`), with `Lsp` appended LAST only when `EvoGit.Config.lsp_enabled?/0` (`[lsp] enabled = true` + non-empty `[lsp] command`); `read_only_schemas/0` = read set + `Context.read/write/edit` + `ShellTool` + `WebFetch` (+ the same gates).
- `job_output`/`job_list`/`job_kill` sit in BOTH schema lists and NEITHER write list (`serial_tool?/1` false — a read-only agent owns its worktree and may collect/kill its jobs); `default_timeout_ms/1` = 65_000 (`job_output`), 120_000 (shell), `nil` otherwise.
- `@write_tools` (17) = `create_files write write_file edit edit_file bash make_dir write_context edit_context run_bash run_powershell run_git skill_add skill_edit skill_remove skill_enable skill_disable`, always normalized through `ToolNames.normalize/1` first.
- `run_command` is in NONE of the lists (dispatch-only, exposed only via the SelfReflective agent's `available_tools/0`); `EvoGit.CustomTools` are dispatch-only and opt-in per agent. Per-tool arguments, caps, seams and the `run_command` command registry: `tools/CONTEXT.md`.

### Delegation Hinting
Two fire-once per-child-dir hints (`DelegationHints.extract_child_paths/4`, `maybe_append_delegation_hint/4`; counters in `LoopState.delegation_hints` + the pd; `filter_child_paths_if_conflicts/2` suppresses them during merge conflicts): write volume > `[:scheduler, :delegation_hint_threshold]` (5) and `:high`-agent read volume > `[:scheduler, :read_delegation_hint_threshold]` (8). The conflict file list comes from the shared per-turn `ConflictState.files/0` snapshot (refreshed exactly once at turn end in `ToolDispatch.continue_after_tools/6`), so the suppression costs no extra git call and is fresher than a pre-batch check.

### Subagent Objective & File Handoff (no automatic path plumbing)
A parent hands work to a child ONLY via the spawn call's `objective` STRING plus the child's checkout; `build_subagent_specs/3` forwards `args["objective"]` VERBATIM to `AgentSpec.new/5`.
- The `path` arg is a DIRECTORY node — RELATIVE for same-repo targets, ABSOLUTE only for foreign repos; a file path is redirected to its parent dir; an unknown absolute path is rejected with a self-correcting hint. A child finds its dir from a fresh worktree at `spec.phylo_node.current_commit` (= its cwd), hence "Do NOT include worktree paths or `cd` commands in the objective", and parent changes are visible only if COMMITTED before the spawn. Inherited opts: `repo_id`, `foreign_repos`, `repo_notes`, `archive`, `model_id`, `task_tmpdir`; absolute-path rules live on the tool ARG (`Shared.normalize_relpath/1`, `Shared.validate_file_scope/4`).

## Subagent Merge Conflict Resolution (`EvoGit.Agent.ContextMerge`)
A parent merges every SAME-REPO child commit into its worktree; `CONTEXT.md` conflicts are ownership-resolved by `ownership_strength/2` over a repo-relative `.../CONTEXT.md` (`3` = the node path IS the file's directory, `2` = a strict segment-wise ancestor, `./` = everybody's, `1` = unrelated). Rationale + contract: root `./CONTEXT.md`.
- `decide/3`: out of the child's scope (1) → keep OURS + record the dropped edit with its truncated `git diff <base> <child_sha> -- <file>`; child strictly deeper → THEIRS; shallower → OURS; EQUAL ownership ≥ 2 → unresolved.
- `merge_children/2,3`: ONE attempt (`git merge` / `git merge_octopus`) — clean → `:clean` (`:no_changes` when HEAD did not move); on conflict it aborts and children merge one at a time in SPAWN order against the CURRENT "ours" (option `:parent_node_path`, default `"./"`, plus every already-merged child that touched the file). Non-`CONTEXT.md` and equal-ownership conflicts are never auto-picked: that child aborts, the pass ends at `:conflict`, the rest are `:not_attempted`, and every failure path aborts (clean worktree at a reported HEAD).
- `Report`: `status` (`:clean | :no_changes | :conflict | :error`), `starting_sha`, `head_sha`, `merge_output`, `entries` (`index`, `commit_sha`, `branch`, `node_path`, `agent_module`, `agent_type`, `status` = `:merged | :auto_resolved | :conflict | :not_attempted`), `auto_resolutions`, `dropped_edits`, `genuine_conflicts`, `error`; `format_note/2` → `nil` for `:no_changes`, else verdicts + dropped diffs + `git merge <sha>` next steps. `collect_mergeable_results/3` (same-`repo_id` children in spawn order); `delete_merged_branches/2` deletes ONLY `:merged`/`:auto_resolved`.

## Tool Call Execution & Process Topology — serial file-mutating phase, then parallel rest
Standard calls in one batch are PARTITIONED by `EvoGit.Agent.Tools.serial_tool?/1` — the single classification source of truth (`tools/CONTEXT.md`).
- **SERIAL** (runs FIRST) = the file-mutating subset (`create_files`, `write`/`write_file`, `edit`/`edit_file`, `make_dir`, `write_context`, `edit_context`, the five `skill_*` writers, any custom write tool) — sequential, request order, in the PARENT agent process (`run_tool_call/3`); NON-ATOMIC read-modify-write, so concurrent calls on one file would each read the ORIGINAL bytes and all but the last edit would be lost.
- **PARALLEL** = everything else (readers + `bash`/`run_git`/`run_command`/`web_search`) via `Task.async_stream` with `max_concurrency` = group size, `ordered: true`, `timeout: :infinity` — the per-tool timeout lives inside `execute_tool_with_timeout/8`; results are re-sorted by index BEFORE hint tracking.
- **Tool slot** (`AgentScheduler.with_tool_slot/2`) is acquired per call for BOTH groups; the pool is sized by `[:scheduler] max_tool_concurrency` (default = CPU thread count). **Caveat**: the parallel group may hold several git-touching calls contending on `index.lock`.
- **A tool body NEVER runs in the agent process**: `run_tool_call/3` → `execute_tool_with_timeout/8` → `with_tool_slot/2` (blocking grant, `fun.()` in the CALLER) → a spawned `Task.async`; `self()` inside `Tools.execute/5` is the TOOL-TASK pid. SERIAL: spawned BY THE AGENT → linked, `$callers` = `[agent_pid, …]`. PARALLEL: spawned by a stream WORKER → linked to it, `$callers` = `[worker_pid, agent_pid, …]`; workers are monitored (not linked), so a worker crash does not kill the agent — the stream's `{:exit, …}` arm `reraise`s/`exit`s in the agent.
- Tool tasks inherit NO pd: `batch_execute_tools/4` resolves the owner ONCE per batch and `execute_tool_task/7` re-installs the tmpdir + the three identity keys per call. `agent_pid` MUST be the AGENT pid — the tool task dies right after the tool returns, so a monitor on it would fire immediately; `EvoGit.BackgroundJobs` binds detached jobs to the AGENT pid.

## Subagent Spawn Fan-Out — no SPAWN-COUNT cap (depth only)
One batch of subagent calls is ONE blocking `AgentScheduler.spawn_sub_agents/2` (`GenServer.call(..., timeout: :infinity)`), registered/dispatched together (`Subagents.spawn_validated_subagents/5` → `Enum.reduce(sub_ids, state, &Dispatch.try_dispatch/2)`); **no width cap in code** (width is prompt-driven, `agents/manager.ex`; one response = one turn).
- Only bounds: DEPTH (`[:scheduler] max_agent_depth` default 8 — `Runner.at_max_depth?/1` drops subagent schemas, `Subagents.validate_subagent_depth/3`), ignored-path/spatial-contract validation, the one-at-a-time writable-foreign-repo gate; execution is throttled only by the LLM/tool slot pools. `subagent_schemas.ex` emits ONE tool per declared subagent module with a SINGLE `path` + `objective` (+ optional `commit_id`) — N subagents = N calls.
- **The parent BLOCKS for the whole batch** (no timeout; `maybe_resume_parent/2` replies when the last child returns), status `:waiting`, holding NO LLM or tool slot. Caps/deadlock: `../agent_scheduler/CONTEXT.md`.

## Grace Period & Graceful Cancellation (runner-side)
Both kinds enter via `Runner.enter_grace/3` (`@doc false`): `maybe_recovery_auto_commit/1` FIRST (best-effort auto-commit — for cancel this is "save the changes"), then `in_grace_period: true` + the budget, then `loop/1`.
- **Turn-limit recovery** (`trigger_recovery/2`, call site `loop/1`: `"max turns (#{max_turns}) exceeded"`): budget **1** — one continue then hard-stop. **Cancel-grace** (`maybe_enter_cancel_grace/1`, in `loop/1` right AFTER `drain_and_inject_user_messages/1`): the ETS `cancel_requested` flag is cleared and grace enters with budget **3**, `message: nil` (the cancel message already arrived via the drain).
- **Budget semantics**: a turn ending WITHOUT `complete_task` decrements `grace_turns_remaining` via `consume_grace_turn/1` at the three `tool_dispatch.ex` call sites (`handle_protocol_violation`, the `process_llm_response` `{:error, :protocol_violation}` branch, `continue_after_tools`); at `<= 1` → `{:error, :recovery_failed}` (`grace_period_continue_failed?/1`). `complete_task` during grace SKIPS the dirty-workspace check.

## Lifecycle Ordering — worktree allocation BEFORE the first LLM slot
`Runner.run/3` calls `setup_dispatch_context/1` FIRST; for non-repo-less agents this BLOCKS on `WorktreeManager.create_worktree_for_agent/6` (raising on `{:error, reason}`), then runs `do_run/2` → `loop/1` → `do_turn/5` → `call_llm_with_retry/5` → `AgentScheduler.with_llm_slot/2`, so EVERY agent (incl. subagents) allocates its worktree before queueing for a slot. Creation is admission-bounded: each create is its own `Task.start` and the caller WAITS INDEFINITELY through a FIFO queue capped at `Application.get_env(:evo_git, :max_concurrent_worktree_creation, 4)` — a slow copy is waited for, a GENUINE failure replies `{:error, reason}` promptly.
- **`ToolDispatch.current_model/0` / `current_generation_params/0` raise contract**: both resolve the caller via `current_agent_id()` + `Store.get_agent_state/1`; a nil agent id or missing ETS row raises a DESCRIPTIVE `ArgumentError` naming caller + agent id (`fetch_current_agent_state!/1`). Do NOT add nil fallbacks — pinned by `tool_dispatch_retry_slot_test.exs`.

## Update-Timing Safety (in-flight state vs BEAM restart)
- **No turn-level wall-clock timeout**: a turn = LLM call(s) + tools + subagent waits, uncapped. Hard stops: `max_turns` (128, incl. subagents), `max_turns_root` (1000, root only; `Dispatch.resolve_max_turns/3`), the 3-turn cancel grace (TURNS, not wall-clock). Per-piece bounds: LLM stream receive 30 s (300 s thinking), `stream_pool_timeout` 300 s, inner retries + 15-attempt outer backoff; per-tool `min(requested, max_tool_timeout)`; subagent waits unbounded.
- **Per-turn ETS checkpoint, in-memory only**: `context.messages` lives in the agent heap; a snapshot goes to ETS (`AgentState.context`) each turn at `batch_update_agent`. ETS dies with the VM — **no durable conversation checkpoint exists**; `get_agent_history` reads this snapshot.
- **Worktree wipe at next boot**: the FIRST `create_worktree_for_agent` for a repo after restart runs `WorktreeManager.maybe_init_repo/3` → `rm_rf .genesis/workers` → `Git.prune_worktrees` → `clean_orphaned_branches` (all `evogit-agent-*`) — PRIMARY repo only; only commits protected by `refs/genesis/archive/T<task>-A<local>-start/-final` survive (`../agent_scheduler/CONTEXT.md`).
- **`Runner.run/3`'s `after` block** runs `Dispatch.commit_pending_in_worktree/0` ("Agent: auto-commit fallback") on ANY agent-process exit — normal completion, `{:error, :recovery_failed}`, crashes — BEFORE the value is handed back; NOT on `:brutal_kill` or VM shutdown. **Post-fallback `commit_sha` refresh**: `Result.commit_sha` was captured BEFORE the fallback, so `run/3` re-reads the worktree HEAD via `Runner.refresh_commit_sha/1` (repo-less/non-success shapes unchanged; unset/blank `:repo_path`, vanished worktree, non-git dir or git `{:error, _}` leave it unchanged, never raises) — `merge_and_report/3,4` compares it against the live HEAD; a match or nil → `no_changes: true`, `branch_name: nil`, NO `genesis/agent_*` branch.
- **Terminal exit semantics (agent Task)**: `run/3` returns `{:ok, %Result{}}`, `{:error, :recovery_failed}` or `{:error, {:llm_request_rejected, message}}` — ALL plain values, so the task exits `:normal` and the scheduler recycles (`Lifecycle.handle_agent_down/4` → `recycle_agent/2`). Only a RAISE inside `do_run/2` or a force-kill `Task.shutdown(task_ref, :brutal_kill)` is ABNORMAL (→ `handle_agent_crash`); `setup_dispatch_context/1` runs BEFORE `run/3`'s `try`, so a creation raise skips the `after` fallback. Orphaned `:running` tasks wait for lease expiry (`:lease_sweep` → `:failed`); orphaned `:finalizing`/`:cancelling` reconcile at TaskRegistry init (`task_registry/CONTEXT.md`).

## LLM Request Retry Mechanism (3 layers)
**Layer 1 — EvoGit outer loop (`call_llm_with_retry/5`).** MANUAL recursive attempt loop: first attempt index 0, no initial sleep; attempts = `max_retries + 1`, from `agent_state.max_retries` / `[scheduler] max_retries` default **15**. Each attempt runs inside `AgentScheduler.with_llm_slot/2` for ONE `stream_text` + `process_stream`, released (`after`) BEFORE any backoff; inside the slot a `Logger.warning` pairs with `ReqLLMPool.excess_queuing_error?/1` → `bump_for_excess_queuing/2`. The agent keeps its turn and context across attempts.
- **Classification** (`handle_llm_failure/7`): `TruncationFeedback.classify_model_exhaustion/1` on the RAW reason + `LlmError.non_retryable?/1` on the unwrapped struct; precedence model-exhaustion → non-retryable → attempts exhausted → ordinary transient. **Exhaustion always wins**; the class check is raw-reason-based, so a wrapped 402 without a balance/quota phrase takes the ordinary transient path.
- **Exhaustion, attempts remain**: `report_llm_error(agent_id, class, model_exhaustion_delay(attempt + 1))` then RECURSE IMMEDIATELY with no agent-side sleep — the multi-hour wait is the scheduler's per-model backoff queue (cancel-safe). **Ordinary transient**: `:timer.sleep` of an exponential schedule from the `:llm_retry_backoff_base_ms` seam (default 1_000 ms), doubling, capped at 60_000 ms, ±10% jitter. **Exhausted**: a non-nil `class` seeds a fresh model-wide backoff via `model_exhaustion_delay(15)`; then `{:error, reason}` propagates to `prompt_until_tools_or_limit/6`, which **RAISES** `"LLM request failed after N retries"` → agent crash → scheduler crash-retry (`[:scheduler, :agent_max_retries]` default 3). Exceptions propagate immediately (no `rescue`).
- **A 0-capacity model** (peak hard pause) does NOT raise — the slot request BLOCKS (`:blocked`) until capacity returns (`grant_pending_on_resume`) or a force-kill purge replies `{:error, :cancelled}`.
- **Fail-fast on a non-retryable rejection**: a deterministic 4xx (HTTP 400, Z.AI code 1210, `retryable: false`) returns the terminal `{:error, {:llm_request_rejected, message}}` IMMEDIATELY after the first failed attempt — no sleep, no further attempt, no scheduler backoff — with ONE `Logger.error`. The message comes from `LlmError.format_failure(reason, params: <the exact keyword list handed to ReqLLM.stream_text/3>, model: <spec>)`, the spec from the private TOTAL `ToolDispatch.diagnostic_model_spec/0`; parameter NAMES also log per attempt at `Logger.debug`. `prompt_until_tools_or_limit/6` has a pass-through arm (the `raise` stays for every other `{:error, reason}`) and `do_turn/5` a matching arm returning `{:error, terminal}` — NOT the grace path or `handle_protocol_violation/5`, so the task persists `:failed`. `retry_intent/1` appends `" (non-retryable — failing fast)."`

**Layer 2 — ReqLLM inner retries (inside each `stream_text/3`).** `ReqLLM.Streaming.Retry`, `max_retries` default **3** (per-profile `max_retries` generation param). Retried only: HTTP 429 (delay from `Retry-After`, seconds→ms; missing/unparseable/zero → 1000 ms) and transport errors BEFORE any body data (`data_received?: false`; `pool_not_available` → 250 ms, `closed`/`timeout`/`econnrefused` → 0 ms). 5xx and other statuses are NOT retried here, and nothing is retried once streaming started.

**Layer 3 — scheduler per-model backoff.** `AgentScheduler.report_llm_error/3` → `Slots.handle_report_llm_error/4`: for both `:rate_limit` and `:insufficient_balance` it sets per-model `llm_backoff_until[model_id] = now + backoff_ms`, re-queues ALL waiting agents of that model and schedules `:retry_llm_waiting`; a nil/unknown class is a no-op; expired backoffs clear on any grant path (`maybe_clear_model_backoff/2`). Scoped per `model_id`, NOT global.

**Slot per attempt.** `with_llm_slot/2` acquires via a blocking `GenServer.call(request_llm_slot, timeout: :infinity)` and releases via `after` → cast; both backoff sleeps happen while the slot is FREE. A retrying agent's next attempt blocks at re-acquisition while `AgentScheduler.pause/0` is active (granted on `resume/0`).

## First Message Construction (objective → LLM) — single choke point
The objective (`AgentState.objective`, a plain `String.t()`) enters the conversation ONLY inside the first **user** message, built in `Runner.do_run/2`.
- `combined_prompt` = `context_block(context_body)` joined with `objective_block(objective_body)` via `"\n\n---\n\n"` (`<context>…</context>` / `<objective>…</objective>`; a blank objective → `""`). `build_initial_messages/4` returns `[system, user]` via `ReqLLM.Context.new/1`; system = `agent_module.system_prompt()` only. No attachments / non-root / repo-less → the legacy plain-binary `user(combined_prompt)` fast path (byte-identical); a ROOT agent with attachments → `user([text | media parts])`.
- Every turn receives the whole `%ReqLLM.Context{}` by value (`do_turn/5` → `prompt_until_tools_or_limit/6` → `call_llm_with_retry/5` → `ReqLLM.stream_text(current_model(), context, Keyword.merge([tools: tools], llm_gen_opts))`); messages are never re-assembled — every other site only APPENDS (turn warnings, pending drain, grace/recovery, nudges, tool results, compression refreshes).
- **`<context>` section order**: context tree → **delegation authority** (`build_authority_section/1`, pure `%{parent_id, repo_less, foreign_repos}`, never the pd; only for non-repo-less agents on tasks with non-primary foreign repos; ROOT = `AgentState.parent_id == nil`, equivalent to `SchedMeta.depth == 0`) → **foreign repos** (`build_foreign_repos_section/1`) → **repo notes** (`build_repo_notes_section/1`: the `## Git Submodules` note from `AgentState.repo_notes`, set by `Runtime.Helpers.load_repo_notes/2`, inherited by subagents; nil → `""`) → **quality guidance** (`build_quality_guidance_section/1`, ROOT only, via `EvoGit.QualityLevel.guidance/1`; `"balanced"`/absent/unknown, subagents, repo-less → `""`) → **background jobs** (`BackgroundJobNotice.section/1`) → the clock line LAST. Only the summarising refresh injects background jobs; message #1 never carries them.
- The objective stays strictly `String.t()`; attachment bytes travel as a spec opt + base64 in persisted task opts; **no objective-size truncation exists** — the only conversation limit is the window-relative compression trigger. `refresh_first_user_message/2` exists and is tested, but compression does not use it, so `[system, first_user]` stays BYTE-IDENTICAL.

- Per-step media accumulates: compression keeps recent tool media (last K turns VERBATIM) and collapses older tool media into `[... tool result media omitted ...]` per message.

Error/timeout/crash paths stay plain strings; caps apply PER TOOL OUTPUT too.

## Tool-Execution Crash Semantics (raises are CONTAINED in the tool task)
Every tool call runs in a LINKED `Task.async` in `execute_tool_with_timeout/8` (hosted by the AGENT process in the serial phase, by a `Task.async_stream` worker in the parallel phase). `execute_tool_task/7` wraps `Tools.execute/5` in `try/rescue/catch`: a raise → `{:tool_crashed, Exception.format_banner(:error, exception)}`, a throw/other exit → `{:tool_crashed, "<kind> <reason>"}`, both reaching the model as `"Error: Tool execution crashed: …"`; only `:normal`/`:shutdown`/`:kill`/`{:shutdown, _}` re-raise unchanged, so the agent SURVIVES a raising tool and the `{:exit, reason}` arm sees only those (`nil` = its own timeout) — and `Tools.execute/5` itself has NO try/rescue around a tool implementation.
- **Timeout is a per-call WHOLE-CALL budget** (not idle) resolved by `resolve_timeout/4`; `apply_advertised_tool_timeout/3` raises it to `Tools.default_timeout_ms/1` when no explicit `timeout` was given; level-2/3 `run_command` calls are floored to `CommandApproval.timeout() + 30_000` and still capped. `Task.shutdown/2` unlinks before killing, so the timeout path is link-safe.
- **NO escalation to the app**: the agent task is `Task.Supervisor.async_nolink(EvoGit.TaskSupervisor, ...)` — monitor-only, `:temporary`, so OTP never counts its exit toward restart intensity; the scheduler crash-retries (`agent_max_retries` 3) then fails it — a tool failure is NEVER fatal.

## Tool Dispatch Flow & Turn-Loop Contract
- `effective_tools/1` = `agent_module.available_tools()` `++ skill_schemas`, minus subagent tools at max depth; the macro default `available_tools/0` = `Tools.schemas() ++ SubagentSchemas.schemas(__MODULE__) ++ [CompleteTask.schema()]`.
- **Per-agent whitelist = schema-granting ONLY — NO runtime membership filter**: a called tool is never checked against it; an unknown name falls to `execute_tool/5`'s catch-all → `EvoGit.CustomTools.execute/3` (a configured custom tool wins over a same-named dynamic skill; `:unknown` falls through) → dynamic-skill lookup → `"Error: Unknown tool '<name>'. Did you mean '<closest>'? Available tools: ..."` (`closest_tool_name/1`: `String.jaro_distance/2` ≥ 0.7). **Protocol violation = an `:empty` turn only**; zero tool calls with usable text is an IMPLICIT COMPLETION. Repo-less consequence: a hallucinated tool name still dispatches by literal name — write tools are blocked, but non-write tools outside both `@write_tools` and the agent's own list WOULD run (`skill_*` readers, `web_search` — `WebSearch.execute/3` has NO runtime `search_enabled` gate).
- **Execute-time gate chain** (`Tools.execute/5`; sole call site `tool_dispatch.ex`): map args (or JSON-string-decoded) → **shell-tool alias normalization** → `maybe_block_repo_less/5` (`"Error: this agent has read-only access to the system — the <name> tool is disabled."`) → `maybe_block_read_only_foreign_repo/5` → `execute_tool/5`. `write_call?/2` = `write_tool?/1` OR the shell tool with a truthy `run_in_background` (lenient `background_start?/1` — `true`/`"true"` only), matched FIRST in both `cond`s; `write_tool?/1` = built-in `@write_tools` OR `EvoGit.CustomTools.write_tool?/1`. **Alias normalization runs FIRST, deliberately**: `run_bash`/`run_powershell` are in `@write_tools`, so normalizing later would let a repo-less or read-only-foreign-repo agent bypass the block by calling "Bash"/"Shell"/"RUN_BASH".
- **Flow**: `do_turn/5` → `prompt_until_tools_or_limit/6` → `process_llm_response/6` (`dedupe_and_sync`, turn-tag context, `batch_update_agent` ETS sync) → `process_tool_calls` (`"complete_task"` → `handle_complete_call`/`do_complete`, else `process_regular_tool_calls`) → partition subagent vs standard via `subagent_module_for` → `batch_execute_tools/4` → results re-sorted by index in `continue_after_tools`.
- **One LLM response = one blocking batch — the ONLY wait-for-user seam is the `run_command` approval gate**: ALL `tool_calls` execute synchronously and the loop returns to the LLM only after every call produced a result, appended as a `:tool`-role message; a level-2/3 shell command BLOCKS the tool task (holding its tool slot) until approval, window expiry, or owning-task death.
- **Every tool call gets a result**: `{:error, reason}` → `"Error: #{inspect(reason)}"`, crash → `"Error: Tool execution crashed: ..."`, timeout → `"Error: Tool execution timed out after ..."`; the only call-without-result case is deliberate (a batch CONTAINING `complete_task` executes ONLY `complete_task`). `dedupe_tool_calls/2` dedupes WITHIN one response by `:id` then `{name, args_map}`; NO cross-turn detection, NO call cap per response.
- **Injection points**: the ONLY external one is `drain_and_inject_user_messages/1` at the TOP of `loop/1` (once per turn boundary, BEFORE the LLM call); the ONE internal one is `inject_background_job_notices/1` (public `@doc false`) in `continue_loop/2` AFTER the drain and BEFORE `maybe_enter_cancel_grace/1` — claims this owner's finished-but-unannounced jobs (`BackgroundJobs.claim_finished_notices(owner_pid: self())`, exactly-once) and appends `BackgroundJobNotice.notice/1` as ONE turn-tagged `:user` message; SKIPPED during grace.
- **Tool events — NO per-tool broadcast**: outputs live only in the context; the dashboard sees the ETS syncs → `{:agent_updated, agent_id, changed_fields, node}` with `changed_fields = [message_count: length(messages)] ++ strip_heavy_fields(fields)` (`:context` stripped), `message_count` added by `AgentScheduler.Store`. Per-message correlation is only `metadata[:turn]` + `metadata[:timestamp]`; `%ReqLLM.Message{}` has NO EvoGit UUID.

### Command-approval gate (`run_command` level-2/3, `EvoGit.CommandApproval`)
Levels are enforced INSIDE the `run_command` tool call (`CommandShell.execute/1`, `:chat` mode); `execute/2` also supports `approval: :auto` (CLI `run` subcommand), which bypasses the gate for ALL levels.
- `CommandShell.security_level/1` → 1|2|3 (`"help"`/`"Help"` → 1; unknown/non-binary → 1). Level 1 runs immediately; level 2 (`GuideUser.guide_user`) and level 3 (`StartTask`, `CancelTask`, `ForceKillTask`, `DeleteTask`) wait for approval; parse/validation errors surface BEFORE the gate.
- Level ≥ 2 calls `CommandApproval.request(path, human_args, level, Process.get(:evogit_agent_id), Process.get(:evogit_task_id))` — a blocking `GenServer.call(:infinity)`: `:approved` → handler runs; `:denied` → `{:error, "Action denied by the user: ..."}`; `:timeout` → `{:error, "The user did not confirm ... in time ..."}`. The handler NEVER runs on anything but `:approved` (fails closed, incl. when the service is down); window `Application.get_env(:evo_git, :command_approval_timeout)` (default 120_000 ms) read per request.
- **Task-lifecycle auto-deny**: the service subscribes to `"tasks"`; a same-node `{:task_updated, task_id, status, node}` with `status in [:cancelling, :completed, :failed, :cancelled]` auto-resolves `:denied` for that task's pending requests; caller death resolves `:timed_out`. Topic `"approvals"`: `{:approval_requested, %{request_id: "aprv-…", command, args, level, agent_id, task_id, node}}` / `{:approval_resolved, request_id, :approve | :deny | :timed_out}` — one requested ⇒ one resolved; responders `RemoteAPI.respond_approval/2`, `EvoGit.RemoteNode.respond_approval/3`.

## Repo-Path Assumptions (agent-loop crash points on a missing repo)
The loop hard-assumes a real git worktree, set once by `Runner.setup_dispatch_context/1`: it UNCONDITIONALLY requests a fresh worktree via `WorktreeManager.create_worktree_for_agent/6` and RAISES `"Failed to create worktree..."` on error — a repo-less agent type must branch here (`../agent_scheduler/CONTEXT.md`).
- `sync_current_commit_after_tools/1` and `sync_and_get_current_commit/1` are BOTH repo-less-safe, so `do_complete/2` and `build_completion/2` finish a repo-less agent without git. For a repo-backed agent: unset `:repo_path` → `"repo_path not in process dictionary"`; vanished worktree → `"Worktree vanished while agent was running (removed mid-run): ..."`; else → `"Git rev_parse failed (#{code}): #{msg}"`. `batch_execute_tools/4`/`process_standard_calls` require BOTH `:repo_path` and `:genesis_repo_root`; `do_run/2` validates `Path.join(repo_path, node_path)` exists → `{:error, :path_not_exist}`.
- `CompleteTask.complete/4` builds `%Result{}` with `commit_sha`, `branch` (from ETS `lookup_task_info/1`), `repo_id`, `usage`; note/archive refs are gated on `base_commit`; `check_workspace_dirty/1` is tolerant (`_ -> {:clean, nil}`).

## Repo-less Agents
A repo-less agent runs WITHOUT a worktree (chatbot-style), marked by `Process.get(:repo_less)` (set in `setup_dispatch_context/1` from `spec.opts[:repo_less]`); `:repo_path` points at the REAL Genesis source root. Cardinal rule: **never touch git, never write files.**
- **Write guard**: `Tools.execute/5` blocks all write CALLS via `write_call?/2` on BOTH argument paths (`maybe_block_repo_less/5`, then `maybe_block_read_only_foreign_repo/5` — the role comes from `:foreign_repos` via `:evogit_repo_id` id-match, never the path alone); `Shared.validate_file_scope/3` adds a path-level check. `read_only_schemas/0` keeps `Context.write_schema`/`edit_schema` + `ShellTool` by design — read-only FOREIGN-repo writes are blocked by the role gate, while `CONTEXT.md` updates and `mix test` in their own repo stay allowed.

## Foreign-Repo Path Resolution & Commit Propagation
A `%ForeignRepo{}` carries only `root` (absolute; no worktree field); each spawn gets a fresh ephemeral worktree `<repo_root>/.genesis/workers/worker_T<task>_A<local>`, while every WRITABLE non-primary repo ALSO carries the persistent READ view `<root>/.genesis/foreign_repos/<id>` (`ForeignRepo.worktree_path/1`, `AgentScheduler.ForeignWorktree` → `agent_scheduler/CONTEXT.md`).
- `ForeignRepo.resolve/2` → `{:ok, repo, base_dir, rel_path}` (a WRITABLE repo's persistent-worktree prefix is intercepted BEFORE the generic `root` match). **Spawn arg → repo_id/base** (`resolve_subagent_path/4`): absolute → `ForeignRepo.resolve/2` (`<wt>/src/foo` → `./src/foo`); absolute under NEITHER → prefix match against the primary `repo_path` → else a descriptive error listing every foreign root; RELATIVE → the PARENT's id (`parent_state.repo_id`) with the PARENT'S worktree as target root (never hardcoded `"primary"`). `build_subagent_specs/3` keys `ContextNode.load` AND the phylo clause on `same_repo?`; a relative-path `:read_write` child is SAME-REPO (the UNRESTRICTED arm of `validate_spatial_contract_for_spec/4`). `Dispatch.resolve_agent_repo_root_regular/2` takes the id-matched `spec.foreign_repos` entry's `.root`; `spec.phylo_node.repo` is IGNORED there.
- **Advance authority lives in the scheduler**: `subagent_processing.ex` only READS the tracked map (`AgentScheduler.get_foreign_repo_commits/1`); a child's `Result.foreign_repo_commits` is NOT populated here (`CompleteTask` leaves `%{}`) — the scheduler injects it at completion (`Lifecycle.handle_task_result/3` → `inject_foreign_repo_commits/2`). A repo's tracked commit advances ONLY via a completing child that is ITSELF a writable agent in that repo (task-level `writable: true` AND `agent_type() == :read_write`) — `Subagents.store_sub_result/3,4`.
- `AgentSpec.foreign_repos` is a struct FIELD that also rides inside `opts`; built ONCE per task by `Runtime.Helpers.build_root_agent_spec/7` with the ORIGINAL per-repo `base_sha` (nil = HEAD), copied into `%AgentState{}.foreign_repos` at registration with no update path, INHERITED verbatim by child specs. Phylo precedence for a foreign target: (1) non-nil inherited `base_sha`; (2) the PARENT's tracked map at spawn-batch time; (3) foreign HEAD — (1) over (2) pinned by `test/evo_git/agent/subagent_processing_test.exs`. A child's OWN `SchedMeta.foreign_repo_commits` starts EMPTY; the LLM `commit_id` arg is silently IGNORED for foreign targets; the parent's in-memory `foreign_repos` is NEVER updated (only the scheduler roll-up and the note `"  - <repo_id>: <sha>"`).
- **STALENESS HAZARD (READ SIDE)**: a non-nil task-level `base_sha` wins unconditionally, masking intra-task progress — every later foreign spawn restarts there, and a NESTED agent's spawn (empty own map) falls back to foreign HEAD; a stale-seeded spawn can leave an advanced foreign commit unreachable from the reviewed branch.

## Per-Task Scratch Space (TMPDIR)
`EvoGit.TaskTmpdir` (`../task_tmpdir.ex`) is the single source of truth — `[tmp] mode` `:system` / `:custom` / `:per_repo`, path math and event-driven reclaim: `apps/evo_git/CONTEXT.md`.
- **Runner installs it** (`setup_dispatch_context/1`): prefers a parent-threaded `spec.opts[:task_tmpdir]`, else `TaskTmpdir.ensure(meta.task_id, primary_repo_path)` with `primary_repo_path = Process.get(:genesis_repo_root)` or `nil` for repo-less agents (`:per_repo` then falls back — the Genesis source root must never receive `.genesis/tmp`), then `TaskTmpdir.put_current/1` unconditionally; subagent specs inherit it and `batch_execute_tools/4` reads `TaskTmpdir.current/0` once per batch.
- **Tool path-scope is ASYMMETRIC**: SIX tools call `Shared.validate_file_scope/4` — the four file-creating writers (`file_write.ex`, `file_edit.ex`, `file_create.ex`, `make_dir.ex`) and the `CONTEXT.md` writers (`context.ex`) — rejecting paths outside `repo_path`, outside `node_path`, and inside read-only foreign repos; every READ/exec tool accepts arbitrary/absolute paths (`EvoGit.Platform.safe_expand/2` returns an absolute input unchanged), except `web_fetch` (no filesystem path) and `lsp`'s `path` (must resolve INSIDE the agent's repo path).
- **`bash` runs INSIDE the sandbox** (`EvoGit.Sandbox.run_with_partial/7`) with `TMPDIR=<EvoGit.Sandbox.resolve_tmpdir()>` (POSIX `$TMPDIR`, `$env:TEMP` on Windows), which PREFERS `TaskTmpdir.current/0`; the only LLM-visible tmp instruction is the ShellTool schema text "Always use $TMPDIR for temporary files, never /tmp."

## Archive (per-agent, streaming)
One `task_agent_archives` row per agent, written STREAMING at agent completion: `CompleteTask.write_archive_refs/7` (gated `archive && base_commit`) builds the record and calls `TaskRegistry.put_task_archive/1` → `Store.put_task_archive/2` (upsert on `{task_id, agent_id}`, so a crash-retry completing twice REPLACES the row).
Nothing is buffered in memory, there is no archive in `%Result{}` and none in the task report, and no compression layer exists anywhere on the archive path.
The same function writes the protecting refs `refs/genesis/archive/T<task>-A<local>-start/-final` (always, before the row) and the metadata note (`add_metadata_note/3`, gated on `base_commit` alone); an unknown task id (`nil`/`0`/`""`) skips the row write and logs a debug line; `started_at`/`completed_at` are ISO-8601 STRINGS.

## Constraints
- Every agent MUST `use EvoGit.Agent` and implement `system_prompt/0`; system prompts MUST NOT contain dynamic state, objectives or context trees (those are injected as user prompts).
- Read-only agents (`agent_type: :read`) should restrict `available_tools/0` to read-only tools; `complete_task` is injected by the macro.
- Tool schemas use the `ReqLLM.tool/2` format; agents commit before delegating subagents (auto-commit fallback enforces it).
- **LoopState discipline**: loop state is always a `%LoopState{}`. **Result discipline**: completion produces `%Result{}`; consumers pattern-match on struct fields, not `Map.get/2`.

## Known Issues
- **`CompleteTask`'s metadata git note and archive refs lag the reported `commit_sha` on a fallback-only commit**: they are written at the PRE-fallback sha while `run/3` refreshes `Result.commit_sha` to the POST-fallback HEAD — when the fallback created the only commit, neither covers the commit the task reports.
- **LLM cost is recomputed by EvoGit; ReqLLM's reported cost is NOT trusted** (token COUNTS stay accurate and come from ReqLLM). `Usage.from_response_usage/1` copies the three cost fields and BOTH cost-producing sites override them through `Cost.apply_to_usage/3` (`ToolDispatch.update_turn_usage/2`; `ContextCompression`'s `{:ok, response}` branch); a `nil` recompute KEEPS ReqLLM's values. `total_cost` is the TOKEN cost only; a `{provider, model}` TUPLE spec makes `ReqLLM.model/1` raise inside its own validation builder, caught by `Cost`'s `safe/3` boundary.
- **Thinking text is DUPLICATED in a stored assistant message** (thinking and response stay SEPARATE in the core): ReqLLM materializes it BOTH as a `%ReqLLM.Message.ContentPart{type: :thinking}` inside `message.content` (after `:text`) AND as `message.reasoning_details`; the whole `%ReqLLM.Message{}` is stored verbatim in `AgentState.context` and only `reasoning_details` is compacted (`compact_reasoning_details/1`), so `get_agent_history/1` returns both. **Any consumer joining `message.content` parts without a `type == :text` filter renders thinking as the response** (no visible `:text` → the join equals the thinking text EXACTLY). Display sites: `apps/evo_dash` (`AgentsLive.message_to_history_entry/1`, `HomeLive.Messages.message_text/1`); decoder contract: root `./CONTEXT.md`.
- **`reasoning_tokens` is not a `%Usage{}` field**: `Usage` has 8 fields and no reasoning bucket; `update_turn_usage/2` adds `Map.get(usage, :reasoning_tokens, 0)` into `state.total_tokens` (the compression trigger), and `Cost` maps that meter / the `token.reasoning*` prefix into `output_cost`.
- **LLM errors can become abnormal agent exits only where documented above**: the exhaust-all-retries raise in `prompt_until_tools_or_limit/6`, the `ContextCompression` `MatchError` for a non-fail-fast error (one compression LLM call, no retry, no rescue), and the `with_llm_slot/2` raise on a non-`:ok` slot reply (`{:error, :cancelled}` from a force-kill/cancel purge). `do_turn/5` matches exactly FOUR shapes from `prompt_until_tools_or_limit/6`, so a `CaseClauseError` can only appear if that contract is widened without a matching clause.
