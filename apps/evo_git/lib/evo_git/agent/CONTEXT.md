# EvoGit Agent Behaviour & Tools

## Intent
`EvoGit.Agent` is the behaviour every agent module `use`s; the runtime loop is `EvoGit.Agent.Exchange` over `%EvoGit.Agent.State{}`, driven by the per-agent `EvoGit.Agent.Session`, and `EvoGit.Agent.Runner` is only a helper module.
A run finishes ONLY by replying with NO tool calls — that reply text IS the report — and `EvoGit.Agent.Completion.Builder.finalize/2` writes the completion side effects once, at the session's terminal outcome.
This node owns the exchange engine + tool-dispatch orchestration, the LLM tool library, `State`/`Result`, compression orchestration, subagent spawning/merging, token/cost accounting and the PUSH-ONLY delta stream (`./stream.ex` + `./stream/`).
Agent TYPE implementations live in `../agents/`; per-tool contracts `tools/CONTEXT.md`; compression stages `compression/CONTEXT.md`; streaming `stream/CONTEXT.md`.

### Helper Modules
- **`ContextCompression`** — `compress_if_needed/2` is `%State{}` → `%State{}` at every turn top; the trigger is window-relative over the CONFIGURED `context_window` (default 200_000, NEVER catalog metadata) with the `[:llm, :compression_threshold_tokens]` override; stage 1 prunes old tool text/media model-free and is adopted only at/under `Threshold.pruning_target/2`, else DISCARDED; stage 2 keeps `[system, first_user]` BYTE-IDENTICAL plus a bounded verbatim tail and exactly ONE UNTAGGED checkpoint `:user` message — formulas and seams in `compression/CONTEXT.md`.
- **`Completion.Builder`** — `finalize/2` is the ONE completion entry point; fixed order: `Dispatch.commit_pending_in_worktree/0` (no-op for a clean workspace and repo-less agents, never raises) → POST-commit HEAD (`sync_and_get_current_commit/1`, still RAISES a descriptive `rev_parse` error when the worktree vanished mid-run) → live HEAD (`Runner.refresh_commit_sha/1`) → `Completion.complete/4` ONCE; answers `{:ok, %Result{}}`, `{:error, {:agent_state_not_found, agent_id}}` or `{:error, {:sched_meta_not_found, agent_id}}`, never `{:error, _}` for a git problem.
- **`CompletionProtocol`** — `classify/1` → `{:tool_calls, calls} | {:text_reply, text} | :empty` (usable text = IMPLICIT COMPLETION); `report_text/1` (thinking never becomes the report); `:empty` → ONE nudge (`@max_no_tool_call_nudges` 1) then `{:error, :protocol_violation}` → `handle_protocol_violation/3`.
- **`ToolInvocation`** — `arguments/1` (decoded object passes; non-blank UNPARSEABLE string passes RAW; else `{:error, reason}`), `invalid_arguments_result/1` → `"Error: invalid arguments: <reason>"`, missing arg → `"Missing required argument '<key>'"`; `resolve_timeout/4` = an explicit POSITIVE duration in ANY shape (integer, float truncated, numeric string with optional `ms`/`s`/`m` via `Tools.Shared.fetch_duration_ms/2`) capped by `max_tool_timeout`, else `default_timeout/2`; non-positive/unparseable counts as ABSENT.
- **`ToolNames`** — `normalize/1`: `read`/`write`/`edit` → `read_file`/`write_file`/`edit_file`, shell aliases (`shell`, `sh`, `execute_bash`, `bash_command`, `run_shell`, `shell_command`, `run_bash`, `run_powershell`, case-insensitive) → the platform name, `grep`/`ripgrep` → `rg`, `websearch`/`web_search` → `search_web`, `task`/`subagent` → `subagent_manager`; unknown names pass through.
- **`SubagentProcessing`** — spawns subagents, resolves cross-repo paths, merges same-repo results, deletes only merged/auto-resolved branches; an unresolvable `base_sha`/non-git root yields `{:error, {call, index, msg}}` (never a MatchError); `format_subagent_result/1` surfaces gate rejections verbatim as `"Error: #{msg}"`.
- **`TurnWarning`** — `:beginning` at ~25% of budget (min turn 6); `:middle` every 15 (`:high`) / 45 (`:low`) turns; `:end` at ≤ `min(10, max(3, div(max_turns, 6)))`; `:critical` at ≤ `min(5, max(1, div(max_turns, 20)))`; `:low` skips `:beginning`; delegation notices are suppressed in a merge conflict (no `last_warned_level` advance, `turns_since_subagent` frozen) while `:end`/`:critical` ALWAYS fire; the flag is `ConflictState.in_conflict?/0`, never a git call.
- **`LlmError`** — `non_retryable?/1` unwraps error/exit/throw/shutdown tuples, `%ReqLLM.Error.API.Stream{}`/`Request{}` and map-or-keyword `:cause` (depth ≤ 5): `retryable == true` or 408/409/425/429/500..599 → retryable; other 400..499 or `retryable == false` → non-retryable; no signal → retryable (model-exhaustion wins on the UNWRAPPED struct). `format_failure/1` = status + provider code + provider name + human message; `/2` adds `Request parameters sent: [a, b].` + the "remove unsupported parameters" line naming `<spec>`; anti-leak = parameter NAMES only (`parameter_names/1`) + model identity.
- **`Cost` / `Usage`** — `Cost.recompute/3` prices raw counts via `LLMDB.Pricing.components_for(model, %{pricing_period: period})` (only `kind: "token"` components minus `pricing.excluded_cost_components`), `total_cost` = `input_cost + output_cost` at 6 decimals, and `apply_to_usage/3` overrides only those three fields and only on a non-nil recompute. `Usage.cache_hit_rate/1` = `cached_tokens / input_tokens * 100` (input only; absent → `0`; stream chunks keep the MAX via `ReqLLM.Usage.merge/2`); two gaps: a lost usage payload drops the WHOLE turn's usage, and DeepSeek's `prompt_cache_hit_tokens` is never read. Per-account period + peak seams: Provider-Profile Model Selection below.
### Tool Library (`EvoGit.Agent.Tools`)
- `schemas/0` = the standard coding set (incl. read-only `WebFetch`, plus `WebSearch` when `[:tools] search_enabled`), with `Lsp` appended LAST only when `EvoGit.Config.lsp_enabled?/0` (`[lsp] enabled = true` + non-empty command); `read_only_schemas/0` = read set + `Context.read/write/edit` + `ShellTool` + `WebFetch` (+ the same gates).
- `job_output`/`job_list`/`job_kill` sit in BOTH schema lists and NEITHER write list (`serial_tool?/1` false); `default_timeout_ms/1` = `[:scheduler, :max_tool_timeout]` for `job_output` (DERIVED at call time as `BackgroundJobs.wait_max_ms() + dispatch_headroom_ms()` — 1_800_000 ms by default), 120_000 (shell), 30_000 (`elixir_eval`), `nil` otherwise; `Tools.timeout_arg_is_wait_budget?/1` is `true` only for `job_output`, so its advertised default is a FLOOR even against an explicit `timeout`.
- `@write_tools` (17) = `create_files write write_file edit edit_file bash make_dir write_context edit_context run_bash run_powershell run_git skill_add skill_edit skill_remove skill_enable skill_disable`, always normalized through `ToolNames.normalize/1` first.
- `elixir_eval` is dispatch-only, absent from BOTH shared schema sets, exposed only by the reflective assistant's own schema list, and EVERY tier is serial; `Tools.execute/5` reserves it before the pd-based write guards and calls `ElixirEval.execute/3`, which authorizes the live root reflective owner against scheduler ETS, ancestry and task lifecycle independently of tool-task role flags — coding/custom/foreign agents cannot acquire it by hallucinating the name or advertising the schema.
- Legacy `run_command` is unconditionally refused by `Tools.execute/5` with `Error: use elixir_eval exact-code approval path`; direct `RunCommand` and CLI `CommandShell` APIs remain compatible outside agent dispatch.
- Write/sudo outer tool timeouts are floored to `CommandApproval.timeout() + 30_000` even against an explicit outer `timeout`, then capped by `max_tool_timeout`; read/default/invalid tiers get no approval floor, and numeric `timeout_ms` is only the inner engine cap (5 s). `EvoGit.CustomTools` are dispatch-only and opt-in per agent (`tools/CONTEXT.md`).
### Delegation Hinting
Two fire-once per-child-dir hints (`DelegationHints.extract_child_paths/4`, `maybe_append_delegation_hint/4`; counters in `State.delegation_hints` + the pd; `filter_child_paths_if_conflicts/2` suppresses them in a merge conflict): write volume > `[:scheduler, :delegation_hint_threshold]` (5) and `:high`-agent read volume > `[:scheduler, :read_delegation_hint_threshold]` (8); the conflict file list comes from the per-turn `ConflictState.files/0` snapshot, so suppression costs no extra git call.

### Subagent Objective & File Handoff (no automatic path plumbing)
A parent hands work to a child ONLY via the spawn call's `objective` STRING plus the child's checkout; `build_subagent_specs/3` forwards `args["objective"]` VERBATIM to `AgentSpec.new/5`.
The `path` arg is a DIRECTORY node — RELATIVE for same-repo targets, ABSOLUTE only for foreign repos; a file path is redirected to its parent dir; an unknown absolute path is rejected with a self-correcting hint.
A child's dir is its fresh worktree at `spec.phylo_node.current_commit` (= cwd), so "Do NOT include worktree paths or `cd` commands in the objective", and parent changes are visible only if COMMITTED before the spawn; inherited opts: `repo_id`, `foreign_repos`, `repo_notes`, `archive`, `model_id`, `task_tmpdir`; absolute-path rules live on the tool ARG (`Shared.normalize_relpath/1`, `Shared.validate_file_scope/4`).

## Exchange Engine, State & Test Seams
`Exchange.run/2` is the public entry: ONE exchange = N turns returning exactly `{:yield, state, String.t()} | {:finish, state, %Result{}} | {:error, reason}`; a `{:yield}` is terminal for ONE exchange, never for the agent (only an `:interactive` agent produces one — `ToolDispatch.process_llm_response/7` commits the pending work and returns it instead of finalizing), so a `:oneshot` run is exactly ONE exchange with outcome set `{:finish, …} | {:error, reason}`; `:finish` and `:yield` are checkpointed identically, once, before the outcome is returned.
`%State{}` carries no funs and no pids, so the whole struct is snapshot-able and JSON-clean; the turn loop's continuations (`%{loop: fun, trigger_recovery: fun}`) are closures created by `run/2` and handed to `Turn.run/3`, never stored in the struct. Seams resolve through `Exchange.Seams.from_opts/1` — explicit `opts` key, else the call-time app env, else `nil` = production path — so an unseamed exchange runs in a bare process.
| Option key | App env | Arity | Return shape | Production default (absent key) |
|---|---|---|---|---|
| `:llm_call` | `:agent_exchange_llm_call` | 5 — `(context, tools, llm_generation_params, agent_id, max_retries)` | `{:ok, response} \| {:implicit_completion, response, text} \| {:error, reason}` | `LLMPrompting.prompt_until_tools_or_limit/5`; else the real `call_llm_with_retry/5` path |
| `:tool_batch` | `:agent_exchange_tool_batch` | 2 — `(indexed_calls, state)` | `[{index, tool_call_id, name, output}]` | none — replaces the real batch, hint tracking AND commit sync |
| `:scheduler` | `:agent_exchange_scheduler` | 3 — `(kind, payload, state)` | `term()` (CONTROL-PLANE only: `:drain_inputs`, `:cancel_requested?`, `:clear_cancel`) | `AgentScheduler.Store` drains/flags |
| `:checkpoint` | `:agent_exchange_checkpoint` | 1 — `(state)` | any `term()` — DISCARDED (observable-only) | the session worker sends `{:checkpoint, %State{}}` to the session, which merges the summary fields via `Session.Summary.publish/3` |
The `:checkpoint` seam is the turn BOUNDARY hook: exactly ONCE PER TURN after that turn's state update — with the state handed to the recursive loop step for a CONTINUING turn (inside `continuations/2`, so turn-0 never counts) and once with the finishing (`:finish` OR `:yield`) turn's state in `run/2`; `{:error, reason}` checkpoints nothing, the return value is discarded, and an explicit `nil`/`false` (opts key or app env) means no state work. The engine reads from the STRUCT instead of ETS: `objective` (grace message), `llm_model`, `llm_generation_params`, `llm_context_window` (compression), `max_turns`, `max_depth`, `max_retries`, `repo_less`, `repo_path` (recovery auto-commit) and `current_commit` (recorded post-tool via the per-process `:evogit_current_commit`, read by `subagent_processing.ex`).

## Subagent Merge Conflict Resolution (`EvoGit.Agent.ContextMerge`)
A parent merges every SAME-REPO child commit into its worktree; `CONTEXT.md` conflicts are ownership-resolved by `ownership_strength/2` over a repo-relative `.../CONTEXT.md` (`3` = the node path IS the file's directory, `2` = a strict segment-wise ancestor, `./` = everybody's, `1` = unrelated). Contract + rationale: root `./CONTEXT.md`.
- `decide/3`: out of the child's scope (1) → keep OURS + record the dropped edit with its truncated `git diff <base> <child_sha> -- <file>`; child strictly deeper → THEIRS; shallower → OURS; EQUAL ownership ≥ 2 → unresolved.
- `merge_children/2,3`: ONE attempt (`git merge` / `git merge_octopus`) — clean → `:clean` (`:no_changes` when HEAD did not move); on conflict it aborts and children merge one at a time in SPAWN order against the CURRENT "ours" (option `:parent_node_path`, default `"./"`, plus every already-merged child that touched the file). Non-`CONTEXT.md` and equal-ownership conflicts are never auto-picked: that child aborts, the pass ends at `:conflict`, the rest are `:not_attempted`, and every failure path aborts (clean worktree at a reported HEAD).
- `Report`: `status` (`:clean | :no_changes | :conflict | :error`), `starting_sha`, `head_sha`, `merge_output`, `entries` (`index`, `commit_sha`, `branch`, `node_path`, `agent_module`, `agent_type`, `status` = `:merged | :auto_resolved | :conflict | :not_attempted`), `auto_resolutions`, `dropped_edits`, `genuine_conflicts`, `error`; `format_note/2` → `nil` for `:no_changes`, else verdicts + dropped diffs + `git merge <sha>` next steps. `collect_mergeable_results/3` takes same-`repo_id` children in spawn order; `delete_merged_branches/2` deletes ONLY `:merged`/`:auto_resolved`.

## Tool Call Execution & Process Topology — serial file-mutating phase, then parallel rest
Execution lives in the MANAGED runtime (`../tool_runtime/CONTEXT.md`): `ToolDispatch.batch_execute_tools/5` only resolves the agent-side context into ONE `EvoGit.ToolRuntime.Request` and delegates, and the serial/parallel partition, `Task.async_stream` parameters, `$callers` topology, slot acquisition, the tool-task pd re-installation and the durable-owner rule are documented THERE.
`EvoGit.Agent.Tools.serial_tool?/1` stays the single classification source of truth (`tools/CONTEXT.md`); **the evaluator does not trust tool-task role pd** — `ElixirEval.Authorization` validates the explicit owner identity/ETS, ancestry and live task state independently.
The pd key/owner table (`:evogit_agent_id`, `:evogit_agent_pid`, `:repo_path`, `:conflict_files`, … who writes each and who reads it) lives in `./session/CONTEXT.md`.

## Subagent Spawn Fan-Out — no SPAWN-COUNT cap (depth only)
One batch of subagent calls is ONE blocking `AgentScheduler.spawn_sub_agents/2` (`GenServer.call(…, timeout: :infinity)`), registered/dispatched together (`Subagents.spawn_validated_subagents/5` → `Enum.reduce(sub_ids, state, &Dispatch.try_dispatch/2)`); **no width cap in code** (width is prompt-driven; one response = one turn).
Only bounds: DEPTH (`[:scheduler] max_agent_depth` default 8 — `Turn.effective_tools/1` drops subagent schemas, `Subagents.validate_subagent_depth/3`), ignored-path/spatial-contract validation, and the one-at-a-time writable-foreign-repo gate; execution is throttled only by the LLM/tool slot pools (`subagent_schemas.ex` emits ONE tool per declared module with a SINGLE `path` + `objective` + optional `commit_id`).
**The parent BLOCKS for the whole batch** (no timeout; `maybe_resume_parent/2` replies when the last child returns), status `:waiting`, holding NO LLM or tool slot; caps/deadlock: `../agent_scheduler/CONTEXT.md`.

## Grace Period & Graceful Cancellation (exchange-side)
Both kinds enter via `Exchange.Grace.enter_grace/2,3` (`@doc false`; `Runner.enter_grace/2,3` is a `@doc false` compatibility delegate for the test suite): `maybe_recovery_auto_commit/1` FIRST (best-effort auto-commit `"auto-commit: turn-limit recovery"` — for cancel this is "save the changes"), then `in_grace_period: true` + the budget, then the private turn loop.
- **Both grace kinds use a 3-turn budget**: turn-limit recovery (the private `trigger_recovery`, call site `"max turns (#{max_turns}) exceeded"`, `@turn_limit_grace_turns`) and cancel-grace (`maybe_enter_cancel_grace/1`, in the turn loop right AFTER `Exchange.Pending.drain_and_inject_user_messages/1`: the ETS `cancel_requested` flag is cleared, `message: nil` — the cancel message already arrived via the drain). Three turns is the cost of "one bounded final commit + a plain-text report", because a tool-calling turn does not finish the run: at most two grace turns may end in a tool call, and a third continued turn hard-stops.
- **Recovery message contract** (`recovery_warning_message/2`, `@doc false`, reading `state.objective`; turn count interpolated from `@turn_limit_grace_turns` so it cannot drift): states the exceeded budget and the number of final turns, the ONE completion rule (a reply with NO tool calls ends the run and its text IS the report; a tool-calling turn does not finish it), and the terminal consequence (window used up without such a reply → the run stops immediately with NO report); it permits at most ONE final commit in the first of those turns, only when work is genuinely uncommitted, and instructs the agent to STOP and report what was done / what remains / what a follow-up must pick up. The objective variant keeps the "report MUST summarize the status of this ENTIRE objective" requirement and the `Your original objective was:` block; a blank `objective` omits both.
- **Budget semantics**: a turn that CONTINUES without completing (a plain-text reply completes and consumes nothing) decrements `grace_turns_remaining` via `consume_grace_turn/1` at the three `tool_dispatch.ex` call sites (`handle_protocol_violation`, the `process_llm_response` `{:error, :protocol_violation}` branch, `continue_after_tools`); at `<= 1` → `{:error, :recovery_failed}` (`grace_period_continue_failed?/1`).

## Lifecycle Ordering — worktree allocation BEFORE the first LLM slot
`Session.Setup.bind_worktree/2` runs FIRST inside the session's ONE start task (the SESSION pid is the create owner, so a slow/queued/hung create never blocks the session process); for non-repo-less agents it BLOCKS there on `WorktreeManager.create_worktree_for_agent/6` (raising on `{:error, reason}`), and `build_initial_state/3` then runs in the session process before the per-exchange worker → `Exchange.run/2` → `Turn.run/3` → `ToolDispatch.do_turn/6` → `call_llm_with_retry/5` → `AgentScheduler.with_llm_slot/2`, so EVERY agent (incl. subagents) allocates its worktree before queueing for a slot; creation is admission-bounded by the `max_concurrent_worktree_creation` FIFO queue (a slow copy is waited for, a GENUINE failure replies promptly) — detail `../agent_scheduler/CONTEXT.md`.
- **`ToolDispatch.current_model/0` / `current_generation_params/0` raise contract**: both resolve the caller via `current_agent_id()` + `Store.get_agent_state/1`; a nil agent id or a missing summary row raises a DESCRIPTIVE `ArgumentError` naming caller + agent id (`fetch_current_agent_state!/1`). Do NOT add nil fallbacks — pinned by `tool_dispatch_retry_slot_test.exs`.

## Run Lifecycle — a fresh exchange per run, no resume of a finished run, no external-input wait in the loop
Every agent run STARTS with ONE fresh exchange: `Session.Setup.build_initial_state/3` always constructs a `[system, user]` context via `ContextBuilder.build_initial_messages/4` (context tree rebuilt from disk, objective re-rendered), and no entry point accepts an existing `%ReqLLM.Context{}` from OUTSIDE the agent — a resumed/cancelled TASK is a brand-new task row plus a brand-new session, and `TaskRegistry.ResumeContext` only seeds task OPTS. A `:oneshot` agent runs exactly that ONE exchange; an `:interactive` session instead runs N exchanges on ONE session pid, resuming append-only from the state it holds.
`Exchange.run/2`'s turn loop never `receive`s and never blocks for external input: its only inbound channels are the LLM response and the per-turn drains (`Exchange.Pending.drain_and_inject_user_messages/1`, `Exchange.Pending.inject_background_job_notices/1`).
`drain_and_inject_user_messages/1` is ETS-only and non-blocking (`AgentScheduler.Store.drain_pending_user_messages/1` over `ControlPlane`'s inbox) and REQUIRES a LIVE agent (`append_pending_user_message/2` answers `{:error, :not_found}` once `recycle_agent/2` deleted the row); it is the ONLY mid-run follow-up channel, and graceful cancel reuses it (`Session.start_input/3` starts a NEW exchange between turns instead).
Termination is exhaustive: implicit completion → `{:finish, state, %Result{}}` (side effects written INSIDE `ToolDispatch.process_llm_response/7` via `Completion.Builder.finalize/2`, before the stack unwinds) or → `{:yield, state, text}` for an `:interactive` agent; `Session.Worker.run/3` then re-reads the post-fallback HEAD and sends `{:exchange_finished, self(), outcome}`; grace exhaustion → `{:error, :recovery_failed}`; non-retryable provider rejection → `{:error, {:llm_request_rejected, message}}`; every other exhausted-retry path RAISES (`"LLM request failed after N retries"`) and is crash-retried by the scheduler.

## Interactive Sessions (P3) — contracts here, mechanics in `session/CONTEXT.md`
An `:interactive` session runs N exchanges on ONE `EvoGit.Agent.Session` pid, while a `:oneshot` agent (the macro default, and every production agent today) runs exactly one exchange and stops.
Mode resolution, `:awaiting_input` parking, `start_input/3` policy (`:queue`/`:interrupt`), append-only resume and `on_yield/1` are the session's: `./session/CONTEXT.md`.
What the AGENT node fixes is the budget and identity contract: ONE exchange is measured by `EvoGit.Agent.exchange_turn_budget/1` (explicit `state.max_exchange_turns`, else `state.max_turns`) counted from `state.exchange_turn_base`, the WHOLE session by `EvoGit.Agent.session_turn_budget/1` (explicit `state.max_session_turns`, else the call-time seam `Application.get_env(:evo_git, :interactive_session_turns, exchange_turn_budget * 10)`, with any non-positive/non-integer value IGNORED at each step so a mistyped seam cannot wedge a session at zero turns); production dispatch leaves both override fields unset.
`EvoGit.Agent.trigger_turn_limit_recovery?/1` applies the burst-or-session condition for `:interactive` and plain `turn >= max_turns` for `:oneshot`, and BOTH exhaustions enter the SAME 3-turn grace window.
Resume keeps conversation, worktree and identity VERBATIM and rebases `exchange_turn_base`; the context tree is never rebuilt and `prompt_cache_key` never changes, so the provider prefix cache survives across exchanges.
Completion is written exactly ONCE per session, at its terminal outcome, by `Completion.Builder.finalize/2` — ONE git note, ONE archive row and ONE `%Result{}` covering all N exchanges — while a `:yield` commits the pending work and writes nothing.
The worktree is bound to the SESSION pid (created by `Session.Setup.bind_worktree/2` before the first exchange) and reclaimed exactly once — when the session process stops — never at a yield, so an idle session keeps its transcript and checkout until closed.

## Update-Timing Safety (in-flight state vs BEAM restart)
Cross-cutting restart/idle semantics (leases, `:lease_sweep`, startup reconciliation, restart posture) live in `../CONTEXT.md` ("Update-Timing Safety") and `../task_registry/CONTEXT.md`; this node owns only what an exit does to an IN-FLIGHT agent.
- **No turn-level wall-clock timeout**: a turn = LLM call(s) + tools + subagent waits, uncapped; hard stops are `max_turns` (128, incl. subagents), `max_turns_root` (1000, root only; `Dispatch.resolve_max_turns/3`) and the 3-turn grace window (TURNS, not wall-clock). Per-piece bounds: LLM stream receive 30 s (300 s thinking), `stream_pool_timeout` 300 s, inner retries + 15-attempt outer backoff, per-tool `min(requested, max_tool_timeout)`, unbounded subagent waits.
- **Per-turn publication, in-memory only**: `context.messages` lives in the session-owned `%State{}`; the ONE publication path is the `:checkpoint` seam — `Session.Worker` sends each turn's state to `Session.Summary.publish/3`, which merges only the SUMMARY fields (`turn`, `message_count`, `usage`, `total_tokens`, `compression_count`, `last_activity_at`) onto `:evogit_agent_summary` and never writes `context`. ETS dies with the VM, so **no durable conversation checkpoint exists** and streamed deltas are equally transient (no replay buffer).
- **`Session.Worker.run/3`'s `after` block** runs `Dispatch.commit_pending_in_worktree/0` ("Agent: auto-commit fallback") on ANY agent-process exit — normal completion, `{:error, :recovery_failed}`, crashes — BEFORE the value is handed back; NOT on `:brutal_kill` or VM shutdown. `Result.commit_sha` was captured BEFORE the fallback, so `run/3` re-reads the worktree HEAD via `Runner.refresh_commit_sha/1` (never raises; an unset/blank `:repo_path`, vanished worktree, non-git dir or git `{:error, _}` leave it unchanged) — `merge_and_report/3,4` treats a match or nil as `no_changes: true`, `branch_name: nil`, NO `genesis/agent_*` branch.
- **Terminal exit semantics**: `Session.Worker.run/3` always returns `:ok` after sending `{:exchange_finished, self(), outcome}` (`{:finish, …}`, `{:yield, …}`, `{:error, :recovery_failed}`, `{:error, {:llm_request_rejected, message}}` — all plain values), so a `:oneshot` session reaches `:normal` and the scheduler recycles (`Lifecycle.handle_agent_down/4` → `recycle_agent/2`). Only a RAISE inside the `Exchange` engine or `Session.cancel(pid, :force)` is ABNORMAL; a worker that dies WITHOUT reporting an outcome stops the session with its own exit reason, and `bind_worktree/2` runs in the session's start task BEFORE any worker exists, so a creation raise stops the SESSION (crash/retry path) and skips the fallback.

## LLM Request Assembly (what actually reaches ReqLLM)
ONE call site per turn: `LLMPrompting.run_llm_attempt/4` calls `ReqLLM.stream_text(current_model(), context, request_params)` inside `AgentScheduler.with_llm_slot/2`, wiring `ReqLLM.StreamResponse.process_stream/2` callbacks from `Stream.Sink.stream_opts/0` (`stream/CONTEXT.md`); `current_model/0` returns `AgentState.llm_model` (a `"provider:model"` string, or `%{provider: atom, id: model, base_url: url, extra: map}` for a custom-endpoint account) and `context` is the whole `%ReqLLM.Context{}` by value.
`request_parameters/2` is literally `Keyword.merge([tools: tools], llm_gen_opts)` — no validation, filtering or extra keys at call time; `llm_gen_opts` is `state.llm_generation_params`, read from the struct once per turn (`ToolDispatch.do_turn/6`). Compression's stage-2 call reuses the same `llm_model` and keyword list and passes NO tools.
`llm_generation_params` is produced ONCE at scheduler admission by `Config.Schema.LLM.profile_generation_params/1`: at most `:temperature :max_tokens :reasoning_effort :top_p :top_k :frequency_penalty :presence_penalty :provider_options :api_key` (nils omitted, model-constraint filtered, `api_key` appended last and resolved once — a credential is frozen per agent, while an OAuth `oauth_file` rides as a PATH ReqLLM re-reads per request).
ReqLLM adds `max_tokens` from the catalog output limit when the request omits one, plus `stream: true`, and nothing else; unknown option keys are NOT silently dropped (`NimbleOptions.validate!` rejects them), provider-schema keys are auto-hoisted into `:provider_options`, and `@internal_keys` (`:api_key :auth_mode :oauth_file :base_url :req_http_options …`) bypass validation.
Request identity is FROZEN at registration, never varied per request: `prompt_cache_key`/`session_id` are attached ONCE by `Config.Schema.LLM.with_cache_identity/3` INSIDE the account's `provider_options` (provider-gated — `:openai` key only, `:openai_codex` key + session — and an explicit account value always wins), so every turn/retry/compression call of that agent shares one routing key; the only other Genesis-added option is `provider_options: [store: false]` for a NATIVE OpenAI endpoint (static, model-derived). No `cache_control`, `user`, seed, option-level `metadata`, `include`, `telemetry` or per-agent `store:` exists, and the only `metadata` is EvoGit's per-message turn/timestamp/checkpoint tag, never encoded to the wire.
Tools ride the SAME keyword list (`tools:`), never a separate argument; the list is rebuilt every turn by `Turn.effective_tools/1` = `agent_module.available_tools()` ++ the per-run `skill_schemas` (loaded once by `Session.Setup.build_initial_state/3`), minus subagent tools at max depth — a literal ordered list (`Tools.schemas/0` + `SubagentSchemas.schemas/1`), stable across turns unless a call-time config gate (`search_enabled`, `lsp_enabled`) flips mid-run.

## LLM Request Retry Mechanism (3 layers)
**Layer 1 — EvoGit outer loop (`call_llm_with_retry/5`).** MANUAL recursive attempt loop: first attempt index 0, no initial sleep, attempts = `max_retries + 1` from `agent_state.max_retries` / `[scheduler] max_retries` default **15**. Each attempt runs inside `AgentScheduler.with_llm_slot/2` for ONE `stream_text` + `process_stream`, released (`after`) BEFORE any backoff; inside the slot a `Logger.warning` pairs with `ReqLLMPool.excess_queuing_error?/1` → `bump_for_excess_queuing/2`. The agent keeps its turn and context across attempts; parameter NAMES log per attempt at `Logger.debug`.
- **Classification** (`handle_llm_failure/7`): `TruncationFeedback.classify_model_exhaustion/1` on the RAW reason plus `LlmError.non_retryable?/1` on the unwrapped struct, precedence model-exhaustion → non-retryable → attempts exhausted → ordinary transient; exhaustion always wins, and because the class check is raw-reason-based a wrapped 402 without a balance/quota phrase takes the ordinary transient path.
- **Exhaustion, attempts remain**: `report_llm_error(agent_id, class, model_exhaustion_delay(attempt + 1))` then RECURSE IMMEDIATELY with no agent-side sleep — the multi-hour wait is the scheduler's per-model backoff queue (cancel-safe). **Ordinary transient**: `:timer.sleep` of an exponential schedule from the `:llm_retry_backoff_base_ms` seam (default 1_000 ms), doubling, capped at 60_000 ms, ±10% jitter. **Exhausted**: a non-nil `class` seeds a fresh model-wide backoff via `model_exhaustion_delay(15)`, then `{:error, reason}` reaches `prompt_until_tools_or_limit/6`, which **RAISES** `"LLM request failed after N retries"` → agent crash → scheduler crash-retry (`[:scheduler, :agent_max_retries]` default 3); exceptions propagate immediately (no `rescue`).
- **Fail-fast on a non-retryable rejection**: a deterministic 4xx (HTTP 400, Z.AI code 1210, `retryable: false`) returns the terminal `{:error, {:llm_request_rejected, message}}` IMMEDIATELY after the first failed attempt — no sleep, no further attempt, no scheduler backoff — with ONE `Logger.error`. The message is `LlmError.format_failure(reason, params: <the exact keyword list handed to ReqLLM.stream_text/3>, model: <spec>)` with the spec from the private TOTAL `diagnostic_model_spec/0`; `prompt_until_tools_or_limit/6` has a pass-through arm (the `raise` stays for every other `{:error, reason}`) and `do_turn/6` a matching arm returning `{:error, terminal}` — NOT the grace path or `handle_protocol_violation/5` — so the task persists `:failed`. `retry_intent/1` appends `" (non-retryable — failing fast)."`
**Layer 2 — ReqLLM inner retries** (inside each `stream_text/3`): `ReqLLM.Streaming.Retry`, `max_retries` default **3** (a per-profile generation param); only HTTP 429 (delay from `Retry-After` seconds→ms; missing/unparseable/zero → 1000 ms) and transport errors BEFORE any body data (`data_received?: false`; `pool_not_available` → 250 ms, `closed`/`timeout`/`econnrefused` → 0 ms) are retried — never 5xx/other statuses, and nothing once streaming started. Slot acquisition stays a blocking purgeable `request_llm_slot` call released in `after`, so both backoff sleeps happen while the slot is FREE and a paused scheduler gates the next attempt.
**Layer 3 — scheduler per-model backoff**: `AgentScheduler.report_llm_error/3` → `Slots.handle_report_llm_error/4` sets `llm_backoff_until[model_id] = now + backoff_ms` for BOTH `:rate_limit` and `:insufficient_balance`, re-queues that model's waiting agents and schedules `:retry_llm_waiting`; a nil/unknown class is a no-op, expired backoffs clear on any grant path, and the scope is per `model_id`, NOT global — detail `../agent_scheduler/CONTEXT.md`.

## First Message Construction (objective → LLM) — single choke point
The objective (`AgentState.objective`, a plain `String.t()`) enters the conversation ONLY inside the first **user** message, built in `Session.Setup.build_initial_state/3`.
- **Context-tree chain** (`build_dynamic_context/1` → `EvoGit.Core.ContextNode.build_context/2` over `hierarchy_nodes/3` + `load/3`): the `# Context Tree` body is the repo-root→node ANCESTOR chain only (`"./"` … `"<node_path>"`, inclusive, NEVER children), built by `Path.split/1` + `Enum.scan`; non-directory paths are skipped, absolute/`..` paths yield `{:error, :invalid_path}`, and no CONTEXT.md at all yields `"Current Path: '<node_path>'."`. The chain is re-read from DISK at run start AND on every compression refresh, so it is the only view of on-disk CONTEXT.md changes.
- `combined_prompt` = `context_block(context_body)` joined with `objective_block(objective_body)` via `"\n\n---\n\n"` (`<context>…</context>` / `<objective>…</objective>`; a blank objective → `""`). `build_initial_messages/4` returns `[system, user]` via `ReqLLM.Context.new/1`, system = `agent_module.system_prompt()` only. No attachments / non-root / repo-less → the legacy plain-binary `user(combined_prompt)` fast path (byte-identical); a ROOT agent with attachments → `user([text | media parts])`.
- Every turn receives the whole `%ReqLLM.Context{}` by value and messages are never re-assembled — every other site only APPENDS (turn warnings, pending drain, grace/recovery, nudges, tool results, compression refreshes).
- **`<context>` section order**: context tree → **delegation authority** (`build_authority_section/1`, pure `%{parent_id, repo_less, foreign_repos}`, never the pd; only for non-repo-less agents on tasks with non-primary foreign repos; ROOT = `AgentState.parent_id == nil`, equivalent to `SchedMeta.depth == 0`) → **foreign repos** (`build_foreign_repos_section/1`) → **repo notes** (`build_repo_notes_section/1`: the `## Git Submodules` note from `AgentState.repo_notes`, set by `Runtime.Helpers.load_repo_notes/2`, inherited by subagents; nil → `""`) → **quality guidance** (`build_quality_guidance_section/1`, ROOT only, via `EvoGit.QualityLevel.guidance/1`; `"balanced"`/absent/unknown, subagents and repo-less → `""`) → **background jobs** (`BackgroundJobNotice.section/1`) → the clock line LAST. Only the summarising refresh injects background jobs; message #1 never carries them.
- **`# Foreign Repositories` row shape**: one row per NON-primary repo — `| :<id> | <absolute root>` (`writable: true` appends ` (worktree: <abs persistent-worktree path>)`) `| <description or "(no description)"> |` — plus a fixed "Use absolute paths (e.g., `<first root>`)" line and, only when some repo is writable, a writable/read-view note; there is NO mode/read-only COLUMN and `base_sha` is NEVER rendered, so per-repo base vs HEAD is invisible to the model.
- The objective stays strictly `String.t()` and attachment bytes travel as a spec opt plus base64 in persisted task opts; **no objective-size truncation exists** — the only conversation limit is the window-relative compression trigger. `refresh_first_user_message/2` exists and is tested but compression does not use it, so `[system, first_user]` stays BYTE-IDENTICAL.

## Multimodal Content — three sites, one contract
Images/audio ride real req_llm content parts at THREE sites: the ROOT agent's first user message (`:attachments` task opt), an injected user message, and a TOOL RESULT. `EvoGit.Attachments` (`../attachments.ex`) is the single source of truth for content shape, the ≤4 attachments / ≤15 MiB raw caps, base64 at every data-plane boundary and `Attachments.message/1` — full contract: `../CONTEXT.md` ("Multi-Modal Content").
- **Node-side wiring**: `:attachments` reaches the root's first message ONLY (`build_initial_messages/4` gates on `parent_id == nil` AND a non-empty list; subagents and resume/merge follow-ups never inherit it), while **injected user messages have NO root gate** — `send_user_message/2` stores a binary VERBATIM or canonicalizes a map via `Attachments.message/1`, materialized by `build_injected_message/2` from `drain_and_inject_user_messages/1`.
- Per-step media accumulates: compression keeps recent tool media (last K turns VERBATIM) and collapses older tool media into `[... tool result media omitted ...]` per message; no built-in tool produces media today (`read` is text-only, `web_fetch` omits binary bodies, custom tools are string-only).
### Multimodal Tool Outputs (`EvoGit.Agent.ToolOutput`)
`%EvoGit.Agent.ToolOutput{text: String.t(), attachments: [EvoGit.Attachments.t()] | nil}` — STRING-keyed base64 maps, so it survives a node/`:erpc` hop and a Store.Codec round trip; accessors are the ONLY sanctioned surface: `new/2` (validates at CONSTRUCTION; `nil`/`[]` = no media), `wrap/1`, `text/1`, `with_text/2` (PRESERVES media), `media?/1`, `to_content_parts/1`.
- **Wrap boundary invariant (pinned)**: `OutputSanitizer`, `TruncationFeedback`, `DelegationHints` keep their BINARY-ONLY contract; wrap/unwrap happens ONLY in `agent/tool_dispatch.ex`. `sanitize_tool_result/3` runs the binary pipeline on the TEXT component only and COLLAPSES an all-text output back to a plain binary; `assemble_tool_result/3` is the ONE message-construction site (media → content-part LIST; else `ReqLLM.Context.tool_result/3`); error/timeout/crash paths stay plain strings and caps apply PER TOOL OUTPUT.

## Tool-Execution Crash Semantics (raises are CONTAINED in the tool task)
Each call runs in a LINKED `Task.async` inside `ToolRuntime.Executor.execute_tool_with_timeout/4` (hosted by the AGENT process in the serial phase, by a `Task.async_stream` worker in the parallel phase), and `execute_tool_task/4` wraps `Tools.execute/5` in `try/rescue/catch`: a raise → `{:tool_crashed, Exception.format_banner(:error, exception)}`, a throw/other exit → `{:tool_crashed, "<kind> <reason>"}`, both reaching the model as `"Error: Tool execution crashed: …"`; only `:normal`/`:shutdown`/`:kill`/`{:shutdown, _}` re-raise unchanged. The agent therefore SURVIVES a raising tool (`nil` yield = its own timeout arm), and `Tools.execute/5` has NO try/rescue around a tool implementation.
- **Timeout is a per-call WHOLE-CALL budget** (not idle) resolved by `resolve_timeout/4`; `apply_advertised_tool_timeout/4` raises it to `Tools.default_timeout_ms/1` when no USABLE explicit `timeout` was given (`explicit_timeout_arg?/1` recognises every duration shape and only a positive one counts), except `job_output` where the advertised default is a FLOOR even against an explicit argument; write/sudo `elixir_eval` calls are floored to `CommandApproval.timeout() + 30_000` and still capped by `max_tool_timeout`. Evaluator `timeout_ms` only controls the inner engine (≤ 5 s plus bounded cleanup), and read/default/invalid tiers get no approval floor.
- `Task.shutdown/2` unlinks before killing (link-safe), and **timeout excludes slot queueing and final rendering**: `with_tool_slot/2` is entered before `Task.async`/`Task.yield`, and `sanitize_tool_result/3` runs after the yield, outside that budget.
- **Direct-eval return contract**: successful output must be a binary, `%ToolOutput{}` or nil (`ToolOutput.wrap/1`), never an arbitrary evaluated term; render with explicit inspection limits INSIDE the tool, since post-yield rendering errors sit outside `execute_tool_task/4`'s containment boundary.
- The generic sanitizer strips invalid UTF-8/ANSI/progress artifacts and clips output but does NO secret redaction, and oversized sanitized output can spill in full to the task scratch dir — truncation is not a confidentiality boundary.
- **NO escalation to the app**: the per-exchange worker is `Task.Supervisor.async_nolink(EvoGit.TaskSupervisor, …)` under its session — monitor-only and `:temporary` (the session is `restart: :temporary` too), so OTP never counts a worker exit toward restart intensity; the scheduler crash-retries (`agent_max_retries` 3) then fails it, so a tool failure is NEVER fatal.

## Tool Dispatch Flow & Turn-Loop Contract
- `effective_tools/1` = `agent_module.available_tools()` `++ skill_schemas`, minus subagent tools at max depth; the macro default `available_tools/0` = `Tools.schemas() ++ SubagentSchemas.schemas(__MODULE__)` (no completion tool exists).
- **The per-agent whitelist grants SCHEMAS ONLY — there is NO runtime membership filter**: an unknown name falls to `execute_tool/5`'s catch-all → `EvoGit.CustomTools.execute/3` (a configured custom tool wins over a same-named dynamic skill) → dynamic-skill lookup → `"Error: Unknown tool '<name>'. Did you mean '<closest>'? Available tools: ..."` (`String.jaro_distance/2` ≥ 0.7). A hallucinated name just takes that path; **a protocol violation is an `:empty` turn ONLY**, while zero tool calls with usable text is an IMPLICIT COMPLETION. Repo-less consequence: dispatch is by literal name, so a non-write tool outside both `@write_tools` and the agent's list WOULD run (`skill_*` readers; `WebSearch.execute/3` has NO runtime `search_enabled` gate).
- **Execute-time gate chain** (`Tools.execute/5`, sole call site `ToolRuntime.Executor.execute_tool_task/4`): `run_command` refusal → map args (or JSON-string-decoded) → alias normalization → reserved `elixir_eval` route with tool-owned runtime authorization → `maybe_block_repo_less/5` → `maybe_block_read_only_foreign_repo/5` → `execute_tool/5` plus custom/skill fallback. `write_call?/2` = `write_tool?/1` OR a shell background start (`true`/`"true"`), and normalization precedes both role guards so aliases cannot bypass them.
- **Flow**: `do_turn/6` → `prompt_until_tools_or_limit/6` → `process_llm_response/7` (`dedupe_and_sync`, turn-tag context — no ETS write; the turn is published by `:checkpoint`) → a text reply finishes via `Completion.Builder.finalize/2`, or yields `{:yield, state, text}` WITHOUT finalizing for an `:interactive` agent; tool calls go `process_tool_calls/3` → `process_regular_tool_calls/3` → partition subagent vs standard via `subagent_module_for` → `batch_execute_tools/4` → results re-sorted by index in `continue_after_tools`. **One LLM response = ONE blocking batch**: every `tool_calls` entry runs synchronously and the loop returns to the LLM only after all results are appended as `:tool`-role messages; a write/sudo `elixir_eval` BLOCKS its serial tool task (holding its tool slot) while approval is pending.
- **Every tool call gets a result**: `{:error, reason}` → `"Error: #{inspect(reason)}"`, crash → `"Error: Tool execution crashed: ..."`, timeout → `"Error: Tool execution timed out after ..."`, unknown name → `"Error: Unknown tool ..."`; `dedupe_tool_calls/2` dedupes WITHIN one response by `:id` then `{name, args_map}` (NO cross-turn detection, NO call cap).
- **Injection points**: the ONE external one is `drain_and_inject_user_messages/1` at the top of every turn BEFORE the LLM call; the ONE internal one is `inject_background_job_notices/1` AFTER the drain and BEFORE `maybe_enter_cancel_grace/1` — it claims this owner's finished-but-unannounced jobs (`claim_finished_notices(owner_pid: self())`, exactly-once) and appends `BackgroundJobNotice.notice/1` as ONE turn-tagged `:user` message, SKIPPED during grace.
- **Delta events, no per-tool summary broadcast**: outputs live only in the session-owned context; watchers get push-only `{:tool_call, id, name}`/`{:tool_result, id, status}`/`{:turn, …}` deltas (`stream/CONTEXT.md`), while non-watchers see only the `:checkpoint` summary merge → `{:agent_updated, agent_id, changed_fields, node}`. Correlation is only `metadata[:turn]` + `metadata[:timestamp]` (`%ReqLLM.Message{}` has no EvoGit UUID).
- **Exact-code approval replaced legacy commands**: `elixir_eval` supersedes `run_command` — read needs no approval, write/sudo require per-call approval of the exact code via `CommandApproval.request_eval/5`, authority is revalidated before approval, after approval and after execution, and denied/timed-out approval never starts evaluation while committed effects cannot be rolled back. `Tools.execute/5` refuses `run_command` for ALL callers, while direct `RunCommand.execute/3` and `CommandShell.execute/1,2` stay compatible outside agent dispatch (the CLI uses `approval: :auto`). Detail: `tools/CONTEXT.md`.

## Repo Identity, Paths, Repo-Less Agents, Foreign Repos, TMPDIR & Archive
`Session.Setup` takes the scheduler's `dispatch_ctx` (a KEYWORD list; the `%AgentSpec{}` is only `Keyword.fetch!(ctx, :spec)`) with repo identity PRE-RESOLVED as ctx keys `:repo_root`, `:repo_id`, `:worktree_path`; primary root = `Worktrees.repo_root_from_worktree(spec.phylo_node.repo)` (strips `/.genesis/workers/`), foreign root = the `spec.foreign_repos` entry whose `id == spec.repo_id` (ID match, NEVER path matching). `%AgentState{repo_id, repo_root, foreign_repos}` is set once at registration, so `AgentState.repo_root` is the ROOT while pd `:repo_path` is the TRANSIENT worktree.
Worktree base = `spec.phylo_node.current_commit`; subagent phylo bases: same-repo = an explicit `commit_id` (rev_parse-validated) else the parent's live `%State{}.current_commit`, cross-repo = foreign `base_sha` → tracked `foreign_repo_commits` → foreign HEAD. Single-repo assumptions: ONE `:repo_path`/`:genesis_repo_root`/`:worktree_path` per agent, ONE base→final commit pair, ONE branch `evogit-agent-T<n>-A<m>`, and the init script runs only for `spec.repo_id == "primary"`.
- **Repo-path crash points**: `bind_worktree/2` requests its worktree via `WorktreeManager.create_worktree_for_agent/6` and RAISES `"Failed to create worktree..."` on error; repo-less `sync_current_commit_after_tools/1` (`:ok`) and `sync_and_get_current_commit/1` (`nil`) let `Completion.Builder.finalize/2` finish without git. A repo-backed agent instead gets unset `:repo_path` → `"repo_path not in process dictionary"`, a vanished worktree → `"Worktree vanished while agent was running (removed mid-run): ..."`, else `"Git rev_parse failed (#{code}): #{msg}"`; `batch_execute_tools/4` requires BOTH `:repo_path` and `:genesis_repo_root`, and `build_initial_state/3` validates `Path.join(repo_path, node_path)` → `{:error, :path_not_exist}`. The agent process NEVER chdirs (no `File.cd!`/`File.cd` in `lib/`); every git/shell call passes its directory explicitly (`Git.run(args, cd)`).
- **Repo-less agents**: `Process.get(:repo_less)` with `:repo_path` at the REAL source root (`SelfReflectiveSource.reference_path() || File.cwd!()`); write tools stay forbidden through `write_call?/2` on both argument paths, while `elixir_eval` is a separately authorized capability, not a relaxation. Dispatch uses `:repo_less_repo_path` (fallback `:repo_root`) for both pd roots, forces `attachments` nil, skips the path check, and the run is single-shot under `max_turns_root` (1000). Short-circuits: `sync_current_commit_after_tools/1` → `:ok`, `sync_and_get_current_commit/1` → `nil`, `base_commit` → `nil`, `ConflictState.refresh/1` → `[]`, `ForeignWorktree.sync_from_agent/0` → `:ok`, `build_authority_section/1`/`build_quality_guidance_section/1` → `""`.
- **Foreign repos**: a WRITABLE non-primary repo carries a persistent read view `<root>/.genesis/foreign_repos/<id>` beside its ephemeral spawn worktree (`ForeignRepo.worktree_path/1`); `ForeignRepo.resolve/2` intercepts that prefix BEFORE the generic `root` match, a RELATIVE spawn path keeps the PARENT's `repo_id` (never `"primary"`), and `build_subagent_specs/3` keys `ContextNode.load` AND the phylo clause on `same_repo?` — worktree leasing and `base_sha` precedence: `../agent_scheduler/CONTEXT.md`.
- **STALENESS HAZARD (READ SIDE)**: a non-nil task-level `base_sha` wins unconditionally over the parent's tracked map (pinned by `test/evo_git/agent/subagent_processing_test.exs`), masking intra-task progress — a later foreign spawn restarts there, a NESTED agent's spawn (empty own map) falls back to foreign HEAD, and a stale-seeded spawn can leave an advanced foreign commit unreachable from the reviewed branch.
- **Per-task scratch space (TMPDIR)**: one managed dir per TASK, installed by `Session.Setup.ensure_tmpdir/1` (`spec.opts[:task_tmpdir]` else `TaskTmpdir.ensure(meta.task_id, Process.get(:genesis_repo_root) || nil)`) then `put_current/1`, inherited by subagents and re-installed per batch — `:per_repo` falls back for repo-less so the source root never receives `.genesis/tmp`, and `bash` runs with `TMPDIR=<EvoGit.Sandbox.resolve_tmpdir()>`, which PREFERS `TaskTmpdir.current/0` (modes/path math/reclaim: `../sandbox/CONTEXT.md`).
- **Tool path scope is ASYMMETRIC**: WRITE tools (`file_write`, `file_edit`, `file_create`, `make_dir`, `context`) call `Shared.validate_file_scope/4` and reject paths outside `repo_path`, outside `node_path` or inside a read-only foreign repo (ALLOW-ALL for a `"./"` node path and a non-binary `node_path`; `read_context` has NO scope check), while READ/exec tools accept arbitrary paths (`EvoGit.Platform.safe_expand/2`) except `web_fetch` (no path) and `lsp`'s `path` (must resolve INSIDE the repo path) — exact rules: `tools/CONTEXT.md`.
- **Archive (per-agent, streaming)**: `Completion.write_archive_refs/7` (gated `archive && base_commit`) upserts the ONE `task_agent_archives` row per agent IN THE COMPLETING AGENT's process, then writes refs `refs/genesis/archive/T<task>-A<local>-start/-final` and the metadata note (`add_metadata_note/3`, gated on `base_commit` alone); nothing is buffered or carried in `%Result{}`/the report, an unknown task id skips the row, `started_at`/`completed_at` are ISO-8601 STRINGS, and credentials are NEVER archived (`:api_key` dropped at any depth) — shape/reads/paging: `../store/CONTEXT.md` + `../CONTEXT.md` (Archive), per-task lifecycle: `../task_registry/CONTEXT.md`.

## Constraints
- Every agent MUST `use EvoGit.Agent` and implement `system_prompt/0`; system prompts MUST NOT contain dynamic state, objectives or context trees (those are injected as user prompts), and a read-only agent restricts `available_tools/0` to read-only tools (completion is implicit, so no tool is injected by the macro).
- Tool schemas use the `ReqLLM.tool/2` format; agents commit before delegating subagents (the auto-commit fallback enforces it). **State discipline**: loop state is always a `%EvoGit.Agent.State{}`; **Result discipline**: completion produces `%Result{}` and consumers pattern-match on struct fields, not `Map.get/2`.
- Streaming is PUSH-ONLY (`./stream/`): never add a replay buffer, cursor or polling loop, and never broadcast the full context — a delta plus a monotonic `seq` and a bounded `snapshot/1` are the whole contract.

## Conversation Mutation Map & Prompt-Cache Prefix Stability
Between consecutive turns the conversation only GROWS by appends; existing messages are byte-stable EXCEPT two per-response rewrites and compression events.
- Message #1 (`[system, first_user]`) is FROZEN at run start (`build_initial_messages/4`), clock line included (`NaiveDateTime.local_now/0` at MINUTE granularity); every later CLOCK lives in an APPENDED refresh message, never in message #1.
- Appended at the END each turn, in order: the turn warning (`Exchange.Warnings.check_limit_warnings/1`), drained user messages (`Exchange.Pending.drain_and_inject_user_messages/1`), one `[NOTICE]` (`Exchange.Pending.inject_background_job_notices/1`), the assistant message (inside ReqLLM's response context), tool results + an optional merge-conflict note.
- Two rewrites hit the NEWEST assistant message only: `dedupe_and_sync/3` replaces its `tool_calls` when duplicates were dropped, and `compact_reasoning_details/1` merges streamed `reasoning_details` fragments into ONE entry; that merged value IS encoded into the next request (ReqLLM adds it whenever non-nil), so it must settle before the message's first send.
- Message `metadata` (`:turn`, `:timestamp`, `:checkpoint`) is LOCAL ONLY and never encoded on the OpenAI-compatible path (`include_metadata?` false by default), so turn tagging and timestamps cannot invalidate a provider cache prefix.
- Only compression mutates already-sent messages: stage 1 rewrites old tool-result content in place, `Recency` truncates retained tail content, and `drop_stale_refreshes/1` DELETES an earlier refresh message from the MIDDLE of the list before appending the new one — the one place where a mid-list message disappears.
- **Wire stability**: `request_parameters/2` is the whole per-request surface and `llm_generation_params` is fixed at admission, so nothing varies per turn; `prompt_cache_key`/`session_id` are fixed per agent run (attached once at registration inside `provider_options`), the only other Genesis-added option is `provider_options: [store: false]` for a NATIVE OpenAI endpoint, and NO `prompt_cache_options`/`prompt_cache_breakpoint`/`prompt_cache_retention` or per-agent `store:` exists.
- Reported cache hits are faithful (`cached_tokens`/`input_tokens`), so within one run the prefix is byte-stable: a low hit rate points at provider-side routing/TTL, at run-unique content in message #1 (per-agent worktree path + minute-granularity clock), or at compression events — never at per-turn prompt mutation.

## Known Issues
- **A grace-exhausted SUBAGENT's committed partial work is DISCARDED**: `{:error, :recovery_failed}` carries NO sha even though the `after` fallback / `maybe_recovery_auto_commit/1` committed the tree; `collect_mergeable_results/3` takes only `{:ok, %Result{commit_sha: sha}}`, `destroy_worktree/3` deletes its `evogit-agent-*` branch, the parent sees "exceeded its execution limit", and no archive refs are written — the 3-turn grace window is the mitigation, not a fix.
- **`Completion`'s metadata note and archive refs lag the reported `commit_sha` on a fallback-only commit**: written at the PRE-fallback sha while `run/3` refreshes `Result.commit_sha` to the POST-fallback HEAD.
- **Cost is recomputed by EvoGit; ReqLLM's reported cost is NOT trusted** (counts stay accurate): `Cost.apply_to_usage/3` overrides the three cost fields at BOTH sites (`ToolDispatch.update_turn_usage/2`, compression's `{:ok, response}` branch) and a `nil` recompute KEEPS the reported values; `total_cost` is TOKEN cost only and a `{provider, model}` TUPLE spec raises inside `ReqLLM.model/1`, contained by `Cost`'s `safe/3`; `reasoning_tokens` is not a `%Usage{}` field — `update_turn_usage/2` adds it into `state.total_tokens` and `Cost` maps that meter / the `token.reasoning*` prefix into `output_cost`.
- **Thinking text is DUPLICATED in a stored assistant message**: ReqLLM materializes it both as a `:thinking` content part (after `:text`) and as `message.reasoning_details`, and only `reasoning_details` is compacted — so **any consumer joining `message.content` parts without a `type == :text` filter renders thinking as the response** (`EvoDashWeb.AgentsLive.message_to_history_entry/1`, `HomeLive.Messages.message_text/1`).
- **LLM errors become abnormal agent exits only here**: the exhaust-all-retries raise in `prompt_until_tools_or_limit/6`, the `ContextCompression` `MatchError` on a non-fail-fast error (one call, no retry, no rescue), and the `with_llm_slot/2` raise on a non-`:ok` slot reply (`{:error, :cancelled}` from a force-kill/cancel purge); `do_turn/6` matches exactly FOUR shapes from `prompt_until_tools_or_limit/6`.
