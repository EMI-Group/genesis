# Sandbox — Multi-Platform Sandbox Backend

## Intent
Provides platform-specific sandboxing for agent-executed commands. Dispatches to the appropriate backend based on `EvoGit.Platform.sandbox_backend/0`.

## Routing Table
None — leaf directory (modules: `sandbox.ex`, `behaviour.ex`, `helpers.ex`, `linux.ex`, `bwrap.ex`, `macos.ex`, `none.ex`). Note: `EvoGit.Sandbox` dispatcher itself lives at `lib/evo_git/sandbox.ex` — a SIBLING FILE (outside this node; read-only for agents here). Test suite is at `apps/evo_git/test/evo_git/sandbox/` — also a sibling node (read-only from here; escalate test-file changes to the parent).

Gate: `active?/0` (enabled + dev-env build not failed); `enabled?/0` is the static capability check |

## macOS SBPL Profile — Root-Readable Reads + Deny-List Policy

`generate_profile/2` (`macos.ex`) emits `(deny default)` with READS allow-by-default at the ROOT: `(allow file-read* (subpath "/"))` makes the whole filesystem readable so user-installed tools work anywhere. Protection for sensitive locations comes from the deny-read list (SBPL deny precedence: denies win over allows). Writes are deny-by-default with an explicit allow list. The specific read rules below (nix, home, host `$TMPDIR`, vendored git, file-read-metadata, ssh literals) are REDUNDANT under the root-wide read allow but intentionally KEPT as a safety net (belt-and-suspenders) — see `macos.ex` `generate_profile/2`. Emitted rule groups, in order:

1. `(version 1)` / `(deny default)`
2. **Root read allow**: `(allow file-read* (subpath "/"))` — the WHOLE filesystem is readable so user-installed tools work anywhere (Homebrew `/opt/homebrew`, Intel `/usr/local`, `/Applications`, custom `/opt` installs, nix, asdf/mise); reads do not need per-tool-path rules. Deny rules still win (SBPL deny precedence); WRITES are NOT covered (writes stay deny-by-default)
3. **Nix** (only when `Nix.enabled?()`): read + write for `/nix/store`, `/nix/var`
4. **Repo**: read+write on `cwd` (worktree) and `<repo_root>/.git` — the git rule resolves linked-worktree `gitdir:` pointers (`.git`-as-file) to the COMMON git dir (see "macOS Git Commit Coverage" below)
5. **Tmp**: read+write on `Platform.tmp_paths()` (`/tmp`, `/var/tmp`)
6. **Genesis dirs**: read+write on `Platform.config_dir()` + `Platform.data_dir()` (macOS: `~/Library/Application Support/genesis` — NOT under /tmp or repo)
7. **Home read allow** `(allow file-read* (subpath home))` — tool configs (`~/.gitconfig`, `~/.npmrc` — note `.npmrc` is deny-read) — then immediately after:
8. **Deny-read sensitive list** (deny takes precedence over allow in SBPL): `.ssh`, `.gnupg`, `.aws`, `.kube`, `.config/sops`, `.git-credentials`, `.netrc`, `.password-store`, `Library/Keychains`, `.npmrc`, `.pypirc`, `.docker`, `.gem` (credential stores; Linux InaccessiblePaths parity) — **plus system-level sensitive locations** (defense in depth under the root-wide read allow; both symlink spellings `/etc`↔`/private/etc` and `/var`↔`/private/var`): `/etc/ssh` + `/private/etc/ssh` (host SSH keys), `/var/root` + `/private/var/root` (root's home: `.ssh`, `.gnupg`, ...), `/etc/master.passwd` + `/private/etc/master.passwd` (password hashes), `/var/db/dslocal` + `/private/var/db/dslocal` (local user account DB), `/var/db/Keychains` + `/private/var/db/Keychains` (system keychains)
9. **SSH host-verification literal reads**: `(allow file-read-data (literal "<home>/.ssh/known_hosts"))` + `.ssh/config` — keeps `git fetch/push` over SSH working for public repos while private keys stay blocked; key-auth needs ssh-agent (`SSH_AUTH_SOCK`)
10. **Host `$TMPDIR` read** `(allow file-read* (subpath <expanded $TMPDIR>))` — CRITICAL: macOS per-user tmp is `/var/folders/...`, NOT under `/tmp`; temp files written via `System.tmp_dir!()` BEFORE the sandbox starts must remain readable inside, so a read rule for the expanded `$TMPDIR` is emitted. Skipped when `$TMPDIR` unset
11. `(allow file-read-metadata)` unqualified — stat/ls/glob on arbitrary paths under default-deny
12. **Writes**: build-cache dirs under home (`.cache`, `.local/share`, `.local/state`, `.cargo`, `.rustup`, `.mix`, `.hex`, `.npm`, `.yarn`, `.bun`, `.m2`, `.gradle`, `go`) — documented rationale: package managers/toolchains (`mix deps.get`, `npm install`, `cargo build`) must write caches; plus `/dev/null` + `/dev/dtracehelper` literals. **The cache-dir list is configurable via `[sandbox] write_paths`** — nil (unset) = this default list; set (even `[]`) = the user's list REPLACES it (see "Configurable Writable Paths" below)
13. **Deny-write sensitive list** (defense in depth): `.ssh`, `.gnupg`, `.aws`, `.kube`, `.config/sops`, `.npmrc`, `.git-credentials`, `.netrc`
14. **Process limit**: `(limit number #{@max_processes})` (`@max_processes 200`, module attribute, tunable) + `(allow process-exec)`, `(allow process-fork)`
15. **Network: `(allow network*)` — KEPT (default-allow), deliberate decision** — agents legitimately run `git fetch/push`, `mix deps.get`, `curl`, web tools; default-deny network breaks core workflows. The primary boundary is the tightened filesystem + process limits. **Future extension point (schema proposal, NOT yet implemented):** a `[sandbox] network_mode = "allow" | "deny"` TOML key belongs in `config/schema/` (outside this node) to gate this rule.
16. mach/sysctl/ipc: `(allow mach-lookup)`, `(allow sysctl-read)`, `(allow process-info*)`, `(allow signal)`, `(allow ipc-posix-sem)`, `(allow ipc-posix-shm)`

### Process-limit fail-safe — do not remove
The exact SBPL `limit` parameter syntax (`(limit number N)` vs `(limit (number N))`) **could not be verified without a macOS host** (CI is Linux; `sandbox-exec` unavailable). A wrong form would make `sandbox-exec` reject the WHOLE profile → every sandboxed command fails on macOS in `:auto` mode (the default). Therefore `run/4` and `run_with_partial/6` (enabled paths) implement a fail-safe: on non-zero exit with no cached decision, retry ONCE with `strip_process_limit(profile)`; on retry success, cache `true` at `:persistent_term` key `{EvoGit.Sandbox.MacOS, :process_limit_rejected}` and warn once; subsequent calls use the stripped profile directly. On healthy macOS: zero overhead (first attempt succeeds). On a rejecting macOS: one extra spawn once, then only the process-count limit is lost. **Keep this machinery even if the syntax is confirmed on real macOS** — it is cheap insurance. `generate_profile/2` still emits the limit; the fallback only catches rejection.

### Real-macOS validation points (unverifiable on Linux CI)
- `sandbox-exec -p` acceptance of the FULL profile (all rules incl. `(limit number 200)`)
- `sandbox-exec -p` acceptance of `(allow file-read* (subpath "/"))` — the root-wide read rule is unvalidated syntax (CI is Linux)
- bash/dyld startup reads (covered by the root read allow; verify on real hardware)
- SSH literal allows vs deny-precedence: if strict deny-precedence shadows `known_hosts`/`config` literals, git-over-SSH host verification fails (then move the literals outside the `.ssh` deny-read subpath)
- `/tmp` → `/private/tmp` symlink aliasing (existing rules use literal `/tmp`/`/var/tmp`)

## macOS Git Commit Coverage

The `write_context`/`edit_context` commit path (`agent/tools/context.ex`) calls `EvoGit.sandbox_run(repo_path, "git", ["add", relative_path], repo_root)` + `EvoGit.sandbox_run(repo_path, "git", ["commit", ...], repo_root)` → `Sandbox.run/4` → `MacOS.run/4` wraps in `bash -c "git ... < /dev/null"` (macos.ex) → `sandbox-exec`. The CONTEXT.md file write itself is UNSANDBOXED `File.write` (context.ex). Both `do_context_write/5` and `do_context_edit/8` check git exit codes: `{output, 0}` on both add + commit → success message; a failing step returns `"Error: git add failed (exit N):\n..."` / `"Error: git commit failed (exit N):\n..."` so the LLM can retry/report.

The git rule resolves the REAL git metadata dir via `git_metadata_dir/2` + `parse_gitdir_pointer/3` (macos.ex): when `<repo_root>/.git` is a regular FILE (linked-worktree `gitdir:` pointer), the read/write rule subpath becomes the COMMON git dir (prefix before the LAST `/worktrees/` segment of the resolved target, computed via `:binary.matches`/`:binary.part` — NOT `String.split`, which is ambiguous when the path itself contains `worktrees`); when `.git` is a dir → literal `<repo_root>/.git`; repo_root nil + no `.git` dir → no git rule; repo_root nil + `.git` dir → literal `<cwd>/.git`. A vendored-git read rule is emitted when `EvoGit.Executable.resolve("git")` returns an ABSOLUTE path (desktop bundle, git off PATH): `(allow file-read* (subpath "<dirname of binary>"))` so the bundled binary + support files are readable (redundant under the root read allow, kept as belt-and-suspenders).

**Remaining caveats (by design):** `commit.gpgsign = true` breaks commits (git reads `~/.gnupg` → deny-read list) — documented, not addressed. Real-macOS smoke verification is still pending (incl. `sandbox-exec -p` acceptance of `(allow file-read* (subpath "/"))`) — CI is Linux, only pure-function `generate_profile/2` tests pin the output (see Test Strategy). Linux backend has the same `Path.join(repo_root, ".git")` shape (linux.ex:172-186) but NO default-deny reads (no ReadOnlyPaths/ProtectSystem in args, linux.ex:222-247) → harmless there; do NOT change it.

## Bwrap Backend — Filesystem-Only Isolation (bubblewrap)

`args/4` (`bwrap.ex`) emits the bwrap argv for Linux environments where `systemd-run` is unavailable or undesirable (containers/docker, systemd-less distros, sandboxed CI). It needs only a `bwrap` binary and either root privileges or unprivileged user namespaces — **no `evogit.slice` slice and no unit registry** (`ensure_initialized/0` is a no-op; the backend never touches `SandboxSlice`/`SandboxProcessRegistry`).

**Namespace shape** (verified against bwrap 0.11.2): `--unshare-user-try --unshare-ipc --unshare-pid --unshare-uts --unshare-cgroup-try` — exactly `--unshare-all` minus `--unshare-net`, spelled out so future bwrap versions adding namespaces to `--unshare-all` do not silently change the shape. user/cgroup use `-try` variants (bwrap skips them gracefully when the kernel/container blocks them) so the sandbox RUNS both as root in docker and as an unprivileged user with userns enabled. **`--unshare-net` is deliberately NOT used** — the network namespace is retained so `git fetch/push`, `mix deps.get`, `curl` and web tools keep working, matching both other Unix backends. `--die-with-parent` (SIGKILL the sandboxed command if bwrap or the BEAM parent dies) + `--new-session` (setsid runs in bwrap's MAIN process BEFORE forking → bwrap is session leader, pgid == bwrap's pid → the whole sandbox tree is one process group).

**Rootless podman degradation (`:degraded` mode — `--unshare-pid` dropped)**: in rootless podman containers (container root WITHOUT `CAP_SYS_ADMIN`, e.g. `podman run` as an unprivileged user / `--userns=keep-id`) `mount(2)` is kernel-denied, so the full argv always exits 1 (`Creating new namespace failed: Operation not permitted` / `Failed to make / slave` / `Can't mount proc on /newroot/proc: Operation not permitted`). The escape hatch is the NESTED USER NAMESPACE: `CLONE_NEWUSER` is allowed in the container, bwrap's existing `--unshare-user-try` creates one, and inside it the sandbox gains `CAP_SYS_ADMIN` so all bind/tmpfs/devtmpfs mounts work. The only remaining blocker: the kernel refuses to mount a FRESH procfs inside a NEW pid namespace created within a user namespace — so `--unshare-pid` + `--proc` always fails there. Empirically verified: the exact current argv MINUS `--unshare-pid` exits 0 (including `--proc` and `--dev`). `probe_capability/0` detects this at runtime (runs the full argv against a trivial `true`; on failure retries with `--unshare-pid` removed): exit 0 → `:full`, pid-less exit 0 → `:degraded`, else `:unusable`; exceptions (missing bwrap) → `:unusable`. `capability/0` caches the probe result in `:persistent_term` (`{EvoGit.Sandbox.Bwrap, :capability}`) with an override seam `Application.get_env(:evo_git, :bwrap_capability)` (any of `:full | :degraded | :unusable | :unknown`) — both skip probing in the test env (`@mix_env == :test`) and `capability/0` also skips when no `bwrap` binary is on PATH. In `:degraded` mode `args/4` emits the SAME argv with `--unshare-pid` REMOVED (everything else identical); `:full`/`:unknown`/`:unusable` keep the current shape. `enabled?/0` in `:auto` mode = `Platform.bwrap_available?() and capability() != :unusable` (a `:degraded` host still counts as usable — filesystem isolation remains). The pid-namespace timeout-cleanup guarantee is absent in degraded mode; the process-group kill still works unchanged (`--new-session` setsid is independent of `--unshare-pid`).

**Filesystem layout (order matters)**: `--ro-bind / /` first (whole root read-only — "everything readable, writes restricted", same posture as `ProtectSystem=strict` and the macOS root read allow), `--dev /dev`, `--proc /proc`, `--bind-try` per `Platform.tmp_paths()` (writable), `--bind-try` writable binds (cwd, resolved `[sandbox] write_paths`, `/nix/store` + `/nix/var` when `Nix.enabled?()`, git metadata dir), then `--tmpfs <home>/<dir>` deny overlays LAST (after the ro-bind so they override it — bwrap's replacement for `InaccessiblePaths`; bwrap has no "inaccessible" primitive). `--bind-try` (not `--bind`) makes missing writable-path sources skip the mount op entirely (`ALLOW_NOTEXIST` + `ENOENT` → `continue` in `setup_newroot`, verified in the 0.11.2 source) — exactly systemd's `ReadWritePaths=-` semantics. The deny `--tmpfs` mounts are safe for non-existent dirs (bwrap mkdir_with_parents the destination). Deny list: 12 home-relative dirs (`.ssh`, `.gnupg`, `.aws`, `.kube`, `.config/sops`, `.git-credentials`, `.netrc`, `.password-store`, `.docker`, `.gem`, `.npmrc`, `.pypirc` — superset of linux.ex's 8, mirrors the macOS deny-read list minus `Library/Keychains`).

**Environment handling**: bwrap inherits the caller env (unlike `systemd-run --user`), so `PATH`/`HOME`/`NIX*`/`SSL_CERT_FILE` flow through WITHOUT injection. Explicit `--setenv` only where needed: `TMPDIR` → `EvoGit.Sandbox.resolve_tmpdir()` (on systemd desktops `$TMPDIR` is `/run/user/<uid>`, read-only inside), and the full `EvoGit.GitEnv.git_env_list(cwd)` when the original executable is a git command (`GitEnv.git_command?/1`). The BEAM process does NOT carry the GitEnv-resolved identity vars, and GitEnv's `"Genesis"`/`"noreply@evogit.ai"` fallback would NOT apply inside the sandbox — without injection, commits in unconfigured repos would fail with "Please tell me who you are". ⚠️ **GOption constraint**: bwrap's option parser STOPS at the first non-option argument (empirically verified — `bwrap --ro-bind / / true --bogus` reports no "Unknown option"), so ALL `--setenv` args MUST precede the command; `run/4`/`run_with_partial/6` prepend `git_env_args/1` before the `args/4` result for this reason.

**Timeout handling**: no systemd unit to stop, so `run_with_partial/6`'s enabled path owns a `Port` directly (via `EvoGit.Sandbox.None.resolve_executable("bwrap")` — Port.open does no PATH search), reads the OS pid (`:erlang.port_info(port, :os_pid)`), redirects output to a temp file, and on timeout kills the whole sandbox: `kill -TERM -<pgid>` → 100ms grace → `kill -KILL -<pgid>` (negative pgid = bwrap's own pgid, session leader), then a direct `kill -KILL <pid>` as belt-and-suspenders (killing bwrap triggers `--die-with-parent`; and because the sandboxed command is PID 1 in its pid namespace, its death makes the kernel SIGKILL every remaining namespace member — this also catches daemonized grandchildren that escaped the process group). Partial output is recovered from the temp file via `Helpers.read_tempfile/2`; the `{:timeout, partial <> "\n[TRUNCATED due to timeout]"}` contract matches the other backends.

**Scope**: filesystem-only isolation — **no resource limits and no syscall filtering** (bwrap has no systemd-equivalent CPUQuota/MemoryMax). Validated against bwrap 0.11.2; real execution requires a host where `mount(2)` works.

## Configurable Writable Paths — `[sandbox] write_paths`

Linux (`args/4` → `-p ReadWritePaths=-<path>`), Bwrap (`args/4` → `--bind-try <path> <path>` writable bind), and macOS (`generate_profile/2` → `(allow file-write* (subpath "<path>"))`) resolve the writable cache-dir list from `EvoGit.Config.resolve([:sandbox, :write_paths])` (schema key `:list_of_strings`, default `nil`):

- **`nil` (unset)** → the built-in default cache-dir list (`.cache`, `.local/share`, `.local/state`, `.cargo`, `.rustup`, `.mix`, `.hex`, `.npm`, `.yarn`, `.bun`, `.m2`, `.gradle`, `go`, home-relative).
- **set (even `[]`)** → the user's list REPLACES the default cache-dir list; `[]` disables the cache-dir write paths entirely.

**Path convention** (per entry): `~`-prefixed → `System.user_home!()` (e.g. `~/cache` → `<home>/cache`, bare `~` → `<home>`); absolute (leading `/`) → used as-is; relative → joined to `System.user_home!()` (the same base the defaults use). `Path.expand` is deliberately NOT used — env substitutions like `$HOME` are NOT expanded (a `$HOME/x` entry is treated as a relative path component).

**Structural paths are ALWAYS appended** after the cache-dir list — they are required for the sandbox to function, NOT part of the user-configurable list: Linux appends `cwd`, `Platform.tmp_paths()`, nix `/nix/store` + `/nix/var` (when `Nix.enabled?()`), and `<repo_root>/.git`; Bwrap emits writable `--bind-try` for `cwd`, `Platform.tmp_paths()`, nix store/var, and the git metadata dir (linked-worktree `gitdir:` pointers resolved to the COMMON git dir via `git_metadata_dir/2` + `parse_gitdir_pointer/3` — same logic as the macOS backend; bwrap binds are per-path, not per-tree); macOS always grants cwd, tmp paths, nix, repo `.git`, and genesis dirs in their own profile groups.

**Deny lists are NEVER affected** — the config replaces only the ALLOW/write list: Linux `InaccessiblePaths` (sensitive-dir deny), the Bwrap `--tmpfs` deny overlays, and the macOS deny-read/deny-write sensitive lists stay exactly as-is.

Implementation: all three backends define a `@default_cache_dirs` module attribute (the platform-specific defaults, kept local — they may diverge later) + delegate the shared path-resolution logic to the single public `EvoGit.Sandbox.Helpers.resolve_write_paths/3` (`config_paths, defaults, home`): `nil` config → defaults joined to home; set config (even `[]`) → the user's list replaces defaults. This follows the node constraint that shared helpers live in `Helpers` rather than being duplicated per backend.

## Windows / None Backend — No-Sandbox Gap (Known Issue)

**Status**: `EvoGit.Sandbox.None` is the fallback backend for Windows and unsupported platforms. It provides **no OS-level isolation** — a known, documented gap, not an oversight. The timed path has one minimal hardening (process-tree kill); the rest requires Windows APIs unreachable from pure Elixir.

**What Windows execution currently provides:**
- `run/4` — direct `System.cmd(executable, args, cd: cwd, stderr_to_stdout: true, env: git_env)`: **cwd confinement** via `cd: cwd` (raises if dir missing); **no command-injection surface** (args passed as an ARRAY — deliberately NO shell wrapper / `bash -c` string assembly on Windows); **no timeout — by contract** (`run/4` is unbounded; `git add`/`git commit` callers like `EvoGit.sandbox_run/4` rely on it — do NOT add a default timeout); git identity/`LC_ALL`/`GIT_EDITOR` injected via `EvoGit.GitEnv.git_env_list/1`. **PowerShell args**: `["-Command", cmd]` args for powershell/pwsh are transformed to `-EncodedCommand` (`EvoGit.Powershell.transform_args/2`) before the `System.cmd` call, and the returned `output` is run through `EvoGit.Powershell.decode_output/1` (BOM-aware, idempotent) before returning.
- `run_with_partial/6` (Windows clause): runs via a directly-owned `Port.open({:spawn_executable, ...})` mirroring `System.cmd`'s exact port options (`:binary, :exit_status, :hide, :stderr_to_stdout`, args/cd/env), so the OS PID is readable via `Port.info(port, :os_pid)`. **On timeout the WHOLE process tree is killed** via `taskkill /PID <pid> /T /F` (kills cmd.exe/powershell grandchildren, not just the direct child). **Partial output accumulated up to the timeout is returned** (`{:timeout, partial_output}`, truncated to `max_bytes`). Graceful degradation: if the OS PID hasn't materialized when the timeout fires (rare), falls back to `Port.close/1` (direct child only). Executable resolution uses `resolve_executable/1` (absolute paths as-is; else `System.find_executable/1` PATH/PATHEXT — finds MinGit bash; nil → `:erlang.error(:enoent)` to preserve `System.cmd/3` semantics). **PowerShell args**: the same `EvoGit.Powershell.transform_args/2` defense-in-depth runs at the top of the Windows clause (before executable resolution/port opening), and the accumulated output is decoded via `EvoGit.Powershell.decode_output/1` in BOTH return branches (`{:ok, ...}` and `{:timeout, ...}`) before `Helpers.truncate_output` is applied.

### PowerShell Invocation — `-EncodedCommand`

Powershell commands run via `-EncodedCommand` args built by the pure module `EvoGit.Powershell` (`lib/evo_git/powershell.ex` — single source of truth for arg building + output decode; Linux-tested in `apps/evo_git/test/evo_git/powershell_test.exs`). `Platform.shell_args/1`'s Windows clause returns `invoke_args/1` (the ShellTool + worktrees paths), and both `none.ex` Windows clauses additionally run `transform_args/2` as defense-in-depth so direct callers passing `["-Command", cmd]` are covered.

**Why `-EncodedCommand` (do not re-investigate):** `powershell.exe -Command <script>` spawned from Erlang is unreliable because PowerShell re-joins the raw command line and re-parses it as PowerShell code (standard Windows argv quoting does NOT apply) → quotes/escapes from Erlang's spawn (`Port.open`/`System.cmd` arg quoting) get mangled → PowerShell falls back to INTERACTIVE mode → closed/EOF stdin → immediate exit 0 with NO output. Secondary: PS 5.1 writes piped output using `[Console]::OutputEncoding` (OEM/UTF-16 code page), and `EvoGit.UTF8.ensure_utf8/1` treats the UTF-16LE BOM as invalid UTF-8 → empty valid prefix. The invocation therefore goes through `-NoProfile -NonInteractive -ExecutionPolicy Bypass -EncodedCommand <b64>` where `b64` = base64(`UTF-16LE`(`& { [Console]::OutputEncoding = [System.Text.Encoding]::UTF8; <script> } *>&1`)) — eliminates command-line parsing, forces UTF-8, merges all streams via `*>&1`. Elixir side: `EvoGit.Powershell.decode_output/1` (BOM-aware) applied at output collection.

**Residual risks (fixing them requires OS APIs):** arbitrary file-system read/write anywhere the user can access (no read-only paths); no CPU/memory/process-count limits; no kill-tree on `run/4` (unbounded by contract); no network isolation; no AppContainer/restricted token (children run with the user's full privileges).

**What a real Windows sandbox would require:** **Job Objects** — `CreateJobObject` + `SetInformationJobObject` with `JobObjectExtendedLimitInformation` (CPU/memory limits) + `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` (guaranteed kill-tree, replacing best-effort `taskkill /T`) — via a NIF or Erlang port program (Windows API not reachable from pure Elixir); **AppContainer / restricted token** — also NIF/port; **simpler alternatives**: run agent tool calls inside WSL2 or a Windows Sandbox/container as an external wrapper.

**Windows-only caveats worth preserving (do not "fix"):** MinGit bash used for skills scripts — keep PATH/PATHEXT resolution so it is found; the arg-array form avoids PowerShell's `<` input-redirection parser error (the Unix `bash -c "<cmd> < /dev/null"` wrapping must stay Unix-only; with `-EncodedCommand` the script is quoting-free so `<` never appears — input redirection must never appear in the PowerShell invocation); keep the `taskkill /PID <pid> /T /F` tree-kill on timeout and the UNBOUNDED `run/4` contract (git add/commit callers rely on it); the powershell `-EncodedCommand` transform applies ONLY to powershell/pwsh executables with the exact `["-Command", cmd]` 2-element shape (bash/git and already-encoded args are untouched — no double transform); `EvoGit.Powershell` (`lib/evo_git/powershell.ex`) is the single source of truth for the arg building + output decode.

**Testing note**: the Windows clauses are unreachable in the Linux/macOS test suite (`EvoGit.Platform.windows?/0` is runtime `:os.type()`, not injectable) — the port-based collect loop, `taskkill` path, and the `-EncodedCommand` transform/decode in `none.ex` are compile-checked only on Linux; the pure logic (arg building, transform matching, BOM-aware output decode) is Linux-tested via `apps/evo_git/test/evo_git/powershell_test.exs` (26 tests, `async: true`; the `shell_args/1` test in `apps/evo_git/test/evo_git_test.exs` branches on `Platform.os()` so it passes on both Linux and Windows). Windows runtime verification is required before further changes.

## Skills Script Execution Through the Sandbox

The skills executor (`lib/evo_git/skills/executor.ex` — outside this node) runs skill scripts via `EvoGit.sandbox_run(repo_path, "bash", [tmp_file | values], nil)` on Linux/macOS (script written under `EvoGit.Sandbox.resolve_tmpdir()`, values passed as positional argv `$1..$N`), and directly via `System.cmd(bash_path, [tmp_file | values], cd: repo_path, ...)` on Windows (argv-style, injection-safe; the `System.find_executable("bash")` guard returns the friendly "Install Git for Windows" error when bash is missing — a bare `sandbox_run` with missing bash raises `ErlangError(:enoent)`):
- **Dispatcher** — `run/4`/`run_with_partial/6` accept any executable+args; `Executable.resolve("bash")` returns `"bash"` when on PATH. Return shape `{output, exit_code}` is identical to the `System.cmd` result.
- **Linux**: script at `EvoGit.Sandbox.resolve_tmpdir()` (`/tmp`) is inside `ReadWritePaths` (`[cwd | Platform.tmp_paths()]`); `InaccessiblePaths` covers only the 8 sensitive home dirs; systemd defaults make everything else readable → works unchanged.
- **Bwrap**: script at `EvoGit.Sandbox.resolve_tmpdir()` (`/tmp`) is covered by the writable `--bind-try` per tmp path; `--ro-bind / /` keeps everything else readable; the 12-dir `--tmpfs` deny overlays hide credential stores → works unchanged.
- **macOS**: `resolve_tmpdir()` returns `/tmp` (the host `$TMPDIR` under `/var/folders/...` is NOT under the `tmp_paths` list, so it falls back to the first tmp path) → the script is covered by the tmp read/write rules (group 5). The host-`$TMPDIR` read rule (group 10) covers any caller that writes temp files via `System.tmp_dir!()` BEFORE the sandbox starts — if that rule is ever removed, such files break inside the sandbox. Optionally use `sandbox_run_with_partial/6` for a timeout (`{:ok, output, code} | {:timeout, partial}` — handle the different return shape).
- **Windows**: works via arg-array (no shell); keep the `System.find_executable("bash")` guard that returns the friendly "Install Git for Windows" error.
- `Helpers.shell_escape/1` safely quotes the script path in the assembled `bash -c` string; `Nix.wrap_command/2` accepts any executable name (compatible).

## Constraints
- All backends implement `@behaviour EvoGit.Sandbox.Behaviour` — the dispatch module (`EvoGit.Sandbox`) calls the behaviour callbacks uniformly
- Shared helpers live in `EvoGit.Sandbox.Helpers` — `shell_escape/1`, `read_tempfile/2` (with `read_truncated/3`), and `system_cmd/2`. Backends and `EvoGit.Nix` alias `Helpers` and delegate to these functions instead of duplicating them
- `shell_escape/1` is **security-sensitive** (command injection prevention) — it has exactly one definition in `EvoGit.Sandbox.Helpers`
- `EvoGit.Sandbox.Linux` depends on `EvoGit.SandboxProcessRegistry` (caller-process monitoring) and `EvoGit.SandboxSlice` (systemd slice management) — both started in Application supervision tree on Linux only
- `EvoGit.Sandbox.Bwrap` depends on NEITHER `EvoGit.SandboxSlice` NOR `EvoGit.SandboxProcessRegistry` — `ensure_initialized/0` is a no-op; it needs only a `bwrap` binary (+ root or userns). Its `--setenv` args MUST precede the command (bwrap's GOption parser stops at the first non-option argument)
- `EvoGit.Sandbox.MacOS` uses inline SBPL profile generation (no external template files). Emitted profile is PURE SBPL — no `#` comments inside (comment support in sandbox-exec not validated; all rationale lives in Elixir source comments)
- `EvoGit.Sandbox.None` is the fallback for Windows and unsupported platforms
- Callers use `EvoGit.sandbox_run/4` (delegates to `EvoGit.Sandbox.run/4`) — tool modules do not need to know about backends
- `EvoGit.Nix` is a standalone helper module (not a sandbox backend) — backends consult it to optionally wrap commands when Nix is enabled. It depends on `EvoGit.Config` (for the `[nix]` table and config dir) and `EvoGit.Platform` (`nix_available?/0`)
- When nix is active, Linux backend forwards all `NIX*` + `SSL_CERT_FILE` env vars via `--setenv` and grants read-write access to `/nix/store` and `/nix/var`. macOS backend adds `/nix/store` and `/nix/var` to its SBPL profile. Bwrap grants writable `--bind-try` for `/nix/store` + `/nix/var` and relies on env INHERITANCE (bwrap inherits the caller env, unlike `systemd-run --user`) — no NIX* `--setenv` needed. None backend wraps directly (inherits parent env). All four backends source the cached dev-env script (`nix print-dev-env` output) via `bash -c` rather than per-call `nix develop`. The `nix_paths`/`nix_env_vars` gating uses `Nix.enabled?/0` (static capability); the wrap decision uses `Nix.active?/0` (enabled + build not failed).

## Behaviour Contract
All four backends (`Linux`, `Bwrap`, `MacOS`, `None`) formally implement `@behaviour EvoGit.Sandbox.Behaviour`. The behaviour declares four callbacks:
- `enabled?/0` — whether sandboxing is available for this platform/mode
- `ensure_initialized/0` — lazily initialize backend resources (e.g. systemd slice); no-op when unneeded
- `run/4` — synchronous command execution returning `{output, exit_code}`
- `run_with_partial/6` — command execution with timeout + partial-output recovery returning `{:ok, output, exit_code}` or `{:timeout, partial_output}`

## Known Issues / Test Strategy
- **OTP 27+ `:os.find_executable/1` binary trap:** raw `:os.find_executable/1` raises `ArgumentError` on Elixir BINARY input on OTP 27+ (kernel 11.0.3) — `os.erl:verify_executable/3` does `Name ++ ".exe"` where `".exe"` is a charlist, and `binary ++ charlist` fails (`:erlang.++("c:/Windows/System32/powershell", ~c".exe")`). `EvoGit.Sandbox.None.resolve_executable/1` works around it: it uses `System.find_executable/1` (converts to charlist internally — never raises for binaries or charlists) plus Windows known-location fallbacks for `powershell`/`pwsh` (`WINDIR\System32\WindowsPowerShell\v1.0\powershell.exe`, `ProgramFiles`/`ProgramW6432`/`ProgramFiles(x86)` `PowerShell\7\pwsh.exe`). **Rule: never call raw `:os.find_executable/1` with an Elixir binary on OTP 27+; use `System.find_executable/1` (or this helper) instead.**
- **Test coverage gap:** `linux_test.exs` tests only `args/4` generation; `macos_test.exs` only `generate_profile/2` string assertions. NO test executes a real sandboxed command (systemd-run/sandbox-exec/bwrap) — the `@mix_env == :test` gates in `Linux.enabled?/0`/`Bwrap.enabled?/0` and the Linux-only CI make the real paths untested. All four backends' enabled paths are runtime-verified only.
- **Bwrap test strategy / real-execution caveat:** `bwrap_test.exs` (sibling test node) tests only `args/4` generation like `linux_test.exs`. Real bwrap execution requires a host where `mount(2)` works (bare metal, privileged container, or unprivileged-userns host) — worker/CI environments running inside a systemd-run unit with read-only `/` block `mount(2)` (`bwrap: Failed to make / slave: Operation not permitted`), so only flag-syntax validation is possible there. The argv shape was parse-validated against bwrap 0.11.2 and cross-checked against the bubblewrap 0.11.2 source (`setup_newroot` `ALLOW_NOTEXIST` skip semantics, `--unshare-all` = try-variants for user/cgroup, setsid-before-fork process model). **Rootless podman**: container root lacks `CAP_SYS_ADMIN`; the nested userns (`--unshare-user-try`) is the escape hatch (bind/tmpfs/devtmpfs mounts work inside it), but the kernel refuses a FRESH procfs inside a NEW pid ns created within a userns — so `--unshare-pid` + `--proc` always exits 1 there. `probe_capability/0` detects this (full argv, then pid-less retry) and `:degraded` mode drops `--unshare-pid`; the probe result is cached via `capability/0` (`:persistent_term`) with the `:bwrap_capability` app-env override — tests must use the override seam (probing is `@mix_env == :test`-gated and never runs in tests). **GOption gotcha for future work**: bwrap's option parser stops at the first non-option argument, so any new `--setenv`/option MUST be added before the command — never after.
- **Backend-selection invariant (`linux.ex` consistency, decision):** `EvoGit.Sandbox.Linux.enabled?/0` needs NO `EvoGit.Sandbox.backend() == EvoGit.Sandbox.Linux` guard. The dispatcher consults only the SELECTED backend's `enabled?/0` (`EvoGit.Sandbox.enabled?/0` → `backend().enabled?()`), and the slice/registry gates (`SandboxSlice.sandbox_enabled?/0`, `SandboxProcessRegistry.sandbox_enabled?/0`) are gated on `EvoGit.Sandbox.backend() == EvoGit.Sandbox.Linux` (sibling change) — so the systemd slice/unit-registry machinery only activates when Linux is the selected backend. A redundant guard in `Linux.enabled?/0` was considered and REJECTED: it would add a compile cycle (linux.ex → dispatcher) and could break existing linux tests' expectations; the invariant is already guaranteed by the dispatcher + gate design. The `@mix_env == :test` gate stays first in any case.
- **macos_test.exs is partially pinned** (test node, outside this node): it asserts `(deny default)`, deny-read rules for 8 of the 13 sensitive dirs (`.config/sops`, `.npmrc`, `.pypirc`, `.gem`, `Library/Keychains` NOT pinned), cwd/tmp r/w, `/repo/.git` r/w for the normal repo_root scenario, `(limit number 200)` exactly once, absence of nix rules, and all write_paths behaviors. Pinned (describe "linked-worktree git metadata resolution"): the root read rule `(allow file-read* (subpath "/"))`; the system-level deny-read rules (`/etc/ssh`, `/private/etc/ssh`, `/var/root`, `/private/var/root`, `/etc/master.passwd`, `/private/etc/master.passwd`, `/var/db/dslocal`, `/private/var/db/dslocal`, `/var/db/Keychains`, `/private/var/db/Keychains`); normal-repo literal `.git` rule; linked-worktree `gitdir:` pointer → COMMON git dir rule; nil repo_root + pointer → common dir; plain-dir `.git` + nil repo_root → NO git rule; vendored-git absolute-path read rule. **NOT pinned**: the remaining 5 sensitive deny-read dirs.
- **Windows clauses untested** (see Windows section) — compile-checked only on Linux.
- **`(limit ...)` syntax unverified on real macOS** — mitigated by the fail-safe retry (see above); validate on a Mac and, if the form is wrong, fix `generate_profile/2`'s emission (tests pin `(limit number 200)`).
