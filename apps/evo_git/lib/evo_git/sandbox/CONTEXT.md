# Sandbox — Multi-Platform Sandbox Backend

## Intent
Platform-specific sandboxing for agent-executed commands.
`EvoGit.Sandbox` (sibling `lib/evo_git/sandbox.ex`) dispatches to the active backend, chosen by `EvoGit.Platform.sandbox_backend/0` from `[sandbox] mode`/`[sandbox] backend` (`../config/CONTEXT.md`): systemd-run first, then bwrap, then no sandbox in `:auto`.
The target design, P0–P4 plan, non-goals, gotchas and test strategy live in `../../../docs/platform-sandbox.md` — read it before adding a backend or changing the policy spec.

## Routing Table
- `../process_manager/` → sibling node (`EvoGit.ProcessManager` + `.Handle`/`.Execution`/`.Control`/`.Stats`): the live-execution registry every backend ATTACHES its real OS handle to and SETTLES with the run's terminal fact; read-only from here.
No child directories — leaf directory (`background.ex`, `behaviour.ex`, `bwrap.ex`, `helpers.ex`, `linux.ex`, `macos.ex`, `nix.ex`, `none.ex`, `spec.ex`).
The dispatcher `lib/evo_git/sandbox.ex` and the test suite `apps/evo_git/test/evo_git/sandbox/` are sibling nodes (read-only from here; escalate test-file changes to the parent).

## One Policy Spec — `EvoGit.Sandbox.Spec`
`spec.ex` is the ONLY place that knows Genesis sandbox semantics: readable/writable roots, the canonical credential deny list, the default cache dirs, the git metadata dir, the managed per-task tmpdir, the Genesis config/data dirs, the `TMPDIR` read sources and the process limit.
Each renderer builds it (`Spec.build(:macos | :linux | :bwrap, cwd: cwd, …)`) and only expresses it — **one list, one builder, renderers only render**: no renderer may keep its own copy of a credential list, a cache-dir list or a path/config resolution.
`Spec.credential_paths/0` is the canonical ordered home-relative list (`.ssh`, `.gnupg`, `.aws`, `.kube`, `.config/sops`, `.git-credentials`, `.netrc`, `.password-store`, `.npmrc`, `.pypirc`, `.docker`, `.gem`) — 12 entries consumed by macOS deny-read/deny-write, systemd `InaccessiblePaths` and bwrap deny `--tmpfs`.
`Library/Keychains` is NEVER in that list: it is macOS-only and the macOS renderer appends it itself, immediately AFTER `.password-store` (deny-READ only, never deny-write).
Backend-specific config stays in the backend: `Linux` keeps `security_args/0` (`[:sandbox, :linux]`), `resource_args/0` + `get_process_resources/0` (`[:sandbox, :process]`, scheduler-config precedence, justified try/catch) and the nix wrapping; macOS keeps the `Library/Keychains` entry, the SBPL syntax and `strip_unverified_rules/1` + the rejection cache.
Each call site pins its own historical git-metadata input through the `git_metadata:` build option — systemd foreground passes `[Path.join(repo_root, ".git")]` (or `[]`), systemd detached passes `List.wrap(Helpers.git_metadata_dir(cwd, nil))` — so the two never silently unify.
`repo_root` is the agent's ORIGINAL repo root (the FOREIGN repo root for a foreign-repo agent, installed as `:genesis_repo_root`), while `cwd`/`repo_path` is always the agent's transient worktree — so the only repo-root-owned path any backend makes writable is the git metadata dir; the main working copy stays read-only.

## Rendering & kill primitives
- Linux `args/4` and `detached_args/5` BOTH delegate to ONE private `build_args/6` (`spec, executable, args, unit_args, mode_args, stdio_args`) so shared fragments cannot drift: `--user`, the unit args, `--slice=evogit`, mode args, `-q`, env/nix env, `WorkingDirectory=<cwd>` and `StandardInput=null`, stdio, then `security_args/0`, `resource_args/0`, the `ReadWritePaths` group, the `InaccessiblePaths` group, and finally `[cmd | args]`.
  `args/4` passes `unit_args=[]`, `mode_args=["--wait","--pipe","--collect"]`, `stdio_args=[]`; `detached_args/5` passes the `--unit=<name>` arg, `mode_args=[]` and the two `append:` stdio props.
  `--unit=<name>` never comes from `args/4`: `inject_unit/2` splices it right after `--user` in `run/4`/`run_with_partial/6`, using the name from `SandboxProcessRegistry.register/0` (`"evogit-run-<system_time_ms>-<unique_integer>"`).
  No `--scope` and no `--pty`: the default transient **service** unit is used, `--wait` blocks the client until exit, `--pipe` carries stdout/stderr, and `--collect` GCs the unit on termination — so the unit's state is queryable only WHILE alive, which is why `detached_args/5` omits `--collect`.
  `security_args/0` emits `ProtectSystem=strict`, `ProtectHome=read-only`, `ProtectKernelTunables`, `ProtectControlGroups`, the `SystemCallArchitectures`/`SystemCallFilter` set and `NoNewPrivileges` (each toggleable under `[sandbox.linux]`); `resource_args/0` emits `CPUQuota=`, `MemoryMax=`, `LimitNOFILE=`, `OOMScoreAdjust=` from `[sandbox.process]` when set (`[sandbox.resources]` sizes the slice) — keys/defaults: `../config/CONTEXT.md`.
- bwrap `args/4` builds `Spec.build(:bwrap, cwd: cwd, repo_root: repo_root)` and wraps the private `build_args/4` (`spec, executable, args, unshare_pid?`): `["--die-with-parent","--new-session"] ++ unshare_flags ++ ro-bind/--dev/--proc ++ tmp_bind_args ++ writable_bind_args ++ task_tmp_bind_args ++ deny_args ++ ["--chdir", cwd] ++ env_setenv_args ++ ["--", cmd | cmd_args]` — every option precedes the `--` separator.
- macOS: `run/4` spawns `System.cmd("sandbox-exec", ["-p", <profile>, "--", exec | exec_args], cd: cwd, env: [{"TMPDIR", tmpdir} | git_env])`; `run_with_partial/7` spawns the SAME argv through `Helpers.run_tracked_command/7`; SBPL from `generate_profile/3` (production calls the 2-arity form).
- None: `run/4` = `System.cmd(executable, args, cd: cwd, stderr_to_stdout: true, env: …)`; Windows `run_with_partial/7` = a directly owned `Port.open({:spawn_executable, resolved}, [:binary, :exit_status, :hide, :stderr_to_stdout, {:args, args}, {:cd, cwd}, {:env, Helpers.port_env(git_env)}])`; Unix `run_with_partial/7` = `Helpers.run_task_with_partial/9` (the same port shape around `bash -c <redirected cmd>`, nix-wrapped when active).

Kill/timeout primitives:
- Linux: the timeout shuts down the CLIENT `Task` only — the unit keeps running and is stopped asynchronously by `SandboxProcessRegistry.release(unit)` → `systemctl --user stop <unit>.service`; `run/4` has NO timeout (`--wait` blocks indefinitely).
- bwrap: `kill -TERM -- -<pgid>` → 100 ms → `kill -KILL -- -<pgid>` → `kill -KILL <pid>`; the negative pgid is valid because `--new-session` makes bwrap the session leader.
- Windows/none: `taskkill /PID <pid> /T /F`, pid from `Helpers.wait_for_os_pid/2`.
- macOS: `sandbox-exec` runs through the shared port runner, so a timeout kills the whole child tree via `Helpers.kill_process_tree/1` (TERM → 100 ms → KILL on the port child's group) and closes the port.
- Other long-lived spawns: the SSH remote daemon (its unit/launchd agent is created and removed by the `genesis_server` release's own `bin/genesis` CLI; Elixir only shells `<launcher> remote stop --unit genesis-remote-<id>` on a permitted re-bootstrap) and `Background`'s per-job units.

## Behaviour Contract
All four backends (`Linux`, `Bwrap`, `MacOS`, `None`) implement `@behaviour EvoGit.Sandbox.Behaviour`: `enabled?/0` (available for this platform/mode), `ensure_initialized/0` (lazy backend resources, e.g. the systemd slice; no-op when unneeded), `run/4` (synchronous → `{output, exit_code}`) and `run_with_partial/6` (timeout + partial output → `{:ok, output, exit_code}` | `{:timeout, partial_output}`).
`run_with_partial/7` is OPTIONAL: the same params plus `opts :: keyword()` with `:execution_id` (`"proc-<n>"`, a live `EvoGit.ProcessManager` record) and `:record_exit_status` (default `true`).
The dispatcher calls the 7-arity form only when the selected backend exports it (`Code.ensure_loaded?` + `function_exported?`), else the 6-arity form, so every lower arity keeps working unchanged.
Every backend's `/7` is its `/6` body plus ONE `Helpers.attach_execution/3` call where its OS identity is known, and it SETTLES that execution when the run ends; with `:execution_id` nil (or absent) both are no-ops.
Tracking is best-effort and observability-only: `attach_execution/3`, `record_exit/2` and `record_timeout/1` never raise, so a missing/restarting manager cannot fail, slow or alter a command.
`Helpers.run_task_with_partial/9` (the shared non-sandbox/Unix tail) owns a directly-spawned port, resolves the executable with `None.resolve_executable/1` (nil → `:erlang.error(:enoent)`, `System.cmd/3` semantics), publishes the real OS pid via `wait_for_os_pid/2` + `attach_execution/3`, and on timeout kills the whole process TREE before closing the port; `run_tracked_command/7` is the same primitive reused by the macOS `sandbox-exec` path.
No tracking or settlement is added for internal `rg`/git/skill invocations: threading happens ONLY when a caller supplies `:execution_id`.

## Foreground Execution Terminal Fact (settlement)
`Helpers.record_exit/2` finishes the tracked execution `:completed` with `reason: :exited` and the real OS `exit_code`; a NON-ZERO exit code is still `:completed`, because the tool call itself succeeded.
`Helpers.record_timeout/1` finishes it `:killed` with `reason: :timeout` and `exit_code: nil`.
Both funnel through ONE private `finish_execution/3`, so the `EvoGit.ProcessManager.finish/3` option shape lives in exactly one place.
Recording happens AFTER any kill (the Linux unit release, the bwrap/None tree kills), so the recorded fact describes a command that is actually stopped.
`:record_exit_status: false` suppresses the recording for a command that will be RE-RUN, so only the FINAL attempt's status becomes the outcome — the macOS unverified-rule retry is the only such caller.
A backend that cannot observe a status degrades to `exit_code: nil` on the same `:completed`/`:exited` fact.
Detached/background jobs are NOT settled here: their handle observation belongs to `EvoGit.BackgroundJobs` (sibling `background.ex`).

## Foreground Execution Tracking — attach and settle points
| Path | Handle attached | Settled by |
|---|---|---|
| `Linux` sandboxed | `%Handle{kind: :systemd_unit, unit: unit, backend: Linux}` immediately after `SandboxProcessRegistry.register/0` (the only place the unit name is known) | `record_exit/2` after `unregister/1`, or `record_timeout/1` after `release/1` |
| `Linux` non-sandbox, `Bwrap` disabled, `None` Unix, `MacOS` disabled | `:posix` handle carrying the bash child's REAL pid | inside `Helpers.run_task_with_partial/9` (after `wait_for_os_pid/2`) |
| `Bwrap` enabled | `:posix` with bwrap's own pid (`:undefined` → nil), right after `wait_for_os_pid/2` | `collect_output/6` |
| `MacOS` enabled | `:posix` with the `sandbox-exec` child's pid via `run_tracked_command/7` (no systemd → a pid is the only address) | `run_with_partial/7`'s own `record_result/2`; each `sandbox-exec` attempt runs with `record_exit_status: false` so the retry does not overwrite the outcome |
| `None` Windows | `%Handle{kind: :windows, os_pid: os_pid, backend: None}` after `wait_for_os_pid/2` (`:undefined` → nil) | `collect_windows_output/6` |

**Every foreground path carries an OS identity**: the record becomes `:running` WITH an `os_pid` (or a `unit`), so `ProcessManager.sample/2` reports real CPU/memory and pause/resume/signal reach the child; the only pid-less degradation is the pathological `:undefined` case (a child exiting within the poll window), and that record stays listed and finishable.

## Detached / Background Execution — `EvoGit.Sandbox.Background`
Background jobs (outliving the tool call that started them) go through `EvoGit.Sandbox.spawn_detached/1` / `kill_detached/1` / `detached_status/1`, answered for EVERY backend by `Background` — callers never branch on the backend (and `EvoGit.Sandbox.Behaviour` deliberately omits these: the detached path needs only per-backend argv + `enabled?/0`).
`spawn(spec)` takes `%{command, cwd, output_path, job_id}` (all four required non-empty binaries, else `{:error, {:invalid_spec, spec}}`) → `{:ok, handle} | {:error, term()}`.
A `cwd` that is not an existing directory answers `{:error, {:cwd_missing, path}}` on EVERY backend — validated before dispatch, because `Port.open/2` accepts a missing `{:cd, dir}` and the child would die before `exec`; `EvoGit.BackgroundJobs` maps it to "the working directory does not exist: <path>".
`output_path` and its parent are PRE-CREATED by the caller and never truncated: port-based backends append via the registry, systemd via `StandardOutput=append:` / `StandardError=append:`.
`handle` = `%{kind: :unit, unit, backend}` | `%{kind: :port, port, os_pid, backend}`; `status/1` → `{:running, nil} | {:exited, integer() | nil} | {:unknown, nil}`; `kill/1` → `:ok | {:error, term()}` (`{:error, {:invalid_handle, handle}}` otherwise).
`spawn/1` runs in the CALLER's process (the `EvoGit.BackgroundJobs` registry GenServer), so a `:port` handle's Port is owned by that registry — it receives `{:data, chunk}` / `{:exit_status, n}` and must keep draining them.
Every function is TOTAL: OS calls are wrapped in `rescue`/`catch` → `{:error, term()}` / `{:unknown, nil}` — nothing raises into the registry.
`spawn/1` reuses each backend's public argv builder, so env/isolation/writable-path grants match foreground execution exactly; a false `enabled?/0` (e.g. the `@mix_env == :test` gate) falls back to a plain shell child Port.
No PTY is used anywhere (pipes/files only), so a non-TTY stdout is BLOCK-BUFFERED: a program buffering its own output fills the file in CHUNKS, not line-by-line.

| Backend | Handle | Spawn shape | PRIMARY guarantee |
|---|---|---|---|
| `Linux` | `:unit` | transient user unit, argv from `Linux.detached_args/5` | the unit survives BEAM death by design; killed via `systemctl --user stop` then `reset-failed` inside `Task.start` (returns `:ok` immediately) |
| `Bwrap` | `:port` | `Bwrap.args/4`, inner command `<shell> <shell_args(command)>` (the RAW command); the registry appends the port stream to the output file | bwrap is a session leader and, in `:full` capability, the pid-namespace root, so killing it takes the whole tree; `--die-with-parent` covers BEAM death |
| `MacOS` | `:port` | `sandbox-exec -p <profile> -- <shell> <shell_args(cmd)>`, profile from `MacOS.effective_profile/2` | NO pid namespace — only the owner-process monitor + a tree kill, so a BEAM crash can leak a process |
| `None` | `:port` | `<shell> <shell_args(cmd)>` | no isolation at all — owner-process monitor + tree kill only, so a BEAM crash can leak a process |

EVERY `:port` handle kills via `Helpers.kill_process_tree(os_pid)` and reports liveness via `Port.info/1` (`{:running, nil}` while non-nil, else `{:unknown, nil}` — the real exit code arrives in the port message the registry owns); `kill/1` LEAVES THE PORT OPEN so the registry still receives the natural `{:exit_status, code}`, closing it directly only when no `os_pid` was ever observed.
The `:unit` stop is fire-and-forget (`stop_unit_async/1` → `Task.start`, so a caller has no handle to await); the test-only CALL-TIME seam `Application.get_env(:evo_git, :background_unit_stop_notify)` reports its completion — a `pid` receives `{:background_unit_stop_finished, unit}`, a 1-arity fun is called with the unit — sent AFTER both `systemctl` calls; unset in production (no-op), and `test/evo_git/background_jobs_test.exs` sets it to the test pid.
Only the systemd-run unit survives the BEAM, so its `status/1` stays queryable after a crash and a later boot can prove ownership from the unit name `genesis-job-b<beam_os_pid>-<job_id>` (`Background.unit_name/1`: `beam_os_pid` = `System.pid()`, `job_id` = the caller's `"bash-<n>"`, chars outside `[A-Za-z0-9_.:-]` fold to `_`).
`spawn_unit/1` makes ONE bounded blocking `receive` (`@systemd_run_timeout` 5_000 ms) for the systemd-run client's reply, then reaps via `Helpers.close_port/1`; non-zero status or timeout → `{:error, {:systemd_run_failed, captured_output}}` with the unit stopped so it never leaks.
**Boot sweep** — `sweep_stale_units/0` (total: never raises, always `:ok`) acts ONLY when the active backend is `EvoGit.Sandbox.Linux`: one `systemctl --user list-units --all --plain --no-legend 'genesis-job-*'` (stderr NOT merged; non-zero exit → no-op) → `parse_list_units/1` (pure, `@doc false`).
`inactive`/`failed` rows → `reset-failed` only; `active`/`activating`/`reloading` rows → `stop` then `reset-failed` ONLY when the owning BEAM pid from `beam_pid_from_unit/1` (pure) is NOT alive (`kill -0 <pid>`): a LIVE pid means another instance owns the job, an unattributable name is left ALONE, and a probe that cannot run counts as alive.
`status/1` on a `:unit` = `systemctl --user show <unit> -p ActiveState -p ExecMainStatus -p ExecMainCode` → `parse_systemctl_show/1` → `classify_unit_state/1` (both pure and public `@doc false`):
| `ActiveState` | `ExecMainCode` | Result |
|---|---|---|
| `active` / `activating` / `reloading` | any | `{:running, nil}` |
| `inactive` | `1` (exited) | `{:exited, ExecMainStatus}` |
| `inactive` | `2` (killed by signal) | `{:exited, nil}` |
| `inactive` | `0` or absent | `{:unknown, nil}` |
| `failed` | `2` | `{:exited, nil}` |
| `failed` | other | `{:exited, ExecMainStatus or nil}` — a failed exit, never a crash |
| unknown / missing / garbled, or a dead systemctl | — | `{:unknown, nil}` |

## macOS SBPL Profile — root-readable reads + deny list
`generate_profile/3` (`macos.ex`) emits `(version 1)` + `(deny default)` with READS allow-by-default at the ROOT and deny-by-default WRITES plus an explicit allow list; protection comes from the deny-read list (SBPL deny precedence: denies win). Rule groups, in order:

1. `(allow file-read* (subpath "/"))` — the whole filesystem readable; WRITES not covered.
2. Nix read+write (`/nix/store`, `/nix/var`) only when `Nix.enabled?()`.
3. A read+write PAIR on `cwd` (worktree, `spec.write_roots`) and on the git metadata dir, per SPELLING — linked-worktree `gitdir:` pointers resolve to the COMMON git dir (see § macOS Git Commit Coverage).
4. A read+write PAIR per `spec.tmp_paths` entry (`/tmp`, `/var/tmp`) and per SPELLING, plus the same for the managed per-task tmpdir.
5. A read+write PAIR per SPELLING on `spec.config_dir` + `spec.data_dir` (`~/Library/Application Support/genesis` — NOT under /tmp or repo).
6. `(allow file-read* (subpath home))` (tool configs such as `~/.gitconfig`), immediately followed by:
7. Deny-read credentials (deny beats allow): `spec.credential_deny_paths` in canonical order with the macOS-only `Library/Keychains` after `.password-store`, then `spec.deny_paths` — `/etc/ssh` (host keys), `/var/root`, `/etc/master.passwd`, `/var/db/dslocal`, `/var/db/Keychains` — in both symlink spellings. Each credential rule carries BOTH filters (`(deny file-read* (literal "<p>") (subpath "<p>"))`, repeated per resolved spelling) because SBPL OR-combines a rule's filters while `subpath` alone leaves a first-time `mkdir` gap; the system-level denies keep the subpath-only shape.
8. `(allow file-read-data (literal "<path>"))` for `spec.read_only_subpaths` (`<home>/.ssh/known_hosts` + `.ssh/config`) — keeps `git fetch/push` over SSH working while private keys stay blocked; single-spelling on purpose (the FILES, not the enclosing dirs, are the grant).
9. `(allow file-read* (subpath <spec.host_tmpdir>))` for BOTH spellings — macOS per-user tmp is `/var/folders/...`, so files written BEFORE the sandbox starts stay readable; skipped when `$TMPDIR` is unset (the SPEC reads it, never the renderer).
10. `(allow file-read-metadata)` unqualified — stat/ls/glob on arbitrary paths under default-deny.
11. Writes: `spec.cache_write_paths` (one pair per path per SPELLING; see § `[sandbox] write_paths`) plus `/dev/null` + `/dev/dtracehelper`, and the deny-write credential list (all 12 canonical dirs, same pairing, WITHOUT `Library/Keychains`).
12. Exactly ONE `(deny system-fcntl (fcntl-command 80 110))` immediately after the deny-write group and before the limit — `F_MAKECOMPRESSED`/`F_TRANSFEREXTENTS` mutate file contents through an already-open READ-ONLY descriptor.
13. `(limit number <spec.max_processes>)` (`200` default) + `(allow process-exec)` / `(allow process-fork)`.
14. `(allow network*)` KEPT (default-allow, deliberate): agents need `git fetch/push`, `mix deps.get`, `curl`, web tools; no `[sandbox]` TOML key gates it.
15. Baseline mach/sysctl/ipc allows (`mach-lookup`, `sysctl-read`, `process-info*`, `signal`, `ipc-posix-sem`, `ipc-posix-shm`).

Rules below the root read allow (nix, home, host `$TMPDIR`, vendored git, ssh literals) are REDUNDANT but intentionally KEPT as belt-and-suspenders; composition rationale and the planned `-D`/fragment rework: `../../../docs/platform-sandbox.md` § macOS.

### Unverified-rule fail-safe — do not remove
TWO emitted rules could not be validated without a macOS host (CI is Linux), and a rejected rule makes `sandbox-exec` refuse the WHOLE profile → every sandboxed command would fail on macOS in `:auto`: the exact SBPL `limit` syntax (`(limit number N)` vs `(limit (number N))`) and the `system-fcntl` deny's argument form.
`strip_unverified_rules/1` is the ONE transformation that drops BOTH — every line starting with `(limit ` or `(deny system-fcntl ` — and is what `effective_profile/2`, `run/4`'s retry and `run_with_partial/7`'s strip all use.
`run/4` and `run_with_partial/6` retry ONCE with the stripped profile on a non-zero exit when no decision is cached; on retry success they cache `true` at the `:persistent_term` key `{EvoGit.Sandbox.MacOS, :process_limit_rejected}` (the name is pinned by tests and kept although it now means "this macOS rejected the profile's unverified rules") and warn once naming BOTH rules, after which calls use the stripped profile directly.
`effective_profile/2` (`@doc false`) applies the cached decision for `run/4` and `EvoGit.Sandbox.Background`; `run_with_partial/7` does the same strip INLINE and never calls `effective_profile/2`, so both places must change together.

## macOS Git Commit Coverage
The `write_context`/`edit_context` commit path (`agent/tools/context.ex`) calls `EvoGit.sandbox_run(repo_path, "git", ["add"|"commit", …], repo_root)` → `Sandbox.run/4` → `MacOS.run/4` wraps in `bash -c "git ... < /dev/null"` → `sandbox-exec`; the CONTEXT.md file write itself is UNSANDBOXED `File.write`, and a failing git step becomes `"Error: git add|commit failed (exit N):\n..."` so the LLM can retry/report.
The git rule resolves the REAL metadata dir via `git_metadata_dir/2` + `parse_gitdir_pointer/3`: `<repo_root>/.git` a regular FILE (linked-worktree `gitdir:` pointer) → the COMMON git dir (prefix before the LAST `/worktrees/` segment, via `:binary.matches`/`:binary.part` — NOT `String.split`, ambiguous when the path contains `worktrees`); `.git` a dir → literal `<repo_root>/.git`; repo_root nil + no `.git` dir → no git rule; repo_root nil + `.git` dir → literal `<cwd>/.git`.
A vendored-git read rule is emitted when `EvoGit.Executable.resolve("git")` returns an ABSOLUTE path: `(allow file-read* (subpath "<dirname of binary>"))`.

## Bwrap Backend — Filesystem-Only Isolation (bubblewrap)
`args/4` emits the bwrap argv for Linux where `systemd-run` is unavailable or undesirable (containers/docker, systemd-less distros, sandboxed CI); it needs only a `bwrap` binary and either root or unprivileged user namespaces — **no `evogit.slice` and no unit registry** (`ensure_initialized/0` is a no-op).
**Namespace shape** (validated against bwrap 0.11.2): `--unshare-user-try --unshare-ipc --unshare-pid --unshare-uts --unshare-cgroup-try` — exactly `--unshare-all` minus `--unshare-net`, spelled out so a future bwrap cannot silently change it. `-try` variants are skipped when the kernel/container blocks them. **`--unshare-net` is deliberately absent** (network retained). `--die-with-parent` SIGKILLs the command if bwrap or the BEAM dies; `--new-session` makes bwrap the session leader (pgid == pid), so the whole tree is one process group.
**Capability probe — `probe_capability/0`** runs the full argv against a trivial `true`, retrying with `--unshare-pid` removed: exit 0 → `:full`; pid-less exit 0 → `:degraded`; else `:unusable` (exceptions / missing bwrap → `:unusable`).
**Rootless podman (`:degraded`)**: with container root but no `CAP_SYS_ADMIN` (e.g. `--userns=keep-id`) `mount(2)` is kernel-denied and the full argv exits 1; `--unshare-user-try` creates a NESTED user namespace where the sandbox gains `CAP_SYS_ADMIN`, so bind/tmpfs/devtmpfs mounts work, but a fresh procfs in a NEW pid namespace stays denied — so `--unshare-pid` + `--proc` always fails there. `:degraded` emits the SAME argv MINUS `--unshare-pid` (filesystem isolation retained, `--proc` and `--dev` still work); `:full`/`:unknown`/`:unusable` keep the full shape.
`capability/0` caches the probe in `:persistent_term` (`{EvoGit.Sandbox.Bwrap, :capability}`) with the override seam **`Application.get_env(:evo_git, :bwrap_capability)`** (`:full | :degraded | :unusable | :unknown`); both skip probing under `@mix_env == :test`, and `capability/0` also skips when no `bwrap` binary is on PATH.
`enabled?/0` in `:auto` = `Platform.bwrap_available?() and capability() != :unusable` (degraded is still usable); the pid-namespace timeout-cleanup guarantee is absent in `:degraded`, while the process-group kill still works (`--new-session` setsid is independent of `--unshare-pid`).
**Filesystem layout (order matters)**: `--ro-bind / /` first (root read-only — the posture of `ProtectSystem=strict` and the macOS root read allow), `--dev /dev`, `--proc /proc`, `--bind-try` per `Platform.tmp_paths()`, `--bind-try` writable binds (cwd, resolved `[sandbox] write_paths`, `/nix/store` + `/nix/var` when `Nix.enabled?()`, git metadata dir, the per-task tmpdir), then `--tmpfs <home>/<dir>` deny overlays LAST so they override the ro-bind (bwrap has no `InaccessiblePaths` primitive). Deny list = the canonical 12 from `Spec.credential_paths/0`.
`--bind-try` skips missing sources (`ALLOW_NOTEXIST` + `ENOENT` → `continue` in `setup_newroot`, 0.11.2) — systemd's `ReadWritePaths=-` semantics — and deny `--tmpfs` mounts are safe for non-existent dirs (bwrap creates the destination).
**Environment handling**: bwrap inherits the caller env (unlike `systemd-run --user`), so `PATH`/`HOME`/`NIX*`/`SSL_CERT_FILE` flow through. Explicit `--setenv` only where needed: `TMPDIR` → `resolve_tmpdir/0` (on systemd desktops `$TMPDIR` is `/run/user/<uid>`, read-only inside) and the full `GitEnv.git_env_list(cwd)` for git commands (`GitEnv.git_command?/1`) — the BEAM carries no GitEnv-resolved identity, so commits in unconfigured repos would otherwise fail with "Please tell me who you are".
⚠️ **GOption constraint**: the option parser STOPS at the first non-option argument (verified), so ALL `--setenv` args MUST precede the command — hence `git_env_args/1` is prepended before the `args/4` result.
**Timeout handling**: `run_with_partial/6` owns a `Port` directly (via `None.resolve_executable("bwrap")` — `Port.open` does no PATH search), reads the OS pid, redirects output to a temp file, and on timeout kills the group as described in § Rendering; the `{:timeout, partial <> "\n[TRUNCATED due to timeout]"}` contract matches the other backends.
**Scope**: filesystem-only — **no resource limits and no syscall filtering** (no systemd-equivalent `CPUQuota`/`MemoryMax`).

## Configurable Writable Paths — `[sandbox] write_paths`
All three Unix renderers express `spec.cache_write_paths` (Linux `-p ReadWritePaths=-<path>`, Bwrap `--bind-try <path> <path>`, macOS `(allow file-write* (subpath "<path>"))`), resolved ONCE by `Spec.build/2` from `EvoGit.Config.resolve([:sandbox, :write_paths])` (schema `:list_of_strings`, default `nil`) via `Helpers.resolve_write_paths/3`:
- **`nil` (unset)** → the canonical default cache-dir list from `Spec.default_cache_dirs/0` (`.cache`, `.local/share`, `.local/state`, `.cargo`, `.rustup`, `.mix`, `.hex`, `.npm`, `.yarn`, `.bun`, `.m2`, `.gradle`, `go`, home-relative).
- **set (even `[]`)** → the user's list REPLACES the default list; `[]` disables those write paths entirely.

**Path convention** (per entry): `~`-prefixed → `System.user_home!()`; absolute → as-is; relative → joined to `System.user_home!()`. `Path.expand` is deliberately NOT used — env substitutions like `$HOME` are NOT expanded (a `$HOME/x` entry is a relative path component), and `resolve_write_paths/3` never dedups, sorts or checks existence.
**Structural paths are ALWAYS appended** (required to function, NOT user-configurable) and come from `%Spec{}` fields: Linux `[spec.cwd | spec.tmp_paths] ++ spec.cache_write_paths ++ spec.nix_paths ++ List.wrap(spec.task_tmpdir) ++ List.wrap(spec.git_metadata_dir)`; Bwrap tmp binds first, then `[spec.cwd] ++ spec.cache_write_paths ++ spec.nix_paths ++ List.wrap(spec.git_metadata_dir)`, then the per-task tmpdir bind, then the deny overlays (order is load-bearing); macOS grants cwd, tmp paths, the per-task tmpdir, the genesis config/data dirs and the git metadata dir in their OWN rule groups, so the replacement semantics apply to the cache-dir group alone.
**Deny lists are NEVER affected** — the config replaces only the ALLOW/write list.

## Windows / None Backend — No-Sandbox Gap
`EvoGit.Sandbox.None` is the fallback for Windows and unsupported platforms: **no OS-level isolation** — a documented gap, not an oversight, and no longer a SILENT one (`backend_reason/0` states it and `warn_if_unisolated/0` logs once per BEAM when isolation was demanded); the timed path's only hardening is the process-tree kill. It DOES export the managed per-task tmpdir as `TMPDIR`/`TMP`/`TEMP` when one is installed (`Helpers.temp_env_vars/0`), but has NO writable-path gating.

- `run/4` — `System.cmd(executable, args, cd: cwd, stderr_to_stdout: true, env: git_env)`: cwd confinement via `cd: cwd` (raises if missing); no command-injection surface (args as an ARRAY — deliberately NO shell wrapper on Windows); **no timeout — by contract** (`git add`/`commit` callers such as `EvoGit.sandbox_run/4` rely on it — do NOT add a default); git identity/`LC_ALL`/`GIT_EDITOR` via `GitEnv.git_env_list/1` plus the tmpdir vars on BOTH branches; PowerShell `["-Command", cmd]` args become `-EncodedCommand` (`Powershell.transform_args/2`, also run at the top of the Windows partial clause as defense-in-depth) and output runs through `Powershell.decode_output/1` (BOM-aware, idempotent) in BOTH return branches before `Helpers.truncate_output`.
- `run_with_partial/6` (Windows clause): a directly-owned `Port.open({:spawn_executable, ...})` with `System.cmd`'s option set, the env converted to CHARLISTS by `Helpers.port_env/1`, so the OS pid is readable via `Port.info(port, :os_pid)`; the timeout path kills the whole process tree via `taskkill /PID <pid> /T /F`, driven by the pid from `wait_for_os_pid/2`, and output so far returns as `{:timeout, partial_output}` — an IDLE timeout, not a total budget.
  Executable resolution uses `resolve_executable/1` (absolute paths as-is; else `System.find_executable/1` PATH/PATHEXT, then the known-location `resolve_windows_executable/1` for `powershell`/`pwsh`; nil → `:erlang.error(:enoent)`); `EvoGit.Executable.resolve/1` pre-resolves on the dispatch path but returns the ORIGINAL name when no bundled file exists, so it never pre-empts it.

### Port/OS-pid pitfalls (`Port.open` vs `System.cmd` — verified on OTP 29)
- **`{:env, [...]}` accepts ONLY charlist tuples.** `{:env, [{"K","V"}]}` raises `ArgumentError: invalid option in list`; `{:env, [{~c"K", ~c"V"}]}` works, and the flat `~c"K=V"` form is invalid. `System.cmd/3` is safe with binaries only because it runs `validate_env/1` first. `Helpers.temp_env_vars/0` and `GitEnv.git_env_list/1` return `[{binary, binary}]` and are shared with `System.cmd` call sites and bwrap `--setenv` args — convert LOCALLY at the `Port.open` call site, never in the helper.
- **`{:cd, binary}` and `{:args, [binary]}` ARE accepted**; **`spawn_executable` does NO PATH search** (only an absolute path works).
- **`Port.info(port, :os_pid)` returns `{:os_pid, pid}`** while open (`wait_for_os_pid/2` unwraps it) and the port is ALREADY CLOSED after `{:exit_status, _}`: `Port.close/1` then raises `ArgumentError` — the timeout paths close via `Helpers.close_port/1`.
- **`receive … after timeout` is an IDLE timeout**: the timer restarts on every `{:data, _}`, so `collect_windows_output/5` never times out a child that keeps printing and `acc` grows unbounded (`max_bytes` applies after the loop; Unix backends buffer to a temp file).

### Windows Tree-Kill (`taskkill /T /F`)
- **Fires on IDLE, not total runtime**: a command silent longer than the idle window is KILLED mid-flight even if it would have completed.
- **`os_pid` is resolved ONCE before collection** and never re-validated (`is_integer/1` guard, `:undefined` → `:ok`, so `taskkill /PID undefined` is never issued).
- **Completion race (real)**: the pid may be RECYCLED, in which case `/T /F` kills an unrelated tree; an `{:exit_status, 0}` arriving during the blocking `taskkill` is discarded by `Helpers.drain_port_messages/1`, reporting a COMPLETED command as `{:timeout, partial_output}`. The kill result itself is discarded and NOTHING is logged.
- **Blast radius is DESCENDANT-only**: `taskkill /T` walks the target's CURRENT descendants, so the tree can never contain the BEAM or its launcher `cmd.exe` — THIS CODE PATH CANNOT TERMINATE THE BACKEND BEAM (the realistic victim is a concurrent tool call's shell, and a kill mid-`git` can leave a stale `index.lock`).
- **The Windows route to BEAM death is the command STRING**: `ShellTool` hands the LLM's command verbatim to `powershell -EncodedCommand` with no allow-list (`agent/tools/CONTEXT.md`), so `taskkill /IM erl.exe /F` kills the backend from the inside; the Tauri shell's own `taskkill /PID <cmd.exe> /T /F` can kill the BEAM by design, but only from `run_bootstrap` and the quit/update force-kill paths.
- **The outer tool budget outranks the inner idle timeout**: the tool layer's default per-call budget (`agent/tool_dispatch.ex`) vs `ShellTool`'s advertised 180 s idle window means `Task.shutdown/1` can kill the tool Task first, so `taskkill` never runs.

### PowerShell Invocation — `-EncodedCommand`
PowerShell commands run via `-EncodedCommand` args built by the pure `EvoGit.Powershell` (`lib/evo_git/powershell.ex` — single source of truth for arg building + output decode; Linux-tested in `test/evo_git/powershell_test.exs`). `Platform.shell_args/1`'s Windows clause returns `invoke_args/1` (ShellTool + worktrees paths), and both `none.ex` Windows clauses also run `transform_args/2` for direct callers.
Why (do not re-investigate): `powershell.exe -Command <script>` spawned from Erlang re-joins and re-parses the raw command line as code, so mangled quoting → INTERACTIVE mode → closed stdin → exit 0 with NO output; PS 5.1 also emits its OEM/UTF-16 code page, whose BOM `UTF8.ensure_utf8/1` rejects.
The invocation is `-NoProfile -NonInteractive -ExecutionPolicy Bypass -EncodedCommand <b64>` with `b64` = base64(`UTF-16LE`(`& { [Console]::OutputEncoding = [System.Text.Encoding]::UTF8; <script> } *>&1`)) — no command-line parsing, forced UTF-8, all streams merged.

**Residual risks (would need OS APIs):** arbitrary FS read/write where the user has access, no CPU/memory/process-count limits, no kill-tree on `run/4`, no network isolation, no AppContainer/restricted token — a real sandbox needs Job Objects (`CreateJobObject` + `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`) and an AppContainer/restricted token via a NIF or port program, or WSL2/Windows-Sandbox wrapping.
**Windows-only caveats (do not "fix"):** keep PATH/PATHEXT resolution so MinGit bash for skills scripts is found; the arg-array form avoids PowerShell's `<` redirection parse error (the Unix `bash -c "<cmd> < /dev/null"` wrapping stays Unix-only); keep `taskkill /PID <pid> /T /F` on timeout and the UNBOUNDED `run/4`; the `-EncodedCommand` transform applies ONLY to powershell/pwsh with the exact `["-Command", cmd]` shape.

## TMPDIR Handling — managed per-task dir + always-writable system tmp dirs
Two layers are always in effect:
1. A managed **per-task** scratch dir (`EvoGit.TaskTmpdir`, `task_tmpdir.ex` — outside this node) shared by ALL agents of one task (never per-agent, never per-worktree); `path_for/2` derives it from `[tmp] mode` + task id — `:system` (default) → `<first Platform.tmp_paths/0 entry>/genesis/task_<id>`, `:custom` → `<[tmp] path>/genesis/task_<id>`, `:per_repo` → `<primary repo>/.genesis/tmp/task_<id>` (repo-less → `:system`). The runner installs it via `put_current/1`; the tool-dispatch layer re-installs it in every spawned tool task (they do NOT inherit the caller's process dict); `current/0` reads it.
2. The **system tmp dirs** (`Platform.tmp_paths/0` = `/tmp` + `/var/tmp` on Unix, `System.tmp_dir!()` on Windows) stay FULLY writable in every sandbox — some agents hardcode `/tmp`. The per-task dir is an ADDITIONAL writable path + a `TMPDIR` override — NEVER a `--tmpfs /tmp`, never a replacement.

`EvoGit.Sandbox.resolve_tmpdir/0` returns `TaskTmpdir.current/0` DIRECTLY when a per-task dir is installed; otherwise the legacy per-BEAM constant: `$TMPDIR` unset → the first `Platform.tmp_paths/0` entry (`/tmp`); set → kept ONLY when it exists AND is equal to / under a tmp path, else `/tmp` (so the macOS host `$TMPDIR` under `/var/folders/...` never survives).
**The Nix dev-env wrap must not rotate the injected TMPDIR** (it is sourced INSIDE the sandbox): `Nix.wrap_command/2` emits `bash -c "source '<data_dir>/nix-dev-env.sh'; exec <escaped-command>"`, because the raw `nix print-dev-env` epilogue would `mktemp -d -t nix-shell.XXXXXX` and re-export `TMPDIR`/`TMP`/`TEMP`/`TEMPDIR`/`NIX_BUILD_TOP` to a fresh 0700 dir on EVERY source.
**Sanitization**: `Nix.do_build_dev_env/0` runs the public pure `Nix.sanitize_dev_env_output/1` (a single `String.replace/3`) before caching, replacing the literal `export NIX_BUILD_TOP="$(mktemp -d -t nix-shell.XXXXXX)"` with `export NIX_BUILD_TOP="${TMPDIR:-/tmp}"`; the following `TMP*` exports reference `$NIX_BUILD_TOP`, so no per-call dirs are created and nothing accumulates. A nix that stops emitting the literal makes the replace a no-op; output is otherwise byte-identical across rebuilds for a given invocation cwd and the cache hash keys flake.nix content only.

Each SANDBOX-ENABLED backend injects that value AS `TMPDIR` and ADDITIONALLY grants it write access (both read `TaskTmpdir.current/0` in the same tool-invocation process, so they always agree); disabled/None paths export it as an env override only:
- **systemd-run**: `--setenv=TMPDIR=<resolve_tmpdir()>` plus an extra `-p ReadWritePaths=-<taskdir>` (the `-` prefix keeps a missing path non-fatal); `-p ReadWritePaths=-/tmp -/var/tmp` stays, `ProtectSystem=strict` makes the rest of `/` read-only, and there is no `PrivateTmp` — each fresh unit uses the host's `/tmp`, so files persist across invocations.
- **bwrap (full AND `:degraded`)**: `--setenv TMPDIR <resolve_tmpdir()>` plus `--bind-try <taskdir> <taskdir>` spliced after the always-present `--bind-try /tmp /tmp` + `/var/tmp` and before the `--` separator.
- **sandbox-exec**: an extra read+write pair for the per-task dir (after `tmp_rules`) and `env: [{"TMPDIR", resolve_tmpdir()}]`; the read-only host-`$TMPDIR` rule keeps pre-sandbox BEAM temp files readable.
- **None / Windows + every DISABLED path**: the per-task dir (when installed) IS exported as `TMPDIR`/`TMP`/`TEMP` via `Helpers.temp_env_vars/0`, appended to every non-sandboxed spawn env (`None`'s four clauses AND the Linux/Bwrap/MacOS disabled branches) — no isolation, NO writable-path gating.
- **Shared derivation**: `Helpers.task_tmpdir_path/0` derives from `TaskTmpdir.current/0` (`nil` when unset); `Helpers.temp_env_vars/0` is the single env-override source: `[{"TMPDIR", dir}, {"TMP", dir}, {"TEMP", dir}]` when installed, else `[]`.
- **Runtime-owned temp files land under `resolve_tmpdir/0`**: `Helpers.partial_output_tmpfile/0` → `<dir>/genesis_partial_outputs/`; skills scripts → `<dir>/evogit_skill_<n>.sh` (`skills/executor.ex`; Windows `System.tmp_dir!()`); git `-F` files → `<dir>/genesis_ctx_msg_<n>.txt` (`agent/tools/context.ex`) and `System.tmp_dir!()/genesis_git_msg_<n>` (`adapters/git.ex`).
- **Cleanup is best-effort, NOT uniform, and there is NO runtime-wide temp sweep**: the git `-F` files use `try/after File.rm`, partial-output tmpfiles `read_tempfile/2`'s own `File.rm`, skills scripts a bare `File.rm`. Leaks come from a raise between write and cleanup (e.g. missing bash → `ErlangError(:enoent)`, or `Task.yield`'s `{:exit, reason}` matching no clause), a killed owner, or a BEAM crash; per-task dirs are reclaimed by `TaskTmpdir` (`reclaim/2`), stray system-tmp files are never swept at boot.
- **Agent guidance**: the ShellTool schema tells agents to use `$TMPDIR` ("never /tmp" on POSIX) — inside a Linux/bwrap/macOS sandbox that is the per-task dir; `/tmp` + `/var/tmp` stay writable, hence cross-agent visible to every sandboxed command of the same OS user.
- **Cross-worktree visibility**: other agents' worktrees are READABLE (bwrap `--ro-bind / /`, systemd `ProtectSystem=strict`, macOS root read allow), WRITE access confined to `cwd` + tmp dirs + configured caches + `.git`.

## Skills Script Execution Through the Sandbox
`skills/executor.ex` (outside this node) runs scripts via `EvoGit.sandbox_run(repo_path, "bash", [tmp_file | values], nil)` on Linux/macOS (script under `resolve_tmpdir()`, values as positional argv `$1..$N`), and via `System.cmd(bash_path, [tmp_file | values], cd: repo_path, ...)` on Windows (argv-style, injection-safe); a `System.find_executable("bash")` guard returns "Install Git for Windows" instead of `ErlangError(:enoent)`.
The script path is writable in every enabled backend through the grants above and the canonical deny lists hide credential stores; `sandbox_run_with_partial/6` adds a timeout, `Helpers.shell_escape/1` quotes the path in the assembled `bash -c` string, and `Nix.wrap_command/2` accepts any executable name.

## Constraints
- All backends implement `@behaviour EvoGit.Sandbox.Behaviour`; callers use `EvoGit.sandbox_run/4` (→ `EvoGit.Sandbox.run/4`) and never need to know about backends.
- Shared helpers live in `EvoGit.Sandbox.Helpers` — the anti-duplication home (full list in API Surface); new cross-backend helpers belong there, and backends plus `EvoGit.Nix` alias and delegate to it.
- `shell_escape/1` is **security-sensitive** (command injection prevention) — exactly one definition.
- `kill_process_tree/1` is total (POSIX `kill -TERM -- -<pgid>` → 100 ms → `kill -KILL -- -<pgid>` with a bare-pid fallback when the group is gone; Windows `taskkill /PID <pid> /T /F`; always `:ok`); it expects a session/process-group leader, which `bwrap --new-session` and the `wait_for_os_pid/2` spawn shapes both give. The 100 ms grace is a CALL-TIME app-env seam, `Application.get_env(:evo_git, :kill_grace_ms, @kill_grace_ms)` (production default `@kill_grace_ms` = 100 ms, non-integer/negative values ignored), read at BOTH `Process.sleep` sites in `posix_kill_tree/1`; tests that only poll for the killed pid set it to 0-10 ms.
- `EvoGit.Sandbox` exposes two default-inert test seams, read AT CALL TIME: `Application.get_env(:evo_git, :sandbox_backend_override)` (an atom module → returned by `backend/0` instead of the config/platform resolution) and `Application.get_env(:evo_git, :sandbox_mode_override)` (`:auto | :enabled | :disabled` → used by `resolved_mode/0`, which feeds `backend_reason/0` and `warn_if_unisolated/0`); both are UNSET in production and neither is a user-facing sandbox switch.
- `EvoGit.Sandbox.Linux` depends on `EvoGit.SandboxProcessRegistry` (caller-process monitoring) and `EvoGit.SandboxSlice` (systemd slice management) — both started in the Application supervision tree on Linux only.
- `EvoGit.Sandbox.Bwrap` depends on NEITHER — `ensure_initialized/0` is a no-op; it needs only a `bwrap` binary (+ root or userns); its `--setenv` args MUST precede the command.
- `EvoGit.Sandbox.MacOS` uses inline SBPL generation (no template files); the profile is PURE SBPL — no `#` comments inside.
- There is deliberately NO read-only or deny carveout for `<repo>/.genesis/`: every agent worktree lives UNDER `<repo>/.genesis/workers/…` (and foreign read views under `<repo>/.genesis/foreign_repos/…`), so a blanket deny there would break every agent's own cwd — do not re-attempt it without moving worktrees out of `.genesis/` first.
- `EvoGit.Nix` is a standalone helper (not a backend) — backends consult it to optionally wrap commands; it depends on `EvoGit.Config` (`[nix]` table + config dir) and `EvoGit.Platform` (`nix_available?/0`); when active, Linux forwards all `NIX*` + `SSL_CERT_FILE` via `--setenv` and grants read-write to `/nix/store` + `/nix/var`, macOS adds both to its profile, Bwrap grants writable `--bind-try` for both and relies on env INHERITANCE, None inherits the parent env.
- All four source the cached dev-env script via `bash -c` rather than per-call `nix develop`; `nix_paths`/`nix_env_vars` gating uses `Nix.enabled?/0` (static) while the wrap decision uses `Nix.active?/0`.

## Known Issues / Test Strategy
- **OTP 27+ `:os.find_executable/1` binary trap:** raw `:os.find_executable/1` raises `ArgumentError` on Elixir BINARY input on OTP 27+ (`verify_executable/3` appends a CHARLIST `.exe` suffix). `None.resolve_executable/1` works around it via `System.find_executable/1` plus the Windows known-location fallbacks. **Rule: never call raw `:os.find_executable/1` with an Elixir binary on OTP 27+.**
- **Test coverage gap:** `linux_test.exs`/`bwrap_test.exs` test only `args/4` generation and `macos_test.exs` only `generate_profile/3` string assertions (driven through its `:alias_fun` / `:host_tmpdir` seams, so a Linux host can pin resolved-alias spellings). NO test executes a real sandboxed command (systemd-run/sandbox-exec/bwrap) — the `@mix_env == :test` gates in `Linux.enabled?/0`/`Bwrap.enabled?/0` and Linux-only CI leave all four enabled paths runtime-verified only, and the Windows clauses are compile-checked only.
- **Bwrap real-execution caveat:** real bwrap needs a host where `mount(2)` works — a systemd-run unit with read-only `/` blocks it (`bwrap: Failed to make / slave: Operation not permitted`), so only flag syntax is validated there; rootless podman: use the `:bwrap_capability` override seam (probing never runs in tests).
- **Backend-selection invariant:** `Linux.enabled?/0` needs NO `backend() == EvoGit.Sandbox.Linux` guard — the dispatcher consults only the SELECTED backend's `enabled?/0`, and `SandboxSlice.sandbox_enabled?/0`/`SandboxProcessRegistry.sandbox_enabled?/0` are gated on `EvoGit.Sandbox.backend() == EvoGit.Sandbox.Linux`, so the slice/unit-registry machinery activates only for Linux; the `@mix_env == :test` gate stays first.
- **Renderers are pinned by string/argv assertions** (sibling test node; full assertions: `test/evo_git/sandbox/`): `MacOS.generate_profile/3` — `(deny default)`, the credential deny-read group in canonical order with `Library/Keychains` immediately after `.password-store` and deny-write for the canonical 12, EACH credential rule carrying `(literal "<p>") (subpath "<p>")` in one line, exactly one `(deny system-fcntl (fcntl-command 80 110))` immediately after the deny-write group, cwd/tmp/`/repo/.git` read+write PAIRS, `(limit number 200)` exactly once, no nix rules, all write_paths behaviors, the root read rule, the system-level deny-read spellings, the `.git` variants (literal, linked-worktree pointer → COMMON dir, nil repo_root + pointer, plain dir + nil → NO rule), the vendored-git read rule, and no extra spelling on a host where `Spec.aliases/1` resolves nothing; `Linux.args/4` — the `InaccessiblePaths` group as the canonical 12; `Bwrap.args/4` — the deny `--tmpfs` overlays in canonical order.
- **`spec_test.exs` is the only `async: true` sandbox module**: it drives `Spec.build/2` exclusively through its injection seams, so it touches no BEAM-global state.
- **Nix dev-env wrapping is skipped on Windows (open)**: `Nix.active?/0` has no platform gate, but neither `run_windows/3` nor `run_with_partial_windows/5` consults it — Windows commands run WITHOUT the dev-env `source` every Unix backend performs.
- **The `(limit ...)` syntax and the `system-fcntl` form are unverified on real macOS** — both mitigated by the fail-safe retry; validate on a Mac and fix `generate_profile/3` if a form is wrong (tests pin `(limit number 200)` and the fcntl line). `commit.gpgsign = true` also breaks sandboxed commits by design (git reads `~/.gnupg`, which is deny-read), and the SSH literal allows vs deny-precedence interaction still needs a real-Mac check.
- **No app-env sandbox switch exists**: `Application.put_env(:evo_git, :sandbox, :disabled)` is a NO-OP and `config/config.exs`'s `config :evo_git, sandbox: :auto` is unread — mode/backend resolve only via `EvoGit.Config.resolve([:sandbox, :mode|:backend])` (defaults → user TOML → runtime overrides).
