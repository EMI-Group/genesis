# Sandbox — Multi-Platform Sandbox Backend

## Intent
Platform-specific sandboxing for agent-executed commands.
`EvoGit.Sandbox` (sibling `lib/evo_git/sandbox.ex`) dispatches to the active backend, chosen by `EvoGit.Platform.sandbox_backend/0` from `[sandbox] mode`/`[sandbox] backend` (`../config/CONTEXT.md`): systemd-run first, then bwrap, then no sandbox in `:auto`.

## Routing Table
None — leaf directory (`background.ex`, `behaviour.ex`, `bwrap.ex`, `helpers.ex`, `linux.ex`, `macos.ex`, `nix.ex`, `none.ex`).
The dispatcher `lib/evo_git/sandbox.ex` and the test suite `apps/evo_git/test/evo_git/sandbox/` are sibling nodes (read-only from here; escalate test-file changes to the parent).

## Argv Shapes & Kill Primitives — at a glance

Each builder is the single source of truth for its backend (the detached path reuses these SAME builders).

- Linux `args/4` and `detached_args/5` BOTH delegate to ONE private `build_args/7` so shared fragments cannot drift: `["--user"] ++ unit_args ++ ["--slice=evogit"] ++ mode_args ++ ["-q"] ++ env_args ++ nix_env_args ++ ["-p","WorkingDirectory=<cwd>","-p","StandardInput=null"] ++ stdio_args ++ security_args() ++ resource_args() ++ read_write_args ++ inaccessible_args ++ [cmd | args]`.
  `args/4` passes `unit_args=[]`, `mode_args=["--wait","--pipe","--collect"]`, `stdio_args=[]`; `detached_args/5` passes the `--unit=<name>` arg, `mode_args=[]` and the two `append:` stdio props.
  `--unit=<name>` never comes from `args/4`: `inject_unit/2` splices it right after `--user` in `run/4`/`run_with_partial/6`, using the name from `SandboxProcessRegistry.register/0` (`"evogit-run-<system_time_ms>-<unique_integer>"`).
  No `--scope` and no `--pty`: the default transient **service** unit is used, `--wait` blocks the client until exit, `--pipe` carries stdout/stderr, and `--collect` GCs the unit on termination — so `systemctl --user show <unit> -p ActiveState,ExecMainStatus` is queryable only WHILE it is alive, which is why `detached_args/5` omits `--collect`.
  `security_args/0` emits `ProtectSystem=strict`, `ProtectHome=read-only`, `ProtectKernelTunables`, `ProtectControlGroups`, the `SystemCallArchitectures`/`SystemCallFilter` set and `NoNewPrivileges` (each toggleable under `[sandbox.linux]`); `resource_args/0` emits `-p CPUQuota=`, `MemoryMax=`, `LimitNOFILE=`, `OOMScoreAdjust=` from `[sandbox.process]` when set (`[sandbox.resources]` sizes the slice) — keys/defaults: `../config/CONTEXT.md`.
- bwrap `args/4` wraps the private `build_args/5`: `["--die-with-parent","--new-session"] ++ unshare_flags ++ ["--ro-bind","/","/","--dev","/dev","--proc","/proc"] ++ tmp_bind_args ++ writable_bind_args ++ task_tmp_bind_args ++ deny_args ++ ["--chdir", cwd] ++ env_setenv_args ++ ["--", cmd | cmd_args]` — every option precedes the `--` separator.
- macOS: `run/4`/`run_with_partial/6` spawn `System.cmd("sandbox-exec", ["-p", <profile>, "--", exec | exec_args], cd: cwd, env: [{"TMPDIR", tmpdir} | git_env])`; SBPL from `generate_profile/2`.
- none: `run/4` = `System.cmd(executable, args, cd: cwd, stderr_to_stdout: true, env: …)`; `run_with_partial/6` = direct `Port.open({:spawn_executable, resolved}, [:binary, :exit_status, :hide, :stderr_to_stdout, {:args, args}, {:cd, cwd}, {:env, Helpers.port_env(git_env)}])`.

Kill/timeout primitives:
- Linux: the timeout shuts down the CLIENT `Task` only — the unit keeps running and is stopped asynchronously by `SandboxProcessRegistry.release(unit)` → `systemctl --user stop <unit>.service`; `run/4` has NO timeout (`--wait` blocks indefinitely).
- bwrap: `kill_process_group/1` runs `kill -TERM -- -<pgid>` → 100 ms → `kill -KILL -- -<pgid>` → `kill -KILL <pid>`; the negative pgid is valid because `--new-session` makes bwrap the session leader.
- Windows/none: `taskkill /PID <pid> /T /F`, pid from `Helpers.wait_for_os_pid/1`.
- macOS: `Task.shutdown` only — the `sandbox-exec` child is never explicitly killed.
- Other long-lived spawns: the SSH remote daemon (`systemd-run --user --unit=genesis-remote-<id> --setenv=RELEASE_NODE/RELEASE_COOKIE … <launcher> start`, preceded by `systemctl --user reset-failed`; macOS = launchd plist + `launchctl` — `remote_connection.ex`) and `Background`'s per-job units.

## Behaviour Contract
All four backends (`Linux`, `Bwrap`, `MacOS`, `None`) implement `@behaviour EvoGit.Sandbox.Behaviour`: `enabled?/0` (sandboxing available for this platform/mode), `ensure_initialized/0` (lazily initialize backend resources, e.g. the systemd slice; no-op when unneeded), `run/4` (synchronous → `{output, exit_code}`) and `run_with_partial/6` (timeout + partial output → `{:ok, output, exit_code}` | `{:timeout, partial_output}`).

## Detached / Background Execution — `EvoGit.Sandbox.Background`

Background jobs (outliving the tool call that started them) go through `EvoGit.Sandbox.spawn_detached/1` / `kill_detached/1` / `detached_status/1`, answered for EVERY backend by `Background` — callers never branch on the backend.
`spawn(spec)` takes `%{command, cwd, output_path, job_id}` (all four required non-empty binaries, else `{:error, {:invalid_spec, spec}}`) → `{:ok, handle} | {:error, term()}`.
A `cwd` that is not an existing directory answers `{:error, {:cwd_missing, path}}` on EVERY backend — validated before backend dispatch, because `Port.open/2` accepts a missing `{:cd, dir}` and the child would die before `exec`; `EvoGit.BackgroundJobs` maps it to "the working directory does not exist: <path>" (ITS `normalize_start_spec/1` is the layer-above check).
`output_path` and its parent are PRE-CREATED by the caller and never truncated: port-based backends append via the registry, systemd via `StandardOutput=append:` / `StandardError=append:`.
`handle` = `%{kind: :unit, unit, backend}` | `%{kind: :port, port, os_pid, backend}`; `status/1` → `{:running, nil} | {:exited, integer() | nil} | {:unknown, nil}`; `kill/1` → `:ok | {:error, term()}` (`{:error, {:invalid_handle, handle}}` otherwise).
`spawn/1` runs in the CALLER's process (the `EvoGit.BackgroundJobs` registry GenServer), so a `:port` handle's Port is owned by that registry — it receives `{:data, chunk}` / `{:exit_status, n}` and must keep draining them.
Every function is TOTAL: OS calls are wrapped in `rescue`/`catch` → `{:error, term()}` / `{:unknown, nil}` — nothing raises into the registry.
`spawn/1` reuses each backend's public argv builder, so env/isolation/writable-path grants match foreground execution exactly; a false `enabled?/0` (e.g. the `@mix_env == :test` gate) falls back to a plain shell child Port, mirroring that backend's disabled `run/4`.
No PTY is used anywhere (pipes/files only), so a non-TTY stdout is BLOCK-BUFFERED: a program buffering its own output fills the file in CHUNKS, not line-by-line.

| Backend | Handle | Spawn shape | PRIMARY guarantee |
|---|---|---|---|
| `Linux` (systemd-run) | `:unit` | transient user unit, argv from `Linux.detached_args/5` | the unit itself — survives BEAM death by design; killed via `systemctl --user stop` then `reset-failed` inside `Task.start` (returns `:ok` immediately, never blocking the registry) |
| `Bwrap` | `:port` | `Bwrap.args/4`, inner command `<shell> <shell_args(command)>` (the RAW command); the registry appends the port stream to the output file | bwrap is a session leader (`--new-session`) and in `:full` capability the pid-namespace root, so killing it takes the whole tree; `--die-with-parent` covers BEAM death |
| `MacOS` | `:port` | `sandbox-exec -p <profile> -- <shell> <shell_args(cmd)>`, profile from `MacOS.effective_profile/2` | NO pid namespace — only the registry's owner-process monitor + a tree kill, so a BEAM crash can leak a process |
| `None` (Windows/unsupported) | `:port` | `<shell> <shell_args(cmd)>` | no isolation at all — owner-process monitor + tree kill only, so a BEAM crash can leak a process |

EVERY `:port` handle kills via `Helpers.kill_process_tree(os_pid)` (Windows → `taskkill /PID <pid> /T /F`) and reports liveness via `Port.info/1` (`{:running, nil}` while non-nil, else `{:unknown, nil}` — the real exit code arrives in the port message the registry owns).
The `:unit` stop is fire-and-forget (`stop_unit_async/1` → `Task.start`, so a caller has no handle to await); the test-only CALL-TIME seam `Application.get_env(:evo_git, :background_unit_stop_notify)` reports its completion — a `pid` receives `{:background_unit_stop_finished, unit}`, a 1-arity fun is called with the unit — sent AFTER both `systemctl` calls (and therefore after that path's `failed to stop unit` warning, whose log handler runs synchronously in the task); unset in production (no-op), and `test/evo_git/background_jobs_test.exs` sets it to the test pid.
Only the systemd-run unit survives the BEAM, so its `status/1` stays queryable after a crash and a later boot can prove ownership from the unit name `genesis-job-b<beam_os_pid>-<job_id>` (`Background.unit_name/1`: `beam_os_pid` = `System.pid()`, `job_id` = the caller's `"bash-<16 hex>"`, chars outside `[A-Za-z0-9_.:-]` fold to `_`).
`spawn_unit/1` makes ONE bounded blocking `receive` (`@systemd_run_timeout` 5_000 ms) for the systemd-run client's `{:data, d}`/`{:exit_status, n}`, then reaps via `Helpers.close_port/1`; non-zero status or timeout → `{:error, {:systemd_run_failed, captured_output}}` with the unit stopped so it never leaks.
**Boot sweep** — `sweep_stale_units/0` (total: never raises, always `:ok`) acts ONLY when the active backend is `EvoGit.Sandbox.Linux`: one `systemctl --user list-units --all --plain --no-legend 'genesis-job-*'` (stderr NOT merged; non-zero exit → no-op) → `parse_list_units/1` (pure, `@doc false`) → `{unit, load, active, sub, description}` (whitespace-collapsed columns, description = the remaining columns re-joined, <4-column lines skipped).
`inactive`/`failed` rows → `reset-failed` only; `active`/`activating`/`reloading` rows → `stop` then `reset-failed` ONLY when the owning BEAM pid from `beam_pid_from_unit/1` (pure — `genesis-job-b<digits>-…`, ".service" suffix tolerated) is NOT alive (`kill -0 <pid>`): a LIVE pid means another instance owns the job and the unit is untouched, an unattributable name is left ALONE, and a probe that cannot run counts as alive.
`status/1` on a `:unit` = `systemctl --user show <unit> -p ActiveState -p ExecMainStatus -p ExecMainCode` → `parse_systemctl_show/1` → `classify_unit_state/1` (both pure and public `@doc false`):
| `ActiveState` | `ExecMainCode` | Result |
|---|---|---|
| `active` / `activating` / `reloading` | any | `{:running, nil}` |
| `inactive` | `1` (exited) | `{:exited, ExecMainStatus}` |
| `inactive` | `2` (killed by signal) | `{:exited, nil}` |
| `inactive` | `0` or absent | `{:unknown, nil}` |
| `failed` | `2` | `{:exited, nil}` |
| `failed` | other | `{:exited, ExecMainStatus or nil}` — a failed exit, never a crash |
| unknown / missing / garbled, or a dead systemctl | — | `{:unknown, nil}` |

`kill/1` on a `:port` kills the process TREE but LEAVES THE PORT OPEN so the registry still receives the natural `{:exit_status, code}`; the port is closed directly only when no `os_pid` was ever observed.
`EvoGit.Sandbox.Behaviour` deliberately omits `spawn_detached`/`kill_detached`/`detached_status`: the detached path needs only per-backend argv + `enabled?/0`.

## macOS SBPL Profile — Root-Readable Reads + Deny-List Policy

`generate_profile/2` (`macos.ex`) emits `(deny default)` with READS allow-by-default at the ROOT and deny-by-default WRITES plus an explicit allow list; protection comes from the deny-read list (SBPL deny precedence: denies win). Rules below the root read allow (nix, home, host `$TMPDIR`, vendored git, file-read-metadata, ssh literals) are REDUNDANT but intentionally KEPT as belt-and-suspenders. Emitted rule groups, in order:

1. `(version 1)` / `(deny default)`
2. **Root read allow**: `(allow file-read* (subpath "/"))` — whole filesystem readable (Homebrew `/opt/homebrew`, Intel `/usr/local`, `/Applications`, custom `/opt`, nix, asdf/mise); deny rules still win; WRITES not covered
3. **Nix** (only when `Nix.enabled?()`): read+write `/nix/store`, `/nix/var`
4. **Repo**: read+write on `cwd` (worktree) and the git metadata dir — linked-worktree `gitdir:` pointers resolve to the COMMON git dir (see "macOS Git Commit Coverage")
5. **Tmp**: read+write on `Platform.tmp_paths()` (`/tmp`, `/var/tmp`)
6. **Genesis dirs**: read+write on `Platform.config_dir()` + `Platform.data_dir()` (`~/Library/Application Support/genesis` — NOT under /tmp or repo)
7. **Home read allow** `(allow file-read* (subpath home))` (tool configs such as `~/.gitconfig`), immediately followed by:
8. **Deny-read sensitive list** (deny beats allow): `.ssh`, `.gnupg`, `.aws`, `.kube`, `.config/sops`, `.git-credentials`, `.netrc`, `.password-store`, `Library/Keychains`, `.npmrc`, `.pypirc`, `.docker`, `.gem` (Linux `InaccessiblePaths` parity), plus system-level locations in both symlink spellings (`/etc`↔`/private/etc`, `/var`↔`/private/var`): `/etc/ssh` (host keys), `/var/root`, `/etc/master.passwd`, `/var/db/dslocal`, `/var/db/Keychains`
9. **SSH host-verification literal reads**: `(allow file-read-data (literal "<home>/.ssh/known_hosts"))` + `.ssh/config` — keeps `git fetch/push` over SSH working while private keys stay blocked; key auth needs `SSH_AUTH_SOCK`
10. **Host `$TMPDIR` read** `(allow file-read* (subpath <expanded $TMPDIR>))` — macOS per-user tmp is `/var/folders/...`, NOT under `/tmp`, so files written via `System.tmp_dir!()` BEFORE the sandbox starts stay readable; skipped when `$TMPDIR` unset
11. `(allow file-read-metadata)` unqualified — stat/ls/glob on arbitrary paths under default-deny
12. **Writes**: home build-cache dirs (`.cache`, `.local/share`, `.local/state`, `.cargo`, `.rustup`, `.mix`, `.hex`, `.npm`, `.yarn`, `.bun`, `.m2`, `.gradle`, `go`) plus `/dev/null` + `/dev/dtracehelper` literals; **configurable via `[sandbox] write_paths`** (nil = this default list, set — even `[]` — REPLACES it)
13. **Deny-write sensitive list** (defense in depth): `.ssh`, `.gnupg`, `.aws`, `.kube`, `.config/sops`, `.npmrc`, `.git-credentials`, `.netrc`
14. **Process limit**: `(limit number #{@max_processes})` (`@max_processes 200`, module attribute, tunable) + `(allow process-exec)`, `(allow process-fork)`
15. **Network: `(allow network*)` KEPT (default-allow), deliberate** — agents run `git fetch/push`, `mix deps.get`, `curl`, web tools; the boundary is the tightened filesystem + process limits, and no `[sandbox]` TOML key gates this rule
16. mach/sysctl/ipc: `(allow mach-lookup)`, `(allow sysctl-read)`, `(allow process-info*)`, `(allow signal)`, `(allow ipc-posix-sem)`, `(allow ipc-posix-shm)`

### Process-limit fail-safe — do not remove
The exact SBPL `limit` syntax (`(limit number N)` vs `(limit (number N))`) is unverified without a macOS host (CI is Linux), and a wrong form makes `sandbox-exec` reject the WHOLE profile → every sandboxed command fails on macOS in `:auto` mode.
`run/4` and `run_with_partial/6` (enabled paths) therefore retry ONCE with `strip_process_limit(profile)` on a non-zero exit with no cached decision; on retry success they cache `true` at `:persistent_term` key `{EvoGit.Sandbox.MacOS, :process_limit_rejected}` and warn once, after which calls use the stripped profile directly.
`effective_profile/2` (`macos.ex`, `@doc false`) is the SINGLE place applying the cached decision — `run/4` and `EvoGit.Sandbox.Background` both call it; `generate_profile/2` still emits the limit and the fallback only catches rejection.

## macOS Git Commit Coverage

The `write_context`/`edit_context` commit path (`agent/tools/context.ex`, whose own contract lives there) calls `EvoGit.sandbox_run(repo_path, "git", ["add"|"commit", …], repo_root)` → `Sandbox.run/4` → `MacOS.run/4` wraps in `bash -c "git ... < /dev/null"` → `sandbox-exec`; the CONTEXT.md file write itself is UNSANDBOXED `File.write`, and both `do_context_write/5` and `do_context_edit/8` turn a failing git step into `"Error: git add|commit failed (exit N):\n..."` so the LLM can retry/report.
The git rule resolves the REAL metadata dir via `git_metadata_dir/2` + `parse_gitdir_pointer/3`: `<repo_root>/.git` a regular FILE (linked-worktree `gitdir:` pointer) → the COMMON git dir (prefix before the LAST `/worktrees/` segment of the resolved target, via `:binary.matches`/`:binary.part` — NOT `String.split`, ambiguous when the path contains `worktrees`); `.git` a dir → literal `<repo_root>/.git`; repo_root nil + no `.git` dir → no git rule; repo_root nil + `.git` dir → literal `<cwd>/.git`.
A vendored-git read rule is emitted when `EvoGit.Executable.resolve("git")` returns an ABSOLUTE path (desktop bundle, git off PATH): `(allow file-read* (subpath "<dirname of binary>"))`.

**Remaining caveats (by design):** `commit.gpgsign = true` breaks commits (git reads `~/.gnupg` → deny-read list) — documented, not addressed. Real-macOS smoke verification is still pending for `sandbox-exec -p` acceptance of the FULL profile (incl. `(limit number 200)`) and of the root read allow, bash/dyld startup reads, SSH literal allows vs deny-precedence (if strict deny-precedence shadows `known_hosts`/`config`, git-over-SSH fails — then move the literals outside the `.ssh` deny-read subpath), and `/tmp` → `/private/tmp` aliasing; only pure `generate_profile/2` output is pinned. The Linux backend has the same `Path.join(repo_root, ".git")` shape but NO default-deny reads → harmless there; do NOT change it.

## Bwrap Backend — Filesystem-Only Isolation (bubblewrap)

`args/4` emits the bwrap argv for Linux where `systemd-run` is unavailable or undesirable (containers/docker, systemd-less distros, sandboxed CI); it needs only a `bwrap` binary and either root or unprivileged user namespaces — **no `evogit.slice` and no unit registry** (`ensure_initialized/0` is a no-op; the backend never touches `SandboxSlice`/`SandboxProcessRegistry`).

**Namespace shape** (validated against bwrap 0.11.2): `--unshare-user-try --unshare-ipc --unshare-pid --unshare-uts --unshare-cgroup-try` — exactly `--unshare-all` minus `--unshare-net`, spelled out so future bwrap versions adding namespaces to `--unshare-all` cannot silently change it. `-try` variants are skipped gracefully when the kernel/container blocks them, so the sandbox runs both as root in docker and as an unprivileged user with userns. **`--unshare-net` is deliberately absent** (network is retained for `git fetch/push`, `mix deps.get`, `curl`, web tools). `--die-with-parent` SIGKILLs the command if bwrap or the BEAM dies; `--new-session` runs setsid in bwrap's MAIN process before forking, so bwrap is the session leader (pgid == pid) and the whole tree is one process group.

**Rootless podman degradation (`:degraded` — `--unshare-pid` dropped)**: with container root but no `CAP_SYS_ADMIN` (e.g. `--userns=keep-id`) `mount(2)` is kernel-denied and the full argv exits 1 (`Creating new namespace failed` / `Failed to make / slave`). `--unshare-user-try` creates a NESTED USER NAMESPACE where the sandbox gains `CAP_SYS_ADMIN`, so bind/tmpfs/devtmpfs mounts work; only a FRESH procfs in a NEW pid namespace inside a user namespace stays denied, so `--unshare-pid` + `--proc` always fails there — verified: the exact argv MINUS `--unshare-pid` exits 0 (including `--proc` and `--dev`).
`probe_capability/0` runs the full argv against a trivial `true`, retrying with `--unshare-pid` removed: exit 0 → `:full`, pid-less exit 0 → `:degraded`, else `:unusable` (exceptions/missing bwrap → `:unusable`).
`capability/0` caches the probe in `:persistent_term` (`{EvoGit.Sandbox.Bwrap, :capability}`) with the override seam `Application.get_env(:evo_git, :bwrap_capability)` (`:full | :degraded | :unusable | :unknown`); both skip probing under `@mix_env == :test`, and `capability/0` also skips when no `bwrap` binary is on PATH.
`:degraded` emits the SAME argv with `--unshare-pid` REMOVED; `:full`/`:unknown`/`:unusable` keep the full shape. `enabled?/0` in `:auto` = `Platform.bwrap_available?() and capability() != :unusable` (degraded is still usable — filesystem isolation remains); the pid-namespace timeout-cleanup guarantee is absent there, while the process-group kill still works (`--new-session` setsid is independent of `--unshare-pid`).

**Filesystem layout (order matters)**: `--ro-bind / /` first (root read-only — the posture of `ProtectSystem=strict` and the macOS root read allow), `--dev /dev`, `--proc /proc`, `--bind-try` per `Platform.tmp_paths()`, `--bind-try` writable binds (cwd, resolved `[sandbox] write_paths`, `/nix/store` + `/nix/var` when `Nix.enabled?()`, git metadata dir), then `--tmpfs <home>/<dir>` deny overlays LAST so they override the ro-bind (bwrap has no `InaccessiblePaths` primitive).
`--bind-try` skips missing sources (`ALLOW_NOTEXIST` + `ENOENT` → `continue` in `setup_newroot`, 0.11.2 source) — systemd's `ReadWritePaths=-` semantics — and deny `--tmpfs` mounts are safe for non-existent dirs (bwrap creates the destination).
Deny list: 12 home-relative dirs (`.ssh`, `.gnupg`, `.aws`, `.kube`, `.config/sops`, `.git-credentials`, `.netrc`, `.password-store`, `.docker`, `.gem`, `.npmrc`, `.pypirc` — superset of linux.ex's 8, the macOS deny-read list minus `Library/Keychains`).

**Environment handling**: bwrap inherits the caller env (unlike `systemd-run --user`), so `PATH`/`HOME`/`NIX*`/`SSL_CERT_FILE` flow through. Explicit `--setenv` only where needed: `TMPDIR` → `resolve_tmpdir()` (on systemd desktops `$TMPDIR` is `/run/user/<uid>`, read-only inside) and the full `GitEnv.git_env_list(cwd)` for git commands (`GitEnv.git_command?/1`) — the BEAM carries no GitEnv-resolved identity and GitEnv's `"Genesis"`/`"noreply@evogit.ai"` fallback would not apply inside, so commits in unconfigured repos would fail with "Please tell me who you are".
⚠️ **GOption constraint**: the option parser STOPS at the first non-option argument (verified: `bwrap --ro-bind / / true --bogus` reports no "Unknown option"), so ALL `--setenv` args MUST precede the command — hence `git_env_args/1` is prepended before the `args/4` result.

**Timeout handling**: `run_with_partial/6` owns a `Port` directly (via `None.resolve_executable("bwrap")` — Port.open does no PATH search), reads the OS pid (`:erlang.port_info(port, :os_pid)`), redirects output to a temp file, and on timeout runs `kill -TERM -<pgid>` → 100 ms → `kill -KILL -<pgid>` then `kill -KILL <pid>` (killing bwrap triggers `--die-with-parent`, and the command being PID 1 in its pid namespace makes the kernel SIGKILL every remaining member — daemonized grandchildren included). Partial output comes from `Helpers.read_tempfile/2`; the `{:timeout, partial <> "\n[TRUNCATED due to timeout]"}` contract matches the other backends.

**Scope**: filesystem-only — **no resource limits and no syscall filtering** (no systemd-equivalent CPUQuota/MemoryMax).

## Configurable Writable Paths — `[sandbox] write_paths`

Linux (`-p ReadWritePaths=-<path>`), Bwrap (`--bind-try <path> <path>`) and macOS (`(allow file-write* (subpath "<path>"))`) resolve the writable cache-dir list from `EvoGit.Config.resolve([:sandbox, :write_paths])` (schema `:list_of_strings`, default `nil`):
- **`nil` (unset)** → the built-in default cache-dir list (`.cache`, `.local/share`, `.local/state`, `.cargo`, `.rustup`, `.mix`, `.hex`, `.npm`, `.yarn`, `.bun`, `.m2`, `.gradle`, `go`, home-relative).
- **set (even `[]`)** → the user's list REPLACES the default list; `[]` disables those write paths entirely.

**Path convention** (per entry): `~`-prefixed → `System.user_home!()`; absolute (leading `/`) → as-is; relative → joined to `System.user_home!()`. `Path.expand` is deliberately NOT used — env substitutions like `$HOME` are NOT expanded (a `$HOME/x` entry is a relative path component).

**Structural paths are ALWAYS appended** after the cache-dir list (required for the sandbox to function, NOT user-configurable): Linux appends `cwd`, `Platform.tmp_paths()`, nix `/nix/store` + `/nix/var` (when `Nix.enabled?()`), `<repo_root>/.git`, and the managed per-task tmpdir when installed (`List.wrap(Helpers.task_tmpdir_path/0)`); Bwrap emits writable `--bind-try` for `cwd`, `Platform.tmp_paths()`, nix store/var, the git metadata dir (same `git_metadata_dir/2` + `parse_gitdir_pointer/3` resolution as macOS; binds are per-path) and the per-task tmpdir when installed; macOS grants cwd, tmp paths, nix, repo `.git`, genesis dirs and the per-task tmpdir (read+write) in their own profile groups.

**Deny lists are NEVER affected** — the config replaces only the ALLOW/write list: Linux `InaccessiblePaths`, the Bwrap `--tmpfs` deny overlays and the macOS deny-read/deny-write sensitive lists stay as-is.

Implementation: all three backends define a `@default_cache_dirs` module attribute (kept local per platform) + delegate to the single public `EvoGit.Sandbox.Helpers.resolve_write_paths/3` (`config_paths, defaults, home`).

## Windows / None Backend — No-Sandbox Gap (Known Issue)

`EvoGit.Sandbox.None` is the fallback for Windows and unsupported platforms: **no OS-level isolation** — a documented gap, not an oversight; the timed path's only hardening is the process-tree kill. It DOES export the managed per-task tmpdir as `TMPDIR`/`TMP`/`TEMP` when one is installed (`Helpers.temp_env_vars/0`), but has NO writable-path gating — commands keep the user's own permissions and the system tmp dirs stay fully writable.

- `run/4` — `System.cmd(executable, args, cd: cwd, stderr_to_stdout: true, env: git_env)`: cwd confinement via `cd: cwd` (raises if missing); no command-injection surface (args as an ARRAY — deliberately NO shell wrapper on Windows); **no timeout — by contract** (`git add`/`commit` callers such as `EvoGit.sandbox_run/4` rely on it — do NOT add a default); git identity/`LC_ALL`/`GIT_EDITOR` via `GitEnv.git_env_list/1` plus the tmpdir vars on BOTH branches; PowerShell `["-Command", cmd]` args become `-EncodedCommand` (`Powershell.transform_args/2`, also run at the top of the Windows partial clause as defense-in-depth) and output runs through `Powershell.decode_output/1` (BOM-aware, idempotent) in BOTH return branches before `Helpers.truncate_output`.
- `run_with_partial/6` (Windows clause): a directly-owned `Port.open({:spawn_executable, ...})` with `System.cmd`'s option set (`:binary, :exit_status, :hide, :stderr_to_stdout`, args/cd/env), the env converted to CHARLISTS by `Helpers.port_env/1` (`open_port/2` requires charlist pairs — see pitfalls), so the OS pid is readable via `Port.info(port, :os_pid)`; the timeout path kills the whole process tree via `taskkill /PID <pid> /T /F` (walks cmd.exe/powershell grandchildren), driven by the pid from `wait_for_os_pid/2`, and output so far returns as `{:timeout, partial_output}` (truncated to `max_bytes`) — an IDLE timeout, not a total budget.
  Executable resolution uses `resolve_executable/1` (absolute paths as-is; else `System.find_executable/1` PATH/PATHEXT, then the Windows known-location `resolve_windows_executable/1` for `powershell`/`pwsh`; nil → `:erlang.error(:enoent)` to preserve `System.cmd/3` semantics); `EvoGit.Executable.resolve/1` pre-resolves on the dispatch path but returns the ORIGINAL name when no bundled file exists, so it never pre-empts it.

### Port/OS-pid pitfalls (`Port.open` vs `System.cmd` — verified on OTP 29)

- **`{:env, [...]}` accepts ONLY charlist tuples.** `{:env, [{"K","V"}]}` (binaries) raises `ArgumentError: invalid option in list`; `{:env, [{~c"K", ~c"V"}]}` works; the flat `~c"K=V"` form is invalid. `System.cmd/3` is safe with binaries only because it runs `validate_env/1` first. `Helpers.temp_env_vars/0` and `GitEnv.git_env_list/1` return `[{binary, binary}]` and are shared with `System.cmd` call sites and bwrap `--setenv` args — convert LOCALLY at the `Port.open` call site, never in the helper.
- **`{:cd, binary}` and `{:args, [binary]}` ARE accepted**; **`spawn_executable` does NO PATH search** (only an absolute path works — `System.cmd/3` resolves via `:os.find_executable/1` with `String.to_charlist/1`, avoiding the OTP 27+ binary trap).
- **`Port.info(port, :os_pid)` returns `{:os_pid, pid}`** while open (`wait_for_os_pid/2` unwraps it) and the port is ALREADY CLOSED after `{:exit_status, _}`: `Port.close/1` then raises `ArgumentError` — the timeout paths close via `Helpers.close_port/1`.
- **`receive … after timeout` is an IDLE timeout**: the timer restarts on every `{:data, _}`, so `collect_windows_output/5` never times out a child that keeps printing and `acc` grows unbounded (`max_bytes` applies after the loop; Unix backends buffer to a temp file).

### Windows Tree-Kill (`taskkill /T /F`)

- **Fires on IDLE, not total runtime**: a command silent longer than the idle window is KILLED mid-flight even if it would have completed (long quiet builds/clones/installs).
- **`os_pid` is resolved ONCE before collection** and never re-validated: the only guard is `is_integer(os_pid)`, with `:undefined` → `:ok`, so `taskkill /PID undefined` is never issued.
- **Completion race (real)**: the pid may be dead already (harmless) or RECYCLED, in which case `/T /F` kills an unrelated tree; an `{:exit_status, 0}` arriving during the blocking `taskkill` is discarded by `Helpers.drain_port_messages/1`, reporting a COMPLETED command as `{:timeout, partial_output}`. The kill result itself is discarded and NOTHING is logged — a failed/denied/wrong-pid `taskkill` is indistinguishable from success.
- **Blast radius is DESCENDANT-only**: `taskkill /T` walks the target's CURRENT descendants, so the tree can never contain the BEAM (the port child's parent) or its launcher `cmd.exe` — THIS CODE PATH CANNOT TERMINATE THE BACKEND BEAM (the realistic victim is a concurrent tool call's shell, and a kill mid-`git` can leave a stale `index.lock`).
- **The Windows route to BEAM death is the command STRING**: `ShellTool` hands the LLM's command verbatim to `powershell -EncodedCommand` with no allow-list (`agent/tools/CONTEXT.md`), so `taskkill /IM erl.exe /F` kills the backend from the inside; the Tauri shell's own `taskkill /PID <cmd.exe> /T /F` can kill the BEAM by design, but only from `run_bootstrap` and the quit/update force-kill paths.
- **The outer tool budget outranks the inner idle timeout**: the tool layer's 10 s default per-call budget (`agent/tool_dispatch.ex`) vs `ShellTool`'s advertised 180 s idle window means `Task.shutdown/1` can kill the tool Task first, so `taskkill` never runs.

### PowerShell Invocation — `-EncodedCommand`

PowerShell commands run via `-EncodedCommand` args built by the pure `EvoGit.Powershell` (`lib/evo_git/powershell.ex` — single source of truth for arg building + output decode; Linux-tested in `test/evo_git/powershell_test.exs`). `Platform.shell_args/1`'s Windows clause returns `invoke_args/1` (ShellTool + worktrees paths), and both `none.ex` Windows clauses also run `transform_args/2` for direct callers.

Why (do not re-investigate): `powershell.exe -Command <script>` spawned from Erlang re-joins and re-parses the raw command line as PowerShell code, so mangled quoting → INTERACTIVE mode → closed stdin → exit 0 with NO output; PS 5.1 also emits its OEM/UTF-16 code page, whose BOM `UTF8.ensure_utf8/1` rejects.
The invocation is `-NoProfile -NonInteractive -ExecutionPolicy Bypass -EncodedCommand <b64>` with `b64` = base64(`UTF-16LE`(`& { [Console]::OutputEncoding = [System.Text.Encoding]::UTF8; <script> } *>&1`)) — no command-line parsing, forced UTF-8, all streams merged.

**Residual risks (would need OS APIs):** arbitrary FS read/write where the user has access, no CPU/memory/process-count limits, no kill-tree on `run/4`, no network isolation, no AppContainer/restricted token — a real sandbox needs **Job Objects** (`CreateJobObject` + `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`) and an AppContainer/restricted token via a NIF or port program, or WSL2/Windows-Sandbox wrapping.

**Windows-only caveats (do not "fix"):** keep PATH/PATHEXT resolution so MinGit bash for skills scripts is found; the arg-array form avoids PowerShell's `<` redirection parse error (the Unix `bash -c "<cmd> < /dev/null"` wrapping stays Unix-only, and input redirection must never appear in the PowerShell invocation); keep `taskkill /PID <pid> /T /F` on timeout and the UNBOUNDED `run/4`; the `-EncodedCommand` transform applies ONLY to powershell/pwsh with the exact `["-Command", cmd]` 2-element shape.

**Testing note**: the Windows clauses are unreachable in the Linux/macOS suite (`Platform.windows?/0` is runtime `:os.type()`, not injectable) — the collect loop, `taskkill` path and transform/decode are compile-checked only; the pure logic is Linux-tested (`test/evo_git/powershell_test.exs`; `shell_args/1` branches on `Platform.os()`), and Windows runtime verification is required before further changes.

## TMPDIR Handling — managed per-task dir + always-writable system tmp dirs

Two layers are always in effect:
1. A managed **per-task** scratch dir (`EvoGit.TaskTmpdir`, `task_tmpdir.ex` — outside this node) shared by ALL agents of one task (never per-agent, never per-worktree); `path_for/2` derives it from `[tmp] mode` + task id — `:system` (default) → `<first Platform.tmp_paths/0 entry>/genesis/task_<id>`, `:custom` → `<[tmp] path>/genesis/task_<id>`, `:per_repo` → `<primary repo>/.genesis/tmp/task_<id>` (repo-less → `:system`). The runner installs it via `put_current/1`; the tool-dispatch layer re-installs it in every spawned tool task (they do NOT inherit the caller's process dict); `current/0` reads it.
2. The **system tmp dirs** (`Platform.tmp_paths/0` = `/tmp` + `/var/tmp` on Unix, `System.tmp_dir!()` on Windows) stay FULLY writable in every sandbox — some agents hardcode `/tmp`. The per-task dir is an ADDITIONAL writable path + a `TMPDIR` override — NEVER a `--tmpfs /tmp`, never a replacement.

`EvoGit.Sandbox.resolve_tmpdir/0` returns `TaskTmpdir.current/0` DIRECTLY when a per-task dir is installed (the backends make it writable); otherwise the legacy per-BEAM constant: `$TMPDIR` unset → the first `Platform.tmp_paths/0` entry (`/tmp`); set → kept ONLY when it exists AND is equal to / under a tmp path, else `/tmp` (so the macOS host `$TMPDIR` under `/var/folders/...` never survives).
**The Nix dev-env wrap must not rotate the injected TMPDIR** (it is sourced INSIDE the sandbox): `Nix.wrap_command/2` emits `bash -c "source '<data_dir>/nix-dev-env.sh'; exec <escaped-command>"`, because the raw `nix print-dev-env` epilogue would `mktemp -d -t nix-shell.XXXXXX` and re-export `TMPDIR`/`TMP`/`TEMP`/`TEMPDIR`/`NIX_BUILD_TOP` to a fresh 0700 dir on EVERY source.
**Sanitization**: `Nix.do_build_dev_env/0` runs the public pure `Nix.sanitize_dev_env_output/1` (a single `String.replace/3`) on that output before caching, replacing the single literal `export NIX_BUILD_TOP="$(mktemp -d -t nix-shell.XXXXXX)"` with `export NIX_BUILD_TOP="${TMPDIR:-/tmp}"`; the following `TMP*` exports reference `$NIX_BUILD_TOP`, so no per-call dirs are created and (nix's only cleanup, `rm -f <rcfile>`, never touched `NIX_BUILD_TOP`) nothing accumulates.
A nix that stops emitting the literal makes the replace a no-op and caches the raw output; output is byte-identical across rebuilds for a given invocation cwd (only `out=`, `prefix=` and the `NIX_LDFLAGS` `-rpath` embed it) and the cache hash keys flake.nix content only; when the wrap is NOT active (`[nix] enabled=false`, build failed, no config-dir flake) TMPDIR is likewise the `resolve_tmpdir/0` value.

Each SANDBOX-ENABLED backend injects that value AS `TMPDIR` and ADDITIONALLY grants it write access (both read `TaskTmpdir.current/0` in the same tool-invocation process, so they always agree); disable/None paths export it as an env override only:
- **systemd-run**: `--setenv=TMPDIR=<resolve_tmpdir()>` plus an extra `-p ReadWritePaths=-<taskdir>` (the `-` prefix keeps a missing path non-fatal); `-p ReadWritePaths=-/tmp -/var/tmp` (rw on the REAL host dirs) stays, `ProtectSystem=strict` makes the rest of `/` read-only, and there is no `PrivateTmp` — each fresh unit uses the host's `/tmp`, so files persist across invocations.
- **bwrap (full AND `:degraded`)**: `--setenv TMPDIR <resolve_tmpdir()>` plus `--bind-try <taskdir> <taskdir>` spliced after the always-present `--bind-try /tmp /tmp` + `/var/tmp` and before the `--` separator (GOption); `:degraded` differs ONLY by dropping `--unshare-pid`.
- **sandbox-exec**: an extra read+write pair for the per-task dir (`(allow file-read* (subpath "<taskdir>"))` + the write counterpart, after `tmp_rules`) and `env: [{"TMPDIR", resolve_tmpdir()}]`; the per-tmp-path rules stay, and the read-only host-`$TMPDIR` rule keeps pre-sandbox BEAM temp files readable.
- **None / Windows + every DISABLED path**: the per-task dir (when installed) IS exported as `TMPDIR`/`TMP`/`TEMP` via `Helpers.temp_env_vars/0`, appended to every non-sandboxed spawn env — `None`'s four clauses AND the Linux/Bwrap/MacOS disabled branches — with no isolation and NO writable-path gating (the dir is ADDITIONAL, never a replacement).
- **Shared derivation**: `Helpers.task_tmpdir_path/0` derives from `TaskTmpdir.current/0` (`nil` when unset; each backend shapes it via `List.wrap/1`); `Helpers.temp_env_vars/0` (built on it) is the single env-override source: `[{"TMPDIR", dir}, {"TMP", dir}, {"TEMP", dir}]` when installed, else `[]`.
- **Runtime-owned temp files land under `resolve_tmpdir/0`**: `Helpers.partial_output_tmpfile/0` → `<dir>/genesis_partial_outputs/`; skills scripts → `<dir>/evogit_skill_<n>.sh` (`skills/executor.ex`; Windows `System.tmp_dir!()`); git `-F` files → `<dir>/genesis_ctx_msg_<n>.txt` (`agent/tools/context.ex`) and `System.tmp_dir!()/genesis_git_msg_<n>` (`adapters/git.ex`) — cleanup below.
- **Cleanup is best-effort, NOT uniform, and there is NO runtime-wide temp sweep**: the git `-F` files use `try/after File.rm`, partial-output tmpfiles `read_tempfile/2`'s own `File.rm`, skills scripts and remote-bootstrap `genesis-remote-*` files a bare `File.rm`. Leaks come from a raise between write and cleanup (e.g. missing bash → `ErlangError(:enoent)`, or `run_task_with_partial/7` matching no clause for `Task.yield`'s `{:exit, reason}`), a killed owner, or a BEAM crash; per-task dirs are reclaimed by `TaskTmpdir` (`reclaim/2`), stray system-tmp files are never swept at boot.
- **Agent guidance**: the ShellTool schema tells agents to use `$TMPDIR` ("never /tmp" on POSIX) — inside a Linux/bwrap/macOS sandbox that is the per-task dir; `/tmp` + `/var/tmp` stay writable, hence cross-agent visible to every sandboxed command of the same OS user.
- **Cross-worktree visibility**: other agents' worktrees are READABLE (bwrap `--ro-bind / /`, systemd `ProtectSystem=strict`, macOS root read allow), WRITE access confined to `cwd` + tmp dirs + configured caches + `.git`.
- Tests (sibling `test/evo_git/sandbox/`) pin the enabled-path forwarding (`ReadWritePaths=-/tmp`, bwrap `--setenv TMPDIR` incl. degraded, macOS `resolve_tmpdir/0`), the disabled-path export (real `bash -c` echoing `TMPDIR`/`TMP`/`TEMP`), `temp_env_vars/0`, `genesis_partial_outputs` and the unset fallback; they install a dir via `put_current/1` (+ `on_exit`).

## Skills Script Execution Through the Sandbox

`skills/executor.ex` (outside this node) runs scripts via `EvoGit.sandbox_run(repo_path, "bash", [tmp_file | values], nil)` on Linux/macOS (script under `resolve_tmpdir()`, values as positional argv `$1..$N`), and directly via `System.cmd(bash_path, [tmp_file | values], cd: repo_path, ...)` on Windows (argv-style, injection-safe); a `System.find_executable("bash")` guard returns the friendly "Install Git for Windows" error, since a bare `sandbox_run` without bash raises `ErlangError(:enoent)`.
The script path is writable in every enabled backend through the grants above (Linux `ReadWritePaths` incl. the per-task dir; bwrap writable `--bind-try`; macOS tmp groups 5/10 or the per-task rule), `--ro-bind / /` keeps the rest readable, and the 8/12 deny lists hide credential stores; Windows needs no shell.
`sandbox_run_with_partial/6` is available for a timeout (`{:ok, output, code} | {:timeout, partial}`); `Helpers.shell_escape/1` safely quotes the script path in the assembled `bash -c` string; `Nix.wrap_command/2` accepts any executable name.

## Constraints
- All backends implement `@behaviour EvoGit.Sandbox.Behaviour`; callers use `EvoGit.sandbox_run/4` (→ `EvoGit.Sandbox.run/4`) and never need to know about backends.
- Shared helpers live in `EvoGit.Sandbox.Helpers` — the anti-duplication home (full list in API Surface); new cross-backend helpers belong there, and backends plus `EvoGit.Nix` alias and delegate to it.
- `shell_escape/1` is **security-sensitive** (command injection prevention) — exactly one definition.
- `kill_process_tree/1` is total (POSIX `kill -TERM -- -<pgid>` → 100 ms → `kill -KILL -- -<pgid>` with a bare-pid fallback when the group is gone; Windows `taskkill /PID <pid> /T /F`; always `:ok`); it expects a session/process-group leader, which `bwrap --new-session` and the `wait_for_os_pid/2` spawn shapes both give. The 100 ms grace is a CALL-TIME app-env seam, `Application.get_env(:evo_git, :kill_grace_ms, @kill_grace_ms)` (production default `@kill_grace_ms` = 100 ms, non-integer/negative values ignored), read at BOTH `Process.sleep` sites in `posix_kill_tree/1`; tests that only poll for the killed pid set it to 0-10 ms.
- `EvoGit.Sandbox.Linux` depends on `EvoGit.SandboxProcessRegistry` (caller-process monitoring) and `EvoGit.SandboxSlice` (systemd slice management) — both started in the Application supervision tree on Linux only.
- `EvoGit.Sandbox.Bwrap` depends on NEITHER — `ensure_initialized/0` is a no-op; it needs only a `bwrap` binary (+ root or userns); its `--setenv` args MUST precede the command.
- `EvoGit.Sandbox.MacOS` uses inline SBPL generation (no template files); the profile is PURE SBPL — no `#` comments inside (support unvalidated; rationale lives in Elixir source comments).
- `EvoGit.Nix` is a standalone helper (not a backend) — backends consult it to optionally wrap commands; it depends on `EvoGit.Config` (`[nix]` table + config dir) and `EvoGit.Platform` (`nix_available?/0`); when active, Linux forwards all `NIX*` + `SSL_CERT_FILE` via `--setenv` and grants read-write to `/nix/store` + `/nix/var`, macOS adds both to its profile, Bwrap grants writable `--bind-try` for both and relies on env INHERITANCE, None inherits the parent env.
- All four source the cached dev-env script via `bash -c` rather than per-call `nix develop`; `nix_paths`/`nix_env_vars` gating uses `Nix.enabled?/0` (static) while the wrap decision uses `Nix.active?/0`.

## Known Issues / Test Strategy
- **OTP 27+ `:os.find_executable/1` binary trap:** raw `:os.find_executable/1` raises `ArgumentError` on Elixir BINARY input on OTP 27+ (`verify_executable/3` appends a CHARLIST `.exe` suffix). `None.resolve_executable/1` works around it via `System.find_executable/1` (converts to charlist internally) plus the Windows known-location fallbacks. **Rule: never call raw `:os.find_executable/1` with an Elixir binary on OTP 27+.**
- **Test coverage gap:** `linux_test.exs`/`bwrap_test.exs` test only `args/4` generation, `macos_test.exs` only `generate_profile/2` string assertions. NO test executes a real sandboxed command (systemd-run/sandbox-exec/bwrap) — the `@mix_env == :test` gates in `Linux.enabled?/0`/`Bwrap.enabled?/0` and Linux-only CI leave all four enabled paths runtime-verified only, and the Windows clauses are compile-checked only.
- **Bwrap real-execution caveat:** real bwrap needs a host where `mount(2)` works — a systemd-run unit with read-only `/` blocks it (`bwrap: Failed to make / slave: Operation not permitted`), so only flag syntax is validated there; the argv shape is parse-validated against bwrap 0.11.2 and its source (`setup_newroot` `ALLOW_NOTEXIST` skip, `--unshare-all` = try-variants for user/cgroup, setsid-before-fork). Rootless podman: use the `:bwrap_capability` override seam (probing never runs in tests).
- **Backend-selection invariant:** `Linux.enabled?/0` needs NO `backend() == EvoGit.Sandbox.Linux` guard — the dispatcher consults only the SELECTED backend's `enabled?/0`, and `SandboxSlice.sandbox_enabled?/0`/`SandboxProcessRegistry.sandbox_enabled?/0` are gated on `EvoGit.Sandbox.backend() == EvoGit.Sandbox.Linux`, so the slice/unit-registry machinery activates only for Linux; the `@mix_env == :test` gate stays first.
- **macos_test.exs is partially pinned** (sibling test node; full assertions: `test/evo_git/sandbox/macos_test.exs`): `(deny default)`, deny-read for 8 of the 13 sensitive dirs (`.config/sops`, `.npmrc`, `.pypirc`, `.gem`, `Library/Keychains` NOT pinned), cwd/tmp and `/repo/.git` r/w, `(limit number 200)` exactly once, no nix rules, all write_paths behaviors, the root read rule, the ten system-level deny-read spellings, the `.git` variants (literal, linked-worktree pointer → COMMON dir, nil repo_root + pointer, plain dir + nil → NO rule) and the vendored-git read rule.
- **Nix dev-env wrapping is skipped on Windows (open)**: `Nix.active?/0` has no platform gate, but neither `run_windows/3` nor `run_with_partial_windows/5` consults it (only the `run_unix` clauses wrap) — Windows commands run WITHOUT the dev-env `source` every Unix backend performs.
- **`(limit ...)` syntax unverified on real macOS** — mitigated by the fail-safe retry; validate on a Mac and fix `generate_profile/2` if the form is wrong (tests pin `(limit number 200)`).
- **No app-env sandbox switch exists**: `Application.put_env(:evo_git, :sandbox, :disabled)` is a NO-OP and `config/config.exs`'s `config :evo_git, sandbox: :auto` is unread — mode/backend resolve only via `EvoGit.Config.resolve([:sandbox, :mode|:backend])` (defaults → user TOML → runtime overrides).
