# Sandbox — Multi-Platform Sandbox Backend

## Intent
Provides platform-specific sandboxing for agent-executed commands. Dispatches to the appropriate backend based on `EvoGit.Platform.sandbox_backend/0`.

## Routing Table
None — leaf directory (modules: `behaviour.ex`, `bwrap.ex`, `helpers.ex`, `linux.ex`, `macos.ex`, `nix.ex`, `none.ex`; `EvoGit.Sandbox` dispatcher is a sibling file `lib/evo_git/sandbox.ex` — outside this node, read-only for agents here). Test suite is at `apps/evo_git/test/evo_git/sandbox/` — also a sibling node (read-only from here; escalate test-file changes to the parent).

## API Surface
| Module | Description |
|---|---|
| `EvoGit.Sandbox` | Dispatch module (sibling file `lib/evo_git/sandbox.ex`) — routes to the active backend. `run/4` + `run_with_partial/6` accept ANY executable name + args list (no allowlist) — the skills executor can pass `("bash", [script_path])` unchanged |
| `EvoGit.Sandbox.Behaviour` | Formal `@behaviour` contract all backends implement (`enabled?/0`, `ensure_initialized/0`, `run/4`, `run_with_partial/6`) |
| `EvoGit.Sandbox.Helpers` | Shared utilities: `shell_escape/1` (POSIX-safe, security-sensitive), `read_tempfile/2` (temp read + delete, optional truncation), `system_cmd/2` (normalized `System.cmd` wrapper) |
| `EvoGit.Sandbox.Linux` | Linux/systemd-run backend — full sandboxing (ReadWritePaths/InaccessiblePaths, ProtectHome/System, resource limits, slice). `ReadWritePaths` cache-dir list configurable via `[sandbox] write_paths` (see "Configurable Writable Paths") |
| `EvoGit.Sandbox.Bwrap` | Linux/bubblewrap backend — **filesystem-only isolation** (no resource limits/syscall filtering): `--ro-bind / /` + writable binds + empty-`--tmpfs` deny overlays. **No slice/unit-registry dependency** (`ensure_initialized/0` no-op; never touches `SandboxSlice`/`SandboxProcessRegistry`). Network retained (no `--unshare-net`). Namespaces `--unshare-user-try --unshare-ipc --unshare-pid --unshare-uts --unshare-cgroup-try` + `--die-with-parent` + `--new-session`. Capability probing (`probe_capability/0` uncached + `capability/0` cached in `:persistent_term`, `Application.get_env(:evo_git, :bwrap_capability)` override) detects rootless-podman envs (`:full \| :degraded \| :unusable \| :unknown`) → `:degraded` drops `--unshare-pid`. `run_with_partial/6` kills the process group on timeout (`kill -TERM -<pgid>` → `-KILL`). | `EvoGit.Sandbox.MacOS` | macOS/sandbox-exec backend — SBPL profile: root-readable READS (`(allow file-read* (subpath "/"))`) + deny-read credential-store list, deny-by-default WRITES with explicit allow list, process-count limit (with fail-safe), default-allow network. Details below |
| `EvoGit.Sandbox.None` | Passthrough backend — no OS-level isolation on Windows/unsupported platforms; `run_with_partial` Windows clause kills the whole process tree on timeout via `taskkill /PID <pid> /T /F` (walks cmd.exe/powershell grandchildren, not just the direct child), driven by the OS pid resolved by `wait_for_os_pid/2`. Public `resolve_executable/1` — binary-safe executable resolution for direct port spawning (normalizes via `to_string/1`; absolute paths as-is when regular files; PATH/PATHEXT via `System.find_executable/1`; Windows known-location fallback for `powershell`/`pwsh`; `nil` when not found) |

## Behaviour Contract
All four backends (`Linux`, `Bwrap`, `MacOS`, `None`) formally implement `@behaviour EvoGit.Sandbox.Behaviour`:
- `enabled?/0` — sandboxing available for this platform/mode
- `ensure_initialized/0` — lazily initialize backend resources (e.g. systemd slice); no-op when unneeded
- `run/4` — synchronous execution returning `{output, exit_code}`
- `run_with_partial/6` — execution with timeout + partial-output recovery returning `{:ok, output, exit_code}` or `{:timeout, partial_output}`

## macOS SBPL Profile — Root-Readable Reads + Deny-List Policy

`generate_profile/2` (`macos.ex`) emits `(deny default)` with READS allow-by-default at the ROOT; protection for sensitive locations comes from the deny-read list (SBPL deny precedence: denies win over allows). Writes are deny-by-default with an explicit allow list. The specific read rules (nix, home, host `$TMPDIR`, vendored git, file-read-metadata, ssh literals) are REDUNDANT under the root-wide read allow but intentionally KEPT as belt-and-suspenders. Emitted rule groups, in order:

1. `(version 1)` / `(deny default)`
2. **Root read allow**: `(allow file-read* (subpath "/"))` — whole filesystem readable (Homebrew `/opt/homebrew`, Intel `/usr/local`, `/Applications`, custom `/opt` installs, nix, asdf/mise); deny rules still win; WRITES not covered
3. **Nix** (only when `Nix.enabled?()`): read+write `/nix/store`, `/nix/var`
4. **Repo**: read+write on `cwd` (worktree) and `<repo_root>/.git` — the git rule resolves linked-worktree `gitdir:` pointers (`.git`-as-file) to the COMMON git dir (see "macOS Git Commit Coverage")
5. **Tmp**: read+write on `Platform.tmp_paths()` (`/tmp`, `/var/tmp`)
6. **Genesis dirs**: read+write on `Platform.config_dir()` + `Platform.data_dir()` (macOS: `~/Library/Application Support/genesis` — NOT under /tmp or repo)
7. **Home read allow** `(allow file-read* (subpath home))` — tool configs (`~/.gitconfig`; `.npmrc` is deny-read) — then immediately after:
8. **Deny-read sensitive list** (deny beats allow in SBPL): `.ssh`, `.gnupg`, `.aws`, `.kube`, `.config/sops`, `.git-credentials`, `.netrc`, `.password-store`, `Library/Keychains`, `.npmrc`, `.pypirc`, `.docker`, `.gem` (credential stores; Linux InaccessiblePaths parity) — **plus system-level sensitive locations** (defense in depth under the root-wide read allow; both symlink spellings `/etc`↔`/private/etc` and `/var`↔`/private/var`): `/etc/ssh` + `/private/etc/ssh` (host SSH keys), `/var/root` + `/private/var/root` (root's home), `/etc/master.passwd` + `/private/etc/master.passwd` (password hashes), `/var/db/dslocal` + `/private/var/db/dslocal` (local user account DB), `/var/db/Keychains` + `/private/var/db/Keychains` (system keychains)
9. **SSH host-verification literal reads**: `(allow file-read-data (literal "<home>/.ssh/known_hosts"))` + `.ssh/config` — keeps `git fetch/push` over SSH working for public repos while private keys stay blocked; key-auth needs ssh-agent (`SSH_AUTH_SOCK`)
10. **Host `$TMPDIR` read** `(allow file-read* (subpath <expanded $TMPDIR>))` — CRITICAL: macOS per-user tmp is `/var/folders/...`, NOT under `/tmp`; temp files written via `System.tmp_dir!()` BEFORE the sandbox starts must remain readable inside. Skipped when `$TMPDIR` unset
11. `(allow file-read-metadata)` unqualified — stat/ls/glob on arbitrary paths under default-deny
12. **Writes**: home build-cache dirs (`.cache`, `.local/share`, `.local/state`, `.cargo`, `.rustup`, `.mix`, `.hex`, `.npm`, `.yarn`, `.bun`, `.m2`, `.gradle`, `go`) — package managers/toolchains (`mix deps.get`, `npm install`, `cargo build`) must write caches; plus `/dev/null` + `/dev/dtracehelper` literals. **Configurable via `[sandbox] write_paths`** — nil (unset) = this default list; set (even `[]`) = the user's list REPLACES it (see "Configurable Writable Paths")
13. **Deny-write sensitive list** (defense in depth): `.ssh`, `.gnupg`, `.aws`, `.kube`, `.config/sops`, `.npmrc`, `.git-credentials`, `.netrc`
14. **Process limit**: `(limit number #{@max_processes})` (`@max_processes 200`, module attribute, tunable) + `(allow process-exec)`, `(allow process-fork)`
15. **Network: `(allow network*)` KEPT (default-allow), deliberate** — agents legitimately run `git fetch/push`, `mix deps.get`, `curl`, web tools; default-deny network breaks core workflows. Primary boundary = the tightened filesystem + process limits. **Future extension point (schema proposal, NOT implemented):** a `[sandbox] network_mode = "allow" | "deny"` TOML key belongs in `config/schema/` (outside this node) to gate this rule.
16. mach/sysctl/ipc: `(allow mach-lookup)`, `(allow sysctl-read)`, `(allow process-info*)`, `(allow signal)`, `(allow ipc-posix-sem)`, `(allow ipc-posix-shm)`

### Process-limit fail-safe — do not remove
The exact SBPL `limit` parameter syntax (`(limit number N)` vs `(limit (number N))`) is unverified without a macOS host (CI is Linux; `sandbox-exec` unavailable) — a wrong form would make `sandbox-exec` reject the WHOLE profile → every sandboxed command fails on macOS in `:auto` mode (the default). Therefore `run/4` and `run_with_partial/6` (enabled paths) implement a fail-safe: on non-zero exit with no cached decision, retry ONCE with `strip_process_limit(profile)`; on retry success, cache `true` at `:persistent_term` key `{EvoGit.Sandbox.MacOS, :process_limit_rejected}` and warn once; subsequent calls use the stripped profile directly. On healthy macOS: zero overhead (first attempt succeeds). On a rejecting macOS: one extra spawn once, then only the process-count limit is lost. Keep this machinery even if the syntax is confirmed on real macOS — cheap insurance. `generate_profile/2` still emits the limit; the fallback only catches rejection.

### Real-macOS validation points (unverifiable on Linux CI)
- `sandbox-exec -p` acceptance of the FULL profile (all rules incl. `(limit number 200)`) and of `(allow file-read* (subpath "/"))` — the root-wide read rule is unvalidated syntax
- bash/dyld startup reads (covered by the root read allow)
- SSH literal allows vs deny-precedence: if strict deny-precedence shadows `known_hosts`/`config` literals, git-over-SSH host verification fails (then move the literals outside the `.ssh` deny-read subpath)
- `/tmp` → `/private/tmp` symlink aliasing (existing rules use literal `/tmp`/`/var/tmp`)

## macOS Git Commit Coverage

The `write_context`/`edit_context` commit path (`agent/tools/context.ex`) calls `EvoGit.sandbox_run(repo_path, "git", ["add", relative_path], repo_root)` + `EvoGit.sandbox_run(repo_path, "git", ["commit", ...], repo_root)` → `Sandbox.run/4` → `MacOS.run/4` wraps in `bash -c "git ... < /dev/null"` (macos.ex) → `sandbox-exec`. The CONTEXT.md file write itself is UNSANDBOXED `File.write` (context.ex). Both `do_context_write/5` and `do_context_edit/8` check git exit codes: `{output, 0}` on both add + commit → success message; a failing step returns `"Error: git add failed (exit N):\n..."` / `"Error: git commit failed (exit N):\n..."` so the LLM can retry/report.

The git rule resolves the REAL git metadata dir via `git_metadata_dir/2` + `parse_gitdir_pointer/3` (macos.ex): when `<repo_root>/.git` is a regular FILE (linked-worktree `gitdir:` pointer), the read/write rule subpath becomes the COMMON git dir (prefix before the LAST `/worktrees/` segment of the resolved target, computed via `:binary.matches`/`:binary.part` — NOT `String.split`, which is ambiguous when the path itself contains `worktrees`); when `.git` is a dir → literal `<repo_root>/.git`; repo_root nil + no `.git` dir → no git rule; repo_root nil + `.git` dir → literal `<cwd>/.git`. A vendored-git read rule is emitted when `EvoGit.Executable.resolve("git")` returns an ABSOLUTE path (desktop bundle, git off PATH): `(allow file-read* (subpath "<dirname of binary>"))` so the bundled binary + support files are readable (redundant under the root read allow, kept as belt-and-suspenders).

**Remaining caveats (by design):** `commit.gpgsign = true` breaks commits (git reads `~/.gnupg` → deny-read list) — documented, not addressed. Real-macOS smoke verification is still pending (incl. `sandbox-exec -p` acceptance of `(allow file-read* (subpath "/"))`) — CI is Linux, only pure-function `generate_profile/2` tests pin the output (see Known Issues). Linux backend has the same `Path.join(repo_root, ".git")` shape (linux.ex:172-186) but NO default-deny reads (no ReadOnlyPaths/ProtectSystem in args, linux.ex:222-247) → harmless there; do NOT change it.

## Bwrap Backend — Filesystem-Only Isolation (bubblewrap)

`args/4` (`bwrap.ex`) emits the bwrap argv for Linux environments where `systemd-run` is unavailable or undesirable (containers/docker, systemd-less distros, sandboxed CI). It needs only a `bwrap` binary and either root privileges or unprivileged user namespaces — **no `evogit.slice` slice and no unit registry** (`ensure_initialized/0` is a no-op; the backend never touches `SandboxSlice`/`SandboxProcessRegistry`).

**Namespace shape** (verified against bwrap 0.11.2): `--unshare-user-try --unshare-ipc --unshare-pid --unshare-uts --unshare-cgroup-try` — exactly `--unshare-all` minus `--unshare-net`, spelled out so future bwrap versions adding namespaces to `--unshare-all` do not silently change the shape. user/cgroup use `-try` variants (bwrap skips them gracefully when the kernel/container blocks them) so the sandbox RUNS both as root in docker and as an unprivileged user with userns enabled. **`--unshare-net` is deliberately NOT used** — the network namespace is retained so `git fetch/push`, `mix deps.get`, `curl` and web tools keep working, matching both other Unix backends. `--die-with-parent` (SIGKILL the sandboxed command if bwrap or the BEAM parent dies) + `--new-session` (setsid runs in bwrap's MAIN process BEFORE forking → bwrap is session leader, pgid == bwrap's pid → the whole sandbox tree is one process group).

**Rootless podman degradation (`:degraded` mode — `--unshare-pid` dropped)**: in rootless podman containers (container root WITHOUT `CAP_SYS_ADMIN`, e.g. `podman run` as an unprivileged user / `--userns=keep-id`) `mount(2)` is kernel-denied, so the full argv always exits 1 (`Creating new namespace failed: Operation not permitted` / `Failed to make / slave` / `Can't mount proc on /newroot/proc: Operation not permitted`). The escape hatch is the NESTED USER NAMESPACE: `CLONE_NEWUSER` is allowed in the container, bwrap's existing `--unshare-user-try` creates one, and inside it the sandbox gains `CAP_SYS_ADMIN` so all bind/tmpfs/devtmpfs mounts work. The only remaining blocker: the kernel refuses to mount a FRESH procfs inside a NEW pid namespace created within a user namespace — so `--unshare-pid` + `--proc` always fails there. Empirically verified: the exact current argv MINUS `--unshare-pid` exits 0 (including `--proc` and `--dev`). `probe_capability/0` detects this at runtime (runs the full argv against a trivial `true`; on failure retries with `--unshare-pid` removed): exit 0 → `:full`, pid-less exit 0 → `:degraded`, else `:unusable`; exceptions (missing bwrap) → `:unusable`. `capability/0` caches the probe result in `:persistent_term` (`{EvoGit.Sandbox.Bwrap, :capability}`) with an override seam `Application.get_env(:evo_git, :bwrap_capability)` (any of `:full | :degraded | :unusable | :unknown`) — both skip probing in the test env (`@mix_env == :test`) and `capability/0` also skips when no `bwrap` binary is on PATH. In `:degraded` mode `args/4` emits the SAME argv with `--unshare-pid` REMOVED (everything else identical); `:full`/`:unknown`/`:unusable` keep the current shape. `enabled?/0` in `:auto` mode = `Platform.bwrap_available?() and capability() != :unusable` (a `:degraded` host still counts as usable — filesystem isolation remains). The pid-namespace timeout-cleanup guarantee is absent in degraded mode; the process-group kill still works unchanged (`--new-session` setsid is independent of `--unshare-pid`).

**Filesystem layout (order matters)**: `--ro-bind / /` first (whole root read-only — "everything readable, writes restricted", same posture as `ProtectSystem=strict` and the macOS root read allow), `--dev /dev`, `--proc /proc`, `--bind-try` per `Platform.tmp_paths()` (writable), `--bind-try` writable binds (cwd, resolved `[sandbox] write_paths`, `/nix/store` + `/nix/var` when `Nix.enabled?()`, git metadata dir), then `--tmpfs <home>/<dir>` deny overlays LAST (after the ro-bind so they override it — bwrap's replacement for `InaccessiblePaths`; bwrap has no "inaccessible" primitive). `--bind-try` (not `--bind`) makes missing writable-path sources skip the mount op entirely (`ALLOW_NOTEXIST` + `ENOENT` → `continue` in `setup_newroot`, verified in the 0.11.2 source) — exactly systemd's `ReadWritePaths=-` semantics. The deny `--tmpfs` mounts are safe for non-existent dirs (bwrap mkdir_with_parents the destination). Deny list: 12 home-relative dirs (`.ssh`, `.gnupg`, `.aws`, `.kube`, `.config/sops`, `.git-credentials`, `.netrc`, `.password-store`, `.docker`, `.gem`, `.npmrc`, `.pypirc` — superset of linux.ex's 8, mirrors the macOS deny-read list minus `Library/Keychains`).

**Environment handling**: bwrap inherits the caller env (unlike `systemd-run --user`), so `PATH`/`HOME`/`NIX*`/`SSL_CERT_FILE` flow through WITHOUT injection. Explicit `--setenv` only where needed: `TMPDIR` → `EvoGit.Sandbox.resolve_tmpdir()` (on systemd desktops `$TMPDIR` is `/run/user/<uid>`, read-only inside), and the full `EvoGit.GitEnv.git_env_list(cwd)` when the original executable is a git command (`GitEnv.git_command?/1`). The BEAM process does NOT carry the GitEnv-resolved identity vars, and GitEnv's `"Genesis"`/`"noreply@evogit.ai"` fallback would NOT apply inside the sandbox — without injection, commits in unconfigured repos would fail with "Please tell me who you are". ⚠️ **GOption constraint**: bwrap's option parser STOPS at the first non-option argument (empirically verified — `bwrap --ro-bind / / true --bogus` reports no "Unknown option"), so ALL `--setenv` args MUST precede the command; `run/4`/`run_with_partial/6` prepend `git_env_args/1` before the `args/4` result for this reason.

**Timeout handling**: no systemd unit to stop, so `run_with_partial/6`'s enabled path owns a `Port` directly (via `EvoGit.Sandbox.None.resolve_executable("bwrap")` — Port.open does no PATH search), reads the OS pid (`:erlang.port_info(port, :os_pid)`), redirects output to a temp file, and on timeout kills the whole sandbox: `kill -TERM -<pgid>` → 100ms grace → `kill -KILL -<pgid>` (negative pgid = bwrap's own pgid, session leader), then a direct `kill -KILL <pid>` as belt-and-suspenders (killing bwrap triggers `--die-with-parent`; and because the sandboxed command is PID 1 in its pid namespace, its death makes the kernel SIGKILL every remaining namespace member — this also catches daemonized grandchildren that escaped the process group). Partial output is recovered from the temp file via `Helpers.read_tempfile/2`; the `{:timeout, partial <> "\n[TRUNCATED due to timeout]"}` contract matches the other backends.

**Scope**: filesystem-only isolation — **no resource limits and no syscall filtering** (bwrap has no systemd-equivalent CPUQuota/MemoryMax). Validated against bwrap 0.11.2; real execution requires a host where `mount(2)` works.

## Configurable Writable Paths — `[sandbox] write_paths`

Linux (`args/4` → `-p ReadWritePaths=-<path>`), Bwrap (`args/4` → `--bind-try <path> <path>` writable bind), and macOS (`generate_profile/2` → `(allow file-write* (subpath "<path>"))`) resolve the writable cache-dir list from `EvoGit.Config.resolve([:sandbox, :write_paths])` (schema key `:list_of_strings`, default `nil`):

- **`nil` (unset)** → the built-in default cache-dir list (`.cache`, `.local/share`, `.local/state`, `.cargo`, `.rustup`, `.mix`, `.hex`, `.npm`, `.yarn`, `.bun`, `.m2`, `.gradle`, `go`, home-relative).
- **set (even `[]`)** → the user's list REPLACES the default cache-dir list; `[]` disables the cache-dir write paths entirely.

**Path convention** (per entry): `~`-prefixed → `System.user_home!()` (e.g. `~/cache` → `<home>/cache`, bare `~` → `<home>`); absolute (leading `/`) → used as-is; relative → joined to `System.user_home!()` (the same base the defaults use). `Path.expand` is deliberately NOT used — env substitutions like `$HOME` are NOT expanded (a `$HOME/x` entry is treated as a relative path component).

**Structural paths are ALWAYS appended** after the cache-dir list — they are required for the sandbox to function, NOT part of the user-configurable list: Linux appends `cwd`, `Platform.tmp_paths()`, nix `/nix/store` + `/nix/var` (when `Nix.enabled?()`), `<repo_root>/.git`, and the managed per-task tmpdir when installed (`List.wrap(Helpers.task_tmpdir_path/0)`); Bwrap emits writable `--bind-try` for `cwd`, `Platform.tmp_paths()`, nix store/var, the git metadata dir (linked-worktree `gitdir:` pointers resolved to the COMMON git dir via `git_metadata_dir/2` + `parse_gitdir_pointer/3` — same logic as the macOS backend; bwrap binds are per-path, not per-tree), and the per-task tmpdir when installed; macOS always grants cwd, tmp paths, nix, repo `.git`, genesis dirs, and the per-task tmpdir (read+write) in their own profile groups.

**Deny lists are NEVER affected** — the config replaces only the ALLOW/write list: Linux `InaccessiblePaths` (sensitive-dir deny), the Bwrap `--tmpfs` deny overlays, and the macOS deny-read/deny-write sensitive lists stay exactly as-is.

Implementation: all three backends define a `@default_cache_dirs` module attribute (the platform-specific defaults, kept local — they may diverge later) + delegate the shared path-resolution logic to the single public `EvoGit.Sandbox.Helpers.resolve_write_paths/3` (`config_paths, defaults, home`): `nil` config → defaults joined to home; set config (even `[]`) → the user's list replaces defaults. This follows the node constraint that shared helpers live in `Helpers` rather than being duplicated per backend.

## Windows / None Backend — No-Sandbox Gap (Known Issue)

`EvoGit.Sandbox.None` is the fallback backend for Windows and unsupported platforms: **no OS-level isolation** — a known, documented gap, not an oversight. The timed path has one minimal hardening (process-tree kill); the rest requires Windows APIs unreachable from pure Elixir. It DOES export the managed per-task tmpdir to spawned commands as `TMPDIR`/`TMP`/`TEMP` when a task installs one (shared `EvoGit.Sandbox.Helpers.temp_env_vars/0`), but performs NO writable-path gating — commands keep the user's own filesystem permissions and the system tmp dirs stay fully writable.

**What Windows execution provides:**
- `run/4` — direct `System.cmd(executable, args, cd: cwd, stderr_to_stdout: true, env: git_env)`: **cwd confinement** via `cd: cwd` (raises if dir missing); **no command-injection surface** (args passed as an ARRAY — deliberately NO shell wrapper / `bash -c` string assembly on Windows); **no timeout — by contract** (`run/4` is unbounded; `git add`/`git commit` callers like `EvoGit.sandbox_run/4` rely on it — do NOT add a default timeout); git identity/`LC_ALL`/`GIT_EDITOR` injected via `EvoGit.GitEnv.git_env_list/1` and the managed per-task tmpdir (when installed) as `TMPDIR`/`TMP`/`TEMP` via `Helpers.temp_env_vars/0` (appended on BOTH the git and plain branches). **PowerShell args**: `["-Command", cmd]` args for powershell/pwsh are transformed to `-EncodedCommand` (`EvoGit.Powershell.transform_args/2`) before the `System.cmd` call, and the returned `output` is run through `EvoGit.Powershell.decode_output/1` (BOM-aware, idempotent) before returning.
- `run_with_partial/6` (Windows clause): runs via a directly-owned `Port.open({:spawn_executable, ...})` with `System.cmd`'s option set (`:binary, :exit_status, :hide, :stderr_to_stdout`, args/cd/env — the `env` carries the git identity AND the managed per-task tmpdir via `Helpers.temp_env_vars/0`, converted to CHARLISTS at the port boundary by the pure `Helpers.port_env/1` because `open_port/2` requires charlist env pairs and a binary anywhere in an env tuple invalidates the WHOLE option list → `badarg`), so the OS PID is readable via `Port.info(port, :os_pid)` (returns `{:os_pid, pid}` — see "Port/OS-pid pitfalls"). **The timeout path intends to kill the whole process tree** via `taskkill /PID <pid> /T /F` (walks cmd.exe/powershell grandchildren, not just the direct child), but that kill is currently a NO-OP because `wait_for_os_pid/2` always returns `:undefined` (Known Issue) — only `Port.close/1` (direct child, unreliable on Windows) then applies. **Partial output accumulated up to the timeout is returned** (`{:timeout, partial_output}`, truncated to `max_bytes`). The "timeout" is a per-message IDLE timeout, not a total budget (see "Port/OS-pid pitfalls"). Executable resolution uses `resolve_executable/1` (absolute paths as-is; else `System.find_executable/1` PATH/PATHEXT — finds MinGit bash; nil → `:erlang.error(:enoent)` to preserve `System.cmd/3` semantics). NOTE: the PowerShell known-location fallback in `resolve_windows_executable/1` is bypassed on the normal dispatch path — `EvoGit.Sandbox.run_with_partial/6` pre-resolves via `EvoGit.Executable.resolve/1`, which substitutes the (non-existent) bundled `<priv>/vendor/windows-x64/powershell.exe` when `powershell` is off PATH, so `resolve_executable/1` sees an absolute path, `File.regular?` fails and the result is `nil` → `:erlang.error(:enoent)`. **PowerShell args**: the same `EvoGit.Powershell.transform_args/2` defense-in-depth runs at the top of the Windows clause (before executable resolution/port opening), and the accumulated output is decoded via `EvoGit.Powershell.decode_output/1` in BOTH return branches (`{:ok, ...}` and `{:timeout, ...}`) before `Helpers.truncate_output` is applied.

### Port/OS-pid pitfalls (`Port.open` vs `System.cmd` — verified on OTP 29)

Raw `Port.open/2` is NOT interchangeable with `System.cmd/3`; these shapes were executed and confirmed on this box:

- **`{:env, [...]}` accepts ONLY charlist tuples.** `{:env, [{"K", "V"}]}` (Elixir binaries) raises `ArgumentError: invalid option in list`; `{:env, [{~c"K", ~c"V"}]}` works. The flat `{:env, [~c"K=V"]}` form is ALSO invalid (badarg). `System.cmd/3` is safe with binary tuples because it runs its own private `validate_env/1` (`String.to_charlist/1` per name/value, Elixir `system.ex`) before `open_port` — so "mirroring System.cmd's exact option list" (the comment in `none.ex`) is NOT sufficient. `Helpers.temp_env_vars/0` and `GitEnv.git_env_list/1` both return `[{binary, binary}]` and are shared with `System.cmd` call sites (`linux.ex`/`bwrap.ex`/`macos.ex` disabled paths, `None.run_*`) and with `bwrap`'s `--setenv` args — their public shape is pinned by `helpers_test.exs`, so any conversion must happen LOCALLY at the `Port.open` call site, not by changing the helper.
- **`{:cd, binary}` and `{:args, [binary]}` ARE accepted** as binaries (same as `System.cmd`).
- **`spawn_executable` does NO PATH search**: `Port.open({:spawn_executable, "ls"}, …)` raises `:enoent`; only an absolute path works. `System.cmd/3` resolves the name itself via `:os.find_executable/1` (with `String.to_charlist/1`, avoiding the OTP 27+ binary trap) — hence the two APIs need different executable handling.
- **`Port.info(port, :os_pid)` returns `{:os_pid, pid}`** while the port is open and `nil` once it is closed. `wait_for_os_pid/2` unwraps that tuple to return the integer pid.
- **After `{:exit_status, _}` the port is already closed**: `Port.close/1` then raises `ArgumentError` ("argument error"), and `Port.info(port, :os_pid)` is `nil`. The timeout paths in `none.ex` and `bwrap.ex` close via the shared `EvoGit.Sandbox.Helpers.close_port/1` (a no-op on an already-closed port), because a bare `Port.close/1` on an exited port raises `ArgumentError`.
- **`receive … after timeout` is an IDLE timeout**: the timer restarts on every `{:data, _}` message, so `collect_windows_output/5` never times out a command that keeps producing output (verified: a 500 ms "timeout" ran 3054 ms while the child printed every 300 ms) and `acc` grows unbounded in memory (`max_bytes` is applied only after the loop; the Unix backends buffer to a temp file instead).

### PowerShell Invocation — `-EncodedCommand`

Powershell commands run via `-EncodedCommand` args built by the pure module `EvoGit.Powershell` (`lib/evo_git/powershell.ex` — single source of truth for arg building + output decode; Linux-tested in `apps/evo_git/test/evo_git/powershell_test.exs`). `Platform.shell_args/1`'s Windows clause returns `invoke_args/1` (the ShellTool + worktrees paths), and both `none.ex` Windows clauses additionally run `transform_args/2` as defense-in-depth so direct callers passing `["-Command", cmd]` are covered.

**Why `-EncodedCommand` (do not re-investigate):** `powershell.exe -Command <script>` spawned from Erlang is broken by construction because PowerShell re-joins the raw command line and re-parses it as PowerShell code (standard Windows argv quoting does NOT apply) → quotes/escapes from Erlang's spawn (`Port.open`/`System.cmd` arg quoting) get mangled → PowerShell falls back to INTERACTIVE mode → closed/EOF stdin → immediate exit 0 with NO output. Secondary: PS 5.1 writes piped output using `[Console]::OutputEncoding` (OEM/UTF-16 code page), and `EvoGit.UTF8.ensure_utf8/1` treats the UTF-16LE BOM as invalid UTF-8 → empty valid prefix. The invocation therefore goes through `-NoProfile -NonInteractive -ExecutionPolicy Bypass -EncodedCommand <b64>` where `b64` = base64(`UTF-16LE`(`& { [Console]::OutputEncoding = [System.Text.Encoding]::UTF8; <script> } *>&1`)) — eliminates command-line parsing, forces UTF-8, merges all streams via `*>&1`. Elixir side: `EvoGit.Powershell.decode_output/1` (BOM-aware) applied at output collection.

**Residual risks (fixing them requires OS APIs):** arbitrary file-system read/write anywhere the user can access (no read-only paths); no CPU/memory/process-count limits; no kill-tree on `run/4` (unbounded by contract); no network isolation; no AppContainer/restricted token (children run with the user's full privileges).

**What a real Windows sandbox would require:** **Job Objects** — `CreateJobObject` + `SetInformationJobObject` with `JobObjectExtendedLimitInformation` (CPU/memory limits) + `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` (guaranteed kill-tree, replacing best-effort `taskkill /T`) — via a NIF or Erlang port program (Windows API not reachable from pure Elixir); **AppContainer / restricted token** — also NIF/port; **simpler alternatives**: run agent tool calls inside WSL2 or a Windows Sandbox/container as an external wrapper.

**Windows-only caveats worth preserving (do not "fix"):** MinGit bash used for skills scripts — keep PATH/PATHEXT resolution so it is found; the arg-array form avoids PowerShell's `<` input-redirection parser error (the Unix `bash -c "<cmd> < /dev/null"` wrapping must stay Unix-only; with `-EncodedCommand` the script is quoting-free so `<` never appears — input redirection must never appear in the PowerShell invocation); keep the `taskkill /PID <pid> /T /F` tree-kill on timeout and the UNBOUNDED `run/4` contract (git add/commit callers rely on it); the powershell `-EncodedCommand` transform applies ONLY to powershell/pwsh executables with the exact `["-Command", cmd]` 2-element shape (bash/git and already-encoded args are untouched — no double transform); `EvoGit.Powershell` (`lib/evo_git/powershell.ex`) is the single source of truth for the arg building + output decode.

**Testing note**: the Windows clauses are unreachable in the Linux/macOS test suite (`EvoGit.Platform.windows?/0` is runtime `:os.type()`, not injectable) — the port-based collect loop, `taskkill` path, and the `-EncodedCommand` transform/decode in `none.ex` are compile-checked only on Linux; the pure logic (arg building, transform matching, BOM-aware output decode) is Linux-tested via `apps/evo_git/test/evo_git/powershell_test.exs` (26 tests, `async: true`; the `shell_args/1` test in `apps/evo_git/test/evo_git_test.exs` branches on `Platform.os()` so it passes on both Linux and Windows). Windows runtime verification is required before further changes.

## Temporary Directory (TMPDIR/tmp) Handling — managed per-task dir + always-writable system tmp dirs

**Two layers are always in effect:**
1. A managed **per-task** scratch dir (`EvoGit.TaskTmpdir`, `task_tmpdir.ex` — outside this node) shared by ALL agents of one task (never per-agent, never per-worktree); `EvoGit.TaskTmpdir.path_for/2` derives it from `[tmp] mode` and the task id — `:system` (default) → `<first Platform.tmp_paths/0 entry>/genesis/task_<id>` (e.g. `/tmp/genesis/task_<id>`), `:custom` → `<[tmp] path>/genesis/task_<id>`, `:per_repo` → `<primary repo>/.genesis/tmp/task_<id>` (repo-less tasks fall back to `:system`).
   The runner resolves it once and installs it on the process dictionary (`EvoGit.TaskTmpdir.put_current/1`); the tool-dispatch layer re-installs it inside every spawned tool task (tool tasks do NOT inherit the caller's process dict); `EvoGit.TaskTmpdir.current/0` reads it.
2. The **system tmp dirs** (`Platform.tmp_paths/0` = `/tmp` + `/var/tmp` on Unix, `System.tmp_dir!()` on Windows) stay FULLY writable/accessible inside every sandbox — some agents hardcode `/tmp` instead of `$TMPDIR`.
   The per-task dir is an ADDITIONAL writable path + a `TMPDIR` override — NEVER a `--tmpfs /tmp`, never a replacement for the system dirs.

**`EvoGit.Sandbox.resolve_tmpdir/0` resolves the injected `TMPDIR` value:** it returns `EvoGit.TaskTmpdir.current/0` DIRECTLY when a per-task dir is installed on the calling process (bypassing the path check below — the backends make that dir writable); otherwise the legacy per-BEAM constant resolution applies — `$TMPDIR` unset → the first `Platform.tmp_paths/0` entry (`/tmp`); `$TMPDIR` set → kept ONLY when it exists AND is equal to / under a `Platform.tmp_paths/0` entry, else fallback `/tmp`.
macOS host `$TMPDIR` (`/var/folders/...`) therefore never survives the legacy path.
**The Nix dev-env wrap must not rotate the injected TMPDIR** (the wrap is sourced INSIDE the sandbox). Mechanism: `EvoGit.Nix.wrap_command/2` (`sandbox/nix.ex`) emits `bash -c "source '<data_dir>/nix-dev-env.sh'; exec <escaped-command>"` (`build_bash_command/3`, nix.ex:338-343, cmd built at :341; cache path nix.ex:305) — the raw `nix print-dev-env` epilogue (tail of the file: e.g. lines 2141-2146 of the 2147-line script here) would run `mktemp -d -t nix-shell.XXXXXX` + re-export `TMPDIR`/`TMP`/`TEMP`/`TEMPDIR`/`NIX_BUILD_TOP` to a FRESH random dir (mode 0700) + `eval "${shellHook:-}"` on EVERY source.
**Sanitization:** `EvoGit.Nix.do_build_dev_env/0` (nix.ex) runs the public pure helper `EvoGit.Nix.sanitize_dev_env_output/1` on the `nix print-dev-env` output before it is written to the cache file, replacing the single literal `export NIX_BUILD_TOP="$(mktemp -d -t nix-shell.XXXXXX)"` with `export NIX_BUILD_TOP="${TMPDIR:-/tmp}"`.
`NIX_BUILD_TOP`/`TMP`/`TMPDIR`/`TEMP`/`TEMPDIR` therefore resolve to the backend-injected TMPDIR (the managed per-task dir when one is installed, else the legacy constant; fallback `/tmp`, matching `EvoGit.Sandbox.resolve_tmpdir/0` semantics); the four `TMP*` exports that follow reference `$NIX_BUILD_TOP` and follow automatically.
No per-call fresh `/tmp/nix-shell.<rand>` dirs are created, the dir leak is stopped, and the dev env stays fully functional (store PATH tools and shellHook exports survive unchanged).
**Origin (verified): the epilogue is generated by NIX ITSELF, not by the flake's devShell** — `makeRcScript` in nix's `src/nix/develop.cc` (exports at develop.cc:376-378, `eval "${shellHook:-}"` after), and the block is byte-identical across nix 2.18.7 / 2.24.11 / 2.26.2 / 2.35.2; a minimal empty `mkShell {}` flake reproduces it verbatim, the block prints AFTER all derivation content and BEFORE `eval "${shellHook:-}"`, and there is NO nix CLI flag or env var to disable it (`nix print-dev-env --help` offers only `--json`, whose output omits the bash-only mktemp block).
**No cleanup trap exists (durable fact): nix's only cleanup anywhere is `command rm -f '<rcfile>'` at develop.cc:600, which targets the rc file nix writes for interactive `nix develop`, never NIX_BUILD_TOP** — so nothing in the `source`+`exec` path removes tmp dirs; the sanitized script never creates them, so there is nothing to clean up and no accumulation.
Determinism: `nix print-dev-env` output is byte-identical across rebuilds for a given invocation cwd — only three lines embed the invocation cwd (`out=`, `prefix=`, and the `NIX_LDFLAGS` `-rpath` entry) and change when the BEAM's cwd differs; the cache hash keys flake.nix content only, never the invocation cwd.
Graceful degradation: `sanitize_dev_env_output/1` is a single `String.replace/3` — if a future nix version stops emitting the exact mktemp literal, the substitution silently no-ops and the raw output is cached unchanged, returning the old per-call-fresh TMPDIR behavior.
When the nix wrap is NOT active (`[nix] enabled=false`, build failed, or no config-dir flake), TMPDIR is likewise the `EvoGit.Sandbox.resolve_tmpdir/0` value.

**Each SANDBOX-ENABLED backend injects that value AS `TMPDIR` and ADDITIONALLY grants it write access** (injection and the writable grant both read `EvoGit.TaskTmpdir.current/0` in the same tool-invocation process, so they always agree); the disable/None paths export it as an env override only (no writable-path grant):
- **systemd-run (Linux)**: `args/4` (`sandbox/linux.ex`) emits `--setenv=TMPDIR=<resolve_tmpdir()>` plus an extra `-p ReadWritePaths=-<taskdir>` entry (appended to `read_write_paths`; the `-` prefix keeps a missing path non-fatal, same as the tmp/write entries). The `-p ReadWritePaths=-/tmp -/var/tmp` entries (rw on the REAL host dirs) stay exactly as-is; `ProtectSystem=strict` makes the rest of `/` read-only; no `PrivateTmp` anywhere. Each `run/4` is a fresh transient unit, but its `/tmp` is the host's — files persist across invocations.
- **bwrap (full AND `:degraded`)**: `build_args/5` (`sandbox/bwrap.ex`) emits `--setenv TMPDIR <resolve_tmpdir()>` plus `--bind-try <taskdir> <taskdir>` (spliced AFTER the always-present `--bind-try /tmp /tmp` + `--bind-try /var/tmp /var/tmp` and BEFORE the `--` command separator — bwrap's GOption parser stops at the first non-option argument). `:degraded` differs ONLY by dropping `--unshare-pid`; the tmp binds + setenv are identical in both modes.
- **sandbox-exec (macOS)**: `generate_profile/2` (`sandbox/macos.ex`) emits an extra read+write pair for the per-task dir (`(allow file-read* (subpath "<taskdir>"))` + `(allow file-write* (subpath "<taskdir>"))`, right after `tmp_rules`); the invocation passes `env: [{"TMPDIR", resolve_tmpdir()}]`. The per-`Platform.tmp_paths/0` `tmp_rules` (read+write `/tmp`) stay exactly as-is, and the read-only host-`$TMPDIR` rule keeps pre-sandbox BEAM temp files (`System.tmp_dir!()` = `/var/folders/...`) readable inside.
- **None / Windows + every DISABLED (non-sandboxed) path**: no isolation and NO writable-path gating, but the managed per-task dir (when installed) IS exported to the child as `TMPDIR`/`TMP`/`TEMP` via the single shared `Helpers.temp_env_vars/0`, appended to the `env:`/`{:env, ...}` of every non-sandboxed spawn — the `None` backend (`run_unix`/`run_windows`/`run_with_partial_unix`/`run_with_partial_windows`) AND the Linux/Bwrap/MacOS `run/4` + `run_with_partial/6` disabled branches (`Helpers.run_task_with_partial/7`'s callers pass the appended list). Commands keep the user's own filesystem permissions; the system tmp dirs stay fully accessible — the exported dir is ADDITIONAL, never a replacement. `Platform.tmp_paths/0` Windows = `System.tmp_dir!()`.
- **Shared derivation (anti-duplication)**: `EvoGit.Sandbox.Helpers.task_tmpdir_path/0` is the single derivation of the per-task path from `EvoGit.TaskTmpdir.current/0` (returns `nil` when unset); each backend shapes it (`List.wrap/1`) into its own syntax. `EvoGit.Sandbox.Helpers.temp_env_vars/0` (built on `task_tmpdir_path/0`) is the single env-override source for the non-sandboxed paths: `[{"TMPDIR", dir}, {"TMP", dir}, {"TEMP", dir}]` when a dir is installed, else `[]`.
- **Runtime-owned temp files land under `EvoGit.Sandbox.resolve_tmpdir/0`** (the per-task dir when one is installed, else the legacy constant value): `Helpers.partial_output_tmpfile/0` → `<resolve_tmpdir()>/genesis_partial_outputs/` (timeout partial-output capture) and the skills-executor scripts → `<resolve_tmpdir()>/evogit_skill_<n>.sh` (`skills/executor.ex`; Windows `System.tmp_dir!()`). On Linux/bwrap/macOS these land inside the per-task dir when a task installs one. git `-F` message files → `<resolve_tmpdir()>/genesis_ctx_msg_<n>.txt` (`agent/tools/context.ex`) and `System.tmp_dir!()/genesis_git_msg_<n>` (`adapters/git.ex`).
- **Cleanup is best-effort, NOT uniform, and there is NO runtime-wide temp sweep**: only the git `-F` message files use `try/after File.rm`; the partial-output tmpfiles are removed by `Helpers.read_tempfile/2`'s own `File.rm`; the skills scripts by a bare `File.rm` (no `after` block); remote-connection bootstrap stages `System.tmp_dir!()/genesis-remote-*` files with a bare `File.rm`. Leak paths: a raise between write and cleanup (e.g. `sandbox_run` raising `ErlangError(:enoent)` for a missing bash, or `run_task_with_partial/7` matching no clause for `Task.yield`'s `{:exit, reason}`), a killed owning process, or a BEAM crash. Per-task dirs are reclaimed by `EvoGit.TaskTmpdir` (`reclaim/2` per task); stray files under the shared system tmp are not swept at boot.
- **Agent guidance**: the ShellTool schema (`agent/tools/shell_tool.ex`) tells agents to use `$TMPDIR` for scratch files ("never /tmp" on POSIX). Inside a sandbox on Linux/bwrap/macOS `$TMPDIR` is the managed per-task dir (shared by all agents of the task), so scratch files written through `$TMPDIR` are per-task-scoped. The system `/tmp` + `/var/tmp` remain writable and thus still cross-agent visible on a shared host — anything an agent hardcodes under `/tmp` stays reachable by every other sandboxed command of the same OS user.
- **Cross-worktree visibility note**: files inside OTHER agents' worktrees are READABLE by a sandboxed command (bwrap `--ro-bind / /`, systemd `ProtectSystem=strict` keeps `/` readable, macOS root read allow) but WRITE access is confined to `cwd` + tmp dirs (incl. the per-task dir) + configured caches + `.git`.
- Tests pinning this (sibling test node `apps/evo_git/test/evo_git/sandbox/`): `linux_test.exs`/`bwrap_test.exs`/`macos_test.exs` pin the sandbox-enabled TMPDIR forwarding (`ReadWritePaths=-/tmp`, bwrap `--setenv TMPDIR` incl. degraded, macOS `resolve_tmpdir/0`) AND the DISABLED-path env export (a real `bash -c` echoing `TMPDIR`/`TMP`/`TEMP` == the installed per-task dir); `none_test.exs` pins the `None` backend + the public `EvoGit.Sandbox.run/4` dispatch exporting the vars; `helpers_test.exs` pins `temp_env_vars/0` (`[]` when unset / three tuples when installed); `sandbox/truncation_test.exs` pins `genesis_partial_outputs`. Tests install a per-task dir via `EvoGit.TaskTmpdir.put_current/1` (+ `on_exit` cleanup) to exercise the managed path, and the legacy-fallback path when unset.

## Skills Script Execution Through the Sandbox

The skills executor (`lib/evo_git/skills/executor.ex` — outside this node) runs skill scripts via `EvoGit.sandbox_run(repo_path, "bash", [tmp_file | values], nil)` on Linux/macOS (script written under `EvoGit.Sandbox.resolve_tmpdir()`, values passed as positional argv `$1..$N`), and directly via `System.cmd(bash_path, [tmp_file | values], cd: repo_path, ...)` on Windows (argv-style, injection-safe; the `System.find_executable("bash")` guard returns the friendly "Install Git for Windows" error when bash is missing — a bare `sandbox_run` with missing bash raises `ErlangError(:enoent)`):
- **Dispatcher** — `run/4`/`run_with_partial/6` accept any executable+args; `Executable.resolve("bash")` returns `"bash"` when on PATH. Return shape `{output, exit_code}` is identical to the `System.cmd` result.
- **Linux**: script at `EvoGit.Sandbox.resolve_tmpdir()` (the managed per-task dir when installed, else `/tmp`) is inside `ReadWritePaths` (`[cwd | Platform.tmp_paths()]` + cache dirs + the per-task dir); `InaccessiblePaths` covers only the 8 sensitive home dirs; systemd defaults make everything else readable → works unchanged.
- **Bwrap**: script at `EvoGit.Sandbox.resolve_tmpdir()` (the managed per-task dir when installed, else `/tmp`) is covered by the writable `--bind-try` binds (tmp paths + the per-task dir); `--ro-bind / /` keeps everything else readable; the 12-dir `--tmpfs` deny overlays hide credential stores → works unchanged.
- **macOS**: `resolve_tmpdir()` returns the managed per-task dir when one is installed, else `/tmp` (the host `$TMPDIR` under `/var/folders/...` is NOT under the `tmp_paths` list, so the legacy path falls back to the first tmp path) → the script is covered by the tmp read/write rules (group 5) or the per-task read+write rule. The host-`$TMPDIR` read rule (group 10) covers any caller that writes temp files via `System.tmp_dir!()` BEFORE the sandbox starts — if that rule is ever removed, such files break inside the sandbox. Optionally use `sandbox_run_with_partial/6` for a timeout (`{:ok, output, code} | {:timeout, partial}` — handle the different return shape).
- **Windows**: works via arg-array (no shell); keep the `System.find_executable("bash")` guard that returns the friendly "Install Git for Windows" error.
- `Helpers.shell_escape/1` safely quotes the script path in the assembled `bash -c` string; `Nix.wrap_command/2` accepts any executable name (compatible).

## Constraints
- All backends implement `@behaviour EvoGit.Sandbox.Behaviour` — the dispatch module (`EvoGit.Sandbox`) calls the behaviour callbacks uniformly
- Shared helpers live in `EvoGit.Sandbox.Helpers` — the designated anti-duplication home for helpers shared across the sandbox backends. It owns the output/truncation utilities (`shell_escape/1`, `read_tempfile/2` (with `read_truncated/3`), `system_cmd/2`) plus `git_metadata_dir/2`, `parse_gitdir_pointer/3`, `wait_for_os_pid/2`, `drain_port_messages/1`, `partial_output_tmpfile/0`, `resolve_write_paths/3`, `task_tmpdir_path/0`, `temp_env_vars/0`, `port_env/1` (env tuples → `Port.open/2`'s required charlist pairs), `build_shell_command/2`, `build_redirected_command/3`, `run_task_with_partial/7`, and `sandbox_mode_enabled?/1` (the mode-gate clause used by `SandboxSlice.sandbox_enabled?/0` and `SandboxProcessRegistry.sandbox_enabled?/0`). New cross-backend helpers belong in `Sandbox.Helpers`, not duplicated per backend. Backends and `EvoGit.Nix` alias `Helpers` and delegate to these functions instead of duplicating them
- `shell_escape/1` is **security-sensitive** (command injection prevention) — it has exactly one definition in `EvoGit.Sandbox.Helpers`
- `EvoGit.Sandbox.Linux` depends on `EvoGit.SandboxProcessRegistry` (caller-process monitoring) and `EvoGit.SandboxSlice` (systemd slice management) — both started in Application supervision tree on Linux only
- `EvoGit.Sandbox.Bwrap` depends on NEITHER `EvoGit.SandboxSlice` NOR `EvoGit.SandboxProcessRegistry` — `ensure_initialized/0` is a no-op; it needs only a `bwrap` binary (+ root or userns). Its `--setenv` args MUST precede the command (bwrap's GOption parser stops at the first non-option argument)
- `EvoGit.Sandbox.MacOS` uses inline SBPL profile generation (no external template files). Emitted profile is PURE SBPL — no `#` comments inside (comment support in sandbox-exec not validated; all rationale lives in Elixir source comments)
- `EvoGit.Sandbox.None` is the fallback for Windows and unsupported platforms
- Callers use `EvoGit.sandbox_run/4` (delegates to `EvoGit.Sandbox.run/4`) — tool modules do not need to know about backends
- `EvoGit.Nix` is a standalone helper module (not a sandbox backend) — backends consult it to optionally wrap commands when Nix is enabled. It depends on `EvoGit.Config` (for the `[nix]` table and config dir) and `EvoGit.Platform` (`nix_available?/0`)
- When nix is active: Linux backend forwards all `NIX*` + `SSL_CERT_FILE` env vars via `--setenv` and grants read-write access to `/nix/store` and `/nix/var`. macOS backend adds `/nix/store` and `/nix/var` to its SBPL profile. Bwrap grants writable `--bind-try` for `/nix/store` + `/nix/var` and relies on env INHERITANCE (bwrap inherits the caller env, unlike `systemd-run --user`) — no NIX* `--setenv` needed. None backend wraps directly (inherits parent env). All four backends source the cached dev-env script (`nix print-dev-env` output) via `bash -c` rather than per-call `nix develop`. The `nix_paths`/`nix_env_vars` gating uses `Nix.enabled?/0` (static capability); the wrap decision uses `Nix.active?/0` (enabled + build not failed).

## Known Issues / Test Strategy
- **OTP 27+ `:os.find_executable/1` binary trap:** raw `:os.find_executable/1` raises `ArgumentError` on Elixir BINARY input on OTP 27+ (kernel 11.0.3) — `os.erl:verify_executable/3` does `Name ++ ".exe"` where `".exe"` is a charlist, and `binary ++ charlist` fails (`:erlang.++("c:/Windows/System32/powershell", ~c".exe")`). `EvoGit.Sandbox.None.resolve_executable/1` works around it: it uses `System.find_executable/1` (converts to charlist internally — never raises for binaries or charlists) plus Windows known-location fallbacks for `powershell`/`pwsh` (`WINDIR\System32\WindowsPowerShell\v1.0\powershell.exe`, `ProgramFiles`/`ProgramW6432`/`ProgramFiles(x86)` `PowerShell\7\pwsh.exe`). **Rule: never call raw `:os.find_executable/1` with an Elixir binary on OTP 27+; use `System.find_executable/1` (or this helper) instead.**
- **Test coverage gap:** `linux_test.exs` tests only `args/4` generation; `macos_test.exs` only `generate_profile/2` string assertions. NO test executes a real sandboxed command (systemd-run/sandbox-exec/bwrap) — the `@mix_env == :test` gates in `Linux.enabled?/0`/`Bwrap.enabled?/0` and the Linux-only CI make the real paths untested. All four backends' enabled paths are runtime-verified only.
- **Bwrap real-execution caveat:** `bwrap_test.exs` (sibling test node) tests only `args/4` generation like `linux_test.exs`. Real bwrap execution requires a host where `mount(2)` works (bare metal, privileged container, or unprivileged-userns host) — worker/CI environments running inside a systemd-run unit with read-only `/` block `mount(2)` (`bwrap: Failed to make / slave: Operation not permitted`), so only flag-syntax validation is possible there. The argv shape was parse-validated against bwrap 0.11.2 and cross-checked against the bubblewrap 0.11.2 source (`setup_newroot` `ALLOW_NOTEXIST` skip semantics, `--unshare-all` = try-variants for user/cgroup, setsid-before-fork process model). Rootless podman: see the ":degraded mode" section — tests must use the `:bwrap_capability` override seam (probing is `@mix_env == :test`-gated and never runs in tests). **GOption gotcha for future work**: bwrap's option parser stops at the first non-option argument, so any new `--setenv`/option MUST be added before the command — never after.
- **Backend-selection invariant (`linux.ex` consistency, decision):** `EvoGit.Sandbox.Linux.enabled?/0` needs NO `EvoGit.Sandbox.backend() == EvoGit.Sandbox.Linux` guard. The dispatcher consults only the SELECTED backend's `enabled?/0` (`EvoGit.Sandbox.enabled?/0` → `backend().enabled?()`), and the slice/registry gates (`SandboxSlice.sandbox_enabled?/0`, `SandboxProcessRegistry.sandbox_enabled?/0`) are gated on `EvoGit.Sandbox.backend() == EvoGit.Sandbox.Linux` (sibling change) — so the systemd slice/unit-registry machinery only activates when Linux is the selected backend. A redundant guard in `Linux.enabled?/0` was considered and REJECTED: it would add a compile cycle (linux.ex → dispatcher) and could break existing linux tests' expectations; the invariant is already guaranteed by the dispatcher + gate design. The `@mix_env == :test` gate stays first in any case.
