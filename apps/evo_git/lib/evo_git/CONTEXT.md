# EvoGit Core Library — `lib/evo_git/`

## Intent
Core source of the `:evo_git` OTP application: the Agent system (LLM tool-calling loops), AgentScheduler (scheduling, ETS state, slot management — worktree lifecycle owned by `AgentScheduler.WorktreeManager`), core domain types (ContextNode, PhyloGraphNode, ForeignRepo), the Git adapter, and runtime phases (Genesis, Evolution).
Multi-repo: foreign repos from `genesis.toml` or CLI flags enable cross-repo subagent spawning into isolated worktrees.
This file is the module-level API surface plus the cross-cutting contracts; each section names the child CONTEXT.md owning its detail.

## Routing Table

- `./agent/tools/elixir_eval/` → Genesis Assistant evaluator internals: explicit read/write MFA allowlists calling real runtime APIs with their actual returns, authenticated runtime-local capability broker, bounded evaluation/output and monitored worker cleanup; the single public tool wrapper is `./agent/tools/elixir_eval.ex`.
- `./agents/` → SelfReflective exposes `elixir_eval` plus source-reading tools; evaluator tiers are explicit read/write/sudo, writes require exact-code approval, sudo additionally carries an unrestricted-privileges warning, and no tier auto-escalates.

### SSH Remote (RemoteBootstrap / RemoteConnection)
`EvoGit.RemoteConnection` is a deliberately long, cohesive GenServer module (bootstrap staging, daemon lifecycle over the release CLI, connect worker, port utilities) — do NOT split it; pure platform/asset/download logic lives in `EvoGit.RemoteBootstrap`, and the remote daemon's own process lifecycle (systemd scope + unit, macOS launchd plist, setsid fallback, readiness wait) lives ENTIRELY in that release's `bin/genesis` CLI (`genesis remote start|stop|status|logs`) — no Elixir module builds a `systemctl`/`systemd-run`/`launchctl` command.
`EvoGit.RemoteBootstrap` — pure platform/asset/download logic (no I/O): `parse_uname/2`, `parse_platform/1`, `daemon_os/1`, `asset_name/1` (always `genesis_server_<platform>.tar.xz`, never suffixed), `download_url/1` (deterministic `https://genesis.evox.group/dl/genesis_server_<platform>.tar.xz` → `{:ok, url, "latest"}` — Cloudflare proxy over the GitHub asset, no API query, no asset matching), `cache_path/2`, `sh_wrap/1`, `nixos_detect_command/0`, `nixos_patch_script/1`; extraction is `tar -xJf` (no gz fallback) and CI uploads `linux_x64`/`linux_arm64`/`darwin_arm64`.
Stage atoms: `:probing_platform | :downloading | :downloading_locally | :stopping_daemon | :uploading | :extracting | :setting_permissions | :copying_config | :generating_cookie | :patching_binaries | :starting_daemon`.
Test-pinned error tuples (every remote-command failure carries the trimmed output TAIL): `{:error, {:probe_failed, {:exit_status, n, tail} | :timeout | {:unexpected_output, out}}}` | `{:error, :unsupported_platform}`; `{:error, {:download_failed, {:exit_status, n, tail} | :timeout | {:local, detail} | {:local_scp, detail}}}`; `{:error, {:scp_failed, n, tail} | {:scp_failed, :timeout}}`; `{:error, {:staging_failed, n, tail} | {:staging_failed, :timeout}}`; `{:error, {:daemon_status_failed, n, tail} | :daemon_status_timeout}`; `{:error, {:daemon_launch_failed, n, tail} | {:daemon_launch_failed, :timeout}}`; `{:error, {:daemon_running, details}}` | `{:error, {:daemon_identity_mismatch, details}}`.
`EvoGit.RemoteConnection.format_reason/1` renders any of them as one readable sentence (an already-formatted binary passes through unchanged, every other unknown term via `inspect/1`; total, never raises), and `error_state/3` sets `last_error` to it and logs it once.
Timeouts: bootstrap 900s, download 300s, daemon start 120s.
`EvoGit.RemoteConnection` owns bootstrap + connect. Source priority: `local_binary_path` exists → `scp`, set-but-missing → warning + download, absent → download (remote `curl -fL`, remote `wget -O` fallback, local curl + `scp`).
A silent pre-flight resolves the daemon OS (target `platform` preset → NO ssh probe, else ONE `uname -s && uname -m` round trip; no login-user probe, the CLI owns the scope) and reads `remote status` to apply the running-daemon policy BEFORE staging.
- **The distribution toggle is the release CLI** (the host's ONE `genesis-server` instance also serves HTTP; `genesis-remote-<target_id>` is an identity, not a process): launcher `<remote_path>/bin/genesis_server` (default `remote_path` `/tmp/genesis_server`). `status` → `"<launcher>" remote status --unit <unit>`; exit 0 prints `running node=<node> dist_port=<port>` (parsed by `@daemon_status_re`), exit 1 prints `stopped`, anything else → `{:daemon_status_failed, n, tail}`. `start` → `"<launcher>" remote start --node <node> --cookie <cookie> --dist-port <port> --unit <unit> --wait <N>`: it brings the instance up exactly like `genesis start` when none is running, then writes `control.request` (0600) and `SIGHUP`s the instance; ONE non-retried call with a 120s ssh budget. `stop` → `"<launcher>" remote stop --unit <unit>` detaches distribution and leaves HTTP serving; idempotent and best-effort. No Elixir module builds a `systemctl`/`systemd-run`/`launchctl` command — the CLI owns the scope (`--user` for a non-root login, SYSTEM with `--collect` for `root`), the launchd plist and the setsid/nohup fallback; user-facing remote diagnostics are `genesis remote status|logs`.
- **ARGV, never spawn strings**: `run_ssh_command/4` = `{:spawn_executable, …}` + `{:args, [target, remote_cmd]}` (a quote-wrapped `{:spawn, String}` breaks Windows — the CRT consumes only double quotes — and Unix, where spawn strings go through `/bin/sh -c`); remote commands are wrapped by `sh_wrap/1` as `/bin/sh -c '<script>'` — a plain command word plus ONE single-quoted word, the only form that parses in a fish, nushell, tcsh, zsh, bash or POSIX login shell (NixOS has no `/usr/bin/env`; `/bin/sh` is POSIX-mandated and is NixOS `environment.binsh`).
- **Remote commands are POSIX sh and single-quote-free by construction**: nushell single-quoted strings cannot contain `'` and tcsh is equally picky, so a `'` inside a remote command would break the wrapper outright (the `'\''` close/reopen fallback in `sh_wrap/1` only helps POSIX-ish shells + fish); no bash-isms (`[[`, arrays, `local`, `source`, `type -t`, `pushd`). The interpreter string is read per call from the app env `:remote_shell` (default `/bin/sh`, test seam).
- **Never kill a running daemon without permission**: `bootstrap/2`'s `:on_running` ∈ `:refuse` (default → `{:error, {:daemon_running, details}}`, no staging/kill/broadcast, state untouched; the dashboard renders a permission dialog from that tuple) | `:restart` (`:stopping_daemon` + CLI stop, failure non-fatal, then the normal flow). The RACE net is the `node=` the CLI reports: a daemon already running the EXPECTED node short-circuits to `:ok`, any other node (or none) is `{:error, {:daemon_identity_mismatch, details}}` whose remediation is `<launcher> remote stop --unit <unit>` — fail loud, never auto-kill. The node name is fixed at ENABLE time (a REQUESTED name that differs from the live one is an identity mismatch, never a silent rename) and the cookie is per MACHINE; readiness is the CLI's own `--wait`, so there is NO Elixir-side health poll and no post-launch delay seam.
- **Staging is ONE remote command**: `mkdir -p "<parent>" && tar -xJf "<remote_tarball>" -C "<parent>" && <move> && { test -x "<launcher>" || chmod +x "<launcher>"; } && test -x "<launcher>"`, where `<parent>` is `dirname(remote_path)` and `<move>` is `rm -rf "<remote_path>" && mv "<parent>/genesis_server" "<remote_path>" && ` when the tarball's top-level `genesis_server/` does not already sit at `remote_path` (any legacy/custom `remote_path`), else empty; it broadcasts `:extracting` then `:setting_permissions`, respects an already-executable launcher, runs no second ssh round trip, and cannot leave a half-extracted tree for a later step — the chain stops at the first failing step and the trailing `test -x` self-verifies.
- **Bounded transport retry**: `run_ssh_command_retry/4` (public, `@doc false`) retries an ssh exit `255` (ssh's OWN transport failure — a remote command's own status never reaches 255) exactly once, with `:remote_ssh_retry_backoff_ms` (default 400, read per call) or a `backoff_ms:` override, and only for IDEMPOTENT commands (the platform probe, staging, `mkdir`, `test -f`, the NixOS detect, `remote status`, `remote stop`); never `remote start`, `scp`, the download commands or the NixOS patch script, and never a `:timeout` (the command may still be running).
- `:copying_config` NEVER overwrites an existing remote config.toml/credentials.toml (`ssh <target> 'test -f <file>'` probe → skip the scp) and uploads an absent one accent-rewritten (per-target colour) or unmodified; the remote config dir is `$HOME`-rooted (`$HOME/Library/Application Support/genesis` on Darwin, `$HOME/.config/genesis` elsewhere — never `~`, which does not expand inside quotes) and DOUBLE-quoted in every remote command (`mkdir -p "<dir>"`, `test -f "<file>" && echo yes || echo no`), so the space in `Application Support` cannot word-split the probe; the scp destination keeps its `~` form (remaining space limitation: Known Issues); NixOS remotes add `:patching_binaries` (`nixos_patch_script/1`, GC-rooted at `<release>/.nixos-patch`, file list via `find … > files.txt` + `while IFS= read -r`) and patch only a daemon that is NOT already running → `./sandbox/`.
- `Distribution.ensure_epmd_module/0` (idempotent) runs on both connect paths; BOOT deliberately does NOT set it (inbound discovery keeps real epmd). Distribution is off by default and boot-enables only with `[node] enabled = true`, never in test (`@mix_env != :test` at the CALL SITE, else a developer's config starts `:net_kernel`/EPMD before `ExUnit.start/1`) — tests use `enable_for_remote/1`. A boot-distributed `genesis_server` (started with `RELEASE_DISTRIBUTION=name`) reports its ACTUAL state through `EvoGit.DaemonControl`, and distribution can now also be turned ON/OFF at runtime on the SAME instance (HTTP endpoint stays up) — `Distribution.enable_runtime/3` / `disable_runtime/0`, driven by the daemon control plane, which is what removes the need for a second daemon unit per host (§ Runtime distribution control). `RemoteConnection.Registry` + `.Supervisor` (`:transient`) start before the agent group; `Store`/`TaskRegistry` are supervised so the daemon keeps full history (port 9000 via the release env; zombie prevention: root `../CONTEXT.md`).

**Connect is non-blocking**: `connect/1` replies `{:ok, :connecting}`/`{:ok, :connected}` (5s call) while the I/O (`find_free_port`, ssh spawn, `wait_for_tunnel/4`, `EpmdDist.register_target/2`, `Node.connect/1`) runs in a monitored worker that hands the tunnel `Port` over (`Port.connect/2`) BEFORE reporting `{:connect_result, pid, {:ok, %{port:, local_port:, node_name:}}} | {:connect_result, pid, {:error, message}}` (a `:DOWN` without a result → "connect worker crashed: …"). Broadcasts `{:remote_connection_status, target.id, status_map}` on `"remote_connections"` — NO trailing node element (documented exception; `handle_connection_status/2` is its only consumer): `:connecting`, `:connected`, `:error` (with `last_error`, single `fail_connect/2` choke point), `:disconnected`. Duplicate connects are idempotent; ssh carries `-o ConnectTimeout=8`; `disconnect/1` while `:connecting` kills the worker (it owns the port) then `cleanup/1` → `:disconnected` + `{:stop, :normal, …}`; tests fake `ssh` on PATH, so the only clock seam is the per-call app-env read `:remote_tunnel_poll_interval_ms` (tunnel-readiness poll cadence, default 100 ms = production).
**Tunnel invariant**: `Node.connect/1` must NOT run before the forwarded port accepts TCP (`ssh -L <local_port>:127.0.0.1:<dist_port> -N <target>` can take >1.5s; an early connect fails econnrefused → `{:error, {:node_connect_failed, …}}` with NO remote-side log); `wait_for_tunnel/4` polls (100ms — the worker reads `:remote_tunnel_poll_interval_ms` per call, default 100, so a test whose fake ssh opens the forwarded port a few ms late does not pay a full production interval; 10s budget), fails fast when the ssh Port dies, `@doc false` for tests.
**Known `node_connect_failed` causes**: stale daemon (`{:daemon_identity_mismatch, details}` → `<launcher> remote stop --unit <unit>`, then `bootstrap(target_id, on_running: :restart)`); `dist_port` ≠ 9000 (the daemon is pinned to 9000 and `ssh -L` accepts local connections to a dead forward target, so the poll still passes); a boot-distributed node whose `epmd_module` is `erl_epmd` (real epmd → `:noport`, no journal entry).

### SQLite Store — Ecto Persistence Layer

`EvoGit.Store` is a GenServer facade over pure `Store.Operations.*` (each repo-pid-first via `RepoScope.with_repo/2`) against this store's own UNNAMED dynamic `EvoGit.Repo` (xqlite; pool = `Boot.default_pool_size/0`, per-store `:pool_size`), with WAL + `default_transaction_mode: :immediate` + `busy_timeout: 30_000` from `EvoGit.Repo.start_opts/0`.
**Boot**: `Store.Boot.start_dynamic/2` runs the EIGHT migrations in `priv/repo/migrations/` (`001` baseline adoption, `002` data normalization, `003` composite indexes, `005` covering indexes, `006` legacy-format repair, `007` `task_agent_archives`, `008` legacy-archive fan-out + column drop, `009` `task_agent_archives` shape normalization) on a temporary single connection, THEN opens the pool at the requested size so every connection sees the migrated schema — an existing user DB upgrades on first start.
**Every JSON column is plain UTF-8 TEXT** — `opts`/`logs`/`result`/`usage`/`error` round-trip through `Store.Codec` (the single encode/decode wire oracle); no compression of any kind and no prefix-tagged payload, so any row is readable to plain SQL. `PRAGMA optimize` runs once per boot + hourly (`Store.Maintenance`); `mix store.maintenance [--vacuum]` reclaims on demand (VACUUM never at boot).
**Reads/writes**: reads fan out to 6 WAL readers (8 MiB cache each) and EVERY read runs on `offload/5` (unlinked monitored worker, 25s deadline) degrading to the read's own empty shape — a slow read can never kill `Store` or `TaskRegistry` (whose sync calls are `:exit`-guarded by `StoreGuard`); writes serialize through `Store.Writer` (reply-after-commit) with the disk-full choke point `Errors.disk_full_exception?/1` → `{:error, :disk_full}`. Query shapes, indexes and measured effects: `./store/CONTEXT.md`.

## Review / RemoteNode Return-Shape Contract (remote-SSH payload analysis)

`EvoGit.RemoteNode` review wrappers return the **verbatim** `EvoGit.Review` value (local → `RemoteAPI` direct, remote → `:erpc` via `call_remote/4`); the only added shape is `{:error, {kind, reason}}` on RPC failure. Arity = Review + 1 (leading `node`), and all time out via `rpc_timeout/0` (`Application.get_env(:evo_git, :remote_rpc_timeout, 30_000)`, read at CALL time). **`defnode` convention**: `defnode EvoGit.AgentScheduler.RemoteAPI.fun(args)` (`EvoGit.RemoteNode.Defnode`) generates the local-direct / `call_remote` pair ONLY when the remote branch is exactly `{:ok, r} -> r; {:error, e} -> {:error, e}`; per-function fallbacks (`[]`/`%{}`/`nil`/`false`/`{:error, :rpc_failed}`, nested errors) stay hand-written. Review/task wrappers are all `defnode`-generated and take an explicit `repo_path`.

- **Structs**: `%EvoGit.Review.FileInfo{}` — `:path`, `:status` (`"added" | "deleted" | "modified"`), `:additions`/`:deletions`, `:diff` (String | nil), `:language` (highlight.js name, always populated), `full_new_content: nil`, `full_old_content: nil` — Review NEVER fills `full_*`, callers do via `get_file_content/4`. `%EvoGit.Review.CommitInfo{}` — `:sha`, `:short_sha`, `:message` (subject, `%s`), `:author_name`, `:author_email`, `:date` (`%DateTime{}` from `%aI`, raw String on parse failure).
- **Reads**: `load_review_metadata/2`, `load_review_metadata_from_shas/3`, `load_commit_files/2` (vs `commit_sha~1`) all return `{:ok, %{commit_sha, base_sha, diff_stat (raw --numstat), diff: nil, files: [%FileInfo{}] (diff: nil), changed_files_count, total_additions, total_deletions}}` | `{:error, {tag, output}}`; `load_review_data/2` is the heavy variant (top-level `diff` = full diff, each `FileInfo.diff` = its `"diff --git "` section) and has NO caller in `apps/evo_dash`. `load_file_diff/4,5` / `load_commit_file_diff/3` → `{:ok, diff}` | `{:error, {tag, output}}` (`:context` opt int | `:all` → `-U999999` | nil = 3 lines); `get_file_content/3` → `{:ok, content}` | `{:error, …}`; `list_commits/2` / `list_commits_from_shas/3` → ALWAYS `{:ok, [%CommitInfo{}]}` (`[]` on git errors).
- **Commit graph** (`CommitGraph.for_ranges/3` → `list_commit_graph/3` → `RemoteNode.list_commit_graph/4`): ALWAYS `{:ok, %{commits: [commit], refs: %{sha => [ref_name]}}}` (bad ranges → `[]`, failed ref listing → `%{}`); each `commit` is an atom-keyed MAP (not a struct) with exactly `:sha, :short_sha, :message, :author_name, :author_email, :date` (`%DateTime{}` | nil), `:parents` (full SHAs, `[]` for a root).

## Windows PowerShell Invocation — `-EncodedCommand`

**Why:** PowerShell re-joins and re-parses the raw command line as code — Erlang spawn quoting gets mangled and a lost script arg falls back to INTERACTIVE mode (exit 0, NO output on closed stdin) — and PS 5.1 writes piped output through `[Console]::OutputEncoding` (OEM/UTF-16), which `EvoGit.UTF8.ensure_utf8/1` treats as invalid UTF-8.
**Invocation:** spawn `powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass -EncodedCommand <b64>` where b64 = base64(UTF-16LE of `& { [Console]::OutputEncoding = [System.Text.Encoding]::UTF8; <script> } *>&1`) — `-EncodedCommand` eliminates ALL command-line quoting/parsing, the OutputEncoding line forces UTF-8, `*>&1` merges all streams incl. Write-Host/information; no `<`/input redirection.
Applied at `Platform.shell_args/1`'s PowerShell clause (covers the shell tool and `Worktrees.run_init_script/3`) and `Sandbox.None`'s `run_windows/3` + `run_with_partial_windows/5` (defense-in-depth `transform_args/2` + `decode_output/1`). `transform_args/2` matches ONLY powershell/pwsh (any case, backslash-normalized before `Path.basename`) with the exact 2-element `["-Command", cmd]` shape; already-encoded args and bash/git invocations pass through untouched (no double transform). Tests: `test/evo_git/powershell_test.exs` + the `shell_args/1` test in `test/evo_git_test.exs`.

## Executable Resolution (`EvoGit.Executable`)

`EvoGit.Executable.resolve/1` is system-first, bundled-fallback: a name found on PATH is returned UNCHANGED (so `System.cmd/3`'s own PATH/PATHEXT search runs); only when absent from PATH is a bundled candidate under `priv/vendor/<platform>/` considered, and only if it exists as a regular file. Otherwise the ORIGINAL name comes back, so PATH search, `System.find_executable/1` and the Windows known-location fallback (`Sandbox.None.resolve_windows_executable/1`: WINDIR/ProgramFiles PowerShell/pwsh) still apply — `resolve/1` never returns a non-existent absolute path.
Pure `@doc false` helpers keep this testable without a real Windows vendor layout: `candidates/3` (Windows `git` → `<vendor>/mingit/cmd/git.exe`, other Windows names → `<vendor>/<name>.exe`, elsewhere → `<vendor>/<name>`) and `bundled_path/3` (first EXISTING candidate, else `nil`). `resolve/1` never resolves a bundled bash (a bundled MinGit shell is not put on PATH; see `./skills/`). Tests: `apps/evo_git/test/evo_git/executable_test.exs`.

## Known Issues

- **scp of a remote config path containing SPACES is not handled** (deliberate, remote-SSH limits). `:copying_config` creates/probes the remote config dir with `$HOME`-rooted DOUBLE-quoted paths (`mkdir -p "$HOME/Library/Application Support/genesis"`, `test -f "…/config.toml" && echo yes || echo no`), but the scp destination is rewritten back to the `~` form by `RemoteConnection.scp_remote_path/1` (behavior unchanged from before the quoting fix), because the modern SFTP-speaking scp re-parses the destination itself and would take `$HOME` literally. So on macOS the directory now exists (no more junk dirs) yet uploading `config.toml`/`credentials.toml` into it still depends on scp's protocol: sftp sends the path verbatim (works), legacy scp hands `scp -t ~/Library/Application Support/...` to the remote shell (word-splits). Failures stay best-effort (warned, bootstrap continues — the daemon boots without config). Fixing it means quoting the scp destination for the REMOTE shell, which the local scp argv cannot express portably.
- **Process/thread exhaustion inside containers breaks git forks (EAGAIN).** In rootless podman every process shares the host user's UID, so the kernel per-UID `RLIMIT_NPROC` (`ulimit -u`) spans container + host processes (every OS thread counts); when hit `fork()` fails `EAGAIN` — git prints "cannot fork() ... Resource temporarily unavailable" (e.g. in `git worktree add`). `WorktreeManager` survives (init marker + re-monitoring) but the run loses agents to crash-retry. Prevention: raise the HOST user's nproc limit (`/etc/security/limits.conf`, `systemctl --user set-property user.slice TasksMax=infinity`); `--ulimit nproc=65536:65536 --pids-limit -1` (`pids_limit`/`default_ulimits` in `containers.conf`); delegate the pids controller (`user@.service.d/delegate.conf`); verify with `ulimit -u`, or cut concurrency (`[scheduler] default_llm_max_concurrency`, per-profile `concurrency`).

## Windows-Only Runtime Hazards (audit index)

Code that is latently Windows-broken because the Windows branch is unreachable on Linux/macOS dev+CI (`Platform.windows?()` gates) — each item is a raise/degradation, not a compile error; per-subsystem detail lives in the child CONTEXT.md files.

- **`Port.open` `{:env, ...}` requires CHARLISTS** while `System.cmd/3` normalizes binaries (`validate_env/1` → `String.to_charlist/1`) — the ONE raw-port env site is `Sandbox.None`'s Windows clause (`./sandbox/`).
- **`Port.info(port, :os_pid)` returns `{:os_pid, pid}` (never a bare integer) and `Port.close/1` RAISES `ArgumentError` on a closed port** — raw `Port.open/2` is NOT interchangeable with `System.cmd/3`; `Sandbox.Helpers.wait_for_os_pid/2` unwraps the tuple and timeouts close via the idempotent `Helpers.close_port/1`, so `taskkill /T /F` and bwrap's group kill do fire (`./sandbox/`).
- **Tool-level raises are CONTAINED**: `ToolDispatch.execute_tool_with_timeout/7` spawns a linked `Task.async` and `execute_tool_task/7` has its own `try/rescue/catch`, so a RAISING tool becomes the normal result string `Error: Tool execution crashed: …`; only `:normal`/`:shutdown`/`:kill`/`{:shutdown, _}` exits re-raise into the caller's `{:exit, reason}` arm (a `nil` yield is the timeout arm) → `./agent/tools/`.
- **`EvoGit.GitEnv` exports `GIT_EDITOR` UNQUOTED** (from `derive_windows_true_exe/0`) — git hands it to `sh -c`, so `C:\Program Files\Git\usr\bin\true.exe` splits at the space and editor-opening git ops abort (`./adapters/`).
- **`RemoteConnection.run_cmd/2` spawn strings interpolate LOCAL paths unquoted** (`"curl -fL -o #{cache_file} #{url}"`, `"scp #{local_path} …"`) from `Platform.data_dir()`/`System.tmp_dir!()` — `C:\Users\<First Last>\AppData\...` splits at the space because `Port.open({:spawn, _})` is ONE command line re-parsed by the child (the argv-safe form exists in `run_ssh_command/3`); those sites also pass no `:hide`, so each Windows spawn may open a console window.
- **`SystemCheck.check_tool/1`** passes `Executable.resolve/1`'s output straight to `System.cmd/3`, so a genuinely missing tool raises `ErlangError :enoent` (a check error via the centralized rescue) instead of "unavailable".
- **`EvoGit.Skills.Executor`'s Windows branch resolves bash only via `System.find_executable("bash")`** — bundled MinGit ships `sh`, not `bash.exe`, and is off PATH, so bash skills degrade to the "install Git for Windows" error (`./skills/`).

## OAuth / Subscription Auth (`EvoGit.Auth`)
A model profile can spend a ChatGPT/Claude **subscription login** instead of a per-token API key; the credential lives in ONE managed file and never in `credentials.toml`.
- **Files**: `EvoGit.Auth.oauth_file/1` resolves an explicit `opts[:oauth_file]` (leading `~` expanded) → `default_oauth_file/0` (`<config_dir>/auth.json`) and never reads the user config; a `[[llm.models]]` profile's own `oauth_file` is threaded in as `opts[:oauth_file]` by `Config.Schema.LLM.oauth_file_for/1`; the file is ReqLLM-native JSON keyed by provider OAuth id (`"openai-codex"`, `"anthropic"`) with `type`/`access`/`refresh`/`expires`(ms)/`accountId`.
- **Never runs its own OAuth flow**: `EvoGit.Auth.oauth_import` lazily imports the vendor CLI login (`$CODEX_HOME/auth.json` or `~/.codex/auth.json` for Codex; `~/.claude/.credentials.json` for Claude Code) the first time a credential is needed, only when the managed file lacks the entry or the source mtime is newer (ReqLLM rotates and persists tokens into the managed file, so a fresher managed entry always wins).
- **Guidance**: `EvoGit.Auth.login_instructions/1` returns the one-time vendor steps (`codex login`; `claude` login or `claude setup-token` + `CLAUDE_CODE_OAUTH_TOKEN`) and is printed by the setup wizard and by `config_status/0`'s failure message; `login_instructions/2` appends `managed_file_unwritable_remedy/2` only for a managed-file failure (backward compatible: `/1` is unchanged and the dashboard still calls it).
- **Managed file that cannot be written** (read-only `$HOME`, Nix sandbox, container): the login DID exist, only Genesis's copy could not be stored, so the outcome is `{:error, {:managed_file_unwritable, posix_reason}}` from `EvoGit.Auth.ensure_credentials/2`, `credential_status/2` (via its `managed_file_error:` opt) and `Config.Schema.LLM.oauth_credential_status/1` — never `:no_credentials` (`:no_credentials` stays reserved for "no vendor login, no env token, no managed entry"; `:expired_credentials` deliberately outranks a write failure). `EvoGit.Auth.managed_file_unwritable_remedy/2` renders the ONE actionable text (path + POSIX cause + `set the OAuth profile's oauth_file to a writable location`, "running the vendor login again will not help"), used by `config_status/0`, `EvoGit.SystemCheck` (which resolves the path from the MATCHING `[[llm.models]]` profile via `oauth_file_for/1`) and `genesis setup` → `auth/CONTEXT.md` + `config/CONTEXT.md`.
- **Env fallback**: `CLAUDE_CODE_OAUTH_TOKEN` then `ANTHROPIC_OAUTH_TOKEN` for `:anthropic` when no file credential exists — OAuth without refresh, never written to disk; `:openai_codex` has no env fallback.
- **Provider identity**: `auth_modes`/`oauth_source`/`oauth_only?`/`supports_oauth?` on `Config.LLMCatalog` decide which providers can use OAuth; an OAuth-only provider (`:openai_codex`) needs no `auth_mode` in the profile.
- **Assembly**: `Config.Schema.LLM.profile_generation_params/1` is the choke point (`provider_options` three-level precedence; `ensure_profile_credentials/1` / `oauth_credential_status/1`) → `config/schema/CONTEXT.md`.
- Tests are hermetic via `opts[:home]`/`opts[:codex_home]`/`opts[:oauth_file]` and the call-time app env `:auth_home_fun` → `test/CONTEXT.md`.

## Constraints

- Part of an **umbrella project** — deps, artifacts and lockfile at the repo root; Elixir ~> 1.18; **Git CLI only** (no libgit2); no source at root; subdirectories follow Elixir convention (`./lib/evo_git/<subdir>/` ↔ `EvoGit.<Subdir>`).
- All git operations go through `EvoGit.Adapters.Git` (or `Shared.commit_files/4` → `EvoGit.sandbox_run`); no direct `System.cmd("git", ...)` in domain modules (exception: GitEnv's config reads).
- `remote_api.ex`/`remote_node.ex` are intentionally long cohesive RPC wrappers — do NOT split them; add new RPC functions there (`defnode` for identity-unwrap wrappers, per-function fallbacks hand-written).
- Agents are transient modules using the `EvoGit.Agent` behaviour; framework state lives in ETS; execution happens in **isolated git worktrees** (`WorktreeManager`), never on the main working copy; agents commit before delegating subagents (auto-commit fallback enforced by the scheduler).
- Worktrees are FRESH per run (no pool, no reuse); tool outputs truncate at `[:truncation, :tool_output_max_bytes]` (default 128 KB) and tool timeouts clamp by `[:scheduler, :max_tool_timeout]` (default 30 min), with adaptive turn-limit warnings (`EvoGit.Agent.TurnWarning` via `LoopState.last_warned_level`).
- **Three-level configuration** (`EvoGit.Config`): defaults → user config (`~/.config/genesis/config.toml`, XDG) → runtime overrides; **no default model or username is hardcoded**; caching detail → `config/`.
- **Slot discipline**: all LLM calls acquire/release slots via `AgentScheduler`; independent per-model concurrency slots + generation params + per-model exhaustion backoff (`:rate_limit` / `:insufficient_balance` = HTTP 402); `[[llm.models]]` profiles with old flat `[llm]` auto-migrating to profile `"default"` **at load time only** and flat gen-param fields stripped on save once `llm.models` is non-empty; `AgentSpec.model_id` binds a profile and children inherit it; tools throttled via `max_tool_concurrency`.
- **Task-scoped naming**: worktree dirs `worker_T<task_number>_A<task_local_id>`, branches `evogit-agent-T<task_number>-A<task_local_id>`; `task_id` = 16-char hex GUID, `task_number` = short integer from a linear scan of `.genesis/workers/` (naming only).
- **Task persistence lives here** — `Store` + `TaskRegistry` in the supervision tree so the `genesis_server` daemon has full history; a freshly-started registry leaves orphaned `:running` rows to the lease sweep; `trim_recent_projects/1` is nil-safe (nil `last_opened_at` sorts LAST); test isolation pins `config :evo_git, :data_dir` to a UNIQUE per-run temp path (`config/test.exs`) → `store/` + `task_registry/`.
- **Task Archive (opt-in)**: `--archive` → `runtime_opts` → `AgentSpec.opts` → `AgentState.archive`; each completing agent writes `refs/genesis/archive/T{task_id}-A{agent_id}-start`/`-final` + a usage git note + ONE `task_agent_archives` row STREAMING at completion (idempotent upsert on `(task_id, agent_id)`), with no buffer and nothing in `%Result{}`/report; CRASH/FAILURE/ABORT writes NO row (usage LOST — a retry resets to `Usage.zero()`); Genesis Mode B shares one `task_id` → exactly 2 nil-parent rows; JSON round-trip caveats (string keys/timestamps; keys `input_cost`/`output_cost`/`total_cost`, never `cost`) → `store/` + `agent_scheduler/`.
- **Distribution & releases**: EPMD-less via `-epmd_module Elixir.EvoGit.EpmdDist` + `-start_epmd false` in all `rel/vm.args.eex`; daemon port 9000; releases `genesis`/`genesis_desktop`/`genesis_server` in the root `mix.exs`; prod-only `PORT`/`PHX_IP` → `[server] listen_port`/`listen_ip` (default 9999); zombie prevention via dynamic port + `EVOGIT_LIFETIME_PORT` — root `../CONTEXT.md`.
- **Genesis Mode B** (`Genesis.run_new_codebase/4`): Phase 1 `Agents.Architect` → Phase 2 `Agents.Manager` (second root from the architect's final commit, "Genesis Implementation Mode" prompt); both share ONE `task_id` and their usage + `agent_count` merge into a single `%Result{}` → `merge_and_report/3`; architect failure → immediate error, manager failure → architect's result as partial success; Mode A (`ContextExtractor`) uses one root → `runtime/`.
- **`EvoGit.SandboxSlice`** owns live `evogit.slice` writes (`systemctl --user set-property evogit.slice CPUWeight=… MemoryMax=… TasksMax=…`), Linux + systemd backend only; every call is bounded by `run_systemctl_bounded/4` (`@systemctl_timeout_ms` 5000, seams `:sandbox_slice_systemctl_timeout_ms` / `:sandbox_slice_systemctl_fun`; timeout → `{:error, :timeout}`, raising runner → `{:error, {:runner_crashed, reason}}`); `update_resources/1` (sync 10s call) vs `update_resources_async/1` (cast, `:ok` even when down) — `AgentScheduler` uses the ASYNC one → `sandbox/` + `agent_scheduler/`.
- **No `try/rescue` anti-pattern**: prefer `case`/`if`/`cond`/`with` + non-crashing variants (`Regex.compile`, `:persistent_term.get/2`, `Integer.parse/1`); justified only for `terminate/2` cleanup, centralized boundaries (`safe_llm_call/2`), `SystemCheck` diagnostics, `String.to_existing_atom/1` on untrusted keys, and `try/catch` around functions with no non-crashing variant (`Path.wildcard`). **Every remaining `try/rescue` MUST have a justifying comment.**

## Assistant direct runtime APIs (top-level wrapper contracts)
The evaluator admits individual MFAs explicitly, never whole namespaces; the authoritative tier-specific lists live in `agent/tools/elixir_eval/CONTEXT.md`, and documenting neighboring APIs below does not grant access to them.
Admitted reads return the real APIs' values without evaluator-specific projections or secret filtering, and approved writes call the real mutators.
The read/write tiers guard against accidental self-corruption, not a malicious attacker; write requires exact-code tier-2 approval, while sudo requires separate explicit approval for unrestricted native evaluation.
`TaskRegistry` synchronous client calls use a fixed 30_000 ms deadline and `server/0`'s CALL-TIME process-dictionary seam; no public wrapper catches an absent/restarting registry or caller timeout.
`TaskRegistry.list_tasks_page/0,1` returns `%{rows: [summary_map], total: integer}`, while `list_tasks_paginated/0,1` returns `{[TaskInfo], total}` and `list_tasks/0` is an unbounded full-payload read; exact projection, option bounds and payload risks belong to `store/CONTEXT.md`.
`TaskRegistry.get_task/1` reads synchronously through StoreGuard inside the registry, whereas `get_task_lite/1` uses ReadOffload and does not retain its decoded payload on the registry heap; both return full `%TaskInfo{ref: nil}` or nil, and lite is NOT a redacted or blob-free detail read.
`TaskRegistry.list_tasks_summary/0,1,2`, `list_tasks_summary_by_path/1,2,3`, `list_tasks_changed_since/1` and `list_task_ids/0,1` are unpaged; empty/degraded results do not prove absence of tasks.
`TaskRegistry.start_task/2` generates a new id, starts a wrapper immediately and returns `{:ok, %TaskInfo{status: :running, ref: %Task{}}}` before runtime execution succeeds; the wrapper can run even when persistence fails, so caller timeout or a successful enqueue is not execution success.
`TaskRegistry.cancel_task/1` and `force_kill_task/1` are the task-level controls, not scheduler agent-kill helpers; both reject finalizing/terminal tasks, and force kill additionally requires this registry's live wrapper ref.
`TaskRegistry.delete_task/1` is an asynchronous cast returning `:ok`, not a confirmed deletion or cancellation; its handler performs no status/liveness check and does not kill wrappers, remove task_refs or reclaim scratch space, while store failures are swallowed after logging.
The running-task graceful-cancel handler returns `:ok` even when scheduler notification exits or its status-write path fails; force kill broadcasts a failed-task event even on error, so verify persisted state rather than inferring success from events.
`AgentScheduler` has NO `list_agents/0`, history or agent-summary API; `agent_scheduler/RemoteAPI` owns those exact MFA surfaces and their projection/ETS-copy risks.
`AgentScheduler.get_config/0,1`, `paused?/0`, `max_depth/0`, `get_llm_slot_status/0`, `pause/0`, `resume/0`, `update_config/1` and `send_user_message/2` use the implicit 5_000 ms GenServer deadline with no exit containment.
`AgentScheduler.get_config/0` returns 16 keys including unredacted `llm_generation_params` and `model_profiles` but NOT `model_concurrency`; `get_config(:model_concurrency)` returns the live map, unknown atom keys return nil, and the full-map call also probes sandbox capabilities inside the scheduler.
`AgentScheduler.task_id_for_agent/1` directly calls ETS lookup for integer ids without a missing-table guard despite its docstring; noninteger ids return nil, and current-agent/process-dictionary helpers do not identify an Assistant's owner from a fresh evaluator worker.
Runtime APIs perform no human-approval checks themselves; the evaluator enforces explicit MFA admission and approval at its boundary, without replacing the APIs' return values or adding rollback.
Persistent configuration writes replace the whole user configuration and do not automatically reload it; use the resolved map as the basis for changes, preserve unrelated settings when updating/saving, and explicitly call the admitted reload API afterward (details: `config/CONTEXT.md`).

## Command approval and source-access boundaries
`CommandShell.execute/1,2` is a literal-registry command parser, not Elixir evaluation; `approval: :auto` skips every gate while all other option values select `:chat` (`command_shell.ex:239–247,364–429`).
`CommandApproval.request(command, args_human, level, agent_id, task_id)` preserves the legacy level-2/3 shell contract and exact seven-field public map, blocks via `GenServer.call(:infinity)`, and returns `:approved | :denied | :timeout`.
`CommandApproval.request_eval(code, tier, target_node, agent_id, task_id)` shares registration/resolution machinery, accepts an exact nonempty binary of at most 16_384 bytes with tier `:write | :sudo` and an already-atom target node (`node()` for runtime local; no atom conversion), and returns the same decisions with invalid calls denied and service failures timed out.
Evaluation request maps retain ALL legacy keys `request_id, command, args, level, agent_id, task_id, node` and ADD `kind: :elixir_eval`, `tier`, `code`, `target_node`, `warning`, with `args` and `code` both the exact original binary (never normalized, trimmed, rewritten or truncated).
Write requests use `command: "elixir_eval"`, `level: 2`, `warning: nil`; sudo requests use `command: "elixir_eval sudo"`, `level: 3` and an explicit unrestricted live-BEAM OS/files/network/process-access warning stating server permissions, NOT OS root elevation and NO rollback.
`CommandApproval.pending/0` returns a list of only public request maps (no `from`/monitor/timer internals), or `[]` when the service is unavailable; RPC/dashboard integration is outside this module.
The service timer reads `:command_approval_timeout` per request, accepting only nonnegative integers and falling back to 120_000 ms for invalid values; service-call exits are caught at the public boundary to fail closed.
Approval PubSub topic `"approvals"` publishes `{:approval_requested, %{request_id, command, args, level, agent_id, task_id, node}}` and `{:approval_resolved, request_id, :approve | :deny | :timed_out}`; integer identities normalize to strings, and `respond(request_id, :approve | :deny)` resolves a pending request once (`command_approval.ex:175–214,315–323`).
Pending approvals auto-deny on LOCAL-node task updates with status `:cancelling`, `:completed`, `:failed`, or `:cancelled`; caller death resolves as `:timed_out`, and an absent service returns `:timeout` (`command_approval.ex:106–123,238–286`).
Only evaluation registration prechecks task lifecycle: a known task id is read through the existing 30s-bounded `TaskRegistry.get_task_lite/1` in the CALLER (never inside the approval GenServer), allowing pending/running/finalizing tasks and denying cancelling/terminal/missing/unavailable tasks, while nil task ids skip the read.
The precheck and registration are NOT atomic and approval does not guarantee the task is still live, so the evaluator MUST recheck lifecycle before execution; legacy shell registration and CommandShell retain their existing lifecycle behavior.
Neither approval nor tool timeouts roll back a handler's committed side effects, and direct handler/runtime API calls bypass CommandShell approval entirely.
`AgentScheduler.get_config/0` includes `:llm_generation_params` through `@config_keys` (`agent_scheduler.ex:1022–1059`), so it is not an established credential-safe inspection projection.
`SelfReflectiveSource.reference_path/0` prioritizes nonempty app-env override, then `GENESIS_SOURCE_ROOT`, then a managed directory with `.git` directory plus root CONTEXT.md, else nil; explicit overrides are not validated (`self_reflective_source.ex:171–185,216–235`).
`SelfReflectiveSource.available?/0` uses the reference or cwd and checks only directory plus root CONTEXT.md; `status/0` does run git subprocesses for commit/branch/origin despite its pure-read wording (`self_reflective_source.ex:76–93,205–208,237–272`).
Source clone/update are explicit mutators, and updating a shallow managed clone fetches then hard-resets to origin's default branch (`self_reflective_source.ex:104–121,285–300`).
Repo-less runtime/persona details belong to `runtime/` and `agents/`, tool-task role propagation and execution limits to `agent/`, and exact live/API payload risks to `agent_scheduler/`.

## Managed Per-Task Tmpdir & Reclaim Lifecycle (`EvoGit.TaskTmpdir`)

All agents of one task share ONE scratch directory (`task_<id>` under a node-local managed root) instead of the host `/tmp`; per-task (not per-agent) scope is required because agents hand temp files to **sibling** agents via raw paths. `reclaim/2` NEVER deletes outside `managed_root/1` nor the root itself.
**Sandbox TMPDIR seam**: `Sandbox.resolve_tmpdir/0` prefers `TaskTmpdir.current/0` when set, so every backend injects `TMPDIR=<task dir>`; the Runner resolves once + `put_current/1`, and tool-dispatch re-installs it inside each spawned tool task (they do NOT inherit the caller's dictionary).
**Reclaim is EVENT-DRIVEN ONLY** (owner `TaskRegistry`, node-local; no boot reaper, no periodic sweep): `handle_update_status/6` is the dominant choke point (wrapper result, stuck-`:finalizing` watchdog, startup reconciliation); the direct terminal writes that BYPASS it carry their own call — `force_kill_task` (`:failed`), cancelling a `:pending` task (`:cancelled`), the `:lease_sweep` (`:failed`) and `resolve_recheck_task/3`. A dir orphaned by a full-runtime crash needs manual cleanup; `reclaim/2` never raises.

## First User Prompt Assembly

The `run/1` callback (injected by `use EvoGit.Agent`) assembles the first user message as two XML blocks separated by a `---` rule — `<context>` (context_tree + `{authority_section}` + `{foreign_repos_section}` + `{repo_notes_section}`), then `<objective>`; blank sections vanish entirely (`---` only between two non-blank blocks), bodies come from `build_dynamic_context/1`, `build_authority_section/1`, `build_foreign_repos_section/1`, `build_repo_notes_section/1`.
**Delegation-authority section** (`ContextBuilder.build_authority_section/1`, wired in `Runner.do_run/2` only — never inside `build_dynamic_context/1`) states whether THIS agent is the **ROOT agent** (`AgentState.parent_id == nil` ⇔ `SchedMeta` depth 0 by construction in `Dispatch.register_agent/7`; never the process-dict depth) or **NESTED**, plus the foreign-repo authority that carries (ROOT may spawn `:read_write` foreign-repo subagents one at a time; NESTED may not and reports upward); it returns `""` for repo-less agents (the chat persona must not read a task-role statement) and for tasks with no non-primary foreign repos (mirroring `build_foreign_repos_section/1` so the blank filter drops it). Static system prompts are role-agnostic and point at this statement — only the first user message can state the agent's own role. `build_quality_guidance_section/1` adds the ROOT `QualityLevel` block the same way (gated on `parent_id == nil`; subagents and repo-less/reflect agents get `""`), via `Runtime.Helpers.build_root_agent_spec/7` → `AgentSpec.opts` + the Runner process dict.

## Injected User Messages (mid-run, multimodal)

The ONLY external injection point is the drain at the TOP of `Runner.loop/1`: `Runner.drain_and_inject_user_messages/1` (public `@doc false` for tests; production caller is `loop/1` only) drains `AgentScheduler.Store.drain_pending_user_messages/1`, appends each message via the pure `ContextBuilder.build_injected_message/2` (turn-tagged) and syncs the context to ETS.

- **Entry points** (message = legacy `String.t()` OR `%{text:, attachments:}`): `AgentScheduler.send_user_message/2` (guard widened to binary OR map) and `RemoteNode.send_agent_message/3` (local → `RemoteAPI.send_agent_message/2`, remote → `:erpc`). `Attachments.message/1` is the ONE normalizer and canonicalization happens in the QUEUE — entry points pass messages through verbatim.
- **Materialization**: a legacy binary or a map with `nil`/`[]` attachments → `ReqLLM.Context.user(text)` (byte-identical to plain-text injection); a map with attachments → `user(Attachments.to_content_parts(text, attachments))`; `turn` integer → `tag_message_turn/2` (+timestamp), `nil` → raw untagged; malformed maps raise `ArgumentError`. **NO root gate** — any depth may receive media; the root-only gate stays on the `:attachments` TASK OPT (`build_initial_messages/4`).
- **No per-turn runtime-context block**: `build_context_block/1` runs only at run start (`Runner.do_run/2`) and on a compression refresh (`build_context_refresh_message/2`); the top-of-turn machinery appends messages but never re-renders `<context>`, so any per-turn notice must be an APPENDED message.
- **⚠️ The drain is a non-atomic read-modify-write of the whole `%AgentState{}`** (`get_agent_state` → `put_agent_state(%{state | pending_user_messages: []})`); appends serialize only through the scheduler GenServer, so an append landing between the drain's read and write is silently LOST — as is a concurrent `set_cancel_requested/1`. A notice whose loss is unacceptable must be re-derivable at the turn top, not queue-only.

## Background Job Completion Notices (`announced`)

Every job record carries `announced` — "the owner already knows this job's outcome, so no completion notice is needed"; it starts `false` and is never reset. `snapshot/1` (`owner_pid:` defaults to `current_owner_pid/0`) is the per-turn read: one owner's jobs, newest first (started_at desc, id tie-break), capped at 20, with no backend reconciliation, no output-file I/O and no cursor advance. `claim_finished_notices/1` is the exactly-once feed: ONE GenServer call selects that owner's terminal (`:completed | :killed | :failed`) unannounced jobs, marks them `announced: true` and returns `{:ok, jobs}` newest first. Both answer their empty shapes (`[]` / `{:ok, []}`) when the registry is down or the owner is unknown; `read/2` and `list/1` mark every TERMINAL job they return as announced (never a `:running` one), and a successful `kill/3` marks the job it hands back — including the `{:error, {:already_finished, job}}` branch and a `:stopping` record a unit observer settles later — because the caller requested the stop and already knows the outcome; the `{:error, message}` backend-failure branch deliberately stays unannounced (the outcome is unknown, so the agent should still be told).
**Consumer**: `Runner.inject_background_job_notices/1` (in `continue_loop/2`, right after the pending-user-message drain, before the cancel-grace check and the LLM call) makes ONE `claim_finished_notices(owner_pid: self())` call and appends exactly ONE turn-tagged `:user` message rendered by `Agent.BackgroundJobNotice.notice/1` (`[NOTICE] N background shell job(s) finished:` + `- id — status (detail) — label` per job + a `job_output`/`job_list` hint), syncing the context to ETS; it is notification-only (never job output) and exactly-once, so polling `job_output`/`job_list` never duplicates. The claim is SKIPPED during a grace period (cancel / turn-limit wrap-up), leaving the job for the next non-grace turn.
**Compression contract**: the runtime-context refresh message is appended on every compression event, but the live job snapshot rides ONLY the summarising (stage-2) path (`ContextCompression.refresh_messages/2` with `include_background_jobs?: true`, where `snapshot(owner_pid: self())` is injected and `ContextBuilder.build_context_block/1` renders `## Background Jobs`).
BOTH rebuild paths (stage 1 prune-only and stage 2 summarising) drop EVERY earlier refresh message via `ContextCompression.drop_stale_refreshes/1` — which rejects every message matching `ContextBuilder.refresh_message?/1` and is total over malformed shapes (a non-list comes back as-is, every other message keeps its order) — BEFORE appending the freshly built refresh, so exactly ONE refresh, and therefore exactly ONE current `## Background Jobs` section, survives any compression.
Stage 1 injects no job snapshot, and the summariser does NOT list job ids/statuses under `## Pending Jobs`.

## Background Job Timers (test seam)

The periodic `:reconcile_tick` arm and the public `tick_interval_ms/0` BOTH read `EvoGit.BackgroundJobs.resolved_tick_interval_ms/0`, a CALL-TIME `Application.get_env(:evo_git, :background_tick_interval_ms, @tick_interval_ms)` lookup whose production default stays `@tick_interval_ms` = 1_000 ms (any non-integer/negative override falls back to it).
`poll_interval_ms/0` (the caller-side `wait: true` cadence) is the SAME shape: `Application.get_env(:evo_git, :background_poll_interval_ms, @poll_interval_ms)`, production default `@poll_interval_ms` = 100 ms, read ONCE per wait as the BASE of `Agent.Tools.JobOutput`'s exponential poll backoff (×1.5 per poll, capped at 3_000 ms), not on every sleep (`test/evo_git/agent/tools/job_tools_test.exs` overrides it to 5 ms).
`wait_default_ms/0` (the caller-side `wait: true` default budget) has the SAME call-time shape: `Application.get_env(:evo_git, :background_wait_default_ms, @wait_default_ms)`, production default `@wait_default_ms` = 120_000, non-negative integers only (anything else falls back to it) — read by `Agent.Tools.JobOutput`'s wait loop, so a test can pin the default-budget path without sleeping 120 s.
`wait_max_ms/0` (the caller-side hard cap) is DERIVED at CALL time, not fixed: `EvoGit.Config.resolve([:scheduler, :max_tool_timeout])` minus `dispatch_headroom_ms/0` (`@dispatch_headroom_ms` 25_000 — the ONE headroom literal), floored at 1_000 ms, i.e. 1_775_000 ms (~29.6 min) with the default config, and the documented 1_800_000 ms total when that config value is not a positive integer.
`wait_max_ms/0`'s test-only CALL-TIME seam is app env `:background_wait_max_ms`, honoured only for a POSITIVE integer (anything else falls through to the derivation), so a suite can shrink the cap instead of sleeping minutes.
`EvoGit.Agent.Tools.default_timeout_ms/1` adds the SAME headroom straight back for `job_output`, so its dispatch ceiling lands exactly on `[:scheduler, :max_tool_timeout]` (1_800_000 ms by default).
The timer is armed only while at least one live job uses a `:unit` handle and disarms/re-arms on every change, so a test can await the re-armed `tick_timer` ref instead of sleeping; a module that overrides the key must be `async: false` and restore it in `on_exit` (`background_jobs_test.exs` disarms it with 3_600_000 ms by default and arms a real 25 ms tick only in the test that proves the timer fires).

## ReqLLM Finch Pool (`EvoGit.ReqLLMPool`)

`req_llm_pool.ex` — dynamic, GROW-ONLY runtime reconciliation of ReqLLM's Finch pool (`ReqLLM.Finch`).
**API**: `desired_count(total)` → `max(total + 2, 8)` (single source of truth; `config/runtime.exs` delegates — never inline it); `error_target_count(total)` → `max(ceil(total * 1.5), 8)`; `effective_concurrency(map, default)` → `max(sum of values, default)`; `reconcile/1,2`; `bump_for_excess_queuing/2,3`; `excess_queuing_error?/1`.
**Grow-only (MANDATORY)**: `Finch.set_pool_count/3` grows safely but SHRINKS by terminating pools (killing in-flight streams), so it is applied as `max(current, desired)` per origin and never lowered; nothing raises, and `{:error, :not_found}` (no materialized origins) is a graceful no-op.
**`start_pool_metrics?: true` is REQUIRED**: pools materialize LAZILY per origin and `Finch.get_pool_status(finch, :default)` enumerates them only with the flag — otherwise always `{:error, :not_found}` and reconciliation is a SILENT no-op; `config/runtime.exs` uses the full `finch:` override form with the flag plus top-level `stream_pool_timeout` / RoundRobin `stream_pool_strategy` (both read at CALL time) and `size: 2` ⇒ per-origin capacity `count × 2` HTTP/1 streams. Sizing contract: root `../CONTEXT.md`.
**Per-origin sizing**: identity is `{scheme, host, port, tag}` (paths excluded; `:default` tag — EvoGit sets no connect options/`pool_tag`), so profiles sharing a host share ONE pool; the SUM formula is the sufficient bound per origin, `+2` covers the two non-slot-gated call sites (`system_check`, `pull_request`) and the error path cannot name the failing origin, so the bump is necessarily uniform.
**Triggers**: (1) config change — `AgentScheduler.handle_call({:update_config, opts}, …)`'s success path (`reconcile_pool_after_update/1`) reconciles with `effective_concurrency(new_state.model_concurrency, new_state.default_llm_max_concurrency)`, covering `RemoteAPI.reload_config`, `save_user_config` and the dashboard ConfigIO (the `{:error, "llm_model cannot be nil"}` path never reconciles); (2) excess queuing — `ToolDispatch.run_llm_attempt/4` calls `bump_for_excess_queuing/3` inside the per-attempt `with_llm_slot/2` body when `excess_queuing_error?(reason)` (no `report_llm_error` — the bump IS the fix).
**Tests**: `test/evo_git/req_llm_pool_test.exs` (pure functions + a real tiny Finch: grow / grow-only / `:not_found`; the test Finch sets `start_pool_metrics?: true`) + an `agent_scheduler_test.exs` smoke test (`model_concurrency` keys are STRINGS, e.g. `%{"default" => 3}`).

## SystemSampler — System Topic Sampling (`EvoGit.SystemSampler`)

`system_sampler.ex` — supervised GenServer (child of `EvoGit.Application`, on EVERY node incl. the headless daemon) sampling every 3s and broadcasting on `"system"`; message shape + the exact 13 keys are pinned in the PubSub Event Contract at `../CONTEXT.md`.

- **`llm_slots`** = `%{model_id => %{used, waiting, capacity}}` — REAL per-model occupancy (holders / queue / effective capacity incl. peak-pause `0`) from `AgentScheduler.get_llm_slot_status/0`; `%{}` when the scheduler is down or that tick's bounded call fails. `llm_used`/`llm_waiting` + both tool keys stay `:running`/`:blocked` proxies counted from the local `:evogit_sched_meta` ETS table (guarded `:ets.whereis`); sampling is LOCAL-only (no RPC), `seq` monotonic per instance.
- **Tick**: `Process.send_after(self(), :sample_tick, interval)` with `interval = Application.get_env(:evo_git, :system_sample_interval_ms, 3000)` read ONCE at init (tests raise it and drive `tick/0` or a raw `:sample_tick`), rescheduled BEFORE sampling so a slow step never breaks cadence.
- **Capacity + a 10-tick config cache**: `llm_capacity` = Σ per-profile `concurrency` and `tool_capacity` = `max_tool_concurrency`, from a direct BOUNDED `:get_config` call (2s, seam `:system_sampler_config_fun`) — deliberately NOT `RemoteAPI.get_config/0` (implicit 5000 ms) and NOT `Config.resolve/0` (re-reads disk, misses runtime overrides); cached as `config_cache: {totals, tick}`, refreshed on the `rem(tick, 10) != 1` rule (tick 1 always loads; unloaded refetches every tick until one attempt succeeds).
- **Degradation**: both scheduler reads go through `safe_scheduler_call/1` (explicit 2s bound < the 3s cadence + `catch :exit` for call timeout, the whereis→call `:noproc` race and a mid-call crash — the module's single justified try/catch); a config-refresh failure KEEPS the last cached totals and an `llm_slots` failure broadcasts `%{}`, so the 13-key shape always ships, with rate-limited `Logger.warning`s and automatic recovery. With `scheduler_alive?/0` false the sample carries zero counts/capacities + `llm_slots: %{}` + `scheduler_alive: false`; zero capacities are NEVER cached (that would suppress the refresh for 10 ticks).
- **Ring buffer**: last 60 samples; `get_recent_samples/0` → `{:ok, samples}` | `{:error, :not_found}` (guarded by `Process.whereis(__MODULE__)`); RPC `RemoteAPI.get_recent_system_samples/0` → `{:error, :sampler_down}` when not running, `RemoteNode.get_recent_system_samples/1` local/remote — all three shapes verbatim.

## Peak/Off-Peak Diagnostics (a task stuck blocked after peak exit)

Scenario: `concurrency: 5`, `peak_concurrency: 0` and peak windows — a task launched in-window blocks (0 slots → enqueued, `:blocked`) and stays blocked afterwards. Read these lines in order to separate *engine never woke* / *woke but didn't apply* / *applied but waiter never granted*:

1. `PeakHourEngine: wakeup reason=… now=… utc_now=… scheduler_up=…` (info, every check; `reason` = `:boot | :timer | :broadcast | :manual`) — no post-window `:timer` wakeup ⇒ the engine never woke.
2. `PeakHourEngine: decision=applying|unchanged effective=… current=…` — `unchanged` with the post-window map already equal to `current`, or `applying` with `effective=%{"m" => 0}` ⇒ it still believes it is in peak (clock/window/timezone bug).
3. `PeakHourEngine: next wakeup in <ms>ms … transitions=[{id, tz, wall_transition}]` — per-profile next transitions ("tomorrow instead of today" shows here); the 6h safety net is flagged when none was computable.
4. `AgentScheduler: model_concurrency updated — old=… new=… skip_floor=… default_llm_max_concurrency=…` — POST-application map; `old == new` after the window ⇒ it never applied.
5. `AgentScheduler: LLM slot grant sweep (resume) — model=… capacity=… waiting_before=… granted=… waiting_after=…` (info on meaningful events, debug on empty no-ops) — `capacity=N granted=0 waiting_after>0` ⇒ applied but the waiter was never granted.
6. `PeakHourEngine: starting — watched profiles: …` (info, `init/1`) — boot summary (id, concurrency, peak_concurrency, peak_hours, timezone).

Debug (`slots.ex`): `LLM slot request ENQUEUED — agent=… model=… capacity=0 (peak pause)`, `granted LLM slot — agent=… model=…`, `purged N LLM waiter(s) for model …`; the info line `PeakHourEngine: scheduling 6h safety-net wakeup` marks the no-profiles / scheduler-down path. Logging only — no behavior, timing, floor or fixed-point change; `peak_hour_engine_test.exs` pins the fixed-point invariant (no "applied model concurrency" log on a no-op re-check). Detail: `./agent_scheduler/`.


## Runtime distribution control
`EvoGit.Distribution.enable_runtime/3` is the daemon-side runtime toggle: it pins `:kernel` `inet_dist_listen_min = inet_dist_listen_max = dist_port` UNCONDITIONALLY (before any start attempt) and `epmd_module` to `EvoGit.EpmdDist`, then starts distribution on the live BEAM via `start_net_kernel/1`.
It is idempotent for the SAME node name (cookie re-applied) and, for a DIFFERENT name, stops the current distribution first — deliberately dropping the old identity's cross-node links, which is the "switch remote identity without restarting the daemon" path.
The node name is shape-validated (`name@host`) BEFORE any atom conversion, so a malformed CLI-supplied name never reaches `:net_kernel` nor creates an atom.
The whole body sits in ONE rescue/catch boundary (justified: VM-global distribution state + external input) that logs and returns `{:error, reason}`, and the returned `node` is the ACTUAL `to_string(node())`.
`disable_runtime/0` stops distribution when active (`:ok` otherwise) and leaves the pinned `:kernel` port in place; `active/0` reports `%{enabled: distributed?(), node: to_string(node()), dist_port: inet_dist_listen_min}`.
`enable_for_remote/1` is deliberately NOT delegated to `enable_runtime/3` — the local dashboard path keeps its fixed `genesis@127.0.0.1` identity, the 9100-9200 listen RANGE and the `[node] cookie`.
`EvoGit.DaemonControl` (supervised in every env EXCEPT test) is the file protocol the release CLI drives: the CLI writes `<data_dir>/remote/control.request` (`ACTION=enable|disable`, `NODE`, `COOKIE`, `DIST_PORT`, `SEQ`) and signals SIGHUP; the daemon answers in `dist.env`.
`dist.env` is the authoritative ACTUAL state: `GENESIS_DIST_ENABLED`, `GENESIS_NODE`, `GENESIS_DIST_PORT` (`unknown` when unset), `GENESIS_CONTROL_SEQ` (echoed, empty when absent), `GENESIS_CONTROL_RESULT` (`ok`/`error`) and a ONE-line `GENESIS_CONTROL_MESSAGE`.
Both state files are written atomically (tmp file in the same directory + `File.rename/2`) with mode 0600.
The result is written BEFORE the request file is deleted, so a caller whose request is gone always has a result to read.
`dist.env` is NEVER deleted — it is the daemon's published state, not a mailbox.
`desired.env` is the durable intent, written only after a SUCCESSFUL action (`ENABLED=1` + `NODE`/`COOKIE`/`DIST_PORT`, or `ENABLED=0` alone — no secret kept for a disabled node) and left untouched on failure.
`init/1` re-adopts an `ENABLED=1` intent best-effort (warning, never raise) and then publishes the ACTUAL state, which also covers a node booted distributed via `RELEASE_DISTRIBUTION=name` (real node/port) and a plain boot (`0`).
Any raise/exit inside request processing is caught by ONE centralised boundary that writes the error `dist.env` — the control plane must never crash.
The SIGHUP hook is Unix-only (`EvoGit.Platform.windows?/0`, and `EVOGIT_NO_SIGNAL_HOOK=1` skips it): `:os.set_signal(:sighup, :handle)` plus `:gen_event.add_handler(:erl_signal_server, EvoGit.DaemonControl.SignalHandler, [])`, where an already-present handler normalizes to `:ok`.
Both calls sit in one rescue/catch (justified: they raise/exit on platforms without the signal or without `:erl_signal_server`), and the handler only calls `EvoGit.DaemonControl.reload/1` — file work never runs inline in the shared signal manager.
No timers and no polling anywhere: `reload/1` is a cast, `sync/1` is a `@doc false` barrier for tests, and the functional core (`handle_control_request/2`, `publish_state/2`) runs without a process.
Seams, read at CALL time and default-inert: `:daemon_control_dist` (module with `enable_runtime/3`, `disable_runtime/0`, `active/0`, default `EvoGit.Distribution`) and `:daemon_control_signal_install` (0-arity installer replacement).
`init/1` opts WIN over both `dir:`, `dist:`, `signal_install:` and `name:` — which is why `daemon_control_test.exs` stays `async: true`.
