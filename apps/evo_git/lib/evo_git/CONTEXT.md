# EvoGit Core Library — `lib/evo_git/`

## Intent
Core source of the `:evo_git` OTP application: the Agent system (LLM tool-calling loops), AgentScheduler (scheduling, ETS state, slot management — worktree lifecycle owned by `AgentScheduler.WorktreeManager`), core domain types (ContextNode, PhyloGraphNode, ForeignRepo), the Git adapter, and runtime phases (Genesis, Evolution).
Multi-repo: foreign repos from `genesis.toml` or CLI flags enable cross-repo subagent spawning into isolated worktrees.
This file is the module-level API surface plus the cross-cutting contracts; each section names the child CONTEXT.md owning its detail.

## Routing Table
- `./agent/` → Agent behaviour, tool library, context compression, subagent processing, LLM error classification + retry/backoff policy, tool-name alias spine (`tool_names.ex`), completion protocol (`completion_protocol.ex`)
- `./agents/` → Agent implementations (Manager, Executor, TaskScheduler, Investigator, Architect, ContextExtractor, SkillExtractor, GenesisPlanner)
- `./agent_scheduler/` → AgentState, SchedMeta, Slots, Worktrees, WorktreeManager — ETS schemas, helpers, worktree lifecycle
- `./core/` → ContextNode, PhyloGraphNode, ForeignRepo data structures
- `./adapters/` → Git CLI adapter — all git operations go through this module
- `./runtime/` → Genesis, Evolution, PR helpers, Skill Extraction
- `./config/` → 3-level configuration resolver (defaults → user TOML → runtime overrides), schema, LLM catalog, platform detection, project config
- `./cli/` → CLI argument parsing (`CLI.Parser`), interactive setup wizard (`CLI.Setup`)
- `./custom_agents/` → `EvoGit.CustomAgents` store + `ModelSelector` (agents.toml + per-agent model-selection script)
- `./custom_tools/` → `EvoGit.CustomTools` + `.Tool` behaviour — user tools from `<config_dir>/tools/` (`.ex`/`.exs`/`.beam`)

- `./skills/` → Dynamic skill tools — YAML-frontmatter markdown skills as LLM-callable tools
- `./store/` → Ecto persistence — Operations, Boot/migrations, RepoScope, schemas, Ecto.Types, Codec (the wire oracle), Errors, Writer
- `./task_registry/` → TaskRegistry support modules — Cleanup, Diagnostics, Lease, ResumeContext, RuntimeOpts, TaskExecutor
- `./lib/mix/tasks/` → `Mix.Tasks.Changelog`, `Mix.Tasks.Bump.Version`, `Mix.Tasks.Migrate.Store`, `Mix.Tasks.Store.Maintenance` (+ their `root:`/`shell:`/summarizer-seam injection surface) — detail: `lib/mix/tasks/CONTEXT.md` and root `./CONTEXT.md` ("AI changelog generation")
- **Owner identity from inside a tool call** (fresh tool-task process dictionary; the ONE inherited key `$callers`, `SchedMeta.task_ref.pid`, `AgentScheduler.task_id_for_agent/1`) → `./agent/` ("Tool-task owner identity") + `./agent_scheduler/`
- Supervised per-resource registry that must die with its OWNER (`Process.monitor` in the registry, `:DOWN` = teardown) — precedent `EvoGit.SandboxProcessRegistry` (state map, NO ETS) + `EvoGit.TaskRegistry.server/0`
- **Supervision tree**: built INLINE in `EvoGit.Application.start/2` — there is **no `lib/evo_git/supervisor.ex`**; `EvoGit.Supervisor` is only the root supervisor's registered name, and the nested agent group is `EvoGit.AgentGroupSupervisor` (`one_for_all`: `EvoGit.TaskSupervisor` + `EvoGit.AgentScheduler`)

### SSH Remote (RemoteBootstrap / RemoteConnection)

`EvoGit.RemoteBootstrap` — pure platform/asset/download logic (no I/O): `parse_uname/2`, `parse_platform/1`, `asset_name/1` (always `genesis_remote_<platform>.tar.xz`, never suffixed), `download_url/1` (deterministic `https://genesis.evox.group/dl/genesis_remote_<platform>.tar.xz` → `{:ok, url, "latest"}` — Cloudflare proxy over the GitHub asset, no API query, no asset matching), `cache_path/2`, `bash_wrap/1`, `nixos_patch_script/1`, `parse_unit_environment/1`; extraction is `tar -xJf` (no gz fallback) and CI uploads `linux_x64`/`linux_arm64`/`darwin_arm64`/`windows_x64`.
Stage atoms: `:probing_platform | :downloading | :downloading_locally | :stopping_daemon | :uploading | :extracting | :setting_permissions | :copying_config | :generating_cookie | :patching_binaries | :starting_daemon`. Test-pinned error tuples: `{:error, {:probe_failed, {:exit_status, n} | :timeout | {:unexpected_output, out}}}` | `{:error, :unsupported_platform}`; `{:error, {:download_failed, {:exit_status, n} | :timeout | {:local, detail} | {:local_scp, detail}}}`. Timeouts: bootstrap 900s, download 300s.

`EvoGit.RemoteConnection` owns bootstrap + connect. Source priority: `local_binary_path` exists → `scp`, set-but-missing → warning + download, absent → download (remote `curl -fL`, remote `wget -O` fallback, local curl + `scp`). A silent pre-flight resolves the daemon OS (target `platform`, else one `uname -s && uname -m`) and applies the running-daemon policy BEFORE staging.
- **ARGV, never spawn strings**: `run_ssh_command/3` = `{:spawn_executable, …}` + `{:args, [target, remote_cmd]}` (a quote-wrapped `{:spawn, String}` breaks Windows — the CRT consumes only double quotes — and Unix, where spawn strings go through `/bin/sh -c`); remote commands are `bash_wrap/1`ed (`/usr/bin/env bash -c '…'`) for login-shell independence (NixOS + fish hosts).
- **Never kill a running daemon without permission**: `bootstrap/2`'s `:on_running` ∈ `:refuse` (default → `{:error, {:daemon_running, details}}`, no staging/kill/broadcast, state untouched) | `:restart` (`:stopping_daemon` + stop, failure non-fatal, then the normal flow). `verify_daemon_identity/4` is the RACE net (Linux `parse_unit_environment/1` over `systemctl show -p Environment`; Darwin plist; unknown OS `:ok`; missing keys, differing values, empty output and `:timeout` all mismatch) — fail loud, never auto-kill. Node name + cookie are fixed at LAUNCH time, the cookie per MACHINE.
- `systemctl --user reset-failed` before launch, `verify_daemon_healthy/2` (3 × 1s) after; `:copying_config` NEVER overwrites an existing remote config.toml/credentials.toml (`ssh <target> 'test -f <file>'` probe → skip the scp) and uploads an absent one accent-rewritten (per-target colour) or unmodified; Darwin's unquoted `~/Library/Application Support/genesis` makes that copy unreliable; NixOS remotes add `:patching_binaries` (`nixos_patch_script/1`, GC-rooted at `<release>/.nixos-patch`) → `./sandbox/`.
- `Distribution.ensure_epmd_module/0` (idempotent) runs on both connect paths; BOOT deliberately does NOT set it (inbound discovery keeps real epmd). Distribution is off by default and boot-enables only with `[node] enabled = true`, never in test (`@mix_env != :test` at the CALL SITE, else a developer's config starts `:net_kernel`/EPMD before `ExUnit.start/1`) — tests use `enable_for_remote/1`. `RemoteConnection.Registry` + `.Supervisor` (`:transient`) start before the agent group; `Store`/`TaskRegistry` are supervised so the daemon keeps full history (port 9000 via `rel/vm.args.eex`; zombie prevention: root `../CONTEXT.md`).

**Connect is non-blocking**: `connect/1` replies `{:ok, :connecting}`/`{:ok, :connected}` (5s call) while the I/O (`find_free_port`, ssh spawn, `wait_for_tunnel/4`, `EpmdDist.register_target/2`, `Node.connect/1`) runs in a monitored worker that hands the tunnel `Port` over (`Port.connect/2`) BEFORE reporting `{:connect_result, pid, {:ok, %{port:, local_port:, node_name:}}} | {:connect_result, pid, {:error, message}}` (a `:DOWN` without a result → "connect worker crashed: …"). Broadcasts `{:remote_connection_status, target.id, status_map}` on `"remote_connections"` — NO trailing node element (documented exception; `handle_connection_status/2` is its only consumer): `:connecting`, `:connected`, `:error` (with `last_error`, single `fail_connect/2` choke point), `:disconnected`. Duplicate connects are idempotent; ssh carries `-o ConnectTimeout=8`; `disconnect/1` while `:connecting` kills the worker (it owns the port) then `cleanup/1` → `:disconnected` + `{:stop, :normal, …}`; no app-env/clock seams (tests fake `ssh` on PATH).
**Tunnel invariant**: `Node.connect/1` must NOT run before the forwarded port accepts TCP (`ssh -L <local_port>:127.0.0.1:<dist_port> -N <target>` can take >1.5s; an early connect fails econnrefused → `{:error, {:node_connect_failed, …}}` with NO remote-side log); `wait_for_tunnel/4` polls (100ms, 10s budget), fails fast when the ssh Port dies, `@doc false` for tests.
**Known `node_connect_failed` causes**: stale daemon (`{:daemon_identity_mismatch, details}` → `bootstrap(target_id, on_running: :restart)`; a plain `systemctl restart` re-runs the old unit env); `dist_port` ≠ 9000 (the daemon is pinned to 9000 and `ssh -L` accepts local connections to a dead forward target, so the poll still passes); a boot-distributed node whose `epmd_module` is `erl_epmd` (real epmd → `:noport`, no journal entry).

### SQLite Store — Ecto Persistence Layer

`EvoGit.Store` is a GenServer facade over pure `Store.Operations.*` (each repo-pid-first via `RepoScope.with_repo/2`) against this store's own UNNAMED dynamic `EvoGit.Repo` (xqlite; pool = `Boot.default_pool_size/0`, per-store `:pool_size`), with WAL + `default_transaction_mode: :immediate` + `busy_timeout: 30_000` from `EvoGit.Repo.start_opts/0`.
**Boot**: `Store.Boot.start_dynamic/2` runs the EIGHT migrations in `priv/repo/migrations/` (`001` baseline adoption, `002` data normalization, `003` composite indexes, `005` covering indexes, `006` legacy-format repair, `007` `task_agent_archives`, `008` legacy-archive fan-out + column drop, `009` `task_agent_archives` shape normalization) on a temporary single connection, THEN opens the pool at the requested size so every connection sees the migrated schema — an existing user DB upgrades on first start.
**Every JSON column is plain UTF-8 TEXT** — `opts`/`logs`/`result`/`usage`/`error` round-trip through `Store.Codec` (the single encode/decode wire oracle); no compression of any kind and no prefix-tagged payload, so any row is readable to plain SQL. `PRAGMA optimize` runs once per boot + hourly (`Store.Maintenance`); `mix store.maintenance [--vacuum]` reclaims on demand (VACUUM never at boot).
**Reads/writes**: reads fan out to 6 WAL readers (8 MiB cache each) and EVERY read runs on `offload/5` (unlinked monitored worker, 25s deadline) degrading to the read's own empty shape — a slow read can never kill `Store` or `TaskRegistry` (whose sync calls are `:exit`-guarded by `StoreGuard`); writes serialize through `Store.Writer` (reply-after-commit) with the disk-full choke point `Errors.disk_full_exception?/1` → `{:error, :disk_full}`. Query shapes, indexes and measured effects: `./store/CONTEXT.md`.

## Review / RemoteNode Return-Shape Contract (remote-SSH payload analysis)

`EvoGit.RemoteNode` review wrappers return the **verbatim** `EvoGit.Review` value (local → `RemoteAPI` direct, remote → `:erpc` via `call_remote/4`); the only added shape is `{:error, {kind, reason}}` on RPC failure. Arity = Review + 1 (leading `node`), and all time out via `rpc_timeout/0` (`Application.get_env(:evo_git, :remote_rpc_timeout, 30_000)`, read at CALL time). **`defnode` convention**: `defnode EvoGit.AgentScheduler.RemoteAPI.fun(args)` (`EvoGit.RemoteNode.Defnode`) generates the local-direct / `call_remote` pair ONLY when the remote branch is exactly `{:ok, r} -> r; {:error, e} -> {:error, e}`; per-function fallbacks (`[]`/`%{}`/`nil`/`false`/`{:error, :rpc_failed}`, nested errors) stay hand-written. Review/task wrappers are all `defnode`-generated and take an explicit `repo_path`.

- **Structs**: `%EvoGit.Review.FileInfo{}` — `:path`, `:status` (`"added" | "deleted" | "modified"`), `:additions`/`:deletions`, `:diff` (String | nil), `:language` (highlight.js name, always populated), `full_new_content: nil`, `full_old_content: nil` — Review NEVER fills `full_*`, callers do via `get_file_content/4`. `%EvoGit.Review.CommitInfo{}` — `:sha`, `:short_sha`, `:message` (subject, `%s`), `:author_name`, `:author_email`, `:date` (`%DateTime{}` from `%aI`, raw String on parse failure).
- **Reads**: `load_review_metadata/2`, `load_review_metadata_from_shas/3`, `load_commit_files/2` (vs `commit_sha~1`) all return `{:ok, %{commit_sha, base_sha, diff_stat (raw --numstat), diff: nil, files: [%FileInfo{}] (diff: nil), changed_files_count, total_additions, total_deletions}}` | `{:error, {tag, output}}`; `load_review_data/2` is the heavy variant (top-level `diff` = full diff, each `FileInfo.diff` = its `"diff --git "` section) and has NO caller in `apps/evo_dash`. `load_file_diff/4,5` / `load_commit_file_diff/3` → `{:ok, diff}` | `{:error, {tag, output}}` (`:context` opt int | `:all` → `-U999999` | nil = 3 lines); `get_file_content/3` → `{:ok, content}` | `{:error, …}`; `list_commits/2` / `list_commits_from_shas/3` → ALWAYS `{:ok, [%CommitInfo{}]}` (`[]` on git errors).
- **Commit graph** (`CommitGraph.for_ranges/3` → `list_commit_graph/3` → `RemoteNode.list_commit_graph/4`): ALWAYS `{:ok, %{commits: [commit], refs: %{sha => [ref_name]}}}` (bad ranges → `[]`, failed ref listing → `%{}`); each `commit` is an atom-keyed MAP (not a struct) with exactly `:sha, :short_sha, :message, :author_name, :author_email, :date` (`%DateTime{}` | nil), `:parents` (full SHAs, `[]` for a root).
- **Task-scoped graph** (`TaskCommitGraph.for_task/4` → `list_task_commit_graph/4` → `RemoteNode.list_task_commit_graph/5`, args node + `task_id` + `repo_path` + `live_tips` + `opts`): durable WHOLE-TASK variant that keeps a recycled agent's history. `resolve_refs/1` (pure) / `resolve/1` (reads `TaskRegistry.get_task/1`; total → `%{base_sha: nil, tips: [], project_path: nil}`) take tips from `commit_sha`, `branch_name` and every `result["repos"][repo_id]["commit_sha"|"branch_name"]` (blanks/dupes dropped). Base per `repo_path`, first non-blank: `opts[:base_sha]` → repo-aware task base (`refs.base_sha` when `repo_path == refs.project_path`, else the matching `opts[:foreign_repos]` entry) → `Git.merge_base(repo_path, "HEAD", ref)` → `nil`. Result = the 2-key shape + `truncated: boolean` (from a `limit + 1` fetch), passed verbatim through `:erpc`.
- **Mutating ops**: `merge_branch/2,3` → `{:ok, merged_sha}` | `{:conflict, details}` (trimmed merge stderr on `Git.run` exit-1) | `{:error, {code, output}}` | `{:error, {:switch_back_failed, reason}}`; `reject_branch/2` → `:ok` | `{:error, {code, output}}`. These and `check_merge/3` return `{:error, :no_branch}` for a nil OR blank (`String.trim(x) == ""`) branch/ref via one shared `valid_branch_name?/1`, so `is_binary`-guarded `Adapters.Git` functions never see nil (a no-change multi-repo repo carries `branch_name: nil`). `create_github_pr/4` → `{pr_url, pr_title}` | `{nil, nil}` (never raises; `Runtime.PullRequest.try_create`); `list_branches/1` → `{:ok, [names]}` | `{:error, {tag, output}}`; `branch_exists?/2` → boolean.
- **`check_merge/3`**: `{:ok, :clean}` (identical SHAs short-circuit) | `{:ok, {:conflict, files}}` (path strings; 40-hex OIDs dropped by `conflicted_file_paths/1`) | `{:error, {:merge_failed, output}}` (exit-1, no file lines) | `{:error, {code, output}}` / `{:error, {:conflict, output}}` (rev_parse) | `{:error, :no_branch}`. Non-mutating `git merge-tree --write-tree --name-only --no-messages`: no worktree/index/ref change, nothing under `.genesis/`.
- **`set_review_status`/`set_review_metadata` live in `EvoGit.TaskRegistry`, NOT `Review`** — GenServer **casts** replying `:ok` immediately (`set_review_status/3` → `RemoteAPI.set_review_status/2` → `TaskRegistry.set_review_status/2`; `set_review_metadata/4` → …/`set_review_metadata/3`; both `defnode`). **Review status is TASK-LEVEL only — no per-repo state exists**: one column `tasks.review_status` (TEXT) plus `tasks.base_sha`/`tasks.commit_sha`, written via `Store.update_task_columns/3` behind a `Store.get_task_status/2` check (missing row = silent `:ok` no-op), each broadcasting `{:task_updated, task_id, nil, node()}`. Allowed values (Codec whitelist): `:open, :merged, :rejected, :continued, :ignored, :no_changes` (unknown → nil).
- **Task ops**: `RemoteNode.start_task/3` → `RemoteAPI.start_task/2` → `TaskRegistry.start_task/2` → `{:ok, %TaskInfo{}}` (19 fields incl. in-memory-only `ref`) | `{:error, :cancelled}`; `get_task/2` → bare `%TaskInfo{} | nil` (nil on RPC failure AND missing task). `custom_tools_status/1` → `CustomTools.status/0` per node: `%{ok: [%{name, file, module, read_only?: boolean}], errors: [%{file, reason}]}` verbatim; remote failure → `{:error, {kind, reason}}` (never swallowed into an empty map).

**⚠️ Known spec mismatch — `default_merge_target`**: it returns `{:ok, String.t()}` | `{:error, :no_branch_found}`, but the `RemoteAPI`/`RemoteNode`/`NodeContext` `@spec`s claim `String.t() | {:error, term()}` (the `{:ok, _}` is missing); the runtime value is the wrapped tuple and `ReviewLive` matches `{:ok, name}` — do NOT trust those specs.

## Windows PowerShell Invocation — `-EncodedCommand`

**Why:** PowerShell re-joins and re-parses the raw command line as code — Erlang spawn quoting gets mangled and a lost script arg falls back to INTERACTIVE mode (exit 0, NO output on closed stdin) — and PS 5.1 writes piped output through `[Console]::OutputEncoding` (OEM/UTF-16), which `EvoGit.UTF8.ensure_utf8/1` treats as invalid UTF-8.
**Invocation:** spawn `powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass -EncodedCommand <b64>` where b64 = base64(UTF-16LE of `& { [Console]::OutputEncoding = [System.Text.Encoding]::UTF8; <script> } *>&1`) — `-EncodedCommand` eliminates ALL command-line quoting/parsing, the OutputEncoding line forces UTF-8, `*>&1` merges all streams incl. Write-Host/information; no `<`/input redirection.
Applied at `Platform.shell_args/1`'s PowerShell clause (covers the shell tool and `Worktrees.run_init_script/3`) and `Sandbox.None`'s `run_windows/3` + `run_with_partial_windows/5` (defense-in-depth `transform_args/2` + `decode_output/1`). `transform_args/2` matches ONLY powershell/pwsh (any case, backslash-normalized before `Path.basename`) with the exact 2-element `["-Command", cmd]` shape; already-encoded args and bash/git invocations pass through untouched (no double transform). Tests: `test/evo_git/powershell_test.exs` + the `shell_args/1` test in `test/evo_git_test.exs`.

## Executable Resolution (`EvoGit.Executable`)

`EvoGit.Executable.resolve/1` is system-first, bundled-fallback: a name found on PATH is returned UNCHANGED (so `System.cmd/3`'s own PATH/PATHEXT search runs); only when absent from PATH is a bundled candidate under `priv/vendor/<platform>/` considered, and only if it exists as a regular file. Otherwise the ORIGINAL name comes back, so PATH search, `System.find_executable/1` and the Windows known-location fallback (`Sandbox.None.resolve_windows_executable/1`: WINDIR/ProgramFiles PowerShell/pwsh) still apply — `resolve/1` never returns a non-existent absolute path.
Pure `@doc false` helpers keep this testable without a real Windows vendor layout: `candidates/3` (Windows `git` → `<vendor>/mingit/cmd/git.exe`, other Windows names → `<vendor>/<name>.exe`, elsewhere → `<vendor>/<name>`) and `bundled_path/3` (first EXISTING candidate, else `nil`). `resolve/1` never resolves a bundled bash (a bundled MinGit shell is not put on PATH; see `./skills/`). Tests: `apps/evo_git/test/evo_git/executable_test.exs`.

## Known Issues

- **Process/thread exhaustion inside containers breaks git forks (EAGAIN).** In rootless podman every process shares the host user's UID, so the kernel per-UID `RLIMIT_NPROC` (`ulimit -u`) spans container + host processes (every OS thread counts); when hit `fork()` fails `EAGAIN` — git prints "cannot fork() ... Resource temporarily unavailable" (e.g. in `git worktree add`). `WorktreeManager` survives (init marker + re-monitoring) but the run loses agents to crash-retry. Prevention: raise the HOST user's nproc limit (`/etc/security/limits.conf`, `systemctl --user set-property user.slice TasksMax=infinity`); `--ulimit nproc=65536:65536 --pids-limit -1` (`pids_limit`/`default_ulimits` in `containers.conf`); delegate the pids controller (`user@.service.d/delegate.conf`); verify with `ulimit -u`, or cut concurrency (`[scheduler] default_llm_max_concurrency`, per-profile `concurrency`).

## Windows-Only Runtime Hazards (audit index)

Code that is latently Windows-broken because the Windows branch is unreachable on Linux/macOS dev+CI (`Platform.windows?()` gates) — each item is a raise/degradation, not a compile error; per-subsystem detail lives in the child CONTEXT.md files.

- **`Port.open` `{:env, ...}` requires CHARLISTS** while `System.cmd/3` normalizes binaries (`validate_env/1` → `String.to_charlist/1`) — the ONE raw-port env site is `Sandbox.None`'s Windows clause (`./sandbox/`).
- **`Port.info(port, :os_pid)` returns `{:os_pid, pid}` (never a bare integer) and `Port.close/1` RAISES `ArgumentError` on a closed port** — raw `Port.open/2` is NOT interchangeable with `System.cmd/3`; `Sandbox.Helpers.wait_for_os_pid/2` unwraps the tuple and timeouts close via the idempotent `Helpers.close_port/1`, so `taskkill /T /F` and bwrap's group kill do fire (`./sandbox/`).
- **Tool-level raises are CONTAINED**: `ToolDispatch.execute_tool_with_timeout/7` spawns a linked `Task.async` and `execute_tool_task/7` has its own `try/rescue/catch`, so a RAISING tool becomes the normal result string `Error: Tool execution crashed: …`; only `:normal`/`:shutdown`/`:kill`/`{:shutdown, _}` exits re-raise into the caller's `{:exit, reason}` arm (a `nil` yield is the timeout arm) → `./agent/tools/`.
- **`EvoGit.GitEnv` exports `GIT_EDITOR` UNQUOTED** (from `derive_windows_true_exe/0`) — git hands it to `sh -c`, so `C:\Program Files\Git\usr\bin\true.exe` splits at the space and editor-opening git ops abort (`./adapters/`).
- **`RemoteConnection.run_cmd/2` spawn strings interpolate LOCAL paths unquoted** (`"curl -fL -o #{cache_file} #{url}"`, `"scp #{local_path} …"`) from `Platform.data_dir()`/`System.tmp_dir!()` — `C:\Users\<First Last>\AppData\...` splits at the space because `Port.open({:spawn, _})` is ONE command line re-parsed by the child (the argv-safe form exists in `run_ssh_command/3`); those sites also pass no `:hide`, so each Windows spawn may open a console window.
- **`SystemCheck.check_tool/1`** passes `Executable.resolve/1`'s output straight to `System.cmd/3`, so a genuinely missing tool raises `ErlangError :enoent` (a check error via the centralized rescue) instead of "unavailable".
- **`EvoGit.Skills.Executor`'s Windows branch resolves bash only via `System.find_executable("bash")`** — bundled MinGit ships `sh`, not `bash.exe`, and is off PATH, so bash skills degrade to the "install Git for Windows" error (`./skills/`).

## Constraints

- Part of an **umbrella project** — deps, artifacts and lockfile at the repo root; Elixir ~> 1.18; **Git CLI only** (no libgit2); no source at root; subdirectories follow Elixir convention (`./lib/evo_git/<subdir>/` ↔ `EvoGit.<Subdir>`).
- All git operations go through `EvoGit.Adapters.Git` (or `Shared.commit_files/4` → `EvoGit.sandbox_run`); no direct `System.cmd("git", ...)` in domain modules (exception: GitEnv's config reads).
- `remote_api.ex`/`remote_node.ex` are intentionally long cohesive RPC wrappers — do NOT split them; add new RPC functions there (`defnode` for identity-unwrap wrappers, per-function fallbacks hand-written).
- Agents are transient modules using the `EvoGit.Agent` behaviour; framework state lives in ETS; execution happens in **isolated git worktrees** (`WorktreeManager`), never on the main working copy; agents commit before delegating subagents (auto-commit fallback enforced by the scheduler).
- Worktrees are FRESH per run (no pool, no reuse); tool outputs truncate at `[:truncation, :tool_output_max_bytes]` (default 128 KB) and tool timeouts clamp by `[:scheduler, :max_tool_timeout]` (default 30 min), with adaptive turn-limit warnings (`EvoGit.Agent.TurnWarning` via `LoopState.last_warned_level`).
- **Three-level configuration** (`EvoGit.Config`): defaults → user config (`~/.config/genesis/config.toml`, XDG) → runtime overrides; **no default model or username is hardcoded**; caching detail → `config/`.
- **Slot discipline**: all LLM calls acquire/release slots via `AgentScheduler`; independent per-model concurrency slots + generation params + per-model exhaustion backoff (`:rate_limit` / `:insufficient_balance` = HTTP 402); `[[llm.models]]` profiles with old flat `[llm]` auto-migrating to profile `"default"` **at load time only** and flat gen-param fields stripped on save once `llm.models` is non-empty; `AgentSpec.model_id` binds a profile and children inherit it; tools throttled via `max_tool_concurrency`.
- **Task-scoped naming**: worktree dirs `worker_T<task_number>_A<task_local_id>`, branches `evogit-agent-T<task_number>-A<task_local_id>`; `task_id` = 16-char hex GUID, `task_number` = short integer from a linear scan of `.genesis/workers/` (naming only).
- **Task persistence lives here** — `Store` + `TaskRegistry` in the supervision tree so `genesis_remote` has full history; a freshly-started registry leaves orphaned `:running` rows to the lease sweep; `trim_recent_projects/1` is nil-safe (nil `last_opened_at` sorts LAST); test isolation pins `config :evo_git, :data_dir` to a UNIQUE per-run temp path (`config/test.exs`) → `store/` + `task_registry/`.
- **Task Archive (opt-in)**: `--archive` → `runtime_opts` → `AgentSpec.opts` → `AgentState.archive`; each completing agent writes `refs/genesis/archive/T{task_id}-A{agent_id}-start`/`-final` + a usage git note + ONE `task_agent_archives` row STREAMING at completion (idempotent upsert on `(task_id, agent_id)`), with no buffer and nothing in `%Result{}`/report; CRASH/FAILURE/ABORT writes NO row (usage LOST — a retry resets to `Usage.zero()`); Genesis Mode B shares one `task_id` → exactly 2 nil-parent rows; JSON round-trip caveats (string keys/timestamps; keys `input_cost`/`output_cost`/`total_cost`, never `cost`) → `store/` + `agent_scheduler/`.
- **Distribution & releases**: EPMD-less via `-epmd_module Elixir.EvoGit.EpmdDist` + `-start_epmd false` in all `rel/vm.args.eex`; daemon port 9000; releases `genesis`/`genesis_desktop`/`genesis_remote` in the root `mix.exs`; prod-only `PORT`/`PHX_IP` → `[server] listen_port`/`listen_ip` (default 9999); zombie prevention via dynamic port + `EVOGIT_LIFETIME_PORT` — root `../CONTEXT.md`.
- **Genesis Mode B** (`Genesis.run_new_codebase/4`): Phase 1 `Agents.Architect` → Phase 2 `Agents.Manager` (second root from the architect's final commit, "Genesis Implementation Mode" prompt); both share ONE `task_id` and their usage + `agent_count` merge into a single `%Result{}` → `merge_and_report/3`; architect failure → immediate error, manager failure → architect's result as partial success; Mode A (`ContextExtractor`) uses one root → `runtime/`.
- **`EvoGit.SandboxSlice`** owns live `evogit.slice` writes (`systemctl --user set-property evogit.slice CPUWeight=… MemoryMax=… TasksMax=…`), Linux + systemd backend only; every call is bounded by `run_systemctl_bounded/4` (`@systemctl_timeout_ms` 5000, seams `:sandbox_slice_systemctl_timeout_ms` / `:sandbox_slice_systemctl_fun`; timeout → `{:error, :timeout}`, raising runner → `{:error, {:runner_crashed, reason}}`); `update_resources/1` (sync 10s call) vs `update_resources_async/1` (cast, `:ok` even when down) — `AgentScheduler` uses the ASYNC one → `sandbox/` + `agent_scheduler/`.
- **No `try/rescue` anti-pattern**: prefer `case`/`if`/`cond`/`with` + non-crashing variants (`Regex.compile`, `:persistent_term.get/2`, `Integer.parse/1`); justified only for `terminate/2` cleanup, centralized boundaries (`safe_llm_call/2`), `SystemCheck` diagnostics, `String.to_existing_atom/1` on untrusted keys, and `try/catch` around functions with no non-crashing variant (`Path.wildcard`). **Every remaining `try/rescue` MUST have a justifying comment.**

## Managed Per-Task Tmpdir & Reclaim Lifecycle (`EvoGit.TaskTmpdir`)

All agents of one task share ONE scratch directory (`task_<id>` under a node-local managed root) instead of the host `/tmp`; per-task (not per-agent) scope is required because agents hand temp files to **sibling** agents via raw paths. `reclaim/2` NEVER deletes outside `managed_root/1` nor the root itself.
**Sandbox TMPDIR seam**: `Sandbox.resolve_tmpdir/0` prefers `TaskTmpdir.current/0` when set, so every backend injects `TMPDIR=<task dir>`; the Runner resolves once + `put_current/1`, and tool-dispatch re-installs it inside each spawned tool task (they do NOT inherit the caller's dictionary).
**Reclaim is EVENT-DRIVEN ONLY** (owner `TaskRegistry`, node-local; no boot reaper, no periodic sweep): `handle_update_status/6` is the dominant choke point (wrapper result, stuck-`:finalizing` watchdog, startup reconciliation); the direct terminal writes that BYPASS it carry their own call — `force_kill_task` (`:failed`), cancelling a `:pending` task (`:cancelled`), the `:lease_sweep` (`:failed`) and `resolve_recheck_task/3`. A dir orphaned by a full-runtime crash needs manual cleanup; `reclaim/2` never raises.

## First User Prompt Assembly

The `run/1` callback (injected by `use EvoGit.Agent`) assembles the first user message as two XML blocks separated by a `---` rule — `<context>` (context_tree + `{authority_section}` + `{foreign_repos_section}` + `{repo_notes_section}`), then `<objective>`; blank sections vanish entirely (`---` only between two non-blank blocks), bodies come from `build_dynamic_context/1`, `build_authority_section/1`, `build_foreign_repos_section/1`, `build_repo_notes_section/1`.
**Delegation-authority section** (`ContextBuilder.build_authority_section/1`, wired in `Runner.do_run/2` only — never inside `build_dynamic_context/1`) states whether THIS agent is the **ROOT agent** (`AgentState.parent_id == nil` ⇔ `SchedMeta` depth 0 by construction in `Dispatch.register_agent/7`; never the process-dict depth) or **NESTED**, plus the foreign-repo authority that carries (ROOT may spawn `:read_write` foreign-repo subagents one at a time; NESTED may not and reports upward); it returns `""` for repo-less agents (the chat persona must not read a task-role statement) and for tasks with no non-primary foreign repos (mirroring `build_foreign_repos_section/1` so the blank filter drops it). Static system prompts are role-agnostic and point at this statement — only the first user message can state the agent's own role. `build_quality_guidance_section/1` adds the ROOT `QualityLevel` block the same way (gated on `parent_id == nil`; subagents and repo-less/reflect agents get `""`), via `Runtime.Helpers.build_root_agent_spec/7` → `AgentSpec.opts` + the Runner process dict.

## Injected User Messages (mid-run, multimodal)

The ONLY external injection point is the drain at the TOP of `Runner.loop/1`: `Runner.drain_and_inject_user_messages/1` (public `@doc false` for tests; production caller is `loop/1` only) drains `AgentScheduler.Store.drain_pending_user_messages/1`, appends each message via the pure `ContextBuilder.build_injected_message/2` (turn-tagged) and syncs the context to ETS.

- **Entry points** (message = legacy `String.t()` OR `%{text:, attachments:}`): `AgentScheduler.send_user_message/2` (guard widened to binary OR map) and `RemoteNode.send_agent_message/3` (local → `RemoteAPI.send_agent_message/2`, remote → `:erpc`). `Attachments.message/1` is the ONE normalizer and canonicalization happens in the QUEUE — entry points pass messages through verbatim.
- **Materialization**: a legacy binary or a map with `nil`/`[]` attachments → `ReqLLM.Context.user(text)` (byte-identical to plain-text injection); a map with attachments → `user(Attachments.to_content_parts(text, attachments))`; `turn` integer → `tag_message_turn/2` (+timestamp), `nil` → raw untagged; malformed maps raise `ArgumentError`. **NO root gate** — any depth may receive media; the root-only gate stays on the `:attachments` TASK OPT (`build_initial_messages/4`).
- **No per-turn runtime-context block**: `build_context_block/1` runs only at run start (`Runner.do_run/2`) and on a compression refresh (`build_context_refresh_message/2`); the top-of-turn machinery appends messages but never re-renders `<context>`, so any per-turn notice must be an APPENDED message.
- **⚠️ The drain is a non-atomic read-modify-write of the whole `%AgentState{}`** (`get_agent_state` → `put_agent_state(%{state | pending_user_messages: []})`); appends serialize only through the scheduler GenServer, so an append landing between the drain's read and write is silently LOST — as is a concurrent `set_cancel_requested/1`. A notice whose loss is unacceptable must be re-derivable at the turn top, not queue-only.

## Background Job Completion Notices (`announced`)

Every job record carries `announced` — `false` at start, never reset. `snapshot/1` (`owner_pid:` defaults to `current_owner_pid/0`) is the per-turn read: one owner's jobs, newest first (started_at desc, id tie-break), capped at 20, with no backend reconciliation, no output-file I/O and no cursor advance. `claim_finished_notices/1` is the exactly-once feed: ONE GenServer call selects that owner's terminal (`:completed | :killed | :failed`) unannounced jobs, marks them `announced: true` and returns `{:ok, jobs}` newest first. Both answer their empty shapes (`[]` / `{:ok, []}`) when the registry is down or the owner is unknown; `read/2` and `list/1` mark every TERMINAL job they return as announced (never a `:running` one).
**Consumer**: `Runner.inject_background_job_notices/1` (in `continue_loop/2`, right after the pending-user-message drain, before the cancel-grace check and the LLM call) makes ONE `claim_finished_notices(owner_pid: self())` call and appends exactly ONE turn-tagged `:user` message rendered by `Agent.BackgroundJobNotice.notice/1` (`[NOTICE] N background shell job(s) finished:` + `- id — status (detail) — label` per job + a `job_output`/`job_list` hint), syncing the context to ETS; it is notification-only (never job output) and exactly-once, so polling `job_output`/`job_list` never duplicates. The claim is SKIPPED during a grace period (cancel / turn-limit wrap-up), leaving the job for the next non-grace turn.
**Compression contract**: the runtime-context refresh message is appended on every compression event, but the live job snapshot rides ONLY the summarising (stage-2) path — `ContextCompression.refresh_messages/2` injects `snapshot(owner_pid: self())` when its `include_background_jobs?` flag is true and `ContextBuilder.build_context_block/1` renders `## Background Jobs`; every summarising outcome drops earlier job-carrying refresh messages (`drop_stale_background_job_refreshes/1`) before appending the new one, so exactly ONE current section survives; stage 1 injects no snapshot and does no cleanup, and the summariser does NOT list job ids/statuses under `## Pending Jobs`.

## ReqLLM Finch Pool (`EvoGit.ReqLLMPool`)

`req_llm_pool.ex` — dynamic, GROW-ONLY runtime reconciliation of ReqLLM's Finch pool (`ReqLLM.Finch`).
**API**: `desired_count(total)` → `max(total + 2, 8)` (single source of truth; `config/runtime.exs` delegates — never inline it); `error_target_count(total)` → `max(ceil(total * 1.5), 8)`; `effective_concurrency(map, default)` → `max(sum of values, default)`; `reconcile/1,2`; `bump_for_excess_queuing/2,3`; `excess_queuing_error?/1`.
**Grow-only (MANDATORY)**: `Finch.set_pool_count/3` grows safely but SHRINKS by terminating pools (killing in-flight streams), so it is applied as `max(current, desired)` per origin and never lowered; nothing raises, and `{:error, :not_found}` (no materialized origins) is a graceful no-op.
**`start_pool_metrics?: true` is REQUIRED**: pools materialize LAZILY per origin and `Finch.get_pool_status(finch, :default)` enumerates them only with the flag — otherwise always `{:error, :not_found}` and reconciliation is a SILENT no-op; `config/runtime.exs` uses the full `finch:` override form with the flag plus top-level `stream_pool_timeout` / RoundRobin `stream_pool_strategy` (both read at CALL time) and `size: 2` ⇒ per-origin capacity `count × 2` HTTP/1 streams. Sizing contract: root `../CONTEXT.md`.
**Per-origin sizing**: identity is `{scheme, host, port, tag}` (paths excluded; `:default` tag — EvoGit sets no connect options/`pool_tag`), so profiles sharing a host share ONE pool; the SUM formula is the sufficient bound per origin, `+2` covers the two non-slot-gated call sites (`system_check`, `pull_request`) and the error path cannot name the failing origin, so the bump is necessarily uniform.
**Triggers**: (1) config change — `AgentScheduler.handle_call({:update_config, opts}, …)`'s success path (`reconcile_pool_after_update/1`) reconciles with `effective_concurrency(new_state.model_concurrency, new_state.default_llm_max_concurrency)`, covering `RemoteAPI.reload_config`, `save_user_config` and the dashboard ConfigIO (the `{:error, "llm_model cannot be nil"}` path never reconciles); (2) excess queuing — `ToolDispatch.run_llm_attempt/4` calls `bump_for_excess_queuing/3` inside the per-attempt `with_llm_slot/2` body when `excess_queuing_error?(reason)` (no `report_llm_error` — the bump IS the fix).
**Tests**: `test/evo_git/req_llm_pool_test.exs` (pure functions + a real tiny Finch: grow / grow-only / `:not_found`; the test Finch sets `start_pool_metrics?: true`) + an `agent_scheduler_test.exs` smoke test (`model_concurrency` keys are STRINGS, e.g. `%{"default" => 3}`).

## SystemSampler — System Topic Sampling (`EvoGit.SystemSampler`)

`system_sampler.ex` — supervised GenServer (child of `EvoGit.Application`, on EVERY node incl. the headless daemon) sampling every 3s and broadcasting on `"system"`; message shape + the exact 13 keys are pinned in the PubSub Event Contract at `../CONTEXT.md`.

- **`llm_slots`** = `%{model_id => %{used, waiting, capacity}}` — REAL per-model occupancy (holders / queue / effective capacity incl. peak-pause `0`) from `AgentScheduler.get_llm_slot_status/0`; `%{}` when the scheduler is down or that tick's bounded call fails. `llm_used`/`llm_waiting` + both tool keys stay `:running`/`:blocked` proxies counted from the local `:evogit_sched_meta` ETS table (guarded `:ets.whereis`); sampling is LOCAL-only (no RPC), `seq` monotonic per instance.
- **Tick**: `Process.send_after(self(), :sample_tick, interval)` with `interval = Application.get_env(:evo_git, :system_sample_interval_ms, 3000)` read ONCE at init (tests raise it and drive `tick/0` or a raw `:sample_tick`), rescheduled BEFORE sampling so a slow step never breaks cadence.
- **Capacity + a 10-tick config cache**: `llm_capacity` = Σ per-profile `concurrency` and `tool_capacity` = `max_tool_concurrency`, from a direct BOUNDED `:get_config` call (2s, seam `:system_sampler_config_fun`) — deliberately NOT `RemoteAPI.get_config/0` (implicit 5000 ms) and NOT `Config.resolve/0` (re-reads disk, misses runtime overrides); cached as `config_cache: {totals, tick}`, refreshed on the `rem(tick, 10) != 1` rule (tick 1 always loads; unloaded refetches every tick until one attempt succeeds).
- **Degradation**: both scheduler reads go through `safe_scheduler_call/1` (explicit 2s bound < the 3s cadence + `catch :exit` for call timeout, the whereis→call `:noproc` race and a mid-call crash — the module's single justified try/catch); a config-refresh failure KEEPS the last cached totals and an `llm_slots` failure broadcasts `%{}`, so the 13-key shape always ships, with rate-limited `Logger.warning`s and automatic recovery. With `scheduler_alive?/0` false the sample carries zero counts/capacities + `llm_slots: %{}` + `scheduler_alive: false`; zero capacities are NEVER cached (that would suppress the refresh for 10 ticks).
- **Ring buffer**: last 60 samples; `get_recent_samples/0` → `{:ok, samples}` | `{:error, :not_found}` (guarded by `Process.whereis(__MODULE__)`); RPC `RemoteAPI.get_recent_system_samples/0` → `{:error, :sampler_down}` when not running, `RemoteNode.get_recent_system_samples/1` local/remote — all three shapes verbatim.

## Peak/Off-Peak Diagnostics (a task stuck blocked after peak exit)

Scenario: `concurrency: 5`, `peak_concurrency: 0` and peak windows — a task launched in-window blocks (0 slots → enqueued, `:blocked`) and stays blocked afterwards. Read these lines in order to separate *engine never woke* / *woke but didn't apply* / *applied but waiter never granted*:

1. `PeakHourEngine: wakeup reason=… now=… utc_now=… scheduler_up=…` (info, every check; `reason` = `:boot | :timer | :broadcast | :manual`) — no post-window `:timer` wakeup ⇒ the engine never woke.
2. `PeakHourEngine: decision=applying|unchanged effective=… current=…` — `unchanged` with the post-window map already equal to `current`, or `applying` with `effective=%{"m" => 0}` ⇒ it still believes it is in peak (clock/window/timezone bug).
3. `PeakHourEngine: next wakeup in <ms>ms … transitions=[{id, tz, wall_transition}]` — per-profile next transitions ("tomorrow instead of today" shows here); the 6h safety net is flagged when none was computable.
4. `AgentScheduler: model_concurrency updated — old=… new=… skip_floor=… default_llm_max_concurrency=…` — POST-application map; `old == new` after the window ⇒ it never applied.
5. `AgentScheduler: LLM slot grant sweep (resume) — model=… capacity=… waiting_before=… granted=… waiting_after=…` (info on meaningful events, debug on empty no-ops) — `capacity=N granted=0 waiting_after>0` ⇒ applied but the waiter was never granted.
6. `PeakHourEngine: starting — watched profiles: …` (info, `init/1`) — boot summary (id, concurrency, peak_concurrency, peak_hours, timezone).

Debug (`slots.ex`): `LLM slot request ENQUEUED — agent=… model=… capacity=0 (peak pause)`, `granted LLM slot — agent=… model=…`, `purged N LLM waiter(s) for model …`; the info line `PeakHourEngine: scheduling 6h safety-net wakeup` marks the no-profiles / scheduler-down path. Logging only — no behavior, timing, floor or fixed-point change; `peak_hour_engine_test.exs` pins the fixed-point invariant (no "applied model concurrency" log on a no-op re-check). Detail: `./agent_scheduler/`.
