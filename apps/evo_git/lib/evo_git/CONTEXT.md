# EvoGit Core Library — `lib/evo_git/`

## Intent
Core source of `:evo_git`: the Agent system (LLM tool loops), AgentScheduler (scheduling, ETS, slots; worktrees owned by `AgentScheduler.WorktreeManager`), core types (ContextNode, PhyloGraphNode, ForeignRepo), the Git adapter and the runtime phases (Genesis, Evolution, repo-less Reflect).
Multi-repo: foreign repos from `genesis.toml` or task opts let subagents spawn into isolated worktrees.
This file is the module index plus cross-cutting contracts; each section names the child CONTEXT.md owning its detail.

### SSH Remote (RemoteBootstrap / RemoteConnection)

`RemoteConnection` is one deliberately long cohesive GenServer (staging, daemon lifecycle over the release CLI, connect worker, ports) — do NOT split it; the daemon lifecycle (systemd scope/unit, launchd plist, setsid fallback, readiness) lives ENTIRELY in the release's `bin/genesis` CLI — no Elixir module builds a `systemctl`/`systemd-run`/`launchctl` command.
`RemoteBootstrap` (pure): `parse_uname/2`, `parse_platform/1`, `daemon_os/1`, `asset_name/1` (`genesis_server_<platform>.tar.xz`), `download_url/1`, `cache_path/2`, `sh_wrap/1`, `nixos_detect_command/0`, `nixos_patch_script/1`; extraction `tar -xJf`.
Stages: `:probing_platform | :downloading | :downloading_locally | :stopping_daemon | :uploading | :extracting | :setting_permissions | :copying_config | :generating_cookie | :patching_binaries | :starting_daemon`.
Test-pinned errors (each carries the trimmed output TAIL): `{:probe_failed, {:exit_status, n, tail} | :timeout | {:unexpected_output, out}}`, `:unsupported_platform`, `{:download_failed, {:exit_status, n, tail} | :timeout | {:local, detail} | {:local_scp, detail}}`, `{:scp_failed, n, tail} | {:scp_failed, :timeout}`, `{:staging_failed, n, tail} | {:staging_failed, :timeout}`, `{:daemon_status_failed, n, tail} | :daemon_status_timeout`, `{:daemon_launch_failed, n, tail} | {:daemon_launch_failed, :timeout}`, `{:daemon_running, details}`, `{:daemon_identity_mismatch, details}`; `format_reason/1` (total) renders any as one sentence; `error_state/3` sets `last_error` + logs once. Timeouts: bootstrap 900s, download 300s, daemon start 120s.
Source priority: `local_binary_path` exists → `scp`; set-but-missing → warning + download; absent → remote `curl -fL`, then `wget -O`, then local curl + `scp`. A pre-flight resolves the daemon OS (target `platform` preset → NO ssh probe, else ONE `uname -s && uname -m`) and reads `remote status` BEFORE staging.
- **Toggle = the release CLI** (`genesis-remote-<target_id>` is an identity, not a process): launcher `<remote_path>/bin/genesis_server` (default `/tmp/genesis_server`); `remote status --unit <unit>` exits 0 with `running node=<node> dist_port=<port>` (`@daemon_status_re`), 1 with `stopped`; `remote start --node <node> --cookie <cookie> --dist-port <port> --unit <unit> --wait <N>` (ONE non-retried call); `remote stop --unit <unit>` detaches distribution, keeps HTTP. The CLI owns the scope (`--user` non-root, SYSTEM `--collect` for `root`).
- **ARGV, never spawn strings**: `run_ssh_command/4` = `{:spawn_executable, …}` + `{:args, [target, remote_cmd]}`; remote commands are `sh_wrap/1`-wrapped `<interp> -c '<script>'`, the only form parsing in fish, nushell, tcsh, zsh, bash and POSIX shells.
- **Remote commands are POSIX sh and single-quote-free**: no `[[`, arrays, `local`, `source`, `type -t`, `pushd`. Interpreter = per-call app env `:remote_shell` (default `/bin/sh`).
- **Never kill a running daemon without permission**: `:on_running` ∈ `:refuse` (default → `{:daemon_running, details}`, nothing staged or killed) | `:restart` (`:stopping_daemon` + CLI stop, failure non-fatal). Race net = the reported `node=` (EXPECTED short-circuits to `:ok`, else `{:daemon_identity_mismatch, details}`). Node name fixed at ENABLE time, cookie per MACHINE.
- **Staging is ONE remote command**: `mkdir -p "<parent>" && tar -xJf "<remote_tarball>" -C "<parent>" && <move> && { test -x "<launcher>" || chmod +x "<launcher>"; } && test -x "<launcher>"`, with `<parent>` = `dirname(remote_path)` and `<move>` = `rm -rf "<remote_path>" && mv "<parent>/genesis_server" "<remote_path>" && ` when the tarball's tree is not already there; broadcasts `:extracting` then `:setting_permissions`.
- **Bounded transport retry**: `run_ssh_command_retry/4` retries ssh exit `255` once (`:remote_ssh_retry_backoff_ms`, 400, or `backoff_ms:`), only for IDEMPOTENT commands (`mkdir`, `test -f`, probes, `remote status`, `remote stop`) — never `remote start`, `scp`, downloads, the NixOS patch script, or a `:timeout`.
- `:copying_config` NEVER overwrites an existing remote config (`test -f` probe → skip scp) and uploads only on a POSITIVE "no" (`remote_file_present?/2` three-state); the dir is `$HOME`-rooted (Darwin `Library/Application Support/genesis`, else `.config/genesis`) and DOUBLE-quoted; scp keeps its `~` form (Known Issues); NixOS adds `:patching_binaries` (GC-rooted at `<release>/.nixos-patch`) for a NON-running daemon.
- `Distribution.ensure_epmd_module/0` runs on both connect paths; BOOT does NOT set it. Distribution is off by default, boot-enabled only with `[node] enabled = true`, never in test (`@mix_env != :test` at the CALL SITE) — tests use `enable_for_remote/1`.
**Connect** is non-blocking: `connect/1` replies `{:ok, :connecting}`/`{:ok, :connected}` (5s) while the I/O (`find_free_port`, ssh spawn, `wait_for_tunnel/4`, `EpmdDist.register_target/2`, `Node.connect/1`) runs in a monitored worker handing the tunnel `Port` over BEFORE reporting `{:connect_result, pid, {:ok, %{port:, local_port:, node_name:}}} | {:connect_result, pid, {:error, message}}`. Broadcasts `{:remote_connection_status, target.id, status_map}` on `"remote_connections"` — NO trailing node element (documented exception): `:connecting`, `:connected`, `:error` (`last_error` via the single `fail_connect/2`), `:disconnected`. ssh carries `-o ConnectTimeout=8`; clock seam `:remote_tunnel_poll_interval_ms` (100 ms).
**Tunnel invariant**: `Node.connect/1` must NOT run before the forwarded port accepts TCP (else `{:node_connect_failed, …}` with NO remote-side log); `wait_for_tunnel/4` polls 10s and fails fast when the ssh Port dies. Known causes: a stale daemon (`{:daemon_identity_mismatch, details}` → `<launcher> remote stop --unit <unit>`, then a restart bootstrap), `dist_port` ≠ 9000, or a boot-distributed node using `erl_epmd` (→ `:noport`).

### SQLite Store — Ecto Persistence Layer

`Store` is a GenServer facade over pure `Store.Operations.*` (repo-pid-first via `RepoScope.with_repo/2`) against its own UNNAMED dynamic `EvoGit.Repo` (pool from `Boot.default_pool_size/0`) with WAL + `default_transaction_mode: :immediate` + `busy_timeout: 30_000`.
`Store.Boot.start_dynamic/2` runs the TEN `priv/repo/migrations/` migrations (`000001`–`000009`, `000011` guarded `vct_mounts` rebuild adding nullable `path` + `members`/`description`; `000010` retired, never reused) on a temporary single connection, THEN opens the pool.
Every JSON column is plain UTF-8 TEXT (`Store.Codec` the single wire oracle); `PRAGMA optimize` per boot + hourly; `mix store.maintenance [--vacuum]` on demand.
Reads fan out to 6 WAL readers and EVERY read runs on `offload/5` (25s deadline) degrading to its empty shape, so a slow read cannot kill `Store`/`TaskRegistry` (sync calls `:exit`-guarded by `StoreGuard`); writes serialize through `Store.Writer` with the disk-full choke point `Errors.disk_full_exception?/1` → `{:error, :disk_full}`. Detail: `./store/CONTEXT.md`.

## Context Tree (`EvoGit.Core.ContextNode`) & VCT metadata

`%ContextNode{}` carries exactly `path` (in-repo relative `"./…"`, byte-identical), `repo`, `repo_id` (`"primary"` or a foreign id) and `vct_path`.
`vct_path` = canonical VCT URL (`vct_path_for/2` per `load/2,3`; ONE batched `vct_paths_for/2` in `hierarchy_nodes/2,3`) or `nil` when unmounted/no server; INTERNAL metadata only — no prompt path, tool argument or CONTEXT.md label derives from it; `vct_path` and a VCT "point" are the same value.
`build_context/2` prepends the GLOBAL context as `global/CONTEXT.md` ahead of in-repo stages; an absent/blank/front-matter-only stage is SKIPPED, and when nothing renders the result is the location block ALONE with no `# Context Tree` header. Detail: `./core/CONTEXT.md` + `./vct/CONTEXT.md`.

## Review / RemoteNode Return-Shape Contract

`RemoteNode` review wrappers return the **verbatim** `Review` value (local → `RemoteAPI`, remote → `:erpc` via `call_remote/4`); the only added shape is `{:error, {kind, reason}}`. Arity = Review + 1 (leading `node`), timing out via `rpc_timeout/0` (`:remote_rpc_timeout`, 30_000, read at CALL time).
**`defnode`**: `defnode EvoGit.AgentScheduler.RemoteAPI.fun(args)` generates the local/remote pair ONLY when the remote branch is exactly `{:ok, r} -> r; {:error, e} -> {:error, e}`; fallbacks (`[]`/`%{}`/`nil`/`false`, boolean guards, nested-error UNWRAPPING) stay hand-written; review/task wrappers are all `defnode`-generated and take an explicit `repo_path`. A node's own `{:error, reason}` is NEVER nested inside `{:ok, _}`; boolean predicates (`paused?/1`, `dir?/2`, `file_exists?/1`, `branch_exists?/3`) are TOTAL `boolean()`; `ls/2` propagates the RPC reason.

- **Structs**: `%Review.FileInfo{}` — `:path`, `:status` (`"added" | "deleted" | "modified"`), `:additions`/`:deletions`, `:diff`, `:language`, `full_new_content: nil`, `full_old_content: nil` (callers use `get_file_content/4`). `%Review.CommitInfo{}` — `:sha`, `:short_sha`, `:message`, `:author_name`, `:author_email`, `:date` (`%DateTime{}` from `%aI`, raw String on parse failure).
- **Reads**: `load_review_metadata/2`, `load_review_metadata_from_shas/3`, `load_commit_files/2` (vs `commit_sha~1`) → `{:ok, %{commit_sha, base_sha, diff_stat, diff: nil, files: [%FileInfo{}], changed_files_count, total_additions, total_deletions}}` | `{:error, {tag, output}}`; `load_review_data/2` is the heavy variant (NO `evo_dash` caller). `load_file_diff/4,5` / `load_commit_file_diff/3` → `{:ok, diff}` (`:context` int | `:all` → `-U999999` | nil = 3 lines); `get_file_content/3` → `{:ok, content}`; `list_commits/2` / `list_commits_from_shas/3` → ALWAYS `{:ok, [%CommitInfo{}]}` (`[]` on git errors).
- **Commit graph** (`CommitGraph.for_ranges/3` → `list_commit_graph/3` → `RemoteNode.list_commit_graph/4`): ALWAYS `{:ok, %{commits: [commit], refs: %{sha => [ref_name]}}}`; each `commit` is an atom-keyed MAP with exactly `:sha, :short_sha, :message, :author_name, :author_email, :date` and `:parents` (full SHAs, `[]` for a root).
- **Task-scoped graph** (`TaskCommitGraph.for_task/4` → `list_task_commit_graph/5`: node + `task_id` + `repo_path` + `live_tips` + `opts`): tips from `commit_sha`, `branch_name` and every `result["repos"][repo_id]["commit_sha"|"branch_name"]`; `resolve/1` is total (`%{base_sha: nil, tips: [], project_path: nil}`). Base per `repo_path`, first non-blank: `opts[:base_sha]` → repo-aware task base (`refs.base_sha` when `repo_path == refs.project_path`, else the matching `opts[:foreign_repos]` entry) → `Git.merge_base(repo_path, "HEAD", ref)` → `nil`. Result = the 2-key shape + `truncated: boolean`.
- **Mutating ops**: `merge_branch/2,3` → `{:ok, merged_sha}` | `{:conflict, details}` | `{:error, {code, output}}` | `{:error, {:switch_back_failed, reason}}`; `reject_branch/2` → `:ok` | `{:error, {code, output}}`; these and `check_merge/3` return `{:error, :no_branch}` for a nil OR blank ref via one `valid_branch_name?/1` (a no-change multi-repo repo carries `branch_name: nil`). `create_github_pr/4` → `{pr_url, pr_title}` | `{nil, nil}`; `list_branches/1` → `{:ok, [names]}`; `branch_exists?/2` → boolean.
- **`check_merge/3`**: `{:ok, :clean}` (identical SHAs) | `{:ok, {:conflict, files}}` (path strings; 40-hex OIDs dropped) | `{:error, {:merge_failed, output}}` | `{:error, {code, output}}` / `{:error, {:conflict, output}}` (rev_parse) | `{:error, :no_branch}`; non-mutating `git merge-tree --write-tree --name-only --no-messages`.
- **`set_review_status`/`set_review_metadata` live in `TaskRegistry`, NOT `Review`** — casts replying `:ok` immediately (`set_review_status/3` → `RemoteAPI.set_review_status/2` → `TaskRegistry.set_review_status/2`; `set_review_metadata/4` → …/`set_review_metadata/3`). **Review status is TASK-LEVEL only — no per-repo state**: `tasks.review_status` plus `tasks.base_sha`/`tasks.commit_sha` via `Store.update_task_columns/3` behind `Store.get_task_status/2` (missing row = silent `:ok` no-op), each broadcasting `{:task_updated, task_id, nil, node()}`. Codec whitelist: `:open, :merged, :rejected, :continued, :ignored, :no_changes`.
- **Task ops**: `RemoteNode.start_task/3` → `RemoteAPI.start_task/2` → `TaskRegistry.start_task/2` → `{:ok, %TaskInfo{}}` (19 fields incl. in-memory-only `ref`) | `{:error, :cancelled}`; `get_task/2` → bare `%TaskInfo{} | nil`. `custom_tools_status/1` → `%{ok: [%{name, file, module, read_only?: boolean}], errors: [%{file, reason}]}` verbatim; remote failure → `{:error, {kind, reason}}`.

## Known Issues

- Background launches lose the caller's per-task scratch dir across the registry boundary: `normalize_start_spec/1` keeps command/cwd/repo-root/label/owner/identities only and the launch runs `scratch_dir/0` in the singleton registry where `TaskTmpdir.current/0` is unset, so output resolves against the legacy system tmpdir.
- Systemd slice ownership is OS-user-wide: `SandboxSlice` hardcodes `evogit.slice`, and init cleanup and shutdown stop that whole slice, so instances under one user share budgets and cleanup boundaries.
- `Sandbox.capabilities/0` reports nominal capabilities without consulting `enabled?/0`, while auto-selection checks executable availability, not successful isolation.
- **scp of a remote config path containing SPACES is unhandled**: `:copying_config` creates/probes the dir with `$HOME`-rooted double-quoted paths, but the scp destination is rewritten to the `~` form by `scp_remote_path/1` (SFTP-speaking scp re-parses it), so uploading into `~/Library/Application Support/genesis` depends on scp's protocol (sftp verbatim works; legacy scp word-splits); failures stay best-effort.
- **Process/thread exhaustion in containers breaks git forks (EAGAIN)**: in rootless podman per-UID `RLIMIT_NPROC` spans container + host, so `fork()` fails ("cannot fork() ... Resource temporarily unavailable") and agents are lost to crash-retry; the host-limit prevention list is in root `../CONTEXT.md` § Known Issues.

## Windows-Only Runtime Hazards (audit index)

Latently Windows-broken code (the Windows branch is unreachable on Linux/macOS dev+CI, `Platform.windows?()` gates) — each item is a raise/degradation, not a compile error.

- **`Port.open` `{:env, ...}` requires CHARLISTS** while `System.cmd/3` normalizes binaries — the ONE raw-port env site is `Sandbox.None`'s Windows clause.
- **`Port.info(port, :os_pid)` returns `{:os_pid, pid}` and `Port.close/1` RAISES on a closed port** — `Sandbox.Helpers.wait_for_os_pid/2` unwraps and timeouts close via idempotent `Helpers.close_port/1`, so `taskkill /T /F` and bwrap's group kill fire.
- **Tool raises are CONTAINED**: `ToolRuntime.Executor.execute_tool_with_timeout/4` spawns a linked `Task.async` and `execute_tool_task/4` has its own `try/rescue/catch`, so a raising tool becomes `Error: Tool execution crashed: …`; only `:normal`/`:shutdown`/`:kill`/`{:shutdown, _}` exits re-raise (a `nil` yield is the timeout arm).
- **`GitEnv` exports `GIT_EDITOR` UNQUOTED** (`derive_windows_true_exe/0`) — git hands it to `sh -c`, so `C:\Program Files\…` splits and editor-opening git ops abort (`git_env.ex`).
- **`RemoteConnection.run_cmd/2` spawn strings interpolate LOCAL paths unquoted** (`curl -fL -o #{cache_file} #{url}`, `scp #{local_path} …`) — one command line re-parsed by the child, so a spaced `AppData` path splits; those sites pass no `:hide`.
- **`SystemCheck.check_tool/1`** passes `Executable.resolve/1`'s output to `System.cmd/3`, so a missing tool raises `ErlangError :enoent` instead of "unavailable".
- **`Skills.Executor`'s Windows branch resolves bash only via `System.find_executable("bash")`** — bundled MinGit ships `sh`, not `bash.exe`, so bash skills degrade to the "install Git for Windows" error.

## Tool permits & background-job capacity

## ReqLLM Finch Pool (`EvoGit.ReqLLMPool`)

**API**: `desired_count(total)` → `max(total + 2, 8)` (single source of truth; `config/runtime.exs` delegates); `error_target_count(total)` → `max(ceil(total * 1.5), 8)`; `effective_concurrency(map, default)` → `max(sum of values, default)`; `reconcile/1,2`; `bump_for_excess_queuing/2,3`; `excess_queuing_error?/1`.
**Grow-only (MANDATORY)**: `Finch.set_pool_count/3` shrinks by terminating pools (killing in-flight streams), so it applies `max(current, desired)` per origin and never lowers (`{:error, :not_found}` is a graceful no-op). **`start_pool_metrics?: true` is REQUIRED**: pools materialize LAZILY, and `Finch.get_pool_status(finch, :default)` enumerates them only with the flag — otherwise reconciliation is a SILENT no-op; `config/runtime.exs` uses the full `finch:` override form with the flag plus `stream_pool_timeout` / RoundRobin `stream_pool_strategy` and `size: 2` ⇒ per-origin `count × 2` HTTP/1 streams.
**Per-origin sizing**: identity is `{scheme, host, port, tag}` (paths excluded), so profiles sharing a host share ONE pool; the SUM formula is the sufficient bound, `+2` covering the non-slot-gated `system_check` and `pull_request` calls.
**Triggers**: (1) the success path of `handle_call({:update_config, opts}, …)` (covering `RemoteAPI.reload_config`, `save_user_config`, ConfigIO; the `"llm_model cannot be nil"` error path never reconciles); (2) excess queuing — `Agent.LLMPrompting.run_llm_attempt/4` bumps inside `with_llm_slot/2` when `excess_queuing_error?/1` (the bump IS the fix). **Tests**: `test/evo_git/req_llm_pool_test.exs` + an `agent_scheduler_test.exs` smoke test (`model_concurrency` keys are STRINGS).

## SystemSampler — System Topic Sampling (`EvoGit.SystemSampler`)

Supervised GenServer sampling every 3s and broadcasting on `"system"`; the 14 keys plus the `llm_slots` / `llm_pools` payload shapes are pinned in the PubSub Event Contract at `../CONTEXT.md`.
`llm_slots` = `AgentScheduler.get_llm_slot_status/0` (`%{}` when the scheduler is down or the bounded call fails); `llm_used`/`llm_waiting` and both tool keys stay `:running`/`:blocked` proxies counted from local `:evogit_sched_meta` (guarded `:ets.whereis`); sampling is LOCAL-only, `seq` monotonic per instance.
Tick: `Process.send_after(self(), :sample_tick, interval)`, `interval = Application.get_env(:evo_git, :system_sample_interval_ms, 3000)` read ONCE at init (tests raise it and drive `tick/0`), rescheduled BEFORE sampling.
Capacity and `llm_pools` come from a BOUNDED `:get_config` call (2s, seam `:system_sampler_config_fun`) — deliberately NOT `RemoteAPI.get_config/0` and NOT `Config.resolve/0`, whose RAM snapshot misses runtime overrides — cached as `config_cache: {totals, pools, tick}` and refreshed at `rem(tick, 10) == 1` (tick 1 always loads; an unloaded cache refetches every tick until one attempt succeeds); zero capacities are NEVER cached.
Degradation: scheduler reads go through `safe_scheduler_call/1` (2s bound < the 3s cadence + `catch :exit` — the module's single justified try/catch), a config-refresh failure KEEPS the last totals + pools, and an `llm_slots` failure broadcasts `%{}` with rate-limited warnings; with `scheduler_alive?/0` false the sample carries zero counts/capacities + empty slots/pools.
Ring buffer: last 60 samples; `get_recent_samples/0` → `{:ok, samples}` | `{:error, :not_found}`; `RemoteAPI.get_recent_system_samples/0` → `{:error, :sampler_down}`.

## Runtime distribution control

`Distribution.enable_runtime/3` pins `:kernel` `inet_dist_listen_min = inet_dist_listen_max = dist_port` UNCONDITIONALLY (before any start attempt) and `epmd_module` to `EvoGit.EpmdDist`, then starts via `start_net_kernel/1`; idempotent for the SAME node name (cookie re-applied), it stops the current distribution first for a DIFFERENT name, validates the `name@host` shape BEFORE atom conversion, and returns the ACTUAL `to_string(node())` through ONE rescue/catch boundary. `disable_runtime/0` stops it when active and leaves the pinned port; `active/0` reports `%{enabled:, node:, dist_port:}`; `enable_for_remote/1` is deliberately NOT delegated — the local dashboard path keeps its fixed `genesis@127.0.0.1` identity, the 9100-9200 listen RANGE and the `[node] cookie`.
`DaemonControl` (supervised in every env EXCEPT test) is the file protocol the release CLI drives: request `<data_dir>/remote/control.request` (`ACTION=enable|disable`, `NODE`, `COOKIE`, `DIST_PORT`, `SEQ`) + SIGHUP; answer `dist.env` = the ACTUAL state (`GENESIS_DIST_ENABLED`, `GENESIS_NODE`, `GENESIS_DIST_PORT` (`unknown` when unset), `GENESIS_CONTROL_SEQ`, `GENESIS_CONTROL_RESULT` (`ok`/`error`), `GENESIS_CONTROL_MESSAGE`). Both files are written atomically (tmp + `File.rename/2`, mode 0600), the result BEFORE the request is deleted, and `dist.env` is NEVER deleted.
`desired.env` records intent only after a SUCCESSFUL action (`ENABLED=1` + `NODE`/`COOKIE`/`DIST_PORT`, or `ENABLED=0`) and is untouched on failure; `init/1` re-adopts an `ENABLED=1` intent best-effort (warning, never raise) then publishes the ACTUAL state (covering a `RELEASE_DISTRIBUTION=name` boot and a plain boot `0`), and any raise/exit is caught by ONE boundary writing the error `dist.env`.
The SIGHUP hook is Unix-only (`Platform.windows?/0`; `EVOGIT_NO_SIGNAL_HOOK=1` skips it): `:os.set_signal(:sighup, :handle)` + `:gen_event.add_handler(:erl_signal_server, EvoGit.DaemonControl.SignalHandler, [])`, an already-present handler normalizing to `:ok`; the handler only calls `reload/1`. No timers, no polling: `reload/1` is a cast, `sync/1` a `@doc false` test barrier, the pure core (`handle_control_request/2`, `publish_state/2`) runs without a process, and call-time default-inert seams `:daemon_control_dist` / `:daemon_control_signal_install` plus `init/1` opts (winning over `dir:`, `dist:`, `signal_install:`, `name:`) keep `daemon_control_test.exs` `async: true`.
