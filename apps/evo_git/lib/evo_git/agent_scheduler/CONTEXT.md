# Agent Scheduler Data Structures and Helper Modules

## Intent

Structs + helpers behind the `EvoGit.AgentScheduler` GenServer: `%AgentState{}` rows in ETS `:evogit_agent_state` (shared with agent processes), `%SchedMeta{}` rows in `:evogit_sched_meta` (scheduler-exclusive).
Both tables are created/owned by `EvoGit.Application`, never the scheduler — no heir, they must outlive a scheduler crash (which kills `EvoGit.TaskSupervisor` + all agent Tasks via the `:one_for_all` `AgentGroupSupervisor`; `%State{}` resets, tables keep stale rows).
Helpers are pure over `State.t()` except the GenServers (`WorktreeManager`, `PubSub.Throttle`).

## Routing Table

Leaf directory: `state.ex`, `agent_state.ex`, `sched_meta.ex`, `slots.ex`, `store.ex`, `worktrees.ex`, `worktree_manager.ex`, `worktree_retry.ex`, `foreign_worktree.ex`, `dispatch.ex`, `subagents.ex`, `lifecycle.ex`, `pubsub.ex`, `throttle.ex`, `remote_api.ex`; hub `../agent_scheduler.ex`.

## Throttled PubSub

- The `:agent_registered` `summary` has EXACTLY `status, depth, parent_id, task_id, task_number, objective` — NOT `message_count`/`agent_module` (only `list_agents/0` has those); `message_count` arrives via `:agent_updated` deltas.

## Agent identity: parent_id & depth (root ⇔ parent_id nil ⇔ depth 0)

- `register_agent/7` is the only writer: ROOT (`handle_call({:run_agent, spec}, ...)` → nil/0) and NESTED (`parent_id`, `parent.depth + 1`). Depth is never derived by walking a parent chain.
- Depth reaches the agent as `dispatch_ctx` `depth: meta.depth` → Runner `Keyword.fetch!(ctx, :depth)` → `LoopState.depth` + `Process.put(:evogit_agent_depth, depth)`; crash-retry resets preserve identity (`phylo_node: nil, context: nil`). The writable-foreign-repo root check is `parent_depth == 0` (threaded through `validate_single_subagent/5` → `validate_spatial_contract_for_spec/4`; the `/3` form hardcodes `0`).
- Root-only custom-agent `max_turns`: `if is_nil(parent_id)`; subagents use `state.max_turns`.

## Task Spawn & Starting-Commit Flow (run_agent)

`spec.phylo_node.current_commit` arrives pre-resolved (`%PhyloGraphNode{repo, base_commit, current_commit}`).
Upstream `Runtime.Helpers.resolve_starting_commit/2`: nil → `PhyloGraphNode.current_head/1` (unborn HEAD = structured error), a ref → `Git.rev_parse(repo_path, ref <> "^{commit}")`; failure → `{:error, {:invalid_starting_commit, ref, repo_path, git_output}}`. Sources: CLI `--starting-commit`; resume (`commit_sha`); Genesis Mode B (`architect_output.commit_sha || base_sha`).

`run_agent/2` (both clauses reply `{:error, :llm_not_configured}`): `task_id` from `spec.opts[:task_id]` (else random hex) → refuse `{:error, :cancelled}` while in the `:evogit_cancelling_tasks` marker → guarded `reset_task_archives/1` (`EvoGit.Store.delete_task_archives/1`) → `resolve_agent_repo_root/2` + `next_task_number/1` → `register_agent/7` (`phylo_node: nil`, `task_local_id` from 1) → paused ? queue : `try_dispatch/2`.
`try_dispatch/2` computes `worktree_path = <repo_root>/.genesis/workers/worker_T#{task_number}_A#{task_local_id}`, stores it in SchedMeta BEFORE spawning (so `cancel_agent` finds it), spawns `Task.Supervisor.async_nolink(EvoGit.TaskSupervisor, spec.agent_module, :run, [spec.objective, dispatch_ctx])`, updates `ref_to_agent`. No git/worktree work here.
`setup_dispatch_context/1` requests the worktree; `create_worktree/6` checks out `current_commit` via `EvoGit.Adapters.CowWorktree.create_worktree/5` (fallback `Git.add_worktree`), then `assign_and_prepare_worktree/3` writes the worktree-bound phylo_node (`repo: wt`) into ETS — the nil → live transition; the agent advances it via `ToolDispatch.sync_current_commit_after_tools/1` → `AgentScheduler.update_phylo_node/2`.
Subagent phylo nodes (`build_subagent_phylo_node/6`): explicit `commit_id` validated by `Git.rev_parse`, else the parent's `current_commit`; cross-repo uses tracked `foreign_repo_commits` or foreign HEAD.
**Repo root resolution**: per-agent ETS `AgentState.repo_root` first, then `Process.get(:genesis_repo_root)` (set in `try_dispatch/2`, `current_repo_root/0`) — no global `state.repo_root`; repo-init tracking lives in `WorktreeManager`, running = `map_size(state.ref_to_agent)`.

## Subagent Spawn Fan-Out Bounds & Deadlock Surface

- **Spawn is a blocking batch**: `spawn_sub_agents/2` is a `GenServer.call` with `timeout \\ :infinity`; the parent blocks until ALL subagents complete; the scheduler GenServer is NOT blocked.
- **Batch size UNBOUNDED**: one reduce over the subagent tool calls of ONE LLM response; `SubagentSchemas.schemas/1` has `path`/`objective`/`commit_id` only (no `maxItems`). Gates: `max_agent_depth`, `:path_ignored`, the spatial contract, one-writable-foreign-repo-per-batch, `{:error, :scheduler_paused}`, `:llm_not_configured`.
- **Registration is EAGER at accept** (`:pending` → `:running` + immediate spawn; `state.queue` exists only while paused) and the **worktree is created EAGERLY at child start** (`setup_dispatch_context/1` before `loop/1`), so a child HOLDS a worktree while blocked on an LLM slot; a WAITING parent keeps its live worktree too (reclaim `:DOWN`-only) and holds NO slot, so capping LIVE worktrees/agents with queueing can deadlock, whereas the implemented cap bounds CREATE-pipeline concurrency and cannot.
- **`max_depth`** — `[:scheduler, :max_agent_depth]`, `:pos_integer`, default `8`, `[min: 1]`; `validate_subagent_depth` → `{:error, :max_depth_exceeded}`; Runner `at_max_depth?/1`. Bounds DEPTH only.
- **Defensive ETS lookups**: `Store.get_sched_meta/1`/`get_agent_state/1` return `{:ok, x} | :error`, so four sites degrade when a parent is reaped mid-spawn — `spawn_validated_subagents/5` (replies `[{:error, :parent_recycled}]` per spec, bails BEFORE the `:waiting` mutation), `store_sub_result/3,4` (→ `:ok`), `maybe_resume_parent/2`, `dispatch_ready_parent/3` (still replies/resets meta, logs `"unknown"`). Covered by `subagents_test.exs` + `pubsub_test.exs`.

## Agent-facing submodule awareness (repo_notes)

`AgentSpec.repo_notes` carries the ALREADY-RENDERED git-submodules note, rendered ONCE at root spec build by `Runtime.Helpers.load_repo_notes/2` (`Git.ls_tree_gitlinks/2`; nil when none/fails) → `AgentState.repo_notes` → `LoopState.repo_notes` → `ContextBuilder.build_repo_notes_section/1`. Subagents inherit the rendered TEXT (no re-detection) — a foreign-repo subagent still carries the PRIMARY's note.

## Repo-Nil Tolerance & Repo-Less Agent Plumbing

The repo-less self-reflective agent (`EvoGit.Agents.SelfReflective`, `spec.opts[:repo_less] = true`) runs on this plumbing; nothing here runs git or creates worktrees for it.
**Nil-tolerant:** `phylo_node` defaults nil, written nil at registration + crash-retry reset (a transient nil is NORMAL); `repo_root` defaults nil, `resolve_agent_repo_root/2` returns nil for a foreign id missing from `spec.foreign_repos`; `get_agent_state/1` only drops `:context`; `commit_pending_in_worktree/0` short-circuits on `Process.get(:repo_less)`; skill loading guards `repo_root && is_binary(repo_root)`; `build_agent_summary/3` nil-guards via `safe_phylo_commit/2`/`safe_context_path/1`.
**Hard-dereferences (repo-less must guard/avoid):** `resolve_agent_repo_root/2`'s primary branch splits `spec.phylo_node.repo` on `"/.genesis/workers/"` (nil → FunctionClauseError); `do_try_dispatch`'s `Path.join([agent_repo_root, ".genesis/workers", ...])`; `maybe_init_repo/3` → `workers_dir/1`; `Runner.setup_dispatch_context/1` calls `create_worktree_for_agent/6` unconditionally and raises `"Failed to create worktree..."`; `assign_and_prepare_worktree/3` bare-matches `{:ok, meta}`/`{:ok, %AgentState{}}`.
**Repo-less specifics:** `resolve_agent_repo_root/2` resolves repo-less roots via the SHARED chain `EvoGit.SelfReflectiveSource.reference_path/0` (`:self_reflective_source_root` → `GENESIS_SOURCE_ROOT` → managed clone at `<data_dir>/genesis-source`), fallback `File.cwd!()`, else `"[system]"` (`EvoGit.Runtime.SelfReflective.source_root/0` delegates); `do_try_dispatch` appends `repo_less: true` + `repo_less_repo_path: <root>` (used as `:repo_path`; worktree creation SKIPPED). `dispatch_ctx` keys (all `Keyword.fetch!`'d): `[agent_id:, depth:, repo_root:, repo_id:, worktree_path:, retries:, spec:, meta:]`.

## Slot Management (Slots module)

Two independent pools of agent-ID `MapSet`s; capacity = `capacity - map_size(holders)` — leaks impossible, `release_agent_slots/2` removes the holder from both sets.

| Pool | State keys | Capacity | Backoff |
|---|---|---|---|
| LLM | `llm_holders`, `llm_waiting`, `llm_backoff_until`, `llm_last_granted` | **per-model** `model_concurrency[model_id]` (profile `concurrency`, default 3); fallback `default_llm_max_concurrency` (3) via `State.concurrency_for/2` | **per-model** on `:rate_limit` AND `:insufficient_balance` (HTTP 402) — caller duration (default 60 s, clamped to `@max_timer_ms`), self-rescheduling sweep; one model never blocks others |
| Tool | `tool_holders`, `tool_waiting` | `max_tool_concurrency` (default `EvoGit.Platform.cpu_threads/0`) | None |

`handle_request_llm_slot/3`, `handle_request_tool_slot/3`; `handle_release_llm_slot/2`, `handle_release_tool_slot/2` (`handle_cast`); `release_agent_slots/2` (`:DOWN`: both sets, queue purge, grant); `purge_agents_from_queues/2` (replies `{:error, :cancelled}`); `grant_pending_on_resume/1` (also at the END of every config update, so 0→N grants queued waiters). Sync ops return `{:reply, :ok, state, status_updates}`/`{:noreply, state, status_updates}`, async releases `{state, status_updates}`; `status_updates` = `{agent_id, :blocked | :running}` written to ETS SchedMeta.
`default_llm_max_concurrency` is a DEFAULT per-LLM concurrency, NOT a global cap: `State.concurrency_for/2` prefers `model_concurrency[model_id]`, else the default; the map is filled only at config-load time (`State.from_model_profiles/2` at `init/1`, the `:model_profiles` update branch, or `update_config(model_concurrency: map)`), legacy config yielding `model_concurrency["default"]`. **A runtime override is a FLOOR**: `State.apply_default_llm_concurrency_override/2` sets the default AND raises every entry to `max(c, N)` (explicit `0` stays `0`), while a profile concurrency above the default still wins.

### Slot-Pool Sizing & Concurrency (state.ex + slots.ex — do not regress)

- **Config updates preserve live LLM pools**: the `:model_profiles` branch merges existing `llm_holders`/`llm_waiting`/`llm_backoff_until`/`llm_last_granted` OVER the fresh `from_model_profiles/2` maps, then `prune_empty_pools/1`.
- **Stale-model pools are swept**: `State.all_model_ids/1` = UNION of the keys of `model_concurrency`, `llm_holders`, `llm_waiting`, `llm_backoff_until`, so absent/unknown ids are still swept by `grant_pending_llm_slots`, `release_agent_slots`'s LLM cleanup and `purge_llm_waiting_queues`.
- **LLM release scans all pools**: `handle_release_llm_slot/2` iterates `all_model_ids` (an ETS model lookup picks the wrong pool once the row is gone), removes the agent from every holder set, then grants.
- **`maybe_update_model_concurrency/2`** (engine path) replaces the map then re-applies the floor via `apply_default_llm_concurrency_override/2` — except explicit `0` entries (peak hard-pause sentinel), never floored up (the engine applies the same rule → fixed point holds). `handle_call({:update_config, opts}, ...)` → `reconcile_pool_after_update` reconciles the ReqLLM Finch pool.
- **`:sandbox_resources` changes (Linux) are FIRE-AND-FORGET** via `EvoGit.SandboxSlice.update_resources_async/1` (a synchronous `systemctl` update blocked every scheduler caller and crashed `SystemSampler` on its `:get_config` timeout).
- **0-capacity slots enqueue and block (peak hard pause)**: `concurrency_for/2` may return `0`; `handle_request_llm_slot/3` has no pre-check → stores `{agent_id, from, nil}` and replies `{:noreply, state, [{agent_id, :blocked}]}`; `grant_llm_from_queue/2` at 0 leaves the queue untouched; a 0→N transition grants automatically; in-flight holders are never evicted; `with_llm_slot/2` never raises.
- **Diagnostics (logging only)**: `model_concurrency updated — old=... new=... skip_floor=...` (pre-update vs post-floor); `LLM slot grant sweep (resume) — model=... capacity=... waiting_before=... granted=... waiting_after=...` (info when `granted > 0` or `capacity == 0 and waiting_before > 0`; `capacity=5 waiting_before=3 granted=0` = queued-waiter-never-granted). `handle_retry_llm_waiting/1` self-reschedules while any model sits in future backoff (max across `all_model_ids/1` + epsilon read at CALL time from `:llm_backoff_sweep_epsilon_ms`, fallback `@default_sweep_epsilon_ms` 1000 ms, in BOTH timer sites — shrinkable in tests).

### LLM-model resolution gotchas (scheduler state vs config file)

- **Init always produces non-empty `model_profiles`** — `Schema.model_profiles(config)`; `[]` → `[Schema.LLM.build_legacy_default_profile(config)]`. Init `llm_model` = first-profile `:model` when non-nil, else flat `config[:llm][:model]`; the boot warning "AgentScheduler: LLM model not configured" fires only when BOTH are nil/falsy.
- **Runtime `:model_profiles` updates have NO flat fallback**: `llm_model` comes from `Map.get(first_profile, :model)` only, so nil/absent silently sets `state.llm_model = nil` and the update is ACCEPTED (nil-rejection checks only an explicit `:llm_model => nil` OPTS key). Reload paths never push `:llm_model`.
- **Dispatch selection**: `effective_model_id/5` (`spec.model_id`/custom-agent `:model_id` → `spec.opts[:model_id_locked]` short-circuit → ModelSelector script → base) → `resolve_model_for_agent/2` (unknown id → warn + `List.first(profiles)`; nil id → first profile). Model string = `Map.get(profile, :model, state.llm_model)` — the default applies ONLY when the key is ABSENT.
- **Slot-side resolution reads ONLY `:evogit_agent_state`** (`:evogit_sched_meta` only by `Store.depth_of/1`): `Slots.resolve_model_id/2` → `Store.get_model_id/1`; absent row or nil/`""` id → `State.default_model_id/1` (`"default"` for `model_profiles: []`, else the FIRST profile id) — no separate default pool, no capacity bypass.
- **`get_llm_slot_status/0` is keyed by model-PROFILE-ID string**: `{id, %{used: holders, waiting: queue_len, capacity: concurrency_for}}` over `State.all_model_ids/1`; an idle model appears only if it is a `model_concurrency` key or has a non-empty pool/backoff entry.
- **`run_agent` rejection clauses**: (a) `%State{model_profiles: []}` — reachable only via `update_config(model_profiles: [])` (tests use this, `test/evo_git/runtime/evolution_test.exs`); (b) `llm_model: nil` with `model_profiles == nil` — effectively DEAD. Both reply `{:error, :llm_not_configured}`.
- **No file-watching**: config changes ONLY via `update_config/1` (dashboard save → reload_config; evo_dash ConfigIO; `PeakHourEngine`); `get_config` serves in-memory values while `Config.resolve()`/`config_status()` are file-fresh.

## Worktree Lifecycle (WorktreeManager + Worktrees)

**Fresh per agent run** — no pool, no reuse across retries.

1. **Lazy per-repo init** on the FIRST create for a repo: rm_rf `.genesis/workers` → `git worktree prune` → orphaned `evogit-agent-*` cleanup → mkdir_p (never from the scheduler). Gated on the **persistent marker** `:evogit_worktree_repos` (app-owned ETS, read via `:ets.whereis` — missing = "uninitialized"): **present** (manager-only restart) → wipe skipped, only `mkdir_p_retry/2`; **absent** (first request or genuine BEAM restart) → full wipe, then the marker is recorded. **PRIMARY-ONLY destructive steps** when `primary?` (from `spec.repo_id` via `EvoGit.Core.ForeignRepo.primary?/1`); foreign repos get only prune + mkdir_p + marker. `mkdir_p_retry` raises `File.Error` on exhaustion — safe because the marker is written before the first worktree exists.
2. **Request path**: `create_worktree_for_agent/6` (`:infinity`) offloads to a MONITORED Task (`run_create/6`) replying exactly once — result, or `{:error, reason}` when the create fun raises/throws/exits (`report_create_failure/3`) or the task dies silently (`create_monitors` `:DOWN` net, `handle_create_task_down/4`) — plus the `{:create_finished, agent_id}` permit-release cast.
3. **Create pipeline** (`prepare_new_worktree/5`): destroy leftover dir/branch (rm_rf failure escalates) → CoW create via `EvoGit.Adapters.CowWorktree.create_worktree` (fallback `EvoGit.Adapters.Git.add_worktree`, the uniform `{:ok, v} | {:error, {tag, output}}` adapter; failure → `{:error, {:worktree_create_failed, msg}}`) → `assign_and_prepare_worktree/3` → `run_init_script/3` (genesis.toml `[worktree]` script, primary only; env `SOURCE_REPO_PATH`/`SOURCE_WORKTREE_PATH`/`TARGET_WORKTREE_PATH`; Windows via `Platform.shell_args/1` → PowerShell `-EncodedCommand`, `EvoGit.Powershell`).
4. **Monitor-based reclaim**: `:DOWN` for ANY reason (including after a successful completion) → `destroy_worktree/3`: `File.rm_rf(worktree_path)` → only AFTER the dir is gone `Git.prune_worktrees(repo_root)` → `delete_branch_tolerant(repo_root, branch_name)`; rm_rf failure logs ERROR and skips prune + branch delete. A failed CREATE-path rm_rf returns `{:error, {:worktree_create_failed, msg}}` and also SKIPS prune — a dir surviving WITH its `.git` file + registration is safe, while a partially-removed dir that is pruned becomes a PLAIN unregistered dir (the leak precondition). Idempotent; `recycle_agent/2`, `cancel_agent/2` and permanent failure never delete worktrees; after a manager-only restart `rebuild_monitors/1` re-monitors live agents from `:evogit_sched_meta` + `:evogit_agent_state`, skipping missing/stale rows.

### Worktree Allocation & I/O Concurrency Model (creation admission-bounded; deletion serialized)

**Creation is admission-bounded**: `accept_request/8` registers each request `:queued` on the FIFO `admission_queue`; `admit_next/1` starts requests while `creating_count < max_concurrent_creation/0` (app env `:max_concurrent_worktree_creation`, default 4, read at ADMISSION time), flipping each to `:creating` and spawning an independent `Task.start`; a permit lasts one pipeline and is released by the `{:create_finished, agent_id}` cast (from `try/after`). Agent entries carry `status: :queued | :creating | :live`. **Caps CREATE-pipeline concurrency, NOT live worktrees/agents**; the rest is per-`agent_id` serialization plus synchronous deletion inside `handle_info({:DOWN, ...})`.

### WorktreeRetry — transient filesystem failure retries

Transient set: `:eacces`, `:eperm`, `:eexist`, `:enotempty`, `:ebusy`, `:again`, `:eintr`; `:enoent` deliberately absent — "not found" means the goal is met (`rm_rf_retry/2` → `{:ok, []}`). Retryable: 2-/3-tuple fs errors, git `{:error, {tag, output}}` and binary error shapes — EXCEPT repo-gone outputs (`repo_gone_output?/1`).
Delays: `delay_stream/1` precedence is an explicit `:delays` opt → the CALL-TIME app-env seam `Application.get_env(:evo_git, :worktree_retry_delays)` (test-only) → the production default `exponential_backoff(50, 2) |> cap(200) |> take(3)` = `[50, 100, 200]` (a leading `0` "first attempt now" delay is always prepended, so 4 attempts).

## Persistent Foreign-Repo Worktrees (ForeignWorktree)

`ForeignWorktree` owns the PERSISTENT worktree of every WRITABLE non-primary foreign repo at `<root>/.genesis/foreign_repos/<id>` (`ForeignRepo.worktree_path/1`) — a stable READ view of the latest committed state, addressable by absolute path (`ForeignRepo.resolve/2`, `ContextBuilder.build_foreign_repos_section/1`); it lives OUTSIDE `.genesis/workers/`, so the primary-only wipe and `destroy_worktree/3`/`destroy_leftovers/3` never touch it, the MAIN HEAD never moves, and it is NOT torn down at task end. A foreign agent's WRITE workspace remains its ephemeral worktree.
API: `start_commit/1` (`base_sha` else repo HEAD), `ensure/2` (idempotent create-or-reset; non-writable → no-op; create = `mkdir_p_retry` → `Git.add_worktree(root, wt, sha)` detached, no branch → prune + one retry; update = `Git.checkout(wt, sha)` with `Git.reset_hard/2` fallback), `ensure_all/1` (best-effort, never raises), `sync_from_agent/0`, `worktree_path/1`.

**Hooks**: `Runtime.Helpers.load_foreign_repos/2` calls `ensure_all/1` after validating (before any spawn); `Agent.Runner.run/3`'s `try/after` calls `sync_from_agent/0` right after `commit_pending_in_worktree/0` on EVERY exit path, advancing the agent's OWN repo worktree (id-matched via `Process.get(:evogit_repo_id)`) to `Process.get(:repo_path)`'s HEAD — no-op for primary/repo-less agents, last-writer-wins. NOT torn down at task end (reused/reset by the next task).

## Agent Dispatching (Dispatch module)

1. `register_agent/7` — IDs, task-local IDs, event-sink inheritance, writes both ETS tables.
2. `try_dispatch/2` — scheduling-only; a `with` guard bails cleanly when ETS entries are missing; stores the worktree path BEFORE spawning. CoW copies unchanged files from a source tree (parent's worktree for subagents, repo root for top-level) with `cp --reflink=auto --preserve=timestamps` (Linux) / `cp -cp` (macOS); `[:git, :cow_worktree_creation]` (`:auto` default).
3. `commit_pending_in_worktree/0`; 4. `resolve_agent_repo_root/2`; 5. `dispatch_queued_agents/1`; 6. `process_queue/1`.

## Subagent Management (Subagents module)

1. `spawn_validated_subagents/5` — validates all specs, registers valid ones, replies immediately if all are invalid; the parent commits pending changes BEFORE calling `spawn_sub_agents`.
2. `validate_single_subagent/5` → `validate_subagent_depth/3` (`{:error, :max_depth_exceeded}`), `validate_subagent_not_ignored/1`, `validate_spatial_contract_for_spec/4` + `validate_spawn_spatiality/4` (the `/3` form hardcodes parent depth 0). **Fan-out WIDTH is NOT code-limited** — the spawn gates are depth, `:path_ignored`, the spatial contract, one-writable-foreign-repo-per-batch, `{:error, :scheduler_paused}` and `:llm_not_configured`.
3. Cross-repo rule: `:read` always allowed at ANY depth; `:read_write` only into a repo whose TASK-LEVEL `spec.foreign_repos` entry (never the path alone) is `%{writable: true}` and only from a ROOT parent (`{:error, {:foreign_repo_read_only, msg}}` / `{:error, {:foreign_repo_write_not_root, msg}}`); same-repo spawns WITHIN a foreign repo (`spec.repo_id == parent repo_id`) are unrestricted; the 2nd+ accepted writable foreign spec in a batch → `{:error, {:foreign_repo_write_serialized, msg}}`.
4. `store_sub_result/3,4` — the 4th arg carries the COMPLETING CHILD's `%AgentSpec{}` (or nil) and gates foreign-commit recording via `writable_foreign_repo_agent?/1` (public, `false` for non-`%AgentSpec{}`, never raises); then `maybe_resume_parent/2`, `dispatch_ready_parent/3`, `build_ordered_results/2`.

## Agent Lifecycle (Lifecycle module)

1. `recycle_agent/2` — deletes both ETS entries on normal completion (no worktree I/O; a `case` guard tolerates an already-gone entry), invoked ONLY from the scheduler's agent-monitor `:DOWN` (`handle_agent_down/4`, `reason == :normal or meta.result_sent`), i.e. AFTER `handle_task_result` replied. `cancel_agent/2` is the other path: `Task.shutdown(meta.task_ref, :brutal_kill)` → manager `:DOWN` reclaim, replies to blocked callers, deletes ETS entries.
2. `handle_agent_crash/3` — crash-RETRY policy, ONLY from `handle_agent_down/4` when `reason != :normal AND meta.result_sent == false` (an abnormal exit AFTER delivery is a RECYCLE). `do_handle_agent_crash/4` logs `"Retry #{meta.retries}/#{state.agent_max_retries}"` BEFORE incrementing (first crash logs `Retry 0/3`), then either RETRIES (bump `retries`, `:pending`, `task_ref: nil`, reset `phylo_node`/`context`, re-dispatch via `try_dispatch/2`) or PERMANENTLY FAILS (subagent → `store_sub_result(parent_id, agent_id, {:error, :agent_max_retries_exceeded})` + `maybe_resume_parent/2`; root → `GenServer.reply(meta.from, {:error, :agent_max_retries_exceeded})`; both then `process_queue/1`). Neither deletes worktrees.
3. Limit `state.agent_max_retries` (default 3, `non_neg_integer` min 0 — `[:scheduler, :agent_max_retries]`); lifetime = `1 + agent_max_retries` attempts; the wait lives in the Runner (`setup_dispatch_context/1` runs `Process.sleep(30_000 * retries)` AFTER creating the fresh worktree).
4. Exit-shape contract: a RETURNED value (`{:error, {:llm_request_rejected, msg}}`, `{:error, :recovery_failed}`) arrives as `{ref, result}` BEFORE `:DOWN`; `handle_task_result/3` sets `result_sent: true` and replies `meta.from` VERBATIM for any non-`{:ok, %Result{}}` result — crash-retry applies ONLY to a RAISE before delivery. After `result_sent` it injects `SchedMeta.foreign_repo_commits` via `inject_foreign_repo_commits/2` (`Map.put`, NOT struct update — the field is added by the agent stream in parallel) BEFORE the parent/root split.

## Foreign-Repo Writable Spawn Gate & Per-Repo Commit Roll-up

Writable foreign repos (`EvoGit.Core.ForeignRepo.writable`, default `false`) let `:read_write` agents work in foreign repos.

- **Spawn gate order** (cross-repo `:read_write`): target writable (from `spec.foreign_repos`, never the path)? else `{:foreign_repo_read_only, msg}` → spawner ROOT (`parent.depth == 0`)? else `{:foreign_repo_write_not_root, msg}` → only accepted writable foreign spec in the batch? else `{:foreign_repo_write_serialized, msg}`.
- **Subtree roll-up is authority-gated** (`store_sub_result/3,4`): ONLY a child that is ITSELF a writable agent in its own foreign repo may advance `SchedMeta.foreign_repo_commits` — `repo_id` a binary `!= "primary"`, `agent_module.agent_type() == :read_write`, task-level `spec.foreign_repos` entry `writable: true`; it rolls up its result's subtree map child-wins via `Map.merge`, then records its OWN `commit_sha` via `Map.put`. A LOCAL/PRIMARY or READ-ONLY child (even a probe whose `commit_sha` is its starting commit) leaves the map EXACTLY as-is.
- **Injection + getter**: the `Map.put` happens BEFORE the parent/root split, so the ROOT's result carries what the runtime reads for the per-repo report; `AgentScheduler.get_foreign_repo_commits/1` returns the SPAWNING agent's OWN map (`%{}` when missing), consumed by `agent/subagent_processing.ex` to seed the next subagent phylo-node starts (`resolve_foreign_phylo_commit/4`, precedence task-level `base_sha` → tracked sha → foreign HEAD).

## Pending User-Message Queue (shape tolerance + the `Attachments.message/1` seam)

`AgentState.pending_user_messages` is the ONE external injection queue (drained by the Runner at the top of each turn). Two shapes: **legacy plain `String.t()`** stored/drained VERBATIM (byte-identical end-to-end; pinned by `lifecycle_test.exs`'s `String.contains?(&1, "being cancelled")` assertions) and the **canonical multimodal message** `%{text: String.t(), attachments: [map] | nil}`, where any atom-/string-keyed `%{text:, attachments:}` map is CANONICALIZED through **`EvoGit.Attachments.message/1`** before storing. `Attachments.validate_message!/1` enforces caps (`Attachments.validate/1`) and raises a descriptive `ArgumentError` — never swallowed, nothing queued. Attachments are base64 STRING maps only.
Write: `Store.append_pending_user_message/2` (guard `is_binary or is_map`; private `canonical_pending_message/1`); read: `Store.drain_pending_user_messages/1` returns the queue and resets it to `[]`. Callers: graceful cancel appends the binary `cancel_message/0`; `RemoteAPI.send_agent_message/2` → `AgentScheduler.send_user_message/2` accepts both shapes; both ride the `:agent_updated` `pending_user_messages` delta verbatim.

## Graceful Cancellation (cancel_requested + `:evogit_cancelling_tasks` marker)

**`AgentState.cancel_requested`** — `boolean() | nil`, default nil; set by the scheduler, checked/cleared by the runner at the top of each turn, which then enters cancel-grace (save work → `complete_task`). Store helpers: `set_cancel_requested/1,/2`, `cancel_requested?/1` (`false` when missing), `clear_cancel_requested/1`.
**Delta-broadcast asymmetry**: `@agent_state_tracked_fields` alone produce `:agent_updated` deltas (`put_agent_state`'s struct diff) — `:pending_user_messages` IS tracked (append AND drain), `:cancel_requested` is NOT (its flip emits only the throttled `{:agents_updated, node}`); `batch_update_agent/2` broadcasts the caller kwlist verbatim minus `:context`, so **any new dashboard-visible per-agent flag must go through `batch_update_agent(agent_id, flag: value)` or be added to `@agent_state_tracked_fields`**.

**`begin_graceful_cancel/1`**: (1) registers `task_id` in the `:evogit_cancelling_tasks` marker — a public `:set` ETS table created in `application.ex` and owned by the application process (survives scheduler restarts); (2) scans `SchedMeta.task_id` and per live agent appends the cancel message via **`Store.append_pending_user_message/2`** (NOT `send_user_message/2`, a self-call deadlock) + `Store.set_cancel_requested/1`; (3) purges the task's agents from the LLM/tool waiting queues via **`Slots.purge_agents_from_queues/2`**, replying `{:error, :cancelled}` to each blocked `from`.
Exact `cancel_message/0` text: *"The task is being cancelled by the user. Please immediately save your work: commit any uncommitted changes, then call complete_task with a summary of what was accomplished. You are in a grace period and must call complete_task now."*
**`clear_cancelling_task/1`** — idempotent delete, called by TaskRegistry's guarded `clear_cancelling_marker/1` at terminal transitions; **`cancelling_task?/1`** (public, `@doc false`) is the SHARED nil-safe read (missing table = not cancelling).
**Guards**: `run_agent` replies `{:error, :cancelled}` WITHOUT dispatch while the task is in the marker (blocks Genesis Mode B's second root, which shares the `task_id`); a NEW-agent registration guard gives agents registered meanwhile (subagent spawns, crash-retries, late queued agents) the cancel message + `cancel_requested`.
**`force_kill_task_agents/1`** — brutal reverse-depth `:brutal_kill` cascade (remove refs, purge queues, release slots, `Lifecycle.cancel_agent/2` deepest-first), called by `TaskRegistry.force_kill_task/1`. **RPC**: `RemoteAPI.cancel_task/1` + `force_kill_task/1`, `RemoteNode.cancel_task/2` + `force_kill_task/2` (local-direct when `node == node()`).

## Shutdown & Restart Safety

- **No `terminate/2` in the scheduler ecosystem** (`AgentScheduler`, `Slots`, `State`, `Store`, `WorktreeManager`; the app's only one is `TaskRegistry.terminate/2`) — cleanup is purely monitor-driven. On app stop `EvoGit.Supervisor` terminates children in reverse: `AgentGroupSupervisor` FIRST, whose `one_for_all` kills `EvoGit.TaskSupervisor` (all agent Tasks) + `AgentScheduler`, and WorktreeManager dies before processing queued `:DOWN`s — so `.genesis/workers/worker_T<n>_A<m>/` dirs and `evogit-agent-T<n>-A<m>` branches REMAIN on disk after any BEAM/app stop.
- **Next-start cleanup is the lazy per-repo init** on the FIRST create per repo (`rm_rf_retry` → `Git.prune_worktrees` → `clean_orphaned_branches/1` → `mkdir_p_retry`), ONLY when the marker `:evogit_worktree_repos` is ABSENT and ONLY for the PRIMARY repo; nothing is cleaned at boot without a create request.
- **Task rows survive in SQLite**: `TaskRegistry.init/1` reconciles orphaned `:finalizing` → `:failed` and `:cancelling` → `:cancelled` at boot; `:running` rows fall to the one-shot `:lease_sweep` (150 s after init; `@lease_duration 120`, `@heartbeat_interval 60_000`, `@sweep_after (@lease_duration + 30) * 1000`) → `:failed` ("Lease expired; owning instance no longer renewing"). In-flight agent ETS state (`context`, `pending_user_messages`, `cancel_requested`) is LOST on BEAM death.
- **Slot pools are memory-only**: the restarted `%State{}` has empty pools (holders cannot leak), blocked waiters (`GenServer.call` `:infinity`) exit with the scheduler, and there is no explicit shutdown gate — only `state.paused` plus per-model capacity/backoff. The `:evogit_cancelling_tasks` marker survives scheduler restarts, not app restarts.

## Worktree Safety — Main-Copy HEAD Protection (foreign repos)

The foreign repo's MAIN working copy must never have its HEAD moved pre-merge; a main HEAD on `evogit-agent-T<task>-A<agent>` yields an EMPTY review diff.

- **`Git.clean`/`Git.checkout` are only safe in a REGISTERED linked worktree — `assign_and_prepare_worktree/3` GUARDS this** via `ensure_linked_worktree/2`: `wt/.git` must be a FILE with `"gitdir: <path>"` whose `<path>` (after `EvoGit.Platform.safe_expand/2`) lies under `<repo_root>/.git/worktrees/`; `repo_root` is the explicit param from `prepare_new_worktree/5` (from `resolve_agent_repo_root/2` — NOT `spec.phylo_node.repo`, which for subagents is the PARENT's worktree). Failure → `{:error, {:worktree_prepare_failed, :not_a_linked_worktree}}`, NO git run. `rev-parse --git-common-dir` is unusable: it reports `<repo_root>/.git` for a real worktree AND for a plain dir inside the repo tree, while the repo ROOT has a `.git` DIRECTORY — all indistinguishable.
- **`delete_branch_tolerant/2` RECOVERS git's "cannot delete branch used by worktree"** (both wordings, via `branch_in_worktree?/1`): the stale registration is dropped by `WorktreeRetry.retry_on_transient(fn -> Git.prune_worktrees(repo_root) end)`, then the delete retries ONCE; a branch live in a worktree survives → `{:error, output}` (never force-deleted). Crash-retry interleavings fail safely: a stale `:DOWN` destroy can delete a fresh branch, so `git checkout` errors and main HEAD stays put.
- **LLM cd-escape into the repo root is HARD-BLOCKED at the tool layer**: `do_execute/5` (`agent/tools/shell_tool.ex`) calls `main_copy_mutation_error/3` first — if ANY resolved cd target equals `Path.expand(repo_root)` AND the command matches `@mutating_git_regex` `\bgit\s+(checkout|switch|reset|merge|pull)\b`, it returns an error string and NOTHING executes (`@cd_regex` covers absolute, dot-relative and plain relative targets; `cd_targets/2` resolves via `EvoGit.Platform.safe_expand/2`). `detect_cd_warnings/3` stays warning-only, so prompts still forbid checkout/switch/reset against the repo root.

## Windows-Only Runtime Risks

Windows-only failure modes here; NONE is test-covered (the suite runs on Linux/macOS).

- **`run_init_script/3` spawns a BARE executable name**: `System.cmd(shell, extra_args ++ Platform.shell_args(cmd), cd: repo_root, stderr_to_stdout: true)`; without a shebang `shell` = `Platform.shell()` = `"powershell"`, resolved via `:os.find_executable/1` → `ErlangError :enoent` on a miss (OTP's win32 resolver hardcodes `[".exe", ".com", ".cmd", ".bat"]`, never PATHEXT, and tries cwd LAST; built-in `WorktreeInitScript` windows variants carry NO shebang). Elsewhere the class IS guarded (`EvoGit.Sandbox.None.resolve_executable/1`, `Git.gh_available?/0`); `worktrees.ex` is not.
- **Create-path raises fail safely**: `run_init_script/3` sits in `prepare_new_worktree/5`'s `with` BODY with no `try`/rescue, so a raise reaches `WorktreeManager.run_create/6`, which catches it (`rescue`/`catch :throw,:exit`) into `{:error, {:worktree_create_failed, "worktree create raised: ..."}}` while `after` still fires `{:create_finished, agent_id}`; the create Task is MONITORED too, so a death bypassing the catch replies an error and releases the permit (`handle_create_task_down/4`).
- **No POSIX-only process handling**: no `:os.cmd`, `System.cmd("kill", ...)`, `os_pid`, negative-pgid kill, `chmod` or `sh -c` here — kills are `Task.shutdown/2` + monitor reclaim, and git resolves through `EvoGit.Executable.resolve/1` (bundled-MinGit fallback). A create stuck in a blocking syscall holds its permit until `{:create_finished, agent_id}`, so queued callers WAIT.
- **Windows path normalization is load-bearing and HOLDS — do not "fix" it**: `Path.join/2` emits `/` and `Path.expand/2` normalizes `\` → `/`, so `repo_root_from_worktree/1`'s split on `"/.genesis/workers/"` and the `safe_expand` comparison work only via those stdlib behaviours; a raw backslash path fails to strip → `:not_a_linked_worktree` (fail-safe). `branch_name/2` has no character illegal in a Windows ref.

## AgentScheduler GenServer Hub (`agent_scheduler.ex`)

~1130 lines — agent lifecycle, per-model LLM/tool slot pools, config state + updates, cancellation markers, startup reconciliation; sub-logic lives in `agent_scheduler/`.
**Lazy config-read rule (do not regress)**: single-key config reads inside the scheduler MUST use the lazy private `config_value/2`, never an eagerly built full config map — `config_map/1` evaluates `Platform.sandbox_backend()` and `Sandbox.capabilities()` on every call, which deterministically regressed the system_sampler tests. `config_map/1` is used ONLY for the full `:get_config` reply; `@config_keys` (16 keys) enumerates the fields.

## Task-Scoped Resource Inventory (per-task on-disk artifacts + teardown hooks)

- **The ONLY on-disk artifact this subtree creates is the worktree**: `<repo_root>/.genesis/workers/worker_T<task_number>_A<task_local_id>` + branch `evogit-agent-T<task_number>-A<task_local_id>` (`.genesis` git-ignored). **`task_number` is DERIVED FROM DIRECTORY NAMES, not `task_id`**: `Dispatch.next_task_number/1` scans `.genesis/workers/worker_T*` → max+1 per ROOT spawn.
- **The worktree dir is removed in EXACTLY one function**: `destroy_worktree/3` → `rm_rf_retry` (then prune, then branch delete); callers are the `:DOWN` `:live` branch and the `:create_finished` `pending_cleanup` branch. Extra CREATE-path removals: `Worktrees.destroy_leftovers/3`, `Git.remove_leftover_worktree_dir/1`.
- **Background jobs rooted under a worktree are REAPED first** (`destroy_worktree/3` via the defensive `safe_reap/1`): `EvoGit.BackgroundJobs.reap_under(worktree_path)` runs IMMEDIATELY BEFORE `rm_rf_retry`; a dead/timed-out registry degrades to a logged no-op (`rescue` + `catch :exit` → `:ok`).
- **Reclaim follows AGENT PROCESS DEATH, never task completion**; `recycle_agent/2`/`cancel_agent/2`/`handle_agent_crash/3` do ETS deletes only; the `:finalizing`/merge path never touches worktrees.
- **The managed per-task scratch dir is NOT scheduler-owned**: `EvoGit.TaskTmpdir` (`../task_tmpdir.ex`) is created and reclaimed by `EvoGit.TaskRegistry` (`TaskExecutor.ensure_task_tmpdir/2`); `:per_repo` places it at `<primary repo>/.genesis/tmp/task_<id>`, and an app crash orphans it.
- **Cancel teardown touches NO disk** (marker insert + pending message + `purge_agents_from_queues/2`; force kill adds the brutal kills) and **archive state is persisted per agent, never buffered in RAM**. This subtree writes NOTHING under `EvoGit.Platform.data_dir/0`.

## Known Issues

- **A create pipeline that hangs FOREVER holds one admission permit, and its blocked caller is not cancellable by timeout**: `create_worktree_for_agent/6` waits `:infinity` while the create runs in an unlinked `Task.start` nothing kills, so a create stuck in a blocking syscall (wedged NFS, anti-virus holding the tree) neither fails nor returns; `creating_count` only decrements on the `{:create_finished, agent_id}` cast, so four such creates saturate the default cap of 4 and `admission_queue` starves silently (no stall detection or logging). Escapes: force-kill / graceful-cancel the task (its monitor moves the `:creating` registration to `pending_cleanup`, but the create task and its permit survive); restart `WorktreeManager` (resets `creating_count`); restart the BEAM (orphans the stuck worktrees).

## Constraints

- Data structs are plain data with no behaviour/callbacks; `Slots`, `Worktrees`, `Dispatch`, `Subagents`, `Lifecycle`, `State` are pure functions over `State.t()`. GenServer state must always be `%State{}` (struct update, not `Map.put/3`).
- `AgentState` is shared (scheduler + agent processes); `SchedMeta` is scheduler-exclusive.
- The scheduler process NEVER calls git, does blocking filesystem I/O, or calls ANY worktree function — git work happens in the agent Task process, and ALL worktree filesystem operations (rm_rf, mkdir_p, prune_worktrees, delete_branch) belong to `WorktreeManager`. The only worktree call is Runner → `create_worktree_for_agent/6` (`:infinity`, monitored Task, exactly one reply, `:DOWN` reclaim).
- Slot availability is derived from holder MapSets, never a counter. `SchedMeta.task_ref` stores a `%Task{}` (for `Task.shutdown/2`); `ref_to_agent` keys on `task.ref`.
- `case`/`with` guards on ETS lookups only where a genuine race can make the entry absent (`recycle_agent`, `try_dispatch`, `cancel_agent`).

### Task archive persistence (`task_agent_archives`)

A RELATIONAL table — one row per agent per task, keyed `{task_id, agent_id}`, idempotent upsert (crash-retry double-writes safe).
**The ONLY producer is `CompleteTask.complete/4`** via its private `write_archive_refs/7`, which writes the `refs/genesis/archive/T{task_id}-A{agent_id}-start`/`-final` git refs AND calls `EvoGit.TaskRegistry.put_task_archive/1` (→ `EvoGit.Store.put_task_archive/1`) at agent completion — no ETS archive buffer, no archive field in `%Result{}`, no end-of-task collection (`Lifecycle.handle_task_result/3` persists the root result unchanged; `run_agent` only resets a task's leftover rows via the guarded `EvoGit.Store.delete_task_archives/1`).
`usage` is a PLAIN MAP of the 9 canonical token/cost keys plus the derived `cache_hit_rate` (NEVER a `cost` key), rows round-trip STRING-keyed (`EvoGit.Agent.Usage.from_archive_map/1` is the consumer reader), and a crash/failure/abort writes NO row.

## Per-message timestamp metadata convention

Every message in an agent's session memory (`%ReqLLM.Message{}` list in `%ReqLLM.Context{}.messages`, held in `AgentState.context`) carries `metadata[:timestamp]` — **Unix seconds** (`System.system_time(:second)`), an atom-keyed integer like `:turn`, stamped at message-CREATION time in agent code, never in the Store.
**Single choke point — `ContextBuilder.tag_message_turn/2`** (`agent/context_builder.ex`): every message the loop produces passes through it; it sets BOTH `metadata[:turn]` and `metadata[:timestamp]`, idempotent via `Map.put_new`. `ContextBuilder.tag_message_timestamp/1` stamps just the timestamp (nudge + compression-summary sites); creation-site inventory in `agent/CONTEXT.md`.
**`Store` is a dumb pass-through** (`batch_update_agent/2` writes fields verbatim into ETS, only the broadcast kwlist transformed; `update_agent_context/2` delegates) and **no read-back exists** — the dashboard reads `msg.metadata[:timestamp]` from `RemoteAPI.get_agent_history/1`. An integer is timezone-agnostic (`DateTime` deliberately avoided) and **the dashboard interprets it as Unix SECONDS** (`EvoDashWeb.Helpers.format_history_timestamp/1`) — do NOT change granularity without updating evo_dash.
