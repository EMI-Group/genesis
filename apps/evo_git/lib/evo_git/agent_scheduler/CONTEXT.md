# Agent Scheduler Data Structures and Helper Modules

## Intent

Structs + helpers behind the `EvoGit.AgentScheduler` GenServer: `%AgentState{}` SUMMARY rows in ETS `:evogit_agent_summary` (ONE runtime writer: the agent's `EvoGit.Agent.Session`, plus registration writes), cross-process control in `:evogit_agent_inbox` + `:evogit_agent_control` (`ControlPlane`), `%SchedMeta{}` rows in `:evogit_sched_meta` (scheduler-exclusive).
All four tables are created/owned by `EvoGit.Application`, never the scheduler — no heir, they must outlive a scheduler crash (which kills `EvoGit.TaskSupervisor`, i.e. every exchange worker, and through them all sessions via the `:one_for_all` `AgentGroupSupervisor`; `%State{}` resets, tables keep stale rows).
Helpers are pure over `State.t()` except the GenServers (`WorktreeManager`, `PubSub.Throttle`).

## Routing Table

Leaf directory: `model_selection.ex` (schema/dispatch adapter), `session_opts.ex` (interactive `start_session/1` opts → `%AgentSpec{}` builder + scheduler-side session helpers), `state.ex`, `agent_state.ex`, `control_plane.ex`, `sched_meta.ex`, `slots.ex`, `store.ex`, `worktrees.ex`, `worktree_manager.ex`, `worktree_retry.ex`, `foreign_worktree.ex`, `dispatch.ex`, `subagents.ex`, `lifecycle.ex`, `pubsub.ex`, `throttle.ex`, `remote_api.ex`; hub `../agent_scheduler.ex`.

### RemoteAPI review surface (arbitrary repo_path; task-level review status)

Review RPCs are `repo_path`-first (the CALLER supplies the path), so one RPC serves the primary and every writable foreign repo; shapes are `EvoGit.Review`'s verbatim — full table in `../../CONTEXT.md` ("Review / RemoteNode Return-Shape Contract").
Surface: `get_file_content/3`, `list_commits/2`, `load_review_data/2`, `load_review_metadata/2`, `load_review_metadata_from_shas/3`, `list_commits_from_shas/3`, `load_file_diff/4,5`, `load_commit_files/2`, `load_commit_file_diff/3`, `check_merge/3`, `merge_branch/2,3`, `default_merge_target/1`, `list_branches/1`, `reject_branch/2`, `create_github_pr/4`, `branch_exists?/2`, `list_commit_graph/3`, `list_task_commit_graph/4`.
`list_commit_graph/3` → `{:ok, %{commits: [commit], refs: %{sha => [ref_name]}}}` (atom-keyed `:sha, :short_sha, :message, :author_name, :author_email, :date`, `:parents`); `list_task_commit_graph/4` resolves its base as `opts[:base_sha]` → task/foreign `base_sha` → `Git.merge_base` and adds `truncated: boolean`.
`set_review_status/2` + `set_review_metadata/3` key on `task_id` ONLY, so per-repo outcomes live in dashboard assigns; `get_foreign_repo_commits/1` is NOT exposed over RPC.
`RemoteNode` mirrors `list_tasks_page/2` (deliberate asymmetry vs `select_tasks_page/1`), `get_task_lite/2`, `list_task_archives/3`, `get_agent_archive/3`, `list_commit_graph/4`, `list_task_commit_graph/5`, returning the Store's degraded shape on transport failure (`../store/CONTEXT.md`); guards exist only on `send_agent_message/2`, `get_recent_system_samples/0`, `respond_approval/2`.

### Project-mount surface (Virtual Context Tree)

`RemoteAPI.projects/0` returns PROJECT mounts ONLY as `[%EvoGit.VCT.Mount{}]` newest first (a reserved mount such as `vct:///genesis-source` is never listed), `[]` when nothing is mounted or the VCT is down; `mount_project(path, name)` → `{:ok, mount} | {:error, :relative_path | :store_unavailable | :vct_unavailable}`; `forget_project(key)` → `:ok | {:error, :not_found} | {:error, :invalid_point} | {:error, :reserved_point}` and accepts a VCT point or an OS path.
`RemoteNode` mirrors them as `projects(node)`, `mount_project(node, path, name)` and `forget_project(node, key)` — local-direct, else `call_remote/4`, a failed transport degrading to `[]` for the list and `{:error, {kind, reason}}` for mutations.
Every mount mutation emits its ONE `{:vct_updated, node}` on the target node; these RPCs add no notification of their own.

### Push-only streaming watch surface (cross-node)

`RemoteAPI.register_watcher/2`, `unregister_watcher/2` and `watch_snapshot/1` are thin passthroughs to `EvoGit.Agent.Stream` under `Stream`'s own 5 s session deadline — ONE implementation, no second session-call path.
They are LOCAL-node session calls (the session, its watcher set and its transcript live on the node that OWNS the agent), the snapshot is 🟠 heavy full-transcript while deltas are 🟢 PUBLISHED, and a disconnected cluster silently delivers no deltas while the attach still succeeds.
Return shapes, the notify/watch rule and stream gating: `../agent/stream/CONTEXT.md`.

## Direct-Eval / Assistant API Safety

`RemoteAPI` is a mixed read/write RPC facade, not an authorization boundary: the admission registry, tier rules, facade contracts and the per-admitted-API shape caveats (`list_agents/0`, control wrappers, `cancel_agent/2`, unredacted reads) belong to `../agent/tools/elixir_eval/CONTEXT.md`.
This node's admitted direct calls are `RemoteAPI.list_agents/0`, `AgentScheduler.get_config/1`, `paused?/0`, `get_llm_slot_status/0` in BOTH tiers, with write tier adding `AgentScheduler.update_config/1`, `pause/0`, `resume/0` and `RemoteAPI.reload_config/0`; unlisted MFAs and wrong arities stay denied and refusal never escalates a tier.
Admitted calls invoke the real API with unchanged arguments and return its ACTUAL value — output truncation is not redaction; `get_agent_state/1` returns the native `%AgentState{}` summary row (no conversation) and `get_agent_history/1` proxies `Session.history/1` (TOTAL `[]` within 5 s for a gone session), so neither is a redacted projection.

## Reload and runtime-update contracts

`RemoteAPI.reload_config/0` = `Config.resolve/0` → `build_reload_opts/1` → `AgentScheduler.update_config/1`, with no local validation, exception containment, file write or transaction.
`build_reload_opts/1` requires only an outer map and expects atom-keyed scheduler/sandbox maps: `ModelSelection.config_opts/1`'s model options, scheduler `default_llm_max_concurrency`, `max_tool_concurrency`, `agent_max_retries`, `max_depth` (from `max_agent_depth`), `max_retries`, `max_turns`, `max_turns_root`, plus sandbox `sandbox_mode`/`sandbox_resources`/`sandbox_process_resources` (from `mode`/`resources`/`process`), dropping nil values.
`RemoteAPI.save_user_config/1` persists via `Config.save_user_config/1` and then reloads BEST-EFFORT: a scheduler-side reload error, a caller-side `GenServer.call` timeout, or an unresponsive/restarting scheduler (an exit) is logged with `Logger.warning` and the save still answers `:ok`, because the file already landed and the saved file has no rollback; only a genuine persistence failure returns `{:error, reason}`, and a genuine raise inside `reload_config/0` still escapes (`safe_call/1` catches exits only, and the per-process `with_reload_fun/2` seam makes the reload step testable without a live scheduler). `save_credentials/1` delegates without reload.
`State.do_update_config/2` consumes those keys plus `llm_model`, `llm_generation_params`, `model_concurrency` and `model_concurrency_skip_floor`, ignores unknown keys and applies NO type/range/schema validation: an explicitly present nil IS assigned, profile rebuilding needs a genuine profile-list/map shape, and any truthy skip-floor grants the bypass.
Profile replacement keeps live holder/waiter/backoff/last-granted maps and non-LLM state but rebuilds profile concurrency and default generation parameters; a direct `llm_model` assignment alone does not rewrite `model_profiles`.
That branch logs ONE `Logger.warning`, BEFORE `ModelSelection.update_opts/2`, when `ModelSelection.legacy_replacement?/1` holds while a canonical snapshot is installed (`provider_profiles != []` or `model_selection_config != nil`), naming the consequence (`explicit model_spec selections will no longer resolve` → `:model_spec_schema_unavailable`) and the `ModelSelection.config_opts/1` / `RemoteAPI.build_reload_opts/1` remedy; the reply stays `:ok`.
Every update sweeps available slots and broadcasts a config change, and Linux sandbox-resource changes enqueue an asynchronous slice update, so `:ok` is not confirmation of OS application; nothing here persists files, rewrites existing agents' ETS snapshots or survives scheduler reinitialization.
Persistence is `EvoGit.Config.resolve/0,1` + `Config.save_user_config/1`, which replaces the WHOLE config.toml and invalidates its cache without reloading the scheduler — read-modify-save contract in `../agent/tools/elixir_eval/CONTEXT.md`, public wrapper in the parent hub.

## Throttled PubSub

- The `:agent_registered` `summary` has EXACTLY `status, depth, parent_id, task_id, task_number, objective` — NOT `message_count`/`agent_module` (only `list_agents/0` has those); `message_count` arrives via `:agent_updated` deltas.

## Agent identity: parent_id & depth (root ⇔ parent_id nil ⇔ depth 0)

- `register_agent/7` is the only writer: ROOT (nil/0) and NESTED (`parent_id`, `parent.depth + 1`); depth is never derived by walking a parent chain.
- Depth reaches the agent as `dispatch_ctx` `depth: meta.depth` → `Session.Setup.bind_worktree/2` in the session's start task (`Process.put(:evogit_agent_depth, depth)`) and `Setup.build_initial_state/3` into `%State{}.depth`; crash-retry resets preserve identity (`phylo_node: nil, context: nil`). The writable-foreign-repo root check is `parent_depth == 0` (threaded through `validate_single_subagent/5` → `validate_spatial_contract_for_spec/4`; the `/3` form hardcodes `0`).
- Root-only custom-agent `max_turns` uses `if is_nil(parent_id)`; a repo-less `:reflect` ROOT is registered `parent_id: nil, depth: 0`, so it gets `max_turns_root` (1000), not 128.
- `Dispatch.resolve_max_turns/3` NEVER reads `spec.opts[:max_turns]` (and `RuntimeOpts` has no such key): the only per-agent turn-cap sources are a root custom-agent definition's positive-integer `max_turns` and the scheduler's `max_turns`/`max_turns_root` (boot from `[scheduler]`, changed at runtime only by `update_config/1` for future registrations).

## Task Spawn & Starting-Commit Flow (run_agent)

`run_agent/2` is a BLOCKING boundary (`GenServer.call(..., :infinity)`) returning `{:ok, %Result{}} | {:error, reason}`; the scheduler, never the session, replies the caller's `from`.
`spec.phylo_node.current_commit` arrives pre-resolved: `Runtime.Helpers.resolve_starting_commit/2` maps nil → `PhyloGraphNode.current_head/1` (unborn HEAD = structured error) and a ref → `Git.rev_parse(repo_path, ref <> "^{commit}")`, failure → `{:error, {:invalid_starting_commit, ref, repo_path, git_output}}`; sources are a task `:starting_commit` opt, resume (`commit_sha`) and Genesis Mode B (`architect_output.commit_sha || base_sha`).
`run_agent/2` (both clauses may reply `{:error, :llm_not_configured}`): `task_id` from `spec.opts[:task_id]` (else random hex) → refuse `{:error, :cancelled}` while the task is in `:evogit_cancelling_tasks` → guarded `reset_task_archives/1` → `resolve_agent_repo_root/2` + `next_task_number/1` → `register_agent/7` (`phylo_node: nil`) → paused ? queue : `try_dispatch/2`.
**Registration is STATELESS per call**: a fresh `state.next_agent_id` plus a fresh per-task `task_local_id`, both rows INSERTed (`put_agent_state` + `put_sched_meta`) without reading the existing row; no path looks a row up by `task_id`/`objective` (only `agent_ids_for_task/1` scans by task), so an id reused after a scheduler-only restart is OVERWRITTEN, never resumed.
`AgentSpec.opts` keys consumed here are exactly `:task_id`, `:model_spec`, `:model_id_locked`, `:default_model_spec`, `:archive` (plus `:repo_less`, `:custom_agent_id`, `:attachments`, `:quality_level` in `Setup.install_process_context/3`); this subtree has NO `:history`/`:messages`/`:chat`/`:conversation`/`:session`/`:resume_from`/`:multi_turn` option.
The initial `[system, user]` conversation is built FRESH in the session's start path (after its start task binds the worktree) (`Setup.build_initial_state/3` → `ContextBuilder.build_initial_messages/4`) and only THEN published; `do_register_agent/8` never writes `:context` and crash retry clears it. Re-dispatch of the SAME id happens only on crash retry (row `current_commit` reset, fresh `%State{}`) and for a WAITING parent resumed by `Subagents.dispatch_ready_parent/3`.
`try_dispatch/2` computes `worktree_path = <repo_root>/.genesis/workers/worker_T#{task_number}_A#{task_local_id}`, stores it in SchedMeta BEFORE starting anything (so `cancel_agent` finds it), adds `scheduler: self()` to `dispatch_ctx`, starts the session under `EvoGit.Agent.Session.Supervisor`, then `Process.monitor(pid)` + `ref_to_agent` + `status: :running`/`session_pid`/`phase: :starting`. `{:error, {:already_started, pid}}` is tracked like a fresh start; any other start failure is logged and routed through `Lifecycle.handle_agent_crash/3` as `{:session_start_failed, reason}` (meta stays `:pending`, bounded retry, parent/root replied at permanent failure). No git/worktree work happens here.
The session's start TASK requests the worktree (`Setup.bind_worktree/2`, the SESSION pid as owner); `create_worktree_for_agent/6` checks out `current_commit` via `CowWorktree.create_worktree/5` (fallback `Git.add_worktree`), then `assign_and_prepare_worktree/3` records the prepared commit on the summary row, advanced later by `ToolDispatch.sync_current_commit_after_tools/1` (moved onto the owned `%State{}` at the turn checkpoint, published by `Summary.publish/3`).
Subagent phylo nodes (`build_subagent_phylo_node/6`): explicit `commit_id` validated by `Git.rev_parse`, else the parent's `current_commit`; cross-repo uses tracked `foreign_repo_commits` or foreign HEAD.
**Repo root resolution**: per-agent `AgentState.repo_root` first, then `Process.get(:genesis_repo_root)` (set/re-installed by `Setup.bind_worktree/2` and `install_process_context/3`, read via `current_repo_root/0`) — no global `state.repo_root`; repo-init tracking lives in `WorktreeManager`, running = `map_size(state.ref_to_agent)`.

## Subagent Spawn Fan-Out Bounds & Deadlock Surface

- **Registration is EAGER at accept** (`:pending` → `:running` + immediate spawn; `state.queue` exists only while paused) and the **worktree is created EAGERLY at child start**, so a child HOLDS a worktree while blocked on an LLM slot; a WAITING parent keeps its live worktree too (reclaim `:DOWN`-only) and holds NO slot, so capping LIVE worktrees/agents with queueing can deadlock, whereas the implemented cap bounds CREATE-pipeline concurrency and cannot.
- **`max_depth`** — `[:scheduler, :max_agent_depth]`, `:pos_integer`, default `8`, `[min: 1]`; `validate_subagent_depth/3` → `{:error, :max_depth_exceeded}`; `Turn.effective_tools/1` drops subagent schemas at max depth. Bounds DEPTH only.
- **Defensive ETS lookups**: `Store.get_sched_meta/1`/`get_agent_state/1` return `{:ok, x} | :error`, so four sites degrade when a parent is reaped mid-spawn — `spawn_validated_subagents/5` (replies `[{:error, :parent_recycled}]` per spec, bailing BEFORE the `:waiting` mutation), `store_sub_result/3,4` (→ `:ok`), `maybe_resume_parent/2` and `dispatch_ready_parent/3` (still replies/resets meta, logs `"unknown"`). Covered by `subagents_test.exs` + `pubsub_test.exs`.

**Batch size is UNBOUNDED**: one reduce over the subagent tool calls of ONE LLM response (`SubagentSchemas.schemas/1` has `path`/`objective`/`commit_id` only, no `maxItems`), gated by `max_agent_depth`, `:path_ignored`, the spatial contract, one-writable-foreign-repo-per-batch, `{:error, :scheduler_paused}` and `:llm_not_configured`; the scheduler GenServer itself is never blocked.

## Agent-facing submodule awareness (repo_notes)

`AgentSpec.repo_notes` carries the ALREADY-RENDERED git-submodules note, rendered ONCE at root spec build by `Runtime.Helpers.load_repo_notes/2` (`Git.ls_tree_gitlinks/2`; nil when none/fails) → `%State{}.repo_notes` → `ContextBuilder.build_repo_notes_section/1`. ## Repo-Nil Tolerance & Repo-Less Agent Plumbing

The repo-less self-reflective agent (`EvoGit.Agents.SelfReflective`, `spec.opts[:repo_less] = true`) runs on this plumbing; nothing here runs git or creates worktrees for it.
**Nil-tolerant:** `current_commit` defaults nil (written nil at registration for a repo-less spec and at crash-retry reset — a transient nil is NORMAL); `repo_root` defaults nil; `resolve_agent_repo_root/2` returns nil for a foreign id missing from `spec.foreign_repos`; foreign roots are already ABSOLUTE (`ForeignRepo.new/3` applies `Platform.safe_expand/1`), so nothing re-expands them, and a foreign worktree lands under `<foreign_root>/.genesis/workers/worker_T<n>_A<m>` like a primary one (matched by `spec.repo_id`, never path); `commit_pending_in_worktree/0` short-circuits on `Process.get(:repo_less)`; skill loading guards `repo_root && is_binary(repo_root)`; `build_agent_summary/3` nil-guards via `safe_phylo_commit/2`/`safe_context_path/1`.
**Hard-dereferences a repo-less path must avoid**: `resolve_agent_repo_root/2`'s primary branch splits `spec.phylo_node.repo` on `"/.genesis/workers/"` (nil → FunctionClauseError), `do_try_dispatch`'s `Path.join([agent_repo_root, ".genesis/workers", ...])`, `maybe_init_repo/3` → `workers_dir/1`, and `assign_and_prepare_worktree/3`'s bare `{:ok, meta}`/`{:ok, %AgentState{}}` matches.
**Repo-less specifics:** `resolve_agent_repo_root/2` uses the SHARED chain `EvoGit.SelfReflectiveSource.reference_path/0` (`:self_reflective_source_root` → `GENESIS_SOURCE_ROOT` → the reserved VCT mount `vct:///genesis-source` when its path is a valid checkout → managed clone at `<data_dir>/genesis-source`), fallback `File.cwd!()`, else `"[system]"` (unreachable — `File.cwd!()` raises instead of returning nil); `do_try_dispatch` appends `repo_less: true` + `repo_less_repo_path: <root>` and SKIPS worktree creation, and that skip lives ENTIRELY in `Setup.bind_worktree/2` (the `if repo_less` branch) — `create_worktree_for_agent/6` has no repo-less branch and is never called.
`dispatch_ctx` keys (all `Keyword.fetch!`'d): `[agent_id:, depth:, repo_root:, repo_id:, worktree_path:, retries:, spec:, meta:]`.
`next_task_number/1` still runs for repo-less roots, scanning `<source root>/.genesis/workers` — in dev the real Genesis repo's workers dir.
`rebuild_monitors/1` re-monitors on the SESSION pid with NO repo_less guard (it only needs a binary `worktree`, a pid `session_pid` and an integer `task_number`, all of which a repo-less agent has via its synthetic path), so after a WorktreeManager-only restart its `:DOWN` → `destroy_worktree/3` runs `git prune` + a branch delete inside the SOURCE ROOT (`rm_rf` of the synthetic path no-ops).

## Provider/account selections and resource pools

`ModelSelection.config_opts/1` and `State.from_config/2` share ONE schema snapshot for boot, reload and dispatch: canonical string-keyed `provider_profiles` + `model_selection_config` when `Schema.provider_profiles/1`, `model_selections/1` and `resolve_model_spec/2` exist, else `Schema.effective_model_profiles/1` verbatim (legacy/flat/empty configs, including the one model-less `"default"` profile, emit legacy options only, so a legacy-only reload CLEARS any previous account snapshot — intended).
`model_concurrency`, `llm_holders`, `llm_waiting`, `llm_backoff_until`, `llm_last_granted` keep historical names but are keyed by provider/account id, so every model/effort of ONE account shares capacity and backoff while separate accounts stay isolated.
The default-concurrency floor applies at BOOT too: `State.from_config/2` always injects `[:scheduler] :default_llm_max_concurrency` (default 3), so a lower account `concurrency` is raised (explicit `0` survives); only a lowered scheduler default, or a raw `from_model_profiles/2` call without the key, keeps a lower value.
`ModelSelection.update_opts/2` is PURE and delegates legacy-vs-canonical classification to the public `legacy_replacement?/1` (by `provider_profile_id`, directly or inside `model_spec`); a legacy-only replacement clears `provider_profiles` + `model_selection_config` together, while explicitly supplied keys win.
**Any runtime push that REPLACES model profiles for a canonical `[[llm.providers]]` configuration MUST also carry `provider_profiles` + `model_selection_config`** (from `ModelSelection.config_opts/1` or `RemoteAPI.build_reload_opts/1`), else the snapshot is cleared and every explicit `model_spec` fails with `:model_spec_schema_unavailable`.
`Dispatch.resolve_selection/5` resolves an explicit STRING map from `AgentSpec.model_spec` or `spec.opts[:model_spec]` FIRST and rejects malformed/invalid explicit selections WITHOUT fallback; otherwise priority is locked legacy id → script → `spec.opts[:default_model_spec]` → legacy `spec.model_id` (or the custom definition's id) → configured default.
`opts[:default_model_spec]` is a canonical CUSTOM-DEFINITION fallback, never an explicit selection or lock, omitted when no canonical definition default exists and validated via `ModelSelection.resolve_explicit/2` only when selected; malformed → `:invalid_model_spec`, unavailable snapshot → `:model_spec_schema_unavailable`, other errors propagate UNCHANGED — always before registration mutates ETS or counters.
Scripts still override the fallback (nil/error results use it; invalid canonical script selections fail closed; unknown legacy ids keep the configured default), and a locked LEGACY parent clears both the child's `model_spec` field and its compatibility opts entry, so the inherited legacy id overrides any child canonical selection (`ModelSelection.inherit/2` runs inside `register_agent/7`).
`ModelSelection` copies the ReqLLM-ready identifier into `llm_model`, takes `generation_params` verbatim and reads the context window from `runtime_profile`, never catalog metadata; endpoint config rides the MODEL INPUT, credentials ride `llm_generation_params` (`../config/schema/CONTEXT.md`), and no per-request value (request id, cache key, timestamp) is ever added; legacy-id/default requests keep the resolved provider id as `model_id`, while explicit maps have no legacy alias (`model_id: nil`).
**Per-agent-run prompt-cache identity**: `do_register_agent/8` passes `selection.llm_generation_params` through `Config.Schema.LLM.with_cache_identity/3` with the scope `"genesis-#{task_id}-#{agent_id}"` (or `"genesis-agent-#{agent_id}"`), so every turn, retry and compression call of ONE agent shares one routing key while distinct agents get distinct keys; the helper is provider-gated (`:openai`/`:openai_codex`), so other providers persist byte-identically.
`register_agent/7` returns `{integer_agent_id, state}` or `{:error, reason}` and resolves before any counter or ETS mutation; subagent registration handles errors per child and inherits a locked parent's whole `model_spec` + lock first.

## Slot Management (Slots module)

Two independent pools of agent-ID `MapSet`s; capacity = `capacity - map_size(holders)` — leaks impossible, `release_agent_slots/2` removes the holder from both sets.

| Pool | State keys | Capacity | Backoff |
|---|---|---|---|
| LLM | `llm_holders`, `llm_waiting`, `llm_backoff_until`, `llm_last_granted` | **per-model** `model_concurrency[model_id]` (profile `concurrency`, default 3); fallback `default_llm_max_concurrency` (3) via `State.concurrency_for/2` | **per-model** on `:rate_limit` AND `:insufficient_balance` (HTTP 402) — caller duration (default 60 s, clamped to `@max_timer_ms`), self-rescheduling sweep; one model never blocks others |
| Tool | `tool_holders`, `tool_waiting` | `max_tool_concurrency` (default `EvoGit.Platform.cpu_threads/0`) | None |

`handle_request_llm_slot/3`, `handle_request_tool_slot/3`, `handle_release_llm_slot/2`, `handle_release_tool_slot/2` (`handle_cast`), `release_agent_slots/2` (`:DOWN`: both sets, queue purge, grant), `grant_pending_on_resume/1` (also at the END of every config update, so 0→N grants queued waiters). Sync ops return `{:reply, :ok, state, status_updates}`/`{:noreply, state, status_updates}`, async releases `{state, status_updates}`; `status_updates` = `{agent_id, :blocked | :running}` written to SchedMeta.
`default_llm_max_concurrency` is a DEFAULT per-LLM concurrency, NOT a global cap: `concurrency_for/2` prefers `model_concurrency[model_id]`, else the default; the map is filled only at config-load time (`from_model_profiles/2` at `init/1`, the `:model_profiles` update branch, or `update_config(model_concurrency: map)`), legacy config yielding `model_concurrency["default"]`. **A runtime override is a FLOOR**: `State.apply_default_llm_concurrency_override/2` sets the default AND raises every entry to `max(c, N)` (explicit `0` stays `0`), while a profile concurrency above the default still wins.

## Worktree Lifecycle (WorktreeManager + Worktrees)

**Fresh per agent run** — no pool, no reuse across retries.

1. **Lazy per-repo init** on the FIRST create for a repo: rm_rf `.genesis/workers` → `git worktree prune` → orphaned `evogit-agent-*` cleanup → mkdir_p (never from the scheduler). Gated on the persistent `:evogit_worktree_repos` marker: PRESENT (manager-only restart) → wipe skipped, only `mkdir_p_retry/2`; ABSENT (first request or genuine BEAM restart) → full wipe, then record. Destructive steps are **PRIMARY-ONLY** (`primary?` from `spec.repo_id` via `ForeignRepo.primary?/1`); foreign repos get prune + mkdir_p + marker. `mkdir_p_retry` raises `File.Error` on exhaustion — safe because the marker is written before the first worktree exists.
2. **Request path**: `create_worktree_for_agent/6` (`:infinity`) offloads to a MONITORED Task (`run_create/6`) replying exactly once — result, or `{:error, reason}` when the create fun raises/throws/exits (`report_create_failure/3`) or the task dies silently — plus the `{:create_finished, agent_id}` permit-release cast.
3. **Create pipeline** (`prepare_new_worktree/5`): destroy leftover dir/branch (rm_rf failure escalates) → CoW create (fallback `Git.add_worktree`; failure → `{:error, {:worktree_create_failed, msg}}`) → `assign_and_prepare_worktree/3` → `run_init_script/3` (genesis.toml `[worktree]` script, primary only; env `SOURCE_REPO_PATH`/`SOURCE_WORKTREE_PATH`/`TARGET_WORKTREE_PATH`; Windows via `Platform.shell_args/1` → PowerShell `-EncodedCommand`).
4. **Monitor-based reclaim**: `:DOWN` for ANY reason (including after a successful completion) → `destroy_worktree/3` in FOUR ordered steps: `BackgroundJobs.reap_under(worktree_path)` under `safe_reap/1` (a detached job whose cwd is inside the dir would hold it open) → `rm_rf_retry/2` → only AFTER the dir is gone `Git.prune_worktrees(repo_root)` → `delete_branch_tolerant(repo_root, branch_name)`; rm_rf failure logs ERROR and skips prune + branch delete. A failed CREATE-path rm_rf returns an error and also SKIPS prune — a surviving dir with its `.git` file + registration is safe, while a pruned partially-removed dir becomes a PLAIN unregistered dir (the leak precondition). Idempotent; `recycle_agent/2`, `cancel_agent/2` and permanent failure never delete worktrees; after a manager-only restart `rebuild_monitors/1` re-monitors live agents from `:evogit_sched_meta` + `:evogit_agent_summary`, skipping missing/stale rows.
   Reclaim is keyed ONLY by the agent process monitor — never by task completion — and the ETS rows are deleted by `Lifecycle.recycle_agent/2`, not here.
   `task_number` comes from `Dispatch.next_task_number/1` (a `File.ls` scan for `worker_T<n>_` maxima, `1` when missing) ONCE per task from the ROOT's repo root, and every subagent inherits it — each repo owns its own `.genesis/workers`, so dir and branch names REPEAT across repos (unique per repo, never task-globally).

## Persistent Foreign-Repo Worktrees (ForeignWorktree)

`ForeignWorktree` owns the PERSISTENT worktree of every WRITABLE non-primary foreign repo at `<root>/.genesis/foreign_repos/<id>` (`ForeignRepo.worktree_path/1`) — a stable READ view of the latest committed state, addressable by absolute path (`ForeignRepo.resolve/2`, `ContextBuilder.build_foreign_repos_section/1`); it lives OUTSIDE `.genesis/workers/`, so the primary-only wipe and `destroy_worktree/3`/`destroy_leftovers/3` never touch it, MAIN HEAD never moves, and it is NOT torn down at task end. A foreign agent's WRITE workspace remains its ephemeral worktree.
API: `start_commit/1` (`base_sha` else repo HEAD), `ensure/2` (idempotent create-or-reset; non-writable → no-op; create = `mkdir_p_retry` → `Git.add_worktree(root, wt, sha)` detached, no branch → prune + one retry; update = `Git.checkout(wt, sha)` with `Git.reset_hard/2` fallback), `ensure_all/1` (best-effort, never raises), `sync_from_agent/0`, `worktree_path/1`.
**Hooks**: `Runtime.Helpers.load_foreign_repos/2` calls `ensure_all/1` after validating (before any spawn); `Session.Worker.run/3`'s `try/after` calls `sync_from_agent/0` right after `commit_pending_in_worktree/0` on EVERY exit path, advancing the agent's OWN repo worktree (id-matched via `Process.get(:evogit_repo_id)`) to `Process.get(:repo_path)`'s HEAD — no-op for primary/repo-less agents, last-writer-wins.
`ensure_all/1` filters to `writable == true and not ForeignRepo.primary?(repo.id)`, so an entry whose id is literally `"primary"` is never provisioned, and `sync_from_agent/0` only advances `writable` entries.

## Agent Dispatching (Dispatch module)

`register_agent/7` (IDs, task-local IDs, event-sink inheritance, both ETS writes) → `try_dispatch/2` (scheduling only; a `with` guard bails when ETS entries are missing; stores the worktree path BEFORE spawning) → `commit_pending_in_worktree/0`, `resolve_agent_repo_root/2`, `dispatch_queued_agents/1`, `process_queue/1`.
CoW copies unchanged files from a source tree (parent's worktree for subagents, repo root for top-level) with `cp --reflink=auto --preserve=timestamps` (Linux) / `cp -cp` (macOS); `[:git, :cow_worktree_creation]` (`:auto` default).

## Subagent Management (Subagents module)

1. `spawn_validated_subagents/5` validates all specs, registers valid ones and replies immediately if all are invalid; the parent commits pending changes BEFORE calling `spawn_sub_agents`, which blocks (`timeout \\ :infinity`) until every child completes.
2. `validate_single_subagent/5` → `validate_subagent_depth/3`, `validate_subagent_not_ignored/1`, `validate_spatial_contract_for_spec/4` (the `/3` form hardcodes parent depth 0) + `validate_spawn_spatiality/4`; **fan-out WIDTH is NOT code-limited** (no `maxItems`; gates listed above).
3. Cross-repo rule: `:read` at ANY depth; `:read_write` only into a repo whose TASK-LEVEL `spec.foreign_repos` entry (never the path alone) is `%{writable: true}` and only from a ROOT parent; same-repo spawns WITHIN a foreign repo are unrestricted.
4. `store_sub_result/3,4` — the 4th arg carries the COMPLETING CHILD's `%AgentSpec{}` (or nil) and gates foreign-commit recording via `writable_foreign_repo_agent?/1` (public, `false` for non-`%AgentSpec{}`, never raises); then `maybe_resume_parent/2`, `dispatch_ready_parent/3`, `build_ordered_results/2`.

## Session-Owned Agent Lifecycle
Every agent is ONE `EvoGit.Agent.Session` started by `Dispatch.do_try_dispatch/4` under `EvoGit.Agent.Session.Supervisor`; `ref_to_agent` keys on the session monitor ref, while `SchedMeta.session_pid`/`mode`/`phase` are a best-effort mirror and `EvoGit.Agent.Session.inspect/2` is the live phase truth.
The ONE terminal delivery is `{:agent_session_result, agent_id, session_pid, result}`, sent BEFORE the session stops; `AgentScheduler.handle_info/2` admits it only when `SchedMeta.session_pid` is `nil` (already recycled) or equals the sender, and otherwise logs at `:debug` and ignores it.
A session START failure is routed through `Lifecycle.handle_agent_crash/3` as `{:session_start_failed, reason}` — retried up to `agent_max_retries` and the parent/root replied an error at permanent failure, never silently dropped.
Force cancel uses `Session.cancel(pid, :force)` with a bounded wait plus a `Process.exit(pid, :kill)` fallback, and a `nil` `session_pid` (registered but never dispatched) is a no-op; worktree create/reclaim is keyed on the session pid (`Setup.bind_worktree/2` is called by the session's start task with the SESSION pid as owner), so a WorktreeManager-only restart re-monitors it.

## Interactive Sessions (root-only, non-blocking)

An interactive session is the SAME `EvoGit.Agent.Session` in `mode: :interactive`: it yields to `:awaiting_input` instead of finishing and keeps its worktree, conversation and provider `prompt_cache_key` for its whole life; idle contract, input policies, resume and phase transitions belong to `../agent/session/CONTEXT.md`.
It is LIVE but not BUSY (no worker, LLM slot, tool slot or timer), so it must never count as busy: the `/server/status` active-task count covers only `:running`/`:pending`/`:cancelling`/`:finalizing` task ids, and `list_awaiting_input/0` names the idle sessions an upgrade gate winds down.

| API | Returns |
|---|---|
| `start_session/1` | `{:ok, pos_integer()} \| {:error, reason}` — NON-BLOCKING; keyword input goes through `SessionOpts.build/1`, unknown → `{:error, {:invalid_session_opts, {:not_a_session_spec, other}}}` |
| `send_session_message/3` | `:ok \| {:error, {:session, reason}}` via `Session.start_input/3` (`:bad_policy`/`:bad_target`/`:bad_message`/`:exit` nest inside `:session`) |
| `close_session/1` | `:ok \| {:error, {:session, reason}}` — `Session.close/2`, the ONLY non-cancellation way out of `:awaiting_input` |
| `await_close(agent_id, timeout \\ 30_000)` | `{:ok, %Result{}} \| {:error, :not_found \| :timeout \| term()}` — one close waiter, replied exactly ONCE |
| `list_awaiting_input/0` | `[%{agent_id, task_id, session_pid, task_number, mode}]` from `:evogit_sched_meta` (`SessionOpts.idle_sessions/0`, no scheduler call), `[]` when idle/absent |
| `force_kill_task_agents_for_task/1` | `:ok \| {:error, :not_found}` — the ONLY way to reach a `start_session/1` agent (registered `from: nil`), sharing ONE cascade with the pid form |

- `await_close/2` is race-free only with `notify: {self(), tag}` in the spec opts, the waiter registered BEFORE starting, then matching `{:agent_session_closed, tag, result}`; the budget bounds the WAIT alone (`{:error, :timeout}` leaves the session running), so a human-driven session passes `:infinity`.
- `SessionOpts.build/1` + `force_interactive/1` normalize `session_mode`/`notify`/repo-less/model selection into the `%AgentSpec{}` and reject a non-root request (`depth` other than `0`/absent, or a present `parent_id`) with `{:error, {:interactive_root_only, message}}`; `Dispatch.session_mode/2` forces `:oneshot` for every `depth != 0` agent, and `register_agent/7` mirrors `SchedMeta.mode` (`"interactive"`/`:interactive`; unknown → warn + `:oneshot`) into the dispatch ctx.
- Yield/resume are NON-terminal messages admitted only from the agent's current `session_pid` (`SessionOpts.admit_signal/2`, stale senders logged and dropped), flip the TASK row via `SessionOpts.update_task_status/2` when a `task_id` is present (best-effort cast, `result: nil`, `finished_at`/lease untouched, repeat no-ops) and fire ONE `PubSub.broadcast_agents_updated/0`; a yield NEVER replies `meta.from`/`{:agent_session_result, …}` and never touches slots, worktree, rows, archives or the terminal task status.
- Close waiters live in `State.close_waiters` (`%{agent_id => [{caller_pid, from}]}`, dead callers pruned), registered by `Lifecycle.register_close_waiter/3` and flushed EXACTLY ONCE by `Lifecycle.flush_close_waiters/3` — with the terminal result, the failure term, `{:error, :cancelled}` on `cancel_agent/2`, or `{:error, :not_found}` on `recycle_agent/2`; an agent with no `SchedMeta` row answers `{:error, :not_found}` at once.
- There is NO idle TTL and no idle-timeout sweep: the session lives until close, cancellation, force kill or a crash; graceful cancel on an idle session is IMMEDIATELY terminal (the last yielded text becomes the result) while force kill uses `Session.cancel(pid, :force)` — no gate may assume `:running`.
- An interactive session is NEVER crash-retried (`Lifecycle.retry?/2` keeps the policy for `:oneshot` only): a crash replies `{:error, {:session_crashed, reason}}` to the waiters, and `Lifecycle.apply_status_updates/1` never overwrites `:awaiting_input` with a slot-derived `:running`/`:blocked`.

## Agent Lifecycle (Lifecycle module)

1. `recycle_agent/2` deletes ONLY the two ETS rows (`delete_agent_state` + `delete_sched_meta`, writing `phase: :done` first), tolerating an already-gone entry, and runs ONLY from the session-monitor `:DOWN` (`handle_agent_down/4`, `reason == :normal or meta.result_sent`) i.e. AFTER `handle_session_result/3` replied — no worktree I/O. `ref_to_agent` is popped earlier by `handle_agent_down/4`, `task_agent_counts` by the root/permanent-crash path, and the `:evogit_cancelling_tasks` marker belongs to `TaskRegistry.clear_cancelling_marker/1`.
   Consequence: the conversation lives ONLY in the stopping session's `%EvoGit.Agent.State{}`, so a transcript is unrecoverable once the session ends (archives persist `result`/usage/settings, never messages). `cancel_agent/2` is the other path: `Session.cancel(meta.session_pid, :force)` (BOUNDED; anything but `:ok` — e.g. a session stuck in `:starting` — falls back to `Process.exit(pid, :kill)`, and a `nil` pid no-ops) → manager `:DOWN` reclaim, replies to blocked callers, flushes close waiters with `{:error, :not_found}`, deletes ETS entries.
2. `handle_agent_crash/3` is the crash-RETRY policy, ONLY from `handle_agent_down/4` when `reason != :normal AND meta.result_sent == false` AND `mode` is `:oneshot` (an abnormal exit AFTER delivery is a RECYCLE). `do_handle_agent_crash/4` logs `"Retry #{meta.retries}/#{state.agent_max_retries}"` BEFORE incrementing (first crash logs `Retry 0/3`), then either RETRIES (bump `retries`, `:pending`, `session_pid: nil`, `phase: nil`, reset `phylo_node`/`context`, re-dispatch) or PERMANENTLY FAILS (subagent → `store_sub_result(parent_id, agent_id, {:error, :agent_max_retries_exceeded})` + `maybe_resume_parent/2`; root → `GenServer.reply(meta.from, …)` when `from` is not nil; both then `process_queue/1`). Neither deletes worktrees.
3. `state.agent_max_retries` (default 3, `non_neg_integer` min 0, `[:scheduler, :agent_max_retries]`) gives `1 + agent_max_retries` attempts; the wait lives in the session's start task (`Setup.bind_worktree/2` sleeps `30_000 * retries` AFTER creating the fresh worktree, so the session process stays answerable).
4. A RETURNED value (`{:error, {:llm_request_rejected, msg}}`, `{:error, :recovery_failed}`) arrives as the session's ONE `{:agent_session_result, agent_id, session_pid, result}` BEFORE its `:DOWN`; `handle_session_result/3` sets `result_sent: true`, flushes close waiters and replies `meta.from` VERBATIM for any non-`{:ok, %Result{}}` result (nil-guarded — an interactive session has no `from`), so crash-retry applies ONLY to a RAISE before delivery. After `result_sent` it injects `SchedMeta.foreign_repo_commits` via `inject_foreign_repo_commits/2` (`Map.put`, NOT struct update — the field is added by the agent stream in parallel) BEFORE the parent/root split.

## Foreign-Repo Writable Spawn Gate & Per-Repo Commit Roll-up

Writable foreign repos (`ForeignRepo.writable`, default `false`) let `:read_write` agents work in foreign repos.

- **Spawn gate order** (cross-repo `:read_write`): target writable (from `spec.foreign_repos`, never the path)? else `{:foreign_repo_read_only, msg}` → spawner ROOT (`parent.depth == 0`)? else `{:foreign_repo_write_not_root, msg}` → only accepted writable foreign spec in the batch (`spawn_validated_subagents/5` threads `writable_accepted`)? else `{:foreign_repo_write_serialized, msg}`.
- **Subtree roll-up is authority-gated** (`store_sub_result/3,4`): ONLY a child that is ITSELF a writable agent in its own foreign repo may advance `SchedMeta.foreign_repo_commits` — `repo_id` a binary `!= "primary"`, `agent_module.agent_type() == :read_write`, task-level entry `writable: true`; it rolls up its result's subtree map child-wins via `Map.merge`, then records its OWN `commit_sha` via `Map.put`. A PRIMARY or READ-ONLY child (even a probe whose `commit_sha` is its starting commit) leaves the map EXACTLY as-is.
- **Injection + getter**: that `Map.put` happens BEFORE the parent/root split, so the ROOT result carries what the runtime reads for the per-repo report; `AgentScheduler.get_foreign_repo_commits/1` returns the SPAWNING agent's OWN map (`%{}` when missing), consumed by `agent/subagent_processing.ex` to seed the next subagent phylo-node starts (precedence task-level `base_sha` → tracked sha → foreign HEAD).

## Summary row + Control Plane (the one-writer rule for `:evogit_agent_summary`)

**The agent's session is the ONLY runtime writer of its own `:evogit_agent_summary` row** (`Session.Summary.publish/3`); the rest are registration writes (`Dispatch` creates the row, `Worktrees`/`Lifecycle` update `current_commit`). The row is a SUMMARY with no conversation, so every read is a possibly-stale snapshot and every cross-process control datum lives in `ControlPlane`'s two APP-GLOBAL `:public` tables — created in `application.ex` beside the scheduler tables so they survive scheduler restarts, never purged by the scheduler:

| Table | Type | Object |
|---|---|---|
| `:evogit_agent_inbox` | `:bag`, read+write concurrency | `{agent_id, {seq, message}}`, `seq = System.unique_integer([:monotonic, :positive])` (the scheduler serializes appends, so seq order == append order) |
| `:evogit_agent_control` | `:set`, read concurrency | `{agent_id, cancel_requested}` (the flag is the only payload) |

One atomic primitive per operation, never a read-modify-write: `append_message/2` = one `:ets.insert/2` (gated on the summary row existing, else `{:error, :not_found}`); `drain_messages/1` = `:ets.take/2` (one BIF removing AND returning every object for the key, so a concurrent append is fully drained or fully left — never lost or duplicated) + `Enum.sort_by/2` on `seq`; `pending_messages/1` = `:ets.lookup/2` + the same sort (a peek, never a take); `set_cancel/2` = `:ets.insert_new/2` + `:ets.update_element(table, id, {2, value})`; `delete/1` removes both rows (`Store.delete_agent_state/1` calls it, so a recycled agent leaks nothing).
Every read is TOTAL (`:ets.whereis/1` → documented default) and every write degrades to `{:error, :not_found}`; `Store.get_agent_state/1` returns the RAW row, and `compression_count` is state-owned on the session, published by `Summary.publish/3`.

## Pending User-Message Queue (shape tolerance + the `Attachments.message/1` seam)

The `:evogit_agent_inbox` table is the ONE external injection queue, drained by the running exchange at the top of each turn into the session-owned `State.pending_inputs`. Two shapes: **legacy plain `String.t()`** stored/drained VERBATIM (byte-identical end-to-end; pinned by `lifecycle_test.exs`'s `String.contains?(&1, "being cancelled")` assertions) and the **canonical multimodal message** `%{text: String.t(), attachments: [map] | nil}`, where any atom-/string-keyed `%{text:, attachments:}` map is CANONICALIZED through **`EvoGit.Attachments.message/1`** before storing; `Attachments.validate_message!/1` enforces caps and raises a descriptive `ArgumentError` — never swallowed, nothing queued — and attachments are base64 STRING maps only.
Write: `Store.append_pending_user_message/2` (guard `is_binary or is_map`; private `canonical_pending_message/1`, then `ControlPlane.append_message/2`); read: `Store.drain_pending_user_messages/1` → `ControlPlane.drain_messages/1`, in seq order (`[]` for an absent agent). Callers: graceful cancel appends the binary `cancel_message/0`; `RemoteAPI.send_agent_message/2` → `AgentScheduler.send_user_message/2` accepts both shapes; both ride the `:agent_updated` `pending_user_messages` delta verbatim.
Delivery is best-effort and status-blind: the append checks ONLY that a summary row exists, so a message sent after the agent's final turn but before its `:DOWN` recycle returns `:ok` and is NEVER read, and once `recycle_agent/2` deleted the row (and `ControlPlane.delete/1` both control rows) every later send answers `{:error, :not_found}` — an agent cannot be messaged back to life, because its `session_pid` is gone with the ETS row.

## Graceful Cancellation (cancel_requested + `:evogit_cancelling_tasks` marker)

**`ControlPlane.cancel_requested?/1`** reads the live `:evogit_agent_control` value (`boolean() | nil`, default nil; the summary row carries no such field): set by the scheduler, checked/cleared by the exchange at the top of each turn, which then enters cancel-grace; `Store.set_cancel_requested/1,2`, `cancel_requested?/1` (`false` when missing) and `clear_cancel_requested/1` delegate to it.
**Delta-broadcast asymmetry**: `put_agent_state/2`'s struct diff emits `:agent_updated` for `@agent_state_tracked_fields`, but the queue is not a row field, so the Store helpers emit those deltas THEMSELVES (`append_pending_user_message/2` the whole new queue, `drain_pending_user_messages/1` `[]`) while the cancel flag emits NO delta (only the throttled `{:agents_updated, node}`) — keep it that way, and **any new dashboard-visible per-agent flag must be added to `@agent_state_tracked_fields`**.
**`begin_graceful_cancel/1`**: (1) registers `task_id` in `:evogit_cancelling_tasks`, a public `:set` ETS table created in `application.ex` and owned by the application process, so it survives scheduler restarts; (2) scans `SchedMeta.task_id` and per live agent appends the cancel message via **`Store.append_pending_user_message/2`** (NOT `send_user_message/2`, a self-call deadlock) + `set_cancel_requested/1`, then drives `Session.cancel(session_pid, :graceful)` and mirrors `phase: :cancelling` (best-effort; a `nil`/unreachable session is left to the drain); (3) purges the task's agents from the LLM/tool waiting queues via **`Slots.purge_agents_from_queues/2`**, replying `{:error, :cancelled}` to each blocked `from`.
Exact `cancel_message/0` text: *"The task is being cancelled by the user. Please immediately save your work: commit any uncommitted changes, then reply with a summary of what was accomplished as plain text — a reply with no tool calls ends the run and its text IS the report, so no tool call is required. You are in a grace period: finish now."*
**`clear_cancelling_task/1`** is an idempotent delete called by TaskRegistry's guarded `clear_cancelling_marker/1` at terminal transitions; **`cancelling_task?/1`** (public, `@doc false`) is the SHARED nil-safe read (missing table = not cancelling).
**Guards**: `run_agent` replies `{:error, :cancelled}` WITHOUT dispatch while the task is in the marker (blocking Genesis Mode B's second root, which shares the `task_id`), and a NEW-agent registration guard gives agents registered meanwhile (subagent spawns, crash-retries, late queued agents) the cancel message + `cancel_requested`.
**`force_kill_task_agents/1`** is a brutal reverse-depth `:brutal_kill` cascade (remove refs, purge queues, release slots, `cancel_agent/2` deepest-first), called by `TaskRegistry.force_kill_task/1`; `force_kill_task_agents_for_task/1` is the task-id sibling over the SAME cascade. **RPC**: `RemoteAPI.cancel_task/1` + `force_kill_task/1`, `RemoteNode.cancel_task/2` + `force_kill_task/2`.

## Shutdown & Restart Safety

- **No `terminate/2` in the scheduler ecosystem** (`AgentScheduler`, `Slots`, `State`, `Store`, `WorktreeManager`; the app's only one is `TaskRegistry.terminate/2`) — cleanup is purely monitor-driven. On app stop `EvoGit.Supervisor` terminates children in reverse: `AgentGroupSupervisor` FIRST, whose `one_for_all` kills `EvoGit.TaskSupervisor` (every exchange worker) + `AgentScheduler`, so all sessions die with their workers, and WorktreeManager dies before processing queued `:DOWN`s — `.genesis/workers/worker_T<n>_A<m>/` dirs and `evogit-agent-T<n>-A<m>` branches REMAIN on disk after any BEAM/app stop.
- **Next-start cleanup is the lazy per-repo init** on the FIRST create per repo, ONLY when the `:evogit_worktree_repos` marker is ABSENT and ONLY for the PRIMARY repo; nothing is cleaned at boot without a create request.
- **Task rows survive in SQLite**: `TaskRegistry.init/1` reconciles orphaned `:finalizing` → `:failed` and `:cancelling` → `:cancelled` at boot; `:running` rows fall to the one-shot `:lease_sweep` (150 s after init; `@lease_duration 120`, `@heartbeat_interval 60_000`, `@sweep_after (@lease_duration + 30) * 1000`) → `:failed` ("Lease expired; owning instance no longer renewing"). In-flight agent state (session-owned conversation plus the `pending_user_messages`/`cancel_requested` control rows) is LOST on BEAM death.
- **Slot pools are memory-only**: the restarted `%State{}` has empty pools (holders cannot leak), blocked waiters (`GenServer.call` `:infinity`) exit with the scheduler, and there is no explicit shutdown gate — only `state.paused` plus per-model capacity/backoff. The `:evogit_cancelling_tasks` marker survives scheduler restarts, not app restarts.

## Worktree Safety — Main-Copy HEAD Protection (foreign repos)

A foreign repo's MAIN working copy must never have its HEAD moved pre-merge; a main HEAD on `evogit-agent-T<task>-A<agent>` yields an EMPTY review diff.

- **`Git.clean`/`Git.checkout` are safe ONLY in a REGISTERED linked worktree — `assign_and_prepare_worktree/3` GUARDS it** via `ensure_linked_worktree/2`: `wt/.git` must be a FILE with `"gitdir: <path>"` whose `<path>` (after `Platform.safe_expand/2`) lies under `<repo_root>/.git/worktrees/`; `repo_root` is the explicit param from `prepare_new_worktree/5` (NOT `spec.phylo_node.repo`, which for subagents is the PARENT's worktree). Failure → `{:error, {:worktree_prepare_failed, :not_a_linked_worktree}}` with NO git run. `rev-parse --git-common-dir` is unusable: it reports `<repo_root>/.git` for a real worktree AND for a plain dir inside the repo tree.
- **`delete_branch_tolerant/2` RECOVERS git's "cannot delete branch used by worktree"** (both wordings, via `branch_in_worktree?/1`): the stale registration is dropped by `retry_on_transient(fn -> Git.prune_worktrees(repo_root) end)`, then the delete retries ONCE; a branch live in a worktree survives → `{:error, output}` (never force-deleted). Crash-retry interleavings fail safely: a stale `:DOWN` destroy can delete a fresh branch, so `git checkout` errors and main HEAD stays put.
- **LLM cd-escape into the repo root is HARD-BLOCKED at the tool layer**: `do_execute/5` (`agent/tools/shell_tool.ex`) calls `main_copy_mutation_error/3` first — if ANY resolved cd target equals `Path.expand(repo_root)` AND the command matches `@mutating_git_regex` `\bgit\s+(checkout|switch|reset|merge|pull)\b`, it returns an error string and NOTHING executes (`@cd_regex` covers absolute, dot-relative and plain relative targets; `cd_targets/2` resolves via `Platform.safe_expand/2`). `detect_cd_warnings/3` stays warning-only.

## Multi-Repo Identity: a flat `[%ForeignRepo{}]` list, NO mount/workspace layer
The scheduler's whole multi-repo vocabulary is a flat list plus a string `repo_id`; mounts/virtual-tree grouping have no representation to hook into.
`%EvoGit.Core.ForeignRepo{}` is `[:id, :root, :description, writable: false, base_sha: nil]` (no parent, mount point or ordering; `"primary"` is the only special id), and `AgentState.foreign_repos` is the task-level list copied in at registration, inherited verbatim with no update path.
Root resolution is a LOOKUP, never a tree walk (`resolve_agent_repo_root_regular/2`: strip `"/.genesis/workers/"` for `"primary"`, else `Enum.find` by `spec.repo_id`), and a foreign repo reuses the primary worktree/branch conventions under its own root.
`ContextNode` carries `repo_id`, but the context READ drops it (2-arity `hierarchy_nodes/2` tags every node `"primary"` and resolves against the agent's OWN worktree), so nothing cross-repo is keyed by `{repo_id, path}`; `ContextMerge` and `Shared.validate_file_scope/4` stay repo-agnostic, and the sole repo-aware file gate is the read-only-foreign-repo check via `ForeignRepo.resolve_path/2`.

## Windows-Only Runtime Risks

Windows-only failure modes; NONE is test-covered (the suite runs on Linux/macOS).

- **`run_init_script/3` spawns a BARE executable name**: without a shebang `shell` = `Platform.shell()` = `"powershell"`, and `:os.find_executable/1` → `ErlangError :enoent` on a miss (OTP's win32 resolver hardcodes `[".exe", ".com", ".cmd", ".bat"]`, never PATHEXT, and tries cwd LAST; built-in `WorktreeInitScript` windows variants carry NO shebang). Elsewhere the class IS guarded (`Sandbox.None.resolve_executable/1`, `Git.gh_available?/0`); `worktrees.ex` is not.
- **`run_init_script/3` is NOT sandbox-wrapped**: the `genesis.toml` `[worktree]` script runs through a raw `System.cmd/3` with `cd: repo_root`, so a repo-supplied script executes with the BEAM user's full authority (no filesystem isolation, no timeout, no `ProcessManager` record) at every worktree creation.
- **Create-path raises fail safely**: `run_init_script/3` has no `try`/rescue, so a raise reaches `run_create/6` → `{:error, {:worktree_create_failed, "worktree create raised: ..."}}` while `after` still releases the permit.
- **No POSIX-only process handling**: no `:os.cmd`, `kill`/`os_pid`/negative-pgid kill, `chmod` or `sh -c` — kills are `Task.shutdown/2` + monitor reclaim, git resolves through `EvoGit.Executable.resolve/1`, and a stuck create holds its permit until `{:create_finished, agent_id}`.
- **Windows path normalization is load-bearing and HOLDS — do not "fix" it**: `Path.join/2` emits `/` and `Path.expand/2` normalizes `\` → `/`, the ONLY reason `repo_root_from_worktree/1`'s split works; a raw backslash path fails to strip → `:not_a_linked_worktree` (fail-safe), and `branch_name/2` has no character illegal in a Windows ref.

## AgentScheduler GenServer Hub (`agent_scheduler.ex`)

Agent lifecycle, the interactive-session commands, yield/resume admission, per-model LLM/tool slot pools, config updates, cancellation markers and startup reconciliation; sub-logic lives in `agent_scheduler/`.
Its ~1520 lines exceed the ~1000-line baseline as PRE-EXISTING debt (`RemoteAPI`, `ToolDispatch` are similar); a split is a dedicated refactor, not a drive-by edit.
**Lazy config-read rule (do not regress)**: single-key reads inside the scheduler MUST use the private `config_value/2` — `config_map/1` evaluates `Platform.sandbox_backend()` and `Sandbox.capabilities()` on every call, which regressed the system_sampler tests; it serves ONLY the full `:get_config` reply, and `@config_keys` (16) enumerates the fields.
**`init/1` is O(#model profiles) and KB-scale**: `:ets.whereis` warnings only, `Config.resolve()`/`Config.credentials()`, `Schema.effective_model_profiles/1`, empty pools via `State.from_model_profiles/2`, one best-effort `ReqLLMPool.reconcile/1` no-op — no SQLite query, `.genesis/workers` scan, PubSub subscribe or timer.
**The llm_db catalog load happens BEFORE this process starts, in `EvoGit.CatalogWarmup`** (a `:ignore` child immediately before the scheduler): the first metadata resolution decodes the ~11.7 MB snapshot, builds indexes and leaves the durable store in `:persistent_term` (`:llm_db_store`), so the transient heap dies there instead of sitting in the scheduler; `init/1` only performs WARM lookups that re-resolve without copying (`../config/schema/CONTEXT.md`), a scheduler restart never re-pays the load, and a config with ZERO models does no catalog work (gate: the `:llm_model_metadata_fun` seam or a profile list with no `model`).
`Slots`, `Store`, `PubSub` and `RemoteAPI` are PLAIN modules (no GenServer/init/ETS/timer/`:pg`); the only other process here is `PubSub.Throttle` (state: one timer ref), and every live agent adds exactly two outside this subtree (its session + one short-lived exchange worker) — `../agent/session/CONTEXT.md`.
`task_local_counters` is NEVER pruned (`task_agent_counts` is), so one ~100-byte entry per task_id accumulates for the scheduler's lifetime; nothing purges `:evogit_agent_summary` and `init/1` resets `next_agent_id: 1`, so a scheduler-only crash leaves dead agents' rows until the ids are reused.

## Task-Scoped Resource Inventory (per-task on-disk artifacts + teardown hooks)

- **The ONLY on-disk artifact this subtree creates is the worktree** (`.genesis` git-ignored), removed in EXACTLY one function — `destroy_worktree/3` → `rm_rf_retry`, then prune, then branch delete — whose extra CREATE-path helpers are `Worktrees.destroy_leftovers/3` and `Git.remove_leftover_worktree_dir/1`.
- **Background jobs rooted under a worktree are REAPED first** (`safe_reap/1` → `BackgroundJobs.reap_under(worktree_path)` IMMEDIATELY BEFORE `rm_rf_retry`); a dead/timed-out registry degrades to a logged no-op.
- **Reclaim follows AGENT PROCESS DEATH, never task completion**; `recycle_agent/2`/`cancel_agent/2`/`handle_agent_crash/3` do ETS deletes only, and the `:finalizing`/merge path never touches worktrees.
- **The managed per-task scratch dir is NOT scheduler-owned**: `EvoGit.TaskTmpdir` is created and reclaimed by `EvoGit.TaskRegistry` (`TaskExecutor.ensure_task_tmpdir/2`), `:per_repo` placing it at `<primary repo>/.genesis/tmp/task_<id>` (orphaned by an app crash).
- **Cancel teardown touches NO disk** (marker + pending message + queue purge; force kill adds the brutal kills) and **archive state is persisted per agent, never buffered in RAM**; this subtree writes NOTHING under `EvoGit.Platform.data_dir/0`.

## Known Issues

- **A create pipeline that hangs FOREVER holds one admission permit, and its blocked caller is not cancellable by timeout**: `create_worktree_for_agent/6` waits `:infinity` while the create runs in an unlinked `Task.start` nothing kills, so a create stuck in a blocking syscall (wedged NFS, anti-virus holding the tree) neither fails nor returns; `creating_count` only decrements on the `{:create_finished, agent_id}` cast, so four such creates saturate the default cap of 4 and `admission_queue` starves silently (no stall detection or logging). Escapes: force-kill / graceful-cancel the task (its monitor moves the `:creating` registration to `pending_cleanup`, but the create task and its permit survive); restart `WorktreeManager` (resets `creating_count`); restart the BEAM (orphans the stuck worktrees).
  A SESSION caller of that call is now bounded even though the manager is not: the session runs the whole setup in ONE monitored start task (`agent/session/CONTEXT.md`), warns at `:worktree_create_slow_warn_ms` (120 s default), fails the session with the terminal `{:error, {:worktree_create_stalled, ms}}` at `:worktree_create_stall_timeout_ms` (1 800 s default), and accepts `{:cancel, :force}` while `:starting` — none of which touches the stuck create or its permit. A DIRECT caller still waits `:infinity`.

## Constraints

- Data structs are plain data with no behaviour/callbacks; `Slots`, `Worktrees`, `Dispatch`, `Subagents`, `Lifecycle`, `State` are pure functions over `State.t()`, and GenServer state must always be `%State{}` (struct update, not `Map.put/3`).
- `AgentState` is shared (scheduler + agent processes); `SchedMeta` is scheduler-exclusive.
- The scheduler process NEVER calls git, does blocking filesystem I/O, or calls ANY worktree function: git work happens in the agent's exchange worker (and the session's start task for its worktree create), and ALL worktree filesystem operations (rm_rf, mkdir_p, prune_worktrees, delete_branch) belong to `WorktreeManager`. The only worktree call is the session's `Setup.bind_worktree/2` → `create_worktree_for_agent/6` (`:infinity`, SESSION pid monitored, exactly one reply, `:DOWN` reclaim).
- Slot availability is derived from holder MapSets, never a counter. `SchedMeta.session_pid` stores the agent's `EvoGit.Agent.Session` pid (cancelled through `EvoGit.Agent.Session.cancel/2`); `ref_to_agent` keys on the session monitor ref.
- `case`/`with` guards on ETS lookups only where a genuine race can make the entry absent (`recycle_agent`, `try_dispatch`, `cancel_agent`).

## Per-message timestamp metadata convention

Every message in an agent's session memory (`%ReqLLM.Message{}` list in `%ReqLLM.Context{}.messages`, held in the session-owned `%EvoGit.Agent.State{}.context`) carries `metadata[:timestamp]` — **Unix seconds** (`EvoGit.Agent.Clock.now_seconds/0`: the real clock by default, and an exchange or turn can PIN it through the opts `:now` key, e.g. in a test comparing two exchanges), an atom-keyed integer like `:turn`, stamped at message-CREATION time in agent code, never in the Store.
**Single choke point — `ContextBuilder.tag_message_turn/2`** (`agent/context_builder.ex`): every message the loop produces passes through it, setting BOTH `metadata[:turn]` and `metadata[:timestamp]` idempotently via `Map.put_new` (the value comes from `EvoGit.Agent.Clock`, a per-process pin with no app-env default); `tag_message_timestamp/1` stamps just the timestamp (nudge + compression-summary sites), and the creation-site inventory lives in `agent/CONTEXT.md`.
**`Store` never writes conversation data** and **no read-back exists** — the dashboard reads `msg.metadata[:timestamp]` from `RemoteAPI.get_agent_history/1`. An integer is timezone-agnostic (`DateTime` deliberately avoided) and **the dashboard reads it as Unix SECONDS** (`EvoDashWeb.Helpers.format_history_timestamp/1`) — do NOT change granularity without updating evo_dash.
