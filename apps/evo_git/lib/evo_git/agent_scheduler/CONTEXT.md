# Agent Scheduler — Data Structures, Helpers & Scheduler Hub

## Intent

Structs and helpers behind the `EvoGit.AgentScheduler` GenServer (hub: `../agent_scheduler.ex`).
`%AgentState{}` SUMMARY rows (no conversation, no control state) live in `:evogit_agent_summary`, written by the agent's own `EvoGit.Agent.Session` plus registration; `%SchedMeta{}` rows live in scheduler-exclusive `:evogit_sched_meta`.
Cross-process control lives in `ControlPlane`'s `:evogit_agent_inbox`, `:evogit_agent_control` and `:evogit_task_pause` (§Control Plane), created by `EvoGit.Application` with no heir so they outlive a scheduler crash that resets `%State{}`.
Helpers are pure over `State.t()` except the GenServers `WorktreeManager` and `PubSub.Throttle`.

## Routing Table

One module per file: `model_selection.ex` (schema/dispatch adapter), `session_opts.ex`, `interactive_root.ex`, `state.ex`, `agent_state.ex`, `control_plane.ex`, `sched_meta.ex`, `slots.ex`, `tool_permits.ex`, `store.ex` (ETS helpers — NOT `EvoGit.Store`), `worktrees.ex`, `worktree_manager.ex`, `worktree_retry.ex`, `salvage.ex`, `foreign_worktree.ex`, `spawn_facts.ex`, `resume_plan.ex` (the ONE resume/retry decision), `dispatch.ex`, `subagents.ex`, `subagent_reattach.ex`, `subagent_rebuild.ex`, `lifecycle.ex`, `pubsub.ex`, `throttle.ex`, `remote_api.ex`; hub `../agent_scheduler.ex`.

## Direct-Eval / Assistant API Safety

`RemoteAPI` is a mixed read/write RPC facade, not an authorization boundary: admission registry, tier rules and per-admitted-API shape caveats belong to `../agent/tools/elixir_eval/CONTEXT.md`.
Admitted in BOTH tiers: `RemoteAPI.list_agents/0`, `AgentScheduler.get_config/1`, `paused?/0`, `get_llm_slot_status/0`; the write tier adds `AgentScheduler.update_config/1`, `pause/0`, `resume/0` and `RemoteAPI.reload_config/0`.
Unlisted MFAs and wrong arities stay denied and refusal never escalates a tier; admitted calls run the real API unchanged and return its ACTUAL value — truncation is not redaction (`get_agent_state/1` = the native `%AgentState{}` summary, no conversation; `get_agent_history/1` proxies `Session.history/1`, TOTAL `[]` within 5 s for a gone session).

## Reload and runtime-update contracts

`RemoteAPI.reload_config/0` = `Config.resolve/0` → `build_reload_opts/1` → `AgentScheduler.update_config/1`, with no local validation, exception containment, file write or transaction.
`build_reload_opts/1` requires only an outer map and emits atom-keyed scheduler/sandbox maps — `ModelSelection.config_opts/1`'s model options, `default_llm_max_concurrency`, `max_tool_concurrency`, `agent_max_retries`, `max_depth` (from `max_agent_depth`), `max_retries`, `max_turns`, `max_turns_root`, plus `sandbox_mode`/`sandbox_resources`/`sandbox_process_resources` — dropping nils.
`RemoteAPI.save_user_config/1` persists via `Config.save_user_config/1` then reloads BEST-EFFORT: a reload error, a caller-side timeout or an exit is logged with `Logger.warning` and the save still answers `:ok` (the file already landed, no rollback); only a genuine persistence failure returns `{:error, reason}`, and a raise inside `reload_config/0` still escapes (`safe_call/1` catches exits only; the per-process `with_reload_fun/2` seam keeps the reload testable). `save_credentials/1` delegates without reload.
`State.do_update_config/2` consumes those keys plus `llm_model`, `llm_generation_params`, `model_concurrency` and `model_concurrency_skip_floor`, ignores unknown keys and applies NO type/range/schema validation: an explicit nil IS assigned, profile rebuilding needs a genuine profile-list/map shape, and any truthy skip-floor grants the bypass.
Profile replacement keeps live holder/waiter/backoff/last-granted maps and non-LLM state but rebuilds profile concurrency and default generation parameters; a direct `llm_model` assignment alone does not rewrite `model_profiles`.
That branch logs ONE `Logger.warning`, BEFORE `ModelSelection.update_opts/2`, when `legacy_replacement?/1` holds while a canonical snapshot is installed (`provider_profiles != []` or `model_selection_config != nil`), naming the consequence (`:model_spec_schema_unavailable`) and the `config_opts/1` / `build_reload_opts/1` remedy; the reply stays `:ok`.
Every update sweeps available slots, broadcasts a config change and (Linux) enqueues an asynchronous slice update, so `:ok` is not confirmation of OS application; nothing here persists files, rewrites existing agents' ETS snapshots or survives reinitialization.
`RemoteAPI.reload_config/0` is the ONLY route that re-reads disk (`Config.Cache.reload/0` at `remote_api.ex:197`); dispatch, `start_session/1`, `get_config/0,1` and `get_agent_*` NEVER read config files, so a selection/profile value served from scheduler state can be no fresher than the last `update_config/1`.
`ModelSelection.config_opts/1` has exactly three production callers — `State.from_config/2` (boot, `state.ex:179`), `RemoteAPI.build_reload_opts/1` (`remote_api.ex:273`) and the dashboard's `SettingsLive.ConfigIO.runtime_model_opts/1` — and returns `[model_profiles:, provider_profiles:, model_selection_config:]` for a canonical `llm.providers` config (and for a legacy `llm.models` config whose accounts the schema migrates, because `providers != []`), else `[model_profiles:]` alone (`model_selection.ex:18-44`).
The selection snapshot is invalidated ONLY by `ModelSelection.update_opts/2` (`provider_profiles: []`, `model_selection_config: nil` on a legacy replacement, `model_selection.ex:72-75`) and by `from_model_profiles/2` rebuilding the three fields; nothing caches or re-derives it per read, so a cleared snapshot stays cleared until the next `update_config/1`/restart.
`%State{}`'s `sandbox_backend`/`sandbox_capabilities` are a LAZY MEMO: both start `nil` (unprobed for the current config identity), the first `config_value/2` read computes one and stores it back (the single-key and map forms share the memo through `Enum.map_reduce`), and `State.do_update_config/2` clears both — the ONE handler every config-refresh route funnels through (`RemoteAPI.reload_config/0`, `save_user_config/1`, dashboard config pushes, PeakHourEngine patches) — so `EvoGit.Platform.sandbox_backend/0`'s PATH cascade runs once per config identity instead of once per read.
The probe seam is the DEFAULT-INERT call-time `Application.get_env(:evo_git, :sandbox_backend_probe_fun)` (arity 0; production never sets it).

## Agent identity: parent_id & depth (root ⇔ parent_id nil ⇔ depth 0)

- `register_agent/8` (7-arity defaults `opts` to `[]`) is the only writer: ROOT (`nil`/0) and NESTED (`parent_id`, `parent.depth + 1`); depth is never derived by walking a parent chain.
- Depth reaches the agent as `dispatch_ctx` `depth:` → `Session.Setup.bind_worktree/2` (`Process.put(:evogit_agent_depth, depth)`) and `Setup.build_initial_state/3` into `%State{}.depth`; crash-retry resets preserve identity (`phylo_node: nil, context: nil`). The writable-foreign-repo root check is `parent_depth == 0` (`validate_single_subagent/5` → `validate_spatial_contract_for_spec/4`; the `/3` form hardcodes `0`).
- Root-only custom-agent `max_turns` uses `if is_nil(parent_id)`; a repo-less `:reflect` ROOT registers `parent_id: nil, depth: 0`, so it gets `max_turns_root` (1000), not 128.
- `Dispatch.resolve_max_turns/3` (private) NEVER reads `spec.opts[:max_turns]` (no such key exists): the only turn-cap sources are a root custom-agent definition's positive-integer `max_turns` and the scheduler's `max_turns`/`max_turns_root`.

## Task Spawn, Registration & Dispatch (run_agent)

`run_agent/2` is a BLOCKING boundary (`GenServer.call(..., :infinity)`) returning `{:ok, %Result{}} | {:error, reason} | {:paused, info}`; the scheduler, never the session, replies the caller's `from`, and both clauses may answer `{:error, :llm_not_configured}`.
`spec.phylo_node.current_commit` arrives pre-resolved by `Runtime.Helpers.resolve_starting_commit/2`: nil → `PhyloGraphNode.current_head/1` (unborn HEAD = structured error), a ref → `Git.rev_parse(repo_path, ref <> "^{commit}")`, failure → `{:error, {:invalid_starting_commit, ref, repo_path, git_output}}`; sources are a task `:starting_commit` opt, resume (`commit_sha`) and Genesis Mode B (`architect_output.commit_sha || base_sha`).
Order: `task_id` from `spec.opts[:task_id]` (else random hex) → refuse `{:error, :cancelled}` while the task is in `:evogit_cancelling_tasks` → guarded archive reset `maybe_reset_task_archives/2` (SKIPPED when `spec.opts` carries a pause `:resume_kind`, so a paused roster survives the same task id; any other run takes `reset_task_archives/1`) → `resolve_agent_repo_root/2` + `next_task_number/1` → `register_agent/7` (`phylo_node: nil`, no explicit id) → paused ? queue : `try_dispatch/2`.
**Registration allocates by default and ADOPTS an explicit id on request**: an optional `opts[:agent_id]` (the id a previous run of the SAME logical agent persisted) is taken when FREE, else `state.next_agent_id`; both rows are INSERTed without reading an existing row, and no path looks a row up by `task_id`/`objective` (only `agent_ids_for_task/1` scans by task).
Free means `SpawnFacts.agent_id_free?/1`: `EvoGit.Agent.Session.whereis/1` (the AUTHORITY — the unique-name registry) then the non-terminal summary row; a taken id fails CLOSED with `{:error, {:agent_id_taken, id}}` writing NOTHING, a non-positive/non-integer `:agent_id` is IGNORED, and the counter only moves to `max(counter, id + 1)`.
`AgentSpec.opts` keys consumed here are exactly `:task_id`, `:model_spec`, `:model_id_locked`, `:default_model_spec`, `:archive`, `:persistent_state`, plus `:repo_less`, `:custom_agent_id`, `:attachments`, `:quality_level` in `Setup.install_process_context/3`; this subtree has NO `:history`/`:messages`/`:chat`/`:conversation`/`:session`/`:resume_from`/`:multi_turn` option.
The initial `[system, user]` conversation is built FRESH after the session's start task binds the worktree (`Setup.build_initial_state/3` → `ContextBuilder.build_initial_messages/4`) and only THEN published; `do_register_agent/8` never writes `:context` and crash retry clears it. Re-dispatch of the SAME id happens ONLY on crash retry (`current_commit` reset, fresh `%State{}`); a WAITING parent is resumed in place by `Subagents.dispatch_ready_parent/3`.
`try_dispatch/2` computes `worktree_path = <repo_root>/.genesis/workers/worker_T#{task_number}_A#{task_local_id}`, stores it in SchedMeta BEFORE starting anything (so `cancel_agent` finds it), adds `session_mode`, `persistent_state`, `restore_agent_state`, `worktree_resume_from`, `retry_reason`, `scheduler: self()` and — only on a pause resume — `resume_kind`, starts the session under `EvoGit.Agent.Session.Supervisor`, then monitors it + `ref_to_agent` + `status: :running`/`session_pid`/`phase: :starting`; `{:error, {:already_started, pid}}` is tracked like a fresh start, while any other start failure is logged and routed through `Lifecycle.handle_agent_crash/3` as `{:session_start_failed, reason}` (meta stays `:pending`, bounded retry, parent/root replied at permanent failure).
**Durability flags (`do_try_dispatch/4`, private)**: the ctx carries `persistent_state: Keyword.get(spec.opts, :persistent_state, true) != false` (TASK-WIDE, default `true`; a non-boolean falls back to `true` because the registry validates it earlier) and `restore_agent_state: (retries > 0 or resume_kind != nil or spec.opts[:restore_agent_state] == true) and <that boolean>` — `true` on a crash RETRY of the SAME `agent_id`, a task-level PAUSE RESUME and a RE-SPAWNED child carrying the honest flag, so a rebuilt session merges its persisted conversation onto a fresh dispatch (same identity, new worktree/repo path).
The only git work on the dispatch path is `ResumePlan`'s `Salvage.commit_exists?/2` verification (resume/retry dispatches only) plus `Worktrees.ensure_resume_base/4` inside the worktree create (resumed runs only).
The session's start TASK requests the worktree (`Setup.bind_worktree/2`, SESSION pid as owner); the prepared commit lands on the summary row and is advanced by `ToolDispatch.sync_current_commit_after_tools/1` at each turn checkpoint (published by `Summary.publish/3`).
Subagent phylo nodes (`build_subagent_phylo_node/6`): explicit `commit_id` validated by `Git.rev_parse`, else the parent's `current_commit`; cross-repo uses tracked `foreign_repo_commits` or foreign HEAD.
**Repo root resolution**: per-agent `AgentState.repo_root` first, then `Process.get(:genesis_repo_root)` (set/re-installed by `Setup.bind_worktree/2` and `install_process_context/3`, read via `current_repo_root/0`) — no global `state.repo_root`; repo-init tracking lives in `WorktreeManager`, running = `map_size(state.ref_to_agent)`.

## Resume & Retry Plan (`ResumePlan.plan/5`)

`ResumePlan.plan/5` (`@doc false` delegator `Dispatch.resume_plan/5`) returns exactly `:spec, :meta, :worktree_resume_from, :persistent_state, :restore_agent_state, :resume_kind, :branch`.
**Branch**: the persisted `resume_branch` when the dispatch is a pause resume or carries `restore_agent_state: true` (and it is non-empty), else the fresh `branch_name/2`.
**Base**: the first USABLE candidate of `spec.opts[:pause_commit]` → `spec.opts[:resume_current_commit]` → `meta.crash_commit`, each verified with `Salvage.commit_exists?/2` and degrading to the next (all unusable → the task base with `worktree_resume_from: nil`); the chosen sha is rewritten into `spec.phylo_node.current_commit` (so `create_worktree/6` needs no new argument) and the caller's single `Store.put_sched_meta/2` persists the rewritten meta.
Resolution runs ONLY when the dispatch carries resume input at all (`:resume_kind` set, `:restore_agent_state` true, ANY of `:pause_commit`/`:resume_current_commit`/`:resume_branch`/`:resume_agent_id` PRESENT — a resolved `nil` is a fact too — or a non-empty `meta.crash_commit`), so a first attempt makes ZERO extra git calls.
`spec.opts[:pause_commit]` is PRE-RESOLVED by `EvoGit.TaskRegistry.Pause.resume/4`: only a DIRECT dispatch lacking the key falls back to ONE bounded `EvoGit.TaskRegistry.AgentStateRead.pause_commit/3` read (2 s, degrading to `nil`), so the scheduler GenServer never blocks on `agent_state.sqlite`.
**Branch reuse**: a resolved persisted branch is normalized into `spec.opts[:worktree_branch]` (durable-state dispatches only, and only when it differs from the fresh name) because `prepare_new_worktree/5` later runs with only `spec`/`meta` in hand; `branch_for/3` then names both the ctx `:branch` and the git branch, `destroy_leftovers/3` deletes that branch and `Git.add_worktree/4` re-creates it at the base sha.
**Anchor-based base repair**: `Worktrees.ensure_resume_base/4` repairs an unusable resolved base, called only for a resumed run and TOTAL throughout (verified spec base → the sha `spec.opts[:resume_anchor_ref]` / `AgentState.Anchor.ref(task_id, agent_id)` points at → the existing branch's own sha → the task base, ONE warning on total failure).
**Identity reuse**: `Dispatch.resume_registration_opts/1` (`@doc false`) answers `[agent_id: id]` for a positive-integer `spec.opts[:resume_agent_id]`, else `[]`; on `{:error, {:agent_id_taken, id}}` the caller re-registers WITHOUT it and logs ONE warning.

## Subagent Spawn Fan-Out Bounds & Deadlock Surface

- **Registration is EAGER at accept** (`:pending` → `:running` + immediate spawn; `state.queue` exists only while paused) and the worktree is created EAGERLY at child start, so a child HOLDS a worktree while blocked on an LLM slot; a WAITING parent keeps its live worktree too (reclaim is `:DOWN`-only) and holds NO slot — capping LIVE worktrees/agents with queueing can deadlock, whereas the implemented cap bounds CREATE-pipeline concurrency and cannot.
- `max_depth` — `[:scheduler, :max_agent_depth]`, `:pos_integer`, default `8`, `[min: 1]`; `validate_subagent_depth/3` → `{:error, :max_depth_exceeded}`; `Turn.effective_tools/1` drops subagent schemas at max depth. Bounds DEPTH only.
- **Batch size is UNBOUNDED**: one reduce over the subagent tool calls of ONE LLM response (`SubagentSchemas.schemas/1` has `path`/`objective`/`commit_id`, no `maxItems`), gated by `max_agent_depth`, `:path_ignored`, the spatial contract, one-writable-foreign-repo-per-batch, `{:error, :scheduler_paused}` and `:llm_not_configured`; the scheduler GenServer is never blocked.
- **Defensive ETS lookups**: `Store.get_sched_meta/1`/`get_agent_state/1` return `{:ok, x} | :error`, so four sites degrade when a parent is reaped mid-spawn — `spawn_validated_subagents/5` (replies `[{:error, :parent_recycled}]` per spec, bailing BEFORE the `:waiting` mutation), `store_sub_result/3,4` (→ `:ok`), `maybe_resume_parent/2` and `dispatch_ready_parent/3` (still replies/resets meta, logs `"unknown"`). Covered by `subagents_test.exs` + `pubsub_test.exs`.

## Blocking Surface (ONE GenServer serves every agent)

Every turn-path scheduler interaction is a plain `GenServer.call` into the ONE `EvoGit.AgentScheduler` mailbox, so inline work in a handler delays every other agent's slot grant, release, config read and pause/cancel probe.
`request_llm_slot/2` and `request_tool_slot/2` default to `timeout \\ :infinity`, so a queued caller waits silently; the wait shows only as the `:llm_waiting` activity `Sink.start_call/1` sets BEFORE `with_llm_slot/2`, so queueing renders as "Waiting for model capacity", never `:idle`.
Inline work that stalls all slot traffic:
- `Lifecycle.retry_agent/4` → `WorktreeManager.salvage_for_retry/2` on EVERY abnormal session `:DOWN` (budget `Salvage.timeout_ms() + @salvage_call_grace_ms` = 20 s), the salvage commit + `rm_rf_retry` + `git prune` + branch delete running inline.
- `{:run_agent, …}` → `maybe_reset_task_archives/2` (synchronous `Store.delete_task_archives/1`) + `Dispatch.next_task_number/1` (`File.ls` of `.genesis/workers`).
- `{:update_config, …}` → `reconcile_pool_after_update/1` (`ReqLLMPool.reconcile/1` → `Finch.set_pool_count`).
- `{:DOWN, …}` → `Slots.release_agent_slots/2` + `grant_pending_llm_slots/1`, each a full pass over `State.all_model_ids/1`.
- `{:force_kill_task_agents_for_task | :begin_graceful_cancel | :begin_task_pause, …}` → `Store.list_sched_meta/0` full scan + per-agent ETS writes + queue purges.
The scheduler owns NO periodic scan or heartbeat: its only timers are the per-account backoff sweep (`:retry_llm_waiting`) and the sub-agent re-attach timeout, and `SystemSampler` is the only periodic external caller (3 s, `get_llm_slot_status/0`, cheap map reads).
A crash RETRY sleeps `30_000 * retries` in the session's start task (`agent/session/setup.ex`, after the fresh worktree exists) — 30/60/90 s of registered `:running` with no `:llm_waiting` activity, so the dashboard shows "Idle".

## Slot Management (Slots + ToolPermits)

LLM slots use agent-ID `MapSet`s; availability derives from `MapSet.size/1`, and session `:DOWN` removes the agent from both pools and purges its queued requests.
Tool capacity is granted as per-call permits: `ToolPermits` provides `make_ref()` permits attributed to an agent and monitored on the acquiring caller, with synchronous transfer to a new owner and idempotent synchronous release.
`handle_release(permit, caller_pid, state)` releases only the current owner's permit; a missing or non-owner release answers `{:reply, :ok, state, []}` without granting waiters or mutating state, so a former executor cannot free a transferred background permit (the `self()` form is for direct owner calls only, never hub routing); `handle_transfer(permit, new_owner_pid, state)` authorizes by the unguessable permit reference, not caller ownership.
`occupancy/1` counts legacy holders plus granted permits without copying the queue; explicit permits count separately even for the same agent, share capacity and ONE FIFO queue with legacy agent-keyed tool slots, and survive config rebuilding in `State.tool_permits`/`State.tool_permit_monitors`.
Legacy `request_tool_slot`/`release_tool_slot` stay one-holder-per-agent with serialized ownership (queued callers monitored, dead ones discarded before grant); tool requests queue FIFO as `{agent_id, from}` when paused or full, queued grants emit `:running`, enqueues emit `:blocked`.
`Slots.release_agent_slots/2` purges waiting requests with the existing cancellation reason, drops every attributed explicit permit and demonitor-flushes owners before granting capacity; pause/cancel queue purges preserve `:paused`/`:cancelled` and do not revoke holders.
The hub delegates `acquire_tool_permit/1`, `transfer_tool_permit/2` and `release_tool_permit/1` to `ToolPermits`, routes their calls through `permit_reply/1` to apply status updates, passes the releasing caller pid to `handle_release/3`, and routes every process DOWN through `ToolPermits.handle_down/2` before agent lifecycle handling.
`with_tool_slot/2` acquires a per-call permit and synchronously releases that exact reference in `after`, with a transferred permit protected from the former owner's release.
Handlers: `handle_request_llm_slot/3`, `handle_request_tool_slot/3`, `handle_release_llm_slot/2`, `handle_release_tool_slot/2` (the latter two via `handle_cast`), `release_agent_slots/2` and `grant_pending_on_resume/1` (also at the END of every config update, so 0→N grants queued waiters); sync ops return `{:reply, :ok, state, status_updates}`, async releases `{state, status_updates}`, and `status_updates` = `{agent_id, :blocked | :running}` written to SchedMeta.
`default_llm_max_concurrency` is a DEFAULT per-LLM concurrency, NOT a global cap: `concurrency_for/2` prefers `model_concurrency[pool_id]`, else the default, the map being filled only at config-load time (legacy config yields `model_concurrency["default"]`); **a runtime override is a FLOOR** — `State.apply_default_llm_concurrency_override/2` sets the default AND raises every entry to `max(c, N)` (explicit `0` stays `0`), while an account concurrency above the default still wins.
Detached-job permit acquisition, handoff and terminal release belong to `background_jobs.ex`; worktree cleanup calls `BackgroundJobs.reap_under/1` first.

| Pool | State keys | Capacity | Backoff |
|---|---|---|---|
| LLM | `llm_holders`, `llm_waiting`, `llm_backoff_until`, `llm_last_granted` | **per-account** `model_concurrency[pool_id]` (account `concurrency`, default 3), fallback `default_llm_max_concurrency` (3) via `State.concurrency_for/2` | **per-account** on `:rate_limit` AND `:insufficient_balance` (HTTP 402) — caller duration (default 60 s, clamped to `@max_timer_ms`), self-rescheduling sweep; one account never blocks others |
| Tool | `tool_holders`, `tool_waiting`, `tool_permits`, `tool_permit_monitors` | `max_tool_concurrency` (default `EvoGit.Platform.cpu_threads/0`) | None |

## Worktree Lifecycle (WorktreeManager + Worktrees)

**Fresh per agent run** — no pool, no reuse across retries.

1. **Lazy per-repo init** on the FIRST create for a repo: rm_rf `.genesis/workers` → `git worktree prune` → orphaned `evogit-agent-*` cleanup → mkdir_p (never from the scheduler), gated on the persistent `:evogit_worktree_repos` marker: PRESENT (manager-only restart) → wipe skipped, only `mkdir_p_retry/2`; ABSENT (first request or genuine BEAM restart) → full wipe, then record. Destructive steps are **PRIMARY-ONLY** (`ForeignRepo.primary?/1` on `spec.repo_id`); foreign repos get prune + mkdir_p + marker. `mkdir_p_retry` raises `File.Error` on exhaustion — safe because the marker is written before the first worktree exists.
2. **Request path**: `create_worktree_for_agent/6` (`:infinity`) offloads to a MONITORED Task replying exactly once (the result, or `{:error, reason}` when the create fun raises/throws/exits or the task dies silently) plus the `{:create_finished, agent_id}` permit-release cast.
3. **Create pipeline** (`prepare_new_worktree/5`): destroy leftover dir/branch (rm_rf failure escalates) → CoW create (fallback `Git.add_worktree`; failure → `{:error, {:worktree_create_failed, msg}}`) → `assign_and_prepare_worktree/3` → `run_init_script/3` (genesis.toml `[worktree]` script, primary only; env `SOURCE_REPO_PATH`/`SOURCE_WORKTREE_PATH`/`TARGET_WORKTREE_PATH`; Windows via `Platform.shell_args/1`).
4. **Monitor-based reclaim**: `:DOWN` for ANY reason (including after a successful completion) → `destroy_worktree/3` in FOUR ordered steps: `BackgroundJobs.reap_under(worktree_path)` under `safe_reap/1` → `rm_rf_retry/2` → only AFTER the dir is gone `Git.prune_worktrees(repo_root)` → `delete_branch_tolerant(repo_root, branch_name)`. An rm_rf failure logs ERROR and skips prune + branch delete (a surviving dir with its `.git` file + registration is safe; a pruned partially-removed dir becomes a PLAIN unregistered dir — the leak precondition). Idempotent; `recycle_agent/2`, `cancel_agent/2` and permanent failure never delete worktrees; after a manager-only restart `rebuild_monitors/1` re-monitors live agents from `:evogit_sched_meta` + `:evogit_agent_summary`, skipping missing/stale rows.
   An **ABNORMAL** death (`Salvage.abnormal_exit?/1` rejects `:normal`/`:shutdown`/`{:shutdown, _}`) salvages FIRST (`Salvage.salvage/3`: stage-all + commit the crashed run's dirty state, anchored at `refs/genesis/salvage/<branch_name>` because reclaim deletes the agent branch) and retains the sha in `state.salvaged` (newest 64, in-memory only); `salvage_for_retry/2` answers `Lifecycle` (salvaging on demand while the agent is `:live`, else the retained entry) and stores it as `SchedMeta.crash_commit`. A salvage error/timeout (`:worktree_salvage_timeout_ms`, 15 000) logs at WARNING and reclaims as before.
   Reclaim is keyed ONLY by the agent process monitor — never by task completion — and the ETS rows are deleted by `Lifecycle.recycle_agent/2`, not here.
   `task_number` comes from `Dispatch.next_task_number/1` (`File.ls` for `worker_T<n>_` maxima, `1` when missing) ONCE per task from the ROOT's repo root and every subagent inherits it — each repo owns its own `.genesis/workers`, so dir and branch names REPEAT across repos (unique per repo, never task-globally).

## Persistent Foreign-Repo Worktrees (ForeignWorktree)

`ForeignWorktree` owns the PERSISTENT worktree of every WRITABLE non-primary foreign repo at `<root>/.genesis/foreign_repos/<id>` (`ForeignRepo.worktree_path/1`) — a stable READ view of the latest committed state, addressable by absolute path (`ForeignRepo.resolve/2`, `ContextBuilder.build_foreign_repos_section/1`).
It lives OUTSIDE `.genesis/workers/`, so the primary-only wipe and `destroy_worktree/3`/`destroy_leftovers/3` never touch it, MAIN HEAD never moves and it is NOT torn down at task end; a foreign agent's WRITE workspace stays its ephemeral worktree.
API: `start_commit/1` (`base_sha` else repo HEAD), `ensure/2` (idempotent create-or-reset; non-writable → no-op; create = `mkdir_p_retry` → detached `Git.add_worktree` → prune + one retry; update = `Git.checkout(wt, sha)` with `Git.reset_hard/2` fallback), `ensure_all/1` (best-effort, never raises), `sync_from_agent/0`, `worktree_path/1`.
**Hooks**: `Runtime.Helpers.load_foreign_repos/2` calls `ensure_all/1` after validating (before any spawn); `Session.Worker.run/3`'s `try/after` calls `sync_from_agent/0` after `commit_pending_in_worktree/0` on EVERY exit path, advancing the agent's OWN repo worktree (id-matched via `Process.get(:evogit_repo_id)`) to `Process.get(:repo_path)`'s HEAD — no-op for primary/repo-less agents, last-writer-wins.
`ensure_all/1` filters to `writable == true and not ForeignRepo.primary?(repo.id)` (an entry literally named `"primary"` is never provisioned), and `sync_from_agent/0` advances only `writable` entries.

## Subagent Management (Subagents module)

1. `spawn_validated_subagents/5` validates all specs, registers valid ones and replies immediately if all are invalid; the parent commits pending changes BEFORE calling `spawn_sub_agents`, which blocks (`timeout \\ :infinity`) until every child completes. The hub's `{:spawn_sub_agents, …}` handler reads the parent row with an explicit `case` (a gone row → `{:reply, {:error, :not_found}, state}`, the row being a best-effort mirror) after the `{:error, :scheduler_paused}` check.
2. `validate_single_subagent/5` → `validate_subagent_depth/3`, `validate_subagent_not_ignored/1`, `validate_spatial_contract_for_spec/4` + `validate_spawn_spatiality/4`; width is NOT code-limited (§Fan-Out Bounds). Cross-repo: `:read` at ANY depth; `:read_write` only into a repo whose TASK-LEVEL `spec.foreign_repos` entry (never the path alone) is `%{writable: true}` and only from a ROOT parent; same-repo spawns inside a foreign repo are unrestricted.
3. `store_sub_result/3,4` — the 4th arg carries the COMPLETING CHILD's `%AgentSpec{}` (or nil) and gates foreign-commit recording via `writable_foreign_repo_agent?/1` (public, `false` for non-`%AgentSpec{}`); then `maybe_resume_parent/2`, `dispatch_ready_parent/3`, `build_ordered_results/2`.
4. **Crash-resume of a batch**: `dispatch_ready_parent/3` replies ONLY to a LIVE `{pid, _tag}` waiter; a `nil`/dead one (the crash-retried parent's OLD exchange worker) is never replied and the completed batch is RETAINED (`sub_agent_from: nil`, `status: :running`, `pending_sub_agents` cleared, results/indices/total kept). `maybe_resume_parent/2` never re-dispatches it, and a later `spawn_validated_subagents/5` discards the stale waiter/timer for a FRESH batch.
   Claim it with `reattach_sub_agents(agent_id, expected_count \\ nil, opts \\ [])` → `{:ok, results}` (ordered, missing slots `{:error, :subagent_result_lost}`) | `{:error, :no_pending_batch}` (no/empty/mismatched/already-delivered) | `{:error, :unavailable}`; `opts[:timeout]` → app env `:agent_resume_reattach_timeout_ms` → 1_800_000 ms, validated at call time. A pending batch installs the caller as waiter and, on expiry, marks still-missing slots lost and leaves the parent `:running`; `Lifecycle.retry_agent/4` deliberately KEEPS every batch field.
5. **Durable rebuild**: `{:error, :no_pending_batch}` is not terminal — the resumed parent builds a plan from the children's durable rows (`EvoGit.Agent.Resume.RosterBatch`, in the agent worker) and calls `rebuild_subagent_batch(parent_id, plan, opts)` → `{:ok, results}` (same shape) | `{:error, :no_pending_batch | :batch_in_flight | :invalid_plan | :unavailable}` (all leave the row untouched). It installs the batch fields + caller as waiter (`SubagentReattach.put_waiter/4`), contributes a `done` child's stored result, re-spawns a `running` child under its persisted `agent_id` (persisted spawn position + resume opts) and answers a missing row `{:error, :subagent_result_lost}`; a re-spawned child repeats this for ITS children, so resume is recursive, with the re-attach timer as backstop.

## Session-Owned Lifecycle & Crash Retry

Every agent is ONE `EvoGit.Agent.Session` started by `Dispatch.do_try_dispatch/4` under `EvoGit.Agent.Session.Supervisor`; `ref_to_agent` keys on the session monitor ref while `SchedMeta.session_pid`/`mode`/`phase` are a best-effort mirror (live phase truth: `EvoGit.Agent.Session.inspect/2`).
The ONE terminal delivery `{:agent_session_result, agent_id, session_pid, result}` arrives BEFORE the session stops and is admitted only when `SchedMeta.session_pid` is `nil` or equals the sender (else logged at `:debug` and ignored); a session START failure routes through `Lifecycle.handle_agent_crash/3` as `{:session_start_failed, reason}` with bounded retry.
Crash retry runs ONLY from `handle_agent_down/4` on an abnormal reason with `result_sent` false: salvage the crashed worktree (`SchedMeta.crash_commit`), increment `retries`, reset `current_commit`, install a fresh `%State{}` (identity preserved) and re-dispatch the SAME `agent_id`; `:oneshot`-only (`retry?/2`), so a crashed interactive session replies `{:error, {:session_crashed, reason}}`.
`Lifecycle.recycle_agent/2` deletes ONLY the two ETS rows (`phase: :done` first) and runs ONLY from the session `:DOWN` after `handle_session_result/3` replied — no worktree I/O, so a transcript survives nowhere once the session ends; `cancel_agent/2` instead force-cancels the session (bounded `Session.cancel/2`, any non-`:ok` → `Process.exit(pid, :kill)`, `nil` pid no-op), reclaims via the manager `:DOWN`, replies blocked callers and flushes close waiters.
Close waiters live in `State.close_waiters` (`%{agent_id => [{caller_pid, from}]}`, dead callers pruned), registered by `register_close_waiter/3` and flushed EXACTLY ONCE by `flush_close_waiters/3` (`{:error, :not_found}` at once with no `SchedMeta` row); `apply_status_updates/1` never overwrites `:awaiting_input` with a slot-derived `:running`/`:blocked`, and `inject_foreign_repo_commits/2` rolls a child's commits into `SchedMeta.foreign_repo_commits` (child wins).

## Interactive Sessions (root-only)

The SAME session in `mode: :interactive` yields to `:awaiting_input` instead of finishing and keeps its worktree, conversation and `prompt_cache_key` (contract: `../agent/session/CONTEXT.md`); it is LIVE but not BUSY (no worker, slot or timer), so `/server/status` counts only `:running`/`:pending`/`:cancelling`/`:finalizing` task ids while `list_awaiting_input/0` names the idle sessions an upgrade gate winds down.
`start_session/1` → `{:ok, pos_integer()} | {:error, reason}` (NON-BLOCKING; keyword input via `SessionOpts.build/1`, unknown → `{:error, {:invalid_session_opts, {:not_a_session_spec, other}}}`); `send_session_message/3` and `close_session/1` → `:ok | {:error, {:session, reason}}` (close is the ONLY non-cancellation exit from `:awaiting_input`; `:bad_policy`/`:bad_target`/`:bad_message`/`:exit` nest inside `:session`); `await_close(agent_id, timeout \\ 30_000)` → `{:ok, %Result{}} | {:error, :not_found | :timeout | term()}`, replied exactly ONCE; `list_awaiting_input/0` → `[%{agent_id, task_id, session_pid, task_number, mode}]`; `force_kill_task_agents_for_task/1` → `:ok | {:error, :not_found}` (the ONLY way to reach a `from: nil` agent).
`await_close/2` is race-free only with `notify: {self(), tag}`, the waiter registered BEFORE starting, then matching `{:agent_session_closed, tag, result}`; the budget bounds the WAIT alone and `{:error, :timeout}` leaves the session running.
`SessionOpts.build/1` + `force_interactive/1` normalize `session_mode`/`notify`/repo-less/model selection and reject a non-root request (`depth` other than `0`/absent, or a present `parent_id`) with `{:error, {:interactive_root_only, message}}`; `Dispatch.session_mode/2` forces `:oneshot` for `depth != 0` and `register_agent/8` mirrors `SchedMeta.mode` (unknown → warn + `:oneshot`).
Yield/resume are NON-terminal, admitted only from the current `session_pid` (`admit_signal/2`, stale senders dropped), flip the TASK row via `update_task_status/2` when a `task_id` exists (best-effort cast, `result: nil`, lease untouched), fire ONE `broadcast_agents_updated/0`, and never reply `meta.from` or touch slots/worktree/rows/archives.
No idle TTL and no idle sweep: the session lives until close, cancellation, force kill or a crash, and a graceful cancel on an idle session is IMMEDIATELY terminal (the last yielded text is the result).
`start_session/1` performs NO config I/O: `handle_call({:start_session, …})` gates only on `llm_configured?(state)` (`model_profiles` non-empty — `../agent_scheduler.ex:1750-1752`), then `do_start_session/2` (`:1754-1798`) registers and resolves against the boot-or-reload snapshot with no `Config.resolve/user_config/credentials`, `Config.Cache.reload`, `Config.Watcher.notify_change`, `ModelSelection.config_opts/1` or `update_config` call.
A successful start therefore proves the SCHEDULER's RAM selection resolves (not that `config.toml` is readable at that instant, and it cannot heal another surface's stale model list); it emits only `"agents"` events (`{:agent_registered, …}` / `{:agent_updated, …}` / `{:agents_updated, node}` from `Store.put_sched_meta`/`put_agent_state`, `store.ex:64-91`/`142-163`), never `"config"` or `"scheduler_config"`.

## Control Plane

`ControlPlane` owns `:evogit_agent_inbox` (`:bag` of `{agent_id, {seq, message}}`), `:evogit_agent_control` (`:set` of `{agent_id, cancel_requested, pause_requested}`) and `:evogit_task_pause` (`:set` of `{task_id}`), and every write is an ATOMIC ETS primitive (`:ets.take/2`, `:ets.insert_new/2` + `:ets.update_element/3`) — never a whole-struct read-modify-write.
`append_message/2`/`drain_messages/1`/`pending_messages/1` move `{seq, message}` items and an append needs a LIVE session; `ensure_row/1`, `set_cancel/2`/`cancel_requested?/1`, `set_pause/2`/`pause_requested?/1`, `mark_task_pausing/1` and `delete/1` are the rest; every reader is TOTAL (a missing row/table reads `false`) and `EvoGit.AgentScheduler.Store` (never `EvoGit.Store`) is their thin ETS facade.

## Cancellation & Task Pause

`begin_graceful_cancel/1` sets the `:evogit_cancelling_tasks` marker, sets every agent's cancel flag, appends ONE save-work user message through `Store.append_pending_user_message/2` (NEVER `send_user_message/2` — a scheduler self-call deadlocks) and clears the pause marker + pause flags BEFORE that work; the session finishes its phase within the 3-turn grace budget and persists `:cancelled`, while a force kill kills sessions and persists `:failed` with result nil'd.
`begin_task_pause/1` is the reverse order and lands at a TURN BOUNDARY only (never mid-tool): `mark_task_pausing/1` → `set_pause_requested/1` per agent → `Slots.purge_agents_from_queues/3` with reason `:paused`, so queued requests die while holders keep their slots until the turn ends (the cancel purge uses `:cancelled`).
An agent reports `{:paused, %{agent_id, task_id, checkpoint, branch, reason: :task_pause}}` — neither `%Result{}` nor an error — after reaping background jobs and committing its checkpoint (`WorktreeManager.checkpoint_for_pause/1` → `agent_states.pause_commit`).
Cancel WINS over a pause, a pause during `:cancelling` is IGNORED (`cancel_requested?/1` short-circuits), and `:paused`/`:pausing` tasks stay force-killable.
A pause FREEZES the whole tree: `begin_task_pause/1` opens ONE `%TaskFreeze{}` over the live roster, replies `{:freeze, :task_pause}` to every parent blocked in `spawn_sub_agents/2` (`Subagents.park_for_pause/2`, which also CLEARS its batch fields) and answers a later `spawn_sub_agents/2` for that task `{:freeze, :task_pause}` while registering nothing; every agent then reports `{:paused, info}` to the freeze, NOBODY is answered until the LAST pending agent reports, and that ONE task-level term (`{:paused, %{pause_kind: :clean | :dirty, frozen_agents: [...]}}`) answers the ROOT's caller and its `await_close/2` waiters. A paused child NEVER reaches `store_sub_result/4`, fills no parent batch and merges nothing; a report with no freeze in flight is ignored with one warning. Boot `init/1` reconciliation and the one-shot `:lease_sweep` (150 s; `@lease_duration` 120 s, `@heartbeat_interval` 60_000 ms) map a stale `:running`/`:pausing` row to `:paused` + `pause_kind: :dirty` when resumable, else `:lease_expired` → `:failed`.

## Worktree Safety, Multi-Repo Identity & Windows

`ensure_linked_worktree/2` accepts a worktree only when `wt/.git` is a FILE whose `"gitdir: <path>"` resolves INSIDE `<repo_root>/.git/worktrees/`; `main_copy_mutation_error/3` + `@mutating_git_regex` block any command that cd-escapes into the repo root and mutates the MAIN copy.
The scheduler process performs no blocking FS I/O and no worktree call (creation, reclaim and salvage run in `WorktreeManager`); `Salvage.commit_exists?/2` is the only git call it makes inline.
Multi-repo identity is `spec.repo_id` (`"primary"` or a foreign id) plus an already-absolute root — never a path prefix — and `SchedMeta.foreign_repo_commits` (STRING ids) is the only tracked cross-repo commit map.
`run_init_script/3` is NOT sandbox-wrapped and spawns a bare `"powershell"` on Windows (PATH-resolved, not `Executable.resolve/1`), so a PowerShell-less host fails at worktree-create; Windows path normalization (`Path.join/2` → `/` before git calls) is LOAD-BEARING — do not "fix" it.

## GenServer Hub & Inventory

Hub surface: `run_agent/2`, `start_session/1`, `send_session_message/3`, `close_session/1`, `await_close/2`, `send_user_message/2`, `pause/0`, `resume/0`, `update_config/1`, `get_config/1`, `get_llm_slot_status/0`, `acquire_tool_permit/1`/`transfer_tool_permit/2`/`release_tool_permit/1`, `reattach_sub_agents/3`, `rebuild_subagent_batch/3`, `get_foreign_repo_commits/1`, `force_kill_task_agents_for_task/1`, `get_agent_state/1`.
The live-agent roster read is NOT a hub call: `EvoGit.AgentScheduler.RemoteAPI.list_agents/0` maps over `:evogit_sched_meta` + `:evogit_agent_summary` directly, and the cancel body is `Lifecycle.cancel_agent/2`.
Single-key config reads inside the hub use the LAZY `config_value/2` (never build the whole `config_map/1` for one key); `EvoGit.CatalogWarmup` runs BEFORE `AgentScheduler` so the scheduler retains no transient catalog heap; `state.next_agent_id` is seeded at boot from `AgentStateRead.max_agent_id/1` (2 s budget, degrade `0`); `task_local_counters` is never pruned, because a task-local id must not repeat.
Broadcast asymmetry: queue/slot deltas originate in the `Store` helpers, the cancel flag emits NO delta, and a new dashboard-visible per-agent flag MUST join `@agent_state_tracked_fields` or it never reaches the UI.
The two status vocabularies never mix (`SchedMeta`: `:pending | :running | :waiting | :ready | :blocked | :awaiting_input`; `AgentState`: `:running | :awaiting_input | :cancelling | :done | :failed`); `task_agent_counts` holds per-task live counts and `next_task_number/1` owns task-scoped naming only.

## Constraints

- One module per file (hub aside); `store.ex` here is `EvoGit.AgentScheduler.Store`, never `EvoGit.Store`.
- Helpers stay PURE over `State.t()` except the two GenServers (`WorktreeManager`, `PubSub.Throttle`); the scheduler never blocks on FS, on git beyond `Salvage.commit_exists?/2`, or on `agent_state.sqlite`.
- No `terminate/2` cleanup exists in this ecosystem (only `EvoGit.TaskRegistry.terminate/2`), so a monitor-driven shutdown leaves worktree dirs and branches on disk until the next lazy per-repo init wipes them — never assume a clean tree after a restart.
- `remote_api.ex` is a long cohesive RPC facade shared with `../remote_node.ex`: add functions there (`defnode` for identity-unwrap wrappers, hand-written per-function fallbacks) and never split it.
- Liveness/timing seams are read at CALL time (`Application.get_env(:evo_git, key, default)`), never cached at compile time.
- Messages carry `metadata[:timestamp]` from `EvoGit.Agent.Clock.now_seconds/0`; tests pin it per process with the default-inert `Clock.with_now/2`, never through an app-env global.

## Known Issues

- A hung create leaks its admission slot: `creating_count` drops only when the create task reports back, so a task that never returns stalls the creation queue until the manager restarts.
- `WorktreeManager.workers_dir/1` is public but has no caller.
- `rebuild_monitors/1` has NO repo-less guard, so after a manager-only restart a repo-less agent's `:DOWN` runs `git prune` plus a branch delete inside the SOURCE ROOT (`rm_rf` of its synthetic path no-ops).
- Interactive sessions are never crash-retried, so a session crash loses that conversation; only `agent_state.sqlite` keeps a durable record.
- **A canonical default account with no resolvable model DEGRADES loudly, never crashes**: when `model_selection_config` is a map and `ModelSelection.resolve(seed, nil)` errors (`{:model_not_found, id, nil}` for a half-saved account with an empty `models` list and no `default_model`), `State.from_model_profiles/2` logs `"Default model selection is unresolvable: … (provider account \"<id>\"); the agent scheduler is falling back to NO default model, …"` and falls back to the SAME non-schema default (`{nil, []}` via `fallback_default_tuple/2`), so `AgentScheduler.init/1` and every `{:update_config, _}` — including `RemoteAPI.reload_config/0` after a partially-saved provider account — keep the GenServer alive with `llm_model: nil` and the account pools intact. Explicit per-task `model_spec` selections are unaffected: `ModelSelection.resolve/2` still fails closed with its unchanged errors (`{:model_not_found, id, model}`, `{:provider_profile_not_found, id}`, `:model_spec_schema_unavailable`). Pinned by `test/evo_git/agent_scheduler/model_selection_regression_test.exs` + `remote_api_test.exs` ("reload_config/0").
- `AgentScheduler.get_config/0` (`agent_scheduler.ex:1341`) exposes `:model_profiles` and `:provider_profiles` but NOT `:model_selection_config` (`@config_keys`, `agent_scheduler.ex:1546-1564`), so a caller cannot distinguish "no models configured" from "canonical snapshot cleared"; there is no scheduler model-list RPC at all (only `get_config/0,1`), and the map form is an uncontained 5 s `GenServer.call` whose `:sandbox_backend` key can run a PATH probe.
