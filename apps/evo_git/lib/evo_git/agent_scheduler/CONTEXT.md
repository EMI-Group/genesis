# Agent Scheduler — Data Structures, Helpers & Scheduler Hub

## Intent

Structs and helpers behind the `EvoGit.AgentScheduler` GenServer (hub: `../agent_scheduler.ex`).
`%AgentState{}` SUMMARY rows live in ETS `:evogit_agent_summary` (one runtime writer: the agent's own `EvoGit.Agent.Session`, plus registration writes); `%SchedMeta{}` rows live in scheduler-exclusive `:evogit_sched_meta`.
Cross-process control lives in the `ControlPlane` tables `:evogit_agent_inbox`, `:evogit_agent_control` and `:evogit_task_pause` (§Summary row + Control Plane).
All four tables are created and owned by `EvoGit.Application`, never the scheduler, and have no heir: they must outlive a scheduler crash (which kills `EvoGit.TaskSupervisor`, i.e. every exchange worker, and through them all sessions via the `:one_for_all` `AgentGroupSupervisor`; `%State{}` resets while the tables keep stale rows).
Helpers are pure over `State.t()` except the GenServers `WorktreeManager` and `PubSub.Throttle`.

## Routing Table

Leaf directory, one module per file: `model_selection.ex` (schema/dispatch adapter), `session_opts.ex` (interactive `start_session/1` opts → `%AgentSpec{}`, session helpers), `interactive_root.ex` (interactive-root session-shape predicate), `state.ex`, `agent_state.ex`, `control_plane.ex`, `sched_meta.ex`, `slots.ex`, `tool_permits.ex`, `store.ex` (ETS helpers — NOT `EvoGit.Store`), `worktrees.ex`, `worktree_manager.ex`, `worktree_retry.ex`, `salvage.ex`, `foreign_worktree.ex`, `spawn_facts.ex` (agent-id/spawn facts + `build_dispatch_ctx/6`), `resume_plan.ex` (the ONE resume/retry decision), `dispatch.ex`, `subagents.ex`, `subagent_reattach.ex`, `subagent_rebuild.ex`, `lifecycle.ex`, `pubsub.ex`, `throttle.ex`, `remote_api.ex`; hub `../agent_scheduler.ex`.

### RemoteAPI review surface (arbitrary repo_path; task-level review status)

Review RPCs are `repo_path`-first (the CALLER supplies it), so one RPC serves the primary and every writable foreign repo; shapes are `EvoGit.Review`'s verbatim (`../../CONTEXT.md`).
Surface: `get_file_content/3`, `list_commits/2`, `load_review_data/2`, `load_review_metadata/2`, `load_review_metadata_from_shas/3`, `list_commits_from_shas/3`, `load_file_diff/4,5`, `load_commit_files/2`, `load_commit_file_diff/3`, `check_merge/3`, `merge_branch/2,3`, `default_merge_target/1`, `list_branches/1`, `reject_branch/2`, `create_github_pr/4`, `branch_exists?/2`, `list_commit_graph/3`, `list_task_commit_graph/4`.
`list_commit_graph/3` → `{:ok, %{commits: [commit], refs: %{sha => [ref_name]}}}` (atom-keyed `:sha, :short_sha, :message, :author_name, :author_email, :date, :parents`); `list_task_commit_graph/4` resolves its base as `opts[:base_sha]` → task/foreign `base_sha` → `Git.merge_base` and adds `truncated: boolean`.
`set_review_status/2` + `set_review_metadata/3` key on `task_id` ONLY (per-repo outcomes live in dashboard assigns); `get_foreign_repo_commits/1` is NOT an RPC.
`RemoteNode` mirrors `list_tasks_page/2` (deliberate asymmetry vs the only `select_`-named RPC `select_tasks_page/1`, which delegates to `TaskRegistry.list_tasks_page/1`), `get_task_lite/2`, `list_task_archives/3`, `get_agent_archive/3`, `list_commit_graph/4`, `list_task_commit_graph/5`, returning the Store's degraded shape on transport failure (`../store/CONTEXT.md`); guards exist only on `send_agent_message/2`, `get_recent_system_samples/0`, `respond_approval/2`.

### Project-mount surface (Virtual Context Tree)

`RemoteAPI.projects/0` returns PROJECT mounts ONLY as `[%EvoGit.VCT.Mount{}]` newest first (a reserved mount such as `vct:///genesis-source` and a workspace never appear unless `:include_workspaces` is requested), `[]` when nothing is mounted or the VCT is down.
`mount_project(path, name)` → `{:ok, mount} | {:error, :relative_path | :store_unavailable | :vct_unavailable}`; `forget_project(key)` → `:ok | {:error, :not_found | :invalid_point | :reserved_point}`, accepting a VCT point, an OS path or a bare workspace name.
`RemoteAPI.workspaces/0` lists WORKSPACE mounts (`kind: "workspace"`, no OS path) newest first, `[]` when none exist or the VCT is down; `create_workspace(name, members, opts)` → `{:ok, mount} | {:error, reason}`, an idempotent slug-keyed upsert degrading to `{:error, :vct_unavailable}`.
`workspace_members(point)` → `{:ok, %{workspace:, members:, missing:, nested:}} | {:error, :not_found | :not_a_workspace | :invalid_point | :vct_unavailable}` (an unreachable VCT is `:vct_unavailable`; `:not_found` stays reserved for a genuinely absent workspace); `workspace_entries(opts \\ [])` flattens and resolves EVERY workspace's members in ONE round trip (`[%{workspace:, members: [%{point:, name:, path:}], missing:, nested:}]`, `:limit` supported); `workspaces_for(ref)` lists the workspaces containing a point or OS path.
`RemoteNode` mirrors them as `projects/1`, `mount_project/3`, `forget_project/2`, `workspaces/1`, `create_workspace/4`, `workspace_members/2`, `workspace_entries/2`, `workspaces_for/2` — local-direct else `call_remote/4`, a failed transport degrading to `[]` for list reads and `{:error, {kind, reason}}` for the rest.
Every mount mutation emits its ONE `{:vct_updated, node}` on the target node; these RPCs add no notification of their own.

### Push-only streaming watch surface (cross-node)

`RemoteAPI.register_watcher/2`, `unregister_watcher/2` and `watch_snapshot/1` are thin passthroughs to `EvoGit.Agent.Stream` under `Stream`'s own 5 s session deadline — ONE implementation, no second session-call path.
They are LOCAL-node session calls (session, watcher set and transcript live where the agent is owned); the snapshot is heavy full-transcript while deltas are PUBLISHED, so a disconnected cluster silently delivers no deltas while the attach still succeeds. Shapes and gating: `../agent/stream/CONTEXT.md`.

## Direct-Eval / Assistant API Safety

`RemoteAPI` is a mixed read/write RPC facade, not an authorization boundary: the admission registry, tier rules and per-admitted-API shape caveats belong to `../agent/tools/elixir_eval/CONTEXT.md`.
Admitted here in BOTH tiers: `RemoteAPI.list_agents/0`, `AgentScheduler.get_config/1`, `paused?/0`, `get_llm_slot_status/0`; the write tier adds `AgentScheduler.update_config/1`, `pause/0`, `resume/0` and `RemoteAPI.reload_config/0`.
Unlisted MFAs and wrong arities stay denied; refusal never escalates a tier.
Admitted calls run the real API with unchanged arguments and return its ACTUAL value — output truncation is not redaction; `get_agent_state/1` returns the native `%AgentState{}` summary (no conversation) and `get_agent_history/1` proxies `Session.history/1` (TOTAL `[]` within 5 s for a gone session).

## Reload and runtime-update contracts

`RemoteAPI.reload_config/0` = `Config.resolve/0` → `build_reload_opts/1` → `AgentScheduler.update_config/1`, with no local validation, exception containment, file write or transaction.
`build_reload_opts/1` requires only an outer map and emits atom-keyed scheduler/sandbox maps: `ModelSelection.config_opts/1`'s model options, `default_llm_max_concurrency`, `max_tool_concurrency`, `agent_max_retries`, `max_depth` (from `max_agent_depth`), `max_retries`, `max_turns`, `max_turns_root`, plus `sandbox_mode`/`sandbox_resources`/`sandbox_process_resources` (from `mode`/`resources`/`process`), dropping nils.
`RemoteAPI.save_user_config/1` persists via `Config.save_user_config/1` then reloads BEST-EFFORT: a scheduler-side reload error, a caller-side `GenServer.call` timeout, or an exit is logged with `Logger.warning` and the save still answers `:ok`, because the file already landed and there is no rollback. Only a genuine persistence failure returns `{:error, reason}`; a raise inside `reload_config/0` still escapes (`safe_call/1` catches exits only; the per-process `with_reload_fun/2` seam keeps the reload step testable). `save_credentials/1` delegates without reload.
`State.do_update_config/2` consumes those keys plus `llm_model`, `llm_generation_params`, `model_concurrency` and `model_concurrency_skip_floor`, ignores unknown keys and applies NO type/range/schema validation: an explicitly present nil IS assigned, profile rebuilding needs a genuine profile-list/map shape, and any truthy skip-floor grants the bypass.
Profile replacement keeps live holder/waiter/backoff/last-granted maps and non-LLM state but rebuilds profile concurrency and default generation parameters; a direct `llm_model` assignment alone does not rewrite `model_profiles`.
That branch logs ONE `Logger.warning`, BEFORE `ModelSelection.update_opts/2`, when `ModelSelection.legacy_replacement?/1` holds while a canonical snapshot is installed (`provider_profiles != []` or `model_selection_config != nil`), naming the consequence (`explicit model_spec selections will no longer resolve` → `:model_spec_schema_unavailable`) and the `ModelSelection.config_opts/1` / `build_reload_opts/1` remedy; the reply stays `:ok`.
Every update sweeps available slots and broadcasts a config change, and Linux sandbox-resource changes enqueue an asynchronous slice update, so `:ok` is not confirmation of OS application; nothing here persists files, rewrites existing agents' ETS snapshots or survives reinitialization.
Persistence is `Config.resolve/0,1` + `Config.save_user_config/1`, which replaces the WHOLE config.toml and invalidates its cache without reloading the scheduler.

## Throttled PubSub

- The `:agent_registered` `summary` has EXACTLY `status, depth, parent_id, task_id, task_number, objective` — NOT `message_count`/`agent_module` (only `list_agents/0` has those); `message_count` arrives via `:agent_updated` deltas.

## Agent identity: parent_id & depth (root ⇔ parent_id nil ⇔ depth 0)

- `register_agent/8` (7-arity form defaults `opts` to `[]`) is the only writer: ROOT (`nil`/0) and NESTED (`parent_id`, `parent.depth + 1`); depth is never derived by walking a parent chain.
- Depth reaches the agent as `dispatch_ctx` `depth:` → `Session.Setup.bind_worktree/2` (`Process.put(:evogit_agent_depth, depth)`) and `Setup.build_initial_state/3` into `%State{}.depth`; crash-retry resets preserve identity (`phylo_node: nil, context: nil`). The writable-foreign-repo root check is `parent_depth == 0` (through `validate_single_subagent/5` → `validate_spatial_contract_for_spec/4`; the `/3` form hardcodes `0`).
- Root-only custom-agent `max_turns` uses `if is_nil(parent_id)`; a repo-less `:reflect` ROOT registers `parent_id: nil, depth: 0`, so it gets `max_turns_root` (1000), not 128.
- `Dispatch.resolve_max_turns/3` (private) NEVER reads `spec.opts[:max_turns]` (no such key exists): the only turn-cap sources are a root custom-agent definition's positive-integer `max_turns` and the scheduler's `max_turns`/`max_turns_root` (boot from `[scheduler]`, runtime-changeable only by `update_config/1`, for future registrations).

## Task Spawn & Starting-Commit Flow (run_agent)

`run_agent/2` is a BLOCKING boundary (`GenServer.call(..., :infinity)`) returning `{:ok, %Result{}} | {:error, reason} | {:paused, info}`; the scheduler, never the session, replies the caller's `from`.
`spec.phylo_node.current_commit` arrives pre-resolved: `Runtime.Helpers.resolve_starting_commit/2` maps nil → `PhyloGraphNode.current_head/1` (unborn HEAD = structured error) and a ref → `Git.rev_parse(repo_path, ref <> "^{commit}")`, failure → `{:error, {:invalid_starting_commit, ref, repo_path, git_output}}`; sources are a task `:starting_commit` opt, resume (`commit_sha`) and Genesis Mode B (`architect_output.commit_sha || base_sha`).
`run_agent/2` (both clauses may reply `{:error, :llm_not_configured}`): `task_id` from `spec.opts[:task_id]` (else random hex) → refuse `{:error, :cancelled}` while the task is in `:evogit_cancelling_tasks` → guarded archive reset `maybe_reset_task_archives/2` (SKIPPED when `spec.opts` carries a pause `:resume_kind`, because a resume re-runs the same task id and the paused run's per-agent roster must survive; any other run takes the byte-identical `reset_task_archives/1`) → `resolve_agent_repo_root/2` + `next_task_number/1` → `register_agent/7` (`phylo_node: nil`, no explicit id) → paused ? queue : `try_dispatch/2`.
**Registration allocates by default and ADOPTS an explicit id on request**: `register_agent/8` takes optional `opts[:agent_id]` (the id a previous run of the SAME logical agent persisted) and otherwise allocates `state.next_agent_id`; both rows are INSERTed without reading an existing row, and no path looks a row up by `task_id`/`objective` (only `agent_ids_for_task/1` scans by task).
An explicit id is adopted only when FREE — `SpawnFacts.agent_id_free?/1` asks `EvoGit.Agent.Session.whereis/1` (the AUTHORITY: the unique-name registry that makes one session per agent id structural) then the non-terminal summary row — and a taken one fails CLOSED with `{:error, {:agent_id_taken, id}}`, writing NOTHING; a non-positive/non-integer `:agent_id` is IGNORED and the counter only ever moves to `max(counter, id + 1)`.
`AgentSpec.opts` keys consumed here are exactly `:task_id`, `:model_spec`, `:model_id_locked`, `:default_model_spec`, `:archive`, `:persistent_state`, plus `:repo_less`, `:custom_agent_id`, `:attachments`, `:quality_level` in `Setup.install_process_context/3`; this subtree has NO `:history`/`:messages`/`:chat`/`:conversation`/`:session`/`:resume_from`/`:multi_turn` option.
The initial `[system, user]` conversation is built FRESH in the session's start path after its start task binds the worktree (`Setup.build_initial_state/3` → `ContextBuilder.build_initial_messages/4`) and only THEN published; `do_register_agent/8` never writes `:context` and crash retry clears it.
Re-dispatch of the SAME id happens ONLY on crash retry (row `current_commit` reset, fresh `%State{}`); a WAITING parent is resumed in place by `Subagents.dispatch_ready_parent/3`, which replies its blocked `from` and never rebuilds a session, so it needs no restore flag.
`try_dispatch/2` computes `worktree_path = <repo_root>/.genesis/workers/worker_T#{task_number}_A#{task_local_id}` and stores it in SchedMeta BEFORE starting anything (so `cancel_agent` finds it), adds `session_mode`, `persistent_state`, `restore_agent_state`, `worktree_resume_from`, `retry_reason`, `scheduler: self()` and — only on a pause resume — `resume_kind: :clean_pause | :dirty_pause` to `dispatch_ctx`, starts the session under `EvoGit.Agent.Session.Supervisor`, then monitors it + `ref_to_agent` + `status: :running`/`session_pid`/`phase: :starting`.
`{:error, {:already_started, pid}}` is tracked like a fresh start; any other start failure is logged and routed through `Lifecycle.handle_agent_crash/3` as `{:session_start_failed, reason}` (meta stays `:pending`, bounded retry, parent/root replied at permanent failure).
**Durability flags (`do_try_dispatch/4`, private)**: the ctx carries `persistent_state: Keyword.get(spec.opts, :persistent_state, true) != false` (TASK-WIDE, default `true`; a non-boolean falls back to `true` because the registry validates it earlier) and `restore_agent_state: (retries > 0 or resume_kind != nil or spec.opts[:restore_agent_state] == true) and <the same boolean>` — `true` on a crash RETRY of the SAME `agent_id`, a task-level PAUSE RESUME and a RE-SPAWNED child carrying the honest flag, so a rebuilt session merges its persisted conversation onto a fresh dispatch (fresh worktree/repo path, same identity) while a first attempt always starts clean.
`ResumePlan.plan/5` (reached via the `@doc false` delegator `Dispatch.resume_plan/5`) returns exactly `:spec, :meta, :worktree_resume_from, :persistent_state, :restore_agent_state, :resume_kind, :branch`.
The only git work on the dispatch path is `ResumePlan`'s `Salvage.commit_exists?/2` verification (resume/retry dispatches only) plus `Worktrees.ensure_resume_base/4` inside the worktree create (resumed runs only).
The session's start TASK requests the worktree (`Setup.bind_worktree/2`, SESSION pid as owner); `create_worktree_for_agent/6` checks out `current_commit` via `CowWorktree.create_worktree/5` (fallback `Git.add_worktree`), then `assign_and_prepare_worktree/3` records the prepared commit on the summary row, advanced later by `ToolDispatch.sync_current_commit_after_tools/1` (moved onto the owned `%State{}` at the turn checkpoint, published by `Summary.publish/3`).
Subagent phylo nodes (`build_subagent_phylo_node/6`): explicit `commit_id` validated by `Git.rev_parse`, else the parent's `current_commit`; cross-repo uses tracked `foreign_repo_commits` or foreign HEAD.
**Repo root resolution**: per-agent `AgentState.repo_root` first, then `Process.get(:genesis_repo_root)` (set by `Setup.bind_worktree/2` and `install_process_context/3`, read via `current_repo_root/0`) — no global `state.repo_root`; repo-init tracking lives in `WorktreeManager`, running = `map_size(state.ref_to_agent)`.

## Subagent Spawn Fan-Out Bounds & Deadlock Surface

- **Registration is EAGER at accept** (`:pending` → `:running` + immediate spawn; `state.queue` exists only while paused) and the **worktree is created EAGERLY at child start**, so a child HOLDS a worktree while blocked on an LLM slot; a WAITING parent keeps its live worktree too (reclaim is `:DOWN`-only) and holds NO slot — so capping LIVE worktrees/agents with queueing can deadlock, whereas the implemented cap bounds CREATE-pipeline concurrency and cannot.
- **`max_depth`** — `[:scheduler, :max_agent_depth]`, `:pos_integer`, default `8`, `[min: 1]`; `validate_subagent_depth/3` → `{:error, :max_depth_exceeded}`; `Turn.effective_tools/1` drops subagent schemas at max depth. Bounds DEPTH only.
- **Batch size is UNBOUNDED**: one reduce over the subagent tool calls of ONE LLM response (`SubagentSchemas.schemas/1` has `path`/`objective`/`commit_id` only, no `maxItems`), gated by `max_agent_depth`, `:path_ignored`, the spatial contract, one-writable-foreign-repo-per-batch, `{:error, :scheduler_paused}` and `:llm_not_configured`; the scheduler GenServer is never blocked.
- **Defensive ETS lookups**: `Store.get_sched_meta/1`/`get_agent_state/1` return `{:ok, x} | :error`, so four sites degrade when a parent is reaped mid-spawn — `spawn_validated_subagents/5` (replies `[{:error, :parent_recycled}]` per spec, bailing BEFORE the `:waiting` mutation), `store_sub_result/3,4` (→ `:ok`), `maybe_resume_parent/2` and `dispatch_ready_parent/3` (still replies/resets meta, logs `"unknown"`). Covered by `subagents_test.exs` + `pubsub_test.exs`.

## Repo-Nil Tolerance & Repo-Less Agent Plumbing

The repo-less self-reflective agent (`EvoGit.Agents.SelfReflective`, `spec.opts[:repo_less] = true`) runs on this plumbing; nothing here runs git or creates worktrees for it.
**Nil-tolerant:** `current_commit` defaults nil (written nil at registration for a repo-less spec and at crash-retry reset — a transient nil is NORMAL); `repo_root` defaults nil; `resolve_agent_repo_root/2` returns nil for a foreign id missing from `spec.foreign_repos`; foreign roots are already ABSOLUTE (`ForeignRepo.new/3` applies `Platform.safe_expand/1`), so nothing re-expands them, and a foreign worktree lands under `<foreign_root>/.genesis/workers/worker_T<n>_A<m>` like a primary one (matched by `spec.repo_id`, never path); `commit_pending_in_worktree/0` short-circuits on `Process.get(:repo_less)`; skill loading guards `repo_root && is_binary(repo_root)`; `build_agent_summary/3` nil-guards via `safe_phylo_commit/2`/`safe_context_path/1`.
**Hard-dereferences a repo-less path must avoid**: `resolve_agent_repo_root/2`'s primary branch splits `spec.phylo_node.repo` on `"/.genesis/workers/"`, `do_try_dispatch`'s `Path.join([agent_repo_root, ".genesis/workers", ...])`, and `maybe_init_repo/3` → `workers_dir/1`.
**Specifics:** `resolve_agent_repo_root/2` uses the SHARED chain `EvoGit.SelfReflectiveSource.reference_path/0` (`:self_reflective_source_root` → `GENESIS_SOURCE_ROOT` → the reserved mount `vct:///genesis-source` when its path is a valid checkout → managed clone at `<data_dir>/genesis-source`), fallback `File.cwd!()`. `do_try_dispatch` appends `repo_less: true` + `repo_less_repo_path:` and the worktree-create SKIP lives ENTIRELY in `Setup.bind_worktree/2` (the `if repo_less` branch) — `create_worktree_for_agent/6` has no repo-less branch and is never called.
`dispatch_ctx` keys (all `Keyword.fetch!`'d by the session): `agent_id, depth, repo_root, repo_id, worktree_path, retries, spec, meta, session_mode, persistent_state, restore_agent_state, spawn_turn, spawn_index, branch, base_commit, scheduler`, plus optional `repo_less`/`repo_less_repo_path`, `resume_kind`, `notify`. `branch` = `plan.branch` (`branch_for/3`), `base_commit` = `plan.worktree_resume_from || spec.phylo_node.current_commit` (`nil` for a repo-less run).
`SpawnFacts` owns that spawn-side contract as pure functions over state/meta/spec: `resolve_agent_id/2`, `agent_id_free?/1`, `spawn_facts/1` (INTEGER `spawn_turn`/`spawn_index` only, so a `nil` fact never becomes a `nil` opts entry), `build_dispatch_ctx/6` (`Dispatch.build_dispatch_ctx/6` delegates).

`next_task_number/1` still runs for repo-less roots, scanning `<source root>/.genesis/workers`.
`rebuild_monitors/1` re-monitors on the SESSION pid with NO repo_less guard (it only needs a binary `worktree`, a pid `session_pid` and an integer `task_number`, all present via the synthetic path), so after a WorktreeManager-only restart its `:DOWN` → `destroy_worktree/3` runs `git prune` + a branch delete inside the SOURCE ROOT (`rm_rf` of the synthetic path no-ops).

`ModelSelection.update_opts/2` is PURE and delegates legacy-vs-canonical classification to the public `legacy_replacement?/1` (by `provider_profile_id`, directly or inside `model_spec`); a legacy-only replacement clears `provider_profiles` + `model_selection_config` together, while explicitly supplied keys win.
**Any runtime push that REPLACES model profiles for a canonical `[[llm.providers]]` config MUST also carry `provider_profiles` + `model_selection_config`** (`ModelSelection.config_opts/1` or `build_reload_opts/1`), else the snapshot is cleared and every explicit `model_spec` fails with `:model_spec_schema_unavailable`.

Scripts still override the fallback (nil/error results use it; invalid canonical script selections fail closed; unknown legacy ids keep the configured default), and a locked LEGACY parent clears both the child's `model_spec` field and its compatibility opts entry, so the inherited legacy id overrides any child canonical selection (`ModelSelection.inherit/2` runs inside `register_agent/8`).

## Peak/Off-Peak Concurrency Engine (`EvoGit.PeakHourEngine`)

The engine reads each account's `off_peak_holidays` beside `off_peak_days` through its own tolerant, atom- or string-keyed readers and threads a 4-tuple `{windows, off_peak_days, off_peak_holidays, tz}` through its wakeup math (the 3-tuple `{windows, off_peak_days, tz}` and 2-tuple `{windows, tz}` shapes are still accepted, calendar defaulting to nil).
It includes `:off_peak_holidays` in the schedule map handed to `EvoGit.PeakHours.effective_concurrency/2` and passes the calendar to `PeakHours.in_peak?/4` and `next_transition/4`, keeping NO second code path: every peak/day/holiday decision (including a holiday block's midnight edges) is re-derived from `PeakHours`, and an unknown/blank calendar id degrades to "no calendar" in both readers, never raising.
The 6h safety-net cap, config-PubSub (`"scheduler_config"`) re-derivation, the transition timer and the `:peak_hours_now_fun` / `:peak_hours_utc_now_fun` clock seams do not depend on the calendar.

## Blocking Surface (ONE GenServer serves every agent)

Every turn-path scheduler interaction is a plain `GenServer.call` into the single `EvoGit.AgentScheduler` mailbox, so inline work in one handler delays every other agent's slot grant, release, config read and pause/cancel probe.
`request_llm_slot/2` and `request_tool_slot/2` default to `timeout \\ :infinity`, so a queued caller waits silently with no timeout and no progress report; the wait is visible only as the `:llm_waiting` stream activity, which the agent sets via `Sink.start_call/1` BEFORE `with_llm_slot/2`, so queueing renders as "Waiting for model capacity", never `:idle`.
Inline work that stalls all slot traffic while it runs:
- `Lifecycle.retry_agent/4` → `salvaged_commit/1` → `WorktreeManager.salvage_for_retry/2` on EVERY abnormal session `:DOWN`, budget `Salvage.timeout_ms() + @salvage_call_grace_ms` (15 000 + 5 000 = 20 s), the manager running salvage commit + `rm_rf_retry` + `git prune` + branch delete inline.
- `handle_call({:run_agent, …})` → `maybe_reset_task_archives/2` (synchronous `Store.delete_task_archives/1`) + `Dispatch.next_task_number/1` (a `File.ls` scan of `.genesis/workers`).
- `handle_call({:update_config, …})` → `reconcile_pool_after_update/1` (`EvoGit.ReqLLMPool.reconcile/1` → `Finch.set_pool_count`).
- `handle_info({:DOWN, …})` → `Slots.release_agent_slots/2` + `grant_pending_llm_slots/1`, each a full pass over `State.all_model_ids/1`.
- `handle_call({:force_kill_task_agents_for_task | :begin_graceful_cancel | :begin_task_pause, …})` → `Store.list_sched_meta/0` full-table scan + per-agent ETS writes + queue purges.
The scheduler owns NO periodic scan or heartbeat: its only timers are the per-account backoff sweep (`:retry_llm_waiting`) and the subagent re-attach timeout, and `SystemSampler` is the only periodic external caller (3 s, `get_llm_slot_status/0`, cheap map reads).
A crash RETRY is followed by `Process.sleep(30_000 * retries)` in the session's start task (`agent/session/setup.ex`, after the fresh worktree exists) — 30/60/90 s in which the agent is registered `:running` with no `:llm_waiting` activity, so the dashboard shows "Idle" for exactly that long.

## Slot Management (Slots module)

LLM slots use agent-ID `MapSet`s; availability derives from `MapSet.size/1`, and session `:DOWN` removes the agent from both pools and purges its queued requests.
Tool capacity is granted as per-call permits: `ToolPermits` provides `make_ref()` permits attributed to an agent and monitored on the acquiring caller, with synchronous transfer to a new owner and idempotent synchronous release.
`handle_release(permit, caller_pid, state)` releases only the current owner's permit; missing or nonowner releases return `{:reply, :ok, state, []}` without granting waiters or mutating state, so a former executor cannot free a transferred background permit (the `self()` form is for direct owner calls only, never scheduler-hub routing).
`handle_transfer(permit, new_owner_pid, state)` deliberately authorizes by the unguessable permit reference rather than caller ownership, so the background registry can transfer on behalf of the tool task.
`occupancy/1` counts legacy holders plus granted permits without copying the waiting queue; explicit permits count separately even for the same agent, share capacity and ONE FIFO queue with legacy agent-keyed tool slots, and survive config rebuilding in `State.tool_permits` + `State.tool_permit_monitors`.
Legacy `request_tool_slot`/`release_tool_slot` remain one-holder-per-agent and require serialized ownership; their queued callers are monitored and dead ones discarded before grant. Tool requests queue FIFO as `{agent_id, from}` when globally paused or full; immediate grants do not change status, queued grants emit `:running`, enqueues emit `:blocked`.
`Slots.release_agent_slots/2` purges waiting requests with the existing cancellation reason, drops every attributed explicit permit and demonitor-flushes owners before granting capacity; pause/cancel queue purges preserve `:paused`/`:cancelled` and do not revoke holders.
The hub delegates `acquire_tool_permit/1`, `transfer_tool_permit/2` and `release_tool_permit/1` to `ToolPermits`, routes their calls through `permit_reply/1` to apply status updates, passes the releasing caller pid to `handle_release/3`, and routes every process DOWN through `ToolPermits.handle_down/2` before agent lifecycle handling.
`with_tool_slot/2` acquires a per-call permit and synchronously releases that exact reference in `after`, with a transferred permit protected from the former owner's release.
Detached-job permit acquisition, handoff and terminal release belong to `background_jobs.ex`; worktree cleanup additionally calls `BackgroundJobs.reap_under/1` first.

| Pool | State keys | Capacity | Backoff |
|---|---|---|---|
| LLM | `llm_holders`, `llm_waiting`, `llm_backoff_until`, `llm_last_granted` | **per-account** `model_concurrency[pool_id]` (account `concurrency`, default 3); fallback `default_llm_max_concurrency` (3) via `State.concurrency_for/2` | **per-account** on `:rate_limit` AND `:insufficient_balance` (HTTP 402) — caller duration (default 60 s, clamped to `@max_timer_ms`), self-rescheduling sweep; one account never blocks others |
| Tool | `tool_holders`, `tool_waiting`, `tool_permits`, `tool_permit_monitors` | `max_tool_concurrency` (default `EvoGit.Platform.cpu_threads/0`) | None |

`handle_request_llm_slot/3`, `handle_request_tool_slot/3`, `handle_release_llm_slot/2`, `handle_release_tool_slot/2` (the latter two via `handle_cast`), `release_agent_slots/2` (`:DOWN`: both sets, queue purge, grant) and `grant_pending_on_resume/1` (also at the END of every config update, so 0→N grants queued waiters).
Sync ops return `{:reply, :ok, state, status_updates}`/`{:noreply, state, status_updates}`, async releases `{state, status_updates}`; `status_updates` = `{agent_id, :blocked | :running}` written to SchedMeta.
`default_llm_max_concurrency` is a DEFAULT per-LLM concurrency, NOT a global cap: `concurrency_for/2` prefers `model_concurrency[pool_id]`, else the default; the map is filled only at config-load time (`from_model_profiles/2` at `init/1`, the `:model_profiles` update branch, or `update_config(model_concurrency: map)`), legacy config yielding `model_concurrency["default"]`.
**A runtime override is a FLOOR**: `State.apply_default_llm_concurrency_override/2` sets the default AND raises every entry to `max(c, N)` (explicit `0` stays `0`), while an account concurrency above the default still wins.

## Worktree Lifecycle (WorktreeManager + Worktrees)

**Fresh per agent run** — no pool, no reuse across retries.

1. **Lazy per-repo init** on the FIRST create for a repo: rm_rf `.genesis/workers` → `git worktree prune` → orphaned `evogit-agent-*` cleanup → mkdir_p (never from the scheduler). Gated on the persistent `:evogit_worktree_repos` marker: PRESENT (manager-only restart) → wipe skipped, only `mkdir_p_retry/2`; ABSENT (first request or genuine BEAM restart) → full wipe, then record. Destructive steps are **PRIMARY-ONLY** (`primary?` from `spec.repo_id` via `ForeignRepo.primary?/1`); foreign repos get prune + mkdir_p + marker. `mkdir_p_retry` raises `File.Error` on exhaustion — safe because the marker is written before the first worktree exists.
2. **Request path**: `create_worktree_for_agent/6` (`:infinity`) offloads to a MONITORED Task (`run_create/6`) replying exactly once — the result, or `{:error, reason}` when the create fun raises/throws/exits (`report_create_failure/3`) or the task dies silently — plus the `{:create_finished, agent_id}` permit-release cast.
3. **Create pipeline** (`prepare_new_worktree/5`): destroy leftover dir/branch (rm_rf failure escalates) → CoW create (fallback `Git.add_worktree`; failure → `{:error, {:worktree_create_failed, msg}}`) → `assign_and_prepare_worktree/3` → `run_init_script/3` (genesis.toml `[worktree]` script, primary only; env `SOURCE_REPO_PATH`/`SOURCE_WORKTREE_PATH`/`TARGET_WORKTREE_PATH`; Windows via `Platform.shell_args/1`).
4. **Monitor-based reclaim**: `:DOWN` for ANY reason (including after a successful completion) → `destroy_worktree/3` in FOUR ordered steps: `BackgroundJobs.reap_under(worktree_path)` under `safe_reap/1` (a detached job cwd'd inside the dir would hold it open) → `rm_rf_retry/2` → only AFTER the dir is gone `Git.prune_worktrees(repo_root)` → `delete_branch_tolerant(repo_root, branch_name)`; rm_rf failure logs ERROR and skips prune + branch delete, and a failed CREATE-path rm_rf also skips prune — a surviving dir with its `.git` file + registration is safe, while a pruned partially-removed dir becomes a PLAIN unregistered dir (the leak precondition). Idempotent; `recycle_agent/2`, `cancel_agent/2` and permanent failure never delete worktrees; after a manager-only restart `rebuild_monitors/1` re-monitors live agents from `:evogit_sched_meta` + `:evogit_agent_summary`, skipping missing/stale rows.
   An **ABNORMAL** death (any reason but `:normal`/`:shutdown`/`{:shutdown, _}`) salvages FIRST (`Salvage.salvage/3`: stage-all + commit the crashed run's dirty state, anchor the sha under `refs/genesis/salvage/<branch_name>` because reclaim deletes the agent branch) and retains the sha in `state.salvaged` (newest 64, in-memory only); `salvage_for_retry/2` answers it to `Lifecycle` (salvaging on demand while the agent is still `:live`, else reading the retained entry) and stores it as `SchedMeta.crash_commit`. A salvage error/timeout (`:worktree_salvage_timeout_ms`, default 15 000) logs at WARNING and reclaims exactly as before.
   Reclaim is keyed ONLY by the agent process monitor — never by task completion — and the ETS rows are deleted by `Lifecycle.recycle_agent/2`, not here.
   `task_number` comes from `Dispatch.next_task_number/1` (a `File.ls` scan for `worker_T<n>_` maxima, `1` when missing) ONCE per task from the ROOT's repo root and every subagent inherits it — each repo owns its own `.genesis/workers`, so dir and branch names REPEAT across repos (unique per repo, never task-globally).

## Persistent Foreign-Repo Worktrees (ForeignWorktree)

`ForeignWorktree` owns the PERSISTENT worktree of every WRITABLE non-primary foreign repo at `<root>/.genesis/foreign_repos/<id>` (`ForeignRepo.worktree_path/1`) — a stable READ view of the latest committed state, addressable by absolute path (`ForeignRepo.resolve/2`, `ContextBuilder.build_foreign_repos_section/1`).
It lives OUTSIDE `.genesis/workers/`, so the primary-only wipe and `destroy_worktree/3`/`destroy_leftovers/3` never touch it, MAIN HEAD never moves, and it is NOT torn down at task end; a foreign agent's WRITE workspace remains its ephemeral worktree.
API: `start_commit/1` (`base_sha` else repo HEAD), `ensure/2` (idempotent create-or-reset; non-writable → no-op; create = `mkdir_p_retry` → `Git.add_worktree(root, wt, sha)` detached, no branch → prune + one retry; update = `Git.checkout(wt, sha)` with `Git.reset_hard/2` fallback), `ensure_all/1` (best-effort, never raises), `sync_from_agent/0`, `worktree_path/1`.
**Hooks**: `Runtime.Helpers.load_foreign_repos/2` calls `ensure_all/1` after validating (before any spawn); `Session.Worker.run/3`'s `try/after` calls `sync_from_agent/0` right after `commit_pending_in_worktree/0` on EVERY exit path, advancing the agent's OWN repo worktree (id-matched via `Process.get(:evogit_repo_id)`) to `Process.get(:repo_path)`'s HEAD — no-op for primary/repo-less agents, last-writer-wins.
`ensure_all/1` filters to `writable == true and not ForeignRepo.primary?(repo.id)`, so an entry whose id is literally `"primary"` is never provisioned, and `sync_from_agent/0` advances only `writable` entries.

## Agent Dispatching (Dispatch module)

`register_agent/8` (IDs, task-local IDs, event-sink inheritance, both ETS writes) → `try_dispatch/2` (scheduling only; a `with` guard bails when ETS entries are missing; stores the worktree path BEFORE spawning) → `commit_pending_in_worktree/0`, `resolve_agent_repo_root/2`, `dispatch_queued_agents/1`, `process_queue/1`.
CoW copies unchanged files from a source tree (parent's worktree for subagents, repo root for top-level) with `cp --reflink=auto --preserve=timestamps` (Linux) / `cp -cp` (macOS); `[:git, :cow_worktree_creation]` (`:auto` default).
**Resume/retry decision (`ResumePlan.plan/5`)**: `:branch` is the persisted `resume_branch` when the dispatch is a pause resume or carries `restore_agent_state: true` (and it is non-empty), else the fresh `branch_name/2`.
The **base** is the first USABLE candidate of `spec.opts[:pause_commit]` → `spec.opts[:resume_current_commit]` → `meta.crash_commit`, each verified with `Salvage.commit_exists?/2` and an unusable one degrading to the next (all unusable → the task base with `worktree_resume_from: nil`); the chosen sha is rewritten into `spec.phylo_node.current_commit` (so `create_worktree/6` needs no new argument) and the caller's single `Store.put_sched_meta/2` persists the rewritten meta.
Resolution runs ONLY when the dispatch carries resume input at all (`:resume_kind` set, `:restore_agent_state` true, ANY of `:pause_commit`/`:resume_current_commit`/`:resume_branch`/`:resume_agent_id` PRESENT — a resolved `nil` is a fact too — or a non-empty `meta.crash_commit`), so a first attempt and a no-salvage retry make ZERO extra git calls.
`spec.opts[:pause_commit]` is PRE-RESOLVED by `EvoGit.TaskRegistry.Pause.resume/4`: the scheduler never reads the durable store on the resume path, and only a DIRECT dispatch lacking the key falls back to ONE bounded `EvoGit.TaskRegistry.AgentStateRead.pause_commit/3` read (2 s budget, degrading to `nil`).
**Branch reuse**: a resolved persisted branch is normalized into `spec.opts[:worktree_branch]` (durable-state dispatches only, and only when it differs from the fresh name), because `do_try_dispatch/4` persists `plan.meta` and `prepare_new_worktree/5` later runs in `WorktreeManager` with only `spec`/`meta` in hand; `branch_for/3` names both the ctx `:branch` and the git branch, `destroy_leftovers/3` deletes that branch and `Git.add_worktree/4` re-creates it at the base sha.
**Anchor-based base repair**: an unusable resolved base is repaired by `Worktrees.ensure_resume_base/4`, called only for a resumed run (`resume_branch(spec) != nil`, so the non-resume path makes zero extra git calls) and TOTAL throughout (verified spec base → the sha `spec.opts[:resume_anchor_ref]` / `AgentState.Anchor.ref(task_id, agent_id)` points at → the existing branch's own sha → the task base, ONE warning on total failure).
**Identity reuse**: `Dispatch.resume_registration_opts/1` (`@doc false`) answers `[agent_id: id]` for a positive-integer `spec.opts[:resume_agent_id]`, else `[]`; the caller passes it to `register_agent/8` and, on `{:agent_id_taken, id}`, re-registers WITHOUT it and logs ONE warning.

## Subagent Management (Subagents module)

1. `spawn_validated_subagents/5` validates all specs, registers valid ones and replies immediately if all are invalid; the parent commits pending changes BEFORE calling `spawn_sub_agents`, which blocks (`timeout \\ :infinity`) until every child completes. The hub's `{:spawn_sub_agents, parent_id, specs}` handler reads the parent row with an explicit `case`: a gone row answers `{:reply, {:error, :not_found}, state}` (the row is a best-effort mirror other processes write/delete) after the `{:error, :scheduler_paused}` check.
2. `validate_single_subagent/5` → `validate_subagent_depth/3`, `validate_subagent_not_ignored/1`, `validate_spatial_contract_for_spec/4` + `validate_spawn_spatiality/4`; fan-out WIDTH is NOT code-limited (gates in §Subagent Spawn Fan-Out Bounds).
3. Cross-repo rule: `:read` at ANY depth; `:read_write` only into a repo whose TASK-LEVEL `spec.foreign_repos` entry (never the path alone) is `%{writable: true}` and only from a ROOT parent; same-repo spawns WITHIN a foreign repo are unrestricted.
4. `store_sub_result/3,4` — the 4th arg carries the COMPLETING CHILD's `%AgentSpec{}` (or nil) and gates foreign-commit recording via `writable_foreign_repo_agent?/1` (public, `false` for non-`%AgentSpec{}`, never raises); then `maybe_resume_parent/2`, `dispatch_ready_parent/3`, `build_ordered_results/2`.
5. **Crash-resume of a batch**: `dispatch_ready_parent/3` replies ONLY to a LIVE `{pid, _tag}` waiter — a `nil`/dead waiter (the crash-retried parent's OLD exchange worker) is never `GenServer.reply`'d, and the completed batch is RETAINED instead (`sub_agent_from: nil` marker, `status: :running`, `pending_sub_agents` cleared, `sub_agent_results`/`sub_agent_indices`/`total_sub_specs` kept). `maybe_resume_parent/2` never re-dispatches a retained batch; a later `spawn_validated_subagents/5` discards the stale waiter/timer and starts a FRESH batch.
   The retried parent claims it with `EvoGit.AgentScheduler.reattach_sub_agents(agent_id, expected_count \\ nil, opts \\ [])` → `{:ok, results}` (ordered, missing slots `{:error, :subagent_result_lost}`) | `{:error, :no_pending_batch}` (no/empty/mismatched-with-`expected_count`/already-delivered batch) | `{:error, :unavailable}`; `opts[:timeout]` → app env `:agent_resume_reattach_timeout_ms` → 1_800_000 ms, validated (`> 0` integer) at call time. A pending batch installs the caller as waiter and, on expiry, answers still-missing slots as lost and leaves the parent `:running`. `Lifecycle.retry_agent/4` deliberately KEEPS every batch field — that is what enables re-attach.
6. **Durable rebuild**: `{:error, :no_pending_batch}` is not terminal — the resumed parent builds a plan from the children's durable rows (`EvoGit.Agent.Resume.RosterBatch`, in the agent worker) and calls `rebuild_subagent_batch(parent_id, plan, opts)` → `{:ok, results}` (same ordered shape) | `{:error, :no_pending_batch | :batch_in_flight | :invalid_plan | :unavailable}` (all leave the row untouched). `SubagentRebuild` installs the batch fields + caller as waiter via `SubagentReattach.put_waiter/4`, contributes a `done` child's stored result, re-spawns a `running` child under its persisted `agent_id` (persisted spawn position + resume opts, exactly the crash-retry shape) and treats a missing row as `{:error, :subagent_result_lost}`; a re-spawned child repeats the same steps for ITS children, so resume is recursive. The bounded re-attach timer stays armed as the backstop.

## Session-Owned Agent Lifecycle

Every agent is ONE `EvoGit.Agent.Session` started by `Dispatch.do_try_dispatch/4` under `EvoGit.Agent.Session.Supervisor`; `ref_to_agent` keys on the session monitor ref, while `SchedMeta.session_pid`/`mode`/`phase` are a best-effort mirror and `EvoGit.Agent.Session.inspect/2` is the live phase truth.
The ONE terminal delivery is `{:agent_session_result, agent_id, session_pid, result}`, sent BEFORE the session stops; `AgentScheduler.handle_info/2` admits it only when `SchedMeta.session_pid` is `nil` (already recycled) or equals the sender, else logs at `:debug` and ignores it.
A session START failure is routed through `Lifecycle.handle_agent_crash/3` as `{:session_start_failed, reason}` — retried up to `agent_max_retries`, the parent/root replied an error at permanent failure, never silently dropped.
Force cancel uses `Session.cancel(pid, :force)` with a bounded wait plus a `Process.exit(pid, :kill)` fallback, and a `nil` `session_pid` is a no-op; worktree create/reclaim keys on the session pid (`Setup.bind_worktree/2` is called by the session's start task with the SESSION pid as owner), so a WorktreeManager-only restart re-monitors it.

## Interactive Sessions (root-only, non-blocking)

An interactive session is the SAME `EvoGit.Agent.Session` in `mode: :interactive`: it yields to `:awaiting_input` instead of finishing and keeps its worktree, conversation and provider `prompt_cache_key` for its whole life; idle contract, input policies and phase transitions belong to `../agent/session/CONTEXT.md`.
It is LIVE but not BUSY (no worker, LLM slot, tool slot or timer), so it must never count as busy: the `/server/status` active-task count covers only `:running`/`:pending`/`:cancelling`/`:finalizing` task ids, and `list_awaiting_input/0` names the idle sessions an upgrade gate winds down.

| API | Returns |
|---|---|
| `start_session/1` | `{:ok, pos_integer()} \| {:error, reason}` — NON-BLOCKING; keyword input goes through `SessionOpts.build/1`, unknown → `{:error, {:invalid_session_opts, {:not_a_session_spec, other}}}` |
| `send_session_message/3` | `:ok \| {:error, {:session, reason}}` via `Session.start_input/3` (`:bad_policy`/`:bad_target`/`:bad_message`/`:exit` nest inside `:session`) |
| `close_session/1` | `:ok \| {:error, {:session, reason}}` — `Session.close/2`, the ONLY non-cancellation way out of `:awaiting_input` |
| `await_close(agent_id, timeout \\ 30_000)` | `{:ok, %Result{}} \| {:error, :not_found \| :timeout \| term()}` — one close waiter, replied exactly ONCE |
| `list_awaiting_input/0` | `[%{agent_id, task_id, session_pid, task_number, mode}]` from `:evogit_sched_meta` (`SessionOpts.idle_sessions/0`, no scheduler call), `[]` when idle/absent |
| `force_kill_task_agents_for_task/1` | `:ok \| {:error, :not_found}` — the ONLY way to reach a `start_session/1` agent (registered `from: nil`), sharing ONE cascade with the pid form |

- `await_close/2` is race-free only with `notify: {self(), tag}` in the spec opts, the waiter registered BEFORE starting, then matching `{:agent_session_closed, tag, result}`; the budget bounds the WAIT alone (`{:error, :timeout}` leaves the session running), so a human-driven session passes `:infinity`.
- `SessionOpts.build/1` + `force_interactive/1` normalize `session_mode`/`notify`/repo-less/model selection into the `%AgentSpec{}` and reject a non-root request (`depth` other than `0`/absent, or a present `parent_id`) with `{:error, {:interactive_root_only, message}}`; `Dispatch.session_mode/2` (private) forces `:oneshot` for every `depth != 0` agent, and `register_agent/8` mirrors `SchedMeta.mode` (`"interactive"`/`:interactive`; unknown → warn + `:oneshot`) into the dispatch ctx.
- Yield/resume are NON-terminal messages admitted only from the agent's current `session_pid` (`SessionOpts.admit_signal/2`, stale senders logged and dropped), flip the TASK row via `update_task_status/2` when a `task_id` exists (best-effort cast, `result: nil`, `finished_at`/lease untouched) and fire ONE `PubSub.broadcast_agents_updated/0`; a yield NEVER replies `meta.from`/`{:agent_session_result, …}` and never touches slots, worktree, rows, archives or the terminal task status.
- Close waiters live in `State.close_waiters` (dead callers pruned), registered by `Lifecycle.register_close_waiter/3` and flushed EXACTLY ONCE by `Lifecycle.flush_close_waiters/3` — with the terminal result, the failure term, `{:error, :cancelled}` on `cancel_agent/2`, or `{:error, :not_found}` on `recycle_agent/2`; an agent with no `SchedMeta` row answers `{:error, :not_found}` at once.
- There is NO idle TTL and no idle-timeout sweep: the session lives until close, cancellation, force kill or a crash; graceful cancel on an idle session is IMMEDIATELY terminal (the last yielded text becomes the result) while force kill uses `Session.cancel(pid, :force)` — no gate may assume `:running`.
- An interactive session is NEVER crash-retried (`Lifecycle.retry?/2` is private, `:oneshot` only): a crash replies `{:error, {:session_crashed, reason}}` to the waiters, and `Lifecycle.apply_status_updates/1` never overwrites `:awaiting_input` with a slot-derived `:running`/`:blocked`.

## Agent Lifecycle (Lifecycle module)

1. `recycle_agent/2` deletes ONLY the two ETS rows (`delete_agent_state` + `delete_sched_meta`, writing `phase: :done` first), tolerating an already-gone entry, and runs ONLY from the session-monitor `:DOWN` (`handle_agent_down/4`, `reason == :normal or meta.result_sent`) i.e. AFTER `handle_session_result/3` replied — no worktree I/O. `ref_to_agent` is popped earlier by `handle_agent_down/4`, `task_agent_counts` by the root/permanent-crash path, and the `:evogit_cancelling_tasks` marker belongs to `TaskRegistry.clear_cancelling_marker/1`.
   Consequence: the conversation lives ONLY in the stopping session's `%EvoGit.Agent.State{}`, so a transcript is unrecoverable once the session ends (archives persist `result`/usage/settings, never messages). `cancel_agent/2` is the other path: `Session.cancel(meta.session_pid, :force)` (BOUNDED; anything but `:ok` — e.g. a session stuck in `:starting` — falls back to `Process.exit(pid, :kill)`; a `nil` pid no-ops) → manager `:DOWN` reclaim, replies to blocked callers, flushes close waiters with `{:error, :not_found}`, deletes ETS entries.
2. `handle_agent_crash/3` is the crash-RETRY policy, ONLY from `handle_agent_down/4` when `reason != :normal AND meta.result_sent == false` AND `mode` is `:oneshot` (an abnormal exit AFTER delivery is a RECYCLE). `do_handle_agent_crash/4` logs `"Retry #{meta.retries}/#{state.agent_max_retries}"` BEFORE incrementing (first crash logs `Retry 0/3`), then either RETRIES (bump `retries`, `:pending`, `session_pid: nil`, `phase: nil`, reset `phylo_node`/`context`, record `crash_commit`/`crash_reason`, re-dispatch) or PERMANENTLY FAILS (subagent → `store_sub_result(parent_id, agent_id, {:error, :agent_max_retries_exceeded})` + `maybe_resume_parent/2`; root → `GenServer.reply(meta.from, …)` when `from` is not nil; both then `process_queue/1`). Neither deletes worktrees. `retry_agent/4` first calls `WorktreeManager.salvage_for_retry/2` (total; `{:ok, nil}` when nothing to preserve), RE-READS the meta row so the pre-salvage struct cannot clobber a concurrent write, then re-dispatches the SAME `agent_id` with `retries: meta.retries + 1`, so the rebuilt session receives `restore_agent_state: true` (when the task's `:persistent_state` is not `false`) and merges its persisted conversation. Every batch field (`sub_agent_*`, `total_sub_specs`) is deliberately preserved.
3. `state.agent_max_retries` (default 3, `non_neg_integer` min 0, `[:scheduler, :agent_max_retries]`) gives `1 + agent_max_retries` attempts; the wait lives in the session's start task (`Setup.bind_worktree/2` sleeps `30_000 * retries` AFTER creating the fresh worktree, so the session stays answerable).
4. A RETURNED value (`{:error, {:llm_request_rejected, msg}}`, `{:error, :recovery_failed}`) arrives as the session's ONE `{:agent_session_result, …}` BEFORE its `:DOWN`; `handle_session_result/3` sets `result_sent: true`, flushes close waiters and replies `meta.from` VERBATIM for any non-`{:ok, %Result{}}` result (nil-guarded — an interactive session has no `from`), so crash-retry applies ONLY to a RAISE before delivery. After `result_sent` it injects `SchedMeta.foreign_repo_commits` via `inject_foreign_repo_commits/2` (`Map.put`, NOT struct update — the field is added by the agent stream in parallel) BEFORE the parent/root split.

## Foreign-Repo Writable Spawn Gate & Per-Repo Commit Roll-up

Writable foreign repos (`ForeignRepo.writable`, default `false`) let `:read_write` agents work in foreign repos.

- **Spawn gate order** (cross-repo `:read_write`): target writable (from `spec.foreign_repos`, never the path)? else `{:foreign_repo_read_only, msg}` → spawner ROOT (`parent.depth == 0`)? else `{:foreign_repo_write_not_root, msg}` → only accepted writable foreign spec in the batch (`spawn_validated_subagents/5` threads `writable_accepted`)? else `{:foreign_repo_write_serialized, msg}`.
- **Subtree roll-up is authority-gated** (`store_sub_result/3,4`): ONLY a child that is ITSELF a writable agent in its own foreign repo may advance `SchedMeta.foreign_repo_commits` — `repo_id` a binary `!= "primary"`, `agent_module.agent_type() == :read_write`, task-level entry `writable: true`; it rolls up its result's subtree map child-wins via `Map.merge`, then records its OWN `commit_sha` via `Map.put`. A PRIMARY or READ-ONLY child (even a probe whose `commit_sha` is its starting commit) leaves the map EXACTLY as-is.
- **Injection + getter**: that `Map.put` happens BEFORE the parent/root split, so the ROOT result carries what the runtime reads for the per-repo report; `get_foreign_repo_commits/1` returns the SPAWNING agent's OWN map (`%{}` when missing), consumed by `agent/subagent_processing.ex` to seed the next subagent phylo-node starts (precedence task-level `base_sha` → tracked sha → foreign HEAD).

## Summary row + Control Plane (the one-writer rule for `:evogit_agent_summary`)

**The agent's session is the ONLY runtime writer of its own summary row** (`Session.Summary.publish/3`); the rest are registration writes (`Dispatch` creates it, `Worktrees`/`Lifecycle` update `current_commit`).
Because a row is a SUMMARY with no conversation, every read is a possibly-stale snapshot and every cross-process control datum lives in `ControlPlane`'s three APP-GLOBAL `:public` tables — created in `application.ex` beside the scheduler tables so they survive scheduler restarts, never purged by the scheduler:

| Table | Type | Object |
|---|---|---|
| `:evogit_agent_inbox` | `:bag`, read+write concurrency | `{agent_id, {seq, message}}`, `seq = System.unique_integer([:monotonic, :positive])` (the scheduler serializes appends, so seq order == append order) |
| `:evogit_agent_control` | `:set`, read concurrency | `{agent_id, cancel_requested, pause_requested}` (one independent flag per element, each written by its own single-element update) |
| `:evogit_task_pause` | `:set`, read concurrency | `{task_id}` — the TASK-level pause marker (§Task-Level Pause) |

One atomic primitive per operation, never a read-modify-write: `append_message/2` = one `:ets.insert/2` (gated on the summary row existing, else `{:error, :not_found}`); `drain_messages/1` = `:ets.take/2` (ONE BIF removing AND returning every object for the key, so a concurrent append is fully drained or fully left — never lost or duplicated) + `Enum.sort_by/2` on `seq`; `pending_messages/1` = `:ets.lookup/2` + the same sort (a peek, never a take); `set_cancel/2` / `set_pause/2` = `:ets.insert_new/2` + ONE `:ets.update_element(table, id, {2, value})` / `{3, value}` (a legacy 2-tuple row is upgraded to the 3-tuple shape first, preserving its cancel flag); `delete/1` removes both rows (`Store.delete_agent_state/1` calls it, so a recycled agent leaks nothing).
Every read is TOTAL (`:ets.whereis/1` → documented default) and every write degrades to `{:error, :not_found}`; `Store.get_agent_state/1` returns the RAW row, and `compression_count` is state-owned on the session, published by `Summary.publish/3`.

## Pending User-Message Queue (shape tolerance + the `Attachments.message/1` seam)

`:evogit_agent_inbox` is the ONE external injection queue, drained by the running exchange at the top of each turn into the session-owned `State.pending_inputs`.
Two shapes: **legacy plain `String.t()`** stored/drained VERBATIM (byte-identical end-to-end; pinned by `lifecycle_test.exs`'s `String.contains?(&1, "being cancelled")` assertions) and the **canonical multimodal** `%{text: String.t(), attachments: [map] | nil}`, where any atom-/string-keyed `%{text:, attachments:}` map is CANONICALIZED through `EvoGit.Attachments.message/1` before storing; `Attachments.validate_message!/1` enforces caps and raises a descriptive `ArgumentError` — never swallowed, nothing queued — and attachments are base64 STRING maps only.
Write: `Store.append_pending_user_message/2` (guard `is_binary or is_map`; private `canonical_pending_message/1`, then `ControlPlane.append_message/2`); read: `Store.drain_pending_user_messages/1` → `ControlPlane.drain_messages/1`, in seq order (`[]` for an absent agent).
Callers: graceful cancel appends the binary `cancel_message/0`; `RemoteAPI.send_agent_message/2` → `AgentScheduler.send_user_message/2` accepts both shapes; both ride the `:agent_updated` `pending_user_messages` delta verbatim.
Delivery is best-effort and status-blind: the append checks ONLY that a summary row exists, so a message sent after the agent's final turn but before its `:DOWN` recycle returns `:ok` and is NEVER read, and once `recycle_agent/2` deleted the row (and `ControlPlane.delete/1` both control rows) every later send answers `{:error, :not_found}` — an agent cannot be messaged back to life.

## Graceful Cancellation (cancel_requested + `:evogit_cancelling_tasks` marker)

`ControlPlane.cancel_requested?/1` reads `:evogit_agent_control` element 2 (`boolean() | nil`, default nil; the summary row carries no such field): set by the scheduler, checked/cleared by the exchange at the top of each turn, which then enters cancel-grace; `Store.set_cancel_requested/1,2`, `cancel_requested?/1` (`false` when missing) and `clear_cancel_requested/1` delegate to it.
**Delta-broadcast asymmetry**: `put_agent_state/2`'s struct diff emits `:agent_updated` for `@agent_state_tracked_fields`, but the queue is not a row field, so the Store helpers emit those deltas THEMSELVES (`append_pending_user_message/2` the whole new queue, `drain_pending_user_messages/1` `[]`) while the cancel flag emits NO delta (only the throttled `{:agents_updated, node}`) — keep it that way, and any new dashboard-visible per-agent flag must be added to `@agent_state_tracked_fields`.
**`begin_graceful_cancel/1`**: (1) registers `task_id` in `:evogit_cancelling_tasks`, a public `:set` ETS table created in `application.ex` and owned by the application process, so it survives scheduler restarts; (2) scans `SchedMeta.task_id` and per live agent appends the cancel message via `Store.append_pending_user_message/2` (NOT `send_user_message/2`, a self-call deadlock) + `set_cancel_requested/1`, then drives `Session.cancel(session_pid, :graceful)` and mirrors `phase: :cancelling` (best-effort; a `nil`/unreachable session is left to the drain); (3) purges the task's agents from the LLM/tool waiting queues via `Slots.purge_agents_from_queues/2`, replying `{:error, :cancelled}` to each blocked `from`.
`cancel_message/0` asks the agent to commit any uncommitted changes and reply with a plain-text summary, stating that a reply with no tool calls ends the run and its text IS the report, and that it is in a grace period and must finish now.
`clear_cancelling_task/1` is an idempotent delete called by TaskRegistry's guarded `clear_cancelling_marker/1` at terminal transitions; `cancelling_task?/1` (public, `@doc false`) is the SHARED nil-safe read (missing table = not cancelling).
**Guards**: `run_agent` replies `{:error, :cancelled}` WITHOUT dispatch while the task is in the marker (blocking Genesis Mode B's second root, which shares the `task_id`), and a NEW-agent registration guard gives agents registered meanwhile (subagent spawns, crash-retries, late queued agents) the cancel message + `cancel_requested`.
`force_kill_task_agents/1` is a brutal reverse-depth `:brutal_kill` cascade (remove refs, purge queues, release slots, `cancel_agent/2` deepest-first), called by `TaskRegistry.force_kill_task/1`; `force_kill_task_agents_for_task/1` is the task-id sibling over the SAME cascade.
RPC: `RemoteAPI.cancel_task/1` + `force_kill_task/1`, `RemoteNode.cancel_task/2` + `force_kill_task/2`.

## Task-Level Pause (pause_requested + `:evogit_task_pause` marker)

A task pause is a durable, resumable resting state — NOT a cancel and NOT a failure: it never lands a task in `:cancelled` and never reports one as finished.
`ControlPlane.pause_requested?/1` reads element 3 of `:evogit_agent_control` (`boolean() | nil`, default nil), INDEPENDENT of the cancel flag on the same row; `Store.set_pause_requested/1,2`, `pause_requested?/1`, `clear_pause_requested/1` and `clear_pause_requested_for_task/1` are the ONLY entry points (the task-wide clear is an `:evogit_sched_meta` scan, total and idempotent).
**The task marker `:evogit_task_pause`** exists for LATE REGISTRATION: `ControlPlane.ensure_row/1` seeds a NEW agent's `pause_requested` from `task_pausing?/1` (its task id read from its `SchedMeta` row), so a crash-retried or late-queued agent of a draining task stops at its first turn boundary instead of running a whole extra turn.
**`begin_task_pause/1`**: (1) `mark_task_pausing/1` FIRST, (2) `Store.set_pause_requested/1` for every agent of the task with a live state row, (3) `Slots.purge_agents_from_queues/3` with the `:paused` reason so a pause can never hang behind a slot wait; slot HOLDERS are untouched (an agent mid-call finishes that call and reads the flag at its next loop top — that is what makes the pause clean).
**`clear_task_pause/1`** clears the marker and every agent's pause flag: on drain completion, on resume, and when the pause is abandoned.
**Cancel-over-pause precedence (hard)**: `{:begin_graceful_cancel, task_id}` CLEARS the task marker and every pause flag BEFORE its existing work (a cancel arriving while `:pausing` abandons the pause and wins); `begin_task_pause/1` returns `:ok` immediately while the task is in `:evogit_cancelling_tasks` (no marker, no flag, no purge); both force-kill paths (`cancel_task_agents/2`) clear the marker so a killed task never leaves a pause looking active.
**The paused term** is `{:paused, %{agent_id, task_id, checkpoint, branch, reason: :task_pause}}` — a THIRD documented `run_agent/2` outcome beside `{:ok, %Result{}}` and `{:error, reason}`.
`Lifecycle.handle_session_result/3` routes it like a normal terminal result but WITHOUT completion semantics (no `:finalizing` notification, no merge, no archive/note write): a ROOT sets `result_sent`, replies `{:paused, info}` to its non-nil `from`, flushes its `await_close/2` waiters with the SAME term and drops the task's `task_agent_counts` entry; a CHILD stores `{:paused, info}` through `store_sub_result/4` (unchanged — the roll-up only special-cases `{:ok, %Result{}}`) and `maybe_resume_parent/2` resumes the parent.
A paused CHILD is never a failure: `EvoGit.Agent.SubagentProcessing` merges `info.checkpoint` (its pause commit, with `info.branch`) into the PARENT worktree exactly like a normal completion and formats the result as ONE neutral sentence; a term with no checkpoint sha falls back to no-merge.
`EvoGit.Runtime.Evolution.deliver_agent_result/4` returns a paused term UNCHANGED at `:info` and runs NO `notify_finalizing/1` and NO `merge_and_report/3,4`.
**Slot purge reason**: `Slots.purge_agents_from_queues/3` takes `:cancelled` (the `/2` default, byte-identical) or `:paused`, replying `{:error, :paused}` to the waiters it purges for a pause; both raise the SAME `RuntimeError` in `with_llm_slot/2`/`with_tool_slot/2`, and the session-side pause handling turns an aborted worker into a pause.

## Shutdown & Restart Safety

- **No `terminate/2` in the scheduler ecosystem** (`AgentScheduler`, `Slots`, `State`, `Store`, `WorktreeManager`; the app's only one is `TaskRegistry.terminate/2`) — cleanup is purely monitor-driven. On app stop `EvoGit.Supervisor` terminates children in reverse: `AgentGroupSupervisor` FIRST, whose `one_for_all` kills `EvoGit.TaskSupervisor` (every exchange worker) + `AgentScheduler`, so all sessions die with their workers, and WorktreeManager dies before processing queued `:DOWN`s — `.genesis/workers/worker_T<n>_A<m>/` dirs and `evogit-agent-T<n>-A<m>` branches REMAIN on disk after any BEAM/app stop.
- **Next-start cleanup is the lazy per-repo init** on the FIRST create per repo, ONLY when the `:evogit_worktree_repos` marker is ABSENT and ONLY for the PRIMARY repo; nothing is cleaned at boot without a create request.
- **Task rows survive in SQLite**: `TaskRegistry.init/1` reconciles orphaned `:finalizing` → `:failed` and `:cancelling` → `:cancelled` at boot; a RESUMABLE `:running`/`:pausing` row (its durable ROOT row exists) becomes a DIRTY PAUSE (`:paused` + `pause_kind: :dirty`) through `TaskRegistry.init/1` and the one-shot `:lease_sweep` (150 s after init; `@lease_duration 120`, `@heartbeat_interval 60_000`, `@sweep_after (@lease_duration + 30) * 1000`), and only a non-resumable one falls to `:failed` ("Lease expired; owning instance no longer renewing"). The conversation survives in `agent_state.sqlite` (`:persistent_state`, default on) and is restored on resume; the scheduler's in-flight control rows (pending messages, cancel flag, batch) do NOT survive a BEAM death.
- **Slot pools are memory-only**: the restarted `%State{}` has empty pools (holders cannot leak), blocked waiters (`GenServer.call` `:infinity`) exit with the scheduler, and there is no explicit shutdown gate — only `state.paused` plus per-account capacity/backoff. The `:evogit_cancelling_tasks` marker survives scheduler restarts, not app restarts.

## Worktree Safety — Main-Copy HEAD Protection (foreign repos)

A foreign repo's MAIN working copy must never have its HEAD moved pre-merge; a main HEAD on `evogit-agent-T<task>-A<agent>` yields an EMPTY review diff.

- **`Git.clean`/`Git.checkout` are safe ONLY in a REGISTERED linked worktree — `assign_and_prepare_worktree/3` GUARDS it** via `ensure_linked_worktree/2`: `wt/.git` must be a FILE with `"gitdir: <path>"` whose `<path>` (after `Platform.safe_expand/2`) lies under `<repo_root>/.git/worktrees/`; `repo_root` is the explicit param from `prepare_new_worktree/5` (NOT `spec.phylo_node.repo`, which for subagents is the PARENT's worktree). Failure → `{:error, {:worktree_prepare_failed, :not_a_linked_worktree}}` with NO git run. `rev-parse --git-common-dir` is unusable: it reports `<repo_root>/.git` for a real worktree AND for a plain dir inside the repo tree.
- **`delete_branch_tolerant/2` RECOVERS git's "cannot delete branch used by worktree"** (both wordings, via `branch_in_worktree?/1`): the stale registration is dropped by `retry_on_transient(fn -> Git.prune_worktrees(repo_root) end)`, then the delete retries ONCE; a branch live in a worktree survives → `{:error, output}` (never force-deleted). Crash-retry interleavings fail safely: a stale `:DOWN` destroy can delete a fresh branch, so `git checkout` errors and main HEAD stays put.
- **LLM cd-escape into the repo root is HARD-BLOCKED at the tool layer**: `do_execute/5` (`agent/tools/shell_tool.ex`) calls `main_copy_mutation_error/3` first — if ANY resolved cd target equals `Path.expand(repo_root)` AND the command matches `@mutating_git_regex` `\bgit\s+(checkout|switch|reset|merge|pull)\b`, it returns an error string and NOTHING executes (`@cd_regex` covers absolute, dot-relative and plain relative targets; `cd_targets/2` resolves via `Platform.safe_expand/2`). `detect_cd_warnings/3` stays warning-only.

## Multi-Repo Identity: a flat `[%ForeignRepo{}]` list, NO mount/workspace layer

The scheduler's whole multi-repo vocabulary is a flat list plus a string `repo_id`; mounts/virtual-tree grouping have no representation to hook into.
`%EvoGit.Core.ForeignRepo{}` is `[:id, :root, :description, writable: false, base_sha: nil]` (no parent, mount point or ordering; `"primary"` is the only special id), and `AgentState.foreign_repos` is the task-level list copied in at registration, inherited verbatim with no update path.
Root resolution is a LOOKUP, never a tree walk (`resolve_agent_repo_root_regular/2`: strip `"/.genesis/workers/"` for `"primary"`, else `Enum.find` by `spec.repo_id`), and a foreign repo reuses the primary worktree/branch conventions under its own root.
`ContextNode` carries `repo_id`, but the context READ drops it (2-arity `hierarchy_nodes/2` tags every node `"primary"` and resolves against the agent's OWN worktree), so nothing cross-repo is keyed by `{repo_id, path}`; `ContextMerge` and `Shared.validate_file_scope/4` stay repo-agnostic, and the sole repo-aware file gate is the read-only-foreign-repo check via `ForeignRepo.resolve_path/2`.

## Windows-Only Runtime Risks

Windows-only failure modes; NONE is test-covered (the suite runs on Linux/macOS).

- **`run_init_script/3` spawns a BARE executable name**: without a shebang `shell` = `Platform.shell()` = `"powershell"`, and `:os.find_executable/1` → `ErlangError :enoent` on a miss (OTP's win32 resolver hardcodes `[".exe", ".com", ".cmd", ".bat"]`, never PATHEXT, and tries cwd LAST; built-in `WorktreeInitScript` windows variants carry NO shebang). Elsewhere the class IS guarded (`Sandbox.None.resolve_executable/1`, `Git.gh_available?/0`); `worktrees.ex` is not.
- **`run_init_script/3` is NOT sandbox-wrapped**: the `genesis.toml` `[worktree]` script runs through a raw `System.cmd/3` with `cd: repo_root`, so a repo-supplied script executes with the BEAM user's full authority (no filesystem isolation, no timeout, no `ProcessManager` record) at every worktree creation.
- **Create-path raises fail safely**: `run_init_script/3` has no `try`/rescue, so a raise reaches `run_create/6` → `{:error, {:worktree_create_failed, "worktree create raised: ..."}}` while `after` still releases the permit.
- **No POSIX-only process handling**: no `:os.cmd`, `kill`/`os_pid`/negative-pgid kill, `chmod` or `sh -c` — kills are `Task.shutdown/2` + monitor reclaim, git resolves through `EvoGit.Executable.resolve/1`, and a stuck create holds its permit until `{:create_finished, agent_id}`.
- **Windows path normalization is load-bearing and HOLDS — do not "fix" it**: `Path.join/2` emits `/` and `Path.expand/2` normalizes `\` → `/`, the ONLY reason `repo_root_from_worktree/1`'s split works; a raw backslash path fails to strip → `:not_a_linked_worktree` (fail-safe), and `branch_name/2` has no character illegal in a Windows ref.

## AgentScheduler GenServer Hub (`agent_scheduler.ex`)

Agent lifecycle, interactive-session commands, yield/resume admission, per-account LLM/tool capacity, config updates, cancellation markers and startup reconciliation; sub-logic lives in `agent_scheduler/`.
Its size exceeds the ~1000-line baseline as PRE-EXISTING debt (`RemoteAPI`, `ToolDispatch` are similar); a split is a dedicated refactor, not a drive-by edit.
**Lazy config-read rule (do not regress)**: single-key reads inside the scheduler MUST use the private `config_value/2` — `config_map/1` evaluates `Platform.sandbox_backend()` and `Sandbox.capabilities()` on every call (it once regressed the system_sampler tests), serves ONLY the full `:get_config` reply, and `@config_keys` (16) enumerates the fields.
**`init/1` is O(#model profiles) and KB-scale**: `:ets.whereis` warnings only, `Config.resolve()`/`Config.credentials()`, `Schema.effective_model_profiles/1`, empty pools via `State.from_model_profiles/2`, one best-effort `ReqLLMPool.reconcile/1` no-op — no SQLite query IN THIS PROCESS (the one durable read, the `max_agent_id` boot seed, runs in an offloaded task under a 2 s budget), no `.genesis/workers` scan, no PubSub subscribe, no timer.
**The llm_db catalog load happens BEFORE this process starts, in `EvoGit.CatalogWarmup`** (an `:ignore` child immediately before the scheduler): the first metadata resolution decodes the ~11.7 MB snapshot, builds indexes and leaves the durable store in `:persistent_term` (`:llm_db_store`), so that transient heap never enters the scheduler; `init/1` only performs WARM lookups that re-resolve without copying (`../config/schema/CONTEXT.md`), a scheduler restart never re-pays the load, and a config with ZERO models does no catalog work (gate: the `:llm_model_metadata_fun` seam or a profile list with no `model`).
`Slots`, `Store`, `PubSub` and `RemoteAPI` are PLAIN modules (no GenServer/init/ETS/timer/`:pg`); the only other process here is `PubSub.Throttle` (state: one timer ref), and every live agent adds exactly two outside this subtree (its session + one short-lived exchange worker) — `../agent/session/CONTEXT.md`.
`task_local_counters` is NEVER pruned (`task_agent_counts` is), so one ~100-byte entry per task_id accumulates for the scheduler's lifetime; nothing purges `:evogit_agent_summary`, so a scheduler-only crash leaves dead agents' rows until the ids are reused.
`init/1` seeds `next_agent_id` from `EvoGit.TaskRegistry.AgentStateRead.max_agent_id/1` — a 2 s-bounded offloaded read degrading to `0` (i.e. the bare `1`) on a locked/dead database or an absent `EvoGit.TaskSupervisor` — and `%State{}`'s struct default stays `1`.
`EvoGit.AgentGroupSupervisor` is ONE `one_for_all` group over `[EvoGit.TaskSupervisor, EvoGit.CatalogWarmup, EvoGit.AgentScheduler]` (the warm-up returns `:ignore`), so the offload target is up first and a scheduler crash restarts the whole group; a scheduler started WITHOUT the app tree degrades to `1`.
The `:agent_state_store` init option is the default-inert seam for that read (an isolated test points it at its own agent-state server, because `init/1` runs in the scheduler's process and cannot use the process-dictionary seam).

## Task-Scoped Resource Inventory (per-task on-disk artifacts + teardown hooks)

- **On-disk artifacts**: the worktree is the only DIRECTORY this subtree creates (`.genesis` is git-ignored), removed in EXACTLY one function — `destroy_worktree/3` → `rm_rf_retry`, then prune, then branch delete — whose extra CREATE-path helpers are `Worktrees.destroy_leftovers/3` and `Git.remove_leftover_worktree_dir/1`. The git REF written outside a normal agent branch is the crash-salvage anchor `refs/genesis/salvage/<branch_name>` (never pruned here); `refs/genesis/agent-state/<task_id>/<agent_id>` is written by the SESSION's checkpoint (`../agent_state/CONTEXT.md`).
- **Background jobs rooted under a worktree are REAPED first** (`safe_reap/1` → `BackgroundJobs.reap_under(worktree_path)` IMMEDIATELY BEFORE `rm_rf_retry`); a dead/timed-out registry degrades to a logged no-op.
- **Reclaim follows AGENT PROCESS DEATH, never task completion**; `recycle_agent/2`/`cancel_agent/2`/`handle_agent_crash/3` do ETS deletes only, and the `:finalizing`/merge path never touches worktrees.
- **The managed per-task scratch dir is NOT scheduler-owned**: `EvoGit.TaskTmpdir` is created and reclaimed by `EvoGit.TaskRegistry` (`TaskExecutor.ensure_task_tmpdir/2`), `:per_repo` placing it at `<primary repo>/.genesis/tmp/task_<id>` (orphaned by an app crash).
- **Cancel teardown touches NO disk** (marker + pending message + queue purge; force kill adds the brutal kills), **archive state is persisted per agent, never buffered in RAM**, and this subtree writes NOTHING under `EvoGit.Platform.data_dir/0`.

## Vocabulary Traits (read before renaming anything here)

- `permit` names TWO unrelated resources: a WORKTREE-CREATE admission permit (`WorktreeManager`'s `creating_count`/`admission_queue`, cap `max_concurrent_creation/0`) and a TOOL-CAPACITY permit (`tool_permits.ex`, a `make_ref()` capability). Rename the former "admission slot"; do not rename the tool permit.
- `slot` still names the LEGACY one-holder-per-agent tool pool (`handle_request_tool_slot/3` / `handle_release_tool_slot/2`) that production no longer reaches (`tool_runtime/executor.ex` and `background_jobs.ex` take `acquire_tool_permit/1`); only LLM slots (`with_llm_slot/2`) are on the hot path.
- `model_id` in `Slots.resolve_pool_id/2` (`resolve_model_id/2` is a legacy alias kept for out-of-scope test callers) and the `State.concurrency_for/2`…`update_last_granted/2` family is the provider/ACCOUNT pool id, not a model; `State.pool_id/2` is the primary name, `State.default_model_id/1` its legacy alias, `ModelSelection.pool_id/1` a module-level sibling. New code reads `pool_id`.
- `Store` here is `EvoGit.AgentScheduler.Store` (ETS helpers), never `EvoGit.Store` (SQLite); `ControlPlane` owns the inbox/control/pause tables that `Store.append_pending_user_message/2`, `drain_pending_user_messages/1`, `cancel_requested?/1` and `pause_requested?/1` only delegate to.
- Four verbs describe ONE lifecycle: `register_agent/8` (writes both ETS rows) → `try_dispatch/2` (schedules) → `dispatch.ex`'s private `start_session/1` (DynamicSupervisor), with the hub's PUBLIC `start_session/1` reserved for interactive roots and `spawn_sub_agents/2` as the parent-facing batch entry point; `dispatch_queued_agents/1` and `process_queue/1` both drain `state.queue`.
- The hub's `start_session/1` returns raw `{:error, reason}`, while `RemoteAPI.start_session/1` rewraps it as `{:error, {:start_session_failed, reason}}` — a layer switch must re-map.
- `salvage` intentionally names the same anchored-commit operation for two exits: `Salvage.salvage/3` on an ABNORMAL `:DOWN` (via `salvage_for_retry/2` → `SchedMeta.crash_commit`) and `WorktreeManager.checkpoint_for_pause/1` on a CLEAN pause (→ `agent_states.pause_commit`); both anchor under `refs/genesis/salvage/<branch>`, which reclaim survives because it deletes the agent branch.
- Two DIFFERENT status vocabularies coexist, each defined ONCE with totality accessors: `SchedMeta`'s `@statuses` + accessors (`sched_meta.ex`), and the summary row's on `AgentState` (`status/0`, `statuses/0`, `live_statuses/0`, `terminal_statuses/0`, `live?/1`, `terminal?/1`), which is what `SpawnFacts` and every row reader must use; `InteractiveRoot.accepted_statuses/0` is the third list and is correct only for `SchedMeta` rows.
- Two PRIVATE liveness predicates encode different intents and must not be merged: `ToolPermits.owner_alive?/1` is node-aware (`node(owner) != node() or Process.alive?/1`), `Subagents.waiter_alive?/1` is local-only.
- `safe_call/1` (exit → `{:error, {:exit, reason}}`) and `with_manager/2` (exit → caller-supplied degraded DEFAULT) are deliberate siblings, not duplicates: one returns a result, the other a degraded value; `WorktreeManager.safe_reap/1` is a third variant that also rescues raised errors.
- Duplicated private helpers to extract when next touched: `reply/2` + `clear_batch/2` (`subagent_reattach.ex` ≡ `subagent_rebuild.ex`), `task_number/1` (`resume_plan.ex` ≡ `worktrees.ex`), and the `Salvage.timeout_ms() + @salvage_call_grace_ms` try/catch pair in `worktree_manager.ex`.
- `destroy_worktree/3` and `Worktrees.destroy_leftovers/3` run the SAME rm_rf → prune → branch-delete sequence with the same branch naming, differing only in failure reaction (`{:error, {:worktree_create_failed, msg}}` on the CREATE path vs log-and-continue on reclaim) — intentional, but the shared steps belong in one function.
- `WorktreeManager.workers_dir/1` has NO caller; use `Worktrees.workers_dir/1`.
- `Dispatch.session_mode/2` (private) re-implements `SessionOpts.normalize_mode/1` inline with a lenient fallback instead of delegating.

## Known Issues

- **A crash-retried parent only sees its surviving children's results if it asks for them (`reattach_sub_agents/3`, else `rebuild_subagent_batch/3`)**: a completed batch is retained on the ETS row, which a scheduler/BEAM restart wipes — the durable rebuild covers exactly that case from the children's rows, so only a slot with NO usable durable row reports `{:error, :subagent_result_lost}`. A resumed parent that never asks leaves an ETS-retained batch until a fresh `spawn_validated_subagents/5` overwrites it, paying for the children twice (retained results are never auto-injected). Children of a PERMANENTLY failed parent are still not killed by the crash path — their results are dropped as "Parent recycled" and they keep holding LLM/tool slots and worktrees until they finish (only `force_kill_task_agents/1,2` cascades to them).
- **Crash salvage survival is partial**: `SchedMeta.crash_commit` and `WorktreeManager`'s retained salvage shas live in ETS/GenServer state, so a scheduler or WorktreeManager restart loses them; a retry then relies on the durable candidates (`agent_states.current_commit`, `pause_commit`, the `anchor_ref`) that `ResumePlan`/`ensure_resume_base/4` read back, and on `refs/genesis/salvage/<branch_name>` only through those persisted shas — no code reads that ref by name, and nothing prunes it.
- **A create pipeline that hangs FOREVER holds one admission permit, and its blocked caller is not cancellable by timeout**: `create_worktree_for_agent/6` waits `:infinity` while the create runs in an unlinked `Task.start` nothing kills, so a create stuck in a blocking syscall (wedged NFS, anti-virus holding the tree) neither fails nor returns; `creating_count` only decrements on the `{:create_finished, agent_id}` cast, so four such creates saturate the default cap of 4 and `admission_queue` starves silently (no stall detection or logging). Escapes: force-kill / graceful-cancel the task (its monitor moves the `:creating` registration to `pending_cleanup`, but the create task and its permit survive); restart `WorktreeManager` (resets `creating_count`); restart the BEAM (orphans the stuck worktrees).
  A SESSION caller of that call IS bounded even though the manager is not: the session runs the whole setup in ONE monitored start task (`agent/session/CONTEXT.md`), warns at `:worktree_create_slow_warn_ms` (120 s default), fails with the terminal `{:error, {:worktree_create_stalled, ms}}` at `:worktree_create_stall_timeout_ms` (1 800 s default), and accepts `{:cancel, :force}` while `:starting` — none of which touches the stuck create or its permit. A DIRECT caller still waits `:infinity`.
- **Out-of-scope `terminal?/1` mismatch (reported, not fixed here)**: two identically-named public predicates outside this subtree disagree on the unknown shape — `agent/tools/job_output.ex` answers "not in `@live_statuses`" (an unknown/absent status is TERMINAL) while `background_jobs/notice.ex` matches an explicit `[:completed, :killed, :failed]` list (an unknown status is NOT terminal). Inside `agent_scheduler/**` the name means ONE thing: `AgentState.terminal?/1` is the total complement of `live?/1`, and a `nil`/unknown status is neither live nor terminal.
- **`@doc`/spec drift on the RPC facade**: `RemoteAPI.list_agents/0`'s `@doc` lists statuses without `:awaiting_input`/`:pausing`/`:paused`; `reload_config/0`'s `@spec` promises `:ok | {:error, String.t()}` while the delegated path can answer other `{:error, term()}`; `get_foreign_repo_commits/1` specifies `%{atom() => String.t()}` although the keys are STRING repo ids; `agent_states_by_id/0` hand-rolls an `:ets.select` over `:evogit_agent_summary` instead of going through `Store`, and `normalize_context_window/1` repeats the `200_000` default owned by `AgentState`.

## Constraints

- Data structs are plain data with no behaviour/callbacks; `Slots`, `Worktrees`, `Dispatch`, `Subagents`, `Lifecycle`, `State` are pure functions over `State.t()`, and GenServer state must always be `%State{}` (struct update, not `Map.put/3`).
- `AgentState` is shared (scheduler + agent processes); `SchedMeta` is scheduler-exclusive.
- The scheduler process NEVER does blocking filesystem I/O or calls ANY worktree function: git work happens in the agent's exchange worker (and the session's start task for its worktree create), and ALL worktree filesystem operations (rm_rf, mkdir_p, prune_worktrees, delete_branch, salvage commits) belong to `WorktreeManager` (through `Salvage`). The worktree calls are the session's `Setup.bind_worktree/2` → `create_worktree_for_agent/6` (`:infinity`, SESSION pid monitored, exactly one reply, `:DOWN` reclaim) and `Lifecycle`'s `salvage_for_retry/2` on a crash RETRY (bounded, total). The ONE git call the scheduler itself makes is the retry-only, read-only `Salvage.commit_exists?/2` (`git cat-file -e`) validating a recorded `crash_commit` before using it as the worktree base.
- The scheduler likewise NEVER makes a synchronous durable-state call: its resume base comes from `spec.opts` and, only on a direct dispatch without one, from ONE bounded `EvoGit.TaskRegistry.AgentStateRead` read (2 s, degrading to `nil`).
- Slot availability is derived from holder MapSets and permit monitors, never an integer counter. `SchedMeta.session_pid` stores the agent's `EvoGit.Agent.Session` pid (cancelled through `Session.cancel/2`); `ref_to_agent` keys on the session monitor ref.
- `case`/`with` guards on ETS lookups only where a genuine race can make the entry absent (`recycle_agent`, `try_dispatch`, `cancel_agent`).

## Per-message timestamp metadata convention

Every message in an agent's session memory (`%ReqLLM.Message{}` list in `%ReqLLM.Context{}.messages`, held in the session-owned `%EvoGit.Agent.State{}.context`) carries `metadata[:timestamp]` — Unix seconds (`EvoGit.Agent.Clock.now_seconds/0`: the real clock by default, pinnable per exchange/turn through the opts `:now` key) — plus an atom-keyed integer like `:turn`, stamped at message-CREATION time in agent code, never in the Store.
`ContextBuilder.tag_message_turn/2` is the single choke point (sets `metadata[:turn]` + `metadata[:timestamp]` idempotently via `Map.put_new`); `tag_message_timestamp/1` stamps just the timestamp (nudge + compression-summary sites); the creation-site inventory lives in `agent/CONTEXT.md`.
`Store` never writes conversation data and no read-back exists — the dashboard reads `msg.metadata[:timestamp]` from `RemoteAPI.get_agent_history/1`, interpreted as Unix SECONDS (`EvoDashWeb.Helpers.format_history_timestamp/1`) — do NOT change granularity without updating evo_dash.
