# TaskRegistry Support Modules

## Intent
Support modules behind the `EvoGit.TaskRegistry` GenServer, which owns the task-lifecycle state machine (transitions, lease/heartbeat, cancel/force kill, pause/resume, startup reconciliation, review status).
Every module here is pure-function, ETS-only or a bounded offloaded read task — none owns GenServer state.

## Routing Table
None — leaf directory (all modules at this level).

## Process-Scoped Isolation Seam

`EvoGit.TaskRegistry.server/0` resolves the registry name for the CURRENT process AT CALL TIME (`:evogit_task_registry_server` pdict, else `__MODULE__`); every client function routes through it EXCEPT `put_task_archive/1`, which only uses it to find that instance's store.
An isolated pair is `EvoGit.Store.start_link(name:, data_dir:)` + `EvoGit.TaskRegistry.start_link(name:, task_store:, data_dir:)`; the app-global singletons are never started or stopped, Store clients take an explicit `store`, and several instances need explicit `id:`/`:name`.
An `:agent_state_server` pid option lands under `:evogit_agent_state_server`, so an isolated registry reads, flushes and cascades against its OWN `EvoGit.AgentState`; there is NO mount state, so `task_store` alone isolates it.
`init/1` passes the registered name as the 4th wrapper-spawn argument and publishes `name => task_store` into the APP-OWNED ETS table `:evogit_task_registry_stores` (created in `EvoGit.Application.start/2`, survives registry restarts) — how `put_task_archive/1` resolves a store without touching the mailbox (unpublished → `EvoGit.Store`).
Processes not descending from the wrapper (self-reflective `agent/tools/*`, `agent_scheduler/remote_api.ex`, evo_dash callers) never inherit the key, so their suites stay serialized against the global singleton.

## Constraints

- **Task-type whitelist**: `start_task/2` is TYPE-AGNOSTIC; `do_execute_task/3` has one clause per type (`:genesis`, `:evolve`, `:extract_skills`, `:reflect`) and NO catch-all (unknown → `FunctionClauseError` → `:failed`); `type` round-trips `Store.Codec.@known_atoms` (`decode_atom` → `nil` otherwise), so a NEW type MUST be added there.
- **Purity**: no GenServer state; I/O only in `Cleanup` (Store deletion), `ReadOffload`/`AgentStateRead` (supervised read workers) and `TaskExecutor` (`TaskTmpdir.ensure/2`, run OUTSIDE the GenServer under `Task.Supervisor`); `RuntimeOpts`/`ResumeContext`/`MergeContext`/`PrevTaskRepos` are pure builders and `Pause` only validates + persists.
- **NO synchronous durable-state call in the registry process**: the agent-state cascade is a cast, and every registry-side durable READ (ROOT-run roster, `pause_commit`, the `max_agent_id` boot seed) goes through `AgentStateRead`'s bounded offload.
- **Reaping is SQLite-row-only** — init reconciliation, `:lease_sweep`, `cleanup_expired_tasks/1`, `:periodic_cleanup`, `clear_finished_tasks` and `delete_task` touch only `tasks.sqlite` rows (plus cascaded `agent_state.sqlite` rows), the in-memory `task_refs` entry and the `:evogit_cancelling_tasks` marker; worktree reclamation belongs to `AgentScheduler.WorktreeManager` (`:DOWN`-driven).
- **Task delete cascades to durable agent state as a TOTAL CAST**: one `AgentState.delete_task/2` after a successful row delete, one batched `delete_tasks/2` for `clear_finished_tasks/0`, so a stopped/locked/dead `agent_state.sqlite` can neither fail nor delay a delete; `cleanup_expired_tasks/1`'s age/count deletions carry NO cascade.
- **`task_registry.ex` stays long by design** — it IS the task-lifecycle state machine.

## Task Status Sets & `:awaiting_input`

`:awaiting_input` is NON-TERMINAL: an interactive session yielded on a tool-free reply and waits for its next message.
Its wrapper is alive, so the row is LIVE (lease renewed, never swept as leaked, never deleted by `clear_finished_tasks`) but IDLE — no LLM slot, tool slot or worker — so it must not count toward an update/idle gate (that "busy" set belongs to the dashboard / `/server/status`).
Sessions are in-memory only, so boot reconciliation resolves an orphaned `:awaiting_input` row to `:failed` ("Runtime restarted during interactive session", `error.kind :restart`, `source :startup_reconcile`) — never resumed.
`:running` ↔ `:awaiting_input` is an ordinary legal non-terminal pair (a plain `update_task_status/4` write; `finished_at` and the lease untouched); `:awaiting_input → :cancelled` is IMMEDIATE (never via `:cancelling`).
`EvoGit.TaskRegistry.update_status/2` is the status-only cast the session lifecycle calls (through `update_task_status/4`, so the stale-terminal guard and `:cancelling` force-map apply); it carries no result, is for non-terminal flips only, and a repeat of the current status writes and broadcasts nothing.
Status enumerations live ONE place each with a `@doc false` accessor so a table-driven test asserts totality (`:awaiting_input` wherever `:running` appears, `:pausing` wherever `:running` appears, `:paused` wherever `:awaiting_input` appears):

| Owner | Accessor | Content | Meaning |
|---|---|---|---|
| `lease.ex` | `renewed_statuses/0` | `[:running, :pending, :cancelling, :awaiting_input, :pausing]` | heartbeat-renewed (`:paused` deliberately absent: no wrapper, no lease) |
| `lease.ex` | `leaked_statuses/0` | `[:running, :awaiting_input, :pausing]` | the one-shot sweep may fail these; `:paused` is a legitimate resting row |
| `task_registry.ex` | `terminal_statuses/0` | `[:completed, :failed, :cancelled]` | no further transition except terminal → `:completed`; `:pausing`/`:paused` are NON-terminal |
| `task_registry.ex` | `killable_statuses/0` | `[:running, :awaiting_input, :cancelling, :pausing, :paused]` | `force_kill_task/1` accepts these |
| `task_registry.ex` | `gracefully_cancellable_statuses/0` | `[:running, :awaiting_input, :pausing, :paused]` | `cancel_task/1` accepts these (`:running` → `:cancelling` grace; `:awaiting_input`/`:paused` → immediate `:cancelled`; `:pausing` abandons the pause first) |
| `task_registry.ex` | `unstartable_statuses/0` | `[:cancelled, :cancelling, :awaiting_input, :pausing, :paused]` | `start_task/2` refuses these ids (a paused row owns its id for `resume_task/1`) |
| `task_registry.ex` | `finalizing_ignored_statuses/0` | `[:completed, :cancelled, :cancelling, :pausing, :paused]` | a `:finalizing` broadcast is ignored (`:awaiting_input` and `:failed` deliberately ABSENT — see Known Issues) |
| `task_registry.ex` | `active_statuses/0` | `[:running, :pending, :finalizing, :cancelling, :awaiting_input, :pausing, :paused]` | "a live task whose wrapper exists" — the in-flight set, NOT the busy set |

Store-side halves (not owned here): `Store.Codec.@known_statuses`, `Store.Types.Status`, `TaskInfo.status`, and `Store.Operations.Lightweight`'s `@live_statuses` (else `clear_finished_tasks` deletes a waiting session) and `@lease_statuses` (else init reconciliation and the sweep never see it).

## RuntimeOpts Key Contract

`build_common_runtime_opts(opts, task_id, task_type)` returns `{nil, runtime_opts}` BY CONTRACT: element 0 is a reserved placeholder no caller may consume and the pair must NOT be unwrapped (~20 tests pattern-match it).
`:path` is REQUIRED (`Keyword.fetch!` → `KeyError`; never `:repo_path`), persisted as `tasks.project_path` and the `:per_repo` tmpdir base; validation is DOWNSTREAM (runtimes default to `File.cwd!()`, `Platform.safe_expand/1`, then `Runtime.ensure_repo/1` + `Runtime.Helpers.validate_repo_path!/1`, which reject non-repos and UNC roots).
`:node_path` is a repo-RELATIVE context-tree directory (`validate_node_path/2` rejects absolute paths and needs an existing dir with CONTEXT.md); a dashboard cluster node is a SEPARATE ARGUMENT of `EvoDash.NodeContext.start_task/3`.
`:mode` is a STRING (`"new"`/`"existing"` genesis, `"simple"`/`"custom"` evolve) via `mode_atom/2`; an ATOM raises `ArgumentError`, a MISSING mode defaults to `"simple"` (raises for genesis), and genesis `"custom"` raises (evolve-only).
Always emitted: `repo_path`, `mode` (atom) and `task_id`; `put_if/4` filters only nil/false, so empty strings/lists pass for `node_path`/`starting_commit`/`foreign_repos`/`archive`/`build_system` while `agent` needs a non-empty binary, and every other input key is silently DROPPED.
`admit_model_selection(opts, config)` runs BEFORE enqueue and is rechecked by `execute_task/4` before tmpdir/dispatch: a PRESENT `:model_spec` wins over legacy `:model_id` even when invalid; Auto (neither key, or an empty legacy id) drops both selection keys AND `:model_id_locked`; an explicit selection is checked by `Config.Schema.resolve_model_spec/2`.
`model_spec` is the STRING-keyed `provider_profile_id`/`model`/optional `reasoning_effort` map (a non-map is `{:error, :invalid_model_spec}`), and `canonical_model_spec/1` materializes only the schema's resolved top-level fields (no profile, generation parameter or credential reaches task opts).
`admit_task_path/1` admits absent/`nil` (repo-less `:reflect`) and any ordinary binary without an absoluteness check, refuses `vct:///workspaces/…` (`:workspace_not_executable`) and any other `vct:` point (`:vct_point_not_executable`), and answers `:invalid_path` for a present non-binary; the builder raises a descriptive `ArgumentError` for a `vct:` path and copies the path verbatim.
`:attachments` is validated UNCONDITIONALLY via `EvoGit.Attachments.validate/1` (nil/`[]` → `:ok`; malformed → `ArgumentError`) and put only when non-nil and non-`[]`, as STRING-keyed base64 maps.
`:session_mode` is OPTIONAL (`"oneshot"` default, the key then OMITTED so one-shot paths stay byte-identical), a STRING in the builder, gated by `admit_session_mode/1` (`{:error, :invalid_session_mode}`); `:persistent_state` is an OPTIONAL BOOLEAN defaulting to `true` (whole task, root plus descendants) and ALWAYS present, with `persistent_state/1` raising on a non-boolean and `admit_persistent_state/1` the non-raising gate (absent/`nil` pass); the `:reflect` path builds neither key, and both persist with the raw opts.
`:quality_level` is normalized via `EvoGit.QualityLevel.normalize/1` (anything unusable → warning + `"balanced"`) and appended ONLY when ≠ `"balanced"`; `:objective` defaults to `""` ONLY when absent (an explicit nil is not defaulted); `:starting_commit` has NO default (absent → the runtime resolves HEAD via `PhyloGraphNode.current_head/1`; present → it must `git rev-parse` cleanly or evolution fails).
`:foreign_repos` (list of `%ForeignRepo{}`) is threaded VERBATIM and unvalidated here (a non-list passes too); normalization lives in `Runtime.Helpers.load_foreign_repos/2` (a task-opts entry REPLACES the genesis.toml entry wholesale, id-keyed merge), and the persisted JSON nests it as an ARRAY of STRING-keyed objects with only the OUTER key atomized, so every reader normalizes via `ForeignRepo.normalize/1`.
`ResumeContext`/`MergeContext` preserve caller-supplied model keys but never inherit the previous task's selection or its lock, while the reflect and skill-extraction paths sit outside this whitelist.

## TaskExecutor Dispatch & Task Start

`execute_task/4` defaults `server` to its own module `EvoGit.TaskRegistry.TaskExecutor` (NOT the production registry name), so wrapper callers must supply the explicit fourth argument.
It installs `server` in the `:evogit_task_registry_server` pdict FIRST, then checks `RuntimeOpts.admit_model_selection(opts, EvoGit.Config.resolve())` (an error returns unchanged before tmpdir creation or process registration), then `ensure_task_tmpdir/2`, then private `do_execute_task/3`: `:genesis` → `Runtime.Genesis.run(prompt, runtime_opts)`; `:evolve` → merge-context step, then resume-context-or-plain, then `Runtime.Evolution.run(objective, runtime_opts)`; `:extract_skills` → `Runtime.SkillExtraction.run(runtime_opts)`; `:reflect` → `Runtime.SelfReflective.run(opts ++ [task_id: task_id])`, or `Runtime.Assistant.run/2` when `:session_mode` is `"interactive"` (any other value keeps the byte-identical `SelfReflective.run/1` call).
Every clause FIRST calls `register_task_process/1` (`Registry.register(EvoGit.TaskRegistry.ProcessRegistry, task_id, :task)`), the runtime call is the LAST expression (synchronous, returned verbatim), the module has ZERO `Logger`/`IO` calls, and no helper here calls `CommandApproval` (those hooks live in the parent registry).
`:reflect` bypasses `build_common_runtime_opts` (whose `Keyword.fetch!(:path)` would `KeyError`) and returns `{:ok, %{result: …, commit_sha: nil, branch_name: nil, tag: nil}}`; with no `:usage`/`:agent_count` those columns stay NULL and `tasks.result` is its only durable artifact.
**The wrapper never writes statuses**; the TaskRegistry GenServer performs every write from `{ref, result}`, `:DOWN`, the `:finalizing` handler and `update_status` casts.
`start_task/2` mints an id via `generate_id/0`, then `handle_call({:start_task, ...})`: refuse `unstartable_statuses/0` with `{:error, :cancelled}` → the four non-raising gates (`admit_task_path/1`, `admit_model_selection/2`, `admit_session_mode/1`, `admit_persistent_state/1`), replying `{:error, reason}` and enqueuing nothing → `Task.Supervisor.async_nolink(EvoGit.TaskSupervisor, TaskExecutor, :execute_task, [task_type, opts, task_id, state.server_name])` → persist `%TaskInfo{status: :running, opts: <ADMITTED opts>, started_at, logs: [], result: nil, lease_expires_at: now + 120 s, model_id: opts[:model_id]}` (store faults → warning/no-op, in-memory only) → `task_refs` entry → broadcast `:running` → `{:ok, task}`.
TaskRegistry creates NO on-disk state, and no `create_task` exists anywhere in evo_git/evo_dash.
All opts defaults live in the CALLERS: the dashboard (`ProjectsLive.handle_event("task_submit", ...)`) and the `StartTask.start_task` shell handler; the remaining defaults (`:prompt`/`:objective` → `""`, mode → `"simple"`) live in TaskExecutor/RuntimeOpts.
Remote path: `RemoteAPI.start_task/2` → `TaskRegistry.start_task/2` via `RemoteNode.start_task/2` / `NodeContext.start_task/3`; the shell's `StartTask.start_task` calls the local registry directly.
`resolve_recheck_task/3` recovers a task whose wrapper died before replying (best-effort result via `Lease.lookup_sched_meta_result/1`, fallback `:completed`) and shares the `{:ok, %{branch_name: _}}` extraction with `handle_update_status/6`.

## Per-Task Tmpdir Lifecycle

Each task owns ONE managed scratch directory shared by all its agents (`EvoGit.TaskTmpdir`, a PARENT-node file; `[tmp] mode` and path resolution live there — `../sandbox/CONTEXT.md`).
- **Create trigger (here)**: `execute_task/4` calls private `ensure_task_tmpdir/2` after the pdict seam and model admission, BEFORE dispatch, so a rejected selection creates no tmpdir; it calls `EvoGit.TaskTmpdir.ensure(task_id, Keyword.get(opts, :path))` and discards the path. `ensure/2` never raises from its mkdir step, but its PATH RESOLUTION is not exception-free (`System.tmp_dir!()` raises when no writable temp dir exists, aborting the wrapper BEFORE dispatch).
- **Reclaim is event-driven ONLY**: `EvoGit.TaskTmpdir.reclaim/2` removes `task_<id>` on a terminal status — from `handle_update_status/6` plus the direct terminal writes that bypass it (`force_kill_task/1`, `cancel_task/1`'s `:pending` arm, `:lease_sweep`, `resolve_recheck_task/3`); no boot reaper, no periodic sweep. It never deletes outside the managed root nor the root itself; `handle_update_status/6` reads the FINAL (post force-map) status, so `:cancelling`/`:finalizing` never reclaim.
- **Gotchas**: `cleanup_expired_tasks/1` deletes ROWS, never directories; a dir orphaned by a full-runtime CRASH is NEVER reaped automatically; `[tmp] mode` is re-resolved at RECLAIM time (never stored per task), so changing it mid-flight can orphan the dir created under the old mode.

## OS Surface & Portability

The only OS API is `System.system_time(:second)` (lease arithmetic) — no `System.cmd`, `Port.open`, `:os.*` or file I/O beyond `TaskExecutor`'s `TaskTmpdir` call, so no Windows-only crash can ORIGINATE here; the tmpdir BINARY later reaches the Windows sandbox's `Port.open`, whose env pairs MUST be charlists (OTP-29) — convert at that call site (`../sandbox/CONTEXT.md`).

## Failed-Task Error Persistence (`TaskInfo.error`)

Every transition to `:failed` records a 4-key map (ATOM keys after decode) in the dedicated `error` column (JSON TEXT): `%{kind: atom, source: atom, message: String.t(), stacktrace: [String.t()] | nil}`, available in the full-decode paths (`Store.get_task/1`, `list_tasks_paginated/1`) and the 16-key summary projection (lenient `Codec.decode_error/1`; nil for non-failed rows).
`kind` ∈ `:error | :exit | :down | :force_kill | :timeout | :restart | :lease_expired | :recheck`; `source` ∈ `:result_handler | :down_handler | :force_kill_task | :finalizing_watchdog | :startup_reconcile | :lease_sweep | :recheck_resolve`; the sole producer is the pure `Diagnostics.failure_error/3,4`, decode is lenient, `:cancelled` is NOT a failure, and `handle_update_status/6` appends `error:` ONLY when the FINAL persisted status is `:failed`.

| Source | kind | message (also written as `result` unless noted) |
|---|---|---|
| wrapper `{:error, reason}` | `:error` | `"Task failed: #{inspect(reason)}"` |
| wrapper `{:exit, reason}` | `:exit` | `"Task exited: ..."` |
| abnormal `:DOWN` (only when `Lease.sched_meta_has_active_agents?/1` is false) | `:down` | `"Task process exited: #{inspect(reason)}"` |
| stuck-`:finalizing` watchdog | `:timeout` | `"Finalization did not complete within N minutes"` |
| force kill | `:force_kill` | `"Task force-killed by user"` (`result` stays nil) |
| startup reconciliation | `:restart` | `"Runtime restarted during task finalization"` |
| lease sweep | `:lease_expired` | `"Lease expired; owning instance no longer renewing"` |

`stacktrace` holds the last 8 frames for the wrapper-result and `:DOWN` sites and nil elsewhere.
The wrapper-result error rides `update_task_status_with_caller(..., error: error)` → self-cast → `handle_update_status/6`; `result` is PRESERVED as the RAW error tuple (Codec `{"__result_tag__": "error", …}` decoding back to `{:error, reason}`), while `usage`/`agent_count`/`commit_sha`/`branch_name` stay nil; `finished_at` IS set, the lease cleared, and the wrapper exits `:normal` — no raise, no retry.

## Restart Recovery & Status Transitions

**Startup reconciliation.** `init/1` runs `EvoGit.Store.select_running_lease_info/1` (id + status + lease_expires_at); each `:finalizing`/`:cancelling`/`:awaiting_input` row gets a SYNCHRONOUS `handle_update_status/6` with `{:startup_reconcile, ...}` caller info: `:finalizing` → `:failed`, `:cancelling` → `:cancelled`, `:awaiting_input` → `:failed`.
A `:running`/`:pausing` row takes the PAUSE classification instead: RESUMABLE → `:paused` + `pause_kind: :dirty` (`park_dirty_pause/2` applying the `Restart.classify/2` verdict), non-resumable → left to the one-shot `:lease_sweep`, which fails it with `:lease_expired`.
The handler narrow-reads `select_task_update_info/2` (status/opts/finished_at/lease — no full decode), applies the stale guard, handles finished_at/lease, broadcasts `{:task_updated, task_id, status, node()}` and cleans `task_refs`; init writes are SYNCHRONOUS (an async cast would race callers).
`state.task_refs` is in-memory only — empty after restart, so `{ref, result}` / `{:DOWN, ...}` never fire for pre-restart tasks.

- **Lease mechanics**: `@lease_duration` 120 s, `@heartbeat_interval` 60_000 ms; the lease is set at start, renewed via `Store.renew_leases/3` only for `Lease.lease_renewable?/1` statuses plus `{:unknown, raw}`, and `:lease_sweep` (one-shot, 150 s after init = `(@lease_duration + 30) * 1000`) fails a `Lease.leaked?/3` row — a KNOWN `leaked_statuses/0` row, lease expired/missing, agent-free per `sched_meta_has_active_agents?/1` — then runs cleanup + broadcasts; `:finalizing` is excluded by design, `:paused` is never swept and `{:unknown, raw}` is never leaked.
- `:periodic_cleanup` → `cleanup_expired_tasks/1` deletes only rows with `finished_at != nil`.
- **Resolution paths for `:finalizing`**: (a) startup reconcile → `:failed`; (b) `clear_finished_tasks` (`select_finished_task_ids`' SQL `status NOT IN ('running','pending','cancelling')` INCLUDES it) or `delete_task`; (c) in-process wrapper completion/crash or the `update_task_status/4` cast (the stale guard blocks terminal→terminal except → `:completed`; `cancel_task` from `:finalizing` → `{:error, :not_running}`); (d) the stuck-`:finalizing` watchdog. Lease expiry plays NO role here.
- **Stuck-`:finalizing` grace watchdog**: on a SUCCESSFUL persist of `:finalizing` the handler schedules ONE-SHOT `{:recheck_task, task_id}`; grace minutes come from the app-env seam `:finalizing_watchdog_grace_minutes` read at SCHEDULE time (`false` → DISABLED; unset/nil or anything non-numeric → **60**; numeric ≥ 0 → that many — `config/config.exs` 60, `config/test.exs` 1). At fire time the dedicated `%TaskInfo{status: :finalizing}` arm calls `resolve_finalizing_watchdog/3` and resolves `:failed` through `handle_update_status/6`; it does NOT check `sched_meta_has_active_agents?`, does NOT reschedule, and leaves residual agent state untouched (timers are per-boot; a restart mid-grace is covered by init reconciliation).
- **Late-wrapper-result semantics** (pinned in `persistence_test.exs`): after the watchdog resolved `:failed`, a still-alive wrapper's `{ref, result}` / `{:DOWN, ...}` handlers are complete NO-OPS — the terminal branch deleted the `task_refs` entry, `Process.demonitor(ref, [:flush])` clears queued `:DOWN`, and nothing re-adds the task.
- **`resolve_recheck_task/3` and its 30 s live-agent reschedule are effectively unreachable**: `Lease.lookup_sched_meta_result/1` is reached only from the recheck handler's generic arm for non-terminal, non-`:finalizing` rows, which nothing schedules.
- **Stuck-`:finalizing` cause**: `Runtime.Helpers.notify_finalizing/1` broadcasts from INSIDE the runtime phase, right after `AgentScheduler.run_agent` returns and BEFORE `merge_and_report/4`, so a blocked merge blocks the wrapper while the status stays `:finalizing`.

## Task-Level Pause & Resume

A task-level pause (`docs/task-pause.md`) winds ONE named task DOWN to a durable, resumable RESTING state — neither a cancel nor a failure, resting on the `agent_state.sqlite` substrate.
`:pausing` (draining — wrapper alive, lease renewed) and `:paused` (every agent stopped at a turn boundary with its worktree and state checkpointed — no lease, no wrapper, `finished_at` nil) are NON-terminal.
`pause_kind` (`:clean | :dirty | nil`, `tasks.pause_kind`) is the ONE persisted discriminator: `:clean` = the user paused (resume repairs nothing), `:dirty` = a restart brought the row back (the last tool batch may be partial, so resume runs the crash repair), `nil` = not paused; `:cancelled` keeps meaning "gracefully cancelled".
`TaskRegistry.pause_task/1` / `resume_task/1` are `GenServer.call`s (validation/persistence in `Pause`), mirrored by `RemoteAPI`/`RemoteNode`; `pause_task/1` → `:ok` (including idempotent `:pausing`/`:paused`) or `{:error, :not_found | :not_pausable | :not_resumable | :not_running | :scheduler_unavailable | :disk_full | :store_unavailable}`, `resume_task/1` → `:ok` or `{:error, :not_found | :not_paused | :not_resumable | <admission reason>}`.

**Pause (clean).** Only `:running` transitions for real: an interactive-session task (`:awaiting_input`, or persisted `:session_mode == "interactive"`) is `{:error, :not_pausable}`, a stored `:persistent_state == false` (or non-boolean) is `{:error, :not_resumable}`, `:pausing`/`:paused` are idempotent no-ops, and `:pending`/`:finalizing`/`:cancelling`/terminal rows are `{:error, :not_running}`.
`Pause.pause/2` writes `:pausing` FIRST, then calls `EvoGit.AgentScheduler.begin_task_pause/1` (sets the `:evogit_task_pause` marker, flips each agent's control-plane pause flag, purges their queued LLM/tool slot waits with `{:error, :paused}`); a down/timing-out scheduler reverts the row to `:running` with `{:error, :scheduler_unavailable}` (a `:pausing` row with nothing to drain is unrecoverable without a restart), and `{:task_updated, task_id, :pausing, node()}` broadcasts after that call, only for a real transition.
Each agent honours the flag at a TURN BOUNDARY (never mid-tool), reaps background jobs, commits a worktree checkpoint, flushes durable state and delivers `{:paused, info}`; `info.durable` is `true` only when `EvoGit.AgentState.flush/1` answered `:ok`, and the ROOT reports only after its children paused, so ONE wrapper result closes the task.
The `{:paused, info}` arm of `handle_wrapper_result/3` writes a TARGETED `status: :paused, pause_kind: :clean, finished_at: nil, lease_expires_at: nil` (never a full `put_task`, so `result`/`usage`/`commit_sha`/`branch_name`/`started_at`/`opts` stay byte-identical and a resume ACCUMULATES usage), broadcasts on that successful write and reuses the terminal in-memory cleanup (`task_refs` dropped, marker cleared via `Pause.abandon/1`); worktrees are reclaimed normally because the checkpoint commit survives. No `:finalizing` and no merge run for a pause.

**Straggler guard.** A late `{:ok, %Result{}}`/`{:error, _}`/`:DOWN` on a `:pausing`/`:paused` row is DISCARDED (`pause_settled?/2` + `discard_paused_result/3`, logging only the RESULT SHAPE), so it can never resurrect a paused task or clobber result/usage; a `{:paused, info}` report on a `:cancelling` row resolves it the cancellation way (`:cancelled` — a cancel during the drain WINS), and on a terminal or `:awaiting_input` row it is discarded outright.

**Resume.** `resume_task/1` accepts `:paused` ONLY and re-enqueues the SAME task id with the PERSISTED opts — never `start_task/2` (a fresh id would reset the archive roster).
It re-runs `start_task/2`'s four admissions against the CURRENT config, requires the durable ROOT run (`read_root_run/2`: ONE bounded, offloaded `AgentStateRead.roster/2` read whose ROOT is the record with an absent `parent_id`; no durable row or a CHILD-only roster is `{:error, :not_resumable}`), clears the stale scheduler pause marker FIRST, spawns the wrapper through the registry's call-time seam (`wrapper_spawn_fun`), and only then writes `status: :running, finished_at: nil, error: nil, pause_kind: nil` + a FRESH lease (a failed write stops the spawned wrapper), broadcasting `{:task_updated, task_id, :running, node()}`.
Spawn opts carry `resume_kind: :clean_pause` (`pause_kind == :clean` or legacy `nil`) or `:dirty_pause` (forwarded by `RuntimeOpts.build_common_runtime_opts/3` to `spec.opts`) plus the ROOT row's five facts — `pause_commit`, `resume_agent_id` (the persisted root id, so every `(task_id, agent_id)` durable read still resolves), `resume_current_commit`, `resume_branch`, `resume_anchor_ref` (`fields[:anchor_ref]`, else `EvoGit.AgentState.Anchor.ref/2`) — each PRESENCE-based with its value (`nil` = "resolved, nothing stored"), so dispatch never reads the durable database on its hot path while a non-resume run's opts stay byte-identical; `RuntimeOpts.resume_fact_keys/0` is the ONE key list shared with `Runtime.Helpers.build_root_agent_spec/7`.
`AgentScheduler.Dispatch` bases the resumed worktree on `:pause_commit` (`meta.crash_commit` first, both `git cat-file -e`-verified, degrading to the task base) and carries the other facts as the persisted root identity; `EvoGit.Agent.Resume` picks the narration (clean = NO repair only while the transcript proves it intact (`clean_pause_intact?/1`), else repair; dirty = crash repair + ONE `[RESUME]` notice).
**The resumed ROSTER is the whole tree**: the resumed parent's dangling subagent calls are rebuilt from the durable roster by `EvoGit.Agent.Resume.RosterBatch.plan/4` — a `status == "done"` child contributes its stored result (no re-spawn, no double cost), a `status == "running"` child is re-spawned on its OWN anchored commit/branch with its restored conversation (`:resume_agent_id`, `:resume_current_commit`, `:resume_branch`, `:resume_anchor_ref`, `:restore_agent_state: true`, `:resume_kind` deliberately ABSENT), a child with no rebuildable row degrades to `:missing` → `{:error, :subagent_result_lost}`, and each re-spawned child recurses into its own batch. Clean vs dirty therefore differs ONLY in narration/repair, never in roster scope.
The archive roster is PRESERVED: `AgentScheduler.run_agent/2` skips its per-task archive reset when the spec opts carry `resume_kind`, so archived completions UPSERT onto the paused run's rows (keyed `(task_id, agent_id)`); `:paused` defeats `clear_finished_tasks` because it lives in `Lightweight.live_statuses/0` while carrying `finished_at: nil`.

**Restart mapping.** `init/1` owns the rows present AT BOOT, `:lease_sweep` the ones that become owner-less later; both park a RESUMABLE wrapper-less `:running`/`:pausing` row as `:paused` + `pause_kind: :dirty` (`finished_at` nil, lease cleared, result/usage untouched, one broadcast AFTER the persist) and otherwise keep the sweep-fail path — classifier detail: § Heartbeat, Restart Classification & `list_tasks/0` Bound.

## Graceful Cancellation & Force Kill

The **`{:task_updated, id, :finalizing, node}` handler** matches ONLY `:finalizing`, with a node-filter guard `when node == node()` plus a no-op clause for other nodes (task ids are per-node); a `:cancelling` task ignores phase-finalization broadcasts, and a successful persist schedules the one-shot watchdog.
`handle_update_status/6` force-maps the final result: stored `:cancelling` + incoming `:completed | :failed` → persisted `:cancelled`, with result/usage/archive flowing through untouched (never nil'd).
**`:cancelling`** is the graceful-cancel state, deliberately NON-terminal: the `task_refs` entry stays, `finished_at` stays nil and the lease stays valid; it is whitelisted in `Store.Codec.@known_atoms`, `Store.select_finished_task_ids` keeps `clear_finished_tasks` from deleting in-flight cancelling tasks (while `:finalizing` still counts as finished), `Store.select_running_lease_info` includes it, and startup reconciliation maps it to `:cancelled`.
**`TaskRegistry.cancel_task/1` is GRACEFUL**:

- `:pending` → immediate `:cancelled` write (finished_at set, lease cleared) + broadcast only on the successful write.
- `:running` → `handle_update_status(..., :cancelling, ...)` (the ONLY broadcast for this arm; non-terminal, so finished_at/lease/task_refs stay), then `AgentScheduler.begin_graceful_cancel(task_id)` (`:exit`-guarded — a down scheduler leaves the task `:cancelling` for force kill or restart reconciliation).
- `:awaiting_input` → immediate terminal `:cancelled` write (lease cleared, NO `result` column so transcript/result is preserved) + `clear_cancelling_marker/1` + tmpdir reclaim + broadcast; the idle session is stopped best-effort BEFORE the write (task-addressed `AgentScheduler.force_kill_task_agents_for_task/1`, then `Task.shutdown(ref, :brutal_kill)` while the task_refs entry is still present so the kill's `:DOWN` cannot race the write).
- `:pausing` → the pause is ABANDONED first (`Pause.abandon/1`) and the `:running` arm then runs, so a cancel that arrives mid-drain wins and the pause can never be re-introduced.
- `:paused` → immediate terminal `:cancelled` write exactly like an idle session (lease cleared, `pause_kind: nil`, result/usage preserved).
- `:cancelling` → `:ok` idempotent (does NOT re-send the cancel message).
- terminal, `:finalizing` or `{:unknown, raw}` → `{:error, :not_running}`; missing → `{:error, :not_found}`.

**`TaskRegistry.force_kill_task/1`**: gate `killable_statuses/0` (`pause_kind` cleared in the same write) → `AgentScheduler.force_kill_task_agents(pid)` (reverse-depth `:brutal_kill` cascade, `:exit`-guarded) + `Task.shutdown(ref, :brutal_kill)` + a direct terminal write (`:failed`, finished_at set, lease nil, result nil — a force-killed task is never `:cancelled`) + `Pause.abandon/1` + `clear_cancelling_marker(task_id)`; the body is status-agnostic, so a `:paused` row (no wrapper) takes the same path.
**Marker cleanup** — `clear_cancelling_marker/1` prefers `AgentScheduler.clear_cancelling_task/1` (serialized, cannot race `begin_graceful_cancel`) and falls back to `:ets.delete(:evogit_cancelling_tasks, task_id)` when the scheduler is down (TaskRegistry starts BEFORE AgentScheduler); called from every terminal transition.

## PubSub Broadcast Contract (topic `"tasks"`)

Ordering is **persist-then-broadcast**: `handle_update_status/6` writes via `Store.update_task_columns` FIRST and broadcasts `{:task_updated, task_id, status, node()}` only in the `:ok` arm, gated on `status != task_status` — a missing row, stale-guard skip or disk-full write never broadcasts. The trailing `node()` is the emitting node (subscribers ignore other nodes).

| Broadcast | Site |
|---|---|
| `{:task_updated, id, :running, node()}` | `start_task`; `resume_task/1` |
| `{:task_updated, id, :pausing, node()}` | `pause_task/1` `:running` arm (persist → `begin_task_pause/1` → broadcast) |
| `{:task_updated, id, :paused, node()}` | `handle_wrapper_result/3` `{:paused, info}` arm (clean); `init/1` reconciliation and `:lease_sweep` (dirty) — write → broadcast, exactly one per transition |
| `{:task_updated, id, :cancelling, node()}` | `cancel_task/1` `:running` and `:pausing` arms |
| `{:task_updated, id, :cancelled, node()}` | `cancel_task/1` `:pending` / `:awaiting_input` / `:paused` arms |
| `{:task_updated, id, :failed, node()}` | `force_kill_task/1`; `:lease_sweep`; recheck resolution; watchdog/startup reconcile (force-kill fires unconditionally — see Known Issues) |
| `{:task_updated, id, nil, node()}` | `set_review_status` / `set_review_metadata` casts, only after a SUCCESSFUL write |
| `{:task_deleted, id, node()}` | `clear_finished_tasks` (one per id), `delete_task`, only on the successful write |

- **Terminal sequences**: completed = wrapper sends `{ref, result}` → handler maps to `:completed`/`:failed`/`:exit` → cast `update_task_status_with_caller` → `handle_update_status/6` force-maps `:cancelling`+terminal → `:cancelled` (result preserved) → persist, then broadcast. Abnormal wrapper death = `{:DOWN, ...}`: `:normal` → `update_task_status(:completed)`; other reasons → `:failed` ONLY when `Lease.sched_meta_has_active_agents?/1` is false, else the row stays `:running` with no broadcast.
- **The ONLY broadcast preceding its persist is `:finalizing`**: `Runtime.Helpers.notify_finalizing/1` fires it from INSIDE the wrapper and the local handler persists afterward; a disk-full `put_task` leaves subscribers told `:finalizing` while the row stays `:running`. Reflect tasks never emit `:finalizing`.
- **`Cleanup.cleanup_expired_tasks/1` deletes rows with NO broadcast.**

## Task Lifecycle & Terminal-Write Sites

- **Start / Run**: `start_task/2` spawns the wrapper; the wrapper runs the WHOLE lifecycle synchronously (incl. `Runtime.Helpers.merge_and_report/4`) and never writes statuses.
- **DOMINANT terminal choke point = `handle_update_status/6`**: its terminal branch runs the in-memory teardown (`clear_cancelling_marker/1` + `TaskTmpdir.reclaim/2` + `task_refs` deletion), reached from the wrapper result handler, the `:DOWN` handler, startup reconciliation and the watchdog.
- **Terminal transitions that BYPASS it (direct `Store` writes)**: `force_kill_task/1` (`:failed` + reclaim + broadcast), `cancel_task/1`'s `:pending` arm (`:cancelled` + reclaim + broadcast), `resolve_recheck_task/3` (reclaim), `:lease_sweep` (`put_task`, reclaim, `:failed`). Hence NO single teardown choke point: a task-end teardown needs a hook at ALL FIVE sites.
- **Per-task on-disk artifact**: the managed tmpdir above. `cleanup_expired_tasks/1` only DELETEs finished task ROWS; archive rows live in their own per-agent table.
- **Boot profile (init is NOT the growth vector)**: state keeps exactly five keys — `data_dir`, `task_store`, `task_refs` (only THIS instance's live tasks, removed at terminal), `read_offloads` (transient) and `server_name`; no task row, `result` or `logs` is retained. `select_running_lease_info/1` projects three columns and discards the list; only reconciled rows cost one `select_task_update_info/2` read plus a write; rows-proportional id-only allocations are bounded by `task_history` and deleted in 500-id chunks.

## Merge-Conflict-Resolution Flow (MergeContext / TaskExecutor)

- **Only trigger point**: `execute_task(:evolve, opts, task_id)` runs a merge-context step BEFORE `resume_from` handling: a non-empty trimmed `opts[:merge_from]` triggers `MergeContext.apply_merge_context(opts, task_id, trimmed_merge_from, opts[:merge_target])`, whose result replaces `opts`; only the merge keys are stripped, so an independently supplied `resume_from` still triggers ResumeContext afterward and can override the merge-derived starting commit.
- **`apply_merge_context/4`**: strips `:merge_from`/`:merge_target` FIRST → `prev_task = EvoGit.TaskRegistry.get_task(merge_from)` (full `%TaskInfo{}` decode). **nil** → stripped opts unchanged. **Found** → `:starting_commit` overridden with `prev_task.commit_sha` when a non-empty binary (caller value preserved otherwise) → `:foreign_repos` carried from `prev_task.opts` when present/non-nil, each entry normalized via `ForeignRepo.normalize/1` (unparseable dropped) → each carried repo's `base_sha` overridden from the prev result's `repos[repo_id]["commit_sha"]` via `PrevTaskRepos.apply_starting_commits/2` (repos absent from the prev `repos` keep their base_sha; legacy tasks without `repos` are a no-op) → `:objective` = `build_merge_context_block(prev_task, merge_target, carried_repos) <> "\n\n" <> old_objective`. Pure keyword-in/out (returns bare opts, NOT a `{objective, runtime_opts}` tuple).
- **`build_merge_context_block/2,3`** returns a block fenced by `--- Merge Conflict Resolution Context ---` / `--- End … ---` with `Previous task id:`, `Base sha:` / `End (commit) sha:` (each omitted when nil/empty — the block is still emitted), `Task branch name:` and `Merge target branch:` (each falling back to `"unknown"`), a `Goal:` paragraph (merge the target via `git merge <target>`, resolve ALL conflicts by combining both sides, commit, keep developing until coherent), a `Writable foreign repos:` line ONLY when ≥1 writable repo (the 3-arity takes explicit repos so the block shows the ACTUAL starting commits; the 2-arity derives them from `prev_task.opts[:foreign_repos]`), and a `Hints:` section before the closing delimiter on BOTH paths. Non-struct input → `""`.
- **CONTEXT.md conflict policy**: keep the version of the side whose node path OWNS the file (an agent rooted at `./src` owns `./src/CONTEXT.md`; the root agent at `./` is everybody's ancestor); a genuine same-node conflict is merged from BOTH sides, keeping both routing-table entries and both sets of documented facts; prefer `edit_context` surgical edits over whole-file rewrites; if ownership is ambiguous, report it to the parent instead of picking a side. Pinned by `test/evo_git/task_registry/merge_context_block_test.exs`.

## Resume-From Flow (ResumeContext / TaskExecutor / RuntimeOpts)

- **Only trigger point**: `execute_task(:evolve, opts, task_id)` calls `ResumeContext.apply_resume_context/3` when `opts[:resume_from]` is a non-empty binary after `String.trim/1`; non-resume evolve tasks build `{objective, runtime_opts}` directly.
- **`apply_resume_context/3`** strips `:resume_from` → `prev_task = get_task(resume_from_id)` (FULL decode). Caller-supplied `:foreign_repos` are normalized to `%ForeignRepo{}` (string-keyed Codec maps allowed; unparseable dropped) and each repo's `base_sha` is overridden from the prev result's `repos[repo_id]["commit_sha"]`; the key is (re)added only when the normalized list is non-empty. **nil prev** → original objective plus `build_common_runtime_opts` with the caller's own repos. **Found** → the objective becomes `context_block <> "\n\n" <> objective` only when the block is non-empty; `:starting_commit` is overridden with `prev_task.commit_sha` when a non-empty binary (a caller-provided value is silently dropped), else the caller's passes through. **Foreign repos are NOT inherited from `prev_task.opts` on resume** — only caller-supplied ones flow through; `MergeContext` is the ONLY cross-task inheritance path.
- **Context block format**: `"--- Previous Task Context ---\n" <> Enum.join(parts, "\n\n") <> "\n--- End Previous Task Context ---"`, empty string when `parts == []`; parts: `"Previous task commits: #{base_sha}..#{commit_sha}"` (just `commit_sha` when base_sha is empty/nil; omitted when commit_sha is empty); an undelimited `"Writable foreign repos: …"` (only when ≥1 writable repo in `prev_task.opts[:foreign_repos]`); `"Previous task objective:"` and `"Previous task result:"` blocks wrapped in `<<<BEGIN …>>>`/`<<<END …>>>`, each omitted when empty.
- **`extract_result_summary/1`**: `{:ok, %{result: s}}` binary → passthrough, atom → `to_string/1`; `{:error, reason}` → `"Error: #{inspect(reason)}"`; `{:exit, reason}` → `"Exited: #{inspect(reason)}"`; anything else → nil.
- **SHA provenance**: `prev_task.commit_sha` is populated at completion by the `{ref, result}` handler (the merge result carries `commit_sha: final_sha || base_sha`); `prev_task.base_sha` is set ONLY by the review flow (`set_review_metadata/3` cast), so a never-reviewed task's commits line is just the commit_sha.

## Repo-Less (`:reflect`) Task Option & Lifecycle Contract

- **No reflect-specific validation exists here**: `handle_call({:start_task, ...})` is TYPE-AGNOSTIC — it persists the WHOLE opts keyword list and the only checks are the shared `RuntimeOpts` gates, so `:history`/`:messages`/`:conversation`/`:session`/`:resume_from` are neither required nor rejected; they ride into `Runtime.SelfReflective.run/1` and are ignored there.
- **`:path` is neither required nor forbidden for reflect**: `admit_task_path/1` admits an absent/`nil` `:path`; `do_execute_task(:reflect, ...)` never reads it and never calls `build_common_runtime_opts`, so its only consumer is `ensure_task_tmpdir/2`. A `vct:` path is refused for EVERY task type.
- **`:attachments`, `:quality_level` and `:archive` are inert**: `Session.Setup.build_initial_state/3` nils attachments for repo-less agents; `:quality_level` bypasses `QualityLevel.normalize/1`; `:archive` cannot produce a row because the gate requires `archive and base_commit` while repo-less `base_commit` is nil (`agent/completion.ex`).
- **Resume/merge do NOT support reflect**: `apply_resume_context/3` and `apply_merge_context/4` are only reachable from `do_execute_task(:evolve, ...)`, so a `:reflect` task ignores `:resume_from`/`:merge_from`; an evolve task resuming FROM a reflect task id embeds that task's objective + final `result` string only (no commits line), and NO path replays a prior reflect conversation.
- **One agent, one run, nothing survives but `task.result`**: `Runtime.SelfReflective.run/1` builds ONE `EvoGit.Agents.SelfReflective` root spec (`subagent_modules/0` is `[]`) and blocks on `AgentScheduler.run_agent/1`; the result is `{:ok, %{result: report_text, commit_sha: nil, branch_name: nil, tag: nil}}` with no `:usage`/`:agent_count`. No `task_agent_archives` row is written and the conversation lives only in that agent's ETS summary row, deleted at completion.
- **Review status is not type-guarded, but merging cannot work**: `set_review_status/2`/`set_review_metadata/3` write on any existing row (a missing row is a no-op), yet a reflect task has nil `branch_name`/`commit_sha` and no repo, so `Review.merge_branch/2,3`/`check_merge/3`/`default_merge_target/1` have no branch to act on.

## Known Issues

- `awaiting_input_test.exs` pins the status-set totality table (every set containing `:running` also contains `:awaiting_input`, except the deliberate `:finalizing` ignore-list exemptions) plus the reconcile/kill/cancel/flip behaviour.
- **A status string outside `Store.Codec.known_statuses/0` keeps its lease but is masked in full decodes.** `get_task_status/2` answers `{:unknown, raw}` (the heartbeat renews it, the sweep never leaks it), but `Codec.decode_task/1` renders the row as a LIVE `:pending` row on `get_task/2`/`get_task_lite/2` and the summary projections — liveness decisions must use the narrow `Store.get_task_status/2`, never the masked struct field.
- **A restart is FATAL for a `:running` task that is not dirty-pausable.** The one-shot `:lease_sweep` 150 s after EVERY boot fails every row absent from THIS instance's `task_refs` whose lease lapsed and which looks agent-free; "owning instance" exists ONLY as `task_refs` (no persisted instance/node/boot id), so ANY fresh BEAM sharing the DB owns nothing and writes `:failed` + `error.kind :lease_expired` WITHOUT `branch_name`/`commit_sha` → NOT reviewable.
- **`sched_meta_has_active_agents?/1` reads a BEAM-LOCAL ETS table** (`:evogit_sched_meta`, `:public` but NOT distributed), so B's boot sweep can fail A's STILL-RUNNING task while its worktrees are alive — and a later primary-repo spawn in a fresh BEAM re-runs the WorktreeManager full wipe (rm_rf `.genesis/workers` + delete all `evogit-agent-*` branches), destroying in-flight work.
- **The `:finalizing` handler's ignore-list deliberately omits `:failed`** (`finalizing_ignored_statuses/0`): recovering a persisted-`:failed` row to `:finalizing` on a stale broadcast is intended (pinned by `persistence_test.exs` "recovery before completion"; the list must NOT gain `:failed`).
- **`force_kill_task/1` broadcasts `{:task_updated, task_id, :failed, node()}` UNCONDITIONALLY** — also on `{:error, :not_running}` / `{:error, :not_found}` with no persisted change, so the dashboard sees a spurious `:failed`.
- **Disk-full at a terminal write can leave a row `:finalizing` with NO in-process retry.** `handle_update_status/6`'s `{:error, :disk_full}` arm only logs, so the row keeps its OLD status, no broadcast fires and nothing retries (one-shot watchdog; heartbeat renews only `lease_renewable?/1` statuses; the sweep only `Lease.leaked?/3` rows; `:periodic_cleanup` needs `finished_at != nil`) — until an explicit `clear_finished_tasks`/`delete_task` or a registry restart whose init reconcile maps it to `:failed`.
- **Memory scales with `tasks.sqlite` size — via the summary-query path, NOT init.** `Store.select_tasks_summary*`/`select_tasks_changed_since` decode every matching row's `opts` JSON off-process (retained ≈ O(rows × opts-blob size), capped at `max_tasks: 100`), and the dashboard re-fetches status-filtered sidebar summaries on every broadcast.
- **Derived foreign-repo `base_sha` is a FROZEN snapshot never re-validated against git.** `PrevTaskRepos.apply_starting_commits/2` reads the previous task's `repos[repo_id]["commit_sha"]` (persisted ONCE at that task's terminal write) and nothing re-reads the foreign branch tip or checks ancestry, so a follow-up from an OLDER task starts that repo at the older commit when a LATER task advanced it; recording is skipped when the foreign-repo subagent's result is not `{:ok, %Result{}}` or the child is not itself a writable `:read_write` agent there (`Subagents.store_sub_result/3,4`).
- **Resume block vs runtime mismatch**: the `Writable foreign repos:` line comes from the PREVIOUS task's own `opts[:foreign_repos]`, NOT from the overridden per-repo starting commits threaded into runtime opts (`MergeContext` avoids this via its 3-arity builder).
- **A task-level resume carries the ROOT run's durable identity to the scheduler; consuming it belongs to the scheduler node.** `Pause.resume/4` puts the ROOT row's five facts on the spawn opts, `RuntimeOpts` → `Runtime.Helpers.build_root_agent_spec/7` forward them PRESENCE-based, and `AgentScheduler.Dispatch` owns the restore/base precedence; a dirty pause writes no `pause_commit`, so that resume bases on the task base unless the ROOT row's `current_commit` is usable.
- **`persist_paused/3` drops the honesty flag**: the wrapper reports `{:paused, %{durable: boolean()}}` (`agent/session/pause.ex`), but `persist_paused/3` binds `_info` and writes `pause_kind: :clean` unconditionally — a `durable: false` pause is recorded as if durable, so a resume skips the crash repair it needs.
- **`pause_settled?/2` reads through the DEGRADED `safe_store_read`**: on a store outage the read answers `nil`, which falls through to `false`, so the straggler guard is OFF for that window.

## Project Mounts Are Not Registry State

The registry owns task state only: `EvoGit.VCT` owns the project mount list, its `"vct"` broadcast and every mount read, and no registry handler, seam or state key references it (mounts live in the store's `vct_mounts` table).

## Store Access, Fault Isolation & Three-State Reads

`StoreGuard`: `read/3` (degraded answer on fault), `write/2` (`{:error, :store_unavailable}`), `fetch/2` (`{:ok, value} | :unavailable`), where `fetch/2` is MANDATORY wherever a degraded `nil`/`[]` would read as a DOMAIN fact.
`StoreRead` is the ONE three-state surface: `status/2` → `{:ok, known_atom | {:unknown, raw}} | :absent | :unavailable`, `update_info/2` → `{:ok, map} | :absent | :unavailable`, `restart_info/2` → `{:ok, [map]} | :unavailable`; `:absent` = no such row, `:unavailable` = the store could not answer (never evidence).
Call sites pick the CONSERVATIVE direction: `handle_update_status/6` and the review casts write/broadcast NOTHING on either; `persist_paused/3` drops the ref on both (ONE warning on `:unavailable`), so the sweep later parks a resumable row as DIRTY; `start_task/2` PROCEEDS on both; `pause/2`/`resume/4` distinguish `{:error, :not_found}` from `{:error, :store_unavailable}`; `{:recheck_task, id}` no-ops on `:absent` but RESCHEDULES 30 s on `:unavailable`; `Restart.classify/2` classifies nothing on either; review casts broadcast `{:task_updated, task_id, nil, node()}` ONLY where `update_task_columns/3` answered `:ok`.

- **Cleanup is the ONE unguarded store caller**: `cleanup_expired_tasks/1` calls `Store.select_cleanup_info/3` + `Store.delete_tasks/2` directly (ids from SQL: age cutoff and over-limit keys, `idx_tasks_finished_at_id`), matches only `:ok`/`{:error, :disk_full}`, and emits no event.
- **Direct `EvoGit.Store` callers here**: `task_registry.ex`, `cleanup.ex`, `heartbeat.ex`, `store_read.ex` (plus `pause.ex`'s one `update_task_columns/3` write); `restart.ex`/`agent_state_read.ex` go through `StoreRead`/`AgentStateRead`; `lease.ex`/`diagnostics.ex` are ETS/Logger-only; `task_executor.ex` reaches Store only via ResumeContext. (`agent_scheduler/*` `Store.` is `EvoGit.AgentScheduler.Store`, a DIFFERENT ETS module.)
- **`get_task/1` is the ONE unoffloaded full decode** (`task_get/2`, as are the `:recheck_task`/`:finalizing` handlers); `get_task_lite/1` is the same decode (`result`/`logs`/`usage` included) but offloaded, degrading to `nil`.
- **`Store.get_task_status/2` is TRI-STATE**: `nil` = NO row (the only "absent" answer), a known atom, or `{:unknown, raw}` = the row EXISTS with unreadable status. Heartbeat renews `{:unknown, _}`, `Lease.leaked?/3` never leaks it, `cancel_task/1`/`force_kill_task/1` answer `{:error, :not_running}`, `start_task` proceeds, review casts write, and no consumer may collapse it into "absent".
- **Narrow reads**: writes go through `update_task_columns/3` and narrow reads through `Store.select_task_update_info/2` + `Store.select_tasks_restart_info/2`; FULL decode stays for `ResumeContext`/`MergeContext` (need `result`) and the `:finalizing` handler, and a handler that can answer from the status column must do so before `task_get/2` (`prev_status/2` = `StoreRead.status/2`).
- **Registry read offload** (`ReadOffload`): every large-decode read (`list_tasks`, `list_tasks_paginated`, `list_tasks_page`, `get_task_lite`, `list_task_archives`, `get_agent_archive`, the three summary reads) runs in an `async_nolink` worker of `EvoGit.TaskRegistry.ReadSupervisor` that runs `StoreGuard.read/3` and replies itself, so the value never enters the registry heap (`get_unique_paths`/`list_task_ids` reply INLINE; `@deadline` 28 s kills a wedged worker; each site keeps its exact degraded shape).
- **Per-agent archive**: `put_task_archive/1` → `StoreGuard.write/2` around `Store.put_task_archive/2` (STREAMING) in the CALLER, so a multi-MB insert never holds the registry; `list_task_archives/2` → STRING-KEYED `%{entries: [], total: 0}` on fault (`depth ASC, agent_id ASC`), `get_agent_archive/2` is the lazy per-agent detail (`"result"` included) and there is no task-wide reader; deletes cascade EXPLICITLY (`delete_by_task/2`, chunked `delete_by_tasks/2`, `delete_all/1`).
- Store-owned internals (migrations, summary APIs, JSON storage, `mix store.maintenance`, disk-full classifier): `../store/CONTEXT.md`.

## Heartbeat, Restart Classification & `list_tasks/0` Bound

`EvoGit.TaskRegistry.Heartbeat.renew(store, task_ids, expires_at) :: :ok` is the WHOLE heartbeat body: `[]` ids is a no-op with no read; otherwise ONE `Store.select_task_statuses/2`, keep the ids whose status passes `Lease.lease_renewable?/1` (`:running | :pending | :cancelling | :awaiting_input | :pausing | {:unknown, raw}`), return `:ok` WITHOUT a write when nothing is renewable, else ONE `Store.renew_leases/3`.
`{:error, :disk_full}` logs exactly ONE warning naming the task COUNT; `{:error, :store_unavailable}` answers `:ok` (StoreGuard already logged it); a degraded/absent status read (`%{}`) renews nothing. The registry keeps `@lease_duration` and passes the ABSOLUTE `expires_at`.
`EvoGit.TaskRegistry.Restart.classify(store, task_ids) :: %{optional(id) => :dirty}` is the ONE restart classifier both recovery paths share: ONE `StoreRead.restart_info/2` read, keep the rows `Pause.dirty_pausable?/2` accepts (`:persistent_state` on, opts-only), ONE `AgentStateRead.roster_many/2` (batched 5 s bounded offload), and a row is `:dirty` only when one of that task's durable records is a ROOT RUN (`Pause.root_run?/1`, `fields[:parent_id] == nil`). A degraded read (`:unavailable` or `[]`) classifies NOTHING, so `init/1`/`:lease_sweep` fall through to the sweep-fail path (`:lease_expired` → `:failed`).
`init/1` and `:lease_sweep` call it ONCE for all their candidates and then only perform the targeted dirty-pause write (`park_dirty_pause/2`: `status: :paused`, `pause_kind: :dirty`, `finished_at` nil, lease nil) — one broadcast per persisted transition, AFTER the persist.
`Pause.pause_kind_for_restart/1,2` stays public and delegates `/2` through `Restart.classify(store, [task_id])` (tests use both arities).
`list_tasks/0` is bounded to `@list_tasks_limit` (100) rows, `started_at DESC`, decoded through `Store.safe_select_paginated_tasks/1`; the return shape stays `[%TaskInfo{}]`.

## Naming & Vocabulary Debt (open)

- **Duplicated rules**: the interactive-session predicate exists as `Pause`'s private `interactive?/1` (atom AND string `:session_mode` keys), `TaskExecutor`'s `interactive_session?/1` (atom key only) and `RuntimeOpts.session_mode/1`; the persistent-state default-true rule as `Pause`'s non-raising `persistent_state_on?/1`, `RuntimeOpts.persistent_state/1` and `admit_persistent_state/1`; and `resume_context.ex` re-implements `PrevTaskRepos.normalize_foreign_repos/1` inline. A shared non-raising `RuntimeOpts` predicate should own the first two.
- **`safe_store_read/3`/`safe_store_write/2` are one-line aliases of `StoreGuard.read/write`** used only inside the registry (`pause.ex`/`read_offload.ex` call `StoreGuard` directly); delete the aliases.
- **Four `list_*` return conventions**: `list_tasks/0` → plain list (bounded 100), `list_tasks_paginated/1` → `{tasks, total}`, `list_tasks_page/1` → `%{rows:, total:}`, `list_task_archives/2` → `%{entries:, total:}`; each `@doc` names its own.
- **Lease vocabulary: four words for two facts** — "orphaned" (a wrapper-less row), "leaked" (`Lease.leaked?/3`), "expired" (the timestamp, error kind `:lease_expired`), "stale" (an out-of-date update).
