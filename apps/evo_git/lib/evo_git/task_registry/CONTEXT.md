# TaskRegistry Support Modules

## Intent

Support modules extracted from the `EvoGit.TaskRegistry` GenServer so the main module stays focused on the task-lifecycle state machine.
Every module here is pure-function, ETS-only or a bounded offloaded read task — none owns GenServer state.

## Routing Table

None — leaf directory (all modules at this level).

## Process-Scoped Isolation Seam

`EvoGit.TaskRegistry.server/0` resolves the registry name for the CURRENT process — the `:evogit_task_registry_server` process-dictionary value when present, else `__MODULE__` — at CALL time, never cached.
Every client function routes its call/cast through it EXCEPT `put_task_archive/1`, which uses it only to look up that instance's store (`start_task/2`, `get_task/1`, `get_task_lite/1`, `list_task_archives/2`, `get_agent_archive/2`, `list_tasks/0`, `list_tasks_paginated/1`, `list_tasks_page/1`, `cancel_task/1`, `force_kill_task/1`, `update_task_status/4`, `set_review_status/2`, `set_review_metadata/3`, `list_tasks_summary/2`, `list_task_ids/1`, `list_tasks_summary_by_path/3`, `list_tasks_changed_since/1`, `get_unique_paths/0`, `delete_task/1`, `clear_finished_tasks/0`).
`EvoGit.Store` needs no seam: every Store client takes an explicit `store` first argument (default `__MODULE__`) and `start_link/1` honours a custom `:name` (`child_spec/1` keeps `id: __MODULE__`, so several instances need an explicit `id:`).
An isolated pair is `EvoGit.Store.start_link(name: <store>, data_dir: <tmp>)` + `EvoGit.TaskRegistry.start_link(name: <unique_atom>, task_store: <store>, data_dir: <tmp>)`; the app-global singletons are never started or stopped.
An `:agent_state_server` pid option is the durable-state counterpart of that seam: `init/1` puts it under `:evogit_agent_state_server` (pid only, anything else ignored), so an isolated registry reads, flushes and cascades against its OWN `EvoGit.AgentState` instance instead of the app-global one.
The registry holds NO mount state and never touches the VCT: project mounts are `EvoGit.VCT`'s business, so an isolated registry is isolated by its `task_store` alone.
The registry stores its registered name (`Keyword.get(opts, :name, __MODULE__)`) in state, sets it under `:evogit_task_registry_server` in `init/1`, and passes it as the 4th wrapper-spawn argument, so `execute_task/4` re-installs it and in-wrapper `MergeContext`/`ResumeContext` callbacks (`get_task/1`) hit the SAME instance; its in-process self-casts (`update_task_status_with_caller/4` / `update_task_status/2` from the `{ref, result}` and `:DOWN` handlers) therefore resolve to THIS instance, and with the key unset every seam read resolves to `__MODULE__` (production unchanged).
`init/1` additionally publishes `registered name => task_store` into the APP-OWNED ETS table `:evogit_task_registry_stores` (created in `EvoGit.Application.start/2`, so it survives registry restarts), which is how `put_task_archive/1` resolves a store without touching the registry mailbox; an unpublished name falls back to `EvoGit.Store` (the same default `init/1` uses for `:task_store`).
Processes NOT descending from the wrapper (self-reflective `agent/tools/*`, `agent_scheduler/remote_api.ex`, evo_dash callers) never inherit the key — their suites stay serialized against the global singleton.

## Constraints

- **Task-type atom whitelist in the SQLite Codec**: `start_task/2` is TYPE-AGNOSTIC — any atom reaches `TaskExecutor.execute_task/3`, whose private `do_execute_task/3` has one clause per type (`:genesis`, `:evolve`, `:extract_skills`, `:reflect`) and NO catch-all (unknown type → `FunctionClauseError` in the spawned task → task `:failed`). The persisted `type` column round-trips `EvoGit.Store.Codec.@known_atoms` (task types + status/review atoms); `decode_atom` returns `nil` for non-whitelisted strings, so a NEW task type MUST be added there or its tasks load back with `type: nil` (`TaskInfo.type` is `atom() | nil`).
- **Purity**: no GenServer state, no I/O except `Cleanup` → `EvoGit.Store` deletion, `ReadOffload`/`AgentStateRead` → supervised read workers, and `TaskExecutor` → `EvoGit.TaskTmpdir.ensure/2`. `TaskExecutor` runs OUTSIDE the GenServer (under `Task.Supervisor`); `RuntimeOpts`/`ResumeContext`/`MergeContext`/`PrevTaskRepos` are pure builders and `Pause` only validates + persists.
- **NO synchronous durable-state call ever runs inside the registry process**: the agent-state cascade is a cast, and every registry-side durable READ (the ROOT-run roster read, `pause_commit`, and the scheduler's `max_agent_id` boot seed) goes through `AgentStateRead`'s bounded offload, so `agent_state.sqlite` can never park the task-lifecycle GenServer.
- **Cleanup/reaping is SQLite-row-only — NO disk or `.genesis/` reaping.** Init reconciliation, the one-shot `:lease_sweep`, `Cleanup.cleanup_expired_tasks/1`, the 5-minute `:periodic_cleanup`, `clear_finished_tasks` and `delete_task` only touch `tasks.sqlite` rows (plus the cascaded `agent_state.sqlite` rows below) plus the in-memory `task_refs` entry and the `:evogit_cancelling_tasks` marker. Worktree reclamation belongs to `EvoGit.AgentScheduler.WorktreeManager` (`:DOWN`-driven), outside this subtree.
- **Task delete cascades to the durable agent state as a TOTAL CAST**: after a SUCCESSFUL row delete the `{:delete_task, task_id}` cast calls `EvoGit.AgentState.delete_task/2`, and `clear_finished_tasks/0` issues exactly ONE batched `EvoGit.AgentState.delete_tasks/2` for the whole cleared set — both are casts (one writer message, always `:ok`), so a stopped, locked or dead `agent_state.sqlite` can neither fail nor delay a task delete; retention pruning is the backstop. The extra age/count deletions done by `Cleanup.cleanup_expired_tasks/1` carry NO cascade (they expose ids only through `Store.delete_tasks/2`), so retention pruning reclaims those runs too.
- **`task_registry.ex` stays long by design**: the main GenServer is the task-lifecycle state machine (status transitions, lease/heartbeat, graceful cancel + force kill, startup reconciliation, review-status handlers), deliberately cohesive.

## Task Status Sets & `:awaiting_input`

`:awaiting_input` is a NON-TERMINAL task status: an interactive agent session yielded on a tool-free reply and waits for its next user message.
Its wrapper (`%Task{}` in `task_refs`) is still alive on the node, so the row is LIVE: the lease keeps being renewed, it must never be swept as leaked, and `clear_finished_tasks` must never delete it.
It is IDLE, not busy: an idle session holds no LLM slot, no tool slot and no worker, so it must not count toward an update/idle gate (that "busy" set belongs to the dashboard / `/server/status`, not to this node).
Sessions are in-memory only: a BEAM restart destroys every open session, so boot reconciliation resolves an orphaned `:awaiting_input` row to `:failed` (never resumed).
`:running` and `:awaiting_input` are an ordinary legal non-terminal pair — a session yields and resumes many times, and both directions are a plain `update_task_status/4` write (`finished_at` and the lease untouched, no stale-terminal interference).
`:awaiting_input → :cancelled` is IMMEDIATE (never via `:cancelling`): an idle session has nothing to save but its transcript, so the targeted write sets `:cancelled` + `finished_at` + a cleared lease with NO `result` column (the transcript/result is preserved), clears the cancelling marker, reclaims the tmpdir, broadcasts `{:task_updated, task_id, :cancelled, node()}` on the successful write, and stops the session best-effort through the TASK-addressed `AgentScheduler.force_kill_task_agents_for_task/1` (an interactive session need not have a depth-0 SchedMeta `from` pid, so the pid-addressed force kill cannot find it).
`:awaiting_input` is force-killable exactly like `:running` (`:failed`, lease nil, result nil'd, the canonical `:force_kill` error payload).
Boot reconciliation resolves an orphaned `:awaiting_input` row to `:failed` with `result`/`error.message` = `"Runtime restarted during interactive session"` and `error.kind :restart`/`source :startup_reconcile`.
`EvoGit.TaskRegistry.update_status/2` is the status-only convenience the session lifecycle calls (a cast through `update_task_status/4`, so the stale-terminal guard and the `:cancelling` force-map apply unchanged); it carries no result, so it is for non-terminal flips only, and a call that repeats the current status writes nothing observable and broadcasts nothing.

Status enumerations this subtree owns, in ONE place each with a `@doc false` accessor so a table-driven test can assert totality (`:awaiting_input` wherever `:running` appears, `:pausing` wherever `:running` appears, `:paused` wherever `:awaiting_input` appears — see "Task-Level Pause & Resume" for the pins):

| Owner | Accessor | Content | Meaning |
|---|---|---|---|
| `lease.ex` | `renewed_statuses/0` | `[:running, :pending, :cancelling, :awaiting_input, :pausing]` | the heartbeat renews these (`:paused` is deliberately absent: no wrapper, no heartbeat) |
| `lease.ex` | `leaked_statuses/0` | `[:running, :awaiting_input, :pausing]` | the one-shot sweep may fail these (`:pausing` included: a mid-drain task whose wrapper died is leaked; `:paused` is a legitimate resting row) |
| `task_registry.ex` | `terminal_statuses/0` | `[:completed, :failed, :cancelled]` | no further transition (except terminal → `:completed`); `:pausing`/`:paused` are NON-terminal |
| `task_registry.ex` | `killable_statuses/0` | `[:running, :awaiting_input, :cancelling, :pausing, :paused]` | `force_kill_task/1` accepts these |
| `task_registry.ex` | `gracefully_cancellable_statuses/0` | `[:running, :awaiting_input, :pausing, :paused]` | `cancel_task/1` accepts these (`:running` → `:cancelling` grace; `:awaiting_input`/`:paused` → immediate `:cancelled`; `:pausing` abandons the pause first) |
| `task_registry.ex` | `unstartable_statuses/0` | `[:cancelled, :cancelling, :awaiting_input, :pausing, :paused]` | `start_task/2` refuses these ids (a paused row owns its id for `resume_task/1`) |
| `task_registry.ex` | `finalizing_ignored_statuses/0` | `[:completed, :cancelled, :cancelling, :pausing, :paused]` | a `:finalizing` broadcast is ignored (`:awaiting_input` is deliberately ABSENT: closing an idle session legitimately moves it to `:finalizing`; adopting `:finalizing` would clobber the pause bookkeeping) |
| `task_registry.ex` | `active_statuses/0` | `[:running, :pending, :finalizing, :cancelling, :awaiting_input, :pausing, :paused]` | "a live task whose wrapper exists" — the in-flight set, NOT the busy set (`:paused` is live for the UI only) |

The store-side halves of the same admission (not owned here) are `Store.Codec.@known_statuses`, `Store.Types.Status`, `TaskInfo.status`, `Store.Operations.Lightweight`'s `@live_statuses` (else `clear_finished_tasks` deletes a waiting session) and `@lease_statuses` (else init reconciliation and the sweep never see it).

## RuntimeOpts Key Contract

`RuntimeOpts.build_common_runtime_opts(opts, task_id, task_type)` returns `{nil, runtime_opts}` (first element always `nil`).

- `:path` is REQUIRED (`Keyword.fetch!` → `KeyError`; the key is `:path`, never `:repo_path`).
- `:path` is the task's ONE primary repo — persisted as the `tasks.project_path` column from `opts[:path]` (`store/operations/tasks.ex:527,536-538`) and used as the `:per_repo` tmpdir base (`task_executor.ex:50` → `task_tmpdir.ex:170-175`) — while the ONLY multi-repo admission construct is `:foreign_repos` (list of `%ForeignRepo{id, root, description, writable, base_sha}`), threaded VERBATIM and unvalidated here.
- `:node_path` is a repo-RELATIVE context-tree directory, never a machine: `Evolution.run/2` reads it (`runtime/evolution.ex:23,34`) and `Runtime.Helpers.validate_node_path/2` rejects absolute paths and requires an existing dir with CONTEXT.md (`runtime/helpers.ex:207-223`); a dashboard cluster node is a SEPARATE ARGUMENT of `EvoDash.NodeContext.start_task/3` (never an opts key), and a task `:node_path` opt names the same directory.
- `:mode` is a STRING — `"new"`/`"existing"` for `:genesis`, `"simple"`/`"custom"` for `:evolve` — converted via `mode_atom/2`. An ATOM hits the catch-all `ArgumentError` ("invalid genesis/evolution mode"); a MISSING mode defaults to `"simple"`, which raises for genesis ("invalid genesis mode: \"simple\"") — genesis callers must pass `mode`. Genesis `"custom"` raises `"custom mode is evolve-only; use an evolve task with mode \"custom\""`.
- Base keys always emitted: `repo_path` (from `:path`), `mode` (atom), `task_id` (the parameter, not an opts key).
- Generic `put_if/4` filters only nil/false, so empty strings and empty lists pass for `node_path`, `starting_commit`, `foreign_repos`, `archive` and `build_system`; `agent` requires a non-empty binary.
- `admit_model_selection(opts, config)` is the shared admission boundary for a configuration snapshot: a PRESENT `:model_spec` wins over legacy `:model_id` even when invalid, Auto (no spec and nil/empty legacy id) omits both selection keys AND `:model_id_locked`, and an explicit selection is checked by `Config.Schema.resolve_model_spec(config, spec_or_legacy_id)`.
- A new explicit `:model_spec` forces `model_id_locked: true`, while a legacy `:model_id` alone never introduces a lock and only preserves a supplied truthy lock normalized to true (nil/false locks are omitted), keeping legacy model-selection scripts enabled.
- Explicit `model_spec` is the STRING-keyed serializable map `provider_profile_id` / `model` / optional `reasoning_effort`; a non-map spec returns `{:error, :invalid_model_spec}` rather than being interpreted as a legacy id, and map/legacy-id validation errors pass through from the schema unchanged.
- Admission projects explicit specs through the shared private `canonical_model_spec/1` helper from the schema's resolved top-level `provider_profile_id`, `model` and optional non-nil `reasoning_effort` fields into string keys, materializing defaults and normalized model/effort spelling while dropping every caller-supplied extra field.
- The schema's resolved `model_spec` is a ReqLLM identifier, not the task identity map; resolved profiles, generation parameters and credentials are never copied into task opts.
- Legacy ids remain legacy ids with their existing lock semantics; explicit specs drop a competing legacy id, and admission retains unrelated task opts.
- TaskRegistry callers must run admission BEFORE enqueue/persistence, and `TaskExecutor.execute_task/4` rechecks it BEFORE tmpdir creation/dispatch, returning a resolver error unchanged without starting a runtime.
- `build_common_runtime_opts/3` retains its existing `{nil, runtime_opts}` API and expects admission to have run already; shared private `put_model_selection/2` threads the spec (forcing its lock to true) or legacy id (normalizing only an existing truthy lock) without depending on a resolved-profile shape.
- Direct builder callers with an independently supplied `model_id_locked` and no selection retain the legacy truthiness behavior (`put_if_true/3`), whereas admission Auto strips that stray lock before normal task execution.
- `admit_task_path(opts)` is the PATH admission gate beside the model-selection, session-mode and persistent-state gates: absent/`nil` `:path` is admitted (repo-less `:reflect`), an ordinary binary is admitted without an absoluteness check, a `vct:///workspaces/…` point answers `{:error, :workspace_not_executable}`, any other `vct:` point `{:error, :vct_point_not_executable}` and a present non-binary `{:error, :invalid_path}` — a workspace and any other VCT point are metadata, never an execution path.
- `build_common_runtime_opts/3` raises a descriptive `ArgumentError` for a `vct:` `:path` (defense in depth for direct callers that skip admission); every non-`vct:` path is still copied verbatim without expansion, absoluteness or repo-root validation.
- `:objective` is read separately by TaskExecutor with default `""` only when absent (an explicit nil is not defaulted), so practical direct evolve callers should supply an absolute path and binary objective (`runtime_opts.ex:17–25`, `task_executor.ex:81–90`).
- Path resolution and repo validation happen DOWNSTREAM of this layer, not in TaskRegistry: `Runtime.Genesis.run/2` / `Runtime.Evolution.run/2` / `Runtime.SkillExtraction.run/1` default `:repo_path` to `File.cwd!()` and apply `EvoGit.Platform.safe_expand/1` (UNC-preserving `Path.expand/1`, so `~` and relative components are expanded against the BEAM cwd) and then `EvoGit.Runtime.ensure_repo/1` (`runtime.ex`) + `Runtime.Helpers.validate_repo_path!/1` reject non-repos (and UNC roots) at task start.
- `attachments` is validated UNCONDITIONALLY via `EvoGit.Attachments.validate/1` (nil/`[]` → `:ok`; malformed → descriptive `ArgumentError` at task start) and put only when non-nil AND non-`[]`; values are STRING-keyed base64 maps (`EvoGit.Attachments`).
- `:session_mode` is OPTIONAL: absent means the default `"oneshot"` and the key is then omitted from the runtime opts (every one-shot path stays byte-identical); `"interactive"` is passed through so the session driver yields instead of finishing.
  The value is a STRING at the data plane — exactly like `:mode` — so an ATOM (or any other value) raises a descriptive `ArgumentError` in the builder, while `admit_session_mode/1` is the non-raising gate the registry calls before enqueue (a raise inside the registry GenServer would kill it).
  It is persisted with the task's raw opts (`tasks.opts` JSON) and, once the store read model carries the column, as `task.session_mode`.
- `:persistent_state` is an OPTIONAL BOOLEAN with DEFAULT `true` — a task that does not pass it persists per-agent state, and `persistent_state: false` opts out for the WHOLE task (root plus every descendant, inherited through `%EvoGit.Agent.State{}`).
  Unlike `:session_mode`, the key is ALWAYS present in `runtime_opts` as an explicit boolean (`true` when the task did not opt out), so no downstream consumer has to apply its own default.
  `persistent_state/1` is the strict normalizer (`nil` → `true`, `true`/`false` → itself, anything else raises a descriptive `ArgumentError`), while `admit_persistent_state/1` is the non-raising gate the registry calls before enqueue: absent and `nil` pass through unchanged, booleans are re-put, and any other value answers `{:error, :invalid_persistent_state}`.
  It is persisted with the task's raw opts (`tasks.opts` JSON); the repo-less `:reflect` path never builds these opts, so it omits the key and the session's own default (`true`) applies.
- `:quality_level` is normalised via `EvoGit.QualityLevel.normalize/1` (nil/`""` → `"balanced"` silently; recognised value unchanged; anything else → `Logger.warning` + `"balanced"`) and appended ONLY when ≠ `"balanced"`.
- Private `put_if/4` (default predicate = truthiness) and `put_if_true/3` build the chain; everything else in the input opts is silently DROPPED.
- ResumeContext and MergeContext preserve caller-supplied model keys in their intermediate keyword lists but never inherit model selection or its lock from the previous task; both ultimately use RuntimeOpts's whitelist, including `:model_spec`.
- TaskExecutor has two independent option paths outside that whitelist: reflect forwards admitted opts to SelfReflective, while skill extraction builds a PR-context list plus the admitted `:model_spec`/`:model_id`/`:model_id_locked` keys.
- `foreign_repos` is threaded VERBATIM — never normalized (`ForeignRepo.normalize/1`) or validated, even a non-list passes. Normalization/validation live in `EvoGit.Runtime.Helpers.load_foreign_repos/2` (`merge_foreign_repos/2` + `validate_foreign_repo!`), where a task-opts entry for an id REPLACES the genesis.toml entry wholesale (id-keyed `Map.merge`; TOML `writable`/`base_sha` are lost when the opts entry differs).
- The persisted opts JSON nests `foreign_repos` as an ARRAY of STRING-keyed objects (`%ForeignRepo{}` derives `Jason.Encoder` with only `id`/`root`/`description`/`writable`/`base_sha`, and `Codec.decode_opts/1` atomizes only the OUTER `:foreign_repos` key), so every reader of a decoded row normalizes via `ForeignRepo.normalize/1`.
- `:starting_commit` has NO default: absent → the runtime resolves HEAD (`resolve_starting_commit(repo_path, nil)` → `PhyloGraphNode.current_head/1`); present → it must `git rev-parse` cleanly or evolution fails. No concurrency key is built here.

## TaskExecutor Dispatch & Task Start

`execute_task/3` defaults `server` to its own module `EvoGit.TaskRegistry.TaskExecutor`, NOT the production registry name despite its doc comment; normal wrapper callers must supply the explicit fourth argument.
The `:reflect` clause passes `opts ++ [task_id: task_id]` verbatim, so a caller-provided earlier `:task_id` wins ordinary `Keyword.get/2` lookup; this helper neither removes duplicate keys nor validates reflect options.
No helper in this directory calls `CommandApproval` or implements approval denial on cancellation; those lifecycle hooks must be checked in the parent registry and command-approval owner.
`execute_task/4` stores `server` in the `:evogit_task_registry_server` process dictionary FIRST, then checks `RuntimeOpts.admit_model_selection(opts, EvoGit.Config.resolve())`; an error returns unchanged before tmpdir creation or process registration.
On success it calls `ensure_task_tmpdir/2`, then private `do_execute_task/3`: `:genesis` → `Runtime.Genesis.run(prompt, runtime_opts)`; `:evolve` → merge-context step, then resume-context-or-plain, then `Runtime.Evolution.run(objective, runtime_opts)`; `:extract_skills` → `Runtime.SkillExtraction.run(runtime_opts)` including model-selection keys; `:reflect` → `Runtime.SelfReflective.run(opts ++ [task_id: task_id])`.
A `:reflect` task whose `:session_mode` is `"interactive"` runs the session-driving `EvoGit.Runtime.Assistant.run/2` instead of the one-shot engine; every other value (absent / `"oneshot"`) keeps the byte-identical `Runtime.SelfReflective.run/1` call (`task_executor.ex:143–150`).
`:reflect` bypasses `RuntimeOpts.build_common_runtime_opts` (whose `Keyword.fetch!(:path)` would `KeyError`) and returns `{:ok, %{result: ..., commit_sha: nil, branch_name: nil, tag: nil}}`, leaving `commit_sha`/`branch_name`/`project_path` nil and, because the map carries no `:usage`/`:agent_count`, leaving those columns NULL too — `tasks.result` (the final text) is its only durable artifact.
A reflect task has no `base_commit`, so `EvoGit.Agent.Completion.complete/4` writes neither the `refs/notes/evogit` note nor a `task_agent_archives` row, and its message list lives only in the live session's `%EvoGit.Agent.State{}` (never in ETS) until the session ends.
Reflect caller keys are forwarded unvalidated: everything except `:objective`/`:source_root`/`:node_path` (dropped by `SelfReflective.build_spec/2`) — including `:resume_from`/`:history`/`:messages` — is admitted, persisted into `tasks.opts` and lands inert in `AgentSpec.opts`, so conversational continuity comes only from the dashboard's TEXT preamble prepended to the objective, never from structured history.
NO catch-all clause: an unknown type raises `FunctionClauseError` in the spawned task → `{ref, {:exit, ...}}` → `:failed`.
Every clause FIRST calls `register_task_process/1` (`Registry.register(EvoGit.TaskRegistry.ProcessRegistry, task_id, :task)`); the runtime call is the LAST expression — a plain SYNCHRONOUS call (no spawn, no try/rescue/catch) returning the runtime value verbatim — and the module has ZERO `Logger`/`IO` calls.
**The wrapper never writes statuses**; the TaskRegistry GenServer performs every write from `{ref, result}`, `:DOWN`, the `:finalizing` handler and `update_status` casts.

`TaskRegistry.start_task(task_type, opts)` mints an id via `generate_id/0`, then `handle_call({:start_task, ...})`: the guard refuses the statuses in `unstartable_statuses/0` (`:cancelled`/`:cancelling`/`:awaiting_input`) with `{:error, :cancelled}` (reachable only through a direct `{:start_task, id, type, opts}` call — the public API always mints a FRESH id) → opts admission (`RuntimeOpts.admit_task_path/1`, then `RuntimeOpts.admit_model_selection/2`, `RuntimeOpts.admit_session_mode/1` and `RuntimeOpts.admit_persistent_state/1`, all non-raising inside the GenServer so `{:error, reason}` is replied and nothing is enqueued) → `Task.Supervisor.async_nolink(EvoGit.TaskSupervisor, TaskExecutor, :execute_task, [task_type, opts, task_id, state.server_name])` → persists `%TaskInfo{status: :running, opts: RAW, started_at, logs: [], result: nil, lease_expires_at: now + 120s, model_id: opts[:model_id]}` (ref nulled; disk-full → warning, in-memory only) → `task_refs` entry → broadcast `:running` → `{:ok, task}`.
`:session_mode` is the interactive-session driver selector (`"oneshot"` default, `"interactive"` for a session that yields to `:awaiting_input`); `RuntimeOpts.session_mode/1` raises on an invalid value, `admit_session_mode/1` answers `{:error, :invalid_session_mode}` so this handler never raises.
TaskRegistry creates NO on-disk state (`opts[:path]`/`opts[:foreign_repos]`); no `create_task` exists anywhere in evo_git/evo_dash.

All opts defaults live in the CALLERS: the DASHBOARD (`ProjectsLive.handle_event("task_submit", ...)`: `path` required, `mode` always, `:prompt`/`:objective`, conditional `build_system`/`node_path`/`starting_commit`/`foreign_repos`/`archive`/`model_id`/`model_spec`/`resume_from`) and the `StartTask.start_task` shell handler (`:path`, STRING `:mode`, `:prompt` for genesis plus `:objective`, put-if-present `:resume_from`/`:starting_commit`/`:model_id`); remaining defaults (`:prompt`/`:objective` → `""`, mode → `"simple"`) live in TaskExecutor/RuntimeOpts.
Remote path: `RemoteAPI.start_task/2` → `TaskRegistry.start_task/2` via `RemoteNode.start_task/2` / `NodeContext.start_task/3`; the shell's `StartTask.start_task` handler calls the local `TaskRegistry.start_task/2` directly.

`resolve_recheck_task/3` recovers a task whose wrapper died before replying: best-effort result via `Lease.lookup_sched_meta_result/1`, falling back to `:completed`; it shares the `{:ok, %{branch_name: _}}` extraction with `handle_update_status/6`.

## Per-Task Tmpdir Lifecycle

Each task owns ONE managed scratch directory shared by all its agents (`EvoGit.TaskTmpdir`, a PARENT-node file read-only from here; `[tmp] mode` (`:system`/`:custom`/`:per_repo`) and path resolution live there — `../../task_tmpdir.ex` + `../sandbox/CONTEXT.md`).
- **Create trigger (here)**: `TaskExecutor.execute_task/4` — the single entry point for all four types — calls private `ensure_task_tmpdir/2` after installing the process-dictionary seam and admitting the model selection, BEFORE dispatch, so the dir exists before any tool can spawn and rejected selections create no tmpdir.
  It calls `EvoGit.TaskTmpdir.ensure(task_id, Keyword.get(opts, :path))` (never `fetch!` — a nil/missing `:path` must not crash the wrapper), discards the path and returns `:ok`; `ensure/2` never raises from its mkdir step (logged, path still returned), but its PATH RESOLUTION is not exception-free: `System.tmp_dir!()` raises `RuntimeError` when no writable temp dir exists, aborting the wrapper BEFORE dispatch so the whole task fails.
- **Reclaim triggers (parent `task_registry.ex`)**: reclaim is **event-driven ONLY** — `EvoGit.TaskTmpdir.reclaim/2` removes `task_<id>` on a terminal status: the terminal reclaim in `handle_update_status/6` plus the direct terminal writes that bypass it (`force_kill_task/1`, `cancel_task/1`'s `:pending` arm, `:lease_sweep`, `resolve_recheck_task/3`). No boot reaper, no periodic sweep.
  `reclaim/2` never deletes outside the managed root nor the root itself; it is best-effort and never raises. The `handle_update_status/6` reclaim reads the FINAL (post force-map) status, so a graceful-cancelled task that completes still reclaims; `:cancelling`/`:finalizing` never reclaim.
- **Gotchas**: (a) `Cleanup.cleanup_expired_tasks/1` deletes ROWS, never directories — no age-based tmpdir GC; (b) a dir orphaned by a full-runtime CRASH (no terminal write) is NEVER reaped automatically in ANY mode — manual cleanup; (c) `[tmp] mode` is re-resolved at RECLAIM time (never stored per task), so changing it mid-flight can orphan the dir created under the old mode.

## OS Surface & Portability

- **OS-agnostic**: the only OS API is `System.system_time(:second)` (lease arithmetic) — no `System.cmd`, `Port.open`, `:os.*` or `File.*`/`Path.*` beyond `TaskExecutor`'s `TaskTmpdir` call, so no Windows-only crash can ORIGINATE here; the tmpdir BINARY later reaches the Windows sandbox's `Port.open`, whose env pairs MUST be charlists (OTP-29: binary tuples raise `ArgumentError: invalid option in list`) — convert at that call site (`../sandbox/CONTEXT.md` → "Port/OS-pid pitfalls").

## Failed-Task Error Persistence (`TaskInfo.error`)

Every transition to `:failed` records a structured payload in the dedicated `error` column (JSON TEXT), decoded onto `TaskInfo.error` (`map() | nil`), visible in the full-decode paths (`Store.get_task/1`, `list_tasks_paginated/1` via `Codec.decode_task/1`) AND the 16-key summary projection (lenient `Codec.decode_error/1`; nil for non-failed rows).
Shape is a fixed 4-key map with ATOM keys after decode: `%{kind: atom, source: atom, message: String.t(), stacktrace: [String.t()] | nil}`.
`kind` ∈ `:error | :exit | :down | :force_kill | :timeout | :restart | :lease_expired | :recheck`; `source` ∈ `:result_handler | :down_handler | :force_kill_task | :finalizing_watchdog | :startup_reconcile | :lease_sweep | :recheck_resolve`.
Sole producer: the pure `Diagnostics.failure_error(kind, source, message, stacktrace \\ nil)`; decode is lenient (nil / invalid JSON / non-object → nil), so a corrupt cell cannot break a row read.
Graceful-cancel `:cancelled` is NOT a failure — no error is recorded there.
`handle_update_status/6` appends `error:` ONLY when the FINAL persisted status is `:failed` (after the force-map rewriting stored `:cancelling` + terminal → `:cancelled`), so a force-mapped `:cancelled` row never carries one.

- **(a) wrapper result error/exit** (`handle_info({ref, result}, state)` case): `{:error, reason}` → kind `:error`, `"Task failed: #{inspect(reason)}"`; `{:exit, reason}` → kind `:exit`, `"Task exited: ..."`; unknown shape → kind `:error`; source always `:result_handler`; stacktrace = last 8 frames via private `stacktrace_lines/0` (the REGISTRY process's stack via `Diagnostics.capture_stacktrace/8` + `format_stacktrace_frame/1`, not the dead wrapper's). The error rides `update_task_status_with_caller(..., error: error)` → self-cast → `handle_update_status/6`.
  - `result` is PRESERVED as the RAW error tuple (never nil, never the human string), so `tasks.result` holds the Codec `{"__result_tag__": "error", "reason": <reason | inspect(reason)>}` JSON decoding back to `{:error, reason}`; `"Task failed: ..."` lives ONLY in `error.message` (`{:error, {:llm_request_rejected, "<actionable message>"}}` is persisted verbatim, per the runtime result spec).
  - `usage`/`agent_count`/`commit_sha` are nil here: `result_field(result, key, validator)` returns nil for anything not `{:ok, data} when is_map(data)`, and the matching `if usage, do: ...` guards OMIT those columns (earlier values untouched; nil for a fresh failed task) — never explicitly nil'd. `branch_name` is likewise nil; `finished_at` IS set and the lease cleared.
  - The wrapper returns the runtime value verbatim (no try/rescue) and exits `:normal`: the failure is persisted as a VALUE — no raise, no retry, no scheduler agent-crash retry.
- **(b) wrapper abnormal `:DOWN`** (persisted `:failed` only when `Lease.sched_meta_has_active_agents?/1` is false): kind `:down`, source `:down_handler`, message = the same `"Task process exited: #{inspect(reason)}"` string also written as `result`, stacktrace captured.
- **(c) stuck-`:finalizing` grace watchdog** (`resolve_finalizing_watchdog/3`): kind `:timeout`, source `:finalizing_watchdog`, message = the same `"Finalization did not complete within N minutes"` string written as `result`, stacktrace nil.
- **(d) force kill** (the direct `Store.update_task_columns` write): kind `:force_kill`, source `:force_kill_task`, `"Task force-killed by user"`, stacktrace nil — same update as the status flip; `result` stays nil, the error records why.
- **(e) startup reconciliation** (`init/1`, `:finalizing` → `:failed`): kind `:restart`, source `:startup_reconcile`, message `"Runtime restarted during task finalization"` (same as `result`), stacktrace nil.
- **(lease sweep)**: kind `:lease_expired`, source `:lease_sweep`, message `"Lease expired; owning instance no longer renewing"` (same as `result`), set on the full `%TaskInfo{error: ...}` before `Store.put_task`.

## Restart Recovery & Status Transitions

**Startup reconciliation.** `init/1` runs `EvoGit.Store.select_running_lease_info/1` (id + status + lease_expires_at, SQL `status IN ('running','pausing','awaiting_input','finalizing','cancelling')`); each `:finalizing`/`:cancelling`/`:awaiting_input` row gets a SYNCHRONOUS `handle_update_status/6` with `{:startup_reconcile, ...}` caller info: `:finalizing` → `:failed` (`"Runtime restarted during task finalization"`), `:cancelling` → `:cancelled` (`"Runtime restarted during task cancellation"`), `:awaiting_input` → `:failed` (`"Runtime restarted during interactive session"`, `error.kind :restart`).
A `:running`/`:pausing` row takes the PAUSE classification instead: RESUMABLE → `:paused` + `pause_kind: :dirty` (the `Restart.classify/2` verdict applied by `park_dirty_pause/2`), non-resumable → the existing behaviour (left to the one-shot `:lease_sweep`, which fails it with `:lease_expired`) — see "Task-Level Pause & Resume" and "Heartbeat, Restart Classification & `list_tasks/0` Bound".
The handler narrow-reads `select_task_update_info/1` (status/opts/finished_at/lease_expires_at — no full decode), applies the stale-guard, logs via `Diagnostics.log_failed_transition`, handles finished_at/lease, broadcasts `{:task_updated, task_id, status, node()}`, cleans `task_refs`.
Writes are SYNCHRONOUS in init (NOT the async cast, which would race callers).

- `state.task_refs` is in-memory only — empty after restart, so `{ref, result}` / `{:DOWN, ...}` never fire for pre-restart tasks.
- `:heartbeat` renews leases only for owned tasks where `Lease.lease_renewable?/1` is true — `Lease.renewed_statuses/0` = `:running | :pending | :cancelling | :awaiting_input | :pausing` (never `:finalizing`, never `:paused`) plus `{:unknown, raw}`; a missing row (`nil`) and every terminal status renew nothing (an idle `:awaiting_input` session keeps its lease exactly like a running task, and so does a `:pausing` drain whose wrapper is alive).
- `:lease_sweep` (one-shot, 150 s after init = `(@lease_duration + 30) * 1000`) filters with `Lease.leaked?/3` — a KNOWN `Lease.leaked_statuses/0` row (`:running`, `:pausing` or `:awaiting_input`), not in `owned_ids`, lease expired/missing; `:finalizing` is excluded by design (init handled it), `:paused` is never swept (no lease, no wrapper — it is a legitimate resting row), live statuses respect lease validity for the multi-VM case, and `{:unknown, raw}` is never leaked.
- `:periodic_cleanup` → `Cleanup.cleanup_expired_tasks/1` deletes only rows with `finished_at != nil`; `:finalizing` has `finished_at == nil` → never deleted.
- **Lease mechanics**: `@lease_duration` 120 s, `@heartbeat_interval` 60_000 ms; the lease is set at start, renewed by the heartbeat via `Store.update_lease_expires_at`, and the sweep marks expired `:running` foreign tasks `:failed` only when `sched_meta_has_active_agents?` is false, then runs cleanup + broadcasts.
- **Cleanup semantics**: never changes status — age cutoff + count trim (newest `max_tasks`) pushed into SQL; defaults `max_tasks: 100`, `max_age_days: 14`.

**Resolution paths for `:finalizing`:** (a) startup reconcile → `:failed`; (b) explicit — `clear_finished_tasks` uses `select_finished_task_ids` (SQL `status NOT IN ('running','pending','cancelling')`, which includes `:finalizing`) and DELETEs them, or `delete_task`; (c) in-process — wrapper completion (`{:ok,_}` → `:completed`, error/exit → `:failed`), wrapper crash (`:normal` → `:completed`; abnormal → `:failed` only if no active sched_meta agents), or the public `update_task_status/4` cast (stale-guard blocks terminal→terminal except →`:completed`); `cancel_task` from `:finalizing` → `{:error, :not_running}` (graceful works from `:pending`/`:running`); (d) the stuck-`:finalizing` watchdog.
**Lease expiry plays NO role here** — a stuck wrapper just stops getting renewals; the in-process watchdog bounds `:finalizing` while the BEAM is alive.

**Stuck-`:finalizing` grace watchdog.** On a SUCCESSFUL persist of `:finalizing` (`Store.put_task` `:ok` arm only — never the disk-full path) the local handler schedules a ONE-SHOT `Process.send_after(self(), {:recheck_task, task_id}, trunc(minutes * 60_000))` via `schedule_finalizing_watchdog/1` (always an integer; 0 fires immediately).
Grace minutes come from the app-env seam `:finalizing_watchdog_grace_minutes`, read at SCHEDULE time by `finalizing_watchdog_grace/0`: `false` → DISABLED; unset/nil → **60**; numeric ≥ 0 → that many minutes (floats tolerated); anything else → 60. `config/config.exs` sets 60 and `config/test.exs` 1.
At fire time the recheck handler's dedicated `%TaskInfo{status: :finalizing}` arm (between the terminal and generic clauses) calls `resolve_finalizing_watchdog/3` (re-reads the minutes for the message via `finalizing_watchdog_result_minutes/0`; `:disabled` at fire time falls back to the default) and resolves `:failed` + `"Finalization did not complete within N minutes"` through the shared `handle_update_status/6` with caller_info `{:finalizing_watchdog, task_id}`: Diagnostics log, `finished_at` set, lease cleared, broadcast only on a successful write, marker cleared, `task_refs` deleted.
It does NOT check `sched_meta_has_active_agents?`, does NOT reschedule, kills nothing and leaves residual sched_meta/agent state untouched; timers are per-boot and a restart mid-grace is covered by startup reconciliation.

**Pinned late-wrapper-result semantics**: after the watchdog resolves to `:failed` the wrapper is still alive (blocked, e.g. slow NFS git I/O); its `{ref, result}` / `{:DOWN, ...}` handlers are complete NO-OPS — `task_id_for_ref/2` returns nil because the terminal branch deleted the `task_refs` entry, so both skip their write bodies (the row keeps the watchdog result + finished_at, never clobbered) and `Process.demonitor(ref, [:flush])` clears the monitor plus any queued `:DOWN`; nothing re-adds the task to `task_refs` (test-pinned in `persistence_test.exs`).

**`resolve_recheck_task/3` and the 30 s live-agent reschedule remain effectively unreachable**: `Lease.lookup_sched_meta_result/1` is used only there, reached only from the recheck handler's generic arm for non-terminal, non-`:finalizing` rows — the watchdog schedules rechecks only for `:finalizing` rows and nothing schedules a first recheck for `:running` rows.

**Stuck-`:finalizing` cause**: `Runtime.Helpers.notify_finalizing/1` broadcasts from INSIDE the runtime phase, right after `AgentScheduler.run_agent` returns and BEFORE `merge_and_report/4`, so a blocked merge blocks the wrapper while the status stays `:finalizing`; `task_id` reaches the runtime via the base `task_id:` runtime-opt key.
While blocked, `{ref, result}`/`:DOWN` never fire, heartbeat/lease-sweep/periodic-cleanup skip `:finalizing`, `cancel_task` → `{:error, :not_running}`, and the force-kill gate is `killable_statuses/0` = `[:running, :awaiting_input, :cancelling, :pausing, :paused]`.

## Task-Level Pause & Resume

A task-level pause is `docs/task-pause.md`'s wind-down of ONE named task to a durable, resumable RESTING state; it is neither a cancel nor a failure, and it lives on top of the `agent_state.sqlite` durability substrate rather than replacing it.
Two NON-terminal statuses carry it: `:pausing` (a pause request is draining the task's agents — wrapper alive, lease renewed) and `:paused` (every agent stopped at a turn boundary with its worktree checkpointed and its state checkpointed — no lease, no wrapper, `finished_at` nil, resumable).
`pause_kind` (`:clean | :dirty | nil`, the `tasks.pause_kind` column) is the ONE persisted discriminator: `:clean` = the user paused (nothing was interrupted, so the resume repairs nothing), `:dirty` = a restart brought the row back (the last tool batch may be partial, so the resume runs the existing crash-repair), and `nil` = not paused.
`:cancelled` keeps meaning "gracefully cancelled by the user"; a pause never lands there.

**Public entry points.** `TaskRegistry.pause_task/1` and `TaskRegistry.resume_task/1` are `GenServer.call`s on the registry (validation/persistence in `EvoGit.TaskRegistry.Pause`), mirrored by `AgentScheduler.RemoteAPI.pause_task/1` / `resume_task/1` and `RemoteNode.pause_task/2` / `resume_task/2`.
`pause_task/1` → `:ok` (including the idempotent `:pausing`/`:paused` case) or `{:error, :not_found | :not_pausable | :not_resumable | :not_running | :scheduler_unavailable | :disk_full | :store_unavailable}`.
`resume_task/1` → `:ok` or `{:error, :not_found | :not_paused | :not_resumable | <admission reason>}`.

**Pause protocol (clean).** `pause_task/1` accepts `:running` only for a real transition: an interactive-session task (`:awaiting_input`, or persisted `:session_mode == "interactive"`) is `{:error, :not_pausable}`, a stored `:persistent_state == false` (or a non-boolean) is `{:error, :not_resumable}` (pause without durability would be a lie), `:pausing`/`:paused` are idempotent no-ops, and `:pending`/`:finalizing`/`:cancelling`/terminal rows are `{:error, :not_running}`.
The row is written `:pausing` FIRST, the broadcast follows, and only then is `EvoGit.AgentScheduler.begin_task_pause/1` called (it sets the `:evogit_task_pause` marker, flips each agent's control-plane pause flag and purges their queued LLM/tool slot waits with `{:error, :paused}`), so a pause can never hang behind a slot wait; a scheduler that is down/timeouts reverts the row to `:running` and answers `{:error, :scheduler_unavailable}` (a `:pausing` row with no agents to drain is unrecoverable without a restart).
Each agent honours the flag at a TURN BOUNDARY (never mid-tool), reaps background jobs, commits a checkpoint of its worktree, flushes its durable state and delivers `{:paused, info}`; `info.durable` is `true` only when that `EvoGit.AgentState.flush/1` barrier answered `:ok`, so a timed-out flush still pauses the task while honestly reporting that the last writes were not confirmed; the scheduler's ROOT agent reports only after its children have paused, so ONE wrapper result closes the whole task.
`handle_wrapper_result/3`'s `{:paused, info}` arm then writes a TARGETED `status: :paused, pause_kind: :clean, finished_at: nil, lease_expires_at: nil` (never a full `put_task`, so `result`/`usage`/`commit_sha`/`branch_name`/`started_at`/`opts` stay byte-identical and a resume ACCUMULATES usage), broadcasts `{:task_updated, task_id, :paused, node()}` on the successful write and reuses the terminal in-memory cleanup (`task_refs` entry dropped, scheduler pause marker cleared via `Pause.abandon/1`); the worktrees are reclaimed normally because the checkpoint commit is what survives.
No `:finalizing` notification and no merge ever run for a pause.

**Straggler guard.** A late `{:ok, %Result{}}`/`{:error, _}`/`:DOWN` for a task whose row is already `:pausing`/`:paused` is DISCARDED (`pause_settled?/2` + `discard_paused_result/3`, logging only the RESULT SHAPE): a straggler must never resurrect a paused task, flip it to `:completed`/`:failed`, or clobber the result/usage a later resume depends on.
A `{:paused, info}` report that arrives while the row is `:cancelling` resolves the row the cancellation way (`:cancelled`, the normal teardown) — a cancel that arrives during the drain WINS; one that arrives on a terminal or `:awaiting_input` row is discarded outright.

**Cancel / force-kill precedence.** `cancel_task/1` accepts `:pausing` and `:paused` (`gracefully_cancellable_statuses/0`): `:pausing` ABANDONS the pause first (`Pause.abandon/1`, so the pause can never be re-introduced) and then runs the ordinary `:running` graceful-cancel arm, while `:paused` is retired immediately like an idle session (`:cancelled`, `pause_kind: nil`, result preserved).
`force_kill_task/1` accepts both (`killable_statuses/0`) and lands `:failed` with the result nil'd, clearing `pause_kind` in the same write.
Every terminal transition clears the scheduler pause marker; a pause requested while the task is `:cancelling` is a total no-op.

**Resume protocol.** `resume_task/1` accepts `:paused` ONLY (`{:error, :not_paused}` otherwise) and re-enqueues the SAME task id with the PERSISTED opts — never `start_task/2`, which mints a fresh id and would reset the archive roster.
It re-runs `start_task/2`'s admission (`RuntimeOpts.admit_task_path/1`, `RuntimeOpts.admit_model_selection/2` against the current config, `admit_session_mode/1`, `admit_persistent_state/1`), requires the durable ROOT run (`read_root_run/2`: ONE bounded, offloaded `AgentStateRead.roster/2` read whose ROOT is the record with an absent `parent_id` — no durable row at all or a CHILD-only roster is `{:error, :not_resumable}`), resolves that row's five resume facts up front, clears the stale scheduler pause marker FIRST, spawns the wrapper through the registry's call-time seam (`wrapper_spawn_fun`), and only then writes `status: :running, finished_at: nil, error: nil, pause_kind: nil` + a FRESH lease, broadcasting `{:task_updated, task_id, :running, node()}` after the write (a failed write stops the spawned wrapper).
The spawn opts carry `resume_kind: :clean_pause` (`pause_kind == :clean` or legacy `nil`) or `:dirty_pause`, which `RuntimeOpts.build_common_runtime_opts/3` forwards to the same key in `spec.opts`, plus the ROOT run's five resume facts — `pause_commit` (the worktree checkpoint), `resume_agent_id` (the persisted root id the resumed run registers under, so every durable read keyed `(task_id, agent_id)` still resolves), `resume_current_commit`, `resume_branch` and `resume_anchor_ref` (`fields[:anchor_ref]`, else `EvoGit.AgentState.Anchor.ref/2`).
Each fact is PRESENCE-based with its value (`nil` included, meaning "resolved, nothing stored"), so the dispatch side never reads the durable database on its own hot path while a non-resume run's opts stay byte-identical; `RuntimeOpts.resume_fact_keys/0` is the ONE key list shared with `Runtime.Helpers.build_root_agent_spec/7`.
`AgentScheduler.Dispatch` bases the resumed worktree on `:pause_commit` (`meta.crash_commit` first, both `git cat-file -e`-verified, degrading to the task base) and carries `:resume_agent_id` / `:resume_current_commit` / `:resume_branch` / `:resume_anchor_ref` as the persisted root identity; `EvoGit.Agent.Resume` selects the narration (clean = no repair, dirty = the crash-repair + `[RESUME]` notice).
The archive roster is PRESERVED: `AgentScheduler.run_agent/2` skips its per-task archive reset when the spec opts carry `resume_kind` (`TaskRegistry.Pause` sets it), so the paused run's rows survive and the resume's archived completions UPSERT onto them (the table is keyed `(task_id, agent_id)`: a re-run of the SAME agent id REPLACES its row, a new agent id appends), and `:paused` defeats `clear_finished_tasks` because it lives in `Lightweight.live_statuses/0` while carrying `finished_at: nil`.

**Restart mapping (dirty pause).** Both restart paths classify every wrapper-less `:running`/`:pausing` row in ONE batched `Restart.classify/2` pass (the ONE resumability classifier: `:persistent_state` on AND NOT an interactive session — the SAME rule the clean pause refuses with `:not_pausable` — AND a durable ROOT run, never "any durable row"; `Pause.pause_kind_for_restart/1,2` stays the public single-row view of the same rule): a RESUMABLE row is parked `:paused` with `pause_kind: :dirty`, `finished_at` nil, lease cleared and result/usage untouched (one broadcast after the persist), while a NON-resumable row — an interactive session included, a CHILD-only roster included, and an unanswerable durable read, which degrades to `[]` and therefore `nil` — keeps today's behaviour — `init/1` leaves `:running` to the one-shot `:lease_sweep` and the sweep maps its expired lease to `:failed` with the `:lease_expired` payload.
`init/1` owns the rows present AT BOOT (`:running` and `:pausing`, no lease check needed on a fresh BEAM); the sweep owns rows that become owner-less later (`Lease.leaked?/3`).
Only the ROOT agent is resumable after a restart: subagent processes are gone, their retained batch is scheduler memory, and a child's partial work survives only if it was already merged.

## Graceful Cancellation & Force Kill

**Task status `:cancelling`** is the graceful-cancel state, deliberately **NON-terminal**: the `task_refs` entry stays, `finished_at` stays nil, the lease stays valid (heartbeat renews it).
It is whitelisted in `Store.Codec.@known_atoms` and the `TaskInfo` typespec; `Store.select_finished_task_ids` (SQL `status NOT IN ('running','pending','cancelling')`) keeps `clear_finished_tasks` from deleting in-flight cancelling tasks while `:finalizing` still counts as finished; `Store.select_running_lease_info` includes it; startup reconciliation maps it to `:cancelled`; heartbeat renewal covers it via `Lease.lease_renewable?/1`.

The **`{:task_updated, id, :finalizing, node}` handler** matches ONLY `:finalizing` (other statuses are persisted locally), with a node-filter guard `when node == node()` plus an explicit no-op clause for other nodes (a remote finalizing broadcast must never persist locally — task ids are per-node, cross-node collisions corrupt rows).
A `:cancelling` task ignores phase-finalization broadcasts; on a successful persist the handler schedules the one-shot watchdog.

`handle_update_status/6` force-maps the final result: stored `:cancelling` + incoming `:completed | :failed` → persisted `:cancelled`, with result/usage/archive flowing through untouched (never nil'd), so the agent's final summary is preserved.

**`TaskRegistry.cancel_task/1` is GRACEFUL**:

- `:pending` → immediate `:cancelled` write (finished_at set, lease cleared) + `{:task_updated, task_id, :cancelled, node()}` broadcast only on the successful write; `start_task` refuses already-`:cancelled`/`:cancelling`/`:awaiting_input`/`:pausing`/`:paused` ids with `{:error, :cancelled}`.
- `:running` → `handle_update_status(..., :cancelling, ...)`, which broadcasts `{:task_updated, task_id, :cancelling, node()}` (the ONLY broadcast for this arm; non-terminal, so finished_at/lease/task_refs stay), then `AgentScheduler.begin_graceful_cancel(task_id)` (`:exit`-guarded — a down scheduler leaves the task `:cancelling` for force kill or restart reconciliation).
- `:awaiting_input` → immediate terminal `:cancelled` write (finished_at set, lease cleared, NO `result` column so the transcript/result is preserved) + `clear_cancelling_marker/1` + tmpdir reclaim + `{:task_updated, task_id, :cancelled, node()}` on the successful write; the idle session is stopped best-effort BEFORE the write (`AgentScheduler.force_kill_task_agents_for_task/1`, task-addressed, `:exit`- and undefined-function-guarded, then this instance's `Task.shutdown(ref, :brutal_kill)` while its task_refs entry is still present so the kill's `:DOWN` cannot race the write and map the row to `:failed`).
- `:pausing` → the pause is ABANDONED first (`Pause.abandon/1`) and the `:running` arm then runs, so a cancel that arrives mid-drain wins and the pause can never be re-introduced.
- `:paused` → immediate terminal `:cancelled` write exactly like an idle session (finished_at set, lease cleared, `pause_kind: nil`, result/usage preserved).
- `:cancelling` → `:ok` idempotent (does NOT re-send the cancel message).
- terminal (`:completed`/`:failed`/`:cancelled`) or `:finalizing` → `{:error, :not_running}`; missing → `{:error, :not_found}`.

**`TaskRegistry.force_kill_task/1`**: gate `killable_statuses/0` (`:running | :awaiting_input | :cancelling | :pausing | :paused`; `pause_kind` is cleared in the same write so a killed task is never mistaken for a paused one) → `AgentScheduler.force_kill_task_agents(pid)` (reverse-depth `:brutal_kill` cascade, `:exit`-guarded) + `Task.shutdown(ref, :brutal_kill)` + a direct terminal write (`:failed`, finished_at set, lease nil, result nil — a force-killed task is never `:cancelled`) + `clear_cancelling_marker(task_id)`. The body is status-agnostic: only the gate widened for waiting sessions.

**Marker cleanup** — `clear_cancelling_marker/1` prefers `AgentScheduler.clear_cancelling_task/1` (serialized, cannot race `begin_graceful_cancel`) and falls back to `:ets.delete(:evogit_cancelling_tasks, task_id)` when the scheduler is down (TaskRegistry starts BEFORE AgentScheduler, e.g. during startup reconciliation). Called from every terminal transition (`handle_update_status/6`, the `:finalizing` handler, force kill).

## PubSub Broadcast Contract (topic `"tasks"`)

Default ordering is **persist-then-broadcast**: `handle_update_status/6` writes via `Store.update_task_columns` FIRST and broadcasts `{:task_updated, task_id, status, node()}` only in the `:ok` arm, gated on `status != task_status` — a missing row, stale-guard skip or disk-full write never broadcasts, so a listener that re-fetches sees the NEW row.
The trailing `node()` is the emitting node; subscribers ignore other nodes for node-local state.

| Broadcast | Site | Ordering |
|---|---|---|
| `{:task_updated, id, :running, node()}` | `start_task`; `resume_task/1` (a paused task resumed in place) | put_task → broadcast / update_task_columns → broadcast |
| `{:task_updated, id, :pausing, node()}` | `pause_task/1` `:running` arm | persist → broadcast, BEFORE `begin_task_pause/1` |
| `{:task_updated, id, :paused, node()}` | `handle_wrapper_result/3` `{:paused, info}` arm (clean); `init/1` reconciliation and `:lease_sweep` (dirty) | write → broadcast (exactly one per transition; the clean arm fires only on a successful write) |
| `{:task_updated, id, :cancelling, node()}` | `cancel_task/1` `:running` arm (and the `:pausing` arm, after abandoning the pause) | persist → broadcast |
| `{:task_updated, id, :cancelled, node()}` | `cancel_task/1` `:pending` arm AND `:awaiting_input` arm | write → broadcast |
| `{:task_updated, id, :failed, node()}` | `force_kill_task/1`; `:lease_sweep`; recheck resolution; watchdog/startup reconcile | write → broadcast (force-kill fires unconditionally) |
| `{:task_updated, id, nil, node()}` | `set_review_status` / `set_review_metadata` casts | after the write (no status change) |
| `{:task_deleted, id, node()}` | `clear_finished_tasks` (one per id), `delete_task` | only on the successful write |

- **Terminal sequences end-to-end**: completed = wrapper sends `{ref, result}` → handler maps to `:completed`/`:failed`/`:exit` → cast `update_task_status_with_caller` → `handle_update_status/6` force-maps `:cancelling`+terminal → `:cancelled` (result preserved) → persist, then broadcast. Abnormal wrapper death = `{:DOWN, ...}`: `:normal` → `update_task_status(:completed)`; other reasons → `:failed` ONLY when `Lease.sched_meta_has_active_agents?` is false, else the row stays `:running` with no broadcast.
- **The ONLY broadcast preceding its persist is `:finalizing`**: `Runtime.Helpers.notify_finalizing/1` fires it from INSIDE the wrapper and the local handler persists afterward; a disk-full `put_task` leaves subscribers told `:finalizing` while the row stays `:running` (self-heals at the terminal broadcast). Reflect tasks never emit `:finalizing` (`:running → :completed/:failed/:cancelled`).
- **`Cleanup.cleanup_expired_tasks/1` deletes rows with NO broadcast.**

## Task Lifecycle & Terminal-Write Sites

- **Start / Run**: `start_task/2` spawns the wrapper (above); the wrapper runs the WHOLE lifecycle synchronously (incl. `Runtime.Helpers.merge_and_report/4`) and never writes statuses — `notify_finalizing/1` broadcasts `:finalizing` from inside it before `merge_and_report`, and the local handler persists it.
- **DOMINANT terminal choke point = `handle_update_status/6`**: its terminal branch runs the in-memory teardown — `clear_cancelling_marker/1` + `TaskTmpdir.reclaim/2` + `task_refs` deletion. Reached from the wrapper result handler, the `:DOWN` handler, startup reconciliation and the watchdog.
- **Terminal transitions that BYPASS it (direct `Store` writes)**: `force_kill_task/1` (`:failed` + reclaim + broadcast), `cancel_task/1`'s `:pending` arm (`:cancelled` + reclaim + broadcast), `resolve_recheck_task/3` (reclaim), `:lease_sweep` (`put_task`, reclaim, `:failed`). Hence NO single teardown choke point and no shared `terminal_cleanup/3` helper: a task-end teardown needs a hook at ALL FIVE sites.
- **Per-task on-disk artifact**: the managed tmpdir above. `Cleanup.cleanup_expired_tasks/1` only DELETEs finished task ROWS (called from `clear_finished_tasks`, `:lease_sweep`, `:periodic_cleanup`); archive rows live in their own per-agent table ("Store Access…").
- **Boot-time reconciliation**: `init/1` enumerates orphaned `:running`/`:finalizing`/`:cancelling` rows via `Store.select_running_lease_info/1`; worktree/scheduler artifacts are per-AGENT and monitor-reclaimed, never task-scoped (`../agent_scheduler/CONTEXT.md`), and runtime phases write nothing outside the repo (`../runtime/CONTEXT.md`).
- **Boot memory profile (init is NOT the growth vector)**: the state keeps exactly five keys — `data_dir` (string, never read again), `task_store` (atom/pid), `task_refs` (`%{task_id => %Task{}}`, only THIS instance's live tasks, removed at terminal), `read_offloads` (transient `ref => entry`) and `server_name` (atom); no task row, `result` or `logs` is ever retained. `select_running_lease_info/1` projects only `id`/`status`/`lease_expires_at` (SQL `status IN ('running','awaiting_input','finalizing','cancelling')`) and the row list is `Enum.reduce`d and DISCARDED; only `:finalizing`/`:cancelling`/`:awaiting_input` rows cost one `select_task_update_info/2` read (status/opts/finished_at/lease — `opts` may carry base64 `:attachments`), then a write.
- **Rows-proportional allocations that DO land on the registry heap are id-only** (`:periodic_cleanup` → `Cleanup.cleanup_expired_tasks/1` and `clear_finished_tasks` → `select_finished_task_ids/1` run inline, not offloaded): strings bounded by `task_history` (`max_tasks` 100 / `max_age_days` 14), deleted in 500-id chunks.

## Merge-Conflict-Resolution Flow (MergeContext / TaskExecutor)

- **Only trigger point**: `TaskExecutor.execute_task(:evolve, opts, task_id)` runs a merge-context step BEFORE `resume_from` handling: a non-empty trimmed `opts[:merge_from]` triggers `MergeContext.apply_merge_context(opts, task_id, trimmed_merge_from, opts[:merge_target])`, whose result replaces `opts`; only the merge keys are stripped, so an independently supplied `resume_from` still triggers ResumeContext afterward and can override the merge-derived starting commit (`task_executor.ex:59–90`, `merge_context.ex:31–35`).
- **`apply_merge_context/4`** strips `:merge_from`/`:merge_target` FIRST (never leak into runtime opts) → `prev_task = EvoGit.TaskRegistry.get_task(merge_from)` (full `%TaskInfo{}` decode). **nil** → stripped opts unchanged. **Found** → `:starting_commit` overridden with `prev_task.commit_sha` when a non-empty binary (caller's value preserved otherwise) → `:foreign_repos` carried from `prev_task.opts` when present/non-nil, each entry normalized via `EvoGit.Core.ForeignRepo.normalize/1` with unparseable entries dropped (STRING-keyed after the Codec round trip; raw carry-over crashes downstream dot-access) → each carried repo's `base_sha` overridden from the prev result's `repos[repo_id]["commit_sha"]` via `PrevTaskRepos.apply_starting_commits/2` (defensive string-key reads; repos absent from the prev `repos` keep their base_sha; legacy tasks without `repos` are a no-op) → `:objective` = `build_merge_context_block(prev_task, merge_target, carried_repos) <> "\n\n" <> old_objective`. Pure keyword-in/out (no `RuntimeOpts` call; returns opts, NOT a `{objective, runtime_opts}` tuple).
- **`build_merge_context_block/2,3`** returns a "Merge Conflict Resolution Context" string fenced by `--- Merge Conflict Resolution Context ---` / `--- End Merge Conflict Resolution Context ---`: `Previous task id:`; `Base sha:` / `End (commit) sha:` (each omitted when nil/empty — the block is still emitted); `Task branch name: <branch_name || "unknown">`; `Merge target branch: <merge_target || "unknown">`; a `Goal:` paragraph (merge the target into the worktree via `git merge <target>`, resolve ALL conflicts by combining both sides, commit, keep developing until coherent); a `Writable foreign repos: <id>@<base_sha|HEAD>, ...` line (ONLY when ≥1 writable repo — the 3-arity takes explicit repos so the block shows the ACTUAL starting commits, the 2-arity derives them from `prev_task.opts[:foreign_repos]`); a `Hints:` section. Non-struct input → `""`.
- **Hints (8 bullets)**: commit conflict resolutions before delegating follow-up work (subagents spawn at clean checkouts, so uncommitted changes are invisible); inspect `git log/diff <base>..<end_sha>` and `git log/diff <base>..<target>` (ranges interpolated when the shas exist, placeholders otherwise); incremental milestone merges OR rough-resolve-then-develop-on-top as fallbacks; plus the five CONTEXT.md ownership bullets.
- **CONTEXT.md conflict policy (five ownership bullets)**: keep the version of the side whose node path OWNS the file (the node directory whose subtree contains it — the agent rooted at `./src` owns `./src/CONTEXT.md`, the root agent at `./` is everybody's ancestor); a genuine same-node conflict (e.g. two agents rooted at `./src`) is merged deliberately from BOTH sides, keeping both routing-table entries and both sets of documented facts, reconciling wording only where it is the same fact; prefer `edit_context` with small surgical edits over whole-file rewrites; never drop another node's routing-table entries merely because they conflict textually (a child's entry must survive, and entries for different children both belong in the merged table); never resolve by discarding one side's content — if ownership is genuinely ambiguous, keep both sides and note the ambiguity.
  Covered by `test/evo_git/task_registry/merge_context_block_test.exs` (hints present, appended before the closing delimiter, kept on both arity paths).

## Resume-From Flow (ResumeContext / TaskExecutor / RuntimeOpts)

- **Only trigger point**: `TaskExecutor.execute_task(:evolve, opts, task_id)` calls `ResumeContext.apply_resume_context/3` when `opts[:resume_from]` is a non-empty binary after `String.trim/1`; non-resume evolve tasks build `{objective, runtime_opts}` directly (`objective = Keyword.get(opts, :objective, "")`).
- **`apply_resume_context/3`** strips `:resume_from` (never leaks into runtime opts) → `prev_task = get_task(resume_from_id)` (FULL 18-column decode — known inefficiency, low priority). Caller-supplied `:foreign_repos` are normalized to `%ForeignRepo{}` structs (string-keyed Codec maps allowed; unparseable dropped) and each repo's `base_sha` is overridden from the prev result's `repos[repo_id]["commit_sha"]` via `PrevTaskRepos.apply_starting_commits/2` (string-keyed, defensive; absent repos keep their base_sha; legacy tasks without `repos` are a no-op); the `:foreign_repos` key is (re)added only when the normalized list is non-empty.
  **nil prev** → original objective, `build_common_runtime_opts` with the caller's own (normalized) repos. **Found** → `context_block = build_resume_context_block/1`; the objective becomes `context_block <> "\n\n" <> objective` only when the block is non-empty; `:starting_commit` is overridden with `prev_task.commit_sha` when a non-empty binary (a caller-provided value is silently dropped), else the caller's passes through; then `build_common_runtime_opts(opts_with_commit, task_id, :evolve)`.
  **Foreign repos are NOT inherited from `prev_task.opts` on resume** — only caller-supplied ones flow through; `MergeContext` is the ONLY cross-task inheritance path.
- **Context block exact format**: `"--- Previous Task Context ---\n" <> Enum.join(parts, "\n\n") <> "\n--- End Previous Task Context ---"`, empty string when `parts == []`; parts join with blank lines.
  Part 1: `"Previous task commits: #{base_sha}..#{commit_sha}"` (both non-empty; just `commit_sha` when base_sha is empty/nil; omitted when commit_sha is empty). Part 2 (only when ≥1 writable foreign repo in `prev_task.opts[:foreign_repos]`, normalized first, not delimited): `"Writable foreign repos: <id>@<base_sha|HEAD>, ..."`.
  Part 3 (delimited): `"Previous task objective:\n<<<BEGIN OBJECTIVE>>>\n#{old_objective}\n<<<END OBJECTIVE>>>"` (from `prev_task.opts` `:objective` || `:prompt`, only when non-empty). Part 4 (delimited): `"Previous task result:\n<<<BEGIN RESULT>>>\n#{summary}\n<<<END RESULT>>>"` (omitted when `extract_result_summary/1` returns nil or `""`).
  The `<<<BEGIN ...>>>`/`<<<END ...>>>` markers wrap arbitrary multi-line content so the agent cannot confuse a label with its content or content with the outer fence; the all-caps triple-angle form cannot plausibly collide with agent-generated text.
- **`extract_result_summary/1`**: `{:ok, %{result: s}}` binary → passthrough, atom → `to_string/1`; `{:error, reason}` → `"Error: #{inspect(reason)}"`; `{:exit, reason}` → `"Exited: #{inspect(reason)}"`; anything else → nil.
- **SHA provenance**: `prev_task.commit_sha` is populated at completion by the `{ref, result}` handler extracting `{:ok, %{commit_sha: sha}}` (the runtime merge result carries `commit_sha: final_sha || base_sha`). `prev_task.base_sha` is set ONLY by the review flow (`set_review_metadata/3` cast), so a never-reviewed task's commits line is just the commit_sha.

## Repo-Less (`:reflect`) Task Option & Lifecycle Contract

- **No reflect-specific validation exists here**: `handle_call({:start_task, ...})` (`task_registry.ex:447-492`) is TYPE-AGNOSTIC — it persists the WHOLE opts keyword list (`task.opts = opts` at `:484`) and the only checks are the shared `RuntimeOpts` admission gates (`admit_task_path/1`, `admit_model_selection/2`, `admit_session_mode/1`, `admit_persistent_state/1`), so `:history`/`:messages`/`:conversation`/`:session`/`:resume_from` are neither required nor rejected; they ride into `Runtime.SelfReflective.run/1` and are ignored there.
- Auto admission (`runtime_opts.ex:32-33`) DROPS `:model_spec`/`:model_id`/`:model_id_locked`; an explicit `:model_spec` is schema-validated and canonicalized, and `:model_id_locked: true` is forced — reflect gets exactly this one admission step, at enqueue and again at `execute_task/4` (`task_executor.ex:34`).
- **`:path` is neither required nor forbidden for reflect** — `admit_task_path/1` admits an absent/`nil` `:path` (the repo-less case) and any ordinary binary; `do_execute_task(:reflect, ...)` never reads it and never calls `build_common_runtime_opts` (`task_executor.ex:130-139`); the only consumer is `ensure_task_tmpdir/2` (`task_executor.ex:49-51`), which would use it as the `:per_repo` tmpdir base. A `vct:` path is refused for EVERY task type, reflect included.
- **`:attachments` is accepted but inert for reflect**: `RuntimeOpts` never validates it on this path and `Session.Setup.build_initial_state/3` nils it for repo-less agents (`agent/session/setup.ex`, `if repo_less, do: nil`), so no media reaches the Assistant.
- **`:quality_level` and `:archive` pass through unvalidated but are inert/ineffective**: `:quality_level` bypasses `QualityLevel.normalize/1` (it reaches the session's initial state as-is via `agent/session/setup.ex` `Session.Setup.build_initial_state/3`, `state.quality_level`) and `:archive` cannot produce a row because the archive gate requires `archive and base_commit` while repo-less `base_commit` is nil (`agent/completion.ex:74`).
- **Resume/merge do NOT support reflect**: `ResumeContext.apply_resume_context/3` and `MergeContext.apply_merge_context/4` have NO task-type guard but are only reachable from `do_execute_task(:evolve, ...)` (`task_executor.ex:61-96`), so a `:reflect` task simply ignores `:resume_from`/`:merge_from`; an evolve task resuming FROM a reflect task id would embed that task's objective + final `result` string only (no commits line), and NO path replays a prior reflect conversation (chat continuity is the dashboard's `Transcript.build_preamble/2` text in `:objective`).
- **One agent, one run**: `Runtime.SelfReflective.run/1` builds ONE `EvoGit.Agents.SelfReflective` root spec (`subagent_modules/0` is `[]`) and blocks on `AgentScheduler.run_agent/1`; its result is `{:ok, %{result: report_text, commit_sha: nil, branch_name: nil, tag: nil}}` with no `:usage`/`:agent_count`, so the task's terminal status comes from the shared wrapper-result handler (`handle_wrapper_result/3`: `{:ok, _}` → `:completed`, `{:error, reason}`/`{:exit, reason}`/other → `:failed`) and the report text lands verbatim in `tasks.result`.
- **Review status is not type-guarded, but merging cannot work**: `set_review_status/1`/`set_review_metadata/3` write on any existing row (only a missing row is a no-op), yet a reflect task has nil `branch_name`/`commit_sha` and no repo, so `Review.merge_branch/2,3`/`check_merge/3`/`default_merge_target/1` have no branch to act on.
- **Nothing survives except `task.result`**: reflect writes no `task_agent_archives` row (archive gated on `archive and base_commit`) and its agent conversation lives only in that agent's `:evogit_agent_summary` ETS row, deleted by `Lifecycle.recycle_agent/2` at completion (`delete_agent_state`/`delete_sched_meta`) — `run_agent` itself also calls `reset_task_archives(task_id)` (`agent_scheduler.ex:677`), so no transcript is recoverable post-hoc.

## Known Issues

- `awaiting_input_test.exs` pins the status-set totality table (every set containing `:running` also contains `:awaiting_input`, except the deliberate `:finalizing` ignore-list exemption) plus the reconcile/kill/cancel/flip behaviour.
- **A status string outside `Store.Codec.known_statuses/0` keeps its lease but is still masked in full decodes.** Liveness is safe (see the tri-state bullet in "Store Access…": `get_task_status/2` answers `{:unknown, raw}`, the heartbeat renews it and the sweep never leaks it), but the full-row decode cannot carry `{:unknown, _}` in the `TaskInfo.status` atom, so `Codec.decode_task/1` (`mask_unknown_status/1`) renders the row as a LIVE `:pending` row on `get_task/2`/`get_task_lite/2` and the summary projections — the codec logs the offending value on every such read. Liveness decisions must therefore use the narrow `Store.get_task_status/2`, never the masked struct field; adding a task status without extending that whitelist still leaves the dashboard showing a wrong (live) status label.
- **A restart is FATAL for a `:running` task that is not dirty-pausable, and there is no other resume path.** `init/1` reconciles `:finalizing` → `:failed`, `:cancelling` → `:cancelled`, `:awaiting_input` → `:failed`, and parks a RESUMABLE `:running`/`:pausing` row as `:paused` + `pause_kind: :dirty`; every other `:running` row falls to the one-shot `:lease_sweep` **150 s after EVERY boot**, which fails every `:running` row that is (a) not in THIS instance's `task_refs`, (b) lease-lapsed, and (c) agent-free per THIS instance's `sched_meta_has_active_agents?/1`. "Owning instance" exists ONLY as `task_refs` — no persisted instance/node/boot id column — so ANY fresh BEAM sharing the DB owns nothing. The sweep writes `:failed` + `"Lease expired; owning instance no longer renewing"` + `error.kind :lease_expired`, lease nil, finished_at set, but NOT `branch_name`/`commit_sha` → NOT reviewable.
- **`sched_meta_has_active_agents?/1` reads a BEAM-LOCAL ETS table** (`:evogit_sched_meta`, `:named_table`/`:public` but NOT distributed), so it never sees another instance's live agents: if A's lease lapses (dead BEAM, restarted registry with empty `task_refs`, stalled heartbeat), B's boot sweep fails A's STILL-RUNNING task while its agent worktrees are alive — a later primary-repo spawn in a fresh BEAM then re-runs the WorktreeManager full wipe (`:evogit_worktree_repos` is app-owned → rm_rf `.genesis/workers` + delete all `evogit-agent-*` branches), destroying in-flight work.
- **The `:finalizing` handler's ignore-list deliberately omits `:failed`**: `task.status in finalizing_ignored_statuses/0` (`[:completed, :cancelled, :cancelling]`) — recovering a persisted-`:failed` row to `:finalizing` on a stale broadcast is intended (pinned by `persistence_test.exs` "recovery before completion"; the list must NOT gain `:failed`). The in-code "tasks already terminal" wording covers exactly those three; this only fires on a stale in-flight broadcast (a cross-node one is dropped by the node guard).
- **`force_kill_task/1` broadcasts `{:task_updated, task_id, :failed, node()}` UNCONDITIONALLY** — also on `{:error, :not_running}` / `{:error, :not_found}` / `{:error, :disk_full}` with no persisted change. Local subscribers only act on `:finalizing`, but the dashboard sees a spurious `:failed` for an unchanged row.
  The same shape applies to `set_review_status/2` and `set_review_metadata/3`: their `{:task_updated, task_id, nil, node()}` broadcast sits OUTSIDE the write `case`, so it fires for an absent row and for a disk-full/store-unavailable write that persisted nothing.
- **Disk-full at a terminal write can leave a row `:finalizing` with NO in-process retry.** `handle_update_status/6`'s `{:error, :disk_full}` arm only logs; the in-memory cleanup still runs, but the row keeps its OLD status and no broadcast fires. Nothing retries: the watchdog is ONE-SHOT, heartbeat renews only the statuses `Lease.lease_renewable?/1` accepts, `:lease_sweep` only considers rows `Lease.leaked?/3` calls leaked (`:running`/`:awaiting_input`), `:periodic_cleanup` needs `finished_at != nil`, and a late `{ref, result}` after `task_refs` deletion only logs `"received task result for unknown ref ... result dropped"`. Wedge: the watchdog's own `:failed` write also hits disk-full (timer consumed) → the row stays `:finalizing` until an explicit `clear_finished_tasks`/`delete_task` or a registry restart whose init reconcile maps it to `:failed`.
- **⚠️ Memory scales with `tasks.sqlite` size — via the summary-query path, NOT init.** `init/1` and retained state (`task_refs` = running tasks only) are clean; the O(N) path decodes every matching row's `opts` JSON in `Store.select_tasks_summary*` / `select_tasks_changed_since` (`result` is NOT in the 16-column projection, so `Codec.decode_result` never runs), offloads both handler sides to a supervised read worker that replies via `GenServer.reply/2` (no large terms retained in either GenServer, and a decode crash degrades that one read), and has the dashboard re-fetch statuses-filtered sidebar summaries on every broadcast (300 ms debounce) while each ProjectsLive session keeps the 16-key maps (`opts` kept, `result` dropped) in assigns for its lifetime. Retained memory ≈ O(rows × opts-blob size) (`periodic_cleanup` caps finished rows at `max_tasks: 100`); nothing loads the DB at boot.
- **Derived foreign-repo `base_sha` is a FROZEN snapshot never re-validated against git.** `PrevTaskRepos.apply_starting_commits/2` reads `prev_task.result`'s `repos[repo_id]["commit_sha"]`, persisted ONCE at the previous task's terminal write and never rewritten. Nothing re-reads the foreign branch tip or checks ancestry, so a follow-up (resume / merge-auto-resolve) from an OLDER task starts that repo at the older commit when a LATER task advanced it (the sha is merely an ancestor; only existence is validated, via `Runtime.Helpers.validate_foreign_repo_base_sha!`, and an unresolvable sha raises a descriptive `ArgumentError` at task start). Recording is skipped when the foreign-repo subagent's result is not `{:ok, %Result{}}` AND for any child that is not itself a writable `:read_write` agent running there (`Subagents.store_sub_result/3,4`).
- **Resume block vs runtime mismatch**: the `Writable foreign repos:` line comes from the PREVIOUS task's own `opts[:foreign_repos]`, NOT from the overridden per-repo starting commits threaded into runtime opts — the two can disagree. `MergeContext` avoids this via its 3-arity builder.

- **A task-level resume carries the ROOT run's durable identity to the scheduler; consuming it belongs to the scheduler node.** `Pause.resume/4` resolves the task's ROOT roster row (`AgentStateRead.roster/2`) and puts its `agent_id`, `current_commit`, `branch` and `anchor_ref` (derived via `EvoGit.AgentState.Anchor.ref/2` when the row stores none) plus its `pause_commit` on the spawn opts, and `RuntimeOpts` → `Runtime.Helpers.build_root_agent_spec/7` forward them PRESENCE-based into `%AgentSpec{}.opts` (`RuntimeOpts.resume_fact_keys/0` is the ONE key list).
  `EvoGit.AgentScheduler.Dispatch` is the consumer of these keys — its `agent_scheduler/` CONTEXT owns the restore/base precedence (`:pause_commit` ahead of the task base, `:resume_agent_id` as the identity the resumed root registers under, and the anchor ref that keeps the commits reachable after worktree reclamation); the registry resolves the ONE ROOT row and never reads the durable store on the scheduler's behalf beyond that.
  A dirty pause writes no `pause_commit`, so such a resume still bases on the task base unless the ROOT row's own `current_commit` is usable.

## Project Mounts Are Not Registry State

The registry owns task state only: `EvoGit.VCT` owns the project mount list, its `"vct"` broadcast and every mount read, and no registry handler, seam or state key references it.

## Three-State Reads: Outage Is NOT Absence
The registry MUST never read a store OUTAGE as a domain answer.
`StoreGuard` offers three helpers: `read/3` (degraded answer on fault), `write/2` (`{:error, :store_unavailable}` on fault) and `fetch/2` (`{:ok, value} | :unavailable`), and `fetch/2` is MANDATORY for any read whose degraded `nil`/`[]` would be treated as a DOMAIN fact (gone row, empty list, unhealthy config).
`EvoGit.TaskRegistry.StoreRead` is the ONE three-state read surface built on it: `status(store, task_id) :: {:ok, status} | :absent | :unavailable`, `update_info(store, task_id) :: {:ok, map} | :absent | :unavailable` and `restart_info(store, task_ids) :: {:ok, [map]} | :unavailable`, where `status` is a known atom OR `{:unknown, raw}` (the row EXISTS, its status text is unreadable).
`:absent` means "no such row"; `:unavailable` means "the store could not answer", which is never evidence of anything.
Each call site picks the CONSERVATIVE direction for its own failure mode:
| Site | `:absent` | `:unavailable` |
|---|---|---|
| `handle_update_status/6` | no write, no broadcast (row gone) | no write, no broadcast (cannot read the row to decide: stale-terminal guard, `:cancelling` map, finished_at/lease preservation) |
| `set_review_status/2`, `set_review_metadata/3` | silent no-op | no write (never persist blind), no broadcast |
| `pause_settled?/2` | not settled | **`true`** — the straggler guard stays ON, so a late `{:ok, %Result{}}`/`:DOWN` can never flip a `:pausing`/`:paused` row to `:completed`/`:failed` and clobber the result/usage a resume needs |
| `persist_paused/3` | drop the ref (the row is gone) | drop the ref + ONE warning — the pause is never reported as persisted, and the lease sweep parks a resumable row as a DIRTY pause |
| `start_task/2` | proceed (a fresh minted id cannot be `:cancelled`) | proceed, for the same reason — refusing would strand a task nothing else could start |
| `pause/2`, `resume/4` admission | `{:error, :not_found}` | `{:error, :store_unavailable}` (an unreadable row is never "not found") |
| `{:recheck_task, id}` | no-op | reschedule 30 s later (a periodic watchdog must not disappear on a store blip) |
| `Restart.classify/2` | nothing classified | nothing classified (rows keep their live status; the sweep later fails them — today's degradation) |
The review casts removed the tautological `nil ->` / `present when not is_nil(present)` pair: `{:ok, _present}` (including `{:unknown, raw}`, because the row exists) is writable, and the `{:task_updated, task_id, nil, node()}` broadcast fires ONLY inside the arm where `update_task_columns/3` answered `:ok` — a no-op, a missing row and a failed write are not state changes.
The pause WRAPPER RESULT path reads through `StoreRead.update_info/2` too: `{:paused, info}` → `persist_paused/3` is a decision on the CURRENT row (park it, let a cancel win, bookkeep an already-paused row, discard a lost race), so an outage must not read as "no row".
`:absent` there drops the `task_refs` entry silently, because a gone row has nothing to persist or broadcast.
`:unavailable` logs ONE warning naming the task id and drops the same entry: the pause was NOT persisted, so it is never reported as persisted.
Dropping the ref stops lease renewal, which leaves recovery to the lease sweep — `Lease.leaked?/3` sweeps a `:pausing`/`:running` row with an expired lease, and a resumable one is parked as a DIRTY pause instead of failing.
## Heartbeat, Restart Classification & `list_tasks/0` Bound
`EvoGit.TaskRegistry.Heartbeat.renew(store, task_ids, expires_at) :: :ok` is the WHOLE heartbeat body: `[]` ids is a no-op with no read; otherwise ONE `Store.select_task_statuses/2`, keep the ids whose status passes `Lease.lease_renewable?/1` (`:running | :pending | :cancelling | :awaiting_input | :pausing | {:unknown, raw}` — a row that EXISTS with unreadable status is still renewed; absent rows and terminal statuses are not), return `:ok` WITHOUT a write when nothing is renewable, else ONE `Store.renew_leases/3`.
`{:error, :disk_full}` logs exactly ONE warning naming the task COUNT (never one per task); `{:error, :store_unavailable}` answers `:ok` (StoreGuard already logged it).
A degraded/absent status read (`%{}`) renews nothing — the documented degradation.
The registry keeps `@lease_duration` and passes the ABSOLUTE `expires_at`; the heartbeat is purely renewal and NEVER sweeps.
`EvoGit.TaskRegistry.Restart.classify(store, task_ids) :: %{optional(id) => :dirty}` is the ONE restart classifier both recovery paths share: ONE `StoreRead.restart_info/2` read, keep the rows `Pause.dirty_pausable?/2` accepts (`:persistent_state` on, opts-only), ONE `AgentStateRead.roster_many/2` (batched 5 s bounded offload), and a row is `:dirty` only when one of that task's durable records is a ROOT RUN (`Pause.root_run?/1`, `fields[:parent_id] == nil`).
A degraded read (`:unavailable` or `[]`) classifies NOTHING, so `init/1`/`:lease_sweep` fall through to the sweep-fail path (`:lease_expired` → `:failed`).
`init/1` and `:lease_sweep` call it ONCE for all their candidates and then only perform the targeted dirty-pause write (`park_dirty_pause/2`: `status: :paused`, `pause_kind: :dirty`, `finished_at` nil, lease nil) — one broadcast per persisted transition, AFTER the persist.
`Pause.pause_kind_for_restart/1,2` stays public and delegates `/2` through `Restart.classify(store, [task_id])` (tests use both arities).
`list_tasks/0` is bounded to `@list_tasks_limit` (100) rows, `started_at DESC`, decoded through `Store.safe_select_paginated_tasks/1`; the return shape stays `[%TaskInfo{}]`.
## Store Access, SQL Lowering & Fault Isolation

- **Cleanup is the ONE unguarded store caller**: `Cleanup.cleanup_expired_tasks/1` calls `Store.select_cleanup_info/3` and `Store.delete_tasks/2` directly (no `StoreGuard`), so only its CALLERS' wrappers contain a store exit; `cleanup.ex:39-51` matches only `:ok` and `{:error, :disk_full}` (another error tuple raises `CaseClauseError`), and the helper emits no PubSub event or command-approval cancellation.
- **No per-row store loops remain on the hot paths**: the 60 s `:heartbeat` makes ONE `Store.select_task_statuses/2` read plus AT MOST ONE `Store.renew_leases/3` write for the whole `task_refs` set (`EvoGit.TaskRegistry.Heartbeat.renew/3`), and boot reconciliation plus the one-shot `:lease_sweep` classify every candidate with ONE `Restart.classify/2` (one `Store.select_tasks_restart_info/2` read + ONE `AgentStateRead.roster_many/2`), then write the dirty pause per row through targeted columns; `sweep_fail_task/5` still adds a full `get_task/1` + full `put_task/2` for a genuinely failing row (usually 0-1 per sweep). Every one of these runs synchronously inside the registry process, so the batching is what keeps the mailbox responsive.
- **`get_task/1` is the ONE in-registry full decode**: `{:get_task, id}` → `task_get/2` → `Store.get_task/2` runs UNOFFLOADED (as do `prev_status/2`, the `:recheck_task` handler and the `:finalizing` handler), while `get_task_lite/1` — the same 20-column decode — IS offloaded, so the heavier path is the one that can stall the registry mailbox.
- **`list_tasks/0` is BOUNDED** → `Store.safe_select_paginated_tasks/1` with `limit: @list_tasks_limit` (100), ordered `started_at DESC`, so it decodes the newest 100 rows' heavy JSON instead of the whole table; the shape stays `[%TaskInfo{}]` (its only caller is `RemoteAPI.list_tasks/0`, which depends on it, and the dashboard uses the paged/page reads). There is still no status filter.
- **Store callers in `apps/evo_git/lib`**: only `task_registry.ex` and `task_registry/cleanup.ex` (the `agent_scheduler/*` `Store.` references are `EvoGit.AgentScheduler.Store`, a DIFFERENT ETS module); none in `lease.ex` (ETS-only; `sched_meta_has_active_agents?/1` scans via `:ets.tab2list`), `diagnostics.ex`, `runtime_opts.ex`, `task_executor.ex` (Store only transitively via ResumeContext), `store_guard.ex`.
- **`Store.get_task_status/2` is TRI-STATE and every consumer here honours it**: `nil` = NO row (the only "absent" answer), a known status atom, or `{:unknown, raw}` = the row EXISTS with unreadable status text (already logged by `Codec.decode_status/1`).
  The heartbeat renews via `Lease.lease_renewable?/1` (which renews `{:unknown, _}`), the `:lease_sweep` decides via `Lease.leaked?/3` (which never leaks `{:unknown, _}`; `select_running_lease_info/1`'s SQL `IN ('running','pausing','awaiting_input','finalizing','cancelling')` filter means such a row cannot even reach the sweep — the classifier stays the single source of truth, defence-in-depth rather than a duplicate rule).
  The guards answer conservatively and explicitly: `cancel_task/1` and `force_kill_task/1` → `{:error, :not_running}` (never `:not_found` — the row is present — and nothing is marked or killed), `start_task/4` proceeds (it always allocates a FRESH id, so refusing would strand a task nothing else could start; it is also not `:cancelled`-provable), and `set_review_status/2` / `set_review_metadata/3` write (only a missing row is their no-op).
  Every consumer logs the unreadable value through `log_unreadable_status/3`; none of them may collapse `{:unknown, raw}` into "absent".
- **Lightweight reads**: `list_tasks_page/1` → `Store.select_tasks_page/2` (16-key rows + `total`, no blobs; degrades to `%{rows: [], total: 0}`) and `get_task_lite/1` → `Store.get_task_lite/2` (same 20-column `Codec.decode_task/1` as `get_task/2`, `result`/`logs`/`usage` INCLUDED — it is NOT a blob-free read; degrades to `nil`).
- **Per-agent archive mirrors**: `put_task_archive/1` → `StoreGuard.write/2` around `Store.put_task_archive/2` (STREAMING write, `:ok` | `{:error, _}`); the client never raises or exits into the writing agent — a dead store degrades to `{:error, :store_unavailable}`, so completion never fails on a store fault. `list_task_archives/2` → `Store.list_task_archives/3` roster page returning `%{entries: [], total: 0}` on a read fault; entries are STRING-KEYED, ordered `depth ASC, agent_id ASC` (root first), `opts` = `:limit` (default 100, clamp 1..1000), `:offset` (default 0), `:include_results` (default `false` → the `"result"` key is ABSENT), `:include_settings` (default `false` → the three export-only JSON keys are ABSENT) and `:include_total` (default `true`; `false` skips the `count(*)` and yields `total: nil`); the registry forwards `opts` UNCHANGED — it adds, drops and defaults nothing — and `total` is the task's whole row count. `get_agent_archive/2` → `Store.get_agent_archive/3` is the lazy per-agent detail (includes `"result"`), degrading to `nil`. There is no single task-wide archive reader.
  The producer write runs IN THE CALLER (`EvoGit.Agent.Completion` → the completing agent's process), NOT in the registry: `put_task_archive/1` resolves the instance's store from `:evogit_task_registry_stores` (published by `init/1`) and writes there directly, so a multi-MB insert never holds the registry — nor the dashboard reads and the heartbeat queued behind it. There is no GenServer handler for it.
  **Durability ordering**: the call stays SYNCHRONOUS for that caller and `Store.Writer` replies only after the commit, so the archive row is durable before the completing agent returns and the task's terminal status is written (the terminal transition happens only after the agent's completion). A registry crash/restart can no longer lose an archive row in flight, and the store mapping is deliberately NOT deleted on registry terminate.
  The archive never rides a task write: each completing agent writes its OWN `task_agent_archives` row, so a result write persists exactly what the result holds; nothing archive-related rides `%Result{}` or the report. Being a side table with no foreign key, deletes cascade EXPLICITLY: `Store.delete_task_archives/2` → `Operations.Archives.delete_by_task/2`, `Operations.Archives.delete_by_tasks/2` (chunked) inside `Store.delete_tasks/2`, `Operations.Archives.delete_all/1` on a full clear; task-level archive metadata is not stored on the task row.
- **Narrow reads over full decode**: `set_review_status`, `set_review_metadata`, `handle_update_status`/`update_task_status_with_caller`, `cancel_task` and `resolve_recheck_task` write through `update_task_columns/3`.
  The narrow read side is the ONE three-state surface `EvoGit.TaskRegistry.StoreRead` (`status/2`, `update_info/2`, `restart_info/2`) — `Store.select_task_update_info/2` DOES carry the maintained `project_path` scalar (no `opts` decode for the path any more), and `Store.select_tasks_restart_info/2` is the batched row shape (id/status/type/opts/pause_kind/project_path) restart classification and `Pause.read_row/2` use.
  Still FULL-decode: `ResumeContext`/`MergeContext` via `TaskRegistry.get_task/1` (single-row paths that need `result`, justified) and the `:finalizing` handler, which re-encodes the whole row through `put_task/2` (`result`/`logs`/`usage`/`opts`) to set ONE column; `resolve_recheck_task/3` avoids that by writing targeted columns.
  **Narrow-read rule**: a read whose value is a STATUS, a LOG field or a path takes the narrow projection; only a caller that needs the STRUCT (`result`, `opts`, the whole row) may run the 20-column decode, and a registry handler that can answer from the status column alone must do so before falling back to `task_get/2`.
  Applied: `prev_status/2` is a log-only status read through `StoreRead.status/2`, and `{:recheck_task, id}` reads the status FIRST (`:absent` → no-op, `:unavailable` → reschedule, terminal → no-op) and only then runs the full `task_get/2` for the `:finalizing` watchdog and `resolve_recheck_task/3`.
- **Registry read offload** (`EvoGit.TaskRegistry.ReadOffload`): every large-decode read (`list_tasks`, `list_tasks_paginated`, `list_tasks_page`, `get_task_lite`, `list_task_archives`, `get_agent_archive`, `list_tasks_summary`, `list_tasks_summary_by_path`, `list_tasks_changed_since`) runs inside a `Task.Supervisor.async_nolink/2` worker of the dedicated `EvoGit.TaskRegistry.ReadSupervisor` (in the app supervision tree, separate from `EvoGit.TaskSupervisor` so a scheduler restart cannot kill in-flight reads); the worker runs `StoreGuard.read/3`, allocates AND discards the decoded term, and replies to the caller with `GenServer.reply/2` itself, so the value never enters the registry heap — not even in transit (`get_unique_paths` and `list_task_ids` reply INLINE: tiny projections).
  The registry tracks in-flight reads in `state.read_offloads` (`ref => entry`): `{ref, :ok}` is ignored (the worker already replied), `:DOWN` `:normal` settles the entry, `:DOWN` with any other reason answers the caller with that read's DEGRADED value and logs at `:error`, and `{:read_offload_deadline, ref}` (`@deadline` 28 s, between the store's 25 s read deadline and the registry's 30 s call budget) kills the wedged worker with `Task.shutdown(…, :brutal_kill)` and answers the degraded value — so a read NEVER exits or raises in the registry.
  Each call site keeps its own exact degraded shape (`[]`, `{[], 0}`, `%{rows: [], total: 0}`, `%{entries: [], total: 0}`, `nil`); a failed worker START degrades the same way (justified `catch` around the one cross-process call). The registry keeps this layer although the store isolates its own reads: the store replies to its CALLER, which without this layer is the registry.
- **Cleanup SQL**: `cleanup_expired_tasks/1` reads only ids — age cutoff (`AND finished_at < ?cutoff`) and over-limit keys (`ORDER BY finished_at DESC LIMIT -1 OFFSET ?max_tasks`) pushed into SQL — then deletes via `delete_tasks/2` (chunked, all-or-nothing per chunk); both legs use the covering `idx_tasks_finished_at_id` index, with no row decode / Elixir-side sort or filter.
- **`select_running_lease_info`** SQL-filters `status IN ('running','pausing','awaiting_input','finalizing','cancelling')` (a `:pausing` drain must be reconciled too; `:paused` is deliberately absent — a paused row holds no lease and is never reconciled or swept); callers still filter Elixir-side, as do `id not in owned_ids` and lease-expiry-vs-wall-clock (ISO-8601 fixed-precision ordering caveat: `../store/CONTEXT.md`).
- **Project mounts are not task state**: they live in the store's `vct_mounts` table, owned by `EvoGit.VCT`, so no registry read, write, broadcast or cache involves them.
- **Store-owned internals** (migrations, summary/`changed_since` APIs, JSON storage model, `mix store.maintenance`, disk-full classifier): `../store/CONTEXT.md`.

- **"Task archive" names a per-AGENT row**: `put_agent_archive/1` is the aligned row-level writer (ONE agent's row) and `put_task_archive/1` stays as its public alias because the completing-agent path in `agent/completion.ex` calls it; `list_task_archives/2` pages agent rows and `get_agent_archive/2` already uses the agent noun.
- **`RuntimeOpts.build_common_runtime_opts/3` returns `{nil, runtime_opts}` BY CONTRACT**: element 0 is a reserved placeholder no caller may consume, and the pair must NOT be unwrapped — ~20 tests pattern-match it, so returning the keyword list alone would be a test-visible break rather than a cleanup.
- **`MergeContext.apply_merge_context/4` ignores its third parameter `_task_id`** (`merge_context.ex:31`, passed by `task_executor.ex:70-75`) and returns bare opts, while the sibling `ResumeContext.apply_resume_context/3` returns `{objective, runtime_opts}`.
- **`cancel_task/1` and `force_kill_task/1` docs omit the pause statuses they accept**: the `@doc`s at `task_registry.ex:355-378` and `:383-398` list only pending/running/cancelling/awaiting-input while `@gracefully_cancellable_statuses` (`:123`) and `@killable_statuses` (`:112`) include `:pausing` and `:paused`; the comment at `:117` also cites a nonexistent `cancel_awaiting_input_session/2` (the function is `/1`, `:1831`).
- **`Pause.persist_paused/3` drops the honesty flag**: the wrapper reports `{:paused, %{durable: boolean()}}` (produced by `agent/session/pause.ex:20`, documented as "nothing downstream can overstate it"), but `task_registry.ex:2676` binds `_info`, writes `pause_kind: :clean` and logs "clean checkpoint" unconditionally — a `durable: false` pause is recorded as if it were durable.
- **`Lease.lookup_sched_meta_result/1` contradicts its doc** (`lease.ex:42`): the doc promises `{:ok,_}|{:error,_}|{:exit,_}|nil` "if a recognizable result is found", the code returns `List.first(Map.values(sub_agent_results))` unchecked, so any term can leak through while the `lookup_` prefix suggests a metadata lookup (it returns an agent RESULT).
- **Lease vocabulary: four words for two facts** — "orphaned" (a wrapper-less row: the `Restart.classify/2` verdict plus its `park_dirty_pause/2` write), "leaked" (`lease.ex:143 leaked?/3`, `@leaked_statuses`), "expired" (the lease timestamp, `lease_valid?/1`, error kind `:lease_expired`) and "stale" (an out-of-date update or marker, `:1364,2277`, `pause.ex:229`) — use "orphaned" for the row condition, "lease expired" only for the timestamp, "stale" only for updates.
- **`run` vs `record`/`row`**: `pause.ex`/`agent_state_read.ex` call one durable agent execution a "run" (`read_root_run/2`, "ROOT run"), yet the same entity is `%AgentState.Record{}`, "row" and "entry" elsewhere — settle on "agent run" for the record and keep "task" for the whole tree.
- **Cross-layer verb families are asymmetric** (outside this node, referenced here): `TaskControl.cancel/1` folds the force-kill into a `"force"` boolean (`task_control.ex:240`, mirrored by the MCP `genesis_cancel_task` tool) while the core keeps `cancel_task/1` + `force_kill_task/1`; `AgentScheduler.force_kill_task_agents/1` takes a PID but only the task-addressed twin carries a suffix (`agent_scheduler.ex:819,839`), and the cancel family lacks the `task` token the pause family has (`begin_graceful_cancel/1`/`clear_cancelling_task/1` vs `begin_task_pause/1`/`clear_task_pause/1`); `Runtime.Evolution.mode_atom/1` (`runtime/evolution.ex:77`) is a second `mode_atom` with different semantics from `RuntimeOpts.mode_atom/2` (`runtime_opts.ex:459`).
- **Spec coverage is uniform on the public facade**: every public function in `task_registry.ex` carries a `@spec` plus the `@type`s `task_status`/`persisted_status`/`write_result`/`task_read`/`paginated_tasks`/`task_page`/`archive_page`/`unique_paths`, and its `@doc` states the list shape — `list_tasks/0` `[%TaskInfo{}]` (bounded 100), `list_tasks_paginated/1` `{[%TaskInfo{}], non_neg_integer()}`, `list_tasks_page/1` `%{rows: [row], total: non_neg_integer()}`, the archive roster `%{entries: [entry], total: non_neg_integer() | nil}`.
  Remaining gaps are inside `Pause` (`resume_result` is `{:ok, term()} | {:error, term()}` where the success value is a `%Task{}`) and `Diagnostics.log_failed_transition/4`'s `:source` examples (`diagnostics.ex:22-24` names `:reconcile`/`:task_updated_pubsub`, which no longer exist — actual: `:startup_reconcile`, `:update_status_cast`, `:lease_sweep`, `:recheck_resolve`, `:result_handler`, `:down_handler`).
- **`Pause.dirty_pausable?/2` is the pure rule and `/1` its bounded per-task wrapper**: `dirty_pausable?(task_map, durable_root? :: boolean())` is opts-only (never touches a database), while `/1` delegates with ONE bounded `AgentStateRead.roster/2` root check; `Restart.classify/2` calls `/2` with its batched roster. `Pause.root_run?/1` is the ONE "is this record the task's ROOT run" predicate.
