# TaskRegistry Support Modules

## Intent

Support modules extracted from the `EvoGit.TaskRegistry` GenServer so the main module stays focused on the task-lifecycle state machine.
Every module here is pure-function or ETS-only — none owns GenServer state.

## Routing Table

None — leaf directory (all modules at this level).

## Process-Scoped Isolation Seam

`EvoGit.TaskRegistry.server/0` resolves the registry name for the CURRENT process — the `:evogit_task_registry_server` process-dictionary value when present, else `__MODULE__` — at CALL time, never cached.
Every client function routes its call/cast through it: `start_task/2`, `get_task/1`, `get_task_lite/1`, `put_task_archive/1`, `list_task_archives/2`, `get_agent_archive/2`, `list_tasks/0`, `list_tasks_paginated/1`, `list_tasks_page/1`, `cancel_task/1`, `force_kill_task/1`, `update_task_status/4`, `update_task_log/2`, `set_review_status/2`, `set_review_metadata/3`, `list_tasks_by_path/1`, `list_tasks_summary/2`, `list_task_ids/1`, `list_tasks_summary_by_path/3`, `list_tasks_changed_since/1`, `get_unique_paths/0`, `delete_task/1`, `clear_finished_tasks/0`, `add_recent_project/2`, `list_recent_projects/0`, `remove_recent_project/1`.
`EvoGit.Store` needs no seam: every Store client takes an explicit `store` first argument (default `__MODULE__`) and `start_link/1` honours a custom `:name` (`child_spec/1` keeps `id: __MODULE__`, so several instances need an explicit `id:`).
An isolated pair is `EvoGit.Store.start_link(name: <store>, data_dir: <tmp>)` + `EvoGit.TaskRegistry.start_link(name: <unique_atom>, task_store: <store>, data_dir: <tmp>)`; the app-global singletons are never started or stopped.
The registry stores its registered name (`Keyword.get(opts, :name, __MODULE__)`) in state, sets it under `:evogit_task_registry_server` in `init/1`, and passes it as the 4th wrapper-spawn argument, so `execute_task/4` re-installs it and in-wrapper `MergeContext`/`ResumeContext` callbacks (`get_task/1`) hit the SAME instance; its in-process self-casts (`update_task_status_with_caller/4` / `update_task_status/2` from the `{ref, result}` and `:DOWN` handlers) therefore resolve to THIS instance, and with the key unset every seam read resolves to `__MODULE__` (production unchanged).
Processes NOT descending from the wrapper (self-reflective `agent/tools/*`, `cli.ex`, `agent_scheduler/remote_api.ex`, evo_dash callers) never inherit the key — their suites stay serialized against the global singleton.

## Constraints

- **Task-type atom whitelist in the SQLite Codec**: `start_task/2` is TYPE-AGNOSTIC — any atom reaches `TaskExecutor.execute_task/3`, whose private `do_execute_task/3` has one clause per type (`:genesis`, `:evolve`, `:extract_skills`, `:reflect`) and NO catch-all (unknown type → `FunctionClauseError` in the spawned task → task `:failed`). The persisted `type` column round-trips `EvoGit.Store.Codec.@known_atoms` (task types + status/review atoms); `decode_atom` returns `nil` for non-whitelisted strings, so a NEW task type MUST be added there or its tasks load back with `type: nil` (`TaskInfo.type` is `atom() | nil`).
- **Purity**: no GenServer state, no I/O except `Cleanup` → `EvoGit.Store` deletion and `TaskExecutor` → `EvoGit.TaskTmpdir.ensure/2`. `TaskExecutor` runs OUTSIDE the GenServer (under `Task.Supervisor`); `RuntimeOpts`/`ResumeContext`/`MergeContext`/`PrevTaskRepos` are pure builders.
- **Cleanup/reaping is SQLite-row-only — NO disk or `.genesis/` reaping.** Init reconciliation, the one-shot `:lease_sweep`, `Cleanup.cleanup_expired_tasks/1`, the 5-minute `:periodic_cleanup`, `clear_finished_tasks` and `delete_task` only touch `tasks.sqlite` rows plus the in-memory `task_refs` entry and the `:evogit_cancelling_tasks` marker. Worktree reclamation belongs to `EvoGit.AgentScheduler.WorktreeManager` (`:DOWN`-driven), outside this subtree.
- **`task_registry.ex` stays long by design**: the main GenServer is the task-lifecycle state machine (status transitions, lease/heartbeat, graceful cancel + force kill, startup reconciliation, review-status handlers), deliberately cohesive.

## RuntimeOpts Key Contract

`RuntimeOpts.build_common_runtime_opts(opts, task_id, task_type)` returns `{nil, runtime_opts}` (first element always `nil`).

- `:path` is REQUIRED (`Keyword.fetch!` → `KeyError`; the key is `:path`, never `:repo_path`).
- `:mode` is a STRING — `"new"`/`"existing"` for `:genesis`, `"simple"`/`"custom"` for `:evolve` — converted via `mode_atom/2`. An ATOM hits the catch-all `ArgumentError` ("invalid genesis/evolution mode"); a MISSING mode defaults to `"simple"`, which raises for genesis ("invalid genesis mode: \"simple\"") — genesis callers must pass `mode`. Genesis `"custom"` raises `"custom mode is evolve-only; use an evolve task with mode \"custom\""`.
- Base keys always emitted: `repo_path` (from `:path`), `mode` (atom), `task_id` (the parameter, not an opts key).
- Threaded only-if-present (nil/false/`""` dropped): `node_path`, `starting_commit`, `foreign_repos` (an EMPTY `[]` IS truthy and passes), `archive`, `model_id` (non-empty string), `agent` (non-empty binary), `build_system`. `model_id_locked` uses `put_if_true/3` — always `true`, never the value.
- `attachments` is validated UNCONDITIONALLY via `EvoGit.Attachments.validate/1` (nil/`[]` → `:ok`; malformed → descriptive `ArgumentError` at task start) and put only when non-nil AND non-`[]`; values are STRING-keyed base64 maps (`EvoGit.Attachments`).
- `:quality_level` is normalised via `EvoGit.QualityLevel.normalize/1` (nil/`""` → `"balanced"` silently; recognised value unchanged; anything else → `Logger.warning` + `"balanced"`) and appended ONLY when ≠ `"balanced"`.
- Private `put_if/4` (default predicate = truthiness) and `put_if_true/3` build the chain; everything else in the input opts is silently DROPPED.
- `foreign_repos` is threaded VERBATIM — never normalized (`ForeignRepo.normalize/1`) or validated, even a non-list passes. Normalization/validation live in `EvoGit.Runtime.Helpers.load_foreign_repos/2` (`merge_foreign_repos/2` + `validate_foreign_repo!`), where a task-opts entry for an id REPLACES the genesis.toml entry wholesale (id-keyed `Map.merge`; TOML `writable`/`base_sha` are lost when the opts entry differs).
- `:starting_commit` has NO default: absent → the runtime resolves HEAD (`resolve_starting_commit(repo_path, nil)` → `PhyloGraphNode.current_head/1`); present → it must `git rev-parse` cleanly or evolution fails. No concurrency key is built here.

## TaskExecutor Dispatch & Task Start

`execute_task/4` stores `server` in the `:evogit_task_registry_server` process dictionary FIRST, then `ensure_task_tmpdir/2`, then private `do_execute_task/3`: `:genesis` → `Runtime.Genesis.run(prompt, runtime_opts)`; `:evolve` → merge-context step, then resume-context-or-plain, then `Runtime.Evolution.run(objective, runtime_opts)`; `:extract_skills` → `Runtime.SkillExtraction.run(runtime_opts)`; `:reflect` → `Runtime.SelfReflective.run(opts ++ [task_id: task_id])`.
`:reflect` bypasses `RuntimeOpts.build_common_runtime_opts` (whose `Keyword.fetch!(:path)` would `KeyError`) and returns `{:ok, %{result: ..., commit_sha: nil, branch_name: nil, tag: nil}}`, leaving `commit_sha`/`branch_name`/`project_path` nil.
NO catch-all clause: an unknown type raises `FunctionClauseError` in the spawned task → `{ref, {:exit, ...}}` → `:failed`.
Every clause FIRST calls `register_task_process/1` (`Registry.register(EvoGit.TaskRegistry.ProcessRegistry, task_id, :task)`); the runtime call is the LAST expression — a plain SYNCHRONOUS call (no spawn, no try/rescue/catch) returning the runtime value verbatim — and the module has ZERO `Logger`/`IO` calls.
**The wrapper never writes statuses**; the TaskRegistry GenServer performs every write from `{ref, result}`, `:DOWN`, the `:finalizing` handler and `update_status` casts.

`TaskRegistry.start_task(task_type, opts)` mints an id via `generate_id/0`, then `handle_call({:start_task, ...})`: the guard refuses `:cancelled`/`:cancelling` ids with `{:error, :cancelled}` → `Task.Supervisor.async_nolink(EvoGit.TaskSupervisor, TaskExecutor, :execute_task, [task_type, opts, task_id, state.server_name])` → persists `%TaskInfo{status: :running, opts: RAW, started_at, logs: [], result: nil, lease_expires_at: now + 120s, model_id: opts[:model_id]}` (ref nulled; disk-full → warning, in-memory only) → `task_refs` entry → broadcast `:running` → `{:ok, task}`.
TaskRegistry creates NO on-disk state (`opts[:path]`/`opts[:foreign_repos]`); no `create_task` exists anywhere in evo_git/evo_dash.

All opts defaults live in the CALLERS: the DASHBOARD (`ProjectsLive.handle_event("task_submit", ...)`: `path` required, `mode` always, `:prompt`/`:objective`, conditional `build_system`/`node_path`/`starting_commit`/`foreign_repos`/`archive`/`model_id`/`resume_from`) and the CLI (`cli.ex` — thin clients of `start_task/2`: ABSOLUTE `:path`, STRING `:mode`, `:prompt`/`:objective`, put-if-present `:build_system`/`:node_path`/`:starting_commit`/`:agent`/`:archive`, always `:foreign_repos`, `-m` → `model_id` + `model_id_locked: true`); remaining defaults (`:prompt`/`:objective` → `""`, mode → `"simple"`) live in TaskExecutor/RuntimeOpts.
Remote path: `RemoteAPI.start_task/2` → `TaskRegistry.start_task/2` via `RemoteNode.start_task/2` / `NodeContext.start_task/3`; the shell's `StartTask.start_task` handler and the CLI call the local `TaskRegistry.start_task/2` directly.

`resolve_recheck_task/3` recovers a task whose wrapper died before replying: best-effort result via `Lease.lookup_sched_meta_result/1`, falling back to `:completed`; it shares the `{:ok, %{branch_name: _}}` extraction with `handle_update_status/6`.

## Per-Task Tmpdir Lifecycle

Each task owns ONE managed scratch directory shared by all its agents (`EvoGit.TaskTmpdir`, a PARENT-node file read-only from here; `[tmp] mode` (`:system`/`:custom`/`:per_repo`) and path resolution live there — `../../task_tmpdir.ex` + `../sandbox/CONTEXT.md`).
- **Create trigger (here)**: `TaskExecutor.execute_task/4` — the single entry point for all four types — calls private `ensure_task_tmpdir/2` right after installing the process-dictionary seam and BEFORE dispatch, so the dir exists before any tool can spawn.
  It calls `EvoGit.TaskTmpdir.ensure(task_id, Keyword.get(opts, :path))` (never `fetch!` — a nil/missing `:path` must not crash the wrapper), discards the path and returns `:ok`; `ensure/2` never raises from its mkdir step (logged, path still returned), but its PATH RESOLUTION is not exception-free: `System.tmp_dir!()` raises `RuntimeError` when no writable temp dir exists, aborting the wrapper BEFORE dispatch so the whole task fails.
- **Reclaim triggers (parent `task_registry.ex`)**: reclaim is **event-driven ONLY** — `EvoGit.TaskTmpdir.reclaim/2` removes `task_<id>` on a terminal status: the terminal reclaim in `handle_update_status/6` plus the direct terminal writes that bypass it (`force_kill_task/1`, `cancel_task/1`'s `:pending` arm, `:lease_sweep`, `resolve_recheck_task/3`). No boot reaper, no periodic sweep.
  `reclaim/2` never deletes outside the managed root nor the root itself; it is best-effort and never raises. The `handle_update_status/6` reclaim reads the FINAL (post force-map) status, so a graceful-cancelled task that completes still reclaims; `:cancelling`/`:finalizing` never reclaim.
- **Gotchas**: (a) `Cleanup.cleanup_expired_tasks/1` deletes ROWS, never directories — no age-based tmpdir GC; (b) a dir orphaned by a full-runtime CRASH (no terminal write) is NEVER reaped automatically in ANY mode — manual cleanup; (c) `[tmp] mode` is re-resolved at RECLAIM time (never stored per task), so changing it mid-flight can orphan the dir created under the old mode.

## OS Surface & Portability

- **OS-agnostic**: the only OS API is `System.system_time(:second)` (lease arithmetic) — no `System.cmd`, `Port.open`, `:os.*` or `File.*`/`Path.*` beyond `TaskExecutor`'s `TaskTmpdir` call, so no Windows-only crash can ORIGINATE here; the tmpdir BINARY later reaches the Windows sandbox's `Port.open`, whose env pairs MUST be charlists (OTP-29: binary tuples raise `ArgumentError: invalid option in list`) — convert at that call site (`../sandbox/CONTEXT.md` → "Port/OS-pid pitfalls").

## Failed-Task Error Persistence (`TaskInfo.error`)

Every transition to `:failed` records a structured payload in the dedicated `error` column (JSON TEXT), decoded onto `TaskInfo.error` (`map() | nil`), visible in the full-decode paths (`Store.get_task/1`, `list_tasks_paginated/1` via `Codec.decode_task/1`) AND the 16-key summary projection (lenient `Codec.decode_error/1`; nil for non-failed rows).
Shape is a fixed 4-key map with ATOM keys after decode: `%{kind: atom, source: atom, message: String.t(), stacktrace: [String.t()] | nil}`.
`kind` ∈ `:error | :exit | :down | :force_kill | :timeout | :restart | :lease_expired | :recheck`; `source` ∈ `:result_handler | :down_handler | :force_kill_task | :finalizing_watchdog | :startup_reconcile | :lease_sweep | :recheck_resolve`.
Sole producer: the pure `Diagnostics.failure_error(kind, source, message, stacktrace \\ nil)`; decode is lenient (nil / invalid JSON / non-object → nil), so a corrupt cell cannot break a row read.
Graceful-cancel `:cancelled` is NOT a failure — no error is recorded there.
`handle_update_status/6` appends `error:` ONLY when the FINAL persisted status is `:failed` (after the force-map rewriting stored `:cancelling` + terminal → `:cancelled`), so a force-mapped `:cancelled` row never carries one.

- **(a) wrapper result error/exit** (`handle_info({ref, result}, state)` case): `{:error, reason}` → kind `:error`, `"Task failed: #{inspect(reason)}"`; `{:exit, reason}` → kind `:exit`, `"Task exited: ..."`; unknown shape → kind `:error`; source always `:result_handler`; stacktrace = last 8 frames via private `stacktrace_lines/0` (the REGISTRY process's stack via `Diagnostics.capture_stacktrace/8` + `format_stacktrace_frame/1`, not the dead wrapper's). The error rides `update_task_status_with_caller(..., error: error)` → self-cast → `handle_update_status/6`.
  - `result` is PRESERVED as the RAW error tuple (never nil, never the human string), so `tasks.result` holds the Codec `{"__result_tag__": "error", "reason": <reason | inspect(reason)>}` JSON decoding back to `{:error, reason}`; `"Task failed: ..."` lives ONLY in `error.message` (`{:error, {:llm_request_rejected, "<actionable message>"}}` is persisted verbatim, per the runtime result spec).
  - `usage`/`agent_count`/`commit_sha` are nil here: `result_field(result, key, validator)` returns nil for anything not `{:ok, data} when is_map(data)`, and the matching `if usage, do: ...` guards OMIT those columns (earlier values untouched; nil for a fresh failed task) — never explicitly nil'd. `branch_name` is likewise nil; `finished_at` IS set and the lease cleared.
  - The wrapper returns the runtime value verbatim (no try/rescue) and exits `:normal`: the failure is persisted as a VALUE — no raise, no retry, no scheduler agent-crash retry.
- **(b) wrapper abnormal `:DOWN`** (persisted `:failed` only when `Lease.sched_meta_has_active_agents?/1` is false): kind `:down`, source `:down_handler`, message = the same `"Task process exited: #{inspect(reason)}"` string also written as `result`, stacktrace captured.
- **(c) stuck-`:finalizing` grace watchdog** (`resolve_finalizing_watchdog/3`): kind `:timeout`, source `:finalizing_watchdog`, message = the same `"Finalization did not complete within N minutes"` string written as `result`, stacktrace nil.
- **(d) force kill** (the direct `Store.update_task_columns` write): kind `:force_kill`, source `:force_kill_task`, `"Task force-killed by user"`, stacktrace nil — same update as the status flip; `result` stays nil, the error records why.
- **(e) startup reconciliation** (`init/1`, `:finalizing` → `:failed`): kind `:restart`, source `:startup_reconcile`, message `"Runtime restarted during task finalization"` (same as `result`), stacktrace nil.
- **(lease sweep)**: kind `:lease_expired`, source `:lease_sweep`, message `"Lease expired; owning instance no longer renewing"` (same as `result`), set on the full `%TaskInfo{error: ...}` before `Store.put_task`.

## Restart Recovery & Status Transitions

**Startup reconciliation.** `init/1` runs `EvoGit.Store.select_running_lease_info/1` (id + status + lease_expires_at, SQL `status IN ('running','finalizing','cancelling')`); each `:finalizing`/`:cancelling` row gets a SYNCHRONOUS `handle_update_status/6` with `{:startup_reconcile, ...}` caller info: `:finalizing` → `:failed` (`"Runtime restarted during task finalization"`), `:cancelling` → `:cancelled` (`"Runtime restarted during task cancellation"`).
The handler narrow-reads `select_task_update_info/1` (status/opts/finished_at/lease_expires_at — no full decode), applies the stale-guard, logs via `Diagnostics.log_failed_transition`, handles finished_at/lease, broadcasts `{:task_updated, task_id, status, node()}`, cleans `task_refs`.
Writes are SYNCHRONOUS in init (NOT the async cast, which would race callers).

- `state.task_refs` is in-memory only — empty after restart, so `{ref, result}` / `{:DOWN, ...}` never fire for pre-restart tasks.
- `:heartbeat` renews leases only for owned tasks with `status in [:running, :pending, :cancelling]` — never `:finalizing`.
- `:lease_sweep` (one-shot, 150 s after init = `(@lease_duration + 30) * 1000`) filters `status == :running and id not in owned_ids and not lease_valid?`; `:finalizing` is excluded by design (init handled it) and `:running` respects lease validity for the multi-VM case.
- `:periodic_cleanup` → `Cleanup.cleanup_expired_tasks/1` deletes only rows with `finished_at != nil`; `:finalizing` has `finished_at == nil` → never deleted.
- **Lease mechanics**: `@lease_duration` 120 s, `@heartbeat_interval` 60_000 ms; the lease is set at start, renewed by the heartbeat via `Store.update_lease_expires_at`, and the sweep marks expired `:running` foreign tasks `:failed` only when `sched_meta_has_active_agents?` is false, then runs cleanup + broadcasts.
- **Cleanup semantics**: never changes status — age cutoff + count trim (newest `max_tasks`) pushed into SQL; defaults `max_tasks: 100`, `max_age_days: 14`.

**Resolution paths for `:finalizing`:** (a) startup reconcile → `:failed`; (b) explicit — `clear_finished_tasks` uses `select_finished_task_ids` (SQL `status NOT IN ('running','pending','cancelling')`, which includes `:finalizing`) and DELETEs them, or `delete_task`; (c) in-process — wrapper completion (`{:ok,_}` → `:completed`, error/exit → `:failed`), wrapper crash (`:normal` → `:completed`; abnormal → `:failed` only if no active sched_meta agents), or the public `update_task_status/4` cast (stale-guard blocks terminal→terminal except →`:completed`); `cancel_task` from `:finalizing` → `{:error, :not_running}` (graceful works from `:pending`/`:running`); (d) the stuck-`:finalizing` watchdog.
**Lease expiry plays NO role here** — a stuck wrapper just stops getting renewals; the in-process watchdog bounds `:finalizing` while the BEAM is alive.

**Stuck-`:finalizing` grace watchdog.** On a SUCCESSFUL persist of `:finalizing` (`Store.put_task` `:ok` arm only — never the disk-full path) the local handler schedules a ONE-SHOT `Process.send_after(self(), {:recheck_task, task_id}, trunc(minutes * 60_000))` via `schedule_finalizing_watchdog/1` (always an integer; 0 fires immediately).
Grace minutes come from the app-env seam `:finalizing_watchdog_grace_minutes`, read at SCHEDULE time by `finalizing_watchdog_grace/0`: `false` → DISABLED; unset/nil → **60**; numeric ≥ 0 → that many minutes (floats tolerated); anything else → 60. `config/config.exs` sets 60 and `config/test.exs` 1.
At fire time the recheck handler's dedicated `%TaskInfo{status: :finalizing}` arm (between the terminal and generic clauses) calls `resolve_finalizing_watchdog/3` (re-reads the minutes for the message via `finalizing_watchdog_result_minutes/0`; `:disabled` at fire time falls back to the default) and resolves `:failed` + `"Finalization did not complete within N minutes"` through the shared `handle_update_status/6` with caller_info `{:finalizing_watchdog, task_id}`: Diagnostics log, `finished_at` set, lease cleared, broadcast only on a successful write, marker cleared, `task_refs` deleted.
It does NOT check `sched_meta_has_active_agents?`, does NOT reschedule, kills nothing and leaves residual sched_meta/agent state untouched; timers are per-boot and a restart mid-grace is covered by startup reconciliation.

**Pinned late-wrapper-result semantics**: after the watchdog resolves to `:failed` the wrapper is still alive (blocked, e.g. slow NFS git I/O); its `{ref, result}` / `{:DOWN, ...}` handlers are complete NO-OPS — `task_id_for_ref/2` returns nil because the terminal branch deleted the `task_refs` entry, so both skip their write bodies (the row keeps the watchdog result + finished_at, never clobbered) and `Process.demonitor(ref, [:flush])` clears the monitor plus any queued `:DOWN`; nothing re-adds the task to `task_refs` (test-pinned in `persistence_test.exs`).

**`resolve_recheck_task/3` and the 30 s live-agent reschedule remain effectively unreachable**: `Lease.lookup_sched_meta_result/1` is used only there, reached only from the recheck handler's generic arm for non-terminal, non-`:finalizing` rows — the watchdog schedules rechecks only for `:finalizing` rows and nothing schedules a first recheck for `:running` rows.

**Stuck-`:finalizing` cause**: `Runtime.Helpers.notify_finalizing/1` broadcasts from INSIDE the runtime phase, right after `AgentScheduler.run_agent` returns and BEFORE `merge_and_report/4`, so a blocked merge blocks the wrapper while the status stays `:finalizing`; `task_id` reaches the runtime via the base `task_id:` runtime-opt key.
While blocked, `{ref, result}`/`:DOWN` never fire, heartbeat/lease-sweep/periodic-cleanup skip `:finalizing`, `cancel_task` → `{:error, :not_running}`, and the force-kill gate is `[:running, :cancelling]`.

## Graceful Cancellation & Force Kill

**Task status `:cancelling`** is the graceful-cancel state, deliberately **NON-terminal**: the `task_refs` entry stays, `finished_at` stays nil, the lease stays valid (heartbeat renews it).
It is whitelisted in `Store.Codec.@known_atoms` and the `TaskInfo` typespec; `Store.select_finished_task_ids` (SQL `status NOT IN ('running','pending','cancelling')`) keeps `clear_finished_tasks` from deleting in-flight cancelling tasks while `:finalizing` still counts as finished; `Store.select_running_lease_info` includes it; startup reconciliation maps it to `:cancelled`; heartbeat renewal covers `[:running, :pending, :cancelling]`.

The **`{:task_updated, id, :finalizing, node}` handler** matches ONLY `:finalizing` (other statuses are persisted locally), with a node-filter guard `when node == node()` plus an explicit no-op clause for other nodes (a remote finalizing broadcast must never persist locally — task ids are per-node, cross-node collisions corrupt rows).
A `:cancelling` task ignores phase-finalization broadcasts; on a successful persist the handler schedules the one-shot watchdog.

`handle_update_status/6` force-maps the final result: stored `:cancelling` + incoming `:completed | :failed` → persisted `:cancelled`, with result/usage/archive flowing through untouched (never nil'd), so the agent's final summary is preserved.

**`TaskRegistry.cancel_task/1` is GRACEFUL**:

- `:pending` → immediate `:cancelled` write (finished_at set, lease cleared) + `{:task_updated, task_id, :cancelled, node()}` broadcast only on the successful write; `start_task` refuses already-`:cancelled`/`:cancelling` ids with `{:error, :cancelled}`.
- `:running` → `handle_update_status(..., :cancelling, ...)`, which broadcasts `{:task_updated, task_id, :cancelling, node()}` (the ONLY broadcast for this arm; non-terminal, so finished_at/lease/task_refs stay), then `AgentScheduler.begin_graceful_cancel(task_id)` (`:exit`-guarded — a down scheduler leaves the task `:cancelling` for force kill or restart reconciliation).
- `:cancelling` → `:ok` idempotent (does NOT re-send the cancel message).
- terminal (`:completed`/`:failed`/`:cancelled`) or `:finalizing` → `{:error, :not_running}`; missing → `{:error, :not_found}`.

**`TaskRegistry.force_kill_task/1`**: gate `:running | :cancelling` → `AgentScheduler.force_kill_task_agents(pid)` (reverse-depth `:brutal_kill` cascade, `:exit`-guarded) + `Task.shutdown(ref, :brutal_kill)` + a direct terminal write (`:failed`, finished_at set, lease nil, result nil — a force-killed task is never `:cancelled`) + `clear_cancelling_marker(task_id)`.

**Marker cleanup** — `clear_cancelling_marker/1` prefers `AgentScheduler.clear_cancelling_task/1` (serialized, cannot race `begin_graceful_cancel`) and falls back to `:ets.delete(:evogit_cancelling_tasks, task_id)` when the scheduler is down (TaskRegistry starts BEFORE AgentScheduler, e.g. during startup reconciliation). Called from every terminal transition (`handle_update_status/6`, the `:finalizing` handler, force kill).

## PubSub Broadcast Contract (topic `"tasks"`)

Default ordering is **persist-then-broadcast**: `handle_update_status/6` writes via `Store.update_task_columns` FIRST and broadcasts `{:task_updated, task_id, status, node()}` only in the `:ok` arm, gated on `status != task_status` — a missing row, stale-guard skip or disk-full write never broadcasts, so a listener that re-fetches sees the NEW row.
The trailing `node()` is the emitting node; subscribers ignore other nodes for node-local state.

| Broadcast | Site | Ordering |
|---|---|---|
| `{:task_updated, id, :running, node()}` | `start_task` | put_task → broadcast |
| `{:task_updated, id, :cancelling, node()}` | `cancel_task/1` `:running` arm | persist → broadcast |
| `{:task_updated, id, :cancelled, node()}` | `cancel_task/1` `:pending` arm | write → broadcast |
| `{:task_updated, id, :failed, node()}` | `force_kill_task/1`; `:lease_sweep`; recheck resolution; watchdog/startup reconcile | write → broadcast (force-kill fires unconditionally) |
| `{:task_updated, id, nil, node()}` | `set_review_status` / `set_review_metadata` casts | after the write (no status change) |
| `{:task_deleted, id, node()}` | `clear_finished_tasks` (one per id), `delete_task` | only on the successful write |

- **Terminal sequences end-to-end**: completed = wrapper sends `{ref, result}` → handler maps to `:completed`/`:failed`/`:exit` → cast `update_task_status_with_caller` → `handle_update_status/6` force-maps `:cancelling`+terminal → `:cancelled` (result preserved) → persist, then broadcast. Abnormal wrapper death = `{:DOWN, ...}`: `:normal` → `update_task_status(:completed)`; other reasons → `:failed` ONLY when `Lease.sched_meta_has_active_agents?` is false, else the row stays `:running` with no broadcast.
- **The ONLY broadcast preceding its persist is `:finalizing`**: `Runtime.Helpers.notify_finalizing/1` fires it from INSIDE the wrapper and the local handler persists afterward; a disk-full `put_task` leaves subscribers told `:finalizing` while the row stays `:running` (self-heals at the terminal broadcast). Reflect tasks never emit `:finalizing` (`:running → :completed/:failed/:cancelled`).
- **`Cleanup.cleanup_expired_tasks/1` deletes rows with NO broadcast.**

## Task Lifecycle & Terminal-Write Sites

- **Start / Run**: `start_task/2` spawns the wrapper (above); the wrapper runs the WHOLE lifecycle synchronously (incl. `Runtime.Helpers.merge_and_report/4`) and never writes statuses — `notify_finalizing/1` broadcasts `:finalizing` from inside it before `merge_and_report`, and the local handler persists it.
- **DOMINANT terminal choke point = `handle_update_status/6`**: its terminal branch runs the in-memory teardown — `clear_cancelling_marker/1` + `TaskTmpdir.reclaim/2` + `task_refs` deletion. Reached from the wrapper result handler, the `:DOWN` handler, startup reconciliation and the watchdog.
- **Terminal transitions that BYPASS it (direct `Store` writes)**: `force_kill_task/1` (`:failed` + reclaim + broadcast), `cancel_task/1`'s `:pending` arm (`:cancelled` + reclaim + broadcast), `resolve_recheck_task/3` (reclaim), `:lease_sweep` (`put_task`, reclaim, `:failed`). Hence NO single teardown choke point and no shared `terminal_cleanup/3` helper: a task-end teardown needs a hook at ALL FIVE sites.
- **Per-task on-disk artifact**: the managed tmpdir above. `Cleanup.cleanup_expired_tasks/1` only DELETEs finished task ROWS (called from `clear_finished_tasks`, `:lease_sweep`, `:periodic_cleanup`); archive rows live in their own per-agent table ("Store Access…").
- **Boot-time reconciliation**: `init/1` enumerates orphaned `:running`/`:finalizing`/`:cancelling` rows via `Store.select_running_lease_info/1`; worktree/scheduler artifacts are per-AGENT and monitor-reclaimed, never task-scoped (`../agent_scheduler/CONTEXT.md`), and runtime phases write nothing outside the repo (`../runtime/CONTEXT.md`).

## Merge-Conflict-Resolution Flow (MergeContext / TaskExecutor)

- **Only trigger point**: `TaskExecutor.execute_task(:evolve, opts, task_id)` runs a merge-context step BEFORE `resume_from` handling: a non-empty trimmed `opts[:merge_from]` triggers `MergeContext.apply_merge_context(opts, task_id, trimmed_merge_from, opts[:merge_target])`, whose result replaces `opts`; the rest of the flow runs on the transformed opts (merge keys stripped, `resume_from` not passed).
- **`apply_merge_context/4`** strips `:merge_from`/`:merge_target` FIRST (never leak into runtime opts) → `prev_task = EvoGit.TaskRegistry.get_task(merge_from)` (full `%TaskInfo{}` decode). **nil** → stripped opts unchanged. **Found** → `:starting_commit` overridden with `prev_task.commit_sha` when a non-empty binary (caller's value preserved otherwise) → `:foreign_repos` carried from `prev_task.opts` when present/non-nil, each entry normalized via `EvoGit.Core.ForeignRepo.normalize/1` with unparseable entries dropped (STRING-keyed after the Codec round trip; raw carry-over crashes downstream dot-access) → each carried repo's `base_sha` overridden from the prev result's `repos[repo_id]["commit_sha"]` via `PrevTaskRepos.apply_starting_commits/2` (defensive string-key reads; repos absent from the prev `repos` keep their base_sha; legacy tasks without `repos` are a no-op) → `:objective` = `build_merge_context_block(prev_task, merge_target, carried_repos) <> "\n\n" <> old_objective`. Pure keyword-in/out (no `RuntimeOpts` call; returns opts, NOT a `{objective, runtime_opts}` tuple).
- **`build_merge_context_block/2,3`** returns a "Merge Conflict Resolution Context" string fenced by `--- Merge Conflict Resolution Context ---` / `--- End Merge Conflict Resolution Context ---`: `Previous task id:`; `Base sha:` / `End (commit) sha:` (each omitted when nil/empty — the block is still emitted); `Task branch name: <branch_name || "unknown">`; `Merge target branch: <merge_target || "unknown">`; a `Goal:` paragraph (merge the target into the worktree via `git merge <target>`, resolve ALL conflicts by combining both sides, commit, keep developing until coherent); a `Writable foreign repos: <id>@<base_sha|HEAD>, ...` line (ONLY when ≥1 writable repo — the 3-arity takes explicit repos so the block shows the ACTUAL starting commits, the 2-arity derives them from `prev_task.opts[:foreign_repos]`); a `Hints:` section. Non-struct input → `""`.
- **Hints (8 bullets)**: commit conflict resolutions before delegating follow-up work (subagents spawn at clean checkouts, so uncommitted changes are invisible); inspect `git log/diff <base>..<end_sha>` and `git log/diff <base>..<target>` (ranges interpolated when the shas exist, placeholders otherwise); incremental milestone merges OR rough-resolve-then-develop-on-top as fallbacks; plus the five CONTEXT.md ownership bullets.
- **CONTEXT.md conflict policy (five ownership bullets)**: keep the version of the side whose node path OWNS the file (the node directory whose subtree contains it — the agent rooted at `./src` owns `./src/CONTEXT.md`, the root agent at `./` is everybody's ancestor); a genuine same-node conflict (e.g. two agents rooted at `./src`) is merged deliberately from BOTH sides, keeping both routing-table entries and both sets of documented facts, reconciling wording only where it is the same fact; prefer `edit_context` with small surgical edits over whole-file rewrites; never drop another node's routing-table entries merely because they conflict textually (a child's entry must survive, and entries for different children both belong in the merged table); never resolve by discarding one side's content — if ownership is genuinely ambiguous, keep both sides and note the ambiguity.
  Covered by `test/evo_git/task_registry/merge_context_block_test.exs` (hints present, appended before the closing delimiter, kept on both arity paths).

## Resume-From Flow (ResumeContext / TaskExecutor / RuntimeOpts)

- **Only trigger point**: `TaskExecutor.execute_task(:evolve, opts, task_id)` calls `ResumeContext.apply_resume_context/3` when `opts[:resume_from]` is a non-empty binary after `String.trim/1`; non-resume evolve tasks build `{objective, runtime_opts}` directly (`objective = Keyword.get(opts, :objective, "")`).
- **`apply_resume_context/3`** strips `:resume_from` (never leaks into runtime opts) → `prev_task = get_task(resume_from_id)` (FULL 18-column decode — known inefficiency, low priority). Caller-supplied `:foreign_repos` are normalized to `%ForeignRepo{}` structs (string-keyed Codec maps allowed; unparseable dropped) and each repo's `base_sha` is overridden from the prev result's `repos[repo_id]["commit_sha"]` via `PrevTaskRepos.apply_starting_commits/2` (string-keyed, defensive; absent repos keep their base_sha; legacy tasks without `repos` are a no-op); the `:foreign_repos` key is (re)added only when the normalized list is non-empty.
  **nil prev** → original objective, `build_common_runtime_opts` with the caller's own (normalized) repos. **Found** → `context_block = build_resume_context_block/1`; the objective becomes `context_block <> "\n\n" <> objective` only when the block is non-empty; `:starting_commit` is overridden with `prev_task.commit_sha` when a non-empty binary (a caller-provided value is silently dropped), else the caller's passes through; then `build_common_runtime_opts(opts_with_commit, task_id, :evolve)`.
  **Foreign repos are NOT inherited from `prev_task.opts` on resume** — only caller-supplied ones flow through; `MergeContext` is the ONLY cross-task inheritance path.
- **Context block exact format**: `"--- Previous Task Context ---\n" <> Enum.join(parts, "\n\n") <> "\n--- End Previous Task Context ---"`, empty string when `parts == []`; parts join with blank lines.
  Part 1: `"Previous task commits: #{base_sha}..#{commit_sha}"` (both non-empty; just `commit_sha` when base_sha is empty/nil; omitted when commit_sha is empty). Part 2 (only when ≥1 writable foreign repo in `prev_task.opts[:foreign_repos]`, normalized first, not delimited): `"Writable foreign repos: <id>@<base_sha|HEAD>, ..."`.
  Part 3 (delimited): `"Previous task objective:\n<<<BEGIN OBJECTIVE>>>\n#{old_objective}\n<<<END OBJECTIVE>>>"` (from `prev_task.opts` `:objective` || `:prompt`, only when non-empty). Part 4 (delimited): `"Previous task result:\n<<<BEGIN RESULT>>>\n#{summary}\n<<<END RESULT>>>"` (omitted when `extract_result_summary/1` returns nil or `""`).
  The `<<<BEGIN ...>>>`/`<<<END ...>>>` markers wrap arbitrary multi-line content so the agent cannot confuse a label with its content or content with the outer fence; the all-caps triple-angle form cannot plausibly collide with agent-generated text.
- **`extract_result_summary/1`**: `{:ok, %{result: s}}` binary → passthrough, atom → `to_string/1`; `{:error, reason}` → `"Error: #{inspect(reason)}"`; `{:exit, reason}` → `"Exited: #{inspect(reason)}"`; anything else → nil.
- **SHA provenance**: `prev_task.commit_sha` is populated at completion by the `{ref, result}` handler extracting `{:ok, %{commit_sha: sha}}` (the runtime merge result carries `commit_sha: final_sha || base_sha`). `prev_task.base_sha` is set ONLY by the review flow (`set_review_metadata/3` cast), so a never-reviewed task's commits line is just the commit_sha.

## Known Issues

- **A persisted status string outside `Store.Codec`'s `@known_atoms` whitelist silently stops lease renewal.** `decode_atom/1` yields `nil` for an unknown value (logging one warning per row per read), so `Store.get_task_status/2` returns `nil`, the 60 s heartbeat's `status in [:running, :pending, :cancelling]` guard skips that task, its lease lapses and the `:lease_sweep` can fail a LIVE task; the full-decode path masks the same miss as `status: :pending` (`Codec.decode_task/1`), so the dashboard renders it as a live pending row. Adding a task status/type/review status without updating that whitelist turns this on.
- **A restart is effectively FATAL for a `:running` task — there is NO resume path.** `init/1` reconciles only `:finalizing` → `:failed` / `:cancelling` → `:cancelled`; `:running` rows fall to the one-shot `:lease_sweep` **150 s after EVERY boot**, which fails every `:running` row that is (a) not in THIS instance's `task_refs`, (b) lease-lapsed, and (c) agent-free per THIS instance's `sched_meta_has_active_agents?/1`. "Owning instance" exists ONLY as `task_refs` — no persisted instance/node/boot id column — so ANY fresh BEAM sharing the DB owns nothing. The sweep writes `:failed` + `"Lease expired; owning instance no longer renewing"` + `error.kind :lease_expired`, lease nil, finished_at set, but NOT `branch_name`/`commit_sha` → NOT reviewable.
- **`sched_meta_has_active_agents?/1` reads a BEAM-LOCAL ETS table** (`:evogit_sched_meta`, `:named_table`/`:public` but NOT distributed), so it never sees another instance's live agents: if A's lease lapses (dead BEAM, restarted registry with empty `task_refs`, stalled heartbeat), B's boot sweep fails A's STILL-RUNNING task while its agent worktrees are alive — a later primary-repo spawn in a fresh BEAM then re-runs the WorktreeManager full wipe (`:evogit_worktree_repos` is app-owned → rm_rf `.genesis/workers` + delete all `evogit-agent-*` branches), destroying in-flight work.
- **The `:finalizing` handler's ignore-list deliberately omits `:failed`**: `if task.status in [:completed, :cancelled, :cancelling]` — recovering a persisted-`:failed` row to `:finalizing` on a stale broadcast is intended (pinned by `persistence_test.exs` "recovery before completion"; the list must NOT gain `:failed`). The in-code "tasks already terminal" wording covers exactly those three; this only fires on a stale in-flight broadcast (a cross-node one is dropped by the node guard).
- **`force_kill_task/1` broadcasts `{:task_updated, task_id, :failed, node()}` UNCONDITIONALLY** — also on `{:error, :not_running}` / `{:error, :not_found}` / `{:error, :disk_full}` with no persisted change. Local subscribers only act on `:finalizing`, but the dashboard sees a spurious `:failed` for an unchanged row.
- **Disk-full at a terminal write can leave a row `:finalizing` with NO in-process retry.** `handle_update_status/6`'s `{:error, :disk_full}` arm only logs; the in-memory cleanup still runs, but the row keeps its OLD status and no broadcast fires. Nothing retries: the watchdog is ONE-SHOT, heartbeat renews only `[:running, :pending, :cancelling]`, `:lease_sweep` filters `status == :running`, `:periodic_cleanup` needs `finished_at != nil`, and a late `{ref, result}` after `task_refs` deletion only logs `"received task result for unknown ref ... result dropped"`. Wedge: the watchdog's own `:failed` write also hits disk-full (timer consumed) → the row stays `:finalizing` until an explicit `clear_finished_tasks`/`delete_task` or a registry restart whose init reconcile maps it to `:failed`.
- **⚠️ Memory scales with `tasks.sqlite` size — via the summary-query path, NOT init.** `init/1` and retained state (`task_refs` = running tasks only) are clean; the O(N) path decodes every matching row's `opts` JSON in `Store.select_tasks_summary*` / `select_tasks_changed_since` (`result` is NOT in the 16-column projection, so `Codec.decode_result` never runs), offloads both handler sides to `Task.start` + `GenServer.reply` (no large terms retained; the linked Task preserves crash-on-decode-raise), and has the dashboard re-fetch statuses-filtered sidebar summaries on every broadcast (300 ms debounce) while each ProjectsLive session keeps the 16-key maps (`opts` kept, `result` dropped) in assigns for its lifetime. Retained memory ≈ O(rows × opts-blob size) (`periodic_cleanup` caps finished rows at `max_tasks: 100`); nothing loads the DB at boot.
- **Derived foreign-repo `base_sha` is a FROZEN snapshot never re-validated against git.** `PrevTaskRepos.apply_starting_commits/2` reads `prev_task.result`'s `repos[repo_id]["commit_sha"]`, persisted ONCE at the previous task's terminal write and never rewritten. Nothing re-reads the foreign branch tip or checks ancestry, so a follow-up (resume / merge-auto-resolve) from an OLDER task starts that repo at the older commit when a LATER task advanced it (the sha is merely an ancestor; only existence is validated, via `Runtime.Helpers.validate_foreign_repo_base_sha!`, and an unresolvable sha raises a descriptive `ArgumentError` at task start). Recording is skipped when the foreign-repo subagent's result is not `{:ok, %Result{}}` AND for any child that is not itself a writable `:read_write` agent running there (`Subagents.store_sub_result/3,4`).
- **Resume block vs runtime mismatch**: the `Writable foreign repos:` line comes from the PREVIOUS task's own `opts[:foreign_repos]`, NOT from the overridden per-repo starting commits threaded into runtime opts — the two can disagree. `MergeContext` avoids this via its 3-arity builder.

## Store Access, SQL Lowering & Fault Isolation

- **Store containment**: EVERY synchronous Store call routes through `StoreGuard.read/3` / `write/2`, so a dead/restarting store (an exit) or an unexpected raise degrades to the operation's own empty value (reads) or `{:error, :store_unavailable}` (writes) instead of killing the registry — the GenServer every dashboard LiveView subscribes to.
- **Disk-full consequence**: all TaskRegistry/Cleanup write call sites degrade gracefully (`{:error, :disk_full}` from `force_kill_task`/`cancel_task`/`clear_finished_tasks`; log-and-continue for casts/heartbeat/log loss), and `{:error, :store_unavailable}` takes the SAME branch; the in-memory terminal cleanup always runs.
- **Store callers in `apps/evo_git/lib`**: only `task_registry.ex` and `task_registry/cleanup.ex` (the `agent_scheduler/*` `Store.` references are `EvoGit.AgentScheduler.Store`, a DIFFERENT ETS module); none in `lease.ex` (ETS-only; `sched_meta_has_active_agents?/1` scans via `:ets.tab2list`), `diagnostics.ex`, `runtime_opts.ex`, `task_executor.ex` (Store only transitively via ResumeContext), `store_guard.ex`.
- **Lightweight reads**: `list_tasks_page/1` → `Store.select_tasks_page/2` (16-key rows + `total`, no blobs; degrades to `%{rows: [], total: 0}`) and `get_task_lite/1` → `Store.get_task_lite/2` (blob-free; degrades to `nil`).
- **Per-agent archive mirrors**: `put_task_archive/1` → `Store.put_task_archive/2` (STREAMING write, `:ok` | `{:error, _}`); the client never raises or exits into the writing agent — it logs and returns `{:error, _}`, so completion never fails on a dead registry/store. `list_task_archives/2` → `Store.list_task_archives/3` roster page returning `%{entries: [], total: 0}` on a read fault; entries are STRING-KEYED, ordered `depth ASC, agent_id ASC` (root first), `opts` = `:limit` (default 100, clamp 1..1000), `:offset` (default 0), `:include_results` (default `false` → the `"result"` key is ABSENT), and `total` is the task's whole row count. `get_agent_archive/2` → `Store.get_agent_archive/3` is the lazy per-agent detail (includes `"result"`), degrading to `nil`. There is no single task-wide archive reader.
  The producer write runs INLINE in the registry GenServer (`handle_call({:put_task_archive, …})` → `safe_store_write/2` → `Store.Writer`, reply-after-commit), so a completing agent holds the registry — and every dashboard read queued behind it — for the duration of its own SQLite insert; the row is independent, so it needs no ordering relative to other writes.
  The archive never rides a task write: each completing agent writes its OWN `task_agent_archives` row, so a result write persists exactly what the result holds; nothing archive-related rides `%Result{}` or the report. Being a side table with no foreign key, deletes cascade EXPLICITLY: `Store.delete_task_archives/2` → `Operations.Archives.delete_by_task/2`, `Operations.Archives.delete_by_tasks/2` (chunked) inside `Store.delete_tasks/2`, `Operations.Archives.delete_all/1` on a full clear; task-level archive metadata is not stored on the task row.
- **Narrow reads over full decode**: `append_log`, `set_review_status`, `set_review_metadata`, `handle_update_status`/`update_task_status_with_caller`, `cancel_task` and `resolve_recheck_task` use `select_task_logs/2` + `select_task_update_info/2` + `update_task_columns/3`; `ResumeContext`/`MergeContext` still decode the FULL row via `TaskRegistry.get_task/1` (rare single-row paths that need `result`).
- **Registry read offload**: every large-decode read (`list_tasks`, `list_tasks_paginated`, `list_tasks_page`, `get_task_lite`, `list_task_archives`, `list_tasks_summary`, `list_tasks_summary_by_path`, `list_tasks_changed_since`) runs inside `offload/3` (short-lived `Task.start` replying via `GenServer.reply/2`), so decoded terms never ratchet up the registry heap; `get_unique_paths` and `list_task_ids` reply INLINE (tiny projections). All are wrapped in `StoreGuard.read/3`.
  `offload/3` is a bare `Task.start/1` — unlinked, unmonitored and with NO deadline of its own (only the store's 25 s read deadline bounds a wedged read), and `{:ok, _task_pid} = Task.start(…)` raises a MatchError inside the registry if the spawn itself fails (process/`:system_limit` exhaustion); `get_task/1` is the one large-decode read that still replies INLINE.
- **Cleanup SQL**: `cleanup_expired_tasks/1` reads only ids — age cutoff (`AND finished_at < ?cutoff`) and over-limit keys (`ORDER BY finished_at DESC LIMIT -1 OFFSET ?max_tasks`) pushed into SQL — then deletes via `delete_tasks/2` (chunked, all-or-nothing per chunk); both legs use the covering `idx_tasks_finished_at_id` index, with no row decode / Elixir-side sort or filter.
- **`select_running_lease_info`** SQL-filters `status IN ('running','finalizing','cancelling')`; callers still filter Elixir-side, as do `id not in owned_ids` and lease-expiry-vs-wall-clock (ISO-8601 fixed-precision ordering caveat: `../store/CONTEXT.md`).
- **Elixir-side sorting**: `trim_recent_projects` + `sort_projects_by_recency` fully decode all projects (`safe_select_all_projects`) and sort in Elixir (an SQL `ORDER BY last_opened_at DESC` + `LIMIT` would hit the same caveat).
- **Store-owned internals** (migrations, summary/`changed_since` APIs, JSON storage model, `mix store.maintenance`, disk-full classifier): `../store/CONTEXT.md`.
