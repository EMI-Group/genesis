# TaskRegistry Support Modules

## Intent

Support modules behind the `EvoGit.TaskRegistry` GenServer, which owns the task-lifecycle state machine (transitions, lease/heartbeat, cancel/force kill, pause/resume, startup reconciliation, review status).
Every module here is pure-function, ETS-only or a bounded offloaded read task — none owns GenServer state.

## Routing Table

None — leaf directory (all modules at this level).

## Process-Scoped Isolation Seam

`EvoGit.TaskRegistry.server/0` resolves the registry name for the CURRENT process AT CALL TIME (`:evogit_task_registry_server` pdict, else `__MODULE__`); every client function routes through it EXCEPT `put_task_archive/1`, which uses it only to look up that instance's store.
An isolated pair is `EvoGit.Store.start_link(name: <store>, data_dir: <tmp>)` + `EvoGit.TaskRegistry.start_link(name: <unique_atom>, task_store: <store>, data_dir: <tmp>)`; the app-global singletons are never started or stopped, a Store client always takes an explicit `store`, and several instances need an explicit `id:`/`:name`.
An `:agent_state_server` pid option (pid only) is put under `:evogit_agent_state_server` by `init/1`, so an isolated registry reads, flushes and cascades against its OWN `EvoGit.AgentState`; the registry holds NO mount state and never touches the VCT, so `task_store` alone isolates it.
`init/1` passes the registered name as the 4th wrapper-spawn argument (so `execute_task/4` re-installs the pdict key and in-wrapper `MergeContext`/`ResumeContext` `get_task/1` calls hit the SAME instance) and publishes `registered name => task_store` into the APP-OWNED ETS table `:evogit_task_registry_stores` (created in `EvoGit.Application.start/2`, surviving registry restarts) — how `put_task_archive/1` resolves a store without touching the mailbox (an unpublished name falls back to `EvoGit.Store`).
Processes NOT descending from the wrapper (self-reflective `agent/tools/*`, `agent_scheduler/remote_api.ex`, evo_dash callers) never inherit the key, so their suites stay serialized against the global singleton.

## Constraints

- **Task-type whitelist**: `start_task/2` is TYPE-AGNOSTIC; `do_execute_task/3` has one clause per type (`:genesis`, `:evolve`, `:extract_skills`, `:reflect`) and NO catch-all (unknown → `FunctionClauseError` in the spawned task → `:failed`); the persisted `type` round-trips `Store.Codec.@known_atoms` (`decode_atom` → `nil` otherwise), so a NEW task type MUST be added there (`TaskInfo.type` is `atom() | nil`).
- **Purity**: no GenServer state; I/O only in `Cleanup` (Store deletion), `ReadOffload`/`AgentStateRead` (supervised read workers) and `TaskExecutor` (`TaskTmpdir.ensure/2`, run OUTSIDE the GenServer under `Task.Supervisor`); `RuntimeOpts`/`ResumeContext`/`MergeContext`/`PrevTaskRepos` are pure builders and `Pause` only validates + persists.
- **NO synchronous durable-state call in the registry process**: the agent-state cascade is a cast, and every registry-side durable READ (ROOT-run roster, `pause_commit`, the `max_agent_id` boot seed) goes through `AgentStateRead`'s bounded offload.
- **Reaping is SQLite-row-only** — init reconciliation, `:lease_sweep`, `cleanup_expired_tasks/1`, `:periodic_cleanup`, `clear_finished_tasks` and `delete_task` touch only `tasks.sqlite` rows (plus cascaded `agent_state.sqlite` rows), the in-memory `task_refs` entry and the `:evogit_cancelling_tasks` marker; worktree reclamation belongs to `AgentScheduler.WorktreeManager` (`:DOWN`-driven).
- **Task delete cascades to durable agent state as a TOTAL CAST**: one `AgentState.delete_task/2` after a successful row delete, one batched `delete_tasks/2` for `clear_finished_tasks/0`, so a stopped/locked/dead `agent_state.sqlite` can neither fail nor delay a delete (retention pruning is the backstop); `cleanup_expired_tasks/1`'s age/count deletions carry NO cascade.
- **`task_registry.ex` stays long by design** — it IS the task-lifecycle state machine.

## Task Status Sets & `:awaiting_input`

`:awaiting_input` is NON-TERMINAL: an interactive session yielded on a tool-free reply and waits for its next message.
Its wrapper (`%Task{}` in `task_refs`) is alive, so the row is LIVE (lease renewed, never swept as leaked, never deleted by `clear_finished_tasks`) but IDLE — no LLM slot, tool slot or worker — so it must not count toward an update/idle gate (that "busy" set belongs to the dashboard / `/server/status`).
Sessions are in-memory only, so boot reconciliation resolves an orphaned `:awaiting_input` row to `:failed` ("Runtime restarted during interactive session", `error.kind :restart`, `source :startup_reconcile`) — never resumed.
`:running` ↔ `:awaiting_input` is an ordinary legal non-terminal pair (a plain `update_task_status/4` write; `finished_at` and the lease untouched).
`:awaiting_input → :cancelled` is IMMEDIATE (never via `:cancelling`): a targeted write sets `:cancelled` + `finished_at` + a cleared lease with NO `result` column (transcript preserved), clears the cancelling marker, reclaims the tmpdir, broadcasts on success, and stops the session best-effort through the TASK-addressed `AgentScheduler.force_kill_task_agents_for_task/1` (an interactive session need not have a depth-0 SchedMeta `from` pid).
`:awaiting_input` is force-killable exactly like `:running` (`:failed`, lease nil, result nil'd, the canonical `:force_kill` error payload).
`EvoGit.TaskRegistry.update_status/2` is the status-only cast the session lifecycle calls (through `update_task_status/4`, so the stale-terminal guard and `:cancelling` force-map apply); it carries no result, is for non-terminal flips only, and a repeat of the current status writes and broadcasts nothing.
Status enumerations live ONE place each with a `@doc false` accessor so a table-driven test asserts totality (`:awaiting_input` wherever `:running` appears, `:pausing` wherever `:running` appears, `:paused` wherever `:awaiting_input` appears):

| Owner | Accessor | Content | Meaning |
|---|---|---|---|
| `lease.ex` | `renewed_statuses/0` | `[:running, :pending, :cancelling, :awaiting_input, :pausing]` | heartbeat-renewed (`:paused` deliberately absent: no wrapper, no lease) |
| `lease.ex` | `leaked_statuses/0` | `[:running, :awaiting_input, :pausing]` | the one-shot sweep may fail these; `:paused` is a legitimate resting row |
| `task_registry.ex` | `terminal_statuses/0` | `[:completed, :failed, :cancelled]` | no further transition except terminal → `:completed`; `:pausing`/`:paused` are NON-terminal |
| `task_registry.ex` | `killable_statuses/0` | `[:running, :awaiting_input, :cancelling, :pausing, :paused]` | `force_kill_task/1` accepts these |
| `task_registry.ex` | `gracefully_cancellable_statuses/0` | `[:running, :awaiting_input, :pausing, :paused]` | `cancel_task/1` accepts these (`:running` → `:cancelling` grace; `:awaiting_input`/`:paused` → immediate `:cancelled`; `:pausing` abandons the pause first) |
| `task_registry.ex` | `unstartable_statuses/0` | `[:cancelled, :cancelling, :awaiting_input, :pausing, :paused]` | `start_task/2` refuses these ids (a paused row owns its id for `resume_task/1`) |
| `task_registry.ex` | `finalizing_ignored_statuses/0` | `[:completed, :cancelled, :cancelling, :pausing, :paused]` | a `:finalizing` broadcast is ignored (`:awaiting_input` and `:failed` deliberately ABSENT — see Known Issues) |
| `task_registry.ex` | `active_statuses/0` | `[:running, :pending, :finalizing, :cancelling, :awaiting_input, :pausing, :paused]` | "a live task whose wrapper exists" — the in-flight set, NOT the busy set |

The store-side halves (not owned here): `Store.Codec.@known_statuses`, `Store.Types.Status`, `TaskInfo.status`, `Store.Operations.Lightweight`'s `@live_statuses` (else `clear_finished_tasks` deletes a waiting session) and `@lease_statuses` (else init reconciliation and the sweep never see it).

## RuntimeOpts Key Contract

`build_common_runtime_opts(opts, task_id, task_type)` returns `{nil, runtime_opts}` BY CONTRACT: element 0 is a reserved placeholder no caller may consume and the pair must NOT be unwrapped (~20 tests pattern-match it).
`:path` is REQUIRED (`Keyword.fetch!` → `KeyError`; never `:repo_path`), persisted as `tasks.project_path` and used as the `:per_repo` tmpdir base; `:node_path` is a repo-RELATIVE context-tree directory (`Runtime.Helpers.validate_node_path/2` rejects absolute paths and needs an existing dir with CONTEXT.md), while a dashboard cluster node is a SEPARATE ARGUMENT of `EvoDash.NodeContext.start_task/3`.
`:mode` is a STRING (`"new"`/`"existing"` genesis, `"simple"`/`"custom"` evolve) via `mode_atom/2`; an ATOM raises `ArgumentError`, a MISSING mode defaults to `"simple"` (which raises for genesis), and genesis `"custom"` raises (evolve-only).
Always emitted are `repo_path`, `mode` (atom) and `task_id` (the parameter, not an opts key); `put_if/4` filters only nil/false so empty strings/lists pass for `node_path`, `starting_commit`, `foreign_repos`, `archive` and `build_system` while `agent` needs a non-empty binary, and every other input key is silently DROPPED.
`admit_model_selection(opts, config)` runs BEFORE enqueue and is rechecked by `execute_task/4` before tmpdir/dispatch (a resolver error returns unchanged): a PRESENT `:model_spec` wins over legacy `:model_id` even when invalid, Auto (no spec and a nil/empty legacy id) omits both selection keys AND `:model_id_locked`, and an explicit selection is checked by `Config.Schema.resolve_model_spec/2`.
An explicit `model_spec` forces `model_id_locked: true` and drops a competing legacy id, while a legacy `:model_id` alone never introduces a lock and only preserves a supplied truthy lock (nil/false omitted), keeping legacy model-selection scripts enabled.
`model_spec` is the STRING-keyed `provider_profile_id` / `model` / optional `reasoning_effort` map and a non-map is `{:error, :invalid_model_spec}` (never read as a legacy id); `canonical_model_spec/1` materializes only the schema's resolved top-level fields, because the schema's resolved `model_spec` is a ReqLLM identifier and no profile, generation parameter or credential is copied into task opts.
`admit_task_path/1` admits absent/`nil` (repo-less `:reflect`) and any ordinary binary without an absoluteness check, refuses `vct:///workspaces/…` (`:workspace_not_executable`) and any other `vct:` point (`:vct_point_not_executable`), and answers `:invalid_path` for a present non-binary; the builder also raises a descriptive `ArgumentError` for a `vct:` path and otherwise copies the path verbatim (no expansion, absoluteness or repo-root validation).
`attachments` is validated UNCONDITIONALLY via `EvoGit.Attachments.validate/1` (nil/`[]` → `:ok`; malformed → `ArgumentError` at task start) and put only when non-nil and non-`[]`, as STRING-keyed base64 maps.
`:session_mode` is OPTIONAL (`"oneshot"` default, the key then omitted so one-shot paths stay byte-identical); the value is a STRING (an atom raises in the builder) and `admit_session_mode/1` is the non-raising gate (`{:error, :invalid_session_mode}`).
`:persistent_state` is an OPTIONAL BOOLEAN defaulting to `true` (whole task, root plus descendants) and ALWAYS present as an explicit boolean, so no consumer applies its own default; `persistent_state/1` raises on a non-boolean while `admit_persistent_state/1` is the non-raising gate (absent/`nil` pass, booleans re-put, else `{:error, :invalid_persistent_state}`); the repo-less `:reflect` path never builds these opts, and both keys persist with the raw task opts.
`:quality_level` is normalized via `EvoGit.QualityLevel.normalize/1` (nil/`""` → `"balanced"` silently; anything else → warning + `"balanced"`) and appended ONLY when ≠ `"balanced"`.
`:objective` defaults to `""` ONLY when absent (an explicit nil is not defaulted), and `:starting_commit` has NO default (absent → the runtime resolves HEAD via `PhyloGraphNode.current_head/1`; present → it must `git rev-parse` cleanly or evolution fails).
Repo validation happens DOWNSTREAM: the runtimes default `:repo_path` to `File.cwd!()`, apply `EvoGit.Platform.safe_expand/1` (UNC-preserving), then `EvoGit.Runtime.ensure_repo/1` + `Runtime.Helpers.validate_repo_path!/1` reject non-repos (and UNC roots) at task start.
`:foreign_repos` (list of `%ForeignRepo{id, root, description, writable, base_sha}`) is threaded VERBATIM and unvalidated here (a non-list passes too); normalization/validation live in `Runtime.Helpers.load_foreign_repos/2`, where a task-opts entry REPLACES the genesis.toml entry wholesale (id-keyed `Map.merge`; TOML `writable`/`base_sha` lost), and the persisted opts JSON nests it as an ARRAY of STRING-keyed objects with only the OUTER key atomized, so every reader of a decoded row normalizes via `ForeignRepo.normalize/1`.
`ResumeContext`/`MergeContext` preserve caller-supplied model keys but never inherit the previous task's selection or its lock; both end in this whitelist (including `:model_spec`), while TaskExecutor's reflect and skill-extraction paths sit outside it.

## TaskExecutor Dispatch & Task Start

`execute_task/4` defaults `server` to its own module `EvoGit.TaskRegistry.TaskExecutor` (NOT the production registry name despite the doc comment), so wrapper callers must supply the explicit fourth argument.
It installs `server` in the `:evogit_task_registry_server` pdict FIRST, then checks `RuntimeOpts.admit_model_selection(opts, EvoGit.Config.resolve())` (an error returns unchanged before tmpdir creation or process registration), then `ensure_task_tmpdir/2`, then private `do_execute_task/3`: `:genesis` → `Runtime.Genesis.run(prompt, runtime_opts)`; `:evolve` → merge-context step, then resume-context-or-plain, then `Runtime.Evolution.run(objective, runtime_opts)`; `:extract_skills` → `Runtime.SkillExtraction.run(runtime_opts)`; `:reflect` → `Runtime.SelfReflective.run(opts ++ [task_id: task_id])`, or `Runtime.Assistant.run/2` when `:session_mode` is `"interactive"` (every other value keeps the byte-identical `SelfReflective.run/1` call).
`:reflect` bypasses `build_common_runtime_opts` (whose `Keyword.fetch!(:path)` would `KeyError`) and returns `{:ok, %{result: …, commit_sha: nil, branch_name: nil, tag: nil}}`; with no `:usage`/`:agent_count` those columns stay NULL and `tasks.result` is its only durable artifact (no `refs/notes/evogit` note, no `task_agent_archives` row).
The `:reflect` clause forwards `opts ++ [task_id: task_id]` verbatim (an earlier caller `:task_id` wins `Keyword.get/2`; duplicates are neither removed nor validated), and no helper here calls `CommandApproval` — those hooks live in the parent registry.
Every clause FIRST calls `register_task_process/1` (`Registry.register(EvoGit.TaskRegistry.ProcessRegistry, task_id, :task)`), the runtime call is the LAST expression (a plain SYNCHRONOUS call returning the runtime value verbatim), and the module has ZERO `Logger`/`IO` calls.
**The wrapper never writes statuses**; the TaskRegistry GenServer performs every write from `{ref, result}`, `:DOWN`, the `:finalizing` handler and `update_status` casts.
`start_task/2` mints an id via `generate_id/0`, then `handle_call({:start_task, ...})`: refuse `unstartable_statuses/0` with `{:error, :cancelled}` → the four non-raising gates (`admit_task_path/1`, `admit_model_selection/2`, `admit_session_mode/1`, `admit_persistent_state/1`), replying `{:error, reason}` and enqueuing nothing → `Task.Supervisor.async_nolink(EvoGit.TaskSupervisor, TaskExecutor, :execute_task, [task_type, opts, task_id, state.server_name])` → persist `%TaskInfo{status: :running, opts: <ADMITTED opts>, started_at, logs: [], result: nil, lease_expires_at: now + 120 s, model_id: opts[:model_id]}` with the ref nulled (store faults → warning/no-op, in-memory only) → `task_refs` entry → broadcast `:running` → `{:ok, task}`.
TaskRegistry creates NO on-disk state, and no `create_task` exists anywhere in evo_git/evo_dash.
All opts defaults live in the CALLERS: the dashboard (`ProjectsLive.handle_event("task_submit", ...)`: `path` required, `mode` always, `:prompt`/`:objective`, conditional `build_system`/`node_path`/`starting_commit`/`foreign_repos`/`archive`/`model_id`/`model_spec`/`resume_from`) and the `StartTask.start_task` shell handler (`:path`, STRING `:mode`, `:prompt` for genesis plus `:objective`, put-if-present `:resume_from`/`:starting_commit`/`:model_id`); the remaining defaults (`:prompt`/`:objective` → `""`, mode → `"simple"`) live in TaskExecutor/RuntimeOpts.
Remote path: `RemoteAPI.start_task/2` → `TaskRegistry.start_task/2` via `RemoteNode.start_task/2` / `NodeContext.start_task/3`; the shell's `StartTask.start_task` calls the local registry directly.
`resolve_recheck_task/3` recovers a task whose wrapper died before replying (best-effort result via `Lease.lookup_sched_meta_result/1`, fallback `:completed`) and shares the `{:ok, %{branch_name: _}}` extraction with `handle_update_status/6`.

## Per-Task Tmpdir Lifecycle

Each task owns ONE managed scratch directory shared by all its agents (`EvoGit.TaskTmpdir`, a PARENT-node file read-only from here; `[tmp] mode` (`:system`/`:custom`/`:per_repo`) and path resolution live there — `../../task_tmpdir.ex` + `../sandbox/CONTEXT.md`).
- **Create trigger (here)**: `execute_task/4` calls private `ensure_task_tmpdir/2` after the pdict seam and model admission, BEFORE dispatch, so the dir exists before any tool can spawn and a rejected selection creates no tmpdir; it calls `EvoGit.TaskTmpdir.ensure(task_id, Keyword.get(opts, :path))` (never `fetch!`) and discards the path. `ensure/2` never raises from its mkdir step, but its PATH RESOLUTION is not exception-free (`System.tmp_dir!()` raises when no writable temp dir exists, aborting the wrapper BEFORE dispatch).
- **Reclaim is event-driven ONLY** (parent `task_registry.ex`): `EvoGit.TaskTmpdir.reclaim/2` removes `task_<id>` on a terminal status — from `handle_update_status/6` plus the direct terminal writes that bypass it (`force_kill_task/1`, `cancel_task/1`'s `:pending` arm, `:lease_sweep`, `resolve_recheck_task/3`); no boot reaper, no periodic sweep. It never deletes outside the managed root nor the root itself and never raises; `handle_update_status/6` reads the FINAL (post force-map) status, so a gracefully cancelled task that completes still reclaims, while `:cancelling`/`:finalizing` never reclaim.
- **Gotchas**: `cleanup_expired_tasks/1` deletes ROWS, never directories (no age-based tmpdir GC); a dir orphaned by a full-runtime CRASH (no terminal write) is NEVER reaped automatically in ANY mode; `[tmp] mode` is re-resolved at RECLAIM time (never stored per task), so changing it mid-flight can orphan the dir created under the old mode.

## OS Surface & Portability

The only OS API is `System.system_time(:second)` (lease arithmetic) — no `System.cmd`, `Port.open`, `:os.*` or `File.*`/`Path.*` beyond `TaskExecutor`'s `TaskTmpdir` call, so no Windows-only crash can ORIGINATE here; the tmpdir BINARY later reaches the Windows sandbox's `Port.open`, whose env pairs MUST be charlists (OTP-29: binary tuples raise) — convert at that call site (`../sandbox/CONTEXT.md` → "Port/OS-pid pitfalls").

## Failed-Task Error Persistence (`TaskInfo.error`)

Every transition to `:failed` records a structured payload in the dedicated `error` column (JSON TEXT), decoded onto `TaskInfo.error` (`map() | nil`) in the full-decode paths (`Store.get_task/1`, `list_tasks_paginated/1`) AND the 16-key summary projection (lenient `Codec.decode_error/1`; nil for non-failed rows).
The shape is a fixed 4-key map with ATOM keys after decode: `%{kind: atom, source: atom, message: String.t(), stacktrace: [String.t()] | nil}`; `kind` ∈ `:error | :exit | :down | :force_kill | :timeout | :restart | :lease_expired | :recheck`, `source` ∈ `:result_handler | :down_handler | :force_kill_task | :finalizing_watchdog | :startup_reconcile | :lease_sweep | :recheck_resolve`.
The sole producer is the pure `Diagnostics.failure_error/3,4`; decode is lenient (nil / invalid JSON / non-object → nil), so a corrupt cell cannot break a row read.
`:cancelled` is NOT a failure, and `handle_update_status/6` appends `error:` ONLY when the FINAL persisted status is `:failed` (after the force-map rewriting stored `:cancelling` + terminal → `:cancelled`).

| Source | kind | message (also written as `result` unless noted) |
|---|---|---|
| wrapper `{:error, reason}` | `:error` | `"Task failed: #{inspect(reason)}"` |
| wrapper `{:exit, reason}` | `:exit` | `"Task exited: ..."` |
| abnormal `:DOWN` (persisted only when `Lease.sched_meta_has_active_agents?/1` is false) | `:down` | `"Task process exited: #{inspect(reason)}"` |
| stuck-`:finalizing` watchdog | `:timeout` | `"Finalization did not complete within N minutes"` |
| force kill | `:force_kill` | `"Task force-killed by user"` (`result` stays nil) |
| startup reconciliation | `:restart` | `"Runtime restarted during task finalization"` |
| lease sweep | `:lease_expired` | `"Lease expired; owning instance no longer renewing"` (`result` set on the full `%TaskInfo{}` before `Store.put_task`) |

`stacktrace` holds the last 8 frames for the wrapper-result and `:DOWN` sites (the REGISTRY process's stack via `Diagnostics.capture_stacktrace/1` + `format_stacktrace_frame/1`) and nil elsewhere.
The wrapper-result error rides `update_task_status_with_caller(..., error: error)` → self-cast → `handle_update_status/6`; `result` is PRESERVED as the RAW error tuple, so `tasks.result` holds the Codec `{"__result_tag__": "error", "reason": <reason | inspect(reason)>}` decoding back to `{:error, reason}` (`{:error, {:llm_request_rejected, "<message>"}}` persisted verbatim).
`usage`/`agent_count`/`commit_sha`/`branch_name` are nil there (`result_field/3` returns nil for anything not `{:ok, data} when is_map(data)`, and the matching `if usage, do: ...` guards OMIT those columns); `finished_at` IS set and the lease cleared, and the wrapper exits `:normal`, so the failure is persisted as a VALUE — no raise, no retry.

## Restart Recovery & Status Transitions

**Startup reconciliation.** `init/1` runs `EvoGit.Store.select_running_lease_info/1` (id + status + lease_expires_at); each `:finalizing`/`:cancelling`/`:awaiting_input` row gets a SYNCHRONOUS `handle_update_status/6` with `{:startup_reconcile, ...}` caller info: `:finalizing` → `:failed` ("Runtime restarted during task finalization"), `:cancelling` → `:cancelled` ("Runtime restarted during task cancellation"), `:awaiting_input` → `:failed` ("Runtime restarted during interactive session").
A `:running`/`:pausing` row takes the PAUSE classification instead: RESUMABLE → `:paused` + `pause_kind: :dirty` (`park_dirty_pause/2` applying the `Restart.classify/2` verdict), non-resumable → left to the one-shot `:lease_sweep`, which fails it with `:lease_expired`.
The handler narrow-reads `select_task_update_info/2` (status/opts/finished_at/lease_expires_at — no full decode), applies the stale guard, logs via `Diagnostics.log_failed_transition`, handles finished_at/lease, broadcasts `{:task_updated, task_id, status, node()}` and cleans `task_refs`; writes are SYNCHRONOUS in init (an async cast would race callers).

- `state.task_refs` is in-memory only — empty after restart, so `{ref, result}` / `{:DOWN, ...}` never fire for pre-restart tasks.
- `:heartbeat` renews only where `Lease.lease_renewable?/1` is true — `renewed_statuses/0` plus `{:unknown, raw}`; a missing row and every terminal status renew nothing.
- `:lease_sweep` (one-shot, 150 s after init = `(@lease_duration + 30) * 1000`) filters with `Lease.leaked?/3` — a KNOWN `leaked_statuses/0` row, not in `owned_ids`, lease expired/missing; `:finalizing` is excluded by design (init handled it), `:paused` is never swept, and `{:unknown, raw}` is never leaked.
- `:periodic_cleanup` → `cleanup_expired_tasks/1` deletes only rows with `finished_at != nil` (`:finalizing` has nil → never deleted).
- **Lease mechanics**: `@lease_duration` 120 s, `@heartbeat_interval` 60_000 ms; the lease is set at start, renewed via `Store.renew_leases/3`, and the sweep fails an expired `:running` foreign task only when `sched_meta_has_active_agents?` is false, then runs cleanup + broadcasts (cleanup never changes status).
- **Resolution paths for `:finalizing`**: (a) startup reconcile → `:failed`; (b) explicit — `clear_finished_tasks` uses `select_finished_task_ids` (SQL `status NOT IN ('running','pending','cancelling')`, which INCLUDES `:finalizing`) and DELETEs them, or `delete_task`; (c) in-process — wrapper completion, wrapper crash, or the public `update_task_status/4` cast (stale guard blocks terminal→terminal except → `:completed`), while `cancel_task` from `:finalizing` → `{:error, :not_running}`; (d) the stuck-`:finalizing` watchdog. Lease expiry plays NO role here.
- **Stuck-`:finalizing` grace watchdog**: on a SUCCESSFUL persist of `:finalizing` (`put_task` `:ok` arm only) the handler schedules ONE-SHOT `Process.send_after(self(), {:recheck_task, task_id}, trunc(minutes * 60_000))` via `schedule_finalizing_watchdog/1`; grace minutes come from the app-env seam `:finalizing_watchdog_grace_minutes` read at SCHEDULE time by `finalizing_watchdog_grace/0` (`false` → DISABLED; unset/nil → **60**; numeric ≥ 0 → that many; anything else → 60 — `config/config.exs` 60, `config/test.exs` 1). At fire time the recheck handler's dedicated `%TaskInfo{status: :finalizing}` arm calls `resolve_finalizing_watchdog/3` and resolves `:failed` through `handle_update_status/6` with caller_info `{:finalizing_watchdog, task_id}`; it does NOT check `sched_meta_has_active_agents?`, does NOT reschedule, kills nothing and leaves residual sched_meta/agent state untouched — timers are per-boot and a restart mid-grace is covered by init reconciliation.
- **Pinned late-wrapper-result semantics**: after the watchdog resolves to `:failed` the wrapper may still be alive (e.g. slow NFS git I/O); its `{ref, result}` / `{:DOWN, ...}` handlers are complete NO-OPS — `task_id_for_ref/2` returns nil because the terminal branch deleted the `task_refs` entry, so both skip their write bodies (the row keeps the watchdog result + finished_at) and `Process.demonitor(ref, [:flush])` clears the monitor plus any queued `:DOWN`; nothing re-adds the task to `task_refs` (test-pinned in `persistence_test.exs`).
- **`resolve_recheck_task/3` and the 30 s live-agent reschedule are effectively unreachable**: `Lease.lookup_sched_meta_result/1` is used only there, reached only from the recheck handler's generic arm for non-terminal, non-`:finalizing` rows — the watchdog schedules rechecks only for `:finalizing` rows and nothing schedules a first recheck for `:running` rows.
- **Stuck-`:finalizing` cause**: `Runtime.Helpers.notify_finalizing/1` broadcasts from INSIDE the runtime phase, right after `AgentScheduler.run_agent` returns and BEFORE `merge_and_report/4`, so a blocked merge blocks the wrapper while the status stays `:finalizing`.

## Task-Level Pause & Resume

A task-level pause (`docs/task-pause.md`) winds ONE named task DOWN to a durable, resumable RESTING state; it is neither a cancel nor a failure and sits on the `agent_state.sqlite` durability substrate.
Two NON-terminal statuses carry it: `:pausing` (draining — wrapper alive, lease renewed) and `:paused` (every agent stopped at a turn boundary with its worktree and state checkpointed — no lease, no wrapper, `finished_at` nil, resumable).
`pause_kind` (`:clean | :dirty | nil`, the `tasks.pause_kind` column) is the ONE persisted discriminator: `:clean` = the user paused (nothing interrupted, so resume repairs nothing), `:dirty` = a restart brought the row back (the last tool batch may be partial, so resume runs the crash repair), `nil` = not paused; `:cancelled` keeps meaning "gracefully cancelled", and a pause never lands there.
Entry points: `TaskRegistry.pause_task/1` / `resume_task/1` are `GenServer.call`s (validation/persistence in `Pause`), mirrored by `RemoteAPI.pause_task/1` / `resume_task/1` and `RemoteNode.pause_task/2` / `resume_task/2`.
`pause_task/1` → `:ok` (including the idempotent `:pausing`/`:paused` case) or `{:error, :not_found | :not_pausable | :not_resumable | :not_running | :scheduler_unavailable | :disk_full | :store_unavailable}`; `resume_task/1` → `:ok` or `{:error, :not_found | :not_paused | :not_resumable | <admission reason>}`.

**Pause protocol (clean).** `pause_task/1` accepts `:running` only for a real transition: an interactive-session task (`:awaiting_input`, or persisted `:session_mode == "interactive"`) is `{:error, :not_pausable}`, a stored `:persistent_state == false` (or non-boolean) is `{:error, :not_resumable}` (a pause that cannot be resumed is never pretended), `:pausing`/`:paused` are idempotent no-ops, and `:pending`/`:finalizing`/`:cancelling`/terminal rows are `{:error, :not_running}`.
`Pause.pause/2` writes `:pausing` FIRST, then calls `EvoGit.AgentScheduler.begin_task_pause/1` (sets the `:evogit_task_pause` marker, flips each agent's control-plane pause flag and purges their queued LLM/tool slot waits with `{:error, :paused}`, so a pause never hangs behind a slot wait); a down/timing-out scheduler reverts the row to `:running` and answers `{:error, :scheduler_unavailable}` (a `:pausing` row with no agents to drain is unrecoverable without a restart), and `{:task_updated, task_id, :pausing, node()}` broadcasts after that call, only for a real transition.
Each agent honours the flag at a TURN BOUNDARY (never mid-tool), reaps background jobs, commits a worktree checkpoint, flushes durable state and delivers `{:paused, info}`; `info.durable` is `true` only when that `EvoGit.AgentState.flush/1` barrier answered `:ok`; the ROOT agent reports only after its children have paused, so ONE wrapper result closes the task.
`handle_wrapper_result/3`'s `{:paused, info}` arm writes a TARGETED `status: :paused, pause_kind: :clean, finished_at: nil, lease_expires_at: nil` (never a full `put_task`, so `result`/`usage`/`commit_sha`/`branch_name`/`started_at`/`opts` stay byte-identical and a resume ACCUMULATES usage), broadcasts on the successful write and reuses the terminal in-memory cleanup (`task_refs` dropped, pause marker cleared via `Pause.abandon/1`); worktrees are reclaimed normally because the checkpoint commit is what survives. No `:finalizing` notification and no merge ever run for a pause.

**Straggler guard.** A late `{:ok, %Result{}}`/`{:error, _}`/`:DOWN` for a row already `:pausing`/`:paused` is DISCARDED (`pause_settled?/2` + `discard_paused_result/3`, logging only the RESULT SHAPE): a straggler must never resurrect a paused task, flip it to `:completed`/`:failed`, or clobber the result/usage a later resume depends on. A `{:paused, info}` report arriving while the row is `:cancelling` resolves the row the cancellation way (`:cancelled` — a cancel during the drain WINS); one arriving on a terminal or `:awaiting_input` row is discarded outright.

**Resume protocol.** `resume_task/1` accepts `:paused` ONLY (`{:error, :not_paused}` otherwise) and re-enqueues the SAME task id with the PERSISTED opts — never `start_task/2`, which mints a fresh id and would reset the archive roster.
It re-runs `start_task/2`'s four admissions against the CURRENT config, requires the durable ROOT run (`read_root_run/2`: ONE bounded, offloaded `AgentStateRead.roster/2` read whose ROOT is the record with an absent `parent_id` — no durable row or a CHILD-only roster is `{:error, :not_resumable}`), resolves that row's five resume facts up front, clears the stale scheduler pause marker FIRST, spawns the wrapper through the registry's call-time seam (`wrapper_spawn_fun`), and only then writes `status: :running, finished_at: nil, error: nil, pause_kind: nil` + a FRESH lease (a failed write stops the spawned wrapper); it tracks the ref and broadcasts `{:task_updated, task_id, :running, node()}`.
Spawn opts carry `resume_kind: :clean_pause` (`pause_kind == :clean` or legacy `nil`) or `:dirty_pause`, forwarded by `RuntimeOpts.build_common_runtime_opts/3` to `spec.opts`, plus the ROOT run's five facts — `pause_commit` (worktree checkpoint), `resume_agent_id` (the persisted root id, so every `(task_id, agent_id)`-keyed durable read still resolves), `resume_current_commit`, `resume_branch` and `resume_anchor_ref` (`fields[:anchor_ref]`, else `EvoGit.AgentState.Anchor.ref/2`).
Each fact is PRESENCE-based with its value (`nil` included = "resolved, nothing stored"), so the dispatch side never reads the durable database on its hot path while a non-resume run's opts stay byte-identical; `RuntimeOpts.resume_fact_keys/0` is the ONE key list shared with `Runtime.Helpers.build_root_agent_spec/7`.
`AgentScheduler.Dispatch` bases the resumed worktree on `:pause_commit` (`meta.crash_commit` first, both `git cat-file -e`-verified, degrading to the task base) and carries the other facts as the persisted root identity; `EvoGit.Agent.Resume` selects the narration (clean = no repair, dirty = crash repair + `[RESUME]` notice).
The archive roster is PRESERVED: `AgentScheduler.run_agent/2` skips its per-task archive reset when the spec opts carry `resume_kind`, so archived completions UPSERT onto the paused run's rows (keyed `(task_id, agent_id)`); `:paused` defeats `clear_finished_tasks` because it lives in `Lightweight.live_statuses/0` while carrying `finished_at: nil`.

**Restart mapping (dirty pause).** Both restart paths classify every wrapper-less `:running`/`:pausing` row in ONE batched `Restart.classify/2` pass (the ONE resumability classifier: `:persistent_state` on AND NOT an interactive session — the SAME rule the clean pause refuses with `:not_pausable` — AND a durable ROOT run, never "any durable row"; `Pause.pause_kind_for_restart/1,2` is the public single-row view): a RESUMABLE row is parked `:paused` + `pause_kind: :dirty`, `finished_at` nil, lease cleared, result/usage untouched (one broadcast AFTER the persist), while a NON-resumable row (interactive session, CHILD-only roster, or an unanswerable durable read degrading to `[]`) keeps the sweep-fail behaviour.
`init/1` owns the rows present AT BOOT; the sweep owns rows that become owner-less later (`Lease.leaked?/3`). Only the ROOT agent is resumable after a restart: subagent processes are gone, their retained batch is scheduler memory, and a child's partial work survives only where it was already merged.

## Graceful Cancellation & Force Kill

The **`{:task_updated, id, :finalizing, node}` handler** matches ONLY `:finalizing` (other statuses are persisted locally), with a node-filter guard `when node == node()` plus an explicit no-op clause for other nodes (a remote finalizing broadcast must never persist locally — task ids are per-node); a `:cancelling` task ignores phase-finalization broadcasts, and a successful persist schedules the one-shot watchdog.
`handle_update_status/6` force-maps the final result: stored `:cancelling` + incoming `:completed | :failed` → persisted `:cancelled`, with result/usage/archive flowing through untouched (never nil'd).
**`:cancelling`** is the graceful-cancel state, deliberately NON-terminal: the `task_refs` entry stays, `finished_at` stays nil and the lease stays valid (heartbeat renews it).
It is whitelisted in `Store.Codec.@known_atoms` and the `TaskInfo` typespec; `Store.select_finished_task_ids` (SQL `status NOT IN ('running','pending','cancelling')`) keeps `clear_finished_tasks` from deleting in-flight cancelling tasks while `:finalizing` still counts as finished; `Store.select_running_lease_info` includes it; startup reconciliation maps it to `:cancelled`.
**`TaskRegistry.cancel_task/1` is GRACEFUL**:

- `:pending` → immediate `:cancelled` write (finished_at set, lease cleared) + broadcast only on the successful write.
- `:running` → `handle_update_status(..., :cancelling, ...)`, which broadcasts `{:task_updated, task_id, :cancelling, node()}` (the ONLY broadcast for this arm; non-terminal, so finished_at/lease/task_refs stay), then calls `AgentScheduler.begin_graceful_cancel(task_id)` (`:exit`-guarded — a down scheduler leaves the task `:cancelling` for force kill or restart reconciliation).
- `:awaiting_input` → immediate terminal `:cancelled` write (lease cleared, NO `result` column so transcript/result is preserved) + `clear_cancelling_marker/1` + tmpdir reclaim + broadcast on the successful write; the idle session is stopped best-effort BEFORE the write (task-addressed `AgentScheduler.force_kill_task_agents_for_task/1`, guarded, then this instance's `Task.shutdown(ref, :brutal_kill)` while its task_refs entry is still present so the kill's `:DOWN` cannot race the write and map the row to `:failed`).
- `:pausing` → the pause is ABANDONED first (`Pause.abandon/1`) and the `:running` arm then runs, so a cancel that arrives mid-drain wins and the pause can never be re-introduced.
- `:paused` → immediate terminal `:cancelled` write exactly like an idle session (lease cleared, `pause_kind: nil`, result/usage preserved).
- `:cancelling` → `:ok` idempotent (does NOT re-send the cancel message).
- terminal (`:completed`/`:failed`/`:cancelled`), `:finalizing` or `{:unknown, raw}` → `{:error, :not_running}`; missing → `{:error, :not_found}`.

**`TaskRegistry.force_kill_task/1`**: gate `killable_statuses/0` (`pause_kind` cleared in the same write, so a killed task is never mistaken for a paused one) → `AgentScheduler.force_kill_task_agents(pid)` (reverse-depth `:brutal_kill` cascade, `:exit`-guarded) + `Task.shutdown(ref, :brutal_kill)` + a direct terminal write (`:failed`, finished_at set, lease nil, result nil — a force-killed task is never `:cancelled`) + `Pause.abandon/1` + `clear_cancelling_marker(task_id)`; the body is status-agnostic, only the gate widened for waiting sessions.
**Marker cleanup** — `clear_cancelling_marker/1` prefers `AgentScheduler.clear_cancelling_task/1` (serialized, cannot race `begin_graceful_cancel`) and falls back to `:ets.delete(:evogit_cancelling_tasks, task_id)` when the scheduler is down (TaskRegistry starts BEFORE AgentScheduler, e.g. during startup reconciliation); called from every terminal transition.

## PubSub Broadcast Contract (topic `"tasks"`)

Default ordering is **persist-then-broadcast**: `handle_update_status/6` writes via `Store.update_task_columns` FIRST and broadcasts `{:task_updated, task_id, status, node()}` only in the `:ok` arm, gated on `status != task_status` — a missing row, stale-guard skip or disk-full write never broadcasts, so a listener that re-fetches sees the NEW row. The trailing `node()` is the emitting node (subscribers ignore other nodes).

| Broadcast | Site | Ordering |
|---|---|---|
| `{:task_updated, id, :running, node()}` | `start_task`; `resume_task/1` | put_task / update_task_columns → broadcast |
| `{:task_updated, id, :pausing, node()}` | `pause_task/1` `:running` arm | persist → `begin_task_pause/1` → broadcast |
| `{:task_updated, id, :paused, node()}` | `handle_wrapper_result/3` `{:paused, info}` arm (clean); `init/1` reconciliation and `:lease_sweep` (dirty) | write → broadcast (exactly one per transition; the clean arm fires only on a successful write) |
| `{:task_updated, id, :cancelling, node()}` | `cancel_task/1` `:running` arm (and the `:pausing` arm, after abandoning the pause) | persist → broadcast |
| `{:task_updated, id, :cancelled, node()}` | `cancel_task/1` `:pending` arm AND `:awaiting_input`/`:paused` arms | write → broadcast |
| `{:task_updated, id, :failed, node()}` | `force_kill_task/1`; `:lease_sweep`; recheck resolution; watchdog/startup reconcile | write → broadcast (force-kill fires unconditionally — see Known Issues) |
| `{:task_updated, id, nil, node()}` | `set_review_status` / `set_review_metadata` casts | after a SUCCESSFUL write (no status change) |
| `{:task_deleted, id, node()}` | `clear_finished_tasks` (one per id), `delete_task` | only on the successful write |

- **Terminal sequences**: completed = wrapper sends `{ref, result}` → handler maps to `:completed`/`:failed`/`:exit` → cast `update_task_status_with_caller` → `handle_update_status/6` force-maps `:cancelling`+terminal → `:cancelled` (result preserved) → persist, then broadcast. Abnormal wrapper death = `{:DOWN, ...}`: `:normal` → `update_task_status(:completed)`; other reasons → `:failed` ONLY when `Lease.sched_meta_has_active_agents?/1` is false, else the row stays `:running` with no broadcast.
- **The ONLY broadcast preceding its persist is `:finalizing`**: `Runtime.Helpers.notify_finalizing/1` fires it from INSIDE the wrapper and the local handler persists afterward; a disk-full `put_task` leaves subscribers told `:finalizing` while the row stays `:running` (self-heals at the terminal broadcast). Reflect tasks never emit `:finalizing`.
- **`Cleanup.cleanup_expired_tasks/1` deletes rows with NO broadcast.**

## Task Lifecycle & Terminal-Write Sites

- **Start / Run**: `start_task/2` spawns the wrapper; the wrapper runs the WHOLE lifecycle synchronously (incl. `Runtime.Helpers.merge_and_report/4`) and never writes statuses — `notify_finalizing/1` broadcasts `:finalizing` from inside it before `merge_and_report`, and the local handler persists it.
- **DOMINANT terminal choke point = `handle_update_status/6`**: its terminal branch runs the in-memory teardown (`clear_cancelling_marker/1` + `TaskTmpdir.reclaim/2` + `task_refs` deletion), reached from the wrapper result handler, the `:DOWN` handler, startup reconciliation and the watchdog.
- **Terminal transitions that BYPASS it (direct `Store` writes)**: `force_kill_task/1` (`:failed` + reclaim + broadcast), `cancel_task/1`'s `:pending` arm (`:cancelled` + reclaim + broadcast), `resolve_recheck_task/3` (reclaim), `:lease_sweep` (`put_task`, reclaim, `:failed`). Hence NO single teardown choke point and no shared `terminal_cleanup/3` helper: a task-end teardown needs a hook at ALL FIVE sites.
- **Per-task on-disk artifact**: the managed tmpdir above. `cleanup_expired_tasks/1` only DELETEs finished task ROWS (called from `clear_finished_tasks`, `:lease_sweep`, `:periodic_cleanup`); archive rows live in their own per-agent table.
- **Boot memory profile (init is NOT the growth vector)**: state keeps exactly five keys — `data_dir`, `task_store`, `task_refs` (`%{task_id => %Task{}}`, only THIS instance's live tasks, removed at terminal), `read_offloads` (transient `ref => entry`) and `server_name`; no task row, `result` or `logs` is ever retained. `select_running_lease_info/1` projects only `id`/`status`/`lease_expires_at` and the row list is REDUCED and discarded; only reconciled rows cost one `select_task_update_info/2` read (whose `opts` may carry base64 `:attachments`) plus a write.
- **Rows-proportional allocations that DO land on the registry heap are id-only** (`:periodic_cleanup` → `cleanup_expired_tasks/1` and `clear_finished_tasks` → `select_finished_task_ids/1` run inline, not offloaded): strings bounded by `task_history` (`max_tasks` 100 / `max_age_days` 14), deleted in 500-id chunks.

## Merge-Conflict-Resolution Flow (MergeContext / TaskExecutor)

- **Only trigger point**: `execute_task(:evolve, opts, task_id)` runs a merge-context step BEFORE `resume_from` handling: a non-empty trimmed `opts[:merge_from]` triggers `MergeContext.apply_merge_context(opts, task_id, trimmed_merge_from, opts[:merge_target])`, whose result replaces `opts`; only the merge keys are stripped, so an independently supplied `resume_from` still triggers ResumeContext afterward and can override the merge-derived starting commit.
- **`apply_merge_context/4`**: strips `:merge_from`/`:merge_target` FIRST (never leak into runtime opts) → `prev_task = EvoGit.TaskRegistry.get_task(merge_from)` (full `%TaskInfo{}` decode). **nil** → stripped opts unchanged. **Found** → `:starting_commit` overridden with `prev_task.commit_sha` when a non-empty binary (the caller's value is preserved otherwise) → `:foreign_repos` carried from `prev_task.opts` when present/non-nil, each entry normalized via `ForeignRepo.normalize/1` with unparseable entries dropped → each carried repo's `base_sha` overridden from the prev result's `repos[repo_id]["commit_sha"]` via `PrevTaskRepos.apply_starting_commits/2` (repos absent from the prev `repos` keep their base_sha; legacy tasks without `repos` are a no-op) → `:objective` = `build_merge_context_block(prev_task, merge_target, carried_repos) <> "\n\n" <> old_objective`. Pure keyword-in/out (returns bare opts, NOT a `{objective, runtime_opts}` tuple).
- **`build_merge_context_block/2,3`** returns a block fenced by `--- Merge Conflict Resolution Context ---` / `--- End Merge Conflict Resolution Context ---` with `Previous task id:`, `Base sha:` / `End (commit) sha:` (each omitted when nil/empty — the block is still emitted), `Task branch name: <branch_name || "unknown">`, `Merge target branch: <merge_target || "unknown">`, a `Goal:` paragraph (merge the target into the worktree via `git merge <target>`, resolve ALL conflicts by combining both sides, commit, keep developing until coherent), a `Writable foreign repos: <id>@<base_sha|HEAD>, ...` line ONLY when ≥1 writable repo (the 3-arity takes explicit repos so the block shows the ACTUAL starting commits; the 2-arity derives them from `prev_task.opts[:foreign_repos]`), and a `Hints:` section (commit resolutions before delegating; inspect `git log/diff <base>..<end_sha>` and `<base>..<target>`; incremental milestone merges OR rough-resolve-then-develop-on-top; the CONTEXT.md ownership bullets) before the closing delimiter on BOTH arity paths. Non-struct input → `""`.
- **CONTEXT.md conflict policy**: keep the version of the side whose node path OWNS the file (an agent rooted at `./src` owns `./src/CONTEXT.md`; the root agent at `./` is everybody's ancestor); a genuine same-node conflict is merged from BOTH sides, keeping both routing-table entries and both sets of documented facts; prefer `edit_context` small surgical edits over whole-file rewrites; if ownership is genuinely ambiguous, keep both sides and note the ambiguity. Pinned by `test/evo_git/task_registry/merge_context_block_test.exs`.

## Resume-From Flow (ResumeContext / TaskExecutor / RuntimeOpts)

- **Only trigger point**: `execute_task(:evolve, opts, task_id)` calls `ResumeContext.apply_resume_context/3` when `opts[:resume_from]` is a non-empty binary after `String.trim/1`; non-resume evolve tasks build `{objective, runtime_opts}` directly (`objective = Keyword.get(opts, :objective, "")`).
- **`apply_resume_context/3`** strips `:resume_from` (never leaks) → `prev_task = get_task(resume_from_id)` (FULL decode). Caller-supplied `:foreign_repos` are normalized to `%ForeignRepo{}` (string-keyed Codec maps allowed; unparseable dropped) and each repo's `base_sha` is overridden from the prev result's `repos[repo_id]["commit_sha"]` via `PrevTaskRepos.apply_starting_commits/2`; the `:foreign_repos` key is (re)added only when the normalized list is non-empty. **nil prev** → original objective, `build_common_runtime_opts` with the caller's own (normalized) repos. **Found** → `context_block = build_resume_context_block/1`; the objective becomes `context_block <> "\n\n" <> objective` only when the block is non-empty; `:starting_commit` is overridden with `prev_task.commit_sha` when a non-empty binary (a caller-provided value is silently dropped), else the caller's passes through; then `build_common_runtime_opts(opts_with_commit, task_id, :evolve)`. **Foreign repos are NOT inherited from `prev_task.opts` on resume** — only caller-supplied ones flow through; `MergeContext` is the ONLY cross-task inheritance path.
- **Context block format**: `"--- Previous Task Context ---\n" <> Enum.join(parts, "\n\n") <> "\n--- End Previous Task Context ---"`, empty string when `parts == []`; parts: `"Previous task commits: #{base_sha}..#{commit_sha}"` (both non-empty; just `commit_sha` when base_sha is empty/nil; omitted when commit_sha is empty); an undelimited `"Writable foreign repos: <id>@<base_sha|HEAD>, ..."` (only when ≥1 writable repo in `prev_task.opts[:foreign_repos]`, normalized first); `"Previous task objective:\n<<<BEGIN OBJECTIVE>>>\n…\n<<<END OBJECTIVE>>>"` (from `prev_task.opts` `:objective` || `:prompt`, only when non-empty); `"Previous task result:\n<<<BEGIN RESULT>>>\n…\n<<<END RESULT>>>"` (omitted when `extract_result_summary/1` returns nil or `""`); the `<<<BEGIN …>>>`/`<<<END …>>>` markers wrap arbitrary multi-line content so a label cannot be confused with its content.
- **`extract_result_summary/1`**: `{:ok, %{result: s}}` binary → passthrough, atom → `to_string/1`; `{:error, reason}` → `"Error: #{inspect(reason)}"`; `{:exit, reason}` → `"Exited: #{inspect(reason)}"`; anything else → nil.
- **SHA provenance**: `prev_task.commit_sha` is populated at completion by the `{ref, result}` handler extracting `{:ok, %{commit_sha: sha}}` (the runtime merge result carries `commit_sha: final_sha || base_sha`); `prev_task.base_sha` is set ONLY by the review flow (`set_review_metadata/3` cast), so a never-reviewed task's commits line is just the commit_sha.

## Repo-Less (`:reflect`) Task Option & Lifecycle Contract

- **No reflect-specific validation exists here**: `handle_call({:start_task, ...})` is TYPE-AGNOSTIC — it persists the WHOLE opts keyword list and the only checks are the shared `RuntimeOpts` admission gates, so `:history`/`:messages`/`:conversation`/`:session`/`:resume_from` are neither required nor rejected; they ride into `Runtime.SelfReflective.run/1` and are ignored there. Auto admission DROPS `:model_spec`/`:model_id`/`:model_id_locked`; an explicit `:model_spec` is schema-validated and canonicalized with `:model_id_locked: true` forced (same admission at enqueue and at `execute_task/4`).
- **`:path` is neither required nor forbidden for reflect**: `admit_task_path/1` admits an absent/`nil` `:path` and any ordinary binary; `do_execute_task(:reflect, ...)` never reads it and never calls `build_common_runtime_opts`, so its only consumer is `ensure_task_tmpdir/2` as the `:per_repo` tmpdir base. A `vct:` path is refused for EVERY task type, reflect included.
- **`:attachments`, `:quality_level` and `:archive` are inert**: `RuntimeOpts` never validates attachments on this path and `Session.Setup.build_initial_state/3` nils them for repo-less agents (`if repo_less, do: nil`), so no media reaches the Assistant; `:quality_level` bypasses `QualityLevel.normalize/1` and reaches the session's initial state as-is; `:archive` cannot produce a row because the archive gate requires `archive and base_commit` while repo-less `base_commit` is nil (`agent/completion.ex`).
- **Resume/merge do NOT support reflect**: `apply_resume_context/3` and `apply_merge_context/4` have no task-type guard but are only reachable from `do_execute_task(:evolve, ...)`, so a `:reflect` task ignores `:resume_from`/`:merge_from`; an evolve task resuming FROM a reflect task id embeds that task's objective + final `result` string only (no commits line), and NO path replays a prior reflect conversation (chat continuity is the dashboard's text preamble in `:objective`).
- **One agent, one run, nothing survives but `task.result`**: `Runtime.SelfReflective.run/1` builds ONE `EvoGit.Agents.SelfReflective` root spec (`subagent_modules/0` is `[]`) and blocks on `AgentScheduler.run_agent/1`; the result is `{:ok, %{result: report_text, commit_sha: nil, branch_name: nil, tag: nil}}` with no `:usage`/`:agent_count`. No `task_agent_archives` row is written and the conversation lives only in that agent's ETS summary row, deleted by `Lifecycle.recycle_agent/2` at completion (`run_agent` also calls `reset_task_archives(task_id)`).
- **Review status is not type-guarded, but merging cannot work**: `set_review_status/2`/`set_review_metadata/3` write on any existing row (only a missing row is a no-op), yet a reflect task has nil `branch_name`/`commit_sha` and no repo, so `Review.merge_branch/2,3`/`check_merge/3`/`default_merge_target/1` have no branch to act on.

## Known Issues

- `awaiting_input_test.exs` pins the status-set totality table (every set containing `:running` also contains `:awaiting_input`, except the deliberate `:finalizing` ignore-list exemptions) plus the reconcile/kill/cancel/flip behaviour.
- **A status string outside `Store.Codec.known_statuses/0` keeps its lease but is masked in full decodes.** Liveness is safe (`get_task_status/2` answers `{:unknown, raw}`, the heartbeat renews it, the sweep never leaks it), but `Codec.decode_task/1` (`mask_unknown_status/1`) renders the row as a LIVE `:pending` row on `get_task/2`/`get_task_lite/2` and the summary projections, logging the value on every such read — so liveness decisions must use the narrow `Store.get_task_status/2`, never the masked struct field.
- **A restart is FATAL for a `:running` task that is not dirty-pausable.** The one-shot `:lease_sweep` 150 s after EVERY boot fails every row that is (a) not in THIS instance's `task_refs`, (b) lease-lapsed and (c) agent-free per THIS instance's `sched_meta_has_active_agents?/1`; "owning instance" exists ONLY as `task_refs` (no persisted instance/node/boot id column), so ANY fresh BEAM sharing the DB owns nothing — the sweep writes `:failed` + `error.kind :lease_expired`, lease nil, finished_at set, but NOT `branch_name`/`commit_sha` → NOT reviewable.
- **`sched_meta_has_active_agents?/1` reads a BEAM-LOCAL ETS table** (`:evogit_sched_meta`, `:public` but NOT distributed), so it never sees another instance's live agents: if A's lease lapses (dead BEAM, restarted registry with empty `task_refs`, stalled heartbeat), B's boot sweep fails A's STILL-RUNNING task while its worktrees are alive — and a later primary-repo spawn in a fresh BEAM re-runs the WorktreeManager full wipe (`:evogit_worktree_repos` is app-owned → rm_rf `.genesis/workers` + delete all `evogit-agent-*` branches), destroying in-flight work.
- **The `:finalizing` handler's ignore-list deliberately omits `:failed`** (`finalizing_ignored_statuses/0`): recovering a persisted-`:failed` row to `:finalizing` on a stale broadcast is intended (pinned by `persistence_test.exs` "recovery before completion"; the list must NOT gain `:failed`); a cross-node broadcast is dropped by the node guard.
- **`force_kill_task/1` broadcasts `{:task_updated, task_id, :failed, node()}` UNCONDITIONALLY** — also on `{:error, :not_running}` / `{:error, :not_found}` with no persisted change, so the dashboard sees a spurious `:failed` for an unchanged row (the review casts broadcast only after a successful write).
- **Disk-full at a terminal write can leave a row `:finalizing` with NO in-process retry.** `handle_update_status/6`'s `{:error, :disk_full}` arm only logs; the in-memory cleanup still runs, but the row keeps its OLD status and no broadcast fires, and nothing retries (one-shot watchdog; heartbeat renews only `lease_renewable?/1` statuses; the sweep only `Lease.leaked?/3` rows; `:periodic_cleanup` needs `finished_at != nil`; a late `{ref, result}` after `task_refs` deletion only logs) — a disk-full watchdog write too leaves the row `:finalizing` until an explicit `clear_finished_tasks`/`delete_task` or a registry restart whose init reconcile maps it to `:failed`.
- **Memory scales with `tasks.sqlite` size — via the summary-query path, NOT init.** `Store.select_tasks_summary*` / `select_tasks_changed_since` decode every matching row's `opts` JSON (`result` is NOT in the 16-column projection) off-process, so retained memory ≈ O(rows × opts-blob size), capped by `periodic_cleanup`'s `max_tasks: 100`; the dashboard re-fetches status-filtered sidebar summaries on every broadcast (300 ms debounce) and each ProjectsLive session keeps the 16-key maps in assigns for its lifetime.
- **Derived foreign-repo `base_sha` is a FROZEN snapshot never re-validated against git.** `PrevTaskRepos.apply_starting_commits/2` reads the previous task's `repos[repo_id]["commit_sha"]`, persisted ONCE at that task's terminal write and never rewritten, and nothing re-reads the foreign branch tip or checks ancestry — so a follow-up (resume / merge-auto-resolve) from an OLDER task starts that repo at the older commit when a LATER task advanced it (only existence is validated, via `Runtime.Helpers.validate_foreign_repo_base_sha!`); recording is skipped when the foreign-repo subagent's result is not `{:ok, %Result{}}` and for any child that is not itself a writable `:read_write` agent running there (`Subagents.store_sub_result/3,4`).
- **Resume block vs runtime mismatch**: the `Writable foreign repos:` line comes from the PREVIOUS task's own `opts[:foreign_repos]`, NOT from the overridden per-repo starting commits threaded into runtime opts — the two can disagree (`MergeContext` avoids this via its 3-arity builder).
- **A task-level resume carries the ROOT run's durable identity to the scheduler; consuming it belongs to the scheduler node.** `Pause.resume/4` puts the ROOT row's `agent_id`, `current_commit`, `branch`, `anchor_ref` and `pause_commit` on the spawn opts, `RuntimeOpts` → `Runtime.Helpers.build_root_agent_spec/7` forward them PRESENCE-based, and `AgentScheduler.Dispatch` owns the restore/base precedence; a dirty pause writes no `pause_commit`, so such a resume still bases on the task base unless the ROOT row's own `current_commit` is usable.
- **`persist_paused/3` drops the honesty flag**: the wrapper reports `{:paused, %{durable: boolean()}}` (produced by `agent/session/pause.ex`), but `persist_paused/3` binds `_info` and writes `pause_kind: :clean` with a "clean checkpoint" log unconditionally — a `durable: false` pause is recorded as if durable, so a resume skips the crash repair such a pause needs.

## Project Mounts Are Not Registry State

The registry owns task state only: `EvoGit.VCT` owns the project mount list, its `"vct"` broadcast and every mount read, and no registry handler, seam or state key references it (mounts live in the store's `vct_mounts` table).

## Store Access, Fault Isolation & Three-State Reads

`StoreGuard` offers three helpers: `read/3` (degraded answer on fault), `write/2` (`{:error, :store_unavailable}` on fault) and `fetch/2` (`{:ok, value} | :unavailable`); `fetch/2` is MANDATORY for any read whose degraded `nil`/`[]` would be treated as a DOMAIN fact (gone row, empty list, unhealthy config), because the registry MUST never read a store OUTAGE as a domain answer.
`StoreRead` is the ONE three-state surface built on it: `status(store, task_id) :: {:ok, status} | :absent | :unavailable` (status is a known atom OR `{:unknown, raw}` — the row EXISTS, its status text is unreadable), `update_info(store, task_id) :: {:ok, map} | :absent | :unavailable` and `restart_info(store, task_ids) :: {:ok, [map]} | :unavailable`; `:absent` means "no such row" while `:unavailable` means "the store could not answer", which is never evidence of anything.
Each call site picks the CONSERVATIVE direction for its own failure mode: `handle_update_status/6` and the review casts write and broadcast NOTHING on either answer (a gone row, or a row it cannot read to decide the stale-terminal guard / `:cancelling` map / finished_at+lease preservation); `pause_settled?/2` answers **`true`** on `:unavailable` (the straggler guard stays ON, so a late result can never flip a `:pausing`/`:paused` row and clobber the result/usage a resume needs); `persist_paused/3` drops the ref on both (plus ONE warning on `:unavailable`) so the pause is never reported as persisted and the lease sweep parks a resumable row as a DIRTY pause; `start_task/2` PROCEEDS on both (a fresh minted id cannot be `:cancelled`, and refusing would strand the task); `pause/2`/`resume/4` admission answers `{:error, :not_found}` vs `{:error, :store_unavailable}` (an unreadable row is never "not found"); `{:recheck_task, id}` is a no-op on `:absent` but RESCHEDULES 30 s later on `:unavailable` (a periodic watchdog must not disappear on a store blip); `Restart.classify/2` classifies nothing on either (rows keep their live status and the sweep later fails them).
The review casts have no tautological `nil ->`/present pair: `{:ok, _present}` (including `{:unknown, raw}`) is writable, and `{:task_updated, task_id, nil, node()}` fires ONLY inside the arm where `update_task_columns/3` answered `:ok`.
The pause WRAPPER RESULT path reads through `StoreRead.update_info/2` too: `{:paused, info}` → `persist_paused/3` is a decision on the CURRENT row (park it, let a cancel win, bookkeep an already-paused row, discard a lost race), so an outage must not read as "no row"; dropping the ref stops lease renewal and leaves recovery to the lease sweep.

- **Cleanup is the ONE unguarded store caller**: `cleanup_expired_tasks/1` calls `Store.select_cleanup_info/3` and `Store.delete_tasks/2` directly (no `StoreGuard`), so only its CALLERS' wrappers contain a store exit; it matches only `:ok` and `{:error, :disk_full}` and emits no PubSub event.
- **No per-row store loops on the hot paths**: the 60 s `:heartbeat` makes ONE `select_task_statuses/2` read plus AT MOST ONE `renew_leases/3` write for the whole `task_refs` set; boot reconciliation plus the one-shot `:lease_sweep` classify every candidate with ONE `Restart.classify/2`, then write the dirty pause per row through targeted columns; `sweep_fail_task/5` still adds a full `get_task/1` + full `put_task/2` for a genuinely failing row (usually 0–1 per sweep). All run synchronously inside the registry, so batching is what keeps the mailbox responsive.
- **`get_task/1` is the ONE in-registry full decode**: `{:get_task, id}` → `task_get/2` → `Store.get_task/2` runs UNOFFLOADED (as do the `:recheck_task` and `:finalizing` handlers), while `get_task_lite/1` — the same 20-column decode — IS offloaded.
- **Direct `EvoGit.Store` callers here**: `task_registry.ex`, `cleanup.ex`, `heartbeat.ex` and `store_read.ex` (plus `pause.ex`'s single `update_task_columns/3` write and its reads through `StoreRead`); `restart.ex` and `agent_state_read.ex` go through `StoreRead`/`AgentStateRead`; `lease.ex` and `diagnostics.ex` are ETS/Logger-only; `task_executor.ex` reaches Store only transitively via ResumeContext. The `agent_scheduler/*` `Store.` references are `EvoGit.AgentScheduler.Store`, a DIFFERENT ETS module.
- **`Store.get_task_status/2` is TRI-STATE and every consumer honours it**: `nil` = NO row (the only "absent" answer), a known status atom, or `{:unknown, raw}` = the row EXISTS with unreadable status text (already logged by `Codec.decode_status/1`). The heartbeat renews `{:unknown, _}`, `Lease.leaked?/3` never leaks it (the `select_running_lease_info/1` SQL filter also keeps such a row out of the sweep), `cancel_task/1`/`force_kill_task/1` answer `{:error, :not_running}` (never `:not_found`, and nothing is killed), `start_task` proceeds (fresh id), and the review casts write (only a missing row is their no-op). Every consumer logs the value through `log_unreadable_status/3`; none may collapse `{:unknown, raw}` into "absent".
- **Lightweight reads**: `list_tasks_page/1` → `Store.select_tasks_page/2` (16-key rows + `total`, no blobs; degrades to `%{rows: [], total: 0}`) and `get_task_lite/1` → `Store.get_task_lite/2` (the SAME full decode as `get_task/2`, `result`/`logs`/`usage` INCLUDED — NOT blob-free; degrades to `nil`).
- **Per-agent archive**: `put_task_archive/1` → `StoreGuard.write/2` around `Store.put_task_archive/2` (STREAMING), resolving the instance's store from `:evogit_task_registry_stores` and writing IN THE CALLER (the completing agent's process), so a multi-MB insert never holds the registry — there is no GenServer handler; the call stays SYNCHRONOUS and `Store.Writer` replies after the commit, so the row is durable before the agent returns and before the terminal status write, and the store mapping is deliberately NOT deleted on registry terminate (a dead store degrades to `{:error, :store_unavailable}`).
  `list_task_archives/2` → `Store.list_task_archives/3` (`%{entries: [], total: 0}` on fault; STRING-KEYED entries, `depth ASC, agent_id ASC` root first, `opts` forwarded unchanged: `:limit` default 100 clamped 1..1000, `:offset` 0, `:include_results`/`:include_settings` default `false` — the keys are then ABSENT, `:include_total` default `true` where `false` skips the `count(*)` and yields `total: nil`).
  `get_agent_archive/2` → `Store.get_agent_archive/3` is the lazy per-agent detail (includes `"result"`, degrades to `nil`); there is no task-wide archive reader. Deletes cascade EXPLICITLY (side table, no foreign key): `Store.delete_task_archives/2` → `Operations.Archives.delete_by_task/2`, `delete_by_tasks/2` (chunked) inside `Store.delete_tasks/2`, `delete_all/1` on a full clear; nothing archive-related rides `%Result{}` or the report.
- **Narrow reads over full decode**: `set_review_status`/`set_review_metadata`, `handle_update_status`/`update_task_status_with_caller`, `cancel_task` and `resolve_recheck_task` write through `update_task_columns/3`; the narrow read side is the ONE three-state `StoreRead` surface — `Store.select_task_update_info/2` carries the maintained `project_path` scalar (no `opts` decode for the path) and `Store.select_tasks_restart_info/2` is the batched row shape (id/status/type/opts/pause_kind/project_path) restart classification and `Pause.read_row/2` use. Still FULL-decode: `ResumeContext`/`MergeContext` via `TaskRegistry.get_task/1` (single-row paths that need `result`) and the `:finalizing` handler, which re-encodes the whole row through `put_task/2` to set ONE column.
  **Narrow-read rule**: a read whose value is a STATUS, a LOG field or a path takes the narrow projection; only a caller that needs the STRUCT (`result`, `opts`, the whole row) may full-decode, and a registry handler that can answer from the status column alone must do so before falling back to `task_get/2`. Applied: `prev_status/2` is a log-only status read through `StoreRead.status/2`, and `{:recheck_task, id}` reads the status FIRST (`:absent` → no-op, `:unavailable` → reschedule, terminal → no-op) and only then runs `task_get/2`.
- **Registry read offload** (`EvoGit.TaskRegistry.ReadOffload`): every large-decode read (`list_tasks`, `list_tasks_paginated`, `list_tasks_page`, `get_task_lite`, `list_task_archives`, `get_agent_archive`, `list_tasks_summary`, `list_tasks_summary_by_path`, `list_tasks_changed_since`) runs in a `Task.Supervisor.async_nolink/2` worker of the dedicated `EvoGit.TaskRegistry.ReadSupervisor` (separate from `EvoGit.TaskSupervisor`, so a scheduler restart cannot kill in-flight reads); the worker runs `StoreGuard.read/3`, allocates AND discards the decoded term, and replies to the caller with `GenServer.reply/2` itself, so the value never enters the registry heap — not even in transit (`get_unique_paths`/`list_task_ids` reply INLINE: tiny projections).
  The registry tracks in-flight reads in `state.read_offloads` (`ref => entry`): `{ref, :ok}` is ignored (the worker already replied), `:DOWN` `:normal` settles the entry, `:DOWN` with any other reason answers the caller with that read's DEGRADED value and logs at `:error`, and `{:read_offload_deadline, ref}` (`@deadline` 28 s, between the store's 25 s read deadline and the registry's 30 s call budget) kills the wedged worker with `Task.shutdown(…, :brutal_kill)` and answers the degraded value — a read NEVER exits or raises in the registry. Each call site keeps its exact degraded shape (`[]`, `{[], 0}`, `%{rows: [], total: 0}`, `%{entries: [], total: 0}`, `nil`); a failed worker START degrades the same way.
- **Cleanup SQL**: `cleanup_expired_tasks/1` reads only ids — age cutoff (`AND finished_at < ?cutoff`) and over-limit keys (`ORDER BY finished_at DESC LIMIT -1 OFFSET ?max_tasks`) pushed into SQL — then deletes via `delete_tasks/2` (chunked, all-or-nothing per chunk); both legs use the covering `idx_tasks_finished_at_id` index, with no row decode or Elixir-side sort/filter.
- **`select_running_lease_info`** SQL-filters `status IN ('running','pausing','awaiting_input','finalizing','cancelling')` (a `:pausing` drain must be reconciled too; `:paused` is deliberately absent — no lease, never reconciled or swept); callers still filter Elixir-side (`id not in owned_ids`, lease-expiry-vs-wall-clock; ISO-8601 fixed-precision ordering caveat: `../store/CONTEXT.md`).
- **Store-owned internals** (migrations, summary/`changed_since` APIs, JSON storage model, `mix store.maintenance`, disk-full classifier): `../store/CONTEXT.md`.

## Heartbeat, Restart Classification & `list_tasks/0` Bound

`EvoGit.TaskRegistry.Heartbeat.renew(store, task_ids, expires_at) :: :ok` is the WHOLE heartbeat body: `[]` ids is a no-op with no read; otherwise ONE `Store.select_task_statuses/2`, keep the ids whose status passes `Lease.lease_renewable?/1` (`:running | :pending | :cancelling | :awaiting_input | :pausing | {:unknown, raw}`), return `:ok` WITHOUT a write when nothing is renewable, else ONE `Store.renew_leases/3`.
`{:error, :disk_full}` logs exactly ONE warning naming the task COUNT; `{:error, :store_unavailable}` answers `:ok` (StoreGuard already logged it); a degraded/absent status read (`%{}`) renews nothing. The registry keeps `@lease_duration` and passes the ABSOLUTE `expires_at`.
`EvoGit.TaskRegistry.Restart.classify(store, task_ids) :: %{optional(id) => :dirty}` is the ONE restart classifier both recovery paths share: ONE `StoreRead.restart_info/2` read, keep the rows `Pause.dirty_pausable?/2` accepts (`:persistent_state` on, opts-only), ONE `AgentStateRead.roster_many/2` (batched 5 s bounded offload), and a row is `:dirty` only when one of that task's durable records is a ROOT RUN (`Pause.root_run?/1`, `fields[:parent_id] == nil`). A degraded read (`:unavailable` or `[]`) classifies NOTHING, so `init/1`/`:lease_sweep` fall through to the sweep-fail path (`:lease_expired` → `:failed`).
`init/1` and `:lease_sweep` call it ONCE for all their candidates and then only perform the targeted dirty-pause write (`park_dirty_pause/2`: `status: :paused`, `pause_kind: :dirty`, `finished_at` nil, lease nil) — one broadcast per persisted transition, AFTER the persist.
`Pause.pause_kind_for_restart/1,2` stays public and delegates `/2` through `Restart.classify(store, [task_id])` (tests use both arities).
`list_tasks/0` is bounded to `@list_tasks_limit` (100) rows, `started_at DESC`, decoded through `Store.safe_select_paginated_tasks/1`; the return shape stays `[%TaskInfo{}]`.

## Naming & Vocabulary Debt (open)

- **Interactive-session predicate has two implementations**: `Pause`'s private `interactive?/1` (atom AND string `:session_mode` keys) and `TaskExecutor`'s private `interactive_session?/1` (atom key only), beside `RuntimeOpts.session_mode/1` — one rule, three readings; a shared `RuntimeOpts.interactive_session?/1` should own it.
- **Persistent-state default-true rule has three spellings**: `Pause`'s private `persistent_state_on?/1` (non-raising, deliberately never `RuntimeOpts.persistent_state/1`), `RuntimeOpts.persistent_state/1` (raises) and `RuntimeOpts.admit_persistent_state/1`; the non-raising variant belongs in `RuntimeOpts`.
- **`resume_context.ex` re-implements `PrevTaskRepos.normalize_foreign_repos/1`** inline (`Enum.map(&ForeignRepo.normalize/1) |> Enum.reject(&is_nil/1)`); the two copies can drift.
- **`safe_store_read/3`/`safe_store_write/2` are one-line aliases of `StoreGuard.read/write`** that exist only inside the registry, while `pause.ex` and `read_offload.ex` call `StoreGuard` directly; delete the aliases.
- **`list_*` reads have four return conventions**: `list_tasks/0` → plain list (bounded 100), `list_tasks_paginated/1` → `{tasks, total}`, `list_tasks_page/1` → `%{rows:, total:}`, `list_task_archives/2` → `%{entries:, total:}`; every caller depends on its own shape, so each `@doc` names its own.
- **Lease vocabulary: four words for two facts** — "orphaned" (a wrapper-less row), "leaked" (`Lease.leaked?/3`), "expired" (the lease timestamp, error kind `:lease_expired`) and "stale" (an out-of-date update); use "orphaned" for the row condition, "lease expired" only for the timestamp, "stale" only for updates.
