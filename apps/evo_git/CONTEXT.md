# EvoGit — Core Runtime Application

## Intent
The `:evo_git` OTP application is an evolutionary software-development runtime: LLM agents create, analyze and modify codebases in isolated git worktrees, modeling a codebase as a **Context Tree** (spatial) and a **Phylogenetic Graph** (temporal) evolved through a DAG of commits.
Phases: **Genesis**, **Evolution**, and a repo-less **self-reflective** agent (`:reflect`), all on an LLM/tool slot-gated scheduler.
Task persistence (`EvoGit.Store`/`EvoGit.TaskRegistry`) lives here so the headless `genesis_server` daemon has full task history — detail: `lib/evo_git/CONTEXT.md`.

- **Background-job retention is observation-aware and owner-scoped** (`EvoGit.BackgroundJobs.Retention`, run on every accepted start and after a notice claim): a finished record a LIVE owner has not observed is never evicted by an ordinary cap, dead owners are trimmed first, observed records are capped per owner, and the global valve converts a still-unobserved record into a TOMBSTONE instead of deleting it — so `job/2`/`read/2`/`list/1`/`job_output`/`job_list` answer honestly and the ONE `[NOTICE]` survives, while `:not_found` is reserved for an id never issued; caps ride the `:retention` START option (no app-env key) → `background_jobs/CONTEXT.md` + `lib/evo_git/CONTEXT.md` § Background Jobs.

- **A background job inherits its task's tmpdir**: `BackgroundJobs.normalize_start_spec/1` resolves `tmpdir` (= `Sandbox.resolve_tmpdir/0`) and `task_tmpdir` (= the managed dir or nil) in the CALLER, and the registry uses them for both the log path and the detached command's `TMPDIR`/writable grant — so `[tmp] mode` + `reclaim/2` cover job logs and a job's `$TMPDIR` matches its own task's foreground tools; a caller with no tmpdir installed falls back to the system tmpdir with no env override, and a reclaimed task dir yields reclaim prose from `read/2` (never a status change or `:not_found`) → `background_jobs/CONTEXT.md` + `sandbox/CONTEXT.md`.

## PubSub Event Contract (event-driven dashboard)

All dashboard-visible state changes are PUSHED on `EvoGit.PubSub` (Phoenix.PubSub PG2, cluster-aware); every message carries the emitting `node` last and subscribers MUST ignore other nodes' messages for node-local state. Emitter detail: `task_registry/CONTEXT.md`.

## Provider Profiles & Concrete Model Selections

Canonical config selects an account with `[llm] default_provider_profile` in `[[llm.providers]]` (first account when no selector is given); the account owns a stable `id`, `provider`, shared auth (`auth_mode`, `api_key_env_var` or `oauth_file`), endpoint, `concurrency` and peak/off-peak schedule for its ordered `models`, and `LLM.profile_generation_params/1` is the single generation/auth/constraint boundary.
The effort ladder is `Schema.LLM.reasoning_efforts/0`, re-exporting `ReasoningEffort.levels/0` (`[:none, :minimal, :low, :medium, :high, :xhigh]`, ascending, NO `:max`) with `reasoning_effort_options/0` adding `:default`, `allowed?/1` and `canonical_reasoning_effort/1`; `max` is a read-only legacy ALIAS for `xhigh`, and a provider's documented spelling is emitted only at the request boundary (`LLMConstraints`'s `:reasoning_effort_wire_aliases`).
A task `model_spec` is a STRING-keyed identity map (`provider_profile_id`, `model`, optional `reasoning_effort`) — never credentials; the schema's resolved `model_spec` is the ReqLLM-ready qualified string or endpoint-override map, stored by dispatch as effective `llm_model` with `llm_generation_params`, `llm_context_window` and the canonical selection. `provider_profiles/1`, `model_selections/1` and `resolve_model_spec/2` are the inventory/resolution APIs.
Explicit invalid selections fail closed before registration; a locked parent selection overrides child picks and scripts with the ENTIRE identity while unlocked children inherit it as `default_model_spec`; legacy `[[llm.models]]`, flat `[llm] model` and legacy selection ids stay supported (one-for-one account normalization, canonical wins, saving strips legacy mirrors); Auto submits no selection at all, an explicit one is validated and sent as `model_id_locked: true`.
`Config.config_status/0` combines presence with validation errors and `SystemCheck` resolves selections through Schema before testing — full contracts: `config/` + `config/schema/`.

## Custom Agents & Model Selection

`<config_dir>/agents.toml` defines name/prompt, read/read_write authority, delegation level, optional turn cap, tools/subagents whitelists and an optional canonical `model_spec` (legacy `model_id` fallback); `CustomAgents` normalizes keys/efforts, rejects malformed definitions with `:invalid_model_spec` on save, is alias-aware for tools and `reload/0` invalidates caches.

## Multi-Modal Content (objective, tool results, injected messages)

Media (images/audio) rides LLM content parts at THREE sites; wire contract `EvoGit.Attachments` (`attachments.ex`), structured output `EvoGit.Agent.ToolOutput` — detail: `agent/` + `store/`.

- **Shape + caps**: STRING-keyed `%{"type" => "image"|"audio", "name" => basename, "media_type" => IANA, "data" => base64}`; base64 is MANDATORY at every data-plane boundary because `Store.Codec` Jason-encodes whole opts; decoding happens ONLY at materialization (`Attachments.to_content_parts/2` → `[ContentPart.text(text) | media parts]`, NEVER `ReqLLM.ToolResult`); `Attachments.message/1` is the ONE normalizer; ≤ 4 per message, each ≤ 15 MiB RAW (`EvoGit.Attachments` attributes are the single source); malformed payloads raise `ArgumentError`.
- **Site 1 — `:attachments` task opt (root-only)**: the ROOT's FIRST user message (`ContextBuilder.build_initial_messages/4`, gated on `parent_id == nil`); Genesis Mode A, both Mode B roots and the Evolve root receive it, Reflect never; `RuntimeOpts` → `Attachments.validate/1`.
- **Site 2 — tool results (any agent, any turn)**: `Tools.execute/5` returns `String.t() | ToolOutput.t() | {:error, reason}`; `agent/tool_dispatch.ex` is the SOLE **wrap boundary** — sanitize/truncate + hints touch the TEXT component only, media is re-wrapped, error/timeout/crash paths stay plain strings.
- **Site 3 — injected user messages (NO root gate)**: `send_user_message/2`, `send_session_message/3`, `RemoteAPI.send_agent_message/2`, `RemoteNode.send_agent_message/3` accept `String.t() | %{text:, attachments:}`; `Store.append_pending_user_message/2` stores shape-for-shape in the `ControlPlane` inbox, materialized by `ContextBuilder.build_injected_message/2`.
- **Invariants**: a plain-string tool result and a legacy string pending message behave BYTE-IDENTICALLY to pre-media behavior (struct-equality pin: `test/evo_git/agent/tool_output_pipeline_test.exs` + `tool_output_integration_test.exs`); compression keeps `[system, first_user]` BYTE-IDENTICALLY (attachments re-sent after every compression) and the last K turns VERBATIM while OLDER tool-result media collapses into `[... tool result media omitted ...]`; resume / merge-auto-resolve / GitHub-fix follow-ups do NOT re-carry `:attachments`.
- **Plumbing only, no gate**: no built-in tool returns media (`read` is text-only, no `read_image`/`screenshot`, `web_fetch` renders non-text as `[binary content omitted: …]`, custom tools are STRING-ONLY) — only the test seam app env `:evo_git, :tool_dispatch_test_tools` and the dashboard (`EvoDash.AttachedFile`) produce it; nothing checks the selected model, so a text-only model answers HTTP 400 → `Agent.LlmError.non_retryable?/1` → fail-fast `{:llm_request_rejected, message}` → `:failed`, and audio is nominal (a `:file` part, expected to be provider-rejected).

## Multi-Repo Read-Write Foreign Repos

Foreign repos may be **writable** — still ONE primary repo + one final report per task; foreign modifications are tracked but NEVER merged back by the task (the review page merges/rejects). Detail: `agent_scheduler/CONTEXT.md` + `task_registry/CONTEXT.md` + `core/` + `runtime/`.

- **Data model** (`Core.ForeignRepo`): `writable: boolean()` (default `false`) + `base_sha: String.t() | nil` (`nil` = foreign HEAD); a task `:foreign_repos` entry stays READ-ONLY unless `genesis.toml` marks the repo `writable` (TOML-only).
- **Registry**: no `[[repos]]` table in `config.toml`; the declared set is per-project `[foreign_repos.<id>]` (`ProjectConfig.foreign_repos/1`: TOML key IS the id, `path` required, `description`/`writable`/`base_sha` optional), merged id-keyed with the task opt by `Runtime.Helpers.load_foreign_repos/2` (a task entry wins per id, never removes a TOML entry); existence/git-repo/`base_sha`/UNC validation is runtime-only and raises `ArgumentError`.
- **Spawn gate** (`Subagents.validate_spatial_contract_for_spec/3,4`): read-only cross-repo spawns UNRESTRICTED at any depth; `:read_write` cross-repo spawns need `writable: true` (`{:foreign_repo_read_only, msg}`), are **root-only** (`{:foreign_repo_write_not_root, msg}`) and **one per batch** (`{:foreign_repo_write_serialized, msg}`); same-repo spawns inside a foreign repo are UNRESTRICTED, and the role comes from id-matching `spec.foreign_repos`, NEVER the path.
- **Tool gating**: `Tools.execute/5` chains `maybe_block_read_only_foreign_repo/5` after `maybe_block_repo_less/5` (blocks every `@write_tools` entry incl. `run_git`), `Shared.validate_file_scope/3` rejects write targets inside one, and `Tools.read_only_schemas/0` = read tools + Context write/edit + ShellTool + `WebFetch` + `Lsp` (only when `Config.lsp_enabled?/0`).
- **Roots + report** (`Runtime.Helpers.merge_and_report/3,4`): writable repos get worktree roots like the primary with ONE branch name per task reused across all; the report gains top-level **`repos: %{repo_id => %{commit_sha, branch_name}}`** (STRING keys: `"primary"` always, each writable repo that committed, read-only ABSENT), while top-level `commit_sha`/`branch_name`/`result` stay the PRIMARY's, from `Result.foreign_repo_commits` rolled up by `Lifecycle.inject_foreign_repo_commits/2` + `store_sub_result/3` (child-wins).
- **Per-repo review**: `TaskCommitGraph` resolves a base from `opts[:foreign_repos]` (`foreign_base_for/2`) and walks `result["repos"]`, while `Review` stays repo-path-parameterized (`merge_branch/2,3`, `reject_branch`, `check_merge`); `maybe_init_repo/3` wipes `.genesis/workers` + `clean_orphaned_branches` and runs the init script ONLY for the primary.
- **Read view**: a persistent foreign worktree at `<root>/.genesis/foreign_repos/<id>` (`ForeignRepo.worktree_path/1`), reset at task start (`ForeignWorktree.ensure_all/1`) and advanced by `Agent.Runner.run/3` `try/after` → `sync_from_agent/0`; never moves MAIN HEAD, kept at task end.
- **Merge seeding**: `resolve_foreign_repo_starting_commit/2` = `base_sha` else foreign HEAD; phylo precedence = task `base_sha` → tracked `foreign_repo_commits` → foreign HEAD; `apply_merge_context/4` and `apply_resume_context/3` both override each `base_sha` from the previous task's `repos[repo_id]["commit_sha"]` (shared `TaskRegistry.PrevTaskRepos`).
- **Prompts**: `:read_write` foreign spawns are ROOT-ONLY + ONE-AT-A-TIME; `PromptFragments.writable_foreign_repo_clause/0` is role-agnostic (nested agents report upward) and each agent's role is stated in its FIRST-USER context by the pure `ContextBuilder.build_authority_section/1`.

## Self-Reflective Agent (repo-less)

A **repo-less** Assistant with no repository or worktree uses tiered Elixir evaluation to inspect runtime state, control tasks and show transient guides. Detail: `runtime/` + `agents/` + `agent/tools/elixir_eval/CONTEXT.md`; the interactive `/assistant` variant is summarized in the root `./CONTEXT.md`.

- **Task type**: `:reflect` — `TaskExecutor.execute_task(:reflect, opts, task_id)` → `Runtime.SelfReflective.run(opts ++ [task_id: task_id])`; mode `"reflect"`; opts `objective`, optional `model_spec`/`model_id`, `model_id_locked`, `source_root`, `task_id`, **NO `:path`**; result `{:ok, %{result: summary, commit_sha: nil, branch_name: nil, tag: nil}}`.
- **Visibility**: an ordinary `tasks` row (persisted `:running`, leased, settled by `handle_wrapper_result/3`, graceful cancel → `:cancelled`), so it appears in list/summary/page/lite and `/server/status`; hiding it and refusing review are caller/UI decisions (`EvoDashWeb.NodeAware.show_review_button?/1`).

- **Capabilities**: `Agents.SelfReflective` (`agent_type :read`, `delegation_level :low`, `subagent_modules []`) exposes `read`, `rg`, `glob`, `list_dir`, context/history readers, `web_fetch`, config-gated `web_search` and tiered `elixir_eval` — no shell, no file writes, no `run_command`, no subagents.
- **`elixir_eval`**: read/write are Dune-interpreted with explicit module/function/arity grants (projected facades optional); write needs exact-code approval and admits task lifecycle, runtime scheduler updates, `Config.save_user_config/1` and explicit `AgentScheduler.RemoteAPI.reload_config/0`; sudo needs separate approval for unrestricted native Elixir (full VM authority, not a sandbox); refusals never trigger escalation.
- **Live + persistence**: no `:finalizing` broadcast; `Agent.Stream.watch/1` pushes `{:agent_delta, agent_id, seq, events}` (snapshot + `seq` is the only resync) and a completed transcript is fetched once via `get_agent_history/1` — **history is gone once the session ends**, and the persisted artifact is `task.result` with no `resume_from`; multi-message chat is an interactive session (`Runtime.Assistant` + `send_session_message/3`).

## LLM Concurrency & Slot Gating

LLM pools are keyed by immutable `provider_profile_id`, so every model/effort selection in an account shares concurrency and exhaustion backoff while distinct accounts stay isolated (historical field names `model_concurrency`/`llm_backoff_until` hold account ids on the canonical path).
`AgentScheduler.with_llm_slot/2` blocks in a purgeable `:infinity` call, capacity-zero requests enqueue, `default_llm_max_concurrency` is a floor/fallback rather than a global cap (an explicit zero pause is preserved), runtime updates preserve live holders/waiters/backoff, and rate-limit/insufficient-balance failures report growing account-shared backoff via `report_llm_error/3` (agents park in the queue, never sleep).
`ReqLLMPool` sizes HTTP capacity once per account (never multiplied by nested model/effort choices) and reconciliation is grow-only; slot/retry/reload contracts: `agent_scheduler/` + `agent/`.

## Peak/Off-Peak Hour Concurrency Scheduling

Accounts own `peak_concurrency`, `peak_hours`, `off_peak_days`, `off_peak_holidays` and `timezone`, with `peak_concurrency = 0` a hard pause shared by all their models/efforts and exempt from the default-concurrency floor.
`EvoGit.PeakHours` is the single source of truth for half-open/overnight/day-scoped windows, the off-peak-day rule, wall clocks, validation and transition math: a date is off-peak when its weekday is in `off_peak_days` OR (`off_peak_holidays` names a calendar AND `PeakHours.Holidays.non_working_day?/1`), so a statutory CN holiday, a weekend and a 调休 make-up Saturday resolve through the same predicate.
`PeakHours.Holidays` is a static 2025-2027 table (extend yearly), NOT a dependency, to avoid `mix.lock`/`mixFodDeps.hash` churn; `PeakHourEngine` prefers canonical profiles, falls back to legacy only when no canonical account exists, and applies one floored concurrency entry per account; `Config.ProviderPresets` ships the built-in presets (DeepSeek off-peak discount, Z.AI GLM coding plan) as pure data — API detail (`in_peak?`, `next_transition`, `effective_concurrency`): `config/` + `agent_scheduler/`.

## Agent Loop Control Flow + Graceful Task Cancellation

**Loop injection point**: `EvoGit.Agent.Exchange` drains the session inbox at the top of each turn (after compression/limit warnings, before the LLM call); `ControlPlane.drain_messages/1` yields turn-tagged user messages appended to the conversation.
API chain: `EvoDash.NodeContext` → `RemoteNode.send_agent_message/3` → `RemoteAPI.send_agent_message/2` (guards `{:error, :scheduler_not_started}` when `:evogit_agent_summary` is undefined) → `AgentScheduler.send_user_message/2` → the `ControlPlane` inbox append, returning `:ok | {:error, :not_found}`; interactive conversations use `send_session_message/3` → the session's `:input` command.

**Two cancellation actions** (node-aware via `RemoteNode.cancel_task/2` + `force_kill_task/2`):
- **Graceful cancel** (`TaskRegistry.cancel_task/1`): `:pending` → immediate `:cancelled`; `:running`/`:awaiting_input` → `:cancelling` + `{:cancel, :graceful}` (the session appends a save-work user message through the inbox, records the cancel flag in `:evogit_agent_control`, plus an `:evogit_cancelling_tasks` marker). The loop enters cancel-grace with a **3-turn budget** (a recovery auto-commit first); the final status persists `:cancelled` WITH result/usage/archive **preserved**. `:cancelling` is non-terminal + idempotent and blocks new root spawns (`{:error, :cancelled}`).
- **Force kill** (`force_kill_task/1`): kills the in-flight exchange worker, stops the session and wrapper, persists **`:failed`** with result nil'd, from `:running`, `:awaiting_input`, `:pausing`, `:paused` and `:cancelling`; `:cancelled` means ONLY gracefully-cancelled tasks.
- **Task pause** (`pause_task/1`/`resume_task/1`): the NON-terminal `:pausing` (freezing, wrapper alive, lease renewed) and `:paused` (resting, resumable IN PLACE through the same task id) — protocol, restart mapping, dashboard buttons and archive rules: `task_registry/CONTEXT.md`.
  A pause FREEZES the whole tree (`AgentScheduler.begin_task_pause/1` + `EvoGit.AgentScheduler.TaskFreeze`, quiesce 120 s / force grace 10 s): every parent blocked in `spawn_sub_agents/2` is parked, each agent stops at a turn boundary after checkpointing, NOBODY is answered until the last pending agent reports (or the quiesce force-freezes the leftovers), and that ONE task-level term reaches the ROOT's caller — no child ever fills a parent batch or merges.
  `TaskRegistry.persist_paused/3` DERIVES `pause_kind` from that report through `Pause.pause_kind/1` (`:clean` only when every agent proved `clean_freeze: true` and `durable: true`; `:dirty` for a forced freeze, `durable: false` or `clean_freeze: false`), so a resumed `:dirty` run gets the crash repair it needs — detail: `agent_scheduler/CONTEXT.md` §Cancellation & Task Pause + `agent/session/CONTEXT.md`.
  The restart→dirty-pause verdict has ONE batched implementation, `EvoGit.TaskRegistry.Restart.classify/2` (two reads total), shared by boot reconciliation in `TaskRegistry.init/1` and the one-shot `:lease_sweep`; the pause REQUEST never reads durable state (option facts only), while resume and restart classification both gate on the durable ROOT row of the shared `EvoGit.AgentState.Snapshot` (the resume restores the whole frozen tree from its own rows).

## Update-Timing Safety

No restart/update machinery exists in `:evo_git` (zero `System.restart`/`:init.restart`/`:init.stop`, no signal handlers, no exit checkpointing); graceful stop comes from `:evo_dash` (`DesktopQuit.default_stop/0`, SystemLive Stop — both `System.stop/0`), and the Rust shell NEVER sends SIGTERM (its watchdog uses SIGKILL). `bin/<release> stop`/`restart` need `RELEASE_DISTRIBUTION != none` + a resolvable `RELEASE_NODE`, so the non-distributed desktop sidecar must be stopped from within; the pre-restart mechanism is **graceful cancel** (3-turn grace, NOT wall-clock bounded).
Idle detection: `TaskRegistry.list_task_ids/1`, `list_tasks_summary/2`, `list_tasks_changed_since/1`, `get_task/1` (+ RemoteAPI/RemoteNode mirrors); in-flight set `[:running, :pending, :finalizing, :cancelling]`.
Task status lives ONLY in SQLite (`tasks.status`); scheduler ETS holds summary/control rows plus sched_meta for LIVE agents (never the conversation) and dies with the app, so a BEAM restart fails any `:awaiting_input` session and reclaims its worktree. Lease: `@lease_duration` 120 s, heartbeat 60 s renewing `[:running, :pending, :cancelling, :awaiting_input, :pausing]` (not `:finalizing`, never `:paused`); the one-shot `:lease_sweep` at 150 s fails an orphaned `:running` row only when the lease is invalid AND no live sched_meta agent exists.
Startup reconciliation: `:finalizing` → `:failed`, `:cancelling` → `:cancelled` (result preserved), a RESUMABLE `:running`/`:pausing` row → `:paused` + `pause_kind: :dirty` (else `:running` untouched).
In-place resume restores the durable ROOT of the SAME task id, while the Review page's `resume_from` remains a NEW `:evolve` task (`ResumeContext`).

## Constraints

- Part of an **umbrella project** — deps, artifacts and lockfile at the repo root; Elixir ~> 1.18; **Git CLI only** (no libgit2); no source at root, all code under `./apps/`, subdirectories as `./lib/evo_git/<subdir>/` ↔ `EvoGit.<Subdir>`.
- All git operations go through `EvoGit.Adapters.Git` (or `Shared.commit_files/4` → `EvoGit.sandbox_run`); no direct `System.cmd("git", ...)` in domain modules (exception: GitEnv's config reads).
- `remote_api.ex` and `remote_node.ex` are intentionally long cohesive RPC wrappers — do NOT split them; add new RPC functions there (`defnode` from `EvoGit.RemoteNode.Defnode` for identity-unwrap wrappers, hand-written per-function fallbacks otherwise).
- Agents are transient modules using the `EvoGit.Agent` behaviour; framework state lives in ETS; execution happens in **isolated git worktrees** managed by `AgentScheduler.WorktreeManager`, never on the main working copy; agents commit before delegating subagents (auto-commit fallback enforced by the scheduler).
- **Three-level configuration** (`EvoGit.Config`): built-in defaults → user config (`~/.config/genesis/config.toml`, XDG) → runtime overrides; **no default model or username is hardcoded**.
- **Slot discipline**: LLM calls acquire/release account-shared slots via `AgentScheduler`, binding immutable `provider_profile_id` independently of the concrete `model_spec`/`llm_model`; the `[[llm.providers]]` account owns concurrency/peak/backoff and shared auth/endpoint defaults, and nested inventory creates no additional pools; legacy `llm.models`/flat config and `model_id` stay compatibility inputs; locked children inherit the full canonical selection.
- **Task-scoped naming**: worktree dirs `worker_T<task_number>_A<task_local_id>`, branches `evogit-agent-T<task_number>-A<task_local_id>`; `task_id` = 16-char hex GUID, `task_number` = short integer from a linear scan of `.genesis/workers/` (naming only). The owning repo root is derived from a worktree PATH by the one literal split `String.split(path, "/.genesis/workers/", parts: 2)` (`agent_scheduler/worktrees.ex`, `repo_root_from_worktree/1`); a path outside `workers/` returns unchanged, so repo identity is inferred from path SHAPE. Foreign-repo agents resolve their root by ID lookup in `spec.foreign_repos` — one repo root + one worktree per agent.
- **VCT is metadata, never a filesystem**: mount points are virtual and listable even when a mount's OS path is missing (that is what makes a project list portable); the mount table is machine-local `vct_mounts` rows in `tasks.sqlite` holding project mounts, uncapped one-level workspace mounts (no OS path, ordered members) and reserved system mounts; the global context's git repo is initialized lazily only while that context is non-empty.
- **Task persistence runs in `:evo_git`** — `Store` + `TaskRegistry` sit in the supervision tree, so the `genesis_server` daemon has full task history; a freshly-started Registry leaves orphaned `:running` rows to the lease sweep; test isolation pins `config :evo_git, :data_dir` to a UNIQUE per-run temp path in `config/test.exs`.
- **Task Archive (opt-in)**: the `:archive` opt → `runtime_opts` → `AgentSpec.opts` → `%State{}.archive`; each completing agent writes `refs/genesis/archive/T{task_id}-A{agent_id}-start`/`-final` + a usage git note + ONE `task_agent_archives` row streamed at completion (idempotent upsert on `(task_id, agent_id)`). No buffer, nothing in `%Result{}`/report; CRASH/FAILURE/ABORT writes NO row (usage LOST, a retry resets to `Usage.zero()`); Genesis Mode B shares one `task_id` → exactly 2 nil-parent rows; JSON keys are `input_cost`/`output_cost`/`total_cost`, never `cost`.
- **Distribution & releases**: EPMD-less via `-epmd_module Elixir.EvoGit.EpmdDist` + `-start_epmd false` in all `rel/vm.args.eex`; daemon port 9000; releases `genesis`/`genesis_desktop`/`genesis_server` in the root `mix.exs`; prod-only `PORT`/`PHX_IP` → `[server] listen_port`/`listen_ip` (default 9999); zombie prevention via dynamic port + `EVOGIT_LIFETIME_PORT` — detail `lib/evo_git/CONTEXT.md` + root `./CONTEXT.md`.
- **SSH remote bootstrap** (remote commands are argv arrays, never quote-wrapped spawn strings: `run_ssh_command/4` = `{:spawn_executable, ...}` + one argv element wrapped by `sh_wrap/1` as `/bin/sh -c '<script>'` — no `/usr/bin/env`, no bash (stock NixOS lacks the former while `/bin/sh` is POSIX-mandated); remote scripts are POSIX sh and single-quote-free so fish/nushell/tcsh logins pass through; seam `:remote_shell`; the daemon is the `genesis_server` release and ALL its lifecycle — systemd scope/unit, launchd plist, setsid fallback, readiness wait — is delegated to `bin/genesis remote start|stop|status|logs`; NixOS patching only while the daemon is stopped): detail `lib/evo_git/CONTEXT.md`.
- **Config caching is RAM-resident and event-refreshed** (`EvoGit.Config.Cache`: ONE `:persistent_term` snapshot per config dir — user config + credentials + resolved map + validation errors + fingerprint — so `resolve/0,1` is a term lookup with no stat/merge/validate; `save_user_config/1`/`save_credentials/1` raise `Watcher.notify_change/2` synchronously (total and bounded: a `nil`/dead/slow watcher falls back to the same guarded reload), the SAME handler the watcher's ~150 ms debounced file event runs, bumping `generation` and broadcasting `{:config_reloaded, node, dir, generation}`; `RemoteAPI.reload_config/0` forces a re-read; the ACTUAL runtime cache is AgentScheduler state, so a save does not apply scheduler settings; `RemoteConnections.list/0` creates the skeleton `remote_connections.toml` on first access via `ensure_file/0`, a total non-raising call that never overwrites an existing file and returns `[]` with one warning per `{path, reason}` failure identity when creation fails) — detail `config/`.
- **Genesis Mode B** (`Genesis.run_new_codebase/4`): Phase 1 `Agents.Architect` → Phase 2 `Agents.Manager` (second root from the architect's final commit); both share ONE `task_id` and merge usage/`agent_count` into a single `%Result{}` → `merge_and_report/3`; Architect fails → immediate error, Manager fails → architect's result as partial success; Mode A (`ContextExtractor`) uses one root.

## Backend Boot Profile (desktop sidecar readiness)

Boot work in `:evo_git` is CONSTANT-COST: nothing keyed to the release version or install path, and no lockfile/`.genesis/` marker/cache verification/release-tree read at start.
Ordered `EvoGit.Application.start/2` work: (1) the 4 ETS tables; (2) `Distribution.maybe_enable/0` (logs and returns `{:error, _}`, never raises); (3) `Calendar.put_time_zone_database(Tz.TimeZoneDatabase)`; (4) children: PubSub → **`Config.Watcher`** (skipped in `:test`; its `"config"` broadcasts need PubSub) → Throttle → CommandApproval → RemoteConnection Registry/Supervisor → **`Store`** → `Store.Maintenance` → **`VCT`** (`{EvoGit.VCT, system_mounts: EvoGit.SelfReflectiveSource.system_mounts()}`, after `Store`, before `TaskRegistry`) → TaskRegistry ReadSupervisor/ProcessRegistry → TaskRegistry → BackgroundJobs → WorktreeManager → AgentGroupSupervisor (Task.Supervisor → **`EvoGit.CatalogWarmup`** → AgentScheduler) → PeakHourEngine → SystemSampler, plus SandboxProcessRegistry + SandboxSlice on Linux; `CatalogWarmup` sits immediately before the scheduler.
The ONE potentially slow child is `Store`, whose `init/1` runs migrations before any read/write (`Store.Boot.start_dynamic/2`); `TaskRegistry.init/1` then does a synchronous `Store.select_running_lease_info/1`.
**Boot-fatal paths** (a child EXIT ⇒ "Genesis backend unavailable"): an unwritable/missing data dir (`File.mkdir_p!` raises), a failed repo open (`{:stop, {:failed_to_open_sqlite, reason}}`), or ANY raise out of the migration run (baseline post-condition `Ecto.MigrationError`, bad `tasks` shape, `SQLITE_BUSY`, corrupt file); with `start_permanent: Mix.env() == :prod` a terminating permanent app takes the VM down.
`Store` opens with `journal_mode: :wal` + `default_transaction_mode: :immediate` + `busy_timeout: 30_000` (a locked `tasks.sqlite` stalls a statement up to ~30 s in the calling process) and WAL needs `-wal`/`-shm` sidecars.
**Observability**: no boot phase logs of its own — only Ecto.Migrator's lines (`Store.Boot` has ZERO Logger calls), `Config.resolve/0` warnings, the `PeakHourEngine … wakeup reason=:boot` pair and Linux `SandboxSlice` warnings.
**Boot lines CAN repeat inside ONE OS process**: a `Store` crash re-runs `init/1`, and `System.restart/0` re-boots every application inside the running node (only caller: the dashboard System page → `EvoDash.NodeContext.restart_remote/1`). No supervisor declares a restart intensity (OTP default 3/5 s); exceeding it terminates the supervisor and, `evo_git` being `:permanent`, the node — the Rust watchdog respawns a NEW OS process. `<data_dir>/logs/backend.log` is configured in the ROOT `config/runtime.exs` (10 MB × 5), so nothing in `:evo_git` writes/truncates/rotates/deletes there; port resolution / orphan prevention: root `./CONTEXT.md`.

### Boot memory profile
- The five app-owned ETS tables are created EMPTY (one boot insert: the registry's store pid); no boot child loads task rows (`TaskRegistry.init/1` reads lease info only, `AgentScheduler.init/1` reads NO SQLite) and `VCT.init/1` does exactly ONE mount-table read kept as its cache.
- The SQLite page cache is per-connection and LAZY (`Repo.start_opts/0`: `cache_size: -8_000` × `Boot.default_pool_size/0` = 6, a ~48 MB steady-state ceiling but ~0 at boot).
- The ONE eager multi-megabyte boot allocation is the LLMDB catalog, and it must land in a THROWAWAY process: `EvoGit.CatalogWarmup` resolves the configured profiles in its own short-lived process (`Schema.llm_generation_params/1` → `model_metadata/1` → `ReqLLM.model/1` → `LLMDB.ensure_loaded!`, decoding the 11.7 MB packaged snapshot into `:persistent_term`), so its transient heap dies there; a provider STRING resolves through `@known_providers` (`LLMCatalog.providers/0`, required because `Schema.LLM.catalog_key/1` uses `String.to_existing_atom`), and the warm-up is skipped when no model is configured.
- Measured: with the warm-up the scheduler holds KB-scale heap (~29 KB at boot); without it ~92 MB of dead catalog heap survives for the whole BEAM. Steady state ≈ RSS 396 MB embedded / 177 MB interactive; **boot peak is VmHWM ≈ 770 MB (0.6-0.9 GB in every mode)**.
- Probes: reach a running node with `elixir --name probe@127.0.0.1 --cookie <cookie> -e ':erpc.call(…)'` and read `:persistent_term.info/0`, never `get/0` (copies EVERY value); booting from an agent shell needs `[sandbox] mode = "disabled"` (`SandboxSlice.init/1` stops `evogit.slice`, which that shell lives in), `bin/<release> eval` starts no applications, and migrations read blobs only on an UPGRADE (one result set / one row at a time, the `[{version, module}]` source compiled once and memoized in `store/boot.ex`).
- Runtime (NOT boot) growth lives in the conversation, in the session's own heap (`:evogit_agent_summary` carries only the summary projection, removed at session end); CPU-only side effects: `BackgroundJobs.init/1`'s async `Sandbox.Background.sweep_stale_units/0` and `SandboxSlice.init/1`'s slice stop + 100 ms sleep.

## Known Issues

- **Whichever process first touches the LLMDB catalog on a fresh BEAM pays the whole load in ITS OWN heap — so at boot that process must be a throwaway one.** `:llm_db` lazily loads `priv/llm_db/snapshot.json` (11,693,807 B, 239 providers, 10,100 models) on the first query, decoding the JSON, building indexes and canonicalising the catalog for a `term_to_binary` digest in the caller's heap; `:persistent_term` READS never copy, so the retained MBs are dead garbage awaiting a fullsweep, NOT live state — never let a LONG-lived process be the first toucher.
- **Process/thread exhaustion inside containers breaks git forks (EAGAIN).** In rootless podman every process shares the host user's UID, so the per-UID `RLIMIT_NPROC` (`ulimit -u`, counting every OS thread) spans container + host; when hit, `fork()` fails with `EAGAIN` and git prints "cannot fork() ... Resource temporarily unavailable" (e.g. in `git worktree add`). `WorktreeManager` survives (persistent init marker + re-monitoring) but runs lose agents to crash-retry. Prevention: raise the HOST user's nproc limit (`/etc/security/limits.conf` or `systemctl --user set-property user.slice TasksMax=infinity`), `--ulimit nproc=65536:65536 --pids-limit -1` (`pids_limit` + `default_ulimits` in containers.conf), delegate the pids controller (`[Service] Delegate=cpu cpuset io memory pids`), verify `ulimit -u` / `/sys/fs/cgroup/pids.max`, or reduce concurrency.
