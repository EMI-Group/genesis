# EvoGit — Core Runtime Application

## Intent
The `:evo_git` OTP application implements an evolutionary software development runtime where LLM-powered agents create, analyze, and modify codebases using git worktree isolation. It models a codebase as a **Context Tree** (spatial dimension) and a **Phylogenetic Graph** (temporal dimension), evolved through a DAG of git commits. Two-phase execution — **Genesis** (create a codebase from a prompt) and **Evolution** (modify an existing one) — plus a repo-less **self-reflective** agent (`:reflect` task type) and an LLM/tool slot-gated scheduler. Task persistence (`EvoGit.Store`/`EvoGit.TaskRegistry`) lives in this app so the headless `genesis_remote` daemon has full task history.

### SSH Remote Development
Genesis supports SSH remote development (VSCode Remote-SSH-style): a headless `:evo_git` daemon (`genesis_remote` release) runs on a remote server; the local Phoenix dashboard controls it over an SSH tunnel via Erlang distribution. Foundation modules: `EvoGit.RemoteConnections` (TOML SSH-target store), `EvoGit.RemoteConnection` (bootstrap + connect lifecycle), `EvoGit.EpmdDist` (EPMD-less distribution), `EvoGit.Distribution` (on-demand distribution), `EvoGit.AgentScheduler.RemoteAPI` + `EvoGit.RemoteNode` (RPC surface). Full detail: `lib/evo_git/CONTEXT.md`.

### Remote Bootstrap Asset Format
The SSH remote-bootstrap asset is **`.tar.xz`**: `genesis_remote_<platform>.tar.xz` (never suffixed — glibc is the default and ONLY published Linux variant; the musl build is disabled). Uploaded per platform by `.github/workflows/build-desktop.yml` (linux_x64 / linux_arm64 / darwin_arm64 / windows_x64). Extracted with `tar -xJf` — no gz fallback (xz failure fails loudly). On NixOS hosts the glibc-only asset runs via on-the-fly patchelf patching during bootstrap. Detail: `lib/evo_git/CONTEXT.md` + `.github/workflows/CONTEXT.md`.

### SSH Tunnel Readiness (connect-path invariant)
`RemoteConnection.do_connect_distributed/1` polls the local forwarded port (`wait_for_tunnel/4`, 100ms interval, 10s budget) BEFORE `Node.connect/1`; no remote-daemon log entry for a connect attempt ⇒ tunnel/port race; "Invalid challenge reply" in the daemon journal ⇒ cookie mismatch. `connect/1`'s GenServer call timeout = wait budget + 15s. Full invariant: `lib/evo_git/CONTEXT.md`.

## PubSub Event Contract (event-driven dashboard)

All dashboard-visible state changes are PUSHED on `EvoGit.PubSub` (a Phoenix.PubSub PG2 cluster-aware instance — broadcasts on a remote daemon node reach local subscribers; `EvoGit.RemoteNode` is RPC-only and needs no pubsub changes). Every message carries the emitting BEAM `node` as its final element. **Node-identity filtering rule**: subscribers MUST ignore messages whose node ≠ their own `node()` when the payload is node-local state (task/agent ids are per-node; TaskRegistry's `{:task_updated, id, :finalizing, node}` handler is guarded `when node == node()`). Emitter-side detail: `lib/evo_git/task_registry/CONTEXT.md`.

| Topic | Message | Emitted by | Notes |
|---|---|---|---|
| `"tasks"` | `{:task_updated, task_id, status, node}` | TaskRegistry mutations; `Runtime.Helpers.notify_finalizing/1` | status = the task's CURRENT status after the mutation (`:pending \| :running \| :finalizing \| :cancelling \| :completed \| :failed \| :cancelled`), `nil` for review-status/metadata updates. No broadcast on stale/no-op/missing-row updates; heartbeat stays silent (event-storm avoidance) |
| `"tasks"` | `{:task_deleted, task_id, node}` | `clear_finished_tasks` (one per deleted id), `delete_task` | |
| `"agents"` | `{:agent_registered, agent_id, summary, node}` · `{:agent_updated, agent_id, changed_fields, node}` · `{:agent_removed, agent_id, node}` · `{:agents_updated, node}` | `EvoGit.AgentScheduler.PubSub` helpers (Throttle flush or immediate fallback when the Throttle is down) | `:agent_updated` deltas strip the heavy `:context` field; `message_count` (integer) is prepended so consumers detect LLM-history changes without re-transferring `get_agent_history/1` |
| `"scheduler_config"` | `{:scheduler_config_updated, node}` | `AgentScheduler.broadcast_config_updated/0` (agent_scheduler.ex:840,856; state.ex:408) | |
| `"system"` | `{:system_sample, node, seq, sample}` | `EvoGit.SystemSampler` every 3s | sample keys EXACTLY: `llm_used, llm_waiting, tool_used, tool_waiting, llm_capacity, tool_capacity, agents_total, agents_running, agents_blocked, agents_waiting, agents_pending, scheduler_alive, llm_slots`; `llm_slots = %{model_id => %{used, waiting, capacity}}` reports REAL per-model LLM slot occupancy (live holders/queue/effective capacity via `AgentScheduler.get_llm_slot_status/0`, fetched per tick; `%{}` when the scheduler is down) while the aggregated `llm_used`/`llm_waiting` keys remain running/blocked proxies; seq = monotonic per sampler |
| `"guides"` | `{:guide_updated, guide_id, %{message: String.t(), page: String.t() \| nil, selector: String.t() \| nil, dismissible: boolean}, node()}` | `EvoGit.Agent.Tools.GuideUser` (the `GuideUser.guide_user` command handler, invoked via the self-reflective agent's `run_command` shell tool) | Transient user-guide push to the dashboard; best-effort (PubSub down swallowed, tool still returns its confirmation) |

The payload-less `{:tasks_updated}` / `{:task_status, task_id, status}` shapes do NOT exist — all task/agent/config/system messages carry the trailing node element.

## Custom Agents & Model Selection

User-defined agents live in ONE file: `<config_dir>/agents.toml` (per-node semantics — the file on the node executing the agent). Optional `[model_selection] script` + `[[agents]]` array-of-tables:

```toml
[model_selection]
script = """if agent.custom_agent_id == "code_reviewer", do: "deepseek-reasoner", else: nil"""

[[agents]]
name = "Code Reviewer"          # required
description = "Reviews code"
prompt = "You are..."           # required — persona/behavior rules
agent_type = "read"             # "read" | "read_write" (default "read_write")
delegation_level = "low"        # "high" | "low" (default "low")
model_id = "gpt-5"              # optional default model PROFILE id (nil = auto/default)
max_turns = 40                  # optional per-agent turn cap override
tools = ["read_file", "run_bash", "write_file"]  # optional whitelist; absent = all standard tools
subagents = ["executor", "investigator"]          # optional built-in agent types this agent may spawn
```

- **Definition map** (atom keys): `%{id, name, description, prompt, agent_type: :read | :read_write, delegation_level: :high | :low, model_id, max_turns, tools: [String.t()] | nil, subagents: [String.t()]}`; defaults applied on save: `agent_type :read_write`, `delegation_level :low`, `subagents []` (the `EvoGit.Agent` macro default is `:high`; the agents.toml schema default is `:low`). `tools`/`subagents` entries are STRINGS (atom-only saves rejected with `:invalid_tools`/`:invalid_subagents`). ## Multi-Repo Read-Write Foreign Repos

Foreign repos may be **writable** — a task still has exactly ONE primary repo and one final report; foreign repos are additional working repos whose agent modifications are tracked but NEVER merged back by the task itself (merge/reject happens later via the dashboard review page).

- **Data model** (`EvoGit.Core.ForeignRepo`): new fields `writable: boolean()` (default `false` — existing read-only semantics preserved) + `base_sha: String.t() | nil` (per-repo starting commit; `nil` = foreign repo HEAD, same semantics as the primary's starting commit). `new/*` and `normalize/1` are safe for STRING-keyed Codec round-trip maps (missing keys default correctly). `ProjectConfig` (`genesis.toml` `[foreign_repos.<id>]`) accepts `writable = true|false` and `base_sha = "..."`.
- **CLI**: `-R <id>:<path>` stays READ-ONLY by default; marking writable/base_sha is TOML-only (`genesis.toml`). Windows drive-letter paths (`-R C:\path`) are NOT split on `:` (`CLI.Parser.split_foreign_repo_spec`).
- **Spawn gate** (`Subagents.validate_spatial_contract_for_spec/3,4` — the 4-arity adds `parent_depth`; the 3-arity delegates with root depth 0 for backward compat): read-only cross-repo spawns into ANY foreign repo are **UNRESTRICTED at any depth**. `:read_write` cross-repo spawns require the target's task-level entry to have `writable: true` (else `{:error, {:foreign_repo_read_only, msg}}`) AND are restricted two ways: **root-agent-only** — the parent must be depth 0, else `{:error, {:foreign_repo_write_not_root, msg}}` (teaches: only the ROOT agent may spawn write-capable subagents in a foreign repository; a nested agent's write scope is its assigned node in its own repo; alternatives: spawn read-only agents into the foreign repo, or report the needed change back up to the root which spawns the writable subagent one at a time); **one-at-a-time** — at most ONE writable-foreign-repo spec per spawn batch (`spawn_validated_subagents/5` threads a `writable_accepted` flag through its reduce; the 2nd+ accepted writable foreign spec fails with `{:error, {:foreign_repo_write_serialized, msg}}`; one-per-batch == one-at-a-time because the parent blocks until all batch subagents complete). **Same-repo spawns WITHIN a foreign repo (parent already running inside it, `spec.repo_id == parent repo_id`) are UNRESTRICTED** — that is how the foreign-repo Manager does its own internal parallelism; only cross-repo `:read_write` spawns are gated. `format_subagent_result/1` (`agent/subagent_processing.ex`) surfaces all three rejection shapes verbatim as `"Error: #{msg}"`. The role is resolved by id-matching `spec.foreign_repos` (threaded through AgentSpec/LoopState; the Runner puts `Process.get(:foreign_repos)`), NEVER from the path alone — the same path can be writable for one task and read-only for another; unknown ids default to read-only.
- **Tool-layer write gating**: `Tools.execute/5` chains `maybe_block_read_only_foreign_repo/5` after `maybe_block_repo_less/5` — blocks every `@write_tools` entry (now incl. `run_git` + `curl`) when the agent's repo id resolves to a read-only foreign repo (message family "read-only foreign repository"); `Shared.validate_file_scope/3` additionally rejects write targets inside read-only foreign repos (defense-in-depth). `Tools.read_only_schemas/0` NO LONGER includes `Curl` (read tools + Context write/edit + ShellTool remain). Repo-less write guard unchanged.
- **Per-repo runtime roots + report** (`Runtime.Helpers.merge_and_report/3,4`; 3-arity delegates with `foreign_repos: []`): writable foreign repos get worktree roots like the primary; **ONE branch name per task** is reused across the primary + every writable foreign repo (`Git.create_branch(repo.root, branch_name, sha)` — NEVER merged into the foreign default branch; branch failure logs + keeps the entry with `branch_name: nil`). The report gains a top-level **`repos` map: `%{repo_id => %{commit_sha, branch_name}}`** with STRING keys (JSON/Codec-safe): `"primary"` always present (`branch_name` `nil` when no changes), each writable foreign repo that produced a commit present, read-only repos ABSENT. Top-level `commit_sha`/`branch_name`/`result` stay the PRIMARY's (backward compat for TaskInfo/dashboard). The per-repo data source is `Result.foreign_repo_commits` (`%{repo_id => latest_commit_sha}`, default `%{}`), rolled up by the scheduler (`Lifecycle.inject_foreign_repo_commits/2` + `store_sub_result/3` child-wins merge; `AgentScheduler.get_foreign_repo_commits/1` returns `%{}` on missing sched_meta) and read defensively via `Map.get`. Survives the Store/Codec round trip — `Codec.decode_result` deliberately does NOT atomize `"repos"`.
- **Review APIs (dashboard workstream contract)**: each writable foreign repo carries an `evogit-agent-*` branch under the task's SINGLE branch name, pointed at `repos[repo_id].commit_sha`. `EvoGit.Review.merge_branch/2,3` and `reject_branch` are per-repo-path APIs (unchanged signatures) — the dashboard merges by calling `merge_branch` for EVERY repo path (primary + each writable foreign repo) and rejects per path likewise. The task never merges; the review page does.
- **WorktreeManager scoping**: `maybe_init_repo/3` (REQUIRED `primary?` param) — the `.genesis/workers` rm_rf wipe and `clean_orphaned_branches` (deletes every `evogit-agent-*` branch) run ONLY for the primary repo; foreign repos skip both (their `evogit-agent-*` branches carry real task work). `run_init_script` stays primary-only.
- **Graceful foreign path validation**: `Runtime.Helpers.load_foreign_repos/2` validates every entry up front — root must exist AND be a git repo (`Git.rev_parse` succeeds) and a non-nil `base_sha` must resolve — raising a descriptive `ArgumentError` (id/path/problem) at task start, never a mid-run crash. `SubagentProcessing` returns `{:error, {call, 0, "Error: foreign repository path does not exist or is not a git repository: <path>"}}` instead of a MatchError. `resolve_foreign_repo_starting_commit/2` = `base_sha` (non-nil) → that sha, else foreign HEAD. Subagent phylo-node precedence: task-level `base_sha` → tracked `foreign_repo_commits` → foreign HEAD.
- **MergeContext/ResumeContext**: `apply_merge_context/4` carries the full `:foreign_repos` list (writable/base_sha intact) and applies per-repo starting commits — each carried repo's `base_sha` is overridden from the previous task's `repos[repo_id]["commit_sha"]` (repos absent from the prev result keep their base_sha; a legacy prev task without `repos` never crashes). `apply_resume_context/3` no longer drops `:foreign_repos` (caller maps normalized to `%ForeignRepo{}` structs before `RuntimeOpts.build_common_runtime_opts`; per-repo base_sha overridden in BOTH branches). Shared pure helper: `EvoGit.TaskRegistry.PrevTaskRepos` (`prev_repos_map/1`, `repo_commit_sha/2`, `apply_starting_commits/2`, `writable_repos_line/1`).
- **Prompts**: all agent prompts (manager/executor/task_scheduler/genesis_planner/architect/context_extractor + shared `PromptFragments.writable_foreign_repo_clause/0`) teach the writable-foreign-repo delegation model — read-only foreign-repo spawns unrestricted for everyone; write-capable foreign-repo spawns **ROOT-AGENT-ONLY + ONE-AT-A-TIME** (rationale: agents edit only their own path; parallel foreign-repo writes create merge conflicts the spawning agent cannot resolve because the sandbox restricts write access to the agent's LOCAL path; the Manager running INSIDE the foreign repo owns its own parallelism); nested agents needing foreign-repo changes report back up to the root; changes committed to `evogit-agent-*` branches, tracked by the task (per-repo commit + branch in the final report), NEVER merged back by the task.

Detail: `runtime/CONTEXT.md` + `task_registry/CONTEXT.md` (PrevTaskRepos/MergeContext/ResumeContext) + `agent/CONTEXT.md` + `agent_scheduler/CONTEXT.md` (spawn gate, roll-up, WorktreeManager scoping) + `core/CONTEXT.md` (ForeignRepo).

## LLM Concurrency & Slot Gating

Per-model slot pools: `State.concurrency_for/2` (agent_scheduler/state.ex:206-208) returns `Map.get(state.model_concurrency, model_id, state.default_llm_max_concurrency)`; both enforcers read it (`Slots.do_handle_request_llm_slot/4`, `Slots.grant_llm_from_queue/2`). `AgentScheduler.with_llm_slot/2` BLOCKS in an `:infinity` `GenServer.call` until a slot is granted — slot requests ENQUEUE in the per-model waiting queue (agent status `:blocked`); there is NO `{:error, :no_capacity}` reply. `with_llm_slot` RAISES only on the `{:error, :cancelled}` purge reply (force-kill / graceful-cancel purge). `default_llm_max_concurrency` acts as a FLOOR (`apply_default_llm_concurrency_override/2` never lowers explicit profile concurrencies; explicit 0 stays 0 — hard pause). ## Peak/Off-Peak Hour Concurrency Scheduling

Each `[[llm.models]]` profile may declare five optional fields — `peak_concurrency` (concurrency used during peak windows), `peak_hours` (list of `%{start: "HH:MM", end: "HH:MM"}` half-open daily windows, each optionally carrying `days` — day identifiers `"mon".."sun"` and/or keywords `"weekdays"`/`"weekends"`, absent = every day; `start > end` = overnight wrap; absent / `[]` / invalid → disabled, normal `concurrency` 24/7), `off_peak_days` (profile-level list of the same day identifiers/keywords — on those days the profile is off-peak the ENTIRE day: normal `concurrency` 24/7, every `peak_hours` window suppressed, `peak_concurrency` incl. the hard-pause 0 never applies; wins over window `days`; e.g. DeepSeek weekends-off-peak: `off_peak_days = ["weekends"]`), and `timezone` (optional IANA name; absent = server local wall clock, never UTC). **`peak_concurrency = 0` = hard pause**: the model gets ZERO LLM slots during peak windows — the explicit 0 is never raised by the `default_llm_max_concurrency` floor. `timezone` requires the tz database at boot: `Calendar.put_time_zone_database(Tz.TimeZoneDatabase)` in `EvoGit.Application.start/2` (`{:tz, "~> 0.28"}` dep). Validation single source of truth: `EvoGit.PeakHours` (pure) — `parse_time/1`, `parse_window/1`, `validate_windows/1` (overlap validation is per-day — windows with disjoint `days` never overlap), `validate_days/1` (day identifiers/keywords, case-insensitive → canonical atoms), `in_peak?/2,3` (day-aware), `next_transition/2,3` (day-aware — midnight day-boundary flips ARE transitions), `effective_concurrency/2,3`, `validate_timezone/1,2` (nil/"" valid; unknown name → ValidationError at `[:llm, :models, <i>, :timezone]`), `wall_clock_in/2` (DST-aware); the config schema delegates to it — do NOT re-implement. `EvoGit.PeakHourEngine` (supervised after the scheduler) computes the **floored** effective map — `max(effective_concurrency, default)` per model, EXCEPT explicit 0 stays 0 (making the apply a fixed point, so its own `{:scheduler_config_updated, node()}` broadcast re-check no-ops) — and applies via `AgentScheduler.update_config(model_concurrency: map)` only when it differs; wake triggers: day-aware `next_transition` timer (+100ms epsilon, 6h safety-net cap, pending timer cancelled before rescheduling) + local `"scheduler_config"` broadcasts — midnight day-boundary flips ARE transitions, and profiles with ONLY `off_peak_days` contribute no transitions (no needless mid-day wakeups). **0-capacity blocks like paused**: slot requests ENQUEUE (blocked) rather than failing fast; waiters are granted on the 0→N transition by the end-of-update `grant_pending_on_resume` sweep; in-flight holders are never evicted; a blocked agent waits until peak exit (by design). Clock seams: `:peak_hours_now_fun` / `:peak_hours_utc_now_fun` app env, read per wakeup. Detail: `agent_scheduler/CONTEXT.md` (Slot Management) + `config/CONTEXT.md`; root `./CONTEXT.md` also covers the TOML contract — do not duplicate.

## GitEnv — Commit Identity Resolution

`EvoGit.GitEnv.git_env/1` is the single source of truth for the env map injected into EVERY git invocation — both `EvoGit.Adapters.Git` and the sandbox backends (`git_env_list/1`). It always sets `LC_ALL=C` + `GIT_EDITOR` (resolved `true` path). Identity priority: (1) **inherited environment** (`System.get_env/1`, non-empty; empty string treated as unset, mirroring git) — never clobbered; (2) **repository's effective `git config user.name`/`user.email`** (no scope flag → repo → global → system, exactly what git uses); (3) **fallback** `"Genesis"`/`"noreply@evogit.ai"` only when nothing is configured anywhere, so automated commits never fail with "Please tell me who you are". Memoized per repo path in `:persistent_term` (`{GitEnv, :config_identity, repo_path}`; the `nil` key = global/no-repo resolution); stale-if-config-changed until VM restart is an accepted trade-off (avoids 2 extra process spawns per git invocation); inherited env vars are read fresh at call time, never memoized. Test helper: `GitEnv.clear_config_identity_cache/1` (`@doc false`). Only bare `git_env/0` calls (nil path) resolve global-level identity. Detail: `adapters/CONTEXT.md` (GitEnv section).

## Agent Loop Control Flow + Graceful Task Cancellation

**Loop injection point**: `Runner.loop/1` is the top of each turn (after `compress_if_needed`/`check_limit_warnings`, before `do_turn`'s LLM call); `AgentState.pending_user_messages` (`[String.t()]`) is the cross-process writable surface (written via `Store.append_pending_user_message/2` — shared by `send_user_message/2` AND graceful cancellation), drained by `drain_and_inject_user_messages/1` → appended as user-role messages (turn-tagged) → `sync_context_to_ets/2` immediately (visible in `get_agent_history/1`). API chain: `EvoDash.NodeContext` → `RemoteNode.send_agent_message/3` → `RemoteAPI.send_agent_message/2` (guard `{:error, :scheduler_not_started}` when `:evogit_agent_state` ETS undefined) → `AgentScheduler.send_user_message/2` → `Store.append_pending_user_message/2`. Returns `:ok | {:error, :not_found}` (message NOT echoed); ⚠️ RemoteNode's local path nests the inner error — `{:ok, {:error, :not_found}}` — dashboard falsely reports success for a missing agent. Exposed via `get_agent_state/1` (drops only `:context`); every append/drain emits a `{:agent_updated, ..., [pending_user_messages: [...]]}` delta but nothing renders it. Detail: `agent/CONTEXT.md` + `agent_scheduler/CONTEXT.md`.

**Two cancellation actions** (node-aware via the RemoteNode RPC chain — `RemoteNode.cancel_task/2` + `force_kill_task/2`):
- **Graceful cancel** (`TaskRegistry.cancel_task/1`): `:pending` → immediate `:cancelled` (and `start_task` refuses already-cancelled/cancelling ids); `:running` → status `:cancelling` + `AgentScheduler.begin_graceful_cancel/1` (`:evogit_cancelling_tasks` ETS marker + per-agent cancel message via `Store.append_pending_user_message/2` (NOT `send_user_message` — self-call deadlock) + `AgentState.cancel_requested` flag). Runner drains the flag right after user messages (`maybe_enter_cancel_grace/1`) and enters cancel-grace with a **3-turn budget** (`LoopState.grace_turns_remaining`; `maybe_recovery_auto_commit` runs first — "save the changes"). Final-status force-mapping persists `:cancelled` WITH result/usage/archive **preserved** (never nil'd). `:cancelling` is non-terminal + idempotent (codec atom, TaskInfo typespec, lease valid, `clear_finished_tasks` won't delete it, startup reconciliation maps orphaned `:cancelling` → `:cancelled`). New root spawns are blocked for cancelling tasks (`run_agent` replies `{:error, :cancelled}` — blocks Genesis Mode B's second root); new-agent registration for a cancelling task gets the flag immediately.
- **Force kill** (`TaskRegistry.force_kill_task/1`): kills all agents + the wrapper, persists **`:failed`** with result nil'd. `:cancelled` means ONLY gracefully-cancelled tasks. Works from `:running` and `:cancelling`.
- **Dashboard**: visible Cancel button (`[:pending, :running]`) → custom warning modal → `confirm_cancel_task`; force kill lives in the task-card dropdown (`[:running, :cancelling]`, "Danger zone") → warning modal → `confirm_force_kill_task`. `:cancelling` renders violet and is reviewable like completed (ReviewLive treats `:cancelled` like `:completed`).

Detail: `task_registry/CONTEXT.md` (Graceful Cancellation & Force Kill) + `agent_scheduler/CONTEXT.md` (Graceful Cancellation) + `agent/CONTEXT.md` (Grace Period).

## Update-Timing Safety (current mechanics)

No restart/update machinery exists in `:evo_git` (zero `System.restart`/`:init.restart`/`:init.stop` usages; no custom signal handlers; no state checkpointing on exit). Graceful stop is done from `:evo_dash` (`EvoDashWeb.LiveHooks.DesktopQuit.default_stop/0`, SystemLive local Stop — both `System.stop/0`). The Rust shell NEVER sends SIGTERM (headless mode + watchdog force-kill use `child.kill()` = SIGKILL on Unix). `bin/<release> stop`/`restart` require `RELEASE_DISTRIBUTION != none` + a resolvable `RELEASE_NODE` — the desktop sidecar runs non-distributed (`RELEASE_DISTRIBUTION=none`), so `bin/genesis_desktop stop` cannot connect; the desktop backend must be stopped from within. Pre-restart mechanism = **graceful cancel** (3-turn grace; NOT wall-clock bounded — each grace turn is a full LLM+tools cycle with retry backoff, so an update flow must wait for a terminal status with a generous timeout, or force-kill). Idle-detection API (dashboard "safe to restart" check): `TaskRegistry.list_task_ids(statuses \\ [])` / `list_tasks_summary(statuses \\ [], since \\ nil)` / `list_tasks_changed_since/1` / `get_task/1` (+ RemoteAPI/RemoteNode mirrors); in-flight set = `[:running, :pending, :finalizing, :cancelling]`. Task status lives ONLY in SQLite (`tasks.status`); scheduler ETS (`:evogit_sched_meta`, `:evogit_agent_state`, `:evogit_cancelling_tasks`, `:evogit_archive_records`) holds live-agent state only and dies with the app. Lease/heartbeat: `@lease_duration` 120s, heartbeat every 60s renews `[:running, :pending, :cancelling]` (not `:finalizing`), one-shot `:lease_sweep` at `@sweep_after` 150s marks orphaned `:running` → `:failed` ONLY when the lease is invalid AND no live sched_meta agents — the sweep never reschedules (a `:running` row whose lease is still valid at 150s post-boot stays `:running` forever). Startup reconciliation: `:finalizing` → `:failed`, `:cancelling` → `:cancelled` (synchronous, result preserved); `:running` deliberately untouched. **No auto-resume** — resume is always a NEW `:evolve` task via the dashboard Review page (`resume_from` → `ResumeContext`; `review_status: :continued` is a persisted marker only — core never gates on it). Detail: `agent/CONTEXT.md` (Update-Timing Safety) + `agent_scheduler/CONTEXT.md` (Shutdown & Restart Safety) + `task_registry/CONTEXT.md` (Restart Recovery).

## Cross-Node RPC Payload Profile (key design facts)

Remote dashboard RPC (`EvoGit.RemoteNode` → `EvoGit.AgentScheduler.RemoteAPI` via `:erpc.call/5`; local node = direct call) transfers **uncompressed native BEAM terms** (no JSON boundary; `:remote_rpc_timeout` default 30s read at call time). Every wrapper: local → direct call (errors surface truthfully), remote → `:erpc` normalized `{:ok, _} | {:error, {kind, reason}}` with per-function failure fallbacks (`[]`/`%{}`/`nil`/`false`). Payload profile: 🔴 `get_agent_history/1` (full `context.messages`, pre-compression up to ~100k tokens default threshold), `list_tasks/0` (full decode — no dashboard caller); 🟠 `list_agents/0` (re-fetched per broadcast; `objective` dominates when attached-file content is included), `get_task/1`, `list_tasks_paginated/1`, `load_file_diff`/`get_file_content` (lazy per file click); 🟢 `list_tasks_summary/1` (15-key, no result), `list_task_ids/1`, `list_tasks_changed_since/1` (biggest transferred-vs-consumed gap — consumers use only `:updated_at`), config reads, review metadata/commits/`check_merge`. Dead surface (no dashboard caller): `get_agent_state/1`, `load_review_data/2`, `list_tasks/0` — candidates for removal/deprecation. Detail: `lib/evo_git/CONTEXT.md` (Review/RemoteNode Return-Shape Contract).

## Mix Tasks

- **`mix changelog <version> [--from <ref>] [--to <ref>] [--model <id>] [--file <path>]`** (`Mix.Tasks.Changelog`): PR/merge-aware first-parent collection — each merge commit becomes ONE change carrying its branch commits (`git log --no-merges <merge>^1..<merge>`), non-merge first-parent commits = single-commit changes; `^Bump version to` + mechanical-noise (`^Update mix hash`, `^Update CONTEXT.md`) commits filtered (all-filtered → "No commits found..." + exit). **Record-parsing gotcha**: `--pretty=format:` joins records with `\n` — split on `@record_sep` (`"\x1e"`) AND trim each record (`String.split(trim: true)` alone leaves a leading `\n` corrupting hashes). Two-stage map-reduce via `ReqLLM.stream_object` (default `deepseek:deepseek-v4-flash`, `--model` overrides) → Keep-a-Changelog section (Added/Changed/Fixed/Removed/Security/Deprecated, non-empty only); stage 2 (`build_aggregate_prompt/2`, `@doc false` public for direct prompt tests) explicitly instructs the LLM to **merge related changes across PRs/merges into single entries** — separate merges that add/fix/improve the same feature collapse into ONE entry describing the net user-visible state (e.g. "Add feature xyz"). CHANGELOG.md created with `# Changelog` + empty `## [Unreleased]` when missing; else new `## [<version>] - <date>` inserted after the header or same-version section REPLACED in place; on LLM error the file is NOT modified; asks to commit (only that file staged). Test seams: `:changelog_summarizer` / `:changelog_pr_summarizer` / `:changelog_aggregator` (app-env). Full detail: root `./CONTEXT.md` ("AI changelog generation").
- **`mix bump.version <new-version>`** (`Mix.Tasks.Bump.Version`): updates `VERSION` (single source of truth) + syncs `tauri.conf.json`, `Cargo.toml`, `Cargo.lock`, `README.md` badge; interactively asks whether to commit (only touched files staged, never `git add -A`), then optionally delegates to `mix changelog` — invoked DIRECTLY (`Mix.Tasks.Changelog.run([version])`), NOT `Mix.Task.run/2` (refuses re-runs in the current Mix invocation). Full detail: root `./CONTEXT.md` ("Versioning").
- **`mix migrate.store`** (`Mix.Tasks.Migrate.Store`): standalone one-time DB upgrade (never starts `:evo_git` — works even when the app cannot boot on an unmigrated DB): create_tables → migrate_schema → normalize_timestamps → canonical result rewrite → opts object rewrite → branch_name/updated_at backfill → quarantine-table drops; idempotent. Detail: `store/CONTEXT.md`.

## Known Issues

- **Process/thread exhaustion inside containers breaks git forks (EAGAIN).** In a rootless podman container every container process shares the host user's UID, so the kernel's per-UID `RLIMIT_NPROC` (`ulimit -u`) is enforced across container + host user processes together (every OS thread counts — BEAM scheduler/async threads, node/chrome worker threads, git/gh port forks). When hit, `fork()` fails with `EAGAIN` — git prints "cannot fork() ... Resource temporarily unavailable" (e.g. during `git worktree add`). A heavy parallel run can exhaust it mid-run; the WorktreeManager survives such events (persistent init marker + re-monitoring — no cascade wipe), but the run still loses agents to crash-retry. Prevention: (1) raise the HOST user's nproc limit (`/etc/security/limits.conf` or `systemctl --user set-property user.slice TasksMax=infinity`); (2) launch the container with `--ulimit nproc=65536:65536 --pids-limit -1` (or `pids_limit = -1` + `default_ulimits` in `~/.config/containers/containers.conf`); (3) rootless-with-systemd-cgroups: delegate the pids controller (`/etc/systemd/system/user@.service.d/delegate.conf` → `[Service] Delegate=cpu cpuset io memory pids`; `systemctl daemon-reload`); (4) verify live usage via `ulimit -u`, `/sys/fs/cgroup/pids.max`, `/sys/fs/cgroup/pids.current`; (5) reduce runtime concurrency (fewer parallel agents / lower `--concurrency`).

## Constraints

- Part of an **umbrella project** — deps, build artifacts, and lockfile live at the repository root. Elixir ~> 1.18 required. **Git CLI only** (no libgit2 bindings). No source code at root — all code under `./apps/`.
- All git operations must go through `EvoGit.Adapters.Git` — no direct `System.cmd("git", ...)` in domain modules (exceptions: `Shared.do_git_commit`'s raw `System.cmd` for `make_dir` commits, and GitEnv's own config reads).
- `remote_api.ex` (~1090 lines) and `remote_node.ex` (~1150 lines) are intentionally long cohesive RPC wrapper modules — do NOT split them; add new RPC functions to these modules (identity-unwrap wrappers via the `defnode` macro from `EvoGit.RemoteNode.Defnode`; per-function-fallback wrappers stay hand-written).
- Agents are transient modules using the `EvoGit.Agent` behaviour; framework state lives in ETS. Agent execution happens in **isolated git worktrees** managed by `AgentScheduler.WorktreeManager` (monitor-driven reclaim) — never on the main working copy. Agents commit before delegating subagents (auto-commit fallback enforced by scheduler).
- Subdirectories follow Elixir convention: `./lib/evo_git/<subdir>/` maps to `EvoGit.<Subdir>` namespace.
- **Three-level configuration** (`EvoGit.Config`): built-in defaults → user config (`~/.config/genesis/config.toml`) → runtime overrides. **No default model or username is hardcoded**; user config follows XDG conventions.
- **Slot discipline**: all LLM calls must acquire/release slots via `AgentScheduler`. Multi-model support — each model has independent concurrency slots, generation params, and per-model 60-second backoff. Config via `[[llm.models]]` TOML array-of-tables; old flat `[llm]` auto-migrates to a single-profile list with id `"default"` **at load time only**; on save, flat gen-param fields are stripped when `llm.models` is non-empty. `AgentSpec.model_id` binds an agent to a profile; child agents inherit the parent's `model_id` by default. Tool executions independently throttled via `max_tool_concurrency`.
- **Task-scoped naming**: worktree directories `worker_T<task_number>_A<task_local_id>`, branches `evogit-agent-T<task_number>-A<task_local_id>`. `task_id` = 16-char hex GUID (archive refs, task grouping); `task_number` = short integer from a linear scan of `.genesis/workers/`, used only for naming.
- **Task persistence runs in `:evo_git`** — `EvoGit.Store` + `EvoGit.TaskRegistry` are started by `EvoGit.Application`'s supervision tree, so the headless `genesis_remote` release has full task history without any dashboard dependency. TaskRegistry reconciles against the shared platform SQLite DB (`<data_dir>/tasks.sqlite`); a freshly-started Registry leaves orphaned `:running` rows to the lease/heartbeat sweep (respects lease validity for the legitimate multi-VM case). `trim_recent_projects/1` is nil-safe (nil `last_opened_at` sorts LAST — the `DateTime` sorter would raise). Test isolation guard: `config/test.exs:29` sets `config :evo_git, :data_dir, Path.join(System.tmp_dir!(), "evogit_test_data/genesis")` so tests never touch the production DB.
