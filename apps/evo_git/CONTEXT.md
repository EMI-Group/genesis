# EvoGit — Core Runtime Application

## Intent
The `:evo_git` OTP application is an evolutionary software-development runtime: LLM agents create, analyze and modify codebases in isolated git worktrees, modeling a codebase as a **Context Tree** (spatial) and a **Phylogenetic Graph** (temporal) evolved through a DAG of commits.
Phases: **Genesis**, **Evolution**, and a repo-less **self-reflective** agent (`:reflect`), all on an LLM/tool slot-gated scheduler.
Task persistence (`EvoGit.Store`/`EvoGit.TaskRegistry`) lives here so the headless `genesis_remote` daemon has full task history — detail: `lib/evo_git/CONTEXT.md`.

## PubSub Event Contract (event-driven dashboard)

All dashboard-visible state changes are PUSHED on `EvoGit.PubSub` (Phoenix.PubSub PG2, cluster-aware); every message carries the emitting `node` as its final element and subscribers MUST ignore messages whose node ≠ their own for node-local state. Emitter detail: `task_registry/CONTEXT.md`.

| Topic | Message | Emitted by | Notes |
|---|---|---|---|
| `"tasks"` | `{:task_updated, task_id, status, node}` | TaskRegistry mutations; `Runtime.Helpers.notify_finalizing/1` | status = the task's CURRENT status (`:pending \| :running \| :finalizing \| :cancelling \| :completed \| :failed \| :cancelled`), `nil` for review-status/metadata updates; no broadcast on stale/no-op/missing-row updates; heartbeat silent; **`notify_finalizing/1` is the ONE broadcast fired BEFORE its persist**, all others AFTER the store write |
| `"tasks"` | `{:task_deleted, task_id, node}` | `clear_finished_tasks` (one per id), `delete_task` | **`Cleanup.cleanup_expired_tasks/1` deletes rows with NO broadcast** |
| `"agents"` | `{:agent_registered, agent_id, summary, node}` · `{:agent_updated, agent_id, changed_fields, node}` · `{:agent_removed, agent_id, node}` · `{:agents_updated, node}` | `AgentScheduler.PubSub` helpers (Throttle flush or immediate fallback) | `:agent_updated` deltas strip `:context`; `message_count` is prepended so consumers detect history changes without re-transferring `get_agent_history/1` |
| `"scheduler_config"` | `{:scheduler_config_updated, node}` | `AgentScheduler.broadcast_config_updated/0` | |
| `"system"` | `{:system_sample, node, seq, sample}` | `EvoGit.SystemSampler` every 3s | keys EXACTLY `llm_used, llm_waiting, tool_used, tool_waiting, llm_capacity, tool_capacity, agents_total, agents_running, agents_blocked, agents_waiting, agents_pending, scheduler_alive, llm_slots`; `llm_slots = %{model_id => %{used, waiting, capacity}}` = REAL occupancy (`get_llm_slot_status/0`; `%{}` when down), while `llm_used`/`llm_waiting` stay running/blocked proxies; seq monotonic per sampler |
| `"guides"` | `{:guide_updated, guide_id, %{message, page, selector, dismissible}, node}` | `Agent.Tools.GuideUser` (via `run_command`) | transient guide push; best-effort |

The payload-less `{:tasks_updated}` / `{:task_status, task_id, status}` shapes do NOT exist.

## Custom Agents & Model Selection

User-defined agents live in ONE file, `<config_dir>/agents.toml` (per-node):

```toml
[model_selection]
script = """if agent.custom_agent_id == "code_reviewer", do: "deepseek-reasoner", else: nil"""

[[agents]]
name = "Code Reviewer"          # required
prompt = "You are..."           # required — persona/behavior rules
agent_type = "read"             # "read" | "read_write" (default "read_write")
delegation_level = "low"        # "high" | "low" (default "low")
model_id = "gpt-5"              # optional default model PROFILE id (nil = auto)
max_turns = 40                  # optional turn-cap override
tools = ["read_file", "run_bash"]  # optional whitelist; absent = all standard tools
subagents = ["executor"]           # optional built-in agent types
```

- **Definition map** (atom keys): `%{id, name, description, prompt, agent_type: :read | :read_write, delegation_level: :high | :low, model_id, max_turns, tools: [String.t()] | nil, subagents: [String.t()]}`; save defaults `agent_type :read_write`, `delegation_level :low`, `subagents []` (the `EvoGit.Agent` macro default is `:high`); `tools`/`subagents` entries are STRINGS; save errors `:missing_name, :missing_prompt, :invalid_agent_type, :invalid_delegation_level, :invalid_max_turns, :invalid_tools, :invalid_subagents, :duplicate_id`; reads lenient, only `save/1` validates.
- **Tools whitelist**: built-in names (incl. subagent schemas, `complete_task`) AND custom-tool names, matched **ALIAS-AWARE** (`Tools.whitelist_match?/2` → `ToolNames.matches_any?/2`), so pre-rename spellings (`"read_file"`, `"write_file"`, `"edit_file"`, `"run_bash"`, `"search_web"`) resolve to `read`/`write`/`edit`/`bash`/`web_search`; `Agents.Custom.available_tools/0` merges `CustomTools.schemas/0` only for an explicit whitelist; `CustomAgents.reload/0` invalidates both caches.
- **Model-selection script** (`ModelSelector.describe_contract/0`): body wrapped as `fn agent -> <body> end`, `agent = %{agent_type, custom_agent_id, depth, parent_id, task_id, objective}`, last expression = profile id `String.t() | nil` (`""`/`false` → default); errors never crash — `ModelSelector.status/0` → `{:error, {:compile_error, msg}}`, a raising script logs + falls back.
- **Dispatch priority** (`Dispatch.register_agent/7`, before `resolve_model_for_agent/2`): (1) `spec.opts[:model_id_locked]` (script skipped); (2) script on every spawn unless locked; (3) `spec.model_id` from agents.toml or inherited; (4) default profile. Subagent inheritance does NOT set the lock; custom `max_turns` overrides `state.max_turns_root`/`max_turns`.
- **Runtime opts**: `:agent` (validated by `Helpers.resolve_root_agent/2`, `ArgumentError` on unknown id) + `:model_id_locked`; root spec `agent_module: EvoGit.Agents.Custom` + `opts: [custom_agent_id: id]`; the Runner puts `:custom_agent_id` in the process dictionary. Detail: `custom_agents/`.

## Multi-Modal Content (objective, tool results, injected messages)

Media (images/audio) rides LLM content parts at THREE sites; wire contract `EvoGit.Attachments` (`lib/evo_git/attachments.ex`), structured tool output `EvoGit.Agent.ToolOutput` (`agent/tool_output.ex`).

- **Shape**: STRING-keyed `%{"type" => "image"|"audio", "name" => <basename>, "media_type" => <IANA>, "data" => <base64 ASCII>}`; base64 is MANDATORY at every data-plane boundary (task opts, pending-message queue) because `Store.Codec` Jason-encodes whole opts and raw binaries abort Jason; decoding happens ONLY at materialization (`Attachments.to_content_parts/2`: image → `ReqLLM.ContentPart.image(raw, media_type)`, audio → a `:file` part), always a plain `[ContentPart.text(text) | media parts]` list, NEVER `ReqLLM.ToolResult`; `Attachments.message/1` is the ONE normalizer.
- **Caps**: ≤ 4 attachments per message, each ≤ 15 MiB RAW bytes (`EvoGit.Attachments` attributes are the single core source), per task opt AND per tool output; malformed payloads raise a descriptive `ArgumentError`.
- **Site 1 — `:attachments` task opt (root-only)**: ROOT agent's FIRST user message only (`ContextBuilder.build_initial_messages/4`, gated on `parent_id == nil` AND non-empty; subagents never inherit); Genesis Mode A, Mode B both roots and the Evolve root receive it, Reflect never; validated by `RuntimeOpts` → `Attachments.validate/1`.
- **Site 2 — tool results (any agent, any turn)**: `Tools.execute/5` may return `String.t() | ToolOutput.t() | {:error, reason}` (`ToolOutput` = `%{text, attachments}`, `new/2`/`wrap/1`/`with_text/2`/`to_content_parts/1`). `agent/tool_dispatch.ex` is the SOLE **wrap boundary**: sanitize/truncate + hint appenders hit the TEXT component only (`OutputSanitizer`/`TruncationFeedback`/`DelegationHints` keep a binary contract), media is re-wrapped; error/timeout/crash paths stay plain strings. Detail: `agent/`.
- **Site 3 — injected user messages (mid-run, NO root gate)**: `AgentScheduler.send_user_message/2` / `RemoteAPI.send_agent_message/2` / `RemoteNode.send_agent_message/3` accept `String.t() | %{text:, attachments:}`; `Store.append_pending_user_message/2` stores shape-for-shape (legacy binary VERBATIM); `Runner.drain_and_inject_user_messages/1` materializes via `ContextBuilder.build_injected_message/2`. Detail: `agent_scheduler/`.
- **Invariants / limits**: a plain-string tool result and a legacy string pending message behave BYTE-IDENTICALLY to pre-media behavior (`%ReqLLM.Message{}` struct-equality regressions in `test/evo_git/agent/tool_output_pipeline_test.exs` + `tool_output_integration_test.exs`). Compression keeps `[system, first_user]` BYTE-IDENTICALLY (objective attachments re-sent after every compression — the cached prefix must not change) and the last K turns VERBATIM, while OLDER tool-result media collapses into one `[... tool result media omitted ...]` placeholder per message (stage 1). Resume / merge-auto-resolve / GitHub-fix follow-ups do NOT re-carry `:attachments`. Detail: `store/` + `runtime/`.

## Multi-Repo Read-Write Foreign Repos

Foreign repos may be **writable** — still ONE primary repo + one final report per task; foreign modifications are tracked but NEVER merged back by the task (the review page merges/rejects).

- **Data model** (`Core.ForeignRepo`): `writable: boolean()` (default `false`) + `base_sha: String.t() | nil` (`nil` = foreign HEAD); `new/*`/`normalize/1` handle STRING-keyed Codec maps; `ProjectConfig` accepts both; `-R <id>:<path>` stays READ-ONLY (TOML-only to mark writable) and Windows drive letters are NOT split on `:` (`CLI.Parser.split_foreign_repo_spec`).
- **Spawn gate** (`Subagents.validate_spatial_contract_for_spec/3,4`; 3-arity = root depth 0): read-only cross-repo spawns UNRESTRICTED at any depth; `:read_write` cross-repo spawns need `writable: true` (else `{:error, {:foreign_repo_read_only, msg}}`), are **root-only** (depth 0, else `{:error, {:foreign_repo_write_not_root, msg}}`) and **one per batch** (`spawn_validated_subagents/5` threads `writable_accepted`; 2nd+ → `{:error, {:foreign_repo_write_serialized, msg}}`); same-repo spawns INSIDE a foreign repo are UNRESTRICTED. `format_subagent_result/1` surfaces all three verbatim as `"Error: #{msg}"`; the role comes from id-matching `spec.foreign_repos` (Runner puts `Process.get(:foreign_repos)`), NEVER the path; unknown ids → read-only.
- **Tool gating**: `Tools.execute/5` chains `maybe_block_read_only_foreign_repo/5` after `maybe_block_repo_less/5` — blocks every `@write_tools` entry (incl. `run_git`); `Shared.validate_file_scope/3` rejects write targets inside one; `Tools.read_only_schemas/0` = read tools + Context write/edit + ShellTool + `WebFetch` + `Lsp` only when `Config.lsp_enabled?/0`; there is no `curl` tool.
- **Roots + report** (`Runtime.Helpers.merge_and_report/3,4`): writable repos get worktree roots like the primary; ONE branch name per task reused across all (`Git.create_branch(repo.root, branch_name, sha)`; failure logs + `branch_name: nil`). Report gains top-level **`repos: %{repo_id => %{commit_sha, branch_name}}`** (STRING keys): `"primary"` always, each writable repo that committed, read-only ABSENT; top-level `commit_sha`/`branch_name`/`result` stay the PRIMARY's. Source `Result.foreign_repo_commits`, rolled up by `Lifecycle.inject_foreign_repo_commits/2` + `store_sub_result/3` (child-wins), read via `AgentScheduler.get_foreign_repo_commits/1` (`%{}` on missing sched_meta).
- **Review + scoping**: each writable repo carries an `evogit-agent-*` branch at `repos[repo_id].commit_sha`; `Review.merge_branch/2,3` + `reject_branch` are per-repo-path; `maybe_init_repo/3` (required `primary?`) wipes `.genesis/workers` + `clean_orphaned_branches` ONLY for the primary, and `run_init_script` stays primary-only.
- **Persistent foreign worktree (read view)** at `<root>/.genesis/foreign_repos/<id>` (`ForeignRepo.worktree_path/1`), reset at task start (`ForeignWorktree.ensure_all/1`), advanced by `Agent.Runner.run/3` `try/after` → `sync_from_agent/0`; outside `.genesis/workers/`, never moves MAIN HEAD, kept at task end — detail: `agent_scheduler/`.

## LLM Concurrency & Slot Gating

Per-model pools: `State.concurrency_for/2` = `Map.get(state.model_concurrency, model_id, state.default_llm_max_concurrency)`, read by both enforcers (`Slots.do_handle_request_llm_slot/4`, `Slots.grant_llm_from_queue/2`). `AgentScheduler.with_llm_slot/2` BLOCKS in an `:infinity` `GenServer.call` — requests ENQUEUE (agent `:blocked`), there is NO `{:error, :no_capacity}`, and it RAISES only on the `{:error, :cancelled}` purge reply.
`default_llm_max_concurrency` is a FLOOR (`apply_default_llm_concurrency_override/2`; explicit 0 stays 0); runtime overrides are in-memory only (`update_config/1`, lost on restart) from dashboard saves, `RemoteAPI.reload_config` and `PeakHourEngine` — the CLI makes none; `Slots.grant_pending_on_resume/1` sweeps waiters on capacity change; non-slot-gated `stream_text` sites are `system_check.ex` + `runtime/pull_request.ex` only.
**Per-model exhaustion backoff**: `Agent.TruncationFeedback.classify_model_exhaustion/1` → `:insufficient_balance | :rate_limit | nil`, structurally from `%ReqLLM.Error.API.Request{}` (`status: 402`, `provider_code`, `reason`, `response_body`) with a lowercased phrase fallback; a bare `"402"` substring is deliberately NOT matched. `ToolDispatch.call_llm_with_retry/5` reports the class with a growing duration via `AgentScheduler.report_llm_error/3` (`agent_id, error_type, backoff_ms`; `/2` passes `nil`) → `Slots.handle_report_llm_error/4` (accepts `:rate_limit | :insufficient_balance | :model_exhaustion`, sets per-model `llm_backoff_until`, clamps to `@max_timer_ms`). `Agent.LlmRetryPolicy` (pure): 15 delays, base 60 s doubling, cap 28_800_000 ms (8 h), total `216_900_000` ms; seams `:llm_model_exhaustion_backoff_base_ms` (60_000) / `:llm_model_exhaustion_backoff_cap_ms` (28_800_000) at call time.
**No agent-side sleep**: the agent recurses immediately and parks in the purgeable `:infinity` slot-queue call, so cancel/force-kill still work; `Slots.handle_retry_llm_waiting/1` SELF-RESCHEDULES (`schedule_next_backoff_sweep/1`, wakeup = max remaining backoff + epsilon). Ordinary transient errors (`class == nil`) keep the short schedule (app env `:llm_retry_backoff_base_ms`, default 1_000, cap 60_000, ±10% jitter). Detail: `agent_scheduler/` + `agent/`.

## Peak/Off-Peak Hour Concurrency Scheduling

Each `[[llm.models]]` profile may declare five optional fields: `peak_concurrency`, `peak_hours` (half-open daily `%{start: "HH:MM", end: "HH:MM"}` windows, optionally scoped by `days` — `"mon".."sun"` and/or `"weekdays"`/`"weekends"`; `start > end` = overnight wrap), `off_peak_days` (off-peak the ENTIRE day: normal `concurrency`, every window suppressed, wins over window `days`) and `timezone` (IANA; absent = server local wall clock, never UTC; needs `Calendar.put_time_zone_database(Tz.TimeZoneDatabase)`, `{:tz, "~> 0.28"}`). **`peak_concurrency = 0` = hard pause**, never raised by the `default_llm_max_concurrency` floor.
`EvoGit.PeakHours` (pure) is the single source of truth — `validate_windows/1` (overlap per-day), `validate_days/1`, `in_peak?/2,3`, `next_transition/2,3` (midnight day flips ARE transitions), `effective_concurrency/2,3`, `wall_clock_in/2`; the schema delegates — do NOT re-implement.
`PeakHourEngine` (supervised after the scheduler) computes the **floored** map — `max(effective_concurrency, default)`, explicit 0 stays 0 — and applies it via `update_config(model_concurrency: map)` only when different; wake triggers are a day-aware `next_transition` timer (+100ms epsilon, 6h safety-net cap) + local `"scheduler_config"` broadcasts; profiles with ONLY `off_peak_days` contribute no transitions. **0-capacity blocks like paused**: requests ENQUEUE and are granted on the 0→N transition; in-flight holders never evicted. Clock seams `:peak_hours_now_fun` / `:peak_hours_utc_now_fun`. Detail: `agent_scheduler/` + `config/`; TOML contract: root `./CONTEXT.md`.

## Agent Loop Control Flow + Graceful Task Cancellation

**Loop injection point**: `Runner.loop/1` is the top of each turn (after `compress_if_needed`/`check_limit_warnings`, before `do_turn`'s LLM call); `AgentState.pending_user_messages` (`[String.t()]`) is the cross-process writable surface (written via `Store.append_pending_user_message/2`), drained by `drain_and_inject_user_messages/1` → turn-tagged user messages → `sync_context_to_ets/2`.
API chain: `EvoDash.NodeContext` → `RemoteNode.send_agent_message/3` → `RemoteAPI.send_agent_message/2` (guards `{:error, :scheduler_not_started}` when `:evogit_agent_state` is undefined) → `AgentScheduler.send_user_message/2` → `Store.append_pending_user_message/2`, returning `:ok | {:error, :not_found}`; ⚠️ RemoteNode's local path nests the inner error (`{:ok, {:error, :not_found}}`), so the dashboard falsely reports success for a missing agent. Every append/drain emits a `{:agent_updated, ..., [pending_user_messages: [...]]}` delta but nothing renders it. Detail: `agent/` + `agent_scheduler/`.

**Two cancellation actions** (node-aware via `RemoteNode.cancel_task/2` + `force_kill_task/2`):
- **Graceful cancel** (`TaskRegistry.cancel_task/1`): `:pending` → immediate `:cancelled`; `:running` → `:cancelling` + `AgentScheduler.begin_graceful_cancel/1` (`:evogit_cancelling_tasks` marker + per-agent cancel message via `Store.append_pending_user_message/2` (NOT `send_user_message` — self-call deadlock) + `AgentState.cancel_requested`). The Runner drains it right after user messages (`maybe_enter_cancel_grace/1`) and enters cancel-grace with a **3-turn budget** (`LoopState.grace_turns_remaining`; `maybe_recovery_auto_commit` first); final status persists `:cancelled` WITH result/usage/archive **preserved**. `:cancelling` is non-terminal + idempotent (`clear_finished_tasks` skips it, reconciliation → `:cancelled`) and blocks new root spawns (`run_agent` → `{:error, :cancelled}`).
- **Force kill** (`force_kill_task/1`): kills all agents + the wrapper and persists **`:failed`** with result nil'd, from `:running` and `:cancelling`; `:cancelled` means ONLY gracefully-cancelled tasks.
- **Dashboard**: Cancel button (`[:pending, :running]`) → warning modal → `confirm_cancel_task`; force kill in the card dropdown (`[:running, :cancelling]`, "Danger zone") → `confirm_force_kill_task`; `:cancelling` renders violet and is reviewable (ReviewLive treats `:cancelled` like `:completed`). Detail: `task_registry/` + `agent_scheduler/`.

## Update-Timing Safety

No restart/update machinery exists in `:evo_git` (zero `System.restart`/`:init.restart`/`:init.stop`, no signal handlers, no checkpointing on exit); graceful stop comes from `:evo_dash` (`DesktopQuit.default_stop/0`, SystemLive Stop — both `System.stop/0`), and the Rust shell NEVER sends SIGTERM (watchdog uses SIGKILL). `bin/<release> stop`/`restart` need `RELEASE_DISTRIBUTION != none` + a resolvable `RELEASE_NODE`, so the non-distributed desktop sidecar must be stopped from within. Pre-restart mechanism = **graceful cancel** (3-turn grace, NOT wall-clock bounded — each grace turn is a full LLM+tools cycle, so wait for a terminal status with a generous timeout, or force-kill).
Idle-detection API: `TaskRegistry.list_task_ids(statuses \ [])` / `list_tasks_summary(statuses \ [], since \ nil)` / `list_tasks_changed_since/1` / `get_task/1` (+ RemoteAPI/RemoteNode mirrors); in-flight set `[:running, :pending, :finalizing, :cancelling]`.
Task status lives ONLY in SQLite (`tasks.status`); scheduler ETS holds live-agent state and dies with the app. Lease: `@lease_duration` 120s, heartbeat every 60s renews `[:running, :pending, :cancelling]` (not `:finalizing`); one-shot `:lease_sweep` at `@sweep_after` 150s marks orphaned `:running` → `:failed` ONLY when the lease is invalid AND no live sched_meta agents (never reschedules). Startup reconciliation: `:finalizing` → `:failed`, `:cancelling` → `:cancelled` (result preserved), `:running` untouched. **No auto-resume** — resume is a NEW `:evolve` task via the Review page (`resume_from` → `ResumeContext`; `review_status: :continued` is a persisted marker only). Detail: `agent_scheduler/` + `task_registry/`.

## Backend Boot Profile (desktop sidecar readiness)

Boot work in `:evo_git` is CONSTANT-COST: nothing keyed to the release version or install path; no lockfile/`.genesis/` marker/cache verification/release-tree read at start.
Ordered `EvoGit.Application.start/2` work: (1) create the 4 ETS tables; (2) `Distribution.maybe_enable/0` (logs + returns `{:error, _}`, never raises); (3) `Calendar.put_time_zone_database(Tz.TimeZoneDatabase)`; (4) children in order: PubSub → Throttle → CommandApproval → RemoteConnection Registry/Supervisor → **`Store`** → TaskRegistry Registry → TaskRegistry → WorktreeManager → AgentGroupSupervisor (Task.Supervisor + AgentScheduler) → PeakHourEngine → SystemSampler, plus SandboxProcessRegistry + SandboxSlice on Linux.
The ONE potentially slow child is `Store`, whose `init/1` runs the migrations before any read/write (`Store.Boot.start_dynamic/2`); `TaskRegistry.init/1` then does a synchronous `Store.select_running_lease_info/1`; everything else is O(1). Per-migration cost: `store/`.
**Boot-fatal paths** (a child EXIT ⇒ "Genesis backend unavailable"): an unwritable/missing data dir (`File.mkdir_p!` raises), a failed repo open (`{:stop, {:failed_to_open_sqlite, reason}}`), or ANY raise out of the migration run (baseline post-condition `Ecto.MigrationError`, bad `tasks` shape, `SQLITE_BUSY`, corrupt file) — uncaught in `init/1`; with `start_permanent: Mix.env() == :prod` a terminating permanent app takes the whole VM down.
`Store` opens with `journal_mode: :wal` + `default_transaction_mode: :immediate` + `busy_timeout: 30_000` (a locked `tasks.sqlite` stalls a statement up to ~30 s) and WAL needs `-wal`/`-shm` sidecars on a shared-memory-capable filesystem (a network/UNC data dir can fail the open). No boot-time self-exit exists in `:evo_git`.
**Observability**: the boot path emits no phase logs of its own — only Ecto.Migrator's lines (`Store.Boot` has ZERO Logger calls), `Config.resolve/0` warnings, `PeakHourEngine: starting — watched profiles: …` + `wakeup reason=:boot`/`next wakeup in` pair, and Linux `SandboxSlice` warnings.
**Boot lines CAN repeat inside ONE OS process**: a `Store` crash (`:one_for_one` child of `EvoGit.Supervisor`) re-runs `init/1` → the migration lines, and `System.restart/0` re-boots all applications INSIDE the running node (emulator not restarted) — its only caller is the dashboard System page (`system_live.ex`; remote variant `EvoDash.NodeContext.restart_remote/1`). `EvoGit.Supervisor`/`EvoGit.AgentGroupSupervisor` declare no restart intensities (OTP defaults 3/5s); exceeding them terminates the supervisor and, `evo_git` being `:permanent`, the node goes down — the Rust watchdog respawns a NEW OS process. The log handler appends (`type: :file` + rotation, no truncate-at-boot), so N boot sequences cannot distinguish in-place restarts from OS processes; `<data_dir>/logs/backend.log` is configured in the ROOT `config/runtime.exs` (rotating 10 MB × 5) and nothing in `:evo_git` writes/truncates/rotates/deletes under `<data_dir>/logs/`.
**No first-start-of-a-NEW-release-dir delta exists on the Elixir side** — per-BEAM one-time costs recur on EVERY boot. Port resolution / orphan prevention: root `./CONTEXT.md`.

## Known Issues

- **Process/thread exhaustion inside containers breaks git forks (EAGAIN).** In rootless podman every process shares the host user's UID, so the kernel's per-UID `RLIMIT_NPROC` (`ulimit -u`) spans container + host processes (every OS thread counts); when hit, `fork()` fails with `EAGAIN` — git prints "cannot fork() ... Resource temporarily unavailable" (e.g. in `git worktree add`). `WorktreeManager` survives (persistent init marker + re-monitoring) but the run loses agents to crash-retry. Prevention: raise the HOST user's nproc limit (`/etc/security/limits.conf` or `systemctl --user set-property user.slice TasksMax=infinity`); or `--ulimit nproc=65536:65536 --pids-limit -1` (`pids_limit = -1` + `default_ulimits` in `~/.config/containers/containers.conf`); or delegate the pids controller (`/etc/systemd/system/user@.service.d/delegate.conf` → `[Service] Delegate=cpu cpuset io memory pids`); verify via `ulimit -u` / `/sys/fs/cgroup/pids.max`; or reduce concurrency (`[scheduler] default_llm_max_concurrency`, per-profile `concurrency`).
