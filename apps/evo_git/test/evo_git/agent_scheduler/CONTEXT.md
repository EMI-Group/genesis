# AgentScheduler Test Directory

## Intent

ExUnit tests for the `EvoGit.AgentScheduler` subsystem — scheduling (no worktree init in `run_agent`), slot pools (LLM/tool), lifecycle (crash retry, force-kill, graceful cancel), subagent spatial-contract validation (incl. cross-repo read-write foreign-repo gate), authority-gated foreign-repo-commit roll-up (`store_sub_result/3,4`), per-repo WorktreeManager init scoping (foreign vs primary), ETS store, PubSub throttling, and RPC surface.

- `lifecycle_test.exs` → crash/lifecycle handling, sub-result roll-up, graceful-cancel markers
- `subagents_test.exs` → spatial contract (cross-repo gate, same-repo hierarchy), writable-foreign-repo delegation gates (root-only via `:foreign_repo_write_not_root`, one-at-a-time via `:foreign_repo_write_serialized` in `spawn_validated_subagents/5`, same-repo-within-foreign unrestricted), `store_sub_result/3,4`
- `worktrees_test.exs` → WorktreeManager create/reclaim, crash-restart, per-repo init scoping
- `worktree_admission_test.exs` → bounded worktree-creation ADMISSION QUEUE (head-of-line FIFO, cap never exceeded, queue drains / every caller replied once, queued-agent death dropped without starting a create, under-cap immediate admission) via the `:max_concurrent_worktree_creation` + `:worktree_create_fun` app-env seams, PLUS the create-reply contract of the `:infinity` call: a RAISING create fun and a create fun RETURNING `{:error, reason}` each reply the still-blocked caller exactly once and promptly (raise wrapped as `{:error, {:worktree_create_failed, msg}}` with `msg =~ "raised"`, a plain `{:error, reason}` handed back verbatim, permit released so the queue keeps draining / a subsequent create is admitted); an untrappable create-task death still replies via the `handle_create_task_down/4` safety net (`msg =~ "died"`); and a slow-but-succeeding create is held event-driven without aborting the still-blocked caller (case (g) proves it with a ZERO-WAIT `refute_received` against a create fun parked on `receive :release`: the caller is blocked in an `:infinity` `GenServer.call`, so no reply can exist at any instant — structural, not a quiet window).
- `slots_test.exs` → LLM/tool slot pools, hard-pause 0-capacity
- `store_test.exs` / `state_test.exs` / `remote_api_test.exs` / `dispatch_test.exs` / `dispatch_custom_agents_test.exs` / `pubsub_test.exs` / `worktree_retry_test.exs` → ETS store, state/pool config, RPC surface, dispatch, PubSub throttle, retry helpers (`dispatch_test.exs` also covers `resolve_agent_repo_root/2` foreign-repo root resolution and `resolve_context_window/2` / `register_agent/7`'s `llm_context_window`; `remote_api_test.exs` covers `get_agent_state` foreign_repos round-trip, the `list_agents/0` `compression_threshold` key in BOTH summary branches — its describe pins `XDG_CONFIG_HOME` at an empty temp config dir so the operator's threshold override cannot mask the window-derived pins — and the thin `list_commit_graph/3` delegation to `EvoGit.CommitGraph.for_ranges/3` — exact `{:ok, %{commits, refs}}` shape, newest-first shas, the seven atom keys, parent shas, ref labels, an identity comparison against a direct `CommitGraph.for_ranges/3` call, and the `limit:` opts passthrough — all on a real-git temp repo copied per test from the module's `setup_all` `review_templates` via `review_repo/1` + `commit_file/4`)

## Writable Foreign Repo — Test Coverage Map & Gaps
Covered IN THIS node:
- **Spawn gate** (`subagents_test.exs`): read-only cross-repo unrestricted at any depth (L97, L146, L245-260, L349-365); `:read_write` cross-repo requires task-level `writable: true` — reject `{:foreign_repo_read_only, msg}` (L111-127 reject msg text, L189-208 read-only entry, L209-244 empty/unknown/other-id entry), accept when writable (L172-188); **root-only** `{:foreign_repo_write_not_root, msg}` for depth 1 and 3 (L332-348); **one-at-a-time** `{:foreign_repo_write_serialized, msg}` in `spawn_validated_subagents/5` — 2nd writable spec in a batch rejected + lands in `sub_agent_results`, only 1st registered (L451-498); same-repo-within-foreign unrestricted even at nested depth (L366-385, L499-549).
- **Roll-up** (authority-gated): `Subagents.store_sub_result/3,4` per-repo commit tracking — the optional 4th arg is the completing CHILD's `%EvoGit.AgentSpec{}`, and only a child that is ITSELF a writable `:read_write` agent running in a foreign repo (`Subagents.writable_foreign_repo_agent?/1`) may advance that repo's tracked commit. A writable child records its own `repo_id` → `commit_sha` (latest-wins for the same repo) and merges its result's `foreign_repo_commits` subtree view child-wins; a local/primary or read-only child contributes NOTHING, so a stale SHA can never clobber a newer one — a pre-seeded advanced commit survives a later stale local/primary child (subagents_test.exs L550-826: records SHA under `repo_id`, accumulates across repos, ignores `"primary"`, ignores error results, overwrites to latest, local/primary child does not overwrite a pre-seeded commit, read-only child targeting a writable repo records nothing, writable child records its advance, A→B writable advance survives a later stale primary child) + 3-level child-wins roll-up with `Lifecycle.inject_foreign_repo_commits/2` root reply (lifecycle_test.exs L789-870); `AgentScheduler.get_foreign_repo_commits/1` read-back + `%{}` fallback for a missing SchedMeta row (agent_scheduler_test.exs L261-281).
- **WorktreeManager per-repo init scoping** (worktrees_test.exs L915-987, both tests tagged `lazy_init: true`): foreign repo first init PRESERVES a real `evogit-agent-*` branch (L919-953); primary repo first init DELETES every `evogit-agent-*` branch (L957-986).

## Notes for Agents

- `pubsub_test.exs` drives the throttle debounce SYNCHRONOUSLY: the `:schedule` casts are FIFO-ordered ahead of a `:sys.get_state/1`, so after N casts the state already holds the ONE pending timer ref; the test cancels that ref and delivers the `:flush` itself, then pins `:sys.get_state(Throttle) == nil` and a short (25 ms) no-duplicate probe — three casts still yield exactly one `{:agents_updated, node}`.
- **Wait budgets in `worktrees_test.exs` are deliberately GENEROUS — do NOT tighten them.** The shared `wait_until/2` default is 30 s and the `assert_receive {:agent_ready, ...}, 30_000` create/re-create awaits match it, because every site relying on them waits on REAL work: `git worktree add`/prune/branch-delete subprocesses and monitor-driven `:DOWN` reclaim. Under host CPU oversubscription those round trips slow 10-25x, so a 5 s default (and a 10 s re-create await) flunks a slow-but-CORRECT event with a misleading `wait_until timed out`. Pure in-BEAM waits keep their own modest explicit deadlines (`restart_manager/1`'s 10 s `Process.whereis` poll and `finish_agent/3`'s 10 s `{:DOWN, ...}` receive).
  The POLL BEAT is a separate knob from the budget: `wait_until/2` starts at 1 ms and doubles to a 15 ms cap, so a wait whose event is about to happen is not quantized to a full 15 ms — only the interval shrinks, never a deadline or an assertion.
- **Deterministic slow-git reproduction (no load generators needed)**: put a PATH shim `git` on `PATH` that `sleep`s before `exec`ing the real git binary (e.g. `#!/bin/sh` + `sleep 0.8` + `exec /path/to/git "$@"`) and run the file with `--no-compile`. At 0.8 s per git invocation the pre-hardening file fails 21/23 (`wait_until timed out` in "retry-after-crash gets a fresh worktree" and in "defers a re-create request while the previous create is still in flight") while the 30 s budgets pass 23/23 — this is the cheapest way to exercise the load-sensitivity without a loaded host.

## Known Gaps (writable foreign repo)
- No end-to-end test connecting the roll-up to the READ site: the tracked-commit lookup lives in `EvoGit.Agent.SubagentProcessing.build_subagent_phylo_node/7` → `resolve_foreign_phylo_commit/4` (`lib/evo_git/agent/subagent_processing.ex:620-752`) and is consumed at `subagent_processing.ex:197`; no test in this node drives `spawn → store_sub_result → get_foreign_repo_commits → next spawn`. Its precedence is exercised only OUTSIDE this node (`test/evo_git/agent/subagent_processing_test.exs:735`).
- No A→B hierarchy / sibling-or-later-spawn test: nothing asserts that after a writable foreign-repo agent ADVANCES the foreign repo, a subsequent spawn into the same repo starts from the ADVANCED commit rather than a stale one.
- No `base_sha`-staleness test: `resolve_foreign_phylo_commit/4` gives a NON-nil per-repo `base_sha` ABSOLUTE precedence over the tracked `foreign_repo_commits` map (the tracked commit is consulted only when `base_sha` is nil/empty + `Git.rev_parse` fails is not the case) — so a foreign repo with a `base_sha` never advances across sibling spawns. This interaction is untested here.
- No test drives `Lifecycle.handle_task_result/3` → `Subagents.store_sub_result/3,4` through the live scheduler parent/root split; each piece is unit-tested in isolation.
- Multi-repo read-write end-to-end (per-repo worktree roots, the `repos` report map, review merge) is covered outside this node (`test/evo_git/runtime/helpers_test.exs`, `test/evo_git/agent/subagent_processing_test.exs`, `test/evo_git/worktree_main_head_safety_test.exs`).

## Constraints

- `agent_scheduler_test.exs`, `worktrees_test.exs`, `worktree_admission_test.exs`, `slots_test.exs`, `pubsub_test.exs` stay `async: false` for a named GLOBAL: the live scheduler, the `:max_concurrent_worktree_creation` / `:worktree_create_fun` / `:worktree_retry_delays` / `:llm_backoff_sweep_epsilon_ms` app-env seams, or the PubSub/Throttle process registration.
- `remote_api_test.exs` is `async: false` for its global-ETS **wipe** (`clear_ets/0`) plus its writes to the app-global `EvoGit.Store` singleton — NOT for `XDG_CONFIG_HOME`: the `list_agents/0 compression_threshold` describe isolates its config dir per PROCESS (`EvoGit.TestSupport.ConfigDir`).
- `subagents_test.exs`, `dispatch_test.exs`, `dispatch_custom_agents_test.exs`, `worktree_retry_test.exs`, `state_test.exs`, `lifecycle_test.exs`, `store_test.exs`, `pending_user_messages_test.exs` are `async: true`: each writes ETS rows only under per-test-unique agent ids and never wipes a table.
- `state_test.exs` is `async: true` because it only drives the PURE `State`/`Slots` functions on an in-process `%State{}` (no live scheduler GenServer). Its exercised code paths merely READ the app-created `:evogit_agent_state` (model id) and `:evogit_sched_meta` (depth / sched-meta status) tables for the low agent id it uses (3) and never write them — do NOT add ETS seeding or `:ets.delete_all_objects` back (that is exactly the cross-module race that would force it back to `async: false`).
- The admission-queue seams `:max_concurrent_worktree_creation` and `:worktree_create_fun` are GLOBAL app env (read by the manager at admission/create time) — `worktree_admission_test.exs` must stay `async: false` and save/restore both in `on_exit`.
- The LLM-backoff sweep epsilon is a GLOBAL app-env seam `:llm_backoff_sweep_epsilon_ms` (read by `EvoGit.AgentScheduler.Slots` at CALL time at both timer sites, default 1000 ms). `slots_test.exs` overrides it to 10 ms in `setup_all` and restores the original in `on_exit` (delete when it was originally unset) so the two sweep tests do not each pay the full fixed 1000 ms — its assertions are unchanged. Because it is BEAM-global, `slots_test.exs` must stay `async: false` while overriding it.
  Its caller-supplied-duration case passes 20 ms (the stored deadline must be `>= 20` and far below the 60 s default), and the "does not reschedule once the backoff has expired" probe waits 100 ms — a 10× margin over the 10 ms epsilon.
- The worktree retry backoff is a CALL-TIME app-env seam `:worktree_retry_delays` (read inside `EvoGit.AgentScheduler.WorktreeRetry` by `delay_stream/1` — an explicit `:delays` opt still wins — production default `[50, 100, 200]`); `worktrees_test.exs` sets it to `[0, 0, 0]` in `setup_all` and restores it nil-aware in `on_exit` so its two DELIBERATE-failure tests (branch-deletion failure, `rm_rf` failure on a read-only dir) still run the same attempt counts without paying the retry sleeps. The failure shapes, attempt counts and warning/escalation assertions are unchanged.
- SchedMeta seeding idiom for sched-meta tests: `:ets.insert(:evogit_sched_meta, {id, %SchedMeta{...}})`; plain maps work where lib only dot-accesses one key (`Store.get_sched_meta` matches `%{}`).
- `WorktreeManager.maybe_init_repo/3` is PRIVATE — per-repo init scoping tests exercise it through the public `create_worktree_for_agent/6` with a spec `repo_id` ("primary" vs foreign id), each test needing a fresh temp repo (persistent per-repo `:evogit_worktree_repos` marker skips the wipe on subsequent inits).
- `EvoGit.Core.ForeignRepo` struct requires `root:` (no default) when building test structs.
- **`worktrees_test.exs` reclaims are awaited EVENT-DRIVEN, never by polling the filesystem or git.** The manager runs the whole destroy (reap jobs → `rm_rf` → `worktree prune` → branch delete) INSIDE its `:DOWN` handler before dropping the registration, and `:sys.get_state(WorktreeManager)` is answered only after the messages already in the manager's mailbox have been processed — so `await_manager_dropped/2` "no registration for this agent" MEANS the reclaim completed, at one message round trip per probe instead of a sleep plus a `git branch --list` fork.
  The `refute File.dir?(wt_path)` / `refute Git.branch_exists?/2` assertions remain as the exact end state.
  Create completion is awaited as a MESSAGE (the `{:agent_ready, ...}` reply of the `spawn_agent/6` stand-in), never by polling for the transient worktree dir.
- **`worktrees_test.exs` runs on the PLAIN `git worktree add` create path**: `setup_all` calls `EvoGit.Adapters.CowWorktree.disable()` and `on_exit` erases `:persistent_term` key `:evogit_cow_worktree_enabled`, so the pristine `:not_set` state is restored for the rest of the run.
  The CoW pipeline costs 7 subprocesses per create versus 5 for the plain path, CoW itself is covered by `adapters/cow_worktree_test.exs`, and the plain path is also real production (Windows, no `cp`, per-create fallback) — every assertion in this file holds on it.
- **Both worktree suites prime each copied fixture repo and pre-seed the per-repo init marker.** `setup_all` pins a repo-local identity in the template's `.git/config` AFTER its initial commit (so the commit sha is unchanged), and `setup` calls `EvoGit.GitEnv.prime_config_identity_cache(tmp_dir, "Genesis", "noreply@evogit.ai")` — byte-identical to what the fresh copy would resolve on its own, minus the two `git config` forks every new repo path pays on its first git call.
  `setup` also inserts `{tmp_dir, 0}` into `:evogit_worktree_repos`, so the first create takes the marker-present path (`ensure_workers_dir` only — no workers-dir `rm_rf`, no `git branch --list`, no `git worktree prune`); that row is removed in `on_exit` with a targeted `:ets.delete/2`.
  A test that must exercise the genuine first-create init opts out with `@tag lazy_init: true` — in `worktrees_test.exs` the two per-repo init scoping tests and the marker-absent restart test; any NEW test asserting on first-create init must carry that tag.
- `worktrees_test.exs` — NEVER pass `self()` as the monitored agent pid to `WorktreeManager.create_worktree_for_agent/6`: the resulting `:live` registration can only be drained by the test process exiting, so its `:DOWN` cleanup (inline `git worktree prune` / `git branch -D`, spawned with `cd: repo_root`) fires during `on_exit` teardown and races the setup's `File.rm_rf!(tmp_dir)` — when rm_rf wins, the ERTS port program prints `spawn: Could not cd to /tmp/evogit_worktrees_<int>` to stderr (not a Logger message; `capture_log` cannot hide it). Route every create call through the file's `spawn_agent/6` stand-in process (the production shape — the manager monitors the caller) and drain it with `finish_agent/3` (monitor + `:exit_please` + `assert_receive {:DOWN, ...}` + `await_manager_dropped/2`, then the exact `refute File.dir?` / `refute Git.branch_exists?/2` end-state assertions) BEFORE the test ends. A test may skip the drain only when its registration provably cannot outlive it in the shared named manager: the process under test exits mid-test with its cleanup awaited in-test, or the manager instance owning the registration is terminated in-test (e.g. `restart_manager/0`) with no sched_meta row to re-monitor it.

## Global-State Hygiene (BEAM-global ETS + app env)

**Rule: any test that inserts rows into a VM-GLOBAL named ETS table must delete exactly those rows in an `on_exit`.**
Those tables are created once at app boot by `EvoGit.Application.start/2` and owned by the application process, so a row outlives its test process and stays visible to every module that runs later in the same BEAM (the per-file `create_ets_if_missing/1` helpers are no-ops under `mix test`; their `:ets.whereis/1` guards only matter for `--no-start`).
Tables in play in this node: `:evogit_agent_state`, `:evogit_sched_meta`, `:evogit_cancelling_tasks`, `:evogit_worktree_repos`.
A leaked `:evogit_agent_state` row is a REAL flake cause, not cosmetic: `EvoGit.AgentScheduler.Slots.resolve_model_id/2` reads the agent's `model_id` from that table and falls back to the scheduler default ONLY for an id that has no row, so a stale row for a small literal id reroutes another module's slot request into that row's model pool (an empty pool grants immediately instead of queueing, which makes a "waiting" assertion unreachable → deadline burn + failure under host load). The victim shape is literal small ids (1, 2, 99) reused across modules.
Prefer TARGETED deletion of the inserted ids over a wholesale `:ets.delete_all_objects/1`, which could nuke rows another module legitimately owns; keep the cleanup idempotent (`:ets.delete/2` on a missing key is a no-op, guard `:ets.whereis/1` when the table may not exist).
App-env seams (`:llm_backoff_sweep_epsilon_ms`, `:max_concurrent_worktree_creation`, `:worktree_create_fun`) and OS env (`XDG_CONFIG_HOME`, `GENESIS_SOURCE_ROOT`) must be restored nil-aware (delete the key when it was originally unset).

Per-file state (current):
- `slots_test.exs` — targeted: `put_meta/2` and `put_agent_state/2` (the ONLY insert sites) each register an `on_exit` deleting exactly that id from their own table via the guarded, idempotent `delete_ets_row/2` (ids inserted: 1, 2, 3, 4, 99; models `"default"`/`"fast"`). Its `setup` still wipes both tables at test start as the module's defensive precondition; there is deliberately NO wholesale teardown.
- `remote_api_test.exs`, `worktree_admission_test.exs`, `worktrees_test.exs` — wholesale `clear_ets/0` (`:ets.delete_all_objects/1`, `:ets.whereis/1`-guarded) in `on_exit`; complete. `remote_api_test.exs` additionally deletes its injected `EvoGit.Store` task row targeted, `worktree_admission_test.exs` restores both app-env seams nil-aware.
- `lifecycle_test.exs`, `store_test.exs`, `pending_user_messages_test.exs` — NO teardown and NO wipe (they are `async: true`): every row is keyed by a per-test-unique id from the module's own range (`lifecycle_test.exs` 9_700_000+, `store_test.exs` / `pending_user_messages_test.exs` 9_950_000+), so a leftover row is invisible to any other module.
- `agent_scheduler_test.exs`, `dispatch_custom_agents_test.exs`, `subagents_test.exs` — targeted per-id `:ets.delete` in `on_exit` for every row they insert (agent_scheduler_test keeps its 3 model-concurrency restores in `try/after`; dispatch_custom_agents_test restores `XDG_CONFIG_HOME` + `ModelSelector.invalidate/0` nil-aware).
- `pubsub_test.exs` (PubSub unsubscribe + `Process.register/2` of the captured Throttle pid), `dispatch_test.exs` (nil-aware app-env + `GENESIS_SOURCE_ROOT` restore in `try/after`) — complete.
- `state_test.exs`, `worktree_retry_test.exs`, `foreign_worktree_test.exs` — insert nothing global (only process-dict / temp dirs).
- `worktrees_test.exs` + `worktree_admission_test.exs` — pre-seed exactly one `:evogit_worktree_repos` row (`{tmp_dir, 0}`, each keyed by a unique temp path) and delete that same row in `on_exit` with a targeted `:ets.delete/2` (`:ets.whereis/1`-guarded); nothing global survives the test.
**Order dependence to preserve:** `state_test.exs` (`async: true`) READS the global tables for literal id 3 without inserting (`Slots.handle_request_llm_slot(3, …)` → `resolve_model_id/2` + depth lookup) and asserts the scheduler-default fallback. It is safe only because the async cohort fully drains before any `async: false` module runs, and because the sync module that seeds id 3 (`slots_test.exs`) seeds it on model `"default"` — the same model `state_test.exs` assumes. Never flip `slots_test.exs` (or any id-3 seeder) into the async cohort — and an async module must never write small literal ids at all: `lifecycle_test.exs` moved to its own `unique_agent_id/0` range for exactly this reason (it used to seed 1-4, id 3 included).
**How to verify a no-leak claim** (used to prove the `slots_test.exs` teardown): add a TEMPORARY sync probe module whose single test asserts `:ets.lookup(:evogit_agent_state, id) == []` (and the same for `:evogit_sched_meta`) for each literal id the module under test inserts, then run it in ONE BEAM after that module — `mix test --seed 3 --max-requires 1 <probe> <module>` — because `mix test` SHUFFLES the file list by seed and ExUnit runs sync modules in reverse of the shuffled list, so module order must be confirmed with `--trace` (with `--seed 3` the probe runs second). The leak is only observable when the LAST-executed test of the module under test inserts a row (each test's `setup` re-wipes the tables at start), which is why the seed matters. Delete the probe afterwards.
