# evo_git/agent/stream — P4 Push-Only Streaming Tests

## Intent
ExUnit coverage for the P4 push-only streaming layer (`docs/agent-runtime-refactor.md` §3 D5, §4.6, §4.7, §4.12, §5 P4 and §7 invariant 2): the watcher gate, delta coalescing, per-session `seq` reconciliation, the `:interrupt` early-turn path, and the cheap inspection reads (roster summary rows + bounded history snapshot).
The production modules under test are `EvoGit.Agent.Stream` (`agent/stream.ex`), `agent/stream/{sink,watchers,batcher,snapshot,interrupted,CONTEXT}.ex`, `agent/session.ex` (the `:watch`/`{:snapshot}`/`{:input, …}` arms) and `agent_scheduler/remote_api.ex`'s inspection functions.
Each file mirrors the production module family it pins; the cross-node `EvoGit.RemoteNode` watch verbs are covered by `subscription_test.exs` (local-node path only — the `:erpc` route needs a real remote BEAM).
## Files
- `subscription_test.exs` (`EvoGit.Agent.Stream.SubscriptionTest`, `async: true`) → the IDEMPOTENT-subscription contract: two `Stream.subscribe/1` calls from one process deliver ONE copy of a batch, `unsubscribe/1` clears the memo (a later subscribe receives again) and is idempotent, the memo is consumer-local (a second process holds its own subscription), `EvoGit.RemoteNode.watch_agent/2` subscribes the CALLER + registers it + answers the FLAT `{:ok, %Snapshot{}, seq}` with no duplicate delta on a re-watch, a REFUSED watch leaves no subscription, `unwatch_agent/2` always clears the local subscription, and `watch_snapshot/2` registers/subscribes nothing.

- `pure_contract_test.exs` (`EvoGit.Agent.Stream.PureContractTest`, `async: true`) → the process-free contract: `topic/1`, `stale?/2` (including fail-closed non-integer pairs), `normalize_batch/1`, the whole `Batcher` (75 ms window, emission order, `take/1` never re-arms), the pure `Watchers` functions and the ONE `Watchers.flush/4` broadcast site (empty ⇒ silent, zero watchers ⇒ dropped with `seq` unchanged, one watcher ⇒ exactly one `{:agent_delta, …}`), `Snapshot.from/2` producing no `%ReqLLM.Context{}`, and the `Interrupted` exception messages.
- `gate_test.exs` (`EvoGit.Agent.Stream.GateTest`, `async: true`) → unwatched publication silence, watched coalescing, sequence ordering and a synthetic subscribe→snapshot gap; its installed-unwatched-sink expectation of `[]` at line 63 contradicts production's capture-independent contract, which returns all four callbacks whenever a sink exists.
- `watcher_lifecycle_test.exs` (`EvoGit.Agent.Stream.WatcherLifecycleTest`, `async: true`) → (d) watcher `:DOWN` clears the gate, removes the entry/monitor and silences the next exchange; (e) a SELF-subscribed consumer registered with `register_watcher/2` (the local-pid equivalent of a remote consumer) receives pushes and its death closes the gate; (f) N unwatched agents produce zero messages on their own topics.
- `interrupt_test.exs` (`EvoGit.Agent.Stream.InterruptTest`, `async: true`) → (g) `start_input(pid, msg, :interrupt)` appends the message BEFORE signalling the worker, `Sink.interrupt_requested?/0` consumes the `{:evogit_interrupt, ref}` exactly once, the `{:interrupted, reason}` seam result ends the turn with NO assistant message and re-enters the loop so the drained message reaches the next LLM context; and with zero watchers the interrupt degrades to next-turn-boundary delivery without losing the message.
- `inspection_test.exs` (`EvoGit.Agent.Stream.InspectionTest`, `async: false`) → (h) the roster is a summary-row read with no conversation (`RemoteAPI.list_agents/0` / `get_agent_state/1` never call a session and carry no `:context`), history is the snapshot path (`get_agent_history/1` live vs `[]` for a gone/never-registered session, bounded by a `Task.await/2` deadline so a hang fails instead of wedging), and the streaming reads on a nonexistent target are total.

## Shared Fixtures
`test/support/stream_case.ex` (`EvoGit.Agent.StreamCase`, a `CaseTemplate`) is the ONE harness: per-test-unique agent ids (`9_960_000 + System.unique_integer/1`), production-shaped `%AgentState{}`/`%SchedMeta{}` rows with `on_exit` cleanup, `start_session/1` + `dispatch_ctx/3` (a repo-less dispatch context whose `:exchange_opts` carries the `:llm_call` engine seam and the test pid as `scheduler:`/`notify:`), and the driver seams `driver_llm_call/1` (each attempt sends `{:llm_call, worker_pid, context}` and answers `{:reply, text}` / `{:emit, events, text}` / `{:emit_waves, waves, text}`) plus `response/2`, `collect_deltas/3`, `pending_messages/1` and the bounded `wait_until`/`await_*` helpers.
It also defines the two inline roles ABOVE the template: `InteractiveAgent` (`session_mode :interactive` — a tool-free reply yields and parks) and `OneshotAgent` (`:oneshot` — a tool-free reply completes the run).
Do not build a second session harness here; extend this one only in an additive way (all five session-based suites depend on it; four are async and inspection is synchronous).

## Execution-Activity Coverage Boundary
`pure_contract_test.exs:312-356` pins snapshot agent identity, phase, seq, turn, token/usage counters, messages, mode, model_spec and compression_count without asserting an exhaustive key set, so additive snapshot fields do not inherently break these tests.
Its no-context check inspects only top-level snapshot values and does not actually JSON-encode or recursively validate the snapshot.
`pure_contract_test.exs:99-108,120-134` preserves a synthetic `{:tool_call, nil, "read"}` event in generic batch normalization/order checks, but no suite here drives a real tool execution or asserts current-call identity, arguments, start/finish, execution activity or tool-result events.
`gate_test.exs:171-245` proves batch sequence monotonicity and stale-delta rejection but does not prove that an in-flight execution projection recovered by a snapshot equals replayed execution deltas.
The shared LLM seam bypasses real provider callbacks; the existing callback test checks names and arities only (`gate_test.exs:50-79`), not the payload produced by invoking `on_tool_call`.
`subscription_test.exs:89-158` tests RemoteNode watch/snapshot only on `node()`, so real cross-node routing remains outside this directory's coverage.

## Async Policy (this directory)
All suites are `async: true` except `inspection_test.exs`, which names its forcing global in-file: `EvoGit.AgentScheduler.RemoteAPI.list_agents/0` reads the BEAM-global `:evogit_sched_meta` / `:evogit_agent_summary` ETS tables table-wide (`:ets.select/2`), and the test repo's policy treats a table-wide global read as a serialization reason.
The other five suites write only per-test-unique ids into those same tables, delete exactly their own rows, assert only on their own agent's topic, and touch no app-env key, Logger level or `:persistent_term` entry — so they stay `async: true`.

## Notes for Agents
- **`Phoenix.PubSub.subscribe/2` is NOT idempotent** (the Registry runs `keys: :duplicate`): subscribing the SAME process to the same topic twice makes every broadcast arrive TWICE. `Stream.subscribe/1` is the ONE guarded primitive over it — a CONSUMER-LOCAL `Process` memo of subscribed topics makes a repeat subscribe (and therefore a repeated `watch/1` or `RemoteNode.watch_agent/2`) a no-op — while `register_watcher/2` still deliberately subscribes nothing. Raw `Phoenix.PubSub.subscribe/2` in a test bypasses the memo, so `subscribe_topic/1` must be called at most once per topic; the `gate_test.exs` gap simulation relies on broadcasting without re-subscribing.
- **No `process_stream/2` trace test is meaningful here.** Every suite drives the exchange through the `:llm_call` engine seam, which REPLACES `LLMPrompting.prompt_until_tools_or_limit/5` — so `ReqLLM.StreamResponse.process_stream/2` is never called and `:erlang.trace` over it would vacuously pass in both the watched and unwatched case. `pure_contract_test.exs`/`gate_test.exs` pin `Sink.stream_opts/0` at the exact argument the real call site passes instead; turning the real streaming path on needs a loopback SSE responder plus a global scheduler model pool (the `implicit_completion_test.exs` machinery) for no extra coverage.
- **The `{:interrupted, reason}` seam return is the production contract**: `ToolDispatch.do_turn/6` treats it as a non-error early turn end (no assistant message, no retry, no grace turn) and re-enters `loop_fn.(state)` so the loop TOP drains the queued message. `{:error, …}` would instead be a failure path.
- `Sink.install/2` and its four streaming callbacks are watcher-independent, so an unwatched session captures live call text/thinking and supports chunk-level interruption while public batches, timers, sequence consumption and broadcasts remain gated.

## Additive Regression Priorities
Pure Sink tests can install against the test process, start a turn, start calls with attempt indices `[0, 1, 0]`, and require three distinct IDs with the same turn plus replacement of previous attempt text/thinking.
Capture callbacks for call A, start call B, then invoke A's text/thinking callbacks and phase events to prove old envelopes retain A's identity and the Activity reducer leaves B unchanged with no public events.
The installed-unwatched callback test must invoke binary text/thinking callbacks and the interrupt callback, not merely check callback names/arities; no-sink `[]` remains valid.
The existing gap test injects a synthetic broadcast after collecting flushed waves, so it does not prove watch/snapshot flushes a genuinely pending batch before returning coherent activity and sequence.
A deterministic pending-batch test should queue activity messages and the actual snapshot/watch call from one sender while the session is briefly suspended, then resume and assert returned activity is exact, covered deltas are stale, newer appends apply once, and the pending batch is drained without relying on a race against 75 ms.
Real retry/nudge hook coverage cannot use the `:llm_call` engine seam because it replaces LLMPrompting entirely; parent source calls `Sink.start_call/1` before each outer slot acquisition, retries increment attempt, and a nudge restarts attempt at zero with a fresh ID.
A real LLMPrompting regression needs existing serialized scheduler/loopback HTTP machinery or a new lower-level process-local seam; manually calling start_call pins the Sink contract only, not retry/nudge wiring.
Stale worker rejection and session yield/cancel/terminal retirement are session-owned tests, separate from stale call-ID reducer and captured-callback tests here.
The legacy on_tool_call callback emits unkeyed `{:delta, [{:tool_call, nil, name}]}` and does not provide the stale-call protection of keyed text/thinking activity.
- A scripted turn logs one captured `EvoGit.Agent.Cost: recompute/3 failed (…) — keeping the reported cost` warning: the harness's `response/2` carries the non-catalog model id `test:model`, so pricing cannot be recomputed and the reported cost is kept (best-effort by design). It is captured by `capture_log: true` and never reaches the console on a green run.
