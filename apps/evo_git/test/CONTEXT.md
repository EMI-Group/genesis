# Test Directory

## Intent
ExUnit test suite for the EvoGit OTP application. Validates core domain logic, git adapter operations, agent tooling, and context node handling using real git operations on temporary filesystem sandboxes — no mocks.

## Routing Table
- `evo_git/` → Test files mirroring source structure (core, adapters, agent tools, project config tests)
- `evo_git/skills/` → Skills subsystem tests (executor injection safety + sandbox routing)

- **`store_test.exs`** — `EvoGit.StoreTest` (`async: false`, ~1500 lines): `EvoGit.Store` GenServer behavior — encode/decode round-trips, insert/update/select/delete paths, lightweight narrow reads, the **skip-and-log semantics** for undecodable rows (`safe_select_all_tasks/1`, `safe_select_all_projects/1`: bad rows SKIPPED + `Logger.warning`, retained untouched in the live table, and the `*_quarantine` tables are never created — asserted via `sqlite_master`), **`updated_at` write semantics** (put_task stamps fixed-precision ISO; `update_task_columns` auto-bumps it; `update_lease_expires_at` does NOT bump it), **`select_tasks_changed_since/2`** (15-key projection, strict `updated_at > since`), and **Codec result/opts round-trips** (string-tagged result encoding: `{:ok,_}`/`{:error,_}`/`{:exit,_}`/plain-string tags; non-JSON-encodable terms round-trip via the string-tagged inspect fallback — `Codec.decode_result(Codec.encode_result({:weird_term, 1})) == "{:weird_term, 1}"`; `Codec.decode_result/1` raises ArgumentError on any non-canonical input — only string-tagged results decode, raw strings and untagged JSON do not; opts JSON-object encoding with string keys — booleans/atoms preserved — `Codec.decode_opts/1` raises ArgumentError on ANY non-object JSON, including the pair-array `[["path","/x"]]` and the flat `["path","/x"]` form). Note: under the strict canonical codec, decode functions raise on ANY bad/non-canonical value — `opts = "[1,2]"` (valid JSON, wrong shape), a raw-string `result`, or INTEGER `last_opened_at` in a pre-created INTEGER-affinity `projects` table all raise and are skipped+logged (SQL NULL still decodes to nil and passes through).

- **`store_disk_full_test.exs`** — `EvoGit.StoreDiskFullTest` (`async: false`, `use EvoGit.TaskRegistryCase` — isolated Store + TaskRegistry per test): the disk-full write-error boundary in `EvoGit.Store`. **Arm technique: `PRAGMA query_only = ON` on the Store's own connection** (obtained via `:sys.get_state`, then `XqliteNIF.query` — SET pragmas must go through `query`, `execute` returns `:execute_returned_results`) — every write fails with genuine `{:error, {:read_only_database, 8, ...}}` (SQLITE_READONLY), one of the three classified disk-full codes; `OFF` clears it for the retry test. **Why not the alternatives (root-proof/CI-safe rationale, documented in the file moduledoc):** chmod 0444 on the DB file does NOT block WAL writes; chmod 555 on the dir is bypassed by root; and a `RAISE(FAIL, 'database or disk is full')` trigger does NOT reach the classifier (see Known Issues). Coverage: (1) classifier unit tests for `EvoGit.Store.Errors.disk_full_error?/1` — positive shapes (codes 13/10/8, `read_only_database` variant, message fallback case-insensitive) + negatives (`{:ok,_}`, code 19 CONSTRAINT, unknown code + nil message, non-tuple); (2) `put_task` → `{:error, :disk_full}` with `Store: DISK FULL` warning naming the DB path, GenServer alive, reads keep working, retried write succeeds after condition clears; (3) TaskRegistry degradation — `start_task` (direct `GenServer.call` `{:start_task, id, :genesis, [path: "/tmp/test"]}` form) replies `{:ok, %TaskInfo{}}` unchanged, logs "continuing in-memory only", registry alive, task tracked in `state.task_refs` (NOT in `list_tasks()` — that is DB-backed). **Not testable in CI:** a real `SQLITE_FULL` from an actually-full disk, and the non-disk-full MatchError crash path (classifier unit tests pin the mapping instead; the crash path would kill the shared test Store).

## Known Issues

### ⚠️ `RAISE(FAIL, 'database or disk is full')` triggers do NOT reach the disk-full classifier (empirically verified)
The `EvoGit.Store.Errors` moduledoc claims the message-text fallback in `disk_full_error?/1` "catches synthetic `RAISE(FAIL, ...)` triggers with primary code 1". **This is inaccurate** (verified empirically): SQLite reports trigger RAISEs as `SQLITE_CONSTRAINT_TRIGGER` (primary code 19), and xqlite classifies that as `{:error, {:constraint_violation, :constraint_trigger, %{message: ...}}}` — a shape `disk_full_error?/1` deliberately does NOT match (only `{:read_only_database, ...}` and `{:sqlite_failure, ...}` tuples are classified). A RAISE-triggered write therefore hits the MatchError crash path, NOT the graceful `{:error, :disk_full}` path. Do NOT re-attempt the trigger technique for disk-full tests; use `PRAGMA query_only = ON` on the Store's own connection instead (see the `store_disk_full_test.exs` entry). The lib moduledoc could optionally be corrected — the classifier's actual behavior is correct; only the doc claim about RAISE triggers is wrong.

### Bootstrap test notes
- The `"platform override skips the probe and fails at download"` test goes through `RemoteBootstrap.download_url/1` — deterministic and network-free (direct `releases/latest/download/...` URL), so the remote download (curl first, wget fallback) always fails at the ssh level (the fake target has no reachable asset), and the local curl fallback also fails. Assertion is deliberately broad. This test also emits a downloader error line (`curl: (22) ... 404` or wget's equivalent) — harmless.
- The `connect/1` test emits a `Failed to enable distribution` warning (`:net_kernel` can't start in test env) — harmless; the test only asserts the error is NOT `:local_node_not_distributed`.

### Full-suite parallel-run flakiness (pre-existing, verified)
Running the whole suite `mix test apps/evo_git/test` (parallel, max_cases 16) intermittently fails 1-3 timing-sensitive tests that ALL pass in isolation — observed failing: `EvoGit.Sandbox.TruncationTest` ("temp file cleanup does not leave temp files behind after completion"), `EvoGit.Sandbox.MacOSTest` ("resolve_tmpdir/0 falls back when TMPDIR points outside every tmp path"), and `EvoGit.Agent.ToolDispatchRetrySlotTest` ("releases the LLM slot between retry attempts..." and "a paused scheduler blocks the retrying agent's next attempt..."). The failing set varies run-to-run and was reproduced on a feature-free base commit — this is test pollution/timing under parallel load, NOT a regression from any specific feature. Guidance: re-run the suspect file(s) in isolation before treating full-suite failures as regressions.

## Constraints
- Tests use `@moduletag :tmp_dir` which provides a temporary directory via ExUnit's built-in fixture mechanism.
- No mocking libraries — all git tests use real `git` operations on temporary filesystem repos.
- Test module names mirror the source module path under test (e.g., `EvoGit.Core.ContextNodeTest` tests `EvoGit.Core.ContextNode`).
- Each test file is self-contained; `DummyAgent` modules are defined inline where needed to test the `Agent` behaviour.
