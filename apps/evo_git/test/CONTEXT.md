# `:evo_git` Test Suite

## Intent
The ExUnit suite for the `:evo_git` core runtime — real git operations against per-test temp directories, no mocks.
Per-file detail lives in the child CONTEXT.md files below; this file carries only intent, routing, the cross-cutting async-safety policy, shared infrastructure, current known issues, and constraints.
Full per-file history lives in git (`git log -p -- apps/evo_git/test/CONTEXT.md`).

## Async-Safety Policy
`async: true` is allowed ONLY for a module whose tests mutate no BEAM-global state another concurrently-running module can observe.
A module MUST be `async: false` when any test redirects a process-wide env var read by production code (`XDG_CONFIG_HOME`, `PATH`, the app-level `:data_dir`), or mutates an app-env key read by other modules, or mutates `:persistent_term` read by others.
A module MUST also be `async: false` when any test touches the global `EvoGit.AgentScheduler`, the global `:evogit_*` ETS tables, the app-level `EvoGit.Store` / `EvoGit.TaskRegistry` singletons, the `EvoGit.RemoteConnection` Registry/DynamicSupervisor, or a shared PubSub topic it asserts on without node/id filtering.
`EvoGit.TaskRegistryCase` is NOT itself a serialization reason: it starts a UNIQUELY-NAMED isolated `EvoGit.Store` + `EvoGit.TaskRegistry` pair per test (explicit child `id:` override) and never touches the app-global singletons, so `use EvoGit.TaskRegistryCase` may be `async: true`.
The 9 `EvoGit.TaskRegistryCase` modules still `async: false` each name a SEPARATE forcing global: `persistence_test` (app-global `:evogit_sched_meta` table clear/seed + the global `EvoGit.AgentScheduler` on the cancel paths), `completion_logging_test` (global `Logger` level), `finalizing_watchdog_test` (app-env `:finalizing_watchdog_grace_minutes`), `task_executor_reflect_test` / `command_shell_test` / `cli_task_routing_test` / `reflect_tools_test` (global `EvoGit.AgentScheduler` `model_profiles` via `without_model_profiles/1`), `command_shell_test` / `command_approval_test` (app-env `:command_approval_timeout`), and `task_registry/task_tmpdir_reclaim_test` (process-wide `XDG_CONFIG_HOME`, isolated to select a test-owned `[tmp]` mode so the real `/tmp/genesis` is never touched).
Every forced-`async: false` module carries an in-file comment/`@moduledoc` naming the exact BEAM-global that forces serialization — keep it accurate when the forcing state changes.
The async setting is **per MODULE, not per file** — two files carry two test modules each: `command_shell_test.exs` = `EvoGit.CommandShellTest` (`EvoGit.TaskRegistryCase`, sync) + `EvoGit.CommandShellParsingTest` (`async: true`), and `command_approval_test.exs` = `EvoGit.CommandApprovalTest` (`EvoGit.TaskRegistryCase`, sync) + `EvoGit.CommandApproval.RequestTest` (`async: false`). A one-`use`-line-per-file scan misclassifies both.
Inventory (census — module count = explicit `use ExUnit.Case` / `use EvoGit.TaskRegistryCase` lines, the two mutually exclusive so they sum to the total; `defmodule` total = lines beginning with `defmodule`, inline helpers incl.): 150 test modules (173 `defmodule`s incl. inline helpers) — 84 `async: true`, 66 `async: false`, 0 untagged; 16 modules use `EvoGit.TaskRegistryCase` (7 `async: true`, 9 `async: false`).

## Sync-Tail Cost Profile (measured)
Suite wall clock = the `async: true` phase + the serial sum of the `async: false` modules (ExUnit drains the entire async cohort before it runs any sync module, then runs those one at a time), and the sync phase is the larger part (~25s of ~33s) — so only work removed from it, or made cheaper, shortens the suite.
Largest sync contributors (per-test sums from a full run; each file's own CONTEXT.md carries the detail): `agent/tool_dispatch_retry_slot_test` (~4.4s standalone, dominated by the one-off `LLMDB.load/1` — see `./evo_git/agent/CONTEXT.md`), `agent_scheduler/worktrees_test` ~3.1s, `remote_connection_test` ~2.4s, `adapters/cow_worktree_test` ~2.2s, `self_reflective_source_test` ~0.7s, `agent/tools/complete_task_test` ~1.8s, `git_env_test` ~0.9s, `agent/tools_test` ~0.8s, `agent_scheduler/agent_scheduler_test` ~0.6s, `adapters/github_test` ~0.6s.
Every one of those is blocked by a hard global (the global `EvoGit.AgentScheduler`, a named `:evogit_*` ETS table, the app-level `Store`/`TaskRegistry` singletons, the `RemoteConnection` Registry/DynamicSupervisor, `:persistent_term`, or a process-wide `XDG_*`/`PATH`/git-identity env var) and each file's `@moduledoc` names its own — none of them can be flipped by a tag change.
`EvoGit.TaskRegistryCase` cohort (measured): its serialized share is SMALL — moving its 6 now-`async: true` modules out of the sync phase (the `task_registry/` `cleanup` / `lease_heartbeat` / `store_skip_and_log` / `merge_context` / `resume_context` modules plus `store_disk_full_test`) removed ~0.7s of sync and netted ~0.6s of total wall clock (the ~28-way async cohort absorbs it at ~0.1-0.2s), so the cohort is not a large sync-tail lever.
The cohort unlock is BELOW the full-suite A/B noise floor (this machine's full-run total varies by ±3-7s across runs), so measure it per-directory in isolation (~2.4s→1.9s sync for the `task_registry/` directory) rather than by full-suite A/B.
The largest cohort member `task_registry/persistence_test.exs` (50 tests) stays serialized because its `describe "recheck_task resolution"` clears/seeds the app-global `:evogit_sched_meta` ETS table (also used by the `async: true` `agent_scheduler/subagents_test.exs`) and its cancel paths drive the global `EvoGit.AgentScheduler` — unlocking it needs a production seam, not a test edit.
**Do NOT split a module into an `async: true` module just to shrink the sync number**: an 11-run interleaved A/B of exactly such a split (69 tests moved to `async: true` + 5 left serialized) reliably moved ~1.1s out of the sync phase but added ~1.0-3.2s to the async phase (the moved git/shell tests inflate under the ~28-way async cohort), for adjacent-pair TOTAL deltas of +0.1s / +0.2s / +0.5s — the split was reverted. TOTAL wall clock, not the sync figure, is the criterion for any sync→async move.
The `mix/tasks/` suites were flipped to `async: true` via the production call-time `root:`/`shell:`/summarizer seams (opts-injection — no VM-wide `File.cd!`, no global `Mix.shell/1` swap, no app-env seam writes), and the `self_reflective_source_test` non-git resolution fixtures were reduced to plain temp dirs — together ~9-11s off the full-suite wall clock in an interleaved A/B (baseline ~41-44s → ~32-33s; sync ~29.7s → ~25s).
Rejected candidates, with the blocking reason: `cow_worktree_test` keeps a second hard global (`XDG_CONFIG_HOME` is read live by `EvoGit.Config.resolve/1` on the code path that module exercises, and `EvoGit.Config` exposes no seam at all); `github_test` / `remote_node_github_test`'s test mechanism IS process-wide `PATH` (read by every concurrent module's subprocess spawns); `self_reflective_source_test` has only 0-arity production readers (wide blast radius, and an already-`async: true` sibling — `agent_scheduler/dispatch_test.exs` — mutates the same four env knobs) so it stays sync, with its git fixtures cheapened test-side instead.
Rejected for the store suites: `store_test.exs` / `store_summary_test.exs` own the app-global `EvoGit.Store`/`EvoGit.TaskRegistry` for the whole module (terminate/restart in `setup_all`) and register their isolated store under the canonical `EvoGit.Store` name, so going `async: true` would need a unique store name threaded through ~200 `Store.<fn>(Store, …)` call sites and ~150 test signatures — high-risk churn with no coverage benefit (they are already isolated per-test via a copied temp DB).

## Shared Infrastructure
`test_helper.exs` runs after app boot and before any test: it redirects `XDG_DATA_HOME` to a temp dir as a fallback guard against the production DB, sets the one global `:nix_enabled = false` default (nix is only consulted lazily, so setting it here is race-free for every async module; a few `async: false` sandbox modules still set it locally), then calls `ExUnit.start(capture_log: true)`.
The canonical DB guard is `config/test.exs` pinning `:evo_git, :data_dir` to a UNIQUE per-run path (`…/evogit_test_data/genesis-<os-pid>-<unique-integer>`): concurrent `mix test` runs and sibling worker worktrees never share a `tasks.sqlite`, and no rows accumulate across runs.
Each run's `after_suite` hook removes only its own dir (never the shared parent), so any whole-table or global-state failure is a REAL flake rather than test pollution.
`support/fake_gh.ex` — `EvoGit.FakeGh`: puts a fake `gh` on `PATH` (canned JSON, `GH_FAKE_MODE`, argv log); only usable from `async: false` modules, POSIX-gated.
`support/submodule_helper.ex` — the module is `EvoGit.TestSupport.Submodule` (name differs from the filename — grepping `SubmoduleHelper` finds nothing); builds gitlink/submodule entries without cloning.
`support/task_registry_case.ex` — `EvoGit.TaskRegistryCase` (used by 16 modules, 7 `async: true`): `setup` starts a UNIQUELY-NAMED isolated `EvoGit.Store` (`evogit_test_store_<n>`) + `EvoGit.TaskRegistry` (`evogit_test_registry_<n>`) via `start_supervised!/1` with an explicit child `id:` override (both modules hardcode `id: __MODULE__` in `child_spec/1`), on a fresh per-test SQLite DB under a temp dir, then sets `:evogit_task_registry_server` + `:evogit_test_store` in the TEST process and returns `%{data_dir: root, sqlite_path: sqlite_path, store: store_name, registry: registry_name}`.
`TaskRegistry.server/0` resolves the registry name from the `:evogit_task_registry_server` pdict at CALL time (falling back to the `EvoGit.TaskRegistry` singleton), so in-test `EvoGit.TaskRegistry.*` calls hit the isolated instance; `EvoGit.Store` needs no seam because every client function takes the store name as its first arg — the case exposes the isolated name via `store/0`.
Helpers: `store/0`, `trigger_cleanup!/0` (direct `Cleanup.cleanup_expired_tasks/1` against the isolated store), `cleanup_process/1`, `old_age_days/0`, `within_age_days/0`.
No `EvoGit.Supervisor` child is ever terminated or restarted.

## Known Issues
**`EvoGit.SystemSampler` interval can only be changed via restart**: the sampler starts before `test_helper.exs`, so setting `:system_sample_interval_ms` there is too late; a test needing a fast tick sets the env and then calls `Supervisor.terminate_child/2` + `Supervisor.restart_child/2` so `init/1` re-reads it (`terminate_child/2` alone does NOT auto-restart a permanent child — it stays `:undefined`).
**No fake-LLM harness**: there is no Mox/Meck and no injectable LLM runner, so running a macro-driven agent to completion is not testable; the only no-real-LLM idioms are error paths (empty the scheduler `model_profiles` so `run_agent` replies `{:error, :llm_not_configured}`, or point a model at an unreachable `base_url`) plus hand-built `%ReqLLM.ToolCall{}` fed to pure functions.
**Parallel-load timing is the historical failure mode**: never assert tight wall-clock bounds; make waits event-driven rather than `Process.sleep`-based.
**Two concurrent full-suite runs in one checkout are inherently flaky (revision-independent)**: ExUnit's `@moduletag :tmp_dir` path is cwd-relative and deterministic (`tmp/<Module>/<test>-<md5>`), so two `mix test` processes in the SAME checkout collide on it; even in SEPARATE checkouts, `sandbox/macos_test.exs` (reads the VM-global `$TMPDIR`, which it mutates — see `./evo_git/sandbox/CONTEXT.md`), `system_sampler_test`, the `adapters/*` git tests and `agent_scheduler/subagents_test` flake under a 2-suite concurrent load. This reproduces identically at any commit, so it is NOT an async-regression signal — use two separate checkouts (distinct cwd) for a fair concurrent run and expect a small number of pre-existing flakes.
**The `sandbox/` suite has one env-dependent failure inside a Genesis agent worktree**: the agent shell exports `TMPDIR`/`TMP`/`TEMP` = the managed per-task dir, and `linux_test.exs:230` ("no per-task dir installed") clears only `TMPDIR`, so `System.tmp_dir!()` falls back to the still-set `$TMP`/`$TEMP` and `build_args/0`'s cwd leaks a `task_*` `ReadWritePaths` entry (the file's `resolve_tmpdir` assertion still passes). Not a regression from any change — verify with `env -u TMPDIR -u TMP -u TEMP mix test apps/evo_git/test/evo_git/sandbox/` (all pass).

## Constraints
`@moduletag :tmp_dir` supplies the ExUnit temp-dir fixture.
No mocking libraries — git tests use real `git` on temporary repos.
Test module names mirror the source module path under test.
Each test file is self-contained; inline helper modules (`DummyAgent`, `HintAgent`, …) are defined where needed.
`on_exit` callbacks run in a DIFFERENT process than the test, so the `EvoGit.TaskRegistryCase` pdict keys are NOT set there — an `on_exit` that calls `EvoGit.TaskRegistry.*` or a default-store `EvoGit.Store.*` silently hits the global singleton; capture and pass the isolated `store`/`registry` from the setup context instead.
