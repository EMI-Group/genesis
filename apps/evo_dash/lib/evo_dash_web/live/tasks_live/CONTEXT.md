# TasksLive — Tasks Page
## Intent
Support documentation for `EvoDashWeb.TasksLive` (`tasks_live.ex`), the cross-project task list page (`GET /tasks`): filtering by status, project, review state and session mode, search, server-side pagination, expandable task cards, and task actions (graceful cancel, force kill, pause, resume, close session, delete, clear history).
Node-aware — reads task history via `EvoDash.NodeContext` for both the local BEAM node and a remote daemon (the `genesis_server` release in remote-dev mode).
ONE page load transfers one page of the 18-key task SUMMARY projection (`pause_kind` included); the heavy per-card payloads (`result`, `usage`, `logs`) are fetched lazily per card on expand, and the agent archive arrives in bounded pages only after an explicit disclosure.
## Routing Table
- `tasks_live.ex` — the LiveView: filters, pagination, keyed task stream, modals, mutating events.
- `page_load.ex` — `EvoDashWeb.TasksLive.PageLoad`: the ONE async, exit-safe page-load path (spawn seams, loader task, pure helpers) over the summary projection.
- `task_detail.ex` — `EvoDashWeb.TasksLive.TaskDetail`: the lazy per-card DETAIL + PAGED ARCHIVE cache (async fetches, cache/in-flight guards, invalidation, seq/node stale guards, one-page prune).
- `session.ex` — `EvoDashWeb.TasksLive.Session`: stateless idle-session close confirmation markup (`confirm_close_session_modal/1`, `busy` attr driving the confirm button's disabled/spinner state).
- `EvoDashWeb.ModalHelpers` (`live/modal_helpers.ex`) — the `__using__` macro injecting `view_full_result/2`, `close_result_modal/1`, `view_full_options/2`, `close_options_modal/1`; only TasksLive uses it.
## Push-based change detection (no polling)
TasksLive is FULLY push-based — no poll, no dirty tracker, no `list_tasks_changed_since/2`.
`:evo_git` emits on the `EvoGit.PubSub` `"tasks"` topic, node-tagged:
- `{:task_updated, task_id, status, node}` — `status` is the task status atom (`:pending|:running|:awaiting_input|:finalizing|:cancelling|:pausing|:paused|:completed|:failed|:cancelled`) or `nil` for review-only mutations
- `{:task_deleted, task_id, node}`
`node` is the publisher's BEAM node atom.
TasksLive forwards both VERBATIM to `EvoDashWeb.LiveHooks.NodeAware.handle_task_info/2` (returns `{:noreply, socket}` — return its value directly, never re-wrap), which applies `event_from_current_node?/2` (event node vs `socket.assigns[:current_node]`; local viewing → `node()`) BEFORE scheduling a trailing-edge 300 ms debounce (`:node_aware_reload_tasks` + the `:tasks_reload_pending` flag) that coalesces bursts into one reload; foreign-node events are dropped before the debounce, so they never update the UI.
BEFORE delegating, a node-matching event drops that task's cached detail (`TaskDetail.invalidate/2`), so a stale `result`/`usage` is never re-rendered from cache.
Every LiveView receives each broadcast twice (TasksLive in `mount/3`, NodeAware in `on_mount/4`), so invalidating an already-EXPANDED card may refetch twice; the cache/in-flight guards keep that bounded and the debounce coalesces the page reload.
The `:node_aware_reload_tasks` handler never touches the store: the page refresh goes to `PageLoad.start(socket, socket.assigns.current_page, false)` (async; `show_loading? false` keeps the stale rows visible), the sidebar reload to `NodeAware.reload_tasks/1` (async), then `NodeAware.clear_task_reload_pending/1` clears the flag the moment the reload is DISPATCHED, so a later burst re-schedules as usual.
This single debounced reload serves local and remote nodes.
Unexpected messages fall through to the catch-all `handle_info(_msg, socket)`.
**Coalescing**: the debounce flag gates bursts and the page-load stale-guard gates overlapping loads — a burst arriving while a load is in flight spawns a new load (bumping the counter) whose result wins; the superseded result is dropped.
## Async page load (the only page-load path)
Every page load goes through `EvoDashWeb.TasksLive.PageLoad` (`tasks_live/page_load.ex`); the LiveView never fetches a page inline.
- `PageLoad.start/3` bumps the monotonic `:page_load_seq` (its only writer), optionally sets `:tasks_loading`, and hands the spawn fun to the `:tasks_page_load_hook` seam.
- `PageLoad.load/4` issues ONE `EvoDash.NodeContext.list_tasks_page/2` read (`limit: page_size`, `offset: (requested_page - 1) * page_size`, the current `filters`) plus `get_unique_paths/1` and the node's idle sessions (`list_awaiting_input/1`), returning `%{tasks:, current_page:, total_count:, total_pages:, project_paths:, awaiting_sessions: %{task_id => agent_id}}`.
- Rows are the 18-key summary projection — `id`, `status`, `review_status`, `started_at`, `finished_at`, `type`, `project_path`, `opts`, `branch_name`, `model_id`, `agent_count`, `base_sha`, `commit_sha`, `lease_expires_at`, `updated_at`, `error`, `session_mode`, `pause_kind` — never `result`/`usage`/`logs`/`archive_metadata`.
- There is NO second fetch: the store CLAMPS an out-of-range offset onto the LAST page of the filtered set (row total unchanged), so the returned page already IS the clamped page and only `current_page = min(max(1, requested_page), total_pages(total_count, page_size))` is derived arithmetically.
- `PageLoad.run/6` runs `load/4` in a supervised `EvoDash.TaskSupervisor` task behind `EvoDash.SafeCall.run/1` and ALWAYS sends exactly one `{:tasks_page_loaded, seq, node, result}` — even on an exit, a raise or a remote RPC failure.
- `result` is `{:ok, %{tasks:, current_page:, total_count:, total_pages:, project_paths:, awaiting_sessions:}} | {:error, reason}`; `reason` is a VALUE (`{:exit, reason}` / `{:exception, exception}` / a returned remote error), never a crash.
- **Stale guards** in `handle_info({:tasks_page_loaded, seq, node, result}, _)`: a `seq` older than `:page_load_seq`, or a `node` that no longer matches `socket.assigns.current_node`, drops the result.
- `show_loading?` is decided by the page's private `reload/3`: `socket.assigns.filtered_tasks == []` (a first load) shows the placeholder; every later filter/search/pagination/sort/session-mode/toggle/retry load sets `:tasks_refreshing` and leaves the mounted rows alone, so a keystroke never blanks and re-staggers the list.
- **Kickoff is connected-gated** (`handle_params/3`): `handle_params/3` also runs on the disconnected (static) render, whose async result is discarded, so the load spawns ONLY when `connected?(socket)`; the else branch assigns `:tasks_loading, true` so static HTML paints the same placeholder. Exactly ONE page load per navigation (pagination `push_patch` and every filter event still load — the guard is `connected?/1`, not first-only).
- **Three independent load counters**: `:page_load_seq` (page load, `PageLoad.start/3` only writer), `:tasks_load_seq` (`NodeAware`'s sidebar fetch, `request_tasks_load/1` only writer, `handle_tasks_result/2` requiring an exact match) and `:task_detail_seq` (`TaskDetail`). The debounced reload spawns both page and sidebar loads, so a shared counter would invalidate the other's in-flight result. Never merge them; never bump `:tasks_load_seq` from this file.
- **`:tasks_page_load_hook`** is a 1-arity app-env seam (default identity) resolved at spawn time like EvoDash's other runner seams; it exists so tests can count page-load spawns (`:page_load_spawned`).
- **`:tasks_page_load_runner`** is the 4-arity page-load function seam (default `&load/4`), resolved INSIDE `run/6`, so a test can inject an exiting loader and prove the LiveView survives with `:tasks_loading` cleared.
- **`PageLoad.load/4` is the only store-facing function** (the page read + `get_unique_paths/1`); no other module knows the row shape.
## `?task=<id>` — focused single-task view
`params["task"]` (a binary of 1..128 bytes, else nil) sets `@focused_task_id` in `handle_params/3`, which auto-expands that id and passes `workbench_task` to the layout (`workbench_reconnect_params: Map.take(params, ["task"])`, `workbench_remote_requested: params["node"] not in [nil, "local"]`).
In that mode `PageLoad.start/3` replaces the filter keyword with `[focused_task: id, pending_remote: workbench_remote_requested and node == node()]`, and `load/4` runs a single `get_task_lite/2` read (ONE row, page 1/1, no project paths, `awaiting_sessions` limited to that id) instead of `list_tasks_page/2`.
The page renders that one card (`focused` attr), hides the pagination and the list header, skips the `:reflect` hiding for it (`show_reflect_tasks or not is_nil(focused_task_id)` in the landed-load fold) and shows "Task not found" + a "Task History" link when the read yields nothing. `list_enter_scope/1` includes `focused_task_id`.
## Page-load state & failure handling (`:tasks_loading` / `:tasks_error`)
- `:tasks_loading` (seeded `false`; set by `PageLoad.start/3` when `show_loading?`, cleared by every APPLIED `{:tasks_page_loaded, ...}`) drives the FIRST-LOAD placeholder — daisyUI `skeleton` rows inside `#tasks-loading` (`role="status"`, `aria-live="polite"`, with the visually hidden `gettext("Loading tasks...")` text the tests flush on).
- `:tasks_refreshing` (seeded `false`) is set for a non-first load and cleared at the TOP of every `{:tasks_page_loaded, ...}` outcome (ok, error and stale alike), so it can never stick; while true the list renders ONE thin inline line above the rows (`#tasks-refreshing`, `role="status"`, minimal spinner + `gettext("Refreshing tasks…")`) with the loaded rows still mounted underneath.
- **Keyed stream contract**: `#tasks-list` is the outer `ListEnter` scope wrapper (`phx-hook="ListEnter"` + `data-list-enter-scope={list_enter_scope(assigns)}`, a stable binary identity of node + filters + page + focus); `#tasks-stream` inside it is the ONLY `phx-update="stream"` container. Each row's DOM id is exactly `task-<id>` (explicit `dom_id: &task_dom_id/1`, since the stream name `:tasks` would default to `tasks-<id>`) and carries `data-list-enter-key={task.id}`, so `ListEnter` animates only genuinely new rows and reseeds a silent baseline when the scope changes.
- The stream is populated in ONE place — `put_tasks_stream/2` (`stream(:tasks, rows, reset: true, dom_id: …)`) in the `{:tasks_page_loaded, seq, node, result}` success branch — so a first load, a filter change, a page change, a node switch and every refresh reset the container, while a push or a mutation never does.
- The plain `:tasks` and `:filtered_tasks` assigns are RETAINED and stay populated beside `@streams.tasks`: the count line reads `length(@filtered_tasks)`, the empty/error branches test it, and `ModalHelpers.view_full_options/2` plus several tests look rows up in `socket.assigns.tasks`.
- `:tasks_error` (seeded `nil`) holds the reason of the LAST failed page load; it is NOT interpolated into the DOM, it only selects the error UI. A failed load NEVER clears loaded rows (`:tasks` / `:filtered_tasks` / `:total_count` / `:total_pages` / `:project_paths` stay untouched).
- With nothing on screen (`@filtered_tasks == []`) the list area renders a centered "Could not load tasks." block (`#tasks-load-error`) with a Retry button — never an endless spinner (the spinner shows only while `:tasks_loading` is true); with rows on screen it renders normally plus a compact `#tasks-refresh-error` strip above `#tasks-list` ("Could not refresh tasks." + Retry).
- The `retry_load` event re-runs `PageLoad.start/3` on the CURRENT page, showing the placeholder only when `assigns[:filtered_tasks] == []`; a successful load assigns `tasks_error: nil`, so strip/block disappear.
## Lazy per-card detail & archive
The rendered list holds summary rows only; heavy data is fetched per card by `EvoDashWeb.TasksLive.TaskDetail` (`tasks_live/task_detail.ex`) — the SINGLE owner of the `:task_details` cache and its `:task_detail_seq` stale-guard. Nothing is fetched at mount or on page load; an entry exists only once the user expands a card.
### Entry shape
`:task_details` maps `task_id => entry`: `%{state: :loading | :ok | :error, task: %EvoGit.TaskInfo{} | nil, error: term() | nil, seq: pos_integer(), archive: nil | %{state: :loading | :ok | :error, entries: [map()], total: non_neg_integer(), server_total: non_neg_integer() | nil, dropped: non_neg_integer(), exhausted?: boolean(), next_offset: non_neg_integer(), loading_more?: boolean(), more_error: term() | nil, error: term() | nil, seq: pos_integer(), agent_results: %{agent_id => %{state: :loading | :ok | :error, entry: map() | nil, error: term() | nil}}}}`.
`task` is meaningful only when `state == :ok`, `error` only when `state == :error`.
The archive envelope is PAGED: `entries` holds the pages read so far (bounded by the retention window), `total` is the EFFECTIVE total that drives paging, `server_total` the server's own count for the label only (`nil` when a page carried none), `dropped` the entries the retention window evicted, `exhausted?` a short/empty page that proved there is nothing more, `next_offset` the cumulative count of RAW rows fetched (the offset the next/in-flight page is requested at), and `agent_results` the lazily fetched per-agent full entries (the paged read omits every `"result"`).
`total` and `server_total` are OPTIONAL inputs: a page read may stop returning a per-page `COUNT(*)` and the fold stays total when absent.
The detail entry and its nested archive entry carry their OWN seq drawn from the same monotonic `:task_detail_seq`, so a detail refetch never invalidates a landed archive (and vice versa); an append keeps the archive's seq and is identified by `next_offset`.
`entries` is bounded by `EvoDashWeb.ArchiveHelpers.retain_window/2,3` at `ArchiveHelpers.max_retained/0` (500 = 5 pages): the most RECENT entries are kept and the evicted (oldest) count accumulates in `dropped`.
A SHORT page (`length(page_entries) < 100`, empty included) sets `exhausted?: true` and clamps `total` to `dropped + length(entries)`, so a stale server count can never keep the pager alive; a full page sets `total = max(fetched, server_total || 0)`.
The private `more_pages?/1` is the single pager predicate: `not exhausted? and ArchiveHelpers.more_pages?(length(entries), dropped, total) and not loading_more?` — never `length(entries) < total`, which is wrong once rows are evicted.
The cache never exceeds ONE page: `prune/2` keeps only entries whose id is on the freshly loaded page.
### Reads and seams
| read | returns | app-env seam | default |
|------|---------|--------------|---------|
| lite detail | `%EvoGit.TaskInfo{}` with `archive_metadata: nil` and no `:archive_records` in the result | `:tasks_task_detail_runner` (2-arity) | `EvoDash.NodeContext.get_task_lite/2` |
| archive PAGE | `%{entries: [map()]}` plus an OPTIONAL `total` (a non-negative integer becomes `server_total`) for `limit: 100, offset: <page>, include_results: false` | `:tasks_task_archive_runner` (3-arity `fn node, task_id, opts -> end`) | `EvoDash.NodeContext.list_task_archives/3` |
| one agent's full entry | the entry map INCLUDING its `"result"` (`nil` when absent) | `:tasks_task_archive_agent_runner` (3-arity `fn node, task_id, agent_id -> end`) | `EvoDash.NodeContext.get_agent_archive/3` |
All three seams are resolved AT SPAWN TIME from app env (the dashboard's runner-seam idiom), so a test can inject an exiting runner and assert the LiveView survives.
Every fetch is ONE supervised `EvoDash.TaskSupervisor` child running `EvoDash.SafeCall.run/1` around the runner call and always reporting back: `{:task_detail_loaded, seq, node, task_id, result}` / `{:task_archive_loaded, seq, node, task_id, result}` / `{:task_archive_agent_loaded, seq, node, task_id, agent_id, result}`. No polling — results arrive only from those three messages.
### Guards and result folding
`apply_detail/5`, `apply_archive/5` and `apply_archive_agent/6` drop a result unless the message's `node` still equals `socket.assigns.current_node`, the entry still exists, AND the entry's (archive) seq equals the message's seq (a newer fetch, a pruned entry or an invalidated entry supersedes the older result); `apply_archive_agent/6` additionally requires the agent to still be tracked in `agent_results`.
- Detail: `{:ok, %EvoGit.TaskInfo{}}` → `:ok`; `{:ok, nil}` (the task vanished between page load and expand) → `:error` with `:not_found`; `{:error, reason}` (including a SafeCall-captured exit) → `:error` with that reason; any other shape → `:error`.
- Archive FIRST page: `{:ok, %{entries: list}}` (with or without a `total`) → `:ok` — the empty list is a valid "this task archived nothing"; `{:error, reason}` and any other shape → `:error` (Retry → `load_archive/2`).
- APPEND (`loading_more?: true`): success merges the page in (deduped by `agent_id`, order preserved), advances `next_offset` by the RAW rows fetched, refreshes `dropped`/`exhausted?`/`server_total` and the effective `total`; failure keeps the loaded page, clears `loading_more?` and records `more_error` (Retry → `load_more_archive/2`).
- Per-agent: `{:ok, entry_map}` caches `%{state: :ok, entry: entry}` AND folds the entry into `entries` via `ArchiveHelpers.merge_entry/2`; `{:ok, nil}` / `{:error, reason}` / anything else → `%{state: :error, error: reason}`.
### Public API (total — a missing assign reads as an empty cache)
- `toggle/2` — collapse drops the id from `:expanded_task_ids` and keeps the cached entry (a re-expand renders instantly); open adds the id and `ensure/2`s.
- `ensure/2` — fetch when no entry exists; an entry in ANY state (including `:error`) is a no-op, so this is both the cache guard and the in-flight guard.
- `retry/2` — drop the entry, then `ensure/2` (backs the error strip's Retry).
- `load_archive/2` — no-op unless the detail entry is `:ok`; fetches the FIRST page when `archive` is `nil` or an `:error` archive, never while `:loading`/`:ok`.
- `load_more_archive/2` — no-op unless the archive is `:ok` and `more_pages?/1` is true.
- `load_agent_result/3` — no-op unless the archive is `:ok`; per-agent cache/in-flight guard (`:loading`/`:ok` left alone, `:error` refetched). Never called on render.
- `invalidate/2` — drop the entry (archive AND every cached agent result go with it); when the card is still in `:expanded_task_ids` it immediately `ensure/2`s again, so an open card shows the loading state and then the fresh detail instead of blanking. This is the ONLY archive invalidation path.
- `prune/2` — keep only the entries for ids present in the landed page rows.
- `ensure_expanded/2` — after `prune/2`, refetch the detail of every still-expanded row on the new page (an open card survives a background refresh / pagination round-trip).
- `apply_detail/5` / `apply_archive/5` / `apply_archive_agent/6` — the guarded message folds.
### TasksLive wiring
- `toggle_task_details` (`%{"task_id" => id}`) → `TaskDetail.toggle/2` (ensure ONLY when OPENING).
- `retry_task_detail` (`%{"task_id" => id}`) → `TaskDetail.retry/2`; `load_task_archive` (`%{"task_id" => id}`) → `TaskDetail.load_archive/2`; `load_more_task_archive` (`%{"task_id" => id}`) → `TaskDetail.load_more_archive/2`; `load_task_archive_agent_result` (`%{"task_id" => id, "agent_id" => agent_id}`) → `TaskDetail.load_agent_result/3`.
- `{:task_updated, ...}` / `{:task_deleted, ...}` invalidate that id (only when `NodeAware.event_from_current_node?/2`) BEFORE delegating to `NodeAware.handle_task_info/2`.
- A node-context change in `handle_params/3` resets `:task_details` to `%{}` and clears the four confirm ids, `:action_busy`, `:awaiting_sessions`, `:clearing_history` and `:tasks_refreshing` — all belong to the OLD node, and in-flight results are then rejected by the node + entry guards.
- A landed page load runs `TaskDetail.prune/2` then `TaskDetail.ensure_expanded/2`.
### Card rendering states
The card receives `detail={Map.get(@task_details, task.id)}`; while `nil` or `:loading` the expanded body renders the compact `#task-<id>-detail-loading` placeholder ("Loading task details…"), and on `:error` the retry-able `#task-<id>-detail-error` strip ("Could not load task details." + Retry → `retry_task_detail`).
The heavy sections — Agent Message, Token & Cost Usage, Execution Logs and the archive — read `detail.task`; the Agents Spawned tile reads the summary's `agent_count`/`model_id` but is reached only once the detail has landed. The expanded structured-failure block is the exception: it reads the summary's `error` and renders even while the detail is loading.
### Archive disclosure
The archive section appears only when the detail is `:ok` AND (`opts[:archive]` is truthy OR an archive envelope already exists). Records are NEVER fetched with the detail: the section first shows a "Show archive" button (`load_task_archive`) and the hint "The archive loads on demand."
States: not requested (button + hint) → `:loading` spinner → `:ok` with a page rendered through `ArchiveComponents.archive_details` (count/range label, the tree, "Load more" only while `not exhausted? and ArchiveHelpers.more_pages?(loaded, dropped, effective_total)`, per-agent "Show result") → `:ok` with `[]` → "No archived agents for this task." → `:error` strip ("Could not load the task archive.") whose Retry re-fires `load_task_archive`.
An append failure is INLINE and non-destructive: the loaded page stays, `more_error` renders "Could not load more archive pages." + Retry (same `load_more_task_archive` event). Each agent's heavy `"result"` is fetched only when the user presses "Show result" (`load_task_archive_agent_result`), rendered capped through `blob_preview`, never auto-fetched on render.
## Load profile, async boundaries & no N+1
- **`mount/3`** runs NO store query: `project_paths` is seeded `[]` and filled by the async load's `get_unique_paths/1` — a mount-time call would be redundant and wrong (at mount the node context is still local, before `handle_params/3` resolves `?node=`). It does call `Helpers.config_status/0` → `EvoGit.Config.config_status/0` synchronously (local, persistent_term-cached).
- **ASYNC (`EvoDash.TaskSupervisor`)** — page loads via `PageLoad`: the connected mount, `push_patch` pagination, every filter/search/toggle event, `retry_load`, the post-mutation reload and the debounced PubSub reload, landing as `{:tasks_page_loaded, seq, node, result}` guarded by `:page_load_seq` + node identity.
- **ASYNC (`TaskDetail`)** — the per-card detail fetch (`{:task_detail_loaded, ...}`), archive pages (`{:task_archive_loaded, ...}`) and per-agent results (`{:task_archive_agent_loaded, ...}`), guarded by `:task_detail_seq` + the entry + node identity.
- **ASYNC (`EvoDash.SafeCall.start/3`)** — `confirm_pause_task` / `resume_task` (`{{:pause_result, task_id}, result}` / `{{:resume_result, task_id}, result}`, applied by `pause_resume_result/4`) and, through the shared helper, `confirm_cancel_task` (`{:cancel_result, task_id}`), `confirm_force_kill_task` (`{:force_kill_result, task_id}`), `confirm_close_session` (`{:close_session_result, task_id}`), `delete_task` (`{:delete_result, task_id}`) and `clear_task_history` (`{:clear_finished_result}`) — every one arrives NESTED as `{{tag, …}, result}` and is settled by its own `handle_info` clause defined BEFORE the catch-all.
- **SYNCHRONOUS in the LiveView process**: only `mount/3`'s `config_status/0`; no mutation, no page read and no detail/archive read blocks the socket.
- **Stream row re-render rule**: a stream row is NOT re-rendered when a plain assign it reads changes, so every arm that mutates `@expanded_task_ids` / `@task_details` re-inserts the affected row through `refresh_stream_row/2` (`stream_insert/3`, keeping the captured `dom_id`): `toggle_task_details`, `retry_task_detail`, `load_task_archive`, `load_more_task_archive`, `load_task_archive_agent_result` and the three detail/archive result messages. A row that disappears WITHOUT a reload is removed surgically: the `{:delete_result, id}` success path calls `stream_delete/3` (guarded on the stream existing); every path ending in a page load needs no extra work because the reset covers it.
- **No per-task N+1 I/O**: `TaskCardComponents.task_card/1` performs NO git subprocess, `File.stat`/`exists?`, `System.cmd` or `NodeContext` call at render time — it renders the summary row plus whatever `detail` holds, so extra round trips are bounded by what the user opened, never by rows per page.
- Per-load SQL cost, the pool-backed reads (`EvoGit.Store.Boot.default_pool_size/0` = 4) with writes serialized through `EvoGit.Store.Writer`, and the `get_unique_paths/1` scan: `apps/evo_git/lib/evo_git/store/CONTEXT.md`.
## Measured cost
Payload (`test/evo_dash_web/live/tasks_live_test.exs` → "lightweight page load (summary rows)" → "a multi-MB result never rides the page load"), with one fixture whose `result` is `String.duplicate("multi-mb-payload ", 140_000)` = 2,380,000 B:
| read | bytes |
|------|-------|
| the page load's summary rows for that fixture (one row) | 984 B |
| the same row through the full-row read `EvoDash.NodeContext.list_tasks_paginated(node, limit: 50)` | 2,381,183 B (≈ 2.27 MiB) |
≈ 2420× smaller — the page's cost is independent of a task's `result` size because the summary projection never selects it. The measurement sums `:erts_debug.size/1 * 8` PLUS every referenced binary's payload (`term_bytes/1`), because `:erts_debug.size/1` alone reports the summary row as 114 words and the full row as only 141 (a 2 MB refc binary costs ~8 heap words). Assertions: `page_bytes * 50 <= full_bytes` and `page_bytes < byte_size(big) / 50`.
Load profile (isolated `mix run` harness over a COPY of a live `tasks.sqlite`: 854 rows / 29.7 MB, exercising the real async / `TaskSupervisor` path), medians: connected mount + first render ≈ 8 ms (user-visible first paint ≈ 24 ms); pure `render(view)` of 24 cards ≈ 2 ms, one collapsed `TaskCardComponents.task_card` ≈ 0.03–0.07 ms (per-card render is NOT a bottleneck); sidebar `list_tasks_summary` (752 rows incl. `:completed`) ≈ 20–24 ms, async and off the Store GenServer (its read holds one pooled connection, shared with a concurrent page read); a filtered page load is DB-bound, so a broad `status = "completed"` filter is materially slower than a selective one.
## `:reflect` tasks hidden by default (reveal toggle)
The page hides `:reflect` tasks (repo-less Home-chat tasks) by default. Page-local filter state `@show_reflect_tasks` (default `false`, seeded in `mount/3` with the other filters) drives it; the filter-bar checkbox (`name="show_reflect_tasks"`, `value="true"`, `phx-change="toggle_reflect_tasks"`, gettext label "Show chat tasks") reveals them, parsing `params["show_reflect_tasks"] not in [nil, "false"]` and reloading via `PageLoad.start(socket, 1, true)`.
The exclusion is applied **client-side post-load** by `PageLoad.visible_tasks/2` (`Enum.reject/2` when hiding) at the single choke point where loaded rows become the displayed list — the `{:tasks_page_loaded, ...}` handler, which assigns the post-load filtered list to BOTH `:tasks` and `:filtered_tasks`.
`visible_tasks/2` rejects only `type == :reflect` rows whose `session_mode` is not `"interactive"`, so a live interactive session is never hidden by this toggle (see "Task cancellation UX"). A SQL `filters` keyword (`PageLoad.filters/1`) cannot express "exclude type" because the WHERE builder lives in the read-only sibling app `evo_git`.
Rows are 18-key summary maps, so `type` is already a decoded atom and is read with `Map.get/2` — summary-safe, never a dot access. `@total_count`/`@total_pages`/pagination stay SQL-truthful and untouched — a page may show slightly fewer cards when reflect rows are dropped (accepted by design).
The toggle is a **reveal preference, not a narrowing filter**: it survives pagination `push_patch`es and filter reloads (a plain socket assign, never cleared by `handle_params/3`), is NOT reset by `reset_filters`, and does NOT appear in the active-filters indicator. When reflect-hiding empties the list with no other filter active, the empty state shows "Try adjusting your filters or search query." instead of the start-tasks hint (`not @show_reflect_tasks` in the first branch's condition).
## Reads: payload audit, store shapes & round trips
Every read goes `EvoDash.NodeContext.<f>` (local direct / remote `:erpc`) → `EvoGit.RemoteNode` → `EvoGit.AgentScheduler.RemoteAPI` → `EvoGit.TaskRegistry` → `EvoGit.Store`. In the core, reads share a small connection pool (`EvoGit.Store.Boot.default_pool_size/0` = 4) while every write serializes through `EvoGit.Store.Writer`; the registry offloads `list_tasks_page`, `get_task_lite`, `list_task_archives` and `get_agent_archive`, while `get_unique_paths/1` blocks the core TaskRegistry for its read (the store side is still offloaded).
- **`list_tasks_page/2`** — the page data; opts `[limit: 25, offset: (page-1)*25, filters: [status:, project_path:, review_status:, search:, session_mode:]]`. Every key (incl. `session_mode`) is a SQL predicate in the store's shared WHERE builder (`EvoGit.Store.Operations.Filters.where_filters/2`); `"all"`/`""`/absent/unknown means "no clause". Returns `%{rows: [summary_map], total: total_count}` with the 18-key rows: the card reads `id`, `type`, `opts`, `status`, `review_status`, `started_at`, `finished_at`, `agent_count`, `model_id`, `commit_sha`, `branch_name` and `error`; `project_path`, `base_sha`, `lease_expires_at`, `updated_at`, `session_mode` and `pause_kind` ride along (the last two read by the server-side filter and a card's paused explainer / resume confirmation).
- **Search surface**: a case-insensitive raw SQL LIKE over `id`, `opts`, `project_path` and `branch_name` (leading wildcard, full-table scan). The agent RESPONSE (`result`) is NOT searchable — it is not even loaded until a card is expanded.
- **`get_task_lite/2`** — ONE read per EXPANDED card (through `TaskDetail`): a full `%EvoGit.TaskInfo{}` decoded exactly like `get_task/2` except that `archive_metadata` is `nil` and the result carries no `:archive_records`. Consumed: `result` (Agent Message, Full Result modal, expanded "Repositories"), `usage`, `logs`, `opts`, and `commit_sha`/`branch_name` for multi-repo enrichment.
- **`list_task_archives/3`** — ONE read per archive page (`[limit: 100, offset: page, include_results: false]`): `%{entries: [string-keyed map], total: non_neg_integer()}` ordered by `depth, agent_id`, every entry WITHOUT its `"result"`; degraded to `%{entries: [], total: 0}` on a failed remote call.
- **`get_agent_archive/3`** — ONE read per agent the user asked about: the single full entry map INCLUDING its `"result"` (or nil when the agent id is unknown to that task).
- **`get_unique_paths/1`** — fetched ONCE per page load inside the async load task (`PageLoad.load/4`), never from `mount/3`; assigned as `@project_paths` → filter-dropdown options + active-filter badge.
- **`cancel_task/2` / `force_kill_task/2` / `delete_task/2` / `clear_finished_tasks/1`** — phx-event triggered and spawned OFF-PROCESS through `EvoDash.SafeCall.start/3` (see "Mutating events"), never called inline; each returns `:ok | {:error, reason}`, normalized by `mutation_result/1`.
- **Multi-repo `repos` result key** — results may carry a top-level `repos` map (STRING keys) `%{repo_id => %{"commit_sha" => sha, "branch_name" => branch | nil}}`: `"primary"` is ALWAYS present (nil branch_name = no changes), each writable foreign repo that produced commits is present, read-only repos are ABSENT, and top-level `commit_sha`/`branch_name` stay the PRIMARY's. The COLLAPSED card derives per-repo badges from the SUMMARY through the pure `TaskCardComponents.task_repos(task, detail)` (foreign repos from `opts[:foreign_repos]`, enriched by the detail result's `repos` map once landed; `nil` unless genuinely multi-repo); `result_repos/1` + `result_repos_badges/1` back the expanded `render_result/2` "Repositories" section and the Full Result modal.
- **Not issued here**: `list_task_ids/2` (its dashboard consumers are `ProjectsLive.Notifications` for terminal statuses and `ServerStatusController` / `SystemLive.UpdateCard` for active ones), `list_tasks_changed_since/2` (nobody — change detection is broadcast-driven), `list_tasks_paginated/2` and `get_task/2` (full-row reads incl. `Codec.decode_result/1`).
- **Round-trip inventory**: minimum per navigation = 2 core RPCs (page summary + distinct paths), 1 SQL page statement carrying its own `count(*) OVER ()` total (`ORDER BY started_at DESC LIMIT/OFFSET`, index-served by `idx_tasks_started_at` or a matching composite) plus the `DISTINCT project_path` scan, all OUTSIDE the LiveView process; a separate `COUNT(*)` runs only for the rare out-of-range-offset last-page refetch. A mutation adds ONE single-row call off-process plus the same page-read cost in its async reload; expanding a card adds ONE lite read; disclosing an archive adds ONE page read (plus one per "Load more"); each "Show result" adds ONE agent read.
## Task cancellation UX (graceful cancel + force kill)
Two two-step server-side confirmation-modal flows (SystemLive warning-modal pattern; NO custom JS — assigns drive visibility):
- **Graceful cancel** (card's inline Cancel button, visible `[:pending, :running, :awaiting_input]`): `open_cancel_modal` → assign `:confirm_cancel_task_id`; `confirm_cancel_task` → `EvoDash.NodeContext.cancel_task(current_node, task_id)` (GRACEFUL — agents save + exit, result preserved; `:pending` → immediate `:cancelled`) spawned OFF-PROCESS through `EvoDash.SafeCall.start/3` tagged `{:cancel_result, task_id}`; `:ok` → collapse the expanded card + `PageLoad.start(socket, current_page, false)`; error → flash `gettext("Failed to cancel task: %{reason}", reason: inspect(reason))`. Modal: title `gettext("Cancel Task?")`, confirm `gettext("Cancel Task")` (`btn-warning`), dismiss `gettext("Keep Running")`.
- **Force kill** (card's three-dot dropdown, visible `[:running, :awaiting_input, :cancelling, :pausing, :paused]` — a draining or stuck pause must always be killable; "Danger zone" divider): `open_force_kill_modal` → assign `:confirm_force_kill_task_id`; `confirm_force_kill_task` → `EvoDash.NodeContext.force_kill_task(current_node, task_id)` (BRUTAL — kills all agents, result nil'd; escalation from `:cancelling`) through `SafeCall.start/3` tagged `{:force_kill_result, task_id}`; same `:ok` collapse + async reload / error-flash handling. Modal: title `gettext("Force Kill Task?")`, confirm `gettext("Force Kill")` (`btn-error`).
- **Modal-state lifecycle**: the confirm assigns (`@confirm_cancel_task_id`, `@confirm_force_kill_task_id`, `@confirm_close_session_task_id`, `@confirm_pause_task_id`) are seeded `nil` in `mount/3`, MUTUALLY EXCLUSIVE (every opening handler nils the sibling ids, so exactly one modal is open), and cleared on node switch in `handle_params/3` (along with `action_busy`); nil-guarded confirms are no-ops.
- **Status filter**: includes `gettext("Cancelling")` (`value="cancelling"`), `gettext("Pausing")` (`value="pausing"`) and `gettext("Paused")` (`value="paused"`); pure SQL string comparison, so those statuses round-trip as exact stored TEXT — no evo_dash-side atom whitelist or atom conversion.
- **The `:awaiting_input` status and the `session_mode` filter are SERVER-SIDE.** `session_mode` is a real `tasks` column with a shared-WHERE predicate, so the filter travels in `PageLoad.filters/1` exactly like `status`/`project_path`/`review_status`/`search` and a page load stays exactly ONE `list_tasks_page/2` read whose `count(*) OVER ()` reports the FILTERED total — no in-Elixir scan, no in-memory pagination. Predicates: `"oneshot"` matches a stored `NULL` and a legacy blank cell (both decode to `"oneshot"`), `"interactive"` only `'interactive'`, `"all"`/absent/unknown adds no clause (`normalize_session_mode/1`). Events: `filter_session_mode` (whitelist match on the three values — an unknown value keeps the current filter, never an atom conversion) and `clear_filter` with `%{"filter" => "session_mode"}`; reset by `reset_filters`. The filter bar renders a `<select name="session_mode_filter">` plus an active-filter chip (`session_mode_label/1`).
- **Idle sessions on this page**: the page load also returns `awaiting_sessions` — a `%{task_id => agent_id}` map from `EvoDash.NodeContext.list_awaiting_input/1` (empty on a degraded read) — and `session_agent_id/2` resolves a card's id tolerantly (string, integer or integer-parsed key), so `task_card/1` renders the reply panel only for a task whose status is `:awaiting_input` and whose session is known. Events: `session_send_message` (`%{"task_id", "message"}` → `EvoDash.NodeContext.send_session_message(node, agent_id, text, :queue)` via `SafeCall.start/3`, arriving NESTED as `{{:session_message_sent, task_id}, result}` alongside a flat `{:session_message_sent, task_id, result}` clause; blank text or a session that stopped waiting flashes instead of sending), `open_close_session_modal` / `close_close_session_modal` (mutually exclusive with the cancel and force-kill modals), and `confirm_close_session` (`EvoDash.NodeContext.close_session(node, agent_id, :normal)` spawned through `start_task_mutation/5`, tagged `{:close_session_result, task_id}`; the confirm button renders the modal's `busy` attr, the card's controls disable while in flight, and the confirm assign, busy marker and expansion settle on EVERY outcome — success reloads without blanking, failure flashes). `EvoDashWeb.TasksLive.Session.confirm_close_session_modal/1` owns the markup.
- **`:cancelled` reviewability**: gracefully-cancelled tasks ARE reviewable — the card Review button shows for every `:completed`/`:cancelled` task (repo-less `:reflect` excluded); one without a branch still opens the review page (no-changes).
- **A paused task is NOT reviewable** — `show_review_button?/1` stays an allowlist, so `:pausing`/`:paused` never get a Review link; the page offers Resume instead, and force kill is the only terminal exit from a pause.
## Task pause / resume UX (`:pausing`, `:paused`)
Pause and resume follow the same two-step / off-process discipline as cancel, but ASYNC because they are slow: a pause drains the task's agents at their next turn boundary (an in-flight tool call is never interrupted) and a resume re-dispatches an agent — neither may block the LiveView.
- **Assigns**: `:confirm_pause_task_id` (pause confirmation modal) and `:action_busy` — the page's ONE per-task busy map (see "Mutating events"), passed to `task_card/1` so every control of that task disables and the matching spinner renders. Both are cleared in `handle_params/3`'s node-switch branch; the busy entry is deleted on EVERY async result arm.
- **Pause**: card `open_pause_modal` (`phx-value-task_id`) → assign `:confirm_pause_task_id` (nils the other three confirm ids); `close_pause_modal` clears it. The modal follows the SystemLive confirmation pattern: title `gettext("Pause Task?")` with a `gettext("Task: %{task_id}", task_id: …)` line, and a `confirm_pause_task` (`phx-value-task_id`) that closes the modal, collapses the card and sets the busy marker immediately, then runs `EvoDash.NodeContext.pause_task(current_node, task_id)` through `EvoDash.SafeCall.start/3` tagged `{:pause_result, task_id}` (arriving NESTED). A confirm without an open modal is a no-op.
- **Resume**: the card posts `resume_task` (`phx-value-task_id`, DIRECT for a `:clean` pause / `phx-confirm`-gated for a `:dirty` one) → `EvoDash.NodeContext.resume_task(current_node, task_id)` through `SafeCall.start/3` tagged `{:resume_result, task_id}`; a nil `current_node`, or a missing/blank task id, is a silent no-op. The core resumes the WHOLE durable run tree: the root plus every subagent that was still running, each with its own conversation, worktree and branch; an already-consumed child is not revived and a record-less child is reported lost — the card's `:dirty` explainer says exactly that.
- **Result application** (`pause_resume_result/4`): the busy marker is deleted and the card collapsed on EVERY arm, success or failure, so a failed action can never leave a permanently spinning control; `{:ok, :ok}` starts `PageLoad.start/3` (async reload), while `{:ok, {:error, reason}}` (a documented refusal) and `{:error, reason}` (a transport/exit failure) each flash.
- **Error mapping** — one precise gettext line per documented reason: `:not_found` → "Task not found.", `:not_running` → "Only a running task can be paused.", `:not_pausable` → "This task cannot be paused (interactive sessions can't be paused).", `:not_resumable` → "This task can't be resumed because durable agent state is disabled for it.", `:scheduler_unavailable` → "The scheduler is unavailable right now.", `:not_paused` → "Only a paused task can be resumed.", `{kind, _}` with `kind ∈ [:exit, :throw, :error]` → "The node could not be reached — the task's state is unchanged.", and a generic `gettext("Failed to pause task: %{reason}")` / `gettext("Failed to resume task: %{reason}")` with `inspect/1` for anything genuinely unexpected.
## ModalHelpers (full result / full objective)
`view_full_result/2` reads the CACHED `:task_details` entry (never `socket.assigns.tasks` — those rows carry no `result`). `@selected_result` is modal STATE: `nil | %{state: :loading} | %{state: :ok, result: result} | %{state: :error, error: reason}`.
The Full Result modal (`gettext("Task Result")`) renders `TaskCardComponents.render_result_full(result)` and the `#full-result-copy` ClipboardCopy button ONLY in `:ok`; `#full-result-error` ("Could not load the task result.") for `:error` and `#full-result-loading` ("Task result is not loaded yet.") otherwise.
`view_full_options/2` reads the summary `opts` from `socket.assigns.tasks` (always present) → `opts[:prompt] || opts[:objective]`, so it needs no detail fetch; the Full Objective modal (`gettext("Full Objective")`) carries the `#full-options-copy` ClipboardCopy button. TasksLive implements the required `handle_event("copied", ...)` → "Copied to clipboard" flash handler.
## Failed-task error rendering (legacy error result + structured failure record)
A `:failed` task can surface its failure through TWO separate records: the legacy `{:error, reason}` / `{:exit, reason}` task RESULT shape and the structured `error` map field on the task row. Both may coexist, and a `:failed` task may carry either, both, or neither (legacy failed rows have `error` nil).
`error` (ATOM keys after decode) is `%{kind: atom, source: atom, message: String.t(), stacktrace: [String.t()] | nil}` with `kind` ∈ `:error | :exit | :down | :force_kill | :timeout | :restart | :lease_expired | :recheck` and `source` ∈ `:result_handler | :down_handler | :force_kill_task | :finalizing_watchdog | :startup_reconcile | :lease_sweep | :recheck_resolve`. It is `nil` on every non-`:failed` row and rides the SUMMARY projection, so it is available before — and independently of — the lazy detail.
- tasks_live.ex NEVER reads `task.result` / `task.error` itself — every row is delegated whole to `EvoDashWeb.TaskCardComponents.task_card task={task} show_details=... detail={Map.get(@task_details, task.id)} current_node_id=...`; all failure reading/rendering lives in the component.
- COLLAPSED `:failed` card (legacy shape): badge `Helpers.task_status_badge(:failed)` (`bg-error/10 text-error`), accent bar via `task_accent_color/1` → `Helpers.task_status_dot_class(:failed)`, tint `task_card_tint/1` → `Helpers.task_status_tint(:failed)`; badge text is the raw atom and no error text is visible.
- COLLAPSED `:failed` card WITH a structured `error` map: additionally renders a compact error-tinted failure line — the truncated `error.message` (`Helpers.truncate_string/2`, ~160 chars). `error` nil/non-map → nothing extra.
- EXPANDED structured failure block: reads the summary `error` — kind + source captions via `Helpers.task_error_kind_label/1` / `Helpers.task_error_source_label/1` (unknown atoms → a safe generic fallback), the full untruncated `error.message`, and the last ≤8 `stacktrace` frames as monospace lines. It renders even while the detail is loading.
- EXPANDED legacy result box: the Agent Message section is gated on `Map.get(detail.task, :result)` — an `{:error, _}` tuple is truthy, so it renders once the detail lands. Body = `render_result/2`, rendering `{:error, reason}` as a red box headed `gettext("Error")` (hero-x-circle icon) with `<pre> inspect(reason, limit: :infinity)` and `{:exit, reason}` as a "Crashed" box; `:failed` with a nil result → no Agent Message section (the legacy force-killed shape).
- Full Result modal: `view_full_result/2` opens on the CACHED detail; `result_copy_text/1` for `{:error, reason}` is `inspect(reason, limit: :infinity)`. The only UI entry is the "Full" button inside an EXPANDED card's Agent Message section.
- Guards are read-only (`status == :failed and is_map(error)` + `Map.get`) and tolerant of nil/non-map/legacy shapes on BOTH the summary projection and full `%TaskInfo{}` rows.
- `show_review_button?/1` matches EVERY `:completed`/`:cancelled` task except repo-less `:reflect` — a `:failed` task NEVER gets a Review link/navigation on this page (test-pinned).
- Legacy result decoded-shape note (evo_git codec contract): `{:error, reason}` persists tagged, and a non-JSON-safe reason (e.g. a tuple `{128, "fatal: ..."}`) is stored as `inspect(reason)` and decoded back as that string, so the dashboard sees `{:error, "{128, \"fatal: ...\"}"}` and displays it verbatim in the Error box.
- Test pin: `tasks_live_test.exs` asserts an `{:error, "explosion happened"}` result renders "Agent Message" + "Error" + the reason text, with the copy payload containing the reason. No test covers tuple-shaped reasons (they render as their inspect-string after the codec round trip).
- `render_result` clause safety: the catch-all `render_result(result, opts)` pretty-inspects any non-tuple/non-map shape, so no stored result shape can crash a task card.
## Test idioms
- `flush_tasks_load/2` (delegates to `EvoDashWeb.TestHelpers.flush_loading/4`) waits for the async page load by polling until the "Loading tasks..." placeholder disappears, then awaits `:tasks_loading == false` and re-renders.
- `drain_async_loads/2` waits out an armed NodeAware debounce (`:tasks_reload_pending` false) and then for every `EvoDash.TaskSupervisor` child this view spawned to exit (matched via the `$callers` dictionary), so no offloaded store read is in flight at teardown.
- `render_tasks_list/1` (`view |> element("#tasks-list") |> render()`) scopes list assertions away from the SIDEBAR, which also lists `:completed` tasks and can show a row before the page reload lands.
- `wait_for_list/3` polls the `#tasks-list` container until a needle appears (each render is a synchronous round-trip that drains the LiveView mailbox) — use it whenever an ASYNC reload's effect is awaited.
- `install_page_load_hook/0` wraps the `:tasks_page_load_hook` seam so a test receives a `:page_load_spawned` message per spawn and asserts the counter via `:sys.get_state(view.pid).socket.assigns.page_load_seq`; `install_tasks_page_load_runner/1` injects the 4-arity page-load runner.
- `expand_card/3` toggles a card and WAITS for its lazy detail to leave `:loading` (polling `detail_entry/2`, then draining async work and re-rendering) — no sleeps; use it for every expanded-content assertion.
- `install_task_detail_runner/1` / `install_task_archive_runner/1` / `install_task_archive_agent_runner/1` inject the 2-arity `:tasks_task_detail_runner`, the 3-arity `:tasks_task_archive_runner` and the 3-arity `:tasks_task_archive_agent_runner` seams (restored in `on_exit`); the detail runner may block on a `:release_detail` message so the in-flight `:loading` state is observable deterministically, and `paging_runner/2` sends an `{:archive_page, node, task_id, opts}` message per requested page so a test can assert offsets.
- `detail_entry/2` reads `:task_details[task_id]` through `:sys.get_state/1` (a synchronous round-trip, so already-sent async results are applied); `flush_detail_fetches/1` drains pending `{:detail_fetch, id}` notifications (a bounded 100 ms wait) before a "no further fetch" assertion.
- `term_bytes/1` = `:erts_debug.size/1 * 8` + the payload of every referenced binary (structs unwrapped via `Map.from_struct/1`, lists/tuples walked) — the measurement behind "Measured cost".
- Test pins for the lazy path: expanding triggers exactly ONE fetch (a second toggle while loading is a guarded no-op, and a re-expand after landing renders from cache); a `nil` detail becomes `:error`/`:not_found` and an EXITING runner becomes `{:exit, :boom}` with the LiveView alive and Retry recovering in place; a node-matching `{:task_updated, ...}` invalidates + refetches an expanded card while a `{:task_deleted, ...}` drops the entry of a collapsed one; the archive fetches ONLY on click and covers first page + total / empty / error+retry; "Load more" requests `offset: 100` and appends in order without duplicate agent ids (a retried page is idempotent); an append failure keeps the loaded page and retries; "Show result" fetches one agent ONCE, caches it, renders it capped and refetches after a `{:task_updated, ...}` invalidation; an entry without `"result"` renders the button instead of an empty block; and a remote `?node=` propagates the same node atom to both runners.
- The search tests assert a `branch_name` hit (case-insensitive) and pin a regression: text that exists ONLY in a task's `result` no longer matches.
- New-shape events are injected manually — `Phoenix.PubSub.broadcast(EvoGit.PubSub, "tasks", {:task_updated, id, status, node()})` (the `:evo_git` emitters are tested in their own workstream).
- Debounce assertions use the two-phase `wait_until` helper: first `assigns[:tasks_reload_pending] == true` (event processed + node filter matched + debounce scheduled), then `== false` (debounce fired + the ASYNC reload DISPATCHED — the fresh page arrives later, so follow with `wait_for_list/3`). Foreign-node events: sample `tasks_reload_pending == false` across the whole debounce window + assert content unchanged.
- **Proving the reload is off-process**: `:sys.suspend(EvoGit.TaskRegistry)` freezes the serialized registry so ANY synchronous read blocks there (30 s call timeout); the debounced handler must still complete (flag cleared + `page_load_seq` advanced) with the reloaded rows NOT applied, then `:sys.resume(EvoGit.TaskRegistry)` lets the off-process load land. Always pair the suspend with an `on_exit` resume (the `setup/1` isolation teardown runs later, LIFO).
- Store fixtures: `insert_fixture!/1` writes `%EvoGit.TaskInfo{}` rows directly via `EvoGit.Store.put_task` (bypassing the async task spawn, so it emits no broadcast); deletions via `EvoGit.Store.delete_task/2`.
- **Failure state**: a failed load is injected with `send(view.pid, {:tasks_page_loaded, seq, node(), {:error, :boom}})` (current `:page_load_seq`). With no rows on screen that renders `#tasks-load-error` ("Could not load tasks."); with rows loaded it renders `#tasks-refresh-error` above `#tasks-list` and leaves the rows untouched. Both offer a Retry button wired to `phx-click="retry_load"`, which spawns exactly one more page load and clears `:tasks_error` on success.
- Card assertions that need flattened headers use `h4_header_texts/1` (scoped to `<h4>`, because HEEx emits the template's HTML comments verbatim); `attribute/3` + `data_content/2` read ClipboardCopy payloads.
## Mutating events (SafeCall-wrapped, async reload)
- ALL five mutations are ASYNC and share ONE helper pair and ONE busy contract: `start_task_mutation/5` guards a duplicate submit (the `@action_busy` entry for that task id already present → no-op), sets the marker and calls `SafeCall.start(self(), tag, fn -> … end)`; the spawn-failure arm clears the marker immediately (a child that never started sends nothing).
- `@action_busy` is `%{task_id_string => :pause | :resume | :cancel | :force_kill | :close | :delete}` (already passed to `task_card/1`); `action_busy?/2` reads it for the page's own confirm modals, which disable their confirm button and swap the icon for a spinner while busy. `clear_task_history` uses the page-level `:clearing_history` flag (Clear History button disabled + `gettext("Clearing…")`) instead of a task key.
- `task_mutation_result/4` settles EVERY outcome: the busy entry is deleted first (success, `{:error, _}` and SafeCall's captured exit alike, so a button can never wedge), the matching confirm assign is cleared (`clear_confirm_assign/2`), then `:ok` collapses `:expanded_task_ids` for that id and runs `reload(socket, current_page)`, while `{:error, reason}` flashes the existing `gettext("Failed to cancel task: %{reason}", …)` / `gettext("Failed to force kill task: %{reason}", …)` / `gettext("Failed to close session: %{reason}", …)` / `gettext("Failed to delete task: %{reason}", …)` message.
- `clear_task_history` → `SafeCall.start(self(), {:clear_finished_result}, fn -> NodeContext.clear_finished_tasks(node) end)`. Success clears `:expanded_task_ids` and re-runs `reload(socket, 1)`; failure flashes `gettext("Failed to clear task history: %{reason}", reason: inspect(reason))` and does NOT reload; both clear `:clearing_history`.
- `delete_task` has NO confirmation modal (the card's dropdown posts it directly), so `clear_confirm_assign/2` leaves the socket untouched for it while the busy marker and expansion settle like the three confirmed mutations.
- Because the mutation is off-process, the click RETURNS before the store row settles: tests (and any UI copy) await the pushed result / the busy marker clearing, never the click's HTML. Node-aware argument reads (`current_node`, the `session_agent_id/2` lookup for close-session), the nil-confirm no-op and every existing flash string are unchanged.
- `mutation_result/1` (private) normalizes SafeCall's output to `:ok | {:error, reason}`: the NodeContext mutating functions return `:ok | {:error, reason}` (so SafeCall yields `{:ok, :ok}` / `{:ok, {:error, reason}}`) and a caught exit/raise yields `{:error, reason}`.
## Constraints
- Do NOT reintroduce polling (`:remote_poll` / `Process.send_after` self-ticks) or the DirtyTracker module — push events are the single change-detection mechanism, and detail/archive/agent-result values arrive only from their three messages.
- The page loads SUMMARY rows only (`list_tasks_page/2`); heavy data is fetched per card through `TaskDetail` (`get_task_lite/2` / `list_task_archives/3` / `get_agent_archive/3`) and is NEVER transferred with the list or rendered from the summary.
- Keep every load ASYNC and connected-gated: `handle_params/3` must only spawn behind `connected?(socket)`, and every page load — including the debounced reload and the post-mutation reload — must go through `PageLoad.start/3`. Never fetch a page inline in the LiveView.
- Every store/RPC call is exit-safe and OFF the socket: page loads via `PageLoad.run/6`'s `EvoDash.SafeCall.run/1`, detail/archive via `TaskDetail`'s spawned runners, mutations via `EvoDash.SafeCall.start/3` (ONE `handle_info` per tag, clearing its busy marker on every outcome). Never add a bare `EvoDash.NodeContext` / `EvoGit.TaskRegistry` call to a LiveView event handler.
- A `:loading`, `:error` or `nil` detail must always be a renderable state — the card shows the loading placeholder or the retry-able error strip; never a stuck spinner, never a crash, and never a heavy section rendered without `detail.task`.
- `:task_details` is bounded to ONE page: every landed page load must run `TaskDetail.prune/2` (then `ensure_expanded/2`), and a node-context change must reset it to `%{}`.
- Failure is a VALUE, not a crash: a failed load assigns `:tasks_error` and keeps the already-loaded rows; the UI offers `retry_load`. Never revert to a flash-only failure on the page-load path, and never clear `:tasks` on error.
- `:page_load_seq`, `:tasks_load_seq` and `:task_detail_seq` are INDEPENDENT stale-guards (page load / sidebar / per-card detail + archive). Never merge them and never bump another owner's counter.
- The node filter lives in `NodeAware.handle_task_info/2` (shared by every consumer of the `"tasks"` topic) — TasksLive only forwards and reloads; the detail invalidation applies the same `event_from_current_node?/2` filter itself.
- Modal state assigns are server-side (no custom JS); follow the warning-modal pattern for any new destructive action.
