# LiveView Pages
## Intent
Phoenix LiveView pages plus their support modules for the EvoDash UI — task management, agent/process inspection, runtime configuration and the Genesis Assistant operator chat.

### ProjectsLive — project overview (the landing step, two entry points)
Selecting a project or a VCT workspace lands on the project overview, not in the composer: `EvoDashWeb.ProjectsLive.Overview.visible?/1` renders `#workbench-project-overview` (between the `#workbench-project-loading` and `#workbench-idle` branches) while the connection gate is inactive, the workbench is not idle, something is selected and the URL carries no compose intent.
The composer is an EXPLICIT step, expressed by `Overview.compose_task?/1`: `wb_task=1`, a non-blank `resume_from` or a non-blank `starting_commit` read from the params in `handle_params/3`, or a restored browser draft (`maybe_restore_compose_task/1` sets the flag and never clears one the URL already set); `wb_home=1`, no selection and a pending/error remote gate keep their own branches.
`#overview-new-task` (`phx-click="compose_task"`) patches to `/projects?project=<exec_path>&wb_task=1` through `WorkbenchComponent.navigation_path/3` so a remote context keeps `&node=`; the explicit flag survives reload and deep links, and the two actions stay disabled when a workspace has no resolvable execution member.
`a#overview-chat-assistant` navigates to `Overview.assistant_path/1`, i.e. `/assistant?wb_project=<OS path | workspace point>&wb_draft=<24 lowercase hex>[&node=]`, with the draft id minted once per navigation by `Overview.draft_id/0` (so the link stays stable across async re-renders) and a workspace's point — never a member path — as `wb_project`.
Recent activity (at most five summary rows) and the git identity are read OFF-PROCESS: `Overview.maybe_spawn/1` spawns `Overview.load/2` (the default body of the `:projects_overview_runner` seam) through `SafeCall.start/4`, so the payload arrives NESTED as `{{:overview_loaded, seq, node, path}, %{git:, tasks:}}` and is accepted only for the current `overview_load_seq`, node and `exec_path`; each half is its own `SafeCall.run/1` and an unavailable or empty half is omitted from the render, never blocking and never a spinner.
Workspace framing, identity facts and DOM ids belong in `projects_live/CONTEXT.md` §"Project overview — the two entry points".
### Workbench page metadata and composers
New Task has one `#task-form` inside the shared task composer, visible Task Options with their existing `form="task-form"` associations, and a separate Project Settings disclosure (`#workbench-task-settings`); no Configure dialog gates routine options.
Projects publishes `#dashboard-root[data-workbench-compose]` only as active when the task form renders, `data-task-draft-project` from the URL, and `data-task-draft-scope` from `DraftScope`; the workbench Git pane uses the resolved execution member's raw OS path, not the VCT token.
The normal Projects layout (not `/dashboard`) receives `workbench_default_draft` from `Overview.default_draft_path/1` only for a confirmed explicit project or workspace selection, never for a local project implicitly reactivated on a bare route.
Separately, `workbench_new_conversation?` requires `Overview.assistant_path/1` to confirm the scope and the advertised `workbench_project` to match its execution path (the selected member for a workspace).
The normal Projects render suppresses scoped New conversation on gated or pending nodes and while remote activation or workbench selection owns the path, without changing the default draft or New task policy.
Overview and composer patches for the same project reuse the loaded project/model state; the overview loads its metadata when the workspace roster first resolves an execution member and when the selected member changes.
Assistant uses `ComposerComponents.composer/1` with `kind="assistant"` around a `composer_surface/1` with the existing `#chat-form` in its editor slot and `#chat-composer-controls` as its final toolbar sibling.
The toolbar Send submits `#chat-form` via `form="chat-form"`; attachment and workspace controls keep their own forms and hook ids.
`wb_project` plus `wb_draft` restore/select a draft on the viewed node and do not start a session until send.
Assistant passes the draft id and its raw execution path to `Layouts.app/1`; the VCT token remains a draft-storage identity and never substitutes for an execution path.
Review passes the route's task id and the currently loaded task's objective and raw primary repo path to `Layouts.app/1` independently of the selected diff repo; unresolved remote targets cannot load or advertise local review data.
Review node changes and reconnects retain the current route (including commit SHA) and `tab`/`repo` query state; review-load results are scoped by the target id as well as the serving BEAM node.
### AgentsLive task scope and selected-agent streaming
An explicit nonblank `?task=<id>` owns the scope `{target_id, beam_node, task_id}`; `?agent_id=` still works independently and selects only a matching live agent when a task is present.
The loader reads task metadata and matching agent summaries off-process, guards the combined result by scope and generation, and never reads local data for a pending remote target.
The shell gets `workbench_task` from the URL only when explicitly scoped, project/title from verified task metadata only, and an All agents patch clears the task while preserving the node.
Task switches, target switches (including BEAM aliases), and disconnects clear scope-owned inspector, graph and event state; reconnect preserves the task query, and a confirmed scope distinguishes missing task from no agents.
`agents_live.ex` attaches the selected connected inspector through `StreamWatch` (forwarding `:inspector_stream_ready`, `:inspector_stream_reconciled`, `:agent_delta`, `{:agent_stream_closed, agent_id, snapshot, seq}` and worker `:DOWN` in the LiveView process); selection close, node/target changes and termination detach it, a selected owned watch survives agent removal. Snapshots atomically capture checkpoint messages, nested `activity: %{phase:, current_call: nil | %{text:, thinking:}}`, an authoritative sequence and an optional terminal `status`; a sealed snapshot outranks late summaries, a late terminal summary can settle an already-removed agent without restoring its tree row, and `phase: :done` alone never implies success.
`StreamWatch` freezes retirement/replacement batches, replays only newer deltas and guards scope/request identity/sequence watermark in `reconciled/6`; watched checkpoint history belongs exclusively to the stream (Retry and empty-history refresh via `StreamWatch.reconcile/1`, transport failure requires explicit reattachment), unwatchable agents keep the fallback `{:agent_history_loaded, agent_id, node, history_seq, watch_token, result, modal_index}` guarded by selection/node/sequence/watch token, `StreamPanel.stream_panel/1` renders the live current-call row at the memory tail, `data-inspector-scope` binds node/target/selection/watch/snapshot scope, and activity interpretation stays in `StreamPresentation`/`StreamPanel`. Details: `agents_live/CONTEXT.md`.
### ProcessesLive (managed OS processes)
`ProcessesLive` (`GET /processes`, sidebar **Processes**) lists every execution `EvoGit.ProcessManager` tracks on the viewed node — agent tool calls (in-BEAM built-ins included) and background jobs — with node-filtered PUSH liveness off the `"processes"` topic (`{:process_started, execution, node}`, `{:process_updated, id, changes, node}`, `{:process_exited, execution, node}`, `{:process_sample, node, seq, entries}`, `{:process_control, id, entry, node}`) and NO polling; the snapshot and any `agent_id`/`task_id`/node change load asynchronously via `ProcessesLive.Load` (`{:processes_loaded, seq, node, result}`, `load_seq` + node guards); status/kind/text filters are pure render-time state (`Format.filter/2`), URL state is `?status=live|finished|all`, `?kind=tool_call|background_job`, `?q=`, `?agent_id=`, `?task_id=` with `node` appended by `&` (never `Helpers.with_node_param/2`, which appends `?`), pause/resume are one-click with default reasons, and terminate/kill require a non-empty reason through `ProcessesLive.Actions` (`:processes_control_runner`, 4-arity).
A `:builtin` call has no OS process (no stats, no controls); terminal facts (`exit_code` plus a `reason` of `:exited`, `:timeout`, `:invalid_arguments`, `:owner_died`, `{:killed_by, actor}`, `{:crashed, detail}` or `:no_os_process`) are recorded for foreground shell calls too, and a genuinely new row (newest-first) enters with the `process-row-enter` class from the `:entering` MapSet, cleared after `:processes_entering_ttl_ms` (default 1500 ms) and never on the initial load. Detail: `processes_live/CONTEXT.md`.
### HomeLive interactive-session UX (session, send path, queue/interrupt, approvals)
A conversation is ONE long-lived interactive agent session at `/assistant?session=<agent_id>` (`?node=` appended by `&`, always `push_patch`); the agent id IS the `EvoDash.ChatHistory` chat id, `session` is authoritative in `handle_params/3` (MISSING → the local draft), `SessionActions.url/2` is the only URL builder, `parse_session/1` is `Integer.parse/1` + a positive guard, and `session_mode` is `:interactive`, `:one_shot` (legacy `:reflect` fallback) or nil.
There is NO conversation rail: `#chat-session-list` is the sidebar **Conversations** body (`SessionList.session_list/1`) — live sessions (`SessionActions.list/1` → `list_agents/1` + `list_awaiting_input/1`) unioned with cached chats, ordered awaiting-input → running → ended, rows `#chat-session-<id>` that PATCH here but NAVIGATE elsewhere (a cross-LiveView patch is illegal); loaded ASYNC by `LiveHooks.NodeAware` on the connected LOCAL mount, every `assign_node/2` change and every `:node_aware_reload_tasks` debounce — never on a timer.
Send with NO session starts one via `NodeContext.start_session/2` + `SessionActions.session_opts/2` (repo-less `EvoGit.Agents.SelfReflective`, `objective` = the text with NO preamble, no `model_spec` for Auto), adopting `{:ok, agent_id}` (chat id = agent id, `chat_agent_id`, `chat_status: :running`); send WITH one is `send_session_message(node, agent_id, %{text:, attachments:}, :queue)` — no new task or chat; `{:session, :finished | :not_found}` → `:ended` (cache kept, New chat offered), `{:session, {:bad_state, phase}}` and other failures only flash a retry-able error. The fallback fires ONLY when sessions are unavailable — `function_exported?/3` false, `:llm_not_configured`, or `{:interactive_root_only, _}`/`{:invalid_session_opts, _}`/`{:unsupported_session_mode, _}` (also inside `{:start_session_failed, _}`) — as the one-shot `:reflect` task (`mode: "reflect"`, no `:path`, `session_mode: :one_shot`); `:timeout`/`:noconnection` are NOT triggers, and both branches keep the source gate, `ModelSelect.task_opts/4` validation before any send, the pending-remote refusal and the attachment caps.
`Composer.composer/1` keeps the shared provider/model/reasoning capsule and Send/Stop beside the editor in the shared toolbar, with no header picker.
The composer stays usable while `:running` (only `:cancelling`, `:ended`, the source gate, a pending remote target or an unready model snapshot disable it); queue and interrupt behave IDENTICALLY (Send `:queue`, `#chat-interrupt-button` `:interrupt`, both at the next turn boundary — no copy may promise a chunk-level halt); a running send appends a transient `queued_echoes` entry (cap 20) dropped when `message_count` grows, Stop is a graceful `cancel_task/2` on the session task id (fallback `SessionActions.close/3`), Enter submits / Shift+Enter newlines, a mid-run model choice applies to the NEXT session, and New chat (`:idle`/`:ended`) clears draft, refs, echoes and attachments.
Reattach (`?session=<id>`) restores `ChatHistory.get_state(session_id)`, spawns ONE supervised attach loader (`list_agents` + `list_awaiting_input` + `get_agent_history`) and attaches the push-only delta watch (`Watch.attach/1`: PubSub subscription inline, watcher registration + snapshot in a supervised task) whose snapshot seeds `Messages.transcript/1`; an independent attach history replaces the cache only while no watch owns the surface, `:awaiting_input` maps to `:idle`, a summary-less ended session with an empty cache shows "This session has ended." (disabled composer + New chat; one WITH a cache renders read-only), a failed terminal read degrades to nil → "The conversation was deleted.", and node switches reset chat state without cancelling the session. Caps: 200 transcript entries / 8 000 rendered characters / 40 live thought entries.
Attachments are local-filesystem-only (picker ids `"chat_file"`, `"chat_file_image"`, `"chat_file_audio"`): a text file appends its content to the message text; image/audio stage as `%{"type" => "image"|"audio", "name" => …, "media_type" => IANA, "data" => raw}` with base64 only at submit, at most 4 per message of at most 15 MiB each, cleared on a successful send; a remote/pending target sets `attach_unavailable: true` with a manual-path fallback that reads on the LOCAL node.
**Approvals** are session-scoped (`chat_agent_id`, `chat_task_id`, set on adoption AND reattach) and re-inited + re-recovered on every session switch; `ApprovalWorkflow` recovers `EvoGit.CommandApproval.pending/0` off-process after chat restoration and whenever usable chat/node/root-agent scope changes (explicit `retry_approvals`, no polling); ownership requires a nonblank request id, a matching task OR normalized agent id and a matching source node. Two surfaces come from `approval_dialog.ex`: the fixed-height `#approval-status-bar` (`approval_bar/1`, `h-10`, count + Review, reserved even when empty) and ONE `<dialog id="approval-dialog" class="modal" phx-hook="DialogModal">` (`approval_dialog/1`); `approval_dialog_open`/`approval_dialog_index` are LOCAL VIEW state (never persisted, reset by `reset_chat/1`), and the events are `open_approval_dialog`, `dialog_closed`, `prev_approval`, `next_approval`, `retry_approvals`, `approval_response`. Markup, heights and notification wiring: `home_live/CONTEXT.md`.
`requested_with_notification/2` admits live arrivals as `{socket, payload_or_nil}`: only a novel owned pending live request auto-opens review and pushes a privacy-safe `task_notification` (`%{title:, body:, request_id:, scope:, tag:}`); `#assistant-notifications` hosts `BrowserNotifications` (`data-approval-request-ids`/`data-approval-scope`, explicit `data-enable-notifications` opt-in, NO automatic permission request), `review_approval_notification` opens the index as REVIEW only, and a click or dismissal never authorizes execution. Tiers follow the root three-tier contract; decisions route by chat/source node (never evaluator target), BOTH are disabled while a response is in flight (`approval_responses`), a failed request is retained with retry guidance, and approval state stays ephemeral outside ChatState.
Watch messages delegate to `Watch.ready/5`, `Watch.push/4`, `Watch.closed/4`, `Watch.down/4`, atomically installing the socket plus the transcript/thought-process/meta surface; `phase: :done` ends the chat and an optional authoritative `status` settles the task status after projection, task broadcasts cannot reopen a sealed terminal watch, `stream_attach_seq` stops independent attach/history results from overwriting a newer watch, pending/failed watches retain display and phase ownership, an interactive terminal broadcast closes the bubble but RETAINS watch ownership, completed/cancelled events fetch a lite task row and finalize from its result, a live failed broadcast shows generic "The task failed." without the structured error, `chat_fetch_seq`/`chat_task_fetch_seq`/the model/source counters are separate (`reset_chat/1` resets only the chat pair), and persistence is local-only at lifecycle updates. Layout is stable end to end: an entry's footer ALWAYS renders, the interrupt affordance shares a constant `h-7` row with `ExecutionIndicator.execution_indicator/1`, the approval strip reserves its height, and `#chat-messages` (`flex-1 min-h-0`, `overflow-anchor: none`, `overscroll-behavior: contain`) is scrolled by the instant coalesced `AgentHistoryAutoScroll` hook (ONE `requestAnimationFrame`, 56 px threshold). Strip/dialog markup, notification wrappers, scroll internals and per-entry rendering: `home_live/CONTEXT.md`.

### Draft scope identity (`EvoDashWeb.DraftScope`)

## Async data-load & exit-safety contract
**Rule: no LiveView process ever blocks on a store / registry / cross-node RPC call, and no page renders unbounded task blobs.**
Every read that can cost an `:erpc` round-trip or a task-store `GenServer.call` runs in a supervised `EvoDash.TaskSupervisor` child (each call inside `EvoDash.SafeCall.run/1`) and lands as a self-message guarded by a monotonic seq/generation counter PLUS a node match (usually with a project-path / task-id match too); every per-click MUTATION is either a guarded `SafeCall.run/1` in the handler or a supervised `SafeCall.start/3,4` task whose result message is ALWAYS sent, so a loading flag can never stick.
Exit-safety is load-bearing: a `GenServer.call` timeout, a dead store or an unreachable remote node EXITS the caller (which `rescue` alone cannot catch) — an unwrapped call in a handler kills the LiveView, one in a loader wedges the loading state forever.
**Spawn-only-when-connected**: `handle_params/3` runs twice per mount (the DISCONNECTED static render, then the connected one) and a spawner's result goes to the calling process, so a spawn from the dead render is always discarded — gate the spawn (`if connected?(socket)`) while keeping the loading assigns the static shell renders (`ReviewLive.start_async_load/2` is the reference implementation).
`EvoDash.SafeCall` (`../../evo_dash/safe_call.ex`) is the ONLY sanctioned boundary: `run/1` → `{:ok, v} | {:error, {:exit, reason} | {:exception, e} | {kind, reason}}`, `run/2` → the value or a caller-supplied fallback, `start/3,4` → a supervised task that always reports `{tag, result}`.
**Message-shape rule (gotcha): `start/3,4` sends the tag VERBATIM as the message's first element — a multi-element tuple tag stays ONE nested tuple and is NEVER flattened.** A `{:foo, seq, node}` tag arrives as `{{:foo, seq, node}, result}`; handlers MUST match that nested shape (a flattened clause silently never matches, so the outcome is lost). Tasks spawned directly with `Task.Supervisor.start_child` + a manual `send/2` have FLAT tags.

### Projects parent resume and target-identity gotchas
`ProjectsLive.handle_params/3` derives `remote?` only from BEAM-node inequality, while project activation selects the remote path by non-nil target id, so a connected target aliasing the local BEAM follows inconsistent branches.
The remote-activation continuation sets `resume_foreign_repos_guard` from the pending resume id; the parent clears it only on target-id switches, so a same-BEAM connected target can leave the guard set.
The URL `resume_from` handling also unconditionally starts `start_foreign_repos_restore/2`, whose lookup is the LOCAL `TaskRegistry.get_task_lite/1` even in a remote-target context; its result guard checks only task id and BEAM node, not target id or request generation, so it can overwrite the remote activation's restored list or survive a same-BEAM target switch.

### Task read shapes — the lightweight reads

## Constraints
- Each LiveView uses either an inline `render/1` or a companion `.html.heex` template — not both. (Every page except `AgentsLive`, which uses its companion template, renders inline.)
- Auto-refresh intervals must be gated behind `connected?/1` to avoid leaking timers.
- Naming: `<name>_live.ex` for modules, `<name>_live.html.heex` for companion templates.
- **No `try/rescue` around config/core-value loading.** LiveViews must NOT wrap `EvoGit.Config.*`, `EvoGit.AgentScheduler.*` or `EvoGit.SystemCheck.*` calls: if these crash the LiveView SHOULD crash truthfully — a wrong default (`false`, `%{}`, `100_000`) is worse than a visible crash, and the supervision tree handles recovery.
- **`try/rescue` for external boundaries requires a justification comment.** The only accepted use is around genuinely untrusted external execution (e.g. `System.cmd` running project-config-defined shell commands in `ProjectsLive`'s `run_command`), where a friendly error flash beats a crash.
- **Atom conversion from untrusted input uses whitelist lookups, not `try/rescue`.** For user-supplied strings (URL params, form POST data) use explicit `Map` lookups (`Map.get/2`, `Map.fetch/2`) or a `case` against a known whitelist — never `String.to_existing_atom/1` in a rescue, and never `String.to_atom/1` (atom-table exhaustion DoS).
