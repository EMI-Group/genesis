# AgentsLive Support Modules

## Intent

`agents_live.ex` is the LiveView ONLY: `mount/3`, `handle_params/3`, one-expression `handle_info`/`handle_event` routers, `terminate/2` and bare template delegates; every state transition lives in a module in this directory, and the template renders only what those modules computed.
`agents_live.html.heex` is a THIN COMPOSITION: the `Layouts.app` shell, the remote gate, the `.agents-page-layout` wrapper and three function-component calls (`TreePanel.tree_panel/1`, `DetailPanel.detail_panel/1`, `Modals.modals/1`).

## Template Composition

`agents_live.html.heex` holds only the shell (`Layouts.app`, the `RemoteGateComponents.gate_active?/1` branch, `div.agents-page-layout`, the three component calls).
`TreePanel` renders `div.agents-left-col`, `DetailPanel` `div.agents-detail-col`, `Modals` the modals as SIBLINGS of `.agents-page-layout`; function components add no wrapper, so the DOM is byte-for-byte the pre-split markup (`.agents-page-layout` keeps exactly its two column children).
Partials `use EvoDashWeb, :html`, hold no state/event/async work, and take whole assigns with shell-side fallbacks (`assigns[:commit_graph] || []` etc.); `agents_live.ex` carries no template helper and no partial aliases.

## Constraints

- Pure, no I/O: `ToolCallDisplay`, `PendingEvents`, `HistoryGate`, `ContextMeter`, `AgentList`, `TreeView`, `OptimisticMessages`, `RuntimeStream`, `StreamLimits`, `StreamPresentation`, `CommitGraph`, `Render` (plus `ThresholdCache.read/3`/`put/4`/`threshold_from_config/1`/`threshold_for_agent/2`/`default_threshold/0`); model labels come from `EvoDashWeb.ModelLabel`; deliberate I/O exceptions are `LoadData` and `ThresholdCache.fetch/3` (`EvoDash.TaskSupervisor` children only, never the LiveView process).
- No `try/rescue`: the exit-safe boundary is `EvoDash.SafeCall.run/1` inside `Loader`'s two spawners, `CommitGraphState`'s fetch spawn, `Inspector`'s history fetch and `SendMessage`'s private `send_user_message_safely/3` (an EXIT becomes an error VALUE).
- Three config reads only: the threshold (`:agents_config_runner` in `ThresholdCache.fetch/3`), the layout-banner health status (`LoadData.node_config_status/1`), and `AgentMerge`'s `safe_compression_threshold/1` fallback (fresh cache read → LOCAL inline `EvoGit.Config.resolve/1` → `default_threshold/0` on a remote miss).
- `@config_status` is reloaded ONLY by `LoadData.load/2`; `refresh/2` never re-reads it, so the banner keeps its mount-time value until a page load.
- Subscriptions: `"agents"` only (`mount/3`) plus NodeAware's `"tasks"`/`"remote_connections"` — no `"scheduler_config"`, no config topic.
- `Helpers.tool_call_name/1`/`tool_call_arguments/1`/`tool_call_is_shell?/1` are reused; `Helpers.tool_call_display/1` is NOT used here but stays public and test-pinned (do not remove it).
- New user-facing strings use `gettext`; never run `mix gettext.extract`/`merge`/`translate` during development.
- `commit_graph.ex` is ~1 213 lines and legitimately long (~437 lines of `@moduledoc` that IS the pinned output contract); extract into `commit_graph/` rather than trimming the contract.

## Async Load & Exit-Safety Contract

No render path blocks on a store, scheduler or cross-node RPC: every such read runs in an `EvoDash.TaskSupervisor` child and reports back as a tagged message; the page load spawns ONLY on the connected mount (`@agents_loading` seeds `true`, the dead render paints the shell and spawns nothing).
Every spawned loader calls its runner through `EvoDash.SafeCall.run/1` INSIDE the task body, so a timeout or dead target is an error VALUE and the result message is ALWAYS sent — no task can wedge a loading flag.
Page/refresh reads report nested `{{:agents_data_loaded | :agents_refresh_result, scope, generation}, safe_result}`; graph reads report `{:commit_graph_loaded, scope, seq, result}`.
All three require the exact active `{target_id, beam_node, task_id}` and request counter, and the target must still be available; the legacy flat page/refresh and atom-node graph receipts are admissible only on the bare local unscoped view.
Loader seams (`:agents_list_runner`, `:agents_task_runner`, `:agents_config_runner`, `:agents_commit_graph_runner`) resolve inside their workers.
Every loading/error assign clears on its result path; a failed page load keeps the last good tree for the same scope and renders `#agents-load-error` with Retry (`retry_agents_load`, no polling), while scope changes clear old data and all in-flight ownership.

## Parent Wiring — Focused Task Scope

`NodeAware.assign_node(socket, params, preserve_unresolved?: true) |> Scope.prepare(params) |> Loader.start_page_load()` is the parameter path; `Scope.prepare/2` compares its own persisted identity even if a hook already changed node assigns, and `Loader` spawns only when connected and available.
A nonblank `task` stays an opaque binary in `@task_scope_id`; `Scope.path(task_id, target_id, agent_id)` URL-encodes the independent queries, and an All agents patch uses `Scope.path(nil, @current_node_id)`.
`@current_path` retains `task` and any URL `agent_id` for reconnect; `{:node_selected, id}` routes to `Scope.node_selected/2` and keeps `task` but drops the previous node's agent deep link.
`{:remote_connection_status, _, _}` routes to `Scope.connection_status/2`, which delegates NodeAware chrome, invalidates disconnected data immediately and re-patches when the same target resolves to a different BEAM.
A target is available only when its `:connected` status advertises the resolved BEAM; a connected alias of the local BEAM is valid but a pending local placeholder is not.
`Scope.prepare/2` initializes the scope presentation assigns; the parent may keep its existing mount seeds and should not duplicate the old node-only reset or pre-load inspector selection.
Availability/identity change clears both live and retained rows, inspector/watch/history state and modals, optimistic/queued messages, raw/folded graph and folds, buffered events and timer tokens; page, refresh and graph counters advance while the user’s `left_view` and serialized stream worker are preserved.
Reset advances the watch token even without an attached watch, rejecting stale independent history results across same-BEAM target and task switches; `inspector_history_seq` advances only for independent history fetches and adopted checkpoints, not resets.
On a successful page load the loader applies only matching rows, then consumes the requested agent id; in focused mode selection, deep links and send actions require a matching live row.

The focused loader uses `NodeContext.call_remote/4` for `RemoteAPI.get_task_lite/1` and `list_agents/0` so a failed RPC does not masquerade as a missing task or zero agents.
The task seam `:agents_task_runner` takes `(beam_node, task_id)` and returns a task, `nil`, `{:ok, task_or_nil}` or `{:error, reason}`; the agent seam continues to take `(beam_node)` and scoped reads accept a list or an explicit error envelope.
The lite task's projected `@scoped_task` is `%{id:, objective:, project_path:, status:, type:}` or nil; agent summaries are filtered by exact task id before building child links.
Task and agent result are applied together via `Loader.loaded(socket, scope, gen, result)`; scoped refresh uses the same generation, while the nested unscoped refresh message routes to `Loader.refreshed(socket, scope, seq, result)` on its own sequence.
The old flat `{:agents_data_loaded, node, gen, result}` and `{:agents_refresh_result, seq, node, result}` test envelopes route to `Loader.legacy_loaded/4` and `Loader.legacy_refreshed/4` respectively and cannot change a scoped or target view.
`@scoped_task_state` is nil for unscoped, else `:loading | :unavailable | :missing | :error | :ready`; pass it as `scoped_task_state={@scoped_task_state}` to `TreePanel`, which distinguishes initial loading, unavailable/missing/error, a real empty roster and a refresh of a retained view.
Pass `Loader.history_scope_pending?(assigns)` to `Layouts.app` as `workbench_history_scope_pending?`: this reports only a started, available scoped load awaiting the task row, not the tree's initial loading placeholder.
`Loader` records the scoped request's existing `{scope, generation}` only after a successful connected spawn and consumes it on the matching receipt; scope resets, task deletion and spawn failure discard it, while stale or duplicate scoped receipts cannot change it or apply metadata.
A same-scope refresh keeps its task metadata and does not mark History pending, even for an already known task with no project; settled missing/error states, the disconnected render, unavailable targets and the unscoped view report false.
`retry_agents_load` delegates to `Loader.start_page_load/1`, including in focused mode.

`{:task_updated, …}` and `{:task_deleted, …}` route to `Scope.task_event/2`; only a node/task match can refresh or clear the focused data, while available-node events retain the independent shared sidebar debounce (`:node_aware_reload_tasks` stays with NodeAware).
Incremental agent events still route to `AgentMerge.buffer_event/2`, but focused registrations require `summary.task_id`, updates require a matching explicit task id or a known live/retained/pending-registration id, and removals require known membership.
`{:agents_updated, node}` routes to `AgentMerge.buffer_node_refresh/2`; the unowned node-wide fallback is ignored in focused mode, and a matching task event, incomplete known agent or explicit Retry can refresh the scoped snapshot.
Only current timer tokens can drain (`{:flush_agent_events, token}` → `Loader.flush(socket, token)`; `{:commit_graph_tick, token}` → `CommitGraphState.tick(socket, token)`); an old timer cannot drain new-scope buffers or trigger git reads.
The atom `:flush_agent_events` maps to `Loader.flush(socket, :manual)` and the atom `:commit_graph_tick` to `CommitGraphState.tick/1` for manually driven legacy tests; production timers are always tagged.
During a scoped snapshot read, matching pushes wait in the buffer, and the admitted response re-arms one flush so the snapshot cannot overwrite an already-applied event batch.

## Left-Panel View Switcher & Commit-History (Temporal) View

The left panel renders the spatial agent tree OR the temporal commit graph, switched by a segmented control (`#left-view-tree` / `#left-view-commits`, `phx-click="switch_left_view"`, `phx-value-view`).
`@left_view` (`:tree | :commits`, default `:tree`) is whitelisted by PATTERN MATCHING the two literals in `CommitGraphState.switch_left_view/2` (no atom conversion); switching to `:commits` force-refreshes the graph, switching back never touches the git RPC, and the preference survives a node switch while the commit-graph DATA is per-node and reset there.

### Commit-graph async contract

- Assigns: `@commit_graph` (`[repo_view]`), `@commit_graph_raw` (`%{repo_key => %{commits:, refs:, truncated:}}`), `@commit_graph_loading`/`_error`/`_loaded`, `@commit_graph_seq` (never reset), `@commit_graph_fingerprint`, `@commit_graph_fetched_at`, `@commit_graph_tick_scheduled`, `@commit_fold_expanded` (per-node `MapSet` of expanded fold keys), `@retained_agents`.
- **Fingerprint gate** — a NON-forced call compares `CommitGraphRefresh.fingerprint/1` over `commit_graph_agents/1` with `@commit_graph_fingerprint`: unchanged and non-empty skips rebuild AND refetch; changed/nil rebuilds from `@commit_graph_raw` + the merged agent set and refetches. Bypasses: `force: true` (first activation, tick, view re-switch), the initial load and an in-flight fetch. Selection needs neither: `start_ids`/`end_ids` exist for every agent and markers derive from `selected_id` at render time.
- `commit_graph_agents/1` is the ONE agent set: `@agents` MERGED with `Map.values(@retained_agents)`, de-duplicated by `id` (live wins); the TREE still renders `@agents` only.
- `commit_graph_groups/1` groups eligible agents (`repo_root`, `base_commit`, `current_commit`, `task_id` all binaries) by `{repo_key (= repo_root), task_id}`; `live_tips` = de-duplicated `current_commit`s of NON-ended agents only; empty groups mark the view loaded with an empty graph.
- `spawn_commit_graph_fetch/2` calls the runner ONCE per group through `CommitGraphRefresh.fetch_result/3` (limit 100) and sends `{:commit_graph_loaded, scope, seq, result}`.
- **PARTIAL SUCCESS** — a reply other than `{:ok, %{commits: list}}` drops only THAT group, so one failing git RPC never blanks the page; `{:error, reason}` only when EVERY group failed, carrying the LAST failure as `{:commit_graph_repo_failed, {repo_key, task_id}, reply}`.
- `raw_by_repo` unions groups sharing a `repo_key` via `CommitGraphRefresh.merge_repo_graph/5` (commits de-duped by `:sha`, `refs` unioned per sha, `truncated` OR-unioned).
- Runner seam `:agents_commit_graph_runner` (arity 5, default `&EvoDash.NodeContext.list_task_commit_graph/5`, the durable TASK-SCOPED RPC) resolves at spawn time; `fetch_result/3` runs inside `SafeCall.run/1` (an EXIT → `{:error, :commit_graph_fetch_failed}`).
- **Throttle** — a refetch inside the minimum interval (1000 ms, read at call time via `:agents_live_commit_graph_tick_ms`) is skipped and arms ONE one-shot `:commit_graph_tick` (never a repeating poll) whose `tick/1` retries with `force: true`; triggers are `AgentMerge.apply_result/2` and a `flush/1` answering `:refresh`, each running ONE `maybe_load(socket, [])`.
- **Base de-duplication** — the task-scoped fetch INCLUDES the base commit, so `CommitGraph.base_shas/2` suppresses a synthesized `:base` node when that sha is present; a fetched commit equal to an agent `base_commit` stays a NORMAL `:commit` node — never add a second base node.
- The per-group limit is FLAGGED as data (`truncated: boolean` per group, surfaces as `repo_view.truncated`); the renderer has no "+N more" indicator, older commits simply stop appearing.

### Retained ended agents (in-session)

The core deletes an agent's ETS rows (and its branch) on recycle, which would remove its lane and START/END markers; `@retained_agents` (`%{agent_id => agent_map}`) is the in-session remedy — committed agents only, NOT durable.

- An entry is the last-known agent map with `ended: true` added.
- `apply_agent_removed/2` captures the removed row there and KEEPS `selected_agent_id` pointing at it (the graph annotation persists while the panel shows "Agent not found"); the rest of the cleanup is unchanged (children orphaned to `parent_id: nil`, tracking sets and `repo_trees` cleaned).
- `apply_result/2` moves ids absent from the fresh list (but present in `@agents`/`@retained_agents`) into `@retained_agents` marked `ended: true` and DROPS ids that reappear live; nothing is mass-retained on the first apply or after a node switch, and `merge_registered_agent/3` deletes the id.
- `CommitGraph.build/2` reports `ended` on the `agents` entry; retention contributes entries and grouping (an all-ended group is still fetched with empty `live_tips`, recovering the task from its durable refs) but never tips.

### Commit view markup (contract boundary)

`EvoDashWeb.AgentsComponents.CommitGraphView.commit_graph_view/1` — called FULLY QUALIFIED from `TreePanel.tree_panel/1`, attrs `repos`/`selected_id`/`loading`/`error`/`node_key` — owns ONLY the view model; every DOM id, tooltip, legend chip and hook belongs to the renderer (`../../components/agents_components/CONTEXT.md`).
Frozen scroll contract: `#cg-scroll-<repo_dom_id>` (`.cg-scroll`, `overflow: auto`) is the ONE bounded scroller and the sticky lane header (`#cg-lane-header-<repo_dom_id>`, `position: sticky; top: 0`) resolves against it, not the page; the card body → `#commit-graph` → repo → `.cg-scroll` chain must stay a DIRECT-child flex chain (each link `min-height: 0`).

### Commit-Graph View Model (`CommitGraph` + `commit_graph/`)

`build/2` (collapsed) and `build/3` (3rd arg = expanded fold keys, a `MapSet`/list of binaries; any other shape = collapsed) return one `repo_view` per repo group, sorted by `{repo_name, repo_dom_id}`; `fold_keys/2` lists every fold key, and `grouping_key/1` (`repo_root || repo_id`) / `repo_display_name/1` are shared with `TreeView`. Total: non-map input degrades to empty nodes/edges/agents, never raises, no try/rescue.

- **Nodes** — every fetched commit de-duplicated by sha, PLUS one `kind: :base` node per agent `base_commit` absent from the fetch, PLUS one `kind: :noop` stub per child with an empty progress path; keys `%{sha, short_sha, message, author_name, date, refs, row, column, depth, kind, owner_id, start_ids, end_ids}` where `row` is the unique top→bottom position, `column`/`depth` the owner's lane/depth (0 unowned), and `start_ids`/`end_ids` the agents forking from / tipping at the sha.
- **Rows** — a cycle-safe topological LAYER over PRESENT parents (`L = 0` with none, else `max(L(parent)) + 1`; memoized DFS with a `visiting` set); rows sort ascending `{L, date_unix, sha}`, parents strictly above children.
- **Lanes (one per agent)** — a subtree-contiguous pre-order from the ROOTS (nil `parent_id`, or one matching no agent of the group), unreachable agents appended as fallback roots; lane = the index, SHIFTED RIGHT BY 1 when the repo has ≥1 unowned node, so lane 0 is NEUTRAL.
- **Ownership** — a first-parent walk from `current_commit` backwards stopping WITHOUT collecting at a non-binary sha, `base_commit`, an already-seen sha or a sha absent from the fetch; the deepest path agent wins (ties: smallest index), a commit on NO path inherits the owner of the commit it is the FIRST parent of, else is UNOWNED; a base node belongs to the shallowest agent forked from it, a stub to its child.
- **Edges** — `%{from_sha, to_sha, from_column, from_row, to_column, to_row, kind, owner_id}`, `to_sha` never nil. Commit edges: `:parent` for the FIRST present parent, `:merge` for every other, identical pairs de-duplicated, DROPPED when the unordered sha pair matches an agent-level edge. Agent-level edges (child C, parent P in the group): `:spawn` dashed from `C.base_commit` to C's OLDEST progress-path commit (or stub); `:merge_back` dashed from C's tip (or stub) into P's lane, landing on the TOPMOST P-owned node strictly BELOW the source, else the NEAREST P-owned node ABOVE, else DROPPED — NEVER a mid-air stub, never `to_sha: nil`, never on the source's own row. `edges` = commit ++ agent.
- **`agents`** — one entry per agent in lane order: `%{agent_id, task_local_id, status, depth, lane, parent_id (raw), color, start_sha, end_sha, ended}`.
- **Folding — COLLAPSED BY DEFAULT** — `Fold` keeps only structural ANCHORS visible: the lane owner's START and END, any node in a `start_ids`/`end_ids`, every node carrying `refs`, every `:base`/`:noop` stub and every unowned neutral-lane node. A maximal run of hidden interior commits on ONE lane folds only at length ≥ 2 into EXACTLY ONE `kind: :gap` node (`sha: "gap-" <> fold_key`, blank text fields, the run owner's `column`/`depth`, plus `fold_key`/`hidden_count`/`expanded`) present in BOTH states; it takes the run head's row slot, so visible rows re-index `0..n-1`, and a lone hidden commit stays a real `:commit` row (never hidden, never aliased). `fold_key = "<agent_key>|<above_key>|<below_key>"` with the nearest VISIBLE same-lane anchor shas and `"^"`/`"$"` sentinels, stable while the commit set is unchanged. ONE alias map (hidden sha → its gap sha) covers commit AND agent-level edges; an edge whose endpoints alias to the same node is dropped. `repo_view.fold_count` counts runs (expanded or not), an unknown/stale key is ignored, and a fold toggle rebuilds the pure model IN-PROCESS from `@commit_graph_raw` — no git RPC, no fetch spawn, no throttle/fingerprint consultation.
- **Depth hue (verbatim)** — `color = EvoDashWeb.ThemeColor.hsl_to_hex(hue, 70, 54)` with `hue = Integer.mod(round(depth * 137.508) + 265, 360)`; depth 0 = `#7c38dc`; non-integer/nil/negative → 0.
- **Output shape** — `%{repo_key, repo_dom_id, repo_name, node_count, edge_count, row_count, column_count, truncated, fold_count, nodes, edges, agents}`, `row_count == node_count`, `nodes` sorted by `row`, `repo_dom_id` the stable DOM id.

## Inspector RuntimeStream Reducer

`RuntimeStream` is a pure reducer — `new/2`, `seed/3`, `apply_batch/4`, `active?/1`, `replace_activity/2`, `current_call_id/1`, `checkpoint_transition?/2` — independent of the Assistant's `Delta` reducer.
Snapshots and ordered activity events carry `%{phase: :idle | :llm_waiting | :llm | :llm_complete | :retry_wait | :tools | :compressing | :preparing, current_call: nil | %{id:, turn:, attempt:, text:, thinking:, checkpointed: boolean()}}`; `:compressing`/`:preparing` are admitted NON-call phases, only `:llm_complete`/`:tools` prove generation completion, and only `:llm` is an active call phase.
`checkpointed` is the core's authoritative adoption marker of that call: `false` on every fresh call id, flipped to `true` exactly when the batch-start checkpoint adopts it (its assistant message is then in `snapshot.messages`), delivered as an ordinary activity replacement and present in later snapshots; an ABSENT key reads as `false`.

- An activity event replaces the WHOLE current-call projection including accumulated text/thinking; chunks append only to an existing call. Core captures content without watchers, so a mid-call snapshot with both text and thinking as explicit binaries proves complete capture — no invented coverage flags.
- Phase lives in `state.activity`, bounded content in `state.projections`, retaining ONLY the current call (`%{identity: %{id: id}, turn:, attempt:, message_index:, response:, thinking:, tool_calls:, checkpointed:, complete:, generation_complete:, capture_coverage:, chunks_seen:, omitted_*}`); `message_index` is a local monotonic live-call DOM ordinal, not a checkpoint index.
- Same-id replacement keeps tool descriptors, the DOM ordinal and the checkpoint marker (an absent marker preserves it); a fresh attempt id replaces all content/tools, resets the marker to `false` and advances the ordinal, and a PRESENT marker reads strictly (`true` only for `true`). `current_call: nil` retires every excerpt and tool (aborted retries and checkpointed calls included), and later chunks, accounting, yield or tool announcements cannot resurrect them.
- Generation completion follows only `:llm_complete`/`:tools` — never turn accounting, yield, retry, failure or lifecycle finish; yield sets `:awaiting_input`, finish freezes later events without asserting success, and `active?/1` means only a nonterminal running/cancelling lifecycle.
- `seed/3` keeps agent/node ownership and raw checkpoint messages, rejects a foreign agent, and prefers an explicit nonnegative seq over the embedded seq over zero; a reseed keeps the DOM ordinal and same-call tools but REPLACES response/thinking, and missing/malformed activity clears stale projections while preserving the ordinal.
- `apply_batch/4` rejects stale/invalid seq, foreign agent and post-finish events (unknown events are inert; an accepted newer batch still advances the watermark); `checkpoint_transition?/2` walks every ordered activity event with an accumulator carrying the rendered call id AND its `checkpointed` flag, and reports a transition on retirement/replacement of an existing call or on a not-yet-checkpointed call being adopted (`checkpointed: true`), never on a repeated marker of an already checkpointed call.
- Admission and node/watch-generation guards belong to StreamWatch; the obsolete in-flight/message-start/flattened-activity protocols are not consumed, no checkpoint identity reader exists, and checkpoint suppression is driven ONLY by the authoritative `checkpointed` marker of the current call — never by turn, content, byte-prefix or message-index guessed overlap.
- `StreamLimits` owns the budgets (12 projections, 48_000 bytes per response AND thinking, 20 tools first kept, 1_024 bytes per tool name): UTF-8-safe copied prefixes, no unbounded concatenation before a bounded append, omission counted rather than inserted after a missing boundary, authoritative replacement recomputing missing bytes, tool announcements never implying execution; checkpoint messages and protocol identities are never truncated.

## Inspector StreamWatch Lifecycle

`StreamWatch.attach(socket, agent_id)` subscribes in the connected LiveView process and asynchronously registers that same pid through one serialized, consumer-monitored worker; forward `{:inspector_stream_ready, node, token, agent_id, result}` to `ready/5` and `{:agent_delta, agent_id, seq, events}` to `push/4`, then render `assigns.inspector_stream.state` as the `RuntimeStream` projection.
`active?/2` includes snapshot-pending and reconciling watches and excludes errors, so the page suppresses independent whole-history reads while watched; the rendered checkpoint source is exclusively `inspector_stream.state.messages`, seeded atomically with live activity from `inspector_stream.snapshot`.

- `reconcile/1` coalesces explicit refreshes while a request is outstanding and keeps the old coherent checkpoint/live pair while buffering newer deltas; a batch retiring or replacing the current call starts reconciliation BEFORE applying anything in it. Forward `{:inspector_stream_reconciled, node, token, agent_id, request, result}` to `reconciled/6`, guarded on viewed node, watch token, agent id and the outstanding request; reconciliation reuses the SAME runner and worker without unregistering.
- An admitted snapshot replaces checkpoint messages and activity together; buffered batches replay only above its authoritative sequence, and replay crossing another ownership boundary freezes that batch and starts another coalesced snapshot request.
- `snapshot_request`, `reconciling` and `required_seq` distinguish the outstanding request and its minimum watermark from the rendered `seq`; a snapshot older than its triggering boundary, an RPC failure or a buffer overflow FAILS the watch visibly (keeping the last coherent pair) and requires explicit reattachment — NO automatic error retries.
- `detach/1` clears render state and the consumer-local subscription immediately, with asynchronous serialized unregister; `inspector_stream_token`/`inspector_stream_worker(_monitor)` survive page resets (tokens stay monotonic; one worker orders rapid A→B→A registrations). Forward the worker's `:DOWN` to `down/4` after other page-owned monitors: a matching death fails the watch and allows a retry.
- Pending remote contexts cannot attach locally; readiness and push application require the current viewed node; negative watermarks are rejected; a snapshot naming another agent fails the watch.
- Buffering admits up to 128 ordered batches or 1 MiB; duplicate/stale batches consume no capacity; overflow or supervisor-start failure produces an explicit watch error rather than silent loss or stuck loading.
- Seams `:agents_watch_runner` / `:agents_unwatch_runner` (both `(node, agent_id, liveview_pid)`) default to the `NodeContext` watcher functions and resolve through `EvoDash.Seam.get/2` on the resolving process' spawn chain (the consumer's own dictionary, then `$callers`, then `$ancestors`, then app env), so an override reaches only the consumer that installed it plus the serial worker it spawned and every other page/worker resolves the production RPC; the worker does RPC through `SafeCall`, cleans up after consumer death and never polls; delta messages have no publisher-node stamp.
- `closed/4` admits the direct `{:agent_stream_closed, agent_id, snapshot, seq}` handoff atomically, even after a finished delta, summary removal or a failed async snapshot request: admission requires a `Snapshot` with matching agent, `phase: :done`, embedded sequence, selected-agent/current-token/target-id/viewed-node ownership, and a sequence at least as new as the rendered, required and buffered watermarks; it replaces checkpoint messages and activity together, clears buffers/errors, unsubscribes deltas and seals the pair against later ready/reconciled failures, worker death and deltas, and `seed/3` treats `:done` as terminal.
- `owns?/2` includes selected pending, failed and terminal watches; `terminal?/2` means an admitted handoff and `active?/2` excludes that sealed watch. A same-target attach preserves a sealed watch; only explicit selection/node/lifecycle teardown may detach it. The parent must retain the selected watch across summary removal, forward the handoff to `closed/4`, project its checkpoint in the same callback and keep the detail panel visible via the retained ended row; retained terminal history is page-local, not durable.

## Inspector Streaming Integration & Protocol Boundaries

The parent forwards ready/reconciled/delta messages through StreamWatch and projects the admitted raw messages into checkpoint rows in the SAME callback as the live-state update; support owns reconciliation requests, snapshot admission and bounded replay, and the parent owns checkpoint-row rendering, whose suppression follows the authoritative `checkpointed` marker of the current call only.
Snapshot-pending, reconciling and failed watches own their checkpoint rows exclusively; independent history reads and late results cannot overwrite a watched pair, watched-history Retry and full-message refresh use `StreamWatch.reconcile/1`, and unwatchable agents keep the separately scoped independent history fallback.
The history list is TWO nested elements: the OUTER `#agent-history-scroll-<id>` (`agent-history-scroll overflow-y-auto …`, `phx-hook="AgentHistoryAutoScroll"`) is the ONE bounded scroller and a DIRECT child of `.agent-detail-history` (CSS pins `.agent-detail-history > .agent-history-scroll { flex: 1 1 0 }`); the INNER `#agent-history-<id>` keeps `phx-hook="InspectorMessages"`, `data-inspector-scope` (node/target/selection/watch/snapshot) and the stable `data-inspector-message` markers, carries `divide-y divide-base-300` (preserving the pinned `.agent-history-scroll > .divide-y > div` entrance selector — `InspectorMessages` animates only newly keyed rows and never scrolls), and holds `#inspector-history-error` FIRST and the `StreamPanel` tail row LAST.

Core contracts: `apps/evo_git/lib/evo_git/agent/stream/CONTEXT.md` + `.../agent/session/CONTEXT.md` — snapshots atomically capture checkpoint `messages`, nested `activity` and an authoritative `seq`; ordered `{:activity, projection}` events replace the projection while text/thinking events append to its current call; a completed call stays available until atomic checkpoint retirement, and the inspector adopts `activity.current_call` from snapshots/replacements and appends only strictly newer chunks through StreamWatch admission.

Protocol boundaries:

- Tool-result/yield/finish events alone cannot replace the automatic retirement/replacement snapshot trigger; deltas expose text/thinking chunks and tool id/name/status but not tool arguments, result bodies or full history changes.
- StreamWatch fixtures must include `snapshot_request: 0`, `reconciling: false`, `required_seq: 0` and real snapshot agent ids; duplicate/stale batches consume no capacity.
- Activity fixtures use real nested `current_call` projections; synthetic `in_flight`, flattened identities, `message_start`, bare chunks without a current call and the removed `message_identity/1` API are unsupported.
- All eight phases have truthful labels; successful empty-thinking notices require complete binary capture plus `:llm_complete`/`:tools` (never `:compressing`/`:preparing`). No checkpoint-message call identity or coverage watermark exists, so checkpoint suppression reads ONLY the current call's authoritative `checkpointed` marker: a not-yet-checkpointed → checkpointed replacement of the same call is an ownership boundary that must resync the checkpoint rows before rendering, a repeated already-checkpointed replacement is not, and reconciliation by guessed turn/content stays unsupported.
- This reducer is not the Assistant's bubble-oriented `Delta` reducer (`../home_live/CONTEXT.md`); neither is a lossless history model.

## Agent Event Contract (push-based, node-identity, coalesced flush)

The page is FULLY push-based — NO periodic poll; the `:evo_git` emitters broadcast exactly four shapes on `"agents"`, each carrying the publisher's BEAM node atom, and every event is availability- and node-filtered FIRST via `Scope.event_from_scope?/2` so foreign events are dropped BEFORE buffering.
The three incremental events are COALESCED: each `handle_info` clause hands the raw event to `AgentMerge.buffer_event/2` (append to `:pending_agent_events`, newest-first, and ONE trailing-edge timer whose window `maybe_schedule_agent_flush/1` reads AT CALL TIME via `:agents_live_flush_ms`, production default `PendingEvents.flush_ms/0` = 300 ms).
`Loader.flush/2` guard-checks a tagged timer then calls `AgentMerge.flush/1`, which drains in ARRIVAL order and answers `{socket, after_flush}`: `:refresh` → ONE `Loader.spawn_refresh/1`, `:refetch` → ONE `Inspector.refetch_selected_history/1`, `:none` → nothing; the loader then updates the graph once if applicable.
Buffer, token and pending-refresh flag clear on scope changes; an incomplete registration and a known task-scoped update in need of metadata can still trigger one fallback snapshot, while anonymous unknown-id updates and node-only bulk signals trigger refreshes only in the unscoped view.

- `{:agents_updated, node}` — throttled bulk-change signal → `buffer_refresh/1` sets the coalesced `:pending_agents_refresh` boolean and arms the same timer; foreign → ignored.
- `{:agent_registered, id, summary, node}` — the full `RemoteAPI.list_agents/0` summary shape, merged IN-MEMORY for local AND remote through ONE shared path (`merge_registered_agent/3` → `build_registered_agent/2`, the same field mapping and derived fields as `LoadData`) at the sorted `{depth, id}` position; a duplicate id is a no-op.
- `{:agent_updated, id, changed_fields, node}` — `changed_fields` NEVER contains `:context`; merged in-memory for BOTH nodes. `context_node` → `context_path`, `phylo_node` → `current_commit`, nil `usage` → zero, `compression_pct` recomputed on `total_tokens` OR `compression_threshold` (a nil/non-positive threshold keeps the previous denominator), `context_window` is NOT a delta key (omitted keeps the row's value — never reset to 200_000), `:pending_user_messages` re-anchors the queue (an absent key leaves it untouched); children, `repo_trees`, status tracking and `id_to_display` refresh as usual, and a missing row sets the refresh flag.
- `{:agent_removed, id, node}` — the row is dropped in-memory (children orphaned to `parent_id: nil`, parent's children and `repo_trees` refreshed) and captured into `@retained_agents`, for BOTH nodes; foreign → ignored.

## Notes for Agents — coalesced flush (one index, one pass)

`AgentMerge.flush/1` answers `{socket, after_flush}` and never spawns a task or touches the commit graph — the LiveView performs that ONE follow-up.
A flush builds ONE `%{id => agent}` and ONE `%{id => position}` index for the whole burst (`AgentList.by_id/1` / `positions/1`), so an update is a map lookup plus a map put instead of `Enum.find_index/2` + `List.replace_at/2`, and k events over n agents cost O(k + n).
Arrival order is part of the contract: every merge reads the CURRENT row (already merged earlier in the burst) as its base, and a structural event (`:agent_registered`/`:agent_removed`) first folds pending merges into the list, then mutates it.
Preserved semantics: fallback refresh, `Inspector.preserve_terminal/2` settlement, threshold/context-window carry-over, `compression_pct` gating, children recalculation, ONE `repo_trees` rebuild per flush and at most one selected-history refetch per burst.

## Notes for Agents — Agents page layout & legend tooltip

At `xl+` the page fills the SHELL CONTENT BOX, never the viewport: the root `div.agents-page-layout.shell-fill` (`height: 100%` from `main#main-content`, whose definite box already excludes the persistent top bar and the main padding), then the grid rule (`overflow: hidden`), `.agents-left-col` (column flex, `overflow: hidden`), `.agents-tree-panel` (card, `flex: 1 1 0`), tree content scrolling inside `.agents-tree-panel .card-body`, and `.agents-legend` as a SIBLING of card-body at the panel bottom; below `xl` the grid rule does not apply, so the page is normal flow under `#main-scroll` inside `#app-layout`.
**Legend tooltips use the `LegendTooltip` JS hook, NOT DaisyUI `.tooltip`**: DaisyUI's absolutely positioned, horizontally centered pseudo-element can extend outside the panel at the right-aligned chips, where the page's overflow containers can clip long `data-tip` text.

Chips carry `data-tip` (gettext) + `phx-hook="LegendTooltip"` + unique ids (LiveView requires `id` for a hook) and omit the `tooltip` class to avoid duplicate tips; the "Send Message" button tooltip (`tooltip` class, short text near the card edge) fits and stays — do not convert it.

## Notes for Agents — Context tile (context-usage meter)

The Context tile is a context-usage METER, not a threshold-relative `progress`: the bar's full width is the model's CONTEXT WINDOW, the fill is current context size (`:total_tokens`) and a vertical TICK marks the compression THRESHOLD.
It is a full-width sunken tile directly below the 2-column Cached Tokens / Cache Hit Rate grid; all geometry and numeric labels come from ONE `<% meter = ContextMeter.build(agent) %>` block in `agents_live/detail_panel.ex`, user-facing prose is gettext, and there is no phx-hook or JS.
`#agent-context-meter` (`relative mt-2`) data-attribute contract (render-test pinned): `data-context-fill-pct`, `data-context-tick-pct` (OMITTED when unknown), `data-context-zone` (`success`/`warning`/`error`), `data-context-window-tokens`, `data-context-threshold-tokens` (omitted when unknown), `data-context-current-tokens` — every percentage `Float.round/2` to EXACTLY one decimal (`:erlang.float_to_binary(_, decimals: 1)`, clamped 0..100), with CSS and labels derived from the SAME rounded float, and the fill div carries `style="width: <fill_label>%"` + `meter.fill_class`.
Zones are integer math on current vs threshold: `< 80%` → `:success`, `< 100%` → `:warning`, `>= 100%` → `:error`, unknown threshold → `:success`; `fill_class` → `bg-success`/`bg-warning`/`bg-error`, `tick_class` → `bg-base-content`.
The tick is a `w-0.5` bar centered with `-translate-x-1/2` at `style="left: <tick_label>%"` with a rotated-square cap and a compression-threshold tooltip; the header shows `current / threshold` (current only when unknown) and the caption `gettext("Compression at %{tokens}", …)` or "Compression threshold unknown" plus `gettext("Compressions")` and the legacy `count (pct%)` label.
The unknown-threshold render is reachable only for an agent map with NO `:compression_threshold` key; the real update path always restores a known threshold.

## Notes for Agents — `whitespace-pre-wrap` content must sit flush against its tags

HEEx newline + indentation between tags becomes a literal text node that `whitespace-pre-wrap` preserves as leading blank lines/indentation inside the rendered block: always put the interpolated content on the SAME line as the opening tag (`<pre class="whitespace-pre-wrap break-words"><%= text %></pre>`) or use `<%= ... %>` inside a single-line element.
The page's pre-wrap site is the full-objective modal's single-line `<pre …>…</pre>`; multi-line markup around pre-wrap content silently adds whitespace.
