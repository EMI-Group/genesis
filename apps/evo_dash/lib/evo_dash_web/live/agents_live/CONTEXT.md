# AgentsLive Support Modules

## Intent

`agents_live.ex` is the LiveView ONLY: `mount/3`, `handle_params/3`, one-expression `handle_info`/`handle_event` routers, `terminate/2` and bare template delegates — no template helpers, no presentation logic.
Every state transition those routers delegate to lives in a module in this directory; the template renders only what those modules computed.
`agents_live.html.heex` is a THIN COMPOSITION: the `Layouts.app` shell, the remote-connection gate, the `.agents-page-layout` wrapper and three function-component calls — `TreePanel.tree_panel/1`, `DetailPanel.detail_panel/1`, `Modals.modals/1`.

## Template Composition

`agents_live.html.heex` holds only the shell: `EvoDashWeb.Layouts.app` (flash/config/node/sidebar/update/guide/accent), the `RemoteGateComponents.gate_active?/1` branch, the `div.agents-page-layout` wrapper and the three component calls.
`TreePanel` renders `div.agents-left-col`, `DetailPanel` `div.agents-detail-col`, and `Modals` renders the modals as SIBLINGS of `.agents-page-layout`.
Function components add no wrapper, so the DOM is byte-for-byte the pre-split markup: `.agents-page-layout` keeps exactly its two column children.
Partials `use EvoDashWeb, :html` and hold no state, no event handling and no async work — every event still routes through `Inspector`, `SendMessage` and `CommitGraphState`.
`DetailPanel` takes the whole-assigns passthrough; shell-side fallbacks (`assigns[:commit_graph] || []`, `assigns[:commit_graph_loading] == true`, `assigns[:commit_graph_error]`, `assigns[:send_message_text] || ""`) keep a partial-assigns render working.
`agents_live.ex` carries no template helper and no `ContextMeter`/`StreamPanel`/`HistoryEntry`/`ToolCallDisplay` alias.

## Constraints

- Pure, no I/O: `ToolCallDisplay`, `PendingEvents`, `HistoryGate`, `ContextMeter`, `AgentList`, `TreeView`, `OptimisticMessages`, `RuntimeStream`, `StreamLimits`, `StreamPresentation`, `CommitGraph`, `Render` (plus `ThresholdCache.read/3`/`put/4`/`threshold_from_config/1`/`threshold_for_agent/2`/`default_threshold/0`). The model label comes from the shared `EvoDashWeb.ModelLabel`. Deliberate I/O exceptions: `LoadData` and `ThresholdCache.fetch/3` (NodeContext RPCs via the seam runners) — `EvoDash.TaskSupervisor` children only, never the LiveView process.
- No `try/rescue` — defensive extraction and `case`/pattern matching only. The exit-safe boundary is `EvoDash.SafeCall.run/1` inside `Loader.start_page_load/1`, `Loader.spawn_refresh/1`, `CommitGraphState`'s private `spawn_commit_graph_fetch/2`, `Inspector`'s private `spawn_history_fetch/1` and `SendMessage`'s private `send_user_message_safely/3` (an EXIT from a `GenServer.call` timeout / dead target becomes an error VALUE).
- Three config reads only: the threshold (`NodeContext.get_resolved_config/1` via `:agents_config_runner` in `ThresholdCache.fetch/3`), the layout-banner health status (`LoadData.node_config_status/1` — local `EvoGit.Config.config_status()`, remote `NodeContext.get_remote_config_status/1`), and the LiveView-process fallback in `AgentMerge`'s private `safe_compression_threshold/1` (fresh `read/3` hit, else LOCAL inline `EvoGit.Config.resolve([:llm, :compression_threshold_tokens])`, else on a remote cache miss `default_threshold/0`).
- `@config_status` is reloaded ONLY by `LoadData.load/2`; `refresh/2` never re-reads it, so the layout banner keeps its mount-time value until a page load.
- Subscriptions: `"agents"` only (`mount/3`) plus NodeAware's `"tasks"`/`"remote_connections"` — no `"scheduler_config"`, no config topic — so `@config_status`/`@threshold_cache` are not invalidated by a config change; the threshold refreshes on the next load/refresh after the 30 s TTL.
- Reuses `Helpers.tool_call_name/1`, `tool_call_arguments/1`, `tool_call_is_shell?/1` — do not reimplement. `Helpers.tool_call_display/1` is NOT used here; it stays public and test-pinned (do not remove it).
- New user-facing strings use `gettext`; POT/PO entries appear at release-time extraction only — never run `mix gettext.extract`/`merge`/`translate` during development.
- `commit_graph.ex` is ~1 213 lines and legitimately long (~437 lines of `@moduledoc` that IS the pinned output contract); extract further concerns into `commit_graph/` rather than trimming the contract.

## Async Load & Exit-Safety Contract

No render path (mount / `handle_params/3` / `handle_event/3` / `handle_info/2`) blocks on a store, scheduler or cross-node RPC: every such read runs in an `EvoDash.TaskSupervisor` child and reports back as a tagged message.
The initial page load is spawned ONLY on the connected mount (`if connected?(socket), do: Loader.start_page_load(socket), else: socket`); the dead render paints the shell (`@agents_loading` seeds `true`) and spawns nothing.
Every spawned loader calls its loader/runner through `EvoDash.SafeCall.run/1` INSIDE the task body, so a timeout or dead target is an error VALUE and the result message is ALWAYS sent — no task can wedge a loading flag.
Result shapes: `{:agents_data_loaded, node, gen, result}`, `{:agents_refresh_result, seq, node, result}`, `{:commit_graph_loaded, node, seq, result}` (`result` = `{:ok, ...}` or `{:error, reason}`), each stale-guarded on its monotonic counter (`@load_generation` / `@refresh_seq` / `@commit_graph_seq`) AND the viewed node.
Loader seams (`:agents_list_runner`, `:agents_config_runner`, `:agents_commit_graph_runner`) are resolved AT SPAWN TIME inside the task.
Every loading/error assign clears on its result path; a failed page load keeps the last good tree and records `@agents_error`, rendered by `TreePanel` as `#agents-load-error` with Retry (`#agents-load-retry`, `phx-click="retry_agents_load"`).
`retry_agents_load` clears the error and re-runs `Loader.start_page_load/1`; no polling, no auto-retry; `@agents_error` also clears when a load starts, on any success, and on a node switch.

## Left-Panel View Switcher & Commit-History (Temporal) View

The left panel renders the spatial agent tree OR the temporal commit graph, switched by a segmented control (`#left-view-tree` / `#left-view-commits`, `phx-click="switch_left_view"`, `phx-value-view="tree"|"commits"`).
`@left_view` (`:tree | :commits`, default `:tree`) is whitelisted by PATTERN MATCHING the two literals in `CommitGraphState.switch_left_view/2` (no atom conversion).
Switching to `:commits` force-refreshes the graph; switching back to `:tree` never touches the git RPC.
`@left_view` survives a node switch (user preference) and is not in the `handle_params/3` reset branch; the commit-graph DATA is per-node and IS reset there.

### Commit-graph async contract

- Assigns (seeded in `mount/3`; data assigns reset on a node switch): `@commit_graph` (`[repo_view]`), `@commit_graph_raw` (`%{repo_key => %{commits:, refs:, truncated:}}`), `@commit_graph_loaded`, `@commit_graph_loading`, `@commit_graph_error`, `@commit_graph_seq` (never reset), `@commit_graph_fingerprint` (of the agent set the LAST build consumed), `@commit_graph_fetched_at`, `@commit_graph_tick_scheduled` (one-shot guard), `@commit_fold_expanded` (expanded fold-key `MapSet`, per-node) and `@retained_agents`.
- **Fingerprint gate**: a NON-forced call (forced = `force: true` OR graph not yet loaded) compares `CommitGraphRefresh.fingerprint/1` over `commit_graph_agents/1` with `@commit_graph_fingerprint`; an unchanged non-empty value skips BOTH the rebuild and the refetch, a changed/nil one rebuilds from `@commit_graph_raw` + the merged agent set (private `rebuild_commit_graph/3`, so a new child's lane and nodes appear without a fetch) + refetches and stores it. Bypasses: `force: true` (first activation, the tick, a view re-switch), the initial load and an in-flight fetch (`@commit_graph_loading`), whose result re-stores the fingerprint of the agent set it built from, so an identical raw map cannot loop. Selection needs neither rebuild nor refetch (`start_ids`/`end_ids` are built for every agent; markers derive from `selected_id` at render time).
- `commit_graph_agents/1` is the ONE agent set: `@agents` MERGED with `Map.values(@retained_agents)`, de-duplicated by `id` (live wins); it feeds both the grouping and `CommitGraph.build/2`. The TREE still renders `@agents` only.
- `commit_graph_groups/1` groups eligible agents (`repo_root`, `base_commit`, `current_commit`, `task_id` all binaries) by `{repo_key, task_id}` (repo_key = `repo_root`), `live_tips` = de-duplicated `current_commit`s of NON-ended agents only; sorted by `{repo_key, task_id}`; empty groups mark the view loaded with an empty graph.
- `spawn_commit_graph_fetch/2` runs in a `TaskSupervisor` child, calls the runner ONCE per group through `CommitGraphRefresh.fetch_result/3` (limit `CommitGraphRefresh.limit/0` = 100) and sends `{:commit_graph_loaded, node, seq, result}`.
- **PARTIAL SUCCESS**: a reply other than `{:ok, %{commits: list}}` drops only THAT group; the rest still fold, so one failing git RPC never blanks the page (a failed group's repo keeps its lanes/START-END from the agent set). `{:error, reason}` only when EVERY group failed, carrying the LAST failure as `{:commit_graph_repo_failed, {repo_key, task_id}, reply}`.
- `raw_by_repo` is keyed by `repo_key`; groups sharing one are UNIONED via `CommitGraphRefresh.merge_repo_graph/5` (commits de-duped by `:sha`, non-map entries dropped, `refs` unioned per sha, `truncated` OR-unioned into an explicit boolean).
- Runner seam `:agents_commit_graph_runner` (arity 5, default `&EvoDash.NodeContext.list_task_commit_graph/5` — the durable TASK-SCOPED RPC), resolved at spawn time; the spawn wraps `fetch_result/3` in `SafeCall.run/1` (an EXIT → `{:error, :commit_graph_fetch_failed}`), so the view never wedges on a spinner.
- The result is stale-guarded on node AND seq; `{:ok, raw}` builds from `commit_graph_agents/1` (clearing loading/error, re-storing the fingerprint), `{:error, reason}` only clears loading and records the error (the last good graph stays rendered).
- **Throttle**: a refetch within the minimum interval (1000 ms, read AT CALL TIME via `:agents_live_commit_graph_tick_ms` through the same private helper that arms the timer) is skipped; a throttled request arms ONE one-shot `:commit_graph_tick` (never a repeating poll) whose `tick/1` re-attempts with `force: true`, bypassing both the throttle and the fingerprint gate. Trigger points: `AgentMerge.apply_result/2` and a `flush/1` answering `:refresh` are each followed by ONE `maybe_load(socket, [])`; first activation and the tick pass `force: true`.
- **Base de-duplication**: the task-scoped fetch INCLUDES the base commit, and `CommitGraph.base_shas/2` suppresses a synthesized `:base` node when the sha is present — a fetched commit equal to an agent `base_commit` stays a NORMAL `:commit` node and is never duplicated. Do not add a second base node.
- The per-group limit is FLAGGED as data: the core returns `truncated: boolean` per group, `merge_repo_graph/5` OR-unions it and `build/2` surfaces `repo_view.truncated`; the renderer has no "+N more" indicator, so older commits simply stop appearing.

### Retained ended agents (in-session)

The core deletes an agent's ETS rows (and its branch) on recycle, which would remove its lane and START/END markers from the graph. `@retained_agents` (`%{agent_id => agent_map}`) is the in-session remedy: committed agents only, NOT durable (the core persists no per-agent commit attribution).

- A retained entry is the last-known agent map with `ended: true` added (keeping `id, task_local_id, task_id, repo_id, repo_root, depth, status, base_commit, current_commit, usage, ...`).
- `apply_agent_removed/2` captures the removed row there and KEEPS `selected_agent_id` pointing at it — the graph annotation must persist while the panel shows its "Agent not found" state; the rest of the cleanup is unchanged (children orphaned to `parent_id: nil`, tracking sets and `repo_trees` cleaned).
- `apply_result/2` moves ids absent from the fresh list (but present in `@agents`/`@retained_agents`) into `@retained_agents` marked `ended: true`, and DROPS ids that reappear live; nothing is mass-retained on the first apply or after a node switch. `merge_registered_agent/3` deletes the id — a live agent supersedes its copy.
- `CommitGraph.build/2` reports `ended` on the `agents` entry; retention contributes entries and grouping (an all-ended group is still fetched with empty `live_tips`, recovering the task from its durable refs) but never tips.

### Commit-Graph View Model (`CommitGraph` + `commit_graph/`)

`build/2` (collapsed — `build/3` with an empty expansion set) and `build/3` (3rd arg = expanded fold keys, a `MapSet` or list of binaries; any other shape = collapsed) return one `repo_view` per repo group, sorted by `{repo_name, repo_dom_id}`, from `%{repo_key => %{commits:, refs:, truncated:}}`. `fold_keys/2` lists every fold key (expand-all driver); `grouping_key/1` (`repo_root || repo_id`) and `repo_display_name/1` ("Primary Repo" / path basename / "Repo: <repo_id>" / "Unknown Repo") are shared with `TreeView`. Total: defensive `Map.get/2`, non-map input degrades to empty nodes/edges/agents, never raises, no try/rescue.

- **Nodes** — every fetched commit de-duplicated by sha, PLUS one `kind: :base` node per agent `base_commit` absent from the fetch, PLUS one `kind: :noop` stub per child with an empty progress path (`current_commit` nil, equal to its base, or absent from the fetch). Keys `%{sha, short_sha, message, author_name, date, refs, row, column, depth, kind, owner_id, start_ids, end_ids}` (`kind: :commit | :base | :noop | :gap`); `row` is the unique top→bottom position, `column`/`depth` the owner's lane/depth (0 unowned), `owner_id` nil when unowned, `start_ids`/`end_ids` the agents forking from / tipping at the sha.
- **Rows** — each node carries a cycle-safe topological LAYER over its PRESENT parents (`L = 0` with none, else `max(L(parent)) + 1`; memoized DFS with a `visiting` set so a malformed cycle terminates; base nodes join as parentless pseudo commits). Rows sort ascending `{L, date_unix, sha}` (missing date → 0): parents strictly above children, parallel agents interleaved by date.
- **Lanes (one per agent)** — a DFS / SUBTREE-CONTIGUOUS pre-order from the ROOTS (nil `parent_id`, or one matching no agent of the group), children in stable `{task_local_id, agent_id}` order; a cycle stops the walk and unreachable agents are appended as fallback roots. `depth` is not an ordering key. Lane = the index, SHIFTED RIGHT BY 1 when the repo has ≥1 unowned node, so lane 0 is the NEUTRAL lane.
- **Ownership / progress path** — a first-parent walk from `current_commit` backwards that stops WITHOUT collecting at a non-binary sha, `base_commit`, an already-seen sha or a sha absent from the fetch (NEWEST → OLDEST). The deepest path agent wins (ties: smallest agent-order index); a commit on NO path inherits the owner of the commit it is the FIRST parent of (DESCENDING layer order), else UNOWNED; a base node belongs to the agent with the smallest `{depth, index}` forked from it; a stub belongs to its child. A repo without agents has no nodes, edges or agents.
- **Edges** — `%{from_sha, to_sha, from_column, from_row, to_column, to_row, kind, owner_id}`; `to_sha` is never nil. Commit edges: `:parent` for the FIRST present parent, `:merge` for every other (owner = the child node's), identical pairs de-duplicated, DROPPED when the unordered sha pair matches an agent-level edge. Agent-level edges (child C, parent P resolved in the group): `:spawn` dashed from `C.base_commit` to C's OLDEST progress-path commit (or its stub); `:merge_back` dashed from C's tip (or stub) into P's lane, landing on the TOPMOST P-owned node strictly BELOW the source, else the NEAREST P-owned node ABOVE, else DROPPED — NEVER a mid-air stub, never `to_sha: nil`, never on the source's own row. Sorting: commit edges by `{from_sha, to_sha}`, agent edges by `{kind, owner_key, from_sha, to_sha}`; `edges` = commit ++ agent.
- **`agents`** — one entry per agent in lane order: `%{agent_id, task_local_id, status, depth, lane, parent_id (raw), color, start_sha, end_sha, ended}` (`start_sha`/`end_sha` = `base_commit`/`current_commit`).
- **Folding — COLLAPSED BY DEFAULT** — `Fold` keeps only structural ANCHORS visible: the lane owner's START and END, any node in any `start_ids`/`end_ids`, every node carrying `refs`, every `:base`/`:noop` stub and every unowned neutral-lane node. A maximal run of hidden interior commits on ONE lane folds only at length ≥ 2 into EXACTLY ONE `kind: :gap` node (`sha: "gap-" <> fold_key`, empty `short_sha`/`message`/`author_name`/`date`/`refs`/`start_ids`/`end_ids`, the run owner's `column`/`depth`, plus `fold_key`/`hidden_count`/`expanded`) present in BOTH states; it takes the run head's row slot, so visible rows re-index `0..n-1`. A lone hidden commit stays a real `:commit` row, never hidden and never aliased. `fold_key = "<agent_key>|<above_key>|<below_key>"` with the nearest VISIBLE same-lane anchor shas and `"^"`/`"$"` sentinels, stable while the commit set is unchanged. ONE alias map (hidden sha → its gap sha) covers commit AND agent-level edges; an edge whose endpoints alias to the same node is dropped. `repo_view.fold_count` counts runs (expanded or not); an unknown/stale key is ignored. A fold toggle rebuilds the pure model IN-PROCESS from `@commit_graph_raw` — no git RPC, no fetch spawn, no throttle/fingerprint consultation.
- **Depth hue (verbatim)** — `color = EvoDashWeb.ThemeColor.hsl_to_hex(hue, 70, 54)` with `hue = Integer.mod(round(depth * 137.508) + 265, 360)`; depth 0 = `#7c38dc`; non-integer/nil/negative depth → 0. Palettes and theme tokens are the renderer's concern.
- **Output shape** — `%{repo_key, repo_dom_id, repo_name, node_count, edge_count, row_count, column_count, truncated, fold_count, nodes, edges, agents}` with `row_count == node_count`; `nodes` sort by `row`; `repo_dom_id` is the stable DOM id and the module emits no further render/DOM concern.

## Inspector RuntimeStream Reducer

`RuntimeStream` is a pure reducer — `new/2`, `seed/3`, `apply_batch/4`, `active?/1`, `replace_activity/2`, `current_call_id/1`, `checkpoint_transition?/2` — independent of the Assistant's `Delta` reducer.
Snapshots and ordered activity events carry `%{phase: :idle | :llm_waiting | :llm | :llm_complete | :retry_wait | :tools | :compressing | :preparing, current_call: nil | %{id:, turn:, attempt:, text:, thinking:}}`; `:compressing`/`:preparing` are admitted NON-call phases, only `:llm_complete`/`:tools` prove generation completion, and only `:llm` is an active call phase.

- An activity event replaces the WHOLE current-call projection including accumulated text/thinking; chunks append only to an existing call. Core captures content without watchers, so a mid-call snapshot with both text and thinking as explicit binaries proves complete capture — no invented coverage flags or message-start events.
- Phase lives in `state.activity`, bounded content in `state.projections`, retaining ONLY the current call: `%{identity: %{id: id}, turn:, attempt:, message_index:, response:, thinking:, tool_calls:, complete:, generation_complete:, capture_coverage:, chunks_seen:, omitted_response_bytes:, omitted_thinking_bytes:, omitted_tools:}`. `message_index` is a local monotonic live-call DOM ordinal, not a checkpoint index (neither it nor `turn` identifies a checkpoint bubble).
- Same-id replacement keeps tool descriptors and the DOM ordinal; a fresh attempt id replaces all content/tools and advances the ordinal even after retirement. `current_call: nil` retires every excerpt and tool (aborted retries and checkpointed calls included), and later chunks, accounting, yield or tool announcements cannot resurrect them.
- Generation completion follows only `:llm_complete`/`:tools` — never turn accounting, yield, retry, failure or lifecycle finish. Yield sets `:awaiting_input` without treating its checkpoint text as a live replacement; finish freezes later events without asserting success; `active?/1` means only a nonterminal running/cancelling lifecycle.
- `seed/3` keeps agent/node ownership and raw checkpoint messages, rejects a foreign agent, and prefers an explicit nonnegative seq over the embedded seq over zero; a reseed keeps the DOM ordinal and same-call tool descriptors but REPLACES response/thinking from the snapshot prefix, and missing/malformed/empty activity (or explicit `current_call: nil`) clears stale projections, response, thinking and tools while preserving the ordinal.
- `apply_batch/4` rejects stale/invalid seq, foreign agent and post-finish events (unknown events are inert; an accepted newer batch still advances the watermark); `checkpoint_transition?/2` scans every ordered activity replacement for retirement/replacement of an existing call, even when a later event starts another call in the same batch.
- Admission and node/watch-generation guards belong to StreamWatch; the obsolete in-flight/message-start/flattened-activity/caller-owned-coverage protocols are not consumed and no checkpoint identity reader or content/turn/index suppression API exists.
- `StreamLimits` owns the budgets (12 projections, 48_000 bytes per response AND thinking, 20 tools first kept, 1_024 bytes per tool name): UTF-8-safe copied prefixes, no unbounded concatenation before a bounded append, omission counted rather than inserted after a missing boundary, authoritative replacement recomputing missing bytes, and tool announcements never imply execution. Checkpoint messages and protocol identities are never truncated.

## Inspector StreamWatch Lifecycle

`StreamWatch.attach(socket, agent_id)` subscribes in the connected LiveView process and asynchronously registers that same pid through one serialized, consumer-monitored worker.
Forward `{:inspector_stream_ready, node, token, agent_id, result}` to `ready/5` and `{:agent_delta, agent_id, seq, events}` to `push/4`, then render `assigns.inspector_stream.state` as the `RuntimeStream` projection.
`active?/2` includes snapshot-pending and reconciling watches and excludes errors, so the page suppresses independent whole-history reads while watched; the rendered checkpoint source is exclusively `inspector_stream.state.messages`, seeded atomically with live activity from `inspector_stream.snapshot`.

- `reconcile/1` coalesces explicit refreshes while a request is outstanding and keeps the old coherent checkpoint/live pair while buffering newer deltas; a batch retiring or replacing the current call starts reconciliation BEFORE applying anything in it. Forward `{:inspector_stream_reconciled, node, token, agent_id, request, result}` to `reconciled/6`, guarded on viewed node, watch token, agent id and the outstanding request; reconciliation reuses the SAME registration runner and serial worker without unregistering, preserving the live subscription.
- An admitted snapshot replaces checkpoint messages and activity together; buffered batches replay only above its authoritative sequence, and replay crossing another ownership boundary freezes that batch and starts another coalesced snapshot request instead of rendering an inconsistent pair.
- `snapshot_request`, `reconciling` and `required_seq` distinguish the outstanding request and its minimum watermark from the rendered `seq`. A snapshot older than its triggering boundary, an RPC failure or a buffer overflow FAILS the watch visibly (keeping the last coherent pair) and requires explicit reattachment — there are NO automatic error retries.
- `detach/1` clears render state and the consumer-local subscription immediately, with asynchronous serialized unregister on selection, node or lifecycle teardown; `inspector_stream_token`, `inspector_stream_worker` and `inspector_stream_worker_monitor` survive page resets (tokens stay monotonic; one worker orders rapid A→B→A registrations). Forward worker `{:DOWN, ref, :process, pid, reason}` to `down/4` after other page-owned monitors: a matching death fails the watch, unsubscribes and allows a retry; unrelated monitors are inert.
- Pending remote contexts cannot attach locally; readiness and push application require the current viewed node; negative watermarks are rejected; a snapshot naming another agent fails the watch.
- Buffering admits up to 128 ordered batches or 1 MiB; duplicate/stale batches consume no capacity; overflow or supervisor-start failure produces an explicit watch error rather than silent loss or stuck loading.
- Seams `:agents_watch_runner` / `:agents_unwatch_runner` (both `(node, agent_id, liveview_pid)`) default to the `NodeContext` watcher functions; the worker does RPC through `SafeCall`, cleans up after consumer death and never polls. Delta messages have no publisher-node stamp.
- `closed/4` admits the direct `{:agent_stream_closed, agent_id, snapshot, seq}` handoff atomically, including after a finished delta, summary removal or a failed async snapshot request. Admission requires a `Snapshot` with matching agent, `phase: :done`, embedded sequence, selected-agent/current-token/target-id/viewed-node ownership, and a sequence at least as new as the rendered, required and buffered watermarks; the handoff replaces checkpoint messages and activity together, clears buffers/errors, unsubscribes deltas and seals the pair against late ready/reconciled failures, worker death and deltas, without replaying older buffered events. `seed/3` treats `:done` as terminal and keeps the snapshot's terminal status.
- `owns?/2` includes selected pending, failed and terminal watches; `terminal?/2` means an admitted handoff and `active?/2` excludes that sealed watch. A same-target attach preserves a sealed watch; only explicit selection/node/lifecycle teardown may detach it. The parent must retain the selected watch across summary removal, forward the handoff to `closed/4`, project its checkpoint in the same callback and use the retained ended row to keep the detail panel visible. Retained terminal history is page-local, not durable.

## Inspector Stream Presentation

`StreamPresentation.build/1` applies a second render cap of 12_000 graphemes per response/thinking part and at most 20 tools without mutating the reducer or checkpoint history; the max-message budget stays 12 (`StreamLimits.max_projections/0`), though production state holds only the current call. Grapheme omission fields describe render-stage loss; byte omission fields sum reducer and render loss without counting full replacements twice.
`activity/1` translates core phases for display: `:tools`→`:tool`, `:llm_waiting`→`:waiting`, every other core phase identity, anything else → `:unknown`.
The label text exists in exactly ONE place, `StreamPanel`'s `#inspector-activity`: `:llm` "Generating response", `:tool` "Executing tools", `:idle` "Idle", `:waiting` "Waiting for model capacity", `:llm_complete` "Response generated", `:retry_wait` "Waiting to retry", `:compressing` "Compressing context", `:preparing` "Preparing next turn", anything else "Activity unavailable".

`StreamPanel` gates the `#inspector-thinking` skeleton, cursor pulse and thinking-only shimmer on `message.active` AND an error-free watch, so completed calls and failed watches retaining `:llm` excerpts stay static under reduced motion; the protocol has no thinking-vs-response subphase, so active LLM generation is the most precise animation predicate.
The detail panel never calls `OptimisticMessages.merge/2` directly: `Inspector.merged_history(agent, page.optimistic_messages)` is the ONE entry source, returning `agent.history` verbatim when that agent has no optimistic entries.

## Inspector Streaming Integration & Protocol Boundaries

The parent forwards ready/reconciled/delta messages through StreamWatch and projects the admitted raw messages into checkpoint rows in the SAME callback as the live-state update; support owns reconciliation requests, snapshot admission and bounded replay, the parent owns checkpoint-row rendering without speculative response/thinking suppression.
Snapshot-pending, reconciling and failed watches own their checkpoint rows exclusively; independent history reads and late results cannot overwrite a watched pair, including a failed watch's last coherent one. Watched-history Retry and full-message refresh use `StreamWatch.reconcile/1`; unwatchable agents keep the separately scoped independent history fallback.
The history list is TWO nested elements: the OUTER `#agent-history-scroll-<id>` (`agent-history-scroll overflow-y-auto bg-base-200/50 border border-base-300 rounded-lg`, `phx-hook="AgentHistoryAutoScroll"`) is the ONE bounded scroller and a DIRECT child of `.agent-detail-history` (CSS pins `.agent-detail-history > .agent-history-scroll { flex: 1 1 0 }`); the INNER `#agent-history-<id>` keeps `phx-hook="InspectorMessages"`, `data-inspector-scope` (node/target/selection/watch/snapshot) and the stable `data-inspector-message` markers, so every DOM id is unchanged.
The inner element carries `divide-y divide-base-300`, preserving the pinned `.agent-history-scroll > .divide-y > div` entrance selector (`InspectorMessages` animates only newly keyed rows, respects reduced motion, never scrolls — scrolling belongs to `AgentHistoryAutoScroll` alone, one hook per element). `#inspector-history-error` is the inner element's FIRST child and the `StreamPanel` tail row its last.

Core contracts: `apps/evo_git/lib/evo_git/agent/stream/CONTEXT.md` + `.../agent/session/CONTEXT.md` — snapshots atomically capture checkpoint `messages`, nested `activity` and an authoritative `seq`; ordered `{:activity, projection}` events replace the projection while text/thinking events append to its current call; a completed call stays available until atomic checkpoint retirement; capture continues without watchers and watch/snapshot flush pending events before returning the sequence.
The inspector adopts `activity.current_call` from snapshots/replacements and appends only strictly newer chunks through StreamWatch admission; fresh call ids separate retry attempts and nil retirement clears obsolete excerpts without touching raw history.

Protocol boundaries:

- Tool-result/yield/finish events alone cannot replace the automatic retirement/replacement snapshot trigger; deltas expose text/thinking chunks and tool id/name/status but not tool arguments, result bodies or full history-message changes.
- StreamWatch fixtures must include `snapshot_request: 0`, `reconciling: false`, `required_seq: 0`, real snapshot agent ids, and account for duplicate/stale batches not consuming capacity.
- Activity fixtures use real nested `current_call` projections; synthetic `in_flight`, flattened activity identities, `message_start`, bare chunks without a current call and the removed `message_identity/1` API are unsupported.
- All eight phases have truthful labels; successful empty-thinking notices require complete binary capture plus `:llm_complete`/`:tools` (never `:compressing`/`:preparing`). No checkpoint-message call identity or coverage watermark exists, so checkpoint suppression and reconciliation by guessed turn/content are unsupported.
- This reducer is not the Assistant's bubble-oriented `Delta` reducer (`../home_live/CONTEXT.md`); neither is a lossless history model.

## Agent Event Contract (push-based, node-identity, coalesced flush)

The page is FULLY push-based — NO periodic poll. The `:evo_git` emitters broadcast exactly four shapes on `"agents"`, each carrying the publisher's BEAM node atom.
Every event is node-filtered FIRST via `NodeAware.event_from_current_node?(socket.assigns, event_node)` (viewed node = `assigns[:current_node]`); foreign events are dropped BEFORE buffering, so they never arm a flush or leak into the tree.
The three incremental events are COALESCED: each `handle_info` clause only hands the raw event to `AgentMerge.buffer_event/2`, which appends it to `:pending_agent_events` (`PendingEvents.append/2`, newest-first) and arms ONE trailing-edge timer.
The flush window is read AT CALL TIME at `maybe_schedule_agent_flush/1` via the `:agents_live_flush_ms` seam (production default `PendingEvents.flush_ms/0` = 300 ms); `PendingEvents` stays pure, the message stays `:flush_agent_events`, and only the FIRST event of a window arms the timer (`:agent_flush_scheduled`).
`{:agents_updated, node}` → `buffer_refresh/1` sets the coalesced `:pending_agents_refresh` boolean and arms the same timer — never one refresh per event.
`handle_info(:flush_agent_events, socket)` calls `AgentMerge.flush/1`, which drains in ARRIVAL order (`PendingEvents.drain/1`) and answers `{socket, after_flush}`: `:refresh` → ONE `Loader.spawn_refresh/1`, `:refetch` → ONE `Inspector.refetch_selected_history/1`, `:none` → nothing — exactly ONE render/diff per burst, so user `phx-click`/`phx-submit` events cannot starve.
Buffer, `:agent_flush_scheduled` and `:pending_agents_refresh` are seeded in `mount/3` and RESET on the node-change branch; a timer still in flight after a switch is harmless (empty buffer).
The fallback refresh is coalesced: an incomplete `:agent_registered` summary, an `:agent_updated` for an unknown id and `{:agents_updated, node}` all set the flag, and the flush spawns AT MOST ONE `Loader.spawn_refresh/1` (seq-guarded via `@refresh_seq`). All heavy loads stay in `TaskSupervisor` children — never in `handle_info`.

- `{:agents_updated, node}` — throttled bulk-change signal → one `spawn_refresh` per window; foreign → ignored.
- `{:agent_registered, id, summary, node}` — full `RemoteAPI.list_agents/0` summary shape (`id, task_local_id, repo_id, repo_root, task_id, task_number, status, depth, parent_id, worktree, retries, agent_module, model_id, objective, context_path, current_commit, base_commit, usage, total_tokens, compression_count, compression_threshold, context_window, message_count`). Merged IN-MEMORY for local AND remote through ONE shared path (`merge_registered_agent/3` → `build_registered_agent/2`): the `LoadData` field mapping (defaults for absent fields, `usage` normalized to `%Usage{}`), derived fields recomputed exactly as the load path (children/`has_children` from `parent_id`, effective `compression_threshold` via `ThresholdCache.threshold_for_agent/2`, `compression_pct` from `total_tokens` + that threshold, `context_window` via `ContextMeter.context_window_from/1`, `model_label` via `EvoDashWeb.ModelLabel`), inserted at the sorted `{depth, id}` position, parent's children refreshed, `id_to_display`/`previous_agent_ids`/`new_agent_ids`/`repo_trees` updated. A duplicate id (race with the fallback refresh) is a no-op; a summary missing `status`/`depth`/`parent_id` sets the refresh flag.
- `{:agent_updated, id, changed_fields, node}` — `changed_fields` NEVER contains `:context`; merged in-memory for local and remote. Special fields: `context_node` → `context_path`, `phylo_node` → `current_commit`, nil `usage` → zero, `compression_pct` recomputed on `total_tokens` OR `compression_threshold` (a nil/non-positive threshold delta keeps the row's previous denominator), `context_window` is NOT part of the delta contract (an omitted key keeps the row's value; a nil/non-positive value restores the previous known window — never reset to 200_000), children recalculated on `parent_id`, status tracking into `previous_statuses`/`changed_status_ids`, `id_to_display` on `task_local_id`, `repo_trees` rebuilt on `context_node`/`repo_root`, queue anchoring on `:pending_user_messages` (a delta without that key leaves the snapshot untouched). A missing row (race) sets the refresh flag.
- `{:agent_removed, id, node}` — the row is dropped in-memory (children orphaned to `parent_id: nil`, parent's children refreshed, tracking sets/selection/`repo_trees` cleaned) and captured into `@retained_agents`, for BOTH local and remote; foreign → ignored.

## Notes for Agents — coalesced flush (one index, one pass)

`AgentMerge.flush/1` answers `{socket, after_flush}` and never spawns a task or touches the commit graph — the LiveView performs that ONE follow-up.
A flush builds ONE `%{id => agent}` index and ONE `%{id => position}` index for the whole burst (`AgentList.by_id/1` / `positions/1`), so an update is a map lookup plus a map put instead of `Enum.find_index/2` + `List.replace_at/2`; accumulated merges fold back in ONE final `Enum.map` pass, so k events over n agents cost O(k + n).
Arrival order is part of the contract: every merge reads the CURRENT row (already merged earlier in the same burst) as its base; a structural event (`:agent_registered`/`:agent_removed`) first folds pending merges into the list, then mutates it.
Preserved semantics: fallback refresh for an unknown agent or incomplete summary, `Inspector.preserve_terminal/2` retained-terminal settlement, threshold/context-window carry-over (`restore_threshold/2`), `compression_pct` gating, children recalculation on `:parent_id`, ONE `repo_trees` rebuild per flush and at most one selected-history refetch per burst.

- **Layout (both sites)**: the label is INLINE beside the rows — a `flex items-start gap-2` row with a `shrink-0` label span and a `min-w-0 flex-1` rows container, so the label and the first key sit on the SAME line, top-aligned. Markup accents it in both sites (inline `bg-info/10` chip + `text-info` label + `hero-clock`; modal box `bg-info/10 border-l-2 border-info/40`).

## Notes for Agents — Agents page layout & legend tooltip

At `xl+` the page uses a fixed-viewport layout: `.agents-page-layout` (grid, `overflow: hidden`), `.agents-left-col` (column flex, `overflow: hidden`), `.agents-tree-panel` (card, `flex: 1 1 0`), tree content scrolling inside `.agents-tree-panel .card-body`, and `.agents-legend` as a SIBLING of card-body at the panel bottom. Below `xl` it is normal flow under `#main-scroll` inside `#app-layout`.
**Legend tooltips use the `LegendTooltip` JS hook (`assets/js/hooks/legend_tooltip.js`), NOT DaisyUI `.tooltip`**: DaisyUI's absolutely positioned, horizontally centered pseudo-element makes the long `data-tip` texts (max-width 20rem) on the right-aligned chips overflow the page-level overflow containers (`#app-layout`, `#main-scroll`, `.agents-page-layout`, `.agents-left-col`), and CSS-only anchoring cannot fix it (the panel is ~480 px wide at xl).
The hook renders the tip as a `position: fixed` element appended to `document.body` — mandatory because `.agents-page-layout`'s `animate-fade-in-up` uses `animation-fill-mode: both`, so `transform: translateY(0)` PERSISTS and would trap even fixed descendants inside its `overflow: hidden`.
Chips carry `data-tip` (gettext) + `phx-hook="LegendTooltip"` + unique ids (LiveView requires `id` for a hook); the `tooltip` class was removed so DaisyUI's clipped tip does not double-render. The "Send Message" button tooltip (`tooltip` class, short text near the card edge) fits and stays — do not convert it.

## Notes for Agents — Context tile (context-usage meter)

The Context tile is a context-usage METER, not a threshold-relative `progress`: the bar's full width is the model's CONTEXT WINDOW, the fill is current context size (`:total_tokens`) and a vertical TICK marks the compression THRESHOLD.
It is a full-width sunken tile (`bg-base-200/50 border border-base-300 rounded-lg p-2.5`) directly below the 2-column Cached Tokens / Cache Hit Rate grid, inside the same bordered usage section; all geometry and numeric labels come from ONE `<% meter = ContextMeter.build(agent) %>` block in `agents_live/detail_panel.ex`, user-facing prose is gettext in the markup, and there is no phx-hook or JS.
`#agent-context-meter` (`relative mt-2`) data-attribute contract (render-test pinned): `data-context-fill-pct` (one-decimal fill % of the window), `data-context-tick-pct` (one-decimal threshold %, OMITTED when unknown), `data-context-zone` (`success`/`warning`/`error`), `data-context-window-tokens`, `data-context-threshold-tokens` (omitted when unknown), `data-context-current-tokens` (plain integers).
Every percentage is `Float.round/2` to EXACTLY one decimal rendered by `:erlang.float_to_binary(_, decimals: 1)` (clamped 0..100), with numeric and label forms derived from the SAME rounded float so CSS and `data-*` cannot disagree; the fill div carries `style="width: <fill_label>%"` + `meter.fill_class`.
Zones are integer math on current vs threshold: `< 80%` → `:success`, `< 100%` → `:warning`, `>= 100%` → `:error`, unknown threshold → `:success`; `fill_class` → `bg-success`/`bg-warning`/`bg-error`, `tick_class` → `bg-base-content`.
The tick is a `w-0.5` bar centered with `-translate-x-1/2` at `style="left: <tick_label>%"` carrying a rotated-square cap and `title={gettext("Compression triggers at %{tokens} tokens", tokens: format_number(meter.threshold_tokens))}`; the header shows `current / threshold` (current only when the threshold is unknown) and the caption `gettext("Compression at %{tokens}", …)` or "Compression threshold unknown" plus `gettext("Compressions")` and the legacy `count (pct%)` label.
The unknown-threshold render is reachable only for an agent map with NO `:compression_threshold` key; the real update path always restores a known threshold (`ThresholdCache.threshold_for_agent/2` resolves a positive integer, 180_000 last resort).

## Notes for Agents — `whitespace-pre-wrap` content must sit flush against its tags

HEEx newline + indentation between tags becomes a literal text node that `whitespace-pre-wrap` preserves as leading blank lines/indentation inside the rendered block. Always put the interpolated content on the SAME line as the opening tag (`<pre class="whitespace-pre-wrap break-words"><%= text %></pre>`) or use `<%= ... %>` inside a single-line element.
The page's pre-wrap site is the full-objective modal's single-line `<pre …>…</pre>`; multi-line markup around pre-wrap content silently adds whitespace.
