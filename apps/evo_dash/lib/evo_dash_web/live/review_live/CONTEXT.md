# ReviewLive — Review Page

## Intent

`EvoDashWeb.ReviewLive` (`review_live.ex`, `GET /review/:task_id`) — GitHub-style code review page: PR title, agent summary, commit list, client-side highlighted diffs (highlight.js), merge/reject/resume actions, optional GitHub PR creation, and Extract Skills (starts an `:extract_skills` task via `TaskRegistry` that spawns a `SkillExtractor` agent to distill PR knowledge into `.agents/skills/` files). **Multi-repo review**: tasks with writable foreign repos render a per-repo tab bar (`@review_repos`, primary first); merge/reject broadcast across ALL review repos; single-repo (legacy) tasks render pixel-identical to before. All page data loads ASYNC (off-process); per-file diffs are LAZY (per-event).

## Routing Table

None — leaf directory (`load_data.ex`, `merge_check.ex`).

## API Surface

| Module | Purpose |
|--------|---------|
| `EvoDashWeb.ReviewLive.LoadData` (`load_data.ex`) | Async review-data load, runs in `EvoDash.TaskSupervisor` children. `load/3` (`node, task_id, opts` with `live_action:`/`inspect_commit_sha:` opts) → `{:review_data_loaded, task_id, node, generation, result}` with `{:ok, assigns_map} \| {:error, reason}` (error strings pre-gettext-wrapped: "Task not found. It may have been deleted." / "Failed to load review data."). `build_assigns/3` (`load_data.ex:77`) builds the `@review_repos` list (one entry per reviewable repo, primary first) plus `active_repo_id`/`merge_outcomes`; `commit_inspection/3` (`:363`, the `:commit` route) is PRIMARY-repo-scoped. `repo_available?/2` and `branch_exists_on_node?/3` take `node` (not a socket). |
| `EvoDashWeb.ReviewLive.MergeCheck` (`merge_check.ex`) | Async non-mutating merge-conflict dry-run (`check_merge/4` → `{:ok, :clean} \| {:ok, {:conflict, files}} \| {:error, reason}}`), started AFTER the load result. **Multi-repo aware**: `maybe_start/1` (`merge_check.ex:48`) spawns ONE `check_merge/4` per review repo under the same gates the merge form renders with (branch exists, `merge_targets != []`, target binary, `repo_available?/2`), each tagged with its `repo_id`; results arrive as 6-tuples `{:merge_check_result, task_id, node, repo_id, target, result}`. Also hosts `repo_available?/2` (defdelegated from ReviewLive) and `handle_auto_resolve/1` (PRIMARY-scoped). |

## Multi-repo review (writable foreign repos)

The core writes writable-foreign-repo results into the task result's top-level `repos` map (`%{repo_id => %{"commit_sha" => sha, "branch_name" => branch \| nil}}`, STRING keys — the top-level key survives a Store/Codec round trip); the review page turns each such repo into a review entry. Detail lives in the bullets below; the flat single-repo assigns are still what the template and action components read, projected from the ACTIVE repo.

- **Repo list construction** (`load_data.ex` `build_assigns/3` → `build_review_repos/7` `:184`): `@review_repos` is a list of per-repo maps `%{repo_id:, repo_path:, branch_name:, commit_sha:, base_sha: (String.t()\|nil), branch_exists:, review_data: (map\|nil), commits:, merge_targets:, default_merge_target:, merge_status:}`, **primary FIRST** (`repo_id "primary"`, from `task.opts[:path]` + result top-level branch/commit). Writable foreign repos come from `task.opts[:foreign_repos]` normalized via `EvoGit.Core.ForeignRepo.normalize/1` (accepts `%EvoGit.Core.ForeignRepo{}` structs AND string-keyed maps after the Store round trip; drops nil/unparseable). **Only repos present in `repos` with a non-nil branch_name get a review entry** — read-only repos are absent from `repos`; writable-with-no-commits has nil branch_name → absent. **Legacy tasks (no `repos` key) → exactly one primary entry → today's single-repo behavior**. Other assigns: `active_repo_id` (default `"primary"`), `merge_outcomes` (default `[]`, reset to `[]` on every successful review-data load — `review_live.ex:968`). `set_review_metadata/4` stays primary-scoped (fire-and-forget; foreign SHAs already live in the persisted `repos` map). The `:commit` route (`commit_inspection/3`) stays PRIMARY-repo-scoped.
- **Per-repo TABS** (`review_live.ex` render): `<EvoDashWeb.ReviewComponents.repo_tabs repos=... active_repo_id=.../>` renders ONLY when `length(@review_repos) > 1` — a single-repo page is pixel-identical to before. The flat assigns (repo_path/branch_name/commit_sha/base_sha/branch_exists/review_data/commits/merge_targets/default_merge_target/merge_status) are projected from the ACTIVE repo by the private `project_active_repo/1` (`review_live.ex:1239`; NO-OP on the `:commit` route). `switch_repo` (`:346`) whitelist-validates `repo_id` against `@review_repos` ids (never `String.to_atom` on client input). `resume`/`create_pr`/`confirm_extract_skills`/`auto_resolve` resolve the `"primary"` entry explicitly — PRIMARY-scoped (documented limitation).
- **Lazy diffs per repo**: on the SHOW route `selected_file`/`expanded_files`/`file_context_levels` are repo-keyed maps (`%{repo_id => %{path => ...}}` for expanded/levels, `%{repo_id => path}` for selected); the `:files_changed` tab reads the ACTIVE repo's submap via inline `Map.get` (`review_live.ex:172-174`); `update_file_diff_in_socket/4` (`:1165`) writes the diff into the ACTIVE repo's `review_repos` entry + updates its submaps, then re-projects. The `:commit` route keeps legacy flat path-keyed state. `scroll_to_file` push_event preserved (`:401`).
- **Merge broadcast** (`handle_event("merge")`, `:491`): submits for ALL repos in `@review_repos`, each with its OWN target — the submitting repo comes from the merge form's hidden `repo_id` input (fallback `@active_repo_id`, then `"primary"`; whitelist-validated), its target validated against ITS `merge_targets` with fallback to its `default_merge_target`; every other repo merges into its own `default_merge_target` (nil → `merge_branch/3` default-resolving path). Test seam `:review_merge_runner` (app-env, resolved AT CALL TIME — mirrors `:merge_check_runner`). ALL `{:ok,_}` → `set_review_status(:merged)` + success flash + `push_navigate` to /projects (preserving `?node=`). ANY conflict/error → `@merge_outcomes` (`%{repo_id:, status: :merged|:conflict|:error, detail:, target:}` for ALL repos — partial-success visibility; conflict detail = `truncate_string(details, 200)`, error detail = `inspect(reason)`) + summary error flash, STAYS on page — never partially applied silently.
- **Reject broadcast symmetric** (`handle_event("reject")`, `:659`): loops `@review_repos` via `EvoDash.NodeContext.reject_branch/3` per repo (test seam `:review_reject_runner`, call-time); ALL `:ok` → `set_review_status(:rejected)` + info flash + navigate; partial → `@merge_outcomes` (`%{repo_id:, status: :rejected|:error, detail:}` — no target key) + error flash, stays.
- **MergeCheck per-repo** (`merge_check.ex`): `maybe_start/1` (`:48`) iterates `@review_repos` under the existing gates — one async dry-run per repo, each tagged with its `repo_id`; the result message is now a **6-tuple** `{:merge_check_result, task_id, node, repo_id, target, result}` (`merge_check.ex:243`). `handle_result/6` (`:151`) stale-guards on task_id/node + repo-entry presence + target-match (`stale_repo_target?/3`, `:276`); `handle_target_change/2` (`:59`) reads `repo_id` from params (blank → `"primary"`) and re-runs THAT repo's check; `handle_auto_resolve/1` (`:88`) is PRIMARY-scoped (documented limitation: if a FOREIGN repo is the conflicted one, primary-scoped auto-resolve won't resolve it — the conflict-outcome panel tells the user which repo conflicted). `:merge_check_runner` seam + justified try/rescue (`:232-241`) unchanged.

## Async load contract

- `handle_params/3` dedup guard `tasks_loaded_for == {current_node, live_action, params["commit_sha"]}` (the tuple includes the route so the `:commit` push_patch re-loads) → private `start_async_load/2` (`review_live.ex:1031`) sets `@loading` and spawns `Task.Supervisor.start_child(EvoDash.TaskSupervisor, ...)`.
- Load sequence: `get_task/2` → per repo (primary first): `list_branches/2` + `default_merge_target/2` → `branch_exists?/3` (only when branch_name + repo available) → `load_review_metadata/3` (branch path) or `load_review_metadata_from_shas/4` (post-merge/reject path, per-repo `base_sha`; skipped when nil) → `list_commits/3` or `list_commits_from_shas/4`; plus a fire-and-forget `set_review_metadata/4` write (primary-scoped) when SHAs were just persisted. The `:commit` route (`/review/:id/commit/:sha`) additionally runs primary-scoped commit inspection (header lookup from the just-loaded commits with `%EvoGit.Review.CommitInfo{}` fallback + `NodeContext.load_commit_files` degrade-to-nil) and adds `inspect_commit_sha`/`commit_header`/`commit_data` — the whole navigation load stays off the LiveView process.
- Result map: ~30 template assigns (`loading: false`, `error: nil`, title/task_type/branch_name/commit_sha/base_sha/agent_summary/review_status/branch_exists/can_resume/is_no_changes/has_pr/pr_url/review_data/repo_path/objective/commits/archive_metadata/task_usage/agent_count/task_status/model_id/started_at/finished_at/merge_targets/default_merge_target/merge_status: nil` + `review_repos: [entry per repo]`, `active_repo_id: "primary"`, `merge_outcomes: []` + resets `expanded_files: %{}`/`file_context_levels: %{}`/`selected_file: nil`).
- **Stale-guard** (`review_live.ex:949-957`): drop unless `task_id == @task_id` and `node == @current_node` and `generation >= @load_generation` (monotonic, seeded 0 in mount, incremented per `start_async_load`). On `{:ok, assigns_map}` assign the map, reset `@merge_outcomes` to `[]`, THEN run `MergeCheck.maybe_start/1` (never from handle_params); on `{:error, reason}` assign the error state and skip MergeCheck.
- Justified `try/rescue` at the async boundary only (node-boundary RPC to a possibly-dead remote daemon / task deleted mid-load; the alternative is the page wedging at loading forever — mirrors `merge_check.ex:232-241`). All RPCs return the verbatim underlying value (only transport failures add `{:error, {kind, reason}}`).

## Diffs are LAZY — never eager

`load_review_metadata*`/`load_commit_files` return per-file `%EvoGit.Review.FileInfo{}` with `diff: nil` (numstat/shortstat metadata only); per-file `load_file_diff/5,/6` (or `load_commit_file_diff/4` on the commit view) runs only on the `select_file` (`review_live.ex:381-405`), `toggle_file_expansion` (`:408-441`), `load_file_diff` (`:444-446`), and `expand_context` (`:454-488`, larger `:context` opt) phx events. `load_review_data/3` (the eager full-diff variant) is NEVER called anywhere in evo_dash — dead path for the dashboard (only a passthrough definition exists at `node_context.ex:703`). Tab switches are pure assigns, no RPC. On the SHOW route the diff-state maps are repo-keyed (see Multi-repo above); `update_file_diff_in_socket/4` (`:1165`) swaps only the file's `diff` field in the ACTIVE repo's entry.

## Merge-target branch selector

The merge action merges into a user-selectable branch, per repo. The async load sets each repo entry's `merge_targets`/`default_merge_target` (defaults `[]`/`nil` in mount) via `EvoGit.Review.list_branches/1` + `default_merge_target/1` when the repo path exists (plain `case` on tuple returns, no try/rescue); the flat assigns are projected from the ACTIVE repo. The `merge` handler reads `params["target_branch"]` (trimmed; non-member targets fall back to the repo's default when a known list was loaded) and broadcasts over all repos — see Multi-repo above. UI: `ReviewComponents.Actions.action_buttons/1` (see `components/review_components/CONTEXT.md`).

## Consumed-vs-transferred (payload audit)

- `get_task/2`: consumed = `opts[:path]`/`opts[:prompt]||opts[:objective]`/`opts[:foreign_repos]`, `result` keys (commit_sha/branch_name/result/pr_url/pr_title + top-level `repos` — accept both `:repos`/`"repos"` key shapes), `review_status`, `status`, `base_sha`, `commit_sha`, `archive_metadata`, `usage`, `agent_count`, `model_id`, `started_at`, `finished_at`. `logs` (and ref/lease_expires_at) transferred by the full TaskInfo but never read by this page.
- `load_review_metadata*` (8-key map: commit_sha, base_sha, diff_stat, diff, files, changed_files_count, total_additions, total_deletions): consumed = `base_sha` (drives the primary-scoped persisted-SHAs `set_review_metadata/4` write), `changed_files_count`, `total_additions`/`total_deletions`, `files` (per-file `path`/`status`/`additions`/`deletions`/`language`/`diff` in the components). Transferred-but-never-read: top-level `commit_sha`, the raw `diff_stat` string, `diff` (nil) — the diff-stats bar renders from the counts.
- `list_commits*` (6-field `%CommitInfo{}`): consumed = sha, short_sha, message, author_name, date (`commits_list` + `format_commit_history` `review_live.ex:1063-1071` + the commit-header lookup in `load_data.ex` `commit_inspection/3`). `author_email` transferred but unused.
- `check_merge/4` → per-repo `merge_status` `%{state: :checking|:clean|:conflict|:error, target:, files: []|paths}` (mapped in `merge_check.ex:151-182`); components read only `state` (spinner/clean banner/conflict block) and `files` (count + first-4 paths, actions.ex:198-241); `target` is server-side only (staleness + merge call).
- One-shot event RPCs (still synchronous in the LiveView, but looped per repo on merge/reject): `merge_branch/3,4` per repo via the `:review_merge_runner` seam (`review_live.ex:560-579`), `reject_branch/3` per repo via `:review_reject_runner` (`:668-676`), `create_github_pr/5` (`:795-801`), `start_task/3` (`:873`, Extract Skills) + auto-resolve (`merge_check.ex:114`), `set_review_status/3` (`:582,:679,:737,:775`), `set_review_metadata/4` (fire-and-forget, in load_data.ex) — only ok/error tags and flash-relevant values consumed (merged sha never rendered; `start_task`'s returned `%TaskInfo{}` discarded).
- **Gotcha**: `default_merge_target` actually returns `{:ok, name}` — the @specs in RemoteAPI/RemoteNode/NodeContext claiming bare `String.t()` are wrong; LoadData matches `{:ok, name}`. Field-consumption details per component: `components/review_components/CONTEXT.md` → "Field-consumption audit".

## Test strategy

Tests assert content synchronously after `live()`/`render()` would see the `@loading` spinner — flush the async load first: the file-local `flush_review_load/2` polling helper (polls `render(view)` until the spinner disappears — `render_async/2` does NOT work here, the load runs in a plain `Task.Supervisor` child, not a LiveView async task) + `wait_until/2` for post-send synchronization. Direct `send(view.pid, {:review_data_loaded, task_id, node(), generation, {:ok, assigns}})` injects results (stale-guard cases use wrong task/node/generation). Merge-check assertions additionally need the 6-tuple `{:merge_check_result, task_id, node(), repo_id, target, result}` message (or the loaded result first — `MergeCheck.maybe_start` runs only after the load result). Multi-repo coverage: repo-list construction (primary-first order, foreign entries only from `repos` with a branch), per-repo merge/reject broadcast via the `:review_merge_runner`/`:review_reject_runner` seams (all-ok navigate vs partial `@merge_outcomes` + stays), 6-tuple merge-check injection, and foreign-repo carry for auto-resolve/resume.

## Merge action + conflict path

The Merge button lives in `EvoDashWeb.ReviewComponents.Actions.action_buttons/1` (`lib/evo_dash_web/components/review_components/actions.ex`) — a `phx-submit="merge"` form (with `phx-change="merge_target_change"`, `id="merge-form"` for LiveView form recovery, and a hidden `repo_id` input) with a `target_branch` `<select>` when `@merge_targets != []`, else a bare `phx-click="merge"` button. `ReviewLive.handle_event("merge", ...)` (`review_live.ex:491-639`) builds a per-repo merge plan and broadcasts (see Multi-repo above): ALL `{:ok, sha}` → `set_review_status(:merged)` + success flash (mentions the effective target of the submitting repo) + `push_navigate` to `/projects`; ANY `{:conflict, details}`/`{:error, reason}` → `@merge_outcomes` per repo + summary error flash, page STAYS. The `{:conflict, _}` tag originates from the Git adapter's exit-code-1 mapping (git.ex:91, unwrapped in review.ex:377-378/400-410); `merge_into_current` leaves a repo mid-merge on conflict (no abort helper), `merge_into_other` force-restores the original branch (`git checkout --force`). The conflict path IS covered by evo_dash tests via the `:review_merge_runner` seam (backend coverage also at `apps/evo_git/test/evo_git/review_test.exs:367-390`).

## Auto merge-conflict resolution (async merge check + auto-resolve)

`action_buttons/1` renders a merge-status block (driven by the ACTIVE repo's projected `@merge_status`) ABOVE the merge form. The logic lives in `EvoDashWeb.ReviewLive.MergeCheck` (`lib/evo_dash_web/live/review_live/merge_check.ex`); ReviewLive's `handle_event`/`handle_info` clauses are thin wrappers and the `repo_available?/2` gate is a `defdelegate` to it (shared with the merge/resume gates — no duplication). After the review-data load result (`handle_info({:review_data_loaded, ...})`, `review_live.ex:973`), `maybe_start/1` spawns `EvoDash.NodeContext.check_merge(node, repo_path, branch_name, target)` (→ `EvoGit.RemoteNode.check_merge/4`, non-mutating dry-run) in a supervised Task (SettingsLive `test_llm` async pattern) for EVERY repo under the same gates the merge form renders with, skipping duplicates already `:checking` the same target. Each result arrives as `{:merge_check_result, task_id, node, repo_id, target, result}`; `handle_result/6` maps `{:ok, :clean}` → `%{state: :clean, files: []}`, `{:ok, {:conflict, files}}` → `%{state: :conflict, files:}`, `{:error, _}` → `%{state: :error}` (renders nothing), and drops stale messages (task_id/node mismatch, repo entry gone, or target mismatch via `stale_repo_target?/3`; unrecognized shapes dropped). UI: `:checking` → muted spinner + "Checking if merge is clean…"; `:clean` → green success box "Merge check passed — clean merge."; `:conflict` → warning box with `ngettext` file count ("Merge conflict detected in %{count} file(s): %{files}", first 4 files + "…" via `conflict_files_summary/1`) + prominent "Auto-resolve conflict" button (`phx-click="auto_resolve"`, `phx-confirm` "This starts a new agent task…", `disabled={@loading}`). `auto_resolve` (`merge_check.ex:88`, PRIMARY-scoped, guarded on the primary's `:conflict` state, else error flash): `set_review_status(node, task_id, :continued)` (resume-flow mirror, return ignored), then `start_task(node, :evolve, [path: repo_path, mode: "simple", objective: <plain interpolated prompt — NOT gettext>, starting_commit: commit_sha, merge_from: task_id, merge_target: target])` — the backend (evo_git `TaskExecutor`/`MergeContext`) handles the merge task itself and carries over the previous task's foreign repos. Success → success flash + `push_navigate` to `/projects` preserving `?node=`; `{:error, reason}` → error flash, stays on page. `merge_target_change` updates the changed repo's `default_merge_target` (params `repo_id`, blank → `"primary"`) and re-runs that repo's check. The manual Merge button + conflict flash remain untouched as fallback. **Test strategy** (`review_live_test.exs`): no mocking lib exists (no :meck/Mimic) — the blocking `:merge_check_runner` stub keeps the status at `:checking` until the view dies, and results are injected directly via `send(view.pid, {:merge_check_result, ...})` + `render(view)` (fully deterministic state machine); the auto-resolve success test uses a fixture with a nonexistent repo path so the REAL `TaskRegistry.start_task` returns `{:ok, task}` and the worker fails fast on the invalid path (documented pattern, projects_live_test.exs:1267-1271), asserting `review_status == :continued`, the redirect, and the started task's `merge_from`/`merge_target`/`starting_commit`/`path` opts (store round-trips `merge_from`/`merge_target` as string keys — see the `merge_opt`/`find_opt` test helpers); the remote error path uses the fake ConnectionManager registry pattern (lines 571-583).

## SHAs

The page's base/end commits come from `EvoGit.TaskInfo` fields `base_sha`/`commit_sha` (both nil until review metadata is persisted) and the task result map's `commit_sha`/`branch_name` — all PRIMARY-scoped. `LoadData.build_assigns/3` (load_data.ex:77) falls back to `task.commit_sha`, derives `base_sha` from `load_review_metadata` or `task.base_sha`, and persists both via `set_review_metadata` (primary-scoped fire-and-forget) when loading from a live branch. Post-merge/reject the page re-loads diffs/commits from the persisted SHAs (`load_review_metadata_from_shas`, `list_commits_from_shas`) — foreign repos use their per-repo `base_sha` (the `ForeignRepo.base_sha` / persisted `repos` SHAs; skipped when nil).

## Resume flow

`handle_event("resume", ...)` (`review_live.ex:726-769`) is PRIMARY-scoped — repo-scoped fields come from the `"primary"` entry explicitly, never from the flat (active-repo-projected) assigns, so a foreign-repo tab must not change what resume prepares. It sets review_status `:continued` and `push_navigate`s to `/projects?resume_from=<task_id>&starting_commit=<commit_sha>&project=<repo_path>[&node=<id>]` (manual `&node=` suffix — the URL already has a query string). `ProjectsLive.handle_params/3` (projects_live.ex:681-705) reads those query params into `@task_starting_commit`/`@task_resume_from` (auto-expanding Advanced Options + `maybe_restore_foreign_repos_from_task/1` — the foreign repos are carried through resume), and `ProjectsLive.do_task_submit/4` threads `:starting_commit` (projects_live.ex:2164-2172) and `:resume_from` (2213-2220) into `EvoGit.TaskRegistry.start_task(:evolve, opts)` / `NodeContext.start_task` (2224-2226). Backend: `TaskExecutor.execute_task` → `ResumeContext.apply_resume_context/3` (prepends previous-task context block, overrides `opts[:starting_commit] = prev_task.commit_sha`) → `Runtime.Evolution.run/2` (`:starting_commit` → `resolve_starting_commit` → git rev-parse).

**Module sizes (deliberate, per Genesis file-size policy)**: `review_live.ex` is ~1270 lines — a cohesive single-page LiveView (render + all review operations incl. per-repo merge/reject broadcast; the multi-repo integration is inlined here by design, so this size is justified — do not split; the async merge-check/auto-resolve logic lives in the `review_live/MergeCheck` support module, same pattern as `projects_live/`). `node_context.ex` is ~870 lines — the single API-surface module for remote SSH; every entry is a thin delegate, intentionally not split. **Remaining known gap**: `handle_info(:node_aware_reload_tasks)` fires on task PubSub broadcasts, which may not cross nodes reliably — the review page itself is loaded once at navigation and doesn't poll remote nodes (acceptable: review data is static after completion).

## Constraints

- The async load is the ONLY way the page fetches data — do not add synchronous RPCs to `handle_params/3`.
- Diffs stay lazy — never fetch full diffs on page load.
- Merge/reject are broadcast over ALL `@review_repos`; PRIMARY-scoped operations (`resume`, `create_pr`, `confirm_extract_skills`, `auto_resolve`, `set_review_metadata`, the `:commit` route) must resolve the `"primary"` entry explicitly, never the active-repo-projected flat assigns.
- Follows the project-wide `try/rescue` anti-pattern policy; the async-boundary rescue is the accepted exception (justified comment in code).
