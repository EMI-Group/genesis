# ReviewLive — Review Page

## Intent

`EvoDashWeb.ReviewLive` (`review_live.ex`, `GET /review/:task_id`) — GitHub-PR-inspired code review page. **Two-page model**: the `:show` route renders a `page_header` + `page_tabs` + one of FIVE tab bodies (`:conversation | :objective | :files_changed | :commits | :archive`); the `:commit` route (`/review/:task_id/commit/:sha`) renders a standalone commit-inspection page (`commit_detail_header` + `commit_diff_layout`, no page tabs, no separate back-button row — the back link lives inside `commit_detail_header`). The objective renders on its own dedicated **`:objective` tab** (a readability column hosting `objective_section`, with the `objective_raw` markdown/raw toggle + copy button). **Multi-repo review**: tasks with writable foreign repos expose repo selection in the Files-changed toolbar, the Commits tab, AND one **per-repo card** (`repo_cards/1`) in the conversation pane; merge and reject act on EXACTLY the one repo whose form/button was clicked (never a fan-out), each repo owning its own `resolution` state. Single-repo (legacy) tasks render one card with no repo affordances. A repo with NO `branch_name` (no changes) is excluded from every merge/reject action and never blocks aggregate completion; a task with NO changes in ANY repo renders the informational no-changes notice (`repo_cards` state 4) and is dismissed via the promoted **"Mark as read"** primary action (`task_actions no_changes: @is_no_changes` → the `ignore` event). No store / registry / git / `EvoDash.NodeContext` call runs in the LiveView process: page loads AND every review action / lazy diff fetch execute in `EvoDash.TaskSupervisor` children behind `EvoDash.SafeCall`, and per-file diffs are LAZY (per-event).
The page load itself is LITE (`EvoDash.NodeContext.get_task_lite/2` — no archive blob transfer), and the archived-agent data is a SEPARATE on-demand, PAGED async load (`review_live/archive_load.ex`) that starts when the Archive tab opens: 100 entries per page behind a 500-entry retention window, "Load more" for the rest, and each agent's heavy `"result"` fetched lazily on demand.
Archiving is OPT-IN per task (`opts[:archive]` via `EvoDashWeb.ArchiveHelpers.archive_opt?/1`): a task started without it renders no Archive tab and never issues an archive fetch.

## Routing Table

Leaf directory — `actions.ex` (off-process action executors), `load_data.ex` (async page load), `merge_check.ex` (async dry-run merge check + auto-resolve payload), `archive_load.ex` (paged archive state machine, lazy per-agent result cache, Archive-tab panel). No child CONTEXT.md.

## API Surface

| Module | Purpose |
|--------|---------|
| `EvoDashWeb.ReviewLive.LoadData` (`load_data.ex`) | Async review-data load, runs in `EvoDash.TaskSupervisor` children. `load/3` (`node, task_id, opts` with `live_action:`/`inspect_commit_sha:` opts) → `{:review_data_loaded, task_id, node, generation, result}` with `{:ok, assigns_map} \| {:error, reason}` (error strings pre-gettext-wrapped). The task row is read with the LITE `EvoDash.NodeContext.get_task_lite/2` (`result` + `opts` + SHAs + timestamps + `usage`/`agent_count`), so the load-result map carries NO archive key at all — applying a load can never wipe an archive that is already loaded. `build_assigns/3` builds the `@review_repos` list (one entry per reviewable repo, primary first) plus `active_repo_id` and the archive opt-in `archive_opt_in?` (`EvoDashWeb.ArchiveHelpers.archive_opt?(task.opts)` — the single opt-in signal for the page); `commit_inspection/3` (the `:commit` route) is PRIMARY-repo-scoped. The load-result map does NOT include `tree_expanded_dirs`/`file_filter` (mount-seeded only) — the tree/filter state survives debounced reloads by construction. `repo_available?/2` and `branch_exists_on_node?/3` take `node` (not a socket). |
| `EvoDashWeb.ReviewLive.ArchiveLoad` (`archive_load.ex`) | Paged, lazy archive state machine + Archive-tab panel (the lite read carries no archive, so the archive is read in bounded pages on demand). Page seam `:review_archive_runner` — 3-arity `fn node, task_id, opts -> %{entries: [map()], total: non_neg_integer()} end`, default `&EvoDash.NodeContext.list_task_archives/3`; per-agent seam `:review_archive_agent_runner` — 3-arity `fn node, task_id, agent_id -> map() \| nil end`, default `&EvoDash.NodeContext.get_agent_archive/3`. Both are resolved AT CALL TIME INSIDE the spawned child. `ensure_loaded/1` spawns the FIRST page (`limit: 100, offset: 0, include_results: false`) only from `:idle` AND only when `archive_opt_in?` is true (otherwise a total no-op — no fetch); `load_more/1` appends the next page at `offset = archive_fetched` only from `:loaded` with no append in flight, `not archive_exhausted?`, and `EvoDashWeb.ArchiveHelpers.more_pages?(retained, dropped, effective_total)`. `load_agent_result/2` fetches ONE agent's full entry on demand (no-op when that agent is unknown to the page or already `:loading`/`:ok`; an `:error` entry retries). Children ALWAYS send `{:review_archive_loaded, task_id, node, seq, offset, result}` (`{:ok, %{entries:, total:}}\|{:error, gettext_string}`) / `{:review_archive_agent_loaded, task_id, node, agent_id, seq, result}`, so no shape can wedge the panel. Assigns: `archive_opt_in?` (owned by `LoadData`; false ⇒ every entry point returns the socket untouched), `archive_state` (`:idle \| :loading \| :loaded \| :error` — only a FIRST page uses `:loading`), `archive_records` (the RETAINED accumulated pages), `archive_dropped` (entries evicted by the retention window), `archive_fetched` (cumulative RAW server rows received — the ONLY source of the next request offset), `archive_exhausted?` (a page returned fewer rows than `@page_limit`), `archive_server_total` (raw server count, `nil` when a page reported none — LABEL only), `archive_total` (EFFECTIVE total driving paging), `archive_loading_more?`, `archive_more_error`, `archive_error`, `archive_key` (`{task_id, node}`), `archive_seq` (context generation), `archive_agent_results` (`%{agent_id => %{state: :loading \| :ok \| :error, entry:, error:}}`), `archive_agent_seq` (result-cache generation). Stale guards: task/node mismatch, or a `seq` below its own generation (pages and per-agent results have SEPARATE generations, so neither invalidates the other). An append failure keeps the loaded page (only `archive_more_error` is set); a first-page failure is `:error` (retry-able) with records/total and the four new counters reset. A successful per-agent result is cached AND folded into `archive_records` via `ArchiveHelpers.merge_entry/2`. `invalidate_agent_results/1` (called from the reviewed task's broadcast) drops the cache AND strips the lazily fetched `"result"` from the loaded entries (pages stay), so the next "Show result" refetches. Caching is by `{task_id, node}`: tab round-trips and `{:review_data_loaded, ...}` reloads never refetch; only `sync_context/1` on a task/node change resets pages, total, the retention/offset counters and per-agent results (bumping both generations) and refetches when the Archive tab is on screen AND the new task opted in. `retry/1` (opt-in guarded) re-arms and refetches the first page for the panel's `retry_archive` event. PURE `export_available?/1` = `archive_state == :loaded and archive_records != []`; PURE total `label_total/1` = `max(server_total, archive_total)` when a server count is known, else the effective total (0 for garbage) — the value the tab badge and section header are LABELLED with. `panel/1` renders the states (`opt_in? == false` muted disabled state FIRST, `:idle`/`:loading` spinner, `:error` retry-able box, `:loaded` + `[]` empty state, `:loaded` → `archive_review_section` with `dropped`/`exhausted?`/`server_total`). |
| `EvoDashWeb.ReviewLive.MergeCheck` (`merge_check.ex`) | Async non-mutating merge-conflict dry-run (`check_merge/4` → `{:ok, :clean} \| {:ok, {:conflict, files}} \| {:error, reason}`), started AFTER the load result **and** inside `EvoDash.SafeCall` (a dead/failed check becomes `{:error, :check_failed}` → `%{state: :error}` instead of leaving `:checking` up forever). **Multi-repo aware**: `maybe_start/1` spawns ONE `check_merge/4` per review repo under the same gates the repo cards render with (branch exists, `merge_targets != []`, target binary, `repo_available?/2`), skipping a repo already `:checking` the same target; results arrive as 6-tuples `{:merge_check_result, task_id, node, repo_id, target, result}`. Also hosts `repo_available?/2`, the PUBLIC `update_repo/3` (in-place single-entry update of `@review_repos`, shared with ReviewLive's per-repo tails), `handle_target_change/2`, `handle_result/6`, and the PURE `auto_resolve_payload/1` (PRIMARY-scoped: `{:ok, %{opts:, to:}}` from the primary's `:conflict` status, else `:unavailable`; performs no I/O). |
| `EvoDashWeb.ReviewLive.Actions` (`actions.ex`) | Off-process ACTION executors — no socket in or out, each returns a small outcome tuple: `merge/4` (`{:merged, target} \| {:conflict, details} \| {:error, reason}`), `merge_all/2` (`[{repo_id, outcome}]`, sequential + best-effort), `reject/3` (`:rejected \| {:error, reason}`), `set_review_status/3` (`:ok \| {:error, reason}`), `create_pr/5` (`{:pr, url, title} \| :no_pr \| {:error, reason}`), `start_task/3`, `auto_resolve/3` (best-effort `:continued` write + `start_task/3`), `load_review_diff/6`, `load_commit_diff/4`, `load_commit_diff_with_opts/5` (`{:ok, diff} \| {:error, reason}`). TOTAL — an unexpected underlying shape becomes `{:error, {:unexpected, other}}`, never a `FunctionClauseError`. Test seams `:review_merge_runner` / `:review_reject_runner` are resolved at CALL time (inside the spawned task); a batch resolves the merge seam once. |

**Component-contract boundary**: every component `review_live.ex` renders (`page_header`, `page_tabs`, `agent_summary`, `objective_section`, `diff_stats_bar`, `task_summary`, `repo_cards`, `task_actions`, `extract_skills_modal`, `split_diff_layout`, `commit_diff_layout`, `commits_list`, `commit_detail_header`, `archive_review_section`) is defined in the SIBLING `components/review_components*` tree — its full attr/event surface is documented in `components/review_components/CONTEXT.md`. This page owns the wiring (attrs + event handlers), that tree owns the markup.

## Async boundary — nothing blocks the LiveView

`review_live.ex` is the wiring (assigns + `handle_event`/`handle_info`); `review_live/actions.ex` holds the executors it spawns. Every store / registry / git / `EvoDash.NodeContext` RPC on this page runs in an `EvoDash.TaskSupervisor` child wrapped in `EvoDash.SafeCall.run/1` — the single exit boundary (`apps/evo_dash/lib/evo_dash/safe_call.ex`), because a `GenServer.call` timeout or dead target EXITS the caller (a `rescue` cannot catch it). The boundary turns every failure mode (exit / raise / throw) into a value, so the spawned closure ALWAYS sends its result message and no loading flag can wedge; the page files themselves contain no `try/rescue`.

| Incoming message | Producer → shape | Handling |
|---|---|---|
| `{:review_data_loaded, task_id, node, generation, result}` | `start_async_load/2` → `LoadData.load/3`; `result` = `{:ok, assigns_map} \| {:error, gettext_string}` | Stale-guarded on task + node + monotonic `@load_generation` (older generation dropped). `loading: false` set on BOTH branches; the error branch also clears the header assigns and renders the "Review Not Available" panel with a `retry_load` Retry button (plus Back to Dashboard). |
| `{:review_action_result, task_id, node, action, action_ref, result}` | `spawn_action/4` → `result` = `{:ok, outcome}` (SafeCall-wrapped `Actions` outcome) \| `{:error, reason}` | A different task/node ⇒ dropped entirely (that load context is gone). Applied by `apply_action_result/4` BEFORE `clear_action_state/3` (the lazy-diff apply step needs the pre-clear seq). |
| `{:merge_check_result, task_id, node, repo_id, target, result}` | `MergeCheck.start/7` (one per repo) | `MergeCheck.handle_result/6` validates the shape + stale-guards (task/node/repo-gone/target-changed), then re-projects. |
| `{:review_archive_loaded, task_id, node, seq, offset, result}` | `ArchiveLoad.ensure_loaded/1` (offset 0) / `load_more/1` → the `:review_archive_runner`; `result` = `{:ok, %{entries: [map()], total: n}} \| {:error, gettext_string}` | `ArchiveLoad.handle_result/6` stale-guards (task + node + page generation) then REPLACES on offset 0 and APPENDS (deduped by `agent_id`) on a larger offset; a first-page failure is `:error`, an append failure only sets `archive_more_error`. |
| `{:review_archive_agent_loaded, task_id, node, agent_id, seq, result}` | `ArchiveLoad.load_agent_result/2` → the `:review_archive_agent_runner`; `result` = `{:ok, map} \| {:error, reason}` | `ArchiveLoad.handle_agent_result/6` stale-guards (task + node + result-cache generation), caches the entry AND folds it into `archive_records`; every other shape becomes a retry-able `:error` entry. |
| anything else | — | Catch-all `handle_info(_msg, socket)` returns the socket unchanged: an unknown or stray message can never crash the page. |

## Action table

Every action handler first checks `@review_action == nil` (the double-submit gate), takes a monotonic ref from `next_action_seq/1` (`@action_seq`), marks its in-progress state, and hands the work to `spawn_action/4`.

| Action | `action_ref` | In-progress state | Outcome branches (`apply_action_result/4`) |
|---|---|---|---|
| `:merge` | `%{repo_id, target, seq}` | `@review_action` `%{kind: :merge, repo_id:, seq:}` + repo id in `@busy_repos` | `{:ok, {:merged, target}}` → `settle_repo_action/4` (terminal resolution + success flash + completion); `{:ok, {:conflict, details}}` → `%{state: :conflict}` on that card + error flash; anything else → `%{state: :error}` + error flash. Always STAYS. |
| `:merge_all` | `%{repo_ids, seq}` | `@review_action` `%{kind: :merge_all, seq:}` + every repo id in `@busy_repos` | `{:ok, [{repo_id, outcome}]}` → each repo settles on its own card (one conflict/error never aborts the rest) + ONE batch summary flash + completion; unexpected → single error flash. |
| `:reject` | `%{repo_id, seq}` | review_action + repo in `@busy_repos` | `{:ok, :rejected}` → terminal resolution + success flash + completion; anything else → `%{state: :error}` + error flash. |
| `:resume` / `:ignore` | `%{to, flash_msg, seq}` | review_action + `@action_loading` | `{:ok, :ok}` → `invalidate_active_tasks/1` + info flash + `push_navigate(to:)`; anything else → error flash, STAY. |
| `:create_pr` | `%{seq}` | review_action + `@action_loading` | `{:ok, {:pr, url, title}}` → `has_pr: true` / `pr_url` + success flash; `{:ok, :no_pr}` → "gh CLI" error flash; anything else → error flash. |
| `:extract_skills` | `%{seq}` | review_action + `@action_loading` | `{:ok, {:ok, task}}` → close the modal + info flash; anything else → error flash (modal stays open). |
| `:auto_resolve` | `%{to, seq}` | review_action + `@action_loading` | `{:ok, {:ok, task}}` → invalidate + success flash + `push_navigate(to:)`; anything else → error flash. |
| `:completion` | `%{status, seq}` | NONE (background bookkeeping write — `clear_action_state/3` leaves it alone) | error → error flash only. |
| `:diff` / `:expand_context` | `%{repo_id: scope, path, level, seq}` | `@diff_in_flight[{scope, path}] = seq` | see "Diffs are LAZY". |

`@action_loading` feeds `task_actions loading` (the primary/aggregate action spinner) and is set ONLY by the task-level actions (`resume`, `ignore`, `create_pr`, `extract_skills`, `auto_resolve`). `clear_action_state/3` runs on every result (ok OR error): it releases the diff-in-flight entry only when this result still owns the seq, and otherwise clears `@review_action`, the repo's `@busy_repos` membership (all `repo_ids` for `:merge_all`), and the task-level spinner. `spawn_action/4` clears the same state itself when the child cannot even be started (error flash). A node/route context change in `handle_params/3` resets `review_action`/`action_loading`/`busy_repos`/`diff_in_flight`/`review_broadcast_status` (their result messages would be dropped anyway). **COMPONENTS-ROUND GAP**: `@busy_repos` (per-repo in-flight) is assigned and maintained but the sibling `components/review_components*` tree does not consume it yet — per-card in-flight disabling is a components-tree change, not a page change.

## Page model (`:show`)

`render/1` computes two values inline (no extra assigns): `stats = aggregate_stats(@review_repos)` and `primary = Enum.find(@review_repos, &(&1.repo_id == "primary"))`.

- **`page_header`** — PRIMARY-scoped fields (`repo_path`/`branch_name`/`merge_target` = primary's `default_merge_target`/`commit_sha` from the `"primary"` entry explicitly, never the active-repo projection), `back_url = with_node_param(~p"/projects", @current_node_id)`, full `title`, task/review status + meta, `stats` (aggregate map, see below).
- **`page_tabs`** — underline tab bar with count badges driven by the AGGREGATE stats (`files_count`, `commits_count`), `show_archive` (a constant `true` — the tab bar only renders in the loaded branch, and the lite load cannot know whether an archive exists), `archive_count` (= `@archive_total`, the archive's true size — `0` renders no badge).
- **`:conversation`** — readability column `max-w-4xl mx-auto w-full space-y-4`, in order: `agent_summary` → `diff_stats_bar` (aggregate) → `task_summary` → **`repo_cards` AT THE BOTTOM** (`repos: @review_repos`, `completion: completion_status(@review_repos, @review_status)`, `back_url: with_node_param(~p"/projects", @current_node_id)`) → `task_actions` (PRIMARY/aggregate action surface: `can_resume: @can_resume`, `loading: @action_loading`, `branch_exists: @branch_exists`, `has_pr: @has_pr`, `pr_url: @pr_url`, `show_export: EvoDashWeb.ReviewLive.ArchiveLoad.export_available?(assigns)` (an export link renders ONLY once the archive is `:loaded` with a non-empty list — the export endpoint 404s without an archive), `export_url: with_node_param("/tasks/#{@task_id}/export", @current_node_id)`, `no_changes: @is_no_changes`) → `extract_skills_modal`.
- **`:objective`** — readability column `max-w-4xl mx-auto w-full space-y-4` hosting only `objective_section` (`objective:`, `objective_raw:`). The tab is ALWAYS rendered (no count badge); a nil/`""` objective shows the component's in-card empty state.
- **`:files_changed`** — FULL WIDTH (no max-w): `split_diff_layout` reading the ACTIVE repo's repo-keyed submaps via inline `Map.get` (`expanded_files`/`selected_file`/`file_context_levels`/`tree_expanded_dirs` — same keying as the diff state), plus flat `file_filter`, `repos: @review_repos`, `active_repo_id:`. Repo selection lives in the layout's toolbar. nil `@review_data` → the empty-state icon panel.
- **`:commits`** — `commits_list commits: @commits` (ACTIVE repo's commits — repo switching lives in the files toolbar / commits toolbar).
- **`:archive`** — the single `EvoDashWeb.ReviewLive.ArchiveLoad.panel/1` call (`state`/`records`/`total`/`loading_more?`/`more_error`/`agent_results`/`error`/`task_id`/`node_id: @current_node_id`); it owns all four states (spinner, retry-able error, empty state, `archive_review_section`) and forwards the node-aware export href (`with_node_param("/tasks/#{@task_id}/export", @node_id)`). Opening the tab starts the FIRST page (see "Archive tab — paged load & export decision"); paging and the per-agent lazy result live inside the section.
- Trailing warning block (branch_exists && nil review_data && !loading) kept, restyled `rounded-xl border-warning/30 bg-warning/10`.

**Aggregate stats** — private `aggregate_stats/1` sums EVERY repo's `review_data.changed_files_count/total_additions/total_deletions` (repos with nil review_data contribute 0) plus `length(repo.commits)`; result `%{files_count:, additions:, deletions:, commits_count:}`. Consumed by `page_header` (stat row), `page_tabs` (count badges), and the conversation `diff_stats_bar` — never the active repo alone, so the numbers are stable across repo switches.

## Multi-repo review (writable foreign repos)

The core writes writable-foreign-repo results into the task result's top-level `repos` map (`%{repo_id => %{"commit_sha" => sha, "branch_name" => branch \| nil}}`, STRING keys); the review page turns each such repo into a review entry.

- **Repo list construction** (`load_data.ex` `build_review_repos/6`): `@review_repos` is a list of per-repo maps `%{repo_id:, repo_path:, branch_name:, commit_sha:, base_sha: (String.t()\|nil), branch_exists:, review_data: (map\|nil), commits:, merge_targets:, default_merge_target:, merge_status:, resolution:}`, **primary FIRST**. Foreign entries come from `task.opts[:foreign_repos]` normalized via `EvoGit.Core.ForeignRepo.normalize/1`; only repos present in `repos` with a non-nil branch_name get an entry. **Legacy tasks (no `repos` key) → exactly one primary entry**. `active_repo_id` defaults `"primary"`.
- **Repo `resolution` (per-repo control state machine)** — every entry carries a `:resolution` (built in `build_repo_entry/2`, updated by `MergeCheck.update_repo/3` through the merge/reject tails). Value domain: `nil` (unresolved; actions available when `branch_exists`), `%{state: :merged, target: target_branch}` (TERMINAL; `target` = the branch merged into), `%{state: :rejected}` (TERMINAL), `%{state: :handled}` (TERMINAL — branch already gone at page LOAD, exact outcome unknown), `%{state: :error, detail: String}` (NON-terminal, retryable), `%{state: :conflict, detail: String}` (NON-terminal, retryable). TERMINAL = `:merged \| :rejected \| :handled`; NON-terminal = `nil \| :error \| :conflict`. **Load seeding**: a repo that HAD a branch (`is_binary(branch_name) and String.trim(branch_name) != ""`) whose `branch_exists` is false seeds `%{state: :handled}` so reopening a PARTIALLY resolved review is coherent; the `branch_name == nil` "no changes" case stays `nil`.
- **Self-reload overlay (`:local_repo_resolutions`)** — the page's OWN `set_review_status/3` broadcast (`{:task_updated, id, nil, node}`) rides the 300ms NodeAware debounce into a fresh `LoadData.load/3`, which re-derives each resolution from REPOSITORY state only (a branch that still exists → `nil`); without an overlay that reload clobbers the resolution the user just earned. `set_repo_resolution/3` — the SINGLE funnel used by the merge/reject/merge_all tails (never the load seeding, never fixtures) — therefore ALSO records `%{repo_id => resolution}` in the action-scoped `local_repo_resolutions` assign (mount-seeded `%{}`). The `{:ok, assigns_map}` branch applies `carry_local_resolutions/2` → `overlay_local_resolutions/2`: ONLY TERMINAL entries overlay, and only onto loaded repos whose loaded resolution is `nil` (a non-nil loaded value — e.g. a genuinely deleted branch → `:handled` — stays authoritative); entries for repo_ids no longer in the loaded list are pruned. `handle_params/3` resets the assign whenever the `{current_node, live_action, commit_sha}` load context changes, so the overlay is per-SESSION (the assign is deliberately NOT derived from `@review_repos`, which the load itself seeds).
- **Repo selection is component-owned**: no page-level `repo_tabs`. The Files-changed toolbar (`split_diff_layout`) and the Commits tab (`commits_list`) render the ACTIVE-repo selector from `repos:`/`active_repo_id:` attrs, shown only when `length(@repos) > 1`. Each selector is a `<select name="repo_id">` wrapped in its OWN `<form phx-change="switch_repo">` (ids `diff-repo-switch-form`/`commits-repo-switch-form`) — a form-less `<select phx-change>` NEVER delivers its event (LiveView JS `pushInput` throws "form events require the input to be inside a form"); the form-level change serializes the field by `name` → `%{"repo_id" => id}`. `switch_repo` has TWO clauses — `%{"repo_id" => id}` (form-wrapped selects) and `%{"value" => id}` (defensive form-less shape) — both delegating to one private `switch_repo/2` that whitelist-validates against `@review_repos` ids (never `String.to_atom` on client input), sets the active id, **clears `file_filter`** (shared filter never leaks stale text into the new repo's list), and re-projects the flat assigns via `project_active_repo/1`.
- **Flat projection** (`project_active_repo/1`): the flat assigns (repo_path/branch_name/commit_sha/base_sha/branch_exists/review_data/commits/merge_targets/default_merge_target/merge_status) are projected from the ACTIVE repo; NO-OP on the `:commit` route. The diff/tree state maps are NOT re-projected — the template reads the active submap inline.
- **PRIMARY-scoped operations**: `resume`, `create_pr`, `confirm_extract_skills`, `auto_resolve`, `set_review_metadata`, the `:commit` route, and the `page_header` repo fields all resolve the `"primary"` entry explicitly (documented limitation — never the active-repo projection).
- **Per-repo merge** (`handle_event("merge")`): dispatched ONLY by a per-repo merge form submit (params `%{"repo_id" => id, "target_branch" => target}`); acts on EXACTLY the one repo named by `repo_id` (whitelisted; an unknown id, a repo whose `resolution` is TERMINAL, OR a repo with NO changes (`RepoCards.repo_has_changes?/1` false) is a no-op). Target resolution (`resolve_merge_target/2`): the trimmed `target_branch`, falling back to the repo's `default_merge_target` when blank/absent or when not a member of a non-empty `merge_targets`. The merge runs off-process via `Actions.merge/4` (seam `:review_merge_runner` resolved at call time) and its outcome is applied by `apply_action_result(:merge, ...)`; NEVER fans out; NEVER navigates.
- **Merge all** (`handle_event("merge_all")`): the batch shortcut — the button (`#merge-all-repositories`, `phx-confirm`) renders only when the task has >= 2 repos AND >= 2 CHANGE-BEARING repos (`RepoCards.repo_has_changes?/1`) are still unresolved. The handler folds the CURRENTLY-UNRESOLVED CHANGE-BEARING repos (`resolution == nil` AND `RepoCards.repo_has_changes?/1`) into `%{repo_id, repo_path, branch_name, target}` entries (`target = repo.default_merge_target || List.first(repo.merge_targets || [])` — the merge-target select writes the choice back into `default_merge_target`) and runs them through `Actions.merge_all/2` off-process; a no-change repo is excluded, so its nil branch never reaches the runner. **Best-effort per repo**: a conflict/error lands on that repo's own card while the rest still merge; the fold never aborts or wedges. When the last repo reaches terminal the same completion path runs as a per-repo action (`settle_batch_outcome/2` → `maybe_persist_completion/1`); ONE batch summary flash is put (never per-repo flashes) and there is no `push_navigate`/`push_patch`. Zero actionable repos → no-op with no flash.
- **Per-repo reject** (`handle_event("reject")`, params `%{"repo_id" => id}`): same single-repo whitelist/Terminal/no-changes no-op. Runs off-process via `Actions.reject/3` (seam `:review_reject_runner`, call time). `:rejected` → terminal resolution + `branch_exists: false`; any error → `%{state: :error, detail: inspect(reason)}` (STAY).
- **Completion** (`completion_status/2` + `settle_repo_action/4` → `maybe_persist_completion/1`): after a per-repo merge/reject succeeds, `settle_repo_action/4` records the resolution, flashes, and recomputes `completion_status(@review_repos, @review_status)` → `nil \| :merged \| :rejected`. `completion_status/2` first filters `@review_repos` to the CHANGE-BEARING repos (`RepoCards.repo_has_changes?/1`) — a no-change repo needs no action, so it never blocks completion. It is `nil` when that actionable list is EMPTY (a fully-no-change task is NEVER reported as `:rejected` — it is dismissed via "Mark as read") OR when any actionable repo's resolution is NOT TERMINAL; when EVERY actionable repo is TERMINAL it returns the persisted `@review_status` if that is `:merged`/`:rejected` (reload coherence), else `:merged` if ANY actionable repo is `%{state: :merged, _}`, else `:rejected`. A NON-nil result is the COMPLETION path: `assign(:review_status, status)` + `invalidate_active_tasks/1` + the async `:completion` action (`Actions.set_review_status/3`). NON-terminal outcomes (`:conflict`/`:error`) only flash an error and STAY. The same `completion_status/2` value drives the render's completion banner (`repo_cards` `completion` attr).
- **No-change repos & the `review_status`/`is_no_changes` computation** (`load_data.ex`): the shared public predicate is `EvoDashWeb.ReviewComponents.RepoCards.repo_has_changes?/1` (a repo's `branch_name` is a NON-BLANK binary; nil/`""`/whitespace → false) — ONE definition reused by `show_merge_all?/1`, the `merge_all` fold, the per-repo `merge`/`reject` guards, `completion_status/2`, AND the load's `is_no_changes`. On load, `review_status` = the persisted `task.review_status` when non-nil, else `:open` — a primary with no branch is NOT forced to `:no_changes`, so a task whose primary made no changes but whose FOREIGN repos did renders a NORMAL/OPEN review. `is_no_changes` = "NO repo in `@review_repos` has changes" (computed from `review_repos`, NOT just the primary) and is threaded into `task_actions no_changes:` to promote the dismissal to the primary "Mark as read" action.
- **Per-repo cards**: `repo_cards/1` has exactly ONE render site (`:conversation` tab, after `task_summary`) fed the whole `repos: @review_repos`; it renders one card per repo with that repo's `resolution` badge, own merge form (`merge-form-<repo_id>` → `phx-submit="merge"` with hidden `repo_id`, `phx-change="merge_target_change"`), own reject button (`phx-click="reject"` + `phx-value-repo_id`), and an `open_repo_diff` jump button. There is no global merge box and no `@merge_outcomes`.
- **MergeCheck per-repo**: one async dry-run per repo tagged `repo_id`; 6-tuple `{:merge_check_result, task_id, node, repo_id, target, result}`; auto-resolve stays PRIMARY-scoped (a foreign-repo conflict is surfaced on that repo's card, not auto-resolved).

## Async load contract

- `handle_params/3` dedup guard `tasks_loaded_for == {current_node, live_action, params["commit_sha"]}` → private `start_async_load/2` bumps `@load_generation`, sets `loading: true, error: nil`, and spawns the `EvoDash.SafeCall`-wrapped `LoadData.load/3` in `EvoDash.TaskSupervisor`. NO synchronous RPCs in `handle_params/3`.
- Load sequence: `get_task_lite/2` → per repo (primary first): `list_branches/2` + `default_merge_target/2` → `branch_exists?/3` → `load_review_metadata/3` or `load_review_metadata_from_shas/4` (post-merge path, per-repo `base_sha`) → `list_commits/3` or `list_commits_from_shas/4`; fire-and-forget `set_review_metadata/4` (primary-scoped) when SHAs just persisted. The `:commit` route additionally runs primary-scoped commit inspection and adds `inspect_commit_sha`/`commit_header`/`commit_data`. The archive is NOT part of this sequence — it is a separate lazy load.
- Result map: ~30 template assigns + resets `expanded_files: %{}`/`file_context_levels: %{}`/`selected_file: nil`. `tree_expanded_dirs`/`file_filter` are NOT in the map (mount-seeded) → they survive reloads.
- **`LoadData.load/3` reads the task row LITE** (`EvoDash.NodeContext.get_task_lite/2`): `result` + `opts` + SHAs + timestamps + `usage`/`agent_count`, with `archive_metadata` nil and no `:archive_records` in the result data. The archive bytes are fetched only by `ArchiveLoad` when the Archive tab opens (in bounded pages).
- The load-result map carries NO archive key: applying a load can never clear an archive that is already cached.
- **Stale-guard** (`{:review_data_loaded, task_id, node, generation, result}`): drop unless `task_id == @task_id` and `node == @current_node` and `generation >= @load_generation` (monotonic). On `{:ok, assigns_map}`: clear `loading` explicitly, apply `carry_local_resolutions/2`, THEN `MergeCheck.maybe_start/1` (it must see the loaded `merge_targets`/`branch_name`/`branch_exists`) and re-project. On `{:error, reason}`: `loading: false`, assign `@error`, clear the header assigns, skip MergeCheck.
- A failed load is retry-able (`retry_load` → `start_async_load/2`); the page never wedges on the spinner.

## Diffs are LAZY — never eager

`load_review_metadata*`/`load_commit_files` return per-file `%EvoGit.Review.FileInfo{}` with `diff: nil` (numstat metadata only); a per-file diff is fetched only by `select_file`, `toggle_file_expansion` (expand only), `load_file_diff`, and `expand_context` (larger `:context` opt), all of which update their state synchronously and then spawn an `Actions` loader through `start_diff_load/5`. The scope is the ACTIVE repo id on SHOW and the `:commit` atom on the commit route, captured at spawn time (carried in the action ref's `repo_id`), so a result landing after a repo switch is never written into the wrong repo. Duplicate spawns are suppressed per `{scope, path}`: `maybe_start_diff_load/2` starts only when the file's `diff` is nil and no `{scope, path}` entry is in `@diff_in_flight`; `start_diff_load/5` is a no-op for an in-flight key. A result applies only while it is still the latest seq for that key, the captured scope is still on screen (SHOW: still `active_repo_id`; `:commit`: still the commit route), the file still exists in that scope's file list, and — for `:diff` — the file is still selected or expanded (`:expand_context` only requires presence). `:expand_context` is grow-only (`+20` lines, `:all` past 30 or at `:all`) and `max_context_level/2` never downgrades a written level. `update_file_diff_in_socket/5` writes into the CAPTURED scope's data source (`commit_data` on `:commit`, the repo entry's `review_data` on SHOW) and marks the file expanded; the selection is not touched there. Tab switches, tree toggles, and filter typing are pure assigns, no RPC — diffs are never fetched on page load.

## Files-changed toolbar state (tree + filter)

- **`tree_expanded_dirs`** — `%{dir_path => true}` expansion state. SHOW: repo-keyed outer map (`%{repo_id => %{dir => true}}`), toggled per repo via `toggle_dir` (put/delete in the active repo's submap). `:commit`: flat dir-keyed map. `collapse_all_dirs` sets the acting submap (or flat map) to `%{}`; `expand_all_dirs` merges ALL ancestor directory paths of the acting file list (private `all_dir_paths/1` → `dir_chain/2`: every `Path.dirname` chain segment except `"."`) as true. Read in render via inline `Map.get(@tree_expanded_dirs, @active_repo_id, %{})` on SHOW, `@tree_expanded_dirs` directly on `:commit`.
- **`file_filter`** — shared filter string; `filter_files` assigns `%{"filter" => value || ""}` (debounced on the client by the component's `phx-debounce`); `switch_repo` resets it to `""`.
- Both are mount-seeded and deliberately absent from the load-result map (survive debounced reloads).

## Reload policy (task broadcasts, no polling)

- `mount/3` subscribes to `EvoGit.PubSub` `"tasks"` when `connected?/1`. `{:task_updated, task_id, status, node}` is node-filtered FIRST: only the reviewed task's own broadcast from the viewed node STASHES `status` in `@review_broadcast_status`; every event is then forwarded to `NodeAware.handle_task_info/2` (returns `{:noreply, socket}` — never re-wrap).
- `handle_info(:node_aware_reload_tasks)` (NodeAware's shared 300ms trailing-edge debounce) ALWAYS refreshes the sidebar via `NodeAware.reload_tasks/1`, then re-evaluates materiality — `review_reload_material?/2`: `:none` (no reviewed-task broadcast since the last evaluation) ⇒ skip; `nil` (a review-status-only mutation) ⇒ material; a concrete status ⇒ material only when it differs from the loaded `@task_status`. Only a material marker starts a review-data reload (the marker is reset to `:none` either way).
- Other tasks' broadcasts and foreign-node broadcasts never reload review data; `{:task_deleted, ...}` never does (it only feeds the sidebar reload, node-filtered by NodeAware).
- No polling anywhere; remote nodes are served by the same push contract.

## Archive tab — paged load & export decision

The Archive tab ALWAYS renders for a loaded task (`page_tabs show_archive={true}`); the lite page load cannot know whether the task has an archive.
Opening the tab starts the FIRST page (`ArchiveLoad.ensure_loaded/1` → `list_task_archives(node, task_id, limit: 100, offset: 0, include_results: false)` in a supervised child), cached by `{task_id, node}`: tab round-trips, `{:review_data_loaded, ...}` reloads and merge-check results never refetch it.
The header count line reads the SERVER total (falling back to the loaded count) and, while `loaded < total`, shows `N agents — showing 1–100` plus a "Load more" button below the tree.
"Load more" (`load_more_archive`) appends the next page at `offset = length(archive_records)`; a retried/overlapping page is deduped by `agent_id`, and the button disappears once `loaded >= total`.
An append failure keeps the loaded page on screen and renders an inline error line + Retry (the SAME event); a first-page failure renders the retry-able error state (`retry_archive`).
No paged entry carries its heavy `"result"`: each tree node offers "Show result" (`load_archive_agent_result`) which fetches ONE agent's full entry, caches it by `agent_id` and folds it into the loaded page (`ArchiveHelpers.merge_entry/2`); the result renders through the same 8 KB `blob_preview` cap. Rendering NEVER fetches.
A `{:task_updated, task_id, _, node}` broadcast for the REVIEWED task on the viewed node drops the per-agent result cache (`ArchiveLoad.invalidate_agent_results/1`, which also strips the folded `"result"` from the loaded entries so they can be refetched) while the loaded pages and their total stay.
A task/node change (`ArchiveLoad.sync_context/1`, called at the top of `start_async_load/2`) resets pages, total, pager state and per-agent results and refetches only when the Archive tab is the visible one, so the panel never sits on a dead skeleton.
There is no polling and no automatic retry anywhere on this path.
The Export JSON link renders only after a `:loaded`, non-empty archive (`ArchiveLoad.export_available?/1`) — the export endpoint 404s without an archive, so no link can be shown that would fail.
The archive section's own Export JSON link is node-aware: its href carries `?node=<target_id>` when a remote node is viewed and stays bare `/tasks/<task_id>/export` on the local node.
The archived tree is capped at 300 records per render (`@archive_max_records` in `review_components.ex`; paging is the real memory bound, and each record's text is still capped by `blob_preview` at 8 KB result / 4 KB objective); beyond that a note points at the JSON export.
Records whose `parent_id` is on an unloaded/broken page are promoted to top-level tree nodes (never dropped) and still count as shown.

## Consumed-vs-transferred (payload audit)

- `get_task_lite/2`: consumed = `opts[:path]`/`opts[:prompt]||opts[:objective]`/`opts[:foreign_repos]`, `result` keys (commit_sha/branch_name/result/pr_url/pr_title + top-level `repos` — both `:repos`/`"repos"` key shapes), `review_status`, `status`, `base_sha`, `commit_sha`, `usage`, `agent_count`, `model_id`, `started_at`, `finished_at`. `logs` transferred but never read; NO archive is transferred (the lite read nils `archive_metadata` and drops the result's `:archive_records`).
- `list_task_archives/3` (only from the Archive tab): paged reads of `%{entries: [STRING-keyed map], total: non_neg_integer}`, 100 entries with `include_results: false` (so no `"result"` key is transferred); entries are rendered by `archive_review_section`, individual record fields are never read by the page itself. `get_agent_archive/3` transfers ONE full entry (including `"result"`) only when its "Show result" is clicked.
- `load_review_metadata*` (8-key map): consumed = `base_sha`, `changed_files_count`, `total_additions`/`total_deletions` (read per repo via `aggregate_stats/1`), `files` (per-file `path`/`status`/`additions`/`deletions`/`language`/`diff`). Transferred-but-never-read: top-level `commit_sha`, `diff_stat`, `diff` (nil).
- `list_commits*` (6-field `%CommitInfo{}`): consumed = sha, short_sha, message, author_name, date. `author_email` unused.
- `check_merge/4` → per-repo `merge_status` `%{state:, target:, files:}`; `target` server-side only.
- Action RPCs run in the spawned task, ONE call per repo acted on (`merge_all` fans out one per unresolved CHANGE-BEARING repo): `merge_branch/3,4` via `:review_merge_runner`, `reject_branch/3` via `:review_reject_runner`, `create_github_pr/5`, `start_task/3` (Extract Skills + auto-resolve), `set_review_status/3` (resume/ignore/completion), `set_review_metadata/4` (from the load task, not an action) — only ok/error tags and flash-relevant values are consumed.
- **Gotcha**: `default_merge_target` actually returns `{:ok, name}` — LoadData matches `{:ok, name}`.

## Test strategy

Tests must flush the async load before asserting content: the file-local `flush_review_load/2` (drains the mount-time async messages, then delegates to the shared `EvoDashWeb.TestHelpers.flush_loading/4` polling the "Loading review data..." marker — `render_async/2` does NOT work here, the load runs in a plain `Task.Supervisor` child, not a LiveView async task) + `settle_debounced_task_reload/1` for the 300ms trailing-edge reload + `wait_until/2` for post-send synchronization. Direct `send(view.pid, {:review_data_loaded, task_id, node(), generation, {:ok, assigns}})` injects results (stale-guard cases use wrong task/node/generation). Merge-check assertions inject the 6-tuple `{:merge_check_result, task_id, node(), repo_id, target, result}` (or let the load result land first — `MergeCheck.maybe_start` runs only after it). Multi-repo coverage: repo-list construction, per-repo merge/reject through the runner seams (one repo acted on per event — the stubbed runner messages the test with its call args), `merge_all` batch folding (one runner call per unresolved CHANGE-BEARING repo + the summary flash; a no-change repo is never sent to the runner), 6-tuple merge-check injection, foreign-repo carry for auto-resolve/resume.

## Auto merge-conflict resolution (async merge check + auto-resolve)

Each per-repo card renders a merge-status block (driven by that repo's `merge_status`). The logic lives in `EvoDashWeb.ReviewLive.MergeCheck`; ReviewLive's `handle_event`/`handle_info` clauses are thin wrappers and the `repo_available?/2` gate is shared (no duplication). After the review-data load result, `maybe_start/1` spawns `EvoGit.RemoteNode.check_merge/4` (non-mutating dry-run) in a supervised Task for EVERY repo under the same gates the cards render with, skipping duplicates already `:checking` the same target. Each result arrives as `{:merge_check_result, task_id, node, repo_id, target, result}`; `handle_result/6` maps `{:ok, :clean}` → `%{state: :clean, files: []}`, `{:ok, {:conflict, files}}` → `%{state: :conflict, files:}`, `{:error, _}` → `%{state: :error}` (renders nothing), and drops stale messages. `auto_resolve` (PRIMARY-scoped — a conflict in a FOREIGN repo is surfaced on that repo's own card and is NOT auto-resolved): `MergeCheck.auto_resolve_payload/1` (PURE — guarded on the primary's `:conflict` state with a binary target, else `:unavailable`) yields `%{opts:, to:}` with `[path:, mode: "simple", objective: <plain interpolated prompt — NOT gettext>, starting_commit:, merge_from: task_id, merge_target:]`; the LiveView then runs `Actions.auto_resolve/3` off-process (best-effort `set_review_status(:continued)` then `start_task/3`) and, on success, flashes and `push_navigate`s to `/projects` preserving `?node=`. `merge_target_change` updates the changed repo's `default_merge_target` (params `repo_id`, blank → `"primary"`) and re-runs that repo's check. The manual per-repo Merge button + conflict flash remain the fallback.

## SHAs

The page's base/end commits come from `EvoGit.TaskInfo` fields `base_sha`/`commit_sha` (both nil until review metadata is persisted) and the task result map's `commit_sha`/`branch_name` — all PRIMARY-scoped. `LoadData.build_assigns/3` falls back to `task.commit_sha`, derives `base_sha` from `load_review_metadata` or `task.base_sha`, and persists both via `set_review_metadata` (primary-scoped fire-and-forget) when loading from a live branch. Post-merge/reject the page re-loads diffs/commits from the persisted SHAs — foreign repos use their per-repo `base_sha` (skipped when nil).

## Resume flow

`handle_event("resume", ...)` is PRIMARY-scoped — repo-scoped fields come from the `"primary"` entry explicitly. The `:resume` action writes review_status `:continued` off-process, then the success branch `push_navigate`s to `/projects?resume_from=<task_id>&starting_commit=<commit_sha>&project=<repo_path>[&node=<id>]` (manual `&node=` suffix — the URL already has a query string). `ProjectsLive.handle_params/3` reads those query params into `@task_starting_commit`/`@task_resume_from` (auto-expanding Advanced Options + `maybe_restore_foreign_repos_from_task/2`), and `do_task_submit/4` threads `:starting_commit`/`:resume_from` into `TaskRegistry.start_task(:evolve, opts)`. Remote nodes work too: the remote `handle_params` branch routes `?project=` through `ProjectFlow.spawn_remote_project_activation/3`, which restores the resumed task's foreign repos INSIDE the supervised activation task (node-aware `NodeContext.get_task/2`), and the local `maybe_restore_foreign_repos_from_task/2` covers the local branch. Backend: `ResumeContext.apply_resume_context/3` → `Runtime.Evolution.run/2`.

## Async rules & module sizes

- Loads: `EvoDash.TaskSupervisor` + `EvoDash.SafeCall.run/1` inside the child + one `send(parent, {...})` + a matching `handle_info` (load, merge check, archive load). Actions: `spawn_action/4` (supervised, `SafeCall`-wrapped `Actions` call, ALWAYS reports `{:review_action_result, ...}`) + `apply_action_result`/`clear_action_state`.
- PubSub: the `"tasks"` subscription + `NodeAware.handle_task_info/2` 300ms trailing-edge debounce + the materiality check (see Reload policy). Client hooks: `push_event("scroll_to_file", %{target_id: "file-section-#{file_path_to_id(path)}"})`, consumed by the `DiffViewer` JS hook.
- No `try/rescue` in these files: the single deliberate exit-catch boundary is `EvoDash.SafeCall` (justified comment there); everything else is normalized to ok/error values.
- **Module sizes (deliberate, per Genesis file-size policy)**: `review_live.ex` is ~2,300 lines — a cohesive single-page LiveView owning render + all review wiring (event handlers, the per-repo resolution state machine, the action/handle_info apply layer, the files-toolbar tree/filter state); the off-process action executors live in `review_live/actions.ex`, the load in `review_live/load_data.ex`, the merge check + auto-resolve payload in `review_live/merge_check.ex`, the paged archive state machine, per-agent result cache + panel in `review_live/archive_load.ex`. Do not split render/wiring further without a clear seam.

## Constraints

- Nothing in the LiveView process touches the store / registry / git / `EvoDash.NodeContext` — loads and actions go through `EvoDash.TaskSupervisor` children wrapped in `EvoDash.SafeCall.run/1`; do not add synchronous RPCs to `handle_params/3` or `handle_event/3`.
- Every spawned task must report a result message (a dead child would wedge the in-progress state); a new action needs a matching `apply_action_result/4` clause, a `clear_action_state/3` shape, and an `@review_action`/`@busy_repos`/`@action_loading` decision.
- Diffs stay lazy — never fetch full diffs on page load.
- Merge/reject act on ONE repo per event (the `repo_id` named by the clicked form/button), each repo carrying its own `resolution`; completion is the aggregate `completion_status/2` (all change-bearing repos TERMINAL). PRIMARY-scoped operations (`resume`, `create_pr`, `confirm_extract_skills`, `auto_resolve`, `set_review_metadata`, the `:commit` route, the `page_header` repo fields) must resolve the `"primary"` entry explicitly, never the active-repo-projected flat assigns.
- Repo-keyed state on SHOW (`selected_file`/`expanded_files`/`file_context_levels`/`tree_expanded_dirs`); flat on `:commit` (including `tree_expanded_dirs` — no `"commit"` key convention; the flat map is read directly).
- `?node=` preserved on every navigation (`with_node_param/2`; manual `&node=` when the URL already carries a query string — resume/ignore).
