# ProcessesLive — Managed OS Processes Page

## Intent

Support modules for `EvoDashWeb.ProcessesLive` (`GET /processes`): the dashboard view of every execution Genesis tracks (agent tool calls and background jobs), with live status, resource stats and operator controls (pause / resume / terminate / kill).
The page itself (`../processes_live.ex`) owns assigns, URL filters, PubSub wiring and events; these modules hold the pure formatting, the async loader and the control boundary.
Executions are either `:builtin` (ran INSIDE the BEAM — a built-in tool such as `read`/`write`/`edit`/`rg`/`elixir_eval`; no OS process, so no pid/unit, uptime, CPU, memory or controls) or external OS processes behind `:systemd`/`:bwrap`/`:sandbox_exec`/`:none`.
Node-aware like every other page: the viewed node's process manager is reached through `EvoDash.NodeContext`, never directly.
The read and control paths are LOCAL-FIRST: `NodeContext.list_processes/2` and `NodeContext.process_control/4` call `EvoGit.ProcessManager` in-BEAM when the viewed node IS this BEAM, and use the cross-node RPC only for a genuinely remote viewed node.
The execution table body is a keyed LiveView stream (`phx-update="stream"`, `dom_id` `process-row-<id>`), so one execution update patches one row instead of every row.

Labels are gettext-FREE English — the render layer wraps the translatable ones. |
| `EvoDashWeb.ProcessesLive.Load` | `load.ex` | The async, exit-safe initial snapshot. `start/1` bumps the monotonic `:load_seq` assign, paints `executions_loading: true`, and spawns ONE `EvoDash.TaskSupervisor` child (`run/4`); the node and core-side filters (`Load.core_opts/1`) are read from the socket BEFORE the spawn, so a later node switch cannot retarget an in-flight request. The child calls the runner inside `EvoDash.SafeCall.run/1` and ALWAYS sends `{:processes_loaded, seq, node, {:ok, list}} \| {:error, reason}}` to the LiveView, so a dead/busy RPC target (a `GenServer.call` exit) becomes an error value and the loading flag can never stick. `core_opts/1` derives ONLY `:agent_id`/`:task_id` from the `:agent_filter`/`:task_filter` assigns (`typed_id/1` turns numeric strings into integers); status/kind/text narrowing is applied to the already-loaded rows by the page's derived assigns (`recompute/1`), never in `render/1`. |
| `EvoDashWeb.ProcessesLive.Actions` | `actions.ex` | The control boundary. `control/4` runs the control runner inside `EvoDash.SafeCall.run/1` and returns `:ok \| {:error, term()}`; the PAGE spawns it through `EvoDash.SafeCall.start/3` and never calls it inline. `validate_reason/1` → `:ok \| :blank`; `result_message/2` → `{:info \| :error, message}` (all messages gettext-wrapped, unknown reasons fall back to a generic line); `default_reason/1` (`:pause`/`:resume` → the canned `pause_reason/0`/`resume_reason/0`). Precise core answers get their own line: `:unsupported`, `:terminal`, `:not_found`, `:no_handle`, `:invalid_signal`, and `:no_os_process` (a builtin execution has nothing to signal — the UI hides the controls, this is the race/remote fallback). |

## Test Seams (app env, `:evo_dash`)

- `:processes_page_load_runner` — 2-arity `(node, opts)`, default `&EvoDash.NodeContext.list_processes/2`, resolved AT SPAWN TIME inside `Load.run/4` (so a test can swap it before a load and keep it for the whole request).
- `:processes_control_runner` — 4-arity `(node, id, action, reason)`, default `&EvoDash.NodeContext.process_control/4`, resolved AT CALL TIME inside `Actions.control/4`.
- `:processes_entering_ttl_ms` — integer ms a newly joined row keeps the enter-animation class, default `1500`, resolved AT CALL TIME in `ProcessesLive.entering_ttl_ms/0` (a non-integer/negative value falls back to the default); production never sets it.

## Page Contracts
The workbench tab rail owns the page name, so the page renders no in-canvas title or subtitle and the filter bar is its first row (behind the remote connection gate when that gate is active).

- **Async load** — exactly ONE self-message tag, `{:processes_loaded, seq, node, result}`, guarded by the STALE-PAIR check `seq == assigns.load_seq and node == assigns.current_node`: a superseded load and a load for a node the user already left are both dropped. `{:ok, list}` replaces `executions` and sets `executions_loaded`; anything else sets `executions_error` (rendered through `Format.term_text/1`) while keeping the page usable, and the error block offers Retry (`retry` → `Load.start/1`). No load in `mount/3`; a load is started from `handle_params/3` (connected only) on the first visit or on a node / core-filter change, which first clears `executions`, `executions_loaded`, `entering` and any open confirm modal, so rows from the previous node can never linger and a terminate modal opened on one node can never be confirmed against another. There is NO polling.
- **Push events** — the page subscribes to `EvoGit.PubSub` topic `"processes"` only when `connected?/1`, and every clause is ignored unless `NodeAware.event_from_current_node?(assigns, node)`: `{:process_started, execution, node}` (prepend when the id is absent), `{:process_updated, id, changes, node}` (merge ONLY a map `changes` onto a row that already exists — `Map.replace!` per key for the `%EvoGit.ProcessManager.Execution{}` struct), `{:process_exited, execution, node}` (replace by id, prepend when absent), `{:process_sample, node, _seq, entries}` (merge ONLY `:status`/`:stats` from each well-formed `%{id: id}` entry onto a matching row; unknown ids and malformed entries are skipped), `{:process_control, id, entry, node}` (append the entry to that row's `control_log` EXACTLY ONCE — a repeat is detected by comparing the newest existing entry's `Format.entry_get/2` `:at` + `:action`; a non-list `control_log` becomes `[entry]`). Every handler is find-or-nil: an event for an unknown id is a no-op, never a crash.
- **New-row enter animation** — the list is newest-first, so a genuinely new execution appears at the HEAD. `upsert_execution/3` checks `find_execution/2` BEFORE inserting (the same guard that suppresses a duplicate prepend), so only an id the page did not already show is marked in the `:entering` MapSet (STRING ids via `Format.id_string/1`, `""` rejected). Each mark schedules ONE `{:clear_entering, ids}` self-message after `:processes_entering_ttl_ms`, whose handler removes exactly those ids (`MapSet.difference/2`) — so a later `{:process_sample, …}`/`{:process_updated, …}`/`{:process_exited, …}` patch of an already-cleared row can never restart the animation. Covers both the `{:process_started, …}` prepend and the unknown-id `{:process_exited, …}` prepend. The initial load, a refetch, a Retry and a node/filter switch NEVER animate (`apply_load_result/2` and the `handle_params/3` reset clear `:entering`), and timers are only armed on a connected socket. The render passes `entering={MapSet.member?(@entering, Format.id_string(id))}` to `ProcessComponents.execution_row/1`, which adds the literal `process-row-enter` class to the summary `<tr>`; the keyframe lives in `assets/css/app.css` (fade in + 8px downward slide + a fading `--color-primary-standalone` tint, 0.9s) and is disabled under `prefers-reduced-motion: reduce`. Row DOM identity stays `id={"process-row-<id>"}`, the stream `dom_id`, so a patch reaches exactly one `<tr>` and an enter animation restarts only for a row that was genuinely re-created.
- **Keyed row stream** — the table body is `<tbody id="processes-rows" role="rowgroup" phx-update="stream">` rendering `<ProcessComponents.execution_row :for={{_dom_id, execution} <- @streams.executions} …>`, so a push event patches ONE row instead of every row.
  The stream is configured once in `mount/3` with `stream_configure(:executions, dom_id: &row_dom_id/1)` BEFORE the stream exists, and `row_dom_id/1` produces exactly the `<tr>` id the component renders from the same record — `"process-row-" <> (Format.id_string(id) || "unknown")`, with a nil/absent id taking the component's `"unknown"` arm — because `phx-update="stream"` matches children by element id.
  The component's `id` attr still receives the normalized process id (`Format.id_string/1`), which keeps `process-toggle-<id>`, the `:entering` lookup and the control button ids unchanged.
  `:executions` stays a plain list (the source for `recompute/1` and every merge helper); `@streams.executions` is the render projection only.
  Two operations own the projection: `stream_reset/1` (`reset: true` over `@filtered`) and `stream_touch/2` (surgical per-id insert / delete).
  `stream_reset/1` runs on an `{:processes_loaded, …}` success, a node switch or core-filter change (from the `handle_params/3` path) and any status-tab / kind / text-search / agent-filter / task-filter change — the places where membership is recomputed globally.
  `stream_touch/2` runs from the incremental push handlers (`{:process_started, …}`, `{:process_updated, …}`, `{:process_exited, …}`, `{:process_control, …}`, `{{:process_control_result, …}, …}`, `{:process_sample, …}`, `{:clear_entering, …}` and `toggle_process_row`) — never a bulk re-insert of the whole filtered list, which would re-render every row.
  `stream_touch/2` deletes FIRST and then inserts: the row component renders a summary `<tr>` plus, when expanded, a sibling `process-details-<id>` `<tr>`, so a same-id re-insert alone would only morph the row element and leave a stale details row behind; both ids are dropped (`stream_delete_by_dom_id/3`) before the insert, and a row the filters now exclude is deleted only.
  The insert position comes from the row's index in `@filtered`, applied in ascending index order, so a batch that touches several rows lands each at its own place.
  Stream membership therefore mirrors `@filtered` exactly, so a filtered-out row is genuinely removed server-side rather than merely omitted from a shorter list.
  A `{:process_sample, …}` tick carries stats for every live execution, so `update_executions/3` compares each touched row against its previous version and only the rows whose stored map actually changed are streamed — an unchanged tick patches nothing.
- **ListEnter scope** — the `#processes-results` wrapper (the div holding the table) carries `phx-hook="ListEnter"` plus `data-list-enter-scope={list_enter_scope(assigns)}`, a stable binary identity of the current view (`"processes:<node>:<status>:<kind>:<q>:<agent>:<task>"`) so a filter or node change reseeds the hook's silent baseline and the re-rendered rows never animate.
- **Filter URL contract** — `?status=live|finished|all` (unknown → `live`), `?kind=tool_call|background_job` (omitted when `all`), `?q=<text>`, `?agent_id=<id>`, `?task_id=<id>`; blank values are omitted and the node param is appended MANUALLY as `&node=<id>` (or `?node=<id>` when the URL has no query string) because `EvoDashWeb.Helpers.with_node_param/2` always appends `?` and would corrupt a query-string URL. `set_status` / `set_kind` / `search` / `remove_agent_filter` / `remove_task_filter` each merge the current filters with the one override and `push_patch`. Status tabs narrow the already-loaded rows (no refetch); only `agent_id`/`task_id` reach the core (`Load.core_opts/1`).
- **Derived render state** — `:filtered`, `:counts` and `:filters_active` are assigns, never computed in `render/1`: ONE private `recompute/1` derives all three with `Format.filter/2` + `Format.counts/1` and is called from every place that mutates `:executions` or a filter assign (the load result's ok/error arms, every `"processes"` broadcast through `update_executions/2`, `{:clear_entering, …}` and `handle_params/3` after the URL filters are resolved).
  `recompute/1` only derives the assigns; the stream projection is synced separately by `stream_reset/1` (global membership changes) and `stream_touch/2` (the ids one push event touched).
  `update_executions/2` skips the recompute when the event left the row list untouched (`updated == previous`: a sample for an id this page does not show, a repeat `started` broadcast), so a 3-second tick no longer re-filters the whole list twice per render.
  Each tab's badge is `Format.counts/1` over `Format.filter(executions, filters without :status)`, so Live/Finished/All always agree with the rows the tab would show.
- **Controls (async)** — pause/resume run immediately with `Actions.default_reason/1`; terminate/kill open the confirm modal (`ProcessComponents.confirm_modal/1`, `confirm: %{id:, action: :terminate | :kill, execution:}`) and REQUIRE a NON-EMPTY reason: `Actions.validate_reason/1` returning `:blank` sets `confirm_error` plus a "A reason is required." flash and performs NO control call, otherwise the TRIMMED reason string is passed unchanged to the runner with `{:signal, "TERM"}` (terminate) or `:kill` (the flash label stays `:terminate`/`:kill`).
  No control call runs in the LiveView process: `start_control/5` spawns `Actions.control/4` through `EvoDash.SafeCall.start/3` and it settles as `{{:process_control_result, id, action}, result}` — `action` being the FLASH label, so `Actions.result_message/2` still produces the `{kind, message}` pair.
  The settled result is normalized by the page's `normalize_control_result/1`: `{:ok, :ok}` → `:ok`, `{:ok, {:error, reason}}` and a SafeCall `{:error, reason}` → that `{:error, reason}`, and any other term → `{:error, {:unexpected_result, other}}`, so a surprise value is a flashable error instead of a crash.
  A per-row `:action_busy` map (keyed `Format.id_string/1` of the id, value the action) drops a second click on the same row while its call is in flight; it is cleared on EVERY outcome — success, failure and a SafeCall-captured exit alike — and a `SafeCall.start/3` failure (no result message will ever arrive) flashes `Actions.result_message/2` for `{:error, reason}` instead of marking the row busy, so a control can never wedge.
  `:ok` closes the confirm modal when the open modal is still the `{id, action}` that started the call; `{:error, _}` keeps that modal open with the operator's text preserved (`:confirm_reason` is assigned at submit time) and the error shown in place, and a result for a modal the operator already closed only flashes.
- **Rendering the builtin/external split** (`ProcessComponents.execution_row/1`, `execution_details/1`) — a builtin execution shows `—` in Target/Uptime/CPU/Memory and renders NO pause/resume/terminate/kill cluster (`Format.external?/1` gates the whole actions cell); external rows keep the existing status-gated buttons. The Exit column uses `Format.exit_label/1` (code, else a non-`:exited` reason label, else `—`); the expanded detail block shows Target, Exit Code, Reason (`gettext`-wrapped labels with Chinese translator comments for `In-process (built-in)`, `Owner died`, `No OS process`, `Killed by`), Runtime and Backend. `compact_rows/1` (the `/agents` panel) keeps its markup and inherits the `—` figures.
- **Control log** — rendered from `Format.control_log/1`; entries written through this page's control path carry actor `:remote` (local in-BEAM and remote RPC alike), which `Format.actor_label/1` renders as "Dashboard" (the operator acting through this page), never as a raw atom.
- **Assign seeding** — every assign the page renders is either its own (`mount/3`'s `assign/2`) or seeded defensively with `assign_new/3` in `seed_layout_assigns/1` (`current_node`/`current_node_name`/`current_node_id`/`remote_status`/`remote_targets`/`connection_statuses`/`running_tasks`/`pending_tasks`/`session_list*`/`current_session_id`/`accent_color`/`desktop_quit_confirm`/`update_status`/`guide`), so `render/1` reads `@key` and never an `assigns[:key] || default` fallback. The `NodeAware` / `Appearance` / `DesktopQuit` / `UpdateStatus` / `Guide` on-mount hooks run BEFORE `mount/3` and always win, so the seeds change no behaviour.
- **Remote gate** — the page body is replaced by `EvoDashWeb.RemoteGateComponents.remote_connection_gate(assigns)` (called FULLY QUALIFIED with the assigns map) whenever `gate_active?/1` is true, inside the normal `Layouts.app` shell.

## Tests

- `test/evo_dash_web/live/processes_live_test.exs` (`async: false` — process-global seams + the shared `"processes"` PubSub topic) covers load/error/stale guards, every push event, URL filters, the enter animation (`process-row-enter` on a new row only, cleared after the TTL seam, never re-added), the async control contract (a control in flight keeps the socket answerable, a duplicate click is dropped, a success/failure both clear the busy marker) and the derived `:filtered`/`:counts`/`:filters_active` assigns (asserted through `:sys.get_state`, i.e. with NO render, which pins the "no filtering in `render/1`" contract).
  Control assertions await the pushed result (`wait_for_html/2` on the flash, or a `wait_until` on `:action_busy`) exactly like the `/tasks` pause/resume tests — never a fixed sleep.
  The stream projection is pinned through the rendered DOM: `#process-row-<id>` presence, per-id uniqueness, head-first row order, the `#process-row-proc-101` vs `#process-row-proc-1` prefix-collision case, a filtered-out row's ABSENCE (a genuine `stream_delete`) and `#process-toggle-<id>[aria-expanded]` across the collapse/expand round trip.
- `test/evo_dash_web/components/process_components_test.exs` covers the rendered markup (builtin `—` cells and no control buttons, external controls, Exit column, detail block, `entering` class).
- `test/evo_dash_web/components/process_format_test.exs` (`async: true`, pure) unit-tests every Format helper over structs, struct-shaped maps, string-keyed maps and garbage.
