# ProcessesLive — Managed OS Processes Page

## Intent

Support modules for `EvoDashWeb.ProcessesLive` (`GET /processes`): the dashboard view of every execution Genesis tracks (agent tool calls and background jobs), with live status, resource stats and operator controls (pause / resume / terminate / kill).
The page itself (`../processes_live.ex`) owns assigns, URL filters, PubSub wiring and events; these modules hold the pure formatting, the async loader and the control boundary.
Executions are either `:builtin` (ran INSIDE the BEAM — a built-in tool such as `read`/`write`/`edit`/`rg`/`elixir_eval`; no OS process, so no pid/unit, uptime, CPU, memory or controls) or external OS processes behind `:systemd`/`:bwrap`/`:sandbox_exec`/`:none`.
Node-aware like every other page: the viewed node's process manager is reached through `EvoDash.NodeContext`, never directly.
The read and control paths are LOCAL-FIRST: `NodeContext.list_processes/2` and `NodeContext.process_control/4` call `EvoGit.ProcessManager` in-BEAM when the viewed node IS this BEAM, and use the cross-node RPC only for a genuinely remote viewed node.

## API Surface

| Module | File | Purpose |
|--------|------|---------|
| `EvoDashWeb.ProcessesLive.Format` | `format.ex` | Pure, TOTAL presentation helpers — no I/O, no assigns, never raises: `live_statuses/0` (`[:starting, :running, :paused]`), `live?/1`, `finished?/1`, `status_tabs/0` (`["live", "finished", "all"]`), `normalize_status_tab/1` (unknown → `"live"`), `normalize_kind/1` (`"tool_call"`/`"background_job"`, anything else → `"all"`), `status_label/1`, `status_badge_class/1`, `status_dot_class/1`, `kind_label/1`, `backend_label/1` (`:builtin` → `"In-process"`, `:none` → `"Unsandboxed"`, `systemd`/`bwrap`/`sandbox-exec` untranslated, nil → `"—"`), `runtime_label/1` (`:foreground`/`:background`), `builtin?/1`, `external?/1`, `sampleable?/1` (external AND an OS identity: integer `os_pid` or a present `unit`/`job_id`), `target_label/1`, `command_text/1`, `tool_name/1`, `exit_code_label/1` (raw integer-or-`"—"`), `exit_label/1` (exit code, else the reason label when the termination was not a plain `:exited`, else `"—"`), `reason_label/1` → `reason_text/1` (`:exited`/`:timeout`/`:invalid_arguments`/`:owner_died`/`:no_os_process`/`{:killed_by, actor}` → "Killed by …"/`{:crashed, detail}` → "Crashed: …"/nil → `"—"`), `term_text/1` (any term → display text, `nil` → `"—"`), `uptime/2`, `duration_label/1`, `human_bytes/1`, `memory_bytes/1`, `memory_label/1`, `cpu_label/1`, `filter/2`, `matches?/2`, `counts/1` (→ `%{live: n, finished: n, all: n}`), `control_log/1`, `actor_label/1`, `action_label/1`, `signal_label/1`, `entry_get/2`, `entry_time/1`, `id_string/1`. `uptime/2`, `cpu_label/1`, `memory_label/1` and `target_label/1` return `"—"` for a builtin execution (guard first, never rely on absent stats). `filter/2` opts keys: `:status` (tab string), `:kind`, `:q` (case-insensitive text match), `:agent_id`, `:task_id`; non-matching/unknown shapes degrade to `[]`/`false`/`"—"`. Labels are gettext-FREE English — the render layer wraps the translatable ones. |
| `EvoDashWeb.ProcessesLive.Load` | `load.ex` | The async, exit-safe initial snapshot. `start/1` bumps the monotonic `:load_seq` assign, paints `executions_loading: true`, and spawns ONE `EvoDash.TaskSupervisor` child (`run/4`); the node and core-side filters (`Load.core_opts/1`) are read from the socket BEFORE the spawn, so a later node switch cannot retarget an in-flight request. The child calls the runner inside `EvoDash.SafeCall.run/1` and ALWAYS sends `{:processes_loaded, seq, node, {:ok, list}} \| {:error, reason}}` to the LiveView, so a dead/busy RPC target (a `GenServer.call` exit) becomes an error value and the loading flag can never stick. `core_opts/1` derives ONLY `:agent_id`/`:task_id` from the `:agent_filter`/`:task_filter` assigns (`typed_id/1` turns numeric strings into integers); status/kind/text filtering is render-time. |
| `EvoDashWeb.ProcessesLive.Actions` | `actions.ex` | The control boundary. `control/4` runs the control runner inside `EvoDash.SafeCall.run/1` and returns `:ok \| {:error, term()}`; `validate_reason/1` → `:ok \| :blank`; `result_message/2` → `{:info \| :error, message}` (all messages gettext-wrapped, unknown reasons fall back to a generic line); `default_reason/1` (`:pause`/`:resume` → the canned `pause_reason/0`/`resume_reason/0`). Precise core answers get their own line: `:unsupported`, `:terminal`, `:not_found`, `:no_handle`, `:invalid_signal`, and `:no_os_process` (a builtin execution has nothing to signal — the UI hides the controls, this is the race/remote fallback). |

## Test Seams (app env, `:evo_dash`)

- `:processes_page_load_runner` — 2-arity `(node, opts)`, default `&EvoDash.NodeContext.list_processes/2`, resolved AT SPAWN TIME inside `Load.run/4` (so a test can swap it before a load and keep it for the whole request).
- `:processes_control_runner` — 4-arity `(node, id, action, reason)`, default `&EvoDash.NodeContext.process_control/4`, resolved AT CALL TIME inside `Actions.control/4`.
- `:processes_entering_ttl_ms` — integer ms a newly joined row keeps the enter-animation class, default `1500`, resolved AT CALL TIME in `ProcessesLive.entering_ttl_ms/0` (a non-integer/negative value falls back to the default); production never sets it.

## Page Contracts

- **Async load** — exactly ONE self-message tag, `{:processes_loaded, seq, node, result}`, guarded by the STALE-PAIR check `seq == assigns.load_seq and node == assigns.current_node`: a superseded load and a load for a node the user already left are both dropped. `{:ok, list}` replaces `executions` and sets `executions_loaded`; anything else sets `executions_error` (rendered through `Format.term_text/1`) while keeping the page usable, and the error block offers Retry (`retry` → `Load.start/1`). No load in `mount/3`; a load is started from `handle_params/3` (connected only) on the first visit or on a node / core-filter change, which first clears `executions`, `executions_loaded`, `entering` and any open confirm modal, so rows from the previous node can never linger and a terminate modal opened on one node can never be confirmed against another. There is NO polling.
- **Push events** — the page subscribes to `EvoGit.PubSub` topic `"processes"` only when `connected?/1`, and every clause is ignored unless `NodeAware.event_from_current_node?(assigns, node)`: `{:process_started, execution, node}` (prepend when the id is absent), `{:process_updated, id, changes, node}` (merge ONLY a map `changes` onto a row that already exists — `Map.replace!` per key for the `%EvoGit.ProcessManager.Execution{}` struct), `{:process_exited, execution, node}` (replace by id, prepend when absent), `{:process_sample, node, _seq, entries}` (merge ONLY `:status`/`:stats` from each well-formed `%{id: id}` entry onto a matching row; unknown ids and malformed entries are skipped), `{:process_control, id, entry, node}` (append the entry to that row's `control_log` EXACTLY ONCE — a repeat is detected by comparing the newest existing entry's `Format.entry_get/2` `:at` + `:action`; a non-list `control_log` becomes `[entry]`). Every handler is find-or-nil: an event for an unknown id is a no-op, never a crash.
- **New-row enter animation** — the list is newest-first, so a genuinely new execution appears at the HEAD. `upsert_execution/3` checks `find_execution/2` BEFORE inserting (the same guard that suppresses a duplicate prepend), so only an id the page did not already show is marked in the `:entering` MapSet (STRING ids via `Format.id_string/1`, `""` rejected). Each mark schedules ONE `{:clear_entering, ids}` self-message after `:processes_entering_ttl_ms`, whose handler removes exactly those ids (`MapSet.difference/2`) — so a later `{:process_sample, …}`/`{:process_updated, …}`/`{:process_exited, …}` patch of an already-cleared row can never restart the animation. Covers both the `{:process_started, …}` prepend and the unknown-id `{:process_exited, …}` prepend. The initial load, a refetch, a Retry and a node/filter switch NEVER animate (`apply_load_result/2` and the `handle_params/3` reset clear `:entering`), and timers are only armed on a connected socket. The render passes `entering={MapSet.member?(@entering, Format.id_string(id))}` to `ProcessComponents.execution_row/1`, which adds the literal `process-row-enter` class to the summary `<tr>`; the keyframe lives in `assets/css/app.css` (fade in + 8px downward slide + a fading `--color-primary-standalone` tint, 0.9s) and is disabled under `prefers-reduced-motion: reduce`. Row DOM identity stays `id={"process-row-<id>"}` so LiveView patching never restarts an animation.
- **Filter URL contract** — `?status=live|finished|all` (unknown → `live`), `?kind=tool_call|background_job` (omitted when `all`), `?q=<text>`, `?agent_id=<id>`, `?task_id=<id>`; blank values are omitted and the node param is appended MANUALLY as `&node=<id>` (or `?node=<id>` when the URL has no query string) because `EvoDashWeb.Helpers.with_node_param/2` always appends `?` and would corrupt a query-string URL. `set_status` / `set_kind` / `search` / `remove_agent_filter` / `remove_task_filter` each merge the current filters with the one override and `push_patch`. Status tabs stay RENDER-time (all rows are already loaded); only `agent_id`/`task_id` reach the core (`Load.core_opts/1`).
- **Counts** — each tab's badge is `Format.counts/1` over `Format.filter(executions, filters without :status)`, so Live/Finished/All always agree with the rows the tab would show.
- **Controls** — pause/resume run immediately with `Actions.default_reason/1` and flash `Actions.result_message/2`; terminate/kill open the confirm modal (`ProcessComponents.confirm_modal/1`, `confirm: %{id:, action: :terminate | :kill, execution:}`) and REQUIRE a NON-EMPTY reason: `Actions.validate_reason/1` returning `:blank` sets `confirm_error` plus a "A reason is required." flash and performs NO control call, otherwise the TRIMMED reason string is passed unchanged to the runner with `{:signal, "TERM"}` (terminate) or `:kill`. `:ok` closes the modal; `{:error, _}` keeps it open with the error so the operator can retry or adjust.
- **Rendering the builtin/external split** (`ProcessComponents.execution_row/1`, `execution_details/1`) — a builtin execution shows `—` in Target/Uptime/CPU/Memory and renders NO pause/resume/terminate/kill cluster (`Format.external?/1` gates the whole actions cell); external rows keep the existing status-gated buttons. The Exit column uses `Format.exit_label/1` (code, else a non-`:exited` reason label, else `—`); the expanded detail block shows Target, Exit Code, Reason (`gettext`-wrapped labels with Chinese translator comments for `In-process (built-in)`, `Owner died`, `No OS process`, `Killed by`), Runtime and Backend. `compact_rows/1` (the `/agents` panel) keeps its markup and inherits the `—` figures.
- **Control log** — rendered from `Format.control_log/1`; entries written through this page's control path carry actor `:remote` (local in-BEAM and remote RPC alike), which `Format.actor_label/1` renders as "Dashboard" (the operator acting through this page), never as a raw atom.
- **Remote gate** — the page body is replaced by `EvoDashWeb.RemoteGateComponents.remote_connection_gate(assigns)` (called FULLY QUALIFIED with the assigns map) whenever `gate_active?/1` is true, inside the normal `Layouts.app` shell.
