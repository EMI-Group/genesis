# UI Components

## Intent

Reusable Phoenix function components and layout templates for the EvoDash web interface — the presentation layer, organized by domain concern.

## Routing Table

- `layouts/` → the only template: the root layout shell (meta tags, CSRF, theme persistence).
- `agents_components/` → `CommitGraphView` + `commit_graph/{geometry,fold}.ex` — detail: `agents_components/CONTEXT.md`.
- `review_components/` → `DiffViewer`, `Header`, `Actions`, `RepoCards`, `Stats` + the review render caps — detail: `review_components/CONTEXT.md`.
- `settings_components/` → `CategoryMetadata`, `SettingCard`, the `provider_profiles/` family, `ProviderProfileFields`, `ProviderWizard`, `CustomAgentsEditor`, `CustomToolsPanel`, `ModelSelectionEditor`, `Sidebar`, `SearchResults`, the Save/Section/Card/Footer blocks — detail: `settings_components/CONTEXT.md`.
- `task_card_components/` → the card's helper submodules (`ResultRender`, `Options`, `Repos`, `Archive`, `Errors`, re-exported as `EvoDashWeb.TaskCardComponents` delegates) + the SUMMARY-map/`detail` contract and card caps — detail: `task_card_components/CONTEXT.md`.
- Workbench chrome — sidebar order + recent projects (`layouts.ex`, `workbench_component.ex`), Active Tasks (`workbench_active_tasks.ex`), the closed-by-default right panels, server-side search — §Workbench chrome; JS/CSS half → `../../../assets/CONTEXT.md`.
- Mobile conventions — branch-badge truncation (`ResultRender.branch_badge_class/0`) → `task_card_components/CONTEXT.md`; agent-tree `pl-7 xl:pl-0` indent → `agents_components/CONTEXT.md`.

### Templates, usage, flashes, theme

`layouts/root.html.heex` is the only template (meta tags, CSRF, LiveView title, asset links, client-side theme script); every component module `use EvoDashWeb, :html` and is a pure function component (`<.task_card task={@task} />`, `<.flash kind={:warning} flash={@flash} />`).
Flash kinds: `:info` → `alert-info` + `hero-information-circle` (success/informational), `:error` → `alert-error` + `hero-exclamation-circle` (errors, validation), `:warning` → `alert-warning` + `hero-exclamation-triangle` (warnings, missing config).
Theme is client-side except the shell accent: `Layouts.app`'s `attr(:accent_color, :string, default: "blue")` sets `data-accent-color` on `#app-layout` from `LiveHooks.Appearance`'s node-aware `EvoGit.Config.resolve([:appearance, :accent_color])` via `EvoDash.AccentCache`, and app.css's ten accent rules retarget `--color-primary`/`--color-accent` for that subtree; everything else (localStorage `phx:theme`, `data-theme`/`data-theme-mode`, `phx:set-theme`, `@custom-variant dark`, `themes: false` → `--color-base-*` + `color-mix`) is the parent `lib/evo_dash_web/CONTEXT.md` "Theming & Color System"; ProjectsLive's `--project-accent`/`--project-ring-accent` on `#dashboard-root` is separate, and shell chrome is token-based (`#app-layout` + sidebar `bg-base-200`, `#main-scroll`/`main#main-content` `bg-base-100`).

## Constraints

- Every component module **must** use `use EvoDashWeb, :html`; pure functions — assigns in, HEEx out, no side effects or direct LiveView process calls.
- Styling is Tailwind CSS + daisyUI — no inline CSS or external stylesheets; icons via `icon/1` (`hero-<name>[-style]`); layout templates live under `layouts/` (only the root layout exists).
- No component here renders a project's CONTEXT.md, the context tree, or a repository file listing; the only tree/graph renderers are `agents_components.ex` `path_tree/1`, the review changed-files sidebar (`review_components/diff_viewer.ex` `file_tree_sidebar/1`, built from a diff) and `commit_graph_view.ex`; "CONTEXT.md" appears only as mode copy in `EvoDashWeb.Helpers` (`mode_label/1`, `mode_description/1`, `detect_mode` hints).
- Shared cross-component utilities come from `EvoDashWeb.Helpers` (status badges, formatting, `blob_preview/2`/`list_preview/2`, `tip/1`).
- **Task cancellation UX (graceful + force kill)** (`task_card_components.ex`): inline Cancel is GRACEFUL (`phx-click="open_cancel_modal"`, no `phx-confirm`), visible `[:pending, :running, :awaiting_input]`; the three-dot dropdown adds a `text-error` "Force kill" item (`open_force_kill_modal`, `[:running, :awaiting_input, :cancelling, :pausing, :paused]` — a freezing or stuck pause must stay killable) under a `gettext("Danger zone")` divider (Delete keeps its `phx-confirm`); `:cancelling` renders IN-PROGRESS (warning pulsing dot + `gettext("Cancelling…")` via `Helpers.task_status_dot_class/1`/`task_status_tint/1`); `layouts.ex` owns NO task-status list and renders no cancel surface (the sidebar feed is `WorkbenchActiveTasks`).
- **Task pause / resume UX** (same card): a pause is a SNAPSHOT of the whole task tree (every agent frozen at its current position — no subagent call completed or merged, no child result collected) and a resume THAWS that tree in place with the same agent ids; **Pause** (`phx-click="open_pause_modal"`) for `[:running, :pausing]`, disabled — spinner + `gettext("Pausing…")` — while the tree is being frozen or an async call is in flight; **Resume** (`phx-click="resume_task"`) only for `:paused`, direct for `:clean`, through `phx-confirm` for `:dirty`; the `action_busy` attr (`%{to_string(task_id) => :pause | :resume}`, default `%{}`) disables BOTH and renders the matching spinner label (read totally via private `action_busy/2`). The `:paused` explainer strip is `:dirty` → amber warning (`:dirty` = the pause may have cut off an in-flight tool call: a restart/lease sweep, a quiesce timeout or a forced freeze) with the snapshot/thaw line (resuming thaws every agent with its saved context and continues where it stopped; a parent still waiting on its subagents stays waiting) vs `:clean`/nil → neutral `gettext("Paused by you — a snapshot of every agent. Resuming continues from it.")`; `:pausing` joins the amber busy family and pulses, `:paused` gets its OWN `info`/blue family and never pulses.
- **Task-status atom census** — a new status must be registered at every enumeration site (each falls back silently): `Helpers.task_status_badge/1`, `task_status_dot_class/1`, `task_status_tint/1`; the card's label `cond` + pulse gate (the `true ->` arm prints the RAW atom); private `show_review_button?/1`; `NodeAware.@active_statuses` + `partition_active_tasks/1`; `WorkbenchActiveTasks.live_task?/1` / `pulsing_status?/1` / `active_status_title/1` / `review_tasks/2`; the workbench history `@history_statuses` `<select>`; the TasksLive status `<select>` (raw SQL string, NO atom whitelist); the narrower busy sets in `ServerStatusController` + `SystemLive.UpdateCard`; the MCP `genesis_list_tasks` enum; `ReviewComponents.page_header`'s `String.capitalize(to_string(@task_status))` (NOT gettext-wrapped).
- Desktop-only surfaces stay inert outside the Tauri shell: directory/file pickers render only when `@tauri_detected and !@remote`, so the headless server shows the manual path inputs.
- **`phx-value-*` names must be snake_case** (`phx-value-task_id`, never a kebab suffix like `task-id`): LiveView strips only the `phx-value-` prefix, so a kebab attribute arrives as the hyphenated key `"task-id"` and a snake_case `handle_event` clause raises `FunctionClauseError` on a real browser click (LiveViewTest hides it because a test can pass values explicitly).

## Density & Type Scale (components)

The dashboard has ONE density + type scale — design record `docs/ui-density.md`, tokens `assets/css/density.css`; every component here renders on that ladder and never on an arbitrary font size (`text-[10px]`/`text-[11px]` are banned, 12px is the floor).
Roles: `text-2xs` 12/16 all-caps micro badges/chips/lane chips/kbd/counts ONLY · `text-xs` 13/18 metadata (ids, timestamps, helper lines, secondary cells) · `text-sm` 14/20 the UI default (labels, buttons, list rows, cells) · `text-base` 15/24 reading text/task titles/objectives · `text-lg` 17/24 card/section titles · `text-xl` 20/26 the one page h1 · `text-2xl` 24/30 hero.
Weights 400/500/600 only; `font-bold` is reserved for numbers, badges and `<strong>` (numeric metrics, status/type badges, agent ids), and bold headings are `font-semibold`.
Controls: `btn`/`input`/`select` 40px, `-sm` 32px, icon-only `btn-sm btn-square`, `btn-xs` only for an inline adornment beside a larger target (never the sole action); the same action weight uses the same size across components.
Rows: click targets ≥40px (`min-h-[var(--row-h)]`), dense inspector rows ≥36px (`min-h-[var(--row-h-sm)]`), two-line rows 48–56px (`min-h-[var(--row-h-tall)]`); the fixed 44px commit/gap row and the `.cg-scroll` chain stay CSS/JS-owned.
Cards: body `p-4` (`p-5` single hero card), modals `p-5 sm:p-6`, `rounded-xl` cards/panels, `rounded-lg` controls/chips, `gap-3` inside groups and `space-y-4` between cards.
CSS owns the coarse-pointer ≥44px touch floor and the ≥16px form-value floor (`.workbench-row` is `min-height: var(--row-h)` at `--text-sm` in `assets/css/workbench.css`; settings-group, project-picker, Create-menu and git file/branch rows override to `--row-h-sm`); markup never adds `min-h-11`/`pointer: coarse`/`max-sm:` touch variants.
The expanded sidebar width comes from `#sidebar[data-sidebar-collapsed="false"] { width: var(--workbench-left-width, 16rem) }` (`workbench.css:604`) — 256px, NOT the `w-60` utility; below `lg` it is `min(18rem, 86vw)` (`workbench.css:607`) and the collapsed rail is `w-16` (64px, toggled by the `SidebarCollapse` hook).
`.sidebar-label` is a JS marker class with NO CSS rule — `SidebarCollapse` adds/removes `hidden` on it (`assets/js/hooks/sidebar_collapse.js:280,312`).
The review diff panes stack until **xl** (`flex flex-col xl:flex-row`, `review_components/diff_viewer.ex:396`), not lg.
The Settings pane gutters are ONE rhythm: `px-4 sm:px-6` on every pane body, sticky section header, search-results body and save bar, matching `settings_live.ex`'s pane (vertical padding `py-4 sm:py-6` / `py-4` / `py-2.5`).
The review page's `h1` is `text-xl font-semibold` (pinned by `review_live_test.exs`'s `h1.text-xl` lookup).

### `try/rescue` Policy

`try/rescue` is an anti-pattern in these component files; do NOT wrap `String.to_existing_atom/1` in it — normalize untrusted DB data (e.g. archive maps after a Jason round-trip) with a whitelist map lookup (`@known_agent_keys` in `normalize_agent_keys/1`) + `Map.get/3` defaulting to the original key, and any new `try/rescue` MUST carry an inline justification comment.

## Blob & Collection Rendering Caps

No component here may render an unbounded task blob or collection: a task can carry a 100+ MB `result` and every component re-executes on EVERY render (nothing memoizes).
Previews come ONLY from `EvoDashWeb.Helpers` (never an ad-hoc `String.slice`): `blob_preview/2` → `%{text:, truncated?:, total_bytes:}` (UTF-8-safe prefix of at most `limit` BYTES, default `16_384`) and `list_preview/2` → `%{items:, total:, truncated?:}`, both TOTAL; a truncation note renders ONLY when `truncated?: true`, and a multi-MB string is previewed BEFORE `EvoDash.MarkdownRender.render/1`.
The ONLY uncapped paths are explicit user actions: `render_result_full/1` / `render_options_full/1` (`truncate: false`), `result_copy_text/1` / `objective_text/1`, and `TaskExportController`.

### Duration formatting

- `Helpers.format_duration/1` is the ONE millisecond duration formatter (`"#{Float.round(ms / 1000, 1)}s"` for an integer — `0` → `"0.0s"` — and `""` otherwise), imported through `use EvoDashWeb, :html`; `WorkbenchActiveTasks.format_elapsed/1` is a different unit (elapsed SECONDS), not a duplicate.

### Sidebar must stay `overflow-visible` — SSH node-selector dropdown clipping

The sidebar (`layouts.ex`) is a `z-50` stacking context above `#main-scroll` (`z-0`), so its dropdowns paint above the content and must never be clipped: `SidebarCollapse` adds `overflow-visible` in BOTH branches and `<aside id="sidebar">` carries `overflow-visible!` (removing either clips the node-selector dropdown `w-72` at the `w-60`/`w-16` edge; the comment above the `<aside>` documents the invariant).

### Sidebar bottom-bar dropdowns never auto-close (native `<details>`)

All three bottom-bar dropdowns (`theme_toggle_compact/1`, `language_selector/1`, `EvoDashWeb.NodeSelectorComponent`) are `<details>`-based: the panel opens/closes ONLY on a `<summary>` click and `SidebarCollapse.applyCollapsed/1` never removes `open`, so collapsing leaves an open dropdown floating over content (picking a theme leaves it open; a language pick reloads the page).
No reusable outside-click-close infra exists (no generic `details`-close or click-away handler in `app.js`; the old `toggle_dropdown`/`close_parent` JS commands are gone) — closing these is JS-side work owned by `apps/evo_dash/assets/`.
z-index contract (do not disturb): sidebar `<aside>` `z-50`; `#main-scroll` `z-0` (traps page modals below the sidebar); `.dropdown-content { z-index: 50 !important }` in `app.css`; mobile overlay + config warning banner `z-40`; hamburger `z-50`; `simple_nav` mode (WelcomeLive) renders branding only — the node selector lives inside `if !@simple_nav`.

### `Layouts.app` content background lives on the scroll container (`#main-scroll`)

The page content background is `bg-base-100` on **`#main-scroll`** — the scroll container (`flex-1 overflow-auto` inside the fixed `h-dvh` chain `body` / `#app-layout` `bg-base-200` → `#desktop-quit-hook` `flex-1 min-h-0`).
It must stay there: a scroll container's own background paints its visible box at every scroll offset, whereas a background on the non-scrolling inner `main#main-content` only paints the first viewport and would reveal `base-200` as a bottom seam.
`main#main-content` (`flex-1 min-h-0`) keeps a redundant same-color `bg-base-100` and MUST keep `min-h-0` — main being viewport-capped is what makes Projects' expanded task-form pin-to-bottom and Home's internal chat scroll work.

### In-shell page height contract (`main#main-content` content box)

`main#main-content` is a definite-height flex item, so its content box is already viewport minus the persistent top bar (`.workbench-top { flex: 0 0 var(--shell-topbar-h); }`) and minus the main padding (`px-4 … pt-4 pb-4`) — in-shell pages size against THAT box, never against the viewport; `.shell-fill` (app.css: `height: 100%; min-height: 0`) is the ONE utility for a page root that must FILL it (the `/phoenix/dashboard` iframe, the xl+ `AgentsLive` grid), while a page that scrolls normally keeps plain page flow and must not force `height`.
`--shell-topbar-h` is defined once on `#app-layout` in `workbench.css`, defaults to `calc(var(--control-h) + var(--card-pad) / 4)`, and resolves through `--workbench-topbar-size` to `calc(var(--touch-target) + var(--card-pad) * .75)` at widths up to `1023.98px` or with a coarse pointer.
No in-shell page takes `height`/`min-height` from `100vh`/`100dvh` (a `max-height` CAP may); `--shell-topbar-h` is the only way a cap may account for the top bar, and `#main-scroll` stays the ONE page scroller.

### `phx-click` + JS hook on the same element — double firing

`phx-click` + a `phx-hook` on the SAME element sends BOTH the hook's handling AND the `phx-click` event; don't put both on one element unless a matching `handle_event/3` clause exists.
The three directory-picker "Browse" buttons in `project_components.ex` (`project-path-browse-button`, `new-project-location-browse-button`, `foreign-repo-path-browse-button`) carry ONLY `phx-hook="DirectoryPicker"` — the hook pushes `"directory_pick"`, ProjectsLive runs `EvoDash.DirectoryPicker` and pushes back `picker_result:<picker_id>`; adding `phx-click` there has no clause → `FunctionClauseError` → LiveView crash (pinned by `project_components_test.exs`).
**Remote-node gating**: those buttons render only when `@tauri_detected and !@remote` — the picker runs on the LOCAL machine, so under `?node=` the manual path inputs (`project-path-input`, `new-project-path-input`, `foreign-repo-path-input` with PathAutocomplete) are the fallback; `remote` threads from `project_omnibox/1` into `palette_open_path`/`palette_new_project` and from `RemoteView.top_bar/1` into `project_settings_tab/1` (via `project_settings_body/1`).

ONE rule across the dashboard: every FINISHED task is reviewable, and `/review/<id>` renders whatever happened honestly (a failure or a cancellation shows its outcome, its branch and any salvaged changes). Repo-less `:reflect` tasks are the only exclusion — they have no code.

**Route ≠ triage slot.** A `:failed` (or `:cancelled`) task gets a review LINK so its branch, diff and failure report stay reachable, but it never occupies a "Needs review" slot: that bucket is the store's composite `:completed` + nil `review_status` + live-branch predicate, and the section's "View all" link therefore targets `/tasks?status=needs_review` (`/tasks?node=<id>&status=needs_review` on a remote view) rather than the unfiltered list.
Candidacy stays RESULT-AGNOSTIC (no `branch_name`/`no_changes` check) — a multi-repo task may have changed only writable FOREIGN repos, and a failed run's branch is exactly what a reviewer needs.
