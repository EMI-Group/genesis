# UI Components

## Intent

Reusable Phoenix function components and layout templates for the EvoDash web interface — the presentation layer, organized by domain concern.

## Routing Table

- `layouts/` → HTML layout templates (only the root layout shell: meta tags, CSRF, theme persistence).
- `agents_components/` → Agents-page commit-history sub-components (`CommitGraphView` + `commit_graph/geometry.ex` + `commit_graph/fold.ex`) — detail: `agents_components/CONTEXT.md`.
- `review_components/` → Review-page sub-components (`DiffViewer`, `Header`, `Actions`, `RepoCards`, `Stats`) + the review-subtree render caps — detail: `review_components/CONTEXT.md`.
- `settings_components/` → Settings sub-components (`CategoryMetadata`, `SettingCard`, the `provider_profiles/` family — `Panel`/`Row`/`Detail`/`ScheduleEditor`/`WizardForm` — `ProviderProfileFields`, `ProviderWizard`, `CustomAgentsEditor`, `CustomToolsPanel`, `ModelSelectionEditor`, `Sidebar`, `SearchResults`), the `SaveBar`/`SectionHeader`/`CardShell`/`FormFooter` blocks and the Settings pane layout — detail: `settings_components/CONTEXT.md`.
- `task_card_components/` → the card's helper submodules (`ResultRender`, `Options`, `Repos`, `Archive`, `Errors`, re-exported via `EvoDashWeb.TaskCardComponents` delegates) + the card's SUMMARY-map/`detail` contract and card-scoped caps — detail: `task_card_components/CONTEXT.md`.
- Workbench chrome — sidebar order + recent projects (`EvoDashWeb.Layouts.app/1`, `workbench_component.ex`), the Active Tasks section (`workbench_active_tasks.ex`), the closed-by-default right panels and the server-side task/conversation search — see `## Workbench chrome`; JS/CSS half → `../../assets/CONTEXT.md`.
- Narrow-width (mobile) conventions — branch-name badge truncation (`ResultRender.branch_badge_class/0`) → `task_card_components/CONTEXT.md`; agent-tree `pl-7 xl:pl-0` indent → `agents_components/CONTEXT.md`.

### Templates, usage, flashes, theme

`layouts/root.html.heex` is the only template (meta tags, CSRF, LiveView title, asset links, client-side theme script); all component modules `use EvoDashWeb, :html` and are pure function components (`<.task_card task={@task} />`, `<.flash kind={:warning} flash={@flash} />`).

| Flash kind | CSS Class | Icon | Use Case |
|------|-----------|------|----------|
| `:info` | `alert-info` | `hero-information-circle` | Success messages, informational notices |
| `:error` | `alert-error` | `hero-exclamation-circle` | Error messages, validation failures |
| `:warning` | `alert-warning` | `hero-exclamation-triangle` | Warnings, missing configuration alerts |

Theme is 100% client-side (`localStorage["phx:theme"]`, default `"system"`, resolved via `matchMedia` into `data-theme`/`data-theme-mode`; toggles only fire `phx-click={JS.dispatch("phx:set-theme")}` + `data-phx-theme`).
The global accent IS server-driven: `Layouts.app`'s `attr(:accent_color, :string, default: "blue")` sets `data-accent-color` on `#app-layout` from `LiveHooks.Appearance`'s node-aware `EvoGit.Config.resolve([:appearance, :accent_color])` via `EvoDash.AccentCache` — distinct from ProjectsLive's per-project `--project-accent`/`--project-ring-accent` on `#dashboard-root`.
Shell chrome is Adwaita token-based (`#app-layout` + sidebar `bg-base-200`, `#main-scroll`/`main#main-content` `bg-base-100`); the full engine (Tailwind `@custom-variant dark`, `themes: false` → `--color-base-*` + `color-mix`, the ten accent rules) is the parent `lib/evo_dash_web/CONTEXT.md` "Theming & Color System".

## Constraints

- Every component module **must** use `use EvoDashWeb, :html`; pure functions — assigns in, HEEx out, no side effects or direct LiveView process calls.
- Styling is Tailwind CSS + daisyUI — no inline CSS or external stylesheets; icons via `icon/1` (`hero-<name>[-style]`); layout templates live under `layouts/` (only the root layout exists).
- No component here renders a project's CONTEXT.md, the context tree, or a repository file listing; the only tree/graph renderers are `agents_components.ex` `path_tree/1`, the review changed-files sidebar (`review_components/diff_viewer.ex` `file_tree_sidebar/1`, built from a diff) and `agents_components/commit_graph_view.ex`; "CONTEXT.md" appears only as mode copy in `EvoDashWeb.Helpers` (`mode_label/1`, `mode_description/1`, `detect_mode` hints).
- Shared cross-component utilities come from `EvoDashWeb.Helpers` (status badges, formatting, `blob_preview/2`/`list_preview/2`, `tip/1`).
- **Task cancellation UX (graceful + force kill)** (`task_card_components.ex`): inline Cancel is GRACEFUL (`phx-click="open_cancel_modal"`, no `phx-confirm`), visible `[:pending, :running, :awaiting_input]`; the three-dot dropdown adds a `text-error` "Force kill" item (`open_force_kill_modal`, `[:running, :awaiting_input, :cancelling, :pausing, :paused]` — a draining or stuck pause must stay killable) under a `gettext("Danger zone")` menu-title divider (Delete keeps its `phx-confirm`). `:cancelling` renders IN-PROGRESS (warning pulsing dot + `gettext("Cancelling…")` through `Helpers.task_status_dot_class/1`/`task_status_tint/1`); `layouts.ex` treats `:cancelling` as running and has NO cancel surface.
- **Task pause / resume UX** (same card): **Pause** (`phx-click="open_pause_modal"`) for `[:running, :pausing]`, disabled — spinner + `gettext("Pausing…")` — while draining or while an async call is in flight; **Resume** (`phx-click="resume_task"`) only for `:paused`, direct for `:clean`, through `phx-confirm` for `:dirty`; the `action_busy` attr (`%{to_string(task_id) => :pause | :resume}`, default `%{}`) disables BOTH and renders the matching spinner label (read totally via private `action_busy/2`). A `:paused` card's explainer strip is `:dirty` → amber warning (dirty resume restores the root AND subagents still running with saved context; a collected one is not revived, a record-less one is reported lost) vs `:clean`/nil → neutral `gettext("Paused by you — resume continues where it stopped.")`. `:pausing` joins the amber busy family and pulses; `:paused` gets its OWN `info`/blue family and never pulses.
- **Task-status atom census** — a new status must be registered at every enumeration site (each falls back silently): `Helpers.task_status_badge/1`, `task_status_dot_class/1`, `task_status_tint/1`; the card's label `cond` + pulse gate (the `true ->` arm prints the RAW atom); the private `show_review_button?/1`; `NodeAware.@active_statuses` + `partition_active_tasks/1`; the `is_running`/`Enum.split_with` lists in `layouts.ex`; the TasksLive status `<select>` (raw SQL string, NO atom whitelist); the narrower busy sets in `ServerStatusController` + `SystemLive.UpdateCard`; the MCP `genesis_list_tasks` enum; and `ReviewComponents.page_header`'s `String.capitalize(to_string(@task_status))` (NOT gettext-wrapped).
- Desktop-only surfaces stay inert outside the Tauri shell: directory/file pickers render only when `@tauri_detected and !@remote`, so the headless server shows the manual path inputs.

### `try/rescue` Policy

`try/rescue` is an anti-pattern in these component files.
Do NOT wrap `String.to_existing_atom/1` in `try/rescue`: normalize untrusted DB data (e.g. archive maps after a Jason round-trip) with a whitelist map lookup (`@known_agent_keys` in `normalize_agent_keys/1`) + `Map.get/3` defaulting to the original key.
Any new `try/rescue` MUST carry an inline comment explaining why it is justified.

## Blob & Collection Rendering Caps

No component here may render an unbounded task blob or collection: a task can carry a 100+ MB `result` and every component re-executes on EVERY render (nothing memoizes).
- Previews come ONLY from `EvoDashWeb.Helpers` (never an ad-hoc `String.slice`): `blob_preview/2` → `%{text:, truncated?:, total_bytes:}` (UTF-8-safe prefix of at most `limit` BYTES, default `16_384`) and `list_preview/2` → `%{items:, total:, truncated?:}`, both TOTAL; a truncation note renders ONLY when `truncated?: true` and a multi-MB string is previewed BEFORE `EvoDash.MarkdownRender.render/1`.
- The ONLY uncapped paths are explicit user actions: `render_result_full/1` / `render_options_full/1` (`truncate: false`), `result_copy_text/1` / `objective_text/1`, and `TaskExportController`.

| Site | Cap |
|---|---|
| `archive_tree/1` | `300` records via `ArchiveHelpers.build_tree_capped/2` (`@max_agent_records`) + the "Showing %{shown} of %{total} agent records — export JSON for the full archive" line only when truncated (paging is the real bound: 100 per page) |
| `archive_tree_node/1` | `result` `8_192` bytes, `objective` `4_096` bytes, each with its own byte note; `result` renders only once `result_loaded?/1`, otherwise "Show result" / spinner / retry line |

Task-card caps (`@in_card_blob_limit`, `@in_card_log_limit`, `@copy_payload_limit`) → `task_card_components/CONTEXT.md`; review caps (`review_components/header.ex` previews + copy payload, `archive_review_section/1` `300` records, `diff_viewer.ex` `2_000`-line per-file bound, `file_tree_sidebar/1` `500` entries) → `review_components/CONTEXT.md`.

- `ArchiveHelpers.build_tree_capped/2` (default 100) → `%{tree:, total:, shown:, truncated?:}` with `%{agent:, children:}` nodes, `build_review_tree_capped/2` the same envelope with `{agent, children}` tuples; both drop non-map entries, cap BEFORE normalizing/grouping, prefer root records, keep the cycle-safety visited sets and count `shown` AFTER building (an out-of-page `parent_id` is PROMOTED to top level). Only these capped builders exist.
- `ArchiveComponents.archive_count_line/1` is the ONE count/exhaustion line both sites use (`total`, `first`/`last`, `dropped`, `more?`, `exhausted?`; paragraphs only), and `archive_details/1` renders ONE PAGE plus controls: entries under the legacy attr name `archive_metadata` (no such `%EvoGit.TaskInfo{}` field exists) + `total` (EFFECTIVE, nil → loaded count) / `server_total` / `dropped` / `exhausted?` / `agent_results` / `loading_more?` / `more_error` / `task_id` / `export_url`; "Load more" (`load_more_task_archive`) only while `not exhausted? and ArchiveHelpers.more_pages?(loaded, dropped, effective_total)` (NEVER `loaded < total`), each agent's `result` fetched on click (`load_task_archive_agent_result`, `phx-value-agent-id`), the node-aware "Export JSON" link only while `task_id` is present.
- Archive msgids (keep verbatim): "Showing %{shown} of %{total} agent records — export JSON for the full archive" (shared by the task-card tree and the review archive section — one msgid), "%{total} agents — showing %{first}–%{last}" (shared), "%{total} agents — showing %{first}–%{last} (earlier entries omitted; export JSON for the full archive)", "%{total} agents", "No more archive entries.", "Load more", "Show result", "Loading result…", "Could not load this agent's result.", "Could not load more archive pages."
  Task-card msgids ("Showing %{shown} of %{total} bytes", "Showing the last %{shown} of %{total} log entries", "last %{shown} of %{count}", the task-card copy hint) → `task_card_components/CONTEXT.md`; diff/header msgids ("%{count} more lines not shown", "Showing %{shown} of %{total} files", the review copy hint) → `review_components/CONTEXT.md`; the copy hint is TWO distinct msgids ("… open Full for the complete text" / "… open the Full view for the complete text") — do not merge.

## Design Notes

### Restrained shell and core controls

`Layouts.app/1` keeps a semibold base-size wordmark and flat tinted active navigation without a selection shadow; nav/branding/toggles and core default buttons/tabs/accordion summaries use theme-token focus-visible outlines (`rounded-lg` buttons, `text-base-content/70` form labels).
The Assistant link uses `/assistant` (`/help` 302-redirects there, query preserved; label `gettext("Assistant")`, `hero-chat-bubble-left-right`), sits right after Active Tasks, keys to `current_page == :assistant` and threads the node through `with_node_param/2`.
The sidebar always renders a `Conversations` section (`gettext("Conversations")`, body `HomeLive.SessionList.session_list(assigns)`, rows `#chat-session-<id>`, loaded and stale-guarded by `LiveHooks.NodeAware`).
The chat approval surface belongs to `live/home_live/approval_dialog.ex` (`#approval-status-bar` + one `<dialog id="approval-dialog" class="modal" phx-hook="DialogModal">` with 1-of-N stepping, Deny / Allow once and a sudo warning), not this node; the guide panel renders only when `@guide` exists ("Genesis Guide", Dismiss when `dismissible`, node-aware "Go" link).
Below `lg` main content uses `pt-16` (desktop `lg:pt-4`); the fixed configuration notice lists its lines through `EvoDashWeb.ConfigIssues.lines/1`, keeps the model-neutral "Configure now →" link and never blames the LLM model.

### Shell motion (disclosures, transitions, palette, flash)

Motion composes the shared `assets/css/motion.css` foundation (`--motion-*` tokens, `motion-fade-*`/`motion-exit-*` keyframes, global reduced-motion backstop) — no new durations/easings locally.
- The Tools/Conversations disclosures are `details.motion-disclosure` + `phx-hook="DisclosureMotion"` (open AND close animate) with stable ids (`workbench-tools`, `workbench-conversations`) because LiveView refuses a `phx-hook` without one; their `<summary>`s keep `.workbench-row` + a rotating `hero-chevron-right` caret and stay visible in the collapsed `w-16` rail (`SidebarCollapse` hides only `.sidebar-label`).
- Page-to-page navigation is a cross-document view transition (`<meta name="view-transition" content="same-origin">` in `layouts/root.html.heex`); theme switching goes through `root.html.heex`'s feature-detected `transitionTheme/1` (`document.startViewTransition(() => setTheme(theme))`, skipped under `prefers-reduced-motion`); `#main-content` keeps `phx-hook="NodeSwitchFade"` (per-patch transitions → Known Issues).

### `Layouts.app` content background lives on the scroll container (`#main-scroll`)

The page content background is `bg-base-100` on **`#main-scroll`** — the scroll container (`flex-1 overflow-auto` inside the fixed `h-dvh` chain `body` / `#app-layout` `bg-base-200` → `#desktop-quit-hook` `flex-1 min-h-0`). ### `phx-click` + JS hook on the same element — double firing

`phx-click` + a `phx-hook` on the SAME element sends BOTH the hook's handling AND the `phx-click` event; don't put both on one element unless a matching `handle_event/3` clause exists.
The three directory-picker "Browse" buttons in `project_components.ex` (`project-path-browse-button`, `new-project-location-browse-button`, `foreign-repo-path-browse-button`) carry ONLY `phx-hook="DirectoryPicker"` — the hook pushes `"directory_pick"`, ProjectsLive runs `EvoDash.DirectoryPicker` and pushes back `picker_result:<picker_id>`; adding `phx-click` there has no clause → `FunctionClauseError` → LiveView crash (pinned by `project_components_test.exs`).

## Workbench chrome (sidebar sections, recent projects, right panels, history search)

- **Sidebar order** is stated once in the `Layouts` row; `#workbench-settings` is the settings-window slot in the bottom bar, and **Active Tasks is top-level** — never a Tools entry, never finished tasks, rendered only while `running_tasks`/`pending_tasks` are non-empty, on every sidebar page.
- **ListEnter wiring** (`workbench_active_tasks.ex`): the hook mounts on the rows WRAPPER `#workbench-active-tasks-rows` (`.space-y-1`, `phx-hook="ListEnter"` + `data-list-enter-scope`), never a row (morphdom keeps the wrapper + the hook's `seen` baseline); scope is the VIEWED NODE (`"sidebar|" <> (node_id || "local")`) and every row link carries `data-list-enter-key` from `task_key/1` (the TASK ID, so a status change cannot replay it), unique per render.
- **Recent projects** (`WorkbenchComponent` `mode: :projects`): at most `@recent_project_limit` (5) entries by VCT recency across hosts plus the current project as `is-current` + `aria-current="page"`; actions `#workbench-recent-projects`, `#workbench-open-directory`, `#workbench-new-project` (+ `data-workbench-attention`), `data-workbench-projects-loading`; header `gettext("Recent projects")`. NO per-project activity sub-list (`:project_activity`, `load_project_activity/1`, `more_project_activity`, `load_project_sessions/2` do not exist); `WorkbenchSidebarCache` caches only `{:project_registry, hosts}`.
- **Right panels closed by default**: `#workbench-history`/`#workbench-git` render in the INITIAL markup with `hidden` + `data-panel-state="closed"`; the `Workbench` hook owns `data-panel-state` (`closed | open | closing`), `#workbench-history-toggle`/`#workbench-git-toggle` keep `aria-expanded`, and `#workbench-history-overlay`, `#workbench-right-resize` + the center-column `inert` rules stay JS-driven; closed on every breakpoint, animation pure CSS in `apps/evo_dash/assets/`.
- **The history panel is a real SERVER-side search**: `#workbench-history-project` is a server-rendered scope label (project name or "All projects"); ONE `<form id="workbench-history-filters" phx-change="history_filters" phx-submit="history_filters" phx-target={@myself}>` holds `#workbench-history-query` wrapping `#workbench-history-search` (`name="query"`, `phx-debounce="300"`), `#workbench-history-project-filter` (`name="project"`, leading `""` "All projects") and `#workbench-history-status-filter` (`name="status"`, leading `""` "Any status"); `history_filters` diffs all three and reloads only on a real change, while the kind control stays two `type="button"` buttons (`data-workbench-kind`, `phx-click="history_kind"` + `phx-value-kind`).
- **Queries**: tasks via `NodeContext.list_tasks_page/2` (`:search`/`:project_path`/`:status`, page size 50, `[data-workbench-more]` → `phx-click="more_history"`); conversations filter `HomeLive.SessionList.load/1` rows. Every read is OFF-process (`start_async` + `EvoDash.SafeCall.run/1`) behind `history_sig` AND the request signature `{node_id, target, history_project, history_kind, history_query, history_status, history_offset}`; `data-workbench-history-empty="true"` marks ready-and-empty. The project filter defaults to the CURRENT project over that node's `NodeContext.projects/1` mounts; a project/scope switch resets the filter and clears the query (no per-scope history cache — a refetch shows "Loading…").
