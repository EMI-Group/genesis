# UI Components

## Intent

Reusable UI component modules and layout templates for the EvoDash web interface — the presentation layer, Phoenix function components rendered via HEEx, organized by domain concern.

## Routing Table

- `layouts/` → HTML layout templates (only the root layout shell: meta tags, CSRF, theme persistence).
- `agents_components/` → Agents-page commit-history sub-components (`CommitGraphView` + `commit_graph/geometry.ex` + `commit_graph/fold.ex`) — detail: `agents_components/CONTEXT.md`.
- `review_components/` → Review-page sub-components (`DiffViewer`, `Header`, `Actions`, `RepoCards`, `Stats`) + the review-subtree render caps — detail: `review_components/CONTEXT.md`.
- `settings_components/` → Settings sub-components (`CategoryMetadata`, `SettingCard`, the `provider_profiles/` family — `Panel`/`Row`/`Detail`/`ScheduleEditor`/`WizardForm` — `ProviderProfileFields`, `ProviderWizard`, `CustomAgentsEditor`, `CustomToolsPanel`, `ModelSelectionEditor`, `Sidebar`, `SearchResults`), the shared `SaveBar`/`SectionHeader`/`CardShell`/`FormFooter` blocks and the Settings pane layout/config-path-footer contract — detail: `settings_components/CONTEXT.md`.
- `task_card_components/` → the card's helper submodules (`ResultRender`, `Options`, `Repos`, `Archive`, `Errors`, re-exported via `EvoDashWeb.TaskCardComponents` delegates) + the card's SUMMARY-map/`detail` contract and card-scoped caps — detail: `task_card_components/CONTEXT.md`.
- Workbench chrome — sidebar order + recent projects (`EvoDashWeb.Layouts.app/1`, `workbench_component.ex`), the Active Tasks section (`workbench_active_tasks.ex`), the closed-by-default right panels and the server-side task/conversation search — see `## Workbench chrome` below; JS/CSS half → `../../assets/CONTEXT.md`.
- Narrow-width (mobile) conventions — branch-name badge truncation (`ResultRender.branch_badge_class/0`) → `task_card_components/CONTEXT.md`; agent-tree `pl-7 xl:pl-0` indent → `agents_components/CONTEXT.md`.

### Usage Pattern
All component modules use `use EvoDashWeb, :html`; components are function components: `<.button phx-click="save">Save</.button>`, `<.task_card task={@task} />`, `<.agent_tree agents={@agents} />`, `<.flash kind={:warning} flash={@flash} />`.

### Theme delivery chain (client-side theme state + server-driven global accent)
- **Theme state is 100% client-side.** `layouts/root.html.heex`'s inline script resolves `localStorage["phx:theme"]` (default `"system"`) via `matchMedia("(prefers-color-scheme: dark)")` into `data-theme` (`"light"`/`"dark"`) + `data-theme-mode` and swaps the favicon/`theme-color` meta; cross-tab `storage` sync and system-mode re-resolve only.
- **Toggle buttons never touch the server**: `theme_toggle_compact/1` / legacy `theme_toggle/1` fire `phx-click={JS.dispatch("phx:set-theme")}` with `data-phx-theme`; Tailwind's `dark:` binds to `@custom-variant dark (&:where([data-theme=dark], [data-theme=dark] *))` and DaisyUI's `themes: false` means custom CSS uses `--color-base-*` + `color-mix`.
- **The global accent IS server-driven**: `EvoDashWeb.LiveHooks.Appearance` resolves `EvoGit.Config.resolve([:appearance, :accent_color])` node-aware through `EvoDash.AccentCache` and seeds `@accent_color`, which `Layouts.app` (`attr(:accent_color, :string, default: "blue")`) sets as `data-accent-color` on `#app-layout`, activating the ten `[data-accent-color="<name>"]` rules in `app.css`; distinct from ProjectsLive's per-project `--project-accent`/`--project-ring-accent` on `#dashboard-root`.
- **Shell chrome is token-based (Adwaita)**: `#app-layout` + sidebar `bg-base-200`, `#main-scroll`/`main#main-content` `bg-base-100`, body `bg-base-200` — no slate/white literals.

## Constraints

- Every component module **must** use `use EvoDashWeb, :html`.
- Styling is Tailwind CSS + daisyUI — no inline CSS or external stylesheets in components.
- Icons use the Heroicon set via `icon/1` (naming `hero-<name>[-style]`).
- Layout templates live under `layouts/`; only the root layout exists.
- Components are pure functions — assigns in, HEEx out; no side effects or direct LiveView process calls.
- No component here renders a project's CONTEXT.md, the context tree, or a repository file listing; the only tree/graph renderers are `agents_components.ex` `path_tree/1`, the review changed-files sidebar (`review_components/diff_viewer.ex` `file_tree_sidebar/1`, built from a diff) and `agents_components/commit_graph_view.ex`; "CONTEXT.md" appears only as mode copy in `EvoDashWeb.Helpers` (`mode_label/1`, `mode_description/1`, `detect_mode` hints).
- Shared cross-component utilities come from `EvoDashWeb.Helpers` (status badges, formatting, `blob_preview/2`/`list_preview/2`, `tip/1`).
- **Task cancellation UX (graceful + force kill)** (`task_card_components.ex`): inline Cancel is GRACEFUL (`phx-click="open_cancel_modal"`, no `phx-confirm` — the modal confirms), visible `[:pending, :running, :awaiting_input]`; the three-dot dropdown adds a `text-error` "Force kill" item (`open_force_kill_modal`, `[:running, :awaiting_input, :cancelling, :pausing, :paused]` — a draining or stuck pause must stay killable) under a `gettext("Danger zone")` menu-title divider (Delete keeps its `phx-confirm`). `:cancelling` renders IN-PROGRESS (warning pulsing dot + `gettext("Cancelling…")` through `Helpers.task_status_dot_class/1` / `task_status_tint/1`); `layouts.ex` treats `:cancelling` as running and has NO cancel surface.
- **Task pause / resume UX** (same card): **Pause** (`phx-click="open_pause_modal"`) visible for `[:running, :pausing]`, disabled — spinner + `gettext("Pausing…")` — while draining (`:pausing`, `title` says the agent finishes its current tool call first) or while an async call is in flight; **Resume** (`phx-click="resume_task"`) visible only for `:paused`, posted directly for `:clean` and through `phx-confirm` for `:dirty`. The `action_busy` attr (`%{to_string(task_id) => :pause | :resume}`, default `%{}`) disables BOTH controls and renders the matching spinner label, read totally via private `action_busy/2` (nil/non-map → nothing in flight). A `:paused` card renders its own explainer strip: `pause_kind: :dirty` → amber warning (the last tool call may not have completed; files and background jobs may be inconsistent; a dirty resume restores the root agent AND the subagents still running with their saved context — a collected subagent is not revived, a record-less one is reported lost), `:clean`/nil → neutral info `gettext("Paused by you — resume continues where it stopped.")`. `:pausing` joins the amber busy family and pulses; `:paused` gets its OWN `info`/blue family (badge `bg-info/10 text-info`, dot `bg-info`, tint `bg-info/5 shadow-info/10 border-info/20`) and never pulses.
- **Task-status atom census** — a new status must be registered at every enumeration site (each falls back silently): `Helpers.task_status_badge/1`, `task_status_dot_class/1`, `task_status_tint/1` (closed sets + neutral catch-all), the card's label `cond` + pulse gate (the `true ->` arm prints the RAW atom), the private `show_review_button?/1`, `NodeAware.@active_statuses` + `partition_active_tasks/1`, the `is_running`/`Enum.split_with` lists in `layouts.ex`, the TasksLive status `<select>` (raw SQL string, NO atom whitelist), the narrower busy sets in `ServerStatusController` + `SystemLive.UpdateCard`, the MCP `genesis_list_tasks` enum, and `ReviewComponents.page_header`'s `String.capitalize(to_string(@task_status))` (NOT gettext-wrapped).
- Desktop-only surfaces stay inert outside the Tauri shell: directory/file pickers render only when `@tauri_detected and !@remote`, so the headless server shows the manual path inputs.

### `try/rescue` Policy

`try/rescue` is an anti-pattern in these component files.

- **Do NOT** wrap `String.to_existing_atom/1` in `try/rescue`: normalize untrusted DB data (e.g. archive maps after a Jason round-trip) with a whitelist map lookup (`@known_agent_keys` in `normalize_agent_keys/1`) + `Map.get/3` defaulting to the original key.
- Any new `try/rescue` MUST carry an inline comment explaining why it is justified.

## Blob & Collection Rendering Caps

No component here may render an unbounded task blob or collection: a task can carry a 100+ MB `result` and every component re-executes on EVERY render (nothing memoizes).

- The two `EvoDashWeb.Helpers` functions are the SINGLE source of previews — never ad-hoc `String.slice` caps: `blob_preview/2` → `%{text:, truncated?:, total_bytes:}` (UTF-8-safe prefix of at most `limit` BYTES, default `16_384`) and `list_preview/2` → `%{items:, total:, truncated?:}` (at most `limit` leading elements) — both TOTAL (non-binary/non-list → empty; a non-integer/negative limit → the default).
- A truncation note renders ONLY when `truncated?: true`; a complete payload renders no note and no cap-related `title`, and a multi-MB string is previewed BEFORE `EvoDash.MarkdownRender.render/1`.
- The ONLY uncapped paths are explicit user actions: the Full Result / Full Options modal bodies (`render_result_full/1` / `render_options_full/1`, `truncate: false`), `result_copy_text/1` / `objective_text/1`, and `TaskExportController`.

| Site | Cap |
|---|---|
| `archive_components.ex` `archive_tree/1` | `300` records via `ArchiveHelpers.build_tree_capped/2` (`@max_agent_records`), computed ONCE per render, + the "Showing %{shown} of %{total} agent records — export JSON for the full archive" line only when truncated. Paging is the real bound (100 per page); the tree cap is the second safety net |
| `archive_components.ex` `archive_tree_node/1` | `result` `8_192` bytes, `objective` `4_096` bytes, each with its own byte note; the `result` block renders only once the user fetched that agent's entry (`result_loaded?/1`), otherwise "Show result" / spinner / retry line |

Task-card caps (`@in_card_blob_limit`, `@in_card_log_limit`, `@copy_payload_limit`) → `task_card_components/CONTEXT.md`; review-subtree caps (`review_components/header.ex` previews + copy payload, `archive_review_section/1` `300` records, `diff_viewer.ex` `2_000`-line per-file bound, `file_tree_sidebar/1` `500` entries) → `review_components/CONTEXT.md`.

- `ArchiveHelpers.build_tree_capped(records, max_records \\ 100)` → `%{tree:, total:, shown:, truncated?:}` with `%{agent:, children:}` nodes; `build_review_tree_capped/2` returns the same envelope with `{agent, children}` tuples. Both drop non-map entries, cap BEFORE normalizing/grouping, prefer root records in the slice, keep the cycle-safety visited sets, and count `shown` AFTER building — a record whose `parent_id` is on an unloaded/broken page is PROMOTED to top level and counted. Only these capped builders exist (task card / review tab respectively).
- `ArchiveComponents.archive_count_line/1` is the ONE count/exhaustion line both sites use (attrs `total` — true archive size — `first`/`last` — 1-based retained range — `dropped` — rows evicted by the retention window — `more?` — a pager renders — `exhausted?`): `more? or dropped > 0` renders "%{total} agents — showing %{first}–%{last}" (with "(earlier entries omitted; export JSON for the full archive)" when `dropped > 0`), else "%{total} agents", plus a muted "No more archive entries." when `exhausted?` (replaces the pager). ### Task Form — Single-Card Two-Layout Design (`task_form_components.ex`)

The launch panel is ONE card (`.input-card`) containing the objective textarea AND the bottom toolbar (`.input-controls`) last, in normal flow (never `position: fixed`).
The layout is **server-seeded at render + client-driven**: `layout_for/1` computes the initial `data-layout` on `.input-layout` from `@prompt` (public, unit-tested) — `@short_objective_threshold 1200` means `:expanded` above 1200 graphemes OR 32 explicit lines, else `:compact` (also for non-binary input); compact auto-grows to ~16 lines while expanded fills the card (`flex: 1`, internal scroll, no max-height — the card's `overflow: hidden` bounds it).
There is NO per-keystroke server event (no `phx-change`/`phx-debounce`; `@task_prompt` changes only via `restore_state`/`task_submit`, and the `phx-update="ignore"` textarea is never clobbered; draft persistence is client-side).
The **AdaptiveInput JS hook** mirrors the thresholds, flips `data-layout` while typing, autogrows, and re-asserts the computed layout via a MutationObserver on `.input-layout` after any server re-render — zero network events.
The **objective placeholder** is computed ONCE per render by the private `task_placeholder/2` (suppressed to `""` while `@disabled`) on TWO channels: `placeholder` (SSR first paint only) and `data-placeholder` (live); `phx-update="ignore"` makes LiveView re-merge only `data-*`, so the hook mirrors `data-placeholder` onto `el.placeholder` (mount, `_apply()`, `attributeFilter: ['data-placeholder']` MutationObserver).

### Shared LLM Selection (`llm_selection_components.ex`)

`EvoDashWeb.LLMSelectionComponents.llm_selection/1` is a pure provider-profile/model/discrete-reasoning picker for Projects, Assistant, onboarding and Settings.
Attrs: `provider_profiles` (canonical string-keyed maps with `"id"`, `"name"`, `"provider"`), `model_selections` (the ordered atom-keyed `EvoGit.Config.Schema.model_selections/1` projection), `model_spec` (string-keyed `"provider_profile_id"`, `"model"`, optional `"reasoning_effort"`) — all defaulting empty — plus `id` (default `"llm-selection"`, unique per page), `provider_event` (default `"select_provider_profile"`), `model_event` (default `"select_model"`), `reasoning_event` (default `"select_reasoning_effort"`), `disabled`, `compact`, `class`, `show_auto_option`.
Providers emit `provider_profile_id`, models emit `model`, and reasoning stops emit `reasoning_effort` as a ZERO-BASED INDEX into the selected model's ordered `reasoning_efforts` — never a provider effort string; call `resolve_reasoning_effort(model_selections, model_spec, value)` from event AND submit handlers before persisting (`{:ok, effort_string}` for a supported string/valid index, `{:error, :unsupported_reasoning_effort}` for malformed/out-of-range values or unsupported models).
The component never nests forms, fetches configuration or renders credentials — callers own state, validate changes, clear downstream choices and resolve the spec — and every control is a `type="button"` with `phx-click` + `phx-value-*` (no `form`, no `phx-change`): the Assistant renders it inside `#chat-form`, TaskForm inside `<form id="task-form">`, and neither interaction submits (`chat_input` never fires from a picker click).
The fieldset is non-shrinking so the expanded editor compresses the textarea; stale selections carry `aria-invalid`, a model-empty hint is associated with its disabled control, and models are scoped to the exact selected profile — unavailable persisted providers/models stay visibly unavailable rather than silently substituted.
Reasoning stops use only advertised discrete steps, default to the model's supported default (else its first effort), disappear for unsupported models and are disabled for a single supported level; callers omit reasoning for unsupported models and keep the current/default effort when that single disabled stop is the only option.
Controls carry unique associated labels, native keyboard navigation, `aria-pressed` stop state and translated labels.
`TaskFormComponents.task_form/1` takes the same three projection/spec + three event attrs and renders the picker (`id="task-llm-selection"`) in the toolbar's right cluster; with all new attrs empty, `model_profiles` / `selected_model_id` / `show_auto_model_option` preserve legacy behavior unchanged.

## Design Conventions — Adwaita token grammar (markup)

Rules for writing NEW markup in this subtree (repo-wide catalog: parent `lib/evo_dash_web/CONTEXT.md`):

- **Alpha floor** (base-content on light is binding): user-relevant text never below `/50`; labels/meta ≥ `/60`; small/primary content ≥ `/70`; fold `text-[10px]`/`text-[11px]` → `text-xs` where feasible; decorative large icons and "·" separators may keep `/30`–`/40`.
- **Hairlines/dividers on flat `bg-base-100`** use `border-base-300` (never `border-base-200` — ≈1.06:1 invisible); tinted wells may keep `border-base-200/80`.
- **Corners**: cards/panels `rounded-xl` max (prefer `rounded-lg`); normal action buttons `rounded-lg`/`rounded-md`; only genuine pill/badge elements keep `rounded-full`.
- **`*-content` tokens are tuned for solid fills** — never `text-*-content` on translucent tints; on `/10`–`/30` tints use `text-error`/`text-warning`/`text-success`, and `-content` only on solid fills.
- **No raw color literals** (`text-red-500`, `bg-white/10`, `bg-black/10`, `bg-neutral text-neutral-content`, `bg-base-50` — the last compiles to no fill) → theme tokens (`text-error`, `bg-error/10`, `bg-base-200`, `bg-base-content/5`, …).
- **Empty/loading states**: exactly ONE dim layer (icon and copy should not both sit at floor alpha).
- **Locked contracts — never restyle helper OUTPUTS**: the `EvoDashWeb.Helpers.task_status_*` / `agent_status_*` / `connection_status_*` class helpers, the task-form bottom-toolbar DOM order (attach-kind dropdown | mode+speed capsule | right cluster: custom-agent select? | model capsule | send) + `data-layout`, the `phx-hook`/`phx-click` bindings, and the chart CSS-var strings. Markup class LITERALS may be polished; helper outputs are the single source of truth.
