# EvoDash Domain-Layer Tests

## Intent

Unit/integration tests for the `:evo_dash` domain modules (`./apps/evo_dash/lib/evo_dash/`): `EvoDash.ActiveTasks`, `EvoDash.ChatHistory`, `EvoDash.DirectoryPicker`, `EvoDash.NodeContext`, `EvoDash.AttachedFile`, `EvoDash.SettingsUtils`, `EvoDash.DesktopLifetime`, `EvoDash.MarkdownRender`, `EvoDash.UpdateStatus`. (Store/TaskRegistry domain tests live in `:evo_git`, not here.)

## Routing Table

- `active_tasks_test.exs` → `EvoDash.ActiveTasksTest` (async: false) — ETS-backed `EvoDash.ActiveTasks` pure-module API (named public table `:evo_dash_active_tasks`, boot-created idempotently at the top of `EvoDash.Application.start/2` and owned by the long-lived application process; the module has NO process — tests never reference a process/`start_link`; `reset()` in setup for shared-global-hub hygiene). Tests: `get`/`put` round-trip + same-context overwrite, per-context isolation (local vs remote keying `{nil, node()}` / `{node_id, remote_node}`, distinct node_ids/remote nodes never leak), `{[], []}` valid-snapshot semantics (`{:ok, {[], []}}` ≠ `:empty`), `invalidate/2` (per-context delete → `get` `:empty`, other contexts' snapshots survive with exact contents, never-written key is a `:ok` no-op), `reset/0` (clears every context, idempotent).
- `directory_picker_test.exs` → `EvoDash.DirectoryPickerTest` (async: true) — pick protocol via `EvoDash.DirectoryPicker.Wx.Fake` injected through `:directory_picker_wx` env (`enabled: true` override in setup; test_helper.exs defaults to disabled). Tests: `pick/2` first/subsequent picks, wx-server-killed-between-picks recovery, mid-pick server-death → `:unavailable` + busy cleared, wx `init_fails` → async `:unavailable` + recovery, busy serialization via `FakeWx.set_gate/1` (second pick → sync `{:error, :unavailable}`, no result msg), disabled-config rejection. `pick/3 :file` mirrors: file dialog result `{:ok, "/fake/picked/file.txt"}`, `pick/2` ≡ `pick/3 :directory` (`{:ok, "/fake/picked/dir"}`), kind-agnostic busy, init-fail + disabled-config. Sync helper `await_pick_idle/1` polls the picker's own `:sys.get_state/1` (a FIFO fence) instead of a wall-clock window — `run_pick/4` sends the caller's result BEFORE `{:pick_done, …}`, so observing the picker idle proves the result is already delivered. Every negative `refute_receive {:directory_picker_result, …}` is a ZERO window (a plain mailbox scan, no sleep), backed by two invariants documented at the top of the module: (A) after an `await_pick_idle/1` fence the pick Task has terminated and nothing else can arrive; (B) a pick that returned `{:error, :unavailable}` never reached the GenServer's Task-spawning clause, so no result message for it can ever exist. NO test covers the `:cancelled` result kind (user dismisses dialog); no path validation/normalization is tested — the picker only relays the path (source `normalize_path/1` = chardata→binary passthrough; no expand/exists check).

- `settings_utils_test.exs` → `EvoDash.SettingsUtilsTest`
- `desktop_lifetime_test.exs` → `EvoDash.DesktopLifetimeTest` (async: true) — the TCP lifetime watcher: gating (missing/empty/invalid `EVOGIT_LIFETIME_PORT` → disabled no-op), connect-budget exhaustion → stop, real-TCP peer-close → stop, `classify_recv_result/1` pure branches, and ambiguous-recv retry semantics (a transient ambiguous error alone does not stop / a later peer close does; an always-ambiguous error exhausts the retry budget then stops). It drives the watcher through the module's EXISTING `:recv_fun` / `:parent_stop_fun` seams with a BLOCKING handshake (the seam sends `:recv_called` then waits for the test's `:respond_ambiguous`/`:respond_closed`), so the watcher is parked inside `recv_fun` between assertions and the tests are load-robust (no race against `recv_retry_delay`). The real-TCP cases OBSERVE the watcher instead of waiting: `await_recv_blocked/1` polls `Process.info(pid, [:current_function, :status])` until the watcher is parked inside the blocking `:gen_tcp.recv/3` (`status: :waiting` with a `:prim_inet`/`:inet`/`:gen_tcp`/`EvoDash.DesktopLifetime` frame; bounded 1 ms poll, `flunk` on exhaustion), while `assert_disabled/1` (`:sys.get_state/1` → `enabled: false, stopped: false`) and `assert_no_further_stop/1` (`:sys.get_state/1` → `stopped: true`) fence the watcher state. Every `refute_receive @stop_message` is a ZERO-window mailbox scan; only the POSITIVE assertions keep generous second-scale timeouts. The watcher's own `[desktop] …` warning lines are wrapped in `ExUnit.CaptureLog` and the expected line is asserted (see "Console-noise capture" below).

## Notes for Agents — console-noise capture

ExUnit's suite-wide `capture_log: true` is WINDOW-based (a `:logger` handler is swapped in only while ≥1 test runs), so a logger line emitted by a process at the test boundary prints to the console. Two suites here emit such lines from processes other than the test process and therefore capture them explicitly (never by raising the global Logger level):

- `desktop_lifetime_test.exs`: the `EvoDash.DesktopLifetime` watcher GenServer logs `[desktop] …` warnings from its OWN process. Each stop-driving action is wrapped in `ExUnit.CaptureLog` (`capture_log/1`, or `with_log/2` when the fun's return value is also needed) AND the expected line is asserted — e.g. `log =~ "[desktop] Tauri shell is gone (lifetime connection closed)"`, `log =~ "[desktop] Tauri shell is gone (lifetime connection could not be established)"`, `log =~ "[desktop] lifetime recv kept failing"`. This is both a noise fix and a log-contract pin.
- `node_context_test.exs`: the two real remote-node RPC calls reach real distribution/net-kernel code on a distributed local BEAM, which can emit logger lines (e.g. `No distribution cookie configured…`) from global processes at the test boundary. They are wrapped in `with_log/2` — NOT `capture_log/2`, because `capture_log` returns the log string while the assertions are on the wrapped call's RETURN value (`with_log/2` returns `{result, log}`).

## Notes for Agents — deterministic waits (no fixed sleeps, no tight windows)

- Negative assertions in these two suites are ZERO-window mailbox scans (`refute_receive …, 0` — a plain `receive … after 0`, which still flunks on a stray message), never fixed wall-clock windows, and each is backed by a fence proving the unwanted message cannot be sent or is already in the mailbox. Never (re)introduce a tight numeric window.
- `desktop_lifetime_test.exs` fences: the blocking-handshake `:recv_fun` seam (a preceding `assert_receive :recv_called` proves the watcher is parked inside the seam), `assert_disabled/1`, `assert_no_further_stop/1`, and `await_recv_blocked/1` for the real-socket cases.
- `directory_picker_test.exs` fences: `await_pick_idle/1` after an accepted pick, and the synchronous `{:error, :unavailable}` reply itself (which proves no Task — hence no result message — exists).
- Preference order: drive an async/GenServer collaborator through its SEAMS with a blocking handshake, then observe a real condition (process state, `Process.info/2`) with a bounded poll; race a sleep-driven timer only when no condition is observable.
- Positive assertions stay generous (`:gen_tcp.accept(…, 5000)`, `assert_receive …, 2000/5000`) so real breakage still fails loudly.
- Validated by running both files under sustained CPU load (`for i in $(seq 1 24); do (while :; do :; done) & done`) at several seeds — 23 tests, 0 stray console log lines.

## Known Issues / Test Gaps (multi-repo relevant)

- **No `NodeContext.start_task/3` test in this suite** (only a comment at node_context_test.exs:33 mentions `start_task/2`). `start_task/3` (node_context.ex:605) passes `opts` verbatim to `EvoGit.RemoteNode.start_task/3` — `:path`, `:foreign_repos`, `:mode`, `:agent`, `:model_id` threading has NO domain-layer regression coverage here (only LiveView-level coverage in projects_live_test/home_live_test).
- **`foreign_repos` appears NOWHERE** in node_context.ex or this test dir (rg: zero matches). Multi-repo opt threading is untested at the NodeContext layer.
- **Remote `:erpc` delegation path largely untested here** — most tests call with `node()` (local direct); the remote transport envelope (`{:error, {kind, reason}}`) is exercised ONLY for `approval_response/3` (nonexistent-node transport failure). All other remote delegates are never exercised in this suite.
- **`approval_response/3` distributed-node branch is environment-brittle** — the test documents "distributed node → `{:error, :nodedown}`", but the target node `:"nonexistent-node@nowhere"` has an UNRESOLVABLE host, so `:erpc.call` raises `:noconnection` (the non-distributed raise path, normalized to `{:error, {:error, {:erpc, :noconnection}}}`) even on a distributed local BEAM. The documented `{:error, :nodedown}` branch is only reached for a reachable-but-down node.
- **Picker: no `:cancelled` result-kind test, no path normalization/existence assertions** — the fake always delivers literal `/fake/picked/dir` | `/fake/picked/file.txt` binaries; downstream path normalization is covered in `evo_dash_web/live/projects_live/project_flow_test.exs`, not here.

## Notes for Agents — async policy (per-suite)

Tests inside ONE module always run serially, so `async:` decides only whether a MODULE runs concurrently with OTHER modules — and `async: false` modules never run concurrently with `async: true` ones (ExUnit starts sync modules only after every async module finished).
The domain-layer suites here are `async: true` (`attached_file_test`, `chat_history_test`, `desktop_lifetime_test`, `directory_picker_test`, `markdown_render_test`, `settings_utils_test`, `update_status_test`) EXCEPT two that stay `async: false`:
- `active_tasks_test.exs` — the shared boot-created `:evo_dash_active_tasks` ETS table (application-owned, no process), which `EvoDashWeb.ConnCase` resets in setup; a concurrent async ConnCase reset while this file reads/writes would be a wipe race. The file resets it in setup + `on_exit` so its shape-agnostic atom sentinels never leak.
- `node_context_test.exs` — swaps the process-global `XDG_CONFIG_HOME` and juggles the GLOBAL `EvoGit.Store`/`EvoGit.TaskRegistry` singletons via `Supervisor.terminate_child/restart_child`.

Async-safety facts for the flipped suites:
- `chat_history_test.exs` reads the shared `EvoDash.ChatHistory` table; its only other consumer (`home_live_test.exs`) is `async: false`, so no concurrent async writer exists.
- `update_status_test.exs` reads + resets the shared `EvoDash.UpdateStatus` hub and injects app-env seams (`:update_notify_only_override`, `:desktop_release`, `EVOGIT_DESKTOP`), snapshot-restored; the other consumers (`system_live_test`, `live_hooks/update_status_test`) are `async: false`.
- `desktop_lifetime_test.exs` snapshots/restores the process-global `EVOGIT_LIFETIME_PORT` env var + the `:parent_stop_fun` app env; no other async module reads either key. The watcher is driven via the blocking-handshake `:recv_fun` seam (see the deterministic-waits notes above).
- `directory_picker_test.exs` overrides the app env `:directory_picker` (`enabled: true`) + `:directory_picker_wx` = `EvoDash.DirectoryPicker.Wx.Fake` and uses the app-started picker's global busy flag + `FakeWx` `:persistent_term` mode/gate; no other async module calls `DirectoryPicker.pick` (its only other caller, `projects_live_test.exs`, is `async: false`).
