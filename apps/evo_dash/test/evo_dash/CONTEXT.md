# EvoDash Domain-Layer Tests

## Intent

Unit/integration tests for the `:evo_dash` domain modules (`./apps/evo_dash/lib/evo_dash/`): `EvoDash.ActiveTasks`, `EvoDash.ChatHistory`, `EvoDash.DirectoryPicker`, `EvoDash.NodeContext`, `EvoDash.AttachedFile`, `EvoDash.SettingsUtils`, `EvoDash.DesktopLifetime`, `EvoDash.MarkdownRender`, `EvoDash.UpdateStatus`. (Store/TaskRegistry domain tests live in `:evo_git`, not here.)

## Routing Table

- `active_tasks_test.exs` → `EvoDash.ActiveTasksTest` (async: false) — ETS-backed `EvoDash.ActiveTasks` pure-module API (named public table `:evo_dash_active_tasks`, boot-created idempotently at the top of `EvoDash.Application.start/2` and owned by the long-lived application process; the module has NO process — tests never reference a process/`start_link`; `reset()` in setup for shared-global-hub hygiene). Tests: `get`/`put` round-trip + same-context overwrite, per-context isolation (local vs remote keying `{nil, node()}` / `{node_id, remote_node}`, distinct node_ids/remote nodes never leak), `{[], []}` valid-snapshot semantics (`{:ok, {[], []}}` ≠ `:empty`), `invalidate/2` (per-context delete → `get` `:empty`, other contexts' snapshots survive with exact contents, never-written key is a `:ok` no-op), `reset/0` (clears every context, idempotent).
- `directory_picker_test.exs` → `EvoDash.DirectoryPickerTest` (async: true) — pick protocol via `EvoDash.DirectoryPicker.Wx.Fake` injected through `:directory_picker_wx` env (`enabled: true` override in setup; test_helper.exs defaults to disabled). Tests: `pick/2` first/subsequent picks, wx-server-killed-between-picks recovery, mid-pick server-death → `:unavailable` + busy cleared, wx `init_fails` → async `:unavailable` + recovery, busy serialization via `FakeWx.set_gate/1` (second pick → sync `{:error, :unavailable}`, no result msg), disabled-config rejection. `pick/3 :file` mirrors: file dialog result `{:ok, "/fake/picked/file.txt"}`, `pick/2` ≡ `pick/3 :directory` (`{:ok, "/fake/picked/dir"}`), kind-agnostic busy, init-fail + disabled-config. Helper `wait_until_pick_ok/2` polls because result msg and `:pick_done` are sent in that order (busy can briefly linger). NO test covers the `:cancelled` result kind (user dismisses dialog); no path validation/normalization is tested — the picker only relays the path (source `normalize_path/1` = chardata→binary passthrough; no expand/exists check).
- `node_context_test.exs` → `EvoDash.NodeContextTest` (async: false, `EvoDashWeb.ConnCase`) — all delegates are thin node-first passthroughs to `EvoGit.RemoteNode.*` (local direct vs `:erpc` routing happens in RemoteNode); the LOCAL path (`node()`) is exercised throughout, plus one remote transport-failure case (see `approval_response/3`). Covers: cancel_task/force_kill_task (`:not_found`, `:pending`→`:cancelled` store-verified via `insert_fixture!/1`), get_task (nil / `%TaskInfo{}`), set_review_status/set_review_metadata casts, review git wrappers shape-only (`{:error, _}` against `/nonexistent` — real git calls fail, never raise), GitHub delegates (verbatim `{:error, {:enoent, "/nonexistent"}}`, `state:` opt accepted), get_resolved_config (scheduler/llm/tools/sandbox maps), get_recent_system_samples (`{:ok, list}`), custom-agents RPC (isolated `XDG_CONFIG_HOME`; list/save/duplicate_id/missing_name/delete/script round-trip + compile_error/empty clears/reload), `approval_response/3` (junk-decision whitelist is total pre-dispatch; valid decisions on the local path — `Code.ensure_loaded?(EvoGit.CommandApproval)`-guarded since the core module is parallel work, `{:error, :command_approval_unavailable}` until it lands, atom `:deny` idempotent; remote transport failure to `:"nonexistent-node@nowhere"` never raises — non-distributed test node → `{:error, {:error, {:erpc, :noconnection}}}`, distributed node → `{:error, :nodedown}`).
- `chat_history_test.exs` → `EvoDash.ChatHistoryTest` (async: true) — the `EvoDash.ChatHistory` GenServer + its named ETS table `:evo_dash_chat_history` (app-started child, chat_history.ex:171-189): supervision presence, `new_chat/0` (positive integer id from `System.unique_integer([:positive])`, becomes current), `current_chat_id/0`/`set_current_chat/1` (no id validation), `list_chats/0` newest-first by an internal `:monotonic` seq (NOT by id), `put_state/2`/`get_state/1` (opaque state; unknown id upserts as newest chat), `delete_chat/1` (clears current pointer if it was current), `prune/1` (keeps newest N; `0` clears; non-integer/negative ignored), `reset/0`. ## Known Issues / Test Gaps (multi-repo relevant)

- **No `NodeContext.start_task/3` test in this suite** (only a comment at node_context_test.exs:33 mentions `start_task/2`). `start_task/3` (node_context.ex:605) passes `opts` verbatim to `EvoGit.RemoteNode.start_task/3` — `:path`, `:foreign_repos`, `:mode`, `:agent`, `:model_id` threading has NO domain-layer regression coverage here (only LiveView-level coverage in projects_live_test/home_live_test).
- **`foreign_repos` appears NOWHERE** in node_context.ex or this test dir (rg: zero matches). Multi-repo opt threading is untested at the NodeContext layer.
- **Remote `:erpc` delegation path largely untested here** — most tests call with `node()` (local direct); the remote transport envelope (`{:error, {kind, reason}}`) is exercised ONLY for `approval_response/3` (nonexistent-node transport failure). All other remote delegates are never exercised in this suite.
- **Picker: no `:cancelled` result-kind test, no path normalization/existence assertions** — the fake always delivers literal `/fake/picked/dir` | `/fake/picked/file.txt` binaries; downstream path normalization is covered in `evo_dash_web/live/projects_live/project_flow_test.exs`, not here.

## Notes for Agents — async policy (per-suite)

Tests inside ONE module always run serially, so `async:` decides only whether a MODULE runs concurrently with OTHER modules — and `async: false` modules never run concurrently with `async: true` ones (ExUnit starts sync modules only after every async module finished).
The domain-layer suites here are `async: true` (`attached_file_test`, `chat_history_test`, `desktop_lifetime_test`, `directory_picker_test`, `markdown_render_test`, `settings_utils_test`, `update_status_test`) EXCEPT two that stay `async: false`:
- `active_tasks_test.exs` — the shared boot-created `:evo_dash_active_tasks` ETS table (application-owned, no process), which `EvoDashWeb.ConnCase` resets in setup; a concurrent async ConnCase reset while this file reads/writes would be a wipe race. The file resets it in setup + `on_exit` so its shape-agnostic atom sentinels never leak.
- `node_context_test.exs` — swaps the process-global `XDG_CONFIG_HOME` (L159-171) and juggles the GLOBAL `EvoGit.Store`/`EvoGit.TaskRegistry` singletons via `Supervisor.terminate_child/restart_child` (L9-10, L25-26).

Async-safety facts for the flipped suites:
- `chat_history_test.exs` reads the shared `EvoDash.ChatHistory` table; its only other consumer (`home_live_test.exs`) is `async: false`, so no concurrent async writer exists.
- `update_status_test.exs` reads + resets the shared `EvoDash.UpdateStatus` hub and injects app-env seams (`:update_notify_only_override`, `:desktop_release`, `EVOGIT_DESKTOP`), snapshot-restored; the other consumers (`system_live_test`, `live_hooks/update_status_test`) are `async: false`.
- `desktop_lifetime_test.exs` snapshots/restores the process-global `EVOGIT_LIFETIME_PORT` env var + the `:parent_stop_fun` app env; no other async module reads either key.
- `directory_picker_test.exs` overrides the app env `:directory_picker` (`enabled: true`) + `:directory_picker_wx` = `EvoDash.DirectoryPicker.Wx.Fake` and uses the app-started picker's global busy flag + `FakeWx` `:persistent_term` mode/gate; no other async module calls `DirectoryPicker.pick` (its only other caller, `projects_live_test.exs`, is `async: false`).
