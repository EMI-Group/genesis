# Live Hooks Test Directory

## Intent

ExUnit suites for the global on-mount hooks. The `live_view/0` macro (`apps/evo_dash/lib/evo_dash_web.ex` L49-58) registers them in order: SetLocale → **NodeAware** → Appearance → DesktopQuit → UpdateStatus → Guide, so EVERY real LiveView mount (dead render AND connected) runs the full chain — including the NodeAware sidebar hub seed (`on_mount/4` → `EvoDash.ActiveTasks.get` at `node_aware.ex` L110-111 + `assign_new` seeds L121-122).

Two styles: **pure unit/socket tests** (no LiveView boot) and **full LiveView integration through `Layouts.app`** (which exercises the shared on-mount chain as a side effect).

## Notes for Agents

- **NodeAware hub seed runs on every real mount in this directory**: `EvoDash.ActiveTasks` (supervised child of `EvoDash.Application`, `application.ex` L27) is alive for the whole `mix test` run and its `{nil, node()}` local key is shared across ALL evo_dash suites in the OS process. node_aware_test resets it per test in setup (L50) and the mounting suites in this directory now do too — guide_test L111, desktop_quit_test L26, appearance_test L54 (each setup calls `EvoDash.ActiveTasks.reset()`). A warm non-empty local hub from any earlier suite would otherwise seed sidebar tasks into their dead-render html.
- **Connected-mount fetch side effect**: mounting suites with a cold LOCAL hub spawn a fire-and-forget fetch (`EvoDash.TaskSupervisor`) against the TaskRegistry in force at mount time. guide_test isolates its registry (empty → harmless); desktop_quit_test and appearance_test run against the REAL global registry — task rows left by other suites could warm the sidebar mid-test, and the spawned fetch can overlap other async:false suites' TaskRegistry terminate/restart windows (the documented ~1-in-7 full-suite flake mechanism; see `apps/evo_dash/test/CONTEXT.md` Known Issues).
- **Fragility of HTML assertions**: no suite in this directory asserts on "Active Tasks" sidebar content/absence. Asserted strings are modal/guide-specific ("Quit Genesis?", "Stop System?", "Genesis Guide", "hello guide", "fixed top-4 right-4 z-50", phx-click/hook attrs, "Go" link text) — none collide with sidebar task rows, but note guide_test L121-124 already documents that a literal "Genesis Guide" assertion would false-positive on the layout's always-rendered HTML comment (the tests use the unique panel class `fixed top-4 right-4 z-50` instead). Layout gate: `layouts.ex` L179 (`@running_tasks != [] or @pending_tasks != []`).
- **Direct on_mount calls DO read the hub**: `node_aware.ex` L110-111 (`node_context_from_params` + `hub_snapshot`) runs unconditionally on both dead and connected paths — only the connected-mount FETCH (L133-155) is gated on `connected?(socket)` AND a cold LOCAL hub. Direct-call tests therefore observe: reset-cold hub → seeds `[]` via `assign_new` (boot sockets preset no running/pending); pre-warmed hub → seeds the snapshot synchronously; dead-render sockets never receive a fetch message; connected cold-local sockets receive `{:node_aware_active_tasks, 1, nil, node(), ...}`.
- **`use ExUnit.Case` vs `use EvoDashWeb.ConnCase`**: node_aware_test and update_status_test use plain `ExUnit.Case` (no conn fixtures); the three mounting suites use `ConnCase` + `import Phoenix.LiveViewTest`. All five are `async: false`.
