# Live Hooks Test Directory

## Intent

ExUnit suites for the global on-mount hooks. The `live_view/0` macro (`apps/evo_dash/lib/evo_dash_web.ex` L49-58) registers them in order: SetLocale → **NodeAware** → Appearance → DesktopQuit → UpdateStatus → Guide, so EVERY real LiveView mount (dead render AND connected) runs the full chain — including the NodeAware sidebar hub seed (`on_mount/4` → `EvoDash.ActiveTasks.get` at `node_aware.ex` L110-111 + `assign_new` seeds L121-122).

Two styles: **pure unit/socket tests** (no LiveView boot) and **full LiveView integration through `Layouts.app`** (which exercises the shared on-mount chain as a side effect). The pure tests live in dedicated `*_pure_test.exs` splits so they can run `async: true`.

`async:` split: four suites are `async: false` (`node_aware_test`, `guide_test`, `update_status_test`, `appearance_test`); three are `async: true` (`node_aware_pure_test`, `guide_pure_test`, `desktop_quit_test`) — 123 tests total. Rationale: see "Notes for Agents — async policy".

## Notes for Agents

- **NodeAware hub seed runs on every real mount**: `EvoDash.ActiveTasks` is a boot-created named public ETS table (`:evo_dash_active_tasks`, owned by the long-lived application process — the module is a pure ETS helper with no process), alive for the whole `mix test` run, and its `{nil, node()}` local key is shared across ALL evo_dash suites in the OS process. node_aware_test resets it per test in setup (L48); the mounting suites reset it too — guide_test L50, desktop_quit_test L33 (each setup calls `EvoDash.ActiveTasks.reset()`; appearance_test additionally resets the sibling `EvoDash.AccentCache` per-node accent hub). A warm non-empty local hub from any earlier suite would otherwise seed sidebar tasks into their dead-render html.
- **Connected-mount fetch side effect**: EVERY mounting suite with a LOCAL page spawns a fire-and-forget fetch (`EvoDash.TaskSupervisor`) on each connected mount against the TaskRegistry in force at mount time (the local fetch is unconditional). guide_test isolates its registry (empty → harmless); desktop_quit_test and appearance_test run against the REAL global registry — task rows left by other suites could surface as fetched sidebar rows mid-test.
- **Fragility of HTML assertions**: no suite in this directory asserts on "Active Tasks" sidebar content/absence. Asserted strings are modal/guide-specific ("Quit Genesis?", "Stop System?", "Genesis Guide", "hello guide", "fixed top-4 right-4 z-50", phx-click/hook attrs, "Go" link text) — none collide with sidebar task rows, but note guide_test already documents that a literal "Genesis Guide" assertion would false-positive on the layout's always-rendered HTML comment (the tests use the unique panel class `fixed top-4 right-4 z-50` instead). Layout gate: `layouts.ex` L179 (`@running_tasks != [] or @pending_tasks != []`).
- **Direct on_mount calls DO read the hub**: `node_aware.ex` L114-115 (`node_context_from_params` + `hub_snapshot`) runs unconditionally on both dead and connected paths — the connected-mount FETCH is gated only on `connected?(socket)` AND a LOCAL context (`seed_node_id == nil`). Direct-call tests therefore observe: reset-cold hub → seeds `[]` via `assign_new`; pre-warmed hub → seeds the snapshot synchronously (then the connected local fetch still fires); dead-render sockets never receive a fetch message; connected local sockets receive `{:node_aware_active_tasks, 1, nil, node(), ...}`; connected remote/pending sockets never do on mount.
- **`use ExUnit.Case` vs `use EvoDashWeb.ConnCase`**: node_aware_test, node_aware_pure_test, guide_pure_test, and update_status_test use plain `ExUnit.Case` (no conn fixtures); guide_test, desktop_quit_test, and appearance_test use `EvoDashWeb.ConnCase` + `import Phoenix.LiveViewTest`.

## Notes for Agents — async policy (per-suite, verified)

**Scheduling model**: ExUnit runs ALL `async: true` modules first (concurrently, up to `max_cases`) and only then runs `async: false` modules one at a time — so a sync module NEVER overlaps another module (async or sync), and an async module's only concurrency partners are the other async modules (Elixir 1.20 `ex_unit/runner.ex` `async_loop/4`). A flip is therefore only unsafe when another `async: true` module touches the same global state.
- **`node_aware_pure_test.exs`, `guide_pure_test.exs`, `desktop_quit_test.exs` → `async: true`.** The pure splits touch no global Store/TaskRegistry, `XDG_CONFIG_HOME`, or ETS hub, so they are safe alongside the other async modules. desktop_quit_test is the SOLE async owner of `:desktop_quit_stop_fun` (it saves/restores the seam; `update_status_test.exs`, the other user, is `async: false`) and writes only the `ActiveTasks` hub, via ConnCase's reset.
- **`node_aware_test.exs`, `guide_test.exs` → `MUST-STAY-SYNC`**: the integration setups terminate + restart the production `EvoGit.TaskRegistry`/`EvoGit.Store` GLOBAL singleton under the fixed registered name; node_aware_test additionally swaps `XDG_CONFIG_HOME` and registers 12 fake ConnectionManagers in the global unique `EvoGit.RemoteConnection.Registry`.
- **`appearance_test.exs` → `MUST-STAY-SYNC`**: `System.put_env("XDG_CONFIG_HOME", ...)` mutates a process-global env var (no per-test or per-process seam exists — an app-env override would itself be global), and it writes the `AccentCache` hub.
- **`update_status_test.exs` → `MUST-STAY-SYNC`**: shares `:desktop_quit_stop_fun` + the `EvoDash.UpdateStatus` hub with the `async: true` `desktop_quit_test.exs`.
- **Cross-suite hazard for ANY async fake-manager suite**: `EvoGit.RemoteConnection.Registry` is `keys: :unique` and fakes call non-bang `Registry.register/3` whose error tuple is ignored — two suites using the SAME target id concurrently would silently route lookups to the first-registered manager (assertion failures, not a crash). Keep new async fake ids unique.

## Notes for Agents — deterministic negative waits (do not re-grow these windows)

The negative "nothing was fetched / nothing was scheduled" assertions in `node_aware_test.exs` and `node_aware_pure_test.exs` are backed by an observable side effect, so their `refute_receive` windows are a small belt-and-braces margin (50 ms), never the evidence.

- **Sidebar-fetch backstop — `:tasks_load_seq`**: `NodeAware.request_tasks_load/1` (the single spawner behind `on_mount/4`'s connected-LOCAL fetch, `assign_node/2`'s context-change reload and `reload_tasks/1`) bumps the socket's `:tasks_load_seq` assign BEFORE spawning on `EvoDash.TaskSupervisor`, and `on_mount/4` seeds it to 0 — so `assigns[:tasks_load_seq] == 0` DETERMINISTICALLY proves no fetch was spawned (no `{:node_aware_active_tasks, ...}` message can ever arrive), and an unchanged seq proves the `:tasks_node_loaded` dedup guard suppressed a re-spawn.
- Every `refute_receive {:node_aware_active_tasks, _, _, _, _}, 50` in node_aware_test.exs sits next to its `tasks_load_seq` assertion; the two `initiate_remote_connect/2` "NO `{:remote_connect_result, ...}` self-message" tests first await `not Process.alive?(caller)` for the spawned connect Task (its `{:error, reason}` arm is its LAST expression, so a dead Task proves any send is already in the mailbox) before their 50 ms refute.
- **Deliberately kept full window**: the `nil target_id → no spawn` `initiate_remote_connect/2` test keeps `refute_receive {:remote_connect_result, _, _}, 150` — it has no deterministic backstop (its `GenServer.call(manager, :calls) == []` corroboration is itself timing-dependent).
- **Debounce backstop**: the `handle_task_info/2` drop/coalescing negatives use 50 ms windows (~5× the 10 ms `:node_aware_reload_debounce_ms` test seam), each proven by the unchanged-socket / `tasks_reload_pending == false` / already-consumed-`assert_receive` assertions — any path reaching `debounce_task_reload/1` would have returned a CHANGED socket with `tasks_reload_pending: true`.
- `await_until/2`'s `Process.sleep(10)` is a bounded poll (10 ms ticks, 2000 ms deadline) — not a fixed wait. The `Process.sleep(state.delay_ms)` in the `ConnectionManager` fake is deliberate test choreography.
- Current cost of the two suites: ~2.1 s for 69 tests, 0 stray console log lines across repeated runs.
