# Test Directory — AgentsLive Support Modules

## Intent

Support-module regression tests mirror `apps/evo_dash/lib/evo_dash_web/live/agents_live/`.
Pure reducer suites are async and require no page mounts or shared state mutations.
`stream_watch_test.exs` is also async, using hand-built Phoenix sockets, unique consumer-local PubSub topics and a worker-command capture boundary without mutating global runner seams.
`load_data_model_label_test.exs` is synchronous because it replaces the global `:agents_list_runner` seam used by the async page suite.
Stateful AgentsLive page integration tests live in `../agents_live_test.exs` (parent directory, owned elsewhere).

## Routing Table

- `runtime_stream_test.exs` → pure reducer initialization, call identity, transition and retention contracts.
- `stream_watch_test.exs` → async transport, atomic snapshot barrier and worker-command boundary contracts.
- `../agents_stream_integration_test.exs`, `../agents_stream_render_test.exs` and `../agents_stream_watch_lifecycle_test.exs` → mounted/render/actual-worker coverage (siblings — read-only, escalate writes to parent).

## Constraints

- New support tests use `ExUnit.Case, async: true`, no `ConnCase`, no global hub resets and no app-env mutations.
- StreamWatch command-boundary tests install the test pid as `inspector_stream_worker` to capture desired/cleanup commands without starting its actual worker or invoking watcher RPC runners.
- Consumer-local PubSub checks use per-test unique agent ids and synchronous broadcast dispatch as the witness before zero-timeout duplicate/unsubscribed assertions.
- The existing synchronous model-label suite retains its documented global runner ownership.
- Fixtures are built with file-local helpers (`agent/3`, `commit/2`,
  `chain/1`, `raw/2`) deliberately mirroring the shapes the module reads.
- Assertion styles follow the sibling convention: one-sentence explanatory
  comments above non-obvious expectations.
- `commit_graph_test.exs` is ~2000 lines — a legitimately long suite (one
  `describe` per model rule group plus an explicit totality matrix); don't split
  casually.
## Inspector Stream Coverage Boundaries

The tests execute production reducers and transport helpers, never a copied reducer or replacement implementation.
The stream suites never start a real core session, so Session/provider callback behavior remains outside this node's coverage.
`runtime_stream_test.exs` uses nested `activity.current_call` maps with `id`, `turn`, `attempt`, `text` and `thinking`, including optional string-keyed snapshots.
`Snapshot.phase` describes session lifecycle independently from activity phases `:idle`, `:llm_waiting`, `:llm`, `:llm_complete`, `:retry_wait` and `:tools`.
An activity event replaces the whole activity and current call, text/thinking events append to that call, a new attempt replaces prior excerpts and nil current call retires the projection.
`stream_watch_test.exs` includes compatibility coverage through public core `Activity.apply/2` and `Snapshot.from/3`, then feeds those snapshots/events through production consumer helpers.
Its self-pid worker-command capture boundary and consumer-local PubSub checks establish subscription ownership, not actual core watch registration or provider callback delivery.
Real-session mid-call attachment and completed-call checkpoint retirement coverage belongs to the parent `../real_stream_consumers_test.exs`; these helper fixtures establish only reducer/transport compatibility.
`RuntimeStream` keeps raw checkpoint messages untouched and separate from the current live projection; `seed/3` replaces checkpoint history without duplication while the transport owns node/token guards and snapshot admission.
These helper suites make no guessed historical checkpoint-part suppression assertions.
The reducer suite retains independent response/thinking byte budgets, exact-boundary and UTF-8-safe copied-prefix assertions, cumulative omissions, bounded tool descriptors/names and uncapped checkpoint fidelity.
These reducer contracts do not assert a UI no-thinking label; production presentation and mounted page/component suites own that display contract.
The actual serialized watch/unwatch worker, consumer-death cleanup and blocked-RPC A-to-B-to-A race are exercised by the parent `../agents_stream_watch_lifecycle_test.exs`, not this child's command-capture fixture.
Those synchronous worker tests own BEAM-global `:agents_watch_runner` and `:agents_unwatch_runner` seams; this child's async tests never replace them.
`ready/5` rejects a foreign viewed node before issuing worker commands, rejects obsolete same-target tokens without unregistering the current watch, and cleans up obsolete successful registrations for another agent on the current node.
A snapshot explicitly naming another agent fails with `:snapshot_agent_mismatch` before adopting its seq, clears buffered deltas and permits explicit attach retry.
A duplicate ready result cannot replace an established snapshot even when its seq is newer; the registration watermark takes precedence over the snapshot's embedded seq.
Matching worker death preserves the last checkpoint and excerpts with a visible error, ignores later deltas/results, and allows a fresh attachment to replace rather than append checkpoint history.
The helper retry fixture reinstalls only its worker-command capture pid after `down/4` clears worker ownership; it does not spawn a replacement worker or claim RPC ordering coverage.
Page/template integration exists in `AgentsLive`, with live excerpts separate from checkpoint history; presentation and checkpoint-part rendering are owned outside this child.
`StreamWatch.reconcile/1` owns the watched checkpoint refresh: it coalesces requests, keeps the coherent checkpoint/excerpt pair frozen and admits replacements through `reconciled/6` with node/token/agent/request guards.
Retirement or replacement freezes the entire boundary batch; buffered replay above the admitted snapshot watermark may trigger another atomic barrier rather than mixing checkpoint and live-call generations.
Pending buffers reject stale/duplicate sequences and malformed/foreign batches before capacity accounting, with explicit 128-batch and 1 MiB overflow failures.
The watch worker obtains reconciliation through the snapshot/watch runner, never an independent history runner; these command-boundary tests assert reconcile commands rather than executing runner RPCs.
Watch-owned checkpoint history and its live projection are replaced together, while mounted page history ownership and actual worker RPC invocation remain sibling-suite responsibilities.
Deltas have no publisher-node or attachment-token field, so old same-agent deltas across node switches cannot be distinguished by these helpers.
Snapshot-plus-sequence replay cannot recover pre-attachment chunks absent from the core's snapshot.
Run the scoped tests with `mix test apps/evo_dash/test/evo_dash_web/live/agents_live` from the umbrella root.

## Persistent Terminal Snapshot Contracts
`stream_watch_test.exs` exercises the public `StreamWatch.closed/4` boundary for `{:agent_stream_closed, agent_id, snapshot, seq}` with async command capture, not a real Session or page-message handler.
The selected-agent fixture sets `selected_agent_id` before attachment, and `owns?/2` includes pending, healthy, failed and terminal watches while rejecting another agent, deselection, obsolete tokens, changed node/target scope, pending remote contexts and detached watches.
`terminal?/2` requires an admitted final handoff rather than a finished delta, and `active?/2` excludes admitted terminal watches.
Closure replaces checkpoint messages and live excerpts atomically even when the reducer already received a finished delta, preserving exact final answer and reasoning data while clearing buffered batches, errors and reconciliation state.
Freshness is checked against applied sequences, required boundary sequences and buffered sequences, with rejection leaving the socket and local subscription untouched and equality accepted without sequence regression.
Mismatched agent identities, nonterminal snapshots, inconsistent embedded/envelope sequences, invalid sequences and non-Snapshot payloads are inert.
Admission unsubscribes the consumer locally and emits exactly one same-token desired-nil cleanup command; duplicate or newer repeated closures, reattachment, refresh and deltas cannot reopen or overwrite the terminal pair before explicit detach.
Closure can overtake initial registration or reconciliation and recover failed registration/reconciliation, while late successful or failed ready/reconciled envelopes preserve the terminal socket exactly and issue no extra cleanup.
`RuntimeStream.seed/3` permits sequence regression for admitted snapshots, so these freshness assertions live at the transport boundary rather than assuming reducer protection.
Tests of the page's incoming closure-message handler, actual Session removal and real worker-result races belong to parent integration suites, not these command-capture helpers.

## Page-Level Commit-History Contracts (owned by `../agents_live_test.exs`)
`@left_view` (`:tree` default | `:commits`) is toggled by `handle_event("switch_left_view", %{"view" => "tree"|"commits"})` (any other value is a no-op); the segmented buttons are `#left-view-tree` / `#left-view-commits`.
Switching to `:commits` lazily fetches the TEMPORAL graph via `:agents_commit_graph_runner` (default `&EvoDash.NodeContext.list_task_commit_graph/5`), resolved AT SPAWN TIME inside an `EvoDash.TaskSupervisor` child — stub it BEFORE `live/3` and never let a test reach the real RPC/core (`EvoGit.CommitGraph` may be absent).
The fetch is TASK-SCOPED: `commit_graph_groups/1` groups eligible agents by `{repo_key, task_id}` (repo_key = `repo_root`), and each group issues ONE call `runner.(node, task_id, repo_key, live_tips, limit: 100)`, where `live_tips` is that group's de-duplicated non-nil `current_commit`s among its NON-ended agents (an all-ended group is still fetched with `live_tips == []`); a non-`{:ok, _}` reply HALTS the per-group loop.
Apply: `handle_info({:commit_graph_loaded, node, seq, result}, socket)`, stale-guarded on the viewed node AND `seq < commit_graph_seq`; `raw_by_repo` groups sharing a `repo_key` are UNIONED (commits deduped by `:sha`, refs merged); `{:error, reason}` KEEPS the last good graph and only sets `commit_graph_error`.
The graph is fed by `commit_graph_agents/1` = live `@agents` ++ `@retained_agents` (live wins) while the agent TREE still shows only `@agents`; `@retained_agents` is `%{agent_id => agent_map}` holding an ended agent's last-known map with `ended: true` (populated on `{:agent_removed, …}` or a full-refresh disappearance, dropped on reappearance, RESET on a node switch), and `apply_agent_removed/2` keeps `selected_agent_id`.
Helpers: `install_agents/1`, `install_commit_graph_runner/1` (ARITY-5 stub recording the 6-tuple `{:commit_graph_call, node, task_id, repo_root, live_tips, opts}`, responder keyed by `repo_root`), `graph_error_responder/0`, `graph_partial_responder/1`, `mount_loaded_commit_graph/2` (`select: true` selects the agent in the tree view before switching), `clear_agents_env/0` (also clears `:agents_commit_graph_runner`), `flush_agents_load/2`.
Page-level ids: `#commit-graph` (`phx-hook="CommitGraph"`) → the per-repo wrapper whose id IS `repo.repo_dom_id` → sticky `#cg-lane-header-<dom>` (one `#cg-lane-<dom>-<lane>` chip per lane — a `select_agent` button, or a non-clickable "Pre-task" span for neutral lane 0) + `#cg-list-<dom>.cg-list.relative` (absolute `svg.cg-gutter` beside `.cg-rows`); the gutter holds every `path.cg-edge` then every `g.cg-node` (`#commit-node-<dom>-<sha>`); edge ids are `#commit-edge-<dom>-<from>-<to>` (solid `:parent`, dashed `4 3` `:merge`) vs agent connectors `#commit-edge-<dom>-<kind>-<owner>-<from>-<to>`; rows are `div.cg-row` (`#commit-row-<dom>-<sha>`, `data-commit-graph-anim="row"`) carrying `select_agent` + `phx-value-id` (both omitted for an unowned node); chips are `button.cg-agent-tag` / `span.cg-ref-tag`.
The sibling COMPONENT suite (`../components/commit_graph_view_test.exs`) renders the component in isolation via `render_component/2`, bypassing the diff path.
Socket-state assertions remain the right tool for stale-seq / foreign-node / failed-refresh cases.
Node-switch reset is tested by calling `EvoDashWeb.AgentsLive.handle_params(%{}, "/agents", socket)` directly on the socket from `:sys.get_state(view.pid)` with `previous_node` forced to differ (mutating `current_node` via `:sys.replace_state` does NOT run the reset); the reset clears the commit-graph assigns while `@left_view` SURVIVES.
`describe "commit history view — partial success and the fingerprint gate"` pins a garbage-shaped group still loading with only the good repo in `@commit_graph_raw` and NO error/stale strip, and proves a commit-irrelevant `{:agent_updated, id, [status: :waiting, total_tokens: 999], node()}` records NO new runner call while `[current_commit: "new_sha"]` records one with the new tip.
Two production behaviours the tests work around: the commits-view right-hand detail panel keeps the last-known agent data after a removal (assert ABSENCE via the tree view), and `live_tips` order inside a group is agent iteration order (assert order only for groups with distinct tips).
