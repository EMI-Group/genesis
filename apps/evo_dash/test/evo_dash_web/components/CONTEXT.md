# Components Test Directory

## Intent

ExUnit suites for the function components in `./lib/evo_dash_web/components/` (one test file per component module). All suites are `async: true`, import `Phoenix.LiveViewTest`, and use `render_component/2` + Floki (parsed via `Floki.parse_document!/1` — the file-local `parse/1` helper — because `Floki.find/2` + `attribute/2` require a parsed tree, not a raw binary).

### commit_graph_view_test.exs (11 describes, 47 tests)

`EvoDashWeb.AgentsComponents.CommitGraphView.commit_graph_view/1` — the TEMPORAL (git commit history) view of the Agents page left panel, a VERTICAL GitKraken/GitLen-style commit graph (one visible row per commit, top → bottom by agent depth, with an absolute left gutter `<svg>` drawing the dots and the child → parent edges) — rendered in ISOLATION (no `live/3`, like the rest of this dir).
The happy-path fixture is REAL builder output — `EvoDashWeb.AgentsLive.CommitGraph.build/2` fed realistic agent maps + a raw commit graph (the fixture has `column_count == 2`, so the derived gutter width is `24 + 2 * 16 = 56` and the height is `node_count * 44`). Hand-crafted repo/node/edge/agent maps cover shapes the builder cannot produce (odd/absent grid values, a fixed `repo_dom_id`, unowned entries, missing colors, non-map entries).
Coverage: root markers (`#commit-graph` + `phx-hook="CommitGraph"` → `#commit-graph-body-<node_key>` incl. a NON-DEFAULT `node_key`, which changes only the body id); states (`:loading` → a spinner + "Loading commit history…" and nothing else; `:empty` → "No commit history yet."; `:error` with no data → `#commit-graph-error` "Could not load commit history."; mutually exclusive texts; `#commit-graph-stale-warning` rendered ALONGSIDE the still-rendered graph when repos are non-empty AND error non-nil); repo sections (wrapper `div` id IS `repo.repo_dom_id` VERBATIM — the builder already emits `commit-graph-repo-<slug>-<hash>`, the component adds NO prefix — with the repo-name header as its FIRST child block and the list BELOW it; two repos → two independent sections, each with its own gutter/list); list + gutter geometry (`#cg-list-<dom>.cg-list.relative` holding the absolute gutter `svg.cg-gutter.absolute.left-0.top-0.pointer-events-none` with `role="img"`, the `"Git commit history graph"` aria-label, `width = 24 + column_count * 16` (`@gutter_pad * 2 + column_count * @col_w`), `height = node_count * 44` (`@row_h`) and a `"0 0 <w> <h>"` `viewBox`; the `.cg-rows` container left-padded by the gutter width; one `div.cg-row` per node at the fixed `height: 44px`; a repo with NO nodes renders `p.cg-empty-note` "No commit history for this repository." and NO gutter); edges (`path.cg-edge[data-commit-graph-anim="edge"]` per model edge with the stable `#commit-edge-<dom>-<from_sha>-<to_sha>` id, `fill="none"` and an ORTHOGONAL (right-angle) `d` (`M fx fy L fx my L tx my L tx ty`, corner at the vertical midpoint); a `:parent` edge is SOLID (`stroke-width="2"`, no `stroke-dasharray`) vs a `:merge` edge DASHED (`stroke-dasharray="4 3"`, `stroke-width="1.6"`); stroke = the child owner's depth hue, muted base ink for an edge with no owner); nodes (`g.cg-node[data-commit-graph-anim="node"]`, one per model node, id `#commit-node-<dom>-<sha>`, carrying `data-cg-sha`/`data-cg-agent-id` and an inner `<title>` tooltip (base prefix, first line only, refs); a `:base` node is HOLLOW at `r = @base_r` (4) with a base-content stroke, a real commit FILLED at `r = @node_r` (6) — the gutter is `pointer-events: none`, so the click contract lives on the ROWS); rows (`div.cg-row[data-commit-graph-anim="row"]` id `#commit-row-<dom>-<sha>` with `data-cg-sha`/`data-cg-agent-id`, `phx-click="select_agent"` + `phx-value-id` (both OMITTED for an unowned node), the first-line `.cg-row-sha` short sha + either a `.cg-base-label` "base" (a `:base` node — no message/meta) or `.cg-row-message` (first-line subject), and the `.cg-row-meta` `"<author> · <date>"`); tags (`button.cg-agent-tag#commit-agent-tag-<dom>-<sha>-<start|end>-<agent_key>` per agent in `start_ids` (SOLID border, `start` marker) and `end_ids` (DASHED border, `end` marker), labelled `T<task_local_id || agent_id>` in that agent's depth hue and firing `select_agent`, plus non-clickable `span.cg-ref-tag#commit-ref-tag-<dom>-<sha>-<ref_key>`; an agent that no longer exists still renders its chip); animation markers (`data-commit-graph-anim` takes EXACTLY `edge`/`node`/`row`; NO animation classes in server markup; NO `phx-update` anywhere); selection (`selected_id` adds an EXTRA `circle.cg-node-ring` child on the selected agent's START node (SOLID primary) and END node (DASHED primary), accents those rows and their `.cg-row-marker` (`start`/`end`), and renders `#cg-selection-readout-<dom>` `"Selected T<id> · <start-short-sha> → <end-short-sha>"` (the sha range is dropped when the agent has none); a `nil`/non-matching id → no rings, no readout); ended (retained) agents (`ended: true` → the agent's owned node dots `fill-opacity: 0.5` (hue/status fill unchanged), its owned edges `stroke-opacity: 0.4`, its rows the `opacity-50` class and its tooltip/`start`/`end` markers untouched — while an agent whose `ended` key is ABSENT or non-`true` (incl. `nil`/`false`) is BYTE-IDENTICAL to a live agent); defensive shapes (non-map repo/node/edge/agent entries are dropped without crashing; a node without a proper owner omits the click contract; odd grid values and non-binary shas degrade without crashing; an agent without a color falls back to base ink).
Every DOM id is derived from the fixture's `repo_dom_id`/sha/agent id — the builder's `repo_dom_id/1` already returns a `commit-graph-repo-<slug>-<hash>` string and the component adds NO prefix, so never assume a single prefix. NOTE: Floki's HTML parser lowercases attribute names, so the SVG's `viewBox` is queried as `viewbox`.
File-local Floki helpers: `parse/1`, `attr/2`, `text/1`, `dom_id/1`, `render_repos/2`, `element_children/1`, `edge_selector/2`, `node_title/2`; fixtures `happy_repos/0` + `happy_two_repo_fixture/0` (both REAL `CommitGraph.build/2` output) and the hand-crafted `repo_view/1`, `node_view/1`, `edge_view/1`, `agent_map/1`; the `happy/0` / `happy_selected/1` one-liners each return a `{repo, dom, tree}` triplet, and `happy_ended/0` is the same happy fixture with its agent flagged `ended: true` (`mark_agent_ended/2`) — the real builder output is otherwise untouched and `build/2` already emits `ended: false` for live agents, so the pre-existing expectations stay valid.
File length ~1060 lines — a legitimately large render-contract suite (one describe per DOM contract group); don't split casually.
