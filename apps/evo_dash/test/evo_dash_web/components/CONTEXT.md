# Components Test Directory

## Intent

ExUnit suites for the function components in `./lib/evo_dash_web/components/` (one test file per component module). All suites are `async: true`, import `Phoenix.LiveViewTest`, and use `render_component/2` + Floki (parsed via `Floki.parse_document!/1` — the file-local `parse/1` helper — because `Floki.find/2` + `attribute/2` require a parsed tree, not a raw binary).

### commit_graph_view_test.exs (11 describes, 31 tests)

`EvoDashWeb.AgentsComponents.CommitGraphView.commit_graph_view/1` — the HORIZONTAL AGENT-SWIMLANE temporal view (plain HTML divs + spans, NO SVG) — rendered in ISOLATION (no `live/3`, like the rest of this dir).
The main happy-path fixture is REAL builder output — `EvoDashWeb.AgentsLive.CommitGraph.build/2` fed realistic agent maps + a raw commit graph (a1 depth 0, base `b0000000`, current `c2000000`; a2 depth 1, base `c2000000`, current `c3000000`; commits c1 → c2 → c3 chained, c1's parent absent from the fetch) — so the component provably renders real `repo_view` shapes; hand-crafted repo/lane/marker/agent maps cover odd/absent geometry, a fixed `repo_dom_id`, and empty lanes/markers.
Coverage: root markers (`#commit-graph` + `phx-hook="CommitGraph"`, body id `commit-graph-body-<node_key>` incl. a non-default node key); repo sections (section `id = repo.repo_dom_id` VERBATIM — the builder already emits `commit-graph-repo-<slug>-<hash>`, the component adds NO prefix — with the repo-name header as the section's FIRST child block and the lane rows in the block BELOW it; two repos → two independent sections; NO `<svg>`/`<circle>`/`<path>` anywhere); agent rows (`#commit-agent-row-<dom>-<agent_id>` — exactly one per lane, DOM order == lane order `{depth, id}`; the left gutter's status-dot `<span>` carries `style="background-color: <Helpers.agent_status_svg_color(status)>"` + the mono `T<task_local_id || id>` label; `title="T<label> · <status label>"`; the ROW owns the `phx-click="select_agent"` + `phx-value-id` contract — exactly one click target per lane, markers/lane bar carry none); lane progress bars (`#commit-lane-<dom>-<agent_id>` + `data-commit-graph-anim="lane"`, `style="left: <L>%; width: <W>%; background-color: <depth hue>"` — `L = from_column/count*100`, `W = max(to-from+1,1)/count*100` compacted by `pct/1`, pins `left: 0%; width: 66.667%` for a1 and `left: 66.667%; width: 33.333%` for a2; tinted with the agent's depth hue, `#7c38dc` for depth 0; OMITTED when `column_count` is not positive or the bounds are not integers); commit markers (`#commit-marker-<dom>-<agent_id>-<sha>` + `data-commit-graph-anim="node"`, ONE per commit per lane with no duplicates, DOM order == `lanes × markers`; `left = (column + 0.5)/count*100` → `16.667%` / `50%` / `83.333%`; TIP marker = `Helpers.agent_status_svg_color(status)` + `size-3`, non-tip = the depth hue + `size-2.5`; `title` = first-line message · short sha · author · `YYYY-MM-DD HH:MM` date · comma-joined refs, multi-line body dropped, ref-less marker has no ref segment); percentage layout (every `[id^="commit-lane-"]`/`[id^="commit-marker-"]` style matches `left: <n>%` with NO `px`; the status dot's style is a color, not a position; NO `min-width`/`<svg>`/`viewBox`); selection styling (`selected_id` = a STYLE change on the SAME elements — the agent's row gains `bg-primary/5` and its TIP marker gains `ring-2 ring-primary-standalone`, its non-tip marker and the unselected agent's tip gain nothing; marker/row element counts are identical to the unselected render, so NO stacked extra element; `nil`/non-matching → no tint, no ring anywhere); view states (loading wins over a non-nil error with empty repos → spinner + "Loading commit history…", empty → "No commit history yet.", error with empty repos → `#commit-graph-error` "Could not load commit history."; mutually exclusive texts; body wrapper present in every state); stale warning (`#commit-graph-stale-warning` renders AND the swimlanes still render when repos non-empty AND error non-nil; hard error suppressed); animation markers (exactly 3 `node` + 2 `lane` markers on the happy fixture, `edge` absent; NO `phx-update` anywhere); defensive shapes (a repo missing `column_count`/`lanes`/`markers` → header only; columns + empty lanes → header only; non-map lane/marker entries dropped while the surviving map lane/marker render; an agent with `color` nil/`""`/non-binary → `var(--color-base-content)` fallback on both its lane bar and markers; `column_count: "3"` → no lane bar and marker `left: 0%`, non-binary marker sha still gets a stable DOM id).
DOM ids are always derived from the fixture's `repo_dom_id` — the builder's `repo_dom_id/1` already returns a `commit-graph-repo-<slug>-<hash>` string and the component adds NO prefix, so never assume a single prefix.
File-local Floki helpers: `parse/1`, `attr/2`, `dom_id/1`, `render_repos/2`, `positioned_elements/1`, `style_of/2`, `title_of/2`; fixtures `happy_repos/0` + `happy_two_repo_fixture/0` (both built by the REAL `CommitGraph.build/2`), `repo_view/1`, `lane/1`, `agent/1`, `marker/1`.
