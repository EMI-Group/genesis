# Components Test Directory

## Intent

ExUnit suites for the function components in `./lib/evo_dash_web/components/` (one test file per component module). All suites are `async: true`, import `Phoenix.LiveViewTest`, and use `render_component/2` + Floki (parsed via `Floki.parse_document!/1` — the file-local `parse/1` helper — because `Floki.find/2` + `attribute/2` require a parsed tree, not a raw binary).

### commit_graph_view_test.exs (12 describes, 35 tests)

`EvoDashWeb.AgentsComponents.CommitGraphView.commit_graph_view/1` — the TEMPORAL (git commit history) view of the Agents page left panel, a COMMIT-CENTRIC HORIZONTAL SVG DAG (commits are grid nodes, one lane row per agent) — rendered in ISOLATION (no `live/3`, like the rest of this dir).
The happy-path fixtures are REAL builder output — `EvoDashWeb.AgentsLive.CommitGraph.build/2` fed realistic agent maps + a raw commit graph (a1 depth 0 `:running`, base `b0000000` → current `c2000000`; a2 depth 1 `:completed`, base `c2000000` → current `c3000000`; plus a folded side commit `c2b00000` from Dave) — so the component provably renders real `repo_view` shapes: 5 nodes / 5 edges (4 `:parent` + exactly 1 `:merge`) / 2 lanes, `viewBox "0 0 779 132"` (selected: `"0 0 779 156"`), `height="140"` (clamped up to `@min_h`). Hand-crafted repo/lane/node/edge maps cover shapes the builder cannot produce (odd/absent geometry, a fixed `repo_dom_id`, unowned entries, missing colors, non-map entries).
Coverage: root markers (`#commit-graph` + `phx-hook="CommitGraph"` → `#commit-graph-body-<node_key>` incl. a NON-DEFAULT `node_key`, which changes only the body id); repo sections (section `id = repo.repo_dom_id` VERBATIM — the builder already emits `commit-graph-repo-<slug>-<hash>`, the component adds NO prefix — with the repo-name header as the section's FIRST child block and the `.cg-graph` block BELOW it; two repos → two independent sections, each with its own toolbar/readout/svg); zoom toolbar (`.cg-graph[data-cg-repo-id]` hosts `div.cg-toolbar` + `svg.cg-svg`; three `button[type="button"][data-cg-action]` = `zoom-in`/`zoom-out`/`fit`; `span.cg-zoom-readout[aria-live="polite"]` is EMPTY server-side — the hook writes the zoom level into it); svg scaffold (`svg.cg-svg` = `width="100%"`, `role="img"`, `aria-label="Git commit history graph"`, `preserveAspectRatio="xMinYMin meet"`, a padded `"0 0 W H"` `viewBox`, a clamped `height`; its SOLE child is `g.cg-viewport`, whose paint order is edges → nodes → lanes); edges (`path.cg-edge[data-commit-graph-anim="edge"]` per model edge with a stable `#commit-edge-<dom>-<from>-<to>` id, `fill="none"` and a cubic-bezier `d`; a `:parent` edge is SOLID (`stroke-width="2"`, no `stroke-dasharray`) vs a `:merge` edge DASHED (`stroke-dasharray="4 3"`, `stroke-width="1.6"`); stroke = the owning lane's depth hue, muted base ink for an edge with no owning lane); nodes (`g.cg-node[data-commit-graph-anim="node"]`, one per model node, carrying `data-cg-agent-id`/`data-cg-sha` + the `phx-click="select_agent"`/`phx-value-id` contract (all OMITTED for an unowned node) and an inner `<title>` tooltip (base prefix, first line only, refs); a base node is HOLLOW at `r=5`, a real commit FILLED at `r=7`; a base node ADDITIONALLY renders a VISIBLE `text.cg-base-label#commit-base-label-<dom>-<sha>` short-sha label centred BELOW its dot (`x = cx`, `y > cy`, `text-anchor="middle"`) while regular commit nodes stay unlabeled (tooltip only); an owner's END commit takes `Helpers.agent_status_svg_color/1` (the shared status color — never mapped locally), other owned nodes the lane depth hue); lanes (`g.cg-lane[data-commit-graph-anim="lane"]`, one per lane in model order, with the stable anchor id `#commit-agent-row-<dom>-<agent_id>`, an inner `<title>` `"T<label> · <status>"`, the `phx-click="select_agent"` contract and the `T<task_local_id || agent_id>` label; a `rect.cg-lane-band id="commit-lane-<dom>-<id>"` with `pointer-events="none"` spans `x_start → x_end` in pixels and is OMITTED when either bound is not an integer; an `agent_id: nil` lane keeps a stable `…-nil` id/label but no click contract); animation markers (`data-commit-graph-anim` takes EXACTLY `edge`/`node`/`lane`; NO animation classes in server markup; NO `phx-update` anywhere); selection (`selected_id` rings the selected agent's START node with a SOLID `.cg-selection-start` circle + a "start" tag BELOW and its END node with a DASHED `.cg-selection-end` circle + an "end" tag ABOVE, tints that lane band's stroke primary, and renders `#cg-selection-readout-<dom>` `"Selected T<id> · <start-short-sha> → <end-short-sha>"` (the sha range is dropped when the lane has none); a `nil`/non-matching id → no rings, no readout, no primary band); view states (empty repos + `loading` → spinner + "Loading commit history…" and nothing else; empty + not loading + no error → "No commit history yet."; empty + non-nil error → `#commit-graph-error` "Could not load commit history."; mutually exclusive texts; the node-scoped body wrapper is present in every state); stale warning (`#commit-graph-stale-warning` renders ALONGSIDE the still-rendered graph when repos are non-empty AND error non-nil; the hard error state is suppressed); defensive shapes (non-map repo/node/edge/lane entries are dropped without crashing; a repo without nodes or lanes renders its header plus the `p.cg-empty-note` "No commit history for this repository." — the SVG scaffold is still emitted; an agent without a color falls back to `var(--color-base-content)`; a node/lane without a proper owner omits the click contract; odd grid values and non-binary shas degrade without crashing).
Every DOM id is derived from the fixture's `repo_dom_id`/agent id — the builder's `repo_dom_id/1` already returns a `commit-graph-repo-<slug>-<hash>` string and the component adds NO prefix, so never assume a single prefix. NOTE: Floki's HTML parser lowercases attribute names, so the SVG's `viewBox` / `preserveAspectRatio` are queried as `viewbox` / `preserveaspectratio`.
File-local Floki helpers: `parse/1`, `attr/2`, `dom_id/1`, `render_repos/2`, `element_children/1`, `viewport_classes/2`, `edge_selector/2`, `node_title/2`, `lane_title/2`, `num_attr/2`; fixtures `happy_repos/0` + `happy_two_repo_fixture/0` (both REAL `CommitGraph.build/2` output) and the hand-crafted `repo_view/1`, `lane/1`, `graph_node/1`, `edge/1`; the `happy/0` / `happy_selected/1` / `happy_error/1` one-liners each return a `{repo, dom, tree}` triplet.
File length ~1135 lines — a legitimately large render-contract suite (one describe per DOM contract group); don't split casually.
