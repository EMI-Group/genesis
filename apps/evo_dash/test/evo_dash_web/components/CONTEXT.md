# Components Test Directory

## Intent

ExUnit suites for the function components in `./lib/evo_dash_web/components/` (one test file per component module). All suites are `async: true`, import `Phoenix.LiveViewTest`, and use `render_component/2` + Floki (parsed via `Floki.parse_document!/1` — the file-local `parse/1` helper — because `Floki.find/2` + `attribute/2` require a parsed tree, not a raw binary).

## Coverage Boundary — review-page components

### commit_graph_view_test.exs (9 describes, 23 tests)

`EvoDashWeb.AgentsComponents.CommitGraphView.commit_graph_view/1` rendered in ISOLATION (no `live/3`, like the rest of this dir).
The main happy-path fixture is REAL builder output — `EvoDashWeb.AgentsLive.CommitGraph.build/2` fed realistic agent maps + a raw commit graph — so the component provably renders real `repo_view` shapes; hand-crafted lane/commit maps cover depth > 1, ref-less commits and a fixed `repo_dom_id`.
Coverage: root markers (`#commit-graph` + `phx-hook="CommitGraph"`, body id `commit-graph-body-<node_key>` incl. a non-default node key); lanes + commit nodes (one lane per agent, one stable-id lane-commits container per lane, `#commit-node-*` with short sha + FIRST-LINE subject only, repo header name, one `badge badge-outline badge-xs` chip per ref and none for a ref-less commit); agent chips (`T<task_local_id>` label, the `font-mono` model_id line only when `lane.model_id` is a non-empty binary); selection (`selected_id` rings exactly the matching chip via the `ring-2` + `ring-primary-standalone` fragments — counted tree-wide by `ringed_chips/1`; nil/non-matching → none); view states (loading with empty repos wins over a non-nil error, empty, error → `#commit-graph-error`; mutually exclusive texts); stale warning (`#commit-graph-stale-warning` renders AND the repos still render when repos non-empty AND error non-nil); animation markers (`lane`/`node`/`edge` present; the parent connector elbow `class*="rounded-bl-md"` only when `connects?: true`; `#commit-edge-<dom>-<sha>` only before the 2nd+ commit of a lane); click-to-select (the commit node and the agent chip both carry `phx-click="select_agent"` + `phx-value-id`); depth indentation (`depth * 0.75`rem; non-integer/negative → `0rem`).
DOM ids are always derived from the fixture's `repo_dom_id` — the component prefixes `commit-graph-repo-` onto the ALREADY-prefixed builder id (`CommitGraph.repo_dom_id/1` returns a `commit-graph-repo-…` string), so never assume a single prefix.
File-local Floki helpers: `parse/1`, `attr/2`, `ref_chips/1`, `chip_label/1` (`span.font-bold.text-sm` — `text-sm` disambiguates the chip label from the also-`font-bold` status badge), `ringed_chips/1`, `class_contains?/2`, `dom_id/1`, `render_repos/2`; fixtures `happy_repos/0`, `repo_view/1`, `lane/1`, `commit/1`.

### layouts_test.exs (1 describe, 2 tests)
