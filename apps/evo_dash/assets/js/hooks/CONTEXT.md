# JS Hooks

## Intent

Phoenix LiveView JavaScript hooks for the EvoDash dashboard: plain JS objects with `mounted`/`updated`/`destroyed` lifecycles, registered with the `LiveSocket` and attached by page markup through `phx-hook="<Name>"`.
Every HOOK module here is imported and registered by NAME in `../app.js`'s `hooks:` map (`SidebarCollapse`, `AdaptiveInput`, `LegendTooltip`, `DiffViewer`, `CommitGraph`, `CapsulePanel`, `DisclosureMotion`, `MotionPanel`, `DirectoryPicker`, `FilePicker`, `StatePersistence`, `AgentHistoryAutoScroll`, `DesktopQuit`, `DesktopQuitConfirm`, `UpdateStatus`, `Guide`, `ListEnter`, `InspectorMessages`, `AssistantComposer`, `Workbench`, `WorkbenchSection`, `WorkbenchWindow`, `BrowserNotifications`, `DialogModal`), so a page only mounts the attribute and supplies the DOM contract below.
The workbench helpers `workbench_tabs.js` (pure tab store), `workbench_navigation.js` (route confirmation and pending intent), `workbench_rail.js` (rail, overflow and history DOM), `workbench_history.js` (right dock and History handoff), `workbench_panel.js`, `workbench_panel_dom.js` and `workbench_project_preview.js` are imported by `Workbench`, not registered as separate hooks.
`../app.js` is a thin entry: the `LiveSocket` + `hooks:` map, `longestCommonPrefix`, the hooks declared inline (`TauriDetect`, `PathAutocomplete`, `ClipboardCopy`, `AutoClearFlash`, `PlatformDetect`, `FocusInput`, `PaletteList`), the `guide_client_id` connect param from `./guide.js`, and the topbar/live-reload tail.

### ClipboardCopy hook — copy strategy & fallback

`ClipboardCopy` is the SINGLE copy mechanism for ALL copy buttons (Tasks, Code Review, Projects, Settings, Welcome): `phx-hook="ClipboardCopy"` + `data-content`, and a falsy/empty `data-content` is a no-op.
Strategy, in order:
1. `navigator.clipboard.writeText(content)` where available (secure contexts only: https, `localhost`/`127.0.0.1`, `file:`); a REJECTION is `console.warn`ed and falls through — never swallowed.
2. Legacy fallback — temporary `<textarea>` (`position: absolute; left: -9999px; readonly`), `select()` + `setSelectionRange(0, value.length)`, `document.execCommand("copy")`, remove it, restore the prior selection/range (`getSelection()` saved, `removeAllRanges()` + `addRange()`). Used when `navigator.clipboard` is absent (plain HTTP on a LAN IP / non-localhost host — the documented prod and `PHX_IP` configurations) or after a rejection; it works inside the click gesture in non-secure contexts and most webviews.
Every success path (writeText resolve, `execCommand` true) goes through `markCopied()`: push `"copied"` and tint the button's first `<svg>` with `text-success` for 2 s.
The `"copied"` flash (`gettext("Copied to clipboard")`) has handlers in `tasks_live.ex`, `review_live.ex`, `projects_live.ex` and `welcome_complete_live.ex`; SettingsLive has none, so its copy works without a flash.
If BOTH paths fail (execCommand false or throws) NO fake `"copied"` event is pushed and a clear `console.warn` surfaces the failure.

### UpdateStatus hook — module-level once-bound listener/timer pattern

`UpdateStatus` is the reference pattern for a global push-based hook: module-level `updateListenersBound` / `updateTimersStarted` / `updateCurrentHook` flags.
`mounted()` returns early outside the shell (`window.__TAURI__ || window.__TAURI_OS_INTERNALS__`), sets `updateCurrentHook = this`, binds three window listeners ONCE (`phx:update_check_requested`, `phx:update_download_requested`, `phx:update_apply_requested` → the matching `invoke*`), and starts the timers once: `setTimeout(…, 30000)` startup check + `setInterval(…, 6 * 60 * 60 * 1000)` periodic.
The `invoke*` functions `window.__TAURI__.core.invoke` the Rust commands `check_update`/`download_update`/`begin_update` and push results back through `pushUpdateEvent` (ref guarded, `pushEvent` try/caught).
`destroyed()` clears `updateCurrentHook` only while it still points at this instance — another mount may have taken over.
Server side, `EvoDashWeb.LiveHooks.UpdateStatus` (`lib/evo_dash_web/live_hooks/update_status.ex`) attaches `handle_info` + `handle_event` interceptors on EVERY page — the reference pattern for a server-side global push hook (`live_hooks/CONTEXT.md`).

### CapsulePanel hook — animated open/close + view drill-down

`CapsulePanel` owns the client half of every fused-capsule `<details>` root; the server only renders the markup (initial `data-capsule-view="model"` on the model capsule) and the persistence events.
Root attributes: `data-capsule-state="closing"` (present only while the exit runs — `css/app.css` keys the close keyframes off it, and it is removed the instant the panel closes) and `data-capsule-view="model"|"provider"` (which `.capsule-view` shows; only roots with `.capsule-view` children ever receive it, so the mode+speed capsule never grows one).
A Layer-2 submenu being closed carries `data-capsule-sub-state="closing"` (gated by app.css's `details.capsule-sub[…] > .capsule-list` exit rule; its `open` is released by the shared close).
Every instance is independent: its own document `pointerdown` (capture) + `keydown` (capture) listeners, scoped to its own root.
Outside `pointerdown` (the press, not the later click) and `Escape` both run `closeAnimated()`; Escape also `preventDefault()`s and focuses the root `<summary>`, and only a panel that is actually `open` reacts.
`closeAnimated()` delegates to the shared `closeAnimated(el, {panel: el.querySelector(".capsule-panel"), attr: "data-capsule-state", onComplete})` from `./disclosure_motion.js`.
Bookkeeping: drop `openRequested` first, ignore a second dismiss while `closing`, and re-assert the flag in the completion callback so a straggler cannot resurrect a closed panel.
`destroyed()` removes every listener AND completes an in-flight close (the root's `data-capsule-state` plus every nested `details.capsule-sub` `data-capsule-sub-state`) through the shared helper with `fallbackMs: 0`, so a mid-exit teardown leaves no closing attribute or live timer.
One delegated `click` handler intercepts a summary click in BOTH places a native toggle would snap: the root `<summary>` closes the panel, and a `<summary>` whose closest `details.capsule-sub` is inside this hook element and `open` is `preventDefault()`ed and closed through the same primitive (`sub > .capsule-list`, `attr: "data-capsule-sub-state"`); a CLOSED submenu and another instance's submenu keep their native `[open]` path.
That handler also drives the view switch: `[data-capsule-drill]` → `setView(dataset.capsuleDrill)`, `[data-capsule-back]` → `setView("model")`, and a `role="option"` (or `.capsule-item` fallback) inside `[data-view="provider"]` → `setView("model")` WITHOUT `preventDefault()`, so its `phx-click` still persists the choice; `setView` writes only on change, there is no `phx-click` on the hook element, and nothing stops propagation.
An open panel survives re-renders: a `toggle` listener records `openRequested` (resetting to the model view on a GENUINE closed → open), and `updated()` — only while `openRequested` — restores a stripped `open`, clears a leftover `closing` and re-asserts the current view (a patch removes every attribute the server does not render).
Never touch the DOM of a closed capsule in `updated()`.

### InspectorMessages hook — stable-key transcript entries

`InspectorMessages` owns entry animation only and never scrolling: mount `phx-hook="InspectorMessages"` on a wrapper with a unique DOM `id` and a nonempty `data-inspector-scope` (viewed node + agent/session identity), and `data-inspector-message="<stable-key>"` on each entry.
Keys are opaque strings, not CSS selectors, stable across streamed text/token patches, Markdown re-renders and DOM replacements (never token counts, content hashes or shifting indices); the wrapper is the sole scope boundary, so never nest a differently scoped inspector inside it.
The mount snapshot and every scope change's complete snapshot are recorded without animation (an empty/missing scope is inert, becoming scoped seeds a baseline), so change the scope and its transcript in the SAME DOM patch.
A scope-local Set remembers keys across removal/reinsertion and node replacement, so only a genuinely new key gets `inspector-message-enter`, duplicates never animate twice, and the history lasts until a scope change or `destroyed()`.
A MutationObserver watches `childList` throughout the subtree plus only the `data-inspector-scope`/`data-inspector-message` attributes, with an idempotent `updated()` reconciliation (character-data and class/style mutations are not observed).
Integrators supply `.inspector-message-enter` CSS/keyframes plus a `prefers-reduced-motion: reduce` guard in `../../css/app.css` using theme tokens; the hook also respects reduced motion in JS, remembers suppressed keys so they cannot replay, and clears active animations on a live preference change.
An entry's own `animationend`/`animationcancel` removes its class and both listeners (bubbled descendant events ignored); removed/re-keyed entries, scope changes and `destroyed()` release everything — no timers, rAF or polling.
Keep `AgentHistoryAutoScroll` on a DIFFERENT wrapper: LiveView accepts one hook name per element and the scroll hook stays the sole scrolling owner.

### AgentHistoryAutoScroll hook — instant, coalesced stick-to-bottom

While pinned the hook snaps a transcript scroller to the latest content with NO animation — one coalesced `requestAnimationFrame` assigning `scrollTop = scrollHeight` — and stays out of the way otherwise.
The pure decision is `shouldFollowLatest(scrollTop, scrollHeight, clientHeight, threshold?)` with `STICK_TO_BOTTOM_THRESHOLD_PX = 56`: the boundary is inclusive, non-finite geometry follows (a no-op assignment is harmless, a lost pin is not), and content that fits or an overscroll past the bottom counts as "at the latest".
`pinned` (initially `true`) is re-evaluated only on USER intent — `scroll`, `wheel`, `touchmove`, `keydown` — coalesced onto the next frame so the geometry already reflects the movement; a programmatic write's own `scroll` lands at the bottom, so the pin survives (no suppression flag, no timestamp window).
While pinned, content growth schedules ONE stick per frame; while unpinned the hook early-returns and DISCONNECTS both observers, so reading history costs no observer work.
A `ResizeObserver` on the scroller and its direct children re-follows late layout changes (Markdown render, images, an opening `<details>`) and a `MutationObserver` on the scroller (`childList`) re-syncs the observed child set.
Lifecycle: `mounted()` sets the pin, attaches listeners/observers and schedules a stick; `updated()` schedules a stick; `reconnected()` re-derives the pin from live geometry and re-attaches; `destroyed()` cancels both pending frames and releases every listener and observer.
The panels' CSS invariants (`../../css/app.css`, "Auto-scrolled transcripts") are load-bearing: `overflow-anchor: none` (the hook owns anchoring), `overscroll-behavior: contain`, `scroll-behavior: auto` (the document sets `html { scroll-behavior: smooth }`, which would animate every assignment into shaking) and `min-height: 0`.
Only the pure predicate has Node coverage (`../agent_history_scroll.test.cjs`); frame scheduling, observer lifecycle, reconnect and keyboard/scroll races are untested.

### ListEnter hook — shared list entry animation

`ListEnter` owns the ONE entry animation for server-rendered lists (task cards, conversation rows, process rows) and never scrolls or orders anything.
DOM contract (Elixir side): mount on a LIST WRAPPER with a nonempty `data-list-enter-scope` (e.g. `"<node>|<project>"`) and one `data-list-enter-key="<stable unique key>"` per row, surviving text/token patches and DOM replacements.
Rows genuinely NEW in the CURRENT scope get `motion-list-enter` (keyframes/timings from `../../css/motion.css`'s `motion-slide-in` + tokens; the rule lives in `app.css` — `../../css/CONTEXT.md`).
The pure planner is `planListEnter({scope, previousScope, keys, seen, reducedMotion})` → `{changedScope, seen, animate}`: side-effect free, never mutating the input `seen` (returns a NEW Set), ignoring empty/non-string keys and keeping a key's first occurrence.
The FIRST snapshot (`previousScope` undefined) and ANY scope change are baseline-only (`seen` re-seeded from the current keys), so a project/node/session switch paints silently, and nothing animates under reduced motion or on an unscoped wrapper (`animate` stays empty while keys are still remembered).
One coalesced `requestAnimationFrame` per mutation burst reconciles (ten appended rows plan once against the final list), a scope change clears any running animation, and detached/re-keyed rows, `animationend`/`animationcancel` and `destroyed()` release the class and its listeners.
Inert until a template opts in with the two data attributes; `./list_enter.test.cjs` pins the planner through `node:vm`.

### Motion foundation (DisclosureMotion + close helpers)

`./disclosure_motion.js` is the ONE motion foundation for exits: every duration, easing and keyframe lives in `../../css/motion.css` (tokens, keyframes, the global `prefers-reduced-motion` backstop), JS only decides WHEN an exit is over, and no timing is duplicated in JS — tokens, recipes and the one-direction/symmetric inventory: `../../css/CONTEXT.md` § Motion foundation.
Markup recipes this package applies:
- `phx-hook="DisclosureMotion"` → animated open AND close: a click on the element's OWN `<summary>` while open sets `data-disclosure-state="closing"` and only then removes `open` (without the hook, disclosure is open-animated only and closes natively).
- `data-disclosure-dismiss` → additionally closes on an outside `pointerdown` or `Escape`; the VALUE is ignored (presence opts in) and without it the hook registers NO document listener.
- `closeAnimated(el, {panel, attr, fallbackMs, onComplete})` → the reusable exit primitive for any `:if`-mounted or `<dialog>` node whose hide must wait for an animation.

`closeAnimated` is idempotent — exactly ONE completion however many events, timers or repeated requests arrive — and completes IN THE SAME TASK (synchronously, before returning) under reduced motion, with no animatable panel, or while a previous close already runs.
Only an `animationend` whose `target` IS the panel finishes an exit; a child element's animation (nested disclosure, spinner) and a native `::backdrop` event never can.
`DISCLOSURE_CLOSE_FALLBACK_MS` (200 ms, documented bound `0 < x <= 500`) is the safety net for a panel that fires no animation at all.
A `<dialog>`-shaped root is released through its own `close()` so its `"close"` listeners still fire; everything else simply loses `open`.
Opening is deliberately CSS-only (`details.motion-disclosure[open] > :not(summary)`), so a patch never re-arms an entry animation, and Enter/Space on the focused summary still closes as an intercepted click.
`open` stays browser-native — `data-disclosure-state="closing"` is the ONLY exit gate — but the hook OWNS `open` after mount: `wantOpen` is seeded from the rendered attribute, kept current by a `toggle` listener (native opens, keyboard activation, our own `releaseOpen`), set by an open click, and reconciled against a patch by the pure `planOpenReconcile({domOpen, wantOpen, closing})` → `{wantOpen, action}`.
A browser-owned disclosure's server never writes `open`, so the action is always `"none"`; where the SERVER writes it (the Settings provider account's `#provider-profile-advanced`, `open={@advanced_open?}`), `"readd"` re-asserts the previous frame in the same task while our exit runs (a mid-exit patch cannot cut the fade short), `"readd-and-close"` re-asserts it then plays the exit when the server closed what the hook believes open, and `"drop"` removes a stale server `open` until the server catches up.
`destroyed()` removes BOTH element listeners (click + toggle), both DOCUMENT listeners when the disclosure opted in, and releases a running exit.
Dismissal is opt-in per element and pure-decided (`wantsDismissOnOutside({dismiss, open, closing, insideTarget})`, `wantsDismissOnEscape({dismiss, open, closing, key})`): true only for an OPTED-IN, open, not-already-closing disclosure with an outside pointer target / `key === "Escape"`; every other input reads "no dismissal".
Both gesture listeners sit on `document` in the CAPTURE phase (a menu must close before an inner handler for the same gesture, and a target that stops propagation never reaches a bubble listener) and are ADDITIVE — no `preventDefault`/`stopPropagation` — so a pointerdown inside the element (its own content or a NESTED disclosure's summary) closes nothing and the gesture still lands.
A dismissal sets `wantOpen = false` FIRST and then plays the animated `closeAnimated` exit (never a raw `open` removal), and Escape afterwards returns focus to the element's OWN summary with `{preventScroll: true}`.
`prefersReducedMotion(win = globalThis.window)` is the ONE guarded `matchMedia` call (`false` where absent) and is published on `globalThis.genesisMotion` next to `closeAnimated`, because `../dialog_modal.js` is vm-sliced as a CLASSIC script by its test and cannot statically import this module (the `highlight_setup.js`/`window.hljs` side-effect contract).
Attribute contracts: `data-disclosure-state="closing"` (the `<details>` exit), `data-window-state="closing"` (the workbench `<dialog class="workbench-window">` exit, written by `closeAnimated` through `Workbench.closeWindow/1`), `data-capsule-sub-state="closing"` (the Layer-2 submenu, `./capsule_panel.js`), `data-file-manual-state="closing"` (the FilePicker manual panel), `data-dialog-state="opening"|"open"|"closing"` (the native modal, `../dialog_modal.js`), plus the `MotionPanel` pair below — `data-motion-want` is SERVER-owned intent, `data-motion-state` is HOOK-owned state.
Reduced motion never waits: every one of those paths tears down in the same task instead of waiting for an `animationend` that may never arrive; the decisions are pinned by `./disclosure_motion.test.cjs`.

### MotionPanel hook — the one writer of `data-motion-state`

`../../css/motion.css` §4 defines a two-direction panel vocabulary; `./motion_panel.js` (pure) + `./motion_panel_dom.js` (DOM + the `MotionPanel` hook) are its only writer.
Recipe — a panel the server KEEPS MOUNTED and toggles with an assign: `<div id="workspace-panel" class="motion-panel assistant-menu-panel" phx-hook="MotionPanel" data-motion-want={to_string(@workspace_open)} hidden={!@workspace_open} role="dialog">`.
The INTENT is the server's (`data-motion-want`, re-rendered every patch, `null` = unknown/absent → a NO-OP so a stripped attribute never moves the panel); the STATE is the hook's (`data-motion-state="opening"|"open"|"closing"|"closed"` plus the `hidden` frame it writes only once an exit SETTLED), held in the hook's own Maps and never in the DOM — so a patch that puts the server markup back is repaired in the same task and can never cut a running exit short or snap the panel shut.
`opening` is both the mount-time entry (an open intent at mount IS the entrance) and the transition out of `closed`; `closing` keeps the panel displayed for its whole exit; a re-entrant open while `closing` continues from its live interpolated frame with no starting frame; repeated intents are idempotent, and a settle completes exactly ONCE (a duplicated `animationend` after the bounded `PANEL_SETTLE_FALLBACK_MS` of 200 ms, or the timer after the event, is inert).
Only an `animationend` whose `target` IS the panel root may settle it (a child animation bubbles through), and reduced motion completes in the SAME TASK.
Every duration, easing and keyframe stays in `motion.css`: the hook writes attributes only, and `.motion-panel[data-motion-state="closed"], .motion-panel[hidden] { display: none; }` is the hooked closed frame (no `!important`; specificity beats a utility display class).
`data-motion-focus` is the OPT-IN "focus this element when the panel finishes opening" attribute (put it on ONE element inside the panel): once the panel SETTLED into `open`, the writer calls `focus({preventScroll: true})` on the first match; it replaces `phx-mounted={JS.focus(...)}` for a mounted panel (which fires once at mount, never on a later open, and is swallowed while the panel is `hidden`). A closed mount, an unchanged re-assert and a close never focus, and every DOM capability is guarded so a fake/detached panel is a silent no-op.
WHEN NOT TO USE IT: a node the server REMOVES (`:if`, a streamed row, a `<dialog>` it closes) cannot animate this way — LiveView tears it out in the same frame, so its exit is the `phx-remove` + `JS.hide(transition: {"motion-exit-fade", "motion-exit-visible", "motion-exit-hidden"})` recipe (`../../css/CONTEXT.md`); a mounted panel is REQUIRED only when the exit must fade real content.
The `hidden` frame also makes `phx-click-away` inert while closed (LiveView guards it with `JS.isVisible`), but `phx-window-keydown` is NOT visibility-guarded — so a mounted panel's click-away/Escape must push an IDEMPOTENT close event (e.g. `workspace_close`), never the toggle.
The decisions are pinned by `./motion_panel.test.cjs`; the writer (armed settle + target filter + bounded fallback, in-task reduced motion, the one-close re-assert that repairs patched markup, re-entrant open, `destroy()`) by `./motion_panel_dom.test.cjs`.

### DialogModal hook — integration routing

`../dialog_modal.js` is imported and registered by `../app.js`; `../CONTEXT.md` § DialogModal Integration Contract is authoritative for host markup, accessibility, focus restoration, native/nonmodal fallback, dismissal and lifecycle.
BOTH phases are hook-driven and animate the SAME node: `_hide()` writes `data-dialog-state="closing"` and `_enter()` writes `"opening"`, and `motion.css` §9 keys a `.modal-box` keyframe off each state while only a `::backdrop` fade sits on the `<dialog>` itself, which never carries an animation (`../../css/CONTEXT.md`).
The hook's watcher is exactly that `.modal-box`: settle needs an `animationend` whose `target` IS the panel (a backdrop event is dispatched at the dialog, a child animation bubbles from the child) or the 200 ms bound.
`_openModal()` mirrors it with `"opening"` → `"open"`, and a genuine reopen cancels a pending exit so its timer can never close the freshly reopened dialog.
Without an animatable `.modal-box`, without the `matchMedia` bridge, and under reduced motion the teardown happens in the SAME TASK — which is what lets the fake-DOM `../dialog_modal.test.cjs` assert `open`/focus immediately after an event.
`destroyed()` (server teardown) stays fully SYNCHRONOUS: remove listeners, tear the dialog down and restore focus in one task, never leaving a closing dialog or focus inside a removed node.
Dismissal: `_dismiss()` pushes `dialog_closed` synchronously and keeps the `_closed` latch.

### WorkbenchProjectPreview — bounded handoff cache + release()

`./workbench_project_preview.js` keeps the last rendered `#main-content` snapshot of each project for the visual handoff while its live view mounts, and the cache is BOUNDED: `MAX_WINDOWS = 2` entries, because only the project being LEFT is ever handed off.

### Server→client push_event patterns

Server `push_event(socket, "name", payload)` reaches the client two ways:
1. `this.handleEvent("name", cb)` inside a hook (hook-level; lives until the hook is destroyed and survives reconnects): `scroll_to_file` (diff_viewer.js), `picker_result:<id>` (file_picker.js), `persist_state` (state_persistence.js), `task_notification` (../browser_notifications.js), `dialog_open` (../dialog_modal.js), `desktop_quit_closed` (desktop_quit.js) — the callback receives the payload as its argument (LiveSocket destructures the CustomEvent detail).
2. `window.addEventListener("phx:name", ...)` — LiveSocket dispatches every server push as `CustomEvent("phx:" + event, {detail: payload})` on `window`, so `e.detail` is the payload: `phx:update_check_requested`, `phx:page-loading-start/stop` (detail ignored), `phx:live_reload:attached` (`({detail: reloader})` destructures it).

## Constraints

- **NOT colocated**: there are ZERO `.exh` files, so `colocatedHooks` from `phoenix-colocated/evo_dash` resolves to an empty object; every hook is a hand-written module in this directory (only `TauriDetect`, `PathAutocomplete`, `ClipboardCopy`, `AutoClearFlash`, `PlatformDetect`, `FocusInput` and `PaletteList` are inline `const` objects in `app.js`). Do not rely on `.exh` colocated hook generation.
- The modules export proper ES modules (`export default` plus named pure helpers where they exist — `closeAnimated`/`prefersReducedMotion`/`planOpenReconcile`/`wantsDismissOnOutside`/`wantsDismissOnEscape`, `planListEnter`/`LIST_ENTER_CLASS`, `shouldFollowLatest`/`STICK_TO_BOTTOM_THRESHOLD_PX`, `guideClientId`, `DesktopQuit`/`DesktopQuitConfirm`, the `Workbench` trio, the tab store's `openTab`/`pinTab`/`closeTab`/`cycleTab`/`restore`/`tabsForProject`/`alwaysPinned`/`safeHref`/`tabKey`/`activate`/`MAX_TABS_PER_PROJECT`, `createPanelHost`/`settleDisplayedLayout`).
- **Mobile sidebar toggle**: `#sidebar-mobile-toggle` and `#sidebar-overlay` (in `layouts.ex`) are wired by `SidebarCollapse`. On mobile (`window.matchMedia('(max-width: 1023.98px)')`) the hamburger opens the sidebar (removes `-translate-x-full`, shows the overlay by removing `opacity-0`/`pointer-events-none`, locks body scroll with `overflow-hidden`), an overlay click closes it, nav-link clicks inside close it (event delegation on the sidebar, survives morphdom re-renders), and `updated()` re-applies the mobile state after LiveView patches reset the classes. Mobile state lives in `this.mobileOpen`; on desktop the mobile handlers no-op behind `isMobile()`.
- **`SidebarCollapse` sync is probe-guarded**: the collapse sweep (four `querySelectorAll` walks plus class writes) runs only when the pure probe `collapseSyncNeeded(state, collapsed)` reports disagreement, so an ordinary `#sidebar` patch costs a handful of `querySelector`/`classList.contains` checks.
  Probes: the applied state, `data-sidebar-collapsed`, the width class (`w-16`/`w-60`), a wrong-state `.sidebar-label`, a wrong-state `.sidebar-collapsed-only`, a wrong-state `[data-sidebar-task-link]` and the collapse toggle's expected chevron class; a MISSING probe element counts as fine, and the label/row families are probed with `:not(...)` because they also live in dynamic lists.
  The icon swap is a non-destructive `classList.replace(from, to)` (no `innerHTML` rewrite), `applyMobileState()` runs on every patch, only the desktop sweep is gated, and the probe is pinned by `./sidebar_collapse.test.cjs`.
- **Sidebar dropdown dismissal (outside click + collapse)**: the three sidebar `<details>` dropdowns (theme, language, node selector) only close on their own `<summary>` click, so `SidebarCollapse` — whose `<aside id="sidebar">` wraps all three — closes every open `details[open]` descendant on a document-level outside click (listener added in `mounted()`, removed in `destroyed()`) and whenever the sidebar is collapsed (the collapsed branch of `applyCollapsed()`). Clicks inside an open dropdown's content are excluded so they register before anything closes, opening one dismisses the others, and `closeOpenDropdowns()` is scoped to the aside and uses `removeAttribute('open')` — DaisyUI's close mechanism.
- **`SetLocale` is NOT a JS hook** — it is the server-side Elixir on-mount hook `EvoDashWeb.LiveHooks.SetLocale` (`lib/evo_dash_web/live_hooks/set_locale.ex`). Do not look for it in JS assets.
- **AdaptiveInput `--app-vh` sync (mobile keyboard-aware heights)**: `mounted()` binds `resize`+`scroll` on `window.visualViewport` (guarded on `'visualViewport' in window`) writing `--app-vh` on `document.documentElement.style` (keyboard-visible viewport height; initialized once, removed in `destroyed()`), consumed by the `@media (max-width: 640px)` rules of `css/app.css` so the expanded card bounds above the keyboard; without visualViewport the var stays unset and CSS falls back to `100dvh`.
- **AdaptiveInput placeholder mirroring (`data-placeholder` is the LIVE channel)**: the textarea is `phx-update="ignore"`, so LiveView re-merges only `data-*` attributes and `updated()` never fires for that element.
  `_syncPlaceholder()` writes `this.el.placeholder = this.el.dataset.placeholder || ""` behind an equality guard and runs on mount, at the top of `_apply()` (so every input, `updated()`, the `data-layout` observer and `clear_prompt` refresh also refresh the hint) and from a second MutationObserver on the textarea (`attributeFilter: ['data-placeholder']`, disconnected in `destroyed()`).
  Never move the hint back to `placeholder`-only or drop that observer: a project becoming active or a mode switch re-renders the hint server-side and only the observer delivers it.

## Known Issues

- **LiveView 1.2 `phx-hook` accepts exactly ONE hook name per element.** The ENTIRE attribute value is looked up as a single hook name (no whitespace splitting), so space-separated multi-hook lists silently attach NOTHING and log `unknown hook found for "..."`. Never use them; merge the behaviours into one hook instead (which is why `DiffViewer` combines syntax highlighting AND scroll-to-file).
- **`AdaptiveInput.measureAndApply` height write must be UNCONDITIONAL — never "skip when unchanged".** The `applyLayout` `data-layout` equality guard is load-bearing (it terminates the observer cycle), but no observer watches the height write, so it must always write `ta.style.height = scrollHeight + "px"`.
  A `prevHeight` skip-guard is a regression: whenever the measured `scrollHeight` equals the previous inline height (typing on the same line), the write is skipped, the inline style stays at the `"auto"` set for measurement, the CSS `min-height: 120px` collapses the box, content overflows, and the next keystroke measures from the collapsed state and restores the taller height — the compact box oscillates between the two heights per keystroke.
  An unconditional write cannot loop (only `data-layout` is observed) and writing an identical value is a rendering no-op.
- **MutationObserver fires on same-value attribute sets — the `AdaptiveInput` equality guard is MANDATORY.** Chrome fires the callback even when an attribute is set to the value it already holds, so `applyLayout()` writing `data-layout` unconditionally re-triggers the observer mounted on `.input-layout` (`attributeFilter: ['data-layout']`) → `observer → write → observer`, an infinite synchronous microtask loop that pegs the CPU and blocks the page.
  The guard (`if (layoutEl.dataset.layout !== layout) layoutEl.dataset.layout = layout;`) makes the cycle terminate in ≤2 firings; never simplify it away, and never mutate an observed property inside its own observer without an equality guard.
