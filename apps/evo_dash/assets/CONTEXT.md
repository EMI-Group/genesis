# Frontend Assets

## Intent

All frontend source assets (JavaScript, CSS, vendor libraries, editor config) for the EvoDash Phoenix web application.
Single source of truth for client-side code, compiled by **esbuild** (JS) and **Tailwind CSS 4** (styles) via Mix aliases (`assets.build`, `assets.deploy`).

### How to use

- **New JS module**: under `js/`, imported from `app.js` (a hook module goes under `js/hooks/` and into the `hooks:` map).
- **Custom CSS**: extend `css/app.css` or add files under `css/` (auto-scanned by Tailwind).
- **Vendor library**: drop a `.js` in `vendor/` and import via relative path (e.g. `import "../vendor/my-lib"`).
- **DaisyUI/Heroicons update**: replace the matching `.js` in `vendor/` with the latest release.
- **highlight.js update**: download `highlight.min.js` (FULL default build) plus the packs (v11.11.1) from cdnjs into `vendor/`; **zig is NOT on cdnjs** — re-adapt it from the third-party repo into the self-registering IIFE form. Verify the byte counts above (commit them) and run `mix assets.build`.
  Packs MUST stay the cdnjs IIFE form (self-registering on the global `hljs`); an ES-module pack breaks the `window.hljs` load-order contract.
  Runtime loading is fully esbuild-bundled — there are NO runtime CDN `<script>` tags.

### Client-side syntax highlighting (highlight.js)

The review diff viewer highlights in the BROWSER (no server-side highlighter): the backend renders escaped plain-text diff lines and stamps `data-language` (Lumis-style names from `EvoGit.Review.language_for_file/1`) on each `.diff-file-section`; the `DiffViewer` hook highlights `.diff-split-cell` cells with vendored highlight.js 11.11.1.

- **`js/highlight_setup.js`** — exposes the instance as `window.hljs` via a module SIDE EFFECT. Load-bearing: the cdnjs packs are IIFEs that self-register on the global `hljs` and export nothing, so `app.js` imports `highlight_setup.js` BEFORE the vendored packs (ESM evaluation is depth-first in import order); a changed order throws `ReferenceError: hljs is not defined` at bundle load.
- **Language coverage** — FULL default build = the ~35 common grammars; the 19 packs add the rest (elixir, dart, dockerfile + the 16-language "tier-2" set — names in the vendor table). Every lumis name resolves through `LANG_MAP` (`c_sharp`→`csharp`, `text`→`plaintext`) plus hljs aliases (`html`→xml, `toml`→ini, `jsx`→javascript, `tsx`→typescript); unknown names are skipped harmlessly.
- **`js/hooks/diff_viewer.js`** — the `DiffViewer` hook (`phx-hook="DiffViewer"` on `#diff-viewer`). Runs in `mounted()` AND `updated()`; per `.diff-file-section` reads `data-language`, skips unknown languages, highlights each unmarked `.diff-split-cell` (`dataset.hl === "1"` and empty/whitespace-only cells skipped) via `hljs.highlight` in try/catch (a throw leaves plain text — never breaks the page), and marks `dataset.hl = "1"`. No-ops if hljs failed to load.
- **CSS palette** (`css/app.css`, `.hljs-*` tokens for BOTH themes). Light: comment `#6e7781`, keyword `#cf222e`, string/regexp `#0a3069`, number/literal/built_in/type/selector-class/id/attr `#0550ae`, title/function_/class_/meta `#8250df`, attr/attribute/symbol/variable/section/doctag `#953800`, strong = `font-weight: 700`, emphasis = `font-style: italic` (GitHub markup: weight/style only, color inherited). Dark (`[data-theme="dark"]`): comment `#8b949e`, keyword `#ff7b72`, string/regexp `#a5d6ff`, number/literal/built_in/type/selector-class/id/attr `#79c0ff`, title/function_/class_/meta `#d2a8ff`, attr/attribute/symbol/variable/section/doctag `#ffa657`.
  Markdown/diff/yaml/html tokens: code/quote `#6e7781` / `#8b949e`, link `#0969da` / `#58a6ff`, bullet `#735c0f` / `#f2cc60`, name/selector-tag/selector-pseudo `#116329` / `#7ee787`, subst `#24292e` / `#c9d1d9`, addition `#22863a` / `#aff5b4`, deletion `#b31d28` / `#ffdcd7`.
  `hljs-tag`/`hljs-punctuation` and the `hljs-class`/`hljs-function` wrappers stay default (children carry the colors); the span-neutralizer rules (`.diff-line-content span` / `.diff-split-cell span` → inline, transparent background, inherited font but NOT `color: inherit`) keep injected spans from breaking the diff grid.

## Constraints

- **Build tooling**: JS by esbuild; CSS by Tailwind CSS 4. No Node.js toolchain — vendor libs are committed directly.
- **Tailwind source scanning** via explicit `@source` directives in `app.css` covering `css/`, `js/`, `lib/evo_dash_web/`. Any new directory with Tailwind classes must be added as an `@source` entry.
- **CSS import order**: `@import` precedes every other rule, so `motion.css`/`view_transitions.css` sit in `app.css`'s import block (`view_transitions.css` LAST) and before the `@source` lines.
- **Theme system**: DaisyUI built-ins disabled (`themes: false`); only the custom "dark"/"light" themes exist; dark mode is driven by `data-theme="dark"`, not `prefers-color-scheme` alone.
- **Phoenix LiveView hooks** are hand-written — zero colocated `.exh` files, so `app.js`'s `phoenix-colocated/evo_dash` import resolves to an empty object. All hooks live in `js/hooks/` or inline in `app.js`; full registration table in `js/hooks/CONTEXT.md`.
- **Live reload features** (server logs, click-to-editor) are gated behind `process.env.NODE_ENV === "development"` and must not be relied upon in production.
- **No `node_modules/`**: dependencies live in `vendor/` or resolve via esbuild path aliasing to `../deps/`. Do not run `npm install` unless a `package.json` is introduced.
- **Motion invariants** — new animation goes through `css/motion.css` (a class or one data attribute) and, for exits of `:if`-mounted or `<dialog>` nodes, through `closeAnimated/1` or the `JS.hide(transition: …)` recipe; never per-component keyframes or hand-written JS timers. Motion is opacity/transform only (the single exception is `.motion-collapse-grid`'s bounded `grid-template-rows`), never `height`/`width` on the transcript scrollers, the composer or the sidebar, and never `scroll-behavior: smooth` on `#chat-messages`, `.agent-history-scroll`, `.cg-scroll` or `#workbench-history`. The global reduced-motion backstop must stay the LAST rule in `motion.css`.

## Notes for Agents

- **StatePersistence — draft scope key** (`js/hooks/state_persistence.js`; server identity `EvoDashWeb.DraftScope` owns the token; storage key shape + adoption order: `js/CONTEXT.md` § Projects State Persistence): reads `data-task-draft-project` (raw path) and `data-task-draft-scope` (canonical VCT token `vct:///projects/…` / `vct:///workspaces/…`; absent/empty until the server knows one) off `#dashboard-root`, and scopes storage as `{node, token}` with `token = taskDraftScope || project` (a plain path is its own token and keeps the exact legacy key); every write (`persist_state`, `persist_model_selection`, `clear_prompt`, the debounced flush) stamps `scope_token` through ONE `stamp(state, scope)`; a scope-key change flushes the pending edit under the OLD scope first and clears the textarea only on a node/project change (a project gaining its point keeps typing); two VCT points over one OS path are separate drafts, one point via another path spelling (symlink, second mount, workspace member) is ONE.
- **Brand icon sizing (`.brand-icon svg`)**: `brand-*` icons (`EvoDashWeb.CoreComponents.icon/1` — `git.svg`, `nix.svg` in `vendor/brand/`) are inline SVGs with no `width`/`height` inside a `size-*` wrapper span; `.brand-icon svg { display: block; width: 100%; height: 100%; }` fills it, so the span controls size. Keep new brand SVGs square; regression symptom: the System self-check git logo renders larger than the ripgrep check-circle.
- **DirectoryPicker — server-side pick protocol** (`js/hooks/directory_picker.js`): thin LiveView client — no Tauri, no File System Access API. Click → `pushEvent("directory_pick", {picker_id})` → `ProjectsLive` (local node only) → `EvoDash.DirectoryPicker` GenServer runs the native dialog in a Task (macOS `osascript` / Linux `zenity` / Windows PowerShell .NET, `:wx` `wxDirDialog` fallback) → server pushes `picker_result:<picker_id>` `{path, cancelled, unavailable}`.
  `path` → absolute-path regex guard → `fillInput`, then `data-picker-id="project"`/`"new-project"` browse buttons auto-submit via `form.requestSubmit()` (server re-validates) while `"foreign-repo"` only fills; `cancelled` no-ops; `unavailable` → `markManualFallback` (`data-picker-error="manual"`, cleared by `fillInput`).
  `handleEvent` registers in `mounted()` (survives reconnects) with NO JS timeout; degrades to `unavailable` on a remote/headless node, picker disabled (`config :evo_dash, :directory_picker, enabled: false`), no native tool/wx, picker busy, or GenServer down. `this._picking` prevents stacked dialogs (re-armed by `picker_result` and `reconnected()`); remote nodes hide Browse entirely (`@tauri_detected and !@remote` in `project_components.ex`) but keep manual inputs.
- **FilePicker — attach-file protocol (`file_pick`, kind dropdown)** (`js/hooks/file_picker.js`): the objective editor's "+" control is a daisyUI `<details class="dropdown ..." phx-hook="FilePicker">`, a DIRECT child of `.input-controls` (the sibling `<div id="objective-file-manual" class="file-manual" phx-update="ignore" hidden>` is unchanged in position/ids).
  `<summary id="objective-file-button">` is the trigger (native details toggling; summary clicks never start a pick); `dropdown-content` holds exactly three `<button type="button">` with NO `phx-click`: `data-picker-kind="text"`/`"image"`/`"audio"` with `data-picker-id="objective_file"`/`objective_file_image`/`objective_file_audio` (`task_form_components.ex`). ONE hook instance on the `<details>` delegates: a `[data-picker-kind]` click closes the dropdown and pushes `file_pick` `%{picker_id, prompt: <current textarea value as this._basePrompt>, kind}`; other clicks are ignored. `mounted()` registers one shared `picker_result:<id>` handler; the flow is `ProjectsLive` (local only) → `DirectoryPicker` (`:file` mode).
  Text success `%{prompt, block, attached: true, name}` (`prompt` = base prompt + attached Markdown block; `block` = the appended block) drives the push-back; image/audio success `%{attached: true, name, kind}` has NO `prompt`/`block`, so the textarea is never written (the server's staged-chip re-render is the feedback). `cancelled` no-ops, `unavailable` opens the manual fallback, `error` (+ optional `reason`) warns and no-ops.
  **`phx-update="ignore"` push-back (text only)**: the hook writes `textarea[name="prompt"].value` and dispatches `input` + `change` (AdaptiveInput reacts to `input`; StatePersistence persists on `input`). **Append-not-clobber**: if the value still equals `this._basePrompt` apply the full `prompt`, else append ONLY `block`; with no `block` and a changed value do nothing.
  **Manual fallback (all kinds)**: `unavailable` → `openManual()` reveals the `#objective-file-manual` path input (popover above the toolbar "+"; CSS in `app.css`); confirm/Enter pushes `file_pick_manual` with `_pendingPick = %{picker_id, kind}` captured at item-click, retained through the unavailable result and cleared when the flow ends.
  **Manual panel exit**: `closeManual()` never flips `hidden` in the same task — it writes `data-file-manual-state="closing"` and delegates to `closeAnimated` (`.file-manual-input-wrap` → `motion-fade-out`), hiding on target-verified `animationend` or the bounded fallback; `openManual()`/`destroyed()` settle an in-flight close synchronously first. Manual submissions answer with the SAME payloads (success → close, `error` → inline error + panel open with `_pendingPick` for a retry, unavailable/cancelled → close). `this._picking` prevents stacked dialogs (re-armed by the result handler and `reconnected()`, which also re-arms `_manualSubmitted`; `_pendingPick` survives a reconnect).
- **Guide — Genesis Guide overlay client (`Guide` hook + `.guide-highlight`)** (`js/hooks/guide.js`): the server-side `EvoDashWeb.LiveHooks.Guide` on-mount hook pushes `"guide_highlight"` with `%{selector}`; the client retries boundedly (~10 × 250 ms, then silent give-up), scrolls the target into view (centering inside `#main-scroll` when it contains it, else `scrollIntoView({block: "center"})`), adds `guide-highlight` and removes it after ~3 s.
  Dismissal pushes `"guide_cleared"` and clears the stored `lastGuideHighlight` so a remount cannot re-apply it. A stable per-tab `guide_client_id` (`crypto.randomUUID()` with a `Math.random` fallback, sessionStorage-backed) rides the LiveSocket connect params; the server keys its guide store by it (stable across `push_navigate` because the socket persists), restores the `@guide` assign per page, and the module-level `lastGuideHighlight` re-applies on remount.
  No `window.__TAURI__` gating. `.guide-highlight` (app.css Utility section) is a 2px `var(--color-primary-standalone)` outline + 2px offset + `border-radius: 0.25rem`; panel styling is markup-only Tailwind.
- **CommitGraph — vertical commit graph client (Agents page temporal view)** (`js/hooks/commit_graph.js` + `css/app.css` "Commit Graph"): a VERTICAL agent-DAG — one ROW per visible node (commit, stub, folded-run `:gap`) top → bottom inside the `.cg-scroll` both-axis container, with a fixed left `<svg class="cg-gutter">` drawing dots and child → parent edges.
  **Commits-mode fill chain (xl+)**: the LiveView adds `agents-tree-body-commits` to the `.agents-tree-panel` card body only in commits view; app.css hands height down `.agents-tree-panel .card-body.agents-tree-body-commits` → `#commit-graph` → `#commit-graph-body-<node_key>` → `.cg-repo` → `.cg-scroll` (every link a flex column, `min-height: 0; overflow: hidden`). The switch row and error/stale/loading/empty strips are `flex: 0 0 auto`. `.cg-scroll` is the ONE bounded VERTICAL scroller — the sticky lane header resolves against it, so it never takes an `overflow-*` override; below xl the cap is `min(26rem, 60vh)` (xl+ outside commits mode `min(38rem, 70vh)`), and `#cg-truncated-<dom>`/`.cg-empty-note` stay INSIDE it.

## Known Issues — Custom CSS Variables (`css/app.css`)

- **(i) No old DaisyUI `--b1/--b2/--b3/--bc/--p` namespace.** With `themes: false` only the new `--color-base-100/-200/-300`, `--color-base-content`, `--color-primary` (etc.) variables exist, defined by the two `@plugin "../vendor/daisyui-theme"` blocks at the top of `app.css`. ## Form-control focus styling ("glow-on-focus")

**ONE global un-layered rule in `css/app.css` is the single source of truth** for every DaisyUI `.input`/`.select`/`.textarea` focus look (solid standalone-accent border + 2px ring at 40%): `:focus` on all three plus `:focus-within` on `.input` (mirroring DaisyUI's selectors), each guarded with `:not(<class>-success):not(<class>-error)` so state classes keep their own focus styling (`input-success` on API-key inputs, `-error` validation classes via `CoreComponents`). It sets `outline: none; border-color: var(--color-primary-standalone); box-shadow: 0 0 0 2px color-mix(in oklab, var(--color-primary-standalone) 40%, transparent)` — colors via `color-mix + var(--color-*)` only, never `--input-color` re-pointing.

**Why un-layered**: DaisyUI 5 emits its own form-control focus rule (`outline: 2px solid var(--input-color)` — the "detached double border") inside `@layer components`, so a layer-wrapped rule would LOSE; `app.css` has no `@layer` blocks and its un-layered author CSS beats the plugin's layered styles (the precedence the accent overrides rely on). Tailwind `focus:ring-*`/`focus:border-*` utilities are therefore redundant and were removed from every DaisyUI input/select/textarea control (tasks live filter bar, projects live build select, welcome model search, project pickers, task-form selects/inputs, settings sidebar search — which keeps `focus:bg-base-100`); any new control just gets the class.

**Exceptions (intentionally unchanged)**: HomeLive's composer (`#chat-form`: the picker capsule renders only buttons/listboxes and the borderless composer textarea glows via `.help-composer:focus-within`); `.input-prompt` (task-form textarea, custom class, `.input-prompt:focus { outline: none }`); `.file-manual-input:focus` (amber border). Checkboxes/toggles keep DaisyUI's `:focus-visible` outline and are out of scope.

**Regeneration recipe (run whenever `images/logo.svg` changes):**

```bash
# 1. Render PNGs at nominal widths 16/32/48/64/128/256 — height follows the
#    logo's aspect ratio (1.2334), transparent background, no distortion:
for W in 16 32 48 64 128 256; do
  inkscape --export-type=png --export-filename=favicon-$W.png --export-width=$W priv/static/images/logo.svg
done
# 2. Combine into a multi-size ICO with alpha. Prefer PNG-compressed entries
#    (compact, ~28 KB); a Python one-liner stitching ICONDIR + PNG blobs works,
#    or ImageMagick: magick favicon-16.png ... favicon-256.png favicon.ico
#    (note: IM writes uncompressed BMP entries → ~300 KB; PNG entries are better)
cp favicon.ico priv/static/favicon.ico
# 3. favicon.svg = square-fitted copy of logo.svg (square viewBox, logo group
#    centered via transform="translate(0 <(squareH - logoH)/2>)", width/height 180)
```
