# EvoDash — Phoenix LiveView Dashboard

## Intent

EvoDash is the web dashboard of the EvoGit umbrella: a project-based real-time Phoenix LiveView interface to launch and monitor tasks (genesis / evolve), inspect the agent tree, review results, and manage scheduler settings, user configuration and per-project settings incl. foreign repositories.
Users open a Project (a Git repository path) through the command-palette selector, which mounts it in the core's Virtual Context Tree and makes it the single active project; the dashboard auto-detects the task mode.
Phoenix 1.8 umbrella child app (`:evo_dash`) depending on sibling `:evo_git`.

### Canonical LLM Provider Profiles & Selection

Canonical config is `llm.providers` + `llm.default_provider_profile` (never a flat `llm.models` editor); the identity/selection split, reasoning ladder (`none minimal low medium high xhigh`, no `max`), provider-derived `id`/`name` and the `config_opts/1` push contract are owned by the root `./CONTEXT.md` provider-profile bullets.
`LLMSelection` (`live/llm_selection.ex`) is the dashboard's shared boundary (core `Schema.provider_profiles/1`, `model_selections/1`, `resolve_model_spec/2`): the fused capsule shows model + effort, a provider drill row switching to a provider view (Auto + disabled stale row), and the model's ordered effort stops decoded by `resolve_reasoning_effort/3`.
Picker state holds only string-keyed `provider_profile_id`, `model` and optional `reasoning_effort` (nil = node default, `%{}` = explicit Auto); reconciliation migrates/falls back for stale saved choices but launch validation REJECTS invalid explicit selections; explicit choices emit `:model_spec` + `model_id_locked: true`, Auto removes both; Projects stores `model_spec` per target node and `persist_model_selection` merges selection fields without replacing form data, while Assistant scopes by target id AND BEAM node — pending/disconnected remote targets never borrow local models or credentials.
Settings is ONE guided provider surface (compact roster → ONE expanded account editor + inline wizard from `SettingsComponents.ProviderWizard` steps, no Quick Setup path) built on `LLMSetup.Identity` (provider-derived id/name, collision-safe `-2`/`-3`), `LLMSetup.Reasoning` (the single effort chip list) and `LLMSetup.Schedule` (peak-hour presets, holiday calendars); OAuth belongs to the profile (`auth_mode`, optional `oauth_file` overriding `EvoGit.Auth.default_oauth_file/0`), and `AuthStatus` loads credential status off-process with node/sequence stale guards.
**In-app SIWC** — `:openai_codex` signs in FROM THE BROWSER for a LOCAL node (`EvoDash.ChatGPTLogin` binds an ephemeral `127.0.0.1` listener carrying the real port, `LLMSetup.ChatGPTSignIn` polls off-process then reloads accounts); a REMOTE node keeps `genesis chatgpt login` CLI guidance; the CLI drives the SAME flow.

### SSH Remote Development — Node-Aware Dashboard

The dashboard controls a remote headless daemon over Erlang distribution via an SSH tunnel (ONE `genesis_server` instance per host, distribution enabled by `<launcher> remote start`; node `genesis_remote_<target_id>@127.0.0.1`) through `NodeContext`, `LiveHooks.NodeAware` (node assigns, `?node=` resolution, unified sidebar Active-Tasks loader, connection status) and `NodeSelectorComponent`.

- **URL threading**: nav links carry `?node=<target_id>` (`with_node_param/2`; ⚠️ it appends with `?`, so query-string URLs need a manual `&node=`); every load routes through `NodeContext` (local direct, remote `:erpc`) off the LiveView process with no polling — push-based via `EvoGit.PubSub` (PG2/`:pg`); evo_dash owns no SQLite/Ecto/xqlite and has ZERO `EvoGit.Store` references in production code.
- **Per-page**: SettingsLive edits remote config (`save_user_config` + `reload_remote_config`), SystemLive controls via RPC (update + source cards hidden), ProjectsLive shows the remote form with read-only projects, TasksLive reads the full remote list; lifecycle calls return safe fallbacks and the selector renders "Local" by default. Inventory: `lib/CONTEXT.md` + `lib/evo_dash/CONTEXT.md` + `live/CONTEXT.md` + `live_hooks/CONTEXT.md` + `lib/evo_dash_web/CONTEXT.md` ("SSH Remote UX") + `live/agents_live/CONTEXT.md`.

### Push-based event contract (node-identity PubSub)

`:evo_git` broadcasts on `EvoGit.PubSub`; every event carries the **publisher's BEAM node atom** and only a matching viewed node updates the UI — `NodeAware.event_from_current_node?/2`; task events flow through `NodeAware.handle_task_info/2` (300 ms trailing debounce → `:node_aware_reload_tasks`).

| Topic | Events | Consumers |
|-------|--------|-----------|
| `"tasks"` | `{:task_updated, task_id, status, node}` (status `:pending\|:running\|:finalizing\|:cancelling\|:completed\|:failed\|:cancelled`, `nil` for review-only mutations); `{:task_deleted, task_id, node}` | NodeAware, TasksLive, ProjectsLive, ReviewLive, AgentsLive, SettingsLive, SystemLive |
| `"agents"` | `{:agent_registered, id, summary, node}`, `{:agent_updated, id, changed_fields, node}` (NEVER `:context`; carries `:message_count` when context changed), `{:agent_removed, id, node}`, `{:agents_updated, node}` | AgentsLive; HomeLive (fallback refetch only) |
| `"agent:<id>"` | `{:agent_delta, agent_id, seq, batch}` — `batch` a LIST of `{:text, bin}` / `{:thinking, bin}` / `{:tool_call, id, name}` / `{:tool_result, id, status}` / `{:turn, map}` / `{:yield, text}` / `{:finished, status}`, coalesced ~75 ms by the core's batcher; no replay buffer, no node tag | HomeLive (a watched `/assistant?session=<id>` page subscribes in its own process, dropping `seq <= snapshot.seq`) |
| `"scheduler_config"` | `{:scheduler_config_updated, node}` | SettingsLive, SystemLive (node-filtered → async reloads) |
| `"system"` | `{:system_sample, node, seq, sample}` every 3 s: aggregates plus **`llm_slots`** (per-PROVIDER-PROFILE pool `%{used:, waiting:, capacity:}` keyed by `[[llm.providers]]` account id — all models of one profile share it; `%{}` when the scheduler is dead) and OPTIONAL **`llm_pools`** labels (`%{pool_id => %{label:, models:}}`, read defensively) | SystemLive charts (ring buffer, cap 60) |
| `"vct"` | `{:vct_updated, node}` | ProjectsLive |

- **Data safety**: `handle_*` callbacks have NO try/rescue (a Store failure crashes the GenServer and the supervisor restarts it; WAL keeps data safe), `EvoGit.Store.Codec` is total encode / raise-on-bad-decode, `safe_select_all_tasks/projects` SKIP corrupt rows with a `Logger.warning`, cleanup runs only on completion / explicit clear / init with `put_task` BEFORE cleanup, and lease checking is two-check one-shot (startup reconcile + one `:lease_sweep`, `lease_expires_at` renewed every 60 s) so a second BEAM instance can never kill a running task → `apps/evo_git/CONTEXT.md`.

## Desktop Mode (Tauri Shell)

The backend is a **standalone web server** with no desktop-shell dependency (no `:desktop`); desktop mode is provided externally by a Tauri shell (repo root `./desktop/`) launching the backend as a sidecar.

- **Directory picking is server-side** via `EvoDash.DirectoryPicker` (native tools, `:wx` fallback) — NOT Tauri, NOT the browser File System Access API: the `DirectoryPicker` hook pushes `directory_pick` → `ProjectsLive` (local node only; remote/headless → `unavailable`) → picker GenServer → `picker_result:<picker_id>`; remote nodes hide Browse; disable via `config :evo_dash, :directory_picker, enabled: false`. No `:desktop`/`Desktop.Window`/`is_desktop`/`?client=desktop` plumbing exists: `EVOGIT_DESKTOP` is referenced by `UpdateStatus.desktop?/0` and `DesktopLifetime`'s gating, and `:wx` ONLY by `DirectoryPicker` + its `Wx` seam (loaded via `wx: :load` in the root `mix.exs`; `genesis_server` stays wx-free).
- **Tray quit confirm**: tray "Quit Genesis" → Rust emits `quit-requested` → the `DesktopQuit` hook pushes `desktop_quit_requested` → `LiveHooks.DesktopQuit` shows a confirm dialog on ANY page → confirm runs graceful `System.stop(0)` through the `:desktop_quit_stop_fun` seam (150 ms-delayed, NO force quit, no timeout) → `live_hooks/CONTEXT.md` + `desktop/CONTEXT.md`.
- **Static assets** (`priv/static/`): `favicon.ico` + `images/favicon.svg` are DERIVED from `images/logo.svg` (source of truth; dark gray `#373435` + red `#C8383C`, aspect ≈ 1.2334); `images/logo-alt.svg` is the dark-theme variant; regeneration recipe: `assets/CONTEXT.md` → "Static Assets".
- **Release configuration** (owned by the ROOT `mix.exs` — this app has no `rel/`): releases `genesis` (both apps, dev), `genesis_desktop` (bakes `evo_dash: [desktop_release: true]`, bundled as a Tauri resource) and `genesis_server` (the only headless distribution: dashboard server AND SSH remote daemon, wx-free, `include_erts`); `config/runtime.exs` handles `PHX_SERVER=true` and server mode; production needs `SECRET_KEY_BASE` + `PHX_HOST`.

### Backend Boot Order (HTTP listener is bound LAST)

The Tauri readiness probe measures the ENTIRE umbrella boot — the port accepts connections only after `:evo_git` has fully started.

- `evo_dash.app` lists `:evo_git`, so `EvoGit.Application.start/2` completes first (incl. `EvoGit.Store.init/1` → synchronous `Store.Boot.start_dynamic/2` migrations and `TaskRegistry.init/1`'s lease read); the endpoint is the LAST child of `EvoDash.Application` and Bandit/ThousandIsland binds synchronously in its Listener `init/1` before `start/2` returns (`server: true` from `config/runtime.exs`), so a slow `:evo_git` boot presents as "backend unavailable" with no listener.
- **Boot observability is thin**: no boot line from either app, and `backend.log` is configured ONLY by the root `config/runtime.exs` (`type: :file`, APPENDED, 10 MB × 5 files) — the markers are Ecto's `Migrations already up` and `Running EvoDashWeb.Endpoint with Bandit <vsn> at <address>:<port> (http)` at `:info` per successful bind, plus `… failed, port <port> already in use`; `PORT`/`PHX_IP` are read ONCE per BEAM, a BOOT bind failure aborts `start/2` while a RUNTIME restart retries to the endpoint supervisor's intensity (3/5 s) then `EvoDash.Supervisor`'s (10/60 s), and no OS pid is logged, so `backend.log` cannot tell repeated boots from sidecar respawns vs `System.restart/0`.
- `DesktopLifetime` is the ONLY self-exit (5 connect attempts × 200 ms, 1 s timeout, then a warning + `System.stop(0)`; exit 0 is INTENTIONAL to the Tauri watchdog → silent quit, not the error page — `lib/evo_dash/CONTEXT.md`), and the shell error page is NOT the first-run `push_navigate(to: "/welcome")`: that 302 on `GET /` is real, but the load latch matches host+port only and post-upgrade launches never take it, because `VersionState.onboarding_needed?/0` keys on the version-state FILE existing.

## Research Notes — ReqLLM-Native Multimodal (Image/Audio) Attachments

Refines the root `./CONTEXT.md` note ("Research Notes: PDF/DOCX → Plain Text Extraction"): the plain-text pipeline (`EvoDash.AttachedFile.read/1` + `ex_pdf`) is unchanged, and image/audio attachments are ADDITIONALLY server-side-staged raw-binary content parts (`AttachedFile.read_kind/2` — image/audio kinds, extension allowlist, 15 MiB cap) staged into the Projects page's `:staged_attachments` assign and submitted as the `:attachments` task opt (base64 `"data"`, string-keyed maps) → `lib/evo_dash/CONTEXT.md` + `live/projects_live/CONTEXT.md`.

- Part types are `:text | :image_url | :video_url | :image | :file | :thinking | :provider_block` (no `input_image`/`input_audio`), and encoding is per-provider at encode time — the OpenAI-compatible flock turns ANY `:file` bytes into an `image_url` data-URI (silently mis-encoding non-images) — so check BOTH codec path and modality: capability truth is `:llm_db`'s `%LLMDB.Model{modalities: %{input: [...]}}` (`LLMDB.model/2`), with no "accepts image?" helper.
