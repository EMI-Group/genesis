# ./docs — Design Records & Reference Documentation

## Intent
Long-form design records, reference documentation and short user-facing guides for Genesis: rationale, verified external facts, and implementation details too granular for the CONTEXT.md tree.

## API Surface
- `agent-runtime-refactor.md` — design record + phased plan (P0–P6) for the **implemented** agent-runtime refactor (P0–P4 core, P5 per-run durability and P6 dashboard landed; only transparent survival of a LIVE session remains out of scope — boot reconciliation still marks an `:awaiting_input` session `:failed`): ONE supervised `EvoGit.Agent.Session` (`gen_statem`) per agent — one-shot and interactive alike — owning the single copy of `%EvoGit.Agent.State{}` (the ETS context mirror collapses to the summary-only `:evogit_agent_summary` read model), a per-exchange worker `Task` running the loop so the owner stays responsive, a `:yield`/`:finish` split that lets ONE engine serve both today's one-shot agents and interactive sessions (`:awaiting_input` task status), consumer-gated PUSH-ONLY `EvoGit.Agent.Stream` deltas (one `watch/1` call = snapshot + monotonic `seq` + registration in the session-owned watcher set, coalesced broadcasts on the `EvoGit.PubSub` `"agent:<id>"` topic, no callbacks and no broadcast with zero watchers, no polling/cursor path, gaps repaired by a fresh snapshot), a worktree kept for the session's whole life and reclaimed exactly once when it ends (no idle TTL, no suspend, explicit close instead), lifecycle re-keying onto the session pid, and the invariants to pin with tests.
- `genesis-assistant.md` — user guide (not a design record): the dashboard **Assistant** (`/assistant`; `/help` 302-redirects there) as a general-purpose Genesis operator — reading the Genesis source through the `vct:///genesis-source` system mount (the running checkout in a dev run, the `<data_dir>/genesis-source` managed clone in a release; re-pointable, `GENESIS_SOURCE_ROOT` override), CONTEXT.md/git-history reading, `elixir_eval` read/write/sudo tiers with exact-code approvals, task control, the guide overlay, and runtime versus saved configuration.
- `auto-update.md` — full design record for the desktop auto-update / push-update system (tauri-plugin-updater v2): two-phase check/download/apply model, the genesis.evox.group `/dl/` update feed, CI signing, platform matrix, and remaining blockers.
- `server-update.md` — design record AND user guide for the headless `genesis_server` self-update: why the release shell CLI (not the desktop plugin) performs it, the shared `latest.json` `server` map + published `.sha256`, the `genesis update`/`upgrade` flags, exit codes and output lines, the `/server/status` idle gate, the staged stop→swap→start→`/health`→rollback flow, and the deferred dashboard/remote-node orchestration.
- `experiments.md` — results/reference document: the per-regime experimental results (formation, continuation, redevelopment, Terminal-Bench) and their figures, moved out of the top-level README; figures live under `images/experiments/`.
- `harness-alignment.md` — comparison record: Genesis agent runtime (tools, result conventions, role prompts, compression, loop, delegation) vs the DeepSeek Harness (`dsh`), with a tiered proposal list for aligning our environment with the harness newer DeepSeek models are trained on. Carries the verified `dsh` facts (tool names/caps/footers, prompt-slot table, compaction thresholds, subagent limits) so future agents do not re-investigate `/home/bill/Source/deepseek-harness`.
- `llm-profiles.md` — user guide: canonical provider accounts and nested concrete-model inventories, reasoning defaults versus explicit effort selection, dashboard setup, shared capacity and schedules, credentials, and legacy configuration compatibility.
- `llm-oauth.md` — user guide: ChatGPT/Codex or Claude Pro-Max subscription authentication through the dashboard's in-browser sign-in (plus its pasted-redirect fallback) or vendor CLI login, managed `auth.json` import, canonical provider-profile examples, setup paths, and troubleshooting.
- `process-management.md` — design record of the managed process & tool-execution platform: `EvoGit.ProcessManager`'s `%Execution{}` lifecycle, normalized OS handles and their control backends (systemd unit / POSIX pid+pgid / Windows pid), stats sampling and CPU-percent derivation, the `"processes"` PubSub contract, `EvoGit.ToolRuntime`'s batch responsibilities, the `/processes` inspector (the only dashboard surface, with its `?agent_id=`/`?task_id=` filters), an extension guide, and the known limitations (untested systemd control path, no Windows pause/resume/signal).
- `platform-sandbox.md` — design record + phased plan for platform sandboxing: verified reference facts from OpenAI Codex (Windows **MXC**/PSEC — `mxc-sdk` git dep, no service/setup/elevation, runtime create/close probe, child via suspended start + kill-on-close job, **no memory quota**; macOS **Seatbelt** — inline `-p` profile with `-D` parameters, writable-root unlink anchors, protected ancestors of carveouts, `literal`+`subpath` carveouts, metadata-name regexes, nested-symlink fail-closed, fcntl 80/110 deny), what Genesis has today (systemd/bwrap/macOS allow-most profile, **nothing on Windows**), and the target architecture (`EvoGit.Sandbox.Spec` — P0 shipped — consumed by per-OS renderers; a small standalone Rust helper `genesis-sandbox.exe` on Windows only, P1 deferred for lack of a Windows host; macOS stays in Elixir), with P0–P4 phases, non-goals, gotchas and test strategy; resource governance (OOM) is explicitly a separate workstream.
- `virtual-tree.md` — design record of the **implemented, deliberately minimal** Virtual Context Tree (VCT): an internal `vct:///…` namespace with a DB-backed, capped mount registry (`vct_mounts` in the task store, 100 projects by default, oldest evicted), the optional global context level (`<data_dir>/vct/CONTEXT.md`, rendered as `global/CONTEXT.md`), `ContextNode.vct_path`, the first reserved system mount `vct:///genesis-source` (Genesis's own source checkout — the running checkout in `:source` mode, the `<data_dir>/genesis-source` managed clone in `:release` mode: boot-seeded via `EvoGit.SelfReflectiveSource.system_mounts/0`, re-ensured with `VCT.ensure_mount/3`, release boot auto-pull when the clone's `VERSION` differs, a boot merge that never steals a project-owned path and a reserved row re-pointed to a project point when a user opens it, resolvable but excluded from `projects/1`/`search/2`, never evicted, `{:error, :reserved_point}` on forget), and the **workspace** grouping layer (`vct:///workspaces/<slug>`: no OS path, an ordered member list of project refs with `missing`/`nested` reporting, exactly one nesting level, uncapped, and never an execution path — `RuntimeOpts.admit_task_path/1` refuses a workspace point); never materialized on the filesystem — explicitly NOT symlink farms, bind mounts, FUSE, junctions, per-mount worktrees or any filesystem-layout change (tasks still run in one concrete repo worktree with unchanged `foreign_repos`); closes with the deferred future extension (remote `vct://<host>/…`, global-context UI, further capability/system mounts as git mounts, nested mounts, materialization explicitly rejected).
- `ui-density.md` — design record for the dashboard's ONE comfortable UI density and type scale: the type ladder (12/13/14/15/17/20 px), control and row height tokens, spacing/radius rhythm, the scroll-containment shape for list panels, the coarse-pointer/touch floor, per-surface targets, and the migration rules (read before adding or changing any dashboard styling, row, control, card or panel).
- `ui-rearchitecture.md` — design record for Tasks as the execution and audit subject, separate Assistant and New Task flows using a shared editor and toolbar, lifecycle destinations, the compact rail integrated with the canvas, and the role-based right dock and local motion rules.
- `live-async-loads.md` — reference inventory (not a design record) for the dashboard's off-process data loading: the ONE `TaskSupervisor` + `SafeCall` spawn contract, the nested-vs-flat result tag rule, each LiveView page's spawn sites and stale guards, and the Review in-progress UI contract; the contract itself lives in `apps/evo_dash/lib/evo_dash_web/live/CONTEXT.md`, which points here for the per-page detail.
- `agent-run-durability.md` — design record of per-agent durable state and resume: the live-run row model (identity/parent/batch position/git anchor/re-dispatch), stable `agent_id` across restarts, the `refs/genesis/agent-state/…` commit anchors, the recursive whole-tree resume protocol (root + re-spawned children through the rebuilt batch), and the containment rules that keep durable state from ever stalling or crashing a run (read before changing `EvoGit.AgentState`, pause/resume, crash retry, agent-id allocation or worktree reclamation).
- `agent-mcp.md` — user guide (not a design record): connecting an external coding agent to a running Genesis instance over MCP — Streamable HTTP at `/mcp` behind a bearer `mcp-token` file (created in the instance's config dir with mode `0600`, read per request, endpoint disabled until it exists), local-only reachability, the eleven `genesis_*` tools, the start/track/reconnect/continue/stop/pause-resume/inspect collaboration loop, the bounded `genesis_get_task.progress` projection, the saved-result envelope, and the limits of what the connector promises.
- `task-pause.md` — design record of task-level **pause/resume**: a pause SNAPSHOTS the whole task tree in place and a resume THAWS it, the `:pausing`/`:paused` state model and its lease/terminal semantics, the freeze protocol (`AgentScheduler.begin_task_pause/1` + one `TaskFreeze` over the live roster, parents parked on their subagent batch instead of completing it, the preserved in-flight marker as the recorded position, the bounded quiesce + force grace), the clean-vs-dirty pause distinction (`pause_kind` DERIVED: `:clean` only when every agent proved `clean_freeze: true`/`durable: true`, versus a restart/lease sweep, an expired quiesce or an unprovable freeze that resumes through the crash repair and ONE `[RESUME]` notice), the persisted facts (`tasks.pause_kind`, per-agent `agent_states.pause_commit`), the thaw protocol (durable ROOT row as the gate, `EvoGit.AgentState.Snapshot` as the one read, same task id, `resume_kind` `:clean_pause`/`:dirty_pause`/nil, persisted agent ids, the checkpoint/anchor worktree base, whole-tree restore with the same topology and positions), the invariants and the deliberate limits (interactive sessions and `persistent_state: false` tasks are refused, 120 s quiesce + 10 s force grace).
- `context-scopes.md` — design record of the two-scope `CONTEXT.md`: one git-tracked file split by a single `<!-- genesis:local -->` divider line into a **Shared** part inherited by the node and its descendants and a **Local** part rendered only for agents assigned to that directory, with `EvoGit.Core.ContextScope` as the single split/selection source of truth consumed per stage by `ContextNode.build_context/2` (global and ancestor stages Shared-only, the assigned node whole-file, front matter stripped after selection, truncation per rendered stage), the `scope` parameter contract on `read_context` (`all`/`shared`/`local`) and `edit_context` (`shared` default plus `local`/`all`) while writes stay subtree-confined and `write_context` stays whole-file, the authoring rules, the edge cases (no divider = byte-identical legacy render), the whole-file `ContextMerge` limitation and the non-goals (read before changing context rendering, the context tools or the split rule).
- `images/` — figures referenced by the design records and reference documents (`images/experiments/` for the experimental plots), plus the promo-film poster `promo-poster.jpg`.
- `images/readme/` — original README diagrams in the website palette: light/dark recursive-agent Git-history AVIF recordings (29.2 seconds, 30 FPS, 1440 x 960) with matching reduced-motion/static PNG fallbacks, and a three-layer architecture SVG. The README uses a centered 720px picture with theme and reduced-motion sources. Legacy recursive-work SVG/GIF assets remain available; their editable sources, render/encode scripts and all asset notes live alongside the files.

## Constraints

- README curation/update instructions live in `readme-evidence.md`; `readme-evidence.json` selects exactly three projects and result fields, and `readme-evidence.snapshot.json` stores minimal published data for deterministic offline generation.
- These are design records, not CONTEXT.md nodes: they may carry rationale and sequencing that CONTEXT.md deliberately must not.
- Keep external-fact claims accurate (Cloudflare worker behaviour, GitHub release redirect chains, CI mechanics) — other agents cite these instead of re-investigating.
- The desktop updater (`tauri-plugin-updater`) and the headless server updater (`genesis update`) share ONE `latest.json`: `platforms` is the desktop half and `server` the headless-tarball half, so a manifest change has to keep both consumers working and a server-only release must still publish the file.
- The tag-scoped `/dl/<tag>/<asset>` worker form is only live after a manual `pnpm deploy` in `genesis-doc`; the unversioned `/dl/<asset>` form is what shipped consumers use, and pinned server installs may fall back to GitHub.
- Design records describe the CURRENT design; edit them in place as the design changes rather than appending change history.
- The numbers in `experiments.md` mirror the published Genesis paper — keep them verbatim; they are observed system-level results, not normalized benchmarks.
